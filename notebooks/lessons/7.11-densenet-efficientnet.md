# 7.11 — DenseNet & EfficientNet

DenseNet and EfficientNet are two answers to the same scaling question: how can a CNN grow without wasting computation? DenseNet grows by **reusing features** — each layer adds a few new channels and passes the whole stack forward by concatenation. EfficientNet grows by **balancing scale** — depth, width, and input resolution rise together under one compound coefficient instead of being tuned one at a time.

### 1. DenseNet concatenation: a layer writes new feature maps, then keeps the old ones

A plain CNN layer usually replaces its input stack with a new stack. A DenseNet layer does something different: it reads all previous channels, writes only `k` new feature maps, and then **concatenates** old and new channels. If the block starts with $C_0$ channels and each layer contributes growth rate $k$, then after $L$ dense layers the channel count is $C_L=C_0+kL$.

```python
C0_w = 16  # initial channels entering a dense block.
k_w = 12  # growth rate: each layer contributes 12 new feature maps.
L_w = np.arange(0, 5)  # inspect the block after 0, 1, 2, 3, 4 layers.
channels_w = C0_w + k_w * L_w  # DenseNet channel law C_L = C_0 + kL.
print("layers:", L_w)
print("channels:", channels_w)
assert channels_w[1] == 28 and channels_w[2] == 40 and channels_w[4] == 64
```
▶ What you'll see: the canonical sequence 16 → 28 → 40 → 52 → 64, where each layer adds exactly 12 channels.

```python
old_features_w = np.arange(2 * 2 * 3).reshape(2, 2, 3)  # a tiny H×W×C stack with 3 old channels.
new_features_w = 100 + np.arange(2 * 2 * 2).reshape(2, 2, 2)  # two new feature maps from one dense layer.
stack_w = np.concatenate([old_features_w, new_features_w], axis=2)  # concatenate along channels, not height or width.
print("old shape:", old_features_w.shape, "new shape:", new_features_w.shape)
print("after concat:", stack_w.shape)
assert stack_w.shape == (2, 2, 5)
```
▶ What you'll see: spatial size stays 2×2, while channels grow from 3 to 5.

```python
plt.figure(figsize=(5, 3))
plt.plot(L_w, channels_w, marker="o", color="seagreen")
plt.title("1: DenseNet channel growth")
plt.xlabel("dense layer L")
plt.ylabel("channels C_L")
plt.xticks(L_w)
plt.show()
```
▶ What you'll see: a straight line because concatenation adds a fixed growth rate each layer.

*Why it's done this way:* DenseNet separates **preserving information** from **creating new information**. Concatenation keeps earlier feature maps exactly available to later layers, while the growth rate limits how many new maps each layer is allowed to add. The formula $C_L=C_0+kL$ is linear because each layer contributes a fixed-width packet of new evidence instead of replacing the whole representation.

### 2. A DenseNet layer reads every earlier channel, so later convolutions get larger

Feature reuse is not free. A DenseNet layer that outputs $k$ new maps with a $3\times3$ convolution must read every channel already in the shared stack. If the current stack has $C$ input channels, then the weight count is $3\cdot3\cdot C\cdot k$. Later layers therefore have more input weights even though they still output only `k` new maps.

```python
kernel_w = 3  # use a 3x3 spatial kernel.
input_channels_w = 40  # the third dense layer sees 40 existing channels in the lesson arithmetic.
growth_w = 12  # it writes 12 new channels.
weights_w = kernel_w * kernel_w * input_channels_w * growth_w
print("weights per output channel:", kernel_w * kernel_w * input_channels_w)
print("total weights:", weights_w)
assert weights_w == 4320
```
▶ What you'll see: `3×3×40=360` weights per new map and `360×12=4320` weights total.

```python
def conv3x3_same_w(x, kernels):
    pad = 1
    xp = np.pad(x, ((pad, pad), (pad, pad), (0, 0)), mode="constant")
    H, W, _ = x.shape
    out = np.zeros((H, W, kernels.shape[-1]))
    for i in range(H):
        for j in range(W):
            patch = xp[i:i+3, j:j+3, :]
            for oc in range(kernels.shape[-1]):
                out[i, j, oc] = np.sum(patch * kernels[..., oc])
    return out

x_w = np.arange(3 * 3 * 2, dtype=float).reshape(3, 3, 2) / 10  # two old channels.
K_w = np.ones((3, 3, 2, 1)) / 18  # one averaging output channel that reads both inputs.
y_w = conv3x3_same_w(x_w, K_w)
print("input shape:", x_w.shape, "new maps shape:", y_w.shape)
print("center response:", round(float(y_w[1, 1, 0]), 3))
assert round(float(y_w[1, 1, 0]), 3) == 0.85
```
▶ What you'll see: one new map is computed from all old channels; the center response averages all 18 patch values.

```python
Cs_w = C0_w + k_w * np.arange(4)  # inputs seen by layers 1..4: 16, 28, 40, 52.
param_per_layer_w = kernel_w * kernel_w * Cs_w * k_w
plt.figure(figsize=(5, 3))
plt.bar(["L1", "L2", "L3", "L4"], param_per_layer_w, color="steelblue")
plt.title("2: later dense layers read wider stacks")
plt.ylabel("3×3 weights in the layer")
plt.show()
```
▶ What you'll see: each bar rises because every new layer reads all earlier channels.

*Why it's done this way:* The dense layer's input dimension is the accumulated feature notebook. That is the source of reuse: a later layer can combine low-level edges, mid-level parts, and recent features directly. The mathematical cost follows the convolution shape rule — every output channel owns one kernel over every input channel — so the input side grows as $C$ even when the output side stays fixed at $k$.

### 3. Transition compression: a 1×1 layer controls the widening stack

Because DenseNet channels keep growing, blocks usually end with a transition layer. A $1\times1$ convolution can mix channels at each spatial location and reduce the channel count from $C$ to $\lfloor\theta C\rfloor$, where $0<\theta\le1$ is the compression factor. With $C=64$ and $\theta=0.5$, the next block receives 32 channels instead of 64.

```python
C_before_w = 64  # channels at the end of the dense block.
theta_w = 0.5  # compression factor.
C_after_w = int(theta_w * C_before_w)
removed_w = C_before_w - C_after_w
print("compressed channels:", C_after_w)
print("channels removed:", removed_w)
assert C_after_w == 32 and removed_w == 32
```
▶ What you'll see: transition compression halves the 64-channel stack to 32 channels.

```python
features_w = np.arange(2 * 2 * 4, dtype=float).reshape(2, 2, 4)  # four channels at each location.
W1x1_w = np.array([[1, 0], [0, 1], [0.5, 0.5], [-0.5, 0.5]], dtype=float)  # mix 4 channels into 2.
compressed_w = features_w @ W1x1_w  # 1x1 convolution is a channel matrix multiply at each pixel.
print("before:", features_w.shape, "after:", compressed_w.shape)
print("top-left compressed:", compressed_w[0, 0])
assert compressed_w.shape == (2, 2, 2)
assert np.allclose(compressed_w[0, 0], [-0.5, 3.5])
```
▶ What you'll see: each pixel keeps its spatial position but its channel vector shrinks from length 4 to length 2.

```python
no_compress_w = C0_w + k_w * np.arange(0, 9)
with_compress_w = np.array([16, 28, 40, 52, 64, 32, 44, 56, 68])  # compress after four layers, then grow again.
plt.figure(figsize=(5, 3))
plt.plot(no_compress_w, marker="o", label="no transition")
plt.plot(with_compress_w, marker="s", label="compress after block")
plt.title("3: compression resets channel growth")
plt.xlabel("step")
plt.ylabel("channels")
plt.legend()
plt.show()
```
▶ What you'll see: the compressed path drops at the transition, preventing unbounded widening.

*Why it's done this way:* A $1\times1$ convolution is the cheapest place to decide which channels should be kept, merged, or discarded because it touches only the channel vector at each pixel. Compression trades some raw feature availability for a smaller interface to the next block, keeping memory and later convolution weights under control.

### 4. EfficientNet compound scaling: depth, width, and resolution grow together

EfficientNet asks a different question: if we have more compute, should the model become deeper, wider, or see larger images? Its answer is to tie all three to one compound coefficient $\phi$: $d=\alpha^\phi$, $w=\beta^\phi$, and $r=\gamma^\phi$. The constants decide the proportions; $\phi$ selects the budget level.

```python
alpha_w, beta_w, gamma_w = 1.2, 1.1, 1.15  # sample compound-scaling constants.
phi_w = 2  # scale level.
d_w = alpha_w ** phi_w
wid_w = beta_w ** phi_w
res_w = gamma_w ** phi_w
print("depth multiplier:", round(d_w, 4))
print("width multiplier:", round(wid_w, 4))
print("resolution multiplier:", round(res_w, 4))
assert round(d_w, 4) == 1.44 and round(wid_w, 4) == 1.21 and round(res_w, 4) == 1.3225
```
▶ What you'll see: the lesson multipliers 1.44, 1.21, and 1.3225 for $\phi=2$.

```python
base_depth_w, base_width_w, base_res_w = 10, 32, 224  # a toy baseline CNN.
scaled_depth_w = int(np.ceil(base_depth_w * d_w))
scaled_width_w = int(np.ceil(base_width_w * wid_w))
scaled_res_w = int(np.ceil(base_res_w * res_w))
print("scaled depth/width/resolution:", scaled_depth_w, scaled_width_w, scaled_res_w)
assert scaled_depth_w == 15 and scaled_width_w == 39 and scaled_res_w == 297
```
▶ What you'll see: one $\phi$ choice changes the number of layers, channels, and input pixels together.

```python
phis_w = np.arange(0, 5)
d_curve_w = alpha_w ** phis_w
w_curve_w = beta_w ** phis_w
r_curve_w = gamma_w ** phis_w
plt.figure(figsize=(5, 3))
plt.plot(phis_w, d_curve_w, marker="o", label="depth")
plt.plot(phis_w, w_curve_w, marker="s", label="width")
plt.plot(phis_w, r_curve_w, marker="^", label="resolution")
plt.title("4: compound multipliers from one coefficient")
plt.xlabel("compound coefficient φ")
plt.ylabel("multiplier")
plt.legend()
plt.show()
```
▶ What you'll see: all three curves rise smoothly, with depth rising fastest for these constants.

*Why it's done this way:* Scaling only one axis creates bottlenecks: more pixels need enough channels to describe details, and enough layers to combine them into larger patterns. Exponential rules make each extra $\phi$ step apply the same proportional growth, so model families can be expanded systematically instead of by guesswork.

### 5. EfficientNet compute budgeting: depth × squared width × squared resolution

A rough convolutional cost scales like $d\cdot w^2\cdot r^2$. Depth multiplies because more layers repeat work. Width is squared because convolution cost depends on both input and output channels. Resolution is squared because image area grows with height times width. This is why modest multipliers can produce a large compute jump.

```python
cost_factor_w = d_w * (wid_w ** 2) * (res_w ** 2)
print("w^2:", round(wid_w ** 2, 4))
print("r^2:", round(res_w ** 2, 6))
print("combined compute factor:", round(cost_factor_w, 3))
assert round(cost_factor_w, 3) == 3.687
```
▶ What you'll see: the sample $\phi=2$ model costs about 3.687× the baseline convolutional work.

```python
base_ops_w = 1_000_000  # toy baseline convolution work units.
scaled_ops_w = base_ops_w * cost_factor_w
print("baseline ops:", f"{base_ops_w:,}")
print("scaled ops:", f"{int(round(scaled_ops_w)):,}")
assert int(round(scaled_ops_w)) == 3687437
```
▶ What you'll see: one million toy ops becomes about 3.69 million after compound scaling.

```python
cost_curve_w = (alpha_w ** phis_w) * (beta_w ** phis_w) ** 2 * (gamma_w ** phis_w) ** 2
plt.figure(figsize=(5, 3))
plt.plot(phis_w, cost_curve_w, marker="o", color="crimson")
plt.axhline(1, color="black", linewidth=0.7)
plt.title("5: compound compute grows multiplicatively")
plt.xlabel("compound coefficient φ")
plt.ylabel("relative convolution cost")
plt.show()
```
▶ What you'll see: compute rises much faster than any single multiplier because the axes multiply.

*Why it's done this way:* The cost formula mirrors convolution arithmetic. A wider layer has more input channels and more output channels, so width appears twice. A larger image has more rows and more columns, so resolution appears twice. EfficientNet's discipline is not that compute stays small; it is that every extra unit of compute is allocated across the axes that need one another.

## 🛠️ Setup

```python
import numpy as np # load NumPy for arrays, channel stacks, convolution loops, and numerical checks.
import matplotlib.pyplot as plt # load Matplotlib for the heatmaps, bar charts, and scaling curves.
np.random.seed(0) # make all random examples reproducible across notebook runs.

def conv2d_same(x, kernels): # compute a tiny same-padded 2D convolution for H×W×C inputs.
    pad_h = kernels.shape[0] // 2 # infer vertical padding for odd-sized kernels.
    pad_w = kernels.shape[1] // 2 # infer horizontal padding for odd-sized kernels.
    xp = np.pad(x, ((pad_h, pad_h), (pad_w, pad_w), (0, 0)), mode="constant") # zero-pad spatial dimensions only.
    H, W, _ = x.shape # read spatial size from the input feature grid.
    out = np.zeros((H, W, kernels.shape[-1])) # allocate one output map per output channel.
    for i in range(H): # slide over rows.
        for j in range(W): # slide over columns.
            patch = xp[i:i+kernels.shape[0], j:j+kernels.shape[1], :] # gather the local patch across all channels.
            for oc in range(kernels.shape[-1]): # compute each output channel separately.
                out[i, j, oc] = np.sum(patch * kernels[..., oc]) # sum spatial and channel products.
    return out # return the convolved feature stack.

def dense_concat(x, new_maps): # append new DenseNet feature maps to the existing stack.
    return np.concatenate([x, new_maps], axis=2) # concatenate only along the channel axis.

def transition_1x1(x, W): # apply a 1×1 channel-mixing projection at every pixel.
    return x @ W # matrix multiply each H×W channel vector by W.

def compound(alpha, beta, gamma, phi): # compute EfficientNet-style multipliers.
    return alpha ** phi, beta ** phi, gamma ** phi # depth, width, and resolution multipliers.

def conv_cost_factor(d, w, r): # approximate convolutional cost multiplier.
    return d * (w ** 2) * (r ** 2) # depth times squared width times squared resolution.
```
