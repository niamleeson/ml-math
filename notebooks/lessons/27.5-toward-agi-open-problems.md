# 27.5 — Toward AGI & Open Problems

AGI is not one score going up; it is many abilities holding together under shift. This lesson treats “toward AGI” as a map of unresolved mechanisms: generalization, representation transfer, agency, continual learning, scalable oversight, world modeling, robust evaluation, and alignment. The key habit is to replace vague hype with toy measurements that reveal bottlenecks, gaps, and tradeoffs.

## 📖 Concept walkthrough — build each idea from scratch

Before the worked examples, we build the open-problems map one idea at a time. Run each cell in order and inspect the printed values and plots — every metric is simulated from scratch so the logic is visible. The walkthrough uses `_w` suffixes so it does not clash with the examples below.

```python
import numpy as np  # arrays, simple metrics, and deterministic simulations.
import matplotlib.pyplot as plt  # every walkthrough and example uses Matplotlib visual checks.
np.random.seed(0)  # reproducibility for toy trends.
```

### 1. One leaderboard is not general intelligence

A broad system has many load-bearing abilities: factual recall, reasoning, robustness, tool use, memory, and alignment. A single arithmetic average can look respectable even when one link is weak. Bottleneck-aware summaries such as a minimum or geometric mean deliberately punish missing links, which is closer to how real systems fail under pressure.

```python
cap_w = np.array([0.90, 0.80, 0.20, 0.40])  # capability coordinates from the lesson math.
labels_w = ["knowledge", "reasoning", "robustness", "alignment"]  # readable ability names.
avg_w = float(np.mean(cap_w))  # arithmetic score rewards compensation across abilities.
geo_w = float(np.exp(np.mean(np.log(cap_w))))  # geometric score punishes low coordinates.
bottleneck_w = float(np.min(cap_w))  # floor score asks whether every link is strong enough.
print("average:", round(avg_w, 3), "geometric:", round(geo_w, 3), "bottleneck:", round(bottleneck_w, 3))
assert round(avg_w, 3) == 0.575
assert round(geo_w, 3) == 0.490
assert round(bottleneck_w, 3) == 0.200
plt.figure(figsize=(6, 3.2))
plt.bar(labels_w, cap_w, color=["seagreen", "seagreen", "crimson", "orange"])
plt.axhline(avg_w, color="navy", linestyle="--", label="average")
plt.axhline(bottleneck_w, color="crimson", linestyle=":", label="bottleneck")
plt.ylim(0, 1)
plt.title("1: capability vector exposes a weak link")
plt.ylabel("score")
plt.xticks(rotation=15)
plt.legend()
plt.show()
```
▶ What you'll see: the average looks moderate, but the robustness coordinate is a visible weak link.

*Why it's done this way:* AGI claims should specify aggregation; averages reward spiky systems, while floor-like scores ask whether essential abilities hold together.

### 2. Generalization means surviving distribution shift

A model that performs well on the training distribution may fail when goals, wording, observations, or tools shift. The robustness gap compares in-distribution score with shifted score. The retained fraction asks how much apparent competence survives outside the comfortable setting.

```python
in_dist_w = 0.82  # score on familiar benchmark-like inputs.
shifted_w = 0.49  # score after the input distribution changes.
gap_w = in_dist_w - shifted_w  # absolute robustness gap.
retained_w = shifted_w / in_dist_w  # fraction of competence retained under shift.
print("gap:", round(gap_w, 3), "retained fraction:", round(retained_w, 3))
assert round(gap_w, 3) == 0.330
assert round(retained_w, 3) == 0.598
difficulty_w = np.linspace(0, 1, 80)  # increasing shift severity.
curve_id_w = in_dist_w - 0.10 * difficulty_w  # familiar test changes slowly.
curve_shift_w = in_dist_w - gap_w * (difficulty_w ** 0.7)  # shifted test degrades faster.
plt.figure(figsize=(5.5, 3.2))
plt.plot(difficulty_w, curve_id_w, label="in-distribution", color="teal")
plt.plot(difficulty_w, curve_shift_w, label="shifted", color="crimson")
plt.fill_between(difficulty_w, curve_shift_w, curve_id_w, color="crimson", alpha=0.15)
plt.title("2: robustness gap under shift")
plt.xlabel("shift severity")
plt.ylabel("score")
plt.ylim(0, 1)
plt.legend()
plt.show()
```
▶ What you'll see: the shifted curve falls away from the in-distribution curve as severity increases.

*Why it's done this way:* generalization is not the original score; it is the gap between apparent competence and competence when the setting changes.

### 3. Representation learning asks what transfers

A benchmark feature can correlate with success without being the concept we wanted. Transfer asks whether a learned representation keeps working when superficial correlations break. In the toy below, a shortcut feature saturates quickly, while a concept feature grows more slowly but transfers better.

```python
steps_w = np.arange(1, 11)  # training stages.
shortcut_w = 1 - np.exp(-0.8 * steps_w)  # fast benchmark-specific correlation.
concept_w = 1 - np.exp(-0.25 * steps_w)  # slower reusable abstraction.
transfer_w = 0.25 * shortcut_w + 0.75 * concept_w  # transfer relies more on real concepts.
print("final shortcut:", round(shortcut_w[-1], 3), "final transfer:", round(transfer_w[-1], 3))
assert transfer_w[-1] < shortcut_w[-1]
plt.figure(figsize=(5.5, 3.2))
plt.plot(steps_w, shortcut_w, marker="o", label="benchmark shortcut", color="orange")
plt.plot(steps_w, concept_w, marker="s", label="concept representation", color="seagreen")
plt.plot(steps_w, transfer_w, marker="^", label="transfer score", color="navy")
plt.title("3: shortcut saturation vs transferable concepts")
plt.xlabel("training stage")
plt.ylabel("score")
plt.ylim(0, 1.05)
plt.legend()
plt.show()
```
▶ What you'll see: benchmark performance can saturate before transfer catches up.

*Why it's done this way:* representation quality is judged by behavior under new tasks, not by a shortcut-heavy benchmark alone.

### 4. Agent learning compounds errors over long horizons

Agents must combine goals, memory, feedback, and actions. Even a high per-step success probability can collapse over long horizons because every step is another chance to fail. Recovery mechanisms matter because they bend the horizon curve upward after mistakes.

```python
horizon_w = np.arange(1, 31)  # number of sequential decisions.
step_success_w = 0.94  # probability one action is correct.
no_recovery_w = step_success_w ** horizon_w  # all steps must go right.
with_recovery_w = no_recovery_w + 0.35 * (1 - no_recovery_w) * (1 - np.exp(-horizon_w / 10))  # toy recovery gain.
print("30-step no recovery:", round(no_recovery_w[-1], 3), "with recovery:", round(with_recovery_w[-1], 3))
assert with_recovery_w[-1] > no_recovery_w[-1]
plt.figure(figsize=(5.5, 3.2))
plt.plot(horizon_w, no_recovery_w, label="no recovery", color="crimson")
plt.plot(horizon_w, with_recovery_w, label="memory + feedback recovery", color="teal")
plt.title("4: long-horizon agency needs recovery")
plt.xlabel("decision horizon")
plt.ylabel("task success probability")
plt.ylim(0, 1)
plt.legend()
plt.show()
```
▶ What you'll see: success decays with horizon, and recovery slows the decay.

*Why it's done this way:* agent capability is not just one-step accuracy; long-horizon reliability depends on error detection, correction, and memory.

### 5. Continual learning exposes forgetting

A system can learn a new task while damaging old skills. Continual learning therefore tracks old-task scores before and after the update, not just the new-task score. The open problem is to add knowledge without overwriting useful representations.

```python
before_w = np.array([0.85, 0.80, 0.78])  # scores before adding the new task.
after_w = np.array([0.55, 0.57, 0.90])  # old tasks dropped, new task improved.
old_change_w = float(np.mean(after_w[:2] - before_w[:2]))  # average change on old tasks.
before_mean_w = float(np.mean(before_w))
after_mean_w = float(np.mean(after_w))
print("before mean:", round(before_mean_w, 3), "after mean:", round(after_mean_w, 3), "old-task change:", round(old_change_w, 3))
assert round(before_mean_w, 3) == 0.810
assert round(after_mean_w, 3) == 0.673
assert round(old_change_w, 3) == -0.265
x_w = np.arange(3)
plt.figure(figsize=(5.5, 3.2))
plt.bar(x_w - 0.18, before_w, width=0.36, label="before", color="gray")
plt.bar(x_w + 0.18, after_w, width=0.36, label="after", color="purple")
plt.xticks(x_w, ["old A", "old B", "new C"])
plt.ylim(0, 1)
plt.title("5: new skill can hide forgetting")
plt.ylabel("score")
plt.legend()
plt.show()
```
▶ What you'll see: the new task improves, but two old tasks visibly drop.

*Why it's done this way:* continual learning metrics must separate new-task acquisition from old-task retention.

### 6. Alignment is a floor, not a postscript

When a system can affect users or environments, helpfulness cannot simply average away a low safety or honesty score. Alignment changes the objective from “maximize one scalar” to “satisfy multiple constraints while remaining useful.”

```python
align_w = np.array([0.92, 0.88, 0.40])  # helpfulness, honesty, safety from the lesson math.
align_labels_w = ["helpful", "honest", "safe"]
align_avg_w = float(np.mean(align_w))
align_floor_w = float(np.min(align_w))
print("alignment average:", round(align_avg_w, 3), "required-floor score:", round(align_floor_w, 3))
assert round(align_avg_w, 3) == 0.733
assert round(align_floor_w, 3) == 0.400
plt.figure(figsize=(5.2, 3.2))
plt.bar(align_labels_w, align_w, color=["seagreen", "seagreen", "crimson"])
plt.axhline(0.70, color="black", linestyle="--", label="deployment floor")
plt.axhline(align_avg_w, color="navy", linestyle=":", label="average")
plt.ylim(0, 1)
plt.title("6: safety floor cannot be averaged away")
plt.ylabel("score")
plt.legend()
plt.show()
```
▶ What you'll see: the average clears a moderate line, but the safety bar fails the deployment floor.

*Why it's done this way:* alignment is a constraint system; some failures matter even when other abilities are strong.

### 7. Scaling helps, but it does not certify reasoning

More compute and data often reduce predictive loss, but lower loss alone does not prove long-horizon reasoning, causal abstraction, or robust tool use. Scaling curves are evidence about one target; AGI claims need separate tests for bottlenecks and shift.

```python
compute_w = np.logspace(0, 2, 50)  # 1x to 100x compute.
start_loss_w = 0.300
scaled_loss_w = start_loss_w * compute_w ** (-0.08)  # lesson scaling exponent.
improvement_w = start_loss_w - scaled_loss_w[-1]
print("100x loss:", round(float(scaled_loss_w[-1]), 3), "improvement:", round(float(improvement_w), 3))
assert round(float(scaled_loss_w[-1]), 3) == 0.208
assert round(float(improvement_w), 3) == 0.092
reasoning_w = 0.45 + 0.18 * (1 - np.exp(-np.log10(compute_w) / 0.9))  # toy slower reasoning gain.
plt.figure(figsize=(5.5, 3.2))
plt.plot(compute_w, scaled_loss_w, label="predictive loss", color="crimson")
plt.plot(compute_w, reasoning_w, label="reasoning stress score", color="teal")
plt.xscale("log")
plt.title("7: scaling curve vs reasoning stress test")
plt.xlabel("relative compute")
plt.ylabel("metric")
plt.legend()
plt.show()
```
▶ What you'll see: predictive loss improves smoothly, while the reasoning stress score moves differently.

*Why it's done this way:* compute is a powerful axis, but open problems require targeted measurements beyond a loss curve.

### 8. Open problems form a connected taxonomy

The final stance is neither dismissal nor hype: name missing mechanisms precisely. Interpretability, scalable oversight, continual learning, world modeling, robust evaluation, and aligned agency interact; progress on one link does not automatically solve the others.

```python
nodes_w = {
    "Robust\nevaluation": (0.1, 0.7),
    "World\nmodeling": (0.35, 0.88),
    "Continual\nlearning": (0.62, 0.75),
    "Interpretability": (0.22, 0.35),
    "Scalable\noversight": (0.52, 0.35),
    "Aligned\nagency": (0.82, 0.55),
}
plt.figure(figsize=(6, 3.8))
for name_w, (x_w, y_w) in nodes_w.items():
    plt.scatter([x_w], [y_w], s=650, color="lightsteelblue", edgecolor="navy")
    plt.text(x_w, y_w, name_w, ha="center", va="center", fontsize=9)
for a_w, b_w in [("Robust\nevaluation", "World\nmodeling"), ("World\nmodeling", "Continual\nlearning"), ("Continual\nlearning", "Aligned\nagency"), ("Interpretability", "Scalable\noversight"), ("Scalable\noversight", "Aligned\nagency"), ("Robust\nevaluation", "Interpretability")]:
    xa_w, ya_w = nodes_w[a_w]
    xb_w, yb_w = nodes_w[b_w]
    plt.arrow(xa_w, ya_w, 0.82 * (xb_w - xa_w), 0.82 * (yb_w - ya_w), head_width=0.025, color="gray", length_includes_head=True)
plt.xlim(0, 1)
plt.ylim(0.15, 1)
plt.axis("off")
plt.title("8: AGI open-problem taxonomy")
plt.show()
```
▶ What you'll see: the open problems are connected rather than a single ladder.

*Why it's done this way:* a taxonomy prevents one impressive curve from being mistaken for a complete solution.

## ✍️ Toy Examples

> ✍️ **Toy examples — trace each mechanic by hand.** These open-problem toys avoid hype by turning
> each claim into a tiny calculation: aggregation, shift, transfer, horizon reliability, forgetting,
> safety floors, scaling curves, and graph coupling.

### ✍️ Toy 1 · Aggregation exposes bottlenecks

Averages can hide weak capabilities. Compare the arithmetic mean, geometric mean, and minimum on one
small capability vector.

```python
import numpy as np
import matplotlib.pyplot as plt

t1_rng = np.random.default_rng(0)                 # seeded generator for reproducibility
t1_caps = np.array([0.9, 0.7, 0.3])               # knowledge, reasoning, robustness
print("capabilities:", t1_caps.tolist())          # -> [0.9, 0.7, 0.3]
t1_average = float(t1_caps.mean())                # compensating average score
print("average:", round(t1_average, 3))           # -> 0.633
t1_geo = float(np.exp(np.mean(np.log(t1_caps))))  # geometric mean score
print("geometric mean:", round(t1_geo, 3))        # -> 0.574
t1_floor = float(t1_caps.min())                   # bottleneck score
print("bottleneck floor:", round(t1_floor, 3))    # -> 0.3
assert round(t1_floor, 3) == 0.3
assert t1_floor < t1_geo < t1_average

plt.figure(figsize=(4.6, 2.8))
plt.bar(["knowledge", "reason", "robust"], t1_caps, color=["#4c78a8", "#4c78a8", "#e45756"])
plt.axhline(t1_average, color="black", linestyle="--", label="average")
plt.axhline(t1_floor, color="crimson", linestyle=":", label="floor")
plt.ylim(0, 1)
plt.ylabel("score")
plt.title("Toy 1 · weak-link aggregation")
plt.legend()
plt.show()
```
▶ What you'll see: the average line is much higher than the weakest capability bar.

### ✍️ Toy 2 · Shift gap measures retained skill

Generalization under distribution shift is a gap calculation, not just a headline score. Compute the
retained fraction and draw shifted degradation.

```python
import numpy as np

t2_rng = np.random.default_rng(0)                 # seeded generator for reproducibility
t2_in_score = 0.84                                # familiar-setting score
print("in-distribution score:", round(float(t2_in_score), 3)) # -> 0.84
t2_shift_score = 0.56                             # shifted-setting score
print("shifted score:", round(float(t2_shift_score), 3)) # -> 0.56
t2_gap = t2_in_score - t2_shift_score             # robustness gap
print("shift gap:", round(float(t2_gap), 3))      # -> 0.28
t2_retained = t2_shift_score / t2_in_score        # retained fraction under shift
print("retained fraction:", round(float(t2_retained), 3)) # -> 0.667
t2_severity = np.array([0.0, 0.5, 1.0])           # shift severity grid
print("severity:", t2_severity.tolist())          # -> [0.0, 0.5, 1.0]
t2_in_curve = t2_in_score - 0.05 * t2_severity    # mild in-distribution degradation
print("in curve:", np.round(t2_in_curve, 3))      # -> [0.84  0.815 0.79 ]
t2_shift_curve = t2_in_score - t2_gap * np.sqrt(t2_severity) # shifted degradation
print("shift curve:", np.round(t2_shift_curve, 3)) # -> [0.84  0.642 0.56 ]
assert round(t2_retained, 3) == 0.667

plt.figure(figsize=(4.6, 2.8))
plt.plot(t2_severity, t2_in_curve, marker="o", label="in-distribution")
plt.plot(t2_severity, t2_shift_curve, marker="s", label="shifted")
plt.xlabel("shift severity")
plt.ylabel("score")
plt.ylim(0.5, 0.9)
plt.title("Toy 2 · retained skill")
plt.legend()
plt.show()
```
▶ What you'll see: the shifted curve separates from the familiar curve as severity rises.

### ✍️ Toy 3 · Shortcut features transfer poorly

A shortcut can saturate quickly on the benchmark while the slower concept feature determines transfer
quality.

```python
import numpy as np

t3_rng = np.random.default_rng(0)                 # seeded generator for reproducibility
t3_steps = np.arange(1, 5)                        # training stages
print("steps:", t3_steps.tolist())                # -> [1, 2, 3, 4]
t3_shortcut = 1 - np.exp(-1.0 * t3_steps)         # fast shortcut learning
print("shortcut:", np.round(t3_shortcut, 3))      # -> [0.632 0.865 0.95  0.982]
t3_concept = 1 - np.exp(-0.35 * t3_steps)         # slower concept learning
print("concept:", np.round(t3_concept, 3))        # -> [0.295 0.503 0.65  0.753]
t3_transfer = 0.2 * t3_shortcut + 0.8 * t3_concept # transfer-weighted score
print("transfer:", np.round(t3_transfer, 3))      # -> [0.363 0.576 0.71  0.799]
assert t3_transfer[-1] < t3_shortcut[-1]

plt.figure(figsize=(4.8, 2.8))
plt.plot(t3_steps, t3_shortcut, marker="o", label="shortcut")
plt.plot(t3_steps, t3_concept, marker="s", label="concept")
plt.plot(t3_steps, t3_transfer, marker="^", label="transfer")
plt.xlabel("stage")
plt.ylabel("score")
plt.title("Toy 3 · transfer needs concepts")
plt.legend()
plt.show()
```
▶ What you'll see: shortcut performance rises fastest, but transfer follows the slower concept curve.

### ✍️ Toy 4 · Horizon reliability compounds

Long-horizon agents multiply per-step reliability. A recovery mechanism can bend the curve upward,
but it does not remove compounding risk.

```python
import numpy as np

t4_rng = np.random.default_rng(0)                 # seeded generator for reproducibility
t4_horizon = np.array([1, 5, 10])                 # sequence lengths
print("horizons:", t4_horizon.tolist())           # -> [1, 5, 10]
t4_step_success = 0.92                            # one-step success probability
print("one-step success:", round(float(t4_step_success), 3)) # -> 0.92
t4_no_recovery = t4_step_success ** t4_horizon    # all steps must succeed
print("no recovery:", np.round(t4_no_recovery, 3)) # -> [0.92  0.659 0.434]
t4_recovery = t4_no_recovery + 0.25 * (1 - t4_no_recovery) * (1 - np.exp(-t4_horizon / 5.0)) # recovery gain
print("with recovery:", np.round(t4_recovery, 3)) # -> [0.924 0.713 0.557]
t4_gain = t4_recovery - t4_no_recovery            # recovery improvement
print("recovery gain:", np.round(t4_gain, 3))     # -> [0.004 0.054 0.122]
assert t4_recovery[-1] > t4_no_recovery[-1]

plt.figure(figsize=(4.6, 2.8))
plt.plot(t4_horizon, t4_no_recovery, marker="o", label="no recovery")
plt.plot(t4_horizon, t4_recovery, marker="s", label="with recovery")
plt.xlabel("horizon")
plt.ylabel("success probability")
plt.ylim(0, 1)
plt.title("Toy 4 · compounding reliability")
plt.legend()
plt.show()
```
▶ What you'll see: success falls with horizon, while recovery partially lifts the long-horizon endpoint.

### ✍️ Toy 5 · Continual learning measures forgetting

Adding a new skill can reduce old-task performance. Separate old-task retention from new-task gain.

```python
import numpy as np

t5_rng = np.random.default_rng(0)                 # seeded generator for reproducibility
t5_before = np.array([0.80, 0.75, 0.20])          # old A, old B, new C before update
print("before:", t5_before.tolist())              # -> [0.8, 0.75, 0.2]
t5_after = np.array([0.62, 0.58, 0.78])           # scores after learning new C
print("after:", t5_after.tolist())                # -> [0.62, 0.58, 0.78]
t5_old_change = t5_after[:2] - t5_before[:2]      # changes on old tasks
print("old-task changes:", np.round(t5_old_change, 3)) # -> [-0.18 -0.17]
t5_old_mean_change = float(t5_old_change.mean())  # average forgetting on old tasks
print("mean old-task change:", round(t5_old_mean_change, 3)) # -> -0.175
t5_new_gain = float(t5_after[2] - t5_before[2])   # gain on new task
print("new-task gain:", round(t5_new_gain, 3))    # -> 0.58
t5_before_mean = float(t5_before.mean())          # overall average before
print("before mean:", round(t5_before_mean, 3))   # -> 0.583
t5_after_mean = float(t5_after.mean())            # overall average after
print("after mean:", round(t5_after_mean, 3))     # -> 0.66
assert t5_old_mean_change < 0
assert t5_new_gain > 0

plt.figure(figsize=(4.8, 2.8))
t5_x = np.arange(3)                               # bar positions
plt.bar(t5_x - 0.18, t5_before, width=0.36, label="before")
plt.bar(t5_x + 0.18, t5_after, width=0.36, label="after")
plt.xticks(t5_x, ["old A", "old B", "new C"])
plt.ylim(0, 1)
plt.ylabel("score")
plt.title("Toy 5 · forgetting vs new skill")
plt.legend()
plt.show()
```
▶ What you'll see: the new task improves while both old-task bars drop.

### ✍️ Toy 7 · Scaling loss differs from reasoning score

Predictive loss can improve smoothly while another stress metric follows a different curve. Compute
both changes from 1x to 100x compute.

```python
import numpy as np

t7_rng = np.random.default_rng(0)                 # seeded generator for reproducibility
t7_compute = np.array([1.0, 10.0, 100.0])         # relative compute
print("compute:", t7_compute.tolist())            # -> [1.0, 10.0, 100.0]
t7_loss = 0.30 * t7_compute ** (-0.08)            # predictive-loss scaling curve
print("loss:", np.round(t7_loss, 3))              # -> [0.3   0.25  0.208]
t7_reason = 0.45 + 0.12 * (1 - np.exp(-np.log10(t7_compute) / 0.8)) # reasoning stress score
print("reasoning score:", np.round(t7_reason, 3)) # -> [0.45  0.536 0.56 ]
t7_loss_drop = float(t7_loss[0] - t7_loss[-1])    # loss improvement
print("loss drop:", round(t7_loss_drop, 3))       # -> 0.092
t7_reason_gain = float(t7_reason[-1] - t7_reason[0]) # reasoning score improvement
print("reasoning gain:", round(t7_reason_gain, 3)) # -> 0.11
assert round(float(t7_loss[-1]), 3) == 0.208
assert t7_reason_gain > t7_loss_drop
```
