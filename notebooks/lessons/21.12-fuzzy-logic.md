# 21.12 — Fuzzy Logic

Fuzzy logic replaces brittle yes-or-no categories with degrees of truth in `[0, 1]`, so words like **warm**, **near**, or **high risk** can guide numerical decisions without pretending their boundaries are sharp. In this lesson, we build membership functions, fuzzy connectives, rule firing, Mamdani inference, centroid defuzzification, and a small controller from scratch with NumPy.

### 1. Fuzzy membership functions

A fuzzy set is a function $\mu_A(x)\in[0,1]$, not a hard yes/no container. For temperature, `warm` should rise gradually from not-warm to fully-warm and then fall gradually as the room becomes hot. Triangles and trapezoids are common because they encode that idea with only a few interpretable breakpoints.

```python
def triangle_w(x, a, b, c):
    x = np.asarray(x, dtype=float)
    left = (x - a) / (b - a)
    right = (c - x) / (c - b)
    return np.clip(np.minimum(left, right), 0, 1)

def trapezoid_w(x, a, b, c, d):
    x = np.asarray(x, dtype=float)
    left = np.ones_like(x, dtype=float) if b == a else (x - a) / (b - a)
    right = np.ones_like(x, dtype=float) if d == c else (d - x) / (d - c)
    return np.clip(np.minimum(np.minimum(left, 1), right), 0, 1)

temps_w = np.linspace(10, 40, 301)
warm_w = triangle_w(temps_w, 18, 25, 32)
print("warm(25):", float(triangle_w(25, 18, 25, 32)))
print("warm(21):", round(float(triangle_w(21, 18, 25, 32)), 3))
assert float(triangle_w(25, 18, 25, 32)) == 1.0
```
▶ What you'll see: 25°C fits `warm` completely, while 21°C fits it only partly.

```python
cold_w = trapezoid_w(temps_w, 10, 10, 16, 22)
hot_w = trapezoid_w(temps_w, 28, 34, 40, 40)
plt.figure(figsize=(5, 3))
plt.plot(temps_w, cold_w, label="cold")
plt.plot(temps_w, warm_w, label="warm")
plt.plot(temps_w, hot_w, label="hot")
plt.xlabel("temperature (°C)"); plt.ylabel("membership")
plt.title("1: fuzzy temperature sets"); plt.legend(); plt.show()
```
▶ What you'll see: overlapping curves, so a temperature can be partly warm and partly hot instead of abruptly switching labels.

*Why it's done this way:* a membership function measures **compatibility with a word**, not probability. The triangle formula rises linearly from 0 to 1 because each step toward the prototype `b` should increase compatibility at a constant rate; it then falls symmetrically or asymmetrically toward `c`. The clipping keeps truth degrees inside `[0,1]`, which is the algebra fuzzy connectives expect.

### 2. T-norms, t-conorms, and fuzzy negation

Classical logic has AND, OR, and NOT. Fuzzy logic keeps the same roles but lets truth values be real numbers. The most common Mamdani choices are `min` for AND, `max` for OR, and `1 - x` for NOT.

```python
humid_w = 0.7
warm_degree_w = 0.4
and_min_w = min(humid_w, warm_degree_w)
or_max_w = max(humid_w, warm_degree_w)
not_humid_w = 1 - humid_w
print("AND min:", and_min_w)
print("OR max:", or_max_w)
print("NOT humid:", round(not_humid_w, 3))
assert and_min_w == 0.4 and or_max_w == 0.7
```
▶ What you'll see: the lesson numbers from the content block: `min(0.7, 0.4)=0.4` and `max(0.7,0.4)=0.7`.

```python
x_w = np.linspace(0, 1, 101)
y_w = 0.6
plt.figure(figsize=(5, 3))
plt.plot(x_w, np.minimum(x_w, y_w), label="min(x, 0.6) AND")
plt.plot(x_w, np.maximum(x_w, y_w), label="max(x, 0.6) OR")
plt.plot(x_w, 1 - x_w, label="NOT x")
plt.xlabel("x"); plt.ylabel("truth degree")
plt.title("2: fuzzy connectives"); plt.legend(); plt.show()
```
▶ What you'll see: AND is capped by the weaker premise, OR is supported by the stronger premise, and NOT reverses the scale.

*Why it's done this way:* with AND, a conjunction cannot be truer than its least true part, so `min` implements the weakest-link idea. With OR, one good reason is enough to support the conclusion, so `max` keeps the strongest support. These are not the only possible t-norm/t-conorm pair, but they are simple, monotone, bounded, and match the rule-clipping picture used by Mamdani inference.

### 3. Fuzzy rules fire partially

A fuzzy rule has the form `IF antecedent THEN consequent`. Unlike a crisp rule, it can fire with strength 0.6, 0.2, or any value in between. In Mamdani inference, that strength clips the consequent membership curve so the rule cannot recommend more strongly than its premise was supported.

```python
fan_w = np.linspace(0, 10, 201)
fast_w = triangle_w(fan_w, 5, 8, 10)
rule_strength_w = 0.6
clipped_fast_w = np.minimum(rule_strength_w, fast_w)
print("rule strength:", rule_strength_w)
print("max clipped consequent:", round(float(clipped_fast_w.max()), 3))
assert round(float(clipped_fast_w.max()), 3) == 0.6
```
▶ What you'll see: a rule with strength 0.6 clips the `fast` fan-speed recommendation so its maximum is 0.6.

```python
plt.figure(figsize=(5, 3))
plt.plot(fan_w, fast_w, label="fast consequent")
plt.fill_between(fan_w, clipped_fast_w, alpha=0.35, label="clipped by rule")
plt.axhline(rule_strength_w, color="black", linestyle="--")
plt.xlabel("fan speed"); plt.ylabel("membership")
plt.title("3: partial rule firing clips a consequent"); plt.legend(); plt.show()
```
▶ What you'll see: the original triangular `fast` set with its top flattened at the rule's firing strength.

*Why it's done this way:* the consequent shape encodes *which actions fit the word fast*, while the antecedent strength encodes *how much this rule should matter now*. Taking the minimum combines those two constraints: every possible action keeps its original compatibility, but no action can exceed the evidence supplied by the antecedent.

### 4. Mamdani inference: fuzzify → apply rules

Mamdani inference begins by fuzzifying crisp inputs into degrees, then applying each rule's antecedent connective. For a room at 27°C with humidity 70%, the controller computes degrees for words like `warm`, `hot`, and `humid`, then turns rules into clipped output sets.

```python
temp_value_w = 27.0
humidity_value_w = 70.0
humid_grid_w = np.linspace(0, 100, 201)
dry_w = trapezoid_w(humid_grid_w, 0, 0, 30, 50)
humid_set_w = trapezoid_w(humid_grid_w, 50, 70, 100, 100)
mu_warm_w = float(triangle_w(temp_value_w, 18, 25, 32))
mu_hot_w = float(trapezoid_w(temp_value_w, 28, 34, 40, 40))
mu_humid_w = float(trapezoid_w(humidity_value_w, 50, 70, 100, 100))
print("warm:", round(mu_warm_w, 3), "hot:", round(mu_hot_w, 3), "humid:", round(mu_humid_w, 3))
assert round(mu_warm_w, 3) == 0.714 and round(mu_humid_w, 3) == 1.0
```
▶ What you'll see: 27°C is substantially warm but not yet hot, while 70% humidity is fully humid under this set.

```python
slow_w = triangle_w(fan_w, 0, 2, 4)
medium_w = triangle_w(fan_w, 3, 5, 7)
fast_w = triangle_w(fan_w, 6, 8, 10)
strength_medium_w = mu_warm_w
strength_fast_w = max(mu_hot_w, min(mu_warm_w, mu_humid_w))
medium_clip_w = np.minimum(strength_medium_w, medium_w)
fast_clip_w = np.minimum(strength_fast_w, fast_w)
print("medium rule:", round(strength_medium_w, 3), "fast rule:", round(strength_fast_w, 3))
assert round(strength_fast_w, 3) == 0.714
```
▶ What you'll see: the warm→medium rule and the warm AND humid→fast rule both fire at about 0.714.

*Why it's done this way:* fuzzification translates measured numbers into the vocabulary of the expert rules. The rule strength is then ordinary fuzzy logic: `warm AND humid` uses `min`, while `hot OR (warm AND humid)` uses `max`. This keeps the whole controller interpretable because every output action can be traced back to a linguistic premise.

### 5. Aggregate overlapping recommendations

Several rules can recommend different output sets at the same time. Mamdani aggregation combines all clipped consequents with `max`, meaning the final support for each possible action is the strongest rule that recommends it.

```python
low_rule_w = min(1 - mu_warm_w, 1 - mu_humid_w)
slow_clip_w = np.minimum(low_rule_w, slow_w)
aggregated_w = np.maximum.reduce([slow_clip_w, medium_clip_w, fast_clip_w])
print("slow rule:", round(low_rule_w, 3))
print("aggregated max:", round(float(aggregated_w.max()), 3))
assert round(float(aggregated_w.max()), 3) == 0.714
```
▶ What you'll see: the slow rule is inactive here, while medium and fast create the aggregated output shape.

```python
plt.figure(figsize=(5, 3))
plt.fill_between(fan_w, medium_clip_w, alpha=0.25, label="medium rule")
plt.fill_between(fan_w, fast_clip_w, alpha=0.25, label="fast rule")
plt.plot(fan_w, aggregated_w, color="black", linewidth=2, label="aggregated")
plt.xlabel("fan speed"); plt.ylabel("membership")
plt.title("5: aggregate clipped consequents"); plt.legend(); plt.show()
```
▶ What you'll see: an output fuzzy set with support over medium and fast speeds; look for the black envelope over the colored rule shapes.

*Why it's done this way:* each output value is a candidate action. If any rule strongly supports that action, the aggregated set should preserve that support, so `max` acts like a union of recommendations. Summing would double-count overlapping rules and could push membership above 1; `max` keeps the result a valid fuzzy set.

### 6. Centroid defuzzification

The controller eventually needs one crisp action. Centroid defuzzification returns the balance point of the aggregated fuzzy set:

$$x^*=\frac{\int x\mu(x)dx}{\int \mu(x)dx}.$$

On a grid, the integrals become weighted sums.

```python
def centroid_w(x, mu):
    area = np.trapz(mu, x)
    return float(np.trapz(x * mu, x) / area) if area > 0 else float(np.mean(x))

sym_x_w = np.linspace(0, 12, 241)
sym_mu_w = triangle_w(sym_x_w, 3, 6, 9)
sym_centroid_w = centroid_w(sym_x_w, sym_mu_w)
print("symmetric centroid:", round(sym_centroid_w, 2))
assert round(sym_centroid_w, 2) == 6.00
```
▶ What you'll see: a symmetric triangular output centered at 6 has centroid exactly 6.00.

```python
fan_centroid_w = centroid_w(fan_w, aggregated_w)
print("controller fan speed:", round(fan_centroid_w, 3))
plt.figure(figsize=(5, 3))
plt.fill_between(fan_w, aggregated_w, alpha=0.35, color="steelblue")
plt.axvline(fan_centroid_w, color="crimson", linestyle="--", label=f"centroid={fan_centroid_w:.2f}")
plt.xlabel("fan speed"); plt.ylabel("membership")
plt.title("6: centroid defuzzification"); plt.legend(); plt.show()
```
▶ What you'll see: the red dashed line sits near the balance point of the aggregated output area.

*Why it's done this way:* the centroid treats membership as graded support spread across possible actions. Multiplying by `x` computes the first moment (how much support pulls toward each location), and dividing by total area normalizes that pull into one action on the same scale as the output variable.

### 7. A full fuzzy controller and its response surface

Now we wrap the pieces into a reusable controller. Inputs are temperature and humidity; outputs are fan speeds from 0 to 10. The same fuzzify→apply→aggregate→defuzzify steps run for every point on a grid, producing a smooth response surface.

```python
def fan_controller_w(temp, humidity):
    mu_cold = float(trapezoid_w(temp, 10, 10, 16, 22))
    mu_warm = float(triangle_w(temp, 18, 25, 32))
    mu_hot = float(trapezoid_w(temp, 28, 34, 40, 40))
    mu_dry = float(trapezoid_w(humidity, 0, 0, 30, 50))
    mu_humid = float(trapezoid_w(humidity, 50, 70, 100, 100))
    slow = triangle_w(fan_w, 0, 2, 4)
    medium = triangle_w(fan_w, 3, 5, 7)
    fast = triangle_w(fan_w, 6, 8, 10)
    r_slow = min(mu_cold, mu_dry)
    r_medium = max(mu_warm, min(mu_cold, mu_humid))
    r_fast = max(mu_hot, min(mu_warm, mu_humid))
    agg = np.maximum.reduce([np.minimum(r_slow, slow), np.minimum(r_medium, medium), np.minimum(r_fast, fast)])
    return centroid_w(fan_w, agg)

print("fan(20,30):", round(fan_controller_w(20, 30), 3))
print("fan(30,80):", round(fan_controller_w(30, 80), 3))
assert fan_controller_w(30, 80) > fan_controller_w(20, 30)
```
▶ What you'll see: hotter, more humid conditions produce a larger fan-speed command.

```python
t_grid_w = np.linspace(12, 38, 35)
h_grid_w = np.linspace(10, 95, 35)
surface_w = np.array([[fan_controller_w(t, h) for t in t_grid_w] for h in h_grid_w])
print("surface min/max:", round(float(surface_w.min()), 3), round(float(surface_w.max()), 3))
plt.figure(figsize=(5.4, 3.6))
plt.imshow(surface_w, origin="lower", aspect="auto", extent=[t_grid_w.min(), t_grid_w.max(), h_grid_w.min(), h_grid_w.max()], cmap="viridis")
plt.colorbar(label="fan speed")
plt.xlabel("temperature (°C)"); plt.ylabel("humidity (%)")
plt.title("7: fuzzy controller response surface"); plt.show()
```
▶ What you'll see: a smooth aggregated output surface; look for fan speed increasing toward the hot-and-humid corner rather than jumping at one threshold.

*Why it's done this way:* the controller is nonlinear but interpretable. Smoothness comes from overlapping membership functions and centroid averaging, while rule logic preserves expert structure: low evidence fires weakly, multiple partial recommendations blend, and the final action remains a single usable number.

### ✍️ Toy 1 · Membership functions turn numbers into degrees

A triangular membership function rises toward its prototype and falls away from it, then clips the
result into `[0, 1]`.

```python
import numpy as np
import matplotlib.pyplot as plt

t1_rng = np.random.default_rng(0)
t1_x = np.array([16.0, 20.0, 24.0, 28.0])
t1_a = 16.0
t1_b = 24.0
t1_c = 32.0
print("x values:", t1_x.tolist())  # -> [16.0, 20.0, 24.0, 28.0]
t1_left = (t1_x - t1_a) / (t1_b - t1_a)
print("left ramp:", t1_left.tolist())  # -> [0.0, 0.5, 1.0, 1.5]
t1_right = (t1_c - t1_x) / (t1_c - t1_b)
print("right ramp:", t1_right.tolist())  # -> [2.0, 1.5, 1.0, 0.5]
t1_raw = np.minimum(t1_left, t1_right)
print("raw min:", t1_raw.tolist())  # -> [0.0, 0.5, 1.0, 0.5]
t1_mu = np.clip(t1_raw, 0.0, 1.0)
print("membership:", t1_mu.tolist())  # -> [0.0, 0.5, 1.0, 0.5]
assert t1_mu.tolist() == [0.0, 0.5, 1.0, 0.5]

plt.figure(figsize=(4.6, 2.8))
plt.plot(t1_x, t1_mu, marker="o", color="seagreen")
plt.xlabel("temperature")
plt.ylabel("warm degree")
plt.title("Toy 1 · triangular membership")
plt.show()
```
▶ What you'll see: the degree peaks at `24` and is `0.5` at the two nearby points.

### ✍️ Toy 2 · Fuzzy AND, OR, and NOT are graded connectives

Mamdani logic commonly uses `min` for AND, `max` for OR, and `1 - x` for NOT.

```python
import numpy as np

t2_rng = np.random.default_rng(0)
t2_a = 0.25
t2_b = 0.8
print("truth a:", t2_a)  # -> 0.25
print("truth b:", t2_b)  # -> 0.8
t2_and = min(t2_a, t2_b)
print("AND min:", t2_and)  # -> 0.25
t2_or = max(t2_a, t2_b)
print("OR max:", t2_or)  # -> 0.8
t2_not_a = 1.0 - t2_a
print("NOT a:", t2_not_a)  # -> 0.75
t2_values = np.array([t2_and, t2_or, t2_not_a])

plt.ylabel("truth degree")
plt.title("Toy 2 · fuzzy connectives")
plt.show()
```
▶ What you'll see: AND keeps the weaker truth value, OR keeps the stronger one, and NOT flips `a`.

### ✍️ Toy 3 · A partial rule clips its consequent

When a rule fires at strength `0.5`, no output action can be recommended more strongly than `0.5`.

```python
import numpy as np

t3_rng = np.random.default_rng(0)
t3_fan = np.array([0.0, 2.0, 4.0, 6.0])
print("fan grid:", t3_fan.tolist())  # -> [0.0, 2.0, 4.0, 6.0]

def t3_triangle(t3_x, t3_a, t3_b, t3_c):
    t3_x = np.asarray(t3_x, dtype=float)
    t3_left = (t3_x - t3_a) / (t3_b - t3_a)
    t3_right = (t3_c - t3_x) / (t3_c - t3_b)
    return np.clip(np.minimum(t3_left, t3_right), 0.0, 1.0)

t3_fast = t3_triangle(t3_fan, 0.0, 3.0, 6.0)

t3_clipped = np.minimum(t3_strength, t3_fast)
print("clipped consequent:", np.round(t3_clipped, 3).tolist())  # -> [0.0, 0.5, 0.5, 0.0]
print("max clipped:", float(t3_clipped.max()))  # -> 0.5
assert float(t3_clipped.max()) == 0.5

plt.figure(figsize=(4.6, 2.8))
plt.plot(t3_fan, t3_fast, marker="o", label="fast")
plt.fill_between(t3_fan, t3_clipped, alpha=0.35, label="clipped")
plt.axhline(t3_strength, linestyle="--", color="black")
plt.xlabel("fan speed")
plt.ylabel("membership")
plt.title("Toy 3 · rule strength caps output")

plt.show()
```
▶ What you'll see: the triangular consequent is flattened wherever it would exceed `0.5`.

### ✍️ Toy 4 · Mamdani inference fuzzifies inputs into rule strengths

### ✍️ Toy 6 · Centroid defuzzification balances the area

The centroid is the output coordinate where the membership mass balances: moment divided by area.

```python
import numpy as np

t6_rng = np.random.default_rng(0)
t6_x = np.array([0.0, 2.0, 4.0, 6.0])
t6_mu = np.array([0.0, 1.0, 1.0, 0.0])
print("x grid:", t6_x.tolist())  # -> [0.0, 2.0, 4.0, 6.0]
print("membership:", t6_mu.tolist())  # -> [0.0, 1.0, 1.0, 0.0]
t6_area = float(np.trapz(t6_mu, t6_x))
print("area:", round(t6_area, 3))  # -> 4.0
t6_moment = float(np.trapz(t6_x * t6_mu, t6_x))
print("moment:", round(t6_moment, 3))  # -> 12.0
t6_centroid = t6_moment / t6_area
print("centroid:", round(t6_centroid, 3))  # -> 3.0
assert round(t6_centroid, 3) == 3.0

plt.figure(figsize=(4.6, 2.8))
plt.fill_between(t6_x, t6_mu, alpha=0.35, color="steelblue")
plt.axvline(t6_centroid, linestyle="--", color="crimson", label="centroid")
plt.xlabel("output")
```

### ✍️ Toy 7 · A controller repeats fuzzify → rules → aggregate → defuzzify

A full fuzzy controller is just the same small pipeline wrapped in a function and evaluated over
several inputs.

```python
import numpy as np

t7_rng = np.random.default_rng(0)

def t7_triangle(t7_x, t7_a, t7_b, t7_c):
    t7_x = np.asarray(t7_x, dtype=float)
    t7_left = (t7_x - t7_a) / (t7_b - t7_a)
    t7_right = (t7_c - t7_x) / (t7_c - t7_b)
    return np.clip(np.minimum(t7_left, t7_right), 0.0, 1.0)

def t7_centroid(t7_x, t7_mu):
    t7_area = float(np.sum(t7_mu))
    if t7_area == 0.0:
        return float(np.mean(t7_x))
    return float(np.sum(t7_x * t7_mu) / t7_area)

t7_fan = np.array([0.0, 2.0, 4.0, 6.0])
t7_slow = t7_triangle(t7_fan, -2.0, 0.0, 2.0)
t7_medium = t7_triangle(t7_fan, 1.0, 3.0, 5.0)
t7_fast = t7_triangle(t7_fan, 4.0, 6.0, 8.0)
print("slow set:", np.round(t7_slow, 3).tolist())  # -> [1.0, 0.0, 0.0, 0.0]
print("medium set:", np.round(t7_medium, 3).tolist())  # -> [0.0, 0.5, 0.5, 0.0]
print("fast set:", np.round(t7_fast, 3).tolist())  # -> [0.0, 0.0, 0.0, 1.0]

def t7_controller(t7_temp, t7_hum):
    t7_cool = float(t7_triangle(t7_temp, 10.0, 15.0, 20.0))
    t7_warm = float(t7_triangle(t7_temp, 15.0, 20.0, 25.0))
    t7_hot = float(t7_triangle(t7_temp, 20.0, 25.0, 30.0))
    t7_dry = float(t7_triangle(t7_hum, 20.0, 40.0, 60.0))
    t7_humid = float(t7_triangle(t7_hum, 50.0, 70.0, 90.0))
    t7_r_slow = min(t7_cool, t7_dry)
    t7_r_medium = t7_warm
    t7_r_fast = max(t7_hot, min(t7_warm, t7_humid))
    t7_agg = np.maximum.reduce([np.minimum(t7_r_slow, t7_slow), np.minimum(t7_r_medium, t7_medium), np.minimum(t7_r_fast, t7_fast)])
    return t7_centroid(t7_fan, t7_agg)

t7_low = t7_controller(18.0, 40.0)
print("controller(18,40):", round(t7_low, 3))  # -> 2.143
t7_high = t7_controller(26.0, 80.0)
print("controller(26,80):", round(t7_high, 3))  # -> 6.0
t7_temps = np.array([18.0, 22.0, 26.0])
t7_hums = np.array([40.0, 60.0, 80.0])
t7_surface = np.array([[t7_controller(t7_temp, t7_hum) for t7_temp in t7_temps] for t7_hum in t7_hums])
print("surface:", np.round(t7_surface, 3).tolist())  # -> [[2.143, 3.857, 6.0], [4.0, 4.0, 6.0], [4.0, 4.0, 6.0]]
assert t7_high > t7_low

plt.figure(figsize=(4.6, 3))
plt.imshow(t7_surface, origin="lower", cmap="viridis", extent=[18, 26, 40, 80], aspect="auto")
plt.colorbar(label="fan speed")
plt.xlabel("temperature")
plt.ylabel("humidity")
plt.title("Toy 7 · tiny fuzzy control surface")
plt.show()
```
▶ What you'll see: fan speed rises from about `2.143` to `6.0` as inputs become hotter and humid.

### Advanced 1 — Build a reusable fan controller

**Goal.** Package the full fuzzy pipeline into one function, because deployed controllers repeatedly run the same inference steps. We build it in 4 steps.

```python
def tri_a1(x, a, b, c):
    x = np.asarray(x, dtype=float)
    return np.clip(np.minimum((x - a) / (b - a), (c - x) / (c - b)), 0, 1)

def centroid_a1(x, mu):
    area = np.trapz(mu, x)
    return float(np.trapz(x * mu, x) / area) if area > 0 else float(np.mean(x))

speed_a1 = np.linspace(0, 10, 201)
print("controller output grid:", speed_a1.shape)
```
▶ What you'll see: the controller will choose among 201 possible fan-speed samples.

```python
def fan_a1(temp, humidity):
    cold = float(tri_a1(temp, 10, 15, 22))
    warm = float(tri_a1(temp, 18, 25, 32))
    hot = float(tri_a1(temp, 28, 35, 40))
    dry = float(tri_a1(humidity, 0, 25, 50))
    humid = float(tri_a1(humidity, 45, 70, 100))
    slow = tri_a1(speed_a1, 0, 2, 4)
    medium = tri_a1(speed_a1, 3, 5, 7)
    fast = tri_a1(speed_a1, 6, 8, 10)
    agg = np.maximum.reduce([np.minimum(min(cold, dry), slow), np.minimum(max(warm, min(cold, humid)), medium), np.minimum(max(hot, min(warm, humid)), fast)])
    return centroid_a1(speed_a1, agg)

print("function ready")
```
