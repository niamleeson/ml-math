# 21.6 — Rule-Based Expert Systems

Rule-based expert systems make symbolic reasoning inspectable: facts live in working memory, production rules add new facts, and the fired rule trace explains why a conclusion appeared. In this lesson, we build a tiny expert-system engine from scratch, then add the practical pieces that make rules useful: forward chaining, backward chaining, conflict resolution, RETE-style matching, and certainty factors.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build rule-based expert systems one idea at a time. Run each cell in order and read the printed intermediate values — every piece of logic is visible, so the system never feels like a black box. This walkthrough is self-contained (it imports what it needs) and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
from dataclasses import dataclass  # lightweight rule records.
from collections import defaultdict, deque  # indexing rules and drawing simple trees.

import matplotlib.pyplot as plt  # visualizations for traces, agendas, and trees.
```

### 1. Facts, production rules, and working memory

A rule-based expert system separates **knowledge** from **control**. The knowledge is a rule base: if all antecedent facts are present, add a consequent fact. The control state is working memory: the facts currently believed. This separation is why the same rule base can be rerun, traced, audited, or prioritized without rewriting nested `if` statements.

```python
@dataclass(frozen=True)
class RuleW:
    name: str
    antecedents: tuple
    consequent: str
    priority: int = 0
    cf: float = 1.0

rules_w = [
    RuleW("r_flu", ("fever", "cough"), "possible_flu", priority=2, cf=0.9),
    RuleW("r_rest", ("possible_flu",), "recommend_rest", priority=1, cf=0.8),
    RuleW("r_hydrate", ("recommend_rest",), "recommend_hydration", priority=1, cf=0.7),
]
working_memory_w = {"fever", "cough"}
print("initial facts:", sorted(working_memory_w))
print("rule names:", [r.name for r in rules_w])
```
▶ What you'll see: two starting symptoms and three separate production rules that can reason from them.

```python
def applicable_w(rule_w, facts_w):
    return set(rule_w.antecedents).issubset(facts_w) and rule_w.consequent not in facts_w

agenda_w = [r.name for r in rules_w if applicable_w(r, working_memory_w)]
print("currently fireable rules:", agenda_w)
assert agenda_w == ["r_flu"]
```
▶ What you'll see: only `r_flu` can fire at the beginning because its two required symptoms are already known.

```python
plt.figure(figsize=(5, 2.6))
plt.bar(["facts", "rules", "fireable"], [len(working_memory_w), len(rules_w), len(agenda_w)], color=["steelblue", "gray", "seagreen"])
plt.title("1: working memory vs rule base")
plt.ylabel("count")
plt.show()
```
▶ What you'll see: working memory is small and changing, while the rule base is the reusable knowledge store.

*Why it's done this way:* production rules keep expert knowledge declarative: each rule says what relationship holds, not when the program should visit it. Working memory keeps the current case separate from the rule book, so explanations can say exactly which facts triggered which rules.

### 2. Forward chaining to a fixed point

**Forward chaining** is data-driven reasoning. Start with observed facts, repeatedly fire every rule whose prerequisites are satisfied, and stop when no rule can add anything new. Mathematically, each firing grows the fact set; because the set only grows and the rule base is finite, the process reaches a fixed point.

```python
def forward_chain_w(facts_w, rules_w):
    facts_w = set(facts_w)
    trace_w = []
    changed_w = True
    while changed_w:
        changed_w = False
        for rule_w in rules_w:
            if applicable_w(rule_w, facts_w):
                facts_w.add(rule_w.consequent)
                trace_w.append((rule_w.name, rule_w.antecedents, rule_w.consequent))
                changed_w = True
                print(f"fired {rule_w.name}: {rule_w.antecedents} -> {rule_w.consequent}")
    return facts_w, trace_w

final_facts_w, trace_w = forward_chain_w({"fever", "cough"}, rules_w)
print("final facts:", sorted(final_facts_w))
assert "recommend_hydration" in final_facts_w
```
▶ What you'll see: flu is inferred first, then rest, then hydration; the trace is the explanation chain.

```python
fact_counts_w = [2]
seen_w = {"fever", "cough"}
for _, _, c_w in trace_w:
    seen_w.add(c_w)
    fact_counts_w.append(len(seen_w))
print("fact count growth:", fact_counts_w)
assert fact_counts_w == [2, 3, 4, 5]
```
▶ What you'll see: the fact count grows `2 → 3 → 4 → 5` and then stops.

```python
plt.figure(figsize=(5, 3))
plt.step(range(len(fact_counts_w)), fact_counts_w, where="post", marker="o", color="purple")
plt.xticks(range(len(fact_counts_w)))
plt.xlabel("firing step")
plt.ylabel("facts in working memory")
plt.title("2: forward chaining reaches a fixed point")
plt.show()
```
▶ What you'll see: a staircase that flattens once no rule can add a new fact.

*Why it's done this way:* forward chaining is useful when data arrives first and the system should discover every consequence. The fixed-point loop is deliberately simple: fire rules, add only new facts, and halt when another pass changes nothing.

### 3. Backward chaining as goal-directed proof

**Backward chaining** reverses the question. Instead of asking “what follows from these facts?”, it asks “what would prove this goal?” If the goal is already a fact, it succeeds. Otherwise, the engine finds rules whose consequent is the goal and recursively proves their antecedents.

```python
def backward_chain_w(goal_w, facts_w, rules_w, depth_w=0):
    indent_w = "  " * depth_w
    if goal_w in facts_w:
        print(indent_w + f"✓ {goal_w} is known")
        return True, [("fact", goal_w)]
    for rule_w in [r for r in rules_w if r.consequent == goal_w]:
        print(indent_w + f"try {rule_w.name} to prove {goal_w}")
        subproofs_w = []
        ok_w = True
        for ant_w in rule_w.antecedents:
            proved_w, proof_w = backward_chain_w(ant_w, facts_w, rules_w, depth_w + 1)
            ok_w = ok_w and proved_w
            subproofs_w.extend(proof_w)
        if ok_w:
            return True, subproofs_w + [(rule_w.name, goal_w)]
    print(indent_w + f"✗ cannot prove {goal_w}")
    return False, []

proved_w, proof_w = backward_chain_w("recommend_hydration", {"fever", "cough"}, rules_w)
print("proved?", proved_w)
assert proved_w is True
```
▶ What you'll see: the engine works backward from hydration to rest to flu to the observed symptoms.

```python
print("proof objects:")
for item_w in proof_w:
    print(item_w)
assert proof_w[-1] == ("r_hydrate", "recommend_hydration")
```
▶ What you'll see: the proof is a compact derivation list ending with the target recommendation.

```python
levels_w = {"recommend_hydration": 0, "recommend_rest": 1, "possible_flu": 2, "fever": 3, "cough": 3}
xs_w = {"recommend_hydration": 0, "recommend_rest": 0, "possible_flu": 0, "fever": -0.7, "cough": 0.7}
edges_w = [("recommend_hydration", "recommend_rest"), ("recommend_rest", "possible_flu"), ("possible_flu", "fever"), ("possible_flu", "cough")]
plt.figure(figsize=(5, 4))
for a_w, b_w in edges_w:
    plt.plot([xs_w[a_w], xs_w[b_w]], [-levels_w[a_w], -levels_w[b_w]], color="gray")
for node_w in levels_w:
    plt.scatter(xs_w[node_w], -levels_w[node_w], s=700, color="lightyellow", edgecolor="black")
    plt.text(xs_w[node_w], -levels_w[node_w], node_w, ha="center", va="center", fontsize=8)
plt.axis("off")
plt.title("3: backward-chaining derivation tree")
plt.show()
```
▶ What you'll see: the goal at the top expands downward into subgoals until it reaches known facts; look for the two symptom leaves.

*Why it's done this way:* backward chaining avoids deriving irrelevant facts. It is the right control strategy when the user asks for one conclusion and the system should prove only what that conclusion requires.

### 4. Conflict resolution when several rules can fire

A real rule base often has many fireable rules at once. The **conflict set** or agenda contains those candidates, and a conflict-resolution strategy chooses one: highest priority, most specific rule, newest fact, or a stable rule order. This is control policy, not domain knowledge, so we keep it outside the rules themselves.

```python
conflict_rules_w = [
    RuleW("r_treat_fever", ("fever",), "give_antipyretic", priority=1),
    RuleW("r_call_doctor", ("fever", "rash"), "call_doctor", priority=3),
    RuleW("r_monitor", ("fever",), "monitor_temperature", priority=2),
]
facts_conflict_w = {"fever", "rash"}
agenda_conflict_w = [r for r in conflict_rules_w if applicable_w(r, facts_conflict_w)]
print("agenda:", [(r.name, r.priority, len(r.antecedents)) for r in agenda_conflict_w])
assert len(agenda_conflict_w) == 3
```
▶ What you'll see: three rules are all legal to fire from the same working memory.

```python
def choose_rule_w(agenda_w, strategy_w):
    if strategy_w == "priority":
        return max(agenda_w, key=lambda r: r.priority)
    if strategy_w == "specificity":
        return max(agenda_w, key=lambda r: len(r.antecedents))
    return agenda_w[0]

for strategy_w in ["order", "priority", "specificity"]:
    chosen_w = choose_rule_w(agenda_conflict_w, strategy_w)
    print(strategy_w, "chooses", chosen_w.name)
assert choose_rule_w(agenda_conflict_w, "priority").name == "r_call_doctor"
```
▶ What you'll see: different legal strategies can choose different first explanations, even with the same facts.

```python
labels_w = [r.name for r in agenda_conflict_w]
priorities_w = [r.priority for r in agenda_conflict_w]
specificity_w = [len(r.antecedents) for r in agenda_conflict_w]
x_w = np.arange(len(labels_w))
plt.figure(figsize=(6, 3))
plt.bar(x_w - 0.18, priorities_w, width=0.36, label="priority", color="seagreen")
plt.bar(x_w + 0.18, specificity_w, width=0.36, label="specificity", color="orange")
plt.xticks(x_w, labels_w, rotation=15)
plt.title("4: conflict-resolution scores")
plt.legend()
plt.show()
```
▶ What you'll see: `r_call_doctor` wins both priority and specificity in this tiny triage example.

*Why it's done this way:* firing order changes explanations and sometimes final actions, so the policy must be explicit. Keeping strategy separate lets a safety-critical system prefer high-priority rules while another system prefers the most specific rule.

### 5. The RETE matching idea: index partial matches

Naive forward chaining checks every rule against all facts on every pass. RETE-style matching improves this by caching partial matches: index rules by the facts they need, update counts when a new fact arrives, and place a rule on the agenda only when all prerequisites have been seen. We build the core idea, not the full industrial algorithm.

```python
rete_rules_w = [
    RuleW("r1", ("fever", "cough"), "possible_flu"),
    RuleW("r2", ("fever", "rash"), "possible_measles"),
    RuleW("r3", ("possible_flu", "aches"), "flu_likely"),
]
need_index_w = defaultdict(list)
remaining_w = {}
for rule_w in rete_rules_w:
    remaining_w[rule_w.name] = len(rule_w.antecedents)
    for ant_w in rule_w.antecedents:
        need_index_w[ant_w].append(rule_w)
print("rules waiting on fever:", [r.name for r in need_index_w["fever"]])
print("remaining counts:", remaining_w)
```
▶ What you'll see: the index jumps directly from a new fact like `fever` to only the rules that mention it.

```python
def rete_arrivals_w(fact_stream_w, index_w, remaining_template_w):
    remaining_w = dict(remaining_template_w)
    agenda_w = []
    for fact_w in fact_stream_w:
        print("new fact:", fact_w)
        for rule_w in index_w.get(fact_w, []):
            remaining_w[rule_w.name] -= 1
            print(" ", rule_w.name, "remaining antecedents:", remaining_w[rule_w.name])
            if remaining_w[rule_w.name] == 0:
                agenda_w.append(rule_w.name)
    return agenda_w

agenda_rete_w = rete_arrivals_w(["fever", "cough", "aches"], need_index_w, remaining_w)
print("ready rules:", agenda_rete_w)
assert agenda_rete_w == ["r1"]
```
▶ What you'll see: `r1` becomes ready as soon as its last missing antecedent arrives, while unrelated rules are not rescanned.

```python
naive_checks_w = len(rete_rules_w) * 3
indexed_touches_w = sum(len(need_index_w[f]) for f in ["fever", "cough", "aches"])
print("naive checks:", naive_checks_w, "indexed touches:", indexed_touches_w)
plt.figure(figsize=(4.5, 3))
plt.bar(["naive passes", "indexed touches"], [naive_checks_w, indexed_touches_w], color=["crimson", "seagreen"])
plt.title("5: RETE idea saves repeated matching")
plt.ylabel("rule inspections")
plt.show()
```
▶ What you'll see: the indexed version touches fewer rule antecedents because new facts route directly to affected rules.

*Why it's done this way:* matching, not rule execution, is often the bottleneck. RETE makes repeated reasoning fast by remembering partial progress instead of rediscovering the same partial matches every cycle.

### 6. Certainty factors for uncertain expert judgment

Expert rules are often plausible rather than guaranteed. A **certainty factor** attaches confidence to facts and rules. One simple scheme says the conclusion confidence is `min(antecedent confidences) × rule strength`, because a chain should be no more confident than its weakest required input.

```python
cf_facts_w = {"fever": 0.8, "cough": 0.7}
cf_rule_w = RuleW("r_flu_cf", ("fever", "cough"), "possible_flu", cf=0.9)
ant_cf_w = min(cf_facts_w[a] for a in cf_rule_w.antecedents)
conclusion_cf_w = ant_cf_w * cf_rule_w.cf
print("weakest antecedent:", ant_cf_w)
print("conclusion CF:", round(conclusion_cf_w, 3))
assert round(conclusion_cf_w, 3) == 0.63
```
▶ What you'll see: `min(0.8, 0.7) × 0.9 = 0.63`, so the conclusion is useful but not certain.

```python
def combine_cf_w(old_w, new_w):
    return old_w + new_w * (1 - old_w)

first_path_w = 0.63
second_path_w = 0.40
combined_w = combine_cf_w(first_path_w, second_path_w)
print("combined independent support:", round(combined_w, 3))
assert round(combined_w, 3) == 0.778
```
▶ What you'll see: a second independent rule raises confidence, but the value stays below 1.

```python
plt.figure(figsize=(5, 3))
plt.bar(["fever", "cough", "rule", "conclusion", "+2nd path"], [0.8, 0.7, 0.9, conclusion_cf_w, combined_w], color=["gray", "gray", "orange", "seagreen", "purple"])
plt.ylim(0, 1)
plt.ylabel("certainty factor")
plt.title("6: certainty flows through rules")
plt.show()
```
▶ What you'll see: the conclusion is lower than the rule strength because weak evidence limits the chain.

*Why it's done this way:* certainty factors make expert systems honest about uncertainty while keeping explanations symbolic. The `min × rule` heuristic encodes a conservative logic: every required premise must be credible before the conclusion can be credible.

### ✍️ Toy 2 · Forward chaining grows to a fixed point

Forward chaining repeatedly fires any ready rule until a full pass adds nothing new.

```python
import numpy as np                              # arrays and tiny numeric checks.

t2_rng = np.random.default_rng(0)               # reproducible toy seed.
print("rng seed:", 0)                           # -> 0
t2_rules = [
    {"name": "r_slip", "if": ("wet",), "then": "slippery"},
    {"name": "r_care", "if": ("slippery", "dark"), "then": "slow_down"},
]
print("rules:", t2_rules)                       # -> [{'name': 'r_slip', 'if': ('wet',), 'then': 'slippery'}, {'name': 'r_care', 'if': ('slippery', 'dark'), 'then': 'slow_down'}]
t2_facts = {"wet", "dark"}
print("initial facts:", sorted(t2_facts))       # -> ['dark', 'wet']
t2_trace = []
t2_counts = [len(t2_facts)]
t2_changed = True
while t2_changed:
    t2_changed = False
    for t2_rule in t2_rules:

print("trace:", t2_trace)                       # -> [('r_slip', 'slippery'), ('r_care', 'slow_down')]
print("final facts:", sorted(t2_facts))         # -> ['dark', 'slippery', 'slow_down', 'wet']
print("fact counts:", t2_counts)                # -> [2, 3, 4]
t2_counts_array = np.array(t2_counts)           # -> [2 3 4]
print("counts array:", t2_counts_array.tolist()) # -> [2, 3, 4]
assert "slow_down" in t2_facts

plt.figure(figsize=(4.8, 2.8))
plt.step(range(len(t2_counts_array)), t2_counts_array, where="post", marker="o", color="purple")
plt.xticks(range(len(t2_counts_array)))

plt.ylabel("facts")
plt.title("Toy 2 · fixed-point growth")

```
▶ What you'll see: the fact count rises from two to four, then no new rule can fire.

### ✍️ Toy 3 · Backward chaining proves only the requested goal

Backward chaining starts at a goal and recursively asks which smaller goals would prove it.

```python
import numpy as np                              # arrays and tiny numeric checks.

t3_rng = np.random.default_rng(0)               # reproducible toy seed.
print("rng seed:", 0)                           # -> 0
t3_facts = {"phone", "smoke"}
print("known facts:", sorted(t3_facts))         # -> ['phone', 'smoke']
t3_rules = [
    {"name": "r_neighbor", "if": ("smoke",), "then": "ask_neighbor"},
    {"name": "r_help", "if": ("ask_neighbor", "phone"), "then": "call_help"},
]
print("rules:", t3_rules)                       # -> [{'name': 'r_neighbor', 'if': ('smoke',), 'then': 'ask_neighbor'}, {'name': 'r_help', 'if': ('ask_neighbor', 'phone'), 'then': 'call_help'}]

def t3_prove(t3_goal, t3_facts, t3_rules):
    if t3_goal in t3_facts:
        return True, [("fact", t3_goal)]
    for t3_rule in t3_rules:
        if t3_rule["then"] == t3_goal:
            t3_proof = []
            t3_ok = True
            for t3_need in t3_rule["if"]:
                t3_sub_ok, t3_sub_proof = t3_prove(t3_need, t3_facts, t3_rules)
                t3_ok = t3_ok and t3_sub_ok
                t3_proof.extend(t3_sub_proof)
            if t3_ok:
                return True, t3_proof + [(t3_rule["name"], t3_goal)]
    return False, []

t3_ok, t3_proof = t3_prove("call_help", t3_facts, t3_rules)
print("proved?:", t3_ok)                         # -> True
print("proof:", t3_proof)                       # -> [('fact', 'smoke'), ('r_neighbor', 'ask_neighbor'), ('fact', 'phone'), ('r_help', 'call_help')]
t3_rule_flags = np.array([1 if t3_step[0].startswith("r_") else 0 for t3_step in t3_proof])  # -> [0 1 0 1]
print("rule-step flags:", t3_rule_flags.tolist()) # -> [0, 1, 0, 1]
assert t3_proof[-1] == ("r_help", "call_help")

plt.figure(figsize=(5.2, 2.8))
plt.bar(range(len(t3_proof)), t3_rule_flags, color=["seagreen" if t3_flag else "lightgray" for t3_flag in t3_rule_flags])
plt.xticks(range(len(t3_proof)), [t3_step[1] for t3_step in t3_proof], rotation=20)
plt.ylabel("rule step?")
plt.title("Toy 3 · proof path to one goal")
plt.show()
```
▶ What you'll see: the proof touches only facts and rules needed for `call_help`.

### ✍️ Toy 5 · RETE-style indexing updates only affected rules

Index each antecedent to the rules waiting on it, then decrement only those rules when a new fact arrives.

```python
import numpy as np                              # arrays and tiny numeric checks.

t5_rng = np.random.default_rng(0)               # reproducible toy seed.
```

## 🛠️ Setup

```python
import numpy as np  # arrays, scoring, masks, and small numerical checks.
import matplotlib.pyplot as plt  # heatmaps, bars, curves, and derivation-tree visuals.
from dataclasses import dataclass  # compact immutable rule records.
from collections import defaultdict, deque  # indices, agendas, and breadth-first tree layout helpers.
np.random.seed(0)  # make every example reproducible.

@dataclass(frozen=True)
class Rule:
    name: str
    antecedents: tuple
    consequent: str
    priority: int = 0
    cf: float = 1.0

def is_applicable(rule, facts):
    return set(rule.antecedents).issubset(facts) and rule.consequent not in facts

def forward_chain(facts, rules, strategy="order"):
    facts = set(facts)
    trace = []
    while True:
        agenda = [r for r in rules if is_applicable(r, facts)]
        if not agenda:
            break
        if strategy == "priority":
            rule = max(agenda, key=lambda r: (r.priority, len(r.antecedents)))
        elif strategy == "specificity":
            rule = max(agenda, key=lambda r: (len(r.antecedents), r.priority))
        else:
            rule = agenda[0]
        facts.add(rule.consequent)
        trace.append(rule)
    return facts, trace

def backward_chain(goal, facts, rules):
    if goal in facts:
        return True, [("fact", goal)]
    for rule in [r for r in rules if r.consequent == goal]:
        proof = []
        ok = True
        for ant in rule.antecedents:
            sub_ok, sub_proof = backward_chain(ant, facts, rules)
            ok = ok and sub_ok
            proof.extend(sub_proof)
        if ok:
            return True, proof + [(rule.name, goal)]
    return False, []

def combine_cf(old, new):
    return old + new * (1 - old)

def draw_simple_tree(edges, title):
    children = defaultdict(list)
    all_children = set()
    for parent, child in edges:
        children[parent].append(child)
        all_children.add(child)
    root = next(parent for parent, _ in edges if parent not in all_children)
    levels = defaultdict(list)
    queue = deque([(root, 0)])
    seen = set()
    while queue:
        node, depth = queue.popleft()
        if node in seen:
            continue
        seen.add(node)
        levels[-depth].append(node)
        for child in children[node]:
            queue.append((child, depth + 1))
    pos = {}
    for yy, ns in levels.items():
        xs = np.linspace(-1, 1, len(ns)) if len(ns) > 1 else np.array([0.0])
        for x, n in zip(xs, ns):
            pos[n] = (x, yy)
    plt.figure(figsize=(5, 3.5))
    for parent, child in edges:
        plt.plot([pos[parent][0], pos[child][0]], [pos[parent][1], pos[child][1]], color="gray")
    for n, (x, yy) in pos.items():
        plt.scatter(x, yy, s=600, color="lightyellow", edgecolor="black")
        plt.text(x, yy, n, ha="center", va="center", fontsize=8)
    plt.title(title)
    plt.axis("off")
    plt.show()
```

### Advanced 3 — Simulate RETE incremental matching

**Goal.** Track remaining antecedents as facts arrive, because RETE-like systems update partial matches incrementally. We build it in 4 steps.

```python
rules_a3 = [Rule("r_ab", ("a", "b"), "ab"), Rule("r_ac", ("a", "c"), "ac"), Rule("r_bd", ("b", "d"), "bd")]
remaining_a3 = {r.name: len(r.antecedents) for r in rules_a3}
index_a3 = defaultdict(list)
for r_a3 in rules_a3:
    for ant_a3 in r_a3.antecedents:
        index_a3[ant_a3].append(r_a3)
print("initial remaining:", remaining_a3)
```
▶ What you'll see: each two-antecedent rule starts with two missing pieces.

```python
history_a3 = []
ready_a3 = []
for fact_a3 in ["a", "b", "d"]:
    for r_a3 in index_a3[fact_a3]:
        remaining_a3[r_a3.name] -= 1
        if remaining_a3[r_a3.name] == 0:
            ready_a3.append(r_a3.name)
    history_a3.append([remaining_a3[r.name] for r in rules_a3])
print("ready:", ready_a3)
print("history:", history_a3)
```
▶ What you'll see: `r_ab` becomes ready after `b`, and `r_bd` becomes ready after `d`.

```python
assert ready_a3 == ["r_ab", "r_bd"]
history_arr_a3 = np.array(history_a3)
print("history array shape:", history_arr_a3.shape)
```
▶ What you'll see: the history matrix has one row per arriving fact and one column per rule.

```python
plt.figure(figsize=(5, 3))

    plt.plot(history_arr_a3[:, j_a3], marker="o", label=r_a3.name)
```

### Advanced 4 — Chain certainty factors through a rule graph

**Goal.** Propagate confidence through several rules, because real recommendations often rest on multi-step uncertain evidence. We build it in 4 steps.

