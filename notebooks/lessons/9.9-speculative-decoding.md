# 9.9 — Speculative Decoding

Speculative decoding speeds up autoregressive language generation by letting a cheap draft model propose several future tokens, then asking the expensive target model to verify those proposals in one parallel pass. The math is careful: accepted tokens must still follow the target distribution, so the notebook builds draft-verify sampling from tiny NumPy distributions instead of hiding the key acceptance ratio inside a library call.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build speculative decoding one idea at a time. Run each cell in order and read the printed intermediate values — every piece of math, including draft probabilities, target probabilities, and the acceptance sampler, is made visible. This walkthrough is self-contained and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays, probabilities, sampling, and simple vectorized checks.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
np.random.seed(0)  # reproducibility for stochastic accept/reject demos.
```

### 1. Autoregressive decoding is a serial bottleneck

A language model normally emits one token, appends it to the context, then emits the next. That loop is expensive because a large model must run once per accepted token. Speculative decoding targets exactly this control-loop bottleneck: it keeps the same target model distribution, but tries to verify several drafted tokens with one target call.

```python
vocab_w = np.array(["A", "B", "C", "D"])  # a tiny vocabulary for readable output.
target_cost_w = 10.0  # pretend one large-model call costs 10 time units.
serial_tokens_w = 4  # generate four tokens the standard way.
serial_cost_w = serial_tokens_w * target_cost_w  # one target call per token.
print("serial target calls:", serial_tokens_w)
print("serial cost:", serial_cost_w)
assert serial_cost_w == 40.0
```
▶ What you'll see: four generated tokens require four expensive target-model calls in the serial loop.

```python
positions_w = np.arange(1, serial_tokens_w + 1)  # token positions in the decode loop.
plt.figure(figsize=(4.4, 3))
plt.bar(positions_w, np.full(serial_tokens_w, target_cost_w), color="gray")
plt.title("1: serial decoding pays every step")
plt.xlabel("generated token position")
plt.ylabel("large-model cost")
plt.show()
```
▶ What you'll see: every token position has the same expensive bar — there is no batching across future tokens.

*Why it's done this way: autoregressive probability factors as $p(x_1,x_2,\dots)=\prod_i p(x_i\mid x_{<i})$, so the target cannot know the next context until the previous token is chosen; speculative decoding only helps if several proposed choices can be checked without changing that distribution.*

### 2. A draft model proposes from q

The draft model is a cheaper approximation $q(x_i\mid x_{<i})$. It is allowed to be imperfect because it does not get final authority; it only proposes tokens. Here the draft distribution puts too much mass on token B compared with the target, which creates a useful rejection case later.

```python
q_w = np.array([0.10, 0.60, 0.20, 0.10])  # draft probabilities for A,B,C,D.
p_w = np.array([0.20, 0.30, 0.40, 0.10])  # target probabilities for the same context.
print("draft q:", q_w)
print("target p:", p_w)
print("both sum to:", q_w.sum(), p_w.sum())
assert np.allclose(q_w.sum(), 1.0) and np.allclose(p_w.sum(), 1.0)
```
▶ What you'll see: q and p are both valid distributions, but they disagree about which token is likely.

```python
x_w = np.arange(len(vocab_w))
plt.figure(figsize=(5, 3))
plt.bar(x_w - 0.18, q_w, width=0.36, label="draft q", color="orange")
plt.bar(x_w + 0.18, p_w, width=0.36, label="target p", color="teal")
plt.xticks(x_w, vocab_w)
plt.title("2: draft and target distributions")
plt.ylabel("probability")
plt.legend()
plt.show()
```
▶ What you'll see: q over-proposes B and under-proposes C relative to the target model.

*Why it's done this way: the small model earns speed by being cheap, not by being exact; the verifier will correct mismatches so the final samples still behave as if they came from p.*

### 3. Verify a proposal with the acceptance ratio p/q

For a drafted token $x$, speculative sampling accepts it with

$$a(x)=\min\left(1,\frac{p(x\mid x_{<i})}{q(x\mid x_{<i})}\right).$$

If q over-proposed a token, $p/q<1$ and we sometimes reject it. If q under-proposed a token, $p/q>1$ and we accept it every time because the draft did not sample that token often enough.

```python
ratios_w = p_w / q_w  # target-to-draft probability ratio for each token.
accept_w = np.minimum(1.0, ratios_w)  # clip at 1 to form acceptance probabilities.
print("p/q ratios:", np.round(ratios_w, 3))
print("acceptance probs:", np.round(accept_w, 3))
assert np.allclose(np.round(accept_w, 3), [1.0, 0.5, 1.0, 1.0])
```
▶ What you'll see: token B is accepted with probability 0.5 because target probability 0.30 is half the draft probability 0.60.

```python
plt.figure(figsize=(5, 3))
plt.bar(vocab_w, accept_w, color=["seagreen", "crimson", "seagreen", "seagreen"])
plt.ylim(0, 1.05)
plt.title("3: acceptance probability min(1, p/q)")
plt.ylabel("acceptance probability")
plt.show()
```
▶ What you'll see: only the over-proposed draft token has an acceptance bar below 1.

*Why it's done this way: the ratio is importance correction in one token; q controls how often proposals appear, and multiplying by $\min(1,p/q)$ prevents over-sampled proposals from surviving too often while never punishing under-sampled ones further.*

### 4. Rejection samples from the leftover target mass

When a draft token is rejected, we cannot simply take the target model's top token greedily. The correct replacement is sampled from the residual distribution proportional to $\max(0,p-q)$: the probability mass that the draft failed to provide often enough.

```python
residual_w = np.maximum(0.0, p_w - q_w)  # target mass not already covered by draft proposals.
residual_w = residual_w / residual_w.sum()  # normalize the leftover into a distribution.
print("residual distribution:", np.round(residual_w, 3))
assert np.allclose(np.round(residual_w, 3), [0.333, 0.0, 0.667, 0.0])
```
▶ What you'll see: rejected samples are replaced only by A or C, because those are under-proposed by q.

```python
def sample_from_w(probs):
    return int(np.searchsorted(np.cumsum(probs), np.random.rand()))

np.random.seed(1)
replacement_w = sample_from_w(residual_w)
print("one residual sample:", vocab_w[replacement_w])
assert replacement_w in [0, 2]
```
▶ What you'll see: the replacement token is drawn from the leftover mass, not from a greedy argmax rule.

*Why it's done this way: after accepted draft samples account for the shared mass $\min(p,q)$, the only target probability still missing is $p-q$ where p exceeds q; sampling from that residual preserves the exact target distribution.*

### 5. Draft a block, verify left to right

A speculative step drafts a block, then verifies proposed tokens in order. Verification is sequential logically — the first rejection stops the block because later drafted tokens depended on a context that did not actually happen — but the target probabilities for the proposed block can be computed in one large-model pass.

```python
draft_tokens_w = np.array([1, 2, 1])  # B, C, B proposed by the draft model.
accept_for_block_w = accept_w[draft_tokens_w]  # acceptance probabilities of those concrete proposals.
print("draft block:", vocab_w[draft_tokens_w])
print("accept probs:", accept_for_block_w)
assert np.allclose(accept_for_block_w, [0.5, 1.0, 0.5])
```
▶ What you'll see: B is risky, C is always accepted in this context, and the final B is risky again.

```python
uniforms_w = np.array([0.20, 0.70, 0.80])  # fixed uniforms make the accept/reject path inspectable.
accepted_mask_w = uniforms_w < accept_for_block_w  # proposal accepted if uniform is below a_i.
first_reject_w = np.where(~accepted_mask_w)[0]
accepted_count_w = int(first_reject_w[0]) if len(first_reject_w) else len(draft_tokens_w)
print("uniforms:", uniforms_w)
print("accepted before first rejection:", accepted_count_w)
assert accepted_count_w == 2
```
▶ What you'll see: the first two tokens pass, then the third proposal is rejected and the block stops.

```python
kept_tokens_w = draft_tokens_w[:accepted_count_w]
replacement_after_reject_w = 2  # choose C from the residual distribution for the rejected position.
output_block_w = np.r_[kept_tokens_w, replacement_after_reject_w]
print("output tokens:", vocab_w[output_block_w])
assert list(output_block_w) == [1, 2, 2]
```
▶ What you'll see: accepted draft tokens are copied, then the rejected position is filled from the residual distribution.

*Why it's done this way: accepting past a rejection would condition later tokens on the wrong prefix; stopping at the first rejection keeps the autoregressive context consistent while still letting the expensive model check the whole proposed block at once.*

### 6. Speedup depends on accepted tokens, not proposed tokens

The speed benefit comes from how many draft tokens survive per target pass. If every token accepts, one target call can cover the whole block. If rejections happen early, the large-model call was still spent but fewer output tokens were produced.

```python
accept_probs_w = np.array([0.9, 0.8, 0.5])  # worked probabilities from the lesson page.
all_accept_w = float(np.prod(accept_probs_w))  # probability the whole block survives.
expected_naive_w = float(np.sum(accept_probs_w))  # simple diagnostic used on the page.
print("all-accepted probability:", round(all_accept_w, 3))
print("sum of acceptance probabilities:", round(expected_naive_w, 1))
assert round(all_accept_w, 3) == 0.36 and round(expected_naive_w, 1) == 2.2
```
▶ What you'll see: even high individual acceptance probabilities multiply down to a smaller all-accepted probability.

```python
block_sizes_w = np.arange(1, 7)
mean_accept_w = 0.8
ideal_speed_w = block_sizes_w
rough_speed_w = 1 + mean_accept_w * (block_sizes_w - 1)  # expected tokens per target pass under a simple survival proxy.
plt.figure(figsize=(5, 3))
plt.plot(block_sizes_w, ideal_speed_w, marker="o", label="all accepted")
plt.plot(block_sizes_w, rough_speed_w, marker="s", label="80% average acceptance")
plt.title("6: speed tracks accepted work")
plt.xlabel("draft block size")
plt.ylabel("tokens per target pass")
plt.legend()
plt.show()
```
▶ What you'll see: the realistic curve grows more slowly than the ideal line because rejected proposals waste part of the block.

*Why it's done this way: proposed tokens are only a promise; accepted tokens are the actual output, so latency analysis must count target passes divided by accepted progress, not by how many guesses the draft produced.*

## 🛠️ Setup

```python
import numpy as np  # load NumPy for tiny probability tables, sampling, and assertions.
import matplotlib.pyplot as plt  # load Matplotlib for bars, heatmaps, and speed curves.
np.random.seed(0)  # make all examples deterministic unless a cell states its own local seed.

def normalize(probs):  # convert nonnegative scores into a probability vector.
    probs = np.asarray(probs, dtype=float)  # ensure floating-point arithmetic.
    total = float(np.sum(probs))  # compute the mass that should become 1.
    return probs / total if total > 0 else np.ones_like(probs) / len(probs)  # fall back to uniform only for empty mass.

def draw_index(probs, u=None):  # sample one index from a categorical distribution.
    probs = normalize(probs)  # guard against tiny numerical drift in probabilities.
    u = np.random.rand() if u is None else float(u)  # use provided uniform for inspectable demos.
    return int(np.searchsorted(np.cumsum(probs), u, side="right"))  # inverse-CDF sampling.

def acceptance_probs(p, q):  # compute speculative acceptance probabilities min(1,p/q).
    p = normalize(p)  # target distribution.
    q = normalize(q)  # draft distribution.
    return np.minimum(1.0, p / np.maximum(q, 1e-12))  # avoid division by zero in toy code.

def residual_distribution(p, q):  # compute replacement distribution after a rejection.
    p = normalize(p)  # target distribution.
    q = normalize(q)  # draft distribution.
    return normalize(np.maximum(0.0, p - q))  # leftover target mass.

def speculative_step(p, q, draft_tokens, uniforms):  # verify one drafted block for a fixed context.
    acc = acceptance_probs(p, q)[draft_tokens]  # acceptance probability for each proposed token.
    accepted = []  # store proposals that survive before the first rejection.
    for tok, a, u in zip(draft_tokens, acc, uniforms):  # verify proposals in order.
        if u < a:  # accept when the uniform falls below min(1,p/q).
            accepted.append(int(tok))  # copy the draft token into output.
        else:  # first rejection stops the block.
            replacement = draw_index(residual_distribution(p, q), u=0.75)  # deterministic residual sample for examples.
            return np.array(accepted + [replacement]), len(accepted), False  # return output and accepted count.
    return np.array(accepted), len(accepted), True  # the whole drafted block survived.
```

**Goal.** Draw a block of draft tokens from q, because speculative decoding starts with cheap proposals rather than target-model samples. We build it in 3 steps.

### Advanced 1 — Verify distribution preservation empirically
