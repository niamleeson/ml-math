# 7.31 — Neural Rendering & NeRF

Neural rendering replaces an explicit triangle mesh with a continuous radiance field: for every point sampled along a camera ray, the field returns a color and a density, and volume rendering composites those answers front to back into one pixel. In this lesson, we build the NeRF rendering math from scratch with NumPy so the ray geometry, density-to-opacity conversion, transmittance, sampling, and positional encoding are all visible rather than hidden inside a neural network.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build neural rendering one idea at a time. Run each cell in order and read the printed intermediate values — every piece of math is spelled out so the renderer is never a black box. This walkthrough is self-contained (it imports what it needs) and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays, geometry, and vectorized ray calculations.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
np.random.seed(0)  # reproducibility for sampled rays and toy fields.
```
▶ What you'll see: no printed output; the cell prepares the only libraries used in this lesson.

### 1. Rays turn pixels into queried 3D points

A NeRF image begins with a ray for each pixel. A ray is just a line, written

$$r(t)=o+td,$$

where $o$ is the camera origin, $d$ is a direction vector, and $t$ says how far to move along that direction. The field is not evaluated at a whole continuous line; in practice we choose several $t$ values, plug them into the equation, and ask the radiance field what lives at those sample locations.

```python
o_w = np.array([0.0, 0.0])          # camera origin in a 2-D teaching slice.
d_w = np.array([1.0, 0.5])          # ray direction; every +1 in x moves +0.5 in y.
t_w = np.array([0.0, 1.0, 2.0, 3.0])  # distances sampled along the ray.
points_w = o_w[None, :] + t_w[:, None] * d_w[None, :]  # r(t)=o+td for every t.
print("sample points:\n", points_w)        # inspect the queried coordinates.
assert np.allclose(points_w[2], [2.0, 1.0])  # checked lesson point r(2).
```
▶ What you'll see: the samples `[0,0]`, `[1,0.5]`, `[2,1]`, and `[3,1.5]` along one camera ray.

```python
plt.figure(figsize=(4.5, 3.2))                         # compact ray plot.
plt.plot(points_w[:, 0], points_w[:, 1], "o-", color="teal")  # connect sampled positions.
for k_w, p_w in enumerate(points_w):                    # label each sample by t.
    plt.text(p_w[0] + 0.04, p_w[1], f"t={t_w[k_w]:.0f}")
plt.scatter([o_w[0]], [o_w[1]], color="crimson", label="camera origin")
plt.axis("equal"); plt.grid(True, alpha=0.3); plt.legend()
plt.title("1: one pixel casts one sampled ray"); plt.show()
```
▶ What you'll see: equally spaced queried points marching away from the camera origin.

*Why it's done this way:* the ray equation separates camera geometry from scene content. Calibration supplies $o$ and $d$; sampling supplies the $t$ values; the radiance field only needs to answer questions at points. This is why wrong camera poses blur NeRFs: if $o$ or $d$ is wrong, every queried point is in the wrong physical place.

### 2. A radiance field returns color and density, not a mesh

A mesh stores explicit surfaces. A NeRF-style field instead behaves like a function

$$(x,d)\mapsto (c,\sigma),$$

returning RGB color $c$ and volume density $\sigma$ for a queried point and view direction. To keep the lesson NumPy-only, we use a handcrafted field: density is high near a circular "surface" and low in empty space; color changes smoothly with location. The real NeRF learns this function with a neural net, but the renderer math is identical.

```python
def toy_field_w(xy_w):
    x_w, y_w = xy_w[:, 0], xy_w[:, 1]                         # split point coordinates.
    radius_w = np.sqrt((x_w - 2.0) ** 2 + (y_w - 1.0) ** 2)    # distance from a toy object center.
    sigma_w = 5.0 * np.exp(-((radius_w - 0.55) ** 2) / 0.03)  # dense near a ring-like surface.
    colors_w = np.stack([0.5 + 0.5 * np.sin(x_w),              # red varies with x.
                         0.5 + 0.5 * np.cos(y_w),              # green varies with y.
                         0.3 + 0.2 * np.sin(x_w + y_w)], axis=1)  # blue is another smooth signal.
    return np.clip(colors_w, 0, 1), sigma_w                    # RGB in [0,1], density nonnegative.

colors_w, sigma_w = toy_field_w(points_w)                      # query the field at ray samples.
print("densities:", np.round(sigma_w, 3))                      # inspect opacity source.
print("first RGB:", np.round(colors_w[0], 3))                  # inspect color source.
```
▶ What you'll see: each sampled point receives both an RGB color and a density value.

```python
grid_x_w, grid_y_w = np.meshgrid(np.linspace(0, 4, 80), np.linspace(-0.5, 2.5, 60))  # a 2-D scene grid.
grid_w = np.c_[grid_x_w.ravel(), grid_y_w.ravel()]                                  # points to query.
_, grid_sigma_w = toy_field_w(grid_w)                                                # density on the grid.
plt.figure(figsize=(5, 3.4))
plt.imshow(grid_sigma_w.reshape(grid_x_w.shape), origin="lower", extent=[0, 4, -0.5, 2.5], cmap="magma", aspect="auto")
plt.colorbar(label="density σ"); plt.plot(points_w[:, 0], points_w[:, 1], "co-")
plt.title("2: a continuous density field queried by a ray"); plt.xlabel("x"); plt.ylabel("y"); plt.show()
```
▶ What you'll see: the ray crosses a bright high-density band where a surface-like region lives.

*Why it's done this way:* a continuous field can be queried between pixels and between training views, which is the key to novel-view synthesis. The renderer does not need triangles; high density makes surfaces emerge because dense regions become opaque during compositing.

### 3. Positional encoding gives a field high-frequency coordinates

Plain coordinates such as $x=0.37$ are smooth inputs. NeRFs often use positional encoding: concatenate sine and cosine waves at multiple frequencies. This lets a simple model represent sharp edges and thin structures because high-frequency features change rapidly with position.

```python
def encode_1d_w(x_w, levels_w=4):
    freqs_w = 2.0 ** np.arange(levels_w)                         # 1,2,4,8 cycles of detail.
    pieces_w = [x_w[:, None]]                                     # keep raw coordinate too.
    pieces_w += [np.sin(freqs_w[None, :] * np.pi * x_w[:, None]),  # sine features.
                 np.cos(freqs_w[None, :] * np.pi * x_w[:, None])] # cosine features.
    return np.concatenate(pieces_w, axis=1)                       # encoded design matrix.

xline_w = np.linspace(0, 1, 9)                                    # inspect a few positions.
enc_w = encode_1d_w(xline_w, levels_w=3)                           # 1 raw + 3 sine + 3 cosine.
print("encoded shape:", enc_w.shape)                              # 9 positions x 7 features.
assert enc_w.shape == (9, 7)                                       # concrete dimensionality check.
```
▶ What you'll see: one scalar coordinate expands into several wave features.

```python
fine_x_w = np.linspace(0, 1, 300)                                  # dense line for plotting.
fine_enc_w = encode_1d_w(fine_x_w, levels_w=4)                      # raw plus multiscale waves.
plt.figure(figsize=(5, 3))
plt.plot(fine_x_w, fine_enc_w[:, 1], label="sin(πx)")
plt.plot(fine_x_w, fine_enc_w[:, 4], label="sin(8πx)")
plt.title("3: positional encoding adds fast-changing features")
plt.xlabel("x"); plt.ylabel("feature value"); plt.legend(); plt.show()
```
▶ What you'll see: the high-frequency curve wiggles much faster than the low-frequency curve.

*Why it's done this way:* a neural network built from smooth operations tends to learn low-frequency variation first. Feeding it multiple sine/cosine scales makes sharp geometry easier to express, because the basis already contains rapidly changing coordinates.

### 4. Density over an interval becomes opacity

Density $\sigma_i$ is not directly the probability of stopping. A sample also covers an interval length $\delta_i$. NeRF converts density to opacity with

$$\alpha_i = 1-e^{-\sigma_i\delta_i}.$$

This is the survival law for a constant-density slab: $e^{-\sigma\delta}$ is the chance light survives the slab, so one minus that is the chance it terminates there.

```python
sigma_demo_w = np.array([0.1, 1.0, 3.0])   # low, medium, high density.
delta_demo_w = 0.5                         # equal sample interval.
alpha_demo_w = 1.0 - np.exp(-sigma_demo_w * delta_demo_w)  # density-to-opacity conversion.
print("alpha:", np.round(alpha_demo_w, 4))  # checked values from the lesson block.
assert np.allclose(np.round(alpha_demo_w, 4), [0.0488, 0.3935, 0.7769])
```
▶ What you'll see: opacity rises from about 0.049 to 0.777 as density grows.

```python
sigma_curve_w = np.linspace(0, 6, 200)                       # density sweep.
plt.figure(figsize=(4.5, 3))
for delta_w in [0.25, 0.5, 1.0]:                              # compare interval lengths.
    plt.plot(sigma_curve_w, 1 - np.exp(-sigma_curve_w * delta_w), label=f"δ={delta_w}")
plt.title("4: opacity depends on density and interval length")
plt.xlabel("density σ"); plt.ylabel("alpha opacity"); plt.legend(); plt.show()
```
▶ What you'll see: larger intervals become opaque faster, even at the same density.

*Why it's done this way:* $\sigma$ is a rate per unit distance. Multiplying by $\delta$ turns a rate into expected absorption across a finite slab. Ignoring $\delta$ would make the same scene brighter or darker merely because we changed the number of samples.

### 5. Transmittance tracks foreground survival

A far sample should not fully contribute if foreground density already blocked the ray. Transmittance $T_i$ is the fraction of light that reaches sample $i$:

$$T_i=\prod_{j<i}(1-\alpha_j).$$

The product is exclusive: the first sample has $T_1=1$ because nothing is in front of it.

```python
alpha_w = np.array([0.2, 0.5, 0.1])              # checked alpha values.
survival_w = 1.0 - alpha_w                       # per-sample light survival.
T_w = np.concatenate([[1.0], np.cumprod(survival_w[:-1])])  # exclusive cumulative product.
weights_w = T_w * alpha_w                        # probability ray terminates at each sample.
print("T:", np.round(T_w, 3))                    # [1.0, 0.8, 0.4].
print("weights:", np.round(weights_w, 3))        # [0.2, 0.4, 0.04].
assert np.allclose(T_w, [1.0, 0.8, 0.4])
assert np.allclose(weights_w, [0.2, 0.4, 0.04])
```
▶ What you'll see: the middle sample contributes most because enough light reaches it and it is fairly opaque.

```python
plt.figure(figsize=(5, 3))
idx_w = np.arange(len(alpha_w))
plt.bar(idx_w - 0.18, alpha_w, width=0.36, label="alpha", color="orange")
plt.bar(idx_w + 0.18, weights_w, width=0.36, label="T × alpha", color="teal")
plt.xticks(idx_w, ["sample 1", "sample 2", "sample 3"]); plt.ylabel("value")
plt.title("5: foreground samples reduce later contribution"); plt.legend(); plt.show()
```
▶ What you'll see: sample 3 has alpha 0.1 but an even smaller contribution because only 40% of light reaches it.

*Why it's done this way:* alpha alone asks "how opaque is this slab?" Transmittance asks "does the ray even reach this slab?" Multiplying them gives a valid front-to-back termination probability, preventing hidden background colors from shining through foreground density.

### 6. Volume rendering is a weighted color sum

Once each sample has color $c_i$ and weight $w_i=T_i\alpha_i$, the rendered pixel is

$$C(r)=\sum_i w_i c_i.$$

The weights usually sum to less than 1 if some light escapes the far end of the ray; the leftover can be blended with a background color.

```python
rgb_w = np.array([[1.0, 0.0, 0.0],   # red sample.
                  [0.0, 1.0, 0.0],   # green sample.
                  [0.0, 0.0, 1.0]])  # blue sample.
pixel_w = weights_w @ rgb_w          # weighted sum of RGB colors.
print("rendered RGB:", np.round(pixel_w, 3))
assert np.allclose(pixel_w, [0.2, 0.4, 0.04])
```
▶ What you'll see: the rendered pixel is `[0.2, 0.4, 0.04]`, not the color of a single sample.

```python
plt.figure(figsize=(4.5, 3))
plt.imshow(pixel_w.reshape(1, 1, 3), extent=[0, 1, 0, 1])  # show the final RGB patch.
plt.title("6: accumulated ray color"); plt.xticks([]); plt.yticks([]); plt.show()
```
▶ What you'll see: a dark greenish patch because the green sample has the largest weight.

*Why it's done this way:* volume rendering is an expectation: each weight is the probability the ray terminates at that sample, and each color is what you would see if it did. Summing probability times color gives the expected pixel color, and the formula remains differentiable for learning.

### 7. Sampling controls what the renderer can see

Even a perfect field cannot render a thin surface if no sampled point lands near it. Coarse sampling is cheap but can miss narrow density peaks; fine or importance sampling spends more queries where density is likely to matter.

```python
def thin_density_w(t_w):
    return 8.0 * np.exp(-((t_w - 2.35) ** 2) / 0.002)  # very thin high-density structure.

coarse_t_w = np.linspace(0, 4, 9)                      # few samples.
fine_t_w = np.linspace(0, 4, 161)                       # many samples.
print("coarse max density:", round(float(thin_density_w(coarse_t_w).max()), 3))
print("fine max density:", round(float(thin_density_w(fine_t_w).max()), 3))
assert thin_density_w(fine_t_w).max() > thin_density_w(coarse_t_w).max()
```
▶ What you'll see: the fine grid detects the thin density peak much better than the coarse grid.

```python
plt.figure(figsize=(5, 3))
plt.plot(fine_t_w, thin_density_w(fine_t_w), color="black", label="true thin density")
plt.scatter(coarse_t_w, thin_density_w(coarse_t_w), color="crimson", label="coarse samples")
plt.title("7: coarse samples can miss thin geometry")
plt.xlabel("t along ray"); plt.ylabel("density σ"); plt.legend(); plt.show()
```
▶ What you'll see: most coarse samples fall away from the narrow peak, so the object would receive weak evidence.

*Why it's done this way:* sampling is part of the model, not just an implementation detail. The differentiable renderer can only send gradients through queried points, so undersampling thin structures means the field may never learn they exist.

## 🛠️ Setup

```python
import numpy as np # load NumPy for ray geometry, positional encoding, and volume-rendering arrays.
import matplotlib.pyplot as plt # load Matplotlib for line plots, heatmaps, and RGB patches.
np.random.seed(0) # make all stochastic examples reproducible.

def normalize(v): # return a unit-length vector while safely handling zero vectors.
    v = np.asarray(v, dtype=float) # convert input to a float array.
    n = np.linalg.norm(v) # compute Euclidean length.
    return v if n == 0 else v / n # divide by length unless the vector is zero.

def ray_points(origin, direction, t_values): # sample positions r(t)=o+td along one ray.
    origin = np.asarray(origin, dtype=float) # ensure origin is a float vector.
    direction = np.asarray(direction, dtype=float) # ensure direction is a float vector.
    t_values = np.asarray(t_values, dtype=float) # ensure sample distances are floats.
    return origin[None, :] + t_values[:, None] * direction[None, :] # broadcast one point per t.

def density_to_alpha(sigma, delta): # convert density over interval length into opacity.
    return 1.0 - np.exp(-np.asarray(sigma, dtype=float) * np.asarray(delta, dtype=float)) # alpha=1-exp(-σδ).

def transmittance(alpha): # compute exclusive cumulative survival before each sample.
    alpha = np.asarray(alpha, dtype=float) # ensure alpha is numeric.
    return np.concatenate([[1.0], np.cumprod(1.0 - alpha[:-1])]) # T_i=prod_{j<i}(1-alpha_j).

def volume_weights(alpha): # compute NeRF compositing weights from alpha values.
    alpha = np.asarray(alpha, dtype=float) # ensure alpha is numeric.
    return transmittance(alpha) * alpha # w_i=T_i alpha_i.

def render_volume(colors, sigma, delta, background=None): # render one ray from colors, densities, and intervals.
    alpha = density_to_alpha(sigma, delta) # convert densities to opacities.
    weights = volume_weights(alpha) # compute front-to-back termination weights.
    rgb = weights @ np.asarray(colors, dtype=float) # weighted color accumulation.
    if background is not None: # optionally add escaped light as background.
        rgb = rgb + np.prod(1.0 - alpha) * np.asarray(background, dtype=float) # remaining transmittance times background.
    return rgb, weights, alpha # return useful debugging values.

def positional_encoding(x, levels=4): # encode scalar coordinates with sine/cosine frequencies.
    x = np.asarray(x, dtype=float).reshape(-1) # flatten coordinates.
    freqs = 2.0 ** np.arange(levels) # powers-of-two frequencies.
    return np.concatenate([x[:, None], np.sin(np.pi * x[:, None] * freqs[None, :]), np.cos(np.pi * x[:, None] * freqs[None, :])], axis=1) # raw + sin + cos.

def toy_radiance_field(points): # deterministic NumPy field used in examples.
    points = np.asarray(points, dtype=float) # ensure point matrix.
    x, y = points[:, 0], points[:, 1] # split coordinates.
    sigma = 4.0 * np.exp(-((np.sqrt((x - 2.0) ** 2 + (y - 1.0) ** 2) - 0.55) ** 2) / 0.04) # ring-like density.
    colors = np.stack([0.5 + 0.5 * np.sin(x), 0.5 + 0.5 * np.cos(y), 0.4 + 0.3 * np.sin(x + y)], axis=1) # smooth RGB.
    return np.clip(colors, 0, 1), sigma # return valid RGB and nonnegative density.
```
▶ What you'll see: no printed output; helper functions define ray sampling, encoding, and volume rendering.

### Basic 7 — Accumulate RGB along a ray

**Goal.** Render one pixel as a weighted RGB sum, because the final color is accumulated radiance along the ray. We build it in 2 steps.

```python
def loss_a5(sigma_vec_a5): # squared RGB error for current densities.
    rgb_a5, _, _ = render_volume(colors_a5, sigma_vec_a5, delta_a5, background=None) # render current pixel.
    return float(np.sum((rgb_a5 - target_a5) ** 2)) # return squared color error.
```

▶ What you'll see: the initial densities do not reproduce the target pixel.

```python
losses_a5 = [] # record optimization progress.
for step_a5 in range(80): # run small finite-difference gradient descent.
    grad_a5 = np.zeros_like(sigma_a5) # allocate gradient estimate.
    eps_a5 = 1e-4 # finite-difference step.
    base_loss_a5 = loss_a5(sigma_a5) # current loss.
    for j_a5 in range(len(sigma_a5)): # estimate each partial derivative.
        bumped_a5 = sigma_a5.copy() # copy current densities.
        bumped_a5[j_a5] += eps_a5 # perturb one density.
        grad_a5[j_a5] = (loss_a5(bumped_a5) - base_loss_a5) / eps_a5 # finite-difference slope.
    sigma_a5 = np.maximum(0.0, sigma_a5 - 0.25 * grad_a5) # gradient step with nonnegative density constraint.
    losses_a5.append(loss_a5(sigma_a5)) # record new loss.
print("final sigma:", np.round(sigma_a5, 3), "final loss:", round(losses_a5[-1], 5)) # inspect optimized densities.
assert losses_a5[-1] < losses_a5[0] # verify training reduced rendering error.
```
▶ What you'll see: the loss falls as densities adapt to make the composited color closer to target.
