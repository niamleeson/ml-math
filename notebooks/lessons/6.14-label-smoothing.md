# 6.14 — Label Smoothing

Label smoothing replaces brittle one-hot certainty with a small probability budget for the other classes. In this lesson, we build the smoothed target, feed it through softmax cross-entropy, inspect the gradient it creates, and see why a tiny target-side constraint can make classification less overconfident and more robust.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build label smoothing one idea at a time. Run each cell in order and read the printed intermediate values — every piece of math is shown so the target, loss, gradient, and regularization effect are visible. This walkthrough is self-contained and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays, softmax arithmetic, and small numerical checks.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
np.random.seed(0)  # reproducibility for synthetic logits and noisy labels.
```
▶ What you'll see: the only two libraries used in the lesson are NumPy and Matplotlib.

### 1. From one-hot certainty to a smoothed distribution

A classifier usually trains against a one-hot target: the true class receives probability 1 and every other class receives 0. Label smoothing says that this is too brittle. With $K$ classes and smoothing strength $\varepsilon$, the target becomes

$$y'_k=(1-\varepsilon)y_k+\frac{\varepsilon}{K}.$$

So the true class keeps most of the mass, but every class receives a small shared floor. The floor matters because cross-entropy is a probability comparison, not just an index lookup.

```python
K_w = 5  # number of classes in the toy classifier.
true_class_w = 2  # the observed label is class 2.
eps_w = 0.10  # smoothing strength: move 10% of the target toward uniform.
y_w = np.eye(K_w)[true_class_w]  # one-hot target vector.
y_smooth_w = (1 - eps_w) * y_w + eps_w / K_w  # smoothed target distribution.
print("one-hot target:", y_w)
print("smoothed target:", np.round(y_smooth_w, 3))
print("sum:", round(float(y_smooth_w.sum()), 3))
assert np.allclose(y_smooth_w, [0.02, 0.02, 0.92, 0.02, 0.02])
```
▶ What you'll see: class 2 drops from 1.00 to 0.92, while each class receives 0.02, and the vector still sums to 1.

```python
plt.figure(figsize=(5, 3))
plt.bar(np.arange(K_w) - 0.18, y_w, width=0.36, label="one-hot", color="gray")
plt.bar(np.arange(K_w) + 0.18, y_smooth_w, width=0.36, label="smoothed", color="teal")
plt.xticks(range(K_w), [f"c{k}" for k in range(K_w)])
plt.ylim(0, 1.05)
plt.ylabel("target probability")
plt.title("1: label smoothing changes the target")
plt.legend()
plt.show()
```
▶ What you'll see: one tall bar becomes slightly shorter, and the zero bars become small nonzero bars.

*Why it's done this way:* the formula is a convex mixture of the hard label and the uniform distribution. That keeps the observed class dominant while admitting that the training label is not perfect knowledge; mathematically, it prevents the loss from rewarding infinite confidence in a probability of exactly 1.

### 2. Softmax turns scores into the probabilities the target compares against

The model does not output probabilities directly; it outputs logits. Softmax exponentiates and normalizes them, so cross-entropy can compare a predicted distribution $p$ to the target distribution $y'$. We subtract the maximum logit before exponentiating because probabilities are unchanged by adding or subtracting the same constant from every logit, and the shifted version is numerically safer.

```python
logits_w = np.array([0.4, -0.2, 3.25, 1.1, -1.0])  # raw class scores before softmax.
shifted_w = logits_w - np.max(logits_w)  # same softmax, safer exponentials.
exp_w = np.exp(shifted_w)  # exponentiate shifted scores.
p_w = exp_w / exp_w.sum()  # normalize to probabilities.
print("shifted logits:", np.round(shifted_w, 3))
print("softmax p:", np.round(p_w, 3))
print("true-class probability:", round(float(p_w[true_class_w]), 3))
assert round(float(p_w[true_class_w]), 3) == 0.819
```
▶ What you'll see: the large class-2 logit becomes probability about 0.819, high but not certain.

```python
plt.figure(figsize=(5, 3))
plt.bar([f"c{k}" for k in range(K_w)], p_w, color="purple")
plt.axhline(1 / K_w, color="black", linestyle="--", label="uniform")
plt.title("2: softmax probabilities from logits")
plt.ylabel("predicted probability")
plt.legend()
plt.show()
```
▶ What you'll see: class 2 dominates, while the dashed line marks the 0.20 uniform baseline for five classes.

*Why it's done this way:* softmax converts arbitrary real scores into a normalized distribution, and subtracting the max preserves ratios like $e^{z_i}/e^{z_j}$ while avoiding overflow. Label smoothing lives on the same probability simplex as softmax, so the loss can compare target mass and predicted mass coordinate by coordinate.

### 3. Cross-entropy with smoothed targets is a weighted log-probability average

Cross-entropy is

$$H(y',p)=-\sum_k y'_k\log p_k.$$

With a one-hot target, only the true class contributes. With label smoothing, every class contributes a little. That means the model is still rewarded for putting high probability on the true class, but it is also penalized for crushing all alternatives to near zero.

```python
ce_hard_w = -np.sum(y_w * np.log(p_w))  # one-hot cross-entropy.
ce_smooth_w = -np.sum(y_smooth_w * np.log(p_w))  # smoothed-target cross-entropy.
terms_w = -y_smooth_w * np.log(p_w)  # per-class contributions to smoothed CE.
print("hard CE:", round(float(ce_hard_w), 3))
print("smoothed CE:", round(float(ce_smooth_w), 3))
print("smoothed terms:", np.round(terms_w, 3))
assert round(float(ce_hard_w), 3) == 0.199
assert round(float(ce_smooth_w), 3) == 0.453
```
▶ What you'll see: smoothed CE is larger here because the target asks the model to leave some probability for non-true classes.

```python
plt.figure(figsize=(5, 3))
plt.bar([f"c{k}" for k in range(K_w)], terms_w, color="darkorange")
plt.title("3: per-class contributions to smoothed CE")
plt.ylabel("- y'_k log p_k")
plt.show()
```
▶ What you'll see: the true class still contributes most, but non-true classes now have visible loss terms.

*Why it's done this way:* the logarithm makes assigning tiny probability to a target-supported class expensive. Smoothing gives every class a small positive target, so the optimum is no longer “send the true logit to infinity”; it is “match a high-but-not-one target distribution.”

### 4. The gradient becomes less extreme: softmax cross-entropy gives p − y'

For softmax followed by cross-entropy, the gradient with respect to each logit is simply $p_k-y'_k$. That is the local training signal passed backward through the network. Label smoothing changes the target side of that subtraction, which directly changes the update direction.

```python
grad_hard_w = p_w - y_w  # gradient dL/dlogit for one-hot CE.
grad_smooth_w = p_w - y_smooth_w  # gradient dL/dlogit for smoothed CE.
print("hard gradient:", np.round(grad_hard_w, 3))
print("smoothed gradient:", np.round(grad_smooth_w, 3))
print("true-class gradient change:", round(float(grad_smooth_w[true_class_w] - grad_hard_w[true_class_w]), 3))
assert round(float(grad_hard_w[true_class_w]), 3) == -0.181
assert round(float(grad_smooth_w[true_class_w]), 3) == -0.101
```
▶ What you'll see: the true-class negative gradient is smaller in magnitude, and non-true gradients are reduced by the smoothing floor.

```python
x_w = np.arange(K_w)
plt.figure(figsize=(5, 3))
plt.bar(x_w - 0.18, grad_hard_w, width=0.36, label="hard", color="crimson")
plt.bar(x_w + 0.18, grad_smooth_w, width=0.36, label="smoothed", color="seagreen")
plt.axhline(0, color="black", linewidth=0.8)
plt.xticks(x_w, [f"c{k}" for k in range(K_w)])
plt.title("4: gradient p - y")
plt.ylabel("dL / dlogit")
plt.legend()
plt.show()
```
▶ What you'll see: smoothing pulls every gradient bar closer to zero, especially the correct class.

*Why it's done this way:* the model update is driven by the mismatch between predicted probability and target probability. Smoothing deliberately reduces the mismatch created by a perfectly hard label, so training still learns the class but stops pushing logits toward unbounded confidence as aggressively.

### 5. Smoothing regularizes confidence and can improve calibration

A perfectly separable training set can tempt cross-entropy to keep increasing the winning logit even after the classification is correct. Label smoothing resists that by making the desired target probability less than 1. The model can still be accurate, but it is discouraged from saying “100% certain” when data, labels, and future examples are never perfect.

```python
conf_grid_w = np.linspace(0.50, 0.999, 200)  # possible predicted probabilities for the true class.
hard_loss_grid_w = -np.log(conf_grid_w)  # hard target loss as confidence increases.
smooth_binary_grid_w = -(0.95 * np.log(conf_grid_w) + 0.05 * np.log(1 - conf_grid_w))  # binary-smoothed target with 0.95/0.05.
best_conf_w = float(conf_grid_w[np.argmin(smooth_binary_grid_w)])
print("hard loss at p=0.999:", round(float(hard_loss_grid_w[-1]), 3))
print("smoothed best confidence:", round(best_conf_w, 3))
assert round(best_conf_w, 3) == 0.949
```
▶ What you'll see: the hard loss keeps improving toward p=1, but the smoothed loss is minimized near the target confidence 0.95.

```python
plt.figure(figsize=(5, 3))
plt.plot(conf_grid_w, hard_loss_grid_w, label="hard target", color="gray")
plt.plot(conf_grid_w, smooth_binary_grid_w, label="smoothed target", color="teal")
plt.axvline(best_conf_w, color="teal", linestyle="--", label="smoothed optimum")
plt.xlabel("predicted probability for true class")
plt.ylabel("loss")
plt.title("5: smoothing has a finite-confidence optimum")
plt.legend()
plt.show()
```
▶ What you'll see: the smoothed curve bottoms out before probability 1, while the hard curve keeps falling.

*Why it's done this way:* the smoothed target encodes a finite desired confidence. That acts like regularization on logits: correct classifications remain correct, but the loss no longer encourages unlimited separation simply to make the winning probability closer to one.

### 6. Choosing epsilon is a bias-variance knob, not a magic constant

The smoothing strength $\varepsilon$ controls how much probability mass moves from the observed label toward uniform uncertainty. Too little smoothing barely changes training; too much smoothing erases the class signal. The right value is a validation choice, especially when labels are noisy or classes overlap.

```python
eps_values_w = np.array([0.0, 0.05, 0.10, 0.20, 0.50])  # candidate smoothing strengths.
true_masses_w = 1 - eps_values_w + eps_values_w / K_w  # target mass assigned to the observed class.
other_masses_w = eps_values_w / K_w  # target mass assigned to each class.
print("eps:", eps_values_w)
print("true-class target mass:", np.round(true_masses_w, 3))
print("each-class floor:", np.round(other_masses_w, 3))
assert np.allclose(np.round(true_masses_w, 3), [1.0, 0.96, 0.92, 0.84, 0.6])
```
▶ What you'll see: increasing epsilon steadily lowers the observed-class target and raises the probability floor.

```python
plt.figure(figsize=(5, 3))
plt.plot(eps_values_w, true_masses_w, marker="o", label="true class target", color="seagreen")
plt.plot(eps_values_w, other_masses_w, marker="s", label="each class floor", color="darkorange")
plt.xlabel("epsilon")
plt.ylabel("target probability")
plt.title("6: epsilon controls target softness")
plt.legend()
plt.show()
```
▶ What you'll see: the true-class line falls and the class-floor line rises as smoothing becomes stronger.

*Why it's done this way:* epsilon trades bias against variance. A small uniform mixture can absorb label noise and reduce overconfidence; a large mixture tells the model that the label is weak evidence, so it can underfit by making targets too similar across classes.

## 🛠️ Setup

```python
import numpy as np # load NumPy for arrays, softmax, losses, gradients, and small simulations.
import matplotlib.pyplot as plt # load Matplotlib for probability bars, loss curves, and diagnostics.
np.random.seed(0) # make all stochastic examples reproducible.

def softmax(z): # define a numerically stable softmax for one vector of logits.
    z = np.asarray(z, dtype=float) # convert input scores to a float array.
    shifted = z - np.max(z) # subtract the maximum because softmax is shift-invariant and this prevents overflow.
    e = np.exp(shifted) # exponentiate shifted scores.
    return e / np.sum(e) # normalize exponentials into probabilities.

def smooth_one_hot(class_id, K, eps): # define label smoothing for a single class index.
    y = np.eye(K)[class_id] # create a hard one-hot target.
    return (1 - eps) * y + eps / K # mix the hard target with the uniform distribution.

def cross_entropy(target, probs): # define cross-entropy for a target distribution and predicted probabilities.
    probs = np.clip(probs, 1e-12, 1.0) # clip probabilities to avoid log(0) in tiny examples.
    return float(-np.sum(target * np.log(probs))) # compute -sum target times log probability.

def accuracy_from_logits(logits, labels): # define a tiny accuracy helper for 2-D logits arrays.
    return float(np.mean(np.argmax(logits, axis=1) == labels)) # compare predicted class indices with labels.
```
▶ What you'll see: reusable helpers for stable softmax, smoothed labels, cross-entropy, and accuracy.

### Basic 9 — Keep softmax numerically stable

**Goal.** Use max-shifted softmax on large logits, because exponentiating raw large values can overflow. We build it in 2 steps.

```python
logits_b9 = np.array([1000.0, 999.0, 998.0]) # define very large scores with modest differences.
shifted_b9 = logits_b9 - np.max(logits_b9) # subtract the max before exponentiating.
```

**Goal.** Inspect smoothing floors for different class counts, because $\varepsilon/K$ becomes tiny in large-label problems. We build it in 3 steps.



### Advanced 5 — Find the finite-confidence optimum

**Goal.** Minimize binary cross-entropy for a smoothed target, because the optimum predicted probability equals the smoothed target rather than 1. We build it in 4 steps.

```python
eps_a5 = 0.1 # smoothing strength in a two-class problem.
target_pos_a5 = 1 - eps_a5 + eps_a5 / 2 # positive-class target under uniform smoothing.
target_neg_a5 = eps_a5 / 2 # negative-class target under uniform smoothing.
print("positive target:", target_pos_a5, "negative target:", target_neg_a5) # inspect binary smoothed target.
assert round(float(target_pos_a5), 3) == 0.95 # verify finite confidence target.
```
▶ What you'll see: the positive class target is 0.95, not 1.0.

```python
p_grid_a5 = np.linspace(0.01, 0.99, 300) # candidate predicted positive probabilities.
loss_grid_a5 = -(target_pos_a5 * np.log(p_grid_a5) + target_neg_a5 * np.log(1 - p_grid_a5)) # binary CE for smoothed target.
best_p_a5 = float(p_grid_a5[np.argmin(loss_grid_a5)]) # find the grid optimum.
print("best p on grid:", round(best_p_a5, 3)) # inspect numerical optimum.
assert abs(best_p_a5 - target_pos_a5) < 0.003 # verify optimum is at the target probability.
```
▶ What you'll see: the minimum occurs near 0.95, matching the smoothed positive target.


