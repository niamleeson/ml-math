# 5.8 — Structure Learning

Structure learning chooses the graph itself: which dependencies deserve edges, and which apparent patterns are too weak to justify extra complexity. In this lesson, we build tiny Bayesian-network structure scores from scratch, using likelihood for data fit and BIC penalties so every edge must earn its keep.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build structure learning one idea at a time. Run each cell in order and read the printed intermediate values — every score is decomposed so you can see which term rewards evidence and which term penalizes complexity. This walkthrough is self-contained and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays, counts, logs, and simple graph search.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
np.random.seed(0)  # reproducibility for generated Bernoulli data.
```

### 1. Data, candidate edges, and what “learning a graph” means

Structure learning starts with variables and asks which arrows should connect them. We will use three binary variables: a possible cause `X`, a strong response `Y`, and a weak response `Z`. The question is not whether a full graph can fit the data — it usually can — but whether each extra dependency improves likelihood enough to pay for its added parameters.

```python
n_w = 100  # sample size used by the BIC arithmetic in the lesson text.
rng_w = np.random.default_rng(0)  # local generator so the walkthrough is repeatable.
X_w = rng_w.binomial(1, 0.50, size=n_w)  # candidate parent variable.
Y_w = np.where(X_w == 1, rng_w.binomial(1, 0.85, n_w), rng_w.binomial(1, 0.20, n_w))  # strong child.
Z_w = np.where(X_w == 1, rng_w.binomial(1, 0.57, n_w), rng_w.binomial(1, 0.43, n_w))  # weak child.
D_w = np.column_stack([X_w, Y_w, Z_w])  # data table: rows are samples, columns are variables.
print("data shape:", D_w.shape)
print("first five rows [X,Y,Z]:\n", D_w[:5])
```
▶ What you'll see: 100 binary observations; `Y` was generated to depend strongly on `X`, while `Z` only weakly depends on `X`.

```python
means_w = D_w.mean(axis=0)  # empirical marginal probabilities for X, Y, Z.
print("empirical P(variable=1):", np.round(means_w, 3))
plt.figure(figsize=(4.4, 3))
plt.bar(["X", "Y", "Z"], means_w, color=["gray", "teal", "orange"])
plt.ylim(0, 1); plt.ylabel("fraction of ones")
plt.title("1: observed binary variables")
plt.show()
```
▶ What you'll see: marginal rates alone do not tell you whether an edge is warranted; the edge decision needs conditional fit.

*Why it's done this way:* a graph is a claim about factorization. With no edges, each variable pays only for its marginal probability; with an edge like `X→Y`, `Y` gets a separate conditional probability for each value of `X`. The edge is useful only if those two conditional distributions differ enough to explain the data better.

### 2. Likelihood gain: how much an edge improves data fit

For binary variables, the maximum-likelihood probability is just a count ratio. The no-edge model for `Y` uses one probability, $p(Y=1)$; the edge model `X→Y` uses two probabilities, $p(Y=1\mid X=0)$ and $p(Y=1\mid X=1)$. The log-likelihood gain is the number of nats the conditional model saves by matching the data more closely.

```python
def bern_ll_w(y):  # maximized Bernoulli log-likelihood for one binary vector.
    y = np.asarray(y, dtype=float)
    p = np.clip(y.mean(), 1e-9, 1 - 1e-9)
    return float(np.sum(y * np.log(p) + (1 - y) * np.log(1 - p)))

def cond_bern_ll_w(parent, child):  # maximized conditional Bernoulli log-likelihood child|parent.
    total = 0.0
    for value in [0, 1]:
        group = child[parent == value]
        total += bern_ll_w(group)
    return float(total)

ll_y_ind_w = bern_ll_w(Y_w)
ll_y_edge_w = cond_bern_ll_w(X_w, Y_w)
gain_y_w = ll_y_edge_w - ll_y_ind_w
print("LL(Y independent):", round(ll_y_ind_w, 3))
print("LL(Y | X):", round(ll_y_edge_w, 3))
print("edge gain X→Y:", round(gain_y_w, 3))
```
▶ What you'll see: conditioning `Y` on `X` improves the maximized log-likelihood substantially.

```python
ll_z_ind_w = bern_ll_w(Z_w)
ll_z_edge_w = cond_bern_ll_w(X_w, Z_w)
gain_z_w = ll_z_edge_w - ll_z_ind_w
print("edge gain X→Z:", round(gain_z_w, 3))
plt.figure(figsize=(4.4, 3))
plt.bar(["X→Y strong", "X→Z weak"], [gain_y_w, gain_z_w], color=["teal", "orange"])
plt.ylabel("log-likelihood gain (nats)")
plt.title("2: fit gain from adding one edge")
plt.show()
```
▶ What you'll see: the strong edge gains many more nats than the weak edge.

*Why it's done this way:* likelihood is the evidence term. Because maximum likelihood always improves or stays equal when we add parameters, it cannot be the whole score; by itself it would keep adding weak edges that merely chase noise.

### 3. BIC: making an edge pay for its extra parameter

BIC combines the fitted log-likelihood with a complexity charge: $\mathrm{BIC}(G)=\log p(D\mid\hat\theta_G,G)-\frac{k_G}{2}\log n$. For a binary child with one binary parent, the edge replaces one Bernoulli probability with two, so it adds one free parameter. At $n=100$, that one-parameter penalty is $0.5\log(100)=2.303$ nats.

```python
penalty_one_w = 0.5 * np.log(n_w)  # one additional free parameter at n=100.
print("BIC penalty for one extra parameter:", round(penalty_one_w, 3))
assert round(penalty_one_w, 3) == 2.303
```
▶ What you'll see: the fixed cost an edge must beat in this tiny example.

```python
bic_delta_y_w = gain_y_w - penalty_one_w  # BIC change for adding X->Y.
bic_delta_z_w = gain_z_w - penalty_one_w  # BIC change for adding X->Z.
print("ΔBIC X→Y:", round(bic_delta_y_w, 3))
print("ΔBIC X→Z:", round(bic_delta_z_w, 3))
```
▶ What you'll see: a strong edge has positive ΔBIC, while a weak edge can lose to the same penalty.

```python
plt.figure(figsize=(4.6, 3))
plt.bar(["gain X→Y", "gain X→Z", "penalty"], [gain_y_w, gain_z_w, penalty_one_w], color=["teal", "orange", "gray"])
plt.ylabel("nats")
plt.title("3: edge gains must exceed BIC cost")
plt.show()
```
▶ What you'll see: compare each gain bar with the penalty bar; only a gain above the penalty is worth the edge.

*Why it's done this way:* BIC approximates a model-selection tradeoff: data fit grows with sample evidence, while the penalty grows with parameter count and sample size. As $n$ grows, tiny accidental gains must be more convincing before the score trusts them.

### 4. Local scores: a graph score decomposes into node families

Bayesian-network scores are local: each node contributes the likelihood of itself given its parents, plus the parameter penalty for that family. That means a candidate edge can often be evaluated by recomputing only the child’s local score instead of refitting the whole graph.

```python
def local_score_w(parent, child, n):  # BIC local score for either no parent or one binary parent.
    if parent is None:
        ll = bern_ll_w(child)
        k = 1
    else:
        ll = cond_bern_ll_w(parent, child)
        k = 2
    return ll - 0.5 * k * np.log(n)

score_y_no_w = local_score_w(None, Y_w, n_w)
score_y_x_w = local_score_w(X_w, Y_w, n_w)
print("local BIC Y with no parent:", round(score_y_no_w, 3))
print("local BIC Y with parent X:", round(score_y_x_w, 3))
print("local score difference:", round(score_y_x_w - score_y_no_w, 3))
```
▶ What you'll see: the local score difference exactly matches the ΔBIC for adding `X→Y`.

```python
families_w = np.array([local_score_w(None, X_w, n_w), score_y_x_w, local_score_w(None, Z_w, n_w)])
print("family scores [X, Y|X, Z]:", np.round(families_w, 3))
print("total graph BIC:", round(float(families_w.sum()), 3))
plt.figure(figsize=(4.6, 3))
plt.bar(["X", "Y|X", "Z"], families_w, color=["gray", "teal", "orange"])
plt.ylabel("local BIC contribution")
plt.title("4: graph score as sum of families")
plt.show()
```
▶ What you'll see: the total graph score is a sum of node-family terms, making edge search modular.

*Why it's done this way:* local decomposition is the computational trick that makes structure search possible. Instead of treating a graph as one giant object, we score each variable with its proposed parents and update only the family affected by an edge change.

### 5. Greedy search: useful, but not a guarantee

A practical search tries local edits: add, delete, or reverse one edge, keep the edit if it improves the score, and repeat. This is greedy hill climbing. It is easy to inspect and often effective, but it can get trapped because a locally bad edge might be needed before a later reversal or companion edge becomes good.

```python
candidates_w = ["X→Y", "X→Z"]
deltas_w = np.array([bic_delta_y_w, bic_delta_z_w])
chosen_w = [candidates_w[i] for i in np.where(deltas_w > 0)[0]]
print("candidate ΔBIC:", dict(zip(candidates_w, np.round(deltas_w, 3))))
print("greedy additions kept:", chosen_w)
```
▶ What you'll see: the greedy rule keeps the strong edge and rejects the weak one.

```python
score_path_w = [0.0]
for delta in sorted(deltas_w, reverse=True):
    if delta > 0:
        score_path_w.append(score_path_w[-1] + delta)
    else:
        score_path_w.append(score_path_w[-1])
print("relative greedy score path:", np.round(score_path_w, 3))
plt.figure(figsize=(4.6, 3))
plt.step(range(len(score_path_w)), score_path_w, where="post", color="purple")
plt.xticks(range(len(score_path_w)))
plt.xlabel("greedy edit step"); plt.ylabel("relative BIC")
plt.title("5: greedy score only accepts improvements")
plt.show()
```
▶ What you'll see: the score rises when the strong edge is added and stays flat when the weak edge is rejected.

*Why it's done this way:* exhaustive graph search is combinatorial, so greedy edits are a scalable approximation. The safeguard is the score threshold: an edit must improve penalized fit, not just raw likelihood, but the search still needs restarts, constraints, or expert structure when local optima matter.

### 6. Markov equivalence: some arrows cannot be identified from observational data

Observational data can determine some conditional independences but not every arrow direction. For two variables, `X→Y` and `Y→X` have the same saturated joint likelihood and the same number of parameters, so BIC cannot choose a direction from observational scores alone. This is Markov equivalence in its smallest form.

```python
ll_x_ind_w = bern_ll_w(X_w)
ll_xy_direction1_w = bern_ll_w(X_w) + cond_bern_ll_w(X_w, Y_w)  # X root, Y child.
ll_xy_direction2_w = bern_ll_w(Y_w) + cond_bern_ll_w(Y_w, X_w)  # Y root, X child.
print("LL for X→Y factorization:", round(ll_xy_direction1_w, 6))
print("LL for Y→X factorization:", round(ll_xy_direction2_w, 6))
print("absolute difference:", round(abs(ll_xy_direction1_w - ll_xy_direction2_w), 10))
assert abs(ll_xy_direction1_w - ll_xy_direction2_w) < 1e-9
```
▶ What you'll see: the two directions have identical maximized likelihood on the same two-variable data.

```python
bic_xy_1_w = ll_xy_direction1_w - 0.5 * 3 * np.log(n_w)  # root has 1 parameter, child has 2.
bic_xy_2_w = ll_xy_direction2_w - 0.5 * 3 * np.log(n_w)  # same parameter count in reverse.
plt.figure(figsize=(4.2, 3))
plt.bar(["X→Y", "Y→X"], [bic_xy_1_w, bic_xy_2_w], color=["teal", "slateblue"])
plt.ylabel("BIC")
plt.title("6: equivalent two-node directions")
plt.show()
```
▶ What you'll see: equal-height bars; score alone cannot orient this edge.

*Why it's done this way:* structure learning from observational likelihood recovers dependency patterns, not necessarily causality. Direction needs asymmetries such as interventions, time order, forbidden edges, or v-structures; otherwise multiple DAGs encode the same observable claims.

## 🛠️ Setup

```python
import numpy as np  # load NumPy for counts, logs, random data, and graph-score calculations.
import matplotlib.pyplot as plt  # load Matplotlib for compact diagnostic plots.
np.random.seed(0)  # make all random examples reproducible across Colab runs.

def binary_ll(y):  # Compute the maximized Bernoulli log-likelihood for a binary vector.
    y = np.asarray(y, dtype=float)  # Convert input to float so logs and means are predictable.
    p = np.clip(np.mean(y), 1e-9, 1 - 1e-9)  # Estimate and clip the MLE probability to avoid log(0).
    return float(np.sum(y * np.log(p) + (1 - y) * np.log(1 - p)))  # Return the fitted Bernoulli log-likelihood.

def conditional_binary_ll(parent, child):  # Compute child|parent Bernoulli log-likelihood for one binary parent.
    parent = np.asarray(parent, dtype=int)  # Convert parent values to integer labels 0/1.
    child = np.asarray(child, dtype=float)  # Convert child values to floats for binary_ll.
    total = 0.0  # Accumulate one fitted Bernoulli likelihood per parent value.
    for value in [0, 1]:  # Loop over the two parent configurations.
        total += binary_ll(child[parent == value])  # Add the child likelihood inside this parent group.
    return float(total)  # Return the conditional log-likelihood.

def bic_score(ll, k, n):  # Compute BIC from fitted log-likelihood, parameter count, and sample size.
    return float(ll - 0.5 * k * np.log(n))  # Subtract the standard BIC complexity penalty.

def local_bic(parent, child):  # Score a binary child with no parent or one binary parent.
    n = len(child)  # Count samples for the BIC penalty.
    if parent is None:  # No-parent family has one Bernoulli parameter.
        return bic_score(binary_ll(child), 1, n)  # Score the marginal model.
    return bic_score(conditional_binary_ll(parent, child), 2, n)  # One binary parent creates two Bernoulli parameters.
```

### Advanced 5 — Use bootstrap edge stability

**Goal.** Resample the data and relearn candidate edges, because stable structure decisions are more trustworthy than one lucky split. We build it in 5 steps.

```python
X_a5 = X_e1.copy()  # Use the strong parent variable from Easy 1.
Y_a5 = Y_e1.copy()  # Use the strong child variable.
Z_a5 = np.r_[np.r_[np.zeros(22, dtype=int), np.ones(18, dtype=int)], np.r_[np.zeros(27, dtype=int), np.ones(33, dtype=int)]]  # Use the weak child variable aligned to X.
data_a5 = np.column_stack([X_a5, Y_a5, Z_a5])  # Combine variables into a resampling table.
print("data shape:", data_a5.shape)  # Inspect bootstrap source data.
```
▶ What you'll see: 100 rows and three variables ready for resampling.

```python
rng_a5 = np.random.default_rng(5)  # Create reproducible bootstrap randomness.
B_a5 = 80  # Choose the number of bootstrap resamples.
kept_xy_a5 = []  # Store whether X→Y is accepted in each resample.
kept_xz_a5 = []  # Store whether X→Z is accepted in each resample.
print("bootstrap samples:", B_a5)  # Inspect the resampling count.
```

```python
for b_a5 in range(B_a5):  # Repeat structure decisions on resampled datasets.
    idx_a5 = rng_a5.integers(0, len(data_a5), size=len(data_a5))  # Sample rows with replacement.
    boot_a5 = data_a5[idx_a5]  # Build the bootstrap data table.
    Xb_a5, Yb_a5, Zb_a5 = boot_a5[:, 0], boot_a5[:, 1], boot_a5[:, 2]  # Split variables.
    kept_xy_a5.append(local_bic(Xb_a5, Yb_a5) - local_bic(None, Yb_a5) > 0)  # Record X→Y decision.
    kept_xz_a5.append(local_bic(Xb_a5, Zb_a5) - local_bic(None, Zb_a5) > 0)  # Record X→Z decision.
stability_a5 = np.array([np.mean(kept_xy_a5), np.mean(kept_xz_a5)])  # Compute selection frequencies.
print("selection frequencies [X→Y, X→Z]:", np.round(stability_a5, 3))  # Inspect edge stability.
```

