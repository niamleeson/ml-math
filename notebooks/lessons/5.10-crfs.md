# 5.10 — Conditional Random Fields

Conditional Random Fields (CRFs) are discriminative sequence models: instead of explaining how observations were generated, they score whole label sequences directly conditioned on the observed input. In this lesson, we build a tiny linear-chain CRF from NumPy arrays, inspect every score, normalize with a sequence-level partition function, and decode the best label path.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build conditional random fields one idea at a time. Run each cell in order and read the printed intermediate values — every score, normalization, dynamic program, and decoding choice is exposed. This walkthrough is self-contained and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays, exponentials, and dynamic programming tables.
import matplotlib.pyplot as plt  # compact visualizations for scores and paths.
np.random.seed(0)  # reproducibility for every small stochastic check.
```

### 1. Observations, labels, and local feature scores

A linear-chain CRF starts with an observed sequence `x` and a candidate label sequence `y`. The model does not try to generate `x`; it asks how compatible each possible `y` is with this particular `x`. We begin with two labels, `0` and `1`, and a length-3 input whose unary evidence is positive when label `1` looks plausible and negative when label `0` looks plausible.

```python
x_w = np.array([1.0, -0.5, 0.8])  # observed token features: positive tends to support label 1.
labels_w = np.array([0, 1])  # two possible labels at each position.
unary_weight_w = 1.0  # strength of observation evidence.
unary_w = np.vstack([-unary_weight_w * x_w, unary_weight_w * x_w]).T  # rows=time, cols=label.
print("x:", x_w)
print("unary scores by time,label:\n", unary_w)
assert unary_w.shape == (3, 2)
```
▶ What you'll see: each time step has two local scores; at the middle token, label 0 is favored because `x=-0.5`.

```python
plt.figure(figsize=(4.4, 3))
plt.imshow(unary_w, cmap="coolwarm", aspect="auto")
plt.colorbar(label="unary score")
plt.xticks([0, 1], ["label 0", "label 1"]); plt.yticks([0, 1, 2], ["t0", "t1", "t2"])
plt.title("1: local evidence scores")
plt.show()
```
▶ What you'll see: red/blue evidence flips by token; CRF decoding will decide whether transitions should override one local preference.

*Why it's done this way:* A CRF can use arbitrary, overlapping features of the input because it only models $p(y\mid x)$. Unary scores are the simplest feature: they say how much the observed token at time $t$ supports each label before we consider neighboring labels.

### 2. Transition features couple neighboring labels

Sequence labels are not independent. In named-entity tagging, part-of-speech tagging, and segmentation, labels usually prefer smooth or legal transitions. We encode that with a transition score matrix: staying in the same label gets a reward, switching gets no reward here.

```python
transition_w = np.array([[0.9315064901562538, 0.0],
                         [0.0, 0.9315064901562538]])  # reward same-label transitions.
y_demo_w = np.array([1, 0, 1])  # a path that switches twice.
trans_terms_w = np.array([transition_w[y_demo_w[t-1], y_demo_w[t]] for t in range(1, len(y_demo_w))])
print("path:", y_demo_w)
print("transition terms:", trans_terms_w, "sum:", round(float(trans_terms_w.sum()), 3))
assert round(float(trans_terms_w.sum()), 3) == 0.0
```
▶ What you'll see: the path `1→0→1` earns no transition reward because it changes labels at both boundaries.

```python
y_smooth_w = np.array([1, 1, 1])
smooth_terms_w = np.array([transition_w[y_smooth_w[t-1], y_smooth_w[t]] for t in range(1, len(y_smooth_w))])
print("smooth path:", y_smooth_w)
print("transition terms:", smooth_terms_w, "sum:", round(float(smooth_terms_w.sum()), 3))
assert round(float(smooth_terms_w.sum()), 3) == 1.863
```
▶ What you'll see: the all-1 path receives two same-label rewards, totaling 1.863.

```python
plt.figure(figsize=(3.6, 3))
plt.imshow(transition_w, cmap="Greens", vmin=0, vmax=0.932)
plt.colorbar(label="transition score")
plt.xticks([0, 1], ["to 0", "to 1"]); plt.yticks([0, 1], ["from 0", "from 1"])
plt.title("2: transition rewards")
plt.show()
```
▶ What you'll see: the diagonal is bright because same-label transitions are rewarded.

*Why it's done this way:* Transitions are pairwise features $f(y_{t-1},y_t,x,t)$. They let the sequence model express beliefs like “labels persist” or “this transition is illegal,” which independent per-token classifiers cannot represent.

### 3. A whole-sequence score is unary evidence plus transitions

A CRF assigns an unnormalized score to an entire label path. For a candidate sequence, we add the unary score selected at each time and the transition score selected at each boundary. The exponential of this score becomes the unnormalized probability mass.

```python
def path_score_w(y_w, unary_w, transition_w):
    unary_sum_w = sum(unary_w[t, y_w[t]] for t in range(len(y_w)))
    trans_sum_w = sum(transition_w[y_w[t-1], y_w[t]] for t in range(1, len(y_w)))
    return float(unary_sum_w + trans_sum_w), float(unary_sum_w), float(trans_sum_w)

for y_w in [np.array([1, 0, 1]), np.array([1, 1, 1])]:
    total_w, unary_sum_w, trans_sum_w = path_score_w(y_w, unary_w, transition_w)
    print(y_w, "unary=", round(unary_sum_w, 3), "transition=", round(trans_sum_w, 3), "score=", round(total_w, 3))
assert round(path_score_w(np.array([1, 1, 1]), unary_w, transition_w)[0], 3) == 3.163
```
▶ What you'll see: `(1,1,1)` wins even though the middle token locally dislikes label 1, because transition smoothness compensates.

```python
paths_w = np.array(np.meshgrid(labels_w, labels_w, labels_w)).T.reshape(-1, 3)
scores_w = np.array([path_score_w(path_w, unary_w, transition_w)[0] for path_w in paths_w])
print("all paths and scores:")
for path_w, score_w in zip(paths_w, scores_w):
    print(tuple(path_w), round(float(score_w), 3))
```
▶ What you'll see: all $2^3=8$ path scores are small enough to inspect by hand.

*Why it's done this way:* Adding feature weights keeps the model linear in features, but the features can depend on adjacent labels and on the whole observed input. Exponentiating later turns these additive energies into positive probability mass.

### 4. Conditional normalization: the partition function $Z(x)$

The raw sequence scores are not probabilities. To get $p(y\mid x)$, we exponentiate every path score and divide by the sum over all possible label sequences. That sum is the conditional partition function $Z(x)$.

```python
unnormalized_w = np.exp(scores_w)
Z_w = float(np.sum(unnormalized_w))
probs_w = unnormalized_w / Z_w
print("Z(x):", round(Z_w, 6))
print("probabilities:", np.round(probs_w, 4))
print("sum probabilities:", round(float(probs_w.sum()), 6))
assert round(Z_w, 6) == 47.151013
assert round(float(probs_w.sum()), 6) == 1.0
```
▶ What you'll see: `Z(x)=47.151013`, and the normalized probabilities sum to exactly 1.

```python
plt.figure(figsize=(5.2, 3))
plt.bar(["".join(map(str, p)) for p in paths_w], probs_w, color="teal")
plt.ylabel("p(y | x)"); plt.xlabel("label path")
plt.title("4: CRF distribution over complete paths")
plt.show()
```
▶ What you'll see: probability mass concentrates on smooth paths with strong unary support, especially `111`.

*Why it's done this way:* The normalization is conditional because $Z$ depends on the observed sequence $x$. That is the discriminative move: the model never needs $p(x)$, but it must normalize across all label paths for this particular input.

### 5. Forward recursion computes $Z(x)$ without enumerating every path

Enumeration works for length 3, but a length-50 binary sequence has $2^{50}$ paths. The forward algorithm reuses partial sums: the total mass of paths ending in each label at time $t$ is enough to extend to time $t+1$.

```python
alpha_w = np.exp(unary_w[0])  # masses for paths ending at each label at t=0.
print("alpha t=0:", np.round(alpha_w, 4))
for t_w in range(1, len(x_w)):
    next_alpha_w = np.zeros_like(alpha_w)
    for y_w in labels_w:
        next_alpha_w[y_w] = np.exp(unary_w[t_w, y_w]) * np.sum(alpha_w * np.exp(transition_w[:, y_w]))
    alpha_w = next_alpha_w
    print(f"alpha t={t_w}:", np.round(alpha_w, 4))
Z_forward_w = float(np.sum(alpha_w))
print("forward Z:", round(Z_forward_w, 6))
assert round(Z_forward_w, 6) == 47.151013
```
▶ What you'll see: the forward `Z` matches enumeration, but it uses a compact table instead of listing all paths.

```python
plt.figure(figsize=(4.4, 3))
plt.bar(["end 0", "end 1"], alpha_w, color=["gray", "teal"])
plt.title("5: final forward masses")
plt.ylabel("unnormalized mass")
plt.show()
```
▶ What you'll see: most mass ends in label 1 because both final unary evidence and smooth transitions favor it.

*Why it's done this way:* The distributive law is doing the work: many complete paths share the same prefix ending label, so we sum those prefixes once and reuse them. This is message passing on the chain.

### 6. Viterbi decoding replaces sums with maxes

Sometimes we want the single best label sequence, not all probabilities. Viterbi uses the same dynamic-programming shape as forward, but replaces summing over previous labels with taking a maximum and storing backpointers.

```python
delta_w = unary_w[0].copy()  # best score ending in each label at t=0.
back_w = []
print("delta t=0:", np.round(delta_w, 3))
for t_w in range(1, len(x_w)):
    new_delta_w = np.zeros_like(delta_w)
    prev_choice_w = np.zeros_like(delta_w, dtype=int)
    for y_w in labels_w:
        candidates_w = delta_w + transition_w[:, y_w] + unary_w[t_w, y_w]
        prev_choice_w[y_w] = int(np.argmax(candidates_w))
        new_delta_w[y_w] = float(np.max(candidates_w))
    delta_w = new_delta_w
    back_w.append(prev_choice_w)
    print(f"delta t={t_w}:", np.round(delta_w, 3), "back:", prev_choice_w)
```
▶ What you'll see: each time step stores the best score ending in label 0 or label 1 and where it came from.

```python
best_last_w = int(np.argmax(delta_w))
best_path_w = [best_last_w]
for bp_w in back_w[::-1]:
    best_path_w.append(int(bp_w[best_path_w[-1]]))
best_path_w = np.array(best_path_w[::-1])
print("best path:", best_path_w, "score:", round(float(np.max(delta_w)), 3))
assert np.all(best_path_w == np.array([1, 1, 1]))
```
▶ What you'll see: Viterbi returns `(1,1,1)`, matching the worked arithmetic.

*Why it's done this way:* Forward answers “how much total probability mass exists?” by summing paths. Viterbi answers “which path has maximum score?” by keeping only the best predecessor at each local state.

### 7. Learning signal: observed features minus expected features

CRF training increases the score of the gold label sequence and decreases scores of competing paths. For a feature weight, the log-likelihood gradient is the feature count under the gold path minus its expected count under the model distribution.

```python
gold_w = np.array([1, 0, 1])  # pretend these are the true labels.
gold_same_w = sum(gold_w[t-1] == gold_w[t] for t in range(1, len(gold_w)))
model_same_w = 0.0
for path_w, prob_w in zip(paths_w, probs_w):
    same_count_w = sum(path_w[t-1] == path_w[t] for t in range(1, len(path_w)))
    model_same_w += prob_w * same_count_w
print("gold same-transition count:", gold_same_w)
print("model expected same-transition count:", round(float(model_same_w), 3))
print("gradient for same-transition weight:", round(float(gold_same_w - model_same_w), 3))
assert gold_same_w == 0
```
▶ What you'll see: because the gold path switches twice but the model likes smoothness, the gradient for the same-transition reward is negative.

```python
plt.figure(figsize=(4.4, 3))
plt.bar(["gold count", "model expectation"], [gold_same_w, model_same_w], color=["black", "orange"])
plt.title("7: CRF gradient intuition")
plt.ylabel("same-transition feature count")
plt.show()
```
▶ What you'll see: the model expects more same transitions than the gold path contains, so learning should weaken that feature.

*Why it's done this way:* The partition function couples all paths, so changing one weight changes both the gold score and the normalization. The gradient’s “gold minus expected” form is exactly the correction for that normalization.

### Basic 5 — Turn scores into probabilities

**Goal.** Exponentiate and normalize path scores, because CRF probabilities are $e^{s(y)}/Z(x)$. We build it in 3 steps.

```python
x_b5 = np.array([1.0, -0.5, 0.8]) # define observed sequence.
unary_b5 = np.vstack([-x_b5, x_b5]).T # compute label evidence.
transition_b5 = np.array([[0.9315064901562538, 0.0], [0.0, 0.9315064901562538]]) # define smooth transitions.
paths_b5 = np.array(np.meshgrid([0, 1], [0, 1], [0, 1])).T.reshape(-1, 3) # enumerate all paths.
print("paths:", len(paths_b5)) # inspect path count.
```
▶ What you'll see: there are eight paths to score and normalize.

```python
scores_b5 = [] # store one score per path.
for path_b5 in paths_b5: # loop over candidate label sequences.
    unary_sum_b5 = sum(unary_b5[t, path_b5[t]] for t in range(3)) # add selected unary terms.
    trans_sum_b5 = sum(transition_b5[path_b5[t-1], path_b5[t]] for t in range(1, 3)) # add selected transition terms.
    scores_b5.append(unary_sum_b5 + trans_sum_b5) # store total path score.
scores_b5 = np.array(scores_b5) # convert scores to a NumPy array.
Z_b5 = float(np.sum(np.exp(scores_b5))) # compute partition function by enumeration.
probs_b5 = np.exp(scores_b5) / Z_b5 # normalize into probabilities.
print("Z_b5:", round(Z_b5, 6), "prob sum:", round(float(probs_b5.sum()), 6)) # inspect normalization.
assert round(Z_b5, 6) == 47.151013 # verify the canonical partition value.
```
▶ What you'll see: the printed values or plot expose the intermediate CRF quantity being built in this cell.

```python
plt.figure(figsize=(5, 3)) # create probability bar chart.

plt.show() # display the distribution.
```
▶ What you'll see: all path probabilities sum to one, with `111` among the largest.

👀 Takeaway: sequence-level normalization turns arbitrary path scores into a conditional distribution.

### Basic 7 — Compute the partition with forward recursion

**Goal.** Recompute $Z(x)$ with dynamic programming, because enumeration becomes impossible for long sequences. We build it in 3 steps.

```python
x_b7 = np.array([1.0, -0.5, 0.8]) # define observed sequence.
unary_b7 = np.vstack([-x_b7, x_b7]).T # compute unary scores.
transition_b7 = np.array([[0.9315064901562538, 0.0], [0.0, 0.9315064901562538]]) # define transition scores.
alpha_b7 = np.exp(unary_b7[0]) # initialize forward masses at t=0.
print("alpha start:", np.round(alpha_b7, 4)) # inspect initial masses.
```
▶ What you'll see: two starting masses, one for each first label.

```python
history_b7 = [alpha_b7.copy()] # keep all alphas for plotting.
for t_b7 in range(1, 3): # extend the chain one position at a time.
    new_alpha_b7 = np.zeros(2) # allocate next forward message.
    for y_b7 in range(2): # compute mass ending in each current label.
        new_alpha_b7[y_b7] = np.exp(unary_b7[t_b7, y_b7]) * np.sum(alpha_b7 * np.exp(transition_b7[:, y_b7])) # sum over previous labels.
    alpha_b7 = new_alpha_b7 # advance the message.
    history_b7.append(alpha_b7.copy()) # store the current message.
Z_forward_b7 = float(alpha_b7.sum()) # sum final masses to get Z.
print("forward Z:", round(Z_forward_b7, 6)) # inspect dynamic-programming partition.
```

```python
assert np.all(loglikes_a2 < 0) # probabilities are below 1, so logs are negative.
```

### Advanced 4 — Forward-backward edge marginals

**Goal.** Estimate expected transition counts with forward and backward messages, because gradients need feature expectations without path enumeration. We build it in 4 steps.

```python

transition_a4 = np.array([[0.9315064901562538, 0.0], [0.0, 0.9315064901562538]]) # define transition scores.

alpha_hist_a4 = [alpha_a4.copy()] # store forward messages.
print("start alpha:", np.round(alpha_a4, 3)) # inspect start.
```
▶ What you'll see: forward messages begin with exponentiated first-token unary scores.

```python

    alpha_a4 = np.exp(unary_a4[t_a4]) * np.array([np.sum(alpha_a4 * np.exp(transition_a4[:, y_a4])) for y_a4 in range(2)]) # update alpha.
    alpha_hist_a4.append(alpha_a4.copy()) # store alpha.
beta_a4 = np.ones(2) # initialize backward masses at final time.
beta_hist_a4 = [None, None, beta_a4.copy()] # allocate backward history.
for t_a4 in range(1, -1, -1): # move backward from t to t+1.
    beta_a4 = np.array([np.sum(np.exp(transition_a4[y_a4, :] + unary_a4[t_a4 + 1, :] ) * beta_a4) for y_a4 in range(2)]) # update beta.
    beta_hist_a4[t_a4] = beta_a4.copy() # store beta.
Z_a4 = float(np.sum(alpha_hist_a4[-1])) # compute partition.
print("Z:", round(Z_a4, 6)) # inspect partition.
assert round(Z_a4, 6) == 47.151013 # verify known partition.
```
▶ What you'll see: the printed values or plot expose the intermediate CRF quantity being built in this cell.

