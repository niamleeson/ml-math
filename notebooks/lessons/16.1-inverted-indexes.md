# 16.1 — Inverted Indexes

An inverted index is the first data structure behind fast keyword retrieval: it flips a corpus from “document → terms” into “term → documents,” so a query jumps straight to the postings lists that could contain its answer. In this lesson, you will build tokenization, postings lists, Boolean retrieval, skip pointers, and simple frequency signals from scratch using only Python, NumPy, and Matplotlib.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build inverted indexes one idea at a time. Run each cell in order and read the printed intermediate values — the point is to see how raw text becomes sorted postings lists, how Boolean queries become set arithmetic, and why the exact data layout matters for speed. This walkthrough is self-contained and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import re  # tokenization with regular expressions.
from collections import defaultdict, Counter  # dictionaries of postings and term counts.
import numpy as np  # arrays, logs, and compact numerical checks.
import matplotlib.pyplot as plt  # walkthrough visualizations.
np.random.seed(0)  # reproducibility for any stochastic examples.
```

### 1. Tokenization and normalization

An inverted index can only index **terms**, not raw strings. Tokenization cuts text into pieces, and normalization makes equivalent surface forms share one key: `Search`, `search!`, and `SEARCH` should all become `search`. This is not cosmetic; if normalization splits one idea into many keys, recall drops because a query touches only the key it asks for.

```python
corpus_w = [
    "Neural search retrieves documents.",
    "Graph search links documents.",
    "Neural retrieval uses embeddings.",
    "Graph retrieval improves search."
]

def tokenize_w(text_w):
    return re.findall(r"[a-z]+", text_w.lower())

for i_w, doc_w in enumerate(corpus_w, start=1):
    print(i_w, tokenize_w(doc_w))
```
▶ What you'll see: punctuation and capitalization disappear, leaving lowercase term lists for the four documents.

```python
raw_terms_w = re.findall(r"\w+", "Search, search, SEARCH!")
norm_terms_w = tokenize_w("Search, search, SEARCH!")
print("raw tokens:", raw_terms_w)
print("normalized tokens:", norm_terms_w)
assert norm_terms_w == ["search", "search", "search"]
```
▶ What you'll see: three different surface forms collapse into one index key, `search`.

*Why it's done this way:* Boolean retrieval is exact key matching. The index cannot know that `Search` and `search` should match unless we choose a normalization rule before indexing and apply the same rule to queries.

### 2. Postings lists: flipping documents into term → documents

A document-term table says which terms are inside each document, but search wants the reverse question: “which documents contain this term?” The inverted index stores that answer as a **postings list** `P(t)`. For Boolean retrieval, each document id should appear once per term, even if the term occurs multiple times in the document; counts are stored separately when ranking needs them.

```python
doc_terms_w = [set(tokenize_w(doc_w)) for doc_w in corpus_w]
index_w = defaultdict(list)
for doc_id_w, terms_w in enumerate(doc_terms_w, start=1):
    for term_w in terms_w:
        index_w[term_w].append(doc_id_w)
index_w = {term_w: sorted(postings_w) for term_w, postings_w in sorted(index_w.items())}
print(index_w)
assert index_w["neural"] == [1, 3]
assert index_w["search"] == [1, 2, 4]
```
▶ What you'll see: `neural → [1, 3]`, `search → [1, 2, 4]`, `graph → [2, 4]`, and `retrieval → [1, 3, 4]` for this normalized corpus.

```python
terms_w = list(index_w)
lengths_w = [len(index_w[t_w]) for t_w in terms_w]
plt.figure(figsize=(5, 3))
plt.bar(terms_w, lengths_w, color="teal")
plt.title("1: document frequency from postings length")
plt.ylabel("df(t) = |P(t)|")
plt.xticks(rotation=20)
plt.show()
```
▶ What you'll see: common terms have taller bars because they appear in more documents.

*Why it's done this way:* The inverted index pays the cost of scanning documents once during construction, then future queries touch only the few postings lists for their terms. The postings length is already the document frequency `df(t)`, which becomes a ranking clue later.

### 3. Boolean retrieval is set arithmetic

Once each term maps to a set of document ids, Boolean queries become ordinary set operations. `AND` is intersection, `OR` is union, and `NOT` is complement against the universe of all document ids. This gives exact candidates quickly, but not a ranking: every returned document is tied unless we add a scoring rule.

```python
universe_w = set(range(1, len(corpus_w) + 1))
search_w = set(index_w["search"])
graph_w = set(index_w["graph"])
neural_w = set(index_w["neural"])
retrieval_w = set(index_w["retrieval"])
print("search AND graph:", sorted(search_w & graph_w))
print("neural OR retrieval:", sorted(neural_w | retrieval_w))
print("NOT search:", sorted(universe_w - search_w))
assert sorted(search_w & graph_w) == [2, 4]
assert sorted(neural_w | retrieval_w) == [1, 3, 4]
assert sorted(universe_w - search_w) == [3]
```
▶ What you'll see: the exact lesson-style answers `{2,4}`, `{1,3,4}`, and `{3}`.

```python
query_terms_w = ["search", "graph"]
hit_matrix_w = np.array([[int(term_w in doc_terms_w[d_w]) for term_w in query_terms_w] for d_w in range(len(doc_terms_w))])
plt.figure(figsize=(4, 3))
plt.imshow(hit_matrix_w, cmap="Greens", aspect="auto")
plt.xticks(range(2), query_terms_w)
plt.yticks(range(4), [f"d{i}" for i in range(1, 5)])
plt.title("2: AND means both columns are 1")
plt.show()
```
▶ What you'll see: documents 2 and 4 have both query-term indicators turned on.

*Why it's done this way:* Sets encode membership exactly, so Boolean logic becomes algebra over ids. The limitation is also clear: a document about “semantic matching” but without the query terms is invisible to this exact-match filter.

### 4. Sorted postings make AND a linear merge

The main speed trick is not a complicated model; it is keeping postings sorted. To compute `P(a) ∩ P(b)`, two pointers walk left-to-right. If one id is smaller, only that pointer advances; if ids match, the id is emitted and both pointers advance. This is linear in the list lengths, not nested comparison.

```python
def intersect_w(a_w, b_w):
    i_w = j_w = 0
    out_w = []
    trace_w = []
    while i_w < len(a_w) and j_w < len(b_w):
        trace_w.append((a_w[i_w], b_w[j_w]))
        if a_w[i_w] == b_w[j_w]:
            out_w.append(a_w[i_w]); i_w += 1; j_w += 1
        elif a_w[i_w] < b_w[j_w]:
            i_w += 1
        else:
            j_w += 1
    return out_w, trace_w

hits_w, trace_w = intersect_w(index_w["search"], index_w["graph"])
print("comparisons:", trace_w)
print("intersection:", hits_w)
assert hits_w == [2, 4]
```
▶ What you'll see: only three pairwise comparisons are needed to intersect `[1,2,4]` with `[2,4]`.

```python
cost_nested_w = len(index_w["search"]) * len(index_w["graph"])
cost_merge_w = len(trace_w)
plt.figure(figsize=(4, 3))
plt.bar(["nested", "two-pointer"], [cost_nested_w, cost_merge_w], color=["crimson", "seagreen"])
plt.title("3: sorted merge avoids nested checks")
plt.ylabel("comparisons")
plt.show()
```
▶ What you'll see: even in a tiny example, sorted merge performs fewer checks than trying every pair.

*Why it's done this way:* Sorted order gives the algorithm permission to skip impossible matches. If `1 < 2`, document 1 cannot match the current `2`, so advancing the smaller pointer loses nothing and saves work.

### 5. Skip pointers jump over long nonmatching stretches

For long postings lists, a merge can move one id at a time through a long stretch that is too small to match. A **skip pointer** stores a jump from one position to a later position in the same sorted list. During intersection, if the skip target is still no larger than the other list's current id, the algorithm jumps; otherwise it advances normally.

```python
long_a_w = [1, 2, 3, 4, 8, 12, 16]
long_b_w = [8, 16]
skips_w = {0: 3, 3: 4, 4: 5, 5: 6}  # position -> later position in long_a_w.

def intersect_with_skips_w(a_w, b_w, skips_w):
    i_w = j_w = 0
    out_w, actions_w = [], []
    while i_w < len(a_w) and j_w < len(b_w):
        if a_w[i_w] == b_w[j_w]:
            out_w.append(a_w[i_w]); actions_w.append(("match", a_w[i_w])); i_w += 1; j_w += 1
        elif a_w[i_w] < b_w[j_w]:
            if i_w in skips_w and a_w[skips_w[i_w]] <= b_w[j_w]:
                actions_w.append(("skip", a_w[i_w], a_w[skips_w[i_w]])); i_w = skips_w[i_w]
            else:
                actions_w.append(("advance", a_w[i_w])); i_w += 1
        else:
            actions_w.append(("advance b", b_w[j_w])); j_w += 1
    return out_w, actions_w

out_skip_w, actions_w = intersect_with_skips_w(long_a_w, long_b_w, skips_w)
print("actions:", actions_w)
print("intersection:", out_skip_w)
assert out_skip_w == [8, 16]
```
▶ What you'll see: the algorithm jumps from 1 to 4 and then to 8 instead of checking every small id one by one.

```python
no_skip_hits_w, no_skip_trace_w = intersect_w(long_a_w, long_b_w)
skip_checks_w = len(actions_w)
plain_checks_w = len(no_skip_trace_w)
plt.figure(figsize=(4, 3))
plt.bar(["plain merge", "with skips"], [plain_checks_w, skip_checks_w], color=["gray", "orange"])
plt.title("4: skip pointers reduce pointer moves")
plt.ylabel("recorded actions")
plt.show()
```
▶ What you'll see: the skip-pointer version records fewer actions on this deliberately gappy list.

*Why it's done this way:* A skip is safe only because postings are sorted. If the skip target is still ≤ the other current id, every skipped id is too small to match, so the jump preserves exactness while reducing work.

### 6. Term frequency, document frequency, and a first ranking clue

Boolean retrieval says which documents match, not which is best. Counts add the first ranking signals. **Term frequency** `tf(t,d)` counts how often a term appears in one document. **Document frequency** `df(t)=|P(t)|` counts how many documents contain the term. A simple inverse-document-frequency signal is `idf(t)=log(N/df(t))`, so rarer terms carry more discrimination.

```python
tf_w = [Counter(tokenize_w(doc_w)) for doc_w in corpus_w]
N_w = len(corpus_w)
df_w = {term_w: len(postings_w) for term_w, postings_w in index_w.items()}
idf_w = {term_w: np.log(N_w / df_w[term_w]) for term_w in df_w}
for term_w in ["neural", "search", "graph", "retrieval"]:
    print(term_w, "df=", df_w[term_w], "idf=", round(idf_w[term_w], 3))
assert round(idf_w["neural"], 3) == 0.693
assert round(idf_w["search"], 3) == 0.288
```
▶ What you'll see: `search` has lower idf because it appears in three documents, while rarer two-document terms have idf 0.693.

```python
query_w = ["neural", "search"]
scores_w = []
for doc_id_w in range(1, N_w + 1):
    score_w = sum(tf_w[doc_id_w - 1][term_w] * idf_w.get(term_w, 0.0) for term_w in query_w)
    scores_w.append(score_w)
print("tf-idf-like scores:", np.round(scores_w, 3))
plt.figure(figsize=(4, 3))
plt.bar([f"d{i}" for i in range(1, 5)], scores_w, color="purple")
plt.title("5: rare matching terms lift score")
plt.ylabel("sum tf×idf")
plt.show()
```
▶ What you'll see: documents containing both `neural` and `search` score higher than those matching only the common term.

*Why it's done this way:* `df` tells us how selective a term is. Dividing `N` by `df` and taking a log turns “rare terms narrow the candidate set more” into a numerical weight, which BM25 refines in the next lesson.

### ✍️ Toy 2 · Flip documents into postings lists

A postings list is just the document ids where a term is present. Build it from a tiny document-term
presence matrix.

```python
import numpy as np

t2_rng = np.random.default_rng(0)
print("rng seed:", 0)  # -> 0
t2_vocab = np.array(["cat", "dog", "mat"])
print("vocab:", t2_vocab.tolist())  # -> ['cat', 'dog', 'mat']
t2_docs = [["cat", "mat"], ["dog", "cat"], ["dog"]]
print("docs:", t2_docs)  # -> [['cat', 'mat'], ['dog', 'cat'], ['dog']]
t2_present = np.array([[int(t2_term in t2_doc) for t2_term in t2_vocab] for t2_doc in t2_docs])
print("presence matrix:", t2_present.tolist())  # -> [[1, 0, 1], [1, 1, 0], [0, 1, 0]]
t2_doc_ids = np.arange(1, len(t2_docs) + 1)

t2_postings = {str(t2_vocab[t2_j]): t2_doc_ids[t2_present[:, t2_j] == 1].tolist() for t2_j in range(len(t2_vocab))}
print("postings:", t2_postings)  # -> {'cat': [1, 2], 'dog': [2, 3], 'mat': [1]}
t2_df = t2_present.sum(axis=0)
```

### ✍️ Toy 3 · Boolean retrieval is set arithmetic

Once postings are arrays of ids, `AND`, `OR`, and `NOT` are intersection, union, and complement.

```python
import numpy as np

t3_rng = np.random.default_rng(0)
print("rng seed:", 0)  # -> 0
t3_search = np.array([1, 2, 4])
print("P(search):", t3_search.tolist())  # -> [1, 2, 4]
t3_graph = np.array([2, 4])
print("P(graph):", t3_graph.tolist())  # -> [2, 4]
t3_universe = np.array([1, 2, 3, 4])
print("universe:", t3_universe.tolist())  # -> [1, 2, 3, 4]
t3_and = np.intersect1d(t3_search, t3_graph)
print("search AND graph:", t3_and.tolist())  # -> [2, 4]
t3_or = np.union1d(t3_search, t3_graph)
print("search OR graph:", t3_or.tolist())  # -> [1, 2, 4]
t3_not = np.setdiff1d(t3_universe, t3_search)
print("NOT search:", t3_not.tolist())  # -> [3]
assert t3_and.tolist() == [2, 4]
assert t3_not.tolist() == [3]

t3_hit_matrix = np.array([[int(t3_doc in t3_search), int(t3_doc in t3_graph)] for t3_doc in t3_universe])
print("hit matrix:", t3_hit_matrix.tolist())  # -> [[1, 0], [1, 1], [0, 0], [1, 1]]
plt.figure(figsize=(4.0, 3.0))
plt.imshow(t3_hit_matrix, cmap="Blues", aspect="auto")
plt.xticks([0, 1], ["search", "graph"])
plt.yticks(range(4), ["d1", "d2", "d3", "d4"])
plt.title("Toy 3 · AND keeps rows with two 1s")
plt.show()
```
▶ What you'll see: only documents 2 and 4 have both query-term indicators turned on.

### ✍️ Toy 4 · Sorted AND uses two moving pointers

The two-pointer merge compares current ids and advances only the smaller side until matches appear.

```python
import numpy as np

t4_rng = np.random.default_rng(0)
print("rng seed:", 0)  # -> 0
t4_a = np.array([1, 3, 5, 7])
print("left postings:", t4_a.tolist())  # -> [1, 3, 5, 7]
t4_b = np.array([3, 4, 7])
print("right postings:", t4_b.tolist())  # -> [3, 4, 7]
t4_i = 0
t4_j = 0
t4_hits = []
t4_trace = []
while t4_i < len(t4_a) and t4_j < len(t4_b):
    t4_pair = (int(t4_a[t4_i]), int(t4_b[t4_j]))
    t4_trace.append(t4_pair)
    if t4_a[t4_i] == t4_b[t4_j]:
        t4_hits.append(int(t4_a[t4_i]))
        t4_i = t4_i + 1
        t4_j = t4_j + 1
    elif t4_a[t4_i] < t4_b[t4_j]:
        t4_i = t4_i + 1
    else:
        t4_j = t4_j + 1
print("comparisons:", t4_trace)  # -> [(1, 3), (3, 3), (5, 4), (5, 7), (7, 7)]
print("intersection:", t4_hits)  # -> [3, 7]
t4_nested_cost = len(t4_a) * len(t4_b)
print("nested comparison count:", t4_nested_cost)  # -> 12
t4_merge_cost = len(t4_trace)
print("merge comparison count:", t4_merge_cost)  # -> 5
assert t4_hits == [3, 7]
assert t4_merge_cost < t4_nested_cost

plt.figure(figsize=(4.2, 2.8))
plt.bar(["nested", "merge"], [t4_nested_cost, t4_merge_cost], color=["#e45756", "#54a24b"])
plt.ylabel("comparisons")
plt.title("Toy 4 · sorted merge skips pairs")
plt.show()
```
▶ What you'll see: sorted merge checks 5 pairs instead of all 12 nested pairs.

### ✍️ Toy 5 · Skip pointers jump over safe stretches

A skip pointer is safe when its target id is still no larger than the other postings list's current id.

```python
import numpy as np

t5_rng = np.random.default_rng(0)
print("rng seed:", 0)  # -> 0
t5_a = np.array([1, 2, 3, 4, 8, 12])
print("long postings:", t5_a.tolist())  # -> [1, 2, 3, 4, 8, 12]
t5_b = np.array([8, 12])
print("short postings:", t5_b.tolist())  # -> [8, 12]
t5_skips = {0: 3, 3: 4, 4: 5}
print("skip pointers:", t5_skips)  # -> {0: 3, 3: 4, 4: 5}
t5_i = 0
t5_j = 0
t5_hits = []
t5_actions = []
while t5_i < len(t5_a) and t5_j < len(t5_b):
    if t5_a[t5_i] == t5_b[t5_j]:
        t5_hits.append(int(t5_a[t5_i]))
        t5_actions.append(("match", int(t5_a[t5_i])))
        t5_i = t5_i + 1
        t5_j = t5_j + 1
    elif t5_a[t5_i] < t5_b[t5_j]:
        t5_target = t5_skips.get(t5_i)
        if t5_target is not None and t5_a[t5_target] <= t5_b[t5_j]:
            t5_actions.append(("skip", int(t5_a[t5_i]), int(t5_a[t5_target])))
            t5_i = t5_target
        else:
            t5_actions.append(("advance", int(t5_a[t5_i])))
            t5_i = t5_i + 1
    else:
        t5_actions.append(("advance b", int(t5_b[t5_j])))
        t5_j = t5_j + 1
print("skip actions:", t5_actions)  # -> [('skip', 1, 4), ('skip', 4, 8), ('match', 8), ('match', 12)]
print("intersection:", t5_hits)  # -> [8, 12]
t5_plain_i = 0
t5_plain_j = 0
t5_plain_trace = []
while t5_plain_i < len(t5_a) and t5_plain_j < len(t5_b):
    t5_plain_trace.append((int(t5_a[t5_plain_i]), int(t5_b[t5_plain_j])))
    if t5_a[t5_plain_i] == t5_b[t5_plain_j]:
        t5_plain_i = t5_plain_i + 1
        t5_plain_j = t5_plain_j + 1
    elif t5_a[t5_plain_i] < t5_b[t5_plain_j]:
        t5_plain_i = t5_plain_i + 1
    else:
        t5_plain_j = t5_plain_j + 1
print("plain comparisons:", len(t5_plain_trace))  # -> 6
print("skip actions count:", len(t5_actions))  # -> 4
assert t5_hits == [8, 12]
assert len(t5_actions) < len(t5_plain_trace)

plt.figure(figsize=(4.2, 2.8))
plt.bar(["plain", "with skips"], [len(t5_plain_trace), len(t5_actions)], color=["gray", "#f58518"])
plt.ylabel("recorded actions")
plt.title("Toy 5 · jumps reduce pointer work")
plt.show()
```
▶ What you'll see: the skip version jumps 1→4→8 before matching, using fewer actions than plain merge.

### ✍️ Toy 6 · TF, DF, and IDF make a first ranking score

Counts say how often a query term appears; document frequency says how rare it is. Multiplying them
creates a tiny tf-idf ranking clue.

```python
import numpy as np

t6_rng = np.random.default_rng(0)
print("rng seed:", 0)  # -> 0
t6_vocab = np.array(["apple", "banana", "cherry"])
print("vocab:", t6_vocab.tolist())  # -> ['apple', 'banana', 'cherry']
t6_counts = np.array([[2, 1, 0], [0, 1, 1], [0, 1, 0]], dtype=float)
print("term counts:", t6_counts.astype(int).tolist())  # -> [[2, 1, 0], [0, 1, 1], [0, 1, 0]]
t6_df = (t6_counts > 0).sum(axis=0)
print("document frequencies:", t6_df.tolist())  # -> [1, 3, 1]
t6_idf = np.log(t6_counts.shape[0] / t6_df)
print("idf weights:", np.round(t6_idf, 3).tolist())  # -> [1.099, 0.0, 1.099]
t6_query = np.array([1, 0, 1], dtype=float)
print("query mask:", t6_query.astype(int).tolist())  # -> [1, 0, 1]
t6_weighted = t6_counts * t6_idf * t6_query
print("weighted term evidence:", np.round(t6_weighted, 3).tolist())  # -> [[2.197, 0.0, 0.0], [0.0, 0.0, 1.099], [0.0, 0.0, 0.0]]
```

## 🛠️ Setup

```python
import re  # Use regex tokenization to normalize toy document text into lowercase terms.
from collections import defaultdict, Counter  # Use defaultdict for postings construction and Counter for term frequencies.
import numpy as np  # Use NumPy for arrays, logs, sorting checks, and compact numerical assertions.
import matplotlib.pyplot as plt  # Use Matplotlib for heatmaps, bars, and line plots that make index behavior visible.
np.random.seed(0)  # Make all stochastic examples reproducible.

def tokenize(text):
    return re.findall(r"[a-z]+", text.lower())

def build_index(docs):
    postings = defaultdict(list)
    tfs = []
    for doc_id, doc in enumerate(docs, start=1):
        tokens = tokenize(doc)
        tfs.append(Counter(tokens))
        for term in sorted(set(tokens)):
            postings[term].append(doc_id)
    return {term: postings[term] for term in sorted(postings)}, tfs

def intersect_sorted(a, b):
    i = j = 0
    out = []
    while i < len(a) and j < len(b):
        if a[i] == b[j]:
            out.append(a[i]); i += 1; j += 1
        elif a[i] < b[j]:
            i += 1
        else:
            j += 1
    return out

def union_sorted(a, b):
    return sorted(set(a) | set(b))

def show_posting_lengths(index, title):
    terms = list(index.keys())
    lengths = [len(index[t]) for t in terms]
    plt.figure(figsize=(5, 3))
    plt.bar(terms, lengths, color="teal")
    plt.title(title)
    plt.ylabel("postings length")
    plt.xticks(rotation=25)
    plt.show()
```

### Advanced 1 — Add skip pointers to intersection

**Goal.** Use skip pointers during intersection, because long postings lists often contain runs that can be jumped over safely. We build it in 4 steps.

```python
a_a1 = [1, 2, 3, 4, 8, 12, 16, 20, 24]
b_a1 = [8, 16, 24]
skips_a1 = {0: 3, 3: 4, 4: 6, 6: 8}  # Store safe forward jumps by position in a_a1.
print("a:", a_a1, "b:", b_a1)  # Inspect postings lists.
print("skips:", {a_a1[k]: a_a1[v] for k, v in skips_a1.items()})  # Inspect skip values by doc id.
```
▶ What you'll see: skip links jump across increasing doc ids in the first postings list.

```python
def skip_intersect_a1(a, b, skips):
    i = j = 0
    out = []
    actions = []
    while i < len(a) and j < len(b):
        if a[i] == b[j]:
            out.append(a[i]); actions.append(("match", a[i])); i += 1; j += 1
        elif a[i] < b[j]:
            if i in skips and a[skips[i]] <= b[j]:
                actions.append(("skip", a[i], a[skips[i]])); i = skips[i]
            else:
                actions.append(("advance a", a[i])); i += 1
        else:
            actions.append(("advance b", b[j])); j += 1
    return out, actions
print("skip merge function ready")  # Confirm helper definition.
```

```python
hits_a1, actions_a1 = skip_intersect_a1(a_a1, b_a1, skips_a1)  # Intersect using skip pointers.
plain_a1 = intersect_sorted(a_a1, b_a1)  # Intersect without explicit skips.
print("actions:", actions_a1)  # Inspect jumps and matches.
print("hits:", hits_a1)  # Inspect exact intersection.
assert hits_a1 == plain_a1 == [8, 16, 24]  # Verify skip pointers preserve exactness.
```

```python
plt.figure(figsize=(4, 3))  # Create a compact action count plot.
plt.bar(["with skips", "matches"], [len(actions_a1), len(hits_a1)], color=["orange", "seagreen"])  # Summarize skip intersection behavior.
plt.title("A1: skip-pointer intersection")  # Title the plot.
plt.ylabel("count")  # Label count axis.
plt.show()  # Display the chart.
```
▶ What you'll see: skips appear in the action trace, but the final intersection remains exact.

👀 Takeaway: skip pointers speed up sorted merges without changing Boolean answers.
