# 9.6 — Mixture-of-Experts Language Models

Mixture-of-Experts (MoE) language models make a Transformer wider without running every parameter on every token: a small router scores experts, keeps only the top few, normalizes their gates, and mixes their outputs. In this lesson, you will build that routing math from first principles with tiny NumPy arrays, inspect the exact numbers that decide which experts run, and see why load balancing and capacity are not implementation details but part of the model's behavior.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build sparse expert routing one idea at a time. Run each cell in order and read the printed intermediate values — every piece of math, including top-k renormalization and load balancing, is shown directly. This walkthrough is self-contained and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays + linear algebra for router scores, gates, and expert outputs.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
np.random.seed(0)  # reproducibility for any random toy weights.
```

### 1. Router logits become gates

An MoE layer starts with one token representation `x` and several candidate experts. The router computes one logit per expert, then applies softmax so those raw scores become nonnegative gates that sum to 1. The gates are not the expert outputs yet — they are the router's belief about how much each expert should contribute.

```python
logits_w = np.array([2.0, 1.0, 0.0])  # router scores for three experts on one token.
shifted_w = logits_w - np.max(logits_w)  # subtract the max before exp for numerical stability.
exp_w = np.exp(shifted_w)  # convert shifted logits into positive evidence.
gates_w = exp_w / np.sum(exp_w)  # normalize evidence into probabilities/gates.
print("logits:", logits_w)
print("softmax gates:", np.round(gates_w, 3), "sum=", round(float(gates_w.sum()), 3))
assert np.allclose(np.round(gates_w, 3), [0.665, 0.245, 0.090])
```
▶ What you'll see: logits `[2, 1, 0]` become gates `[0.665, 0.245, 0.090]`, so expert 0 is preferred but the others still have nonzero mass.

```python
plt.figure(figsize=(4.4, 3))
plt.bar(["E0", "E1", "E2"], gates_w, color="teal")
plt.title("1: router softmax gates")
plt.ylabel("gate value")
plt.ylim(0, 1)
plt.show()
```
▶ What you'll see: the tallest bar is the selected-looking expert, but the distribution still sums to one across all experts.

*Why it's done this way: softmax turns arbitrary router logits into a comparable distribution. Subtracting the maximum leaves the ratios unchanged because every numerator and denominator is multiplied by the same constant, but it avoids overflow when logits are large.*

### 2. Top-k routing keeps only a sparse subset

A dense mixture would run every expert, which defeats the point of MoE capacity. Top-k routing keeps only the largest k gates, masks the rest to zero, and then renormalizes the survivors. Renormalization matters: without it, the mixed activation would shrink by the dropped probability mass.

```python
top_k_w = 2  # run only two experts for this token.
top_idx_w = np.argsort(gates_w)[::-1][:top_k_w]  # indices of the two largest gates.
mask_w = np.zeros_like(gates_w, dtype=bool)  # start with no expert selected.
mask_w[top_idx_w] = True  # mark selected experts.
kept_w = np.where(mask_w, gates_w, 0.0)  # zero out non-top-k gates.
print("top-k expert indices:", top_idx_w)
print("kept before renorm:", np.round(kept_w, 3), "sum=", round(float(kept_w.sum()), 3))
```
▶ What you'll see: experts 0 and 1 survive, while expert 2 is skipped and its gate becomes 0.

```python
sparse_gates_w = kept_w / kept_w.sum()  # renormalize the kept experts so their weights sum to one.
print("renormalized top-2 gates:", np.round(sparse_gates_w[mask_w], 3))
print("full sparse gate vector:", np.round(sparse_gates_w, 3), "sum=", round(float(sparse_gates_w.sum()), 3))
assert np.allclose(np.round(sparse_gates_w[mask_w], 3), [0.731, 0.269])
```
▶ What you'll see: the kept gates become `[0.731, 0.269]`, exactly the lesson's top-2 arithmetic.

```python
plt.figure(figsize=(4.4, 3))
plt.bar(["E0", "E1", "E2"], gates_w, alpha=0.35, label="dense gates")
plt.bar(["E0", "E1", "E2"], sparse_gates_w, alpha=0.85, label="top-2 renorm")
plt.title("2: top-k masking and renormalization")
plt.ylabel("gate")
plt.legend()
plt.show()
```
▶ What you'll see: expert 2 disappears, and the two remaining bars grow so the selected experts still sum to one.

*Why it's done this way: top-k is the sparse-compute switch, while renormalization preserves the scale of the layer. If we kept `[0.665, 0.245, 0]` without dividing by `0.910`, the whole expert contribution would be about 9% smaller merely because one expert was skipped.*

### 3. Experts transform the token, then gates mix their outputs

Each expert is just a small feed-forward network in a real Transformer. In this toy notebook, each expert returns a tiny 2-D vector so we can see the weighted sum exactly. The MoE output is $y=\sum_{e\in\mathrm{TopK}} g_e(x)E_e(x)$: run selected experts, multiply each output by its gate, and add the results.

```python
expert_outputs_w = np.array([[1.0, 0.0],  # E0 says "move along feature 0".
                             [0.0, 2.0],  # E1 says "move along feature 1".
                             [3.0, 3.0]]) # E2 would be strong but is not selected.
selected_outputs_w = expert_outputs_w[mask_w]  # only selected experts are evaluated in sparse routing.
print("selected expert outputs:\n", selected_outputs_w)
```
▶ What you'll see: only E0 and E1 are used for this token; E2's output is ignored.

```python
weighted_parts_w = sparse_gates_w[mask_w, None] * selected_outputs_w  # gate each selected expert output.
y_w = np.sum(weighted_parts_w, axis=0)  # sum the gated expert outputs.
print("weighted parts:\n", np.round(weighted_parts_w, 3))
print("MoE output y:", np.round(y_w, 3))
assert np.allclose(np.round(y_w, 3), [0.731, 0.538])
```
▶ What you'll see: `0.731[1,0] + 0.269[0,2] = [0.731, 0.538]`.

```python
plt.figure(figsize=(4.5, 3))
plt.bar(["feature 0", "feature 1"], y_w, color="purple")
plt.title("3: gated expert mixture output")
plt.ylabel("activation")
plt.show()
```
▶ What you'll see: the final activation contains feature 0 from E0 and feature 1 from E1, scaled by the router's confidence.

*Why it's done this way: the router decides a convex combination over selected computations. Mixing outputs, rather than choosing exactly one expert, lets one token borrow partial behavior from multiple specialists while still avoiding a full dense layer.*

### 4. Sparse activation grows capacity without proportional compute

MoE layers increase total parameters by adding experts, but each token activates only top-k of them. If there are 16 experts and top-2 routing, the token touches only 12.5% of expert modules. That is the central capacity trick: more stored knowledge, not proportionally more per-token expert compute.

```python
num_experts_w = 16  # total available expert modules.
active_w = 2  # top-k experts run per token.
active_fraction_w = active_w / num_experts_w  # fraction of expert modules used by one token.
print("active experts:", active_w, "of", num_experts_w)
print("active fraction:", f"{100 * active_fraction_w:.1f}%")
assert active_fraction_w == 0.125
```
▶ What you'll see: top-2 over 16 experts activates `12.5%` of the experts per token.

```python
experts_grid_w = np.arange(num_experts_w).reshape(4, 4)  # arrange experts for a compact picture.
active_mask_grid_w = np.isin(experts_grid_w, [0, 1]).astype(float)  # mark two active experts.
plt.figure(figsize=(3.8, 3.4))
plt.imshow(active_mask_grid_w, cmap="Greens", vmin=0, vmax=1)
plt.xticks([]); plt.yticks([])
plt.title("4: only top-2 of 16 experts run")
plt.show()
```
▶ What you'll see: just two highlighted squares in a 16-expert grid.

*Why it's done this way: a dense feed-forward layer spends compute on every parameter for every token. MoE separates parameter count from activated compute by making routing conditional on the token, so capacity grows with expert count while per-token expert work grows with k.*

### 5. Capacity limits and overflow drops

Sparse routing creates queues: many tokens may choose the same expert. Serving and training systems usually set an expert capacity, the maximum number of tokens an expert can process in the current batch. Tokens beyond capacity overflow; if they are dropped or rerouted silently, the mathematical layer you meant to run is not the layer that actually ran.

```python
assignments_w = np.array([0, 1, 1, 1, 1, 1, 0])  # seven tokens routed to expert 0 or 1.
capacity_w = 3  # each expert can process at most three tokens in this toy batch.
loads_w = np.bincount(assignments_w, minlength=2)  # count tokens assigned to each expert.
overflow_w = np.maximum(loads_w - capacity_w, 0)  # tokens beyond capacity per expert.
print("expert loads:", loads_w)
print("overflow tokens:", overflow_w, "total dropped=", int(overflow_w.sum()))
assert np.array_equal(loads_w, [2, 5]) and int(overflow_w.sum()) == 2
```
▶ What you'll see: expert 1 receives 5 tokens but capacity is 3, so 2 tokens overflow.

```python
plt.figure(figsize=(4.4, 3))
plt.bar(["E0", "E1"], loads_w, color=["teal", "crimson"])
plt.axhline(capacity_w, color="black", linestyle="--", label="capacity")
plt.title("5: routing load versus expert capacity")
plt.ylabel("tokens assigned")
plt.legend()
plt.show()
```
▶ What you'll see: E1's bar crosses the capacity line, which is exactly the queueing failure mode.

*Why it's done this way: capacity makes sparse execution predictable, but it also creates a hard constraint. Load measurements are part of correctness because an overloaded expert can lose tokens even when the router logits looked mathematically valid.*

### 6. Load balancing discourages router collapse

A router can collapse by sending most tokens to one expert. A simple load-balancing diagnostic compares the fraction of tokens assigned to each expert with a uniform target. The squared distance from uniform is zero when loads are even and grows when one expert dominates.

```python
batch_assign_w = np.array([0, 0, 0, 0, 1, 1, 2, 3])  # collapsed-ish: expert 0 gets half the batch.
counts_w = np.bincount(batch_assign_w, minlength=4)  # token counts per expert.
load_frac_w = counts_w / counts_w.sum()  # empirical routing fraction.
uniform_w = np.ones_like(load_frac_w) / len(load_frac_w)  # ideal balanced fraction.
balance_loss_w = float(np.sum((load_frac_w - uniform_w) ** 2))  # squared distance from uniform.
print("load fractions:", np.round(load_frac_w, 3))
print("balance loss:", round(balance_loss_w, 4))
assert round(balance_loss_w, 4) == 0.0938
```
▶ What you'll see: expert 0 takes 50% of tokens instead of the uniform 25%, giving a positive balance loss.

```python
plt.figure(figsize=(4.8, 3))
plt.bar(["E0", "E1", "E2", "E3"], load_frac_w, color="orange", label="actual")
plt.axhline(0.25, color="black", linestyle="--", label="uniform target")
plt.title("6: load-balancing diagnostic")
plt.ylabel("fraction of routed tokens")
plt.legend()
plt.show()
```
▶ What you'll see: the overloaded expert rises above the dashed uniform line, while unused capacity sits below it.

*Why it's done this way: the main language-model loss rewards good predictions, not fair traffic. A balancing term adds a mathematical pressure toward using all experts, which protects sparse capacity from becoming one crowded expert plus many idle ones.*

### ✍️ Toy 1 · Router softmax turns logits into gates

A router logit is just a score until softmax shifts, exponentiates, and normalizes it into gates that sum to one.

```python
import numpy as np
import matplotlib.pyplot as plt

t1_rng = np.random.default_rng(0)
t1_logits = np.array([3.0, 1.0, 0.0])
print("logits:", t1_logits.tolist())  # -> [3.0, 1.0, 0.0]
t1_shifted = t1_logits - np.max(t1_logits)
print("shifted logits:", t1_shifted.tolist())  # -> [0.0, -2.0, -3.0]
t1_exp = np.exp(t1_shifted)
print("exp(shifted):", np.round(t1_exp, 3).tolist())  # -> [1.0, 0.135, 0.05]
t1_gates = t1_exp / np.sum(t1_exp)
print("softmax gates:", np.round(t1_gates, 3).tolist())  # -> [0.844, 0.114, 0.042]
t1_gate_sum = float(np.sum(t1_gates))
print("gate sum:", round(t1_gate_sum, 3))  # -> 1.0

plt.figure(figsize=(4.4, 3))
plt.bar(["E0", "E1", "E2"], t1_gates, color="teal")
plt.ylim(0, 1)
plt.title("Toy 1 · router gates sum to one")
plt.ylabel("gate")
plt.show()
assert np.allclose(np.round(t1_gates, 3), [0.844, 0.114, 0.042])
```
▶ What you'll see: expert 0 receives most of the gate mass, while all gates remain nonnegative and sum to 1.

### ✍️ Toy 2 · Top-k masking renormalizes the survivors

Sparse routing keeps only the largest gates, zeroes the rest, and divides by the kept mass so the selected experts still form a full mixture.

```python
import numpy as np

t2_rng = np.random.default_rng(0)
t2_dense_gates = np.array([0.50, 0.30, 0.15, 0.05])
print("dense gates:", t2_dense_gates.tolist())  # -> [0.5, 0.3, 0.15, 0.05]
t2_top_k = 2
print("top-k:", t2_top_k)  # -> 2
t2_top_idx = np.argsort(t2_dense_gates)[::-1][:t2_top_k]
print("top indices:", t2_top_idx.tolist())  # -> [0, 1]
t2_mask = np.zeros_like(t2_dense_gates, dtype=bool)
t2_mask[t2_top_idx] = True
print("top-k mask:", t2_mask.astype(int).tolist())  # -> [1, 1, 0, 0]
t2_kept = np.where(t2_mask, t2_dense_gates, 0.0)
print("kept before renorm:", t2_kept.tolist())  # -> [0.5, 0.3, 0.0, 0.0]
t2_kept_sum = float(np.sum(t2_kept))
print("kept sum:", round(t2_kept_sum, 3))  # -> 0.8
t2_sparse_gates = t2_kept / t2_kept_sum
print("renormalized gates:", np.round(t2_sparse_gates, 3).tolist())  # -> [0.625, 0.375, 0.0, 0.0]
t2_sparse_sum = float(np.sum(t2_sparse_gates))
print("sparse sum:", round(t2_sparse_sum, 3))  # -> 1.0

plt.figure(figsize=(4.8, 3))
plt.bar(np.arange(4) - 0.18, t2_dense_gates, width=0.36, label="dense", color="gray")
plt.bar(np.arange(4) + 0.18, t2_sparse_gates, width=0.36, label="top-2", color="seagreen")
plt.xticks(np.arange(4), ["E0", "E1", "E2", "E3"])
plt.ylim(0, 1)
plt.title("Toy 2 · mask then renormalize")
plt.ylabel("gate")
plt.legend()
plt.show()
assert np.allclose(t2_sparse_gates, [0.625, 0.375, 0.0, 0.0])
```
▶ What you'll see: experts 2 and 3 vanish, and the two kept gates grow from total mass 0.8 back to 1.0.

## 🛠️ Setup

```python
import numpy as np # load NumPy for arrays, routing math, softmax, and small numerical checks.
import matplotlib.pyplot as plt # load Matplotlib so every routing decision can be inspected visually.
np.random.seed(0) # make all random examples reproducible across notebook runs.

def softmax(z): # define a stable softmax for router logits.
    z = np.asarray(z, dtype=float) # convert logits to a float array so exponentials are predictable.
    shifted = z - np.max(z) # subtract the maximum because softmax ratios are unchanged but overflow risk drops.
    exp_z = np.exp(shifted) # exponentiate shifted logits into positive evidence.
    return exp_z / np.sum(exp_z) # normalize evidence into gates that sum to 1.

def topk_gates(logits, k): # define top-k routing with renormalized sparse gates.
    dense = softmax(logits) # convert router logits into dense gates first.
    idx = np.argsort(dense)[::-1][:k] # choose the k largest gates.
    sparse = np.zeros_like(dense) # start with every expert skipped.
    sparse[idx] = dense[idx] # keep only selected expert weights.
    sparse = sparse / np.sum(sparse) # renormalize selected gates so the mixture scale stays stable.
    return idx, sparse # return selected expert ids and the full sparse gate vector.

def route_tokens(logit_matrix, k): # route a batch of tokens by applying top-k to each row of logits.
    choices = [] # store selected expert indices for each token.
    gates = [] # store sparse gate vectors for each token.
    for row in logit_matrix: # route each token independently.
        idx, sparse = topk_gates(row, k) # compute selected experts and gates for this token.
        choices.append(idx) # save selected experts.
        gates.append(sparse) # save sparse gates.
    return np.array(choices), np.array(gates) # return batch-shaped routing decisions.

def load_counts(assignments, num_experts): # count how many tokens choose each primary expert.
    return np.bincount(np.asarray(assignments, dtype=int), minlength=num_experts) # count with zeros for idle experts.

def expert_linear_outputs(x, experts): # apply each linear expert matrix to one token vector.
    return np.array([x @ W for W in experts]) # return one output vector per expert.
```

## 🟢 Basics (warm-up)

### Basic 1 — Softmax router gates

**Goal.** Convert router logits into gates, because MoE routing starts by changing arbitrary scores into normalized expert weights. We build it in 2 steps.

```python
logits_b1 = np.array([2.0, 1.0, 0.0]) # store one token's router logits for three experts.
gates_b1 = softmax(logits_b1) # convert logits to normalized dense gates.
print("gates:", np.round(gates_b1, 3)) # inspect the canonical lesson gates.
assert np.allclose(np.round(gates_b1, 3), [0.665, 0.245, 0.090]) # verify the worked softmax numbers.
```

```python
    ce = -float(np.mean(np.log(probs[np.arange(len(y_target_a1)), y_target_a1] + 1e-12))) # task loss for desired experts.
    load = probs.mean(axis=0) # average probabilistic traffic per expert.
    bal = float(np.sum((load - np.ones(3) / 3) ** 2)) # squared distance from uniform expert use.
    return ce + balance_weight * bal, ce, bal, load # return total and diagnostics.
start_loss_a1, start_ce_a1, start_bal_a1, start_load_a1 = router_loss_a1(W_a1) # evaluate initial router.
print("start total/ce/bal:", round(start_loss_a1, 3), round(start_ce_a1, 3), round(start_bal_a1, 4)) # inspect starting losses.
```

```python
losses_a1 = [] # store total loss during finite-difference training.
for step_a1 in range(80): # run a small gradient-descent loop.
    grad_a1 = np.zeros_like(W_a1) # prepare finite-difference gradient.
    base_a1 = router_loss_a1(W_a1)[0] # current loss.
    eps_a1 = 1e-4 # finite-difference step size.
    for i_a1 in range(W_a1.shape[0]): # loop over weight rows.
        for j_a1 in range(W_a1.shape[1]): # loop over weight columns.
            W_try_a1 = W_a1.copy() # copy weights for one perturbation.
            W_try_a1[i_a1, j_a1] += eps_a1 # nudge one weight.
            grad_a1[i_a1, j_a1] = (router_loss_a1(W_try_a1)[0] - base_a1) / eps_a1 # estimate derivative.
    W_a1 -= 0.4 * grad_a1 # descend the finite-difference gradient.
    losses_a1.append(router_loss_a1(W_a1)[0]) # record updated loss.
print("end loss:", round(losses_a1[-1], 3), "start loss:", round(start_loss_a1, 3)) # inspect improvement.
assert losses_a1[-1] < start_loss_a1 # verify training reduced the objective.
```

```python

pred_a1 = np.argmax(X_a1 @ W_a1, axis=1) # convert trained logits to top-1 routes.

```

### Advanced 3 — Compare overflow policies

**Goal.** Compare drop and second-choice rerouting policies, because capacity overflow can be handled in different ways with different load effects. We build it in 5 steps.


