# 16.4 — Dense Retrieval

Dense retrieval represents queries and documents as learned dense vectors, then retrieves the documents whose vectors point in the same semantic direction as the query. The payoff is semantic recall: a query like "embedding search" can find a document about a "vector database" even when the exact words do not overlap.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build dense retrieval one idea at a time. Run each cell in order and read the printed intermediate values — every piece of math, including the dual-encoder training signal, is shown with NumPy arrays rather than hidden behind a library. This walkthrough is self-contained and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays, linear algebra, and tiny neural-network updates.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
from collections import Counter  # small token-count utility for sparse baselines.
np.random.seed(0)  # reproducibility for toy embeddings and training.
```

### 1. Vocabulary mismatch and why learned coordinates help

Sparse retrieval matches text by observed tokens. That is useful for exact constraints, but it can fail when the query says one phrase and the relevant document says a different phrase with the same meaning. Dense retrieval starts by replacing token-count coordinates with learned semantic coordinates, so nearby vectors can mean "same idea" rather than "same words." Here we first build the sparse failure, then hand-place a tiny semantic geometry.

```python
query_w = "embedding search"  # The user's wording.
docs_w = ["vector database", "keyword search", "banana recipe"]  # Candidate documents.
q_tokens_w = set(query_w.split())  # Sparse retrieval sees only exact tokens.
overlap_w = np.array([len(q_tokens_w & set(d.split())) for d in docs_w])  # Count exact shared words.
print("token overlaps:", overlap_w)  # Inspect sparse evidence.
assert overlap_w.tolist() == [0, 1, 0]  # The semantic match has zero lexical overlap.
```
▶ What you'll see: the document "vector database" gets no sparse credit even though it is the semantic neighbor.

```python
q_sem_w = np.array([0.9, 0.1])  # A hand-built semantic query vector: mostly "vector-search" axis.
d_sem_w = np.array([[0.8, 0.2], [0.2, 0.8], [-0.2, 0.9]])  # Document vectors in the same semantic space.
labels_w = ["vector database", "keyword search", "banana recipe"]  # Labels for printing and plotting.
print("query vector:", q_sem_w)  # Inspect learned coordinates.
print("document vectors:\n", d_sem_w)  # Inspect candidate coordinates.
```
▶ What you'll see: "vector database" is close to the query direction even without shared words.

```python
plt.figure(figsize=(4.5, 3.5))  # Create a compact semantic-space plot.
plt.scatter(d_sem_w[:, 0], d_sem_w[:, 1], s=90, color="steelblue", label="docs")  # Plot document embeddings.
plt.scatter([q_sem_w[0]], [q_sem_w[1]], s=120, color="crimson", marker="*", label="query")  # Plot the query embedding.
for i_w, label_w in enumerate(labels_w):  # Label each document point.
    plt.text(d_sem_w[i_w, 0] + 0.02, d_sem_w[i_w, 1], label_w)  # Add readable text near each point.
plt.text(q_sem_w[0] + 0.02, q_sem_w[1], "query")  # Label the query.
plt.axhline(0, color="gray", linewidth=0.5); plt.axvline(0, color="gray", linewidth=0.5)  # Reference axes.
plt.title("1: semantic coordinates can bridge wording")  # Title the plot.
plt.xlabel("vector-search meaning"); plt.ylabel("other meaning")  # Label axes as learned meanings.
plt.legend(); plt.show()  # Display the geometry.
```
▶ What you'll see: the query and "vector database" sit near each other on the first semantic axis.

*Why it's done this way:* sparse overlap is a high-precision lexical signal, but it has no mechanism for synonyms. Dense retrieval assumes an encoder has learned coordinates where documents with the same relevance meaning point in similar directions; retrieval can then use geometry instead of exact token identity.

### 2. Cosine, normalization, and dot-product retrieval

The ranking score is usually cosine similarity, $$s(q,d)=\frac{q^\top d}{\lVert q\rVert_2\lVert d\rVert_2}.$$ The numerator rewards aligned coordinates; the denominator removes vector length so high-norm embeddings do not win merely because they are large. If every vector is normalized to unit length first, cosine equals a plain dot product, which is why vector stores often normalize once and then run fast inner-product search.

```python
q2_w = np.array([0.9, 0.1])  # Lesson query vector.
Z2_w = np.array([[1.0, 0.0], [0.8, 0.2], [0.0, 1.0], [-0.2, 0.9]])  # Four document embeddings.
norm_q2_w = np.linalg.norm(q2_w)  # Query L2 length.
norms_Z2_w = np.linalg.norm(Z2_w, axis=1)  # Document L2 lengths.
print("||q||:", round(norm_q2_w, 3))  # sqrt(0.9^2 + 0.1^2).
print("||docs||:", np.round(norms_Z2_w, 3))  # Inspect document lengths.
assert round(norm_q2_w, 3) == 0.906  # Verify the lesson number.
```
▶ What you'll see: the query norm is 0.906, matching the worked calculation.

```python
cos2_w = (Z2_w @ q2_w) / (norms_Z2_w * norm_q2_w)  # Cosine with every document.
print("cosine scores:", np.round(cos2_w, 3))  # Inspect ranking scores.
assert np.allclose(np.round(cos2_w, 3), [0.994, 0.991, 0.110, -0.108])  # Verify concrete scores.
```
▶ What you'll see: the first two documents are retrieved because their vectors point with the query.

```python
q2_unit_w = q2_w / norm_q2_w  # Normalize the query to unit length.
Z2_unit_w = Z2_w / norms_Z2_w[:, None]  # Normalize each document row to unit length.
dot_unit_w = Z2_unit_w @ q2_unit_w  # Dot product after normalization.
print("unit-dot scores:", np.round(dot_unit_w, 3))  # Compare to cosine.
assert np.allclose(dot_unit_w, cos2_w)  # Cosine equals dot product for unit vectors.
```
▶ What you'll see: normalized dot products exactly match cosine scores.

```python
plt.figure(figsize=(4.8, 3))  # Create a score bar chart.
plt.bar(["z1", "z2", "z3", "z4"], cos2_w, color=["seagreen", "seagreen", "gray", "indianred"])  # Plot similarities.
plt.axhline(0, color="black", linewidth=0.7)  # Mark the zero-similarity line.
plt.title("2: cosine ranks semantic direction")  # Title the plot.
plt.ylabel("cosine similarity")  # Label score axis.
plt.show()  # Display the chart.
```
▶ What you'll see: aligned documents have tall positive bars; the opposite-direction document is negative.

*Why it's done this way:* cosine isolates direction, which is the part intended to encode meaning. Normalizing embeddings turns the expensive-looking cosine formula into one dot product, while preserving the same ordering and avoiding norm-driven false wins.

### 3. Dual encoders: precompute documents, encode queries on demand

Dense retrieval usually uses a **dual encoder** (also called a bi-encoder): one encoder maps the query to a vector, and another maps each document to a vector. Documents can be encoded offline and stored; at search time only the query is encoded, then compared to the stored document matrix. The speed comes from separating the two texts before scoring.

```python
vocab_w = ["embedding", "vector", "database", "keyword", "recipe", "search"]  # Tiny vocabulary.
tok_to_i_w = {tok_w: i_w for i_w, tok_w in enumerate(vocab_w)}  # Token-to-index map.
Wq_w = np.array([[1.0, 0.1], [0.9, 0.1], [0.8, 0.2], [0.1, 0.8], [-0.2, 0.9], [0.7, 0.3]])  # Query token embeddings.
Wd_w = np.array([[0.9, 0.1], [1.0, 0.0], [0.8, 0.2], [0.0, 0.9], [-0.2, 1.0], [0.6, 0.4]])  # Document token embeddings.
print("vocab size:", len(vocab_w), "embedding dim:", Wq_w.shape[1])  # Inspect encoder dimensions.
```
▶ What you'll see: each encoder maps six token coordinates into two dense coordinates.

```python
def encode_text_w(text_w, W_w):  # Mean-pool token embeddings for one tiny encoder.
    idx_w = [tok_to_i_w[t_w] for t_w in text_w.split() if t_w in tok_to_i_w]  # Convert known tokens to ids.
    return W_w[idx_w].mean(axis=0) if idx_w else np.zeros(W_w.shape[1])  # Average token vectors.

Qvec_w = encode_text_w("embedding search", Wq_w)  # Encode the query with the query encoder.
Dvec_w = np.vstack([encode_text_w(d_w, Wd_w) for d_w in docs_w])  # Precompute document vectors with the doc encoder.
print("query embedding:", np.round(Qvec_w, 3))  # Inspect query-side representation.
print("doc embeddings:\n", np.round(Dvec_w, 3))  # Inspect stored document-side representations.
```
▶ What you'll see: query and document vectors are built separately but live in the same score space.

```python
Qunit_w = Qvec_w / np.linalg.norm(Qvec_w)  # Normalize query embedding.
Dunit_w = Dvec_w / np.linalg.norm(Dvec_w, axis=1, keepdims=True)  # Normalize stored document embeddings.
scores3_w = Dunit_w @ Qunit_w  # Dot product retrieval scores.
order3_w = np.argsort(scores3_w)[::-1]  # Rank highest score first.
print("ranked docs:", [(docs_w[i_w], round(float(scores3_w[i_w]), 3)) for i_w in order3_w])  # Inspect results.
assert order3_w[0] == 0  # The semantic vector-database document ranks first.
```
▶ What you'll see: the precomputed document matrix retrieves the semantic neighbor for the query.

```python
plt.figure(figsize=(4.6, 3.4))  # Plot the dual-encoder vectors.
plt.scatter(Dunit_w[:, 0], Dunit_w[:, 1], color="steelblue", s=90, label="precomputed docs")  # Document points.
plt.scatter([Qunit_w[0]], [Qunit_w[1]], marker="*", s=140, color="crimson", label="query now")  # Query point.
for i_w, d_w in enumerate(docs_w):  # Label docs.
    plt.text(Dunit_w[i_w, 0] + 0.02, Dunit_w[i_w, 1], d_w)  # Add text label.
plt.title("3: dual encoders share a vector space")  # Title the plot.
plt.xlabel("unit axis 0"); plt.ylabel("unit axis 1")  # Label axes.
plt.legend(); plt.show()  # Display the plot.
```
▶ What you'll see: document vectors can be stored before the query arrives; retrieval is a matrix-vector dot product.

*Why it's done this way:* a cross-encoder could read the query and document jointly, but then every query-document pair needs a neural pass. Dual encoders trade some pairwise nuance for speed: precompute $z_i=f_d(d_i)$ once, compute $f_q(q)$ at query time, and rank with $Z f_q(q)$.

### 4. In-batch negatives and contrastive loss

To learn the geometry, a batch often contains matching query-document pairs. Each query's true document is its positive; the other documents in the same batch become **in-batch negatives**. The model builds a similarity matrix, applies a softmax across each row, and minimizes negative log probability of the diagonal. This is contrastive because it pulls matched pairs together while pushing all other batch pairs apart.

```python
Q4_w = np.array([[1.0, 0.0], [0.0, 1.0], [0.7, 0.3]])  # Three query embeddings.
D4_w = np.array([[0.9, 0.1], [0.1, 0.9], [0.2, 0.8]])  # Matching docs are on the diagonal.
Q4_w = Q4_w / np.linalg.norm(Q4_w, axis=1, keepdims=True)  # Normalize queries.
D4_w = D4_w / np.linalg.norm(D4_w, axis=1, keepdims=True)  # Normalize docs.
S4_w = Q4_w @ D4_w.T / 0.2  # Similarity logits with temperature 0.2.
print("logit matrix:\n", np.round(S4_w, 2))  # Inspect all query-doc scores.
```
▶ What you'll see: each row is one query scored against every document in the batch.

```python
S4_shift_w = S4_w - S4_w.max(axis=1, keepdims=True)  # Stable softmax shift.
P4_w = np.exp(S4_shift_w) / np.exp(S4_shift_w).sum(axis=1, keepdims=True)  # Row-wise probabilities.
loss4_w = -np.mean(np.log(np.diag(P4_w)))  # Average negative log probability of correct diagonal docs.
print("row probabilities:\n", np.round(P4_w, 3))  # Inspect where probability mass goes.
print("contrastive loss:", round(float(loss4_w), 3))  # Inspect loss.
assert P4_w.shape == (3, 3) and loss4_w > 0  # Basic correctness checks.
```
▶ What you'll see: a good query puts most probability on its matching diagonal document.

```python
plt.figure(figsize=(4, 3.4))  # Visualize in-batch scores.
plt.imshow(P4_w, cmap="Blues", vmin=0, vmax=1)  # Probability heatmap.
plt.colorbar(label="softmax probability")  # Add probability scale.
plt.xticks(range(3), ["d0", "d1", "d2"]); plt.yticks(range(3), ["q0", "q1", "q2"])  # Label axes.
plt.title("4: diagonal positives, off-diagonal negatives")  # Title the plot.
plt.show()  # Display heatmap.
```
▶ What you'll see: bright diagonal cells mean positives are winning; bright off-diagonal cells would be hard negatives.

*Why it's done this way:* with batch size $B$, one forward pass creates $B$ positives and $B(B-1)$ negatives. The softmax denominator is the competition: a positive score must be large not in isolation, but relative to all other documents that could have been retrieved.

### 5. Training a tiny dual encoder from scratch

Now we make the encoders learn. The model starts with random token embeddings. For each batch, we mean-pool query tokens and document tokens, normalize the resulting vectors, compute the in-batch contrastive loss, and update token embeddings with gradient descent. The code is small but complete: no Torch, no TensorFlow, just NumPy gradients.

```python
pairs5_w = [("embedding search", "vector database"), ("keyword search", "keyword search"), ("banana recipe", "banana recipe")]  # Training pairs.
vocab5_w = sorted(set(" ".join(q_w + " " + d_w for q_w, d_w in pairs5_w).split()))  # Vocabulary from toy data.
toi5_w = {t_w: i_w for i_w, t_w in enumerate(vocab5_w)}  # Token ids.
q_ids5_w = [[toi5_w[t_w] for t_w in q_w.split()] for q_w, _ in pairs5_w]  # Query token ids.
d_ids5_w = [[toi5_w[t_w] for t_w in d_w.split()] for _, d_w in pairs5_w]  # Document token ids.
print("vocab:", vocab5_w)  # Inspect learned token universe.
assert len(vocab5_w) == 7  # Concrete toy size.
```
▶ What you'll see: seven tokens are enough to demonstrate the full training loop.

```python
rng5_w = np.random.default_rng(0)  # Local reproducible generator.
Wq5_w = 0.1 * rng5_w.normal(size=(len(vocab5_w), 2))  # Random query-token embeddings.
Wd5_w = 0.1 * rng5_w.normal(size=(len(vocab5_w), 2))  # Random document-token embeddings.
losses5_w = []  # Track contrastive loss.
print("initial Wq norm:", round(float(np.linalg.norm(Wq5_w)), 3))  # Inspect scale.
```
▶ What you'll see: embeddings begin as small random vectors with no semantic structure.

```python
for step5_w in range(700):  # Train long enough for the tiny batch to separate.
    Qraw5_w = np.vstack([Wq5_w[ids_w].mean(axis=0) for ids_w in q_ids5_w])  # Mean-pooled query vectors.
    Draw5_w = np.vstack([Wd5_w[ids_w].mean(axis=0) for ids_w in d_ids5_w])  # Mean-pooled document vectors.
    Qn5_w = Qraw5_w / np.linalg.norm(Qraw5_w, axis=1, keepdims=True)  # Unit query vectors.
    Dn5_w = Draw5_w / np.linalg.norm(Draw5_w, axis=1, keepdims=True)  # Unit document vectors.
    logits5_w = Qn5_w @ Dn5_w.T / 0.2  # Similarity logits with temperature.
    prob5_w = np.exp(logits5_w - logits5_w.max(axis=1, keepdims=True))  # Stable exponentials.
    prob5_w = prob5_w / prob5_w.sum(axis=1, keepdims=True)  # Row-wise softmax.
    loss5_w = -np.mean(np.log(np.diag(prob5_w)))  # Diagonal cross-entropy loss.
    losses5_w.append(float(loss5_w))  # Store loss.
    G5_w = prob5_w.copy(); G5_w[np.arange(3), np.arange(3)] -= 1; G5_w /= (3 * 0.2)  # dL/d(Qn Dn^T).
    dQn5_w = G5_w @ Dn5_w  # Gradient into normalized queries.
    dDn5_w = G5_w.T @ Qn5_w  # Gradient into normalized docs.
    dQraw5_w = np.zeros_like(Qraw5_w); dDraw5_w = np.zeros_like(Draw5_w)  # Allocate raw-vector gradients.
    for r5_w in range(3):  # Backprop through L2 normalization for each row.
        nq5_w = np.linalg.norm(Qraw5_w[r5_w]); nd5_w = np.linalg.norm(Draw5_w[r5_w])  # Norms.
        dQraw5_w[r5_w] = (np.eye(2) - np.outer(Qn5_w[r5_w], Qn5_w[r5_w])) @ dQn5_w[r5_w] / nq5_w  # Normalize gradient.
        dDraw5_w[r5_w] = (np.eye(2) - np.outer(Dn5_w[r5_w], Dn5_w[r5_w])) @ dDn5_w[r5_w] / nd5_w  # Normalize gradient.
    for r5_w, ids_w in enumerate(q_ids5_w):  # Scatter query gradients to token embeddings.
        for idx5_w in ids_w:
            Wq5_w[idx5_w] -= 0.08 * dQraw5_w[r5_w] / len(ids_w)  # Mean-pool gradient share.
    for r5_w, ids_w in enumerate(d_ids5_w):  # Scatter document gradients to token embeddings.
        for idx5_w in ids_w:
            Wd5_w[idx5_w] -= 0.08 * dDraw5_w[r5_w] / len(ids_w)  # Mean-pool gradient share.
print("loss start -> end:", round(losses5_w[0], 3), "->", round(losses5_w[-1], 3))  # Inspect learning.
assert losses5_w[-1] < losses5_w[0]  # Training reduced contrastive loss.
```
▶ What you'll see: contrastive loss falls because matching query-document pairs become easier to identify.

```python
plt.figure(figsize=(4.8, 3))  # Plot training curve.
plt.plot(losses5_w, color="purple")  # Draw loss over steps.
plt.title("5: dual-encoder contrastive loss decreases")  # Title.
plt.xlabel("step"); plt.ylabel("loss")  # Axis labels.
plt.show()  # Display curve.
```
▶ What you'll see: the curve drops and then flattens as the tiny geometry converges.

*Why it's done this way:* the encoder parameters are token vectors, so the only way to make a positive pair score higher is to move the pooled query and document embeddings toward each other and away from other batch documents. The normalization gradient keeps the update about direction rather than norm.

### 6. Retrieval, scaling cost, and dense failure modes

After training, retrieval is simple: encode a query, compare it with stored normalized document vectors, and sort. Exact search costs $O(Nd)$ per query because every one of $N$ document vectors of dimension $d$ must be touched. Dense retrieval also has a different failure mode from sparse retrieval: it may rank a semantic neighbor high while ignoring exact required terms, so production systems often combine dense scores with filters or sparse signals.

```python
Qraw6_w = np.vstack([Wq5_w[ids_w].mean(axis=0) for ids_w in q_ids5_w])  # Re-encode trained queries.
Draw6_w = np.vstack([Wd5_w[ids_w].mean(axis=0) for ids_w in d_ids5_w])  # Re-encode trained docs.
Qn6_w = Qraw6_w / np.linalg.norm(Qraw6_w, axis=1, keepdims=True)  # Normalize queries.
Dn6_w = Draw6_w / np.linalg.norm(Draw6_w, axis=1, keepdims=True)  # Normalize docs.
S6_w = Qn6_w @ Dn6_w.T  # Cosine retrieval matrix.
print("trained cosine matrix:\n", np.round(S6_w, 3))  # Inspect final pair scores.
assert np.mean(np.diag(S6_w)) > np.mean(S6_w[~np.eye(3, dtype=bool)])  # Positives outrank negatives on average.
```
▶ What you'll see: diagonal pair scores are stronger than off-diagonal scores after training.

```python
query_i6_w = 0  # Search for the first query: embedding search.
rank6_w = np.argsort(S6_w[query_i6_w])[::-1]  # Sort documents by score.
print("retrieval order:", [(pairs5_w[i_w][1], round(float(S6_w[query_i6_w, i_w]), 3)) for i_w in rank6_w])  # Show ranked docs.
assert rank6_w[0] == 0  # The paired document is retrieved first.
```
▶ What you'll see: the trained dense retriever returns "vector database" for "embedding search."

```python
N6_w, d6_w = 1_000_000, 768  # A realistic catalog size and embedding dimension.
multiplies6_w = N6_w * d6_w  # Exact dot-product multiplications for one query.
print("exact search multiplications:", f"{multiplies6_w:,}")  # Inspect O(Nd) cost.
assert multiplies6_w == 768_000_000  # Concrete scaling number.
```
▶ What you'll see: exact dense scanning is hundreds of millions of multiply-adds for one query.

```python
plt.figure(figsize=(4, 3.4))  # Visualize final score matrix.
plt.imshow(S6_w, cmap="coolwarm", vmin=-1, vmax=1)  # Show cosine values.
plt.colorbar(label="cosine")  # Add score scale.
plt.xticks(range(3), ["d0", "d1", "d2"]); plt.yticks(range(3), ["q0", "q1", "q2"])  # Label axes.
plt.title("6: trained retrieval scores")  # Title.
plt.show()  # Display heatmap.
```
▶ What you'll see: the diagonal is the intended retrieval path; scaling this matrix to millions of columns motivates ANN indexes.

*Why it's done this way:* dense retrieval buys semantic recall by trusting learned geometry, but exact matrix scanning is linear in catalog size and the score itself cannot enforce hard lexical constraints. That is why the next lessons add approximate nearest-neighbor search and hybrid retrieval.

### ✍️ Toy 2 · Normalize so dot product equals cosine

Cosine removes vector length; after L2 normalization, the same ranking is just a dot product.

```python
import numpy as np

t2_rng = np.random.default_rng(0)
print("rng seed:", 0)  # -> 0
t2_query = np.array([2.0, 0.0])
print("query vector:", t2_query.tolist())  # -> [2.0, 0.0]
```

### ✍️ Toy 4 · In-batch negatives are softmax competitors

Each row is one query; the diagonal document is the positive, and off-diagonal documents are negatives.

```python
import numpy as np

t4_rng = np.random.default_rng(0)
```

### ✍️ Toy 5 · One gradient step pulls positives together

A contrastive gradient lowers loss by increasing diagonal scores and decreasing off-diagonal scores.

```python
import numpy as np

t5_rng = np.random.default_rng(0)
print("rng seed:", 0)  # -> 0
t5_Q = np.array([[0.2, 0.8], [0.8, 0.2]], dtype=float)
print("initial queries:", t5_Q.tolist())  # -> [[0.2, 0.8], [0.8, 0.2]]
t5_D = np.array([[0.8, 0.2], [0.2, 0.8]], dtype=float)
print("initial docs:", t5_D.tolist())  # -> [[0.8, 0.2], [0.2, 0.8]]
t5_temp = 1.0
print("temperature:", t5_temp)  # -> 1.0
t5_logits = t5_Q @ t5_D.T / t5_temp
print("initial logits:", np.round(t5_logits, 3).tolist())  # -> [[0.32, 0.68], [0.68, 0.32]]
t5_prob = np.exp(t5_logits - t5_logits.max(axis=1, keepdims=True))
t5_prob = t5_prob / t5_prob.sum(axis=1, keepdims=True)
print("initial probabilities:", np.round(t5_prob, 3).tolist())  # -> [[0.411, 0.589], [0.589, 0.411]]
t5_loss_before = -np.log(np.diag(t5_prob)).mean()
print("loss before:", round(float(t5_loss_before), 3))  # -> 0.889
t5_grad_logits = t5_prob.copy()
t5_grad_logits[np.arange(2), np.arange(2)] = t5_grad_logits[np.arange(2), np.arange(2)] - 1
t5_grad_logits = t5_grad_logits / (2 * t5_temp)
print("gradient wrt logits:", np.round(t5_grad_logits, 3).tolist())  # -> [[-0.295, 0.295], [0.295, -0.295]]
t5_grad_Q = t5_grad_logits @ t5_D
print("gradient wrt queries:", np.round(t5_grad_Q, 3).tolist())  # -> [[-0.177, 0.177], [0.177, -0.177]]
t5_grad_D = t5_grad_logits.T @ t5_Q
print("gradient wrt docs:", np.round(t5_grad_D, 3).tolist())  # -> [[0.177, -0.177], [-0.177, 0.177]]
t5_lr = 0.5
print("learning rate:", t5_lr)  # -> 0.5
t5_Q_after = t5_Q - t5_lr * t5_grad_Q
t5_D_after = t5_D - t5_lr * t5_grad_D
t5_logits_after = t5_Q_after @ t5_D_after.T / t5_temp
t5_prob_after = np.exp(t5_logits_after - t5_logits_after.max(axis=1, keepdims=True))
t5_prob_after = t5_prob_after / t5_prob_after.sum(axis=1, keepdims=True)
t5_loss_after = -np.log(np.diag(t5_prob_after)).mean()
print("loss after:", round(float(t5_loss_after), 3))  # -> 0.787
assert t5_loss_after < t5_loss_before

plt.figure(figsize=(4.0, 2.8))
plt.bar(["before", "after"], [t5_loss_before, t5_loss_after], color=["#e45756", "#54a24b"])
plt.ylabel("contrastive loss")
plt.title("Toy 5 · one update lowers loss")
plt.show()
```
▶ What you'll see: the loss bar drops after one gradient step.

```python

    Qraw_e4 = np.vstack([Wq_e4[ids_e4].mean(axis=0) for ids_e4 in q_ids_e4]) # Encode queries.
```

### Advanced 5 — Measure retrieval quality with recall@k

**Goal.** Evaluate whether positives appear in the top-k retrieved set, because retrieval is judged by candidate recall before downstream reranking. We build it in 4 steps.

```python
S_a5 = np.array([[0.95, 0.30, 0.20, 0.10], [0.40, 0.85, 0.82, 0.10], [0.20, 0.70, 0.75, 0.60]]) # Three queries by four docs.
```

```python
ranked_a5 = np.argsort(S_a5, axis=1)[:, ::-1] # Sort docs high to low per query.

```

```python
recalls_a5 = [] # Store recall@k values.

    hit_a5 = [positive_doc_a5[i_a5] in ranked_a5[i_a5, :k_a5] for i_a5 in range(S_a5.shape[0])] # Check if positive is retrieved.
```

👀 Takeaway: dense retrievers are optimized for high recall@k so later rerankers have the right candidates to inspect.
