# 3.43 — Data Leakage

Data leakage happens when training or validation uses information that would not exist at serving time — future labels, target-derived summaries, or preprocessing fit on the whole dataset. This lesson treats leakage as a broken evaluation contract: the empirical loss looks excellent because the model got forbidden hints, while the true future loss stays high.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build data leakage one idea at a time. Run each cell in order and read the printed intermediate values — every score is small enough to inspect, and every comparison separates the raw fit from the evidence that is actually allowed at prediction time. This walkthrough is self-contained and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays, masks, and simple learning calculations.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
np.random.seed(0)  # reproducibility for simulated samples.
```

### 1. The evaluation contract: train on past, judge on future

A supervised model is allowed to learn from training rows and then must make predictions for rows it has not seen. For leakage, the most important question is not “does this feature predict the label?” but “would this feature be available before the prediction is made?” We start with a tiny time-ordered dataset and deliberately split the first six rows as past training data and the last four as future validation data.

```python
time_w = np.arange(10)  # row order: earlier rows must not learn from later rows.
y_w = np.array([0., 0., 1., 1., 0., 1., 0., 1., 1., 0.])  # labels revealed after each event.
allowed_x_w = np.array([0.10, 0.20, 0.80, 0.70, 0.30, 0.90, 0.25, 0.75, 0.85, 0.15])  # known before prediction.
train_w = time_w < 6  # past rows.
val_w = ~train_w  # future rows.
print("train rows:", time_w[train_w])
print("future validation rows:", time_w[val_w])
```
▶ What you'll see: validation rows occur strictly after training rows, so the validation score imitates future deployment.

```python
plt.figure(figsize=(5, 3))
plt.scatter(time_w[train_w], y_w[train_w], s=80, label="train labels", color="teal")
plt.scatter(time_w[val_w], y_w[val_w], s=80, label="future labels", color="orange")
plt.plot(time_w, allowed_x_w, color="gray", linestyle="--", label="allowed feature")
plt.title("1: past/future evaluation contract")
plt.xlabel("time order")
plt.ylabel("value")
plt.legend()
plt.show()
```
▶ What you'll see: the split is temporal, while the allowed feature exists for every row before its label is known.

*Why it's done this way:* generalization is a claim about performance on examples outside the learner's information set. A temporal split is the cleanest toy version of that contract: the validation labels are future facts, so no calculation used to train or preprocess may summarize them.

### 2. A leaky feature can make validation look magically good

Now create a forbidden feature: a value almost equal to the label. This could happen when a table includes “refund issued,” “days until churn,” or any field computed after the outcome. A simple threshold model using this feature will look almost perfect on validation, but only because it has been given the answer in disguise.

```python
leaky_x_w = 0.05 + 0.90 * y_w  # forbidden: derived from the target itself.
pred_allowed_w = (allowed_x_w >= 0.50).astype(float)  # simple allowed threshold model.
pred_leaky_w = (leaky_x_w >= 0.50).astype(float)  # same rule, but using the forbidden hint.
print("allowed feature:", np.round(allowed_x_w, 2))
print("leaky feature:", np.round(leaky_x_w, 2))
```
▶ What you'll see: the leaky feature is low for label 0 and high for label 1 because it was built from the label.

```python
loss_allowed_w = (pred_allowed_w[val_w] - y_w[val_w]) ** 2  # validation squared loss with legal inputs.
loss_leaky_w = (pred_leaky_w[val_w] - y_w[val_w]) ** 2  # validation squared loss with forbidden inputs.
print("allowed validation losses:", loss_allowed_w, "mean =", round(float(loss_allowed_w.mean()), 3))
print("leaky validation losses:", loss_leaky_w, "mean =", round(float(loss_leaky_w.mean()), 3))
assert float(loss_leaky_w.mean()) == 0.0
```
▶ What you'll see: the leaky validation loss is 0, a suspiciously perfect score for such a tiny rule.

```python
plt.figure(figsize=(4.6, 3))
plt.bar(["allowed", "leaky"], [loss_allowed_w.mean(), loss_leaky_w.mean()], color=["teal", "crimson"])
plt.ylabel("future validation MSE")
plt.title("2: leakage flatters validation")
plt.show()
```
▶ What you'll see: the leaky bar is lower, but it is lower for the wrong reason.

*Why it's done this way:* both rules have the same model class and threshold; only the information source changed. That isolates leakage mathematically: the empirical risk is contaminated because the input contains target-derived information unavailable at serving time.

### 3. Preprocessing can leak through target-derived summaries

Leakage is not only a bad column. It can occur when preprocessing is fit using all rows. Here we encode a category by its mean label. If we compute that mean on the full dataset, validation labels sneak into the category statistics. If we compute it on training only, the validation rows get only past information.

```python
group_w = np.array(["A", "A", "B", "B", "A", "B", "A", "B", "B", "A"])  # a categorical feature.
full_mean_A_w = y_w[group_w == "A"].mean()  # wrong: includes validation labels.
train_mean_A_w = y_w[train_w & (group_w == "A")].mean()  # right: training rows only.
print("full-data mean for A:", round(float(full_mean_A_w), 3))
print("train-only mean for A:", round(float(train_mean_A_w), 3))
```
▶ What you'll see: the same category receives a different encoded value depending on whether future labels were allowed in.

```python
encoded_full_w = np.array([y_w[group_w == g].mean() for g in group_w])  # leaky target encoding.
encoded_train_w = np.zeros_like(y_w)  # clean target encoding.
for g_w in np.unique(group_w):
    m_w = train_w & (group_w == g_w)
    encoded_train_w[group_w == g_w] = y_w[m_w].mean()
print("full encoding on validation:", np.round(encoded_full_w[val_w], 3))
print("train-only encoding on validation:", np.round(encoded_train_w[val_w], 3))
```
▶ What you'll see: validation labels alter the full-data encodings even before the model predicts validation rows.

```python
pred_full_enc_w = (encoded_full_w[val_w] >= 0.50).astype(float)
pred_train_enc_w = (encoded_train_w[val_w] >= 0.50).astype(float)
err_full_enc_w = (pred_full_enc_w - y_w[val_w]) ** 2
err_train_enc_w = (pred_train_enc_w - y_w[val_w]) ** 2
print("leaky encoding MSE:", round(float(err_full_enc_w.mean()), 3))
print("clean encoding MSE:", round(float(err_train_enc_w.mean()), 3))
```
▶ What you'll see: the leaky preprocessing score can change because validation labels helped create the feature.

*Why it's done this way:* target encoding is an average of labels, so its allowed sample must match the training information set. The formula is simple — a mean — but the index set in that mean decides whether the model is learning history or peeking at the future.

### 4. The lesson arithmetic: raw risk, cost, gap, and stability

The content block gives a verified toy score. Three per-example losses average to the empirical risk, then a cost term is added. This matters for leakage because the raw training number is exactly the tempting fragment people overtrust; the selection score must include the cost, uncertainty, or protocol penalty that keeps flexibility honest.

```python
losses_toy_w = np.array([0.257, 0.122, 0.420])  # verified toy losses from the lesson block.
risk_w = losses_toy_w.mean()  # empirical risk R_S.
cost_w = 0.060  # complexity / regularization / operational cost.
score_w = round(float(risk_w), 3) + cost_w  # decision score, using the displayed empirical risk from the lesson arithmetic.
print("R_S:", round(float(risk_w), 3))
print("score = R_S + cost:", round(float(score_w), 3))
assert round(float(risk_w), 3) == 0.266
assert round(float(score_w), 3) == 0.326
```
▶ What you'll see: the raw average 0.266 becomes the decision score 0.326 after the required cost is included.

```python
alternative_w = 0.374
gap_w = alternative_w - score_w
relative_gap_w = gap_w / alternative_w
print("gap:", round(float(gap_w), 3))
print("relative gap:", round(float(relative_gap_w), 3))
assert round(float(gap_w), 3) == 0.048
assert round(float(relative_gap_w), 3) == 0.128
```
▶ What you'll see: the baseline beats the flexible alternative by 0.048, about 12.8% of the alternative score.

```python
plt.figure(figsize=(4.8, 3))
plt.bar(["raw risk", "+ cost", "flexible alt"], [risk_w, score_w, alternative_w], color=["gray", "teal", "crimson"])
plt.ylabel("score (lower is better)")
plt.title("4: compare full decision scores")
plt.show()
```
▶ What you'll see: the raw risk is not the fair comparison; the full score is.

*Why it's done this way:* a leaky or overly flexible method usually wins the raw fit. Adding the cost term is a compact way to express the full decision rule: select the method with the lowest honest score, not the most flattering fragment.

### 5. Stabilization chooses the robust score, not the prettiest fit

The lesson's stabilizing knob reduces the decision score by 20%. In practice that knob might be stricter feature availability checks, cross-fitting, stronger regularization, or a more realistic validation split. The arithmetic shows the final rule: compare baseline, flexible alternative, and stabilized score on the same scale.

```python
stable_w = 0.80 * score_w  # 20% score reduction from a stabilizing procedure.
choices_w = np.array([score_w, alternative_w, stable_w])
names_w = np.array(["baseline", "flexible", "stabilized"])
best_w = names_w[np.argmin(choices_w)]
print("stable score:", round(float(stable_w), 3))
print("best choice:", best_w)
assert round(float(stable_w), 3) == 0.261
assert best_w == "stabilized"
```
▶ What you'll see: the stabilized score 0.261 is the minimum of the three decision scores.

```python
plt.figure(figsize=(5, 3))
plt.bar(names_w, choices_w, color=["teal", "crimson", "seagreen"])
plt.ylabel("decision score")
plt.title("5: stabilized model wins on honest scale")
plt.show()
```
▶ What you'll see: the lowest bar belongs to the stabilized version, not the flexible alternative.

*Why it's done this way:* stabilization is valuable because it changes the expected future score, not because it makes the training notebook look clever. The correct comparison unit is the complete score under the same validation contract.

### ✍️ Toy 1 · Time order defines the allowed information set

A future validation row must occur after every training row, so preprocessing and fitting can only use the past rows.

```python
import numpy as np
import matplotlib.pyplot as plt

t1_rng = np.random.default_rng(0)
t1_time = np.arange(8)
print("time index:", t1_time.tolist())  # -> [0, 1, 2, 3, 4, 5, 6, 7]
t1_y = np.array([0, 0, 1, 1, 0, 1, 0, 1])
print("labels:", t1_y.tolist())  # -> [0, 0, 1, 1, 0, 1, 0, 1]
t1_allowed_x = np.array([0.1, 0.2, 0.8, 0.7, 0.3, 0.9, 0.4, 0.6])
print("allowed feature:", t1_allowed_x.tolist())  # -> [0.1, 0.2, 0.8, 0.7, 0.3, 0.9, 0.4, 0.6]
t1_train = t1_time < 5
print("train mask:", t1_train.tolist())  # -> [True, True, True, True, True, False, False, False]
t1_val = ~t1_train
print("validation mask:", t1_val.tolist())  # -> [False, False, False, False, False, True, True, True]
t1_last_train = int(t1_time[t1_train].max())
print("last train time:", t1_last_train)  # -> 4
t1_first_val = int(t1_time[t1_val].min())
print("first validation time:", t1_first_val)  # -> 5

plt.figure(figsize=(4.8, 2.8))
plt.scatter(t1_time[t1_train], t1_y[t1_train], color="teal", label="train")
plt.scatter(t1_time[t1_val], t1_y[t1_val], color="orange", label="future validation")
plt.plot(t1_time, t1_allowed_x, color="gray", linestyle="--", label="allowed feature")
plt.xlabel("time")
plt.ylabel("value")
plt.title("Toy 1 · past predicts future")
plt.legend()
plt.show()

assert t1_last_train < t1_first_val
```
▶ What you'll see: every validation point is to the right of the training window.

### ✍️ Toy 2 · A target-derived feature gives suspiciously perfect validation

A leaky feature made from the label turns validation into answer-copying instead of prediction.

```python
import numpy as np

t2_rng = np.random.default_rng(0)
t2_y = np.array([0, 1, 0, 1, 0, 1, 1, 0], dtype=float)
print("labels:", t2_y.tolist())  # -> [0.0, 1.0, 0.0, 1.0, 0.0, 1.0, 1.0, 0.0]
t2_allowed_x = np.array([0.1, 0.7, 0.4, 0.8, 0.2, 0.6, 0.3, 0.9])
print("allowed feature:", t2_allowed_x.tolist())  # -> [0.1, 0.7, 0.4, 0.8, 0.2, 0.6, 0.3, 0.9]
t2_leaky_x = 0.1 + 0.8 * t2_y
print("leaky feature:", t2_leaky_x.tolist())  # -> [0.1, 0.9, 0.1, 0.9, 0.1, 0.9, 0.9, 0.1]
t2_val = np.arange(t2_y.size) >= 5
print("validation mask:", t2_val.tolist())  # -> [False, False, False, False, False, True, True, True]
t2_pred_allowed = (t2_allowed_x >= 0.5).astype(float)
print("allowed predictions:", t2_pred_allowed.tolist())  # -> [0.0, 1.0, 0.0, 1.0, 0.0, 1.0, 0.0, 1.0]
t2_pred_leaky = (t2_leaky_x >= 0.5).astype(float)
print("leaky predictions:", t2_pred_leaky.tolist())  # -> [0.0, 1.0, 0.0, 1.0, 0.0, 1.0, 1.0, 0.0]
t2_allowed_loss = (t2_pred_allowed[t2_val] - t2_y[t2_val]) ** 2
print("allowed validation losses:", t2_allowed_loss.tolist())  # -> [0.0, 1.0, 1.0]
t2_leaky_loss = (t2_pred_leaky[t2_val] - t2_y[t2_val]) ** 2
print("leaky validation losses:", t2_leaky_loss.tolist())  # -> [0.0, 0.0, 0.0]
t2_allowed_mse = float(t2_allowed_loss.mean())
print("allowed validation MSE:", round(t2_allowed_mse, 3))  # -> 0.667
t2_leaky_mse = float(t2_leaky_loss.mean())
print("leaky validation MSE:", round(t2_leaky_mse, 3))  # -> 0.0

plt.figure(figsize=(4.4, 2.8))
plt.bar(["allowed", "leaky"], [t2_allowed_mse, t2_leaky_mse], color=["teal", "crimson"])
plt.ylabel("validation MSE")
plt.title("Toy 2 · leaked answer wins falsely")
plt.show()

assert t2_leaky_mse == 0.0 and t2_allowed_mse > 0.6
```
▶ What you'll see: the leaky feature gets zero validation loss because it already contains the answer.

### ✍️ Toy 3 · Target encoding must use training labels only

A category mean computed on all rows lets validation labels alter their own encoded feature.

```python
import numpy as np

t3_rng = np.random.default_rng(0)
t3_group = np.array(["A", "A", "B", "B", "A", "A", "B", "B"])
print("groups:", t3_group.tolist())  # -> ['A', 'A', 'B', 'B', 'A', 'A', 'B', 'B']
t3_y = np.array([0, 1, 0, 1, 0, 1, 1, 0], dtype=float)
print("labels:", t3_y.tolist())  # -> [0.0, 1.0, 0.0, 1.0, 0.0, 1.0, 1.0, 0.0]
t3_train = np.arange(t3_y.size) < 5
print("train mask:", t3_train.tolist())  # -> [True, True, True, True, True, False, False, False]
t3_full_A = float(t3_y[t3_group == "A"].mean())
print("full-data mean for A:", round(t3_full_A, 3))  # -> 0.5
t3_train_A = float(t3_y[t3_train & (t3_group == "A")].mean())
print("train-only mean for A:", round(t3_train_A, 3))  # -> 0.333
t3_encoded_full = np.array([t3_y[t3_group == t3_g].mean() for t3_g in t3_group])
print("full-data encoding:", np.round(t3_encoded_full, 3).tolist())  # -> [0.5, 0.5, 0.5, 0.5, 0.5, 0.5, 0.5, 0.5]
t3_encoded_train = np.zeros_like(t3_y)
for t3_g in np.unique(t3_group):
    t3_group_train = t3_train & (t3_group == t3_g)
    t3_encoded_train[t3_group == t3_g] = t3_y[t3_group_train].mean()
print("train-only encoding:", np.round(t3_encoded_train, 3).tolist())  # -> [0.333, 0.333, 0.5, 0.5, 0.333, 0.333, 0.5, 0.5]
t3_val = ~t3_train
print("validation mask:", t3_val.tolist())  # -> [False, False, False, False, False, True, True, True]
t3_pred_full = (t3_encoded_full[t3_val] >= 0.5).astype(float)
print("full-data validation predictions:", t3_pred_full.tolist())  # -> [1.0, 1.0, 1.0]
t3_pred_train = (t3_encoded_train[t3_val] >= 0.5).astype(float)
print("train-only validation predictions:", t3_pred_train.tolist())  # -> [0.0, 1.0, 1.0]
t3_loss_full = (t3_pred_full - t3_y[t3_val]) ** 2
print("full-data validation losses:", t3_loss_full.tolist())  # -> [0.0, 0.0, 1.0]
t3_loss_train = (t3_pred_train - t3_y[t3_val]) ** 2
print("train-only validation losses:", t3_loss_train.tolist())  # -> [1.0, 0.0, 1.0]
t3_mse_full = float(t3_loss_full.mean())
print("leaky encoding MSE:", round(t3_mse_full, 3))  # -> 0.333
t3_mse_train = float(t3_loss_train.mean())
print("clean encoding MSE:", round(t3_mse_train, 3))  # -> 0.667

plt.figure(figsize=(4.8, 2.8))
plt.plot(np.arange(t3_y.size), t3_encoded_full, "o-", label="full data")
plt.plot(np.arange(t3_y.size), t3_encoded_train, "s--", label="train only")
plt.xlabel("row")
plt.ylabel("encoded value")
plt.title("Toy 3 · validation labels change full encoding")
plt.legend()
plt.show()

assert t3_full_A != t3_train_A and t3_mse_full < t3_mse_train
```
▶ What you'll see: the full-data encoding uses future labels and therefore changes the validation features.

### ✍️ Toy 4 · Honest scores add cost before comparing gaps

Leakage often flatters the raw score, so compare the full score and its gap to the alternative.

```python
import numpy as np

t4_rng = np.random.default_rng(0)
t4_losses = np.array([0.2, 0.1, 0.5, 0.2, 0.3, 0.1])
print("honest losses:", t4_losses.tolist())  # -> [0.2, 0.1, 0.5, 0.2, 0.3, 0.1]
t4_risk = float(t4_losses.mean())
print("honest risk:", round(t4_risk, 3))  # -> 0.233
t4_cost = 0.07
print("protocol cost:", t4_cost)  # -> 0.07
t4_score = t4_risk + t4_cost
print("honest score:", round(t4_score, 3))  # -> 0.303
t4_alternative = 0.36
print("alternative score:", t4_alternative)  # -> 0.36
t4_gap = t4_alternative - t4_score
print("absolute gap:", round(t4_gap, 3))  # -> 0.057
t4_relative_gap = t4_gap / t4_alternative
print("relative gap:", round(t4_relative_gap, 3))  # -> 0.157

plt.figure(figsize=(4.6, 2.8))
plt.bar(["risk", "+ cost", "alternative"], [t4_risk, t4_score, t4_alternative], color=["gray", "teal", "crimson"])
plt.ylabel("score")
plt.title("Toy 4 · compare honest scores")
plt.show()

assert round(t4_score, 3) == 0.303 and t4_gap > 0
```
▶ What you'll see: the raw risk is not the comparison; the cost-adjusted score beats the alternative by `0.057`.

### ✍️ Toy 5 · Stabilization beats the prettiest leaky fit

A leaky raw score can look best until the leakage penalty is included; the stabilized honest score is the one to carry forward.

```python
import numpy as np

t5_rng = np.random.default_rng(0)
t5_baseline = 0.30
print("baseline honest score:", t5_baseline)  # -> 0.3
t5_leaky_raw = 0.26
print("leaky raw score:", t5_leaky_raw)  # -> 0.26
t5_leakage_penalty = 0.10
print("leakage penalty:", t5_leakage_penalty)  # -> 0.1
t5_leaky_honest = t5_leaky_raw + t5_leakage_penalty
print("leaky honest score:", round(t5_leaky_honest, 3))  # -> 0.36
t5_stabilized = 0.80 * t5_baseline
print("stabilized score:", round(t5_stabilized, 3))  # -> 0.24
t5_scores = np.array([t5_leaky_raw, t5_leaky_honest, t5_stabilized])
print("scores:", np.round(t5_scores, 3).tolist())  # -> [0.26, 0.36, 0.24]
t5_names = np.array(["leaky raw", "leaky honest", "stabilized"])
print("names:", t5_names.tolist())  # -> ['leaky raw', 'leaky honest', 'stabilized']
t5_winner = str(t5_names[np.argmin(t5_scores)])
print("winner:", t5_winner)  # -> stabilized

plt.figure(figsize=(4.8, 2.8))
plt.bar(t5_names, t5_scores, color=["orange", "crimson", "seagreen"])
plt.ylabel("score")
plt.xticks(rotation=15)
plt.title("Toy 5 · robust score survives")
plt.show()

assert t5_winner == "stabilized"
```
▶ What you'll see: the leaky raw score is tempting, but the stabilized honest score is the lowest fair score.

## 🟢 Basics (warm-up)

### Basic 1 — Average the empirical losses

**Goal.** Compute the toy empirical risk from three losses, because leakage discussions still start from the ordinary average loss. We build it in 2 steps.

```python
losses_b1 = np.array([0.257, 0.122, 0.420])  # store the verified per-example losses from the lesson block.
print("losses:", losses_b1)  # inspect each example's contribution before averaging.
```
▶ What you'll see: three small losses whose mean is the empirical risk.

```python
risk_b1 = float(np.mean(losses_b1))  # average the losses to compute R_S.
print("R_S:", round(risk_b1, 3))  # inspect the empirical risk.
assert round(risk_b1, 3) == 0.266  # verify the lesson number.
plt.figure(figsize=(4, 3))
plt.bar(["ex1", "ex2", "ex3", "mean"], list(losses_b1) + [risk_b1], color=["gray", "gray", "gray", "teal"])
plt.title("Basic 1: empirical risk is an average")
plt.ylabel("loss")
plt.show()
```
▶ What you'll see: the mean bar summarizes the three individual losses.

👀 Takeaway: empirical risk is just an average, so a single contaminated loss can contaminate the score.

### Basic 2 — Add the required cost term

**Goal.** Add the method cost to the raw risk, because the lesson's fair decision score is not the raw fit alone. We build it in 2 steps.

```python
risk_b2 = 0.266  # use the rounded empirical risk from the worked example.
cost_b2 = 0.060  # store the complexity, regularization, or operational cost.
print("risk:", risk_b2, "cost:", cost_b2)  # inspect the two terms before combining.
```
▶ What you'll see: the cost is smaller than the risk but still large enough to change comparisons.

```python
score_b2 = risk_b2 + cost_b2  # compute the full selection score.
print("decision score:", round(score_b2, 3))  # inspect the score used for model choice.
assert round(score_b2, 3) == 0.326  # verify the lesson number.
plt.figure(figsize=(4, 3))
plt.bar(["risk", "cost", "total"], [risk_b2, cost_b2, score_b2], color=["teal", "orange", "purple"])
plt.title("Basic 2: raw fit plus cost")
plt.ylabel("score")
plt.show()
```
▶ What you'll see: the total bar is risk plus cost.

👀 Takeaway: leakage often hides behind a great raw score, so use the full decision score.

### Basic 3 — Compute the gap to a flexible alternative

### Advanced 1 — Cross-fit target encoding

**Goal.** Encode categories without using a row's own label, because out-of-fold encodings reduce target leakage while preserving useful category signal. We build it in 4 steps.

```python

```
▶ What you'll see: the global mean is the fallback when a fold lacks a category.

```python

for f_a1 in np.unique(fold_a1):
    fit_a1 = fold_a1 != f_a1  # fit encoding on other folds only.
    apply_a1 = fold_a1 == f_a1  # apply to held-out fold.
    for g_a1 in np.unique(group_a1):
        rows_fit_a1 = fit_a1 & (group_a1 == g_a1)
        value_a1 = np.mean(y_a1[rows_fit_a1]) if np.any(rows_fit_a1) else global_mean_a1
        enc_oof_a1[apply_a1 & (group_a1 == g_a1)] = value_a1
```

```python

```

```python
plt.show()
```

### Advanced 4 — Simulate leaderboard overfitting
