# 3.19 — Gradient Descent Variants

Gradient descent variants decide how much data to use before taking the next step downhill. In this lesson, you will build batch gradient descent, stochastic gradient descent, and mini-batch gradient descent from first principles, inspect the gradients they compute, and see why batch size trades gradient accuracy against update frequency, noise, and practical cost.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build gradient descent variants one idea at a time. Run each cell in order and read the printed intermediate values — every gradient is derived from per-example losses, then averaged over the batch that produced the update. This walkthrough is self-contained and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays, vectorized gradients, and reproducible sampling.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
np.random.seed(0)  # reproducibility for shuffles and synthetic data.
```

### 1. Empirical risk starts as per-example losses

A supervised model is not judged by one magic number from nowhere. It is judged by a loss on each training example, then by the average of those losses: $R_S(w)=\frac1n\sum_i \ell_i(w)$. For a one-parameter linear model $\hat y=w x$ with squared loss $\ell_i(w)=\frac12(wx_i-y_i)^2$, every example also has its own gradient $\nabla_w\ell_i(w)=(wx_i-y_i)x_i$. The variants in this lesson differ only in which subset of these per-example gradients they average before stepping.

```python
x_w = np.array([1., 2., 3., 4.])  # four one-dimensional training inputs.
y_w = np.array([1.2, 1.9, 3.2, 3.8])  # targets close to the rule y ≈ x.
w0_w = 0.4  # deliberately poor initial slope.
preds_w = w0_w * x_w  # predictions from the current slope.
losses_w = 0.5 * (preds_w - y_w) ** 2  # per-example squared losses.
print("predictions:", np.round(preds_w, 3))
print("per-example losses:", np.round(losses_w, 3))
print("empirical risk:", round(float(np.mean(losses_w)), 3))
assert round(float(np.mean(losses_w)), 3) == 1.336
```
▶ What you'll see: the current slope under-predicts every point, so every loss is positive and the average risk is 1.336.

```python
grads_w = (preds_w - y_w) * x_w  # derivative of 1/2(wx-y)^2 with respect to w.
print("per-example gradients:", np.round(grads_w, 3))
print("mean gradient:", round(float(np.mean(grads_w)), 3))
assert round(float(np.mean(grads_w)), 3) == -4.45
plt.figure(figsize=(4.5, 3))
plt.bar(["i0", "i1", "i2", "i3"], grads_w, color="teal")
plt.axhline(float(np.mean(grads_w)), color="red", linestyle="--", label="mean gradient")
plt.title("1: per-example gradients")
plt.ylabel("gradient contribution")
plt.legend()
plt.show()
```
▶ What you'll see: all gradients are negative, meaning increasing the slope will reduce the loss.

*Why it's done this way:* squared loss is chosen because its derivative is simple and smooth: the residual $(wx_i-y_i)$ says the direction and size of the miss, and multiplying by $x_i$ says how strongly changing $w$ affects that example. Averaging the gradients matches the empirical-risk objective, because the derivative of an average is the average of derivatives.

### 2. Batch gradient descent uses the whole dataset per update

Batch gradient descent sets $B_t$ equal to all training examples. The update is

$$w_{t+1}=w_t-\eta\frac1n\sum_{i=1}^n\nabla_w\ell_i(w_t).$$

This gives the most faithful gradient for the empirical risk at the current point, but each update costs a full pass through the data.

```python
eta_w = 0.08  # learning rate for a visible but stable first step.
batch_grad_w = float(np.mean(grads_w))  # average over all four examples.
w1_batch_w = w0_w - eta_w * batch_grad_w  # descent subtracts the gradient.
print("batch gradient:", round(batch_grad_w, 3))
print("w after one batch step:", round(w1_batch_w, 3))
assert round(w1_batch_w, 3) == 0.756
```
▶ What you'll see: the slope jumps from 0.400 to 0.798 because the average gradient is strongly negative.

```python
w_grid_w = np.linspace(0, 1.5, 120)  # candidate slopes for visualizing the loss curve.
risk_grid_w = np.array([np.mean(0.5 * (w * x_w - y_w) ** 2) for w in w_grid_w])
plt.figure(figsize=(4.6, 3))
plt.plot(w_grid_w, risk_grid_w, color="purple")
plt.scatter([w0_w, w1_batch_w], [np.mean(losses_w), np.mean(0.5 * (w1_batch_w * x_w - y_w) ** 2)], color=["red", "green"])
plt.title("2: one batch step on empirical risk")
plt.xlabel("w")
plt.ylabel("average loss")
plt.show()
```
▶ What you'll see: the new point lands lower on the empirical-risk curve than the starting point.

*Why it's done this way:* using every example makes the update direction exactly match the gradient of the training objective, not a noisy estimate. That accuracy is valuable when the dataset is small or gradients are cheap, but it becomes expensive when a single update must scan millions of examples.

### 3. Stochastic gradient descent updates from one example

Stochastic gradient descent sets $|B_t|=1$. A single example's gradient is a noisy estimate of the full gradient, so SGD can move often and cheaply, but its path wiggles because each point tells only part of the story.

```python
idx_w = 2  # use one training example as the current stochastic batch.
sgd_grad_w = float(grads_w[idx_w])  # one-example gradient estimate.
w1_sgd_w = w0_w - eta_w * sgd_grad_w  # same update rule, smaller batch.
print("example index:", idx_w)
print("single-example gradient:", round(sgd_grad_w, 3))
print("w after one SGD step:", round(w1_sgd_w, 3))
assert round(w1_sgd_w, 3) == 0.88
```
▶ What you'll see: one example pushes harder than the batch average, so the slope moves farther in one update.

```python
plt.figure(figsize=(4.8, 3))
plt.bar(["batch mean", "example 2"], [batch_grad_w, sgd_grad_w], color=["gray", "orange"])
plt.axhline(0, color="black", linewidth=0.8)
plt.title("3: SGD gradient is a noisy estimate")
plt.ylabel("gradient")
plt.show()
```
▶ What you'll see: the one-example gradient has the same sign as the batch gradient here, but a different magnitude.

*Why it's done this way:* if examples are sampled uniformly, the expected one-example gradient equals the full gradient. That makes SGD statistically legitimate while being computationally cheap. The price is variance: the current step may overreact to an unusual point, so SGD usually needs smaller learning rates and multiple passes.

### 4. Mini-batch gradient descent averages a small subset

Mini-batch descent chooses a batch bigger than one but smaller than the full dataset. It averages away some SGD noise while still updating more frequently than batch descent. This is the practical default in most large-scale learning systems.

```python
batch_ids_w = np.array([1, 2])  # a two-example mini-batch.
mini_grad_w = float(np.mean(grads_w[batch_ids_w]))  # average only those examples.
w1_mini_w = w0_w - eta_w * mini_grad_w
print("mini-batch ids:", batch_ids_w)
print("mini-batch gradient:", round(mini_grad_w, 3))
print("w after one mini-batch step:", round(w1_mini_w, 3))
assert round(w1_mini_w, 3) == 0.728
```
▶ What you'll see: the mini-batch step is between the batch and single-example steps.

```python
plt.figure(figsize=(4.8, 3))
plt.bar(["SGD |B|=1", "mini |B|=2", "batch |B|=4"], [sgd_grad_w, mini_grad_w, batch_grad_w], color=["orange", "teal", "gray"])
plt.axhline(0, color="black", linewidth=0.8)
plt.title("4: batch size controls gradient noise")
plt.ylabel("gradient used for one update")
plt.xticks(rotation=15)
plt.show()
```
▶ What you'll see: the mini-batch gradient sits closer to the full gradient than the one-example gradient does.

*Why it's done this way:* averaging independent gradient samples reduces variance roughly like $1/|B|$, so a mini-batch is a compromise: less noisy than SGD, much cheaper per update than full batch, and friendly to vectorized hardware because several examples are processed at once.

### 5. Epochs and shuffling decide which examples speak next

An epoch is one pass through the training set. For SGD and mini-batch methods, we usually shuffle examples at the start of each epoch, then consume them in chunks. Shuffling prevents the model from seeing a fixed curriculum that could bias the update path.

```python
rng_w = np.random.default_rng(0)  # local generator for reproducible shuffles.
order_w = rng_w.permutation(len(x_w))  # one shuffled epoch order.
batches_w = [order_w[i:i+2] for i in range(0, len(order_w), 2)]  # mini-batches of size 2.
print("shuffled order:", order_w)
print("mini-batches:", batches_w)
assert len(batches_w) == 2
```
▶ What you'll see: every index appears exactly once, but in randomized order, split into two mini-batches.

```python
w_epoch_w = w0_w
path_epoch_w = [w_epoch_w]
for batch_w in batches_w:
    grad_w = float(np.mean((w_epoch_w * x_w[batch_w] - y_w[batch_w]) * x_w[batch_w]))
    w_epoch_w = w_epoch_w - eta_w * grad_w
    path_epoch_w.append(w_epoch_w)
print("w path through one shuffled epoch:", np.round(path_epoch_w, 3))
assert len(path_epoch_w) == 3
plt.figure(figsize=(4.5, 3))
plt.plot(path_epoch_w, marker="o", color="seagreen")
plt.title("5: two mini-batch updates in one epoch")
plt.xlabel("update number")
plt.ylabel("w")
plt.show()
```
▶ What you'll see: the parameter changes twice in one epoch because each mini-batch triggers its own update.

*Why it's done this way:* an epoch is a bookkeeping unit for comparing methods fairly, while shuffling makes the mini-batch gradient an unbiased-looking sample of the dataset. Without shuffling, correlated examples can create repeated pushes in the same direction before the model hears from the rest of the data.

### 6. Batch size changes cost, noise, and validation behavior

The final design choice is not just mathematical; it is operational. Batch uses accurate gradients but few updates per pass. SGD uses many cheap noisy updates. Mini-batch lives between them. We compare their paths on the same small regression problem and then check a validation point so the training objective does not become the only story.

```python
x_train_w = np.linspace(0.5, 4.0, 8)  # small training set.
y_train_w = 1.1 * x_train_w + np.array([0.2, -0.1, 0.1, -0.2, 0.15, -0.05, 0.05, -0.1])
x_val_w = np.array([4.5, 5.0])  # held-out future-like inputs.
y_val_w = 1.1 * x_val_w + np.array([0.0, 0.1])
print("train size:", len(x_train_w), "validation size:", len(x_val_w))
```
▶ What you'll see: training and validation are separate, so a lower training loss is not the only criterion.

```python
def run_variant_w(batch_size_w, epochs_w=12, eta_local_w=0.04):
    w_w = 0.0
    train_curve_w, val_curve_w = [], []
    rng_local_w = np.random.default_rng(1)
    for epoch_w in range(epochs_w):
        order_local_w = rng_local_w.permutation(len(x_train_w))
        for start_w in range(0, len(order_local_w), batch_size_w):
            ids_w = order_local_w[start_w:start_w+batch_size_w]
            grad_local_w = float(np.mean((w_w * x_train_w[ids_w] - y_train_w[ids_w]) * x_train_w[ids_w]))
            w_w -= eta_local_w * grad_local_w
        train_curve_w.append(float(np.mean(0.5 * (w_w * x_train_w - y_train_w) ** 2)))
        val_curve_w.append(float(np.mean(0.5 * (w_w * x_val_w - y_val_w) ** 2)))
    return w_w, np.array(train_curve_w), np.array(val_curve_w)

results_w = {"SGD": run_variant_w(1), "mini-batch": run_variant_w(2), "batch": run_variant_w(len(x_train_w))}
for name_w, (w_final_w, train_w, val_w) in results_w.items():
    print(name_w, "final w:", round(w_final_w, 3), "final val loss:", round(float(val_w[-1]), 4))
```
▶ What you'll see: all variants move toward the same slope, but their validation curves need not be identical.

```python
plt.figure(figsize=(5, 3))
for name_w, (_, train_w, val_w) in results_w.items():
    plt.plot(val_w, marker="o", label=name_w)
plt.title("6: validation loss by gradient variant")
plt.xlabel("epoch")
plt.ylabel("validation loss")
plt.legend()
plt.show()
```
▶ What you'll see: batch is smooth, SGD can wiggle, and mini-batch often gives a useful middle path.

*Why it's done this way:* the formula $w_{t+1}=w_t-\eta |B_t|^{-1}\sum_{i\in B_t}\nabla\ell_i(w_t)$ makes batch size the knob for the update estimate. Larger batches reduce gradient noise but spend more examples per update; smaller batches produce more frequent but noisier movement. Validation keeps that optimization bargain tied to future performance instead of just training convenience.

## 🟢 Basics (warm-up)

### Basic 1 — Average three losses

**Goal.** Compute empirical risk from per-example losses, because gradient methods optimize averages over training examples.

```python
losses_b1 = np.array([0.191, 0.083, 0.420])
risk_b1 = float(np.mean(losses_b1))
print("losses:", losses_b1)
print("empirical risk:", round(risk_b1, 3))
assert round(risk_b1, 3) == 0.231
```
▶ What you'll see: the three losses average to 0.231, matching the lesson's tiny training score.

```python
plt.figure(figsize=(4, 3))
plt.bar(["ex0", "ex1", "ex2"], losses_b1, color="teal")
plt.axhline(risk_b1, color="red", linestyle="--", label="average")
plt.title("Basic 1: empirical risk is an average")
plt.ylabel("loss")
plt.legend()
plt.show()
```
▶ What you'll see: the average line sits between the smallest and largest per-example losses.

👀 Takeaway: empirical risk is a mean, so every example contributes one term to the objective.

### Basic 2 — Add a method cost

**Goal.** Add an operational or regularization cost to the raw training score, because model selection should not chase fit alone.

```python
risk_b2 = 0.231
cost_b2 = 0.060
score_b2 = risk_b2 + cost_b2
print("risk:", risk_b2, "cost:", cost_b2, "score:", round(score_b2, 3))
assert round(score_b2, 3) == 0.291
```
▶ What you'll see: the final decision score is 0.291, not just the raw risk 0.231.

```python
plt.figure(figsize=(4, 3))
plt.bar(["risk", "cost", "total"], [risk_b2, cost_b2, score_b2], color=["teal", "orange", "gray"])
plt.title("Basic 2: score includes cost")
plt.ylabel("score component")
plt.show()
```
▶ What you'll see: the cost is smaller than the raw risk but changes the number used for selection.

👀 Takeaway: a training score is only one part of the decision when stability or cost matters.

### Basic 3 — Compare a tempting alternative

**Goal.** Compute absolute and relative gaps, because lower scores matter only if the margin is large enough to trust.

```python
baseline_b3 = 0.291
alternative_b3 = 0.343
gap_b3 = alternative_b3 - baseline_b3
relative_gap_b3 = gap_b3 / alternative_b3
print("gap:", round(gap_b3, 3))

assert round(relative_gap_b3, 3) == 0.152
```
▶ What you'll see: the baseline is lower by 0.052, about 15.2% of the alternative score.

```python
plt.figure(figsize=(4, 3))
plt.bar(["baseline", "alternative"], [baseline_b3, alternative_b3], color=["seagreen", "crimson"])
plt.title("Basic 3: compare full decision scores")
plt.ylabel("lower is better")
plt.show()
```
▶ What you'll see: the baseline bar is visibly lower, but the gap is still a quantity to check.

👀 Takeaway: score gaps should be read as evidence strength, not just as winner labels.

### Basic 4 — Apply a stabilizing knob

**Goal.** Reduce a score by a fixed stability factor, because constraints can trade flexibility for a more durable decision.

```python
score_b4 = 0.291
factor_b4 = 0.80
stable_b4 = factor_b4 * score_b4
print("stabilized score:", round(stable_b4, 3))
assert round(stable_b4, 3) == 0.233
```
▶ What you'll see: a 20% reduction moves the score from 0.291 to 0.233.

```python
plt.figure(figsize=(4, 3))

plt.show()
```
▶ What you'll see: the stabilized score is lower, so it would win in a lower-is-better comparison.

👀 Takeaway: the score used for selection should include the stability assumptions built into the method.

### Basic 5 — Pick the lowest complete score

**Goal.** Select among baseline, flexible, and stabilized scores, because gradient methods are compared by full decision quantities.

```python
scores_b5 = np.array([0.291, 0.343, 0.233])
labels_b5 = np.array(["baseline", "flexible", "stabilized"])
best_idx_b5 = int(np.argmin(scores_b5))
```

```python
plt.figure(figsize=(4.5, 3))

```
▶ What you'll see: the minimum bar is the stabilized method, not the raw baseline or flexible alternative.

👀 Takeaway: model selection compares complete scores on the same scale.

### Basic 6 — Compute one squared-loss gradient

**Goal.** Differentiate one training example, because SGD uses exactly this single-example gradient.

```python
x_b6 = 3.0

pred_b6 = w_b6 * x_b6
```

### Basic 8 — Take one descent step

**Goal.** Apply $w\leftarrow w-\eta g$, because all gradient descent variants share the same update rule after choosing a gradient estimate.

```python
w_b8 = 0.4
eta_b8 = 0.08
grad_b8 = -4.85
w_next_b8 = w_b8 - eta_b8 * grad_b8

```
▶ What you'll see: subtracting a negative gradient increases the parameter.

```python
plt.figure(figsize=(4, 3))

plt.show()
```
▶ What you'll see: the parameter moves upward because the model was under-predicting.

👀 Takeaway: descent means moving opposite the gradient, not necessarily moving downward on the parameter axis.

### Easy 2 — Run stochastic gradient descent

**Goal.** Train with one example at a time, because SGD trades gradient accuracy for many cheap updates.

```python
x_e2 = np.array([1., 2., 3., 4.])
y_e2 = np.array([1.2, 1.9, 3.2, 3.8])
w_e2 = 0.0
eta_e2 = 0.03
losses_e2 = []
rng_e2 = np.random.default_rng(2)
print("initial w:", w_e2)
```
▶ What you'll see: SGD starts from the same kind of poor slope.

```python
for epoch_e2 in range(18):
    for i_e2 in rng_e2.permutation(len(x_e2)):
        grad_e2 = float((w_e2 * x_e2[i_e2] - y_e2[i_e2]) * x_e2[i_e2])
        w_e2 = w_e2 - eta_e2 * grad_e2
```

### Advanced 3 — Add momentum to noisy SGD

**Goal.** Smooth stochastic gradients with a velocity term, because momentum can reduce zig-zagging from noisy updates.

```python
x_a3 = np.array([1., 2., 3., 4., 5., 6.])
y_a3 = 1.2 * x_a3 + np.array([0.3, -0.2, 0.2, -0.1, 0.1, -0.3])
eta_a3 = 0.02
beta_a3 = 0.8
print("eta:", eta_a3, "momentum beta:", beta_a3)
```
▶ What you'll see: beta controls how much previous gradient direction is remembered.

```python
rng_a3 = np.random.default_rng(33)
paths_plain_a3, paths_mom_a3 = [], []
w_plain_a3, w_mom_a3, velocity_a3 = 0.0, 0.0, 0.0
for step_a3 in range(60):
    i_a3 = int(rng_a3.integers(0, len(x_a3)))
    grad_plain_a3 = float((w_plain_a3 * x_a3[i_a3] - y_a3[i_a3]) * x_a3[i_a3])
    w_plain_a3 -= eta_a3 * grad_plain_a3
    grad_mom_a3 = float((w_mom_a3 * x_a3[i_a3] - y_a3[i_a3]) * x_a3[i_a3])
    velocity_a3 = beta_a3 * velocity_a3 + (1 - beta_a3) * grad_mom_a3
    w_mom_a3 -= eta_a3 * velocity_a3
    paths_plain_a3.append(w_plain_a3)
    paths_mom_a3.append(w_mom_a3)

```
▶ What you'll see: both methods learn, but momentum changes the smoothness of the path.

