# 8.16 — Language Model Evaluation

Language-model evaluation is not one question with one answer: perplexity measures how surprised a model is by reference tokens, BLEU measures how much candidate text is supported by reference n-grams, ROUGE measures how much reference content is covered, and METEOR-style scores deliberately rebalance precision and recall. In this lesson, we build each metric from scratch so the arithmetic makes the tradeoffs visible instead of hiding them behind leaderboard numbers.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build language-model evaluation one idea at a time. Run each cell in order and read the printed intermediate values — every piece of math, including clipped overlap and weighted harmonic means, is shown from scratch. This walkthrough is self-contained and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays, logs, exponentials, and vectorized metric arithmetic.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
from collections import Counter  # exact n-gram counting for overlap metrics.
np.random.seed(0)  # reproducibility for any small random demonstrations.
```

### 1. Perplexity: exponentiated average surprise

A language model assigns a probability to each next token in a reference sequence. **Negative log-likelihood** turns each probability into a surprise value: high probability gives a small surprise, low probability gives a large surprise. **Perplexity** exponentiates the average surprise, so it reads like an effective number of equally likely choices the model faced per token.

```python
probs_w = np.array([0.5, 0.25, 0.25])  # model probabilities assigned to the three correct next tokens.
surprises_w = -np.log(probs_w)  # token-level negative log-likelihoods in natural-log units.
print("token probabilities:", probs_w)  # inspect the model's confidence on each token.
print("token surprises:", np.round(surprises_w, 6))  # inspect how low probability becomes high surprise.
```
▶ What you'll see: the 0.25-probability tokens have larger surprise than the 0.5-probability token.

```python
cross_entropy_w = float(np.mean(surprises_w))  # average surprise per reference token.
perplexity_w = float(np.exp(cross_entropy_w))  # exponentiate to convert log surprise back to an effective branching factor.
print("cross-entropy:", cross_entropy_w)  # 1.155245300933242.
print("perplexity:", perplexity_w)  # 3.1748021039363983.
assert abs(perplexity_w - 3.174802103936399) < 1e-12  # self-check the lesson number.
```
▶ What you'll see: average surprise is about 1.155, and perplexity is about 3.175.

```python
plt.figure(figsize=(4.6, 3))  # create a compact bar chart for token surprises.
plt.bar(["t1", "t2", "t3"], surprises_w, color="teal")  # show each token's contribution to average loss.
plt.axhline(cross_entropy_w, color="black", linestyle="--", label="mean NLL")  # mark the average surprise.
plt.title("1: perplexity averages token surprise")  # title the diagnostic plot.
plt.ylabel("-log p(correct token)")  # label the loss scale.
plt.legend()  # show the mean-surprise reference.
plt.show()  # display the chart.
```
▶ What you'll see: two bars sit above the mean because the model assigned only 0.25 probability to those correct tokens.

*Why it's done this way:* log loss is additive across tokens, so averaging $-\log p(x_t\mid x_{<t})$ gives one per-token surprise even for sequences of different lengths. Exponentiating that average reverses the log scale: if every correct token had probability $1/4$, cross-entropy would be $\log 4$ and perplexity would be exactly 4. Lower perplexity therefore means the model placed more probability on the observed reference tokens, but it never checks whether a sampled answer is useful or semantically faithful.

### 2. BLEU-style precision: clipped candidate overlap

BLEU begins from **candidate-side precision**: of the words the model produced, how many are supported by the reference? The clipped count matters. If a candidate repeats a word many times, it cannot receive more credit for that word than the reference contains.

```python
cand_w = "the cat sat".split()  # candidate generated by a model.
ref_w = "the cat slept".split()  # reference answer.
cand_counts_w = Counter(cand_w)  # count candidate unigrams.
ref_counts_w = Counter(ref_w)  # count reference unigrams.
print("candidate counts:", cand_counts_w)  # inspect candidate-side words.
print("reference counts:", ref_counts_w)  # inspect reference-side words.
```
▶ What you'll see: `the` and `cat` appear in both strings, while `sat` and `slept` disagree.

```python
overlap_w = {word: min(cand_counts_w[word], ref_counts_w[word]) for word in cand_counts_w}  # clipped overlap by word.
bleu1_w = sum(overlap_w.values()) / sum(cand_counts_w.values())  # candidate precision.
print("clipped overlap:", overlap_w)  # inspect the credited tokens.
print("BLEU-1 precision:", bleu1_w)  # 2/3.
assert bleu1_w == 2 / 3  # self-check the lesson number.
```
▶ What you'll see: two of three candidate tokens are credited, so BLEU-1 precision is 0.667.

```python
plt.figure(figsize=(4.6, 3))  # create a candidate-token credit plot.
plt.bar(list(cand_counts_w.keys()), [overlap_w[k] for k in cand_counts_w], color="seagreen")  # show credited counts per candidate word.
plt.title("2: BLEU-1 credits supported candidate words")  # title the precision plot.
plt.ylabel("clipped overlap count")  # label the credited-count scale.
plt.show()  # display the chart.
```
▶ What you'll see: `the` and `cat` receive credit; `sat` receives none against `slept`.

*Why it's done this way:* BLEU precision asks whether generated tokens are justified by the reference, so the denominator is candidate length. Clipping is the key mathematical guardrail: without `min(candidate_count, reference_count)`, a candidate like `the the the` could harvest repeated credit from one reference `the`. This precision-heavy design punishes unsupported additions, but it can still score a semantically wrong sentence highly when many surface words match.

### 3. ROUGE-style recall: reference coverage

ROUGE-1 flips the viewpoint. Instead of asking how much of the candidate is supported, it asks how much of the reference is covered. That makes it natural for summarization, where missing important content is often the primary failure.

```python
cand_r_w = "the cat sat".split()  # candidate summary or answer.
ref_r_w = "the small cat sat".split()  # reference contains one extra content word.
cand_r_counts_w = Counter(cand_r_w)  # count candidate unigrams.
ref_r_counts_w = Counter(ref_r_w)  # count reference unigrams.
print("candidate length:", len(cand_r_w))  # candidate has three words.
print("reference length:", len(ref_r_w))  # reference has four words.
```
▶ What you'll see: the candidate is shorter and omits `small`.

```python
covered_w = {word: min(cand_r_counts_w[word], ref_r_counts_w[word]) for word in ref_r_counts_w}  # clipped reference coverage.
rouge1_w = sum(covered_w.values()) / sum(ref_r_counts_w.values())  # reference recall.
print("covered reference counts:", covered_w)  # inspect covered and missed reference words.
print("ROUGE-1 recall:", rouge1_w)  # 3/4.
assert rouge1_w == 0.75  # self-check the lesson number.
```
▶ What you'll see: three of four reference tokens are covered, so ROUGE-1 recall is 0.75.

```python
plt.figure(figsize=(4.6, 3))  # create a reference-coverage plot.
plt.bar(list(ref_r_counts_w.keys()), [covered_w[k] for k in ref_r_counts_w], color="darkorange")  # show which reference words were covered.
plt.title("3: ROUGE-1 credits covered reference words")  # title the recall plot.
plt.ylabel("covered count")  # label the coverage scale.
plt.show()  # display the chart.
```
▶ What you'll see: `small` is the only missed reference word, so every other reference token receives credit.

*Why it's done this way:* ROUGE recall uses reference length in the denominator because omissions are the error it wants to expose. A long candidate can cover all reference words and earn high recall even if it also adds unsupported claims, so ROUGE should be paired with a precision-like check whenever hallucinated additions matter.

### 4. METEOR-style weighted harmonic mean

Precision and recall often disagree, so METEOR-style scoring combines them with a weighted harmonic mean. The common form below weights recall more heavily than precision, so missing reference content can dominate the final score.

```python
P_w = 2 / 3  # precision from two supported candidate words out of three.
R_w = 2 / 4  # recall from two covered reference words out of four.
num_w = 10 * P_w * R_w  # numerator of the METEOR-style score.
den_w = R_w + 9 * P_w  # denominator that gives recall a stronger role in this convention.
print("precision:", P_w, "recall:", R_w)  # inspect the two ingredients.
print("numerator:", num_w, "denominator:", den_w)  # inspect the weighted harmonic pieces.
```
▶ What you'll see: precision is higher than recall, but both enter the combined score.

```python
meteor_w = num_w / den_w  # weighted harmonic mean used in the lesson block.
plain_f1_w = 2 * P_w * R_w / (P_w + R_w)  # unweighted harmonic mean for comparison.
print("METEOR-style score:", meteor_w)  # 0.5128205128205128.
print("plain F1:", plain_f1_w)  # higher because it does not emphasize recall the same way.
assert abs(meteor_w - 0.5128205128205128) < 1e-12  # self-check the lesson number.
```
▶ What you'll see: the recall-weighted score is about 0.513, lower than the unweighted F1.

```python
plt.figure(figsize=(4.6, 3))  # create a comparison plot for combined overlap scores.
plt.bar(["precision", "recall", "plain F1", "METEOR-style"], [P_w, R_w, plain_f1_w, meteor_w], color=["steelblue", "orange", "gray", "purple"])  # compare ingredients and combinations.
plt.ylim(0, 1)  # keep all metric values on the same 0-1 scale.
plt.title("4: weighting changes the combined score")  # title the combination plot.
plt.xticks(rotation=18)  # rotate labels so they fit.
plt.show()  # display the chart.
```
▶ What you'll see: the METEOR-style bar moves closer to recall than plain F1 does.

*Why it's done this way:* a harmonic mean is used because it is pulled down by the smaller of precision and recall; a system cannot fully hide terrible recall behind high precision. The denominator $R+9P$ is not arbitrary decoration: it encodes a product choice that recall should matter more. Changing that weight changes which failure mode is punished most.

### 5. Metric disagreement: precision-heavy and recall-heavy rankings can reverse

Metrics are lenses, not verdicts. A concise output can have high precision but low coverage, while a longer output can cover more reference content but include extra unsupported tokens. BLEU-like and ROUGE-like scores can therefore rank the same systems in opposite orders.

```python
systems_w = np.array(["fluent short", "faithful long"])  # two model outputs to compare.
bleu_w = np.array([0.80, 0.55])  # precision-heavy scores.
rouge_w = np.array([0.40, 0.85])  # recall-heavy scores.
print("BLEU winner:", systems_w[int(np.argmax(bleu_w))])  # precision prefers concise supported text.
print("ROUGE winner:", systems_w[int(np.argmax(rouge_w))])  # recall prefers better coverage.
```
▶ What you'll see: BLEU and ROUGE select different winners.

```python
bleu_gap_w = float(bleu_w[0] - bleu_w[1])  # how much BLEU prefers fluent short.
rouge_gap_w = float(rouge_w[1] - rouge_w[0])  # how much ROUGE prefers faithful long.
print("BLEU gap for fluent short:", bleu_gap_w)  # 0.25.
print("ROUGE gap for faithful long:", rouge_gap_w)  # 0.45.
assert abs(bleu_gap_w - 0.25) < 1e-12 and abs(rouge_gap_w - 0.45) < 1e-12  # self-check lesson gaps.
```
▶ What you'll see: each metric has a clear preference, but the preferences point in opposite directions.

```python
x_w = np.arange(len(systems_w))  # x positions for grouped bars.
plt.figure(figsize=(5, 3))  # create a compact ranking comparison.
plt.bar(x_w - 0.18, bleu_w, width=0.36, label="BLEU", color="seagreen")  # plot precision-heavy scores.
plt.bar(x_w + 0.18, rouge_w, width=0.36, label="ROUGE", color="darkorange")  # plot recall-heavy scores.
plt.xticks(x_w, systems_w)  # label systems.
plt.ylim(0, 1)  # keep metric values on a common scale.
plt.title("5: metric choice can reverse rankings")  # title the ranking plot.
plt.legend()  # show metric labels.
plt.show()  # display the grouped bars.
```
▶ What you'll see: the taller bar switches from the first system under BLEU to the second under ROUGE.

*Why it's done this way:* evaluation reports should name the behavior each metric rewards. Perplexity asks whether the model assigned probability to references, BLEU asks whether generated tokens are supported, ROUGE asks whether reference tokens are covered, and METEOR-style scoring chooses a precision-recall balance. Optimizing one number without stating that lens can improve the leaderboard while worsening the product behavior you actually care about.

## 🛠️ Setup

```python
import numpy as np  # load NumPy for arrays, logs, exponentials, and metric arithmetic.
import matplotlib.pyplot as plt  # load Matplotlib for every small diagnostic plot.
from collections import Counter  # load Counter for exact unigram and n-gram counting.
np.random.seed(0)  # make all stochastic examples reproducible.

def ngrams(tokens, n):  # create contiguous n-grams as tuples so they can be counted exactly.
    return [tuple(tokens[i:i + n]) for i in range(len(tokens) - n + 1)]  # return an empty list if n is longer than the sequence.

def clipped_overlap(candidate, reference, n=1):  # count candidate n-grams clipped by reference counts.
    cand_counts = Counter(ngrams(candidate, n))  # count generated n-grams.
    ref_counts = Counter(ngrams(reference, n))  # count reference n-grams.
    return sum(min(count, ref_counts[gram]) for gram, count in cand_counts.items())  # sum clipped matches.

def bleu_precision(candidate, reference, n=1):  # compute BLEU-style modified n-gram precision.
    cand_total = max(len(ngrams(candidate, n)), 1)  # denominator is candidate n-gram count, guarded for tiny candidates.
    return clipped_overlap(candidate, reference, n) / cand_total  # divide clipped matches by candidate n-grams.

def rouge_recall(candidate, reference, n=1):  # compute ROUGE-style n-gram recall.
    ref_total = max(len(ngrams(reference, n)), 1)  # denominator is reference n-gram count, guarded for tiny references.
    return clipped_overlap(candidate, reference, n) / ref_total  # divide clipped matches by reference n-grams.

def perplexity_from_probs(probs):  # compute perplexity from probabilities assigned to correct tokens.
    probs = np.asarray(probs, dtype=float)  # ensure numeric array arithmetic.
    return float(np.exp(np.mean(-np.log(probs))))  # exponentiate average negative log-likelihood.

def meteor_style(P, R):  # compute the recall-weighted overlap score from the lesson.
    return 0.0 if P == 0 or R == 0 else float((10 * P * R) / (R + 9 * P))  # harmonic-style combination with recall emphasis.
```

## 🟢 Basics (warm-up)

### Basic 1 — Token probabilities become surprise

**Goal.** Convert next-token probabilities into negative log-likelihood values, because perplexity starts by measuring token-level surprise. We build it in 2 steps.

```python
probs_b1 = np.array([0.5, 0.25, 0.25])  # store the probabilities assigned to the correct next tokens.
surprise_b1 = -np.log(probs_b1)  # convert each probability into surprise using natural logs.
print("probabilities:", probs_b1)  # inspect model confidence.
print("surprise:", np.round(surprise_b1, 6))  # inspect token-level NLL values.
```
▶ What you'll see: smaller probabilities create larger surprise values.

```python
plt.figure(figsize=(4, 3))  # create a compact surprise plot.
plt.bar(["token 1", "token 2", "token 3"], surprise_b1, color="teal")  # show one loss bar per token.
plt.title("Basic 1: token surprise")  # title the plot.
plt.ylabel("-log probability")  # label the surprise scale.
plt.show()  # display the chart.
```
▶ What you'll see: the two 0.25-probability tokens have equal, taller bars.

### Basic 2 — Average NLL into cross-entropy

### Advanced 3 — Bootstrap uncertainty for metric differences

**Goal.** Estimate uncertainty in a BLEU-like difference by resampling examples, because small test sets can make metric gaps look more certain than they are. We build it in 4 steps.

```python
scores_A_a3 = np.array([0.9, 0.7, 0.8, 0.6, 0.9])  # per-example metric scores for system A.
scores_B_a3 = np.array([0.8, 0.8, 0.7, 0.7, 0.6])  # per-example metric scores for system B.
diff_obs_a3 = float(np.mean(scores_A_a3 - scores_B_a3))  # observed average difference.
print("observed mean difference A-B:", round(diff_obs_a3, 3))  # inspect point estimate.
assert round(diff_obs_a3, 3) == 0.06  # verify arithmetic.
```
▶ What you'll see: system A is ahead by only 0.06 on average.

```python
rng_a3 = np.random.default_rng(0)  # local reproducible bootstrap generator.
boot_diffs_a3 = []  # store resampled differences.
for _a3 in range(1000):  # draw many bootstrap samples.
    idx_a3 = rng_a3.integers(0, len(scores_A_a3), size=len(scores_A_a3))  # sample examples with replacement.
    boot_diffs_a3.append(float(np.mean(scores_A_a3[idx_a3] - scores_B_a3[idx_a3])))  # compute resampled difference.
boot_diffs_a3 = np.array(boot_diffs_a3)  # convert to array for percentiles.
lo_a3, hi_a3 = np.percentile(boot_diffs_a3, [2.5, 97.5])  # approximate 95% interval.
print("bootstrap interval:", round(float(lo_a3), 3), round(float(hi_a3), 3))  # inspect uncertainty.
```

```python
contains_zero_a3 = bool(lo_a3 <= 0 <= hi_a3)  # check whether zero difference is plausible under bootstrap.
print("interval contains zero:", contains_zero_a3)  # inspect practical uncertainty.
assert contains_zero_a3  # this tiny example is not decisively separated.
```

```python
plt.figure(figsize=(5, 3))  # create bootstrap distribution plot.
plt.hist(boot_diffs_a3, bins=20, color="slateblue", edgecolor="white")  # show resampled differences.
plt.axvline(0, color="black", linestyle="--", label="no difference")  # mark zero.
plt.axvline(diff_obs_a3, color="red", label="observed")  # mark observed difference.
plt.title("Advanced 3: bootstrap metric gap")  # title the plot.
plt.legend()  # show reference labels.
plt.show()  # display the histogram.
```
▶ What you'll see: the bootstrap distribution spreads around the observed gap and crosses zero.

👀 Takeaway: metric differences need uncertainty estimates, not just point values.

### Advanced 4 — Tune the precision-recall weight

**Goal.** Sweep the METEOR-style recall weight, because changing the harmonic-mean weight changes which output is preferred. We build it in 4 steps.

```python

print("long P/R:", P_long_a4, R_long_a4)  # inspect second system.
```
▶ What you'll see: the two systems trade precision for recall.

```python
def weighted_score_a4(P, R, w):  # define a local weighted harmonic-style score.
    return 0.0 if P == 0 or R == 0 else float(((1 + w) * P * R) / (R + w * P))  # larger w emphasizes recall.

short_scores_a4 = np.array([weighted_score_a4(P_short_a4, R_short_a4, w_a4) for w_a4 in weights_a4])  # score concise system.
long_scores_a4 = np.array([weighted_score_a4(P_long_a4, R_long_a4, w_a4) for w_a4 in weights_a4])  # score coverage system.

print("long scores:", np.round(long_scores_a4, 3))  # inspect score curve.
```

