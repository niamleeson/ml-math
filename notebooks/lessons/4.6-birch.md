# 4.6 — BIRCH

BIRCH (Balanced Iterative Reducing and Clustering using Hierarchies) clusters unlabeled data by compressing many points into small **clustering features** first, then clustering those summaries instead of every raw point. The key lesson is not that BIRCH magically finds truth; it is that distances, scales, thresholds, and summaries define the structure the algorithm is able to see.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build BIRCH one idea at a time. Run each cell in order and read the printed intermediate values — every piece of arithmetic is exposed so the clustering summary never feels like a black box. This walkthrough is self-contained and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays, vector geometry, and clustering-feature arithmetic.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
np.random.seed(0)  # reproducibility for the tiny synthetic data.
```

### 1. Distances decide which representative owns a point

BIRCH is an unsupervised method: no label tells a point where it belongs. The first object we can trust is therefore a **distance** from a point $x_i$ to a representative $\mu_k$. The same squared-distance cost from the lesson,

$$J=\sum_i \min_k \lVert x_i-\mu_k\rVert_2^2,$$

is the audit trail for assignment decisions: each point joins the representative with the smallest squared Euclidean distance.

```python
X_w = np.array([[1.0, 2.0], [1.0, 1.0], [4.0, 4.0], [5.0, 4.0]])  # four unlabeled 2-D points.
mu_w = np.array([[1.0, 1.5], [4.5, 4.0]])  # two candidate representatives.
print("X shape:", X_w.shape, "mu shape:", mu_w.shape)  # shape bookkeeping: 4 points, 2 representatives.
print("points:\n", X_w)  # inspect the raw data before assigning anything.
```
▶ What you'll see: four 2-D points arranged as two obvious pairs.

```python
diff_w = X_w[:, None, :] - mu_w[None, :, :]  # broadcast every point against every representative.
d2_w = np.sum(diff_w ** 2, axis=2)  # squared Euclidean distance matrix, shape 4x2.
labels_w = np.argmin(d2_w, axis=1)  # each point chooses its nearest representative.
print("squared distances:\n", d2_w)  # row i, column k is ||x_i - mu_k||^2.
print("nearest representative labels:", labels_w)  # smallest distance per row.
assert d2_w[0, 0] == 0.25 and d2_w[0, 1] == 16.25  # matches the lesson's numeric pass.
```
▶ What you'll see: the first point is 0.25 from the first representative and 16.25 from the second.

```python
J_w = float(np.sum(np.min(d2_w, axis=1)))  # total fit cost under the nearest-representative rule.
print("J:", round(J_w, 3))  # four distances of 0.25 sum to 1.0.
assert round(J_w, 3) == 1.0  # the lesson's tiny numeric pass.
plt.figure(figsize=(4.5, 3.5))
plt.scatter(X_w[:, 0], X_w[:, 1], c=labels_w, cmap="viridis", s=80, label="points")
plt.scatter(mu_w[:, 0], mu_w[:, 1], marker="X", s=180, color="red", label="representatives")
plt.title("1: nearest representative assignments")
plt.xlabel("feature 0"); plt.ylabel("feature 1"); plt.legend(); plt.show()
```
▶ What you'll see: each pair of nearby points attaches to the representative in its neighborhood.

*Why it's done this way:* squared distance is nonnegative, easy to sum, and punishes far-away assignments more than nearby ones. BIRCH later compresses data, but it still needs this local geometry: if a new point is close enough to an existing summary, absorbing it should increase the within-summary cost only a little.

### 2. A clustering feature stores enough statistics to avoid storing every point

The compression trick in BIRCH is the **clustering feature** (CF):

$$CF=(N, LS, SS),$$

where $N$ is the number of points, $LS=\sum_i x_i$ is the linear sum, and $SS=\sum_i \lVert x_i\rVert^2$ is the squared sum. From just these three quantities we can recover the centroid, radius, and merge summaries without revisiting individual points.

```python
cluster_w = X_w[:2]  # the two left points.
N_w = cluster_w.shape[0]  # number of absorbed points.
LS_w = np.sum(cluster_w, axis=0)  # coordinate-wise linear sum.
SS_w = float(np.sum(cluster_w ** 2))  # sum of squared norms.
print("N:", N_w, "LS:", LS_w, "SS:", SS_w)  # the full clustering feature.
assert N_w == 2 and np.allclose(LS_w, [2.0, 3.0]) and SS_w == 7.0
```
▶ What you'll see: two points become the compact summary `(2, [2, 3], 7)`.

```python
centroid_w = LS_w / N_w  # mean point from the summary.
radius2_w = SS_w / N_w - float(centroid_w @ centroid_w)  # average squared distance to centroid.
radius_w = np.sqrt(max(radius2_w, 0.0))  # numerical guard against tiny negative roundoff.
print("centroid:", centroid_w)  # [1, 1.5].
print("radius:", round(radius_w, 3))  # average spread around the centroid.
assert np.allclose(centroid_w, [1.0, 1.5]) and round(radius_w, 3) == 0.5
```
▶ What you'll see: the summary recovers the same representative used in the lesson's arithmetic.

```python
plt.figure(figsize=(4, 3.5))
plt.scatter(cluster_w[:, 0], cluster_w[:, 1], s=90, color="steelblue")
plt.scatter([centroid_w[0]], [centroid_w[1]], marker="X", s=180, color="crimson")
circle_w = plt.Circle(centroid_w, radius_w, fill=False, color="crimson", linestyle="--")
plt.gca().add_patch(circle_w)
plt.axis("equal"); plt.title("2: CF centroid and radius")
plt.xlabel("feature 0"); plt.ylabel("feature 1"); plt.show()
```
▶ What you'll see: the centroid sits midway between the two points, and the radius reaches each point.

*Why it's done this way:* expanding $\frac{1}{N}\sum_i\lVert x_i-\bar x\rVert^2$ gives $SS/N-\lVert LS/N\rVert^2$. That identity is the reason `(N, LS, SS)` is sufficient: BIRCH can measure compactness from summary statistics rather than raw examples.

### 3. The threshold controls whether a point is absorbed or starts a new microcluster

BIRCH streams through data and asks a local question: if we add this point to the nearest leaf summary, would the new radius stay below a threshold $T$? If yes, absorb it. If no, create a new microcluster. The threshold is the compression dial: small $T$ keeps many precise summaries; large $T$ merges aggressively.

```python
def cf_from_points_w(P):
    P = np.asarray(P, dtype=float)
    return int(P.shape[0]), np.sum(P, axis=0), float(np.sum(P ** 2))

def cf_radius_w(N, LS, SS):
    c = LS / N
    return float(np.sqrt(max(SS / N - c @ c, 0.0)))

candidate_w = np.array([1.2, 1.8])  # a new point near the left summary.
N_try_w = N_w + 1
LS_try_w = LS_w + candidate_w
SS_try_w = SS_w + float(candidate_w @ candidate_w)
print("radius before:", round(radius_w, 3), "after adding candidate:", round(cf_radius_w(N_try_w, LS_try_w, SS_try_w), 3))
```
▶ What you'll see: a nearby point only modestly increases the microcluster radius.

```python
T_w = 0.7  # maximum allowed microcluster radius.
near_radius_w = cf_radius_w(N_try_w, LS_try_w, SS_try_w)
absorbed_w = near_radius_w <= T_w
print("threshold:", T_w, "absorb nearby point?", absorbed_w)
assert absorbed_w
```
▶ What you'll see: the nearby point is absorbed because the radius remains under the threshold.

```python
far_w = np.array([3.2, 2.7])  # a point between the two groups.
N_far_w = N_w + 1
LS_far_w = LS_w + far_w
SS_far_w = SS_w + float(far_w @ far_w)
far_radius_w = cf_radius_w(N_far_w, LS_far_w, SS_far_w)
print("radius after adding farther point:", round(far_radius_w, 3))
print("absorb farther point?", far_radius_w <= T_w)
plt.figure(figsize=(4.5, 3.5))
plt.scatter(cluster_w[:, 0], cluster_w[:, 1], color="steelblue", s=80, label="current CF")
plt.scatter([candidate_w[0]], [candidate_w[1]], color="green", s=90, label="absorbed")
plt.scatter([far_w[0]], [far_w[1]], color="red", s=90, label="new CF")
plt.scatter([centroid_w[0]], [centroid_w[1]], marker="X", color="black", s=140, label="centroid")
plt.title("3: threshold decides compression")
plt.xlabel("feature 0"); plt.ylabel("feature 1"); plt.legend(); plt.show()
```
▶ What you'll see: the green point is close enough to compress; the red point would stretch the summary too far.

*Why it's done this way:* the threshold enforces a bound on lost detail. Absorbing a point replaces it with summary statistics, so BIRCH permits absorption only when the summary remains geometrically tight enough to stand in for its members.

### 4. Microclusters can be clustered again as weighted representatives

After compression, BIRCH typically clusters the leaf summaries rather than every raw point. A microcluster with $N=50$ should influence the final result more than a microcluster with $N=2$, so the final representative update uses **weights** from the clustering features.

```python
micro_centers_w = np.array([[1.0, 1.5], [1.3, 1.7], [4.5, 4.0], [4.2, 4.4]])  # leaf centroids.
weights_w = np.array([2, 3, 2, 3])  # how many raw points each microcluster summarizes.
macro_w = np.array([[1.0, 1.5], [4.5, 4.0]])  # initial macro representatives.
print("micro centers shape:", micro_centers_w.shape, "weights:", weights_w)
```
▶ What you'll see: four compressed summaries will be grouped into two final clusters.

```python
d2_micro_w = np.sum((micro_centers_w[:, None, :] - macro_w[None, :, :]) ** 2, axis=2)
macro_labels_w = np.argmin(d2_micro_w, axis=1)
print("micro-to-macro labels:", macro_labels_w)
print("distance table:\n", np.round(d2_micro_w, 3))
```
▶ What you'll see: the two left summaries choose macro 0; the two right summaries choose macro 1.

```python
new_macro_w = []
for k_w in range(2):
    m_w = macro_labels_w == k_w
    center_w = np.average(micro_centers_w[m_w], axis=0, weights=weights_w[m_w])
    new_macro_w.append(center_w)
new_macro_w = np.array(new_macro_w)
print("weighted macro centers:\n", np.round(new_macro_w, 3))
assert np.allclose(np.round(new_macro_w, 3), [[1.18, 1.62], [4.32, 4.24]])
plt.figure(figsize=(4.8, 3.5))
plt.scatter(micro_centers_w[:, 0], micro_centers_w[:, 1], s=weights_w * 50, c=macro_labels_w, cmap="viridis", label="microclusters")
plt.scatter(new_macro_w[:, 0], new_macro_w[:, 1], marker="X", s=180, color="red", label="weighted macro centers")
plt.title("4: cluster the summaries, not every point")
plt.xlabel("feature 0"); plt.ylabel("feature 1"); plt.legend(); plt.show()
```
▶ What you'll see: larger bubbles pull the final macro center more strongly.

*Why it's done this way:* compression changes the dataset from raw points to sufficient summaries. Weighting by $N$ preserves the original point counts, so a tiny summary and a large summary do not get equal votes merely because both occupy one row in the compressed table.

### 5. Scaling changes the structure BIRCH can see

Because BIRCH uses Euclidean radii and distances, feature scale is not cosmetic. If one coordinate is measured in much larger units, it can dominate squared distance and therefore dominate every assignment, threshold check, and fit cost.

```python
X_scale_w = np.array([[0.0, 10.0], [0.1, 12.0], [4.0, 11.0], [4.1, 13.0]])  # x separates groups; y has larger numeric movement.
mu_scale_w = np.array([[0.0, 11.0], [4.0, 12.0]])  # two plausible representatives.
d2_raw_w = np.sum((X_scale_w[:, None, :] - mu_scale_w[None, :, :]) ** 2, axis=2)
print("raw squared distances:\n", np.round(d2_raw_w, 2))
print("raw labels:", np.argmin(d2_raw_w, axis=1))
```
▶ What you'll see: the larger-scale y coordinate heavily affects the distance table.

```python
mean_scale_w = X_scale_w.mean(axis=0)
std_scale_w = X_scale_w.std(axis=0)
Z_scale_w = (X_scale_w - mean_scale_w) / std_scale_w
mu_z_w = (mu_scale_w - mean_scale_w) / std_scale_w
d2_z_w = np.sum((Z_scale_w[:, None, :] - mu_z_w[None, :, :]) ** 2, axis=2)
print("standardized squared distances:\n", np.round(d2_z_w, 2))
print("standardized labels:", np.argmin(d2_z_w, axis=1))
```
▶ What you'll see: after standardization, both coordinates contribute on comparable units.

```python
fig, ax = plt.subplots(1, 2, figsize=(8, 3.2))
ax[0].scatter(X_scale_w[:, 0], X_scale_w[:, 1], c=np.argmin(d2_raw_w, axis=1), cmap="viridis", s=80)
ax[0].set_title("raw units"); ax[0].set_xlabel("feature 0"); ax[0].set_ylabel("feature 1")
ax[1].scatter(Z_scale_w[:, 0], Z_scale_w[:, 1], c=np.argmin(d2_z_w, axis=1), cmap="viridis", s=80)
ax[1].set_title("standardized units"); ax[1].set_xlabel("z feature 0"); ax[1].set_ylabel("z feature 1")
plt.suptitle("5: scaling changes BIRCH's lens"); plt.show()
```
▶ What you'll see: the same four points can look different once units are made comparable.

*Why it's done this way:* BIRCH optimizes geometry in the units supplied. Standardizing is not a ritual; it is a statement that a one-standard-deviation change in either coordinate should have comparable influence on squared distance.

## 🛠️ Setup

```python
import numpy as np  # load NumPy for arrays, vectorized distances, and clustering-feature summaries.
import matplotlib.pyplot as plt  # load Matplotlib for scatter plots, radius sketches, and diagnostic curves.
np.random.seed(0)  # make all random examples reproducible across notebook runs.

def cf_from_points(P):  # compute BIRCH's clustering-feature triple from raw points.
    P = np.asarray(P, dtype=float)  # convert input to a numeric array so sums and products behave predictably.
    return int(P.shape[0]), np.sum(P, axis=0), float(np.sum(P ** 2))  # return N, LS, and SS.

def cf_centroid(N, LS):  # recover the centroid from a clustering feature.
    return np.asarray(LS, dtype=float) / N  # centroid is the coordinate-wise linear sum divided by count.

def cf_radius(N, LS, SS):  # recover the root-mean-square radius from a clustering feature.
    c = cf_centroid(N, LS)  # compute the summary centroid.
    return float(np.sqrt(max(SS / N - c @ c, 0.0)))  # use SS/N - ||centroid||^2 with a roundoff guard.

def squared_distances(A, B):  # compute all squared Euclidean distances from rows of A to rows of B.
    A = np.asarray(A, dtype=float)  # ensure the first collection is numeric.
    B = np.asarray(B, dtype=float)  # ensure the second collection is numeric.
    return np.sum((A[:, None, :] - B[None, :, :]) ** 2, axis=2)  # broadcast differences and sum squared coordinates.
```

### Basic 7 — Merge two clustering features

**Goal.** Add summaries directly, because BIRCH combines subclusters by summing their sufficient statistics. We build it in 2 steps.


```python
N_b7 = N1_b7 + N2_b7  # merge counts.
```
