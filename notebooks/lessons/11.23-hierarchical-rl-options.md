# 11.23 — Hierarchical RL & Options

Hierarchical reinforcement learning lets an RL agent choose reusable **skills** rather than only one-step actions. The options framework makes that precise: an option says where a skill can start, how it acts while running, and when it terminates so the high-level policy can choose again.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build hierarchical RL one idea at a time. Run each cell in order and read the printed values — the gridworld is tiny enough that every option rollout, termination event, and semi-MDP backup can be inspected directly.

```python
import numpy as np  # arrays, tables, and reproducible simulations.

```

### 1. Primitive gridworld actions

Options are built on an ordinary MDP. Here the state is a cell in a 4×4 grid, primitive actions move one cell, the goal gives reward 1, and every non-goal move costs −0.01 so slow skills are slightly worse.

```python
H_w, W_w = 4, 4
goal_w = (3, 3)
actions_w = {0: (-1, 0), 1: (1, 0), 2: (0, -1), 3: (0, 1)}
names_w = {0: "up", 1: "down", 2: "left", 3: "right"}
print("states:", H_w * W_w, "actions:", list(names_w.values()))
```
▶ What you'll see: a 16-state grid with four primitive actions.

```python
def step_w(state, action):
    if state == goal_w:
        return state, 0.0, True
    dr, dc = actions_w[action]
    new_row = min(max(state[0] + dr, 0), H_w - 1)
    new_col = min(max(state[1] + dc, 0), W_w - 1)
    ns = (new_row, new_col)
    reward = 1.0 if ns == goal_w else -0.01
    return ns, reward, ns == goal_w

for action_w in [3, 1]:
    ns_w, r_w, done_w = step_w((0, 0), action_w)
    print(names_w[action_w], "->", ns_w, "reward", r_w, "done", done_w)
```
▶ What you'll see: right and down each move one cell and receive the step cost.

```python
grid_w = np.zeros((H_w, W_w))
grid_w[goal_w] = 1.0
plt.figure(figsize=(3.5, 3.2))
plt.imshow(grid_w, cmap="Greens", vmin=0, vmax=1)
plt.title("1: primitive gridworld")
plt.xticks(range(W_w)); plt.yticks(range(H_w)); plt.grid(color="black", linewidth=0.5)
plt.show()
```
▶ What you'll see: the lower-right goal cell is highlighted.

*Why it's done this way:* every option ultimately expands into primitive MDP transitions. Keeping the primitive dynamics explicit prevents the hierarchy from hiding reward timing or illegal moves.

### 2. Options: initiation, policy, termination

An option is a triple $o=(I_o,\pi_o,\beta_o)$. $I_o$ says where the option may start, $\pi_o(a\mid s)$ chooses primitive actions while the option runs, and $\beta_o(s)$ is the probability of stopping in state $s$.

```python
states_w = [(r, c) for r in range(H_w) for c in range(W_w)]
init_right_w = np.array([s[1] < W_w - 1 and s != goal_w for s in states_w]).reshape(H_w, W_w)
print("start at (0,0)?", bool(init_right_w[0, 0]))
print("start at (0,3)?", bool(init_right_w[0, 3]))
```
▶ What you'll see: the go-right option starts away from the right wall, not at the wall.

```python
def pi_right_w(state):
    return 3

def beta_right_w(state):
    return 1.0 if state[1] == W_w - 1 or state == goal_w else 0.0

for test_w in [(0, 0), (0, 2), (0, 3)]:
    print(test_w, "action", names_w[pi_right_w(test_w)], "beta", beta_right_w(test_w))
```
▶ What you'll see: the internal policy always moves right, and beta becomes 1 at the right wall.

```python
plt.figure(figsize=(3.5, 3.2))
plt.imshow(init_right_w.astype(float), cmap="Blues", vmin=0, vmax=1)
plt.title("2: initiation set for go-right")
plt.xticks(range(W_w)); plt.yticks(range(H_w)); plt.grid(color="black", linewidth=0.5)
plt.show()
```
▶ What you'll see: legal initiation cells are shaded.

*Why it's done this way:* a skill is reusable only if its availability, internal control, and stopping condition are explicit. The high-level policy chooses the option; the option then owns primitive control until termination.

### 3. Option rollouts and discounted option return

Choosing an option produces a variable-duration transition. If the option runs for $k$ primitive steps, its macro reward is $R_o=\sum_{t=0}^{k-1}\gamma^t r_t$, not merely the last reward.

```python
def run_right_w(start, gamma=0.9):
    state = start
    path = [state]
    rewards = []
    total = 0.0
    for k in range(10):
        state, reward, done = step_w(state, pi_right_w(state))
        rewards.append(reward)
        total += (gamma ** k) * reward
        path.append(state)
        if done or beta_right_w(state) == 1.0:
            break
    return path, np.array(rewards), total

path_w, rewards_w, return_w = run_right_w((0, 0))
print("path:", path_w)
print("return:", round(return_w, 4))
assert round(return_w, 4) == -0.0271
```
▶ What you'll see: three right moves terminate at the wall with discounted step cost −0.0271.

```python
weights_w = 0.9 ** np.arange(len(rewards_w))
print("discount weights:", np.round(weights_w, 3))
print("weighted rewards:", np.round(weights_w * rewards_w, 4))
```
▶ What you'll see: the three reward terms are weighted by 1, 0.9, and 0.81.

```python
trace_w = np.zeros((H_w, W_w))
for t_w, cell_w in enumerate(path_w):
    trace_w[cell_w] = t_w + 1
plt.figure(figsize=(3.5, 3.2))
plt.imshow(trace_w, cmap="viridis")
plt.title("3: option rollout path")
plt.xticks(range(W_w)); plt.yticks(range(H_w)); plt.grid(color="white", linewidth=0.5)
plt.show()
```
▶ What you'll see: the top row is marked in the order visited by the option.

*Why it's done this way:* the option is one high-level decision but several low-level transitions. Discounted accumulation keeps reward timing visible instead of pretending all rewards arrive instantly.

### 4. Semi-MDP Bellman backups

Options create a semi-MDP because one high-level action may consume $k$ primitive steps. The Bellman target is $R_o+\gamma^k\max_{o'}Q(s',o')$; the exponent $k$ is the key difference from a one-step backup.

```python
k_w = len(rewards_w)
future_w = 0.8
target_w = return_w + (0.9 ** k_w) * future_w
print("k:", k_w, "gamma^k:", round(0.9 ** k_w, 3))
print("target:", round(target_w, 4))
assert round(target_w, 4) == 0.5561
```
▶ What you'll see: the future value is multiplied by 0.729 because the option lasted three steps.

```python
old_q_w = 0.0
alpha_w = 0.5
new_q_w = old_q_w + alpha_w * (target_w - old_q_w)
print("new option Q:", round(new_q_w, 4))
assert round(new_q_w, 4) == 0.2781
```
▶ What you'll see: a half-step update moves Q from 0 to 0.2781.

```python
plt.figure(figsize=(3.8, 3))
plt.bar(["old", "target", "new"], [old_q_w, target_w, new_q_w], color=["gray", "black", "seagreen"])
plt.title("4: semi-MDP option update")
plt.ylabel("value")
plt.show()
```
▶ What you'll see: the updated estimate sits between the old value and the target.

*Why it's done this way:* using $\gamma$ instead of $\gamma^k$ would overvalue long options by giving them one-step future credit. The duration-aware target is what makes option learning mathematically consistent.

### 5. Termination as a duration distribution

Termination can be deterministic or stochastic. A high termination probability gives frequent replanning; a low termination probability commits longer to the option's internal policy.

```python
def stochastic_lengths_w(beta_mid, trials=200):
    lengths = []
    for _ in range(trials):
        state = (0, 0)
        for k in range(1, 5):
            state, _, _ = step_w(state, 3)
            if state[1] == W_w - 1 or np.random.rand() < beta_mid:
                lengths.append(k)
                break
    return np.array(lengths)

low_w = stochastic_lengths_w(0.1)
high_w = stochastic_lengths_w(0.7)
print("mean lengths:", round(low_w.mean(), 3), round(high_w.mean(), 3))
assert low_w.mean() > high_w.mean()
```
▶ What you'll see: lower beta produces longer option executions.

```python
plt.figure(figsize=(5, 3))
plt.hist(low_w, bins=np.arange(1, 5) - 0.5, alpha=0.7, label="beta=0.1")
plt.hist(high_w, bins=np.arange(1, 5) - 0.5, alpha=0.7, label="beta=0.7")
plt.xticks([1, 2, 3]); plt.xlabel("duration k"); plt.ylabel("count")
plt.title("5: termination changes duration")
plt.legend(); plt.show()
```
▶ What you'll see: the high-beta option stops after one step much more often.

*Why it's done this way:* $\beta_o(s)$ changes both the endpoint distribution and the duration discount. It is therefore part of the model, not just an implementation detail.

### 6. Planning with a small option library

With useful options, a top-level policy can plan over macro actions. We use go-right and go-down options and run value iteration with semi-MDP targets.

```python
def run_option_w(start, direction, gamma=0.9):
    action = 3 if direction == "right" else 1
    state = start
    path = [state]
    rewards = []
    total = 0.0
    for k in range(10):
        state, reward, done = step_w(state, action)
        rewards.append(reward)
        total += (gamma ** k) * reward
        path.append(state)
        stop = (direction == "right" and state[1] == W_w - 1) or (direction == "down" and state[0] == H_w - 1)
        if done or stop:
            break
    return path, np.array(rewards), total

for opt_w in ["right", "down"]:
    p_w, r_w, G_w = run_option_w((0, 0), opt_w)
    print(opt_w, "end", p_w[-1], "k", len(r_w), "return", round(G_w, 4))
```
▶ What you'll see: each macro action travels to a wall in three primitive steps.

```python
V_w = np.zeros((H_w, W_w))
for _ in range(25):
    new_V_w = V_w.copy()
    for s_w in states_w:
        if s_w == goal_w:
            continue
        vals_w = []
        for opt_w in ["right", "down"]:
            p_w, r_w, G_w = run_option_w(s_w, opt_w)
            vals_w.append(G_w + (0.9 ** len(r_w)) * V_w[p_w[-1]])
        new_V_w[s_w] = max(vals_w)
    V_w = new_V_w
print("start value:", round(V_w[0, 0], 3))
assert round(V_w[0, 0], 3) == 0.55
```
▶ What you'll see: the start value becomes positive because two macro choices can reach the goal.

```python
plt.figure(figsize=(3.8, 3.2))
plt.imshow(V_w, cmap="viridis")
plt.colorbar(label="value")
plt.title("6: value iteration over options")
plt.xticks(range(W_w)); plt.yticks(range(H_w)); plt.grid(color="white", linewidth=0.5)
plt.show()
```
▶ What you'll see: values are high near states that can reach the goal with the option library.

*Why it's done this way:* abstraction reduces the number of top-level choices, but the Bellman backup still accounts for every primitive reward and the time consumed by each option.

## 🛠️ Setup

```python
import numpy as np  # load NumPy for tabular RL arrays, rollouts, and assertions.
import matplotlib.pyplot as plt  # load Matplotlib for grid, bar, and line visualizations.
np.random.seed(0)  # make stochastic option examples reproducible.

ACTIONS = {0: (-1, 0), 1: (1, 0), 2: (0, -1), 3: (0, 1)}  # up, down, left, right.
ACTION_NAMES = {0: "up", 1: "down", 2: "left", 3: "right"}  # readable primitive names.
H, W = 4, 4  # default grid size.
GOAL = (3, 3)  # terminal goal.

def grid_step(state, action, h=H, w=W, goal=GOAL):  # deterministic primitive transition.
    if state == goal:
        return state, 0.0, True
    dr, dc = ACTIONS[action]
    new_row = min(max(state[0] + dr, 0), h - 1)
    new_col = min(max(state[1] + dc, 0), w - 1)
    ns = (new_row, new_col)
    reward = 1.0 if ns == goal else -0.01
    return ns, reward, ns == goal

def run_line_option(start, direction, gamma=0.9, h=H, w=W, goal=GOAL):  # deterministic go-right or go-down option.
    action = 3 if direction == "right" else 1
    state = start
    path = [state]
    rewards = []
    total = 0.0
    for k in range(10):
        state, reward, done = grid_step(state, action, h, w, goal)
        rewards.append(reward)
        total += (gamma ** k) * reward
        path.append(state)
        stop = (direction == "right" and state[1] == w - 1) or (direction == "down" and state[0] == h - 1)
        if done or stop:
            break
    return path, np.array(rewards), total

def show_grid(M, title):  # compact heatmap helper.
    plt.figure(figsize=(3.8, 3.2))
    plt.imshow(M, cmap="viridis", aspect="equal")
    plt.colorbar(label="value")
    plt.title(title)
    plt.xticks(range(M.shape[1])); plt.yticks(range(M.shape[0]))
    plt.grid(color="white", linewidth=0.5)
    plt.show()

def smdp_target(option_return, gamma, duration, next_value):  # option Bellman target.
    return option_return + (gamma ** duration) * next_value
```
