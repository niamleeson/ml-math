# 11.34 — Self-Play & Population-Based Training

Self-play turns yesterday's agent into today's training data, so the curriculum grows with the learner instead of being fixed by a human. Population-based training (PBT) adds a second loop: many agents train in parallel, strong ones copy forward, and their hyperparameters mutate so the search for a policy and the search for a training recipe happen together.

Before the terse worked examples, we build self-play and population-based training one idea at a time. Run each cell in order and read the printed intermediate values — every piece of math is exposed so the moving opponent, Elo scores, and hyperparameter evolution are not black boxes. This walkthrough is self-contained and uses a `_w` suffix on variables so it never clashes with the examples below.

```python
import numpy as np  # arrays, random sampling, and vectorized tournament math.
```

### 1. Self-play data comes from the learner's current opponent

Self-play is different from supervised learning because the data distribution moves. If a policy is trained against a fixed weak opponent, it can overfit that opponent. If it trains against a copy of itself, every improvement changes what future games look like. We start with rock-paper-scissors where each policy is just a probability vector over three actions.

```python
actions_w = np.array(["rock", "paper", "scissors"])
payoff_w = np.array([[0, -1, 1], [1, 0, -1], [-1, 1, 0]], dtype=float)
policy_w = np.array([0.70, 0.20, 0.10])
opponent_w = np.array([1/3, 1/3, 1/3])
values_w = payoff_w @ opponent_w
print("action values vs uniform:", np.round(values_w, 3))
print("expected payoff:", round(float(policy_w @ values_w), 3))
```
▶ What you'll see: every action has value 0 against a uniform opponent, so a biased policy gets no advantage.

```python
opponent_w = policy_w.copy()
values_self_w = payoff_w @ opponent_w
best_response_w = np.eye(3)[np.argmax(values_self_w)]
print("action values vs current self:", np.round(values_self_w, 3))
print("best response:", actions_w[np.argmax(values_self_w)], best_response_w)
```
▶ What you'll see: once the opponent is the biased current policy, paper becomes valuable because it beats rock.

```python
plt.figure(figsize=(4.5, 3))
plt.bar(actions_w, policy_w, color="steelblue", label="current policy")
plt.bar(actions_w, best_response_w, alpha=0.45, color="orange", label="best response")
plt.title("1: self-play creates the next lesson")
plt.ylabel("probability")
plt.legend()
plt.show()
```
▶ What you'll see: the policy overplays rock, so the automatically generated lesson is to play paper.

*Why it's done this way:* the expected value of an action is \(\sum_b P(b)\,u(a,b)\), so changing the opponent probabilities changes the target. Self-play deliberately lets the target move because a good agent should handle the strategies produced by its own learning process, not only a fixed script.

### 2. Policy improvement needs smoothing, not instant best responses

A pure best response can cycle forever in competitive games: rock-heavy policies invite paper, paper-heavy policies invite scissors, and so on. A small update toward the best response is a controlled optimization step. It resembles the RL backup idea: move partway toward a target instead of letting one estimate overwrite the whole policy.

```python
policy_w = np.array([0.70, 0.20, 0.10])
lr_w = 0.20
history_w = [policy_w.copy()]
for step_w in range(40):
    values_w = payoff_w @ policy_w
    br_w = np.eye(3)[np.argmax(values_w)]
    policy_w = (1 - lr_w) * policy_w + lr_w * br_w
    history_w.append(policy_w.copy())
history_w = np.array(history_w)
print("final policy:", np.round(history_w[-1], 3))
assert np.allclose(history_w[-1].sum(), 1.0)
```
▶ What you'll see: the policy remains a valid probability vector while moving through the strategic cycle.

```python
plt.figure(figsize=(5, 3))
for j_w, name_w in enumerate(actions_w):
    plt.plot(history_w[:, j_w], label=name_w)
plt.title("2: smoothed self-play dynamics")
plt.xlabel("self-play update")
plt.ylabel("action probability")
plt.legend()
plt.show()
```
▶ What you'll see: probabilities rise and fall as each strategy becomes exploitable and then gets countered.

*Why it's done this way:* the update \(\pi_{new}=(1-\alpha)\pi+\alpha\,BR(\pi)\) is a convex combination, so probabilities stay nonnegative and sum to 1. The small \(\alpha\) reduces variance and instability by treating each best response as a learning signal rather than an absolute truth.

### 3. Elo turns noisy match results into a strength scale

Self-play needs a way to rank agents that were trained at different times. Elo does this by comparing the observed score to the expected score. If player A is rated \(R_A\) and player B is rated \(R_B\), A's expected score is \(1/(1+10^{(R_B-R_A)/400})\). The update is \(R_A \leftarrow R_A + K(S_A-E_A)\).

```python
Ra_w, Rb_w, K_w = 1200.0, 1200.0, 32.0
Ea_w = 1 / (1 + 10 ** ((Rb_w - Ra_w) / 400))
Sa_w = 1.0
Ra_new_w = Ra_w + K_w * (Sa_w - Ea_w)
Rb_new_w = Rb_w + K_w * ((1 - Sa_w) - (1 - Ea_w))
print("expected score A:", round(Ea_w, 3))
print("new ratings:", round(Ra_new_w, 1), round(Rb_new_w, 1))
assert round(Ra_new_w, 1) == 1216.0
```
▶ What you'll see: two equal players start with expected score 0.5, so a win moves A up by 16 Elo.

```python
ratings_w = np.array([1200.0, 1200.0, 1200.0])
results_w = [(0, 1, 1.0), (0, 2, 1.0), (1, 2, 0.0), (2, 0, 0.5), (1, 0, 1.0)]
trace_w = [ratings_w.copy()]
for a_w, b_w, score_w in results_w:
    ea_w = 1 / (1 + 10 ** ((ratings_w[b_w] - ratings_w[a_w]) / 400))
    ratings_w[a_w] += K_w * (score_w - ea_w)
    ratings_w[b_w] += K_w * ((1 - score_w) - (1 - ea_w))
    trace_w.append(ratings_w.copy())
trace_w = np.array(trace_w)
print("final Elo:", np.round(ratings_w, 1))
```
▶ What you'll see: ratings move after each match while the total rating mass stays nearly constant.

```python
plt.figure(figsize=(5, 3))
for i_w in range(3):
    plt.plot(trace_w[:, i_w], marker="o", label=f"agent {i_w}")
plt.title("3: Elo over self-play matches")
plt.xlabel("match index")
plt.ylabel("Elo rating")
plt.legend()
plt.show()
```
▶ What you'll see: look for jumps after wins and smaller changes when results are less surprising.

*Why it's done this way:* Elo is an online residual correction. The residual \(S-E\) is positive when the player beats expectation and negative when it underperforms, while the logistic expected-score formula makes a win over a stronger opponent worth more than a win over a weaker one.

### 4. PBT trains weights and hyperparameters at the same time

Population-based training keeps several learners alive. Each member trains with its own hyperparameters, then weak members copy strong members and perturb the copied hyperparameters. This is not just model selection after training; it changes the training path while learning is happening.

```python
rng_w = np.random.default_rng(0)
quality_w = rng_w.normal(0, 0.05, size=6)
lr_pop_w = np.array([0.02, 0.04, 0.08, 0.12, 0.18, 0.25])
mut_pop_w = np.array([0.02, 0.03, 0.04, 0.05, 0.07, 0.10])
target_lr_w, target_mut_w = 0.10, 0.05
print("initial quality:", np.round(quality_w, 3))
print("learning rates:", lr_pop_w)
```
▶ What you'll see: the population starts with different hyperparameter guesses and slightly different quality.

```python
best_trace_w = []
lr_trace_w = []
for gen_w in range(25):
    gain_w = 0.35 * np.exp(-((lr_pop_w - target_lr_w) / 0.07) ** 2) + 0.15 * np.exp(-((mut_pop_w - target_mut_w) / 0.04) ** 2)
    quality_w += gain_w + rng_w.normal(0, 0.015, size=quality_w.size)
    order_w = np.argsort(quality_w)
    losers_w, winners_w = order_w[:2], order_w[-2:]
    for loser_w, winner_w in zip(losers_w, winners_w):
        quality_w[loser_w] = quality_w[winner_w]
        lr_pop_w[loser_w] = np.clip(lr_pop_w[winner_w] * rng_w.choice([0.8, 1.2]), 0.005, 0.4)
        mut_pop_w[loser_w] = np.clip(mut_pop_w[winner_w] * rng_w.choice([0.8, 1.2]), 0.005, 0.2)
    best_trace_w.append(float(np.max(quality_w)))
    lr_trace_w.append(lr_pop_w.copy())
print("best quality:", round(best_trace_w[-1], 3))
print("final learning rates:", np.round(lr_pop_w, 3))
assert best_trace_w[-1] > best_trace_w[0]
```
▶ What you'll see: the best quality rises, and learning rates drift toward values that train well in this toy world.

```python
plt.figure(figsize=(5, 3))
plt.plot(best_trace_w, color="seagreen")
plt.title("4: PBT best score over generations")
plt.xlabel("generation")
plt.ylabel("best quality")
plt.show()

plt.figure(figsize=(5, 3))
plt.plot(np.array(lr_trace_w), alpha=0.8)
plt.axhline(target_lr_w, color="black", linestyle="--", label="good lr")
plt.title("4: hyperparameters evolve during training")
plt.xlabel("generation")
plt.ylabel("learning rate")
plt.legend()
plt.show()
```
▶ What you'll see: the score improves while copied-and-mutated learning rates cluster near useful values.

*Why it's done this way:* selection exploits evidence already gathered by strong learners, while mutation keeps exploration alive. Copying only weights would freeze the training recipe; copying and perturbing hyperparameters lets the population discover schedules that a single fixed run would miss.

### ✍️ Toy 4 · PBT copies winners and mutates hyperparameters

Population-based training alternates training, ranking, copying, and perturbing hyperparameters. This
one generation shows the exploit-and-mutate step explicitly.

```python
import numpy as np

t4_rng = np.random.default_rng(0)
t4_quality = np.array([0.20, 0.55, 0.40, 0.10])
t4_learning_rate = np.array([0.02, 0.08, 0.12, 0.20])
t4_target_rate = 0.10
t4_gain = 0.10 - np.abs(t4_learning_rate - t4_target_rate)  # -> [0.02, 0.08, 0.08, 0.0]
t4_trained_quality = t4_quality + t4_gain  # -> [0.22, 0.63, 0.48, 0.1]
t4_order = np.argsort(t4_trained_quality)
t4_losers = t4_order[:2]  # -> [3, 0]
t4_winners = t4_order[-2:]  # -> [2, 1]
t4_after_quality = t4_trained_quality.copy()
t4_after_rate = t4_learning_rate.copy()
t4_mutation_factors = np.array([1.2, 0.8])
for t4_loser, t4_winner, t4_factor in zip(t4_losers, t4_winners, t4_mutation_factors):
    t4_after_quality[t4_loser] = t4_trained_quality[t4_winner]
    t4_after_rate[t4_loser] = t4_learning_rate[t4_winner] * t4_factor
t4_min_before = float(t4_trained_quality.min())  # -> 0.1
t4_min_after = float(t4_after_quality.min())  # -> 0.48
print("training gains:", np.round(t4_gain, 3).tolist())  # -> [0.02, 0.08, 0.08, 0.0]
print("quality after training:", np.round(t4_trained_quality, 3).tolist())  # -> [0.22, 0.63, 0.48, 0.1]
print("losers/winners:", t4_losers.tolist(), t4_winners.tolist())  # -> [3, 0] [2, 1]
print("quality after exploit:", np.round(t4_after_quality, 3).tolist())  # -> [0.63, 0.63, 0.48, 0.48]
print("rates after mutation:", np.round(t4_after_rate, 3).tolist())  # -> [0.064, 0.08, 0.12, 0.144]
assert t4_min_after > t4_min_before

plt.figure(figsize=(4.8, 3.0))
t4_x = np.arange(4)
plt.bar(t4_x - 0.18, t4_trained_quality, width=0.36, label="after train", color="gray")
plt.bar(t4_x + 0.18, t4_after_quality, width=0.36, label="after exploit", color="seagreen")
plt.xlabel("population member")
plt.ylabel("quality")
plt.title("Toy 4 · PBT exploit step")
plt.legend()
plt.show()
```
▶ What you'll see: weak members copy stronger quality, while their learning rates are perturbed copies.

## 🛠️ Setup

```python
import numpy as np  # Import NumPy for arrays, random sampling, tournament matrices, and Elo arithmetic.
import matplotlib.pyplot as plt  # Import Matplotlib for policy curves, rating traces, and PBT diagnostics.
np.random.seed(0)  # Fix global randomness so the notebook is reproducible.

def rps_payoff():  # Return the row-player payoff matrix for rock, paper, scissors.
    return np.array([[0, -1, 1], [1, 0, -1], [-1, 1, 0]], dtype=float)  # Win=1, draw=0, loss=-1.

def normalize(p):  # Convert nonnegative weights into a probability vector.
    p = np.asarray(p, dtype=float)  # Ensure numerical array input.
    total = float(np.sum(p))  # Compute total mass.
    return p / total if total > 0 else np.ones_like(p) / len(p)  # Fall back to uniform if all mass vanished.

def expected_scores(strengths):  # Convert latent strengths into pairwise win probabilities.
    diff = strengths[:, None] - strengths[None, :]  # Positive means row agent is stronger than column agent.
    return 1 / (1 + np.exp(-diff))  # Logistic win probability matrix.

def elo_expected(ra, rb):  # Compute player A's expected Elo score against player B.
    return 1 / (1 + 10 ** ((rb - ra) / 400))  # Standard Elo logistic curve.

def elo_update(ra, rb, score_a, k=32):  # Update two Elo ratings after one result.
    ea = elo_expected(ra, rb)  # Expected score for A.
    return ra + k * (score_a - ea), rb + k * ((1 - score_a) - (1 - ea))  # Symmetric residual update.

def softmax(x):  # Convert logits into action probabilities.
    x = np.asarray(x, dtype=float)  # Ensure float array input.
    z = x - np.max(x)  # Stabilize exponentials by subtracting the maximum.
    e = np.exp(z)  # Exponentiate shifted logits.
    return e / np.sum(e)  # Normalize to probabilities.
```

### Basic 4 — Take a small self-play update

**Goal.** Move partway toward a best response, because instant replacement can make competitive learning unstable. We build it in 2 steps.

```python
policy_b4 = np.array([0.7, 0.2, 0.1])  # Start with a rock-heavy policy.
br_b4 = np.array([0.0, 1.0, 0.0])  # Best response to that policy is paper.
alpha_b4 = 0.2  # Choose a conservative update size.
new_policy_b4 = (1 - alpha_b4) * policy_b4 + alpha_b4 * br_b4  # Convexly mix old policy and target.
print("new policy:", np.round(new_policy_b4, 3))  # Inspect the smoothed update.
assert np.allclose(new_policy_b4.sum(), 1.0)  # Verify probabilities still sum to one.
```

### Advanced 3 — PBT with two evolving hyperparameters

**Goal.** Evolve learning rate and entropy bonus together, because useful training recipes often depend on combinations of hyperparameters. We build it in 4 steps.

```python

    reward_ent_a3 = np.exp(-((entropy_a3 - 0.05) / 0.035) ** 2)  # Toy reward for good entropy.

    for loser_a3, winner_a3 in zip(order_a3[:2], order_a3[-2:]):  # Replace two weakest with two strongest.
```

### Advanced 5 — Combine league Elo with PBT selection

**Goal.** Use Elo as the PBT selection signal, because competitive agents should be copied based on head-to-head performance rather than only a scalar training loss. We build it in 4 steps.

```python

n_a5 = 6  # Population size.
strength_a5 = rng_a5.normal(0, 0.2, n_a5)  # Hidden trainable strength.
lr_a5 = np.linspace(0.03, 0.21, n_a5)  # Learning rates.
elos_a5 = np.ones(n_a5) * 1200.0  # League ratings.
best_elo_a5 = []  # Track best Elo over generations.
print("initial lr:", np.round(lr_a5, 3))  # Inspect initial hyperparameters.
```
▶ What you'll see: the population starts with varied learning rates and equal Elo.

```python

    strength_a5 += 0.20 * np.exp(-((lr_a5 - 0.11) / 0.06) ** 2) + rng_a5.normal(0, 0.03, n_a5)  # Train agents.
    for match_a5 in range(8):  # Play a few league matches per generation.
        a_a5, b_a5 = rng_a5.choice(n_a5, 2, replace=False)  # Pick opponents.
        p_a5 = 1 / (1 + np.exp(-(strength_a5[a_a5] - strength_a5[b_a5])))  # Hidden win probability.
        s_a5 = float(rng_a5.random() < p_a5)  # Sample match result.
        elos_a5[a_a5], elos_a5[b_a5] = elo_update(elos_a5[a_a5], elos_a5[b_a5], s_a5, k=20)  # Update ratings.
    order_a5 = np.argsort(elos_a5)  # Select using Elo.
    loser_a5, winner_a5 = order_a5[0], order_a5[-1]  # Weakest and strongest by league rating.
    strength_a5[loser_a5] = strength_a5[winner_a5]  # Copy winner weights.
    lr_a5[loser_a5] = np.clip(lr_a5[winner_a5] * rng_a5.choice([0.8, 1.2]), 0.005, 0.4)  # Mutate lr.
    elos_a5[loser_a5] = elos_a5[winner_a5] - 20  # Start copied agent near winner but slightly below.
    best_elo_a5.append(float(np.max(elos_a5)))  # Track best rating.
```
