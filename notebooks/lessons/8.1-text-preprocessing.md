# 8.1 — Text Preprocessing

Text preprocessing is the deliberate choice of which surface differences in raw text should still matter after a model sees the input. In this lesson, we build normalization, token cleanup, stop-word handling, and padding from scratch, because every later NLP count, vector, and embedding inherits these early decisions.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build text preprocessing one idea at a time. Run each cell in order and read the printed intermediate values — every string rule is made visible so hidden text bugs cannot hide. This walkthrough is self-contained (it imports what it needs) and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays for counts, masks, and small numerical checks.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
import re  # regular expressions for transparent tokenizer and cleanup rules.
```

### 1. Normalization as an equivalence function

A computer treats strings as exact symbol sequences, so `"Cafe"`, `"CAFE"`, and `"cafe!"` are different until we define a function that maps them to one canonical form. Mathematically, preprocessing creates an equivalence relation: two surface forms are treated as the same token exactly when their normalized outputs match, $a\equiv b \iff n(a)=n(b)$.

```python
raw_words_w = ["Cafe", "CAFE", "cafe!", "Tea"]  # surface forms before any cleanup.
def lowercase_strip_w(token_w):  # one tiny normalizer: lowercase then remove non-letters at the edges.
    return re.sub(r"^[^a-z]+|[^a-z]+$", "", token_w.lower())  # canonical lowercase letters.
normalized_words_w = [lowercase_strip_w(t_w) for t_w in raw_words_w]  # apply n(.) to every word.
print("raw words:", raw_words_w)  # inspect the original symbols.
print("normalized:", normalized_words_w)  # inspect the canonical representatives.
```
▶ What you'll see: the first three surface forms collapse to `cafe`, while `Tea` becomes `tea`.

```python
raw_vocab_w = sorted(set(raw_words_w))  # count distinct surface strings.
norm_vocab_w = sorted(set(normalized_words_w))  # count distinct canonical strings.
print("raw vocabulary size:", len(raw_vocab_w), raw_vocab_w)  # four surface types.
print("normalized vocabulary size:", len(norm_vocab_w), norm_vocab_w)  # two canonical types.
assert len(raw_vocab_w) == 4 and len(norm_vocab_w) == 2  # concrete vocabulary shrinkage.
```
▶ What you'll see: vocabulary size drops from 4 to 2 because accidental variants merge.

```python
plt.figure(figsize=(4.4, 3))  # create a compact vocabulary-size chart.
plt.bar(["raw", "normalized"], [len(raw_vocab_w), len(norm_vocab_w)], color=["indianred", "seagreen"])  # compare set sizes.
plt.ylabel("distinct tokens")  # label the count being compared.
plt.title("1: normalization shrinks vocabulary")  # title the visual.
plt.show()  # display the chart.
```
▶ What you'll see: the normalized bar is shorter, showing fewer model parameters needed for the same idea.

*Why it's done this way:* models count exact token strings, so variants split evidence unless a single function merges them first. The set-size arithmetic is the key reasoning: fewer equivalent tokens means later counts concentrate on one entry instead of being scattered across spelling and punctuation accidents.

### 2. Unicode and accent folding

The same visible word can be stored with different code points. `"Café"` may contain one precomposed `é`, while `"Cafe\u0301"` stores `e` plus a combining accent. They look alike to a reader but fail exact equality until preprocessing decides how to fold them.

```python
precomposed_w = "Café"  # visible e-acute stored as one code point.
decomposed_w = "Cafe\u0301"  # visible e-acute stored as e plus combining acute accent.
print("precomposed:", precomposed_w, "length:", len(precomposed_w), "code points:", [hex(ord(c_w)) for c_w in precomposed_w])
print("decomposed:", decomposed_w, "length:", len(decomposed_w), "code points:", [hex(ord(c_w)) for c_w in decomposed_w])
print("raw equality:", precomposed_w == decomposed_w)  # exact string comparison fails.
assert len(precomposed_w) == 4 and len(decomposed_w) == 5  # concrete invisible mismatch.
```
▶ What you'll see: the two words print almost the same, but one has length 4 and the other length 5.

```python
accent_map_w = {"é": "e", "É": "e"}  # tiny explicit fold table for the toy example.
def fold_accents_w(text_w):  # remove combining marks and map common precomposed accents.
    chars_w = []  # collect surviving canonical characters.
    for ch_w in text_w:  # inspect every code point directly.
        if "\u0300" <= ch_w <= "\u036f":  # combining accent range; skip it.
            continue
        chars_w.append(accent_map_w.get(ch_w, ch_w))  # replace known accented letters.
    return "".join(chars_w).lower()  # lowercase after folding.
folded_pre_w = fold_accents_w(precomposed_w)  # canonicalize first spelling.
folded_decomp_w = fold_accents_w(decomposed_w)  # canonicalize second spelling.
print("folded:", folded_pre_w, folded_decomp_w)  # inspect canonical forms.
print("folded equality:", folded_pre_w == folded_decomp_w)  # now they match.
assert folded_pre_w == folded_decomp_w == "cafe"  # both collapse to the same token.
```
▶ What you'll see: both spellings become `cafe`, so exact equality finally agrees with human equality.

*Why it's done this way:* Unicode bugs are dangerous because the screen display hides them. Folding makes the equivalence class explicit: different code-point paths that carry the same downstream meaning are mapped to one representative before counts or vocabulary lookup happen.

### 3. Punctuation and digit policy

Cleanup is not automatically "remove everything weird." The policy decides what information survives. A spam detector may need `5000`, a programming classifier may need `C++`, and a sentiment model may need `!!!`; the right regex depends on the task.

```python
promo_w = "WIN $$$5000 now!!! Learn C++ today."  # inline toy document with symbols, digits, and code punctuation.
def normalize_policy_w(text_w, keep_digits_w=True, keep_plus_w=False):  # expose policy choices as arguments.
    text_w = fold_accents_w(text_w).lower()  # first make characters comparable.
    pattern_w = r"[^a-z0-9+\s]" if keep_digits_w and keep_plus_w else r"[^a-z0-9\s]" if keep_digits_w else r"[^a-z\s]"  # choose what to delete.
    return re.sub(r"\s+", " ", re.sub(pattern_w, " ", text_w)).strip()  # clean and compress whitespace.
print("keep digits:", normalize_policy_w(promo_w, keep_digits_w=True))  # keep amount.
print("letters only:", normalize_policy_w(promo_w, keep_digits_w=False))  # drop amount.
print("keep digits and plus:", normalize_policy_w(promo_w, keep_digits_w=True, keep_plus_w=True))  # preserve C++.
```
▶ What you'll see: the stricter letters-only policy deletes `5000`, while the plus-preserving policy keeps `c++`.

```python
tokens_digits_w = normalize_policy_w(promo_w, keep_digits_w=True).split()  # tokenize after digit-preserving cleanup.
tokens_letters_w = normalize_policy_w(promo_w, keep_digits_w=False).split()  # tokenize after letters-only cleanup.
print("digit policy tokens:", tokens_digits_w, "count:", len(tokens_digits_w))  # amount survives.
print("letters-only tokens:", tokens_letters_w, "count:", len(tokens_letters_w))  # amount disappears.
assert "5000" in tokens_digits_w and "5000" not in tokens_letters_w  # verify the policy tradeoff.
```
▶ What you'll see: token count changes and the amount token appears only under the digit-preserving policy.

```python
plt.figure(figsize=(5, 3))  # compare token counts under the two cleanup policies.
plt.bar(["keep digits", "letters only"], [len(tokens_digits_w), len(tokens_letters_w)], color=["steelblue", "orange"])  # show policy effect.
plt.ylabel("tokens after cleanup")  # label the count.
plt.title("3: punctuation policy changes the evidence")  # title the visual.
plt.show()  # display the chart.
```
▶ What you'll see: different cleanup rules produce different token streams from the same sentence.

*Why it's done this way:* a regex is a modeling assumption written as code. It changes the sample space of tokens the model can ever see, so the correct policy is the one that preserves distinctions useful for the task and deletes distinctions that only fragment counts.

### 4. Stop words and negation

Stop-word removal drops common function words to reduce noise, but "common" is not the same as "safe." Negation words such as `not`, `no`, and `never` can flip sentiment, so the stop list must be task-aware rather than copied blindly.

```python
sentence_w = "the model is not bad"  # small sentence where negation matters.
tokens_w = sentence_w.split()  # simple whitespace tokens after normalization.
safe_stop_w = {"the", "is"}  # remove function words but preserve negation.
risky_stop_w = {"the", "is", "not"}  # over-eager list that deletes negation.
safe_tokens_w = [t_w for t_w in tokens_w if t_w not in safe_stop_w]  # safe filtering.
risky_tokens_w = [t_w for t_w in tokens_w if t_w not in risky_stop_w]  # risky filtering.
print("original:", tokens_w)  # inspect before stop-word removal.
print("safe stoplist:", safe_tokens_w)  # negation remains.
print("risky stoplist:", risky_tokens_w)  # negation disappears.
assert safe_tokens_w == ["model", "not", "bad"] and risky_tokens_w == ["model", "bad"]  # concrete flip risk.
```
▶ What you'll see: the risky list turns `not bad` into just `bad`.

```python
def tiny_sentiment_w(tokens_in_w):  # deliberately tiny scoring rule for illustration.
    score_w = 0  # positive means favorable, negative means unfavorable.
    for idx_w, tok_w in enumerate(tokens_in_w):  # scan tokens with position.
        if tok_w == "bad":  # negative word.
            negated_w = idx_w > 0 and tokens_in_w[idx_w - 1] == "not"  # detect immediately preceding not.
            score_w += 1 if negated_w else -1  # negated bad is favorable in this toy rule.
    return score_w  # return the sentiment score.
print("safe score:", tiny_sentiment_w(safe_tokens_w))  # preserves positive meaning.
print("risky score:", tiny_sentiment_w(risky_tokens_w))  # flips to negative.
assert tiny_sentiment_w(safe_tokens_w) == 1 and tiny_sentiment_w(risky_tokens_w) == -1  # verify the semantic damage.
```
▶ What you'll see: removing `not` changes the toy sentiment score from +1 to -1.

*Why it's done this way:* stop-word removal is a lossy projection from a longer sequence to a shorter one. The mathematical question is whether the removed coordinates are irrelevant to the target; negation is a coordinate whose value often determines the label.

### 5. Padding, masks, and real-token counts

Batches need equal-width arrays, but sentences have different lengths. Padding adds placeholder slots, not words. A mask is the companion object that tells later averages or attention which positions are real evidence.

```python
seqs_w = [["nlp", "rocks"], ["text", "needs", "care", "today"], ["mask"]]  # variable-length token sequences.
maxlen_w = max(len(s_w) for s_w in seqs_w)  # batch width.
padded_w = []  # padded token rows.
mask_w = []  # True where a token is real.
for s_w in seqs_w:  # process each sequence.
    pad_count_w = maxlen_w - len(s_w)  # number of placeholder slots needed.
    padded_w.append(s_w + ["<pad>"] * pad_count_w)  # append placeholders on the right.
    mask_w.append([True] * len(s_w) + [False] * pad_count_w)  # mark real tokens only.
mask_w = np.array(mask_w)  # boolean array for arithmetic.
print("padded:", padded_w)  # inspect equal-width strings.
print("mask:\n", mask_w.astype(int))  # 1 = real token, 0 = padding.
assert mask_w.sum() == 7 and mask_w.size == 12  # 7 real tokens in 12 slots.
```
▶ What you'll see: every row has width 4, but only 7 of the 12 positions are real tokens.

```python
lengths_wrong_w = np.array([len(row_w) for row_w in padded_w])  # counts pad slots too.
lengths_right_w = mask_w.sum(axis=1)  # counts only real tokens.
print("wrong lengths:", lengths_wrong_w)  # all rows look length 4.
print("right lengths:", lengths_right_w)  # original lengths are recovered.
assert np.array_equal(lengths_right_w, np.array([2, 4, 1]))  # verify correct lengths.
```
▶ What you'll see: the mask recovers lengths 2, 4, and 1 instead of pretending every sentence has length 4.

```python
plt.figure(figsize=(4.5, 3))  # visualize real-token positions.
plt.imshow(mask_w.astype(int), cmap="Greens", aspect="auto")  # green cells are real tokens.
plt.colorbar(label="1 = real token")  # color scale.
plt.title("5: padding mask")  # title the mask plot.
plt.xlabel("position")  # positions in the padded batch.
plt.ylabel("sequence")  # row index.
plt.show()  # display the mask.
```
▶ What you'll see: only the left part of shorter rows is green; the remaining slots are scaffolding.

*Why it's done this way:* vectorized models require rectangular arrays, so padding solves a storage problem. The mask solves the statistical problem: averages, losses, and attention must divide by the number of real tokens, not by the number of allocated slots.

### 6. Train and inference must share the same normalizer

The normalizer is part of the model interface. If training lowercases and strips punctuation but inference forgets one rule, familiar words arrive as out-of-vocabulary variants even though the model has seen their meaning before.

```python
train_docs_w = ["Café wins!", "Tea wins.", "CAFE again"]  # tiny training corpus.
def train_norm_w(text_w):  # training-time normalizer.
    return normalize_policy_w(text_w, keep_digits_w=True).split()  # fold, lowercase, strip punctuation.
def serve_norm_bad_w(text_w):  # buggy serving-time normalizer.
    return re.sub(r"\s+", " ", text_w.lower()).split()  # lowercases but leaves accents/punctuation.
vocab_train_w = sorted(set(tok_w for doc_w in train_docs_w for tok_w in train_norm_w(doc_w)))  # build training vocabulary.
print("training vocab:", vocab_train_w)  # inspect learned token set.
assert "cafe" in vocab_train_w and "wins" in vocab_train_w  # known canonical tokens.
```
▶ What you'll see: the training vocabulary contains canonical tokens such as `cafe` and `wins`.

```python
test_doc_w = "CAFÉ wins!"  # inference string with capitalization, accent, and punctuation.
good_tokens_w = train_norm_w(test_doc_w)  # byte-identical preprocessing.
bad_tokens_w = serve_norm_bad_w(test_doc_w)  # inconsistent preprocessing.
good_oov_w = [t_w for t_w in good_tokens_w if t_w not in vocab_train_w]  # unknown tokens under correct path.
bad_oov_w = [t_w for t_w in bad_tokens_w if t_w not in vocab_train_w]  # unknown tokens under buggy path.
print("good serving tokens:", good_tokens_w, "OOV:", good_oov_w)  # should be all known.
print("bad serving tokens:", bad_tokens_w, "OOV:", bad_oov_w)  # accent/punctuation variants become unknown.
assert good_oov_w == [] and len(bad_oov_w) == 2  # verify the mismatch.
```
▶ What you'll see: correct preprocessing yields known tokens, while the buggy path produces two OOV tokens.

*Why it's done this way:* learning attaches parameters to canonical strings. If the serving function is not the same $n(\cdot)$ used at training time, equality classes split after deployment, and the model behaves as if it never learned those words.

## 🛠️ Setup

```python
import numpy as np  # arrays, masks, counts, and numerical checks for all examples.
import matplotlib.pyplot as plt  # plotting helper for bar charts, heatmaps, and curves.
import re  # regular expressions for tokenization and cleanup rules.
np.random.seed(0)  # keep all toy examples reproducible.

def fold_accents(text):  # fold only the small accent set needed by this lesson's toy examples.
    accent_map = {"é": "e", "É": "e", "á": "a", "Á": "a", "í": "i", "Í": "i", "ó": "o", "Ó": "o", "ú": "u", "Ú": "u"}  # explicit readable map.
    chars = []  # collect canonical characters.
    for ch in text:  # inspect code points one by one.
        if "\u0300" <= ch <= "\u036f":  # skip combining accent marks.
            continue
        chars.append(accent_map.get(ch, ch))  # replace known precomposed accents.
    return "".join(chars)  # return the folded string.

def normalize_text(text, keep_digits=True, keep_plus=False):  # define the reusable lesson normalizer.
    text = fold_accents(text).lower()  # collapse case and the toy accent variants first.
    pattern = r"[^a-z0-9+\s]" if keep_digits and keep_plus else r"[^a-z0-9\s]" if keep_digits else r"[^a-z\s]"  # choose allowed characters.
    return re.sub(r"\s+", " ", re.sub(pattern, " ", text)).strip()  # delete disallowed characters and compress spaces.

def tokenize(text, keep_digits=True, keep_plus=False):  # tokenize by applying normalization then splitting on spaces.
    cleaned = normalize_text(text, keep_digits=keep_digits, keep_plus=keep_plus)  # canonical string.
    return [] if cleaned == "" else cleaned.split()  # avoid returning [''] for empty documents.

def vocab_from_docs(docs):  # build a sorted vocabulary from inline documents.
    return sorted(set(tok for doc in docs for tok in tokenize(doc)))  # exact canonical token set.

def count_tokens(tokens, vocab):  # count tokens into a vector aligned with a vocabulary.
    return np.array([sum(tok == word for tok in tokens) for word in vocab], dtype=float)  # simple pure-Python counts in NumPy array.
```

### Basic 1 — Lowercase one sentence

**Goal.** Collapse case variants, because exact string equality treats `Text` and `text` as different tokens unless we choose a canonical case. We build it in 2 steps.

```python

```
▶ What you'll see: the same word appears as three different surface strings.

```python
lower_tokens_b1 = [tok_b1.lower() for tok_b1 in raw_tokens_b1]  # lowercase each token.

```
▶ What you'll see: vocabulary size drops from 3 to 1.

👀 Takeaway: lowercasing is an equivalence rule that merges tokens differing only by case.

### Basic 9 — Pad two short sequences

**Goal.** Create equal-length token rows, because batched numerical models require rectangular arrays. We build it in 2 steps.

```python
seqs_b9 = [["text", "model"], ["mask"]]  # variable-length token sequences.
```
