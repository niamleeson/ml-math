# 9.25 — Guardrails & Safety Filtering

Guardrails are thresholded decisions around model behavior, not magic shields. In this lesson, we build the pieces from scratch: exact rules, classifier-like scores, precision/recall threshold sweeps, cascaded filters, tool-action checks, and explicit utility calculations.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build guardrails one idea at a time. Run each cell in order and inspect the printed intermediate values — every score, threshold, and count is exposed. This walkthrough is self-contained and uses a `_w` suffix so it never clashes with examples below.

```python
import re  # standard-library pattern matching for rule filters.
import numpy as np  # arrays, thresholds, and metric sweeps.
import matplotlib.pyplot as plt  # visual debugging plots.
np.random.seed(0)  # reproducibility.
```

### 1. Thresholded safety decisions

The core guardrail formula is $\mathrm{block}(x)=\mathbf{1}[s(x)\ge\tau]$: compute a safety score $s(x)$, compare it with a threshold $\tau$, and turn continuous evidence into an action.

```python
scores_w = np.array([0.12, 0.31, 0.69, 0.82, 0.94])  # safety scores for five toy requests.
tau_w = 0.70  # block threshold.
blocked_w = scores_w >= tau_w  # apply 1[s >= tau].
print("scores:", scores_w)
print("blocked:", blocked_w.astype(int))
assert blocked_w.tolist() == [False, False, False, True, True]
```
▶ What you'll see: 0.82 and 0.94 block, while 0.69 passes because it is just below the threshold.

```python
plt.figure(figsize=(5, 3))
plt.scatter(range(len(scores_w)), scores_w, c=np.where(blocked_w, "crimson", "seagreen"), s=80)
plt.axhline(tau_w, color="black", linestyle="--", label="τ=0.70")
plt.ylim(0, 1); plt.xlabel("request"); plt.ylabel("safety score")
plt.title("1: thresholded guardrail"); plt.legend(); plt.show()
```
▶ What you'll see: the dashed threshold separates green allowed requests from red blocked requests.

*Why it's done this way:* The threshold is the policy knob. Lowering $\tau$ catches more borderline cases but overblocks more safe ones; raising $\tau$ preserves utility but misses cases with scores in the interval that used to block.

### 2. Rule filters for explicit patterns

Some constraints are best expressed as exact rules. Here the only unsafe placeholder is the benign token `BADWORD`, so a transparent regex can catch it without any learned model.

```python
texts_w = ["please explain fractions", "this has BADWORD", "badword appears", "safe algebra help"]
pattern_w = re.compile(r"\bBADWORD\b", flags=re.IGNORECASE)
rule_hits_w = np.array([bool(pattern_w.search(t)) for t in texts_w])
print("rule hits:", rule_hits_w.astype(int))
assert rule_hits_w.tolist() == [False, True, True, False]
```
▶ What you'll see: only texts containing the placeholder token are flagged.

```python
plt.figure(figsize=(5, 3))
plt.bar(range(len(texts_w)), rule_hits_w.astype(int), color=np.where(rule_hits_w, "crimson", "seagreen"))
plt.yticks([0, 1], ["pass", "hit"]); plt.xlabel("request")
plt.title("2: exact rule hits"); plt.show()
```
▶ What you'll see: two rule-hit bars rise to 1.

*Why it's done this way:* Exact rules have high precision when the pattern is unambiguous, but low recall for paraphrases. They are useful first-stage filters because their behavior is auditable.

### 3. Classifier-like scores from visible features

A learned classifier still produces a score. To keep the math inspectable, we build a tiny linear score from token counts and squash it with a sigmoid.

```python
def featurize_w(text):
    words = re.findall(r"[a-zA-Z]+", text.lower())
    return np.array([words.count("badword"), words.count("urgent"), len(words) / 20.0])

X_w = np.vstack([featurize_w(t) for t in texts_w])
w_w = np.array([3.0, 0.7, 0.2])
b_w = -2.0
logits_w = X_w @ w_w + b_w
clf_scores_w = 1 / (1 + np.exp(-logits_w))
print("features:\n", np.round(X_w, 2))
print("scores:", np.round(clf_scores_w, 3))
assert round(float(clf_scores_w[1]), 3) == 0.737
```
▶ What you'll see: placeholder-token examples receive much larger scores than ordinary math requests.

```python
plt.figure(figsize=(5, 3))
plt.bar(range(len(clf_scores_w)), clf_scores_w, color="slateblue")
plt.axhline(0.70, color="black", linestyle="--", label="τ=0.70")
plt.ylim(0, 1); plt.ylabel("classifier score")
plt.title("3: classifier scores still need a threshold"); plt.legend(); plt.show()
```
▶ What you'll see: the score model and the threshold are separate; changing either changes block behavior.

*Why it's done this way:* The weighted sum makes evidence additive; the sigmoid maps it to $[0,1]$. The final inequality still decides action, so classifier quality and threshold policy must be tuned separately.

### 4. Precision, recall, and threshold sweeps

For labels $y\in\{0,1\}$, each threshold creates true positives, false positives, false negatives, and true negatives. Precision measures blocked-set purity; recall measures unsafe-case catch rate.

```python
y_true_w = np.array([0, 0, 1, 1, 1, 0, 1, 0])
y_score_w = np.array([0.05, 0.20, 0.55, 0.82, 0.93, 0.72, 0.68, 0.31])
tau2_w = 0.70
y_pred_w = (y_score_w >= tau2_w).astype(int)
TP_w = int(np.sum((y_true_w == 1) & (y_pred_w == 1)))
FP_w = int(np.sum((y_true_w == 0) & (y_pred_w == 1)))
FN_w = int(np.sum((y_true_w == 1) & (y_pred_w == 0)))
TN_w = int(np.sum((y_true_w == 0) & (y_pred_w == 0)))
print("TP FP FN TN:", TP_w, FP_w, FN_w, TN_w)
assert (TP_w, FP_w, FN_w, TN_w) == (2, 1, 2, 3)
```
▶ What you'll see: at τ=0.70 the filter catches 2 unsafe examples, overblocks 1 safe example, and misses 2 unsafe examples.

```python
thresholds_w = np.linspace(0, 1, 21)
precision_w, recall_w = [], []
for t in thresholds_w:
    pred = (y_score_w >= t).astype(int)
    tp = np.sum((y_true_w == 1) & (pred == 1)); fp = np.sum((y_true_w == 0) & (pred == 1)); fn = np.sum((y_true_w == 1) & (pred == 0))
    precision_w.append(tp / (tp + fp) if tp + fp else 1.0)
    recall_w.append(tp / (tp + fn) if tp + fn else 0.0)
precision_w, recall_w = np.array(precision_w), np.array(recall_w)
print("precision, recall at τ=0.70:", round(float(precision_w[14]), 3), round(float(recall_w[14]), 3))
assert round(float(precision_w[14]), 3) == 0.667 and round(float(recall_w[14]), 3) == 0.5
```
▶ What you'll see: this threshold has precision 0.667 and recall 0.500.

```python
plt.figure(figsize=(5, 3.4))
plt.plot(recall_w, precision_w, marker="o", color="purple")
plt.xlabel("recall = TP/(TP+FN)"); plt.ylabel("precision = TP/(TP+FP)")
plt.xlim(0, 1.05); plt.ylim(0, 1.05); plt.title("4: precision-recall curve")
plt.show()
```
▶ What you'll see: the PR curve traces how the operating point moves as the threshold changes.

*Why it's done this way:* Precision protects safe traffic from overblocking; recall protects the system from missed unsafe cases. A threshold is an explicit choice between these error types.

### 5. Cascaded filters and utility

Guardrails are often cascades: a rule, a classifier, and an action gate. If two independent stages pass safe traffic with probabilities 0.9 and 0.8, both pass with probability 0.72.

```python
pass_probs_w = np.array([0.90, 0.80])
joint_pass_w = float(np.prod(pass_probs_w))
print("joint pass probability:", round(joint_pass_w, 3))
assert round(joint_pass_w, 3) == 0.720
```
▶ What you'll see: two individually mild filters combine into a 72% safe-pass rate.

```python
utility_w = 10 * 90 - 2 * 5 - 50 * 10
print("utility:", utility_w)
assert utility_w == 390
plt.figure(figsize=(5, 3))
plt.bar(["TP benefit", "FP cost", "FN cost"], [900, -10, -500], color=["seagreen", "orange", "crimson"])
plt.axhline(0, color="black", linewidth=0.8); plt.ylabel("utility contribution")
plt.title("5: explicit utility terms"); plt.show()
```
▶ What you'll see: the missed-case cost is large and negative, explaining why recall can dominate the threshold choice.

*Why it's done this way:* Cascades multiply pass/fail chances, while utility assigns costs to the outcomes. Together they reveal whether a system is safer, merely more restrictive, or actually worse for users.

### 6. Guarding tool actions, not just text

A final-text filter can miss the important thing: an action may execute before text is produced. Guardrails must also wrap retrieval and tool calls.

```python
tools_w = np.array(["calculator", "search", "delete_record", "plotter"])
allowlist_w = {"calculator", "plotter"}
allowed_w = np.array([t in allowlist_w for t in tools_w])
print("actions:", np.where(allowed_w, "execute", "block"))
assert allowed_w.tolist() == [True, False, False, True]
```
▶ What you'll see: only explicitly allowlisted study tools execute.

```python
plt.figure(figsize=(5, 3))
plt.bar(tools_w, allowed_w.astype(int), color=np.where(allowed_w, "seagreen", "crimson"))
plt.xticks(rotation=20); plt.yticks([0, 1], ["block", "execute"])
plt.title("6: action-level guardrail"); plt.show()
```
▶ What you'll see: the disallowed action is blocked before any final response text matters.

*Why it's done this way:* Filtering only final text protects the transcript but not the system. Tool guardrails put the decision at the point where irreversible side effects could happen.

### ✍️ Toy 3 · Linear features become sigmoid scores

A classifier-like guardrail sums feature evidence, adds a bias, and squashes the logit into a score.

```python
import numpy as np

t3_rng = np.random.default_rng(0)
t3_features = np.array([[0.0, 1.0], [1.0, 1.0], [2.0, 0.0]])
print("features:", t3_features.tolist())  # -> [[0.0, 1.0], [1.0, 1.0], [2.0, 0.0]]
t3_weights = np.array([1.5, 0.5])
print("weights:", t3_weights.tolist())  # -> [1.5, 0.5]
t3_bias = -1.0
print("bias:", t3_bias)  # -> -1.0
t3_logits = t3_features @ t3_weights + t3_bias

t3_scores = 1.0 / (1.0 + np.exp(-t3_logits))
print("sigmoid scores:", np.round(t3_scores, 3).tolist())  # -> [0.378, 0.731, 0.881]
t3_blocks = t3_scores >= 0.70
print("blocked at 0.70:", t3_blocks.astype(int).tolist())  # -> [0, 1, 1]
assert round(float(t3_scores[1]), 3) == 0.731

plt.figure(figsize=(4.4, 2.8))

plt.axhline(0.70, color="black", linestyle="--")
plt.ylim(0, 1)
plt.ylabel("score")
plt.title("Toy 3 · sigmoid score then threshold")
plt.show()
```
▶ What you'll see: requests `r1` and `r2` score above the `0.70` threshold.

### ✍️ Toy 5 · Threshold sweeps trade precision and recall

Moving the threshold changes blocked-set purity (precision) and unsafe-case catch rate (recall).


## 🛠️ Setup

```python
import re  # Use the standard library for simple pattern-based safety filters.
import numpy as np  # Use NumPy for scores, thresholds, metrics, and toy arrays.
import matplotlib.pyplot as plt  # Use Matplotlib for debugging curves and threshold plots.
np.random.seed(0)  # Make all examples reproducible.

def sigmoid(z):  # Convert linear evidence into a bounded score.
    return 1 / (1 + np.exp(-z))

def rule_score(text):  # Score the benign placeholder token with an exact rule.
    return 1.0 if re.search(r"\bBADWORD\b", text, flags=re.IGNORECASE) else 0.0

def confusion_counts(y_true, y_score, tau):  # Compute thresholded confusion counts.
    y_true = np.asarray(y_true).astype(int)
    pred = (np.asarray(y_score) >= tau).astype(int)
    tp = int(np.sum((y_true == 1) & (pred == 1)))
    fp = int(np.sum((y_true == 0) & (pred == 1)))
    fn = int(np.sum((y_true == 1) & (pred == 0)))
    tn = int(np.sum((y_true == 0) & (pred == 0)))
    return tp, fp, fn, tn

def precision_recall(y_true, y_score, tau):  # Compute precision and recall at one threshold.
    tp, fp, fn, tn = confusion_counts(y_true, y_score, tau)
    precision = tp / (tp + fp) if (tp + fp) else 1.0
    recall = tp / (tp + fn) if (tp + fn) else 0.0
    return precision, recall
```

## 🟢 Basics (warm-up)

### Basic 1 — Apply the block formula

**Goal.** Convert scores to decisions with $s(x)\ge\tau$, because guardrails need actions, not just scores. We build it in 2 steps.

```python
scores_b1 = np.array([0.10, 0.68, 0.70, 0.91])
tau_b1 = 0.70
print("scores:", scores_b1, "threshold:", tau_b1)
```
▶ What you'll see: four scores around the cutoff.

```python
blocks_b1 = scores_b1 >= tau_b1
```
