# 8.23 — Question Answering

Question answering (QA) turns a passage into a conditional decision: the answer is not "what the passage is about," but the span, document, or generated option that the **question** makes relevant — and sometimes the right output is no answer at all. In this lesson, you will build extractive span scoring, retrieval, abstention, and EM/F1 evaluation from first principles with tiny NumPy examples.

### 1. The question selects evidence from the context

A passage can contain many true facts, so QA must condition on the question before deciding what text matters. Here the same context contains both a city and a country; asking "where is Paris?" should select `France`, while asking "what city is in France?" should select `Paris`. We start with explicit tokens so every later score is tied to a position.

```python
context_w = "Paris is in France"  # a tiny passage with two possible factual answers.
questions_w = ["Where is Paris?", "What city is in France?"]  # two questions over the same passage.
tokens_w = context_w.split()  # keep tokenization simple and inspectable.
print("tokens:", list(enumerate(tokens_w)))  # show zero-based token positions.
print("questions:", questions_w)  # inspect the conditioning inputs.
```
▶ What you'll see: `Paris` is token 0 and `France` is token 3, so different questions should point to different positions.

```python
answer_for_question_w = np.array([3, 0])  # question 0 answers with France; question 1 answers with Paris.
plt.figure(figsize=(4.8, 2.8))  # create a compact position plot.
plt.scatter(answer_for_question_w, [1, 0], s=140, color=["teal", "orange"])  # mark the chosen token for each question.
plt.yticks([1, 0], ["where?", "what city?"])  # label each row by question type.
plt.xticks(range(len(tokens_w)), tokens_w)  # label token positions by the passage words.
plt.title("1: the question chooses the answer token")  # title the plot.
plt.show()  # display the selection map.
```
▶ What you'll see: the two questions land on different tokens even though the context is identical.

*Why it's done this way: QA is conditional reading. Without the question, `Paris` and `France` are both plausible facts; the question supplies the missing variable that tells the model which token should receive probability mass.*

### 2. Start and end distributions over passage positions

An extractive reader does not directly output a string. It gives every passage token a start logit and every passage token an end logit, then softmax turns those logits into two probability distributions. For `Where is Paris?`, the answer is one token, `France`, so both distributions should concentrate on position 3.

```python
def softmax_w(logits_w):  # define a stable softmax from scratch.
    shifted_w = logits_w - np.max(logits_w)  # subtract the max so exponentials stay numerically safe.
    exp_w = np.exp(shifted_w)  # exponentiate shifted logits.
    return exp_w / np.sum(exp_w)  # normalize into probabilities that sum to 1.

start_logits_w = np.array([0.1, 0.2, 0.1, 2.0])  # model scores for start positions.
end_logits_w = np.array([0.1, 0.1, 0.2, 2.5])  # model scores for end positions.
print("start logits:", start_logits_w)  # inspect raw start scores.
print("end logits:", end_logits_w)  # inspect raw end scores.
```
▶ What you'll see: position 3 has the largest start and end logit.

```python
P_start_w = softmax_w(start_logits_w)  # convert start logits into a distribution.
P_end_w = softmax_w(end_logits_w)  # convert end logits into a distribution.
print("P_start:", np.round(P_start_w, 3))  # inspect start probabilities.
print("P_end:", np.round(P_end_w, 3))  # inspect end probabilities.
assert np.allclose(np.round(P_start_w, 3), [0.102, 0.113, 0.102, 0.683])  # verify lesson numbers.
assert np.allclose(np.round(P_end_w, 3), [0.071, 0.071, 0.078, 0.780])  # verify lesson numbers.
```
▶ What you'll see: start probability 0.683 and end probability 0.780 both concentrate on `France`.

```python
x_w = np.arange(len(tokens_w))  # token positions for plotting.
plt.figure(figsize=(5, 3))  # create a compact probability plot.
plt.bar(x_w - 0.18, P_start_w, width=0.36, label="start", color="teal")  # plot start distribution.
plt.bar(x_w + 0.18, P_end_w, width=0.36, label="end", color="orange")  # plot end distribution.
plt.xticks(x_w, tokens_w)  # label each bar by token.
plt.ylabel("probability")  # label probability scale.
plt.title("2: start/end distributions")  # title the plot.
plt.legend()  # show which bars are start and end.
plt.show()  # display the chart.
```
▶ What you'll see: both distributions peak at `France`, turning token-level scores into answer evidence.

*Why it's done this way: softmax makes competing token positions comparable by forcing each distribution to sum to one. The start distribution answers “where should the span begin?” and the end distribution answers “where should it stop?”*

### 3. Span scoring with a legal triangular mask

Start and end argmaxes are not enough because the best independent start could occur after the best independent end. Extractive QA scores every pair `(i, j)` by `P_start[i] * P_end[j]`, then masks out illegal spans where `j < i`. The mask is small, but it encodes the mathematical fact that an interval cannot end before it begins.

```python
span_scores_w = P_start_w[:, None] * P_end_w[None, :]  # outer product gives every start/end pair.
legal_mask_w = np.triu(np.ones_like(span_scores_w, dtype=bool))  # keep spans with end >= start.
legal_scores_w = np.where(legal_mask_w, span_scores_w, 0.0)  # zero impossible intervals.
print("span score matrix:\n", np.round(span_scores_w, 3))  # inspect all raw pair scores.
print("legal mask:\n", legal_mask_w.astype(int))  # inspect the triangular legality structure.
```
▶ What you'll see: the full 4×4 matrix is cut to its upper triangle, because lower-left spans end too early.

```python
flat_idx_w = int(np.argmax(legal_scores_w))  # find the best legal span in flattened form.
start_w, end_w = np.unravel_index(flat_idx_w, legal_scores_w.shape)  # convert flat index back to coordinates.
answer_w = " ".join(tokens_w[start_w:end_w + 1])  # extract the chosen span text.
print("best flat index:", flat_idx_w)  # inspect the flattened index.
print("best span:", (start_w, end_w), answer_w, "score", round(float(legal_scores_w[start_w, end_w]), 3))  # inspect extraction.
assert flat_idx_w == 15 and (start_w, end_w) == (3, 3)  # verify span coordinates.
assert round(float(legal_scores_w[start_w, end_w]), 3) == 0.533  # verify best span score.
```
▶ What you'll see: the best legal span is `(3, 3)` with score `0.533`, exactly the token `France`.

```python
plt.figure(figsize=(4.3, 3.5))  # create a compact span heatmap.
plt.imshow(legal_scores_w, cmap="viridis", aspect="auto")  # visualize legal span scores.
plt.colorbar(label="P(start) × P(end)")  # add a score scale.
plt.scatter([end_w], [start_w], color="red", s=80, label="best span")  # mark the chosen cell.
plt.xticks(range(4), tokens_w)  # label end positions.
plt.yticks(range(4), tokens_w)  # label start positions.
plt.xlabel("end token")  # label x-axis.
plt.ylabel("start token")  # label y-axis.
plt.title("3: legal span matrix")  # title the heatmap.
plt.legend()  # show the best-span marker.
plt.show()  # display the matrix.
```
▶ What you'll see: the brightest legal cell sits at start `France`, end `France`; illegal lower-triangle cells are zero.

*Why it's done this way: multiplying start and end probabilities assumes the two boundary decisions are separately scored but jointly chosen. The triangular mask injects interval structure so the argmax is a valid text span rather than two unrelated tokens.*

### 4. Abstention: when no answer beats the best span

A QA system that always returns a span will hallucinate answers from irrelevant contexts. Modern QA therefore gives the model a no-answer score and compares it with the best span score. If abstention is higher, the system should say the context is insufficient.

```python
best_span_score_w = 0.55  # suppose the reader's best text span is only moderately supported.
no_answer_score_w = 0.62  # the model's score for insufficient evidence.
margin_w = no_answer_score_w - best_span_score_w  # positive margin favors abstention.
print("best span score:", best_span_score_w)  # inspect span confidence.
print("no-answer score:", no_answer_score_w)  # inspect abstention confidence.
print("no-answer minus span:", round(margin_w, 3))  # inspect the decision margin.
assert round(margin_w, 3) == 0.070  # verify the lesson difference.
```
▶ What you'll see: no-answer is higher by 0.07, so the model has evidence to abstain.

```python
decision_w = "abstain" if no_answer_score_w > best_span_score_w else "return span"  # compare scores directly.
print("decision:", decision_w)  # inspect the final QA action.
plt.figure(figsize=(4.2, 3))  # create a compact comparison chart.
plt.bar(["best span", "no answer"], [best_span_score_w, no_answer_score_w], color=["orange", "teal"])  # compare competing actions.
plt.ylabel("score")  # label score axis.
plt.title("4: abstention beats weak extraction")  # title the plot.
plt.show()  # display the decision chart.
```
▶ What you'll see: the no-answer bar is taller, so returning text would be overconfident.

*Why it's done this way: the best available span is only the best among spans, not proof that the question is answerable. A separate abstention score lets the model compare “some text looks plausible” against “the evidence is missing.”*

### 5. Retrieval chooses the context before reading

Open-book QA usually cannot score every document with a reader. Retrieval first picks candidate contexts, commonly by vector similarity or TF-IDF, and the reader only extracts from those contexts. If retrieval chooses the wrong document, span extraction can be perfect and still answer the wrong question.

```python
query_vec_w = np.array([1.0, 0.0])  # query embedding pointing along the first semantic axis.
doc_vecs_w = np.array([[0.9, 0.1], [0.0, 1.0], [0.7, 0.3]])  # three candidate document vectors.
doc_names_w = ["France doc", "river doc", "Europe doc"]  # readable document labels.
print("query:", query_vec_w)  # inspect query vector.
print("docs:\n", doc_vecs_w)  # inspect document vectors.
```
▶ What you'll see: document 0 is almost aligned with the query, document 1 is perpendicular, and document 2 is partly aligned.

```python
def cosine_rows_w(q_w, D_w):  # compute cosine similarity from one query to many document rows.
    q_norm_w = np.linalg.norm(q_w)  # length of query vector.
    d_norms_w = np.linalg.norm(D_w, axis=1)  # length of each document vector.
    return (D_w @ q_w) / (d_norms_w * q_norm_w)  # dot divided by length product.

cosines_w = cosine_rows_w(query_vec_w, doc_vecs_w)  # score all documents.
print("cosines:", np.round(cosines_w, 3))  # inspect retrieval scores.
print("winner:", doc_names_w[int(np.argmax(cosines_w))])  # inspect top document.
assert np.allclose(np.round(cosines_w, 3), [0.994, 0.000, 0.919])  # verify lesson retrieval numbers.
```
▶ What you'll see: document 0 wins because `0.994 > 0.919 > 0.000`.

```python
plt.figure(figsize=(4.8, 3))  # create a retrieval-score plot.
plt.bar(doc_names_w, cosines_w, color="slateblue")  # show cosine for each candidate document.
plt.ylabel("cosine similarity")  # label retrieval score axis.
plt.title("5: retrieval ranks contexts")  # title the chart.
plt.xticks(rotation=15)  # rotate document labels.
plt.show()  # display the ranking.
```
▶ What you'll see: the `France doc` is retrieved first, which is the only context a reader can safely answer from.

*Why it's done this way: retrieval is a coarse but cheap filter. Cosine uses vector direction rather than raw length, so a document wins by matching the query semantics, not merely by having a large vector norm.*

### 6. Exact match and token F1 evaluate the answer string

QA evaluation often uses exact match (EM) and token F1. EM is strict: the normalized predicted string must equal the normalized gold string. Token F1 is softer: it measures overlap between predicted and gold answer tokens, balancing precision and recall.

```python
def normalize_tokens_w(text_w):  # define tiny normalization without external libraries.
    cleaned_w = "".join(ch.lower() if ch.isalnum() or ch.isspace() else " " for ch in text_w)  # lowercase and drop punctuation.
    return cleaned_w.split()  # split on whitespace into tokens.

def em_f1_w(pred_w, gold_w):  # compute exact match and token F1 from scratch.
    p_w = normalize_tokens_w(pred_w)  # normalize predicted answer.
    g_w = normalize_tokens_w(gold_w)  # normalize gold answer.
    em_w = 1.0 if p_w == g_w else 0.0  # exact sequence match after normalization.
    overlap_w = sum((Counter(p_w) & Counter(g_w)).values())  # multiset token overlap.
    precision_w = overlap_w / len(p_w) if p_w else 0.0  # predicted tokens that are correct.
    recall_w = overlap_w / len(g_w) if g_w else 0.0  # gold tokens recovered by prediction.
    f1_w = 0.0 if precision_w + recall_w == 0 else 2 * precision_w * recall_w / (precision_w + recall_w)  # harmonic mean.
    return em_w, precision_w, recall_w, f1_w  # return all pieces for inspection.
```

```python
pred_text_w = "the capital of France"  # a verbose predicted answer.
gold_text_w = "capital France"  # a shorter gold answer.
em_w, precision_w, recall_w, f1_w = em_f1_w(pred_text_w, gold_text_w)  # evaluate the answer.
print("EM:", em_w)  # inspect strict exact match.
print("precision:", round(precision_w, 3), "recall:", round(recall_w, 3), "F1:", round(f1_w, 3))  # inspect token overlap metrics.
assert em_w == 0.0 and round(precision_w, 3) == 0.500 and round(recall_w, 3) == 1.000  # verify metric pieces.
assert round(f1_w, 3) == 0.667  # verify F1.
```
▶ What you'll see: EM is 0, but F1 is 0.667 because both gold tokens appear inside a longer prediction.

```python
plt.figure(figsize=(4.4, 3))  # create a metric comparison figure.
plt.bar(["EM", "precision", "recall", "F1"], [em_w, precision_w, recall_w, f1_w], color=["gray", "teal", "orange", "purple"])  # show metric components.
plt.ylim(0, 1.05)  # keep the metric scale bounded.
plt.title("6: EM is strict, F1 rewards overlap")  # title the chart.
plt.show()  # display the metrics.
```
▶ What you'll see: recall is perfect, precision is partial, and F1 sits between them.

*Why it's done this way: EM catches whether the predicted answer string exactly matches the annotation, while F1 gives partial credit for recovering the right tokens. The harmonic mean is used so high recall cannot hide very low precision, and vice versa.*

### 7. Generative answer confidence

Not every QA system copies a span; some generate an answer token or phrase. Even then, we need confidence over alternatives. A softmax over answer logits exposes whether the model strongly prefers one answer or is merely fluent.

```python
answers_w = ["Paris", "London", "Rome"]  # candidate generated answers.
answer_logits_w = np.array([3.0, 1.0, 0.5])  # model logits for each answer.
answer_probs_w = softmax_w(answer_logits_w)  # convert logits to probabilities.
print("answer probabilities:", dict(zip(answers_w, np.round(answer_probs_w, 3))))  # inspect confidence.
assert np.allclose(np.round(answer_probs_w, 3), [0.821, 0.111, 0.067])  # verify lesson probabilities.
```
▶ What you'll see: `Paris` has probability 0.821, far above the alternatives.

```python
best_answer_w = answers_w[int(np.argmax(answer_probs_w))]  # choose the highest-probability answer.
confident_w = float(np.max(answer_probs_w)) > 0.8  # apply a simple confidence threshold.
print("best answer:", best_answer_w, "confident?", confident_w)  # inspect generation decision.
plt.figure(figsize=(4.4, 3))  # create answer-probability chart.
plt.bar(answers_w, answer_probs_w, color="darkcyan")  # plot probabilities over generated answers.
plt.axhline(0.8, color="red", linestyle="--", label="confidence threshold")  # mark threshold.
plt.ylabel("softmax probability")  # label y-axis.
plt.title("7: confidence over generated answers")  # title the chart.
plt.legend()  # show threshold label.
plt.show()  # display the chart.
```
▶ What you'll see: `Paris` clears the 0.8 threshold, while the alternatives are much lower.

*Why it's done this way: generated text can sound correct even when probability mass is spread across alternatives. Inspecting the distribution makes confidence explicit instead of trusting fluency.*

### Advanced 5 — Evaluate top-k retrieval recall

**Goal.** Measure whether the gold document appears in the retrieved top-k set, because reader accuracy is capped by retrieval recall. We build it in 4 steps.

```python
queries_a5 = ["paris france", "nile river", "rome italy"]  # Define three toy queries.
docs_a5 = ["paris is in france", "the nile is a river", "rome is in italy", "paris is a name"]  # Define candidate documents.
gold_doc_a5 = np.array([0, 1, 2])  # Store gold document index for each query.
print("gold docs:", gold_doc_a5)  # Inspect correct contexts.
```
▶ What you'll see: each query has exactly one gold document.

```python
vocab_a5 = sorted(set(" ".join(queries_a5 + docs_a5).split()))  # Build shared vocabulary.
def bow_a5(text_a5):  # Define a bag-of-words vectorizer.
    c_a5 = Counter(text_a5.split())  # Count words in the text.
    return np.array([c_a5[t] for t in vocab_a5], dtype=float)  # Return vector in vocabulary order.
D_a5 = np.vstack([bow_a5(doc_a5) for doc_a5 in docs_a5])  # Vectorize documents.
Q_a5 = np.vstack([bow_a5(query_a5) for query_a5 in queries_a5])  # Vectorize queries.
print("vocab size:", len(vocab_a5))  # Inspect vector dimension.
```

```python
scores_a5 = Q_a5 @ D_a5.T  # Score retrieval by bag-of-words dot product.
rankings_a5 = np.argsort(scores_a5, axis=1)[:, ::-1]  # Sort documents by descending score for each query.
recall_at_1_a5 = np.mean([gold_doc_a5[i] in rankings_a5[i, :1] for i in range(len(queries_a5))])  # Compute recall@1.
recall_at_2_a5 = np.mean([gold_doc_a5[i] in rankings_a5[i, :2] for i in range(len(queries_a5))])  # Compute recall@2.
print("rankings:\n", rankings_a5)  # Inspect ranked document indices.
print("recall@1:", recall_at_1_a5, "recall@2:", recall_at_2_a5)  # Inspect retrieval recalls.
assert recall_at_1_a5 == 1.0 and recall_at_2_a5 == 1.0  # Verify toy retrieval covers all gold docs.
```

```python
plt.figure(figsize=(4, 3))  # Create retrieval recall chart.
plt.bar(["R@1", "R@2"], [recall_at_1_a5, recall_at_2_a5], color=["teal", "purple"])  # Plot top-k recall.
plt.ylim(0, 1.05)  # Bound recall scale.
plt.title("Advanced 5: retrieval recall caps QA")  # Title chart.
plt.ylabel("fraction gold retrieved")  # Label y-axis.
plt.show()  # Display recall metrics.
```
▶ What you'll see: gold contexts appear in top 1 for all toy queries, so retrieval does not cap reader performance here.

👀 Takeaway: before blaming the reader, check whether retrieval puts the gold evidence in the candidate set.
