# 20.9 — A/B Testing & Online Experimentation

A/B testing estimates causal product impact by randomly splitting traffic, predeclaring metrics, and comparing treatment against a control counterfactual. In this lesson, we build the arithmetic behind online experiments from scratch: conversion-rate tests, power, the danger of peeking, CUPED variance reduction, multiple-testing corrections, bootstrap confidence intervals, and guardrail thinking.

### 1. Randomized traffic creates a counterfactual

A before-after chart mixes the model change with seasonality, marketing, and traffic mix. A randomized A/B test instead flips a fair coin for each eligible unit, so treatment and control are balanced *in expectation*. Then the control group estimates what would have happened to treated users if we had not shipped the change.

```python
rng_w = np.random.default_rng(0)  # local generator so the walkthrough is reproducible.
n_w = 20_000  # total eligible users in the toy launch.
assign_w = rng_w.random(n_w) < 0.5  # True = treatment, False = control.
pre_score_w = rng_w.normal(0, 1, n_w)  # a pre-period engagement score not affected by treatment.
print("treatment users:", int(assign_w.sum()), "control users:", int((~assign_w).sum()))
print("pre-score means:", round(pre_score_w[assign_w].mean(), 3), round(pre_score_w[~assign_w].mean(), 3))
```
▶ What you'll see: the two groups are nearly the same size and have nearly the same pre-period mean.

```python
plt.figure(figsize=(4.6, 3))
plt.hist(pre_score_w[~assign_w], bins=30, alpha=0.55, label="control")
plt.hist(pre_score_w[assign_w], bins=30, alpha=0.55, label="treatment")
plt.title("1: randomization balances pre-period scores")
plt.xlabel("pre-period score"); plt.ylabel("users"); plt.legend(); plt.show()
```
▶ What you'll see: the two histograms overlap; randomization made the groups comparable before treatment.

*Why it's done this way:* randomization breaks the link between treatment assignment and user attributes, so any systematic post-period difference can be interpreted as causal impact rather than selection bias. Balance is not guaranteed exactly in finite samples, but the expected imbalance is zero and shrinks like $1/\sqrt n$.

### 2. Two-proportion z-test for a conversion-rate lift

For binary outcomes, the production calculation compares conversion rates. The null hypothesis says treatment and control have the same true rate, so we pool successes to estimate one shared rate $\hat p$. The standard error is $\sqrt{\hat p(1-\hat p)(1/n_T+1/n_C)}$, and the z-score is observed lift divided by that null standard error.

```python
def normal_cdf_w(x):
    sign = 1 if x >= 0 else -1
    x = abs(float(x)) / math.sqrt(2.0)
    t = 1.0 / (1.0 + 0.3275911 * x)
    a1, a2, a3, a4, a5 = 0.254829592, -0.284496736, 1.421413741, -1.453152027, 1.061405429
    erf = 1.0 - (((((a5 * t + a4) * t + a3) * t + a2) * t + a1) * t) * math.exp(-x * x)
    return 0.5 * (1.0 + sign * erf)

x_c_w, n_c_w = 480, 10_000  # control conversions and users.
x_t_w, n_t_w = 520, 10_000  # treatment conversions and users.
p_c_w, p_t_w = x_c_w / n_c_w, x_t_w / n_t_w
lift_w = p_t_w - p_c_w
print("control:", p_c_w, "treatment:", p_t_w, "absolute lift:", lift_w)
assert round(p_c_w, 3) == 0.048 and round(p_t_w, 3) == 0.052
```
▶ What you'll see: treatment is 0.4 percentage points higher, an 8.3% relative lift over control.

```python
pooled_w = (x_c_w + x_t_w) / (n_c_w + n_t_w)
se_w = math.sqrt(pooled_w * (1 - pooled_w) * (1 / n_c_w + 1 / n_t_w))
z_w = lift_w / se_w
p_value_w = 2 * (1 - normal_cdf_w(abs(z_w)))
print("pooled rate:", round(pooled_w, 3), "SE:", round(se_w, 5))
print("z:", round(z_w, 3), "two-sided p:", round(p_value_w, 3))
assert round(z_w, 3) == 1.298
```
▶ What you'll see: `z = 1.298`; the result is encouraging but not conventionally significant at 5% two-sided.

```python
xs_w = np.linspace(-4, 4, 300)
ys_w = np.array([math.exp(-0.5 * x * x) / math.sqrt(2 * math.pi) for x in xs_w])
plt.figure(figsize=(5, 3))
plt.plot(xs_w, ys_w, color="navy")
plt.axvline(z_w, color="crimson", linestyle="--", label=f"z={z_w:.2f}")
plt.axvline(-z_w, color="crimson", linestyle="--")
plt.title("2: z-score on the null distribution"); plt.xlabel("z"); plt.ylabel("density")
plt.legend(); plt.show()
```
▶ What you'll see: the observed z is not far enough into the tails to be a low-p event under the null.

*Why it's done this way:* under the null, both arms share one true conversion probability, so pooling gives the most stable null variance estimate. Dividing lift by its standard error converts a metric difference into “how many noise units away from zero,” which is why the same z-test can compare experiments with different sample sizes.

### 3. Power and sample size: can the test see the lift?

A null result is only informative if the experiment had enough power. For a planned minimum detectable effect (MDE), the approximate per-arm sample size is $n \approx 2p(1-p)(z_{1-\alpha/2}+z_{1-\beta})^2/\delta^2$, where $\delta$ is the absolute lift we want to detect and $1-\beta$ is power.

```python
def normal_ppf_w(q):
    lo, hi = -8.0, 8.0
    for _ in range(80):
        mid = (lo + hi) / 2
        if normal_cdf_w(mid) < q:
            lo = mid
        else:
            hi = mid
    return (lo + hi) / 2

alpha_w, power_target_w = 0.05, 0.80
z_alpha_w = normal_ppf_w(1 - alpha_w / 2)
z_power_w = normal_ppf_w(power_target_w)
print("z_0.975:", round(z_alpha_w, 3), "z_0.80:", round(z_power_w, 3))
assert round(z_alpha_w, 2) == 1.96 and round(z_power_w, 2) == 0.84
```
▶ What you'll see: the familiar 1.96 significance cutoff and 0.84 power term.

```python
baseline_w = 0.05
mdes_w = np.array([0.002, 0.003, 0.004, 0.005, 0.006])
n_per_arm_w = 2 * baseline_w * (1 - baseline_w) * (z_alpha_w + z_power_w) ** 2 / (mdes_w ** 2)
print("MDEs:", mdes_w)
print("n per arm:", np.round(n_per_arm_w).astype(int))
assert int(round(n_per_arm_w[2])) == 46603
```
▶ What you'll see: detecting a 0.4 percentage-point lift at 80% power needs about 46.6k users per arm, much larger than the 10k-per-arm example.

```python
plt.figure(figsize=(5, 3))
plt.plot(mdes_w * 100, n_per_arm_w, marker="o", color="purple")
plt.title("3: smaller MDEs require many more users")
plt.xlabel("absolute lift to detect (percentage points)"); plt.ylabel("users per arm")
plt.show()
```
▶ What you'll see: the curve rises sharply as MDE shrinks because sample size scales like $1/\delta^2$.

*Why it's done this way:* the signal is the lift $\delta$, while binomial noise shrinks only like $1/\sqrt n$. To halve the detectable lift, we need roughly four times as many users, which is why underpowered experiments can “miss” practically important effects.

### 4. Sequential testing and the peeking problem

If we check the p-value every day and stop as soon as it crosses 0.05, the stopping rule changes the error rate. Even when treatment has no effect, repeated looks create many chances for random noise to look significant.

```python
rng_peek_w = np.random.default_rng(1)
trials_w, days_w, daily_per_arm_w = 700, 10, 400
naive_any_w = []
final_only_w = []
for _ in range(trials_w):
    c_w = rng_peek_w.binomial(daily_per_arm_w, 0.05, days_w)
    t_w = rng_peek_w.binomial(daily_per_arm_w, 0.05, days_w)
    seen_w = False
    for d_w in range(1, days_w + 1):
        xc_w, xt_w = c_w[:d_w].sum(), t_w[:d_w].sum()
        nnow_w = daily_per_arm_w * d_w
        ph_w = (xc_w + xt_w) / (2 * nnow_w)
        se_now_w = math.sqrt(ph_w * (1 - ph_w) * (2 / nnow_w))
        z_now_w = (xt_w / nnow_w - xc_w / nnow_w) / se_now_w if se_now_w > 0 else 0.0
        p_now_w = 2 * (1 - normal_cdf_w(abs(z_now_w)))
        seen_w = seen_w or (p_now_w < 0.05)
    naive_any_w.append(seen_w)
    final_only_w.append(p_now_w < 0.05)
print("final-look false positive:", round(np.mean(final_only_w), 3))
print("peek-until-sig false positive:", round(np.mean(naive_any_w), 3))
assert np.mean(naive_any_w) > np.mean(final_only_w)
```
▶ What you'll see: the false-positive rate under peeking is much higher than the final-look-only rate.

```python
looks_w = np.arange(1, days_w + 1)
fpr_by_look_w = []
for max_look_w in looks_w:
    hits_w = 0
    rng_tmp_w = np.random.default_rng(10 + max_look_w)
    for _ in range(500):
        c_w = rng_tmp_w.binomial(daily_per_arm_w, 0.05, max_look_w)
        t_w = rng_tmp_w.binomial(daily_per_arm_w, 0.05, max_look_w)
        hit_w = False
        for d_w in range(1, max_look_w + 1):
            xc_w, xt_w = c_w[:d_w].sum(), t_w[:d_w].sum()
            nnow_w = daily_per_arm_w * d_w
            ph_w = (xc_w + xt_w) / (2 * nnow_w)
            se_w2 = math.sqrt(ph_w * (1 - ph_w) * (2 / nnow_w))
            z_w2 = (xt_w / nnow_w - xc_w / nnow_w) / se_w2 if se_w2 > 0 else 0.0
            hit_w = hit_w or (2 * (1 - normal_cdf_w(abs(z_w2))) < 0.05)
        hits_w += int(hit_w)
    fpr_by_look_w.append(hits_w / 500)
plt.figure(figsize=(5, 3))
plt.plot(looks_w, fpr_by_look_w, marker="o", color="crimson")
plt.axhline(0.05, color="black", linestyle="--", label="nominal 5%")
plt.title("4: false-positive rate rises when we peek")
plt.xlabel("number of looks"); plt.ylabel("Pr(any p < 0.05 under null)"); plt.legend(); plt.show()
```
▶ What you'll see: the curve climbs above 5% as the number of looks grows; look for the gap above the dashed line.

*Why it's done this way:* a p-value is calibrated for a predeclared analysis, not for “try ten times and keep the luckiest look.” Sequential designs fix this by spending alpha across looks or using always-valid methods; naive peeking silently changes the experiment you are running.

### 5. CUPED variance reduction uses pre-period signal

CUPED subtracts a fitted piece of a pre-treatment covariate from the outcome: $Y' = Y - \theta(X-\bar X)$, where $\theta=\operatorname{Cov}(Y,X)/\operatorname{Var}(X)$. Because $X$ is measured before treatment, this adjustment does not remove the causal effect; it removes predictable user-level noise.

```python
rng_cuped_w = np.random.default_rng(2)
n_cuped_w = 5000
assign_cuped_w = rng_cuped_w.random(n_cuped_w) < 0.5
x_pre_w = rng_cuped_w.normal(0, 1, n_cuped_w)
tau_w = 0.12
y_w = 1.0 + tau_w * assign_cuped_w + 0.8 * x_pre_w + rng_cuped_w.normal(0, 1, n_cuped_w)
raw_diff_w = y_w[assign_cuped_w].mean() - y_w[~assign_cuped_w].mean()
theta_w = np.cov(y_w, x_pre_w, ddof=1)[0, 1] / np.var(x_pre_w, ddof=1)
print("raw diff:", round(raw_diff_w, 3), "theta:", round(theta_w, 3))
assert 0.65 < theta_w < 0.95
```
▶ What you'll see: theta is positive because pre-period score predicts post-period outcome.

```python
y_cuped_w = y_w - theta_w * (x_pre_w - x_pre_w.mean())
cuped_diff_w = y_cuped_w[assign_cuped_w].mean() - y_cuped_w[~assign_cuped_w].mean()
raw_se_w = math.sqrt(y_w[assign_cuped_w].var(ddof=1) / assign_cuped_w.sum() + y_w[~assign_cuped_w].var(ddof=1) / (~assign_cuped_w).sum())
cuped_se_w = math.sqrt(y_cuped_w[assign_cuped_w].var(ddof=1) / assign_cuped_w.sum() + y_cuped_w[~assign_cuped_w].var(ddof=1) / (~assign_cuped_w).sum())
print("CUPED diff:", round(cuped_diff_w, 3))
print("raw SE:", round(raw_se_w, 4), "CUPED SE:", round(cuped_se_w, 4))
assert cuped_se_w < raw_se_w
```
▶ What you'll see: the effect estimate stays similar but the standard error shrinks.

```python
plt.figure(figsize=(5, 3))
plt.bar(["raw SE", "CUPED SE"], [raw_se_w, cuped_se_w], color=["gray", "seagreen"])
plt.title("5: CUPED reduces variance with pre-period signal")
plt.ylabel("standard error of treatment-control difference"); plt.show()
```
▶ What you'll see: the CUPED bar is lower because predictable baseline variation has been removed.

*Why it's done this way:* subtracting the best linear prediction from a pre-treatment covariate leaves the randomized contrast unbiased while reducing residual variance. Mathematically, the optimal $\theta$ is the regression slope that minimizes $\operatorname{Var}(Y-\theta X)$.

### 6. Multiple testing and bootstrap confidence intervals

Experiment dashboards often show many metrics: primary, guardrails, segments, and model-quality slices. If we test many hypotheses at 5%, at least one false alarm becomes likely. For metrics whose sampling distribution is awkward, a bootstrap CI estimates uncertainty by resampling users rather than relying on a closed-form formula.

```python
pvals_w = np.array([0.004, 0.018, 0.041, 0.09, 0.20])
m_w = len(pvals_w)
bonf_w = np.minimum(1.0, pvals_w * m_w)
order_w = np.argsort(pvals_w)
bh_adj_w = np.empty(m_w)
running_w = 1.0
for rank_w, idx_w in reversed(list(enumerate(order_w, start=1))):
    running_w = min(running_w, pvals_w[idx_w] * m_w / rank_w)
    bh_adj_w[idx_w] = running_w
print("raw p:", pvals_w)
print("Bonferroni:", np.round(bonf_w, 3))
print("BH adjusted:", np.round(bh_adj_w, 3))
assert round(bonf_w[0], 3) == 0.02
```
▶ What you'll see: corrections make discoveries harder; BH is less conservative than Bonferroni for controlling false discovery rate.

```python
rng_boot_w = np.random.default_rng(3)
control_rev_w = rng_boot_w.lognormal(mean=1.0, sigma=0.9, size=800)
treat_rev_w = rng_boot_w.lognormal(mean=1.05, sigma=0.9, size=800)
obs_lift_w = treat_rev_w.mean() - control_rev_w.mean()
boot_w = []
for _ in range(1000):
    c_s_w = rng_boot_w.choice(control_rev_w, size=len(control_rev_w), replace=True)
    t_s_w = rng_boot_w.choice(treat_rev_w, size=len(treat_rev_w), replace=True)
    boot_w.append(t_s_w.mean() - c_s_w.mean())
lo_w, hi_w = np.percentile(boot_w, [2.5, 97.5])
print("observed revenue lift:", round(obs_lift_w, 3))
print("bootstrap 95% CI:", round(lo_w, 3), round(hi_w, 3))
assert lo_w < obs_lift_w < hi_w
```
▶ What you'll see: a resampling-based interval around the revenue lift, useful for skewed metrics.

```python
plt.figure(figsize=(5, 3))
plt.hist(boot_w, bins=35, color="steelblue", alpha=0.75)
plt.axvline(lo_w, color="crimson", linestyle="--", label="2.5% / 97.5%")
plt.axvline(hi_w, color="crimson", linestyle="--")
plt.axvline(obs_lift_w, color="black", label="observed lift")
plt.title("6: bootstrap CI for a skewed metric")
plt.xlabel("resampled treatment-control mean difference"); plt.legend(); plt.show()
```
▶ What you'll see: the bootstrap distribution is centered near the observed lift; the dashed lines mark the 95% interval.

*Why it's done this way:* multiple-testing correction accounts for the number of chances to be fooled, while the bootstrap approximates the sampling distribution by repeatedly re-running the experiment on resampled users. Both make uncertainty visible before a launch decision is made.

## 🛠️ Setup

```python
import math  # Use only Python's standard-library math functions for normal approximations.
import numpy as np  # Use NumPy for arrays, random simulation, and vectorized experiment summaries.
import matplotlib.pyplot as plt  # Use Matplotlib for power curves, peeking curves, and metric diagnostics.
np.random.seed(0)  # Keep all notebook examples reproducible.

def normal_cdf(x):  # Approximate the standard normal CDF from scratch with a polynomial erf approximation.
    sign = 1 if x >= 0 else -1  # Track the sign because erf is antisymmetric.
    z = abs(float(x)) / math.sqrt(2.0)  # Convert from normal scale to erf scale.
    t = 1.0 / (1.0 + 0.3275911 * z)  # Compute the Abramowitz-Stegun helper term.
    a1, a2, a3, a4, a5 = 0.254829592, -0.284496736, 1.421413741, -1.453152027, 1.061405429  # Polynomial coefficients.
    erf = 1.0 - (((((a5 * t + a4) * t + a3) * t + a2) * t + a1) * t) * math.exp(-z * z)  # Approximate erf(z).
    return 0.5 * (1.0 + sign * erf)  # Convert erf back to the normal CDF.

def normal_ppf(q):  # Invert the normal CDF by binary search so no SciPy is needed.
    lo, hi = -8.0, 8.0  # Almost all normal probability lies inside this range.
    for _ in range(80):  # Enough iterations for stable notebook arithmetic.
        mid = (lo + hi) / 2  # Candidate quantile.
        if normal_cdf(mid) < q:  # Move right if the CDF is still too small.
            lo = mid
        else:  # Move left if the CDF is too large.
            hi = mid
    return (lo + hi) / 2  # Return the approximate quantile.

def two_prop_z(x_t, n_t, x_c, n_c):  # Compute a two-proportion z-test under the pooled null.
    p_t = x_t / n_t  # Treatment conversion rate.
    p_c = x_c / n_c  # Control conversion rate.
    pooled = (x_t + x_c) / (n_t + n_c)  # Shared null rate.
    se = math.sqrt(pooled * (1 - pooled) * (1 / n_t + 1 / n_c))  # Null standard error.
    z = (p_t - p_c) / se if se > 0 else 0.0  # Standardized lift.
    p = 2 * (1 - normal_cdf(abs(z)))  # Two-sided p-value.
    return p_t, p_c, z, p  # Return rates, z-score, and p-value.
```

### Basic 5 — Turn lift into a z-score

**Goal.** Standardize the observed lift, because z tells us how many standard errors away from zero the result is. We build it in 2 steps.


### Advanced 4 — Combine CUPED with the treatment test

**Goal.** Compare raw and CUPED z-statistics for the same continuous experiment, because variance reduction can turn the same effect into stronger evidence. We build it in 3 steps.

```python
rng_a4 = np.random.default_rng(404)  # Create reproducible data.
n_a4 = 6000  # Total users.
arm_a4 = rng_a4.random(n_a4) < 0.5  # Random treatment assignment.
x_a4 = rng_a4.normal(size=n_a4)  # Pre-treatment metric.
y_a4 = 5.0 + 0.08 * arm_a4 + 0.9 * x_a4 + rng_a4.normal(scale=1.2, size=n_a4)  # Post metric.
print("arm sizes:", int((~arm_a4).sum()), int(arm_a4.sum()))  # Inspect allocation.
```
▶ What you'll see: treatment and control have similar sample sizes.

```python
def diff_se_a4(values, arm):
    return math.sqrt(values[arm].var(ddof=1) / arm.sum() + values[~arm].var(ddof=1) / (~arm).sum())  # Compute SE for a mean difference.

raw_diff_a4 = float(y_a4[arm_a4].mean() - y_a4[~arm_a4].mean())  # Raw effect estimate.
raw_se_a4 = diff_se_a4(y_a4, arm_a4)  # Raw standard error.
theta_a4 = np.cov(y_a4, x_a4, ddof=1)[0, 1] / np.var(x_a4, ddof=1)  # CUPED slope.
y_adj_a4 = y_a4 - theta_a4 * (x_a4 - x_a4.mean())  # CUPED-adjusted outcome.
adj_diff_a4 = float(y_adj_a4[arm_a4].mean() - y_adj_a4[~arm_a4].mean())  # Adjusted effect estimate.
adj_se_a4 = diff_se_a4(y_adj_a4, arm_a4)  # Adjusted standard error.
print("raw z:", round(raw_diff_a4 / raw_se_a4, 3), "CUPED z:", round(adj_diff_a4 / adj_se_a4, 3))  # Compare evidence.
assert adj_se_a4 < raw_se_a4  # Verify CUPED improved precision.
```

```python
plt.figure(figsize=(5, 3))  # Create a raw-vs-CUPED comparison.
plt.bar(["raw SE", "CUPED SE"], [raw_se_a4, adj_se_a4], color=["gray", "seagreen"])  # Compare uncertainty.
plt.title("Advanced 4: CUPED strengthens precision")  # Title the chart.
plt.ylabel("standard error")  # Label the SE axis.
plt.show()  # Display the figure.
```
▶ What you'll see: the CUPED standard error is lower, so the z-statistic is stronger for nearly the same treatment contrast.

👀 Takeaway: CUPED is useful because it removes pre-treatment noise without changing the randomized estimand.
