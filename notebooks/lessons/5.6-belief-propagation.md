# 5.6 — Belief Propagation

Belief propagation turns exact inference on a factor graph into a local conversation: each node sends a compact message summarizing everything it knows from one side of the graph. In this lesson, you will build sum-product and max-product from scratch with tiny NumPy tables, inspect every intermediate number, and see why messages must exclude the neighbor they are being sent to.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build belief propagation one idea at a time. Run each cell in order and read the printed intermediate values — every sum, product, normalization, and max is visible. This walkthrough is self-contained and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays, table arithmetic, and small exact checks.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
np.random.seed(0)  # reproducibility for any stochastic examples.
```

### 1. A factor graph is a product of small tables

Belief propagation starts with a factorization, not with one enormous joint table. For a simple chain $X-Y-Z$, we store a prior for $X$, a pairwise factor between $X,Y$, and a pairwise factor between $Y,Z$. The full joint score is the product $p(X)\,\psi_{XY}(X,Y)\,\psi_{YZ}(Y,Z)$, and exact marginalization sums that product over unwanted variables.

```python
pX_w = np.array([0.6, 0.4])  # prior scores for X=0 and X=1.
psiXY_w = np.array([[0.9, 0.1],
                    [0.2, 0.8]])  # rows X, columns Y.
psiYZ_w = np.array([[0.9, 0.1],
                    [0.2, 0.8]])  # rows Y, columns Z.
eZ_w = np.array([0.3, 0.7])  # evidence likelihood attached to Z.
print("pX:", pX_w)
print("psiXY:\n", psiXY_w)
print("psiYZ:\n", psiYZ_w)
```
▶ What you'll see: three small tables that replace one 2×2×2 joint table.

```python
joint_w = pX_w[:, None, None] * psiXY_w[:, :, None] * psiYZ_w[None, :, :] * eZ_w[None, None, :]
pY_bruteforce_w = joint_w.sum(axis=(0, 2))
pY_bruteforce_w = pY_bruteforce_w / pY_bruteforce_w.sum()
print("joint shape:", joint_w.shape)
print("brute-force p(Y):", np.round(pY_bruteforce_w, 6))
assert np.allclose(np.round(pY_bruteforce_w, 6), [0.472222, 0.527778])
```
▶ What you'll see: brute-force marginalization gives `p(Y=0)=0.472222`, but it had to build all 8 joint entries.

```python
plt.figure(figsize=(4, 3))
plt.imshow(joint_w.reshape(2, 4), cmap="viridis", aspect="auto")
plt.colorbar(label="joint score")
plt.title("1: full joint table flattened")
plt.xlabel("(Y,Z) state")
plt.ylabel("X state")
plt.show()
```
▶ What you'll see: every joint configuration exists even though the model was specified by only local factors.

*Why it's done this way:* the product form is the mathematical reason message passing can help. Brute force expands every assignment, but each factor touches only a few variables, so many partial sums can be computed locally and reused instead of recomputed for every query.

### 2. Factor-to-variable messages are summarized sums

A factor-to-variable message sends the influence of one factor toward one variable. For the right side of the chain, the message from the $(Y,Z)$ factor to $Y$ is

$$m_{YZ\to Y}(y)=\sum_z \psi_{YZ}(y,z)e_Z(z).$$

This is a vector over $Y$: one number for each possible value of $Y$, after all $Z$ possibilities have been summed away.

```python
right_terms_w = psiYZ_w * eZ_w[None, :]  # multiply each Z column by its evidence likelihood.
print("right-side terms:\n", np.round(right_terms_w, 3))
```
▶ What you'll see: each row is a fixed Y value, and the two columns are the Z values being summed out.

```python
m_right_w = right_terms_w.sum(axis=1)
print("m_{YZ->Y}:", np.round(m_right_w, 3))
assert np.allclose(np.round(m_right_w, 3), [0.340, 0.620])
```
▶ What you'll see: `[0.9·0.3 + 0.1·0.7, 0.2·0.3 + 0.8·0.7] = [0.340, 0.620]`.

```python
plt.figure(figsize=(4, 3))
plt.bar(["Y=0", "Y=1"], m_right_w, color="darkorange")
plt.title("2: right message into Y")
plt.ylabel("message score")
plt.show()
```
▶ What you'll see: the evidence at Z favors `Y=1` because the second message entry is larger.

*Why it's done this way:* the sum removes $Z$ because a marginal belief about $Y$ should not commit to a single hidden $Z$ value. Multiplying by evidence before summing weights each hidden $Z$ state by how compatible it is with what was observed.

### 3. Variable-to-factor messages multiply incoming information except the recipient

A variable-to-factor message is a product of all information arriving at that variable except the factor being addressed. In the left-to-right message from $X$ through $\psi_{XY}$ toward $Y$, $X$ has only its prior, so the contribution to $Y$ is

$$m_{XY\to Y}(y)=\sum_x p(x)\psi_{XY}(x,y).$$

```python
left_terms_w = pX_w[:, None] * psiXY_w  # each X row weighted by the prior p(X=x).
print("left-side terms:\n", np.round(left_terms_w, 3))
```
▶ What you'll see: rows from the X-Y factor are weighted by how plausible each X state is.

```python
m_left_w = left_terms_w.sum(axis=0)
print("m_{XY->Y}:", np.round(m_left_w, 3))
assert np.allclose(np.round(m_left_w, 3), [0.620, 0.380])
```
▶ What you'll see: `[0.6,0.4] @ psiXY = [0.620, 0.380]`, so the left side favors `Y=0`.

```python
plt.figure(figsize=(4, 3))
plt.bar(["Y=0", "Y=1"], m_left_w, color="seagreen")
plt.title("3: left message into Y")
plt.ylabel("message score")
plt.show()
```
▶ What you'll see: the left evidence pulls toward `Y=0`, opposite the right evidence from Z.

*Why it's done this way:* when a message returns to a neighbor, it must exclude that neighbor's incoming message or the same evidence would be counted twice. On a tree, this “all information except the recipient” rule is exactly what separates the graph into independent sides.

### 4. A belief is a normalized product of incoming messages

Once all neighboring messages arrive at a variable, its unnormalized belief is the product of those messages. For $Y$, the left side and right side are conditionally independent once $Y$ is fixed, so their scores multiply. Normalization then turns those local scores into probabilities that sum to one.

```python
belief_scores_w = m_left_w * m_right_w
print("belief scores:", np.round(belief_scores_w, 4))
assert np.allclose(np.round(belief_scores_w, 4), [0.2108, 0.2356])
```
▶ What you'll see: the two sides disagree slightly, producing close unnormalized scores for `Y=0` and `Y=1`.

```python
pY_w = belief_scores_w / belief_scores_w.sum()
print("normalized p(Y):", np.round(pY_w, 6))
print("p(Y=0):", round(float(pY_w[0]), 6))
assert round(float(pY_w[0]), 6) == 0.472222
```
▶ What you'll see: normalization gives `p(Y=0)=0.472222` and `p(Y=1)=0.527778`.

```python
plt.figure(figsize=(4, 3))
plt.bar(["Y=0", "Y=1"], pY_w, color="royalblue")
plt.axhline(0.5, color="black", linestyle="--", linewidth=1)
plt.title("4: normalized belief at Y")
plt.ylabel("probability")
plt.ylim(0, 1)
plt.show()
```
▶ What you'll see: the posterior slightly favors `Y=1`; look for both bars summing to one.

*Why it's done this way:* multiplication combines independent pieces of evidence that meet at $Y$; division by the total score is Bayes normalization. Without normalization, the numbers rank states correctly but are not usable probabilities.

### 5. Message passing caches repeated partial sums

The point of belief propagation is not that it changes the answer — it changes how much repeated work is needed. Once the right-side message $m_{YZ\to Y}$ has been computed, every query involving $Y$ can reuse it instead of re-summing over $Z$ from scratch.

```python
queries_w = ["p(Y)", "p(X,Y)", "score Y=0", "score Y=1"]
work_brute_w = np.array([4, 4, 2, 2])  # tiny counts of YZ multiplications if each query recomputes Z.
work_cached_w = np.array([2, 0, 0, 0])  # compute m_{YZ->Y} once, then reuse it.
print("brute work units:", work_brute_w.sum())
print("cached work units:", work_cached_w.sum())
assert int(work_brute_w.sum()) == 12 and int(work_cached_w.sum()) == 2
```
▶ What you'll see: caching replaces repeated right-side summations with one reusable vector.

```python
x_w = np.arange(len(queries_w))
plt.figure(figsize=(5, 3))
plt.bar(x_w - 0.18, work_brute_w, width=0.36, label="recompute", color="crimson")
plt.bar(x_w + 0.18, work_cached_w, width=0.36, label="cached message", color="seagreen")
plt.xticks(x_w, queries_w, rotation=15)
plt.ylabel("toy work units")
plt.title("5: one message reused across queries")
plt.legend()
plt.show()
```
▶ What you'll see: nearly all repeated work disappears after the first cached message is available.

*Why it's done this way:* dynamic programming works because a tree edge separates the graph into two parts. A message is the complete summary of one side as seen from the boundary variable, so downstream computations do not need the original side again.

### 6. Max-product swaps sums for maxima to find MAP states

Sum-product computes marginal probabilities by summing over hidden states. Max-product computes a most likely assignment by replacing each sum with a maximum and keeping backpointers. For the same right factor, the max message is

$$\mu_{YZ\to Y}(y)=\max_z \psi_{YZ}(y,z)e_Z(z).$$

```python
max_terms_w = psiYZ_w * eZ_w[None, :]
mu_right_w = max_terms_w.max(axis=1)
bp_right_w = max_terms_w.argmax(axis=1)
print("max-product right message:", np.round(mu_right_w, 3))
print("best Z for each Y:", bp_right_w)
assert np.allclose(np.round(mu_right_w, 3), [0.270, 0.560])
```
▶ What you'll see: each Y value keeps only its best supporting Z state, not an average over Z.

```python
max_left_terms_w = pX_w[:, None] * psiXY_w
mu_left_w = max_left_terms_w.max(axis=0)
bp_left_w = max_left_terms_w.argmax(axis=0)
map_scores_w = mu_left_w * mu_right_w
best_y_w = int(np.argmax(map_scores_w))
print("max scores at Y:", np.round(map_scores_w, 4))
print("MAP Y:", best_y_w, "best X:", int(bp_left_w[best_y_w]), "best Z:", int(bp_right_w[best_y_w]))
assert best_y_w == 1
```
▶ What you'll see: the single best joint assignment favors `Y=1` here, matching the larger max-product score.

```python
plt.figure(figsize=(4, 3))
plt.bar(["Y=0", "Y=1"], map_scores_w, color="purple")
plt.title("6: max-product scores at Y")
plt.ylabel("best joint score")
plt.show()
```
▶ What you'll see: bars are MAP scores, not probabilities; they are for choosing a path or assignment.

*Why it's done this way:* marginal inference asks “how much total probability mass supports this state?”, so it sums. MAP asks “what is the single best explanation?”, so it maximizes and records which hidden state achieved the maximum.

### 7. Trees are exact; loops are approximate

On a tree, an edge separates independent subproblems, so messages are exact summaries. In a loopy graph, information can circle back and be counted again. Loopy belief propagation often works well, but the same update equations become an iterative approximation rather than guaranteed exact marginalization.

```python
loop_msgs_w = np.ones((3, 2))  # three variable beliefs/messages in a triangle, initialized uniformly.
edge_w = np.array([[0.9, 0.1], [0.1, 0.9]])  # factor encouraging neighboring variables to agree.
evidence_w = np.array([[0.9, 0.1], [0.55, 0.45], [0.1, 0.9]])  # local evidence at three nodes.
print("initial messages:\n", loop_msgs_w)
```
▶ What you'll see: the loopy demo starts with neutral messages before local evidence circulates.

```python
history_w = []
beliefs_loop_w = evidence_w.copy()
for it_w in range(8):
    new_beliefs_w = evidence_w.copy()
    for i_w in range(3):
        left_w = (i_w - 1) % 3
        right_w = (i_w + 1) % 3
        msg_left_w = edge_w.T @ beliefs_loop_w[left_w]
        msg_right_w = edge_w.T @ beliefs_loop_w[right_w]
        new_beliefs_w[i_w] *= msg_left_w * msg_right_w
        new_beliefs_w[i_w] /= new_beliefs_w[i_w].sum()
    beliefs_loop_w = new_beliefs_w
    history_w.append(beliefs_loop_w[:, 1].copy())
print("final loopy beliefs p(state=1):", np.round(history_w[-1], 3))
assert np.all((beliefs_loop_w > 0) & (beliefs_loop_w < 1))
```
▶ What you'll see: beliefs move over iterations and settle to plausible, not guaranteed-exact, values.

```python
plt.figure(figsize=(5, 3))
plt.plot(np.array(history_w), marker="o")
plt.title("7: loopy BP iterates beliefs")
plt.xlabel("iteration")
plt.ylabel("belief in state 1")
plt.legend(["node 0", "node 1", "node 2"])
plt.show()
```
▶ What you'll see: look for convergence rather than one exact inward/outward pass.

*Why it's done this way:* the same local update rule is attractive because it only needs neighboring messages, but the proof of exactness used a tree cut. Cycles break that proof, so iteration becomes a heuristic approximation whose convergence should be checked.

### ✍️ Toy 1 · Factorized tables match a brute-force marginal

A chain model stores local tables, but brute force can still expand all assignments and sum out the
variables we do not ask about.

```python
import numpy as np                              # arrays for tiny message tables.
import matplotlib.pyplot as plt                 # one picture per toy.

t1_rng = np.random.default_rng(0)               # seeded local generator.
t1_pa = np.array([0.5, 0.5])                    # prior over A  # -> [0.5, 0.5]
t1_ab = np.array([[2.0, 1.0],                   # compatibility A-B
                  [1.0, 3.0]])                  # -> [[2.0, 1.0], [1.0, 3.0]]
t1_bc = np.array([[1.0, 2.0],                   # compatibility B-C
                  [2.0, 1.0]])                  # -> [[1.0, 2.0], [2.0, 1.0]]
t1_ec = np.array([1.0, 2.0])                    # evidence on C  # -> [1.0, 2.0]
print("p(A):", t1_pa.tolist())                  # -> [0.5, 0.5]
print("A-B factor:\n", t1_ab)                   # -> [[2. 1.], [1. 3.]]
print("B-C factor:\n", t1_bc)                   # -> [[1. 2.], [2. 1.]]
print("C evidence:", t1_ec.tolist())            # -> [1.0, 2.0]
t1_joint = t1_pa[:, None, None] * t1_ab[:, :, None] * t1_bc[None, :, :] * t1_ec[None, None, :]  # -> shape (2, 2, 2)
print("joint scores flat:", t1_joint.reshape(-1).tolist())  # -> [1.0, 4.0, 1.0, 1.0, 0.5, 2.0, 3.0, 3.0]
t1_b_scores = t1_joint.sum(axis=(0, 2))          # sum out A and C  # -> [7.5, 8.0]
print("B scores:", t1_b_scores.tolist())         # -> [7.5, 8.0]
t1_pb = t1_b_scores / t1_b_scores.sum()          # normalize B marginal  # -> [0.484, 0.516]
print("p(B):", np.round(t1_pb, 3).tolist())       # -> [0.484, 0.516]
assert t1_joint.shape == (2, 2, 2) and np.allclose(t1_b_scores, [7.5, 8.0])

plt.figure(figsize=(4.6, 2.8))
plt.imshow(t1_joint.reshape(2, 4), cmap="viridis", aspect="auto")
plt.colorbar(label="joint score")
plt.xlabel("flattened (B,C)")
plt.ylabel("A")
plt.title("Toy 1 · brute-force joint")
plt.show()
```
▶ What you'll see: all 8 assignments exist in the brute-force table before `A` and `C` are summed away.

### ✍️ Toy 2 · Factor-to-variable messages sum away the neighbor

A factor-to-variable message keeps the recipient states and sums across the hidden neighbor states.

```python
import numpy as np                              # repeat import so the toy is self-contained.

t2_rng = np.random.default_rng(0)               # seeded local generator.
t2_yz = np.array([[1.0, 4.0, 2.0],              # rows Y, columns Z
                  [3.0, 1.0, 2.0]])             # -> [[1.0, 4.0, 2.0], [3.0, 1.0, 2.0]]
t2_ez = np.array([0.5, 1.0, 2.0])               # evidence over Z  # -> [0.5, 1.0, 2.0]
print("Y-Z factor:\n", t2_yz)                   # -> [[1. 4. 2.], [3. 1. 2.]]
print("Z evidence:", t2_ez.tolist())            # -> [0.5, 1.0, 2.0]
t2_terms = t2_yz * t2_ez[None, :]               # weight each Z column  # -> [[0.5, 4.0, 4.0], [1.5, 1.0, 4.0]]
print("weighted terms:", t2_terms.tolist())     # -> [[0.5, 4.0, 4.0], [1.5, 1.0, 4.0]]
t2_msg_to_y = t2_terms.sum(axis=1)              # sum out Z  # -> [8.5, 6.5]
print("message to Y:", t2_msg_to_y.tolist())    # -> [8.5, 6.5]
assert np.allclose(t2_msg_to_y, [8.5, 6.5])

plt.figure(figsize=(4.2, 2.8))
plt.bar(["Y=0", "Y=1"], t2_msg_to_y, color="darkorange")
plt.ylabel("message score")
plt.title("Toy 2 · sum-product message")
plt.show()
```
▶ What you'll see: `Y=0` gets the larger message because its row has more support after Z evidence.

### ✍️ Toy 3 · Variable-to-factor messages exclude the recipient

When a variable sends a message back to a factor, it multiplies all other incoming information but
leaves out the factor it is addressing.

```python
import numpy as np                              # repeat import so the toy is self-contained.

t3_rng = np.random.default_rng(0)               # seeded local generator.
t3_local_y = np.array([1.0, 2.0])               # local evidence at Y  # -> [1.0, 2.0]
t3_left_msg = np.array([3.0, 1.0])              # incoming message from the left  # -> [3.0, 1.0]
t3_right_msg = np.array([0.5, 4.0])             # incoming message from the right  # -> [0.5, 4.0]
print("local Y:", t3_local_y.tolist())          # -> [1.0, 2.0]
print("left message:", t3_left_msg.tolist())    # -> [3.0, 1.0]
print("right message:", t3_right_msg.tolist())  # -> [0.5, 4.0]
t3_msg_to_right = t3_local_y * t3_left_msg      # exclude the right recipient  # -> [3.0, 2.0]
print("message sent to right:", t3_msg_to_right.tolist())    # -> [3.0, 2.0]
t3_echo_wrong = t3_local_y * t3_left_msg * t3_right_msg       # double-counts right evidence  # -> [1.5, 8.0]
print("wrong echoed product:", t3_echo_wrong.tolist())        # -> [1.5, 8.0]
assert np.allclose(t3_msg_to_right, [3.0, 2.0]) and not np.allclose(t3_msg_to_right, t3_echo_wrong)

plt.figure(figsize=(4.6, 2.8))
plt.bar(["send Y=0", "send Y=1"], t3_msg_to_right, color="seagreen", label="correct")
plt.plot(["send Y=0", "send Y=1"], t3_echo_wrong, marker="o", color="crimson", label="echoed")
plt.ylabel("score")
plt.title("Toy 3 · exclude recipient message")
plt.legend()
plt.show()
```
▶ What you'll see: the red echoed product is very different because it counts the right evidence too soon.

### ✍️ Toy 4 · Beliefs normalize products of messages

A variable belief multiplies independent incoming messages, then divides by their total to become a
probability vector.

```python
import numpy as np                              # repeat import so the toy is self-contained.

t4_rng = np.random.default_rng(0)               # seeded local generator.
t4_left = np.array([2.0, 5.0])                  # left-side message  # -> [2.0, 5.0]
t4_right = np.array([3.0, 1.0])                 # right-side message  # -> [3.0, 1.0]
t4_unary = np.array([1.0, 2.0])                 # local unary factor  # -> [1.0, 2.0]
print("left message:", t4_left.tolist())        # -> [2.0, 5.0]
print("right message:", t4_right.tolist())      # -> [3.0, 1.0]
print("unary factor:", t4_unary.tolist())       # -> [1.0, 2.0]
t4_scores = t4_left * t4_right * t4_unary       # unnormalized belief  # -> [6.0, 10.0]
print("belief scores:", t4_scores.tolist())     # -> [6.0, 10.0]
t4_Z = float(t4_scores.sum())                   # local normalizer  # -> 16.0
print("belief Z:", t4_Z)                        # -> 16.0
t4_belief = t4_scores / t4_Z                    # normalized belief  # -> [0.375, 0.625]
print("belief:", t4_belief.tolist())            # -> [0.375, 0.625]
assert np.isclose(t4_belief.sum(), 1.0) and np.allclose(t4_belief, [0.375, 0.625])

plt.figure(figsize=(4.2, 2.8))
plt.bar(["Y=0", "Y=1"], t4_belief, color="royalblue")
plt.ylim(0, 1)
plt.ylabel("probability")
plt.title("Toy 4 · normalized belief")
plt.show()
```
▶ What you'll see: the belief favors `Y=1`, and the two bars sum to exactly one.

### ✍️ Toy 5 · Cached messages remove repeated work

Once a message is computed, later queries reuse that vector instead of resumming the same side of the
graph.

```python
import numpy as np                              # repeat import so the toy is self-contained.

t5_rng = np.random.default_rng(0)               # seeded local generator.
t5_queries = np.array(["pB", "pAB", "B0", "B1", "check", "plot"])  # six tiny queries  # -> ['pB', 'pAB', 'B0', 'B1', 'check', 'plot']
t5_recompute = np.array([6, 6, 3, 3, 6, 3])     # work units if each query resums  # -> [6, 6, 3, 3, 6, 3]
t5_cached = np.array([6, 0, 0, 0, 0, 0])        # compute once, reuse later  # -> [6, 0, 0, 0, 0, 0]
print("queries:", t5_queries.tolist())          # -> ['pB', 'pAB', 'B0', 'B1', 'check', 'plot']
print("recompute work:", t5_recompute.tolist()) # -> [6, 6, 3, 3, 6, 3]
print("cached work:", t5_cached.tolist())       # -> [6, 0, 0, 0, 0, 0]
t5_saved = t5_recompute - t5_cached             # saved work per query  # -> [0, 6, 3, 3, 6, 3]
print("saved work:", t5_saved.tolist())         # -> [0, 6, 3, 3, 6, 3]
t5_totals = np.array([t5_recompute.sum(), t5_cached.sum()])  # total work  # -> [27, 6]
print("total work [recompute, cached]:", t5_totals.tolist()) # -> [27, 6]
assert t5_totals.tolist() == [27, 6]

plt.figure(figsize=(5.2, 2.8))
plt.bar(np.arange(6) - 0.18, t5_recompute, width=0.36, label="recompute", color="crimson")
plt.bar(np.arange(6) + 0.18, t5_cached, width=0.36, label="cached", color="seagreen")
plt.xticks(np.arange(6), t5_queries, rotation=15)
plt.ylabel("work units")
plt.title("Toy 5 · one message reused")
plt.legend()
plt.show()
```
▶ What you'll see: after the first cached message, the remaining query bars drop to zero work.

### ✍️ Toy 6 · Max-product keeps winners and backpointers

Max-product replaces sums with maxima and records which hidden state achieved each maximum.

```python
import numpy as np                              # repeat import so the toy is self-contained.

t6_rng = np.random.default_rng(0)               # seeded local generator.
t6_yz = np.array([[1.0, 3.0, 2.0],              # rows Y, columns Z
                  [2.0, 1.0, 4.0]])             # -> [[1.0, 3.0, 2.0], [2.0, 1.0, 4.0]]
t6_ez = np.array([2.0, 1.0, 0.5])               # evidence over Z  # -> [2.0, 1.0, 0.5]
t6_left_max = np.array([2.0, 1.0])              # best left-side support for each Y  # -> [2.0, 1.0]
```

### ✍️ Toy 7 · Loopy BP iterates toward a fixed point

On a loop, the same local update is run repeatedly; convergence is something we monitor, not a tree
exactness guarantee.

```python
import numpy as np                              # repeat import so the toy is self-contained.

t7_rng = np.random.default_rng(0)               # seeded local generator.
t7_edge = np.array([[0.8, 0.2],                 # neighbors prefer matching states
                    [0.2, 0.8]])                # -> [[0.8, 0.2], [0.2, 0.8]]
t7_evidence = np.array([[0.8, 0.2],             # three nodes in a triangle
                        [0.5, 0.5],
                        [0.2, 0.8]])            # -> [[0.8, 0.2], [0.5, 0.5], [0.2, 0.8]]
print("edge factor:\n", t7_edge)                # -> [[0.8 0.2], [0.2 0.8]]
print("local evidence:\n", t7_evidence)         # -> [[0.8 0.2], [0.5 0.5], [0.2 0.8]]
t7_beliefs = t7_evidence / t7_evidence.sum(axis=1, keepdims=True)  # initial normalized beliefs  # -> [[0.8, 0.2], [0.5, 0.5], [0.2, 0.8]]
print("initial p(state=1):", np.round(t7_beliefs[:, 1], 3).tolist())  # -> [0.2, 0.5, 0.8]
t7_history = []                                 # store p(state=1) after each iteration  # -> []
for t7_step in range(4):
    t7_new = t7_evidence.copy()
    for t7_i in range(3):
        t7_left = (t7_i - 1) % 3
        t7_right = (t7_i + 1) % 3
        t7_msg_left = t7_edge @ t7_beliefs[t7_left]
        t7_msg_right = t7_edge @ t7_beliefs[t7_right]
        t7_new[t7_i] = t7_new[t7_i] * t7_msg_left * t7_msg_right
        t7_new[t7_i] = t7_new[t7_i] / t7_new[t7_i].sum()
    t7_beliefs = t7_new
    t7_history.append(t7_beliefs[:, 1].copy())
    print(f"iteration {t7_step + 1} p(state=1):", np.round(t7_history[-1], 3).tolist())  # -> [0.347, 0.5, 0.653], [0.266, 0.5, 0.734], [0.308, 0.5, 0.692], [0.286, 0.5, 0.714]
t7_history = np.array(t7_history)               # four iterations by three nodes  # -> shape (4, 3)
print("history shape:", t7_history.shape)       # -> (4, 3)
assert np.allclose(np.round(t7_history[-1], 3), [0.286, 0.5, 0.714])

plt.figure(figsize=(4.8, 2.8))
plt.plot(t7_history, marker="o")
plt.xlabel("iteration")
plt.ylabel("belief in state 1")
plt.title("Toy 7 · loopy updates move beliefs")
plt.legend(["node 0", "node 1", "node 2"])
plt.show()
```
▶ What you'll see: the three belief traces wiggle and begin settling, illustrating approximate loopy updates.

```python
import numpy as np # load NumPy for arrays, normalizing tables, message updates, and assertions.
import matplotlib.pyplot as plt # load Matplotlib for heatmaps, bars, curves, and small debugging visuals.
np.random.seed(0) # make every example reproducible.

def normalize(v): # convert a nonnegative score vector into probabilities.
    v = np.asarray(v, dtype=float) # ensure numeric array behavior.
    total = float(np.sum(v)) # compute the normalizing constant.
    return v / total if total > 0 else np.ones_like(v) / len(v) # fall back to uniform if all scores vanish.

    plt.show() # render the figure.
```

### Advanced 1 — Vectorize all messages in a chain

**Goal.** Compute forward and backward messages for every position in a binary chain, because longer trees need the same local recursions repeated efficiently. We build it in 4 steps.

```python
T_a1 = np.array([[0.85, 0.15], [0.25, 0.75]]) # pairwise compatibility between neighboring states.
evidence_a1 = np.array([[0.9, 0.1], [0.6, 0.4], [0.4, 0.6], [0.2, 0.8]]) # unary likelihoods at four nodes.
prior_a1 = np.array([0.5, 0.5]) # prior for the first node.
print("chain length:", len(evidence_a1))
```
▶ What you'll see: four positions, each with local evidence for two states.

```python
forward_a1 = np.zeros_like(evidence_a1)
forward_a1[0] = normalize(prior_a1 * evidence_a1[0])
for t_a1 in range(1, len(evidence_a1)):
    forward_a1[t_a1] = normalize(evidence_a1[t_a1] * (forward_a1[t_a1 - 1] @ T_a1))
print("forward beliefs:\n", np.round(forward_a1, 3))
assert np.allclose(forward_a1.sum(axis=1), 1.0)
```
▶ What you'll see: forward messages summarize evidence from the left up to each position.

```python
backward_a1 = np.ones_like(evidence_a1)
for t_a1 in range(len(evidence_a1) - 2, -1, -1):
    backward_a1[t_a1] = normalize(T_a1 @ (evidence_a1[t_a1 + 1] * backward_a1[t_a1 + 1]))
smoothed_a1 = np.array([normalize(forward_a1[t] * backward_a1[t]) for t in range(len(evidence_a1))])
print("smoothed beliefs:\n", np.round(smoothed_a1, 3))
assert np.allclose(smoothed_a1.sum(axis=1), 1.0)
```
▶ What you'll see: each smoothed belief uses evidence from both directions.

```python
plt.figure(figsize=(5, 3))
plt.plot(forward_a1[:, 1], marker="o", label="forward p(1)")
plt.plot(smoothed_a1[:, 1], marker="s", label="smoothed p(1)")
plt.title("Advanced 1: forward vs smoothed beliefs")
plt.xlabel("position")
plt.ylabel("probability of state 1")
plt.legend()
plt.show()
```
▶ What you'll see: right-side evidence can revise earlier beliefs after the backward pass.

👀 Takeaway: chain BP is forward-backward: two directional passes produce exact smoothed marginals.

### Advanced 2 — Track normalization constants for likelihood

**Goal.** Keep scaling factors during forward messages, because normalizing prevents underflow but the discarded constants contain the sequence likelihood. We build it in 4 steps.

```python
T_a2 = np.array([[0.85, 0.15], [0.25, 0.75]])
evidence_a2 = np.array([[0.9, 0.1], [0.6, 0.4], [0.4, 0.6], [0.2, 0.8]])
prior_a2 = np.array([0.5, 0.5])
alpha_raw_a2 = prior_a2 * evidence_a2[0]
scale0_a2 = alpha_raw_a2.sum()
alpha_a2 = alpha_raw_a2 / scale0_a2
scales_a2 = [scale0_a2]
print("first scale:", round(float(scale0_a2), 4), "alpha:", np.round(alpha_a2, 3))
```
▶ What you'll see: the first normalization constant is the probability of the first evidence item.

```python
for t_a2 in range(1, len(evidence_a2)):
    raw_a2 = evidence_a2[t_a2] * (alpha_a2 @ T_a2)
    scale_a2 = raw_a2.sum()
    alpha_a2 = raw_a2 / scale_a2
    scales_a2.append(scale_a2)
print("scales:", np.round(scales_a2, 6))
likelihood_scaled_a2 = float(np.prod(scales_a2))
print("likelihood from scales:", round(likelihood_scaled_a2, 6))
```
▶ What you'll see: each scale is small, and their product recovers the evidence likelihood.

```python
joint_like_a2 = 0.0
for x0_a2 in range(2):
    for x1_a2 in range(2):
        for x2_a2 in range(2):
            for x3_a2 in range(2):
                xs_a2 = [x0_a2, x1_a2, x2_a2, x3_a2]
                score_a2 = prior_a2[xs_a2[0]] * evidence_a2[0, xs_a2[0]]
                for t_a2 in range(1, 4):
                    score_a2 *= T_a2[xs_a2[t_a2 - 1], xs_a2[t_a2]] * evidence_a2[t_a2, xs_a2[t_a2]]
                joint_like_a2 += score_a2
print("brute likelihood:", round(float(joint_like_a2), 6))
assert np.isclose(likelihood_scaled_a2, joint_like_a2)
```
▶ What you'll see: the scale-product likelihood matches the brute-force sum over 16 paths.

```python
plt.figure(figsize=(5, 3))
plt.bar([f"c{t}" for t in range(len(scales_a2))], scales_a2, color="slateblue")
plt.title("Advanced 2: forward scaling constants")
plt.ylabel("normalizer")
plt.show()
```
▶ What you'll see: every local normalizer is a piece of the total evidence probability.

👀 Takeaway: scaled messages are numerically stable, but their scale factors must be saved when likelihood matters.

### Advanced 3 — Show loopy BP convergence diagnostics

**Goal.** Iterate BP on a triangle and plot the maximum belief change, because loopy graphs need convergence checks rather than one guaranteed exact pass. We build it in 4 steps.

```python
edge_a3 = np.array([[0.9, 0.1], [0.1, 0.9]]) # neighboring variables prefer to agree.
evidence_a3 = np.array([[0.85, 0.15], [0.55, 0.45], [0.2, 0.8]]) # local evidence around a triangle.
belief_a3 = evidence_a3.copy() # start from row-normalized local evidence.
print("initial beliefs:\n", np.round(belief_a3, 3))
```
▶ What you'll see: different nodes begin with different local preferences.

```python
changes_a3 = []
hist_a3 = []
for it_a3 in range(15):
    new_a3 = evidence_a3.copy()
    for i_a3 in range(3):
        n1_a3 = (i_a3 - 1) % 3
        n2_a3 = (i_a3 + 1) % 3
        new_a3[i_a3] *= (edge_a3.T @ belief_a3[n1_a3]) * (edge_a3.T @ belief_a3[n2_a3])
        new_a3[i_a3] = normalize(new_a3[i_a3])

```
▶ What you'll see: updates shrink as the loopy iteration settles.
