# 23.2 — Sequential Games

Sequential games add time to strategic choice. Instead of choosing once from a payoff table, players move through a tree, watch histories, form beliefs, and choose continuation plans that must still make sense when their turn actually arrives. The key habit is: solve the future first, then propagate credible values backward.

## 📖 Concept walkthrough — build each idea from scratch

Before the worked examples, we build extensive-form games one idea at a time. Run the cells in order: every tree is represented with small nested Python structures, every solution is computed from scratch, and every subsection includes a relevant game-tree visualization.

```python
import numpy as np  # arrays and simple expected-value arithmetic.
import matplotlib.pyplot as plt  # all tree, value, information-set, and path visualizations.
np.random.seed(0)  # reproducibility for any small randomized display choices.

def draw_tree_w(nodes, edges, payoffs=None, title="", highlights=(), infosets=()):
    payoffs = payoffs or {}
    highlights = set(highlights)
    plt.figure(figsize=(6.2, 3.8))
    ax = plt.gca()
    for group in infosets:
        xs = [nodes[n][0] for n in group]
        ys = [nodes[n][1] for n in group]
        ax.plot(xs, ys, linestyle="--", color="purple", linewidth=2, alpha=0.8)
    for parent, child, action in edges:
        x1, y1, _ = nodes[parent]
        x2, y2, _ = nodes[child]
        color = "crimson" if (parent, child) in highlights else "gray"
        lw = 3 if (parent, child) in highlights else 1.4
        ax.annotate("", xy=(x2, y2), xytext=(x1, y1), arrowprops=dict(arrowstyle="->", lw=lw, color=color))
        ax.text((x1 + x2) / 2, (y1 + y2) / 2 + 0.08, action, ha="center", fontsize=9, color=color)
    for name, (x, y, label) in nodes.items():
        ax.scatter([x], [y], s=260, color="white", edgecolor="black", zorder=3)
        extra = "\n" + str(payoffs[name]) if name in payoffs else ""
        ax.text(x, y, label + extra, ha="center", va="center", fontsize=9, zorder=4)
    ax.set_title(title)
    ax.set_xlim(-0.7, 4.7)
    ax.set_ylim(-1.9, 1.9)
    ax.axis("off")
    # The caller ends each visualization with plt.show().

def terminal(value):
    return {"payoff": tuple(value)}

def backward_value(tree):
    if "payoff" in tree:
        return tree["payoff"], []
    player = tree["player"]
    best_action, best_value, best_path = None, None, None
    for action, child in tree["actions"].items():
        value, path = backward_value(child)
        if best_value is None or value[player] > best_value[player]:
            best_action, best_value, best_path = action, value, path
    return best_value, [(player, best_action, best_value)] + best_path
```

### 1. Extensive-form games: actions unfold as a tree

A normal-form game lists simultaneous strategies in a table. An extensive-form game instead lays out histories: who moves, which action branches are available, and which terminal payoff appears at each leaf. The tree is the data structure because time matters.

```python
nodes_w1 = {"E": (0, 0, "Entrant"), "O": (2, 1, "Out"), "I": (2, -1, "Incumbent"), "F": (4, -1.4, "Fight"), "A": (4, -0.4, "Accommodate")}
edges_w1 = [("E", "O", "Out"), ("E", "I", "Enter"), ("I", "F", "Fight"), ("I", "A", "Accommodate")]
payoffs_w1 = {"O": (0, 2), "F": (-1, -1), "A": (2, 1)}
print("terminal payoffs:", payoffs_w1)
draw_tree_w(nodes_w1, edges_w1, payoffs_w1, "1: entry game as an extensive-form tree")
plt.show()
```
▶ What you'll see: the entrant moves first; only after Enter does the incumbent choose Fight or Accommodate.

*Why it's done this way:* a tree stores the order of decisions, so later choices can be solved before earlier choices.

### 2. A strategy is a complete contingent plan

In a tree, a strategy is not just the action observed on the final path. It must say what the player would do at every node they might control, including nodes that are not reached. This is why off-path threats can matter—and why we later test their credibility.

```python
entrant_strategy_w2 = {"Entrant@root": "Enter"}
incumbent_strategy_w2 = {"Incumbent@if_entered": "Fight"}
print("entrant plan:", entrant_strategy_w2)
print("incumbent contingent plan:", incumbent_strategy_w2)
highlights_w2 = {("E", "I"), ("I", "F")}
draw_tree_w(nodes_w1, edges_w1, payoffs_w1, "2: a full plan includes the later threat", highlights_w2)
plt.show()
```
▶ What you'll see: the highlighted plan says Enter then Fight, even though Fight may later prove irrational.

*Why it's done this way:* equilibrium in a sequential game checks plans after histories, not only the realized first move.

### 3. Backward induction solves the future first

Backward induction starts at the last decision. At the incumbent node, Fight gives the incumbent −1 and Accommodate gives 1, so Accommodate is chosen. The entrant then compares Out payoff 0 with Enter-then-Accommodate payoff 2.

```python
game_w3 = {"player": 0, "actions": {"Out": terminal((0, 2)), "Enter": {"player": 1, "actions": {"Fight": terminal((-1, -1)), "Accommodate": terminal((2, 1))}}}}
value_w3, path_w3 = backward_value(game_w3)
print("backward-induction value:", value_w3)
print("chosen actions:", path_w3)
assert value_w3 == (2, 1)
draw_tree_w(nodes_w1, edges_w1, payoffs_w1, "3: backward-induction path", {("E", "I"), ("I", "A")})
plt.show()
```
▶ What you'll see: the red path is Enter → Accommodate, yielding payoff `(2, 1)`.

*Why it's done this way:* replacing a solved subgame by its value is dynamic programming on a game tree.

### 4. Subgame perfection removes non-credible threats

A Nash equilibrium in the normal form can contain a threat like “I will Fight if you Enter.” Subgame perfection asks whether the player would still choose that action inside the subgame. Since Fight hurts the incumbent compared with Accommodate, the threat is not credible.

```python
inc_payoffs_w4 = np.array([-1, 1])
actions_w4 = ["Fight", "Accommodate"]
best_w4 = actions_w4[int(np.argmax(inc_payoffs_w4))]
print("incumbent continuation payoffs:", dict(zip(actions_w4, inc_payoffs_w4)))
print("credible continuation action:", best_w4)
assert best_w4 == "Accommodate"
plt.figure(figsize=(5, 3))
plt.bar(actions_w4, inc_payoffs_w4, color=["crimson", "seagreen"])
plt.axhline(0, color="black", linewidth=0.8)
plt.title("4: the off-path Fight threat is not credible")
plt.ylabel("incumbent continuation payoff")
plt.show()
```
▶ What you'll see: Accommodate is strictly better for the incumbent than Fight at the reached subgame.

*Why it's done this way:* subgame perfection requires optimality after every possible history, so irrational punishments cannot support the solution.

### 5. Beliefs and information sets

Sometimes a player moves without knowing exactly which node they are at. An information set groups such indistinguishable nodes and forces the same action across them. The local decision becomes a belief-weighted expected payoff rather than a separate maximum at each node.

```python
nodes_w5 = {"C": (0, 0, "Chance"), "A": (2, 0.8, "P2 at A"), "B": (2, -0.8, "P2 at B"), "AL": (4, 1.2, "L"), "AR": (4, 0.4, "R"), "BL": (4, -0.4, "L"), "BR": (4, -1.2, "R")}
edges_w5 = [("C", "A", "A 0.6"), ("C", "B", "B 0.4"), ("A", "AL", "Left"), ("A", "AR", "Right"), ("B", "BL", "Left"), ("B", "BR", "Right")]
payoffs_w5 = {"AL": 3, "AR": 1, "BL": 0, "BR": 2}
left_w5 = 0.6 * 3 + 0.4 * 0
right_w5 = 0.6 * 1 + 0.4 * 2
print("EV Left:", left_w5, "EV Right:", right_w5)
assert round(left_w5, 3) == 1.8 and round(right_w5, 3) == 1.4
draw_tree_w(nodes_w5, edges_w5, payoffs_w5, "5: one information set, one action", infosets=[["A", "B"]])
plt.show()
```
▶ What you'll see: the dashed purple line marks that P2 cannot distinguish A from B.

*Why it's done this way:* the player cannot condition on hidden node identity, so beliefs turn payoffs into expected values.

### 6. Credibility can be summarized as a continuation probability

If the entrant believes Accommodate will occur with probability `p`, then the value of Enter is `2p + 0(1-p) = 2p` in this simplified credibility model. The first move changes when that expected continuation beats Out.

```python
p_grid_w6 = np.linspace(0, 1, 101)
enter_value_w6 = 2 * p_grid_w6
out_value_w6 = np.zeros_like(p_grid_w6)
print("entry value at p=0.5:", float(2 * 0.5))
assert float(2 * 0.5) == 1.0
plt.figure(figsize=(5, 3))
plt.plot(p_grid_w6, enter_value_w6, label="V(Enter)=2p", color="seagreen")
plt.plot(p_grid_w6, out_value_w6, label="V(Out)=0", color="gray")
plt.title("6: beliefs about future play affect entry")
plt.xlabel("Pr(Accommodate)")
plt.ylabel("entrant expected payoff")
plt.legend()
plt.show()
```
▶ What you'll see: any positive credible chance of accommodation makes Enter better than Out in this payoff setup.

*Why it's done this way:* sequential games price future beliefs at the current decision node.

### 7. Sequential logic links to algorithms

Backward induction is dynamic programming on a finite tree: compute terminal values, choose optimal children at predecessor nodes, and propagate the selected payoff upward. Larger stochastic games and counterfactual-regret algorithms reuse the same “continuation value” idea.

```python
depths_w7 = np.array([2, 1, 0])
labels_w7 = ["terminal payoffs", "incumbent value", "entrant value"]
values_w7 = np.array([1, 1, 2])
print("solving order:", labels_w7)
plt.figure(figsize=(5.5, 3))
plt.plot(depths_w7, values_w7, marker="o", color="purple")
for x_w7, y_w7, lab_w7 in zip(depths_w7, values_w7, labels_w7):
    plt.text(x_w7, y_w7 + 0.08, lab_w7, ha="center")
plt.gca().invert_xaxis()
plt.title("7: continuation values propagate backward")
plt.xlabel("distance from root")
plt.ylabel("selected continuation payoff component")
plt.show()
```
▶ What you'll see: values are computed at the leaves first, then pushed back toward the root.

*Why it's done this way:* once a continuation is solved, earlier decisions can treat it as a single number.

## 🛠️ Setup

```python
import numpy as np  # numeric arrays, payoff vectors, expectations, and assertions.
import matplotlib.pyplot as plt  # every example uses a relevant extensive-form visualization.
np.random.seed(0)  # keep demonstrations reproducible.

def T(payoff):  # create a terminal leaf for nested game trees.
    return {"payoff": tuple(payoff)}

def solve_tree(tree):  # backward induction for perfect-information finite games.
    if "payoff" in tree:
        return tree["payoff"], []
    player = tree["player"]
    chosen = None
    for action, child in tree["actions"].items():
        value, path = solve_tree(child)
        if chosen is None or value[player] > chosen[1][player]:
            chosen = (action, value, path)
    action, value, path = chosen
    return value, [(player, action, value)] + path

def draw_tree(nodes, edges, payoffs=None, title="", highlights=(), infosets=()):
    payoffs = payoffs or {}
    highlights = set(highlights)
    plt.figure(figsize=(6, 3.8))
    ax = plt.gca()
    for group in infosets:
        ax.plot([nodes[n][0] for n in group], [nodes[n][1] for n in group], "--", color="purple", lw=2)
    for parent, child, action in edges:
        x1, y1, _ = nodes[parent]
        x2, y2, _ = nodes[child]
        marked = (parent, child) in highlights
        ax.annotate("", xy=(x2, y2), xytext=(x1, y1), arrowprops=dict(arrowstyle="->", lw=3 if marked else 1.3, color="crimson" if marked else "gray"))
        ax.text((x1 + x2) / 2, (y1 + y2) / 2 + 0.08, action, ha="center", fontsize=9, color="crimson" if marked else "black")
    for name, (x, y, label) in nodes.items():
        ax.scatter([x], [y], s=250, facecolor="white", edgecolor="black", zorder=3)
        ax.text(x, y, label + ("\n" + str(payoffs[name]) if name in payoffs else ""), ha="center", va="center", fontsize=9, zorder=4)
    ax.set_xlim(-0.7, 4.7)
    ax.set_ylim(-1.9, 1.9)
    ax.set_title(title)
    ax.axis("off")
    # The caller ends each visualization with plt.show().
```

#### B1. Draw a one-move extensive-form game

**Goal.** Represent a first mover choosing Out or Enter, because sequential games begin with histories rather than static payoff tables. We build it in 2 steps.

```python
nodes_b1 = {"E": (0, 0, "Entrant"), "O": (3, 1, "Out"), "N": (3, -1, "Enter")}
```

👀 Takeaway: an extensive-form game records who moves and what histories each action creates.

#### E3. Compare normal-form and subgame-perfect predictions

**Goal.** Show why sequential refinement matters, because normal-form reasoning can keep plans that fail at later nodes. We build it in 3 steps.


#### A5. Verify a subgame-perfect solution across subgames

**Goal.** Check every subgame's recommended action, because subgame perfection is a local optimality test at each decision node. We build it in 3 steps.

```python

checks_a5 = []
for name_a5, actions_a5 in subgames_a5.items():
    player_a5 = 1 if name_a5 == "incumbent_subgame" else 0
    best_a5 = max(actions_a5, key=lambda a: actions_a5[a][player_a5])
    checks_a5.append(best_a5 == recommended_a5[name_a5])
print("subgame checks:", checks_a5)
assert all(checks_a5)
plt.figure(figsize=(5, 3))

plt.ylim(0, 1.2)
plt.title("A5: every subgame passes optimality")
plt.ylabel("recommended action is best")
plt.show()
```
▶ What you'll see: both the incumbent subgame and the backed-up root decision pass their optimality checks.

👀 Takeaway: a subgame-perfect equilibrium is a Nash-style best-response check repeated at every subgame.
