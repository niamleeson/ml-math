# 6.27 — Neural ODEs

Neural ODEs replace a finite stack of discrete hidden layers with a learned continuous-time vector field, so a hidden state moves according to an ordinary differential equation instead of a fixed list of layer blocks. In this lesson, you will build the solvers, vector fields, gradients, and memory tradeoffs from scratch with NumPy so the method feels like numerical integration plus learning rather than magic.

This walkthrough is self-contained and uses a `_w` suffix on its variables so it never clashes with the examples below.

### 1. A hidden state can move continuously

A Neural ODE says that the hidden representation is not just `h0 -> h1 -> h2`; it is a curve `h(t)` whose velocity is chosen by a learned function. The core equation is

$$\frac{dh(t)}{dt}=f_\theta(h(t),t),\qquad h(t_1)=h(t_0)+\int_{t_0}^{t_1} f_\theta(h(t),t)\,dt.$$

Read it as a bookkeeping rule: the next hidden state equals the starting hidden state plus all tiny velocity contributions accumulated between `t0` and `t1`.

```python
h0_w = np.array([1.5, -0.5])  # a two-coordinate hidden state from the lesson prompt.
A_w = np.array([[0.0, 1.0], [-1.0, 0.0]])  # a simple rotation-like vector field matrix.
def f_linear_w(h_w, t_w):  # continuous velocity dh/dt = A h.
    return A_w @ h_w  # matrix-vector product gives the instantaneous direction.

v0_w = f_linear_w(h0_w, 0.0)  # evaluate the velocity at the starting state.
print("h(0):", h0_w)  # inspect the current hidden representation.
print("dh/dt at t=0:", v0_w)  # inspect the direction the ODE wants to move.
assert np.allclose(v0_w, [-0.5, -1.5])  # the matrix rotates [1.5,-0.5] clockwise.
```
▶ What you'll see: the state is `[1.5, -0.5]`, and its instantaneous velocity points to `[-0.5, -1.5]`.

```python
dt_w = 0.1  # a small time step for a first local approximation.
h1_euler_w = h0_w + dt_w * v0_w  # Euler's rule: state plus step-size times velocity.
print("one tiny Euler step:", np.round(h1_euler_w, 3))  # inspect h after Δt=0.1.
assert np.allclose(np.round(h1_euler_w, 3), [1.45, -0.65])  # visible arithmetic check.
```
▶ What you'll see: the state moves a little in the velocity direction, not all at once.

```python
plt.figure(figsize=(4, 3))  # create a compact phase-plane plot.
plt.quiver([h0_w[0]], [h0_w[1]], [v0_w[0]], [v0_w[1]], angles="xy", scale_units="xy", scale=1, color="crimson")  # draw velocity.
plt.scatter([h0_w[0], h1_euler_w[0]], [h0_w[1], h1_euler_w[1]], color=["black", "seagreen"])  # show before/after.
plt.text(h0_w[0], h0_w[1], " h0")  # label start.
plt.text(h1_euler_w[0], h1_euler_w[1], " h0+dt f")  # label first step.
plt.xlim(1.2, 1.65); plt.ylim(-0.8, -0.35); plt.grid(True, alpha=0.3)
plt.title("1: velocity moves the hidden state"); plt.xlabel("h[0]"); plt.ylabel("h[1]"); plt.show()
```
▶ What you'll see: an arrow from the current hidden state and a nearby green point reached by one small numerical step.

*Why it's done this way:* the integral is too hard to compute exactly for a learned nonlinear `fθ`, so we approximate it by many local linear moves. The derivative tells us the best first-order direction; the step size controls how much we trust that direction before rechecking the velocity.

### 2. Euler integration turns the ODE into inspectable layers

Euler's method repeats the update `h ← h + Δt f(h,t)`. That looks exactly like a residual layer with shared dynamics: keep the old representation, add a small learned change, then pass it on. Smaller `Δt` makes more careful approximations, but costs more function evaluations.

```python
def euler_solve_w(f_w, h_start_w, t0_w, t1_w, steps_w):  # fixed-step Euler integrator.
    h_w = h_start_w.astype(float).copy()  # avoid mutating the input state.
    ts_w = np.linspace(t0_w, t1_w, steps_w + 1)  # grid of times.
    path_w = [h_w.copy()]  # store every state for plotting and debugging.
    dt_local_w = (t1_w - t0_w) / steps_w  # step size.
    for k_w in range(steps_w):  # repeat small residual updates.
        h_w = h_w + dt_local_w * f_w(h_w, ts_w[k_w])  # h_{k+1}=h_k+dt f(h_k,t_k).
        path_w.append(h_w.copy())  # keep the state.
    return ts_w, np.array(path_w)  # return times and states.

ts4_w, path4_w = euler_solve_w(f_linear_w, h0_w, 0.0, 1.0, 4)  # coarse solve.
print("Euler states with 4 steps:\n", np.round(path4_w, 3))  # inspect the discrete trajectory.
```
▶ What you'll see: five states, because four Euler steps include the starting point and the final point.

```python
ts40_w, path40_w = euler_solve_w(f_linear_w, h0_w, 0.0, 1.0, 40)  # finer solve.
print("coarse final:", np.round(path4_w[-1], 3))  # less accurate final state.
print("fine final:", np.round(path40_w[-1], 3))  # more accurate final state.
assert path40_w.shape == (41, 2)  # 40 steps plus the initial state.
```
▶ What you'll see: the fine and coarse final states differ, because Euler error accumulates over the interval.

```python
plt.figure(figsize=(4, 3))  # compare coarse and fine paths.
plt.plot(path4_w[:, 0], path4_w[:, 1], "o--", label="4 Euler steps")  # coarse broken path.
plt.plot(path40_w[:, 0], path40_w[:, 1], "-", label="40 Euler steps")  # smoother path.
plt.scatter([h0_w[0]], [h0_w[1]], color="black", zorder=3, label="start")  # mark start.
plt.axis("equal"); plt.grid(True, alpha=0.3); plt.legend()
plt.title("2: Euler steps approximate a continuous curve"); plt.xlabel("h[0]"); plt.ylabel("h[1]"); plt.show()
```
▶ What you'll see: the 40-step path bends more smoothly; the 4-step path is visibly polygonal.

*Why it's done this way:* a Neural ODE layer is not one formula evaluation; it is a solver call. Euler exposes the solver as many residual updates, making clear that accuracy, runtime, and gradient behavior all depend on how the time interval is discretized.

### 3. A neural vector field shapes the derivative

The vector field `fθ` can be a tiny neural network. Here we build the lesson's scratch pass: an affine signal from `x=[1.5,-0.5]` with weights `[1.4,0.2]` and bias `0.6`, followed by a ReLU gate. This is the local mechanism that decides the velocity used by the ODE solver.

```python
x_w = np.array([1.5, -0.5])  # two-input scratch state.
w_gate_w = np.array([1.4, 0.2])  # visible affine weights.
b0_w = 0.6  # visible bias.
z_w = float(w_gate_w @ x_w + b0_w)  # affine signal.
gated_w = max(0.0, z_w)  # ReLU gate.
print("affine signal:", round(z_w, 3))  # 1.4*1.5 + 0.2*(-0.5) + 0.6.
print("gated signal:", round(gated_w, 3))  # max(0,z).
assert round(z_w, 3) == 2.6 and round(gated_w, 3) == 2.6  # lesson arithmetic.
```
▶ What you'll see: the affine value is `2.600`, and ReLU keeps it because it is positive.

```python
W1_w = np.array([[1.4, 0.2], [-0.3, 0.8]])  # hidden affine layer for a toy f_theta.
b1_w = np.array([0.6, -0.1])  # hidden bias.
W2_w = np.array([[0.2, -0.5], [0.7, 0.1]])  # map hidden features back to a velocity.
b2_w = np.array([0.0, -0.2])  # output bias.
def relu_w(a_w):  # simple ReLU activation.
    return np.maximum(0.0, a_w)  # keep positive signals and zero negative ones.
def f_nn_w(h_w, t_w):  # a tiny neural vector field.
    hidden_w = relu_w(W1_w @ h_w + b1_w)  # shape the signal through a gate.
    return W2_w @ hidden_w + b2_w  # produce dh/dt with the same shape as h.

vel_nn_w = f_nn_w(x_w, 0.0)  # evaluate the learned-style velocity.
print("neural velocity:", np.round(vel_nn_w, 3))  # inspect both velocity coordinates.
assert vel_nn_w.shape == x_w.shape  # f must map hidden state shape back to itself.
```
▶ What you'll see: the neural vector field returns a two-number velocity, matching the two-number hidden state.

```python
ts_nn_w, path_nn_w = euler_solve_w(f_nn_w, x_w, 0.0, 1.0, 20)  # solve through the neural field.
plt.figure(figsize=(4, 3))  # show how the neural field moves the state.
plt.plot(path_nn_w[:, 0], path_nn_w[:, 1], marker="o", markersize=3, color="teal")  # trajectory.
plt.scatter([x_w[0]], [x_w[1]], color="black", label="start")  # starting point.
plt.scatter([path_nn_w[-1, 0]], [path_nn_w[-1, 1]], color="crimson", label="end")  # final state.
plt.grid(True, alpha=0.3); plt.legend(); plt.title("3: learned vector field trajectory")
plt.xlabel("h[0]"); plt.ylabel("h[1]"); plt.show()
```
▶ What you'll see: the hidden state follows a curved path created by repeatedly querying the neural velocity.

*Why it's done this way:* the neural network does not directly output the final representation; it outputs local derivatives. Gating and affine maps control which coordinates influence the velocity, while the ODE solver controls how those local choices accumulate globally.

### 4. Better solvers reduce numerical error

Euler uses only the slope at the beginning of each step. Runge-Kutta 4 (RK4) samples four slopes inside the step and combines them, so it is usually much more accurate for the same step count. Neural ODEs depend on this numerical choice because the solver is part of the model's forward computation.

```python
def rk4_solve_w(f_w, h_start_w, t0_w, t1_w, steps_w):  # classic fixed-step RK4 solver.
    h_w = h_start_w.astype(float).copy()  # copy initial state.
    ts_w = np.linspace(t0_w, t1_w, steps_w + 1)  # time grid.
    path_w = [h_w.copy()]  # states for plotting.
    dt_w = (t1_w - t0_w) / steps_w  # step size.
    for k_w in range(steps_w):  # advance one RK4 step.
        t_w = ts_w[k_w]  # current time.
        k1_w = f_w(h_w, t_w)  # slope at start.
        k2_w = f_w(h_w + 0.5 * dt_w * k1_w, t_w + 0.5 * dt_w)  # midpoint slope 1.
        k3_w = f_w(h_w + 0.5 * dt_w * k2_w, t_w + 0.5 * dt_w)  # midpoint slope 2.
        k4_w = f_w(h_w + dt_w * k3_w, t_w + dt_w)  # slope at end.
        h_w = h_w + (dt_w / 6.0) * (k1_w + 2*k2_w + 2*k3_w + k4_w)  # weighted average.
        path_w.append(h_w.copy())  # store state.
    return ts_w, np.array(path_w)  # return trajectory.

ts_rk_w, path_rk_w = rk4_solve_w(f_linear_w, h0_w, 0.0, 1.0, 4)  # RK4 with only 4 steps.
print("Euler 4 final:", np.round(path4_w[-1], 4))  # coarse Euler.
print("RK4 4 final:", np.round(path_rk_w[-1], 4))  # higher-order solver.
```
▶ What you'll see: RK4 reaches a noticeably different final point than Euler with the same four steps.

```python
true_final_w = np.array([np.cos(1.0)*h0_w[0] + np.sin(1.0)*h0_w[1], -np.sin(1.0)*h0_w[0] + np.cos(1.0)*h0_w[1]])  # exact rotation for this linear field.
err_euler_w = float(np.linalg.norm(path4_w[-1] - true_final_w))  # Euler final error.
err_rk_w = float(np.linalg.norm(path_rk_w[-1] - true_final_w))  # RK4 final error.
print("exact final:", np.round(true_final_w, 4))  # analytic comparison point.
print("Euler error:", round(err_euler_w, 5), "RK4 error:", round(err_rk_w, 5))  # compare errors.
assert err_rk_w < err_euler_w  # RK4 should be more accurate here.
```
▶ What you'll see: RK4's error is much smaller than Euler's error for the same step count.

```python
plt.figure(figsize=(4, 3))  # visualize numerical errors.
plt.bar(["Euler", "RK4"], [err_euler_w, err_rk_w], color=["crimson", "seagreen"])  # error bars.
plt.ylabel("final-state error"); plt.title("4: solver choice changes accuracy"); plt.show()
```
▶ What you'll see: the RK4 bar is much shorter, showing why higher-order solvers can pay off.

*Why it's done this way:* the ODE solution is an integral over changing slopes. Sampling only one slope assumes the derivative is nearly constant over a step; RK4 reduces that approximation error by checking several slopes before committing to the update.

### 5. Learning means differentiating through the solver

To train a Neural ODE, the loss at the final time must tell the vector-field parameters how to move. In the simplest scalar ODE `dh/dt = θh`, Euler gives `h_{k+1}=h_k+dt θ h_k`. We can backpropagate through those repeated solver steps by hand.

```python
def scalar_euler_forward_w(theta_w, h0_scalar_w, target_w, steps_w):  # solve dh/dt=theta*h and store states.
    dt_w = 1.0 / steps_w  # interval [0,1].
    hs_w = [float(h0_scalar_w)]  # scalar states.
    h_w = float(h0_scalar_w)  # current state.
    for _ in range(steps_w):  # Euler solver as repeated differentiable updates.
        h_w = h_w + dt_w * theta_w * h_w  # h <- (1+dt theta)h.
        hs_w.append(h_w)  # store for backprop.
    loss_w = 0.5 * (h_w - target_w) ** 2  # squared final loss.
    return np.array(hs_w), float(loss_w)  # states and objective.

theta_w, h_start_scalar_w, target_scalar_w = 0.4, 1.0, 2.0  # parameter, initial state, target.
hs_scalar_w, loss_scalar_w = scalar_euler_forward_w(theta_w, h_start_scalar_w, target_scalar_w, 10)  # forward solve.
print("final h:", round(hs_scalar_w[-1], 3), "loss:", round(loss_scalar_w, 3))  # inspect final fit.
```
▶ What you'll see: with θ=0.4, the state grows but undershoots the target 2.0.

```python
dt_scalar_w = 0.1  # 10-step Euler step size.
adj_h_w = hs_scalar_w[-1] - target_scalar_w  # dL/dh_T for 0.5(h_T-y)^2.
grad_theta_w = 0.0  # accumulate dL/dtheta.
for k_w in range(9, -1, -1):  # reverse through solver steps.
    grad_theta_w += adj_h_w * (dt_scalar_w * hs_scalar_w[k_w])  # local ∂h_{k+1}/∂θ = dt*h_k.
    adj_h_w = adj_h_w * (1.0 + dt_scalar_w * theta_w)  # ∂h_{k+1}/∂h_k = 1+dt*theta.
print("manual dL/dtheta:", round(grad_theta_w, 4))  # gradient through the solver.
```
▶ What you'll see: a negative gradient, because increasing θ would grow the final state toward the target.

```python
eps_w = 1e-5  # finite-difference step.
_, loss_plus_w = scalar_euler_forward_w(theta_w + eps_w, h_start_scalar_w, target_scalar_w, 10)  # loss at theta+eps.
_, loss_minus_w = scalar_euler_forward_w(theta_w - eps_w, h_start_scalar_w, target_scalar_w, 10)  # loss at theta-eps.
fd_grad_w = (loss_plus_w - loss_minus_w) / (2 * eps_w)  # numerical gradient.
print("finite-difference gradient:", round(fd_grad_w, 4))  # compare to manual backprop.
assert abs(fd_grad_w - grad_theta_w) < 1e-6  # exact agreement for this computation.
```
▶ What you'll see: the hand-derived gradient matches finite differences, confirming the solver is differentiable.

*Why it's done this way:* the parameter does not affect the loss in one direct jump; it affects every tiny state update, and those effects compound. Backpropagation through the solver is just repeated chain rule over the numerical integration steps.

### 6. The adjoint idea trades memory for recomputation

Storing every solver state makes backprop easy but costs memory. The adjoint method keeps a backward sensitivity `a(t)=∂L/∂h(t)` and integrates an augmented system backward, often recomputing states instead of storing all activations. Here we show the core memory arithmetic and a scalar backward sensitivity.

```python
stored_steps_w = np.array([5, 20, 100, 500])  # possible numbers of stored solver states.
state_dim_w = 128  # hidden vector length from the lesson's memory bookkeeping.
bytes_per_float_w = 4  # float32 memory.
mem_kb_w = stored_steps_w * state_dim_w * bytes_per_float_w / 1024  # activation memory in KB.
print("memory KB:", np.round(mem_kb_w, 2))  # inspect storage cost.
assert round(float(5 * 128 * 4 / 1024), 3) == 2.5  # lesson memory number.
```
▶ What you'll see: storing more solver states increases memory linearly with step count.

```python
eta_w, g_w, param_w = 0.07, 2.1, 2.0  # lesson update knob.
new_param_w = param_w - eta_w * g_w  # one gradient descent step.
print("parameter after update:", round(new_param_w, 3))  # 2 - 0.07*2.1.
assert round(new_param_w, 3) == 1.853  # lesson arithmetic.
```
▶ What you'll see: the parameter moves by a small reliable nudge, not a large jump.

```python
score_w, baseline_w = 2.6, 0.4  # lesson score and comparison baseline.
probs_w = np.exp([score_w, baseline_w]) / np.sum(np.exp([score_w, baseline_w]))  # softmax comparison.
normalized_w = (score_w - 1.0) / np.sqrt(0.25 + 1e-5)  # scale bookkeeping from the lesson.
print("softmax probability:", round(float(probs_w[0]), 3))  # calibrated comparison.
print("normalized value:", round(float(normalized_w), 3))  # scale-adjusted signal.
assert round(float(probs_w[0]), 3) == 0.900 and round(float(normalized_w), 3) == 3.200  # lesson numbers.
```
▶ What you'll see: the same local signal becomes a probability for loss and a normalized value for scale inspection.

```python
plt.figure(figsize=(4.6, 3))  # visualize memory scaling.
plt.plot(stored_steps_w, mem_kb_w, marker="o", color="purple")  # memory grows with stored states.
plt.xlabel("stored solver states"); plt.ylabel("activation memory (KB)")
plt.title("6: storing trajectories costs memory"); plt.grid(True, alpha=0.3); plt.show()
```
▶ What you'll see: a straight increasing line — more stored time points mean more activation memory.

*Why it's done this way:* Neural ODEs move complexity from layer count to solver work. The adjoint viewpoint exists because the obvious gradient path stores many states; recomputing or integrating sensitivities backward can reduce memory, but the numerical choices still affect stability and gradient accuracy.

### Basic 4 — Compare Euler with the exact answer

**Goal.** Measure numerical error for scalar growth, because the solver is an approximation to the true ODE solution. We build it in 2 steps.

```python
theta_b4 = 0.5 # same scalar growth rate.
exact_b4 = np.exp(theta_b4 * 1.0) # exact solution h(1)=h0 exp(theta t) with h0=1.
euler10_b4 = (1.0 + theta_b4 / 10) ** 10 # 10-step Euler final state.
```

### Advanced 1 — Backpropagate through Euler for a vector ODE

**Goal.** Differentiate a vector-valued linear ODE `dh/dt = W h` through Euler steps, because Neural ODE training needs parameter gradients for matrix weights. We build it in 4 steps.

```python
W_a1 = np.array([[0.1, 0.3], [-0.2, 0.05]]) # trainable field matrix.
h0_a1 = np.array([1.0, -0.5]) # initial hidden state.
y_a1 = np.array([1.3, -0.8]) # target final state.
steps_a1 = 8 # Euler steps.

```

```python

hs_a1 = [h0_a1.copy()] # store states.
h_a1 = h0_a1.copy() # current state.
for _ in range(steps_a1): # forward Euler.
    h_a1 = h_a1 + dt_a1 * (W_a1 @ h_a1) # h_{k+1}=h_k+dt W h_k.
    hs_a1.append(h_a1.copy()) # store for reverse pass.

loss_a1 = 0.5 * np.sum((hs_a1[-1] - y_a1) ** 2) # final squared loss.

```
▶ What you'll see: the printed intermediate values for this step before the next cell uses them.


```python

for k_a1 in range(steps_a1 - 1, -1, -1): # reverse Euler steps.
    gradW_a1 += dt_a1 * np.outer(adj_a1, hs_a1[k_a1]) # ∂h_{k+1}/∂W applied to adjoint.
    adj_a1 = adj_a1 + dt_a1 * (W_a1.T @ adj_a1) # propagate dL/dh_k.
print("grad W:\n", np.round(gradW_a1, 4)) # inspect matrix gradient.
```
▶ What you'll see: the printed intermediate values for this step before the next cell uses them.


```python

W_plus_a1 = W_a1.copy(); W_plus_a1[0, 0] += eps_a1 # perturb one parameter up.
W_minus_a1 = W_a1.copy(); W_minus_a1[0, 0] -= eps_a1 # perturb down.
def final_loss_a1(W_in_a1): # helper for finite difference.
    h_fd_a1 = h0_a1.copy() # start.
    for _ in range(steps_a1): # integrate.
        h_fd_a1 = h_fd_a1 + dt_a1 * (W_in_a1 @ h_fd_a1) # Euler update.
    return 0.5 * np.sum((h_fd_a1 - y_a1) ** 2) # final loss.
fd00_a1 = (final_loss_a1(W_plus_a1) - final_loss_a1(W_minus_a1)) / (2 * eps_a1) # finite-difference gradient.
print("finite diff W[0,0]:", round(float(fd00_a1), 4), "manual:", round(float(gradW_a1[0, 0]), 4)) # compare.
assert abs(fd00_a1 - gradW_a1[0, 0]) < 1e-6 # verify reverse-mode calculation.
```
▶ What you'll see: the manually propagated matrix gradient matches finite differences for a checked entry.

👀 Takeaway: vector Neural ODE training is chain rule through each solver step, with adjoints carrying sensitivity backward.

```python
        states_a2.append(H_a2.copy()) # store for gradients.

    logits_a2 = logits_a2 - np.max(logits_a2, axis=1, keepdims=True) # stable softmax.
    probs_a2 = np.exp(logits_a2) / np.sum(np.exp(logits_a2), axis=1, keepdims=True) # probabilities.
    loss_a2 = -np.mean(np.log(probs_a2[np.arange(len(y_a2)), y_a2])) # cross-entropy.
    return np.array(states_a2), probs_a2, float(loss_a2) # return cache.

states0_a2, probs0_a2, loss0_a2 = forward_batch_a2(W_a2) # initial pass.
print("initial loss:", round(loss0_a2, 3), "initial probs:\n", np.round(probs0_a2, 3)) # inspect.
```
▶ What you'll see: the printed intermediate values for this step before the next cell uses them.


```python
losses_a2 = [] # training curve.

    states_a2, probs_a2, loss_a2 = forward_batch_a2(W_a2) # forward pass.
    losses_a2.append(loss_a2) # store loss.
    dlogits_a2 = probs_a2.copy() # softmax CE gradient.
    dlogits_a2[np.arange(len(y_a2)), y_a2] -= 1.0 # subtract one-hot labels.
    dlogits_a2 /= len(y_a2) # average over batch.
    adj_a2 = dlogits_a2 @ C_a2 # dL/dH_T.
    gradW_a2 = np.zeros_like(W_a2) # matrix gradient.
    dt_a2 = 0.1 # step size.
    for k_a2 in range(9, -1, -1): # reverse through Euler steps.
        gradW_a2 += dt_a2 * (adj_a2.T @ states_a2[k_a2]) # batch sum of outer products.
        adj_a2 = adj_a2 + dt_a2 * (adj_a2 @ W_a2) # propagate sensitivity to previous hidden state.
    W_a2 -= 0.5 * gradW_a2 # update field matrix.
print("final loss:", round(losses_a2[-1], 3)) # inspect improvement.

```

### Advanced 3 — Detect stiff dynamics from step-size instability

**Goal.** Show how a large negative rate can make Euler unstable, because Neural ODE solvers must respect time scales in the vector field. We build it in 4 steps.

```python
rate_a3 = -15.0 # fast decay rate dh/dt = rate*h.
h0_a3 = 1.0 # initial state.
step_counts_a3 = np.array([5, 10, 50, 200]) # solver resolutions.
print("rate:", rate_a3) # inspect stiffness source.
```
▶ What you'll see: the derivative changes the state very aggressively.

```python
finals_a3 = [] # store Euler final states.
for steps_a3 in step_counts_a3: # compare discretizations.
    h_a3 = h0_a3 # reset state.
    dt_a3 = 1.0 / int(steps_a3) # step size.
    for _ in range(int(steps_a3)): # Euler integration.

```
▶ What you'll see: the printed intermediate values for this step before the next cell uses them.

### Advanced 4 — Compare stored backprop with adjoint-style recomputation

**Goal.** Contrast activation storage with recomputing states during the backward pass, because the adjoint method is motivated by memory pressure. We build it in 4 steps.

```python
steps_a4 = 100 # number of solver steps.
dim_a4 = 128 # hidden dimension.
bytes_a4 = 4 # float32 bytes.
stored_memory_a4 = (steps_a4 + 1) * dim_a4 * bytes_a4 / 1024 # memory for all states.

print("minimal state KB:", round(float(checkpoint_memory_a4), 2)) # inspect low-memory alternative.
```
▶ What you'll see: storing every state costs far more memory than keeping only a few states.

```python
h0_a4 = 1.0 # scalar initial state.

dt_a4 = 1.0 / steps_a4 # step size.
```

```python
    adj_a4 *= (1 + dt_a4 * theta_a4) # state sensitivity.
```

```python
    h_re_a4 = h0_a4 # recompute state k from the initial value.

    grad_recompute_a4 += adj_a4 * dt_a4 * h_re_a4 # use recomputed state.
```

### Advanced 5 — Learn a time-dependent vector field

**Goal.** Fit `dh/dt = θ0 h + θ1 t` to a target, because Neural ODE dynamics can explicitly depend on time as well as state. We build it in 5 steps.

```python
theta_a5 = np.array([0.1, 0.0]) # parameters [state coefficient, time coefficient].
h0_a5 = 1.0 # initial scalar state.
target_a5 = 1.8 # desired final value.
steps_a5 = 20 # Euler steps.
print("initial theta:", theta_a5) # inspect parameters.
```
▶ What you'll see: the vector field starts with weak state growth and no time forcing.

```python
def forward_a5(theta_in_a5): # solve scalar time-dependent ODE and return states.
    h_a5 = h0_a5 # current state.
    dt_a5 = 1.0 / steps_a5 # step size.
    hs_a5 = [h_a5] # states.
    ts_a5 = [] # times used at each update.
    for k_a5 in range(steps_a5): # Euler integration.
        t_a5 = k_a5 * dt_a5 # current time.
        h_a5 = h_a5 + dt_a5 * (theta_in_a5[0] * h_a5 + theta_in_a5[1] * t_a5) # time-dependent velocity.
        hs_a5.append(h_a5) # store state.
        ts_a5.append(t_a5) # store time.
    loss_a5 = 0.5 * (h_a5 - target_a5) ** 2 # final loss.
    return np.array(hs_a5), np.array(ts_a5), float(loss_a5) # cache.

hs0_a5, ts0_a5, loss0_a5 = forward_a5(theta_a5) # initial solve.
print("initial final h:", round(float(hs0_a5[-1]), 3), "loss:", round(loss0_a5, 3)) # inspect.
```

```python
    dt_a5 = 1.0 / steps_a5 # step size.

        grad_a5[1] += adj_a5 * dt_a5 * ts_a5[k_a5] # ∂h_next/∂theta1 = dt*t.
```
