# 21.9 — SMT Solvers

SMT solvers extend SAT solving from pure true/false variables to formulas whose atoms have mathematical meaning: equalities, arithmetic bounds, and graph-like constraints. In this lesson, we build a tiny SMT engine from scratch so you can see the central partnership: a Boolean search proposes which atoms are true, and a theory solver checks whether those atoms can all be true in the intended mathematics.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build SMT solving one idea at a time. Run each cell in order and inspect the intermediate assignments, equivalence classes, graph edges, propagated facts, and conflicts. The walkthrough is self-contained and uses a `_w` suffix on variables so it never clashes with the examples below.

### 1. Theories beyond Booleans: atoms have meaning

A SAT solver sees only propositional names such as `A` and `B`. An SMT solver still uses that Boolean view, but each name may stand for a theory atom such as `x >= 2`, `x <= 5`, or `f(a) == f(b)`. The same Boolean pattern can therefore be accepted or rejected depending on whether the selected atoms are jointly meaningful in arithmetic or equality.

```python
atoms_w = {
    "A": ("lower", "x", 2.0),   # x >= 2
    "B": ("upper", "x", 5.0),   # x <= 5
    "C": ("lower", "x", 4.0),   # x >= 4
    "D": ("upper", "x", 1.0),   # x <= 1
}
for name_w, atom_w in atoms_w.items():
    op_w = ">=" if atom_w[0] == "lower" else "<="
    print(name_w, "means", f"{atom_w[1]} {op_w} {atom_w[2]:g}")
```
▶ What you'll see: four Boolean names are really interval constraints over the same numeric variable.

```python
def interval_check_w(names_w):
    lo_w, hi_w = -np.inf, np.inf
    for name_w in names_w:
        kind_w, var_w, value_w = atoms_w[name_w]
        if kind_w == "lower":
            lo_w = max(lo_w, value_w)
        else:
            hi_w = min(hi_w, value_w)
    return lo_w <= hi_w, (lo_w, hi_w)

for choice_w in [("A", "B"), ("C", "D")]:
    ok_w, interval_w = interval_check_w(choice_w)
    print(choice_w, "interval", interval_w, "SAT in theory?", ok_w)
assert interval_check_w(("A", "B"))[0]
assert not interval_check_w(("C", "D"))[0]
```
▶ What you'll see: `A ∧ B` leaves the nonempty interval `[2,5]`, while `C ∧ D` demands `x >= 4` and `x <= 1`, which is impossible.

```python
plt.figure(figsize=(5, 2.4))
for y_w, choice_w, color_w in [(1, ("A", "B"), "seagreen"), (0, ("C", "D"), "crimson")]:
    ok_w, (lo_w, hi_w) = interval_check_w(choice_w)
    plt.hlines(y_w, -1, 6, color="lightgray")
    if ok_w:
        plt.plot([lo_w, hi_w], [y_w, y_w], lw=8, color=color_w)
    else:
        plt.scatter([lo_w, hi_w], [y_w, y_w], s=90, color=color_w)
    plt.text(6.2, y_w, f"{choice_w}: {'nonempty' if ok_w else 'empty'}")
plt.xlim(-1, 8); plt.yticks([0, 1], ["C,D", "A,B"]); plt.xlabel("x")
plt.title("1: Boolean atoms checked by arithmetic meaning"); plt.show()
```
▶ What you'll see: one green interval and one red contradiction; the Boolean labels alone do not reveal this.

*Why it's done this way:* SMT separates syntax from meaning. The SAT layer can quickly search over atom names, while the theory layer prevents impossible combinations such as an empty interval from being mistaken for a real solution.

### 2. DPLL(T): a Boolean skeleton plus a theory checker

DPLL(T) is the standard architecture: DPLL searches a Boolean abstraction, and `T` is a theory solver called on each candidate assignment. For a tiny formula, we can enumerate Boolean rows instead of implementing a full watched-literal SAT solver; the important idea is the handoff. The Boolean skeleton asks “which atoms are true?”, and the theory checker asks “can those true atoms be realized?”

```python
clauses_w = [["A"], ["B"], ["C", "D"]]  # A ∧ B ∧ (C ∨ D)
def eval_clause_w(clause_w, row_w):
    return any(row_w[literal_w] for literal_w in clause_w)

def sat_skeleton_rows_w(names_w, clauses_w):
    rows_w = []
    for bits_w in product([False, True], repeat=len(names_w)):
        row_w = dict(zip(names_w, bits_w))
        if all(eval_clause_w(c_w, row_w) for c_w in clauses_w):
            rows_w.append(row_w)
    return rows_w

rows_w = sat_skeleton_rows_w(["A", "B", "C", "D"], clauses_w)
print("Boolean-satisfying rows:", len(rows_w))
for row_w in rows_w:
    print(row_w)
```
▶ What you'll see: the Boolean layer finds rows satisfying `A`, `B`, and at least one of `C` or `D`.

```python
def theory_filter_intervals_w(rows_w):
    accepted_w, rejected_w = [], []
    for row_w in rows_w:
        active_w = [name_w for name_w, value_w in row_w.items() if value_w]
        ok_w, interval_w = interval_check_w(active_w)
        (accepted_w if ok_w else rejected_w).append((row_w, interval_w, active_w))
    return accepted_w, rejected_w

accepted_w, rejected_w = theory_filter_intervals_w(rows_w)
print("accepted by theory:", len(accepted_w))
print("rejected by theory:", len(rejected_w))
for row_w, interval_w, active_w in rejected_w:
    print("conflict from", active_w, "interval", interval_w)
assert len(accepted_w) == 1 and len(rejected_w) == 2
```
▶ What you'll see: Boolean search proposes three rows, but the arithmetic theory rejects the rows containing both `C` and `D`.

```python
plt.figure(figsize=(4.8, 3))
plt.bar(["Boolean rows", "Theory-OK rows", "Theory conflicts"], [len(rows_w), len(accepted_w), len(rejected_w)], color=["gray", "seagreen", "crimson"])
plt.title("2: DPLL(T) = Boolean proposals filtered by T")
plt.ylabel("candidate assignments")
plt.show()
```
▶ What you'll see: the theory solver shrinks the set of Boolean candidates to the rows that have a real arithmetic model.

*Why it's done this way:* Boolean search is excellent at clause structure, but terrible at arithmetic meaning. DPLL(T) keeps each solver in its strength: SAT proposes a skeleton, and the theory checker either produces a model, a conflict, or implied theory facts.

### 3. Equality with congruence closure

The theory of equality says equal terms can be substituted into any context. If `a = b`, then `f(a) = f(b)` must also hold. Congruence closure implements this by merging equivalence classes with union-find, then repeatedly merging function applications whose arguments are already in the same classes.

```python
terms_w = ["a", "b", "c", "f(a)", "f(b)", "f(c)"]
parent_w = {t_w: t_w for t_w in terms_w}
def find_w(x_w):
    while parent_w[x_w] != x_w:
        parent_w[x_w] = parent_w[parent_w[x_w]]
        x_w = parent_w[x_w]
    return x_w

def union_w(x_w, y_w):
    rx_w, ry_w = find_w(x_w), find_w(y_w)
    if rx_w != ry_w:
        parent_w[ry_w] = rx_w

union_w("a", "b")
print("class(a):", find_w("a"), "class(b):", find_w("b"))
assert find_w("a") == find_w("b")
```
▶ What you'll see: `a` and `b` are placed in the same equivalence class.

```python
applications_w = {"f(a)": ("f", "a"), "f(b)": ("f", "b"), "f(c)": ("f", "c")}
changed_w = True
while changed_w:
    changed_w = False
    buckets_w = defaultdict(list)
    for term_w, (fun_w, arg_w) in applications_w.items():
        buckets_w[(fun_w, find_w(arg_w))].append(term_w)
    for group_w in buckets_w.values():
        for term_w in group_w[1:]:
            before_w = find_w(group_w[0]) == find_w(term_w)
            union_w(group_w[0], term_w)
            changed_w = changed_w or not before_w
classes_w = defaultdict(list)
for term_w in terms_w:
    classes_w[find_w(term_w)].append(term_w)
print("equivalence classes:", dict(classes_w))
assert find_w("f(a)") == find_w("f(b)")
assert find_w("f(a)") != find_w("f(c)")
```
▶ What you'll see: the solver infers `f(a) = f(b)` without being told directly.

```python
xpos_w = {"a": 0, "b": 1, "c": 2, "f(a)": 0, "f(b)": 1, "f(c)": 2}
ypos_w = {"a": 1, "b": 1, "c": 1, "f(a)": 0, "f(b)": 0, "f(c)": 0}
plt.figure(figsize=(5, 3))
for term_w in terms_w:
    root_w = find_w(term_w)
    plt.scatter(xpos_w[term_w], ypos_w[term_w], s=250, label=root_w if root_w == term_w else None)
    plt.text(xpos_w[term_w], ypos_w[term_w], term_w, ha="center", va="center", color="white")
plt.plot([0, 1], [1, 1], color="seagreen", lw=3, label="given a=b")
plt.plot([0, 1], [0, 0], color="orange", lw=3, label="implied f(a)=f(b)")
plt.axis("off"); plt.legend(loc="upper right"); plt.title("3: congruence closure merges function terms"); plt.show()
```
▶ What you'll see: the top merge `a=b` forces the bottom merge `f(a)=f(b)`; `c` and `f(c)` stay separate.

*Why it's done this way:* Equality is not just a list of pairs. The solver must close equalities under function contexts, or it would miss consequences that are logically required by substitutability.

### 4. Difference logic as a constraint graph

Difference logic uses constraints of the form `x - y <= c`. Each constraint becomes a directed edge `y → x` with weight `c`, meaning `x` can be at most `c` above `y`. A set is inconsistent exactly when the graph contains a negative-weight cycle, because following the cycle would imply a variable is strictly less than itself.

```python
def difference_logic_check_w(vars_w, edges_w):
    dist_w = {v_w: 0.0 for v_w in vars_w}
    relax_log_w = []
    for _ in range(len(vars_w) - 1):
        changed_w = False
        for src_w, dst_w, weight_w in edges_w:
            if dist_w[dst_w] > dist_w[src_w] + weight_w:
                dist_w[dst_w] = dist_w[src_w] + weight_w
                relax_log_w.append((src_w, dst_w, weight_w, dict(dist_w)))
                changed_w = True
        if not changed_w:
            break
    conflict_w = [(s_w, d_w, w_w) for s_w, d_w, w_w in edges_w if dist_w[d_w] > dist_w[s_w] + w_w]
    return len(conflict_w) == 0, dist_w, conflict_w, relax_log_w

vars_w = ["x", "y", "z"]
sat_edges_w = [("y", "x", 3.0), ("z", "y", 2.0), ("x", "z", 0.0)]  # x-y<=3, y-z<=2, z-x<=0
ok_w, model_w, conflict_w, log_w = difference_logic_check_w(vars_w, sat_edges_w)
print("satisfiable?", ok_w, "model potentials:", model_w)
assert ok_w
```
▶ What you'll see: the graph has a feasible set of potentials, so these inequalities can hold together.

```python
bad_edges_w = [("y", "x", 1.0), ("x", "y", -3.0)]  # x-y<=1 and y-x<=-3 imply x-y>=3 too
ok_bad_w, model_bad_w, conflict_bad_w, log_bad_w = difference_logic_check_w(["x", "y"], bad_edges_w)
print("satisfiable?", ok_bad_w)
print("conflict edge(s):", conflict_bad_w)
assert not ok_bad_w
```
▶ What you'll see: the second system is rejected because it contains a negative cycle.

```python
plt.figure(figsize=(4.8, 3.2))
pos_w = {"x": (0, 1), "y": (2, 1), "z": (1, 0)}
for name_w, (x_w, y_w) in pos_w.items():
    plt.scatter(x_w, y_w, s=500, color="steelblue")
    plt.text(x_w, y_w, name_w, ha="center", va="center", color="white", fontsize=12)
for src_w, dst_w, weight_w in sat_edges_w:
    x0_w, y0_w = pos_w[src_w]; x1_w, y1_w = pos_w[dst_w]
    plt.annotate("", xy=(x1_w, y1_w), xytext=(x0_w, y0_w), arrowprops=dict(arrowstyle="->", lw=2))
    plt.text((x0_w + x1_w) / 2, (y0_w + y1_w) / 2 + 0.08, f"≤ {weight_w:g}")
plt.axis("off"); plt.title("4: difference constraints as weighted edges"); plt.show()
```
▶ What you'll see: every inequality becomes an arrow; the solver checks whether all arrows can be satisfied at once.

*Why it's done this way:* Difference constraints have a graph structure, so Bellman-Ford-style relaxation gives a small, explainable theory solver. Negative cycles are theory conflicts that the Boolean layer can learn to avoid.

### 5. Theory propagation and conflict clauses

A theory solver does more than say yes or no. It can propagate facts that must follow from the current assignment, and it can explain conflicts as clauses for the Boolean solver. If `x >= 2` and `x <= 5`, then `x <= 6` is implied. If `x >= 4` and `x <= 1`, the solver can return the conflict clause `¬C ∨ ¬D`, meaning those two atoms cannot be true together again.

```python
prop_atoms_w = {
    "A": ("lower", "x", 2.0),
    "B": ("upper", "x", 5.0),
    "E": ("upper", "x", 6.0),
    "C": ("lower", "x", 4.0),
    "D": ("upper", "x", 1.0),
}
def interval_bounds_for_w(active_w):
    lo_w, hi_w = -np.inf, np.inf
    for name_w in active_w:
        kind_w, var_w, value_w = prop_atoms_w[name_w]
        lo_w = max(lo_w, value_w) if kind_w == "lower" else lo_w
        hi_w = min(hi_w, value_w) if kind_w == "upper" else hi_w
    return lo_w, hi_w

lo_w, hi_w = interval_bounds_for_w(["A", "B"])
implies_E_w = hi_w <= prop_atoms_w["E"][2]
print("bounds from A,B:", (lo_w, hi_w), "imply E?", implies_E_w)
assert implies_E_w
```
▶ What you'll see: the accepted interval `[2,5]` is enough to force the atom `x <= 6`.

```python
lo_bad_w, hi_bad_w = interval_bounds_for_w(["C", "D"])
conflict_clause_w = ["not C", "not D"] if lo_bad_w > hi_bad_w else []
print("bounds from C,D:", (lo_bad_w, hi_bad_w))
print("learned conflict clause:", conflict_clause_w)
assert conflict_clause_w == ["not C", "not D"]
```
▶ What you'll see: the theory conflict is converted into a Boolean clause that blocks choosing both `C` and `D` later.

```python
plt.figure(figsize=(5, 2.8))
plt.bar(["lower bound", "upper bound", "implied upper E"], [lo_w, hi_w, prop_atoms_w["E"][2]], color=["teal", "orange", "gray"])
plt.axhline(hi_w, color="orange", linestyle="--")
plt.title("5: theory propagation from interval bounds")
plt.ylabel("x bound value")
plt.show()
```
▶ What you'll see: the current upper bound 5 is stronger than the candidate upper bound 6, so `E` is automatically true.

*Why it's done this way:* Propagation lets the theory solver prune Boolean search before a full assignment is tried. Conflict clauses turn mathematical impossibility into reusable Boolean knowledge, which is what makes DPLL(T) much faster than blind generate-and-check.

## 🛠️ Setup

```python
import numpy as np  # arrays, small numerical checks, and plotting coordinates.
import matplotlib.pyplot as plt  # all notebook visualizations.
from itertools import product  # tiny Boolean assignment enumeration for our SAT skeleton.
from collections import defaultdict  # grouping equivalence classes and graph adjacency.
np.random.seed(0)  # make every example reproducible.

def eval_cnf(clauses, assignment):
    def lit_value(literal):
        return (not assignment[literal[1:]]) if literal.startswith("~") else assignment[literal]
    return all(any(lit_value(literal) for literal in clause) for clause in clauses)

def satisfying_rows(names, clauses):
    rows = []
    for bits in product([False, True], repeat=len(names)):
        row = dict(zip(names, bits))
        if eval_cnf(clauses, row):
            rows.append(row)
    return rows

def interval_theory(active, atom_map):
    bounds = defaultdict(lambda: [-np.inf, np.inf])
    for name in active:
        kind, var, value = atom_map[name]
        if kind == "lower":
            bounds[var][0] = max(bounds[var][0], value)
        elif kind == "upper":
            bounds[var][1] = min(bounds[var][1], value)
    conflicts = {v: tuple(b) for v, b in bounds.items() if b[0] > b[1]}
    model = {v: 0.5 * (b[0] + b[1]) if np.isfinite(b[0] + b[1]) else (b[0] if np.isfinite(b[0]) else b[1] if np.isfinite(b[1]) else 0.0) for v, b in bounds.items()}
    return len(conflicts) == 0, dict(bounds), model, conflicts

def difference_logic_check(vars_, edges):
    dist = {v: 0.0 for v in vars_}
    for _ in range(len(vars_) - 1):
        changed = False
        for src, dst, weight in edges:
            if dist[dst] > dist[src] + weight:
                dist[dst] = dist[src] + weight
                changed = True
        if not changed:
            break
    conflict = [(s, d, w) for s, d, w in edges if dist[d] > dist[s] + w]
    return len(conflict) == 0, dist, conflict

def congruence_closure(equalities, disequalities, applications):
    terms = sorted(set([t for pair in equalities + disequalities for t in pair]) | set(applications.keys()) | {arg for _, args in applications.values() for arg in args})
    parent = {t: t for t in terms}
    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x
    def union(a, b):
        ra, rb = find(a), find(b)
        if ra != rb:
            parent[rb] = ra
            return True
        return False
    for a, b in equalities:
        union(a, b)
    changed = True
    while changed:
        changed = False
        buckets = defaultdict(list)
        for term, (fun, args) in applications.items():
            buckets[(fun, tuple(find(a) for a in args))].append(term)
        for group in buckets.values():
            for term in group[1:]:
                changed = union(group[0], term) or changed
    classes = defaultdict(list)
    for t in terms:
        classes[find(t)].append(t)
    conflicts = [(a, b) for a, b in disequalities if find(a) == find(b)]
    return len(conflicts) == 0, dict(classes), conflicts, find

def show_constraint_graph(nodes, edges, title):
    angles = np.linspace(0, 2 * np.pi, len(nodes), endpoint=False)
    pos = {n: (np.cos(a), np.sin(a)) for n, a in zip(nodes, angles)}
    plt.figure(figsize=(4, 3.5))
    for n in nodes:
        plt.scatter(*pos[n], s=500, color="steelblue")
        plt.text(*pos[n], n, ha="center", va="center", color="white")
    for src, dst, weight in edges:
        x0, y0 = pos[src]; x1, y1 = pos[dst]
        plt.annotate("", xy=(x1, y1), xytext=(x0, y0), arrowprops=dict(arrowstyle="->", lw=2))
        plt.text((x0 + x1) / 2, (y0 + y1) / 2, f"≤{weight:g}")
    plt.axis("off"); plt.title(title); plt.show()
```
