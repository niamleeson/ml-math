# 15.9 · The Cold-Start Problem

Cold start happens when a recommender must score a user, item, or whole system before enough interaction history exists. In this lesson, we treat missing behavior as uncertainty: use content, priors, and exploration first, then let collaborative evidence take over as data arrives.

## 📖 Concept walkthrough — build it from scratch

Before the terse worked examples, we build cold-start handling one idea at a time. Run each cell in order and read the printed intermediate values — every fallback is shown numerically. This walkthrough is self-contained (it imports what it needs) and uses a `_w` suffix on its variables so it never clashes with the examples below.

### 1. Three cold starts and why pure CF/MF fails

A **new user** has an empty row, a **new item** has an empty column, and a **new system** has almost no matrix at all. Pure collaborative filtering needs overlapping interactions, and matrix factorization needs observed cells to update the corresponding user/item factors. If a column is all zeros, it has no co-raters with any item; if a row is all zeros, it has no taste anchors.

For item–item CF, a similarity between item columns uses shared users. An all-zero new-item column gives an empty shared set, so the denominator of cosine has no evidence to normalize — not because the item is bad, but because it is unknown.

```python
R_w = np.array([[5., 4., 0., 1., 0.],   # Ava: item 4 is unseen by everyone.
                [4., 5., 0., 1., 0.],   # Ben
                [1., 1., 5., 4., 0.],   # Cam
                [0., 1., 4., 5., 0.]])  # Dee
users_w = ["Ava", "Ben", "Cam", "Dee"]  # row labels.
items_w = ["I0", "I1", "I2", "I3", "NEW"]  # column labels.
print("ratings with new-item column:\n", R_w)  # inspect the cold item.
print("new item observed count:", int((R_w[:, 4] > 0).sum()))  # no interactions yet.
```
▶ What you'll see: the last column is all zeros, so the item is cold rather than disliked.

```python
def item_cos_w(R, i, j):  # cosine over users who rated both items.
    a, b = R[:, i], R[:, j]  # item columns.
    shared = (a > 0) & (b > 0)  # co-raters are the only legal evidence.
    if shared.sum() == 0:  # empty overlap means no CF neighbor signal.
        return 0.0, 0
    denom = np.linalg.norm(a[shared]) * np.linalg.norm(b[shared])  # guarded denominator.
    return (float(np.dot(a[shared], b[shared]) / denom) if denom else 0.0), int(shared.sum())

for j_w in range(4):  # compare the cold item to every warm item.
    sim_w, overlap_w = item_cos_w(R_w, 4, j_w)  # all overlaps will be zero.
    print(f"sim(NEW,{items_w[j_w]})={sim_w:.3f}, shared users={overlap_w}")
```
▶ What you'll see: every similarity is 0.000 with zero shared users — there are no neighbors to average.

```python
new_user_w = np.array([0., 0., 0., 0., 0.])  # a brand-new row.
row_signal_w = int((new_user_w > 0).sum())  # count known preferences.
new_system_w = np.zeros((3, 4))  # a brand-new product has no matrix history.
print("new user observed cells:", row_signal_w)  # no row signal.
print("new system observed cells:", int((new_system_w > 0).sum()))  # no global CF signal.
```
▶ What you'll see: cold start appears on rows, columns, or the entire matrix.

```python
plt.figure(figsize=(4.8, 3.1))  # visualize why the new item has no column evidence.
plt.imshow(R_w, cmap="viridis", aspect="auto")  # rating heatmap.
plt.colorbar(label="rating (0 = unobserved)")  # legend.
plt.xticks(range(len(items_w)), items_w); plt.yticks(range(len(users_w)), users_w)  # labels.
plt.title("1: cold starts are empty rows/columns"); plt.show()  # show the cold column.
```
▶ What you'll see: the NEW column is dark for every user, so pure CF cannot rank it from behavior.

*Why it's done this way: the model must distinguish "no data" from "bad item"; otherwise an empty row or column is scored as zero and never gets the exposure needed to become warm.*

### 2. Content and metadata fallback: score by features

When behavior is missing, content features can still match a user profile to a new item. A user profile might come from onboarding answers or past item metadata; an item vector might describe genre, topic, price, or embedding features. We can compute a legitimate score before any collaborative history using cosine similarity:

$$\cos(u,x)=\frac{\sum_f u_f x_f}{\sqrt{\sum_f u_f^2}\sqrt{\sum_f x_f^2}}.$$

For a new item with content vector $(1,1)$ and user profile $(1,0.5)$, the dot is $1.500$, the norms are $1.118$ and $1.414$, and the cosine is $0.949$.

```python
profile_w = np.array([1.0, 0.5])  # user's inferred preference for two content features.
new_item_feat_w = np.array([1.0, 1.0])  # new item metadata exists even with no clicks.
dot_w = float(profile_w @ new_item_feat_w)  # 1*1 + 0.5*1.
norms_w = np.linalg.norm(profile_w) * np.linalg.norm(new_item_feat_w)  # sqrt(1.25)*sqrt(2).
content_score_w = dot_w / norms_w if norms_w else 0.0  # guarded cosine.
print("dot:", round(dot_w, 3))
print("norms:", round(np.linalg.norm(profile_w), 3), round(np.linalg.norm(new_item_feat_w), 3))
print("content cosine:", round(content_score_w, 3))
assert round(dot_w, 3) == 1.500 and round(content_score_w, 3) == 0.949  # lesson numbers.
```
▶ What you'll see: metadata produces a high score even when the item column is empty.

```python
catalog_feats_w = np.array([[1.0, 0.0], [0.2, 1.0], [1.0, 1.0], [0.0, 1.0]])  # four candidate items.
labels_w = ["sports", "art", "hybrid", "music"]  # readable labels.
def cosine_w(a, b):  # small guarded cosine helper.
    d = np.linalg.norm(a) * np.linalg.norm(b)
    return float(np.dot(a, b) / d) if d else 0.0
scores_w = np.array([cosine_w(profile_w, x_w) for x_w in catalog_feats_w])  # score by content.
print("content scores:", dict(zip(labels_w, np.round(scores_w, 3))))  # inspect ranking.
```
▶ What you'll see: the hybrid item ranks highest because it matches both user features.

```python
plt.figure(figsize=(4.8, 3))  # show content fallback scores.
plt.bar(labels_w, scores_w, color="teal")  # one content score per item.
plt.ylim(0, 1.05); plt.ylabel("cosine score")  # bounded similarity scale.
plt.title("2: content fallback for a new item"); plt.show()  # render fallback ranking.
```
▶ What you'll see: a content-driven ranking exists before collaborative data arrives.

*Why it's done this way: features are not a perfect substitute for behavior, but they prevent the system from treating unseen inventory as unrankable.*

### 3. Popularity and demographic priors

A safe default is a popularity prior: recommend what many users like. The danger is tiny denominators. Raw CTR $\hat p=c/n$ can make a new item with 5 clicks from 20 impressions look better than a stable item with 50 clicks from 1000 impressions. Bayesian shrinkage pulls sparse estimates toward the prior mean.

With a Beta prior $\text{Beta}(\alpha,\beta)$, the posterior mean is

$$\mathbb{E}[p\mid c,n]=\frac{c+\alpha}{n+\alpha+\beta}.$$

For $\alpha=10$, $\beta=190$, the prior mean is $0.05$. It acts like 200 pseudo-impressions, so low-count items must earn their way away from the mean.

```python
clicks_w = np.array([50, 20, 5])  # A, B, C clicks.
imps_w = np.array([1000, 200, 20])  # A, B, C impressions.
raw_ctr_w = clicks_w / imps_w  # c/n raw estimates.
print("raw CTR:", np.round(raw_ctr_w, 3))  # A=0.050, B=0.100, C=0.250.
assert np.allclose(raw_ctr_w, [0.05, 0.10, 0.25])  # cited raw CTRs.
```
▶ What you'll see: raw popularity chooses C because 5/20 = 0.250.

```python
alpha_w, beta_w = 10, 190  # prior: 10 clicks and 190 non-clicks, mean 0.05.
shrunk_w = (clicks_w + alpha_w) / (imps_w + alpha_w + beta_w)  # posterior means.
print("shrunk CTR:", np.round(shrunk_w, 3))  # A=0.050, B=0.075, C=0.068.
assert np.allclose(np.round(shrunk_w, 3), [0.050, 0.075, 0.068])  # lesson numbers.
```
▶ What you'll see: shrinkage chooses B because C's apparent lead was uncertain.

```python
segments_w = ["student", "professional", "parent"]  # demographic/new-user segments.
segment_prior_w = np.array([0.62, 0.48, 0.55])  # prior probability of liking a math-help feature.
new_user_segment_w = "student"  # onboarding or account metadata gives a segment.
prior_score_w = segment_prior_w[segments_w.index(new_user_segment_w)]  # segment fallback.
print("new-user segment prior:", new_user_segment_w, prior_score_w)  # personalized without row history.
```
▶ What you'll see: a new user can receive a segment-specific score instead of a global average.

```python
plt.figure(figsize=(5, 3))  # compare raw and shrunk popularity.
x_w = np.arange(3)  # item positions.
plt.bar(x_w - 0.18, raw_ctr_w, width=0.36, label="raw", color="lightgray")  # raw CTR.
plt.bar(x_w + 0.18, shrunk_w, width=0.36, label="shrunk", color="royalblue")  # posterior mean.
plt.xticks(x_w, ["A", "B", "C"]); plt.ylabel("CTR estimate")  # labels.
plt.title("3: shrink sparse popularity toward the mean"); plt.legend(); plt.show()  # display.
```
▶ What you'll see: the tiny-count item C moves much closer to the 0.05 prior.

*Why it's done this way: shrinkage is a Bayesian prior toward the mean, so estimates with small $n$ do not overpower reliable evidence with large $n$.*

### 4. Exploration gathers the data cold items need

If the system never shows a new item, it never collects impressions, so the item never leaves cold start. Exploration allocates some traffic to uncertain or under-shown items. A simple bonus is larger when impressions are small:

$$\text{score}_i=\hat\mu_i+\lambda\sqrt{\frac{\log(t+1)}{n_i+1}}.$$

The first term exploits known quality; the second term buys information where exposure is scarce.

```python
mean_w = np.array([0.08, 0.07, 0.05, 0.06])  # current click estimates.
shown_w = np.array([1000, 200, 20, 0])  # exposure counts; last item is brand new.
t_w = int(shown_w.sum() + 1)  # total decision count for the bonus.
lam_w = 0.03  # exploration strength.
bonus_w = lam_w * np.sqrt(np.log(t_w + 1) / (shown_w + 1))  # guard n=0 by +1.
explore_score_w = mean_w + bonus_w  # optimistic score.
print("bonus:", np.round(bonus_w, 3))
print("exploration scores:", np.round(explore_score_w, 3))
```
▶ What you'll see: the never-shown item receives the largest uncertainty bonus.

```python
rank_w = np.argsort(explore_score_w)[::-1]  # rank by exploitation + exploration.
print("ranking by exploration score:", rank_w)  # item 3 can surface despite modest mean.
print("top item exposure count:", shown_w[rank_w[0]])  # inspect whether the top is under-shown.
```
▶ What you'll see: exploration may show a low-exposure item to learn whether it is good.

```python
plt.figure(figsize=(5, 3))  # compare estimate and bonus.
x_w = np.arange(len(mean_w))  # item ids.
plt.bar(x_w, mean_w, label="mean", color="gray")  # current estimate.
plt.bar(x_w, bonus_w, bottom=mean_w, label="exploration bonus", color="goldenrod")  # uncertainty.
plt.xticks(x_w, ["I0", "I1", "I2", "NEW"]); plt.ylabel("ranking score")  # labels.
plt.title("4: exploration exposes under-shown items"); plt.legend(); plt.show()  # display.
```
▶ What you'll see: the cold item gets rank help from uncertainty, not from fake popularity.

*Why it's done this way: exploration spends a controlled amount of traffic to convert unknown appeal into measured evidence, preventing permanent long-tail burial.*

### 5. Hybrid warm-up blends content prior with collaborative signal

A practical recommender starts from a content or prior score, then increases the collaborative weight as interactions arrive. One smooth confidence weight is

$$w(n)=\frac{n}{n+k},\qquad \text{score}(n)=(1-w(n))\,s_{content}+w(n)\,s_{collab}.$$

Here $k$ controls how many events are needed before collaboration dominates. With $s_{content}=0.06$, $s_{collab}=0.18$, and $k=5$, the score starts at $0.060$ and rises above $0.150$ after 20 events.

```python
n_w = np.array([0, 1, 2, 5, 10, 20, 50])  # observed interactions during warm-up.
content_prior_w = 0.06  # fallback CTR-like score.
collab_signal_w = 0.18  # later collaborative estimate.
k_w = 5.0  # confidence scale.
weight_w = n_w / (n_w + k_w)  # confidence in collaborative signal.
hybrid_w = (1 - weight_w) * content_prior_w + weight_w * collab_signal_w  # blended score.
print("weights:", np.round(weight_w, 3))
print("hybrid scores:", np.round(hybrid_w, 3))
assert round(hybrid_w[0], 3) == 0.060 and hybrid_w[n_w == 20][0] > 0.150  # cited behavior.
```
▶ What you'll see: the blend shifts monotonically from content toward collaborative evidence.

```python
true_ctr_w = 0.16  # assume the item is actually good.
rmse_w = np.abs(hybrid_w - true_ctr_w)  # one-item RMSE equals absolute error.
print("warm-up RMSE:", np.round(rmse_w, 3))  # error drops as n grows toward the collaborative estimate.
assert rmse_w[-1] < rmse_w[0]  # warming up improves this scenario.
```
▶ What you'll see: error is lower after the item has accumulated interactions.

```python
plt.figure(figsize=(5, 3))  # show the warm-up trajectory.
plt.plot(n_w, hybrid_w, marker="o", label="hybrid score", color="seagreen")  # blended score.
plt.axhline(content_prior_w, ls="--", color="gray", label="content prior")  # start.
plt.axhline(collab_signal_w, ls=":", color="black", label="collab signal")  # destination.
plt.xlabel("interactions n"); plt.ylabel("score")  # labels.
plt.title("5: hybrid score warms from content to CF"); plt.legend(); plt.show()  # display.
```
▶ What you'll see: the score starts at the prior and approaches the collaborative estimate as confidence grows.

*Why it's done this way: a confidence-weighted blend prevents one or two noisy clicks from overriding metadata, while still letting real interaction data take over once enough evidence exists.*

## Setup

```python
import numpy as np  # arrays + vectorized math for all examples.
import matplotlib.pyplot as plt  # plotting for every example.
np.random.seed(9)  # deterministic examples.


def cosine(a, b):  # guarded cosine similarity.
    a = np.asarray(a, dtype=float); b = np.asarray(b, dtype=float)
    d = np.linalg.norm(a) * np.linalg.norm(b)
    return float(np.dot(a, b) / d) if d else 0.0


def item_cf_similarity(R, i, j):  # item-item CF similarity over shared raters.
    a, b = R[:, i], R[:, j]
    shared = (a > 0) & (b > 0)
    if shared.sum() == 0:
        return 0.0
    return cosine(a[shared], b[shared])


def shrink_mean(xbar, n, mu, m):  # Bayesian mean-style shrinkage for a scalar average.
    return (m * mu + n * xbar) / (m + n) if (m + n) else mu


def blend_score(content, collab, n, k=5.0):  # confidence-weighted hybrid score.
    w = n / (n + k) if (n + k) else 0.0
    return (1 - w) * content + w * collab, w
```

#### B5. Shrink sparse item means toward the global mean
