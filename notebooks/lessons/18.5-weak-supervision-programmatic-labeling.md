# 18.5 — Weak Supervision & Programmatic Labeling

Weak supervision turns domain knowledge into code: instead of hand-labeling every example, we write noisy labeling functions, measure when they speak, inspect where they disagree, and combine their votes into probabilistic training labels. In this lesson, abstain is a first-class output, conflicts are debugging signals, and the label model is built from scratch so the uncertainty never disappears.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build weak supervision one idea at a time. Run each cell in order and read the printed intermediate values — every piece of math is spelled out so labeling functions, coverage, conflict, and Snorkel-style aggregation are not black boxes. This walkthrough is self-contained (it imports what it needs) and uses a `_w` suffix on its variables so it never clashes with the examples below.

### 1. Labeling functions: code that can abstain

Weak supervision starts by replacing one expensive human label with several cheap, noisy rules. A **labeling function** takes an example and returns `1` for positive, `0` for negative, or `-1` for abstain. Abstention is not a failure; it is the rule honestly saying "outside my expertise." The toy task below labels short messages as promotional (`1`) or not (`0`) using only hand-written signals.

```python
texts_w = np.array([
    "free trial offer now", "team lunch schedule", "limited discount coupon",
    "project update meeting", "winner claim prize", "family dinner plan"
])
true_w = np.array([1, 0, 1, 0, 1, 0])  # hidden ground truth for checking the toy example.
print("messages:")
for i_w, t_w in enumerate(texts_w):
    print(i_w, "→", t_w)
```
▶ What you'll see: six tiny text examples, three promotional and three ordinary.

```python
ABSTAIN_w = -1  # reserve -1 for "this rule does not know".
def has_offer_w(text_w):
    return 1 if ("offer" in text_w or "discount" in text_w or "free" in text_w) else ABSTAIN_w

def has_meeting_w(text_w):
    return 0 if ("meeting" in text_w or "schedule" in text_w or "lunch" in text_w) else ABSTAIN_w

print("offer LF:", [has_offer_w(t_w) for t_w in texts_w])
print("meeting LF:", [has_meeting_w(t_w) for t_w in texts_w])
```
▶ What you'll see: each rule labels only the examples it recognizes and abstains everywhere else.

```python
coverage_offer_w = np.mean(np.array([has_offer_w(t_w) for t_w in texts_w]) != ABSTAIN_w)
coverage_meeting_w = np.mean(np.array([has_meeting_w(t_w) for t_w in texts_w]) != ABSTAIN_w)
print("coverage offer:", round(coverage_offer_w, 3))
print("coverage meeting:", round(coverage_meeting_w, 3))
assert round(coverage_offer_w, 3) == 0.333
assert round(coverage_meeting_w, 3) == 0.333
```
▶ What you'll see: the offer rule covers one third of the data; the meeting rule covers one third too.

*Why it's done this way:* forcing every rule to emit a class would turn missing expertise into confident noise. The `-1` value preserves the distinction between "negative" and "not enough evidence," so later aggregation can average only the rules that actually spoke.

### 2. The label matrix, coverage, and conflict

After writing several labeling functions, we run all of them on all examples and build a label matrix $L\in\{-1,0,1\}^{m\times K}$. Rows are examples, columns are labeling functions. Coverage of function $k$ is $c_k=\frac{1}{m}\sum_i\mathbf{1}[L_{ik}\ne -1]$. Conflict happens on a row when non-abstaining functions emit both `0` and `1`.

```python
def has_prize_w(text_w):
    return 1 if ("winner" in text_w or "prize" in text_w) else ABSTAIN_w

def has_family_w(text_w):
    return 0 if ("family" in text_w or "dinner" in text_w) else ABSTAIN_w

def broad_now_w(text_w):
    return 1 if ("now" in text_w or "plan" in text_w) else ABSTAIN_w  # intentionally noisy.

lfs_w = [has_offer_w, has_meeting_w, has_prize_w, has_family_w, broad_now_w]
L_w = np.array([[lf_w(t_w) for lf_w in lfs_w] for t_w in texts_w])
print(L_w)
```
▶ What you'll see: a 6×5 matrix where `-1` means abstain, and one row has an intentional conflict.

```python
coverage_w = np.mean(L_w != ABSTAIN_w, axis=0)
spoken_w = L_w != ABSTAIN_w
conflict_w = np.array([len(set(row_w[row_w != ABSTAIN_w])) > 1 for row_w in L_w])
print("coverage per LF:", np.round(coverage_w, 3))
print("conflict rows:", np.where(conflict_w)[0])
print("conflict rate:", round(float(np.mean(conflict_w)), 3))
assert np.allclose(np.round(coverage_w, 3), [0.333, 0.333, 0.167, 0.167, 0.333])
assert round(float(np.mean(conflict_w)), 3) == 0.167
```
▶ What you'll see: coverage exposes how often each rule fires; row 5 conflicts because `plan` votes positive while `family/dinner` votes negative.

```python
plt.figure(figsize=(5, 3))
plt.imshow(L_w, cmap="coolwarm", vmin=-1, vmax=1, aspect="auto")
plt.colorbar(label="LF output (-1 abstain, 0 neg, 1 pos)")
plt.title("1: label matrix L")
plt.xlabel("labeling function")
plt.ylabel("example")
plt.show()
```
▶ What you'll see: abstentions, positive votes, and negative votes appear as different colors; conflicts are rows with both class colors.

*Why it's done this way:* coverage tells whether a rule contributes enough signal to matter, while conflict points to the exact rows where rules disagree. Those are separate diagnostics: a high-coverage rule can still be harmful if its broad reach creates many conflicts.

### 3. Majority vote after abstentions

The simplest aggregator ignores abstentions and asks which class received more non-abstaining votes on each row. If the positive count is larger than the negative count, predict `1`; if the negative count is larger, predict `0`; if nobody speaks or the row ties, keep the weak label unknown.

```python
pos_counts_w = np.sum(L_w == 1, axis=1)
neg_counts_w = np.sum(L_w == 0, axis=1)
spoken_counts_w = np.sum(L_w != ABSTAIN_w, axis=1)
print("positive counts:", pos_counts_w)
print("negative counts:", neg_counts_w)
print("spoken counts:", spoken_counts_w)
```
▶ What you'll see: each row has only the votes from rules that did not abstain.

```python
mv_w = np.where(pos_counts_w > neg_counts_w, 1, np.where(neg_counts_w > pos_counts_w, 0, ABSTAIN_w))
print("majority-vote labels:", mv_w)
print("truth for checking:", true_w)
print("covered accuracy:", round(np.mean(mv_w[mv_w != ABSTAIN_w] == true_w[mv_w != ABSTAIN_w]), 3))
assert np.array_equal(mv_w, np.array([1, 0, 1, 0, 1, -1]))
```
▶ What you'll see: row 5 stays unknown because one positive and one negative vote tie.

```python
plt.figure(figsize=(5, 3))
plt.bar(np.arange(len(texts_w)) - 0.18, pos_counts_w, width=0.36, label="positive votes", color="seagreen")
plt.bar(np.arange(len(texts_w)) + 0.18, neg_counts_w, width=0.36, label="negative votes", color="indianred")
plt.title("2: majority vote ignores abstentions")
plt.xlabel("example")
plt.ylabel("vote count")
plt.legend()
plt.show()
```
▶ What you'll see: rows with a taller green bar become positive, taller red bars become negative, and equal bars tie.

*Why it's done this way:* abstentions are excluded from both numerator and denominator because they contain no class evidence. Majority vote is a transparent baseline, but it assumes every spoken rule has equal reliability — a strong assumption we relax next.

### 4. Weighted voting and a tiny label model

A Snorkel-style label model treats labeling functions as noisy annotators with different reliabilities. In the simplest version, each rule gets a weight $w_k$ related to its accuracy, and a row's positive probability is the positive spoken weight divided by total spoken weight. A reliable positive rule should count more than a broad, noisy rule.

```python
labeled_idx_w = np.array([0, 1, 2, 3])  # a tiny development set used only to estimate rule reliability.
weights_w = []
for k_w in range(L_w.shape[1]):
    spoke_dev_w = L_w[labeled_idx_w, k_w] != ABSTAIN_w
    if np.sum(spoke_dev_w) == 0:
        weights_w.append(0.5)  # no dev evidence: neutral weak weight.
    else:
        acc_w = np.mean(L_w[labeled_idx_w[spoke_dev_w], k_w] == true_w[labeled_idx_w[spoke_dev_w]])
        weights_w.append(0.5 + acc_w)  # map accuracy 0..1 to weights 0.5..1.5.
weights_w = np.array(weights_w)
print("estimated LF weights:", np.round(weights_w, 3))
assert np.allclose(np.round(weights_w, 3), [1.5, 1.5, 0.5, 0.5, 1.5])
```
▶ What you'll see: rules that were correct when they spoke on the dev set get larger weights; unseen rules stay neutral.

```python
pos_weight_w = np.sum((L_w == 1) * weights_w, axis=1)
neg_weight_w = np.sum((L_w == 0) * weights_w, axis=1)
total_weight_w = pos_weight_w + neg_weight_w
prob_pos_w = np.divide(pos_weight_w, total_weight_w, out=np.full_like(pos_weight_w, 0.5, dtype=float), where=total_weight_w > 0)
print("weighted positive probability:", np.round(prob_pos_w, 3))
print("row 5 pos/neg weights:", round(pos_weight_w[5], 3), round(neg_weight_w[5], 3))
assert round(float(prob_pos_w[5]), 3) == 0.75
```
▶ What you'll see: the formerly tied row 5 becomes 0.75 positive because the broad `plan` rule has a higher estimated weight than the unseen family rule.

```python
plt.figure(figsize=(5, 3))
plt.bar(np.arange(len(texts_w)), prob_pos_w, color="steelblue")
plt.axhline(0.5, color="black", linestyle="--")
plt.title("3: weighted label-model probability")
plt.xlabel("example")
plt.ylabel("P(positive)")
plt.ylim(0, 1)
plt.show()
```
▶ What you'll see: confident examples sit near 0 or 1, while conflicts land between the extremes.

*Why it's done this way:* the weighted fraction is a probability-like score because it normalizes by total spoken weight. Reliability does not erase dissent; it changes how strongly each vote moves the posterior away from 0.5.

### 5. Debugging correlated rules and drift

Weak labels are code, so they can share hidden assumptions and drift when data changes. Two rules that both key off the same phrase are not independent annotators; their agreement should not double confidence. The practical workflow is to inspect correlations, coverage shifts, and conflict shifts before trusting weak labels for model training.

```python
L_corr_w = L_w.copy()
L_corr_w = np.column_stack([L_corr_w, L_w[:, 0]])  # duplicate the offer rule to mimic correlated LFs.
spoken_pair_w = (L_corr_w[:, 0] != ABSTAIN_w) & (L_corr_w[:, -1] != ABSTAIN_w)
agreement_w = np.mean(L_corr_w[spoken_pair_w, 0] == L_corr_w[spoken_pair_w, -1])
print("duplicate-rule agreement:", round(float(agreement_w), 3))
print("original columns:", L_w.shape[1], "after duplicate:", L_corr_w.shape[1])
assert round(float(agreement_w), 3) == 1.0
```
▶ What you'll see: the duplicate agrees perfectly, which would falsely look like extra evidence.

```python
new_texts_w = np.array(["free shipping plan", "team dinner plan", "coupon offer", "project schedule"])
L_new_w = np.array([[lf_w(t_w) for lf_w in lfs_w] for t_w in new_texts_w])
old_cov_w = np.mean(L_w != ABSTAIN_w, axis=0)
new_cov_w = np.mean(L_new_w != ABSTAIN_w, axis=0)
print("old coverage:", np.round(old_cov_w, 3))
print("new coverage:", np.round(new_cov_w, 3))
print("coverage shift:", np.round(new_cov_w - old_cov_w, 3))
```
▶ What you'll see: the broad `plan` rule fires more often on the new batch, a warning that its influence changed.

```python
x_w = np.arange(len(lfs_w))
plt.figure(figsize=(6, 3))
plt.bar(x_w - 0.18, old_cov_w, width=0.36, label="old", color="gray")
plt.bar(x_w + 0.18, new_cov_w, width=0.36, label="new", color="darkorange")
plt.title("4: coverage drift by labeling function")
plt.xlabel("labeling function")
plt.ylabel("coverage")
plt.ylim(0, 1)
plt.legend()
plt.show()
```
▶ What you'll see: look for bars that move sharply between old and new batches; those rules need review.

*Why it's done this way:* weak supervision is annotation engineering, not magic. Correlation inflates confidence because repeated evidence is counted twice, and drift changes which parts of the data the rules control. Monitoring these quantities keeps weak labels auditable.

## 🛠️ Setup

```python
import numpy as np # load NumPy for arrays, masks, random toy data, and label-model arithmetic.
import matplotlib.pyplot as plt # load Matplotlib for coverage, conflict, and probability visualizations.
np.random.seed(0) # make all stochastic examples reproducible.

ABSTAIN = -1 # use -1 consistently for a labeling function that declines to vote.

def vote_counts(L): # count positive and negative votes row by row.
    return np.sum(L == 1, axis=1), np.sum(L == 0, axis=1) # return (positive counts, negative counts).

def majority_vote(L): # aggregate weak labels by ignoring abstentions and counting class votes.
    pos, neg = vote_counts(L) # compute class-specific vote counts.
    return np.where(pos > neg, 1, np.where(neg > pos, 0, ABSTAIN)) # ties and no-vote rows remain unknown.

def coverage(L): # measure how often each labeling function emits a non-abstain label.
    return np.mean(L != ABSTAIN, axis=0) # average the spoken indicator down rows.

def row_conflict(L): # mark rows where non-abstaining rules emit both classes.
    return np.array([len(set(row[row != ABSTAIN])) > 1 for row in L]) # a row conflicts only if both 0 and 1 appear.

def weighted_probs(L, weights): # convert weighted weak votes into P(y=1).
    weights = np.asarray(weights, dtype=float) # ensure arithmetic uses floating-point weights.
    pos_weight = np.sum((L == 1) * weights, axis=1) # add weights of positive votes.
    neg_weight = np.sum((L == 0) * weights, axis=1) # add weights of negative votes.
    total = pos_weight + neg_weight # total spoken reliability on each row.
    return np.divide(pos_weight, total, out=np.full(L.shape[0], 0.5), where=total > 0) # no spoken votes mean prior 0.5.

def show_label_matrix(L, title): # draw a compact heatmap for a label matrix.
    plt.figure(figsize=(5, 3)) # create one compact figure.
    plt.imshow(L, cmap="coolwarm", vmin=-1, vmax=1, aspect="auto") # show abstain, negative, and positive distinctly.
    plt.colorbar(label="LF output") # add a legend for the encoded outputs.
    plt.title(title) # add the requested title.
    plt.xlabel("labeling function") # columns are labeling functions.
    plt.ylabel("example") # rows are examples.
    plt.show() # display the figure.
```

### Basic 7 — Convert weighted votes to probabilities

```python
L_b7 = np.array([[1, 1, 0], [0, ABSTAIN, 1], [ABSTAIN, 1, ABSTAIN]]) # define three rows with mixed votes.
```

### Basic 8 — Estimate rule accuracy on a tiny dev set

**Goal.** Use a few trusted labels to estimate LF reliability, because a label model needs some way to know which rules are stronger. We build it in 2 steps.

```python
L_b8 = np.array([[1, ABSTAIN, 1], [0, 0, ABSTAIN], [1, 0, ABSTAIN], [ABSTAIN, 0, 1]]) # create LF outputs.
y_dev_b8 = np.array([1, 0, 1, 0]) # trusted labels for the same rows.
print("dev labels:", y_dev_b8) # inspect the trusted reference.
```
▶ What you'll see: the dev set gives a small accuracy check for each LF.

```python
acc_b8 = [] # collect one accuracy per LF.
for k_b8 in range(L_b8.shape[1]): # loop over LF columns.
    spoke_b8 = L_b8[:, k_b8] != ABSTAIN # keep only rows where this LF voted.
```

### Advanced 5 — Propagate weak-label uncertainty into a tiny model

**Goal.** Fit logistic regression from scratch using soft weak labels, because downstream training should respect label-model probabilities instead of pretending every weak label is clean. We build it in 5 steps.

```python
rng_a5 = np.random.default_rng(15) # create reproducible data.
X_a5 = rng_a5.normal(size=(100, 2)) # generate two numeric features.
y_true_a5 = (X_a5[:, 0] + X_a5[:, 1] > 0.2).astype(float) # hidden truth for simulation.
prob_weak_a5 = np.clip(0.2 + 0.6 * y_true_a5 + rng_a5.normal(0, 0.16, size=100), 0.05, 0.95) # noisy soft weak labels.
print("weak-label mean:", round(float(np.mean(prob_weak_a5)), 3)) # inspect average soft target.
```
▶ What you'll see: weak labels are probabilities, not just zeros and ones.

```python
w_a5 = np.zeros(2) # initialize logistic weights.
b_a5 = 0.0 # initialize bias.
lr_a5 = 0.4 # choose learning rate for the tiny demo.
for step_a5 in range(300): # run gradient descent.
    logits_a5 = X_a5 @ w_a5 + b_a5 # compute linear scores.
    pred_a5 = 1 / (1 + np.exp(-logits_a5)) # sigmoid probabilities.
    err_a5 = pred_a5 - prob_weak_a5 # gradient residual for soft cross-entropy targets.
    w_a5 -= lr_a5 * (X_a5.T @ err_a5) / len(X_a5) # update weights.
    b_a5 -= lr_a5 * np.mean(err_a5) # update bias.
print("learned weights:", np.round(w_a5, 3), "bias:", round(float(b_a5), 3)) # inspect fitted model.
```
▶ What you'll see: both feature weights become positive because the hidden rule depends on their sum.

```python
pred_soft_a5 = 1 / (1 + np.exp(-(X_a5 @ w_a5 + b_a5))) # compute trained probabilities.
loss_a5 = -np.mean(prob_weak_a5 * np.log(pred_soft_a5) + (1 - prob_weak_a5) * np.log(1 - pred_soft_a5)) # soft-label cross-entropy.
acc_a5 = np.mean((pred_soft_a5 >= 0.5).astype(float) == y_true_a5) # evaluate against simulated truth.
print("soft-label loss:", round(float(loss_a5), 3)) # inspect fit to weak labels.
print("simulated true accuracy:", round(float(acc_a5), 3)) # inspect only because truth is synthetic.
assert acc_a5 > 0.75 # verify the soft weak labels trained a useful separator.
```
▶ What you'll see: a simple model trained on soft weak labels recovers much of the true boundary.
