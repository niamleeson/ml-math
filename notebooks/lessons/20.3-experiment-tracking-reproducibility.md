# 20.3 — Experiment Tracking & Reproducibility

Experiment tracking is the habit of turning every model result into an auditable record: data version, code version, config, seed, metrics, and artifact fingerprint. In this lesson, we build a tiny in-memory tracker from scratch so a "good run" is not a mystery, a rerun can be checked against tolerance, and model selection compares like with like.

## 📖 Concept walkthrough — build each idea from scratch

Before the worked examples, we build experiment tracking one idea at a time. Run each cell in order and inspect the printed records — the goal is to make reproducibility feel like small, concrete arithmetic instead of a tool name. This walkthrough is self-contained and uses a `_w` suffix on variables so it never clashes with the examples below.

```python
import numpy as np  # arrays, seeded randomness, and toy training loops.
import matplotlib.pyplot as plt  # visual checks for run metrics and uncertainty bands.
import hashlib, json  # stable config/data/artifact fingerprints without external tracking tools.
np.random.seed(0)  # fix legacy NumPy randomness for any cell that uses it directly.
```
▶ What you'll see: the printed values or plot make this intermediate state inspectable.

### 1. A run is an immutable scientific claim

A production ML result is not just a metric. It is a tuple like `(data_version, code_version, config, seed, metric, artifact)`. If any component changes, the claim changes too, because the observed score may have come from different data, a different algorithm, a different random draw, or a different saved model.

```python
run_w = {
    "data_version": "data:v1",
    "code_version": "code:linear-trainer@abc123",
    "config": {"lr": 0.08, "epochs": 80, "l2": 0.01},
    "seed": 7,
    "metric": {"val_rmse": 0.817},
    "artifact": "model:fingerprint-placeholder",
}
print("run keys:", list(run_w.keys()))
print("recorded val_rmse:", run_w["metric"]["val_rmse"])
```
▶ What you'll see: the run record names the ingredients needed to believe the metric later.

```python
changed_seed_w = dict(run_w)
changed_seed_w["seed"] = 8
same_claim_w = run_w == changed_seed_w
print("same scientific claim after seed change?", same_claim_w)
assert same_claim_w is False
```
▶ What you'll see: changing only the seed creates a different run claim, even if the code and data names stay fixed.

```python
claim_fields_w = ["data", "code", "config", "seed", "metric", "artifact"]
claim_changed_w = np.array([[0, 0, 0, 1, 0, 0]])
plt.figure(figsize=(5, 1.6))
plt.imshow(claim_changed_w, cmap="Reds", vmin=0, vmax=1, aspect="auto")
plt.xticks(range(len(claim_fields_w)), claim_fields_w, rotation=25, ha="right")
plt.yticks([0], ["seed edit"])
plt.title("1: one changed field makes a new claim")
plt.colorbar(label="changed?")
plt.show()
```
▶ What you'll see: only the seed column lights up, yet that single lineage edit is enough to make a different run claim.

*Why it's done this way:* tracking the full tuple prevents accidental comparisons. A metric without lineage cannot tell whether an improvement came from modeling, data leakage, a changed split, or optimizer luck.

### 2. Seeds make randomness repeatable, not irrelevant

A seed fixes the pseudo-random sequence used to create splits, initialization, and minibatches. That makes a run repeatable, but it does not mean the chosen seed is representative. We first show deterministic data generation, then use the same training routine to show why the seed must be recorded.

```python
def make_regression_w(seed_w, n_w=80):
    rng_w = np.random.default_rng(seed_w)
    x_w = rng_w.normal(size=n_w)
    noise_w = 0.15 * rng_w.normal(size=n_w)
    y_w = 1.5 * x_w - 0.4 + noise_w
    return x_w, y_w

x1_w, y1_w = make_regression_w(11)
x2_w, y2_w = make_regression_w(11)
print("same x from same seed?", np.allclose(x1_w, x2_w))
print("first three y:", np.round(y1_w[:3], 3))
assert np.allclose(y1_w, y2_w)
```
▶ What you'll see: the same seed reproduces the same synthetic dataset exactly.

```python
def train_linear_w(seed_w, lr_w=0.08, epochs_w=80, l2_w=0.01):
    x_w, y_w = make_regression_w(seed_w)
    split_w = 60
    xtr_w, ytr_w = x_w[:split_w], y_w[:split_w]
    xval_w, yval_w = x_w[split_w:], y_w[split_w:]
    w_w, b_w = 0.0, 0.0
    losses_w = []
    for _ in range(epochs_w):
        pred_w = w_w * xtr_w + b_w
        err_w = pred_w - ytr_w
        w_w -= lr_w * (2 * np.mean(err_w * xtr_w) + 2 * l2_w * w_w)
        b_w -= lr_w * (2 * np.mean(err_w))
        losses_w.append(float(np.mean(err_w ** 2)))
    val_w = float(np.sqrt(np.mean((w_w * xval_w + b_w - yval_w) ** 2)))
    return {"w": w_w, "b": b_w, "val_rmse": val_w, "losses": losses_w}

fit_w = train_linear_w(seed_w=11)
print("learned w,b:", round(fit_w["w"], 3), round(fit_w["b"], 3))
print("val_rmse:", round(fit_w["val_rmse"], 3))
assert fit_w["val_rmse"] < 0.25
```
▶ What you'll see: the tiny optimizer learns a slope near 1.5 and a small validation RMSE.

```python
repeat_w = train_linear_w(seed_w=11)
other_w = train_linear_w(seed_w=12)
print("rerun same seed:", round(repeat_w["val_rmse"], 6))
print("different seed:", round(other_w["val_rmse"], 6))
assert round(repeat_w["val_rmse"], 12) == round(fit_w["val_rmse"], 12)
```
▶ What you'll see: the repeated seed matches exactly, while another seed gives a different validation score.

```python
seed_compare_w = [fit_w["val_rmse"], repeat_w["val_rmse"], other_w["val_rmse"]]
plt.figure(figsize=(4.8, 3))
plt.bar(["seed 11", "repeat 11", "seed 12"], seed_compare_w, color=["teal", "teal", "gray"])
plt.title("2: same seed repeats, new seed varies")
plt.ylabel("validation RMSE")
plt.show()
```
▶ What you'll see: the two seed-11 bars match exactly, while the seed-12 bar shows seed-to-seed variation.

*Why it's done this way:* deterministic seeding lets us debug and rerun a claim, but seed-to-seed variation still exists; recording the seed preserves the exact path that produced the number.

### 3. Stable hashes give configs and data short identities

A dictionary's printed order is not a safe run identity. We need a canonical representation: sort keys, serialize to JSON, and hash the bytes. Then equivalent configs receive the same ID, while a real hyperparameter change receives a different ID.

```python
def stable_hash_w(obj_w, n_w=10):
    blob_w = json.dumps(obj_w, sort_keys=True, separators=(",", ":"))
    return hashlib.sha256(blob_w.encode("utf-8")).hexdigest()[:n_w]

config_a_w = {"epochs": 80, "lr": 0.08, "l2": 0.01}
config_b_w = {"l2": 0.01, "lr": 0.08, "epochs": 80}
print("hash A:", stable_hash_w(config_a_w))
print("hash B:", stable_hash_w(config_b_w))
assert stable_hash_w(config_a_w) == stable_hash_w(config_b_w)
```
▶ What you'll see: changing dictionary order does not change the config hash.

```python
config_c_w = {"epochs": 80, "lr": 0.05, "l2": 0.01}
print("hash old lr:", stable_hash_w(config_a_w))
print("hash new lr:", stable_hash_w(config_c_w))
assert stable_hash_w(config_a_w) != stable_hash_w(config_c_w)
```
▶ What you'll see: changing the learning rate changes the hash, so the run identity changes.

```python
x_w, y_w = make_regression_w(11)
data_summary_w = {"n": int(len(x_w)), "x_mean": round(float(x_w.mean()), 6), "y_mean": round(float(y_w.mean()), 6)}
print("data summary:", data_summary_w)
print("data hash:", stable_hash_w(data_summary_w))
```
▶ What you'll see: even a toy dataset can be named by stable content-derived metadata.

```python
hash_labels_w = ["config A", "config B", "config C"]
hash_values_w = [stable_hash_w(config_a_w), stable_hash_w(config_b_w), stable_hash_w(config_c_w)]
hash_match_w = np.equal.outer(hash_values_w, hash_values_w).astype(int)
plt.figure(figsize=(4, 3))
plt.imshow(hash_match_w, cmap="Greens", vmin=0, vmax=1)
plt.xticks(range(3), hash_labels_w, rotation=25, ha="right")
plt.yticks(range(3), hash_labels_w)
plt.title("3: canonical hash matches")
plt.colorbar(label="same hash?")
plt.show()
```
▶ What you'll see: configs A and B match despite key order, while the changed learning-rate config does not.

*Why it's done this way:* hashes are compact pointers to exact content. Sorting keys and removing whitespace makes the ID depend on the meaning of the config, not on incidental formatting.

### 4. A mini tracker logs runs and compares like with like

Now we build the simplest possible tracker: a list of dictionaries in memory. Each run receives a deterministic ID from its lineage fields, and comparison selects the lowest validation RMSE rather than the most recent run.

```python
def log_run_w(tracker_w, data_version_w, code_version_w, config_w, seed_w):
    fit_w = train_linear_w(seed_w=seed_w, lr_w=config_w["lr"], epochs_w=config_w["epochs"], l2_w=config_w["l2"])
    identity_w = {"data": data_version_w, "code": code_version_w, "config": config_w, "seed": seed_w}
    run_w = {
        "run_id": stable_hash_w(identity_w, n_w=12),
        "data_version": data_version_w,
        "code_version": code_version_w,
        "config_hash": stable_hash_w(config_w),
        "config": dict(config_w),
        "seed": seed_w,
        "val_rmse": fit_w["val_rmse"],
        "model": np.array([fit_w["w"], fit_w["b"]]),
    }
    tracker_w.append(run_w)
    return run_w

tracker_w = []
base_config_w = {"lr": 0.08, "epochs": 80, "l2": 0.01}
first_run_w = log_run_w(tracker_w, "data:v1", "code:abc123", base_config_w, seed_w=11)
print("logged run_id:", first_run_w["run_id"])
print("tracker length:", len(tracker_w))
assert len(tracker_w) == 1
```
▶ What you'll see: one run is stored with both its metric and its lineage fields.

```python
for lr_w in [0.03, 0.08, 0.14]:
    log_run_w(tracker_w, "data:v1", "code:abc123", {"lr": lr_w, "epochs": 80, "l2": 0.01}, seed_w=11)
rmse_by_run_w = np.array([r_w["val_rmse"] for r_w in tracker_w])
best_idx_w = int(np.argmin(rmse_by_run_w))
print("val_rmse by logged run:", np.round(rmse_by_run_w, 4))
print("best run index:", best_idx_w, "best lr:", tracker_w[best_idx_w]["config"]["lr"])
assert rmse_by_run_w[best_idx_w] == np.min(rmse_by_run_w)
```
▶ What you'll see: the selected run is the minimum validation RMSE, not automatically the last appended record.

```python
plt.figure(figsize=(5, 3))
plt.plot(np.arange(len(rmse_by_run_w)), rmse_by_run_w, marker="o", color="teal")
plt.scatter([best_idx_w], [rmse_by_run_w[best_idx_w]], color="red", zorder=3, label="best")
plt.title("4: metric vs tracked run")
plt.xlabel("run index")
plt.ylabel("validation RMSE")
plt.legend()
plt.show()
```
▶ What you'll see: each point is a logged run; the red point marks the run chosen by validation score.

*Why it's done this way:* a tracker is useful because it separates memory from judgment. It stores every candidate, then the selection rule can be inspected and repeated later.

### 5. Seed variance needs means and confidence intervals

A single seed can win by luck. To make a result reproducible, run the same config over several seeds and summarize the distribution. A simple 95 percent interval for the mean is `mean ± 1.96 * std / sqrt(n)`.

```python
seeds_w = np.arange(20, 30)
seed_scores_w = np.array([train_linear_w(int(s_w), lr_w=0.08, epochs_w=80, l2_w=0.01)["val_rmse"] for s_w in seeds_w])
mean_w = float(seed_scores_w.mean())
std_w = float(seed_scores_w.std(ddof=1))
ci_w = 1.96 * std_w / np.sqrt(len(seed_scores_w))
print("seed RMSEs:", np.round(seed_scores_w, 4))
print("mean ± 95 percent half-width:", round(mean_w, 4), "+/-", round(ci_w, 4))
assert len(seed_scores_w) == 10
```
▶ What you'll see: validation RMSE moves across seeds even though the config is unchanged.

```python
plt.figure(figsize=(5, 3))
plt.plot(seeds_w, seed_scores_w, marker="o", color="slateblue", label="seed RMSE")
plt.axhline(mean_w, color="black", linestyle="--", label="mean")
plt.fill_between(seeds_w, mean_w - ci_w, mean_w + ci_w, color="slateblue", alpha=0.18, label="95 percent mean band")
plt.title("5: seed variance band")
plt.xlabel("seed")
plt.ylabel("validation RMSE")
plt.legend()
plt.show()
```
▶ What you'll see: points wiggle around the mean, and the shaded band shows uncertainty in the average score.

*Why it's done this way:* reporting only the best seed rewards noise. The mean and interval make the reproducible object the config's expected behavior, not one lucky draw.

### 6. Artifact fingerprints and reproducibility gaps

The artifact is the trained object we would hand to serving. We fingerprint the learned weights in memory, rerun the same recipe, and compare the new metric to the recorded metric with a tolerance. The tolerance matters because some systems have small numeric drift, but the drift must be named.

```python
def artifact_hash_w(model_w, n_w=12):
    arr_w = np.asarray(model_w, dtype=np.float64)
    return hashlib.sha256(arr_w.tobytes()).hexdigest()[:n_w]

artifact_run_w = log_run_w([], "data:v1", "code:abc123", base_config_w, seed_w=42)
artifact_id_w = artifact_hash_w(artifact_run_w["model"])
print("model weights:", np.round(artifact_run_w["model"], 6))
print("artifact hash:", artifact_id_w)
assert len(artifact_id_w) == 12
```
▶ What you'll see: the numeric weights get a short fingerprint suitable for a run record.

```python
rerun_w = log_run_w([], "data:v1", "code:abc123", base_config_w, seed_w=42)
gap_w = rerun_w["val_rmse"] - artifact_run_w["val_rmse"]
print("recorded metric:", round(artifact_run_w["val_rmse"], 8))
print("rerun metric:", round(rerun_w["val_rmse"], 8))
print("reproducibility gap:", round(gap_w, 8))
assert abs(gap_w) <= 0.005
assert artifact_hash_w(rerun_w["model"]) == artifact_id_w
```
▶ What you'll see: the same seed and config reproduce both the metric and the artifact fingerprint.

```python
validation_w = 0.824
test_once_w = 0.801
gap_test_w = validation_w - test_once_w
print("validation-selected score:", validation_w)
print("one-time test score:", test_once_w)
print("observed validation-test gap:", round(gap_test_w, 3))
assert round(gap_test_w, 3) == 0.023
```
▶ What you'll see: once validation selects the run, the test metric is reported once, and the observed gap is 0.023.

```python
artifact_match_w = artifact_hash_w(rerun_w["model"]) == artifact_id_w
plt.figure(figsize=(4.8, 3))
plt.bar(["|rerun gap|", "tolerance", "artifact match"], [abs(gap_w), 0.005, float(artifact_match_w)], color=["teal", "gray", "seagreen"])
plt.title("6: metric and artifact reproducibility")
plt.ylabel("gap or pass flag")
plt.show()
```
▶ What you'll see: the metric gap is below tolerance, and the artifact-match flag is 1 for an exact fingerprint match.

*Why it's done this way:* fingerprints make artifacts auditable, and reproducibility gaps turn reruns into pass/fail checks. The test metric is kept out of selection so it remains an honest final estimate.

### ✍️ Toy 1 · A changed run field makes a new claim

Represent a run as numeric ingredients. Changing only the seed flips one field, so the run is no
longer the same scientific claim.

```python
import numpy as np
import matplotlib.pyplot as plt

t1_rng = np.random.default_rng(0)                # seeded generator for reproducibility.
t1_claim = np.array([101, 202, 303, 7, 817, 909]) # data, code, config, seed, metric, artifact  # -> [101 202 303   7 817 909]
t1_changed_claim = t1_claim.copy()               # copy before editing              # -> [101 202 303   7 817 909]
t1_changed_claim[3] = 8                          # change only the seed             # -> 8
t1_changed_mask = t1_claim != t1_changed_claim   # field-wise difference            # -> [False False False  True False False]
print("changed fields:", t1_changed_mask.tolist())             # -> [False, False, False, True, False, False]
t1_changed_count = int(t1_changed_mask.sum())    # number of edited ingredients     # -> 1
print("changed count:", t1_changed_count)                      # -> 1
t1_same_claim = np.array_equal(t1_claim, t1_changed_claim)      # exact claim match    # -> False
print("same claim?", bool(t1_same_claim))                      # -> False
assert t1_changed_count == 1 and not t1_same_claim

plt.figure(figsize=(5.0, 1.8))
plt.imshow(t1_changed_mask.reshape(1, -1), cmap="Reds", vmin=0, vmax=1, aspect="auto")
plt.xticks(range(6), ["data", "code", "config", "seed", "metric", "artifact"], rotation=25, ha="right")
plt.yticks([0], ["edit"])
plt.title("Toy 1 · one field changed")
plt.show()
plt.close()
```
▶ What you'll see: only the seed column lights up, yet the claim comparison is false.

### ✍️ Toy 2 · Seeds reproduce random draws exactly

The same seed gives the same pseudo-random sequence. A different seed gives a different sequence, so
it must be logged.

```python
import numpy as np

t2_rng = np.random.default_rng(0)                # first seeded generator.
t2_repeat_rng = np.random.default_rng(0)         # same seed again.
t2_other_rng = np.random.default_rng(1)          # different seed.
t2_draw_a = t2_rng.integers(0, 10, size=5)       # first draw                       # -> [8 6 5 2 3]
print("seed 0 draw:", t2_draw_a.tolist())                     # -> [8, 6, 5, 2, 3]
t2_draw_b = t2_repeat_rng.integers(0, 10, size=5)               # repeat draw          # -> [8 6 5 2 3]
print("repeat seed 0 draw:", t2_draw_b.tolist())               # -> [8, 6, 5, 2, 3]
t2_draw_c = t2_other_rng.integers(0, 10, size=5)                # other-seed draw      # -> [4 5 7 9 0]
print("seed 1 draw:", t2_draw_c.tolist())                     # -> [4, 5, 7, 9, 0]
t2_same_seed_match = np.array_equal(t2_draw_a, t2_draw_b)       # reproducible?        # -> True
t2_other_seed_match = np.array_equal(t2_draw_a, t2_draw_c)      # same as other seed?  # -> False
print("same/different matches:", bool(t2_same_seed_match), bool(t2_other_seed_match)) # -> True False
assert t2_same_seed_match and not t2_other_seed_match

plt.figure(figsize=(5.0, 2.6))
plt.imshow(np.vstack([t2_draw_a, t2_draw_b, t2_draw_c]), cmap="Blues", aspect="auto")
plt.yticks([0, 1, 2], ["seed 0", "repeat 0", "seed 1"])
plt.xticks(range(5), range(5))
plt.title("Toy 2 · seeded sequences")
plt.colorbar(label="draw")
plt.show()
plt.close()
```
▶ What you'll see: the first two rows match exactly; the different seed row does not.

### ✍️ Toy 3 · Canonical fingerprints ignore config order

Sort numeric config rows by key before fingerprinting. Equivalent rows then share an ID, while a real
hyperparameter change gets a new ID.

```python
import numpy as np

t3_rng = np.random.default_rng(0)                # seeded generator for reproducibility.
t3_config_a = np.array([[1, 80], [2, 8], [3, 1]]) # key/value rows                  # -> [[ 1 80] [ 2  8] [ 3  1]]
t3_config_b = np.array([[3, 1], [1, 80], [2, 8]]) # same rows, different order      # -> [[ 3  1] [ 1 80] [ 2  8]]
t3_config_c = np.array([[1, 80], [2, 5], [3, 1]]) # changed learning-rate code      # -> [[ 1 80] [ 2  5] [ 3  1]]
t3_order_b = np.argsort(t3_config_b[:, 0])       # canonical row order for B        # -> [1 2 0]
print("order for B:", t3_order_b.tolist())                    # -> [1, 2, 0]
t3_sorted_a = t3_config_a[np.argsort(t3_config_a[:, 0])]        # canonical A          # -> [[ 1 80] [ 2  8] [ 3  1]]
t3_sorted_b = t3_config_b[t3_order_b]                           # canonical B          # -> [[ 1 80] [ 2  8] [ 3  1]]
t3_sorted_c = t3_config_c[np.argsort(t3_config_c[:, 0])]        # canonical C          # -> [[ 1 80] [ 2  5] [ 3  1]]
t3_primes = np.array([3, 5, 7])                 # tiny fingerprint weights          # -> [3 5 7]
t3_fingerprint_a = int(np.sum(t3_sorted_a[:, 1] * t3_primes))   # ID for A             # -> 287
t3_fingerprint_b = int(np.sum(t3_sorted_b[:, 1] * t3_primes))   # ID for B             # -> 287
t3_fingerprint_c = int(np.sum(t3_sorted_c[:, 1] * t3_primes))   # ID for C             # -> 272
print("fingerprints:", t3_fingerprint_a, t3_fingerprint_b, t3_fingerprint_c) # -> 287 287 272
assert t3_fingerprint_a == t3_fingerprint_b and t3_fingerprint_a != t3_fingerprint_c

t3_ids = np.array([t3_fingerprint_a, t3_fingerprint_b, t3_fingerprint_c])
t3_match = (t3_ids[:, None] == t3_ids[None, :]).astype(int)      # pairwise match matrix # -> [[1 1 0] [1 1 0] [0 0 1]]
plt.figure(figsize=(4.0, 3.0))
plt.imshow(t3_match, cmap="Greens", vmin=0, vmax=1)
plt.xticks(range(3), ["A", "B", "C"])
plt.yticks(range(3), ["A", "B", "C"])
plt.title("Toy 3 · fingerprint matches")
plt.colorbar(label="same ID?")
plt.show()
plt.close()
```
▶ What you'll see: A and B match despite order, while C gets a different fingerprint.

### ✍️ Toy 4 · A tracker selects the best metric, not the latest run

A tiny tracker table stores learning rates and validation RMSEs. Selection is `argmin`, not the final
row.

```python
import numpy as np

t4_rng = np.random.default_rng(0)                # seeded generator for reproducibility.

print("best lr/rmse:", t4_best_lr, t4_best_rmse)                # -> 0.08 0.79
assert t4_best_idx == 1 and t4_best_rmse == 0.79

plt.figure(figsize=(4.8, 2.8))
plt.plot(t4_run_ids, t4_val_rmse, marker="o", color="teal")
plt.scatter([t4_run_ids[t4_best_idx]], [t4_best_rmse], color="crimson", s=90, label="selected")
plt.xlabel("run id")

plt.title("Toy 4 · best tracked run")
plt.legend()
plt.show()
plt.close()
```
▶ What you'll see: the red selected point is the lowest RMSE, not the last run id.

### ✍️ Toy 5 · Seed variance needs a mean and confidence band

Summarize several seed scores with a mean and a simple 95% half-width `1.96 * std / sqrt(n)`.

```python
import numpy as np

t5_rng = np.random.default_rng(0)                # seeded generator for reproducibility.
```

## 🛠️ Setup

```python
import numpy as np  # NumPy gives us arrays, deterministic random generators, and toy optimizers.
import matplotlib.pyplot as plt  # Matplotlib gives us inspectable metric curves and uncertainty bands.
import hashlib, json  # hashlib and json let us build stable tracker IDs from scratch.
np.random.seed(0)  # Fix global randomness for any example that uses NumPy's legacy random state.

def stable_hash(obj, n=10):  # Make a short deterministic hash for configs, data summaries, and run identities.
    blob = json.dumps(obj, sort_keys=True, separators=(",", ":"))  # Canonical JSON removes formatting and key-order noise.
    return hashlib.sha256(blob.encode("utf-8")).hexdigest()[:n]  # Return a readable prefix of a cryptographic digest.

def make_toy_data(seed, n=80):  # Create one reproducible regression dataset for experiment examples.
    rng = np.random.default_rng(seed)  # Use a local generator so the seed is explicit and isolated.
    x = rng.normal(size=n)  # Draw one feature column.
    y = 1.5 * x - 0.4 + 0.15 * rng.normal(size=n)  # Build a noisy linear target with known structure.
    return x, y  # Return arrays without writing anything to disk.

def train_toy(seed, lr=0.08, epochs=80, l2=0.01):  # Train a tiny linear model and return metrics plus artifact weights.
    x, y = make_toy_data(seed)  # Generate data from the recorded seed.
    split = 60  # Use the first 60 points for training and the rest for validation.
    xtr, ytr = x[:split], y[:split]  # Slice training inputs and targets.
    xval, yval = x[split:], y[split:]  # Slice validation inputs and targets.
    w, b = 0.0, 0.0  # Initialize a one-feature linear model.
    losses = []  # Store training MSE so convergence can be inspected.
    for _ in range(epochs):  # Run deterministic full-batch gradient descent.
        pred = w * xtr + b  # Predict training targets.
        err = pred - ytr  # Compute residuals.
        w -= lr * (2 * np.mean(err * xtr) + 2 * l2 * w)  # Update slope with L2 shrinkage.
        b -= lr * (2 * np.mean(err))  # Update intercept.
        losses.append(float(np.mean(err ** 2)))  # Track training loss in memory.
    val_rmse = float(np.sqrt(np.mean((w * xval + b - yval) ** 2)))  # Score validation RMSE.
    return {"w": w, "b": b, "losses": losses, "val_rmse": val_rmse, "artifact": np.array([w, b])}  # Return the run result.

def artifact_hash(weights, n=12):  # Fingerprint a trained artifact using its exact in-memory bytes.
    arr = np.asarray(weights, dtype=np.float64)  # Force a stable numeric dtype before hashing.
    return hashlib.sha256(arr.tobytes()).hexdigest()[:n]  # Return a short artifact ID.

def log_run(tracker, data_version, code_version, config, seed):  # Append one run record to an in-memory tracker.
    result = train_toy(seed, lr=config["lr"], epochs=config["epochs"], l2=config["l2"])  # Execute the recorded recipe.
    identity = {"data": data_version, "code": code_version, "config": config, "seed": seed}  # Define the run identity tuple.
    record = {"run_id": stable_hash(identity, 12), "data_version": data_version, "code_version": code_version, "config_hash": stable_hash(config), "config": dict(config), "seed": seed, "val_rmse": result["val_rmse"], "artifact_hash": artifact_hash(result["artifact"]), "artifact": result["artifact"]}  # Store lineage, metric, and artifact pointer.
    tracker.append(record)  # Keep the run in memory.
    return record  # Return the new record for immediate inspection.
```
▶ What you'll see: the printed values or plot make this intermediate state inspectable.
