# 7.19 — Instance & Panoptic Segmentation

Instance segmentation adds object identity to semantic pixels: not just "person is here," but "this is person 1 and that is person 2." Panoptic segmentation then combines countable **things** (instances such as people and cars) with amorphous **stuff** (sky, road, grass) into one non-overlapping owner map where every pixel has exactly one final label.

Before the terse worked examples, we build instance and panoptic segmentation one idea at a time. ### 1. Semantic masks say what; instance masks say which object

A semantic segmentation map stores one class label per pixel. That is enough to say "class 1 appears in four pixels," but it is not enough to say whether those four pixels are one object or several. Instance segmentation adds an identity layer: two regions can share the same class while remaining separate objects.

```python
semantic_w = np.array([[0, 0, 1],
                       [0, 1, 1],
                       [2, 2, 1]])  # 0=background, 1=person-like thing, 2=road-like stuff.
print("semantic mask:\n", semantic_w)  # inspect the class-only owner map.
print("unique class labels:", np.unique(semantic_w))  # semantic output has classes, not instance ids.
print("class-1 pixel count:", int(np.sum(semantic_w == 1)))  # four pixels belong to class 1.
assert int(np.sum(semantic_w == 1)) == 4  # concrete number from the lesson block.
```
▶ What you'll see: a 3×3 class map with four pixels labeled `1`, but no identifier separating object copies.

```python
inst1_w = np.array([[0, 0, 1],
                    [0, 1, 0],
                    [0, 0, 0]], dtype=bool)  # first class-1 object.
inst2_w = np.array([[0, 0, 0],
                    [0, 0, 1],
                    [0, 0, 1]], dtype=bool)  # second class-1 object.
instance_id_w = np.zeros_like(semantic_w)  # start with no object owner.
instance_id_w[inst1_w] = 1  # assign object identity 1.
instance_id_w[inst2_w] = 2  # assign object identity 2.
print("instance-id map:\n", instance_id_w)  # now class-1 pixels have ownership.
print("areas:", int(inst1_w.sum()), int(inst2_w.sum()))  # each instance has its own area.
assert int(inst1_w.sum() + inst2_w.sum()) == 4  # identities partition the same four class-1 pixels.
```
▶ What you'll see: class `1` pixels are split into two owners, `1` and `2`, even though they share the same semantic class.

```python
fig, ax = plt.subplots(1, 2, figsize=(6, 2.7))  # compare class-only and identity-aware views.
ax[0].imshow(semantic_w, cmap="viridis", vmin=0, vmax=2); ax[0].set_title("semantic: what")  # class labels.
ax[1].imshow(instance_id_w, cmap="tab10", vmin=0, vmax=2); ax[1].set_title("instance: which")  # object ids.
for a in ax:
    a.set_xticks([]); a.set_yticks([])  # keep focus on regions.
plt.suptitle("1: class labels do not imply object identity"); plt.show()
```
▶ What you'll see: the same class-1 pixels become two separate colored regions once identity is added.

*Why it's done this way: semantic labels answer a per-pixel classification question, so same-class pixels naturally merge; instance segmentation needs an additional discrete owner variable because counting objects is impossible from class labels alone.*

### 2. Mask IoU compares pixel sets, not boxes

Mask IoU is the pixel version of intersection-over-union. For two binary masks, the intersection is the number of pixels both masks claim, and the union is the number of pixels claimed by either mask. This matters because boxes can overlap perfectly while the silhouettes inside them differ.

```python
gt_w = np.array([[0, 0, 1],
                 [0, 1, 1],
                 [0, 0, 1]], dtype=bool)  # ground-truth class-1 mask.
pred_w = np.array([[0, 0, 1],
                   [0, 1, 1],
                   [0, 0, 0]], dtype=bool)  # prediction misses one bottom pixel.
inter_w = np.logical_and(gt_w, pred_w)  # pixels both masks include.
union_w = np.logical_or(gt_w, pred_w)  # pixels either mask includes.
print("intersection pixels:", int(inter_w.sum()))  # 3.
print("union pixels:", int(union_w.sum()))  # 4.
mask_iou_w = inter_w.sum() / union_w.sum()  # IoU = |A∩B| / |A∪B|.
print("mask IoU:", round(float(mask_iou_w), 3))  # 0.75.
assert round(float(mask_iou_w), 3) == 0.750  # concrete lesson number.
```
▶ What you'll see: the prediction gets 3 of 4 relevant pixels right, so mask IoU is `0.75`.

```python
viz_w = gt_w.astype(int) + 2 * pred_w.astype(int)  # 0 neither, 1 GT only, 2 pred only, 3 both.
plt.figure(figsize=(3.2, 3))  # compact pixel-set visualization.
plt.imshow(viz_w, cmap="viridis", vmin=0, vmax=3)  # colors reveal overlap categories.
plt.colorbar(label="0 neither, 1 GT, 2 pred, 3 both")  # decode the overlap map.
plt.title("2: mask IoU categories"); plt.xticks([]); plt.yticks([]); plt.show()
```
▶ What you'll see: three pixels are shared and one ground-truth pixel is missed.

*Why it's done this way: masks are sets of pixels, so the natural similarity is set overlap; dividing by the union penalizes both false positives and false negatives on the same 0-to-1 scale.*

### 3. RoIAlign keeps boundaries from jumping

Mask R-CNN predicts a small mask inside each region of interest (RoI). If feature coordinates are rounded to integer cells, a boundary can shift before the mask head ever sees it. RoIAlign avoids that crude jump by interpolating feature values at fractional coordinates.

```python
feature_line_w = np.array([4., 10., 14., 20.])  # one-dimensional feature samples.
x_w = 1.5  # fractional RoI sample position halfway between index 1 and index 2.
left_w = int(np.floor(x_w))  # left grid point.
right_w = left_w + 1  # right grid point.
alpha_w = x_w - left_w  # interpolation weight for the right value.
aligned_w = (1 - alpha_w) * feature_line_w[left_w] + alpha_w * feature_line_w[right_w]  # linear interpolation.
pooled_w = feature_line_w[left_w]  # coarse pooling by rounding/flooring.
print("RoIAlign value:", aligned_w)  # 12.
print("rounded pooling value:", pooled_w)  # 10.
print("alignment error:", aligned_w - pooled_w)  # 2.
assert aligned_w == 12.0 and pooled_w == 10.0 and aligned_w - pooled_w == 2.0  # lesson numbers.
```
▶ What you'll see: halfway interpolation gives `12`, while rounding down gives `10`, a two-feature-unit boundary error.

```python
plt.figure(figsize=(5, 3))  # show the feature line and the fractional sample.
plt.plot(np.arange(len(feature_line_w)), feature_line_w, marker="o", color="steelblue")  # feature samples.
plt.scatter([x_w], [aligned_w], color="seagreen", s=90, label="RoIAlign 12")  # interpolated value.
plt.scatter([left_w], [pooled_w], color="crimson", s=70, label="rounded 10")  # rounded value.
plt.title("3: fractional RoI sample"); plt.xlabel("feature coordinate"); plt.ylabel("feature value")
plt.legend(); plt.show()
```
▶ What you'll see: the green point lies between feature samples; the red rounded point snaps to the left sample.

*Why it's done this way: a mask is a boundary-sensitive prediction, so preserving sub-pixel geometry lets the mask head learn from an aligned crop instead of a shifted one.*

### 4. A mask head learns binary silhouettes with cross-entropy

For each matched RoI, Mask R-CNN predicts a probability map inside the proposal. The target for the selected class is a binary silhouette, and binary cross-entropy rewards high probability on foreground pixels and low probability on background pixels.

```python
logits_w = np.array([[ 2.0, -1.0],
                     [ 0.5, -2.0]])  # tiny 2x2 mask-head logits for one RoI.
y_w = np.array([[1., 0.],
                [1., 0.]])  # binary target silhouette inside the RoI.
prob_w = 1 / (1 + np.exp(-logits_w))  # sigmoid turns logits into foreground probabilities.
print("probabilities:\n", np.round(prob_w, 3))  # inspect predicted mask probabilities.
assert round(float(prob_w[0, 0]), 3) == 0.881  # concrete sigmoid value.
```
▶ What you'll see: positive logits become foreground probabilities above 0.5; negative logits become background probabilities below 0.5.

```python
eps_w = 1e-9  # numerical guard for logs.
bce_pixels_w = -(y_w * np.log(prob_w + eps_w) + (1 - y_w) * np.log(1 - prob_w + eps_w))  # per-pixel BCE.
loss_w = float(np.mean(bce_pixels_w))  # average over K x K pixels.
print("per-pixel BCE:\n", np.round(bce_pixels_w, 3))  # inspect pixel penalties.
print("mean mask loss:", round(loss_w, 3))  # one RoI mask loss.
assert round(loss_w, 3) == 0.260  # verified value for this toy RoI.
```
▶ What you'll see: confident correct pixels have small loss, while uncertain foreground/background pixels cost more.

```python
fig, ax = plt.subplots(1, 3, figsize=(7, 2.5))  # compare target, probability, and loss.
for a, M, title in zip(ax, [y_w, prob_w, bce_pixels_w], ["target y", "mask prob", "BCE"]):
    im = a.imshow(M, cmap="viridis")  # visualize each 2x2 map.
    a.set_title(title); a.set_xticks([]); a.set_yticks([])  # compact display.
plt.suptitle("4: binary mask loss inside one RoI"); plt.show()
```
▶ What you'll see: the loss map is largest where probability is least compatible with the binary target.

*Why it's done this way: the sigmoid+BCE pair treats each RoI pixel as a foreground-vs-background decision, which matches the silhouette target and avoids forcing different classes to compete at every mask pixel.*

### 5. Class labels choose the mask channel

Mask R-CNN can predict one binary mask channel per class for the same RoI. The class head decides which channel is trained and used. That means category and geometry meet at the RoI: the object class selects the correct silhouette channel, while the mask itself stays binary.

```python
mask_channels_w = np.array([
    [[0.80, 0.20], [0.70, 0.10]],  # class 0 channel.
    [[0.10, 0.85], [0.20, 0.90]],  # class 1 channel.
    [[0.40, 0.40], [0.40, 0.40]],  # class 2 channel.
])  # shape = classes x K x K.
class_scores_w = np.array([0.10, 0.75, 0.15])  # class-head probabilities for the RoI.
chosen_class_w = int(np.argmax(class_scores_w))  # class label chooses the mask channel.
chosen_mask_w = mask_channels_w[chosen_class_w]  # selected silhouette probabilities.
print("chosen class:", chosen_class_w)  # 1.
print("chosen mask:\n", chosen_mask_w)  # use class-1 channel only.
assert chosen_class_w == 1 and round(float(chosen_mask_w[0, 1]), 2) == 0.85  # selected-channel check.
```
▶ What you'll see: class `1` selects the second 2×2 mask channel.

```python
binary_mask_w = chosen_mask_w >= 0.5  # threshold selected channel into a predicted silhouette.
print("binary selected mask:\n", binary_mask_w.astype(int))  # final RoI mask before placing back in the image.
print("foreground pixels:", int(binary_mask_w.sum()))  # class-selected mask area.
assert int(binary_mask_w.sum()) == 2  # two high-probability pixels in the chosen class channel.
```
▶ What you'll see: only the chosen class channel contributes to the final binary instance mask.

```python
fig, ax = plt.subplots(1, 3, figsize=(7, 2.4))  # visualize all class channels.
for c_w in range(3):
    ax[c_w].imshow(mask_channels_w[c_w], cmap="viridis", vmin=0, vmax=1)  # mask prob for class c.
    ax[c_w].set_title(f"class {c_w}"); ax[c_w].set_xticks([]); ax[c_w].set_yticks([])
plt.suptitle("5: the class head selects one mask channel"); plt.show()
```
▶ What you'll see: different class channels contain different silhouettes, but only the predicted class is used.

*Why it's done this way: predicting class-specific binary masks lets each class learn its own shape statistics, while selecting only the matched class channel prevents unrelated class masks from adding loss noise.*

### 6. Panoptic segmentation assigns one final owner per pixel

Panoptic segmentation merges thing instances and stuff classes into a single non-overlapping map. If two instance masks overlap, the system must resolve the conflict; after resolution, every pixel has exactly one owner: either one thing instance or one stuff label.

```python
h_w, w_w = 4, 4  # tiny image size.
stuff_w = np.zeros((h_w, w_w), dtype=int)  # background stuff class 0 everywhere by default.
stuff_w[2:, :] = 3  # bottom half is stuff class 3, like road.
thing1_w = np.zeros((h_w, w_w), dtype=bool); thing1_w[:2, :2] = True  # first thing mask area 4.
thing2_w = np.zeros((h_w, w_w), dtype=bool); thing2_w[2:, 2:] = True  # second thing mask area 4.
print("thing areas:", int(thing1_w.sum()), int(thing2_w.sum()))  # 4 and 4.
print("stuff pixels before things:", int(np.sum(stuff_w == 3)))  # bottom half.
assert int(thing1_w.sum()) == 4 and int(thing2_w.sum()) == 4  # concrete lesson areas.
```
▶ What you'll see: two 2×2 thing masks and a stuff region that fills the bottom half.

```python
panoptic_w = stuff_w.copy()  # start from stuff labels.
panoptic_w[thing1_w] = 101  # encode thing instance 1 as owner 101.
panoptic_w[thing2_w] = 102  # encode thing instance 2 as owner 102, overriding stuff where needed.
owners_w, counts_w = np.unique(panoptic_w, return_counts=True)  # count final owners.
print("panoptic map:\n", panoptic_w)  # every pixel has one owner id.
print("owner counts:", dict(zip(owners_w.tolist(), counts_w.tolist())))  # area per final owner.
print("instance pixels:", int(thing1_w.sum() + thing2_w.sum()), "background/stuff pixels:", int(panoptic_w.size - thing1_w.sum() - thing2_w.sum()))
assert panoptic_w.size == 16 and int(thing1_w.sum() + thing2_w.sum()) == 8  # 16 total, 8 instance pixels.
```
▶ What you'll see: 8 pixels are owned by things and the remaining 8 by stuff/background labels.

```python
plt.figure(figsize=(3.2, 3))  # visualize the final owner map.
plt.imshow(panoptic_w, cmap="tab20")  # colors represent final panoptic owners.
plt.title("6: one owner per pixel"); plt.xticks([]); plt.yticks([]); plt.show()
```
▶ What you'll see: countable thing instances have their own colors, and leftover pixels keep stuff labels.

*Why it's done this way: panoptic output is a partition of the image, so downstream systems can count objects and still know the semantic class of non-object regions without contradictory overlapping owners.*

### 7. Panoptic Quality separates matching, recognition, and segmentation quality

Panoptic Quality (PQ) evaluates a panoptic prediction by matching predicted and true segments, usually with IoU above 0.5. It combines segmentation quality (how good matched overlaps are) and recognition quality (how many segments were found without false positives or false negatives).

```python
gt_segments_w = [np.array([[1, 1, 0], [1, 0, 0], [0, 0, 0]], dtype=bool),
                 np.array([[0, 0, 0], [0, 0, 1], [0, 1, 1]], dtype=bool)]  # two true segments.
pred_segments_w = [np.array([[1, 1, 0], [1, 0, 0], [0, 0, 0]], dtype=bool),
                   np.array([[0, 0, 0], [0, 0, 1], [0, 1, 0]], dtype=bool),
                   np.array([[0, 0, 0], [0, 0, 0], [1, 0, 0]], dtype=bool)]  # one perfect, one partial, one false positive.
ious_w = np.zeros((len(gt_segments_w), len(pred_segments_w)))  # pairwise IoU table.
for i_w, g_w in enumerate(gt_segments_w):
    for j_w, p_w in enumerate(pred_segments_w):
        inter = np.logical_and(g_w, p_w).sum()  # matched pixels.
        union = np.logical_or(g_w, p_w).sum()  # claimed pixels by either segment.
        ious_w[i_w, j_w] = inter / union if union else 0.0  # safe IoU.
print("pairwise IoU table:\n", np.round(ious_w, 3))  # inspect match candidates.
assert np.allclose(np.round(ious_w[0], 3), [1.000, 0.000, 0.000])  # first segment perfect only with pred 0.
```
▶ What you'll see: one perfect match, one partial match, and one extra predicted segment.

```python
matches_w = [(0, 0, ious_w[0, 0]), (1, 1, ious_w[1, 1])]  # both above 0.5 in this toy example.
tp_w = len(matches_w)  # true positives.
fp_w = len(pred_segments_w) - tp_w  # unmatched predictions.
fn_w = len(gt_segments_w) - tp_w  # unmatched truths.
sum_iou_w = sum(m[2] for m in matches_w)  # segmentation quality numerator.
pq_w = sum_iou_w / (tp_w + 0.5 * fp_w + 0.5 * fn_w)  # panoptic quality.
sq_w = sum_iou_w / tp_w  # average IoU over matched segments.
rq_w = tp_w / (tp_w + 0.5 * fp_w + 0.5 * fn_w)  # recognition quality.
print("TP FP FN:", tp_w, fp_w, fn_w)  # 2,1,0.
print("SQ:", round(sq_w, 3), "RQ:", round(rq_w, 3), "PQ:", round(pq_w, 3))  # decomposition.
assert round(pq_w, 3) == 0.667 and round(rq_w, 3) == 0.800  # concrete metric values.
```
▶ What you'll see: the false-positive segment lowers recognition quality even though matched masks overlap well.

```python
plt.figure(figsize=(4.6, 3))  # metric decomposition plot.
plt.bar(["SQ", "RQ", "PQ"], [sq_w, rq_w, pq_w], color=["steelblue", "orange", "seagreen"])  # compare components.
plt.ylim(0, 1.05); plt.title("7: panoptic quality decomposition"); plt.show()
```
▶ What you'll see: PQ sits below SQ because recognition mistakes also matter.

*Why it's done this way: panoptic segmentation is both a detection task and a pixel-labeling task, so PQ multiplies the cost of missed/extra segments with the quality of the segment overlaps that were correctly recognized.*

### ✍️ Toy 2 · Mask IoU counts pixel-set overlap

Mask IoU is intersection pixels divided by union pixels, not a box calculation.

```python
import numpy as np

t2_rng = np.random.default_rng(0)
t2_gt = np.array([[1, 1, 0], [0, 1, 0], [0, 1, 0]], dtype=bool)

print("ground-truth mask:\n", t2_gt.astype(int))  # -> four pixels
```

### ✍️ Toy 4 · Mask BCE trains binary silhouettes

Inside a matched RoI, sigmoid probabilities are compared to a binary foreground/background mask.

```python
import numpy as np

t4_rng = np.random.default_rng(0)
t4_logits = np.array([[1.0, -2.0], [0.5, -1.0]])
print("logits:\n", t4_logits)  # -> [[1,-2],[0.5,-1]]
t4_target = np.array([[1.0, 0.0], [0.0, 1.0]])
print("target:\n", t4_target)  # -> binary silhouette
t4_prob = 1 / (1 + np.exp(-t4_logits))
print("probabilities:\n", np.round(t4_prob, 3))  # -> [[0.731,0.119],[0.622,0.269]]
t4_eps = 1e-9
t4_bce = -(t4_target * np.log(t4_prob + t4_eps) + (1 - t4_target) * np.log(1 - t4_prob + t4_eps))
print("per-pixel BCE:\n", np.round(t4_bce, 3))  # -> [[0.313,0.127],[0.974,1.313]]
t4_loss = float(t4_bce.mean())
print("mean BCE:", round(t4_loss, 3))  # -> 0.682
assert round(t4_loss, 3) == 0.682

fig, t4_ax = plt.subplots(1, 3, figsize=(7, 2.4))
for t4_axis, t4_map, t4_title in zip(t4_ax, [t4_target, t4_prob, t4_bce], ["target", "prob", "BCE"]):
    t4_axis.imshow(t4_map, cmap="viridis")
    t4_axis.set_title(t4_title)
    t4_axis.set_xticks([])
```

## 🛠️ Setup

```python
import numpy as np # load NumPy for all mask operations, interpolation, losses, and metrics in this lesson.
import matplotlib.pyplot as plt # load Matplotlib for small heatmaps, overlays, bar charts, and debugging plots.
np.random.seed(0) # make synthetic probabilities and scores reproducible.

def show_mask(M, title, cmap="viridis"): # define a compact helper for viewing tiny masks.
    plt.figure(figsize=(3.4, 3)) # create a small figure suitable for notebook cells.
    plt.imshow(M, cmap=cmap, aspect="equal") # draw the mask or label map as colored pixels.
    plt.colorbar(label="value") # include a numeric color scale for interpretation.
    plt.title(title) # label the displayed mask.
    plt.xticks([]) # remove x ticks so pixel regions are easier to see.
    plt.yticks([]) # remove y ticks so pixel regions are easier to see.
    plt.show() # display the figure.

def mask_iou(a, b): # compute pixel-set IoU for two binary masks.
    a = np.asarray(a).astype(bool) # convert the first mask to boolean ownership.
    b = np.asarray(b).astype(bool) # convert the second mask to boolean ownership.
    inter = np.logical_and(a, b).sum() # count pixels claimed by both masks.
    union = np.logical_or(a, b).sum() # count pixels claimed by either mask.
    return 0.0 if union == 0 else float(inter / union) # avoid divide-by-zero for two empty masks.

def sigmoid(x): # convert logits into probabilities.
    return 1 / (1 + np.exp(-x)) # standard logistic function applied elementwise.

def binary_cross_entropy(prob, target): # average BCE for a probability mask and binary target.
    eps = 1e-9 # numerical guard so log never sees exactly 0.
    prob = np.asarray(prob, dtype=float) # ensure floating probabilities.
    target = np.asarray(target, dtype=float) # ensure floating binary targets.
    return float(np.mean(-(target * np.log(prob + eps) + (1 - target) * np.log(1 - prob + eps)))) # average per-pixel BCE.
```

### Advanced 1 — Compute panoptic quality from scratch

**Goal.** Calculate PQ, SQ, and RQ manually, because panoptic evaluation combines mask overlap with detection-style false positives and false negatives. We build it in 4 steps.

```python
gt_a1 = [np.array([[1, 1, 0], [1, 0, 0], [0, 0, 0]], dtype=bool), np.array([[0, 0, 0], [0, 0, 1], [0, 1, 1]], dtype=bool)] # two true segments.
pred_a1 = [np.array([[1, 1, 0], [1, 0, 0], [0, 0, 0]], dtype=bool), np.array([[0, 0, 0], [0, 0, 1], [0, 1, 0]], dtype=bool), np.array([[0, 0, 0], [0, 0, 0], [1, 0, 0]], dtype=bool)] # two useful preds plus one extra.
print("segments GT/pred:", len(gt_a1), len(pred_a1)) # inspect segment counts.
```
▶ What you'll see: there are two ground-truth segments and three predicted segments.

```python
iou_a1 = np.array([[mask_iou(g_a1, p_a1) for p_a1 in pred_a1] for g_a1 in gt_a1]) # compute pairwise IoUs.
print("IoU table:\n", np.round(iou_a1, 3)) # inspect all possible matches.
```

```python
matched_a1 = [(0, 0, iou_a1[0, 0]), (1, 1, iou_a1[1, 1])] # choose non-overlapping matches above 0.5.
tp_a1 = len(matched_a1) # matched true positives.
fp_a1 = len(pred_a1) - tp_a1 # unmatched predictions.
fn_a1 = len(gt_a1) - tp_a1 # unmatched ground truths.
sum_iou_a1 = sum(v_a1 for _, _, v_a1 in matched_a1) # sum matched IoUs.
pq_a1 = sum_iou_a1 / (tp_a1 + 0.5 * fp_a1 + 0.5 * fn_a1) # PQ formula.
sq_a1 = sum_iou_a1 / tp_a1 # segmentation quality.
rq_a1 = tp_a1 / (tp_a1 + 0.5 * fp_a1 + 0.5 * fn_a1) # recognition quality.
print("TP FP FN:", tp_a1, fp_a1, fn_a1) # inspect detection counts.
print("SQ/RQ/PQ:", round(sq_a1, 3), round(rq_a1, 3), round(pq_a1, 3)) # inspect metric decomposition.
assert round(pq_a1, 3) == 0.667 # verify the worked PQ value.
```

```python
plt.figure(figsize=(4, 3)) # create a metric summary chart.
plt.bar(["SQ", "RQ", "PQ"], [sq_a1, rq_a1, pq_a1], color=["steelblue", "orange", "seagreen"]) # compare components.

```
▶ What you'll see: PQ is lower than average matched IoU because the extra prediction counts as a false positive.

👀 Takeaway: PQ rewards good masks only when the right objects are also detected.

### Advanced 4 — Train a tiny mask head by gradient descent

**Goal.** Optimize logits for one binary mask target, because the mask head learns probabilities by reducing BCE on matched RoI pixels. We build it in 4 steps.



### Advanced 5 — Sweep score thresholds and measure PQ

**Goal.** Evaluate how confidence filtering changes panoptic quality, because removing low-score masks can reduce false positives but may create false negatives. We build it in 4 steps.

```python
gt_a5 = [np.array([[1, 1, 0], [1, 0, 0], [0, 0, 0]], dtype=bool), np.array([[0, 0, 0], [0, 0, 1], [0, 1, 1]], dtype=bool)] # two true segments.
pred_a5 = [np.array([[1, 1, 0], [1, 0, 0], [0, 0, 0]], dtype=bool), np.array([[0, 0, 0], [0, 0, 1], [0, 1, 0]], dtype=bool), np.array([[0, 0, 0], [0, 0, 0], [1, 0, 0]], dtype=bool)] # perfect, partial, extra.
scores_a5 = np.array([0.95, 0.60, 0.40]) # confidence scores for predictions.
thresholds_a5 = np.array([0.30, 0.50, 0.70]) # score thresholds to sweep.
print("thresholds:", thresholds_a5) # inspect filtering settings.
```
▶ What you'll see: three thresholds will keep different subsets of predictions.

```python
pq_values_a5 = [] # store PQ at each threshold.
for th_a5 in thresholds_a5: # evaluate one threshold.
    kept_a5 = [p for p, s in zip(pred_a5, scores_a5) if s >= th_a5] # filter predictions by score.
    iou_a5 = np.array([[mask_iou(g, p) for p in kept_a5] for g in gt_a5]) if kept_a5 else np.zeros((len(gt_a5), 0)) # pairwise IoU table.
    used_pred_a5 = set() # predictions already matched.
    matched_ious_a5 = [] # IoUs for accepted matches.
    for gi_a5 in range(len(gt_a5)): # greedily match each GT for this simple toy case.
        if iou_a5.shape[1] == 0: # no predictions kept.
            continue # no possible match.
        pj_a5 = int(np.argmax(iou_a5[gi_a5])) # best prediction for this GT.
        if iou_a5[gi_a5, pj_a5] > 0.5 and pj_a5 not in used_pred_a5: # accept unique matches above threshold.
            used_pred_a5.add(pj_a5); matched_ious_a5.append(float(iou_a5[gi_a5, pj_a5])) # record match.
    tp_a5 = len(matched_ious_a5); fp_a5 = len(kept_a5) - tp_a5; fn_a5 = len(gt_a5) - tp_a5 # detection counts.
    pq_a5 = sum(matched_ious_a5) / (tp_a5 + 0.5 * fp_a5 + 0.5 * fn_a5) if (tp_a5 + fp_a5 + fn_a5) else 0.0 # PQ formula.
    pq_values_a5.append(pq_a5) # store score.
print("PQ by threshold:", np.round(pq_values_a5, 3)) # inspect threshold tradeoff.
assert np.allclose(np.round(pq_values_a5, 3), np.array([0.667, 0.833, 0.667])) # verify concrete sweep values.
```

```python

print("best threshold:", float(thresholds_a5[best_idx_a5])) # inspect selected threshold.
assert float(thresholds_a5[best_idx_a5]) == 0.5 # middle threshold drops only the false positive.
```

```python

plt.plot(thresholds_a5, pq_values_a5, marker="o", color="seagreen") # plot PQ against threshold.
plt.axvline(thresholds_a5[best_idx_a5], color="red", linestyle="--", label="best threshold") # mark best threshold.
plt.ylim(0, 1.05); plt.title("Advanced 5: score threshold vs PQ"); plt.xlabel("score threshold"); plt.ylabel("PQ") # label axes.
plt.legend(); plt.show() # display the sweep.
```
▶ What you'll see: a moderate threshold improves PQ by removing an extra mask, while a high threshold hurts by dropping a true object.

👀 Takeaway: confidence thresholds trade false positives against false negatives, so panoptic systems tune them with validation metrics.
