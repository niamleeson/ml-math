# 25.5 — Neural Theorem Proving

Neural theorem proving keeps the proof-search skeleton of symbolic logic, but replaces brittle exact matching with learned, graded similarity. In this lesson, we build a tiny backward-chaining prover, add embedding-based soft unification, score proof paths, and visualize how learned premise/tactic scores guide search.

### 1. Classical proof search: facts and rules derive a query

A classical theorem prover starts with a knowledge base of **facts** and **rules**. A fact is already known, such as `parent(alice,bob)`. A rule says one statement is true if its body statements are true, such as `ancestor(X,Y) :- parent(X,Y)`. Backward chaining proves a query by asking which fact or rule head could support it, then recursively proving the needed subgoals.

```python
facts_w = [("parent", "alice", "bob"), ("parent", "bob", "carol")]  # known ground atoms.
rules_w = [("ancestor", ("X", "Y"), [("parent", "X", "Y")]),
           ("ancestor", ("X", "Y"), [("parent", "X", "Z"), ("ancestor", "Z", "Y")])]  # recursive rule.
query_w = ("ancestor", "alice", "carol")  # what we want to prove.
print("facts:", facts_w)
print("query:", query_w)
```
▶ What you'll see: the query is not a fact, so it needs a rule-based proof.

```python
nodes_w = {"ancestor(alice,carol)": (0, 2), "parent(alice,Z)": (-1.8, 1),
           "ancestor(Z,carol)": (1.8, 1), "parent(alice,bob)": (-1.8, 0),
           "ancestor(bob,carol)": (1.8, 0), "parent(bob,carol)": (1.8, -1)}
edges_w = [("ancestor(alice,carol)", "parent(alice,Z)"), ("ancestor(alice,carol)", "ancestor(Z,carol)"),
           ("parent(alice,Z)", "parent(alice,bob)"), ("ancestor(Z,carol)", "ancestor(bob,carol)"),
           ("ancestor(bob,carol)", "parent(bob,carol)")]
plt.figure(figsize=(7, 4))
for a_w, b_w in edges_w:
    xa_w, ya_w = nodes_w[a_w]; xb_w, yb_w = nodes_w[b_w]
    plt.plot([xa_w, xb_w], [ya_w, yb_w], color="gray", linewidth=1.5)
for name_w, (x_w, y_w) in nodes_w.items():
    plt.scatter([x_w], [y_w], s=450, color="lightsteelblue", edgecolor="black")
    plt.text(x_w, y_w, name_w, ha="center", va="center", fontsize=8)
plt.axis("off"); plt.title("1: backward proof tree for ancestor(alice, carol)"); plt.show()
```
▶ What you'll see: the proof decomposes the goal into subgoals until facts close the leaves.

*Why it's done this way:* proof search preserves logical structure: every derived theorem must be supported by a chain of rule applications ending in facts.

### 2. Exact unification is clean but brittle

Classical unification checks whether two atoms can be made identical by binding variables. It is exact: `parent(alice,bob)` matches `parent(X,Y)`, but `parent(ally,bob)` does not match `parent(alice,bob)` even if `ally` is an alias or typo. Neural theorem proving keeps the same matching location in the proof algorithm but replaces this yes/no gate with a graded score.

```python
def is_var_w(x_w):
    return isinstance(x_w, str) and x_w[:1].isupper()

def unify_exact_w(pattern_w, atom_w):
    if pattern_w[0] != atom_w[0] or len(pattern_w) != len(atom_w):
        return None
    env_w = {}
    for p_w, a_w in zip(pattern_w[1:], atom_w[1:]):
        if is_var_w(p_w):
            if p_w in env_w and env_w[p_w] != a_w:
                return None
            env_w[p_w] = a_w
        elif p_w != a_w:
            return None
    return env_w

pairs_w = [(("parent", "X", "Y"), ("parent", "alice", "bob")),
           (("parent", "alice", "bob"), ("parent", "ally", "bob")),
           (("parent", "alice", "bob"), ("parent", "alice", "bob"))]
results_w = [unify_exact_w(a_w, b_w) is not None for a_w, b_w in pairs_w]
print("exact matches:", results_w)
```
▶ What you'll see: variable binding succeeds, exact equality succeeds, and a near-alias fails.

```python
plt.figure(figsize=(5, 3))
plt.bar(["vars", "alias", "exact"], [int(r_w) for r_w in results_w], color=["seagreen", "crimson", "seagreen"])
plt.ylim(0, 1.2); plt.ylabel("classical match")
plt.title("2: exact unification is binary"); plt.show()
```
▶ What you'll see: the alias case gets zero support even though it might be semantically close.

*Why it's done this way:* exact unification is trustworthy when symbols are canonical, but it cannot exploit learned similarity or tolerate messy names.

### 3. Embeddings make unification soft

Neural theorem proving assigns symbols vectors. If vectors are normalized, cosine similarity becomes a soft unification score: identical or nearby symbols score high, unrelated symbols score low. The proof search still asks whether a fact can support a goal, but the support becomes a number instead of a switch.

```python
emb_w = {"alice": np.array([1.0, 0.0]),
         "bob": np.array([0.9701425001453318, 0.24253562503633294]),
         "carol": np.array([0.0, 1.0]),
         "ally": np.array([0.98, 0.05])}
for k_w in emb_w:
    emb_w[k_w] = emb_w[k_w] / np.linalg.norm(emb_w[k_w])
names_w = list(emb_w)
sim_w = np.array([[float(emb_w[a_w] @ emb_w[b_w]) for b_w in names_w] for a_w in names_w])
print("alice-bob similarity:", round(float(emb_w["alice"] @ emb_w["bob"]), 3))
assert round(float(emb_w["alice"] @ emb_w["bob"]), 3) == 0.970
```
▶ What you'll see: Bob is highly similar to Alice in this toy embedding space, while Carol is orthogonal.

```python
plt.figure(figsize=(4.5, 3.8))
plt.imshow(sim_w, cmap="viridis", vmin=0, vmax=1)
plt.colorbar(label="cosine soft-unification score")
plt.xticks(range(len(names_w)), names_w, rotation=30); plt.yticks(range(len(names_w)), names_w)
plt.title("3: soft unification heatmap"); plt.show()
```
▶ What you'll see: near symbols have bright cells; unrelated symbols are dark.

*Why it's done this way:* cosine gives the prover a differentiable, graded way to use aliases and near-synonyms without deleting the proof-search structure.

### 4. A proof path score multiplies fact, rule, and unification confidence

One proof path has several sources of uncertainty: the fact may be noisy, the rule may be learned rather than guaranteed, and the symbol match may be approximate. A conservative path score multiplies these pieces:

$$s_{path}=f\cdot u\cdot r.$$

```python
fact_conf_w = 0.9
unify_w = float(emb_w["alice"] @ emb_w["bob"])
rule_conf_w = 0.8
path_score_w = fact_conf_w * unify_w * rule_conf_w
print("fact × unification × rule =", round(path_score_w, 3))
assert round(path_score_w, 3) == 0.699
```
▶ What you'll see: a strong path is reduced by each uncertain component.

```python
plt.figure(figsize=(5, 3))
plt.bar(["fact f", "unify u", "rule r", "path"], [fact_conf_w, unify_w, rule_conf_w, path_score_w],
        color=["gray", "purple", "orange", "seagreen"])
plt.ylim(0, 1.05); plt.ylabel("score")
plt.title("4: multiplicative proof-path confidence"); plt.show()
```
▶ What you'll see: the path bar is below every near-one ingredient because multiplication accumulates uncertainty.

*Why it's done this way:* multiplying makes a path fragile to weak links, which helps prevent one dubious premise or match from creating a confident theorem.

### 5. Learned premise and tactic scores guide search

A neural theorem prover rarely expands every branch. It uses learned scores to rank promising facts, premises, or tactics before spending search budget. This is still proof search, but the queue is ordered by learned plausibility rather than by a fixed symbolic rule order.

```python
candidates_w = ["direct parent", "recursive ancestor", "sibling rule", "unrelated rule"]
tactic_scores_w = np.array([0.55, 0.93, 0.28, 0.06])
order_w = np.argsort(tactic_scores_w)[::-1]
print("expansion order:", [candidates_w[i_w] for i_w in order_w])
```
▶ What you'll see: the recursive ancestor rule is expanded first because it has the largest learned score.

```python
plt.figure(figsize=(6, 3))
plt.bar(np.arange(len(candidates_w)), tactic_scores_w[order_w], color="steelblue")
plt.xticks(np.arange(len(candidates_w)), [candidates_w[i_w] for i_w in order_w], rotation=20, ha="right")
plt.ylabel("learned priority")
plt.title("5: learned tactic scores guide proof search"); plt.show()
```
▶ What you'll see: proof search becomes a priority queue over tactics/premises rather than a blind expansion.

*Why it's done this way:* search budgets are finite, so learned ranking spends proof effort on branches that look useful while still producing inspectable proof paths.

### 6. Multiple proof paths combine with a soft OR

A theorem may have several supporting paths. A common soft OR combines path scores as

$$S=1-\prod_j(1-s_j).$$

This rises when independent support accumulates, but it can overstate confidence if the paths all reuse the same noisy fact.

```python
paths_w = np.array([0.6985026001046389, 0.25, 0.10])
soft_or_w = 1 - np.prod(1 - paths_w)
print("path scores:", np.round(paths_w, 3))
print("soft OR theorem score:", round(float(soft_or_w), 3))
assert round(float(soft_or_w), 3) == 0.796
```
▶ What you'll see: the combined theorem score is higher than each weak path alone.

```python
plt.figure(figsize=(5, 3))
plt.bar(["path 1", "path 2", "path 3", "soft OR"], list(paths_w) + [soft_or_w],
        color=["gray", "gray", "gray", "seagreen"])
plt.ylim(0, 1.05); plt.ylabel("score")
plt.title("6: aggregating multiple proof paths"); plt.show()
```
▶ What you'll see: weak extra paths increase support, but the score remains bounded below one.

*Why it's done this way:* soft OR keeps the theorem score differentiable while representing the intuition that several successful proofs are stronger than one.

### 7. Temperature controls cautious versus gullible matching

Softmax attention over candidate matches uses a temperature $\tau$. Low temperature concentrates mass on the closest symbols; high temperature spreads mass to weaker analogies. This is a central safety knob: high temperature can rescue aliases, but it can also make false analogies participate in proofs.

```python
sims_w = np.array([1.0, 0.9701425001453318, 0.0])
temps_w = np.array([0.2, 0.5, 1.0])
weights_w = []
for tau_w in temps_w:
    z_w = np.exp(sims_w / tau_w)
    weights_w.append(z_w / z_w.sum())
weights_w = np.array(weights_w)
print("weights at tau=0.2:", np.round(weights_w[0], 3))
assert np.allclose(np.round(weights_w[0], 3), [0.535, 0.461, 0.004])
```
▶ What you'll see: low temperature nearly ignores the unrelated candidate.

```python
plt.figure(figsize=(5.5, 3))
for j_w, name_w in enumerate(["exact", "near", "far"]):
    plt.plot(temps_w, weights_w[:, j_w], marker="o", label=name_w)
plt.xlabel("temperature τ"); plt.ylabel("attention weight")
plt.title("7: temperature spreads proof attention"); plt.legend(); plt.show()
```
▶ What you'll see: as temperature rises, the far symbol receives more proof mass.

*Why it's done this way:* temperature tunes the generalization-risk tradeoff between strict symbolic matching and permissive neural analogy.

## 🛠️ Setup

```python
import numpy as np  # numerical arrays, vectors, softmax, and assertions.
import matplotlib.pyplot as plt  # required visualization tool for every example.
from collections import deque  # simple queue for breadth-first proof search.
np.random.seed(0)  # reproducible toy examples.

def norm_vec(x):
    x = np.asarray(x, dtype=float)
    n = np.linalg.norm(x)
    return x if n == 0 else x / n

def cosine(a, b):
    a = norm_vec(a); b = norm_vec(b)
    return float(a @ b)

def softmax(x, tau=1.0):
    x = np.asarray(x, dtype=float) / tau
    x = x - np.max(x)
    e = np.exp(x)
    return e / e.sum()

def soft_or(scores):
    scores = np.clip(np.asarray(scores, dtype=float), 0, 1)
    return float(1 - np.prod(1 - scores))

def draw_tree(nodes, edges, scores=None, title="proof tree"):
    plt.figure(figsize=(7, 4))
    for parent, child in edges:
        x0, y0 = nodes[parent]; x1, y1 = nodes[child]
        plt.plot([x0, x1], [y0, y1], color="gray", linewidth=1.3)
    for name, (x, y) in nodes.items():
        color = "lightsteelblue" if scores is None else plt.cm.viridis(scores.get(name, 0.5))
        plt.scatter([x], [y], s=520, color=color, edgecolor="black")
        plt.text(x, y, name, ha="center", va="center", fontsize=8)
    plt.axis("off"); plt.title(title); plt.show()

def prove_parent_chain(facts, start, end, max_depth=4):
    queue = deque([(start, [start])])
    while queue:
        node, path = queue.popleft()
        if node == end:
            return path
        if len(path) > max_depth:
            continue
        for rel, a, b in facts:
            if rel == "parent" and a == node and b not in path:
                queue.append((b, path + [b]))
    return []
```

#### A1. Build a soft backward-chaining scorer

**Goal.** Score candidate facts for a goal with predicate, argument similarity, and fact confidence, because neural theorem proving relaxes exact fact matching into ranked support. We build it in 4 steps.

```python
facts_a1 = [("parent", "alice", "bob", 0.95), ("parent", "ally", "bob", 0.70), ("likes", "alice", "logic", 0.99)]
emb_a1 = {"alice": [1, 0], "ally": [0.99, 0.08], "bob": [0.7, 0.7], "logic": [0, 1]}
goal_a1 = ("parent", "alice", "bob")
scores_a1 = []
for rel, a, b, conf in facts_a1:
    pred_ok = 1.0 if rel == goal_a1[0] else 0.0
    arg_score = cosine(emb_a1.get(a, [0, 0]), emb_a1[goal_a1[1]]) * cosine(emb_a1.get(b, [0, 0]), emb_a1[goal_a1[2]])
    scores_a1.append(pred_ok * arg_score * conf)
scores_a1 = np.array(scores_a1)
print("fact support scores:", np.round(scores_a1, 3))
```

👀 Takeaway: soft backward chaining can rank useful imperfect matches without accepting every relation.
