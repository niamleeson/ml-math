OCR and scene text recognition turn messy pixels into strings: first make a word crop readable left-to-right, then convert a variable-width feature sequence into characters without knowing exactly which image column produced each letter. In this lesson, you will build the main ideas from scratch with NumPy — synthetic text-like images, rectification, CTC collapse and probability, and a tiny language-prior decoder.

### 1. A word crop becomes a left-to-right feature sequence

An OCR recognizer usually does not classify the whole crop as one label. It compresses a word image into a sequence: each time step summarizes a vertical slice of the crop. A convolutional network would learn the filters; here we use simple column features — ink amount, upper-half ink, and lower-half ink — so the geometry is inspectable.

```python
img_w = np.zeros((8, 24), dtype=float)  # a tiny synthetic word crop: height 8, width 24.
img_w[1:7, 2:4] = 1.0                   # first letter-like stroke.
img_w[1:3, 4:7] = 1.0
img_w[3:5, 4:7] = 1.0
img_w[5:7, 4:7] = 1.0
img_w[1:7, 10:12] = 1.0                 # second letter-like stroke.
img_w[1:7, 13:15] = 1.0
img_w[1:3, 12:14] = 1.0
img_w[5:7, 12:14] = 1.0
img_w[1:7, 18:20] = 1.0                 # third letter-like stroke.
img_w[1:3, 20:22] = 1.0
img_w[3:5, 20:22] = 1.0
print("crop shape:", img_w.shape, "ink pixels:", int(img_w.sum()))
assert img_w.shape == (8, 24)
```
▶ What you'll see: a small binary crop with three separated text-like blobs.

```python
plt.figure(figsize=(6, 2.2))
plt.imshow(img_w, cmap="gray_r", aspect="auto")
plt.title("1: synthetic scene-text crop")
plt.xlabel("image column")
plt.ylabel("row")
plt.show()
```
▶ What you'll see: dark ink forms three rough letters across the crop; OCR will read them as a sequence, not as independent boxes.

```python
stride_w = 4
T_w = img_w.shape[1] // stride_w
features_w = []
for t_w in range(T_w):
    patch_w = img_w[:, t_w * stride_w:(t_w + 1) * stride_w]
    total_w = patch_w.mean()
    upper_w = patch_w[:4].mean()
    lower_w = patch_w[4:].mean()
    features_w.append([total_w, upper_w, lower_w])
features_w = np.array(features_w)
print("sequence shape:", features_w.shape)
print(np.round(features_w, 2))
assert features_w.shape == (6, 3)
```
▶ What you'll see: the 8×24 crop becomes 6 time steps, each with 3 numeric features.

```python
plt.figure(figsize=(6, 2.8))
plt.imshow(features_w.T, cmap="viridis", aspect="auto")
plt.yticks([0, 1, 2], ["all ink", "upper", "lower"])
plt.xlabel("time step")
plt.title("1: column-slice features")
plt.colorbar(label="mean ink")
plt.show()
```
▶ What you'll see: feature peaks line up with text strokes, leaving low-ink gaps where blanks are plausible.

*Why it's done this way:* A crop width of 24 with stride 4 gives `24/4 = 6` feature steps, which can be more or fewer than the number of output characters. The sequence representation preserves reading order while letting each frame summarize local visual evidence. This mismatch — many frames, fewer characters — is exactly why OCR needs alignment rather than a fixed one-column-per-letter rule.

### 2. Rectification makes the reading direction simpler

Scene text is often slanted or curved. Before recognition, a detector or rectifier tries to map the crop into a cleaner left-to-right strip. We can model a tiny version by shifting each row horizontally so a diagonal stroke becomes vertical.

```python
slanted_w = np.zeros((8, 16), dtype=float)
for y_w in range(8):
    x_w = 3 + y_w // 2
    slanted_w[y_w, x_w:x_w + 3] = 1.0
print("row centers before:", [int(np.argmax(row_w)) for row_w in slanted_w])
```
▶ What you'll see: the strongest ink column drifts right as the row index increases.

```python
flow_w = np.array([0, 0, -1, -1, -2, -2, -3, -3])
rect_w = np.zeros_like(slanted_w)
for y_w in range(slanted_w.shape[0]):
    rect_w[y_w] = np.roll(slanted_w[y_w], flow_w[y_w])
print("row centers after:", [int(np.argmax(row_w)) for row_w in rect_w])
assert len(set([int(np.argmax(row_w)) for row_w in rect_w])) == 1
```
▶ What you'll see: every row's ink peak now sits in the same column.

```python
fig_w, ax_w = plt.subplots(1, 2, figsize=(7, 2.4))
ax_w[0].imshow(slanted_w, cmap="gray_r", aspect="auto")
ax_w[0].set_title("before rectification")
ax_w[1].imshow(rect_w, cmap="gray_r", aspect="auto")
ax_w[1].set_title("after row shifts")
for a_w in ax_w:
    a_w.set_xlabel("x")
    a_w.set_ylabel("y")
plt.show()
```
▶ What you'll see: the left panel is diagonal; the right panel is upright, so a horizontal sequence scan is easier.

*Why it's done this way:* CTC assumes the feature sequence is in reading order. If perspective bends the text, neighboring time steps may no longer correspond to neighboring characters. A rectification flow stores small coordinate shifts — here row-wise horizontal shifts — so the recognizer sees a simpler strip and the alignment model does not have to explain geometric distortion and spelling at the same time.

### 3. CTC collapse: blanks and repeated letters

CTC predicts one symbol per time step, but the final string is shorter. The collapse rule first merges adjacent repeated labels, then removes blanks. The blank symbol is not output text; it is alignment glue that separates repeated letters and absorbs spacing.

```python
blank_w = "_"
path1_w = ["b", blank_w, "o", "o", blank_w, "k"]
path2_w = ["b", blank_w, "o", blank_w, "o", "k"]
print("path without separating blank between o's:", path1_w)
print("path with separating blank:", path2_w)
```
▶ What you'll see: the two paths differ only around the repeated `o`.

```python
def ctc_collapse_w(path_w, blank=blank_w):
    merged_w = []
    prev_w = None
    for sym_w in path_w:
        if sym_w != prev_w:
            merged_w.append(sym_w)
        prev_w = sym_w
    return "".join(sym_w for sym_w in merged_w if sym_w != blank)

print("collapse path1:", ctc_collapse_w(path1_w))
print("collapse path2:", ctc_collapse_w(path2_w))
assert ctc_collapse_w(path1_w) == "bok"
assert ctc_collapse_w(path2_w) == "book"
```
▶ What you'll see: adjacent `o,o` collapses to one `o`, but `o,blank,o` survives as `oo`.

```python
symbols_w = ["b", "_", "o", "_", "o", "k"]
plt.figure(figsize=(6, 1.8))
plt.imshow(np.arange(len(symbols_w))[None, :], cmap="Pastel1", aspect="auto")
for i_w, s_w in enumerate(symbols_w):
    plt.text(i_w, 0, s_w, ha="center", va="center", fontsize=14)
plt.yticks([])
plt.xticks(range(len(symbols_w)))
plt.title("3: blanks separate repeated letters")
plt.show()
```
▶ What you'll see: the blank between the two `o` frames acts like a separator, not a character.

*Why it's done this way:* If we removed blanks before merging repeats, `b _ o _ o k` would become `book` accidentally for one case but repeated-frame evidence like `o,o` would be ambiguous. CTC's order — merge adjacent equals first, then delete blank — gives one consistent many-to-one map from frame paths to strings and makes repeated letters representable.

### 4. CTC sums many alignments, not just the best one

A target string can be produced by many frame-level paths. CTC assigns the string probability by summing the probabilities of all paths that collapse to that string. For real models this is done with dynamic programming; for a tiny example we can enumerate all paths to see the formula directly.

```python
alphabet_w = [blank_w, "c", "t"]
probs_w = np.array([[0.10, 0.80, 0.10],
                    [0.50, 0.25, 0.25],
                    [0.10, 0.20, 0.70]])
print("row sums:", probs_w.sum(axis=1))
assert np.allclose(probs_w.sum(axis=1), 1.0)
```
▶ What you'll see: each time step is a probability distribution over blank, `c`, and `t`.

```python
valid_paths_w = []
for i_w in range(3):
    for j_w in range(3):
        for k_w in range(3):
            path_w = [alphabet_w[i_w], alphabet_w[j_w], alphabet_w[k_w]]
            if ctc_collapse_w(path_w) == "ct":
                prob_w = probs_w[0, i_w] * probs_w[1, j_w] * probs_w[2, k_w]
                valid_paths_w.append((path_w, prob_w))
for path_w, prob_w in valid_paths_w:
    print(path_w, round(prob_w, 4))
ct_prob_w = sum(prob_w for _, prob_w in valid_paths_w)
print("P(ct|x) =", round(ct_prob_w, 4))
assert round(ct_prob_w, 4) == 0.5975
```
▶ What you'll see: several paths collapse to `ct`; their probabilities add to 0.5975.

```python
plt.figure(figsize=(5, 2.8))
plt.bar(range(len(valid_paths_w)), [p_w for _, p_w in valid_paths_w], color="teal")
plt.xticks(range(len(valid_paths_w)), ["".join(path_w) for path_w, _ in valid_paths_w], rotation=30)
plt.ylabel("path probability")
plt.title("4: CTC string probability sums paths")
plt.show()
```
▶ What you'll see: no single alignment owns all probability; the string score is the sum of multiple bars.

*Why it's done this way:* We usually know the transcription `ct`, not whether frame 2 was blank, `c`, or `t`. Multiplying frame probabilities scores one proposed alignment path, while summing over all paths avoids committing to a segmentation. This is the mathematical reason CTC can train without character boxes.

### 5. Language priors repair visual ambiguity carefully

Visual evidence can confuse similar characters, especially in blurred signs or stylized fonts. A decoder can combine visual log probabilities with a language prior, but the prior must not overpower the image — rare names and serial numbers may be visually correct even if linguistically uncommon.

```python
chars_w = ["c", "a", "r", "t"]
visual_w = {
    "cat": np.array([0.60, 0.70, 0.55]),
    "car": np.array([0.60, 0.70, 0.45]),
    "cut": np.array([0.60, 0.15, 0.55]),
}
prior_w = {"cat": 0.50, "car": 0.35, "cut": 0.15}
for word_w in visual_w:
    print(word_w, "visual product", round(float(np.prod(visual_w[word_w])), 4), "prior", prior_w[word_w])
```
▶ What you'll see: `cat` and `car` are visually close, so the prior can affect the decision.

```python
alpha_w = 0.8
scores_w = {}
for word_w, probs_word_w in visual_w.items():
    visual_log_w = float(np.sum(np.log(probs_word_w)))
    prior_log_w = float(np.log(prior_w[word_w]))
    scores_w[word_w] = visual_log_w + alpha_w * prior_log_w
print("combined scores:", {k: round(v, 3) for k, v in scores_w.items()})
best_w = max(scores_w, key=scores_w.get)
print("decoded word:", best_w)
assert best_w == "cat"
```
▶ What you'll see: the common word `cat` wins when its visual evidence is also strong.

```python
plt.figure(figsize=(5, 2.8))
plt.bar(list(scores_w.keys()), list(scores_w.values()), color="purple")
plt.ylabel("log visual + α log prior")
plt.title("5: language prior as a decoding term")
plt.show()
```
▶ What you'll see: the highest combined log score is the decoded string; changing α would change how much spelling frequency matters.

*Why it's done this way:* Multiplying probabilities is equivalent to adding log probabilities, which is numerically safer and makes a prior just another additive term. The coefficient α is a trust knob: too low ignores useful spelling regularities; too high turns OCR into autocorrect and can overwrite valid rare text.

### Basic 5 — Collapse adjacent repeats

**Goal.** Merge consecutive identical labels before deleting blanks, because this is the first half of CTC decoding.

```python
path_b5 = ["c", "c", "_", "a", "a", "_", "t"]
merged_b5 = []
prev_b5 = None
for sym_b5 in path_b5:
    if sym_b5 != prev_b5:
        merged_b5.append(sym_b5)
    prev_b5 = sym_b5
print("merged:", merged_b5)
assert merged_b5 == ["c", "_", "a", "_", "t"]
```
▶ What you'll see: repeated `c,c` and `a,a` become single labels.

```python
plt.figure(figsize=(5, 2))

```
▶ What you'll see: merging reduces path length before the blanks are removed.

👀 Takeaway: CTC collapse first removes repeated frame labels that came from the same character.

### Basic 6 — Remove blanks after merging

### Basic 10 — Greedy decode a probability table

**Goal.** Pick the most likely symbol at each frame and collapse, because greedy decoding is the simplest OCR decoder.

```python
labels_b10 = np.array(["_", "c", "a", "t"])

                  [0.1, 0.1, 0.7, 0.1],

print("greedy path:", greedy_b10.tolist())
```

```python
merged_b10 = []
```

### Easy 2 — Rectify a slanted crop

**Goal.** Use row shifts to straighten a slanted synthetic stroke, because OCR prefers left-to-right aligned text.


### Advanced 2 — Beam search can beat greedy decoding

**Goal.** Keep multiple prefix candidates, because the best total string can differ from the framewise greedy path.

```python
labels_a2 = ["_", "a", "b"]
P_a2 = np.array([[0.006, 0.494, 0.500],
                 [0.152, 0.106, 0.742],
                 [0.120, 0.052, 0.828]])
greedy_path_a2 = [labels_a2[i_a2] for i_a2 in np.argmax(P_a2, axis=1)]
print("greedy path:", greedy_path_a2)
```
▶ What you'll see: greedy chooses `b` at every frame, so adjacent repeats collapse to one `b`.

```python
def collapse_a2(path_a2):
    merged_a2 = []
    prev_a2 = None
    for sym_a2 in path_a2:
        if sym_a2 != prev_a2:
            merged_a2.append(sym_a2)
        prev_a2 = sym_a2
    return "".join(sym_a2 for sym_a2 in merged_a2 if sym_a2 != "_")

scores_a2 = {}

    for j_a2 in range(3):
        for k_a2 in range(3):
            path_a2 = [labels_a2[i_a2], labels_a2[j_a2], labels_a2[k_a2]]
            text_a2 = collapse_a2(path_a2)

```
▶ What you'll see: greedy emits `b`, but summed path probability prefers `ab`.

### Advanced 3 — Forward dynamic programming for CTC

**Goal.** Compute CTC probability without enumerating every path, because real OCR has too many frames for brute force.


```python

        total_a3 = alpha_a3[t_a3 - 1, s_a3]
```

### Advanced 5 — Measure recognition with edit distance

**Goal.** Compute character error rate from scratch, because OCR quality is about string edits, not just exact-match accuracy.

```python
truth_a5 = "book"
pred_a5 = "bok"
D_a5 = np.zeros((len(truth_a5) + 1, len(pred_a5) + 1), dtype=int)
D_a5[:, 0] = np.arange(len(truth_a5) + 1)
D_a5[0, :] = np.arange(len(pred_a5) + 1)

    for j_a5 in range(1, len(pred_a5) + 1):
        cost_a5 = 0 if truth_a5[i_a5 - 1] == pred_a5[j_a5 - 1] else 1
        D_a5[i_a5, j_a5] = min(D_a5[i_a5 - 1, j_a5] + 1,
                               D_a5[i_a5, j_a5 - 1] + 1,
                               D_a5[i_a5 - 1, j_a5 - 1] + cost_a5)
edits_a5 = int(D_a5[-1, -1])
```
