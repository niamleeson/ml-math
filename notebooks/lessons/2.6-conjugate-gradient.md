# 2.6 — Conjugate Gradient

Conjugate gradient (CG) solves symmetric positive-definite linear systems by minimizing the matching quadratic without forming a dense inverse. In this lesson, you will build CG from first principles in NumPy, inspect residuals and search directions, and see why $A$-conjugate directions avoid undoing progress that steepest descent repeatedly loses.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build conjugate gradient one idea at a time. Run each cell in order and read the printed intermediate values — every piece of math, including the residual, exact step size, and conjugacy update, is derived and shown. This walkthrough is self-contained and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays + linear algebra for quadratic systems.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
np.random.seed(0)  # reproducibility for small numerical demos.
```

### 1. Quadratic minimization is the same as solving Ax = b

CG starts with a symmetric positive-definite matrix $A$ and vector $b$. Instead of solving $Ax=b$ by explicitly computing $A^{-1}$, we minimize the quadratic

$$f(x)=\frac12x^TAx-b^Tx.$$

The gradient is $\nabla f(x)=Ax-b$, so the minimizer has zero gradient exactly when $Ax=b$. Positive-definiteness makes this quadratic a bowl with one global minimum.

```python
A_w = np.array([[4.0, 1.0], [1.0, 3.0]])  # SPD: symmetric with positive eigenvalues.
b_w = np.array([1.0, 2.0])  # right-hand side.
x_star_w = np.linalg.solve(A_w, b_w)  # direct solve only for checking the CG answer.
print("A:\n", A_w)
print("b:", b_w)
print("direct solution:", np.round(x_star_w, 6))
assert np.allclose(x_star_w, [0.09090909, 0.63636364])
```
▶ What you'll see: the exact solution is approximately `(0.090909, 0.636364)`, which CG will recover without forming an inverse.

```python
grid_x_w = np.linspace(-0.35, 0.55, 80)
grid_y_w = np.linspace(0.05, 0.95, 80)
X_w, Y_w = np.meshgrid(grid_x_w, grid_y_w)
Z_w = 0.5 * (A_w[0, 0] * X_w**2 + 2 * A_w[0, 1] * X_w * Y_w + A_w[1, 1] * Y_w**2) - b_w[0] * X_w - b_w[1] * Y_w
plt.figure(figsize=(4.4, 3.4))
plt.contour(X_w, Y_w, Z_w, levels=18, cmap="viridis")
plt.scatter([x_star_w[0]], [x_star_w[1]], color="red", label="minimizer")
plt.title("1: quadratic bowl for Ax=b")
plt.xlabel("x0"); plt.ylabel("x1"); plt.legend(); plt.show()
```
▶ What you'll see: elliptical contours with the direct solution at the unique bowl bottom.

*Why it's done this way:* turning $Ax=b$ into a quadratic gives an optimization view of a linear algebra problem. The SPD assumption matters because $x^TAx>0$ makes curvature positive in every direction, so exact line searches and denominators such as $p^TAp$ are well-behaved.

### 2. Residuals are negative gradients and measure unfinished work

At a current guess $x$, the residual is $r=b-Ax$. It is also $-\nabla f(x)$, so it points in the steepest local downhill direction. If the residual is zero, the gradient is zero and the linear system is solved.

```python
x0_w = np.array([0.0, 0.0])  # start at the origin.
r0_w = b_w - A_w @ x0_w  # residual = b - Ax.
grad0_w = A_w @ x0_w - b_w  # gradient of the quadratic.
print("x0:", x0_w)
print("residual r0:", r0_w)
print("gradient:", grad0_w)
assert np.allclose(r0_w, -grad0_w)
```
▶ What you'll see: at the origin, the residual is `(1, 2)` and it is exactly the negative gradient.

```python
plt.figure(figsize=(4.2, 3.4))
plt.contour(X_w, Y_w, Z_w, levels=18, cmap="Greys")
plt.arrow(x0_w[0], x0_w[1], 0.18 * r0_w[0], 0.18 * r0_w[1], head_width=0.025, color="crimson", length_includes_head=True)
plt.scatter([x0_w[0]], [x0_w[1]], color="black")
plt.title("2: residual points downhill")
plt.xlabel("x0"); plt.ylabel("x1"); plt.show()
```
▶ What you'll see: the residual arrow points from the current guess toward lower contour levels, but not directly to the minimizer because the bowl is stretched.

*Why it's done this way:* CG can use only matrix-vector products $A@x$ and $A@p$, so the residual is a cheap, exact stationarity diagnostic. Its norm tells us whether the equation is solved; its direction gives the first search direction.

### 3. The exact step size minimizes along one direction

Given a search direction $p$, CG chooses the best distance $\alpha$ along that line. For the first step $p_0=r_0$. Minimizing $f(x_0+\alpha p_0)$ with respect to $\alpha$ gives

$$\alpha_0=\frac{r_0^Tr_0}{p_0^TAp_0}.$$

```python
p0_w = r0_w.copy()  # first CG direction is steepest descent.
Ap0_w = A_w @ p0_w
num0_w = float(r0_w @ r0_w)
den0_w = float(p0_w @ Ap0_w)
alpha0_w = num0_w / den0_w
print("A p0:", Ap0_w)
print("r0^T r0:", num0_w, "p0^T A p0:", den0_w)
print("alpha0:", alpha0_w)
assert alpha0_w == 0.25
```
▶ What you'll see: `r0^T r0 = 5`, `p0^T A p0 = 20`, so the exact line-search step is `0.25`.

```python
x1_w = x0_w + alpha0_w * p0_w
r1_w = r0_w - alpha0_w * Ap0_w
print("x1:", x1_w)
print("r1:", r1_w)
assert np.allclose(x1_w, [0.25, 0.5])
assert np.allclose(r1_w, [-0.5, 0.25])
```
▶ What you'll see: the first step reaches `(0.25, 0.5)`, reducing but not eliminating the residual.

```python
alphas_w = np.linspace(0, 0.55, 80)
line_vals_w = []
for a_w in alphas_w:
    x_line_w = x0_w + a_w * p0_w
    line_vals_w.append(0.5 * x_line_w @ A_w @ x_line_w - b_w @ x_line_w)
plt.figure(figsize=(4.4, 3))
plt.plot(alphas_w, line_vals_w, color="purple")
plt.axvline(alpha0_w, color="red", linestyle="--", label="best alpha")
plt.title("3: exact line search along p0")
plt.xlabel("alpha"); plt.ylabel("f(x0 + alpha p0)"); plt.legend(); plt.show()
```
▶ What you'll see: a one-dimensional parabola whose minimum occurs exactly at `alpha0 = 0.25`.

*Why it's done this way:* the denominator $p^TAp$ is the curvature of the quadratic along direction $p$, and the numerator is the current residual energy. Dividing them chooses the distance that removes as much error as possible along this direction in one shot.

### 4. A-conjugate directions avoid undoing solved work

Ordinary perpendicularity is not enough on an elliptical bowl. CG uses $A$-conjugacy: two directions $p_i$ and $p_j$ are independent in the quadratic geometry when $p_i^TAp_j=0$. The update

$$p_1=r_1+\beta_0p_0,\qquad \beta_0=\frac{r_1^Tr_1}{r_0^Tr_0}$$

builds a new direction that is $A$-conjugate to the old one.

```python
beta0_w = float((r1_w @ r1_w) / (r0_w @ r0_w))
p1_w = r1_w + beta0_w * p0_w
conj_check_w = float(p0_w @ A_w @ p1_w)
print("beta0:", beta0_w)
print("p1:", p1_w)
print("p0^T A p1:", round(conj_check_w, 12))
assert beta0_w == 0.0625
assert abs(conj_check_w) < 1e-12
```
▶ What you'll see: `p1 = (-0.4375, 0.375)` and `p0^T A p1` is numerically zero.

```python
plt.figure(figsize=(4.2, 3.4))
plt.contour(X_w, Y_w, Z_w, levels=18, cmap="Greys")
plt.arrow(x0_w[0], x0_w[1], alpha0_w * p0_w[0], alpha0_w * p0_w[1], head_width=0.025, color="teal", length_includes_head=True, label="step 0")
plt.arrow(x1_w[0], x1_w[1], 0.35 * p1_w[0], 0.35 * p1_w[1], head_width=0.025, color="orange", length_includes_head=True, label="conjugate direction")
plt.scatter([x_star_w[0]], [x_star_w[1]], color="red")
plt.title("4: second direction is A-conjugate")
plt.xlabel("x0"); plt.ylabel("x1"); plt.legend(); plt.show()
```
▶ What you'll see: the second direction is not simply the new residual; it is tilted to respect the bowl's metric.

*Why it's done this way:* after an exact line search, CG must move somewhere new without reintroducing error along the previous direction. $A$-conjugacy is the algebraic condition that guarantees the next minimization preserves previous minimizations for this quadratic.

### 5. In exact arithmetic, CG terminates in at most d steps

In a $d$-dimensional SPD system, CG constructs at most $d$ mutually $A$-conjugate directions. For this 2D example, the second line search reaches the exact solution.

```python
Ap1_w = A_w @ p1_w
alpha1_w = float((r1_w @ r1_w) / (p1_w @ Ap1_w))
x2_w = x1_w + alpha1_w * p1_w
r2_w = r1_w - alpha1_w * Ap1_w
print("alpha1:", round(alpha1_w, 6))
print("x2:", np.round(x2_w, 6))
print("r2:", np.round(r2_w, 12))
assert np.allclose(x2_w, x_star_w)
assert np.linalg.norm(r2_w) < 1e-12
```
▶ What you'll see: the second iterate matches the direct solution and the residual is essentially zero.

```python
path_w = np.vstack([x0_w, x1_w, x2_w])
plt.figure(figsize=(4.4, 3.4))
plt.contour(X_w, Y_w, Z_w, levels=18, cmap="viridis")
plt.plot(path_w[:, 0], path_w[:, 1], marker="o", color="black")
plt.scatter([x_star_w[0]], [x_star_w[1]], color="red", label="solution")
plt.title("5: CG path reaches the minimizer")
plt.xlabel("x0"); plt.ylabel("x1"); plt.legend(); plt.show()
```
▶ What you'll see: two line-search moves land on the minimizer of the 2D quadratic.

*Why it's done this way:* each conjugate direction resolves one independent error component in the $A$-geometry. Exact arithmetic preserves those directions perfectly, so after $d$ components no residual can remain.

### 6. Preconditioning reshapes a hard bowl into an easier one

Ill-conditioned systems have long, skinny contours; steepest descent zigzags and CG can still slow down. A preconditioner $M\approx A$ changes the residual into $z=M^{-1}r$, which is a better-scaled search signal. The simplest demo uses the diagonal of $A$.

```python
A_bad_w = np.array([[40.0, 0.0], [0.0, 1.0]])
b_bad_w = np.array([1.0, 1.0])
x_bad_w = np.zeros(2)
r_bad_w = b_bad_w - A_bad_w @ x_bad_w
Mdiag_w = np.diag(A_bad_w)
z_bad_w = r_bad_w / Mdiag_w
print("residual:", r_bad_w)
print("diagonal-preconditioned residual:", z_bad_w)
assert np.allclose(z_bad_w, [0.025, 1.0])
```
▶ What you'll see: the preconditioned residual shrinks the high-curvature coordinate, so the search is not dominated by the stiff axis.

```python
xs_w = np.linspace(-0.08, 0.13, 80)
ys_w = np.linspace(-0.2, 1.8, 80)
XB_w, YB_w = np.meshgrid(xs_w, ys_w)
ZB_w = 0.5 * (40 * XB_w**2 + YB_w**2) - XB_w - YB_w
plt.figure(figsize=(4.4, 3.4))
plt.contour(XB_w, YB_w, ZB_w, levels=20, cmap="magma")
plt.arrow(0, 0, 0.025, 0.025, color="red", head_width=0.025, length_includes_head=True, label="raw r scaled")
plt.arrow(0, 0, z_bad_w[0], z_bad_w[1], color="teal", head_width=0.025, length_includes_head=True, label="M^{-1}r")
plt.title("6: preconditioning rescales directions")
plt.xlabel("x0"); plt.ylabel("x1"); plt.legend(); plt.show()
```
▶ What you'll see: the raw geometry is skinny; the preconditioned direction puts relatively more effort into the slow coordinate.

*Why it's done this way:* CG only needs products with $A$ and solves with $M$. If $M^{-1}A$ has a smaller condition number, fewer iterations are needed because the transformed quadratic is closer to round.

## 🟢 Basics (warm-up)

### Basic 1 — Build an SPD system

**Goal.** Create a tiny symmetric positive-definite system, because CG's guarantees require positive curvature.

```python
A_b1 = np.array([[4.0, 1.0], [1.0, 3.0]])
b_b1 = np.array([1.0, 2.0])
eig_b1 = np.linalg.eigvalsh(A_b1)
print("A shape:", A_b1.shape, "b shape:", b_b1.shape)
print("eigenvalues:", np.round(eig_b1, 3))
assert np.all(eig_b1 > 0)
```
▶ What you'll see: both eigenvalues are positive, so every nonzero direction has positive curvature.

```python
plt.figure(figsize=(4, 3))
plt.bar(["lambda 0", "lambda 1"], eig_b1, color="seagreen")
plt.axhline(0, color="black", linewidth=1)
plt.title("B1: SPD eigenvalues are positive")
plt.ylabel("eigenvalue"); plt.show()
```
▶ What you'll see: both bars sit above zero, confirming the bowl has positive curvature in every direction.

👀 Takeaway: CG is designed for symmetric positive-definite systems, not arbitrary matrices.

### Basic 2 — Evaluate the quadratic objective

**Goal.** Compute $f(x)=\frac12x^TAx-b^Tx$ at two points, because solving the system is equivalent to finding the bowl bottom.

```python
A_b2 = np.array([[4.0, 1.0], [1.0, 3.0]])
b_b2 = np.array([1.0, 2.0])
x0_b2 = np.array([0.0, 0.0])
x1_b2 = np.array([0.25, 0.5])
f0_b2 = 0.5 * x0_b2 @ A_b2 @ x0_b2 - b_b2 @ x0_b2
f1_b2 = 0.5 * x1_b2 @ A_b2 @ x1_b2 - b_b2 @ x1_b2
print("f(origin):", round(float(f0_b2), 3), "f(first point):", round(float(f1_b2), 3))
assert f1_b2 < f0_b2
```
▶ What you'll see: the objective drops after moving from the origin toward the solution.

```python
x_star_b2 = np.linalg.solve(A_b2, b_b2)
gx_b2 = np.linspace(-0.25, 0.65, 70)
gy_b2 = np.linspace(-0.1, 0.9, 70)
X_b2, Y_b2 = np.meshgrid(gx_b2, gy_b2)
Z_b2 = 0.5 * (A_b2[0, 0] * X_b2**2 + 2 * A_b2[0, 1] * X_b2 * Y_b2 + A_b2[1, 1] * Y_b2**2) - b_b2[0] * X_b2 - b_b2[1] * Y_b2
plt.figure(figsize=(4.4, 3.4))
plt.contour(X_b2, Y_b2, Z_b2, levels=16, cmap="viridis")
plt.plot([x0_b2[0], x1_b2[0]], [x0_b2[1], x1_b2[1]], marker="o", color="black", label="objective drop")
plt.scatter([x_star_b2[0]], [x_star_b2[1]], color="red", label="minimizer")
plt.title("B2: moving down the quadratic bowl")
plt.xlabel("x0"); plt.ylabel("x1"); plt.legend(); plt.show()
```
▶ What you'll see: the second point lies on a lower contour and closer to the bowl bottom.

👀 Takeaway: CG can be read as minimizing a quadratic, not just manipulating equations.

### Basic 3 — Compute the residual

**Goal.** Calculate $r=b-Ax$, because the residual is both the equation error and the negative gradient.

```python
A_b3 = np.array([[4.0, 1.0], [1.0, 3.0]])
b_b3 = np.array([1.0, 2.0])
x_b3 = np.zeros(2)
r_b3 = b_b3 - A_b3 @ x_b3
grad_b3 = A_b3 @ x_b3 - b_b3
print("residual:", r_b3)
print("negative gradient:", -grad_b3)
assert np.allclose(r_b3, -grad_b3)
```
▶ What you'll see: at the origin, the residual is exactly `(1, 2)`.

```python
x_star_b3 = np.linalg.solve(A_b3, b_b3)
gx_b3 = np.linspace(-0.25, 0.65, 70)
gy_b3 = np.linspace(-0.1, 0.9, 70)
X_b3, Y_b3 = np.meshgrid(gx_b3, gy_b3)
Z_b3 = 0.5 * (A_b3[0, 0] * X_b3**2 + 2 * A_b3[0, 1] * X_b3 * Y_b3 + A_b3[1, 1] * Y_b3**2) - b_b3[0] * X_b3 - b_b3[1] * Y_b3
plt.figure(figsize=(4.4, 3.4))
plt.contour(X_b3, Y_b3, Z_b3, levels=16, cmap="Greys")
plt.arrow(x_b3[0], x_b3[1], 0.15 * r_b3[0], 0.15 * r_b3[1], head_width=0.025, color="crimson", length_includes_head=True, label="residual")
plt.scatter([x_star_b3[0]], [x_star_b3[1]], color="red", label="solution")
plt.title("B3: residual is the downhill signal")
plt.xlabel("x0"); plt.ylabel("x1"); plt.legend(); plt.show()
```
▶ What you'll see: the residual arrow leaves the current point in the local downhill direction.

👀 Takeaway: residual norm is a stationarity check for the quadratic objective.

### Basic 4 — Use the residual as the first direction

**Goal.** Set $p_0=r_0$, because the first CG step is the same direction as steepest descent.

```python
A_b4 = np.array([[4.0, 1.0], [1.0, 3.0]])
b_b4 = np.array([1.0, 2.0])
x_b4 = np.zeros(2)
r_b4 = b_b4 - A_b4 @ x_b4
p_b4 = r_b4.copy()
print("r0:", r_b4, "p0:", p_b4)
assert np.allclose(p_b4, [1.0, 2.0])
```
▶ What you'll see: the first search direction copies the residual.

```python
plt.figure(figsize=(4, 3.4))
plt.arrow(0, 0, r_b4[0], r_b4[1], head_width=0.08, color="crimson", length_includes_head=True, label="r0")
plt.arrow(0, 0, p_b4[0], p_b4[1], head_width=0.04, color="teal", linestyle="--", length_includes_head=True, label="p0")
plt.xlim(-0.2, 1.4); plt.ylim(-0.2, 2.4)
plt.gca().set_aspect("equal", adjustable="box")
plt.title("B4: first CG direction equals residual")
plt.xlabel("x0"); plt.ylabel("x1"); plt.legend(); plt.show()
```
▶ What you'll see: the two arrows overlap, showing that CG begins as steepest descent.

```python
idx_b4 = np.arange(len(r_b4))
plt.figure(figsize=(4.2, 3))
plt.bar(idx_b4 - 0.16, r_b4, width=0.32, color="crimson", label="residual r0")
plt.bar(idx_b4 + 0.16, p_b4, width=0.32, color="teal", alpha=0.75, label="direction p0")
plt.xticks(idx_b4, ["component 0", "component 1"])
plt.title("B4: residual components become p0")
plt.ylabel("component value"); plt.legend(); plt.show()
```
▶ What you'll see: the paired bars have identical heights, confirming the initial search direction is the residual.

👀 Takeaway: CG starts with the obvious downhill direction before correcting future directions for conjugacy.

### Basic 5 — Compute A times a direction

**Goal.** Form $Ap$, because CG needs matrix-vector products instead of a dense inverse.

```python
A_b5 = np.array([[4.0, 1.0], [1.0, 3.0]])
p_b5 = np.array([1.0, 2.0])
Ap_b5 = A_b5 @ p_b5
print("A p:", Ap_b5)
assert np.allclose(Ap_b5, [6.0, 7.0])
```
▶ What you'll see: multiplying by `A` maps `(1, 2)` to `(6, 7)`.

```python
plt.figure(figsize=(4, 3.4))
plt.arrow(0, 0, p_b5[0], p_b5[1], head_width=0.12, color="teal", length_includes_head=True, label="p")
plt.arrow(0, 0, 0.25 * Ap_b5[0], 0.25 * Ap_b5[1], head_width=0.12, color="purple", length_includes_head=True, label="0.25 Ap")
plt.xlim(-0.2, 2.0); plt.ylim(-0.2, 2.2)
plt.gca().set_aspect("equal", adjustable="box")
plt.title("B5: A reshapes a direction")
plt.xlabel("x0"); plt.ylabel("x1"); plt.legend(); plt.show()
```
▶ What you'll see: the matrix-vector product points in a transformed direction, not just a longer copy of `p`.

```python
idx_b5 = np.arange(len(p_b5))
plt.figure(figsize=(4.2, 3))
plt.bar(idx_b5 - 0.16, p_b5, width=0.32, color="teal", label="p")
plt.bar(idx_b5 + 0.16, Ap_b5, width=0.32, color="purple", label="A @ p")
plt.xticks(idx_b5, ["component 0", "component 1"])
plt.title("B5: direction before and after A")
plt.ylabel("component value"); plt.legend(); plt.show()
```
▶ What you'll see: `A @ p` has much larger components, showing how the matrix encodes curvature along the direction.

👀 Takeaway: CG is attractive for large problems because it only asks for products like `A @ p`.

### Basic 6 — Compute the first alpha

**Goal.** Calculate $\alpha=(r^Tr)/(p^TAp)$, because this is the exact best step length along the current direction.

```python
r_b6 = np.array([1.0, 2.0])
p_b6 = r_b6.copy()
Ap_b6 = np.array([6.0, 7.0])
alpha_b6 = float((r_b6 @ r_b6) / (p_b6 @ Ap_b6))
print("alpha:", alpha_b6)
assert alpha_b6 == 0.25
```
▶ What you'll see: the first step length is `0.25`.

```python
alphas_b6 = np.linspace(0, 0.55, 80)
line_b6 = 0.5 * (p_b6 @ Ap_b6) * alphas_b6**2 - (r_b6 @ p_b6) * alphas_b6
plt.figure(figsize=(4.4, 3))
plt.plot(alphas_b6, line_b6, color="purple")
plt.axvline(alpha_b6, color="red", linestyle="--", label="alpha")
plt.title("B6: exact minimum along p0")
plt.xlabel("alpha"); plt.ylabel("line objective, shifted"); plt.legend(); plt.show()
```
▶ What you'll see: the one-dimensional quadratic is minimized at the computed step length.

👀 Takeaway: alpha balances residual energy against curvature in the search direction.

### Basic 7 — Update x after one line search

**Goal.** Apply $x_{k+1}=x_k+\alpha p_k$, because CG moves exactly to the minimum along the current line.

```python
x_b7 = np.zeros(2)
p_b7 = np.array([1.0, 2.0])
alpha_b7 = 0.25
x_next_b7 = x_b7 + alpha_b7 * p_b7
print("x next:", x_next_b7)
assert np.allclose(x_next_b7, [0.25, 0.5])
```
▶ What you'll see: the first iterate is `(0.25, 0.5)`.

```python
plt.figure(figsize=(4, 3.4))
plt.arrow(x_b7[0], x_b7[1], x_next_b7[0] - x_b7[0], x_next_b7[1] - x_b7[1], head_width=0.035, color="teal", length_includes_head=True)
plt.scatter([x_b7[0], x_next_b7[0]], [x_b7[1], x_next_b7[1]], color=["black", "red"])
plt.xlim(-0.05, 0.35); plt.ylim(-0.05, 0.6)
plt.title("B7: one line-search update")
plt.xlabel("x0"); plt.ylabel("x1"); plt.show()
```
▶ What you'll see: the arrow is exactly the scaled direction `alpha * p`.

👀 Takeaway: each CG iterate is the previous guess plus a scaled search direction.

### Basic 8 — Update the residual cheaply

**Goal.** Use $r_{k+1}=r_k-\alpha Ap_k$, because this avoids recomputing `A @ x` from scratch.

```python
r_b8 = np.array([1.0, 2.0])
Ap_b8 = np.array([6.0, 7.0])
alpha_b8 = 0.25
r_next_b8 = r_b8 - alpha_b8 * Ap_b8
```

▶ What you'll see: the run will deliberately reset the direction periodically.

```python
for k_a5 in range(6):
    Ap_a5 = A_a5 @ p_a5
    rr_a5 = float(r_a5 @ r_a5)
    alpha_a5 = rr_a5 / float(p_a5 @ Ap_a5)
    x_a5 = x_a5 + alpha_a5 * p_a5
    r_new_a5 = r_a5 - alpha_a5 * Ap_a5
    norms_a5.append(float(np.linalg.norm(r_new_a5)))
    beta_a5 = float((r_new_a5 @ r_new_a5) / rr_a5) if rr_a5 > 0 else 0.0
    if (k_a5 + 1) % restart_every_a5 == 0:
        p_a5 = r_new_a5.copy()
    else:
        p_a5 = r_new_a5 + beta_a5 * p_a5
    r_a5 = r_new_a5
print("approx solution:", np.round(x_a5, 6))
print("residual norms:", np.round(norms_a5, 10))
assert norms_a5[-1] < norms_a5[0]
```
▶ What you'll see: restarts still reduce the residual, though they may sacrifice exact finite termination.
