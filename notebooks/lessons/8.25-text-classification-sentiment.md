# 8.25 — Text Classification & Sentiment

Text classification turns a whole review, message, or ticket into a label a system can use. In this lesson we build sentiment classifiers from scratch: words become vectors, vectors become weighted evidence, evidence becomes probabilities, and probabilities become decisions whose threshold should match the cost of mistakes.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build text classification one idea at a time. Run each cell in order and read the printed intermediate values — every piece of math is shown so the classifier never feels like a black box. This walkthrough is self-contained (it imports what it needs) and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays, dot products, and tiny optimization loops.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
from collections import Counter  # small word-count dictionaries.
np.random.seed(0)  # reproducibility for random initialization.
```

### 1. Documents become bag-of-words vectors

A text classifier cannot multiply raw strings by weights, so the first step is a fixed vocabulary. A **bag-of-words** vector counts how often each vocabulary token appears and forgets word order. That is a crude summary, but it is enough to expose the central idea: each word count is a feature coordinate, and a document is a point in a numeric space.

```python
texts_w = ["good good movie", "bad boring movie", "good fun story", "bad dull story"]  # four toy documents.
labels_w = np.array([1, 0, 1, 0])  # 1 = positive sentiment, 0 = negative sentiment.
vocab_w = ["good", "bad", "fun", "boring", "dull", "movie", "story"]  # fixed feature order.
print("vocabulary:", vocab_w)  # inspect the coordinate system.
print("labels:", labels_w)  # inspect document-level targets.
```
▶ What you'll see: seven vocabulary coordinates and four whole-document sentiment labels.

```python
def vectorize_counts_w(texts, vocab):  # convert text strings into count rows.
    rows_w = []  # store one vector per document.
    for text_w in texts:  # process each document independently.
        counts_w = Counter(text_w.split())  # count tokens after simple whitespace splitting.
        rows_w.append([counts_w[token_w] for token_w in vocab])  # align counts to the fixed vocabulary.
    return np.array(rows_w, dtype=float)  # return a numeric design matrix.

X_w = vectorize_counts_w(texts_w, vocab_w)  # build the feature matrix.
print("X shape:", X_w.shape)  # 4 documents by 7 features.
print(X_w.astype(int))  # inspect counts.
assert X_w[0, 0] == 2 and X_w[1, 3] == 1  # good appears twice in doc0; boring once in doc1.
```
▶ What you'll see: each row is a document, each column is a word count, and the first review has two `good` counts.

```python
plt.figure(figsize=(5.4, 3))  # compact heatmap.
plt.imshow(X_w, cmap="Blues", aspect="auto")  # color = count value.
plt.colorbar(label="count")  # translate colors back to counts.
plt.xticks(range(len(vocab_w)), vocab_w, rotation=35, ha="right")  # readable token labels.
plt.yticks(range(len(texts_w)), ["doc0", "doc1", "doc2", "doc3"])  # document labels.
plt.title("1: bag-of-words document matrix"); plt.show()  # display the matrix.
```
▶ What you'll see: positive documents light up `good`/`fun`, while negative documents light up `bad`/`boring`/`dull`.

*Why it's done this way: a fixed vocabulary makes every document live in the same vector space, so the same learned weight can always multiply the same word's evidence; without that stable coordinate system, a dot product would mix meanings across columns.*

### 2. Weighted evidence becomes a logit and probability

Logistic regression assigns each feature a weight. A positive weight pushes the document toward positive sentiment; a negative weight pushes it toward negative sentiment. The weighted sum $z=x^\top w+b$ is a **logit** — unbounded evidence. The sigmoid $\sigma(z)=1/(1+e^{-z})$ squashes that evidence into $(0,1)$ so it can be used as a probability-like score.

```python
x_good_w = np.array([2.0, 0.0])  # features [good, bad] for "good good".
w_good_w = np.array([1.2, -1.5])  # good is positive evidence; bad is negative evidence.
b_good_w = 0.0  # keep the intercept zero for the hand calculation.
z_good_w = float(x_good_w @ w_good_w + b_good_w)  # logit = weighted evidence sum.
print("x:", x_good_w, "w:", w_good_w)  # inspect the vectors before multiplying.
print("logit z:", round(z_good_w, 3))  # 2*1.2 + 0*(-1.5) = 2.4.
assert round(z_good_w, 3) == 2.400  # concrete lesson number.
```
▶ What you'll see: two `good` counts create a logit of 2.4.

```python
def sigmoid_w(z):  # numerically simple sigmoid for tiny lesson values.
    return 1 / (1 + np.exp(-z))  # squash real-valued evidence into (0, 1).

p_good_w = float(sigmoid_w(z_good_w))  # probability-like positive score.
print("P(positive | good good):", round(p_good_w, 3))  # 0.917.
assert round(p_good_w, 3) == 0.917  # matches the source lesson.
```
▶ What you'll see: the logit 2.4 becomes probability 0.917, which is high positive confidence.

```python
z_grid_w = np.linspace(-6, 6, 200)  # possible logits.
p_grid_w = sigmoid_w(z_grid_w)  # map each logit through sigmoid.
plt.figure(figsize=(4.6, 3))  # compact curve.
plt.plot(z_grid_w, p_grid_w, color="purple")  # sigmoid curve.
plt.scatter([z_good_w], [p_good_w], color="crimson", zorder=3)  # mark the worked document.
plt.axhline(0.5, color="gray", linestyle="--")  # neutral probability.
plt.title("2: sigmoid turns evidence into probability"); plt.xlabel("logit z"); plt.ylabel("σ(z)"); plt.show()
```
▶ What you'll see: logits near 0 map near 0.5, while a logit of 2.4 lands high on the curve.

*Why it's done this way: the dot product adds independent pieces of word evidence, while the sigmoid is the inverse-log-odds transform — each +1 in logit space multiplies the odds by $e$, then the result is normalized back to a probability scale.*

### 3. Phrases and negation require richer features

A unigram counter sees `not good` as containing the positive token `good`, so it can make the wrong decision. A simple scratch-built fix is to add phrase features such as `not_good`. This does not make the model linguistic, but it gives the linear classifier a coordinate whose weight can represent the composition of the two words.

```python
phrase_vocab_w = ["good", "not_good"]  # unigram plus a phrase feature.
w_phrase_w = np.array([1.2, -2.0])  # good alone helps; not_good reverses sentiment.
examples_phrase_w = ["good", "not good"]  # compare a positive word with a negated phrase.
print("phrase vocabulary:", phrase_vocab_w)  # inspect the feature coordinates.
print("weights:", w_phrase_w)  # inspect each feature's evidence weight.
```
▶ What you'll see: the phrase feature has a negative weight large enough to reverse `good`.

```python
def phrase_features_w(text):  # build [good_count, not_good_count].
    toks_w = text.split()  # simple tokenization.
    good_count_w = toks_w.count("good")  # unigram evidence.
    not_good_count_w = sum(1 for i_w in range(len(toks_w) - 1) if toks_w[i_w] == "not" and toks_w[i_w + 1] == "good")  # phrase evidence.
    return np.array([good_count_w, not_good_count_w], dtype=float)  # two-feature vector.

X_phrase_w = np.vstack([phrase_features_w(t_w) for t_w in examples_phrase_w])  # vectorize both phrases.
z_phrase_w = X_phrase_w @ w_phrase_w  # phrase-aware logits.
p_phrase_w = sigmoid_w(z_phrase_w)  # phrase-aware probabilities.
print("features:\n", X_phrase_w.astype(int))  # inspect good and not_good counts.
print("probabilities:", np.round(p_phrase_w, 3))  # [0.769, 0.310].
assert np.allclose(np.round(p_phrase_w, 3), [0.769, 0.310])  # source lesson numbers.
```
▶ What you'll see: `good` scores 0.769 positive, while `not good` scores only 0.310.

```python
plt.figure(figsize=(4.6, 3))  # comparison chart.
plt.bar(examples_phrase_w, p_phrase_w, color=["seagreen", "indianred"])  # show phrase effect.
plt.axhline(0.5, color="black", linestyle="--", linewidth=1)  # default decision threshold.
plt.ylim(0, 1); plt.ylabel("P(positive)")  # probability scale.
plt.title("3: negation changes the evidence"); plt.show()  # display.
```
▶ What you'll see: the negated phrase falls below the 0.5 line even though it contains the word `good`.

*Why it's done this way: a linear model can only add weighted coordinates, so it needs a coordinate for any interaction we want it to learn; phrase features turn a non-additive language pattern into an additive numerical feature.*

### 4. Learning weights from labeled text with gradient descent

Hand-picked weights explain the formula, but real classifiers learn weights from labeled examples. For one document, logistic loss is $-[y\log p+(1-y)\log(1-p)]$. Its gradient is $(p-y)x$ for weights and $(p-y)$ for the bias. If the model predicts too low for a positive review, $p-y$ is negative, so subtracting the gradient increases weights on the words in that review.

```python
train_texts_w = ["good fun", "good movie", "bad dull", "bad boring", "not good", "not bad good"]  # inline toy corpus.
y_train_w = np.array([1, 1, 0, 0, 0, 1], dtype=float)  # sentiment labels.
train_vocab_w = ["good", "bad", "fun", "dull", "boring", "not_good", "not_bad"]  # include phrase features.
print("training examples:", len(train_texts_w))  # inspect corpus size.
print("labels:", y_train_w.astype(int))  # inspect targets.
```
▶ What you'll see: six labeled examples with both unigram and negation evidence.

```python
def featurize_train_w(text):  # vectorize one text with unigram and phrase counts.
    toks_w = text.split()  # tokenize.
    counts_w = Counter(toks_w)  # unigram counts.
    feats_w = [counts_w[tok_w] for tok_w in train_vocab_w[:5]]  # first five unigram features.
    feats_w.append(sum(1 for i_w in range(len(toks_w) - 1) if toks_w[i_w] == "not" and toks_w[i_w + 1] == "good"))  # not_good.
    feats_w.append(sum(1 for i_w in range(len(toks_w) - 1) if toks_w[i_w] == "not" and toks_w[i_w + 1] == "bad"))  # not_bad.
    return np.array(feats_w, dtype=float)  # numeric feature vector.

X_train_w = np.vstack([featurize_train_w(t_w) for t_w in train_texts_w])  # design matrix.
print("X_train shape:", X_train_w.shape)  # six docs by seven features.
print(X_train_w.astype(int))  # inspect feature counts.
```
▶ What you'll see: phrase columns activate only for `not good` and `not bad` constructions.

```python
w_lr_w = np.zeros(X_train_w.shape[1])  # start from no word evidence.
b_lr_w = 0.0  # start from neutral intercept.
losses_lr_w = []  # record training loss.
for epoch_w in range(400):  # full-batch gradient descent.
    z_lr_w = X_train_w @ w_lr_w + b_lr_w  # logits for every document.
    p_lr_w = sigmoid_w(z_lr_w)  # probabilities.
    loss_lr_w = -np.mean(y_train_w * np.log(p_lr_w + 1e-9) + (1 - y_train_w) * np.log(1 - p_lr_w + 1e-9))  # logistic loss.
    losses_lr_w.append(loss_lr_w)  # store for the curve.
    grad_w_lr_w = X_train_w.T @ (p_lr_w - y_train_w) / len(y_train_w)  # weight gradient.
    grad_b_lr_w = float(np.mean(p_lr_w - y_train_w))  # bias gradient.
    w_lr_w -= 0.8 * grad_w_lr_w  # descend weights.
    b_lr_w -= 0.8 * grad_b_lr_w  # descend bias.
print("loss start -> end:", round(losses_lr_w[0], 3), "->", round(losses_lr_w[-1], 3))  # should fall.
print("learned weights:", dict(zip(train_vocab_w, np.round(w_lr_w, 2))))  # inspect evidence signs.
assert losses_lr_w[-1] < losses_lr_w[0]  # training learned something.
```
▶ What you'll see: loss falls from 0.693 and positive/negative words get opposite-signed weights.

```python
plt.figure(figsize=(4.8, 3))  # loss curve.
plt.plot(losses_lr_w, color="teal")  # training objective over epochs.
plt.title("4: logistic loss decreases"); plt.xlabel("epoch"); plt.ylabel("mean logistic loss"); plt.show()  # display.
```
▶ What you'll see: a smooth decline, showing the weights are moving toward labels rather than being chosen by hand.

*Why it's done this way: logistic loss is the negative log-likelihood of Bernoulli labels, and its $(p-y)$ error term has the right sign — overconfident false positives reduce positive evidence, while underconfident positives increase it.*

### 5. Thresholds turn probabilities into product decisions

A model outputs probabilities, but the product usually needs a label. The threshold $\tau$ is therefore a policy choice: predict positive when $p>\tau$. Raising $\tau$ makes the classifier speak positive less often, usually increasing precision while decreasing recall.

```python
probs_w = np.array([0.10, 0.35, 0.40, 0.60, 0.72, 0.90])  # model scores.
y_true_w = np.array([0, 1, 0, 1, 1, 1])  # true labels.
thresholds_w = np.array([0.3, 0.5, 0.7])  # operating points to compare.
print("probabilities:", probs_w)  # inspect scores.
print("true labels:", y_true_w)  # inspect labels.
```
▶ What you'll see: one positive has a low-ish score (0.35), making threshold choice matter.

```python
precisions_w, recalls_w, accuracies_w = [], [], []  # metric storage.
for tau_w in thresholds_w:  # evaluate each threshold.
    pred_w = (probs_w > tau_w).astype(int)  # convert probabilities to labels.
    tp_w = int(np.sum((pred_w == 1) & (y_true_w == 1)))  # true positives.
    fp_w = int(np.sum((pred_w == 1) & (y_true_w == 0)))  # false positives.
    fn_w = int(np.sum((pred_w == 0) & (y_true_w == 1)))  # false negatives.
    precisions_w.append(tp_w / (tp_w + fp_w) if tp_w + fp_w else 0.0)  # precision.
    recalls_w.append(tp_w / (tp_w + fn_w) if tp_w + fn_w else 0.0)  # recall.
    accuracies_w.append(float(np.mean(pred_w == y_true_w)))  # accuracy.
    print(f"tau={tau_w}: pred={pred_w.tolist()}, precision={precisions_w[-1]:.3f}, recall={recalls_w[-1]:.3f}")  # inspect.
assert np.allclose(np.round(precisions_w, 3), [0.8, 1.0, 1.0])  # concrete precision pattern.
assert np.allclose(np.round(recalls_w, 3), [1.0, 0.75, 0.5])  # concrete recall pattern.
```
▶ What you'll see: stricter thresholds remove false positives but miss more positives.

```python
plt.figure(figsize=(5, 3))  # threshold tradeoff plot.
plt.plot(thresholds_w, precisions_w, marker="o", label="precision")  # precision rises.
plt.plot(thresholds_w, recalls_w, marker="s", label="recall")  # recall falls.
plt.plot(thresholds_w, accuracies_w, marker="^", label="accuracy")  # accuracy may peak elsewhere.
plt.ylim(0, 1.05); plt.xlabel("threshold τ"); plt.ylabel("metric")  # axes.
plt.title("5: threshold tuning tradeoff"); plt.legend(); plt.show()  # display.
```
▶ What you'll see: precision and recall move in opposite directions as the threshold rises.

*Why it's done this way: the sigmoid gives a ranking and confidence scale, but the threshold encodes asymmetric costs — spam filtering, safety routing, and sentiment dashboards may all prefer different false-positive/false-negative tradeoffs.*

### 6. Confusion matrices reveal the shape of mistakes

Accuracy is the diagonal of a confusion matrix divided by the total count. It is useful, but it hides which mistakes occurred. A sentiment model with many false positives may be unacceptable for moderation even if its overall accuracy looks high, so we inspect the full matrix and derived metrics.

```python
cm_w = np.array([[8, 2], [1, 9]])  # rows = true [negative, positive], cols = predicted [negative, positive].
correct_w = int(cm_w[0, 0] + cm_w[1, 1])  # diagonal count.
total_w = int(cm_w.sum())  # all examples.
acc_w = correct_w / total_w  # accuracy.
print("confusion matrix:\n", cm_w)  # inspect counts.
print("accuracy:", round(acc_w, 3))  # 17/20 = 0.85.
assert round(acc_w, 3) == 0.850  # source lesson number.
```
▶ What you'll see: 17 correct predictions out of 20, but two false positives and one false negative.

```python
tn_w, fp_w, fn_w, tp_w = cm_w.ravel()  # unpack counts from the matrix.
precision_w = tp_w / (tp_w + fp_w)  # among predicted positives, how many were right.
recall_w = tp_w / (tp_w + fn_w)  # among true positives, how many were found.
print("precision:", round(precision_w, 3), "recall:", round(recall_w, 3))  # inspect asymmetric metrics.
assert round(precision_w, 3) == 0.818 and round(recall_w, 3) == 0.900  # concrete metrics.
```
▶ What you'll see: recall is higher than precision because false positives outnumber false negatives.

```python
plt.figure(figsize=(3.8, 3.2))  # compact confusion heatmap.
plt.imshow(cm_w, cmap="Oranges")  # color = count.
plt.colorbar(label="count")  # count scale.
plt.xticks([0, 1], ["pred neg", "pred pos"]); plt.yticks([0, 1], ["true neg", "true pos"])  # labels.
for i_w in range(2):  # annotate rows.
    for j_w in range(2):  # annotate columns.
        plt.text(j_w, i_w, str(cm_w[i_w, j_w]), ha="center", va="center", color="black")  # count label.
plt.title("6: confusion matrix"); plt.show()  # display.
```
▶ What you'll see: the off-diagonal cells show exactly which kind of sentiment error the model makes.

*Why it's done this way: every threshold collapses probabilities into four count types, and different applications attach different costs to those cells; the confusion matrix is the accounting ledger behind accuracy, precision, and recall.*

### ✍️ Toy 1 · Bag-of-words maps reviews to rows

A classifier needs a fixed coordinate system before it can use text. Count each vocabulary word in
each tiny review to build a document matrix.

```python
import numpy as np
import matplotlib.pyplot as plt

t1_rng = np.random.default_rng(0)                              # -> seed 0
t1_texts = ["great snack", "bad snack", "great great meal"]     # -> 3 documents
t1_vocab = ["bad", "great", "meal", "snack"]                   # -> fixed feature order
t1_X = np.zeros((len(t1_texts), len(t1_vocab)), dtype=int)      # -> shape (3, 4)
```

### ✍️ Toy 2 · Dot products become sentiment probabilities

Logistic regression first adds weighted evidence into a logit, then applies the sigmoid to turn that
unbounded score into a probability-like number.

```python
import numpy as np

t2_rng = np.random.default_rng(0)                              # -> seed 0
t2_x = np.array([2.0, 0.0, 1.0])                               # -> feature counts
t2_w = np.array([1.0, -1.5, 0.5])                              # -> feature weights
t2_b = -0.5                                                    # -> bias
t2_products = t2_x * t2_w                                      # -> [2.0, -0.0, 0.5]
t2_sum = float(t2_products.sum())                              # -> 2.5
t2_logit = t2_sum + t2_b                                       # -> 2.0
t2_prob = 1 / (1 + np.exp(-t2_logit))                          # -> 0.881
print("features:", t2_x.tolist())                              # -> [2.0, 0.0, 1.0]
print("weights:", t2_w.tolist())                               # -> [1.0, -1.5, 0.5]
print("feature*weight:", t2_products.tolist())                 # -> [2.0, -0.0, 0.5]
print("sum before bias:", round(t2_sum, 3))                    # -> 2.5
print("logit:", round(t2_logit, 3))                            # -> 2.0
print("probability:", round(float(t2_prob), 3))                # -> 0.881
assert round(float(t2_prob), 3) == 0.881

plt.figure(figsize=(4.8, 3.0))
t2_grid = np.linspace(-5, 5, 200)
t2_curve = 1 / (1 + np.exp(-t2_grid))
plt.plot(t2_grid, t2_curve, color="purple")
plt.scatter([t2_logit], [t2_prob], color="crimson", zorder=3)
plt.axhline(0.5, color="gray", linestyle="--")
plt.xlabel("logit")
plt.ylabel("sigmoid")
plt.title("Toy 2 · evidence to probability")
plt.show()
```
▶ What you'll see: the logit `2.0` lands high on the sigmoid curve at probability `0.881`.

### ✍️ Toy 3 · A phrase feature flips negation

The unigram `good` is positive evidence, but `not good` should not be. Add a phrase feature so the
linear model can give negation its own negative weight.

```python
import numpy as np

t3_rng = np.random.default_rng(0)                              # -> seed 0
t3_texts = ["good", "not good"]                                # -> compare unigram and phrase
t3_weights = np.array([1.0, -2.0])                             # -> [good, not_good] weights
t3_X = []                                                      # -> feature rows
for t3_text in t3_texts:
    t3_tokens = t3_text.split()
    t3_good = t3_tokens.count("good")
    t3_not_good = sum(1 for t3_i in range(len(t3_tokens) - 1) if t3_tokens[t3_i] == "not" and t3_tokens[t3_i + 1] == "good")
    t3_X.append([t3_good, t3_not_good])
t3_X = np.array(t3_X, dtype=float)                             # -> [[1, 0], [1, 1]]
t3_logits = t3_X @ t3_weights                                  # -> [1.0, -1.0]
t3_probs = 1 / (1 + np.exp(-t3_logits))                        # -> [0.731, 0.269]
print("texts:", t3_texts)                                      # -> ['good', 'not good']
print("features [good, not_good]:", t3_X.astype(int).tolist()) # -> [[1, 0], [1, 1]]
print("weights:", t3_weights.tolist())                         # -> [1.0, -2.0]
print("logits:", t3_logits.tolist())                           # -> [1.0, -1.0]
print("probabilities:", np.round(t3_probs, 3).tolist())        # -> [0.731, 0.269]
assert np.allclose(np.round(t3_probs, 3), [0.731, 0.269])

plt.figure(figsize=(4.4, 3.0))
plt.bar(t3_texts, t3_probs, color=["seagreen", "indianred"])
plt.axhline(0.5, color="black", linestyle="--")
plt.ylim(0, 1)
plt.ylabel("P(positive)")
plt.title("Toy 3 · negation feature")
plt.show()
```
▶ What you'll see: `not good` falls below the decision line even though it still contains the word `good`.

### ✍️ Toy 4 · Gradient descent learns sentiment weights

Starting from zero evidence, logistic-loss gradients push the `good-like` coordinate positive and the
`bad-like` coordinate negative.

```python
import numpy as np

t4_rng = np.random.default_rng(0)                              # -> seed 0
t4_X = np.array([[1.0, 0.0], [2.0, 0.0], [0.0, 1.0], [0.0, 2.0]])  # -> two positive, two negative rows
t4_y = np.array([1.0, 1.0, 0.0, 0.0])                          # -> labels
t4_w = np.zeros(2)                                             # -> [0.0, 0.0]
t4_b = 0.0                                                     # -> neutral bias

def t4_sigmoid(t4_z):
    return 1 / (1 + np.exp(-t4_z))

t4_losses = []                                                 # -> loss history
for t4_epoch in range(80):
    t4_z = t4_X @ t4_w + t4_b
    t4_p = t4_sigmoid(t4_z)
    t4_loss = -np.mean(t4_y * np.log(t4_p + 1e-9) + (1 - t4_y) * np.log(1 - t4_p + 1e-9))
    t4_losses.append(t4_loss)
    t4_error = t4_p - t4_y
    t4_grad_w = t4_X.T @ t4_error / len(t4_y)
    t4_grad_b = float(t4_error.mean())
    t4_w -= 0.6 * t4_grad_w
    t4_b -= 0.6 * t4_grad_b
t4_final_p = t4_sigmoid(t4_X @ t4_w + t4_b)                   # -> [0.939, 0.996, 0.061, 0.004]
print("X:", t4_X.astype(int).tolist())                         # -> [[1, 0], [2, 0], [0, 1], [0, 2]]
print("labels:", t4_y.astype(int).tolist())                    # -> [1, 1, 0, 0]
print("loss start/end:", round(float(t4_losses[0]), 3), round(float(t4_losses[-1]), 3))  # -> 0.693 0.034
print("learned weights:", np.round(t4_w, 3).tolist())          # -> [2.732, -2.732]
print("learned bias:", round(float(t4_b), 3))                  # -> -0.0
print("final probabilities:", np.round(t4_final_p, 3).tolist())  # -> [0.939, 0.996, 0.061, 0.004]
assert t4_losses[-1] < t4_losses[0]
assert t4_w[0] > 0 and t4_w[1] < 0

plt.figure(figsize=(4.8, 3.0))
plt.plot(t4_losses, color="teal")
plt.xlabel("epoch")
plt.ylabel("mean logistic loss")
plt.title("Toy 4 · training loss decreases")
plt.show()
```
▶ What you'll see: loss falls from `0.693` to `0.034`, with opposite-signed learned weights.

## 🟡 Easy

### Easy 1 — Train logistic regression from scratch

**Goal.** Learn sentiment weights with batch gradient descent, because real classifiers should infer evidence strengths from labeled data. We build it in 4 steps.

```python
texts_e1 = ["good fun", "good movie", "bad dull", "bad boring", "not good", "not bad good"] # inline training corpus.
y_e1 = np.array([1, 1, 0, 0, 0, 1], dtype=float) # binary sentiment labels.
vocab_e1 = ["good", "bad", "fun", "dull", "boring", "not_good", "not_bad"] # feature vocabulary.
print("training rows:", len(texts_e1)) # inspect corpus size.
```
▶ What you'll see: six labeled examples define the whole dataset.

```python
def make_x_e1(text_e1): # vectorize one review.
    toks_e1 = text_e1.split() # tokenize.
    c_e1 = Counter(toks_e1) # unigram counts.
    feats_e1 = [c_e1[tok_e1] for tok_e1 in vocab_e1[:5]] # unigram feature counts.
    feats_e1 += [sum(1 for i_e1 in range(len(toks_e1)-1) if toks_e1[i_e1] == "not" and toks_e1[i_e1+1] == "good")] # not_good.
    feats_e1 += [sum(1 for i_e1 in range(len(toks_e1)-1) if toks_e1[i_e1] == "not" and toks_e1[i_e1+1] == "bad")] # not_bad.
    return np.array(feats_e1, dtype=float) # numeric vector.
X_e1 = np.vstack([make_x_e1(t_e1) for t_e1 in texts_e1]) # build matrix.
print("X shape:", X_e1.shape) # inspect dimensions.
```

```python
w_e1 = np.zeros(X_e1.shape[1]) # initialize weights.
b_e1 = 0.0 # initialize bias.
losses_e1 = [] # record loss.
for epoch_e1 in range(500): # run batch gradient descent.
    z_e1 = X_e1 @ w_e1 + b_e1 # logits.
    p_e1 = 1 / (1 + np.exp(-z_e1)) # probabilities.
    losses_e1.append(float(-np.mean(y_e1*np.log(p_e1 + 1e-9) + (1-y_e1)*np.log(1-p_e1 + 1e-9)))) # logistic loss.
    w_e1 -= 0.7 * (X_e1.T @ (p_e1 - y_e1) / len(y_e1)) # update weights.
    b_e1 -= 0.7 * float(np.mean(p_e1 - y_e1)) # update bias.
print("loss start/end:", round(losses_e1[0], 3), round(losses_e1[-1], 3)) # inspect learning.
assert losses_e1[-1] < 0.15 # verify strong fit on tiny corpus.
```

```python
plt.figure(figsize=(4.5, 3)) # create training curve.
plt.plot(losses_e1, color="teal") # plot loss by epoch.
plt.title("Easy 1: training logistic regression") # title.
plt.xlabel("epoch") # x label.
plt.ylabel("loss") # y label.
plt.show() # display.
```
▶ What you'll see: loss decreases steadily as weights learn sentiment evidence.

👀 Takeaway: from-scratch logistic regression is just vectorization, sigmoid probabilities, logistic loss, and gradient descent.

### Easy 4 — Tune a threshold for precision and recall

**Goal.** Sweep thresholds and compute metrics, because the best operating point depends on whether false positives or false negatives cost more. We build it in 3 steps.

```python
probs_e4 = np.array([0.05, 0.20, 0.35, 0.55, 0.62, 0.80, 0.95]) # validation probabilities.

taus_e4 = np.array([0.3, 0.5, 0.7]) # thresholds to compare.

```
▶ What you'll see: thresholds span lenient, default, and strict policies.

```python
precision_e4, recall_e4, accuracy_e4 = [], [], [] # metric lists.
for tau_e4 in taus_e4: # evaluate each threshold.
    pred_e4 = (probs_e4 > tau_e4).astype(int) # threshold scores.
    tp_e4 = np.sum((pred_e4 == 1) & (y_e4 == 1)) # true positives.
    fp_e4 = np.sum((pred_e4 == 1) & (y_e4 == 0)) # false positives.
    fn_e4 = np.sum((pred_e4 == 0) & (y_e4 == 1)) # false negatives.
    precision_e4.append(tp_e4 / (tp_e4 + fp_e4) if tp_e4 + fp_e4 else 0) # precision.
    recall_e4.append(tp_e4 / (tp_e4 + fn_e4) if tp_e4 + fn_e4 else 0) # recall.
    accuracy_e4.append(np.mean(pred_e4 == y_e4)) # accuracy.
print("precision:", np.round(precision_e4, 3)) # inspect precision curve.
print("recall:", np.round(recall_e4, 3)) # inspect recall curve.
```

```python

plt.figure(figsize=(5, 3)) # create metric plot.

plt.plot(taus_e4, recall_e4, marker="s", label="recall") # recall curve.
```

▶ What you'll see: stricter thresholds improve precision while recall drops.

👀 Takeaway: threshold tuning is a deployment decision, not a change to the underlying learned probabilities.

### Advanced 1 — Add TF-IDF weighting
