# 22.7 — Monte Carlo Tree Search

Monte Carlo Tree Search (MCTS) chooses actions when the full game tree is too large to search exactly. It grows a partial tree, uses rollouts to estimate rewards, and uses UCT to balance high-value moves against uncertain moves that still deserve evidence.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build Monte Carlo Tree Search one idea at a time. Run each cell in order and read the printed intermediate values — every selection score, rollout, and backup is shown. The walkthrough is self-contained and uses a `_w` suffix on variables so it never clashes with the examples below.

```python
import numpy as np  # arrays, random choices, and numerical checks.
import matplotlib.pyplot as plt  # every walkthrough subsection includes a relevant visualization.
from math import log, sqrt  # UCT uses log and square root.
np.random.seed(0)  # make the walkthrough deterministic.

class NodeW:
    def __init__(self, stones, player, parent=None, action=None):
        self.stones = stones
        self.player = player
        self.parent = parent
        self.action = action
        self.children = []
        self.untried = [a for a in (1, 2) if a <= stones]
        self.visits = 0
        self.value = 0.0

def winner_w(stones, player):
    return -player if stones == 0 else 0

def reward_for_root_w(stones, player):
    return 1.0 if winner_w(stones, player) == 1 else 0.0

def child_state_w(node, action):
    return node.stones - action, -node.player

def uct_w(parent, child, c=1.4):
    if child.visits == 0:
        return float("inf")
    return child.value / child.visits + c * sqrt(log(parent.visits) / child.visits)
```

### 1. Partial search trees replace full minimax trees

Minimax from the previous lesson expands the tree deeply and exactly. MCTS does something cheaper: it keeps a partial tree whose nodes store only two statistics, visit count $n$ and accumulated reward $w$. In this toy game, seven stones are on the table, players alternate taking 1 or 2 stones, and the player who takes the last stone wins. A state is `(stones, player)`, where `player=1` is the root player whose win probability we estimate.

```python
root_w = NodeW(7, 1)
for a_w in root_w.untried:
    s_w, p_w = child_state_w(root_w, a_w)
    root_w.children.append(NodeW(s_w, p_w, parent=root_w, action=a_w))
root_w.visits = 12
root_w.children[0].visits, root_w.children[0].value = 7, 4.0
root_w.children[1].visits, root_w.children[1].value = 5, 2.0
print("root state:", (root_w.stones, root_w.player), "visits:", root_w.visits)
print("children (action, stones, visits, value):", [(c.action, c.stones, c.visits, c.value) for c in root_w.children])
assert len(root_w.children) == 2

x_w = np.array([0, 1, 2])
labels_w = ["root\n7 stones", "take 1\n6 stones", "take 2\n5 stones"]
visits_w = [root_w.visits] + [c.visits for c in root_w.children]
values_w = [root_w.value] + [c.value for c in root_w.children]
plt.figure(figsize=(6, 3.4))
plt.scatter(x_w, [1, 0, 0], s=np.array(visits_w) * 70 + 80, c=values_w, cmap="viridis")
for i_w, lab_w in enumerate(labels_w):
    plt.text(x_w[i_w], [1, 0, 0][i_w] + 0.08, f"{lab_w}\nn={visits_w[i_w]}, w={values_w[i_w]:.1f}", ha="center")
plt.plot([0, 1], [1, 0], color="gray"); plt.plot([0, 2], [1, 0], color="gray")
plt.axis("off")
plt.title("Walkthrough 1: a partial MCTS tree stores statistics")
plt.show()
```
▶ What you'll see: only the root and two children exist, and their circle sizes show how visits concentrate in the partial tree.

*Why it's done this way:* MCTS spends memory and computation only on states it samples, so it can act even when the complete minimax tree is too large.

### 2. UCT balances exploitation and exploration

Selection needs a score that does not blindly choose the current best mean. UCT uses

$$\text{UCT}_i=\bar X_i+c\sqrt{\frac{\ln N}{n_i}},$$

where $\bar X_i=w_i/n_i$ is exploitation, $N$ is the parent visit count, $n_i$ is the child visit count, and $c$ controls exploration. The square-root term is large when a child has few visits, so uncertain moves keep getting chances.

```python
N_w = 20
vis_w = np.array([10, 2, 8], dtype=float)
wins_w = np.array([6, 1, 5], dtype=float)
c_w = 1.4
exploit_w = wins_w / vis_w
explore_w = c_w * np.sqrt(np.log(N_w) / vis_w)
uct_vals_w = exploit_w + explore_w
print("exploitation:", np.round(exploit_w, 3))
print("exploration:", np.round(explore_w, 3))
print("UCT:", np.round(uct_vals_w, 3))
assert np.argmax(uct_vals_w) == 1

x_w = np.arange(3)
plt.figure(figsize=(6, 3.4))
plt.bar(x_w, exploit_w, label="mean reward", color="seagreen")
plt.bar(x_w, explore_w, bottom=exploit_w, label="uncertainty bonus", color="goldenrod")
plt.xticks(x_w, ["A n=10", "B n=2", "C n=8"])
plt.ylabel("UCT score")
plt.title("Walkthrough 2: UCT = exploitation + exploration")
plt.legend()
plt.show()
```
▶ What you'll see: child B wins selection even with a lower mean because its low visit count creates a larger exploration bonus.

*Why it's done this way:* the formula is optimistic under uncertainty — a poorly sampled child is temporarily treated as potentially good until evidence reduces its bonus.

### 3. Expansion adds one new child at the frontier

After selection reaches a node that still has legal actions not in the tree, MCTS expands one of them. Expansion is deliberately incremental: it adds just one child, then immediately estimates that child by simulation. This keeps the tree narrow early and lets the data decide which frontier branches deserve more growth.

```python
frontier_w = NodeW(5, -1)
frontier_w.visits = 3
print("untried before expansion:", frontier_w.untried)
a_w = frontier_w.untried.pop(0)
s_w, p_w = child_state_w(frontier_w, a_w)
new_child_w = NodeW(s_w, p_w, parent=frontier_w, action=a_w)
frontier_w.children.append(new_child_w)
print("expanded action:", a_w, "new state:", (new_child_w.stones, new_child_w.player))
print("untried after expansion:", frontier_w.untried)
assert len(frontier_w.children) == 1

plt.figure(figsize=(5.5, 3.2))
plt.scatter([0, 1], [1, 0], s=[350, 160], color=["steelblue", "orange"])
plt.plot([0, 1], [1, 0], color="gray")
plt.text(0, 1.08, "frontier\n5 stones\nuntried: take 2", ha="center")
plt.text(1, 0.08, "new child\n4 stones\nfrom take 1", ha="center")
plt.axis("off")
plt.title("Walkthrough 3: expansion grows one frontier edge")
plt.show()
```
▶ What you'll see: one action leaves the untried list and appears as a new child in the search tree.

*Why it's done this way:* growing one child per iteration prevents wasteful full-width expansion before rollouts have said which moves are promising.

### 4. Simulation estimates value by rollout

A newly expanded node usually is not terminal, so MCTS estimates its value by playing a cheap rollout policy to the end. Here the rollout policy is uniform random legal moves. The final reward is from the root player's perspective: `1.0` for a root-player win and `0.0` for a loss.

```python
rng_w = np.random.default_rng(4)
stones_w, player_w = 4, 1
trajectory_w = [(stones_w, player_w)]
while stones_w > 0:
    action_w = int(rng_w.choice([a for a in (1, 2) if a <= stones_w]))
    stones_w -= action_w
    player_w = -player_w
    trajectory_w.append((stones_w, player_w))
reward_w = reward_for_root_w(stones_w, player_w)
print("rollout trajectory:", trajectory_w)
print("reward for root player:", reward_w)
assert stones_w == 0

plt.figure(figsize=(6, 3.2))
plt.plot(range(len(trajectory_w)), [s for s, _ in trajectory_w], marker="o", color="purple")
for t_w, (s_w, p_w) in enumerate(trajectory_w):
    plt.text(t_w, s_w + 0.15, f"p={p_w}", ha="center")
plt.xlabel("rollout step"); plt.ylabel("stones remaining")
plt.title("Walkthrough 4: a random rollout reaches a terminal reward")
plt.show()
```
▶ What you'll see: stones decrease to zero along one sampled continuation, producing one noisy win/loss estimate.

*Why it's done this way:* rollouts trade exact evaluation for many cheap samples, so value estimates improve statistically as visits accumulate.

### 5. Backpropagation updates every node on the selected path

The rollout reward belongs to the whole decision path that led to the simulation. Backpropagation walks from the expanded node back to the root, adding one visit and the same root-perspective reward to each node. After many iterations, each child mean $w/n$ becomes an empirical win-rate estimate.

```python
root2_w = NodeW(7, 1)
child2_w = NodeW(6, -1, parent=root2_w, action=1)
grand2_w = NodeW(4, 1, parent=child2_w, action=2)
root2_w.children = [child2_w]; child2_w.children = [grand2_w]
for node_w, n_w, val_w in [(root2_w, 5, 2.0), (child2_w, 3, 1.0), (grand2_w, 1, 0.0)]:
    node_w.visits, node_w.value = n_w, val_w
path_w = [root2_w, child2_w, grand2_w]
before_w = [(n.visits, n.value) for n in path_w]
reward_w = 1.0
for node_w in reversed(path_w):
    node_w.visits += 1
    node_w.value += reward_w
after_w = [(n.visits, n.value) for n in path_w]
print("before:", before_w)
print("after:", after_w)
assert after_w[0] == (6, 3.0)

plt.figure(figsize=(6, 3.2))
labels_w = ["root", "child", "grandchild"]
plt.plot(labels_w, [b[1] / b[0] for b in before_w], marker="o", label="before")
plt.plot(labels_w, [a[1] / a[0] for a in after_w], marker="s", label="after win backup")
plt.ylim(0, 1.05); plt.ylabel("mean reward w/n")
plt.title("Walkthrough 5: backup changes path value estimates")
plt.legend()
plt.show()
```
▶ What you'll see: every node on the path gets one more visit, and its mean reward shifts upward after a winning rollout.

*Why it's done this way:* backup turns a terminal sample into improved statistics for all earlier choices that made the sample possible.

### 6. Repeating the loop allocates visits to promising moves

The complete MCTS loop repeats selection, expansion, simulation, and backpropagation. Early on, exploration tries multiple children; later, children with better empirical outcomes tend to receive more visits. The final action is usually chosen by visit count, not by a fragile mean after few samples.

```python
def run_mcts_w(iterations=80, seed=7):
    rng = np.random.default_rng(seed)
    root = NodeW(7, 1)
    visit_history = []
    for _ in range(iterations):
        node = root
        path = [node]
        while node.stones > 0 and not node.untried and node.children:
            scores = [uct_w(node, ch, 1.4) for ch in node.children]
            node = node.children[int(np.argmax(scores))]
            path.append(node)
        if node.stones > 0 and node.untried:
            a = node.untried.pop(0)
            s, p = child_state_w(node, a)
            node = NodeW(s, p, parent=node, action=a)
            path[-1].children.append(node)
            path.append(node)
        s, p = node.stones, node.player
        while s > 0:
            a = int(rng.choice([x for x in (1, 2) if x <= s]))
            s -= a; p = -p
        reward = reward_for_root_w(s, p)
        for nd in path:
            nd.visits += 1; nd.value += reward
        visit_history.append([ch.visits for ch in root.children] + [0] * (2 - len(root.children)))
    return root, np.array(visit_history)

root_w, hist_w = run_mcts_w()
print("root children:", [(c.action, c.visits, round(c.value / c.visits, 3)) for c in root_w.children])
assert sum(c.visits for c in root_w.children) == root_w.visits

plt.figure(figsize=(6, 3.4))
plt.plot(hist_w[:, 0], label="take 1 visits")
plt.plot(hist_w[:, 1], label="take 2 visits")
plt.xlabel("MCTS iteration"); plt.ylabel("root child visits")
plt.title("Walkthrough 6: visits accumulate where search spends effort")
plt.legend()
plt.show()
```
▶ What you'll see: the two root actions both get explored, then visit counts diverge as evidence accumulates.

*Why it's done this way:* repeated optimistic sampling turns a huge planning problem into a budgeted allocation problem over actions.

### ✍️ Toy 2 · UCT adds an uncertainty bonus

UCT adds exploitation (`w/n`) and an exploration bonus that is largest for under-visited children.

```python
import numpy as np                              # arrays for UCT pieces.

t2_rng = np.random.default_rng(0)               # seeded generator for reproducibility.
```

### ✍️ Toy 4 · A rollout samples a terminal reward

A rollout uses cheap random moves until the game ends, then converts the terminal winner into a
root-perspective reward.

```python
import numpy as np                              # arrays for plotting rollout stones.

t4_rng = np.random.default_rng(0)               # seeded generator for reproducibility.
t4_stones = 5                                   # rollout starts with 5 stones    # -> 5
t4_player = 1                                   # root player moves first        # -> 1
t4_trajectory = [(t4_stones, t4_player)]        # states visited                 # -> [(5, 1)]
t4_actions = []
while t4_stones > 0:
    t4_legal = [t4_action for t4_action in (1, 2) if t4_action <= t4_stones]
    t4_action = int(t4_rng.choice(t4_legal))

    t4_stones = t4_stones - t4_action

print("trajectory:", t4_trajectory)             # -> [(5, 1), (3, -1), (1, 1), (0, -1)]
print("winner:", t4_winner)                     # -> 1
print("root reward:", t4_reward)                # -> 1.0
assert t4_actions == [2, 2, 1] and t4_reward == 1.0

t4_steps = np.arange(len(t4_trajectory))
t4_stones_left = [t4_state[0] for t4_state in t4_trajectory]
plt.figure(figsize=(4.8, 2.8))
plt.plot(t4_steps, t4_stones_left, marker="o", color="purple")

```

### ✍️ Toy 6 · Repeated selection allocates visits

A tiny root-only UCT loop repeatedly selects between two actions, samples rewards, and spends more
visits on the action that looks better.

```python
import numpy as np                              # arrays for repeated UCT updates.

t6_rng = np.random.default_rng(0)               # seeded generator for reproducibility.
t6_win_probs = np.array([0.3, 0.7])             # hidden rollout win chances      # -> [0.3 0.7]
t6_visits = np.zeros(2, dtype=int)              # action visit counts            # -> [0 0]
t6_wins = np.zeros(2, dtype=float)              # action total rewards           # -> [0. 0.]
t6_history = []
for t6_iter in range(20):
    if np.any(t6_visits == 0):
        t6_action = int(np.where(t6_visits == 0)[0][0])
    else:
        t6_scores = t6_wins / t6_visits + 1.2 * np.sqrt(np.log(t6_visits.sum()) / t6_visits)
        t6_action = int(np.argmax(t6_scores))
    t6_reward = float(t6_rng.random() < t6_win_probs[t6_action])
    t6_visits[t6_action] = t6_visits[t6_action] + 1
    t6_wins[t6_action] = t6_wins[t6_action] + t6_reward
    t6_history.append(t6_visits.copy())
t6_means = np.divide(t6_wins, t6_visits, out=np.zeros_like(t6_wins), where=t6_visits > 0)
t6_best_action = int(np.argmax(t6_visits))
print("final visits:", t6_visits.tolist())       # -> [4, 16]
print("final wins:", t6_wins.tolist())           # -> [0.0, 10.0]
print("final means:", np.round(t6_means, 3).tolist())  # -> [0.0, 0.625]
print("most visited action:", t6_best_action)    # -> 1
assert t6_visits.tolist() == [4, 16]
assert t6_best_action == 1

t6_history_array = np.array(t6_history)
plt.figure(figsize=(4.8, 2.8))
plt.plot(t6_history_array[:, 0], label="action 0 visits")
plt.plot(t6_history_array[:, 1], label="action 1 visits")
plt.xlabel("iteration")
plt.ylabel("visits")
plt.legend()
plt.title("Toy 6 · visits concentrate on action 1")
```

## 🛠️ Setup

```python
import numpy as np  # use NumPy for arrays, deterministic random generators, and numerical checks.
import matplotlib.pyplot as plt  # use Matplotlib for tree, score, convergence, and visit-allocation plots.
from math import log, sqrt  # use the UCT formula's natural logarithm and square root.
np.random.seed(0)  # make examples reproducible.

class ToyNode:  # store one MCTS node for the subtract-a-stone game.
    def __init__(self, stones, player, parent=None, action=None):
        self.stones = int(stones)  # number of stones remaining in the toy game.
        self.player = int(player)  # player to move: +1 is the root player, -1 is the opponent.
        self.parent = parent  # link back up the tree for backup.
        self.action = action  # action taken from the parent to reach this node.
        self.children = []  # expanded child nodes.
        self.untried = legal_actions((self.stones, self.player)) if self.stones > 0 else []  # legal actions not expanded yet.
        self.visits = 0  # number of simulations passing through this node.
        self.value = 0.0  # accumulated root-perspective reward.

def legal_actions(state):  # list legal moves in the toy take-1-or-2 game.
    stones, player = state  # unpack the state tuple.
    return [a for a in (1, 2) if a <= stones]  # a player can take one or two stones if available.

def next_state(state, action):  # apply an action to get the successor state.
    stones, player = state  # unpack the current state.
    return (stones - action, -player)  # remove stones and switch the player to move.

def terminal_reward(state, root_player=1):  # return the terminal reward from the root player's perspective.
    stones, player = state  # unpack the terminal or nonterminal state.
    if stones != 0:  # nonterminal states have no final reward yet.
        return None  # signal that rollout should continue.
    winner = -player  # the previous player took the last stone.
    return 1.0 if winner == root_player else 0.0  # root win is 1, root loss is 0.

def uct_score(parent, child, c=1.4):  # compute UCT for selecting a child.
    if child.visits == 0:  # unvisited children must be tried at least once.
        return float("inf")  # optimistic value for forced exploration.
    exploitation = child.value / child.visits  # empirical mean reward.
    exploration = c * sqrt(log(max(parent.visits, 1)) / child.visits)  # uncertainty bonus.
    return exploitation + exploration  # UCT is mean plus optimism.

def expand(node):  # add exactly one child from the node's untried actions.
    action = node.untried.pop(0)  # choose the next unexpanded legal action deterministically.
    child = ToyNode(*next_state((node.stones, node.player), action), parent=node, action=action)  # create the child node.
    node.children.append(child)  # attach the child to the tree.
    return child  # return the new frontier node.

def rollout(state, rng):  # simulate random play until the game ends.
    trajectory = [state]  # keep states for plotting and debugging.
    reward = terminal_reward(state)  # check if the start is already terminal.
    while reward is None:  # continue until a terminal reward exists.
        action = int(rng.choice(legal_actions(state)))  # choose a random legal move.
        state = next_state(state, action)  # advance the game.
        trajectory.append(state)  # record the sampled state.
        reward = terminal_reward(state)  # check terminal status.
    return reward, trajectory  # return both value and path.

def backpropagate(path, reward):  # update every selected node with one rollout reward.
    for node in path:  # all nodes on the root-to-frontier path receive the same root-perspective reward.
        node.visits += 1  # one more simulation passed through this node.
        node.value += reward  # add the rollout result to its accumulated value.

def mcts(root_stones=7, iterations=80, c=1.4, seed=0):  # run a complete MCTS search.
    rng = np.random.default_rng(seed)  # local reproducible generator.
    root = ToyNode(root_stones, 1)  # root player starts.
    root_visit_history = []  # track root child visits after each iteration.
    root_value_history = []  # track root child means after each iteration.
    selection_paths = []  # store action paths for visualization.
    for _ in range(iterations):  # repeat select-expand-simulate-backup.
        node = root  # start selection at the root.
        path = [node]  # keep the nodes selected this iteration.
        actions = []  # keep the actions chosen this iteration.
        while node.stones > 0 and not node.untried and node.children:  # select while fully expanded and nonterminal.
            scores = [uct_score(node, child, c) for child in node.children]  # score existing children.
            idx = int(np.argmax(scores))  # choose the best UCT child.
            node = node.children[idx]  # descend.
            path.append(node)  # store node for backup.
            actions.append(node.action)  # store action for plotting.
        if node.stones > 0 and node.untried:  # expand at the frontier when possible.
            node = expand(node)  # add one new child.
            path.append(node)  # include it in backup.
            actions.append(node.action)  # include its action in the path.
        reward, traj = rollout((node.stones, node.player), rng)  # estimate value by rollout.
        backpropagate(path, reward)  # update visits and values.
        root_visit_history.append([child.visits for child in root.children] + [0] * (2 - len(root.children)))  # record visits.
        root_value_history.append([child.value / child.visits if child.visits else 0 for child in root.children] + [0] * (2 - len(root.children)))  # record means.
        selection_paths.append(actions)  # record selected action path.
    return root, np.array(root_visit_history), np.array(root_value_history), selection_paths  # return search diagnostics.
```

```python
def exact_win(state):  # compute exact win/loss recursively for the player to move.

    return any(not exact_win(next_state(state, a)) for a in legal_actions(state))  # winning if any move leaves opponent losing.
```

#### A3. Compare rollout policies

**Goal.** Replace uniform random rollouts with a simple heuristic rollout, because rollout quality changes the value estimates that backups receive. We build it in 1 step.

```python
def rollout_policy_value(state, rng, prefer_two=False):  # simulate with either random or take-two-when-possible policy.
    trajectory = [state]
    reward = terminal_reward(state)
    while reward is None:
        acts = legal_actions(state)
        action = 2 if prefer_two and 2 in acts else int(rng.choice(acts))
        state = next_state(state, action)
        trajectory.append(state)
        reward = terminal_reward(state)
    return reward, trajectory

rng_a3 = np.random.default_rng(31)  # deterministic comparison.
random_rewards_a3 = [rollout_policy_value((7, 1), rng_a3, False)[0] for _ in range(60)]  # random rollout samples.
rng_a3b = np.random.default_rng(31)  # reset for heuristic samples.
heur_rewards_a3 = [rollout_policy_value((7, 1), rng_a3b, True)[0] for _ in range(60)]  # heuristic rollout samples.
print("random mean:", round(float(np.mean(random_rewards_a3)), 3), "heuristic mean:", round(float(np.mean(heur_rewards_a3)), 3))  # inspect policy effect.
assert len(random_rewards_a3) == 60

plt.figure(figsize=(5, 3))  # create rollout-policy comparison.
plt.bar(["random", "prefer take 2"], [np.mean(random_rewards_a3), np.mean(heur_rewards_a3)], color=["gray", "teal"])  # compare sampled win rates.
plt.ylim(0, 1); plt.ylabel("rollout win-rate estimate")  # label reward scale.
plt.title("A3: rollout policy changes simulation estimates")  # title policy plot.
plt.show()
```
▶ What you'll see: the rollout policy changes the estimated win probability from the same starting state.

👀 Takeaway: MCTS estimates the world induced by its rollout policy, so rollout design matters.

#### A5. Use a budget curve to decide when to stop

**Goal.** Plot action choice stability versus iteration budget, because practical MCTS is stopped by time or simulation count. We build it in 1 step.

