# 11.6 — Temporal-Difference Learning

Temporal-Difference (TD) learning estimates long-run consequence while experience is still unfolding: after one transition, it updates a value toward **reward plus the next value estimate**. In this lesson, you will build TD(0) prediction from scratch with NumPy, inspect the TD error, and see why bootstrapping is powerful but sensitive to step size, discounting, and policy support.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build temporal-difference learning one idea at a time. Run each cell in order and read the printed intermediate values — every piece of math, including the TD target and TD error, is shown. This walkthrough is self-contained (it imports what it needs) and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays, random choices, and compact Bellman calculations.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
np.random.seed(0)  # reproducibility for sampled episodes and plots.
```

### 1. Rewards, returns, and discounting

TD learning is not trying to predict the next reward alone. It is trying to predict a **return**: the discounted sum of future rewards $G_t=r_{t+1}+\gamma r_{t+2}+\gamma^2 r_{t+3}+\cdots$. Discounting makes later rewards count, but count less, so the learner can prefer plans with delayed payoff without pretending the future is free.

```python
rewards_w = np.array([1.0, 0.0, 2.0])  # reward now, one step later, and two steps later.
gamma_w = 0.9  # discount future rewards by 10% each step.
powers_w = gamma_w ** np.arange(len(rewards_w))  # [1, gamma, gamma^2].
print("discount powers:", powers_w)  # inspect how time changes weight.
print("weighted rewards:", rewards_w * powers_w)  # inspect each term in G.
```
▶ What you'll see: the delayed reward of 2 is multiplied by 0.81, so it contributes 1.62 rather than 2.0.

```python
G_w = float(np.sum(rewards_w * powers_w))  # compute 1 + 0.9*0 + 0.9^2*2.
print("three-step return G:", round(G_w, 3))  # canonical lesson number.
assert round(G_w, 3) == 2.620  # verify the discounted consequence calculation.
plt.figure(figsize=(4.4, 3))
plt.bar(["r0", "γr1", "γ²r2"], rewards_w * powers_w, color="teal")
plt.title("1: discounted pieces of the return")
plt.ylabel("contribution to G")
plt.show()
```
▶ What you'll see: the first and third bars create the return; the middle bar is zero because that reward is zero.

*Why it's done this way: TD values estimate expected discounted return, not isolated reward. Multiplying by powers of $\gamma$ is the algebraic way to say that consequences farther away still matter, but are less certain, less immediate, or less valuable than consequences now.*

### 2. The Bellman one-step target

The Bellman idea is that a long return can be split into **one observed reward plus the value of what comes next**: $V(s)\approx r+\gamma V(s')$. TD learning uses this as a target before the episode ends. That is bootstrapping: the target contains a current estimate, so learning can be fast, but the target can also be wrong while the table is still immature.

```python
r_w = 1.0  # reward observed after leaving the current state.
next_value_w = 0.8  # current estimate V(s') for the next state.
gamma_w = 0.9  # discount applied to the next estimate.
target_w = r_w + gamma_w * next_value_w  # one-step TD target.
print("target = r + gamma*V_next:", round(target_w, 3))
assert round(target_w, 3) == 1.720  # 1 + 0.9*0.8.
```
▶ What you'll see: the one-step target is 1.72, combining real reward with a bootstrapped future estimate.

```python
old_value_w = 0.4  # current estimate V(s) before the update.
alpha_w = 0.5  # move halfway toward the target.
new_value_w = old_value_w + alpha_w * (target_w - old_value_w)  # TD update.
print("old V:", old_value_w, "new V:", round(new_value_w, 3))
assert round(new_value_w, 3) == 1.060  # halfway from 0.4 to 1.72.
plt.figure(figsize=(4.4, 3))
plt.bar(["old V(s)", "target", "new V(s)"], [old_value_w, target_w, new_value_w], color=["gray", "black", "seagreen"])
plt.title("2: update moves toward the one-step target")
plt.ylabel("value")
plt.show()
```
▶ What you'll see: the new estimate lands between the old estimate and the target because $\alpha=0.5$.

*Why it's done this way: waiting for a complete return can have high variance and delayed feedback. The Bellman split gives a supervised-looking target immediately, while $\alpha$ prevents one noisy transition or one bad bootstrap estimate from overwriting everything.*

### 3. TD error: the surprise signal

The TD error is $\delta=r+\gamma V(s')-V(s)$. It measures how surprising the transition was relative to the current value table. Positive $\delta$ says the state was better than expected; negative $\delta$ says it was worse; zero says the table is locally Bellman-consistent for that transition.

```python
V_w = np.array([0.0, 0.4, 0.8, 0.0])  # current state-value estimates for a tiny chain.
s_w, s_next_w = 1, 2  # transition from state 1 to state 2.
r_w, gamma_w = 1.0, 0.9  # observed reward and discount.
delta_w = r_w + gamma_w * V_w[s_next_w] - V_w[s_w]  # TD error.
print("TD error delta:", round(delta_w, 3))
assert round(delta_w, 3) == 1.320  # 1 + 0.9*0.8 - 0.4.
```
▶ What you'll see: the positive TD error says state 1 was undervalued given this transition.

```python
alpha_w = 0.25  # conservative learning rate.
V_after_w = V_w.copy()  # keep the original table for comparison.
V_after_w[s_w] += alpha_w * delta_w  # TD(0) changes only the visited current state.
print("before:", V_w)
print("after :", np.round(V_after_w, 3))
plt.figure(figsize=(4.6, 3))
plt.bar(np.arange(len(V_w)) - 0.18, V_w, width=0.36, label="before", color="gray")
plt.bar(np.arange(len(V_w)) + 0.18, V_after_w, width=0.36, label="after", color="teal")
plt.title("3: TD error updates one visited state")
plt.xlabel("state")
plt.ylabel("V")
plt.legend()
plt.show()
```
▶ What you'll see: only state 1 moves upward; untouched states keep their old estimates.

*Why it's done this way: $\delta$ is a local Bellman residual. TD(0) assigns that residual to the state just visited because that state's estimate made the one-step prediction that was just contradicted by reward plus next value.*

### 4. TD(0) prediction on a toy chain

Now we put the pieces into an environment. The agent starts at state 0 and walks right until terminal state 4, receiving reward 1 only on the final transition. TD(0) prediction repeatedly samples episodes under this fixed policy and updates $V(s)\leftarrow V(s)+\alpha[r+\gamma V(s')-V(s)]$ after every step.

```python
n_states_w = 5  # states 0,1,2,3 plus terminal 4.
terminal_w = 4  # terminal state's value is defined as 0 after arrival.
gamma_w, alpha_w = 0.9, 0.3  # discount and step size.
V_chain_w = np.zeros(n_states_w)  # initialize all values at 0.
print("initial values:", V_chain_w)
```
▶ What you'll see: all nonterminal values start with no knowledge of the final reward.

```python
for episode_w in range(25):  # repeat sampled episodes, deterministic right-moving policy.
    s_w = 0  # every episode begins at the left end.
    while s_w != terminal_w:  # stop after reaching terminal.
        sp_w = s_w + 1  # move right one state.
        r_step_w = 1.0 if sp_w == terminal_w else 0.0  # reward only when entering terminal.
        target_step_w = r_step_w + gamma_w * V_chain_w[sp_w]  # TD target.
        delta_step_w = target_step_w - V_chain_w[s_w]  # TD error.
        V_chain_w[s_w] += alpha_w * delta_step_w  # TD(0) update.
        s_w = sp_w  # advance the environment state.
print("learned V:", np.round(V_chain_w, 3))
assert V_chain_w[3] > V_chain_w[2] > V_chain_w[1] > V_chain_w[0]  # closer states are more valuable.
```
▶ What you'll see: values form an increasing ramp toward the terminal reward.

```python
true_V_w = np.array([gamma_w**3, gamma_w**2, gamma_w, 1.0, 0.0])  # exact return under deterministic policy.
print("true V:", np.round(true_V_w, 3))
plt.figure(figsize=(4.8, 3))
plt.plot(V_chain_w, marker="o", label="TD estimate", color="teal")
plt.plot(true_V_w, marker="s", label="true value", color="black", linestyle="--")
plt.title("4: TD(0) prediction approaches Bellman values")
plt.xlabel("state")
plt.ylabel("value")
plt.legend()
plt.show()
```
▶ What you'll see: TD estimates are close to the exact discounted ramp, with terminal value fixed at 0.

*Why it's done this way: TD(0) does not wait to know the whole return from state 0. Each transition teaches the previous state using the next state's current estimate, so reward information propagates backward one step at a time across repeated episodes.*

### 5. Monte Carlo target versus TD target

Monte Carlo prediction waits until the episode ends and uses the full sampled return. TD prediction updates immediately using one reward plus a bootstrap estimate. Monte Carlo targets are unbiased for the sampled episode but can vary a lot; TD targets are lower-variance but biased while $V(s')$ is inaccurate.

```python
episode_rewards_w = np.array([0.0, 0.0, 0.0, 1.0])  # full rewards from state 0 to terminal.
gamma_w = 0.9
mc_target_w = float(np.sum((gamma_w ** np.arange(len(episode_rewards_w))) * episode_rewards_w))  # complete return.
bootstrap_V_w = np.array([0.0, 0.0, 0.5, 0.8, 0.0])  # imperfect current value table.
td_target_w = episode_rewards_w[0] + gamma_w * bootstrap_V_w[1]  # first-step TD target from state 0.
print("MC target from state 0:", round(mc_target_w, 3))
print("TD target from state 0:", round(td_target_w, 3))
assert round(mc_target_w, 3) == 0.729
```
▶ What you'll see: the complete return is 0.729, while the first TD target is 0 because the next estimate is still 0.

```python
bootstrap_V_w[1] = 0.7  # imagine state 1 has already learned something useful.
td_target_better_w = episode_rewards_w[0] + gamma_w * bootstrap_V_w[1]
print("TD target after V(1) improves:", round(td_target_better_w, 3))
plt.figure(figsize=(4.4, 3))
plt.bar(["MC full return", "early TD", "later TD"], [mc_target_w, td_target_w, td_target_better_w], color=["black", "gray", "teal"])
plt.title("5: TD target depends on the current value table")
plt.ylabel("target for V(0)")
plt.show()
```
▶ What you'll see: the TD target rises as the bootstrapped next-state value becomes more accurate.

*Why it's done this way: TD trades waiting for complete evidence for faster incremental updates. That tradeoff is the bias-variance heart of bootstrapping: useful estimates accelerate learning, but bad estimates can temporarily teach the wrong target.*

### 6. Policy weighting and exploration pressure

For a fixed policy $\pi$, the Bellman expectation averages over actions and next states. Even in a small table, changing action probabilities changes expected consequence. Exploration bonuses, such as UCB-style uncertainty terms, deliberately shift choices toward less-sampled actions so the value estimates are not built only from greedy, narrow evidence.

```python
logits_w = np.array([1.0, 0.0])  # preference scores for two actions.
exp_w = np.exp(logits_w - np.max(logits_w))  # stable softmax numerator.
pi_w = exp_w / np.sum(exp_w)  # policy probabilities.
action_rewards_w = np.array([2.0, 0.0])  # immediate reward for each action in this tiny example.
expected_reward_w = float(pi_w @ action_rewards_w)  # policy-weighted expectation.
print("policy probabilities:", np.round(pi_w, 3))
print("expected reward:", round(expected_reward_w, 3))
assert np.allclose(np.round(pi_w, 3), [0.731, 0.269])
```
▶ What you'll see: action 0 gets about 73.1% probability, so expected reward is about 1.462.

```python
mean_w, t_w, count_w, c_w = 0.55, 20, 5, 1.0  # observed mean, time, action count, bonus scale.
ucb_w = mean_w + c_w * np.sqrt(2 * np.log(t_w) / count_w)  # uncertainty-augmented index.
print("UCB-style index:", round(ucb_w, 3))
assert round(ucb_w, 3) == 1.645
plt.figure(figsize=(4.4, 3))
plt.bar(["mean only", "mean + bonus"], [mean_w, ucb_w], color=["gray", "orange"])
plt.title("6: exploration bonus raises uncertain actions")
plt.ylabel("selection index")
plt.show()
```
▶ What you'll see: the uncertain action receives a large temporary bonus above its empirical mean.

*Why it's done this way: TD values are only as good as the data distribution that produced their transitions. Policy weighting says which consequences are being evaluated, while exploration pressure broadens support so bootstrapped estimates are not based on actions the agent almost never tries.*

### ✍️ Toy 1 · Discounted rewards become a return

A return is a weighted sum: multiply each reward by a power of `gamma`, then add the pieces.

```python
import numpy as np
import matplotlib.pyplot as plt

t1_rng = np.random.default_rng(0)
t1_rewards = np.array([2.0, 0.0, 1.0])
print("rewards:", t1_rewards.tolist())  # -> [2.0, 0.0, 1.0]
t1_gamma = 0.5
print("gamma:", t1_gamma)  # -> 0.5
t1_steps = np.arange(t1_rewards.size)
print("time steps:", t1_steps.tolist())  # -> [0, 1, 2]
t1_powers = t1_gamma ** t1_steps
print("discount powers:", np.round(t1_powers, 3).tolist())  # -> [1.0, 0.5, 0.25]
t1_terms = t1_rewards * t1_powers
print("discounted terms:", np.round(t1_terms, 3).tolist())  # -> [2.0, 0.0, 0.25]
t1_return = float(t1_terms.sum())
print("return:", round(t1_return, 3))  # -> 2.25

plt.figure(figsize=(4.4, 3.0))
plt.bar(["r0", "γ r1", "γ² r2"], t1_terms, color="teal")
plt.title("Toy 1 · discounted pieces add to G")
plt.ylabel("contribution")
plt.show()

assert abs(t1_return - 2.25) < 1e-12
```
▶ What you'll see: the delayed reward contributes only `0.25`, so the full return is `2.25`.

### ✍️ Toy 2 · Bellman target plus a partial TD move

The one-step Bellman target mixes one observed reward with the next state's current value, then the
learning rate moves only partway toward that target.

```python
import numpy as np

t2_rng = np.random.default_rng(0)
t2_reward = 1.0
print("reward:", t2_reward)  # -> 1.0
t2_gamma = 0.5
print("gamma:", t2_gamma)  # -> 0.5
t2_next_value = 4.0
print("next value:", t2_next_value)  # -> 4.0
t2_target = t2_reward + t2_gamma * t2_next_value
print("TD target:", round(t2_target, 3))  # -> 3.0
t2_old_value = 1.0
print("old value:", t2_old_value)  # -> 1.0
t2_alpha = 0.25
print("alpha:", t2_alpha)  # -> 0.25
t2_delta = t2_target - t2_old_value
print("TD error:", round(t2_delta, 3))  # -> 2.0
t2_new_value = t2_old_value + t2_alpha * t2_delta
print("new value:", round(t2_new_value, 3))  # -> 1.5

plt.figure(figsize=(4.4, 3.0))
plt.bar(["old V", "target", "new V"], [t2_old_value, t2_target, t2_new_value], color=["gray", "black", "seagreen"])
plt.title("Toy 2 · α moves partway")
plt.ylabel("value")
plt.show()

assert abs(t2_new_value - 1.5) < 1e-12
```
▶ What you'll see: the target is `3.0`, but `alpha=0.25` moves the value from `1.0` to only `1.5`.

worse than expected.

```python
import numpy as np

t3_rng = np.random.default_rng(0)
t3_values = np.array([1.0, 2.0, 0.0])
print("values:", t3_values.tolist())  # -> [1.0, 2.0, 0.0]
t3_states = np.array([0, 1])
print("states:", t3_states.tolist())  # -> [0, 1]
t3_next_states = np.array([1, 2])
```

## 🛠️ Setup

```python
import numpy as np  # Load NumPy for arrays, random sampling, and TD table updates.
import matplotlib.pyplot as plt  # Load Matplotlib for compact learning-curve and value-table visualizations.
np.random.seed(0)  # Make all random examples reproducible across notebook runs.

def chain_step(state, terminal=4):  # Deterministic right-moving toy environment.
    next_state = min(state + 1, terminal)  # Move one state toward the terminal.
    reward = 1.0 if next_state == terminal else 0.0  # Reward arrives only when terminal is reached.
    done = next_state == terminal  # Mark the episode end.
    return next_state, reward, done  # Return the transition tuple used by TD.

def random_walk_step(state, rng, terminal_left=0, terminal_right=6):  # Small stochastic random-walk environment.
    move = rng.choice([-1, 1])  # Choose left or right with equal probability.
    next_state = int(np.clip(state + move, terminal_left, terminal_right))  # Keep the state inside boundaries.
    reward = 1.0 if next_state == terminal_right else 0.0  # Right terminal pays one; left terminal pays zero.
    done = next_state in (terminal_left, terminal_right)  # Either terminal ends the episode.
    return next_state, reward, done  # Return one sampled transition.

def td0_update(V, s, r, sp, alpha, gamma, done):  # One TD(0) prediction update.
    target = r if done else r + gamma * V[sp]  # Do not bootstrap past a terminal state.
    delta = target - V[s]  # TD error: observed target minus old estimate.
    V[s] += alpha * delta  # Move the visited state's value toward the target.
    return target, delta  # Return diagnostics for printing and plotting.
```

## 🟢 Basics (warm-up)

### Basic 1 — Discount one delayed reward

**Goal.** Compute the present value of a reward two steps away, because TD values care about discounted consequence rather than only immediate reward. We build it in 2 steps.

```python
reward_b1 = 2.0  # Define a reward that arrives two steps from now.
gamma_b1 = 0.9  # Define the discount factor.
delay_b1 = 2  # Count how many time steps away the reward is.
print("reward:", reward_b1, "gamma:", gamma_b1, "delay:", delay_b1)  # Inspect the ingredients.
```
▶ What you'll see: the reward is not immediate, so it must be discounted before joining the return.

```python
present_value_b1 = (gamma_b1 ** delay_b1) * reward_b1  # Discount the delayed reward by gamma squared.
print("present value:", round(present_value_b1, 3))  # Inspect the discounted contribution.
assert round(present_value_b1, 3) == 1.620  # Verify 0.9^2 * 2.
plt.figure(figsize=(4, 3))
plt.bar(["undiscounted", "discounted"], [reward_b1, present_value_b1], color=["gray", "teal"])
plt.title("Basic 1: delayed reward discount")
plt.ylabel("value")
plt.show()
```
▶ What you'll see: discounting lowers the two-step-away reward from 2.0 to 1.62.

👀 Takeaway: discounting preserves delayed payoff while making timing matter.

### Advanced 2 — Off-policy support pitfall

**Goal.** Show why rarely sampled actions are hard to evaluate, because TD estimates inherit the support of the behavior policy that generated data. We build it in 5 steps.

```python

means_a2 = np.zeros(2)  # Incremental reward estimates per action.
print("behavior probabilities:", probs_a2)  # Inspect support imbalance.
```
▶ What you'll see: the better action has only 5% sampling probability.

```python

    a_a2 = int(rng_a2.choice([0, 1], p=probs_a2))  # Sample from behavior policy.

    counts_a2[a_a2] += 1  # Count support.
```
