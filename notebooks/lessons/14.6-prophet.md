# 14.6 — Prophet

Prophet is an interpretable forecasting recipe: write the future as a sum of a flexible trend, smooth seasonal waves, and event effects, then fit those pieces with enough shrinkage that the story bends only when the data earns it. In this notebook, we rebuild a Prophet-style additive model from scratch with NumPy so every trend segment, Fourier feature, and component plot is inspectable.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build Prophet one idea at a time. Run each cell in order and read the printed intermediate values — every piece of math is spelled out so nothing is a black box. This walkthrough is self-contained and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays, least squares, Fourier bases, and synthetic time series.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
np.random.seed(0)  # reproducibility for synthetic noise.
```

### 1. Additive decomposition: forecast as a sum of components

Prophet's starting point is the additive equation

$$y(t)=g(t)+s(t)+h(t)+\varepsilon_t.$$ 

The trend $g(t)$ explains the long-run level, seasonality $s(t)$ explains repeating calendar shape, holidays/events $h(t)$ explain named one-off lifts or dips, and the residual is whatever the story did not capture. Additivity is powerful because each component can be plotted and audited separately before the final sum is trusted.

```python
t_w = np.arange(28, dtype=float)  # four weeks of daily time points.
g_w = 20 + 0.25 * t_w  # a simple upward trend component.
s_w = 2.0 * np.sin(2 * np.pi * t_w / 7)  # weekly seasonality component.
h_w = np.zeros_like(t_w); h_w[[10, 11]] = 4.0  # a two-day promotion lift.
yhat_w = g_w + s_w + h_w  # Prophet-style additive prediction.
print("components at day 10:", round(g_w[10], 3), round(s_w[10], 3), round(h_w[10], 3))
print("sum at day 10:", round(yhat_w[10], 3))
assert round(yhat_w[10], 3) == 27.368
```
▶ What you'll see: the day-10 forecast is a transparent sum of trend, weekly position, and event lift.

```python
plt.figure(figsize=(6, 3))
plt.plot(t_w, g_w, label="trend g(t)")
plt.plot(t_w, s_w, label="season s(t)")
plt.plot(t_w, h_w, label="event h(t)")
plt.plot(t_w, yhat_w, color="black", linewidth=2, label="sum")
plt.title("1: additive components sum to the forecast")
plt.xlabel("day"); plt.ylabel("value"); plt.legend(); plt.show()
```
▶ What you'll see: the black forecast line inherits its level from trend, wiggle from seasonality, and a square bump from the event.

*Why it's done this way:* additivity makes the model linear in its component columns, so ordinary least squares can estimate many interpretable effects at once. The logic is not that the world is literally separable; it is that a sum gives analysts a stable baseline where each term answers a specific question: long-run direction, calendar phase, or named event.

### 2. Piecewise-linear trend: a base slope plus slope changes

A Prophet-style linear trend is not one straight line forever. It starts with intercept $m$ and slope $k$, then each changepoint contributes extra elapsed time $(t-s_j)_+ = \max(0,t-s_j)$ multiplied by a slope change $\delta_j$:

$$g(t)=m+kt+\sum_j \delta_j(t-s_j)_+.$$ 

Before a changepoint, its hinge is zero. After it, the hinge grows one unit per time step, so it changes the slope without creating a jump in the level.

```python
t_w2 = np.arange(0, 13, dtype=float)
k_w2, m_w2 = 0.5, 10.0  # base slope and intercept.
s_w2 = np.array([6.0])  # one candidate changepoint.
delta_w2 = np.array([-0.3])  # slope becomes 0.5 - 0.3 after day 6.
hinge_w2 = np.maximum(0, t_w2[:, None] - s_w2[None, :])  # (t - s)+ design column.
g_w2 = m_w2 + k_w2 * t_w2 + hinge_w2 @ delta_w2
print("extra time at t=8:", hinge_w2[8, 0])
print("g(8):", round(float(g_w2[8]), 3))
assert round(float(g_w2[8]), 3) == 13.4
```
▶ What you'll see: only the 2 days after the changepoint receive the -0.3 slope adjustment, giving 13.4.

```python
slope_before_w2 = k_w2
slope_after_w2 = k_w2 + delta_w2.sum()
print("slope before:", round(float(slope_before_w2), 3), "slope after:", round(float(slope_after_w2), 3))
plt.figure(figsize=(5, 3))
plt.plot(t_w2, g_w2, marker="o", color="seagreen")
plt.axvline(s_w2[0], color="crimson", linestyle="--", label="changepoint")
plt.title("2: piecewise-linear trend bends, not jumps")
plt.xlabel("time"); plt.ylabel("trend"); plt.legend(); plt.show()
```
▶ What you'll see: the line is continuous at day 6 but grows more slowly afterward.

*Why it's done this way:* the hinge column is the smallest linear feature that changes slope while preserving continuity. A step indicator would jump the level; $(t-s)_+$ instead accumulates only after $s$, so $\frac{d}{dt}g(t)$ changes from $k$ to $k+\delta$ while $g(t)$ itself remains connected.

### 3. Many candidate changepoints with shrinkage

Prophet usually proposes many possible changepoints, then regularizes their slope changes so most stay near zero. From scratch, we can see the same idea with ridge regression: fit hinge columns, but add an L2 penalty to discourage unnecessary bends. Smaller penalties fit more wiggle; larger penalties keep the trend straighter.

```python
t_w3 = np.arange(60, dtype=float)
cp_w3 = np.array([15., 30., 45.])
true_delta_w3 = np.array([0.0, -0.18, 0.0])
H_w3 = np.maximum(0, t_w3[:, None] - cp_w3[None, :])
trend_true_w3 = 8 + 0.35 * t_w3 + H_w3 @ true_delta_w3
noise_w3 = np.random.normal(0, 0.25, size=t_w3.size)
y_w3 = trend_true_w3 + noise_w3
print("candidate changepoints:", cp_w3.astype(int))
print("true slope changes:", true_delta_w3)
```
▶ What you'll see: three candidates exist, but only the middle one truly bends the series.

```python
def ridge_fit_w(X_w, y_w, lam_w):
    penalty_w = lam_w * np.eye(X_w.shape[1])
    penalty_w[0, 0] = 0.0  # do not shrink the intercept.
    return np.linalg.solve(X_w.T @ X_w + penalty_w, X_w.T @ y_w)

X_w3 = np.column_stack([np.ones_like(t_w3), t_w3, H_w3])
coef_lo_w3 = ridge_fit_w(X_w3, y_w3, 0.1)
coef_hi_w3 = ridge_fit_w(X_w3, y_w3, 500.0)
print("lo-shrink deltas:", np.round(coef_lo_w3[2:], 3))
print("hi-shrink deltas:", np.round(coef_hi_w3[2:], 3))
assert abs(coef_lo_w3[3]) > abs(coef_hi_w3[3])
```
▶ What you'll see: the strong penalty pulls slope-change coefficients closer to zero.

```python
plt.figure(figsize=(6, 3))
plt.scatter(t_w3, y_w3, s=14, alpha=0.45, label="observed")
plt.plot(t_w3, X_w3 @ coef_lo_w3, label="loose changepoints")
plt.plot(t_w3, X_w3 @ coef_hi_w3, label="shrunk changepoints")
for c_w3 in cp_w3:
    plt.axvline(c_w3, color="gray", linestyle=":", linewidth=1)
plt.title("3: shrinkage decides how much the trend may bend")
plt.xlabel("time"); plt.ylabel("y"); plt.legend(); plt.show()
```
▶ What you'll see: loose shrinkage follows the bend more aggressively; strong shrinkage keeps a smoother long-run line.

*Why it's done this way:* users rarely know exact changepoint dates. A bank of candidate hinges makes the model flexible, while regularization encodes the prior belief that most candidates are false alarms. Mathematically, the penalty charges large $\delta_j$ values, trading historical fit for safer extrapolation.

### 4. Fourier seasonality: smooth periodic curves without one parameter per date

A weekly effect could use seven weekday dummies, but Prophet often uses Fourier terms: pairs of sine and cosine waves at increasing harmonics. For period $P$ and order $K$, the columns are

$$\sin(2\pi kt/P),\ \cos(2\pi kt/P),\quad k=1,\ldots,K.$$ 

These columns are smooth, repeat automatically every $P$ units, and let one coefficient set extrapolate into the future.

```python
def fourier_w(t_w, period_w, order_w):
    cols_w = []
    for k_w in range(1, order_w + 1):
        cols_w.append(np.sin(2 * np.pi * k_w * t_w / period_w))
        cols_w.append(np.cos(2 * np.pi * k_w * t_w / period_w))
    return np.column_stack(cols_w)

val_w4 = 2 * np.sin(2 * np.pi * 3 / 7) + np.cos(2 * np.pi * 3 / 7)
print("2 sin(6π/7)+cos(6π/7):", round(float(val_w4), 6))
assert round(float(val_w4), 6) == -0.033201
```
▶ What you'll see: one concrete weekly Fourier calculation matches the lesson's arithmetic.

```python
t_w4 = np.arange(42, dtype=float)
F_w4 = fourier_w(t_w4, period_w=7, order_w=2)
beta_w4 = np.array([1.8, -0.4, 0.5, 0.2])
season_w4 = F_w4 @ beta_w4
print("feature shape:", F_w4.shape)
print("first week repeats next week?", np.allclose(season_w4[:7], season_w4[7:14]))
assert F_w4.shape == (42, 4)
```
▶ What you'll see: order 2 creates four columns, and the resulting seasonal curve repeats every 7 days.

```python
plt.figure(figsize=(6, 3))
plt.plot(t_w4, season_w4, marker="o", markersize=3, color="darkorange")
plt.title("4: Fourier weekly seasonality repeats smoothly")
plt.xlabel("day"); plt.ylabel("seasonal effect"); plt.show()
```
▶ What you'll see: a smooth wave pattern repeats six times, rather than seven unrelated weekday bars.

*Why it's done this way:* sine and cosine form a basis for periodic functions. The first harmonic captures one broad up-and-down per period; higher harmonics add shape. Because the same formula is evaluated for future $t$, the seasonal effect extrapolates by phase rather than memorizing calendar rows.

### 5. Holiday/event regressors: sparse named effects

A holiday component is just a sparse regressor column: 1 on event days and 0 otherwise. Its coefficient says how much to add on those days after trend and seasonality have already explained the baseline. This is useful when a spike is tied to a named date rather than a repeating smooth cycle.

```python
t_w5 = np.arange(30, dtype=float)
event_w5 = np.zeros_like(t_w5)
event_w5[[12, 13]] = 1.0
baseline_w5 = 15 + 0.1 * t_w5 + 1.5 * np.sin(2 * np.pi * t_w5 / 7)
y_w5 = baseline_w5 + 3.0 * event_w5
print("event days:", np.where(event_w5 == 1)[0])
print("event lift coefficient used:", 3.0)
```
▶ What you'll see: the event regressor is nonzero only on the two named days.

```python
X_w5 = np.column_stack([np.ones_like(t_w5), t_w5, np.sin(2*np.pi*t_w5/7), np.cos(2*np.pi*t_w5/7), event_w5])
coef_w5 = np.linalg.lstsq(X_w5, y_w5, rcond=None)[0]
print("estimated event lift:", round(float(coef_w5[-1]), 3))
assert round(float(coef_w5[-1]), 3) == 3.0
```
▶ What you'll see: with a correctly specified baseline, least squares recovers the 3-point event lift.

```python
plt.figure(figsize=(6, 3))
plt.plot(t_w5, y_w5, label="observed with event")
plt.plot(t_w5, X_w5 @ coef_w5 - coef_w5[-1] * event_w5, label="without event component")
plt.scatter(t_w5[event_w5 == 1], y_w5[event_w5 == 1], color="crimson", zorder=3, label="event days")
plt.title("5: sparse event effect adds named lift")
plt.xlabel("day"); plt.ylabel("y"); plt.legend(); plt.show()
```
▶ What you'll see: the red event points sit above the smooth baseline by the learned lift.

*Why it's done this way:* a holiday is not smooth and not permanent, so giving it its own sparse column prevents the trend from bending or the seasonal wave from warping to explain a local spike. The warning is identification: if an event appears only once, its coefficient may be a memorized residual unless it is shrunk or backed by repeated examples.

### 6. Fit and forecast a Prophet-style additive model

Now we put the pieces together: intercept, base time, hinge changepoints, Fourier seasonality, and event columns become one design matrix. Because the model is additive and linear in coefficients, fitting is a regularized least-squares solve. Forecasting means building the same columns for future times and plotting the components before trusting their sum.

```python
t_w6 = np.arange(80, dtype=float)
future_w6 = np.arange(100, dtype=float)
cp_w6 = np.array([30., 55.])
H_w6 = np.maximum(0, t_w6[:, None] - cp_w6[None, :])
event_w6 = np.zeros_like(t_w6); event_w6[[20, 21, 60, 61]] = 1.0
season_w6 = 1.7 * np.sin(2 * np.pi * t_w6 / 7) - 0.6 * np.cos(2 * np.pi * t_w6 / 7)
y_w6 = 12 + 0.22 * t_w6 + H_w6 @ np.array([-0.10, 0.16]) + season_w6 + 2.5 * event_w6 + np.random.normal(0, 0.25, t_w6.size)
print("training length:", len(t_w6), "forecast length:", len(future_w6))
```
▶ What you'll see: a synthetic daily series with trend bends, weekly cycles, and repeated event lifts.

```python
def prophet_design_w(t_w, cps_w, event_days_w=None):
    H_w = np.maximum(0, t_w[:, None] - cps_w[None, :])
    F_w = fourier_w(t_w, 7, 2)
    if event_days_w is None:
        E_w = np.zeros((len(t_w), 1))
    else:
        E_w = np.isin(t_w.astype(int), event_days_w).astype(float)[:, None]
    return np.column_stack([np.ones_like(t_w), t_w, H_w, F_w, E_w])

X_w6 = prophet_design_w(t_w6, cp_w6, event_days_w=np.array([20, 21, 60, 61]))
coef_w6 = ridge_fit_w(X_w6, y_w6, 8.0)
print("design shape:", X_w6.shape)
print("learned event lift:", round(float(coef_w6[-1]), 3))
assert X_w6.shape == (80, 9)
```
▶ What you'll see: nine columns encode all components, and the event lift is learned as a separate coefficient.

```python
X_future_w6 = prophet_design_w(future_w6, cp_w6, event_days_w=np.array([20, 21, 60, 61, 90, 91]))
yhat_w6 = X_future_w6 @ coef_w6
trend_part_w6 = X_future_w6[:, :4] @ coef_w6[:4]
season_part_w6 = X_future_w6[:, 4:8] @ coef_w6[4:8]
event_part_w6 = X_future_w6[:, 8] * coef_w6[8]
print("forecast day 90 components:", np.round([trend_part_w6[90], season_part_w6[90], event_part_w6[90]], 3))
assert abs(yhat_w6[90] - (trend_part_w6[90] + season_part_w6[90] + event_part_w6[90])) < 1e-9
```
▶ What you'll see: the day-90 forecast decomposes exactly into trend, seasonality, and event pieces.

```python
plt.figure(figsize=(7, 4))
plt.scatter(t_w6, y_w6, s=12, alpha=0.45, label="history")
plt.plot(future_w6, yhat_w6, color="black", label="forecast sum")
plt.plot(future_w6, trend_part_w6, label="trend")
plt.plot(future_w6, trend_part_w6 + season_part_w6, label="trend + season", alpha=0.8)
plt.scatter(future_w6[event_part_w6 > 0], yhat_w6[event_part_w6 > 0], color="crimson", label="event forecasts")
plt.title("6: fitted Prophet-style additive forecast")
plt.xlabel("day"); plt.ylabel("y"); plt.legend(); plt.show()
```
▶ What you'll see: the forecast extrapolates the trend bends, repeats weekly waves, and adds event lifts on named future days.

*Why it's done this way:* one design matrix makes the whole forecast auditable: each column family maps to one story component. Regularized least squares balances fit and stability, while component plots reveal whether a changepoint is stealing seasonality or an event is memorizing noise before the final forecast is used.

## 🛠️ Setup

```python
import numpy as np # load NumPy for arrays, least-squares solves, Fourier features, and synthetic time series.
import matplotlib.pyplot as plt # load Matplotlib for the component, forecast, and diagnostic plots.
np.random.seed(0) # make all random examples reproducible across notebook runs.

def fourier_features(t, period, order): # build sine/cosine columns for smooth periodic seasonality.
    t = np.asarray(t, dtype=float) # convert time to a float array so division and broadcasting are predictable.
    cols = [] # collect sin/cos columns in harmonic order.
    for k in range(1, order + 1): # add harmonics from broad to more wiggly.
        cols.append(np.sin(2 * np.pi * k * t / period)) # sine column for harmonic k.
        cols.append(np.cos(2 * np.pi * k * t / period)) # cosine column for harmonic k.
    return np.column_stack(cols) if cols else np.zeros((len(t), 0)) # return a 2K-column matrix.

def hinge_features(t, changepoints): # build (t - s)+ columns for piecewise-linear trend changes.
    t = np.asarray(t, dtype=float) # convert time to float values.
    changepoints = np.asarray(changepoints, dtype=float) # convert changepoints to float values.
    return np.maximum(0, t[:, None] - changepoints[None, :]) # each column activates after its changepoint.

def ridge_solve(X, y, lam=0.0, unpenalized=1): # solve regularized least squares with optional unpenalized leading columns.
    X = np.asarray(X, dtype=float) # ensure numeric design matrix.
    y = np.asarray(y, dtype=float) # ensure numeric response vector.
    penalty = lam * np.eye(X.shape[1]) # start with λI for ridge shrinkage.
    penalty[:unpenalized, :unpenalized] = 0.0 # leave intercept, and sometimes base slope, unpenalized.
    return np.linalg.solve(X.T @ X + penalty, X.T @ y) # return the coefficient vector.

def prophet_matrix(t, changepoints=(), period=7, order=1, event_days=()): # create a Prophet-style additive design matrix.
    t = np.asarray(t, dtype=float) # ensure time is a float array.
    H = hinge_features(t, changepoints) if len(changepoints) else np.zeros((len(t), 0)) # trend bend columns.
    F = fourier_features(t, period, order) # smooth seasonal columns.
    E = np.isin(t.astype(int), np.asarray(event_days, dtype=int)).astype(float)[:, None] # sparse event indicator.
    return np.column_stack([np.ones_like(t), t, H, F, E]) # concatenate additive components.
```

```python
yhat_b1 = trend_b1 + season_b1 + event_b1 # add components into the final forecast.
```

### Basic 3 — Evaluate a piecewise-linear trend

**Goal.** Combine an intercept, base slope, and one slope change, because trend bends are additive hinge effects. We build it in 2 steps.

```python
t_b3 = np.arange(0, 12, dtype=float) # create time points.

cp_b3 = np.array([6.0]) # define one changepoint.
delta_b3 = np.array([-0.3]) # slow the trend after the changepoint.
trend_b3 = m_b3 + k_b3 * t_b3 + hinge_features(t_b3, cp_b3) @ delta_b3 # compute g(t).

assert round(float(trend_b3[8]), 3) == 13.4 # verify 10 + .5*8 - .3*2.
```
▶ What you'll see: the value at time 8 is 13.4 because only two post-changepoint units are adjusted.

```python
plt.figure(figsize=(5, 3)) # create a compact trend plot.
```

### Basic 5 — Form one seasonal curve from Fourier weights

**Goal.** Multiply Fourier features by coefficients, because seasonal effects are learned linear combinations of waves. We build it in 2 steps.

```python
t_b5 = np.arange(21, dtype=float) # create three weeks of daily points.

season_b5 = F_b5 @ beta_b5 # compute the seasonal component.
print("season at day 3:", round(float(season_b5[3]), 6)) # inspect one concrete Fourier value.
assert round(float(season_b5[3]), 6) == -0.033201 # verify 2 sin(6π/7)+cos(6π/7).
```
▶ What you'll see: the day-3 seasonal value matches the worked Fourier calculation.

```python
plt.figure(figsize=(5, 3)) # create a compact seasonal plot.
```

```python
coef_true_a3 = np.array([15.0, 0.1, 0.05, 1.3, -0.3, 2.0]) # choose true coefficients.
y_a3 = X_a3 @ coef_true_a3 + np.random.normal(0, 0.5, size=t_a3.size) # add noise.
print("history length:", len(t_a3)) # inspect data size.
```
▶ What you'll see: a noisy additive history for uncertainty estimation.

```python
coef_a3 = ridge_solve(X_a3, y_a3, lam=1.0, unpenalized=2) # fit additive model.
resid_a3 = y_a3 - X_a3 @ coef_a3 # compute residuals on history.
sigma_a3 = float(np.std(resid_a3, ddof=1)) # estimate residual standard deviation.
print("residual sigma:", round(sigma_a3, 3)) # inspect uncertainty scale.
assert sigma_a3 > 0 # verify nonzero residual spread.
```

```python
Xf_a3 = prophet_matrix(future_a3, changepoints=[35], period=7, order=1, event_days=[20, 21, 80]) # build future rows.
yhat_a3 = Xf_a3 @ coef_a3 # point forecast.
rng_a3 = np.random.default_rng(3) # create local reproducible simulation.
sims_a3 = yhat_a3[:, None] + rng_a3.normal(0, sigma_a3, size=(len(future_a3), 400)) # simulate residual noise around forecast.
lo_a3 = np.percentile(sims_a3, 10, axis=1) # compute lower 80% interval.
hi_a3 = np.percentile(sims_a3, 90, axis=1) # compute upper 80% interval.
print("day 80 interval width:", round(float(hi_a3[80] - lo_a3[80]), 3)) # inspect one band width.
```

```python
plt.figure(figsize=(7, 3)) # create uncertainty plot.
```

👀 Takeaway: residual bands are a simple uncertainty layer, but they assume future errors resemble past residuals.

### Advanced 4 — Backtest a forecast horizon

**Goal.** Hold out the last horizon and evaluate it, because forecasting models should be judged on future-like data. We build it in 4 steps.

```python
t_a4 = np.arange(100, dtype=float) # create full timeline.
X_full_a4 = prophet_matrix(t_a4, changepoints=[50], period=7, order=1, event_days=[30, 31, 80, 81]) # build full design.
coef_true_a4 = np.array([25.0, 0.08, 0.04, 1.0, -0.5, 2.2]) # choose true coefficients.
y_full_a4 = X_full_a4 @ coef_true_a4 + np.random.normal(0, 0.35, size=t_a4.size) # synthesize observations.
horizon_a4 = 20 # choose last 20 days as validation.
train_t_a4 = t_a4[:-horizon_a4] # training times.
test_t_a4 = t_a4[-horizon_a4:] # held-out future times.
print("train/test sizes:", len(train_t_a4), len(test_t_a4)) # inspect split.
```
▶ What you'll see: the last 20 days are held out to mimic forecasting into the future.

```python
X_train_a4 = prophet_matrix(train_t_a4, changepoints=[50], period=7, order=1, event_days=[30, 31]) # build training features only.
y_train_a4 = y_full_a4[:-horizon_a4] # training observations.
coef_a4 = ridge_solve(X_train_a4, y_train_a4, lam=1.0, unpenalized=2) # fit on history only.
X_test_a4 = prophet_matrix(test_t_a4, changepoints=[50], period=7, order=1, event_days=[80, 81]) # build future validation rows.
pred_a4 = X_test_a4 @ coef_a4 # forecast the held-out horizon.
truth_a4 = y_full_a4[-horizon_a4:] # collect validation truth.
rmse_a4 = float(np.sqrt(np.mean((truth_a4 - pred_a4) ** 2))) # compute horizon RMSE.
print("horizon RMSE:", round(rmse_a4, 3)) # inspect forecast error.
assert rmse_a4 < 1.5 # verify the model forecasts the synthetic horizon reasonably.
```

```python
naive_a4 = np.repeat(y_train_a4[-1], horizon_a4) # define last-value baseline.
rmse_naive_a4 = float(np.sqrt(np.mean((truth_a4 - naive_a4) ** 2))) # compute baseline RMSE.
print("model vs naive RMSE:", round(rmse_a4, 3), round(rmse_naive_a4, 3)) # inspect comparison.
assert rmse_a4 < rmse_naive_a4 # verify additive structure beats naive on this synthetic data.
```

```python
plt.figure(figsize=(6, 3)) # create backtest plot.
plt.plot(t_a4, y_full_a4, color="lightgray", label="full series") # show full data for context.
plt.plot(test_t_a4, pred_a4, color="black", label="forecast") # draw held-out forecast.
plt.scatter(test_t_a4, truth_a4, color="red", s=16, label="held-out truth") # draw validation points.
plt.axvline(train_t_a4[-1], color="gray", linestyle="--", label="cutoff") # mark forecast origin.
plt.title("Advanced 4: horizon backtest") # title plot.
plt.legend(); plt.show() # display evaluation.
```
▶ What you'll see: the forecast is drawn only after the cutoff and compared with held-out future points.

👀 Takeaway: Prophet-style models should be validated by time-respecting backtests, not random splits.

### Advanced 5 — Diagnose changepoints versus events

**Goal.** Compare an event-aware model with a changepoint-only model, because isolated spikes should not become permanent trend bends. We build it in 4 steps.

```python
t_a5 = np.arange(80, dtype=float) # create daily history.
event_days_a5 = [40, 41] # create a short promotion spike.
y_base_a5 = 12 + 0.12 * t_a5 + 1.0 * np.sin(2*np.pi*t_a5/7) # define trend plus season.
y_a5 = y_base_a5 + 4.0 * np.isin(t_a5.astype(int), event_days_a5).astype(float) + np.random.normal(0, 0.2, size=t_a5.size) # add isolated event spike.
cps_a5 = [35, 40, 45] # give changepoint-only model chances around the event.
print("event days:", event_days_a5) # inspect the spike location.
```
▶ What you'll see: the only structural surprise is a two-day event, not a sustained regime shift.

```python
X_event_a5 = prophet_matrix(t_a5, changepoints=cps_a5, period=7, order=1, event_days=event_days_a5) # include event indicator.
X_noevent_a5 = prophet_matrix(t_a5, changepoints=cps_a5, period=7, order=1, event_days=[]) # omit event indicator.
coef_event_a5 = ridge_solve(X_event_a5, y_a5, lam=0.1, unpenalized=2) # fit event-aware model.
coef_noevent_a5 = ridge_solve(X_noevent_a5, y_a5, lam=0.1, unpenalized=2) # fit model that must explain spike otherwise.
fit_event_a5 = X_event_a5 @ coef_event_a5 # compute event-aware fit.
fit_noevent_a5 = X_noevent_a5 @ coef_noevent_a5 # compute no-event fit.
print("estimated event lift:", round(float(coef_event_a5[-1]), 3)) # inspect event coefficient.
assert coef_event_a5[-1] > 2.5 # verify spike is captured as event lift.
```

```python
delta_norm_event_a5 = float(np.linalg.norm(coef_event_a5[2:2+len(cps_a5)])) # changepoint usage with event.
delta_norm_noevent_a5 = float(np.linalg.norm(coef_noevent_a5[2:2+len(cps_a5)])) # changepoint usage without event.
print("changepoint norm event/no-event:", round(delta_norm_event_a5, 3), round(delta_norm_noevent_a5, 3)) # inspect whether trend absorbed spike.
assert delta_norm_event_a5 <= delta_norm_noevent_a5 + 0.5 # event column should reduce pressure on trend bends.
```

```python
plt.figure(figsize=(7, 3)) # create diagnostic plot.
plt.scatter(t_a5, y_a5, s=12, alpha=0.4, label="observed") # draw data.
plt.plot(t_a5, fit_event_a5, label="with event") # draw event-aware fit.
plt.plot(t_a5, fit_noevent_a5, label="no event", linestyle="--") # draw no-event fit.

plt.title("Advanced 5: event columns protect trend") # title plot.
plt.legend(); plt.show() # display comparison.
```
▶ What you'll see: the event-aware model uses a local lift, while the no-event model is tempted to bend around the spike.

👀 Takeaway: named event regressors keep short shocks from being mistaken for lasting trend changes.
