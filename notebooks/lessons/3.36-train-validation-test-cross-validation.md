# 3.36 — Train/Validation/Test & Cross-Validation

Train/validation/test splitting is the practical contract that keeps model building honest: train data fits parameters, validation data chooses among choices, and the untouched test set estimates future error once the choice is finished. Cross-validation repeats that train-versus-validation comparison across folds so the decision is less dependent on one lucky split.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build train/validation/test evaluation one idea at a time. Run each cell in order and read the printed intermediate values — every average, gap, and fold score is visible so selection never becomes a black box. This walkthrough is self-contained and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays, losses, folds, and small linear-regression calculations.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
np.random.seed(0)  # reproducibility for splits and toy data.
```

### 1. Empirical risk is an average loss

The smallest unit of evaluation is one example's loss. Empirical risk turns many per-example losses into one number by averaging them: $R_S=\frac{1}{n}\sum_i \ell_i$. The lesson's toy losses are 0.180, 0.122, and 0.437, so we compute the same hand-checkable average before talking about splits.

```python
losses_w = np.array([0.180, 0.122, 0.437])  # three verified per-example losses from the lesson.
risk_w = float(np.mean(losses_w))  # empirical risk = arithmetic mean of losses.
print("losses:", losses_w)  # inspect the individual errors before averaging.
print("sum:", round(float(np.sum(losses_w)), 3), "risk:", round(risk_w, 3))  # 0.739/3.
assert round(risk_w, 3) == 0.246  # the lesson's training score.
```
▶ What you'll see: the three losses add to 0.739, and their average is 0.246.

```python
plt.figure(figsize=(4.4, 3))  # create a compact diagnostic plot.
plt.bar(["ex0", "ex1", "ex2"], losses_w, color="steelblue")  # show each loss.
plt.axhline(risk_w, color="crimson", linestyle="--", label=f"mean={risk_w:.3f}")  # show the average.
plt.title("1: empirical risk averages losses")  # title the plot.
plt.ylabel("loss")  # label the vertical scale.
plt.legend()  # identify the mean line.
plt.show()  # display the plot.
```
▶ What you'll see: the mean line sits between the small and large losses rather than copying any one example.

*Why it's done this way:* averaging makes the score live on the same scale as a single loss, so a dataset with more examples is not automatically assigned a larger score. The division by $n$ is the mathematical move that lets us compare risks across splits of different sizes.

### 2. Train, validation, and test have different jobs

A split is not just bookkeeping. The training set fits parameters, the validation set chooses hyperparameters or model families, and the test set stays untouched until the end. We make a tiny regression problem and assign rows to these roles by shuffled indices.

```python
x_w = np.linspace(-3, 3, 18)  # one-dimensional inputs.
y_w = 1.0 + 0.8 * x_w - 0.25 * x_w**2 + 0.15 * np.sin(3 * x_w)  # deterministic nonlinear targets.
perm_w = np.random.permutation(len(x_w))  # shuffled row order so splits are not sorted by x.
train_idx_w, val_idx_w, test_idx_w = perm_w[:10], perm_w[10:14], perm_w[14:]  # 10/4/4 split.
print("split sizes:", len(train_idx_w), len(val_idx_w), len(test_idx_w))  # inspect role sizes.
assert (len(train_idx_w), len(val_idx_w), len(test_idx_w)) == (10, 4, 4)  # concrete split check.
```
▶ What you'll see: each row belongs to exactly one role: 10 train, 4 validation, and 4 test examples.

```python
plt.figure(figsize=(5, 3.2))  # create a split visualization.
plt.scatter(x_w[train_idx_w], y_w[train_idx_w], label="train", color="steelblue")  # training rows.
plt.scatter(x_w[val_idx_w], y_w[val_idx_w], label="validation", color="darkorange")  # validation rows.
plt.scatter(x_w[test_idx_w], y_w[test_idx_w], label="test", color="seagreen")  # test rows.
plt.title("2: one dataset, three evaluation roles")  # title the plot.
plt.xlabel("x")  # label input axis.
plt.ylabel("y")  # label target axis.
plt.legend()  # show role labels.
plt.show()  # display the plot.
```
▶ What you'll see: the same underlying curve is split into three colored groups with different responsibilities.

*Why it's done this way:* if validation or test examples influence fitting, their errors stop being evidence about future data. Separating roles preserves the logic: optimize on train, choose on validation, and estimate the final future error on data that did not participate in either decision.

### 3. Validation chooses model complexity

A flexible model usually wins on training error, but that can mean it memorized training quirks. We fit polynomial models of different degrees using only training rows, then choose the degree with the lowest validation mean squared error.

```python
degrees_w = np.array([1, 2, 5, 9])  # candidate model complexities.
train_mse_w, val_mse_w = [], []  # store errors for each degree.
for deg_w in degrees_w:  # evaluate one polynomial degree at a time.
    coef_w = np.polyfit(x_w[train_idx_w], y_w[train_idx_w], deg_w)  # fit on training only.
    pred_train_w = np.polyval(coef_w, x_w[train_idx_w])  # training predictions.
    pred_val_w = np.polyval(coef_w, x_w[val_idx_w])  # validation predictions.
    train_mse_w.append(float(np.mean((y_w[train_idx_w] - pred_train_w) ** 2)))  # train risk.
    val_mse_w.append(float(np.mean((y_w[val_idx_w] - pred_val_w) ** 2)))  # validation risk.
print("train MSE:", np.round(train_mse_w, 4))  # inspect fit quality on optimized data.
print("validation MSE:", np.round(val_mse_w, 4))  # inspect unseen selection error.
```
▶ What you'll see: training error tends to shrink with degree, while validation error picks a more cautious degree.

```python
best_deg_w = int(degrees_w[np.argmin(val_mse_w)])  # select by validation, not by train.
print("degree selected by validation:", best_deg_w)  # inspect the chosen complexity.
assert best_deg_w in degrees_w  # concrete check that selection came from the candidate grid.
plt.figure(figsize=(5, 3))  # create an error curve.
plt.plot(degrees_w, train_mse_w, marker="o", label="train MSE")  # training curve.
plt.plot(degrees_w, val_mse_w, marker="o", label="validation MSE")  # validation curve.
plt.axvline(best_deg_w, color="crimson", linestyle="--", label=f"selected={best_deg_w}")  # selected model.
plt.title("3: validation selects complexity")  # title the plot.
plt.xlabel("polynomial degree")  # label complexity axis.
plt.ylabel("MSE")  # label error axis.
plt.legend()  # show curve labels.
plt.show()  # display the plot.
```
▶ What you'll see: the selected degree is where validation error, not training error, is smallest.

*Why it's done this way:* validation estimates how a choice behaves after training but before final reporting. The choice rule is $\arg\min_h R_{val}(h)$ because the training number is biased downward by direct optimization, especially for flexible models.

### 4. The test set estimates the chosen procedure once

After validation picks the model, the test set answers a different question: how well did the completed selection process do on untouched data? We now train the selected degree on train+validation data and evaluate it once on the test set.

```python
trainval_idx_w = np.concatenate([train_idx_w, val_idx_w])  # after selection, validation may join training.
final_coef_w = np.polyfit(x_w[trainval_idx_w], y_w[trainval_idx_w], best_deg_w)  # refit selected complexity.
final_test_pred_w = np.polyval(final_coef_w, x_w[test_idx_w])  # predict untouched test rows.
test_mse_w = float(np.mean((y_w[test_idx_w] - final_test_pred_w) ** 2))  # final test error estimate.
print("selected degree:", best_deg_w, "test MSE:", round(test_mse_w, 4))  # final estimate.
assert test_mse_w >= 0.0  # squared error cannot be negative.
```
▶ What you'll see: one final test MSE for the selected model, not a new hyperparameter search.

```python
grid_w = np.linspace(-3.2, 3.2, 120)  # smooth x grid for the fitted curve.
plt.figure(figsize=(5.2, 3.2))  # create a final-fit plot.
plt.scatter(x_w[trainval_idx_w], y_w[trainval_idx_w], color="gray", label="train+validation")  # data used after selection.
plt.scatter(x_w[test_idx_w], y_w[test_idx_w], color="seagreen", label="test")  # untouched test points.
plt.plot(grid_w, np.polyval(final_coef_w, grid_w), color="crimson", label="selected model")  # final model.
plt.title("4: test estimates the finished choice")  # title the plot.
plt.xlabel("x")  # label input axis.
plt.ylabel("y")  # label target axis.
plt.legend()  # show labels.
plt.show()  # display the plot.
```
▶ What you'll see: the test points are inspected only against the already-selected curve.

*Why it's done this way:* using test error to choose the degree would make the test set another validation set and bias the final number. The test estimate is meaningful only because it is spent once, after all modeling decisions are fixed.

### 5. K-fold cross-validation averages validation roles

One validation split can be noisy. K-fold cross-validation divides the data into $K$ folds, trains on $K-1$ folds, validates on the held-out fold, and averages the fold risks: $CV_K=\frac{1}{K}\sum_k R_{V_k}(\hat f_{-k})$.

```python
K_w = 3  # number of folds for a small demonstration.
folds_w = np.array_split(np.arange(len(x_w)), K_w)  # deterministic fold partition.
cv_scores_w = []  # store fold validation risks.
for k_w in range(K_w):  # hold out one fold at a time.
    val_fold_w = folds_w[k_w]  # current validation fold V_k.
    train_fold_w = np.setdiff1d(np.arange(len(x_w)), val_fold_w)  # all other folds.
    coef_fold_w = np.polyfit(x_w[train_fold_w], y_w[train_fold_w], 2)  # fit on K-1 folds.
    pred_fold_w = np.polyval(coef_fold_w, x_w[val_fold_w])  # predict held-out fold.
    cv_scores_w.append(float(np.mean((y_w[val_fold_w] - pred_fold_w) ** 2)))  # fold risk.
print("fold scores:", np.round(cv_scores_w, 4))  # inspect each validation role.
print("CV_3:", round(float(np.mean(cv_scores_w)), 4))  # average validation risk.
```
▶ What you'll see: three held-out scores and their average cross-validation estimate.

```python
cv_mean_w = float(np.mean(cv_scores_w))  # mean CV risk.
plt.figure(figsize=(4.8, 3))  # create a fold-risk plot.
plt.bar(["fold 1", "fold 2", "fold 3"], cv_scores_w, color="mediumpurple")  # fold risks.
plt.axhline(cv_mean_w, color="black", linestyle="--", label=f"mean={cv_mean_w:.4f}")  # average.
plt.title("5: cross-validation averages held-out folds")  # title the plot.
plt.ylabel("fold MSE")  # label error scale.
plt.legend()  # identify mean.
plt.show()  # display the plot.
```
▶ What you'll see: fold errors vary, so the average is more informative than any single fold.

*Why it's done this way:* each example gets to be validation exactly once and training $K-1$ times. Averaging reduces dependence on a lucky or unlucky split while still preserving the rule that validation data for a fold is not used to fit that fold's model.

### 6. Selection scores can include cost, gaps, and stability

The lesson emphasizes that selection should compare complete decision scores, not raw fit alone. We start with the empirical risk 0.246, add a cost 0.050, compare a flexible alternative at 0.336, and inspect a stabilized score that reduces the baseline by 20%.

```python
raw_risk_w = 0.246  # empirical risk from the tiny loss average.
cost_w = 0.050  # complexity, regularization, or operational cost.
score_w = raw_risk_w + cost_w  # decision score includes both fit and cost.
alt_score_w = 0.336  # a tempting more-flexible alternative.
gap_w = alt_score_w - score_w  # absolute evidence gap.
rel_gap_w = gap_w / alt_score_w  # relative evidence gap.
print("score:", round(score_w, 3), "gap:", round(gap_w, 3), "relative gap:", round(rel_gap_w, 3))  # inspect selection arithmetic.
assert round(score_w, 3) == 0.296 and round(gap_w, 3) == 0.040  # lesson numbers.
```
▶ What you'll see: adding cost changes the score to 0.296, and the flexible alternative is worse by 0.040.

```python
stable_score_w = 0.80 * score_w  # stabilization reduces the decision score by 20%.
choices_w = np.array([score_w, alt_score_w, stable_score_w])  # candidate decision scores.
labels_w = ["baseline", "flexible", "stabilized"]  # readable labels.
winner_w = labels_w[int(np.argmin(choices_w))]  # lower score wins.
print("stabilized:", round(stable_score_w, 3), "winner:", winner_w)  # inspect final selection.
assert round(stable_score_w, 3) == 0.237 and winner_w == "stabilized"  # lesson decision.
plt.figure(figsize=(5, 3))  # create a selection plot.
plt.bar(labels_w, choices_w, color=["steelblue", "darkorange", "seagreen"])  # compare final scores.
plt.title("6: choose by full decision score")  # title the plot.
plt.ylabel("lower is better")  # label decision scale.
plt.show()  # display the chart.
```
▶ What you'll see: the stabilized bar is the lowest, so it is the one carried forward.

*Why it's done this way:* a raw training average answers only “how well did we fit these examples?” A decision score adds the relevant cost or constraint, and the gap asks whether the win is large enough to trust instead of chasing a fragile improvement.

## 🛠️ Setup

```python
import numpy as np  # load NumPy for arrays, shuffling, losses, folds, and polynomial fitting.
import matplotlib.pyplot as plt  # load Matplotlib for split diagrams, error curves, and fold plots.
np.random.seed(0)  # make every split and toy simulation reproducible.

def mse(y_true, y_pred):  # define mean squared error for all later examples.
    y_true = np.asarray(y_true, dtype=float)  # ensure numeric array inputs.
    y_pred = np.asarray(y_pred, dtype=float)  # ensure numeric array predictions.
    return float(np.mean((y_true - y_pred) ** 2))  # average squared residuals.

def split_indices(n, train_frac=0.6, val_frac=0.2, seed=0):  # create train/validation/test indices.
    rng = np.random.default_rng(seed)  # local reproducible generator.
    idx = rng.permutation(n)  # shuffle rows before slicing.
    n_train = int(round(train_frac * n))  # number of training rows.
    n_val = int(round(val_frac * n))  # number of validation rows.
    return idx[:n_train], idx[n_train:n_train + n_val], idx[n_train + n_val:]  # disjoint splits.

def poly_predict(x_train, y_train, degree, x_eval):  # fit a polynomial and predict new x values.
    coef = np.polyfit(x_train, y_train, degree)  # least-squares polynomial fit.
    return np.polyval(coef, x_eval)  # evaluate the fitted polynomial.

def make_curve(n=30):  # generate a deterministic nonlinear regression toy dataset.
    x = np.linspace(-3, 3, n)  # evenly spaced inputs.
    y = 1.0 + 0.8 * x - 0.25 * x**2 + 0.2 * np.sin(3 * x)  # smooth target with mild wiggle.
    return x, y  # return arrays for examples.
```
