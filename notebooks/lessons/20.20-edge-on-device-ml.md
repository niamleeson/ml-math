# 20.20 — Edge & On-Device ML

Edge and on-device ML moves prediction from a remote service into a small, user-owned environment. That swap can improve privacy, offline availability, and latency, but it turns every model choice into a budget calculation: memory, FLOPs, download size, energy, monitoring, and rollback all matter before the model is deployable.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build edge ML one idea at a time. Run each cell in order and read the printed intermediate values — every production quantity is named, measured, and turned into a small decision rule. This walkthrough is self-contained (it imports what it needs) and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays, synthetic data, and small cost calculations.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
np.random.seed(0)  # reproducibility for toy models and measurements.
```

### 1. Memory footprint is model + runtime + feature buffers

The first edge question is not accuracy; it is whether the thing fits. The production memory formula is

$$M = M_{model} + M_{runtime} + M_{features}.$$

A model can be small and still fail if the inference runtime or temporary feature buffers are large. We name each part separately so the budget has levers instead of one mysterious number.

```python
model_mb_w = 18.0       # serialized model parameters and metadata.
runtime_mb_w = 12.0     # interpreter / kernels / allocator overhead.
features_mb_w = 6.0     # input tensors, cached features, temporary buffers.
budget_mb_w = 64.0      # device memory budget reserved for ML.
parts_w = np.array([model_mb_w, runtime_mb_w, features_mb_w])
print("parts MB:", parts_w)
print("total MB:", parts_w.sum())
assert parts_w.sum() == 36.0
```
▶ What you'll see: the lesson's worked total is `18 + 12 + 6 = 36 MB`, which fits under `64 MB`.

```python
headroom_mb_w = budget_mb_w - parts_w.sum()
headroom_frac_w = headroom_mb_w / budget_mb_w
print("headroom MB:", headroom_mb_w)
print("headroom fraction:", round(headroom_frac_w, 3))
assert round(headroom_frac_w, 3) == 0.438
```
▶ What you'll see: 28 MB of headroom remains, so memory is not yet the blocker.

```python
plt.figure(figsize=(4.8, 3))
plt.bar(["model", "runtime", "features", "headroom"], [*parts_w, headroom_mb_w],
        color=["steelblue", "darkorange", "seagreen", "lightgray"])
plt.axhline(budget_mb_w, color="black", linestyle="--", label="64 MB budget")
plt.ylabel("MB")
plt.title("1: edge memory budget components")
plt.legend()
plt.show()
```
▶ What you'll see: the budget is not just the model bar; runtime and feature buffers consume half of the used memory.

*Why it's done this way:* edge deployment fails on peak resident memory, not on parameter size alone. Adding the components forces us to reserve space for code and activations, while headroom protects against allocator fragmentation, OS pressure, and input bursts.

### 2. Parameters, dtype, pruning, and quantization set footprint

A dense layer with `inputs × outputs` weights has that many parameters. Its memory is `parameter_count × bytes_per_parameter`. Quantization reduces bytes per stored value (for example float32 → int8 is 4 bytes → 1 byte), while pruning removes a fraction of weights. Used together, the approximate footprint is

$$M_{compressed} \approx N(1-s)\,b,$$

where $N$ is parameter count, $s$ is sparsity, and $b$ is bytes per remaining parameter.

```python
in_w, hidden_w, out_w = 32, 16, 3
params1_w = in_w * hidden_w + hidden_w
params2_w = hidden_w * out_w + out_w
params_total_w = params1_w + params2_w
print("layer params:", params1_w, params2_w)
print("total params:", params_total_w)
assert params_total_w == 579
```
▶ What you'll see: even a tiny two-layer net has 579 stored numbers once biases are included.

```python
float_bytes_w = 4
int8_bytes_w = 1
sparsity_w = 0.60
float_kb_w = params_total_w * float_bytes_w / 1024
quant_kb_w = params_total_w * int8_bytes_w / 1024
prune_quant_kb_w = params_total_w * (1 - sparsity_w) * int8_bytes_w / 1024
print("float32 KB:", round(float_kb_w, 3))
print("int8 KB:", round(quant_kb_w, 3))
print("60% pruned + int8 KB:", round(prune_quant_kb_w, 3))
assert round(quant_kb_w / float_kb_w, 2) == 0.25
```
▶ What you'll see: int8 gives a 4× storage reduction, and pruning stacks another multiplicative reduction.

```python
rng_w = np.random.default_rng(0)
W_w = rng_w.normal(0, 0.2, size=(in_w, hidden_w))
threshold_w = np.quantile(np.abs(W_w), sparsity_w)
W_pruned_w = np.where(np.abs(W_w) >= threshold_w, W_w, 0.0)
scale_w = np.max(np.abs(W_pruned_w)) / 127
W_q_w = np.round(W_pruned_w / scale_w).astype(np.int8)
W_deq_w = W_q_w.astype(float) * scale_w
print("actual sparsity:", round(float(np.mean(W_pruned_w == 0)), 3))
print("max dequant error:", round(float(np.max(np.abs(W_pruned_w - W_deq_w))), 5))
```
▶ What you'll see: the constructed array is about 60% zero, then int8 dequantization adds only a tiny rounding error.

```python
labels_w = ["float32", "int8", "60% prune + int8"]
sizes_w = [float_kb_w, quant_kb_w, prune_quant_kb_w]
plt.figure(figsize=(5.2, 3))
plt.bar(labels_w, sizes_w, color=["gray", "teal", "purple"])
plt.ylabel("KB")
plt.title("2: footprint from quantization and pruning")
plt.xticks(rotation=12)
plt.show()
```
▶ What you'll see: the footprint falls in steps, first by dtype and then by removing weights.

*Why it's done this way:* quantization and pruning attack different factors in the same product. Quantization changes bytes per value; pruning changes the number of values that must be stored or computed. Multiplying those effects is why compression recipes often combine them.

### 3. FLOPs and latency come from operation counts

Latency on a constrained device is often predicted before it is measured with a simple op-cost model. For a dense layer, multiply-adds scale as `batch × inputs × outputs`; for a rough FLOP count we use `2 × multiply_adds`, one multiply and one add. If the device sustains a known number of FLOPs per second, then

$$latency \approx \frac{FLOPs}{throughput} + overhead.$$

```python
batch_w = 1
flops_dense1_w = 2 * batch_w * in_w * hidden_w
flops_dense2_w = 2 * batch_w * hidden_w * out_w
flops_total_w = flops_dense1_w + flops_dense2_w
print("dense layer FLOPs:", flops_dense1_w, flops_dense2_w)
print("total FLOPs:", flops_total_w)
assert flops_total_w == 1120
```
▶ What you'll see: most arithmetic sits in the first dense layer because it has the larger matrix.

```python
throughput_flops_per_ms_w = 40_000.0
overhead_ms_w = 0.35
latency_ms_w = flops_total_w / throughput_flops_per_ms_w + overhead_ms_w
print("estimated latency ms:", round(latency_ms_w, 3))
assert round(latency_ms_w, 3) == 0.378
```
▶ What you'll see: arithmetic is cheap for this tiny model, so fixed overhead dominates latency.

```python
plt.figure(figsize=(4.6, 3))
plt.bar(["dense1", "dense2"], [flops_dense1_w, flops_dense2_w], color=["steelblue", "darkorange"])
plt.ylabel("FLOPs")
plt.title("3: FLOPs breakdown bars")
plt.show()
```
▶ What you'll see: the first bar is much taller; optimize the biggest operation first.

*Why it's done this way:* FLOP budgeting turns latency from a vague complaint into a sum over layers. The model is approximate because memory traffic, kernels, and scheduling also matter, but the biggest FLOP terms usually identify the first architecture lever.

### 4. Depthwise-separable convolution saves repeated channel mixing

A standard convolution with kernel size $K\times K$, input channels $C_{in}$, output channels $C_{out}$, and output map $H\times W$ costs

$$H W K^2 C_{in} C_{out}.$$

A depthwise-separable convolution splits this into a per-channel spatial filter plus a `1×1` channel mixer:

$$H W K^2 C_{in} + H W C_{in} C_{out}.$$

The saving appears because the expensive spatial kernel is no longer repeated for every output channel.

```python
H_w, Wmap_w, K_w, Cin_w, Cout_w = 32, 32, 3, 16, 32
std_mac_w = H_w * Wmap_w * K_w * K_w * Cin_w * Cout_w
dw_mac_w = H_w * Wmap_w * K_w * K_w * Cin_w
pw_mac_w = H_w * Wmap_w * Cin_w * Cout_w
sep_mac_w = dw_mac_w + pw_mac_w
print("standard MACs:", std_mac_w)
print("depthwise + pointwise MACs:", dw_mac_w, pw_mac_w, "=", sep_mac_w)
assert std_mac_w == 4718592
```
▶ What you'll see: standard convolution needs 4,718,592 MACs, while the split version is much smaller.

```python
saving_w = 1 - sep_mac_w / std_mac_w
speedup_w = std_mac_w / sep_mac_w
print("MAC reduction:", round(saving_w, 3))
print("theoretical speedup:", round(speedup_w, 2), "x")
assert round(speedup_w, 2) == 7.02
```
▶ What you'll see: the split convolution uses about one-seventh as many MACs in this configuration.

```python
plt.figure(figsize=(5, 3))
plt.bar(["standard", "depthwise", "pointwise", "separable total"],
        [std_mac_w, dw_mac_w, pw_mac_w, sep_mac_w],
        color=["crimson", "seagreen", "steelblue", "purple"])
plt.ylabel("MACs")
plt.title("4: convolution operation-cost breakdown")
plt.xticks(rotation=12)
plt.show()
```
▶ What you'll see: pointwise mixing dominates the separable version, but the total is far below the standard convolution bar.

*Why it's done this way:* standard convolution learns a separate spatial filter for every input-output channel pair. Depthwise-separable convolution assumes spatial filtering and channel mixing can be factored, which is a low-rank-style architectural prior that trades a little expressiveness for a large compute cut.

### 5. Energy is per-inference cost times daily volume

Battery impact accumulates. If one inference consumes $e$ millijoules and the device runs $n$ inferences per day, daily energy is

$$E = e\,n.$$

This simple multiplication is useful because a tiny per-call saving can matter when the model wakes up often.

```python
e_mj_w = 120.0
n_per_day_w = 50
daily_mj_w = e_mj_w * n_per_day_w
print("daily energy mJ:", daily_mj_w)
assert daily_mj_w == 6000.0
```
▶ What you'll see: the lesson's battery proxy is `120 mJ × 50 = 6,000 mJ/day`.

```python
candidate_e_w = np.array([180, 120, 60, 30], dtype=float)
daily_w = candidate_e_w * n_per_day_w
print("daily energy by candidate:", daily_w.astype(int))
assert int(daily_w[2]) == 3000
```
▶ What you'll see: halving per-inference energy halves daily energy at the same usage rate.

```python
plt.figure(figsize=(4.8, 3))
plt.plot(candidate_e_w, daily_w, marker="o", color="darkgreen")
plt.xlabel("mJ per inference")
plt.ylabel("mJ per day")
plt.title("5: daily energy = e × n")
plt.show()
```
▶ What you'll see: a straight line; usage frequency converts a per-call metric into battery pressure.

*Why it's done this way:* energy is an integral over time and events. Multiplying cost per inference by count is the smallest useful approximation, and it immediately shows whether optimization should focus on the model, the trigger frequency, or both.

### 6. Offline availability, update time, and privacy aggregation are product budgets

Edge ML is not just smaller inference. It changes product behavior: local prediction covers network gaps, model updates must download safely, and privacy-preserving telemetry sends aggregates rather than raw event streams.

```python
network_unavailable_w = 0.15
requests_w = 10_000
covered_offline_w = network_unavailable_w * requests_w
print("offline fraction covered:", network_unavailable_w)
print("offline requests served locally:", int(covered_offline_w))
assert int(covered_offline_w) == 1500
```
▶ What you'll see: if the network is absent 15% of the time, local inference can cover 1,500 of 10,000 requests.

```python
model_download_mb_w = 18.0
bandwidth_mb_s_w = 6.0
download_s_w = model_download_mb_w / bandwidth_mb_s_w
print("update download seconds:", download_s_w)
assert download_s_w == 3.0
```
▶ What you'll see: the lesson's update calculation is `18 / 6 = 3 seconds` before verification and install overhead.

```python
raw_events_w = 1000
counters_w = 20
records_saved_w = raw_events_w - counters_w
reduction_frac_w = records_saved_w / raw_events_w
print("records saved:", records_saved_w)
print("reduction fraction:", round(reduction_frac_w, 2))
assert records_saved_w == 980
```
▶ What you'll see: sending 20 counters instead of 1,000 events reduces transmitted records by 980.

```python
plt.figure(figsize=(5, 3))
plt.bar(["raw events", "aggregate counters"], [raw_events_w, counters_w], color=["crimson", "teal"])
plt.ylabel("records transmitted")
plt.title("6: privacy aggregation shrinks telemetry")
plt.show()
```
▶ What you'll see: the aggregate bar is tiny compared with raw telemetry, so observability must be designed around summaries.

*Why it's done this way:* on-device systems trade central control for local usefulness. Offline coverage, update time, and aggregate telemetry are budgets because each one affects whether users get reliable predictions without exposing unnecessary raw data.

### 7. Cascades and early exits spend compute only when needed

A cascade runs a cheap model first and calls an expensive model only when the cheap answer is uncertain. An early-exit network does the same inside one model: if an intermediate confidence is high, stop there. The expected cost is a weighted average, not the worst-case cost for every example.

```python
cheap_flops_w = 2_000
heavy_flops_w = 12_000
conf_w = np.array([0.95, 0.88, 0.61, 0.52, 0.99, 0.73, 0.40, 0.92])
threshold_w = 0.80
needs_heavy_w = conf_w < threshold_w
print("needs heavy model:", needs_heavy_w.astype(int))
print("heavy fraction:", round(float(needs_heavy_w.mean()), 3))
assert int(needs_heavy_w.sum()) == 4
```
▶ What you'll see: half the examples are uncertain enough to call the heavier model.

```python
cascade_flops_w = cheap_flops_w + needs_heavy_w.astype(float) * heavy_flops_w
always_heavy_w = cheap_flops_w + heavy_flops_w
expected_cascade_w = float(np.mean(cascade_flops_w))
print("expected cascade FLOPs:", expected_cascade_w)
print("always-heavy FLOPs:", always_heavy_w)
assert expected_cascade_w == 8000.0
```
▶ What you'll see: expected compute is 8,000 FLOPs instead of 14,000 because easy examples exit early.

```python
plt.figure(figsize=(5, 3))
plt.bar(np.arange(len(conf_w)), cascade_flops_w, color=np.where(needs_heavy_w, "crimson", "seagreen"))
plt.axhline(always_heavy_w, color="black", linestyle="--", label="always heavy")
plt.xlabel("example")
plt.ylabel("FLOPs")
plt.title("7: cascade cost by example")
plt.legend()
plt.show()
```
▶ What you'll see: green examples pay only the cheap cost, while red examples pay cheap plus heavy.

*Why it's done this way:* uncertainty gates convert a fixed compute graph into an expected-cost graph. The threshold controls the risk-compute tradeoff: higher thresholds send more examples to the heavy model; lower thresholds save energy but trust the cheap model more often.

### ✍️ Toy 1 · Memory budget adds every resident piece

On-device memory is model plus runtime plus buffers. This toy adds the parts and computes remaining headroom.

```python
import numpy as np
import matplotlib.pyplot as plt

t1_rng = np.random.default_rng(0)
t1_parts = np.array([10.0, 6.0, 4.0])                      # -> [10.  6.  4.]
t1_labels = ["model", "runtime", "buffers"]              # -> ['model', 'runtime', 'buffers']

print("parts MB:", t1_parts.tolist())                      # -> [10.0, 6.0, 4.0]

t1_total = float(t1_parts.sum())                            # -> 20.0
print("total MB:", t1_total)                               # -> 20.0
t1_headroom = t1_budget - t1_total                          # -> 12.0
t1_headroom_frac = t1_headroom / t1_budget                  # -> 0.375

print("headroom fraction:", round(t1_headroom_frac, 3))    # -> 0.375
plt.figure(figsize=(4.8, 2.8))
plt.bar(t1_labels + ["headroom"], list(t1_parts) + [t1_headroom], color=["#4c78a8", "#f58518", "#54a24b", "#bab0ac"])

```
▶ What you'll see: the deployment uses 20 MB and leaves 12 MB of the 32 MB budget.

### ✍️ Toy 3 · Quantization rounds floats onto int8 ticks

Symmetric int8 quantization chooses a scale, rounds float weights to integers, then dequantizes back to approximate floats.

```python
import numpy as np

t3_rng = np.random.default_rng(0)
t3_weights = np.array([-1.0, -0.25, 0.50, 0.75])           # -> [-1.   -0.25  0.5   0.75]
print("float weights:", t3_weights.tolist())               # -> [-1.0, -0.25, 0.5, 0.75]
t3_scale = np.max(np.abs(t3_weights)) / 127                 # -> 0.007874015748031496
print("scale:", round(float(t3_scale), 6))                 # -> 0.007874
t3_q = np.round(t3_weights / t3_scale).astype(np.int8)      # -> [-127  -32   64   95]
print("int8 weights:", t3_q.tolist())                      # -> [-127, -32, 64, 95]
t3_deq = t3_q.astype(float) * t3_scale                      # -> [-1.    -0.252  0.504  0.748]
print("dequantized:", np.round(t3_deq, 3).tolist())        # -> [-1.0, -0.252, 0.504, 0.748]
t3_error = t3_weights - t3_deq                              # -> [ 0.     0.002 -0.004  0.002]
print("quantization error:", np.round(t3_error, 4).tolist())  # -> [0.0, 0.002, -0.0039, 0.002]
t3_max_error = float(np.max(np.abs(t3_error)))              # -> 0.003937007874015741
print("max abs error:", round(t3_max_error, 6))            # -> 0.003937
plt.figure(figsize=(4.6, 2.8))
plt.bar(np.arange(t3_error.size), t3_error, color="#9d755d")
plt.axhline(0, color="black", linewidth=1)
plt.ylabel("error")
plt.title("Toy 3 · rounding error after int8")
plt.show()
assert t3_max_error < 0.005
```
▶ What you'll see: the dequantized weights nearly match the originals, with small rounding error.

### ✍️ Toy 5 · FLOPs become latency through throughput

Operation counts are converted to time by dividing by device throughput, then adding fixed overhead.

```python
import numpy as np

t5_rng = np.random.default_rng(0)
t5_batch = 1                                                 # -> 1
t5_in = 4                                                    # -> 4
t5_hidden = 3                                                # -> 3
t5_out = 2                                                   # -> 2
print("batch/in/hidden/out:", t5_batch, t5_in, t5_hidden, t5_out)  # -> 1 4 3 2
t5_flops1 = 2 * t5_batch * t5_in * t5_hidden                 # -> 24
t5_flops2 = 2 * t5_batch * t5_hidden * t5_out                # -> 12
print("layer FLOPs:", t5_flops1, t5_flops2)                 # -> 24 12
t5_total_flops = t5_flops1 + t5_flops2                       # -> 36
print("total FLOPs:", t5_total_flops)                       # -> 36
t5_throughput = 12.0                                         # -> 12.0
t5_compute_ms = t5_total_flops / t5_throughput               # -> 3.0
t5_overhead_ms = 0.50                                        # -> 0.5

print("latency ms:", t5_latency_ms)                         # -> 3.5
plt.figure(figsize=(4.4, 2.8))

plt.show()
assert t5_latency_ms == 3.5
```
▶ What you'll see: 36 FLOPs at 12 FLOPs/ms takes 3 ms, then overhead makes 3.5 ms total.

### ✍️ Toy 6 · Depthwise separable convolution cuts MACs

A separable convolution pays one spatial filter per channel plus a small pointwise mixer instead of repeating the spatial kernel for every output channel.

```python
import numpy as np

t6_rng = np.random.default_rng(0)
t6_H = 4                                                     # -> 4
t6_W = 4                                                     # -> 4
t6_K = 3                                                     # -> 3
t6_Cin = 2                                                   # -> 2
t6_Cout = 4                                                  # -> 4
print("H W K Cin Cout:", t6_H, t6_W, t6_K, t6_Cin, t6_Cout)  # -> 4 4 3 2 4
t6_standard = t6_H * t6_W * t6_K * t6_K * t6_Cin * t6_Cout   # -> 1152
t6_depthwise = t6_H * t6_W * t6_K * t6_K * t6_Cin            # -> 288
t6_pointwise = t6_H * t6_W * t6_Cin * t6_Cout                # -> 128
```

### Advanced 1 — Train a tiny NumPy net, then prune and quantize it

**Goal.** Build a tiny classifier from scratch and compress it, because edge ML often starts with a model that must be made small without destroying accuracy. We build it in 5 steps.

```python
rng_a1 = np.random.default_rng(1) # create deterministic data and initialization.
X_a1 = rng_a1.normal(size=(240, 2)) # synthesize two input features.
y_a1 = ((X_a1[:, 0] + 0.7 * X_a1[:, 1]) > 0).astype(int) # define a linearly separable label.
Y_a1 = np.eye(2)[y_a1] # one-hot encode labels for softmax training.
print("class counts:", np.bincount(y_a1)) # inspect class balance.
```

```python
W_a1 = 0.1 * rng_a1.normal(size=(2, 8)) # initialize hidden layer weights.
bh_a1 = np.zeros(8) # initialize hidden biases.
V_a1 = 0.1 * rng_a1.normal(size=(8, 2)) # initialize output layer weights.
bo_a1 = np.zeros(2) # initialize output biases.
print("parameter count:", W_a1.size + bh_a1.size + V_a1.size + bo_a1.size) # inspect model size.
```

```python
for step_a1 in range(600): # run full-batch gradient descent.
    H_a1 = np.tanh(X_a1 @ W_a1 + bh_a1) # compute hidden activations.
    logits_a1 = H_a1 @ V_a1 + bo_a1 # compute class logits.
    probs_a1 = np.exp(logits_a1 - logits_a1.max(axis=1, keepdims=True)) # exponentiate stabilized logits.
    probs_a1 = probs_a1 / probs_a1.sum(axis=1, keepdims=True) # normalize to probabilities.
    dlogits_a1 = (probs_a1 - Y_a1) / len(X_a1) # gradient of mean cross-entropy logits.
    dV_a1 = H_a1.T @ dlogits_a1 # gradient for output weights.
    dbo_a1 = dlogits_a1.sum(axis=0) # gradient for output biases.
    dH_a1 = dlogits_a1 @ V_a1.T * (1 - H_a1 ** 2) # backprop through tanh.
    dW_a1 = X_a1.T @ dH_a1 # gradient for hidden weights.
    dbh_a1 = dH_a1.sum(axis=0) # gradient for hidden biases.
    W_a1 -= 0.4 * dW_a1; bh_a1 -= 0.4 * dbh_a1; V_a1 -= 0.4 * dV_a1; bo_a1 -= 0.4 * dbo_a1 # update parameters.
print("training done") # confirm optimization completed.
```

```python

    H_local_a1 = np.tanh(X_local_a1 @ W_local_a1 + bh_local_a1) # hidden layer.
    return np.argmax(H_local_a1 @ V_local_a1 + bo_local_a1, axis=1) # predicted class.
acc_float_a1 = np.mean(predict_a1(X_a1, W_a1, bh_a1, V_a1, bo_a1) == y_a1) # compute float model accuracy.
all_weights_a1 = np.concatenate([W_a1.ravel(), V_a1.ravel()]) # collect weight magnitudes for pruning.
cut_a1 = np.quantile(np.abs(all_weights_a1), 0.5) # choose 50% magnitude pruning threshold.
W_pruned_a1 = np.where(np.abs(W_a1) >= cut_a1, W_a1, 0.0) # prune hidden weights.
V_pruned_a1 = np.where(np.abs(V_a1) >= cut_a1, V_a1, 0.0) # prune output weights.
scale_a1 = max(np.max(np.abs(W_pruned_a1)), np.max(np.abs(V_pruned_a1))) / 127 # shared int8 scale.
W_qdq_a1 = np.round(W_pruned_a1 / scale_a1).astype(np.int8).astype(float) * scale_a1 # quantize/dequantize hidden weights.
V_qdq_a1 = np.round(V_pruned_a1 / scale_a1).astype(np.int8).astype(float) * scale_a1 # quantize/dequantize output weights.
acc_comp_a1 = np.mean(predict_a1(X_a1, W_qdq_a1, bh_a1, V_qdq_a1, bo_a1) == y_a1) # compute compressed accuracy.
print("float acc:", round(float(acc_float_a1), 3), "compressed acc:", round(float(acc_comp_a1), 3)) # inspect accuracy change.
assert acc_float_a1 > 0.9 and acc_comp_a1 > 0.85 # verify compression leaves a usable toy model.
```

```python

compressed_bytes_a1 = (np.count_nonzero(W_pruned_a1) + np.count_nonzero(V_pruned_a1)) * 1 + (bh_a1.size + bo_a1.size) * 4 # approximate sparse int8 weights plus float biases.
```
