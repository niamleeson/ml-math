# 8.3 — Tokenization

Tokenization is the step that turns text into the discrete symbols a language model can count, embed, predict, and generate. The central compromise is granularity: whole words are short but brittle, characters are open-vocabulary but long, and subwords sit between them by learning reusable fragments such as `low`, `##ing`, or `est` from data.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build tokenization one idea at a time. Run each cell in order and read the printed intermediate values — every merge, score, and boundary marker is visible. This walkthrough is self-contained (it imports what it needs) and uses a `_w` suffix on its variables so it never clashes with the examples below.

### 1. Vocabulary design: words, characters, and the granularity budget

A tokenizer fixes the alphabet that every later model sees. Word tokens give short sequences, but any unseen surface form becomes `<unk>`. Character tokens almost never need `<unk>`, but they make sequences much longer. Subwords are the compromise: they keep frequent chunks whole while still decomposing rare words into known pieces.

```python
texts_w = ["low lower lowest", "new newest wider", "widest low"]  # a tiny inline corpus.
words_w = [w for text in texts_w for w in re.findall(r"[a-z]+", text.lower())]  # lowercase word units.
chars_w = [ch for w in words_w for ch in w]  # character units ignore word grouping for now.
print("word tokens:", words_w)
print("word vocabulary:", sorted(set(words_w)))
print("character vocabulary:", sorted(set(chars_w)))
```
▶ What you'll see: the word vocabulary contains complete surface forms, while the character vocabulary is tiny and reusable.

```python
new_word_w = "lowerest"  # not present as a full word, but all characters were seen.
word_vocab_w = set(words_w)  # whole-word vocabulary learned from the tiny corpus.
char_vocab_w = set(chars_w)  # character vocabulary learned from the same corpus.
word_level_w = [new_word_w] if new_word_w in word_vocab_w else ["<unk>"]  # whole-word lookup.
char_level_w = list(new_word_w) if set(new_word_w) <= char_vocab_w else ["<unk-char>"]  # character fallback.
print("word-level result:", word_level_w, "length", len(word_level_w))
print("char-level result:", char_level_w, "length", len(char_level_w))
assert word_level_w == ["<unk>"] and len(char_level_w) == 8
```
▶ What you'll see: whole-word tokenization loses the word as `<unk>`, while character tokenization preserves spelling but uses 8 positions.

```python
lengths_w = [len(word_level_w), len(char_level_w), 3]  # imagine a subword split like lower + ing marker pieces.
plt.figure(figsize=(4.6, 3))
plt.bar(["word", "character", "subword"], lengths_w, color=["crimson", "gray", "seagreen"])
plt.ylabel("token positions")
plt.title("1: granularity changes sequence length")
plt.show()
```
▶ What you'll see: the word view is shortest but throws information away; the character view is longest; the subword middle path is the useful compromise.

*Why it's done this way:* the vocabulary size and the sequence length are traded against each other. A word vocabulary spends many symbols to shorten common words but cannot extrapolate to new forms. A character vocabulary spends almost no vocabulary budget but forces the model to process many time steps. Subwords buy reusable chunks, so rare words stay representable without making every sentence character-long.

### 2. BPE pair counts: greedy compression from adjacent symbols

Byte Pair Encoding starts from characters plus an end-of-word marker, then repeatedly merges the most frequent adjacent pair. The merge rule is greedy: at each step, choose the pair with the largest current corpus count. Ties are real, so deterministic ordering becomes part of the tokenizer.

```python
corpus_w = ["low", "lower", "newest", "widest"]  # the lesson's toy words.
tokens_w = {word: tuple(list(word) + ["_"]) for word in corpus_w}  # _ marks the end of a word.
print("initial tokenized words:")
for word_w, pieces_w in tokens_w.items():
    print(word_w, "->", pieces_w)
```
▶ What you'll see: every word begins as characters, with `_` preserving the word boundary.

```python
def pair_counts_w(tokenized_w):
    counts_w = Counter()
    for pieces_w in tokenized_w.values():
        for i_w in range(len(pieces_w) - 1):
            counts_w[(pieces_w[i_w], pieces_w[i_w + 1])] += 1
    return counts_w

counts_w = pair_counts_w(tokens_w)
for pair_w, count_w in counts_w.most_common(8):
    print(pair_w, "count", count_w)
best_pair_w = max(counts_w, key=lambda p_w: (counts_w[p_w], tuple(reversed(p_w))))  # a visible deterministic tie-break.
print("chosen by this deterministic rule:", best_pair_w, counts_w[best_pair_w])
assert counts_w[("l", "o")] == 2 and counts_w[("e", "s")] == 2
```
▶ What you'll see: several pairs reach count 2; a tokenizer must choose one consistently when counts tie.

```python
def merge_pair_w(pieces_w, pair_w):
    merged_w = []
    i_w = 0
    while i_w < len(pieces_w):
        if i_w < len(pieces_w) - 1 and (pieces_w[i_w], pieces_w[i_w + 1]) == pair_w:
            merged_w.append(pieces_w[i_w] + pieces_w[i_w + 1])
            i_w += 2
        else:
            merged_w.append(pieces_w[i_w])
            i_w += 1
    return tuple(merged_w)

merge_w = ("l", "o")  # the lesson's first maximum.
after_merge_w = {word_w: merge_pair_w(pieces_w, merge_w) for word_w, pieces_w in tokens_w.items()}
print("low before:", tokens_w["low"], "length", len(tokens_w["low"]))
print("low after :", after_merge_w["low"], "length", len(after_merge_w["low"]))
assert len(tokens_w["low"]) - len(after_merge_w["low"]) == 1
```
▶ What you'll see: `low` shrinks from four symbols to three because `l` and `o` became `lo`.

```python
before_lengths_w = np.array([len(p) for p in tokens_w.values()])
after_lengths_w = np.array([len(p) for p in after_merge_w.values()])
plt.figure(figsize=(4.8, 3))
plt.bar(np.arange(len(corpus_w)) - 0.18, before_lengths_w, width=0.36, label="before", color="gray")
plt.bar(np.arange(len(corpus_w)) + 0.18, after_lengths_w, width=0.36, label="after lo", color="seagreen")
plt.xticks(range(len(corpus_w)), corpus_w)
plt.ylabel("pieces per word")
plt.title("2: one BPE merge saves positions")
plt.legend()
plt.show()
```
▶ What you'll see: only words containing `lo` get shorter, which is exactly why frequent fragments pay back their vocabulary cost.

*Why it's done this way:* BPE is a compression algorithm over token positions. If a pair appears `c` times, merging it saves roughly `c` positions immediately, so the most frequent pair gives the largest local sequence-length reduction. The greediness is not globally optimal, but it is simple, deterministic, and scalable.

### 3. Applying a learned merge list to new words

Training produces an ordered list of merges; serving must replay that exact list. A new word starts as characters, then each learned merge is applied in order. This lets a word that was never seen as a whole still be assembled from known fragments.

```python
merges_w = [("l", "o"), ("lo", "w"), ("e", "s"), ("es", "t"), ("low", "est")]  # a tiny learned history.
word_w = "lowest"
pieces_w = tuple(list(word_w) + ["_"])
print("start:", pieces_w)
for pair_w in merges_w:
    pieces_w = merge_pair_w(pieces_w, pair_w)
    print("after", pair_w, "->", pieces_w)
assert "lowest" in pieces_w or ("low" in pieces_w and "est" in pieces_w)
```
▶ What you'll see: the word moves from characters toward larger chunks as the merge history is replayed.

```python
subword_vocab_w = {"low", "lower", "est", "_", "lo", "w", "e", "s", "t"}
word_vocab_w = {"low", "lower"}
new_w = "lowest"
word_token_w = [new_w] if new_w in word_vocab_w else ["<unk>"]
subword_token_w = ["low", "est"] if {"low", "est"} <= subword_vocab_w else ["<unk>"]
print("word-level:", word_token_w)
print("subword-level:", subword_token_w)
assert word_token_w == ["<unk>"] and subword_token_w == ["low", "est"]
```
▶ What you'll see: subwords keep the known stem `low` instead of erasing the whole form as unknown.

```python
plt.figure(figsize=(4.6, 3))
plt.bar(["word <unk>", "subword pieces"], [0, len(subword_token_w)], color=["crimson", "seagreen"])
plt.ylabel("known lexical pieces retained")
plt.title("3: subwords preserve usable evidence")
plt.show()
```
▶ What you'll see: the word-level path retains no internal evidence, while the subword path keeps two known units.

*Why it's done this way:* the merge list is a learned vocabulary definition, not a suggestion. Replaying it identically at serving time ensures the same text maps to the same symbols and ids. When a whole word is unseen, subword decomposition changes the failure mode from "unknown word" to "longer but interpretable sequence."

### 4. WordPiece continuation markers preserve boundaries

WordPiece-style tokenizers often mark non-initial pieces with `##`. The marker is not decoration: it says the piece attaches to the previous word instead of starting a new word. That boundary information matters for both the model and detokenization.

```python
pieces_w = ["play", "##ing", "play", "##er", "un", "##play", "##able"]
continuations_w = [p_w for p_w in pieces_w if p_w.startswith("##")]
fraction_w = len(continuations_w) / len(pieces_w)
print("pieces:", pieces_w)
print("continuations:", continuations_w)
print("continuation fraction:", round(fraction_w, 3))
assert len(continuations_w) == 4 and round(fraction_w, 3) == 0.571
```
▶ What you'll see: 4 of 7 pieces are continuations, matching the lesson's 4/7 calculation.

```python
def detokenize_wordpiece_w(pieces_w):
    out_w = ""
    for piece_w in pieces_w:
        if piece_w.startswith("##"):
            out_w += piece_w[2:]
        else:
            out_w += (" " if out_w else "") + piece_w
    return out_w

sentence_pieces_w = ["un", "##play", "##able", "play", "##er"]
print("with markers:", detokenize_wordpiece_w(sentence_pieces_w))
print("markers stripped too early:", " ".join([p.replace("##", "") for p in sentence_pieces_w]))
assert detokenize_wordpiece_w(sentence_pieces_w) == "unplayable player"
```
▶ What you'll see: markers reconstruct `unplayable player`; stripping them early produces the wrong word boundaries.

```python
marker_counts_w = [sum(not p.startswith("##") for p in sentence_pieces_w), sum(p.startswith("##") for p in sentence_pieces_w)]
plt.figure(figsize=(4.2, 3))
plt.bar(["word starts", "continuations"], marker_counts_w, color=["steelblue", "darkorange"])
plt.ylabel("piece count")
plt.title("4: WordPiece markers encode attachment")
plt.show()
```
▶ What you'll see: most pieces in `unplayable player` are continuations, so deleting the marker would delete most boundary evidence.

*Why it's done this way:* a subword string like `play` can mean either a fresh word or the middle of a longer word. Prefixing continuation pieces gives the tokenizer a finite-state boundary rule: unmarked pieces may start words, marked pieces must attach. That makes detokenization and downstream position interpretation unambiguous.

### 5. SentencePiece-style segmentation by probability

A unigram/SentencePiece view treats segmentation as a scoring problem. Instead of replaying only a merge history, it assigns probabilities to pieces and chooses the segmentation with the highest product probability, or equivalently the largest sum of log probabilities.

```python
piece_prob_w = {"the": 0.40, "re": 0.80, "ther": 0.30, "e": 0.60, "t": 0.10, "here": 0.50}
segmentations_w = [["the", "re"], ["ther", "e"], ["t", "here"]]
for seg_w in segmentations_w:
    prob_w = np.prod([piece_prob_w[p_w] for p_w in seg_w])
    print(seg_w, "probability", round(float(prob_w), 3))
assert round(float(np.prod([piece_prob_w[p] for p in ["the", "re"]])), 3) == 0.32
```
▶ What you'll see: `[the, re]` scores 0.32, higher than the alternative segmentations.

```python
scores_w = np.array([sum(np.log(piece_prob_w[p_w]) for p_w in seg_w) for seg_w in segmentations_w])
best_idx_w = int(np.argmax(scores_w))
print("log scores:", np.round(scores_w, 3))
print("chosen segmentation:", segmentations_w[best_idx_w])
assert segmentations_w[best_idx_w] == ["the", "re"]
```
▶ What you'll see: log scores pick the same winner as probability products, but are numerically easier to add.

```python
plt.figure(figsize=(4.8, 3))
plt.bar(["+".join(s) for s in segmentations_w], np.exp(scores_w), color="mediumpurple")
plt.ylabel("segmentation probability")
plt.title("5: competing segmentations for 'there'")
plt.show()
```
▶ What you'll see: the tallest bar is `the+re`, so the probabilistic tokenizer chooses that split.

*Why it's done this way:* multiplying piece probabilities rewards segmentations made from likely pieces, but products get tiny as sequences grow. Taking logs turns the product into a sum without changing the argmax, so dynamic programs can compare many segmentations stably and explicitly.

### Basic 7 — Merge one adjacent pair

**Goal.** Replace every adjacent `l` + `o` with `lo`, because a BPE merge creates one larger symbol from two neighboring symbols. We build it in 2 steps.

```python
pieces_b7 = tuple(list("low") + ["_"])  # Start with low as characters plus boundary.
merge_b7 = ("l", "o")  # Choose the first merge.
print("before:", pieces_b7)  # Inspect the original pieces.
```
▶ What you'll see: `low` begins as `('l', 'o', 'w', '_')`.

```python
merged_b7 = []  # Store the merged output.
i_b7 = 0  # Walk through the input pieces manually.
while i_b7 < len(pieces_b7):  # Continue until every piece is consumed.
    if i_b7 < len(pieces_b7) - 1 and (pieces_b7[i_b7], pieces_b7[i_b7 + 1]) == merge_b7:  # Detect the target pair.
        merged_b7.append(pieces_b7[i_b7] + pieces_b7[i_b7 + 1])  # Join the pair into one symbol.
        i_b7 += 2  # Skip both old symbols.
    else:
        merged_b7.append(pieces_b7[i_b7])  # Copy untouched symbols.
        i_b7 += 1  # Move one step.
print("after:", merged_b7)  # Inspect the merged word.
assert merged_b7 == ["lo", "w", "_"]  # Verify the exact merge result.
```
▶ What you'll see: the word loses one token position because two symbols became one.

```python
best_path_a3 = [None] * (len(word_a3) + 1)  # best segmentation path up to each position.
best_score_a3[0] = 0.0  # Empty prefix has log probability 0.
best_path_a3[0] = []  # Empty prefix has no pieces.
for end_a3 in range(1, len(word_a3) + 1):  # Fill DP left to right.
    for start_a3 in range(end_a3):  # Try every previous cut.
        piece_a3 = word_a3[start_a3:end_a3]  # Candidate final piece.
        if piece_a3 in piece_prob_a3 and best_path_a3[start_a3] is not None:  # Valid transition.
            score_a3 = best_score_a3[start_a3] + np.log(piece_prob_a3[piece_a3])  # Add log probability.
            if score_a3 > best_score_a3[end_a3]:  # Keep the best predecessor.
                best_score_a3[end_a3] = score_a3
                best_path_a3[end_a3] = best_path_a3[start_a3] + [piece_a3]
print("best path:", best_path_a3[-1], "prob", round(float(np.exp(best_score_a3[-1])), 4))  # Inspect DP winner.
assert best_path_a3[-1] == ["low", "est"]  # Verify the higher product beats whole-word lowest.
```
▶ What you'll see: `low + est` wins because 0.35×0.30 = 0.105 beats the whole-word probability 0.09.


### Advanced 5 — Audit train/serve vocabulary mismatch

**Goal.** Encode the same text with two different merge lists, because training and serving with different tokenizer artifacts changes token identities. We build it in 3 steps.

```python
word_a5 = "lowest"  # Same input at train and serve time.
train_merges_a5 = [("l", "o"), ("lo", "w"), ("e", "s"), ("es", "t")]  # Expected merge history.
serve_merges_a5 = [("e", "s"), ("es", "t"), ("l", "o")]  # Mismatched serving history.
print("word:", word_a5)  # Inspect shared input.
```
▶ What you'll see: only the tokenizer artifact changes, not the raw text.

```python
def apply_merges_a5(word_a5, merges_a5):  # Encode one word by replaying merges.
    pieces_a5 = tuple(list(word_a5) + ["_"])
    for merge_a5 in merges_a5:
        out_a5 = []
        i_a5 = 0
        while i_a5 < len(pieces_a5):
            if i_a5 < len(pieces_a5) - 1 and (pieces_a5[i_a5], pieces_a5[i_a5 + 1]) == merge_a5:
                out_a5.append(pieces_a5[i_a5] + pieces_a5[i_a5 + 1]); i_a5 += 2
            else:
                out_a5.append(pieces_a5[i_a5]); i_a5 += 1
        pieces_a5 = tuple(out_a5)
    return pieces_a5

train_tokens_a5 = apply_merges_a5(word_a5, train_merges_a5)  # Encode with training tokenizer.
serve_tokens_a5 = apply_merges_a5(word_a5, serve_merges_a5)  # Encode with mismatched serving tokenizer.
print("train tokens:", train_tokens_a5)  # Inspect training-time tokens.
print("serve tokens:", serve_tokens_a5)  # Inspect serving-time tokens.
assert train_tokens_a5 != serve_tokens_a5  # Verify mismatch changes segmentation.
```
▶ What you'll see: the same word becomes different token sequences under different merge histories.
