# 21.3 — Knowledge Representation

Knowledge representation (KR) is the art of choosing facts, links, defaults, and explanations so an AI system can draw the conclusions people need without storing every conclusion by hand. In this lesson, we build tiny semantic networks, frames, ontologies, inheritance rules, and frame-problem updates from scratch using only Python dictionaries, NumPy, and Matplotlib.

### 1. Semantic networks: facts as labeled graph edges

A semantic network stores knowledge as a graph: nodes are concepts or individuals, and labeled edges say how they relate. This is more useful than a flat list because a path can explain a conclusion: Tweety is a Penguin, Penguin is a Bird, and Birds have wings.

```python
edges_w = [
    ("Tweety", "is-a", "Penguin"),
    ("Penguin", "is-a", "Bird"),
    ("Bird", "has", "wings"),
    ("Penguin", "has", "flippers"),
]
print("semantic-network edges:")
for s_w, r_w, o_w in edges_w:
    print(f"{s_w:8s} --{r_w:4s}--> {o_w}")
```
▶ What you'll see: a small labeled graph where type links (`is-a`) and property links (`has`) use the same edge format.

```python
pos_w = {"Tweety": (0, 0), "Penguin": (1.5, 1), "Bird": (3, 2), "wings": (4.5, 2.4), "flippers": (3, .4)}
plt.figure(figsize=(6, 3.5))
for node_w, (x_w, y_w) in pos_w.items():
    plt.scatter([x_w], [y_w], s=700, color="white", edgecolor="black")
    plt.text(x_w, y_w, node_w, ha="center", va="center")
for s_w, r_w, o_w in edges_w:
    x1_w, y1_w = pos_w[s_w]; x2_w, y2_w = pos_w[o_w]
    plt.annotate("", xy=(x2_w, y2_w), xytext=(x1_w, y1_w), arrowprops=dict(arrowstyle="->", lw=1.5))
    plt.text((x1_w + x2_w) / 2, (y1_w + y2_w) / 2 + .1, r_w, color="teal")
plt.title("1: semantic network as a labeled graph")
plt.axis("off"); plt.show()
```
▶ What you'll see: arrows from Tweety to Penguin to Bird, plus property arrows to wings and flippers; look for paths, not isolated facts.

```python
def outgoing_w(edges, source, label=None):
    return [(r, o) for s, r, o in edges if s == source and (label is None or r == label)]
print("Tweety outgoing:", outgoing_w(edges_w, "Tweety"))
print("Penguin properties:", outgoing_w(edges_w, "Penguin", "has"))
assert outgoing_w(edges_w, "Tweety", "is-a")[0][1] == "Penguin"
```
▶ What you'll see: a direct lookup finds only immediate facts; inheritance will be needed to reach Bird's wings.

*Why it's done this way:* a labeled graph keeps every assertion uniform, so the same traversal code can inspect class membership, part/property links, and explanations. The graph is not just a container; its paths are the mechanism that makes later inference cheap.

### 2. Frames and slots: structured records with local facts

A frame is a named bundle of slots. It is like a dictionary for a concept or individual: Bird has slots such as covering and locomotion; Penguin overrides some of them; Tweety can inherit from Penguin. Frames make common attributes explicit instead of scattering them across unrelated predicates.

```python
frames_w = {
    "Bird": {"is_a": None, "slots": {"covering": "feathers", "has_wings": True, "can_fly": True}},
    "Penguin": {"is_a": "Bird", "slots": {"can_fly": False, "swims": True}},
    "Tweety": {"is_a": "Penguin", "slots": {"name": "Tweety"}},
}
for name_w, frame_w in frames_w.items():
    print(name_w, "parent=", frame_w["is_a"], "slots=", frame_w["slots"])
```
▶ What you'll see: `Penguin` stores only what differs or is new; it does not repeat every Bird fact.

```python
def lookup_slot_w(frames, thing, slot):
    path = []
    cur = thing
    while cur is not None:
        path.append(cur)
        slots = frames[cur]["slots"]
        if slot in slots:
            return slots[slot], path
        cur = frames[cur]["is_a"]
    return None, path

value_w, path_w = lookup_slot_w(frames_w, "Tweety", "covering")
print("Tweety covering:", value_w, "via", " -> ".join(path_w))
assert value_w == "feathers"
```
▶ What you'll see: Tweety has feathers even though that slot is stored only on Bird.

```python
fly_w, fly_path_w = lookup_slot_w(frames_w, "Tweety", "can_fly")
print("Tweety can_fly:", fly_w, "via", " -> ".join(fly_path_w))
assert fly_w is False
```

```python
frame_names_w = list(frames_w)
slot_names_w = sorted({slot for frame in frames_w.values() for slot in frame["slots"]})
slot_matrix_w = np.array([[int(slot in frames_w[frame]["slots"]) for slot in slot_names_w] for frame in frame_names_w])
plt.figure(figsize=(5.8, 2.8))
plt.imshow(slot_matrix_w, cmap="Blues", aspect="auto")
plt.xticks(range(len(slot_names_w)), slot_names_w, rotation=35, ha="right")
plt.yticks(range(len(frame_names_w)), frame_names_w)
plt.title("2: frame slots stored locally")
plt.colorbar(label="slot stored here")
plt.tight_layout(); plt.show()
```
▶ What you'll see: Bird stores broad reusable slots, while Penguin and Tweety store only local additions or exceptions.
▶ What you'll see: the search stops at Penguin because a specific frame overrides Bird's default flying slot.

*Why it's done this way:* frames separate stable structure from local exceptions. The lookup order is the reasoning rule: try the most specific frame first, then climb upward only when the slot is absent.

### 3. Ontologies and is-a hierarchies: classes as reusable shelves

An ontology makes the `is-a` hierarchy central. If Penguin is a subclass of Bird and Bird is a subclass of Animal, then class queries can include subclasses automatically. The hierarchy is what turns a stored fact into many safe, explainable answers.

```python
parents_w = {"Animal": None, "Bird": "Animal", "Mammal": "Animal", "Penguin": "Bird", "Robin": "Bird"}
instances_w = {"Tweety": "Penguin", "Robin_1": "Robin", "Fido": "Mammal"}
print("class parents:", parents_w)
print("individual types:", instances_w)
```
▶ What you'll see: a small taxonomy plus three individuals placed on its leaves.

```python
def ancestors_w(cls):
    out = []
    cur = cls
    while cur is not None:
        out.append(cur)
        cur = parents_w[cur]
    return out

print("Penguin ancestors:", ancestors_w("Penguin"))
print("Tweety type path:", ancestors_w(instances_w["Tweety"]))
assert "Animal" in ancestors_w(instances_w["Tweety"])
```
▶ What you'll see: Penguin inherits upward through Bird to Animal.

```python
def instances_of_w(target_cls):
    return [ind for ind, cls in instances_w.items() if target_cls in ancestors_w(cls)]
print("all Birds:", instances_of_w("Bird"))
print("all Animals:", instances_of_w("Animal"))
assert set(instances_of_w("Bird")) == {"Tweety", "Robin_1"}
```

```python
pos_tax_w = {"Animal": (2, 3), "Bird": (1, 2), "Mammal": (3, 2), "Penguin": (.4, 1), "Robin": (1.6, 1), "Tweety": (.4, 0), "Robin_1": (1.6, 0), "Fido": (3, 1)}
plt.figure(figsize=(5.8, 3.8))
for child_w, parent_w in parents_w.items():
    if parent_w is not None:
        x1_w, y1_w = pos_tax_w[child_w]; x2_w, y2_w = pos_tax_w[parent_w]
        plt.annotate("", xy=(x2_w, y2_w), xytext=(x1_w, y1_w), arrowprops=dict(arrowstyle="->", lw=1.3))
for ind_w, cls_w in instances_w.items():
    x1_w, y1_w = pos_tax_w[ind_w]; x2_w, y2_w = pos_tax_w[cls_w]
    plt.annotate("", xy=(x2_w, y2_w), xytext=(x1_w, y1_w), arrowprops=dict(arrowstyle="->", lw=1.1, linestyle="dashed", color="gray"))
for node_w, (x_w, y_w) in pos_tax_w.items():
    is_ind_w = node_w in instances_w
    plt.scatter([x_w], [y_w], s=650, color="white", edgecolor="teal" if is_ind_w else "black", zorder=3)
    plt.text(x_w, y_w, node_w, ha="center", va="center", zorder=4)
plt.title("3: ontology hierarchy with typed individuals")
plt.axis("off"); plt.show()
```
▶ What you'll see: dashed individual-to-class links feed into solid subclass links up to Animal.
▶ What you'll see: querying Bird returns Penguin and Robin individuals without duplicating their type labels.

*Why it's done this way:* `is-a` edges encode set containment. Storing one parent link per class lets a query climb the hierarchy and recover all implied memberships with an explanation path.

### 4. Defaults and exceptions: inheritance is not just copying

Default inheritance says a class property usually flows downward, but a more specific class can block it. Bird can default to `can_fly=True`; Penguin can say `can_fly=False`; Tweety should inherit the exception because Penguin is closer than Bird.

```python
defaults_w = {
    "Animal": {"breathes": True},
    "Bird": {"can_fly": True, "has_wings": True},
    "Penguin": {"can_fly": False, "swims": True},
}
print("defaults by class:", defaults_w)
```
▶ What you'll see: both a general default and a more specific exception are present.

```python
def inherited_properties_w(individual):
    cls_path = ancestors_w(instances_w[individual])
    resolved = {}
    explanations = {}
    for cls in reversed(cls_path):
        for prop, val in defaults_w.get(cls, {}).items():
            resolved[prop] = val
            explanations[prop] = cls
    return resolved, explanations

props_w, why_w = inherited_properties_w("Tweety")
print("Tweety properties:", props_w)
print("explanations:", why_w)
assert props_w["has_wings"] is True
assert props_w["can_fly"] is False
```
▶ What you'll see: `has_wings=True` comes from Bird, while `can_fly=False` comes from Penguin.

```python
labels_w = list(props_w)
values_w = [1 if props_w[k] else 0 for k in labels_w]
colors_w = ["seagreen" if props_w[k] else "crimson" for k in labels_w]
plt.figure(figsize=(5, 3))
plt.bar(labels_w, values_w, color=colors_w)
plt.ylim(0, 1.2); plt.title("4: resolved inherited properties for Tweety")
plt.ylabel("truth value"); plt.xticks(rotation=20); plt.show()
```
▶ What you'll see: true properties are green and the blocked flying default is red.

*Why it's done this way:* applying general classes first and specific classes later gives exceptions a principled priority. The result is not a blind union; it is a controlled override policy with traceable justifications.

### 5. Taxonomic inference: answering class queries from paths

Taxonomic inference asks questions like, "Is Tweety an Animal?" or "Which things are Birds?" The answer is computed by graph reachability in the class hierarchy, not by memorizing every pair.

```python
def is_instance_of_w(individual, target_cls):
    cls = instances_w[individual]
    path = ancestors_w(cls)
    return target_cls in path, path

answer_w, path_w = is_instance_of_w("Tweety", "Animal")
print("Is Tweety an Animal?", answer_w, "path:", " -> ".join(path_w))
assert answer_w is True
```
▶ What you'll see: the proof path Penguin → Bird → Animal explains the yes answer.

```python
queries_w = [("Tweety", "Bird"), ("Fido", "Bird"), ("Robin_1", "Animal")]
for ind_w, cls_w in queries_w:
    ans_w, path_w = is_instance_of_w(ind_w, cls_w)
    print(f"{ind_w} is a {cls_w}? {ans_w}; path={path_w}")
```
▶ What you'll see: positive and negative answers both come from checking the same ancestor list.

```python
classes_w = ["Animal", "Bird", "Mammal", "Penguin", "Robin"]
counts_w = [len(instances_of_w(c)) for c in classes_w]
plt.figure(figsize=(5, 3))
plt.bar(classes_w, counts_w, color="slateblue")
plt.title("5: inferred instance counts by class")
plt.ylabel("number of matching individuals"); plt.xticks(rotation=20); plt.show()
```
▶ What you'll see: broad classes such as Animal collect instances from all descendants.

*Why it's done this way:* a taxonomy turns classification into path search. This makes inference cheap, but only because the representation made subclass structure explicit.

### 6. The frame problem: changing one fact without rewriting the world

The frame problem asks how to represent what stays the same after an action. If a robot moves a cup from table to shelf, its color and material should persist without restating every unchanged slot after every action.

```python
state0_w = {
    "cup": {"location": "table", "color": "blue", "clean": True},
    "book": {"location": "shelf", "color": "red", "clean": False},
}
action_w = {"object": "cup", "slot": "location", "new_value": "shelf"}
print("before:", state0_w["cup"])
print("action:", action_w)
```
▶ What you'll see: the action specifies only the one slot that changes.

```python
def apply_action_w(state, action):
    new_state = {obj: slots.copy() for obj, slots in state.items()}
    new_state[action["object"]][action["slot"]] = action["new_value"]
    return new_state

state1_w = apply_action_w(state0_w, action_w)
print("after cup:", state1_w["cup"])
print("after book:", state1_w["book"])
assert state1_w["cup"]["location"] == "shelf"
assert state1_w["cup"]["color"] == "blue"
assert state1_w["book"] == state0_w["book"]
```
▶ What you'll see: only the cup's location changes; unrelated slots and objects persist.

```python
slots_w = ["location", "color", "clean"]
changed_w = [state0_w["cup"][s] != state1_w["cup"][s] for s in slots_w]
plt.figure(figsize=(4.6, 3))
plt.bar(slots_w, [int(x) for x in changed_w], color=["crimson" if x else "gray" for x in changed_w])
plt.ylim(0, 1.2); plt.title("6: one action changes one slot")
plt.ylabel("changed?"); plt.show()
```
▶ What you'll see: only `location` is marked as changed; this is the persistence assumption made visible.

*Why it's done this way:* copying the old state and editing only named effects encodes inertia: facts persist unless an action says otherwise. That avoids an impossible explosion of "nothing else changed" rules.

## 🛠️ Setup

```python
import numpy as np # load NumPy for small arrays, deterministic layouts, and numeric checks.
import matplotlib.pyplot as plt # load Matplotlib for graph, hierarchy, and state-change visualizations.
from collections import deque # use a standard-library queue for graph traversals.
np.random.seed(0) # make all examples reproducible.

def draw_graph(nodes, edges, pos, title): # draw a small labeled directed graph with Matplotlib.
    plt.figure(figsize=(6, 3.6)) # create a compact figure that fits in a notebook cell.
    for node in nodes: # draw every node before drawing arrows.
        x, y = pos[node] # read the fixed layout coordinate.
        plt.scatter([x], [y], s=700, color="white", edgecolor="black", zorder=3) # draw a labeled circle.
        plt.text(x, y, node, ha="center", va="center", zorder=4) # place the node label in the circle.
    for s, label, o in edges: # draw directed labeled edges.
        x1, y1 = pos[s]; x2, y2 = pos[o] # get edge endpoints.
        plt.annotate("", xy=(x2, y2), xytext=(x1, y1), arrowprops=dict(arrowstyle="->", lw=1.4)) # draw an arrow.
        plt.text((x1 + x2) / 2, (y1 + y2) / 2 + .08, label, color="teal", ha="center") # label the relation.
    plt.title(title) # add the example title.
    plt.axis("off") # hide numeric axes because the coordinates are only layout.
    plt.show() # render the figure.

def climb(parent_map, start): # return start, parent, grandparent, ... until the root.
    path = [] # collect the upward chain for explanations.
    cur = start # begin at the most specific class.
    while cur is not None: # continue until a root with no parent.
        path.append(cur) # include the current class.
        cur = parent_map.get(cur) # move to its parent.
    return path # return most-specific to most-general order.

def resolve_slot(frames, thing, slot): # look up a frame slot with inheritance.
    path = [] # keep the explanation path.
    cur = thing # start at the requested frame.
    while cur is not None: # climb until root.
        path.append(cur) # record the frame inspected.
        slots = frames[cur].get("slots", {}) # read local slots.
        if slot in slots: # stop at the most specific available value.
            return slots[slot], path # return value and explanation.
        cur = frames[cur].get("is_a") # otherwise inherit from parent.
    return None, path # return no value if no frame defines the slot.
```

### Basic 7 — Climb a taxonomy

### Advanced 5 — Minimize frame-problem updates

**Goal.** Track changed slots across a plan, because efficient state representations update effects while preserving everything else by inertia. We build it in 4 steps.

```python
state_a5 = {"robot": {"room": "A", "battery": 2}, "box": {"room": "A", "color": "green"}} # define initial state.
plan_a5 = [("robot", "room", "B"), ("robot", "battery", 1), ("box", "room", "B")] # define action effects only.
print("initial state:", state_a5) # inspect starting facts.
```

```python
states_a5 = [state_a5] # store state history.
changed_counts_a5 = [] # count changed slots per action.
for obj_a5, slot_a5, val_a5 in plan_a5: # apply each effect.
    previous_a5 = states_a5[-1] # read current state.
    nxt_a5 = {obj: slots.copy() for obj, slots in previous_a5.items()} # copy all persistent facts.
    before_a5 = nxt_a5[obj_a5][slot_a5] # read old value.
    nxt_a5[obj_a5][slot_a5] = val_a5 # update one effect slot.
    states_a5.append(nxt_a5) # save next state.
    changed_counts_a5.append(int(before_a5 != val_a5)) # count whether the effect changed a value.
print("final state:", states_a5[-1]) # inspect final state.
```

```python
assert states_a5[-1]["box"]["color"] == "green" # verify unrelated box slot persisted.
assert states_a5[-1]["robot"]["room"] == "B" # verify robot movement occurred.
assert sum(changed_counts_a5) == 3 # verify all three listed effects changed a slot.
print("changed counts:", changed_counts_a5) # inspect per-action changes.
```

```python
plt.figure(figsize=(5, 3)) # create a plan update plot.
plt.step(range(1, len(changed_counts_a5) + 1), np.cumsum(changed_counts_a5), where="mid", color="purple") # show cumulative explicit changes.
plt.scatter(range(1, len(changed_counts_a5) + 1), np.cumsum(changed_counts_a5), color="purple") # mark action steps.
plt.title("Advanced 5: explicit effects across a plan"); plt.xlabel("action number"); plt.ylabel("cumulative changed slots") # label axes.
plt.xticks(range(1, len(changed_counts_a5) + 1)); plt.show() # display plot.
```
▶ What you'll see: only named effects accumulate as changes, while all other slots persist silently.

👀 Takeaway: the frame problem is controlled by representing action effects locally and assuming inertia for the rest.
