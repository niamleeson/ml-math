# 19.8 — Adversarial Attacks

Adversarial attacks deliberately search for tiny input changes that make a model change its decision. In this lesson, we build the attack math from scratch with NumPy: a toy differentiable classifier, cross-entropy gradients, FGSM, targeted attacks, PGD, and the geometry of epsilon-balls that defines which perturbations count.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build adversarial attacks one idea at a time. Run each cell in order and read the printed intermediate values — every piece of math is spelled out so the attack is not a magic trick. This walkthrough is self-contained and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays, linear algebra, and gradients from scratch.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
np.random.seed(0)  # reproducibility for toy data and any random starts.
```

### 1. A toy classifier with a visible decision boundary

We start with a binary linear classifier. The logit is $z=w^\top x+b$, the probability is $\sigma(z)$, and the predicted class is 1 when the probability is at least 0.5. This toy model is small enough that every score, boundary, and gradient can be inspected directly.

```python
w_w = np.array([2.0, -1.0])  # feature 0 pushes class 1 up; feature 1 pushes it down.
b_w = -0.2  # boundary offset.
x_w = np.array([0.55, 0.60])  # a clean input near the boundary.
y_w = 1.0  # true label.
def sigmoid_w(z):
    return 1.0 / (1.0 + np.exp(-z))
logit_w = float(w_w @ x_w + b_w)
prob_w = float(sigmoid_w(logit_w))
print("logit:", round(logit_w, 3), "prob class 1:", round(prob_w, 3), "pred:", int(prob_w >= 0.5))
assert round(logit_w, 3) == 0.300
```
▶ What you'll see: the clean point is correctly classified as class 1, but its probability is only about 0.574.

```python
grid_w = np.linspace(-0.1, 1.1, 80)
xx_w, yy_w = np.meshgrid(grid_w, grid_w)
zz_w = w_w[0] * xx_w + w_w[1] * yy_w + b_w
plt.figure(figsize=(4.5, 3.6))
plt.contourf(xx_w, yy_w, zz_w >= 0, levels=1, alpha=0.25, colors=["tomato", "seagreen"])
plt.contour(xx_w, yy_w, zz_w, levels=[0], colors="black")
plt.scatter([x_w[0]], [x_w[1]], s=80, color="navy", label="clean x")
plt.xlim(-0.1, 1.1); plt.ylim(-0.1, 1.1); plt.legend(); plt.title("1: clean point near a boundary"); plt.show()
```
▶ What you'll see: the clean point sits on the class-1 side but close enough that a small shove can cross the black line.

*Why it's done this way:* adversarial attacks are easiest to understand when the model score is differentiable and the boundary is visible. The boundary is $w^\top x+b=0$, so moving $x$ changes the score by $w^\top \delta$; that linear relationship lets us reason exactly about which perturbation directions are dangerous.

### 2. Loss gradients point toward higher error

For binary cross-entropy, $\ell(x,y)=-y\log p-(1-y)\log(1-p)$ with $p=\sigma(w^\top x+b)$. The derivative with respect to the logit is $p-y$, so the input gradient is $\nabla_x\ell=(p-y)w$. For a correctly classified positive point, $p-y<0$, so increasing loss moves opposite the class-1 weight direction.

```python
def loss_grad_w(x, y):
    z = float(w_w @ x + b_w)
    p = float(sigmoid_w(z))
    loss = -(y * np.log(p + 1e-12) + (1 - y) * np.log(1 - p + 1e-12))
    grad = (p - y) * w_w
    return loss, grad, p
loss0_w, grad0_w, prob0_w = loss_grad_w(x_w, y_w)
print("loss:", round(loss0_w, 3), "gradient:", np.round(grad0_w, 3))
assert np.allclose(np.round(grad0_w, 3), [-0.851, 0.426])
```
▶ What you'll see: the gradient has negative first coordinate and positive second coordinate — the local loss-increasing direction.

```python
step_w = 0.12 * grad0_w / np.linalg.norm(grad0_w)
x_step_w = x_w + step_w
loss_step_w, _, prob_step_w = loss_grad_w(x_step_w, y_w)
print("prob before/after:", round(prob0_w, 3), "→", round(prob_step_w, 3))
print("loss before/after:", round(loss0_w, 3), "→", round(loss_step_w, 3))
assert loss_step_w > loss0_w
plt.figure(figsize=(4.5, 3.6))
plt.contour(xx_w, yy_w, zz_w, levels=[0], colors="black")
plt.scatter([x_w[0]], [x_w[1]], color="navy", label="clean")
plt.arrow(x_w[0], x_w[1], step_w[0], step_w[1], head_width=0.025, color="crimson", length_includes_head=True)
plt.scatter([x_step_w[0]], [x_step_w[1]], color="crimson", label="higher loss")
plt.legend(); plt.title("2: gradient raises the loss"); plt.show()
```
▶ What you'll see: the arrow lowers the class-1 probability and raises cross-entropy.

*Why it's done this way:* the gradient is a first-order map of sensitivity: $\ell(x+\delta)\approx\ell(x)+\nabla_x\ell^\top\delta$. If we want the loss to rise as much as possible for a small step, we align $\delta$ with the gradient under the chosen norm constraint.

### 3. FGSM: one signed step inside an $\ell_\infty$ epsilon-ball

The Fast Gradient Sign Method uses $x_{adv}=x+\varepsilon\,\operatorname{sign}(\nabla_x\ell(x,y))$. Under an $\ell_\infty$ budget, every coordinate may move by at most $\varepsilon$, so the sign vector is the perturbation that maximizes the linearized loss increase.

```python
eps_w = 0.20
sign_w = np.sign(grad0_w)
delta_fgsm_w = eps_w * sign_w
x_fgsm_w = x_w + delta_fgsm_w
loss_fgsm_w, grad_fgsm_w, prob_fgsm_w = loss_grad_w(x_fgsm_w, y_w)
print("sign gradient:", sign_w, "delta:", delta_fgsm_w)
print("prob adv:", round(prob_fgsm_w, 3), "pred adv:", int(prob_fgsm_w >= 0.5))
assert np.max(np.abs(delta_fgsm_w)) == eps_w
```
▶ What you'll see: FGSM changes each feature by exactly ±0.2 and flips the prediction to class 0.

```python
plt.figure(figsize=(4.8, 3.7))
plt.contour(xx_w, yy_w, zz_w, levels=[0], colors="black")
plt.scatter([x_w[0]], [x_w[1]], color="navy", label="clean")
plt.scatter([x_fgsm_w[0]], [x_fgsm_w[1]], color="crimson", label="FGSM")
plt.plot([x_w[0], x_fgsm_w[0]], [x_w[1], x_fgsm_w[1]], color="crimson")
rect_w = plt.Rectangle((x_w[0]-eps_w, x_w[1]-eps_w), 2*eps_w, 2*eps_w, fill=False, ls="--", color="gray")
plt.gca().add_patch(rect_w)
plt.legend(); plt.title("3: FGSM within the L∞ box"); plt.show()
```
▶ What you'll see: the adversarial point lies at a corner of the dashed epsilon-box and across the boundary.

*Why it's done this way:* maximizing $g^\top\delta$ subject to $\|\delta\|_\infty\le\varepsilon$ separates by coordinate. Each coordinate chooses $\delta_j=\varepsilon\operatorname{sign}(g_j)$, so every allowed coordinate contributes the largest possible positive product $|g_j|\varepsilon$.

### 4. Targeted versus untargeted attacks

An untargeted attack increases the true-label loss: "make this not class 1." A targeted attack chooses a target label and decreases that target loss: "make this look like class 0." For binary cross-entropy, targeting class 0 means stepping opposite the gradient of $\ell(x,0)$.

```python
target_w = 0.0
loss_t_w, grad_t_w, prob_t_w = loss_grad_w(x_w, target_w)
delta_target_w = -eps_w * np.sign(grad_t_w)
x_target_w = x_w + delta_target_w
loss_after_target_w, _, prob_after_target_w = loss_grad_w(x_target_w, target_w)
print("target gradient:", np.round(grad_t_w, 3), "targeted delta:", delta_target_w)
print("class-1 prob after targeted attack:", round(prob_after_target_w, 3))
assert np.allclose(delta_target_w, delta_fgsm_w)
```
▶ What you'll see: for this binary case, targeting class 0 gives the same perturbation as untargeted FGSM from class 1.

```python
plt.figure(figsize=(4.5, 3))
plt.bar(["clean p(class1)", "targeted p(class1)"], [prob0_w, prob_after_target_w], color=["navy", "crimson"])
plt.axhline(0.5, color="black", ls="--")
plt.title("4: targeted attack lowers the target loss"); plt.ylabel("probability of class 1"); plt.show()
```
▶ What you'll see: the class-1 probability drops below the 0.5 decision threshold.

*Why it's done this way:* targeted optimization reverses the sign because it is minimizing a chosen target loss, not maximizing the true-label loss. In multiclass settings the two directions can differ sharply; the target label defines which wrong class the attack tries to enter.

### 5. PGD: repeated attack steps with projection

Projected Gradient Descent repeats small FGSM-like steps, then projects the result back into the allowed epsilon-ball. The projection is the threat-model guardrail: no matter how many steps we take, the final input must remain within $\|x_{adv}-x\|_\infty\le\varepsilon$.

```python
alpha_w = 0.05
x_pgd_w = x_w.copy()
path_w = [x_pgd_w.copy()]
for t_w in range(8):
    _, grad_w, _ = loss_grad_w(x_pgd_w, y_w)
    x_pgd_w = x_pgd_w + alpha_w * np.sign(grad_w)
    x_pgd_w = x_w + np.clip(x_pgd_w - x_w, -eps_w, eps_w)
    path_w.append(x_pgd_w.copy())
loss_pgd_w, _, prob_pgd_w = loss_grad_w(x_pgd_w, y_w)
print("PGD final:", np.round(x_pgd_w, 3), "prob:", round(prob_pgd_w, 3), "pred:", int(prob_pgd_w >= 0.5))
assert np.max(np.abs(x_pgd_w - x_w)) <= eps_w + 1e-12
```
▶ What you'll see: PGD reaches the same epsilon-box corner as FGSM for this linear model and flips the class.

```python
path_w = np.array(path_w)
plt.figure(figsize=(4.8, 3.7))
plt.contour(xx_w, yy_w, zz_w, levels=[0], colors="black")
plt.plot(path_w[:, 0], path_w[:, 1], marker="o", color="crimson", label="PGD path")
rect_w = plt.Rectangle((x_w[0]-eps_w, x_w[1]-eps_w), 2*eps_w, 2*eps_w, fill=False, ls="--", color="gray")
plt.gca().add_patch(rect_w)
plt.scatter([x_w[0]], [x_w[1]], color="navy", label="clean")
plt.legend(); plt.title("5: PGD steps plus projection"); plt.show()
```
▶ What you'll see: the path takes several small moves but never leaves the dashed epsilon-box.

*Why it's done this way:* FGSM trusts one local linearization. PGD keeps recomputing the gradient, which matters for nonlinear models, while projection enforces the mathematical definition of the attack budget instead of letting accumulated steps drift outside the allowed perturbation set.

## 🛠️ Setup

```python
import numpy as np  # Import NumPy for vectors, logits, gradients, projections, and assertions.
import matplotlib.pyplot as plt  # Import Matplotlib for boundaries, perturbations, and loss curves.
np.random.seed(0)  # Make every random toy example reproducible.

def sigmoid(z):
    return 1.0 / (1.0 + np.exp(-z))

def binary_loss_grad(x, y, w=np.array([2.0, -1.0]), b=-0.2):
    z = float(w @ x + b)
    p = float(sigmoid(z))
    loss = -(y * np.log(p + 1e-12) + (1 - y) * np.log(1 - p + 1e-12))
    grad = (p - y) * w
    return loss, grad, p

def predict01(x, w=np.array([2.0, -1.0]), b=-0.2):
    return int(sigmoid(float(w @ x + b)) >= 0.5)

def fgsm(x, y, eps, w=np.array([2.0, -1.0]), b=-0.2):
    _, grad, _ = binary_loss_grad(x, y, w, b)
    return x + eps * np.sign(grad)

def project_linf(x_adv, x0, eps):
    return x0 + np.clip(x_adv - x0, -eps, eps)
```

### Easy 2 — Sweep epsilon values

### Easy 3 — Targeted attack toward class 0

**Goal.** Implement targeted FGSM, because targeted attacks specify which wrong class the model should predict. We build it in 3 steps.

### Easy 4 — Run PGD for several steps

**Goal.** Build iterative FGSM with projection, because PGD is the standard stronger first-order baseline. We build it in 3 steps.

```python
x0_e4 = np.array([0.55, 0.60])
```

### Easy 5 — Compare $\ell_2$ and $\ell_\infty$ steepest steps

**Goal.** Contrast two norm budgets, because the threat model changes the optimal perturbation shape. We build it in 3 steps.

```python
x_e5 = np.array([0.55, 0.60])
y_e5 = 1.0
eps_e5 = 0.20
_, grad_e5, _ = binary_loss_grad(x_e5, y_e5)
print("grad_e5:", np.round(grad_e5, 3))
```
▶ What you'll see: the same gradient will produce different steps under different norms.

```python
delta_linf_e5 = eps_e5 * np.sign(grad_e5)
delta_l2_e5 = eps_e5 * grad_e5 / np.linalg.norm(grad_e5)
print("linf delta:", np.round(delta_linf_e5, 3), "l2 delta:", np.round(delta_l2_e5, 3))
assert round(float(np.linalg.norm(delta_l2_e5)), 3) == 0.200
```
▶ What you'll see: $\ell_\infty$ uses every coordinate at full magnitude, while $\ell_2$ follows the normalized gradient direction.

```python
plt.figure(figsize=(4, 3)); plt.scatter([0], [0], color="black"); plt.arrow(0, 0, delta_linf_e5[0], delta_linf_e5[1], head_width=0.015, color="red", label="L∞"); plt.arrow(0, 0, delta_l2_e5[0], delta_l2_e5[1], head_width=0.015, color="blue", label="L2"); plt.legend(); plt.title("Easy 5: norm changes step shape"); plt.axis("equal"); plt.show()
```
▶ What you'll see: the two perturbation arrows have different geometry even with the same epsilon number.

👀 Takeaway: robustness is always relative to a norm ball, not to epsilon alone.

### Advanced 2 — Random-start PGD inside the epsilon-ball

**Goal.** Add random starts to PGD, because nonlinear loss surfaces can hide stronger attacks from a single start. We build it in 4 steps.

### Advanced 5 — Adversarial training on toy data

**Goal.** Train a logistic model with FGSM examples included, because one common defense is to optimize for attacked inputs rather than clean inputs alone. We build it in 5 steps.

```python
X_a5 = np.array([[0.2, 0.1], [0.4, 0.2], [0.7, 0.4], [0.8, 0.5], [0.2, 0.7], [0.4, 0.8]])
y_a5 = np.array([1, 1, 1, 1, 0, 0], dtype=float)
w_clean_a5 = np.array([0.1, -0.1])
w_adv_a5 = np.array([0.1, -0.1])
b_clean_a5 = 0.0
b_adv_a5 = 0.0
print("toy training size_a5:", len(y_a5))
```
▶ What you'll see: the tiny dataset has positives with larger feature 0 and negatives with larger feature 1.

```python
for epoch_a5 in range(400):
    z_clean_a5 = X_a5 @ w_clean_a5 + b_clean_a5
    p_clean_a5 = sigmoid(z_clean_a5)
    gw_clean_a5 = X_a5.T @ (p_clean_a5 - y_a5) / len(y_a5)
    gb_clean_a5 = float(np.mean(p_clean_a5 - y_a5))
    w_clean_a5 -= 0.5 * gw_clean_a5
    b_clean_a5 -= 0.5 * gb_clean_a5
print("clean-trained w_a5:", np.round(w_clean_a5, 3))
```
▶ What you'll see: clean training learns a positive weight for feature 0 and a negative weight for feature 1.

```python
for epoch_adv_a5 in range(400):
    z_adv_a5 = X_a5 @ w_adv_a5 + b_adv_a5
    p_adv_train_a5 = sigmoid(z_adv_a5)
    grad_x_a5 = (p_adv_train_a5 - y_a5)[:, None] * w_adv_a5[None, :]
    X_fgsm_a5 = X_a5 + 0.08 * np.sign(grad_x_a5)
    X_mix_a5 = np.vstack([X_a5, X_fgsm_a5])
    y_mix_a5 = np.concatenate([y_a5, y_a5])
    p_mix_a5 = sigmoid(X_mix_a5 @ w_adv_a5 + b_adv_a5)
    gw_adv_a5 = X_mix_a5.T @ (p_mix_a5 - y_mix_a5) / len(y_mix_a5)
    gb_adv_a5 = float(np.mean(p_mix_a5 - y_mix_a5))
    w_adv_a5 -= 0.5 * gw_adv_a5
    b_adv_a5 -= 0.5 * gb_adv_a5
print("adv-trained w_a5:", np.round(w_adv_a5, 3))
```
▶ What you'll see: adversarial training learns from clean and perturbed copies at the same time.

```python

    grad_eval_a5 = (p0_eval_a5 - y_a5)[:, None] * w_eval_a5[None, :]

rob_clean_a5 = acc_under_fgsm_a5(w_clean_a5, b_clean_a5, 0.08)
```

▶ What you'll see: the adversarially trained model does at least as well under this matched toy attack.

```python

```
▶ What you'll see: training on attacked examples can improve robustness for the same threat model.
