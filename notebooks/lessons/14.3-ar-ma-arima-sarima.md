# 14.3 — AR, MA, ARIMA & SARIMA

ARIMA forecasts a single time series by combining four small ideas: values can remember previous values (AR), values can remember recent shocks (MA), unstable levels can become stable differences (I), and repeated seasonal structure can be modeled at a seasonal lag (SARIMA). In this lesson, you will build each piece from scratch with NumPy only, inspect the arithmetic behind the formulas, and forecast synthetic series without relying on statsmodels or any black-box time-series library.

Before the terse worked examples, we build AR, MA, ARIMA, and SARIMA one idea at a time. Run each cell in order and read the printed intermediate values — every piece of math is made visible, including Yule-Walker fitting and recursive forecasting. This walkthrough is self-contained and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays, random shocks, lag matrices, and linear algebra.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
```

### 1. Autoregressive memory: AR(1) as yesterday echoing into today

An autoregressive model predicts the current value from previous values. The smallest case is AR(1): $y_t=c+\phi y_{t-1}+\varepsilon_t$. If $|\phi|<1$, a one-time value fades geometrically; if $\phi$ is close to 1, the series has long memory. We first remove the shock term so the recursion itself is easy to see.

```python
phi_w = 0.6  # stable one-lag memory coefficient.
y_w = [2.0]  # start from y_0 = 2, matching the lesson arithmetic.
for t_w in range(4):  # recursively compute y_1 through y_4 without shocks.
    y_w.append(phi_w * y_w[-1])  # AR(1): next value is phi times the previous value.
y_w = np.array(y_w)  # convert the list to an array for printing and plotting.
print("AR(1) path:", np.round(y_w, 4))  # inspect geometric decay.
assert np.allclose(np.round(y_w[1:5], 4), [1.2, 0.72, 0.432, 0.2592])  # lesson numbers.
```
▶ What you'll see: the values `2.0 → 1.2 → 0.72 → 0.432 → 0.2592`, so each step keeps 60% of the last one.

```python
plt.figure(figsize=(4.4, 3))  # create a compact line plot for the deterministic AR path.
plt.plot(np.arange(len(y_w)), y_w, marker="o", color="teal")  # draw the decaying memory curve.
plt.axhline(0, color="black", linewidth=0.7)  # mark the long-run mean of this zero-intercept model.
plt.title("1: AR(1) memory decays geometrically")  # label the concept.
plt.xlabel("time t")  # label the time axis.
plt.ylabel("y_t")  # label the value axis.
plt.show()  # display the plot.
```
▶ What you'll see: a smooth exponential-like decay toward zero because the same multiplier is applied again and again.

*Why it's done this way:* AR uses lagged values as predictors, so the coefficient $\phi$ literally says how much of yesterday survives into today. Repeated substitution gives $y_t=\phi^t y_0$, which is why $|\phi|<1$ is the stability condition for AR(1): powers of a number smaller than one shrink instead of exploding.

### 2. Moving-average memory: MA(1) as recent shocks echoing briefly

A moving-average model remembers forecast errors, not past values. In MA(1), $y_t=\varepsilon_t+\theta\varepsilon_{t-1}$, so a shock affects the current point directly and the next point once through $\theta$, then disappears. This is finite shock memory, unlike the infinite geometric tail of AR.

```python
theta_w = 0.4  # one-lag shock-memory coefficient.
eps_w = np.array([1.0, -0.5, 0.2])  # fixed shocks from the lesson text.
y_ma_w = np.zeros_like(eps_w)  # allocate MA(1) output.
for t_w in range(len(eps_w)):  # compute one output per shock.
    prev_eps_w = eps_w[t_w - 1] if t_w > 0 else 0.0  # epsilon_{t-1}; zero before the series starts.
    y_ma_w[t_w] = eps_w[t_w] + theta_w * prev_eps_w  # MA(1) equation.
print("MA(1) output:", np.round(y_ma_w, 3))  # inspect shock-plus-lagged-shock values.
assert np.allclose(np.round(y_ma_w, 3), [1.0, -0.1, 0.0])  # lesson numbers.
```
▶ What you'll see: the output is `[1.0, -0.1, 0.0]`, because the previous shock is added once and then forgotten.

```python
plt.figure(figsize=(5, 3))  # create a compact contribution plot.
plt.bar(np.arange(len(eps_w)) - 0.18, eps_w, width=0.36, label="current shock ε_t", color="gray")  # direct shocks.
lagged_contrib_w = theta_w * np.r_[0.0, eps_w[:-1]]  # theta times previous shock.
plt.bar(np.arange(len(eps_w)) + 0.18, lagged_contrib_w, width=0.36, label="θ ε_{t-1}", color="orange")  # one-step echo.
plt.plot(np.arange(len(y_ma_w)), y_ma_w, marker="o", color="teal", label="MA output")  # total output.
plt.title("2: MA(1) remembers shocks for one step")  # label the concept.
plt.xlabel("time t")  # label time.
plt.legend()  # show contribution names.
plt.show()  # display the plot.
```
▶ What you'll see: each output point is the sum of the current gray bar and the previous-shock orange bar.

*Why it's done this way:* MA terms are built from innovations $\varepsilon_t$, the surprises left after forecasting. That makes them useful when residuals have short-lived autocorrelation: the model says, “if the last forecast was surprised upward, adjust the next forecast by $\theta$ times that surprise,” but do not keep propagating it forever.

### 3. Integration: differencing changes levels into increments

ARMA assumes the series being modeled has stable lag relationships. A trending level often violates that, so ARIMA first differences the series: $z_t=\Delta y_t=y_t-y_{t-1}$. The model is then fit to increments $z_t$, and forecasts of increments are accumulated back into level forecasts.

```python
levels_w = np.array([3.0, 4.0, 6.0, 9.0])  # nonstationary-looking level sequence.
diff_w = np.diff(levels_w)  # first difference: consecutive changes.
print("levels:", levels_w)  # inspect raw levels.
print("first differences:", diff_w)  # inspect increments.
assert np.allclose(diff_w, [1.0, 2.0, 3.0])  # lesson numbers.
```
▶ What you'll see: levels `[3,4,6,9]` become increments `[1,2,3]`.

```python
last_level_w = levels_w[-1]  # the latest observed level is the anchor for reintegration.
future_diffs_w = np.array([3.0, 3.0, 3.0])  # pretend an ARMA model forecasts three future increments.
level_forecast_w = last_level_w + np.cumsum(future_diffs_w)  # integrate differences back to levels.
print("forecasted increments:", future_diffs_w)  # inspect model output on differenced scale.
print("level forecasts:", level_forecast_w)  # inspect accumulated level predictions.
assert np.allclose(level_forecast_w, [12.0, 15.0, 18.0])  # 9 plus cumulative [3,6,9].
```
▶ What you'll see: the model forecasts changes, but users usually consume the reconstructed level path.

```python
plt.figure(figsize=(5, 3))  # create a before/after plot.
plt.plot(np.arange(len(levels_w)), levels_w, marker="o", label="levels y_t", color="teal")  # raw levels.
plt.plot(np.arange(1, len(levels_w)), diff_w, marker="s", label="differences Δy_t", color="purple")  # increments.
plt.title("3: differencing changes the target")  # label the concept.
plt.xlabel("time t")  # label time.
plt.legend()  # show both scales.
plt.show()  # display the plot.
```
▶ What you'll see: the differenced series is on a different scale and answers a different question: “how much did the level move?”

*Why it's done this way:* differencing is not cosmetic preprocessing. It changes the statistical target from $y_t$ to $\Delta y_t$, which can remove a drifting level and make ARMA assumptions more reasonable. The price is that forecasts must be summed back up, and unnecessary differencing can turn smooth signal into noisy increments.

### 4. Yule-Walker fitting: estimating AR coefficients from autocorrelation

For AR models, the Yule-Walker equations connect autocovariances to AR coefficients. For AR(2), the equations are $\Gamma\phi=\gamma$, where $\Gamma=\begin{bmatrix}\gamma_0&\gamma_1\\\gamma_1&\gamma_0\end{bmatrix}$ and $\gamma=[\gamma_1,\gamma_2]^\top$. Solving this small linear system estimates how much lags 1 and 2 matter.

```python
rng_w = np.random.default_rng(0)  # local reproducible generator.
phi_true_w = np.array([0.55, -0.20])  # stable AR(2) coefficients.
noise_w = 0.25 * rng_w.normal(size=220)  # white-noise innovations.
y_ar2_w = np.zeros(220)  # allocate the simulated series.
for t_w in range(2, len(y_ar2_w)):  # simulate from lag 2 onward.
    y_ar2_w[t_w] = phi_true_w[0] * y_ar2_w[t_w - 1] + phi_true_w[1] * y_ar2_w[t_w - 2] + noise_w[t_w]  # AR(2).
series_w = y_ar2_w[20:]  # drop the startup transient.
print("first simulated values:", np.round(series_w[:5], 3))  # inspect the synthetic AR(2) data.
```
▶ What you'll see: a noisy but mean-reverting series generated from known AR(2) coefficients.

```python
def autocov_w(x_w, lag_w):  # compute biased sample autocovariance at a chosen lag.
    x_w = np.asarray(x_w, dtype=float)  # ensure numeric array input.
    xc_w = x_w - np.mean(x_w)  # center before measuring covariance.
    return float(np.mean(xc_w[lag_w:] * xc_w[:len(xc_w) - lag_w]))  # average product at lag.

gamma_w = np.array([autocov_w(series_w, k_w) for k_w in range(3)])  # γ0, γ1, γ2.
Gamma_w = np.array([[gamma_w[0], gamma_w[1]], [gamma_w[1], gamma_w[0]]])  # Yule-Walker matrix for p=2.
rhs_w = gamma_w[1:]  # right side [γ1, γ2].
phi_hat_w = np.linalg.solve(Gamma_w, rhs_w)  # solve Γφ=γ.
print("autocovariances:", np.round(gamma_w, 4))  # inspect correlation ingredients.
print("Yule-Walker phi_hat:", np.round(phi_hat_w, 3))  # inspect fitted AR coefficients.
assert abs(phi_hat_w[0] - 0.55) < 0.2 and abs(phi_hat_w[1] + 0.20) < 0.2  # close to truth for this toy sample.
```
▶ What you'll see: the estimated coefficients land near the true `[0.55, -0.20]`, with sampling noise.

```python
plt.figure(figsize=(5, 3))  # create a coefficient comparison plot.
plt.bar(["φ1 true", "φ2 true", "φ1 fit", "φ2 fit"], [phi_true_w[0], phi_true_w[1], phi_hat_w[0], phi_hat_w[1]], color=["gray", "gray", "teal", "teal"])  # compare truth and estimate.
plt.axhline(0, color="black", linewidth=0.7)  # zero reference.
plt.title("4: Yule-Walker recovers AR memory")  # label the concept.
plt.show()  # display the plot.
```
▶ What you'll see: fitted bars are close to the true bars, showing that autocorrelation can estimate AR memory.

*Why it's done this way:* AR coefficients determine autocorrelation, so Yule-Walker runs that relationship backward. Instead of doing iterative optimization, it computes sample autocovariances and solves a linear system. This is why AR fitting can be explained with linear algebra: lagged self-covariances are the normal equations for predicting $y_t$ from its own lags.

### 5. ARIMA forecasting: model differences, then reintegrate forecasts

An ARIMA$(p,d,q)$ model fits ARMA to $z_t=\Delta^d y_t$. Here we build an ARIMA(1,1,0): difference once, fit an AR(1) to the differences with Yule-Walker, recursively forecast future differences, then cumulatively add them back to the last level.

```python
rng_w = np.random.default_rng(1)  # local reproducible generator for a trending series.
increments_w = np.zeros(90)  # allocate increments z_t.
increments_w[0] = 0.5  # initial increment.
for t_w in range(1, len(increments_w)):  # simulate AR(1) increments.
    increments_w[t_w] = 0.65 * increments_w[t_w - 1] + 0.15 * rng_w.normal()  # stationary changes.
level_w = 20 + np.cumsum(increments_w)  # integrate increments to a drifting level.
print("last level:", round(float(level_w[-1]), 3))  # inspect the anchor level.
print("last increment:", round(float(np.diff(level_w)[-1]), 3))  # inspect most recent change.
```
▶ What you'll see: the level drifts because it accumulates stationary increments.

```python
z_w = np.diff(level_w)  # first difference for ARIMA(1,1,0).
g0_w = autocov_w(z_w, 0)  # variance of differenced series.
g1_w = autocov_w(z_w, 1)  # lag-1 autocovariance.
phi_diff_w = g1_w / g0_w  # AR(1) Yule-Walker coefficient.
print("fitted AR coefficient on differences:", round(phi_diff_w, 3))  # inspect differenced-memory estimate.
assert 0.3 < phi_diff_w < 0.9  # should recover positive persistence in increments.
```
▶ What you'll see: a positive AR coefficient because increments were simulated with persistent changes.

```python
h_w = 8  # forecast horizon.
future_z_w = []  # store forecasted differences.
last_z_w = z_w[-1]  # start recursion at the latest observed difference.
for step_w in range(h_w):  # recursively forecast future increments.
    next_z_w = phi_diff_w * last_z_w  # AR(1) forecast has zero future shocks in expectation.
    future_z_w.append(next_z_w)  # save the predicted increment.
    last_z_w = next_z_w  # feed forecast back as the next lag.
future_z_w = np.array(future_z_w)  # convert to array.
forecast_level_w = level_w[-1] + np.cumsum(future_z_w)  # reintegrate to levels.
print("future differences:", np.round(future_z_w[:4], 3))  # inspect first few forecasts on z scale.
print("first level forecast:", round(float(forecast_level_w[0]), 3))  # inspect reconstructed level forecast.
```
▶ What you'll see: forecasted increments decay toward zero, so the level forecast gradually flattens.

```python
plt.figure(figsize=(5.4, 3))  # create a forecast plot.
plt.plot(np.arange(len(level_w)), level_w, label="observed level", color="teal")  # historical levels.
future_x_w = np.arange(len(level_w), len(level_w) + h_w)  # future time indexes.
plt.plot(future_x_w, forecast_level_w, marker="o", label="ARIMA(1,1,0) forecast", color="crimson")  # forecast levels.
plt.title("5: forecast differences, then add them back")  # label the concept.
plt.xlabel("time t")  # label time.
plt.legend()  # show observed and forecast series.
plt.show()  # display the forecast.
```
▶ What you'll see: the forecast continues from the last level and bends according to the predicted future increments.

*Why it's done this way:* the AR equation was fit on $\Delta y_t$ because that is the stationary object. But forecasts must be reported in the original unit, so we reverse differencing by cumulative summation. This separation prevents a trending level from tricking AR coefficients into pretending the raw level is stationary.

### 6. Seasonal memory: SARIMA uses differences and lags at period s

SARIMA adds the same ideas at a seasonal lag $s$. A seasonal difference $y_t-y_{t-s}$ removes a repeated pattern, and seasonal AR or MA terms let last season's residual affect this season. With a four-step season, the lesson's comparable seasonal difference is 0.4 after removing the repeated pattern.

```python
season_w = np.array([10.0, 12.0, 9.0, 11.0])  # one seasonal pattern of length 4.
trend_w = 0.1 * np.arange(12)  # slow drift across three seasons.
y_season_w = np.tile(season_w, 3) + trend_w  # repeated pattern plus drift.
s_w = 4  # seasonal period.
seasonal_diff_w = y_season_w[s_w:] - y_season_w[:-s_w]  # y_t - y_{t-s}.
print("first seasonal differences:", np.round(seasonal_diff_w[:4], 3))  # compare season 2 to season 1.
assert np.allclose(np.round(seasonal_diff_w[:4], 3), [0.4, 0.4, 0.4, 0.4])  # lesson seasonal-difference number.
```
▶ What you'll see: the seasonal difference is `0.4` at each comparable point because drift over four steps is constant.

```python
last_season_value_w = 10.5  # lesson's last comparable seasonal value.
last_season_resid_w = 0.2  # a recent seasonal residual or surprise.
season_phi_w = 0.5  # seasonal AR-style correction weight.
sarima_forecast_w = last_season_value_w + season_phi_w * last_season_resid_w  # seasonal naive plus residual correction.
print("SARIMA-style forecast:", round(sarima_forecast_w, 3))  # inspect worked seasonal forecast.
assert round(sarima_forecast_w, 3) == 10.6  # lesson number.
```
▶ What you'll see: the forecast is `10.600`, made from last season's value plus half of the last seasonal residual.

```python
plt.figure(figsize=(5.4, 3))  # create a seasonal plot.
plt.plot(np.arange(len(y_season_w)), y_season_w, marker="o", label="seasonal series", color="teal")  # raw seasonal levels.
plt.plot(np.arange(s_w, len(y_season_w)), seasonal_diff_w, marker="s", label="seasonal diff", color="purple")  # seasonal differences.
plt.title("6: seasonal differencing removes repeated shape")  # label the concept.
plt.xlabel("time t")  # label time.
plt.legend()  # identify curves.
plt.show()  # display the plot.
```
▶ What you'll see: the raw series repeats a four-step shape, while the seasonal differences collapse to a stable small value.

*Why it's done this way:* ordinary differencing removes adjacent movement; seasonal differencing removes “same position last season” movement. SARIMA is useful when dependence lives at lag $s$ as much as lag 1, such as month-over-month yearly patterns or day-of-week effects.

## 🛠️ Setup

```python
import numpy as np # load NumPy for arrays, simulation, lag features, Yule-Walker systems, and forecasts.
import matplotlib.pyplot as plt # load Matplotlib so each series, residual, and forecast can be inspected visually.
np.random.seed(0) # make random toy series reproducible across notebook runs.

def simulate_ar(phi, n, noise_scale=1.0, seed=0): # simulate an AR(p) process from scratch.
    phi = np.asarray(phi, dtype=float) # ensure coefficients are a float array.
    p = len(phi) # count AR lags.
    rng = np.random.default_rng(seed) # use a local generator so examples are reproducible.
    eps = noise_scale * rng.normal(size=n) # generate white-noise shocks.
    y = np.zeros(n) # allocate the output series.
    for t in range(p, n): # start once all lag values exist.
        y[t] = np.dot(phi, y[t - np.arange(1, p + 1)]) + eps[t] # AR(p): weighted lag sum plus shock.
    return y # return the simulated series.

def simulate_ma(theta, n, noise_scale=1.0, seed=0): # simulate an MA(q) process from scratch.
    theta = np.asarray(theta, dtype=float) # ensure coefficients are a float array.
    q = len(theta) # count MA shock lags.
    rng = np.random.default_rng(seed) # local reproducible generator.
    eps = noise_scale * rng.normal(size=n + q) # include warmup shocks for early lags.
    y = np.zeros(n) # allocate output.
    for t in range(n): # compute each MA output.
        y[t] = eps[t + q] + np.dot(theta, eps[t + q - np.arange(1, q + 1)]) # current shock plus weighted old shocks.
    return y, eps[q:] # return series and aligned current shocks.

def autocov(x, lag): # compute biased sample autocovariance at a lag.
    x = np.asarray(x, dtype=float) # ensure numeric input.
    xc = x - np.mean(x) # center before covariance.
    return float(np.mean(xc[lag:] * xc[:len(xc) - lag])) # average lagged products.

def yule_walker_fit(x, p): # estimate AR(p) coefficients with Yule-Walker equations.
    gammas = np.array([autocov(x, k) for k in range(p + 1)]) # compute gamma_0 through gamma_p.
    Gamma = np.array([[gammas[abs(i - j)] for j in range(p)] for i in range(p)]) # Toeplitz autocovariance matrix.
    rhs = gammas[1:p + 1] # right-hand side autocovariances.
    return np.linalg.solve(Gamma, rhs) # solve for AR coefficients.

def ar_forecast(history, phi, steps): # recursively forecast an AR model with future shocks set to zero.
    phi = np.asarray(phi, dtype=float) # ensure coefficient array.
    vals = list(np.asarray(history, dtype=float)) # mutable list of observed plus forecast values.
    p = len(phi) # number of lag terms.
    out = [] # store future forecasts.
    for _ in range(steps): # forecast one step at a time.
        pred = float(np.dot(phi, np.array(vals[-p:][::-1]))) # weighted newest p values.
        vals.append(pred) # append for recursive multi-step forecasting.
        out.append(pred) # save the prediction.
    return np.array(out) # return forecast vector.

def difference(x, d=1): # apply ordinary differencing d times.
    z = np.asarray(x, dtype=float) # ensure numeric array.
    for _ in range(d): # repeat differencing.
        z = np.diff(z) # one ordinary difference.
    return z # return differenced series.

def seasonal_difference(x, s): # compute y_t - y_{t-s}.
    x = np.asarray(x, dtype=float) # ensure numeric array.
    return x[s:] - x[:-s] # seasonal lag difference.
```

### Basic 1 — Simulate stable AR(1) memory

**Goal.** Build an AR(1) path with no random shocks, because autoregression is easiest to understand when it is only a recursion. We build it in 2 steps.

```python
phi_b1 = 0.6 # choose a stable AR(1) coefficient whose magnitude is below one.
y_b1 = [2.0] # start from the lesson's initial value y0 = 2.
for t_b1 in range(4): # compute four future deterministic steps.
    y_b1.append(phi_b1 * y_b1[-1]) # each value keeps 60 percent of the previous value.
y_b1 = np.array(y_b1) # convert to an array for vector operations.
print("path:", np.round(y_b1, 4)) # inspect the recursion values.
assert np.allclose(np.round(y_b1[1:], 4), [1.2, 0.72, 0.432, 0.2592]) # verify concrete lesson arithmetic.
```

```python
plt.figure(figsize=(4, 3)) # create a compact plot.
```

### Basic 3 — Compare stable and unstable AR coefficients

**Goal.** Contrast $|\phi|<1$ and $|\phi|>1$, because AR stability is a mathematical requirement, not a style preference. We build it in 2 steps.

```python
steps_b3 = 12 # choose a short deterministic horizon.
stable_b3 = [1.0] # start stable path at 1.
unstable_b3 = [1.0] # start unstable path at 1.
for t_b3 in range(steps_b3): # evolve both recursions.
    stable_b3.append(0.8 * stable_b3[-1]) # stable coefficient shrinks powers.
    unstable_b3.append(1.05 * unstable_b3[-1]) # unstable coefficient grows powers.
stable_b3 = np.array(stable_b3) # convert to arrays.
unstable_b3 = np.array(unstable_b3) # convert to arrays.
print("stable final:", round(float(stable_b3[-1]), 3), "unstable final:", round(float(unstable_b3[-1]), 3)) # compare endpoints.
assert stable_b3[-1] < stable_b3[0] and unstable_b3[-1] > unstable_b3[0] # verify decay versus growth.
```
▶ What you'll see: the stable path shrinks below 1, while the unstable path rises above 1.

```python
plt.figure(figsize=(5, 3)) # create comparison plot.
plt.plot(stable_b3, marker="o", label="φ=0.8 stable", color="teal") # plot stable recursion.
plt.plot(unstable_b3, marker="s", label="φ=1.05 unstable", color="crimson") # plot unstable recursion.
plt.title("Basic 3: coefficient magnitude controls stability") # title the plot.
plt.legend() # show labels.
plt.show() # display comparison.
```
▶ What you'll see: even a coefficient only slightly above 1 grows instead of settling.

👀 Takeaway: AR(1) is stationary only when the lag multiplier has magnitude below one.

### Basic 4 — Compute MA(1) by hand

**Goal.** Build MA(1) from fixed shocks, because moving-average terms are shock memory rather than value memory. We build it in 2 steps.


### Advanced 5 — Rolling-origin ARIMA evaluation against baselines

**Goal.** Compare ARIMA-style forecasts against naive and seasonal-naive baselines, because a small statistical model is only useful if it beats simple alternatives. We build it in 5 steps.

```python
rng_a5 = np.random.default_rng(505) # create reproducible generator.
s_a5 = 4 # use a short seasonal period.
pattern_a5 = np.array([10.0, 12.0, 9.0, 11.0]) # seasonal pattern.
noise_a5 = simulate_ar([0.5], n=100, noise_scale=0.2, seed=505) # persistent increment noise.
y_a5 = np.tile(pattern_a5, 25) + 0.05 * np.arange(100) + noise_a5 # seasonal drifting series.
train_end_a5 = 80 # first validation origin.
print("series length:", len(y_a5), "validation points:", len(y_a5) - train_end_a5) # inspect evaluation setup.
```
▶ What you'll see: the final 20 points are reserved for rolling-origin validation.

```python
pred_arima_a5 = [] # store ARIMA-style predictions.
pred_naive_a5 = [] # store last-value baseline predictions.
pred_season_a5 = [] # store seasonal-naive predictions.
truth_a5 = [] # store actual validation values.
for t_a5 in range(train_end_a5, len(y_a5)): # roll one step at a time.
    hist_a5 = y_a5[:t_a5] # history available at this origin.
    dy_a5 = difference(hist_a5, d=1) # ordinary differences for ARIMA(1,1,0).
    phi_a5 = yule_walker_fit(dy_a5, p=1) # fit AR(1) on available differences.
    next_diff_a5 = ar_forecast(dy_a5[-1:], phi_a5, steps=1)[0] # forecast next increment.
    pred_arima_a5.append(hist_a5[-1] + next_diff_a5) # reconstruct next level.
    pred_naive_a5.append(hist_a5[-1]) # naive forecast copies latest value.
    pred_season_a5.append(hist_a5[-s_a5]) # seasonal naive copies same season last cycle.
    truth_a5.append(y_a5[t_a5]) # actual next value.
print("made predictions:", len(truth_a5)) # verify validation count.
assert len(truth_a5) == 20 # verify rolling validation horizon.
```

```python
truth_a5 = np.array(truth_a5) # convert actuals to array.
pred_arima_a5 = np.array(pred_arima_a5) # convert ARIMA predictions.
pred_naive_a5 = np.array(pred_naive_a5) # convert naive predictions.
pred_season_a5 = np.array(pred_season_a5) # convert seasonal predictions.
rmse_arima_a5 = float(np.sqrt(np.mean((pred_arima_a5 - truth_a5) ** 2))) # ARIMA-style RMSE.
rmse_naive_a5 = float(np.sqrt(np.mean((pred_naive_a5 - truth_a5) ** 2))) # naive RMSE.
rmse_season_a5 = float(np.sqrt(np.mean((pred_season_a5 - truth_a5) ** 2))) # seasonal naive RMSE.
print("RMSE ARIMA/naive/seasonal:", round(rmse_arima_a5, 3), round(rmse_naive_a5, 3), round(rmse_season_a5, 3)) # inspect comparison.
assert min(rmse_arima_a5, rmse_naive_a5, rmse_season_a5) >= 0 # verify nonnegative errors.
```

```python
plt.figure(figsize=(5, 3)) # create RMSE comparison chart.
plt.bar(["ARIMA(1,1,0)", "naive", "seasonal naive"], [rmse_arima_a5, rmse_naive_a5, rmse_season_a5], color=["teal", "gray", "orange"]) # compare validation errors.
plt.title("Advanced 5: rolling-origin RMSE") # title plot.
plt.ylabel("RMSE lower is better") # label error scale.
plt.xticks(rotation=15) # rotate labels.
plt.show() # display comparison.
```
▶ What you'll see: the bar chart makes it obvious whether the ARIMA-style model earned its complexity.
