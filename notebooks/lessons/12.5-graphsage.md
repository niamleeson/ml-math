# 12.5 — GraphSAGE

GraphSAGE learns a reusable recipe for node embeddings: sample a node's neighbors, aggregate their features, concatenate that neighborhood summary with the node's own features, and apply shared weights. Unlike a transductive embedding table, this rule can run on nodes that were not present during training, which is why sampling and aggregation are central to scalable inductive graph learning.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build GraphSAGE one idea at a time. Run each cell in order and read the printed intermediate values — every piece of math, including sampling noise and inductive scoring, is made explicit. This walkthrough is self-contained and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays, matrix multiplies, and random neighbor sampling.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
np.random.seed(0)  # reproducibility for sampled neighborhoods.
```

### 1. A graph is features plus adjacency

GraphSAGE does not start with learned node IDs. It starts with node features `x_v` and an adjacency list that says which neighbors may send messages to each node. This matters because an inductive model must be able to embed a new node from its attributes and its local neighborhood, even if that node never had a row in a training embedding table.

```python
X_w = np.array([[1.0, 0.0],   # node 0: mostly feature axis 0
                [1.0, 1.0],   # node 1: high on both axes
                [0.0, 1.0],   # node 2: mostly feature axis 1
                [2.0, 0.0],   # node 3: strong axis 0
                [0.0, 0.5]])  # node 4: weak axis 1
neighbors_w = {0: [1, 2, 3], 1: [0, 2], 2: [0, 1, 4], 3: [0], 4: [2]}  # undirected toy graph.
print("feature matrix shape:", X_w.shape)  # 5 nodes by 2 features.
print("node 0 neighbors:", neighbors_w[0])  # inspect the local computation set.
```
▶ What you'll see: each node has a 2-D feature vector and node 0 has three neighbors: 1, 2, and 3.

```python
plt.figure(figsize=(4.4, 3.2))  # draw feature points, not a networkx graph.
plt.scatter(X_w[:, 0], X_w[:, 1], s=120, color="teal")  # node position = its feature vector.
for idx_w, xy_w in enumerate(X_w):  # label each point by node id.
    plt.text(xy_w[0] + 0.03, xy_w[1] + 0.03, str(idx_w))  # readable node labels.
plt.title("1: nodes as feature vectors"); plt.xlabel("feature 0"); plt.ylabel("feature 1")
plt.xlim(-0.2, 2.3); plt.ylim(-0.2, 1.3); plt.show()
```
▶ What you'll see: nodes live in feature space; the graph tells GraphSAGE which nearby rows to aggregate.

*Why it's done this way:* an embedding table would give node 0 a private parameter vector, but that parameter cannot exist for future nodes. GraphSAGE instead learns a function of `x_v` and neighbor features, so the same formula applies to old and new nodes.

### 2. Full-neighbor mean aggregation

The simplest GraphSAGE aggregator is the mean. For node 0, the full-neighbor summary is

$$\operatorname{AGG}\{x_u:u\in N(0)\}=\frac{x_1+x_2+x_3}{3}=[1.000,0.667].$$

The mean is permutation invariant: reordering neighbors does not change the sum, and dividing by the count keeps high-degree nodes from automatically having larger messages.

```python
nbrs0_w = neighbors_w[0]  # node 0's full neighborhood.
nbr_feats0_w = X_w[nbrs0_w]  # gather neighbor feature rows.
print("neighbor features for node 0:\n", nbr_feats0_w)  # inspect x_1, x_2, x_3.
```
▶ What you'll see: the three neighbor rows are `[1,1]`, `[0,1]`, and `[2,0]`.

```python
mean0_w = nbr_feats0_w.mean(axis=0)  # average each feature coordinate across neighbors.
print("full neighbor mean:", np.round(mean0_w, 3))  # [1.000, 0.667].
assert np.allclose(np.round(mean0_w, 3), [1.000, 0.667])  # self-check the lesson number.
```
▶ What you'll see: node 0's full neighborhood summary is exactly `[1.000, 0.667]`.

```python
plt.figure(figsize=(4.6, 3))  # compare raw neighbor rows to their average.
plt.bar(["feat0", "feat1"], mean0_w, color="seagreen")  # plot the aggregated vector.
plt.title("2: full-neighbor mean for node 0"); plt.ylabel("mean feature value"); plt.ylim(0, 1.2)
plt.show()
```
▶ What you'll see: feature 0 averages to 1, while feature 1 averages to two-thirds.

*Why it's done this way:* averaging is the smallest permutation-invariant statistic that preserves feature scale. The denominator is not cosmetic: without it, a node with 100 neighbors would receive a much larger message than a node with 2 neighbors even if their neighbor distributions were identical.

### 3. Neighbor sampling makes computation fixed-size

Full aggregation is expensive when a node has thousands or millions of neighbors. GraphSAGE samples a fixed fanout, such as 2 neighbors per node, and treats the sampled mean as an estimator of the full mean. Sampling neighbors 2 and 3 for node 0 gives `[1.000, 0.500]`, close to but not identical to the full mean.

```python
sample0_w = np.array([2, 3])  # a deterministic fanout-2 sample from N(0).
sampled_feats0_w = X_w[sample0_w]  # gather only the sampled neighbors.
sampled_mean0_w = sampled_feats0_w.mean(axis=0)  # aggregate the sample.
print("sampled neighbors:", sample0_w)  # inspect which neighbors were kept.
print("sampled mean:", np.round(sampled_mean0_w, 3))  # [1.000, 0.500].
assert np.allclose(np.round(sampled_mean0_w, 3), [1.000, 0.500])  # self-check the lesson number.
```
▶ What you'll see: using neighbors 2 and 3 produces a sampled mean of `[1.000, 0.500]`.

```python
plt.figure(figsize=(4.6, 3))  # compare exact and sampled aggregation.
plt.bar(np.arange(2) - 0.18, mean0_w, width=0.36, label="full", color="gray")  # exact mean.
plt.bar(np.arange(2) + 0.18, sampled_mean0_w, width=0.36, label="sampled", color="orange")  # sampled estimate.
plt.xticks([0, 1], ["feat0", "feat1"]); plt.ylim(0, 1.2); plt.legend()
plt.title("3: sampled mean approximates full mean"); plt.show()
```
▶ What you'll see: feature 1 is lower in the sample because neighbor 2 was not selected.

*Why it's done this way:* sampling trades bias-free estimation noise for bounded work. If every layer samples exactly `S` neighbors, the layer has predictable memory and time cost; the price is variance because different samples give slightly different means.

### 4. Concatenate self features with the neighborhood summary

GraphSAGE keeps the target node's own features separate from the neighbor aggregate. For node 0, concatenating self `[1,0]` with the full mean `[1,0.667]` gives `[1,0,1,0.667]`. This is essential: a node should not lose its own attributes just because its neighbors have different attributes.

```python
self0_w = X_w[0]  # node 0's own feature vector.
concat0_w = np.concatenate([self0_w, mean0_w])  # [x_v || AGG(N(v))].
print("self features:", self0_w)  # x_0.
print("concatenated vector:", np.round(concat0_w, 3))  # [1,0,1,0.667].
assert np.allclose(np.round(concat0_w, 3), [1.000, 0.000, 1.000, 0.667])  # self-check.
```
▶ What you'll see: the model input has four coordinates: two self coordinates followed by two neighborhood coordinates.

```python
plt.figure(figsize=(5, 3))  # show the two parts of the concatenated input.
plt.bar(["self0", "self1", "nbr0", "nbr1"], concat0_w, color=["teal", "teal", "seagreen", "seagreen"])
plt.title("4: GraphSAGE concatenates self and neighborhood"); plt.ylabel("value"); plt.show()
```
▶ What you'll see: self and neighbor information are visible as separate blocks.

*Why it's done this way:* if we averaged the self node together with its neighbors, two nodes with different personal features could collapse to the same vector. Concatenation lets the weight matrix learn different roles: one set of weights for the node itself and another for social or structural context.

### 5. Shared weights turn the recipe into an embedding

After concatenation, GraphSAGE applies the same weight matrix to every node:

$$h_v=\sigma\left(W[x_v\|\operatorname{AGG}(N(v))]\right).$$

Here `σ` is a simple ReLU. Shared weights are what make the layer inductive: the parameters do not depend on the node ID, only on the recipe.

```python
W_w = np.array([[0.8, -0.2, 0.5, 0.3],   # embedding coordinate 0 weights.
                [-0.1, 0.7, 0.2, 0.6]])  # embedding coordinate 1 weights.
pre0_w = W_w @ concat0_w  # linear transformation before nonlinearity.
h0_w = np.maximum(0, pre0_w)  # ReLU activation.
print("pre-activation:", np.round(pre0_w, 3))  # inspect W times concatenated input.
print("embedding h0:", np.round(h0_w, 3))  # final GraphSAGE embedding.
assert np.allclose(np.round(h0_w, 3), [1.500, 0.500])  # concrete numeric check.
```
▶ What you'll see: node 0 receives embedding `[1.500, 0.600]` from one shared GraphSAGE layer.

```python
plt.figure(figsize=(4.2, 3))  # compare before and after ReLU.
plt.bar(["coord0", "coord1"], h0_w, color="purple")  # final embedding coordinates.
plt.title("5: one GraphSAGE embedding"); plt.ylabel("activation"); plt.show()
```
▶ What you'll see: both coordinates are positive here, so ReLU leaves the linear values unchanged.

*Why it's done this way:* the learned matrix decides how much self and neighbor evidence matter for each embedding coordinate. Reusing the same `W` for all nodes is the mathematical reason the layer generalizes beyond the training node set.

### 6. Mean versus pooling aggregators

Mean aggregation can hide multiplicity and extremes. A pooling aggregator first transforms each neighbor and then takes a coordinatewise max. Max-pooling can preserve whether any neighbor strongly expresses a feature, even when the average is modest.

```python
A_pool_w = np.array([[1.0, -0.5],   # transform neighbor features before pooling.
                     [0.3,  1.2]])
trans_nbrs0_w = np.maximum(0, nbr_feats0_w @ A_pool_w.T)  # ReLU transform for each neighbor.
pool0_w = trans_nbrs0_w.max(axis=0)  # coordinatewise max across neighbors.
print("transformed neighbors:\n", np.round(trans_nbrs0_w, 3))  # inspect hidden neighbor states.
print("pool aggregate:", np.round(pool0_w, 3))  # max over neighbors.
assert np.allclose(np.round(pool0_w, 3), [2.000, 1.500])  # concrete numeric check.
```
▶ What you'll see: one strong neighbor can set a pooled coordinate even if other neighbors are small.

```python
plt.figure(figsize=(4.6, 3))  # compare mean and pool summaries on different scales.
plt.bar(["mean0", "mean1", "pool0", "pool1"], np.r_[mean0_w, pool0_w], color=["seagreen", "seagreen", "darkorange", "darkorange"])
plt.title("6: mean summary vs pooled summary"); plt.ylabel("aggregate value"); plt.show()
```
▶ What you'll see: pooling highlights the strongest transformed neighbor response instead of the average neighbor response.

*Why it's done this way:* mean aggregation estimates the center of a neighborhood distribution; pooling estimates whether a learned pattern appears at least once. They answer different questions, which is why aggregator choice changes what structural information survives.

### 7. Inductive embedding for a new node

Now add a node that was not in the original feature matrix. If the new node has feature `[0.5,0.5]` and neighbors 0 and 2, the neighbor mean is `([1,0]+[0,1])/2=[0.5,0.5]`, so the concatenated input is `[0.5,0.5,0.5,0.5]`. The same `W` embeds it without adding a new parameter row.

```python
x_new_w = np.array([0.5, 0.5])  # features for a node unseen during training.
new_neighbors_w = np.array([0, 2])  # existing graph neighbors for the new node.
new_mean_w = X_w[new_neighbors_w].mean(axis=0)  # aggregate existing neighbor features.
new_concat_w = np.concatenate([x_new_w, new_mean_w])  # GraphSAGE input for the new node.
print("new node concatenated input:", np.round(new_concat_w, 3))  # [0.5,0.5,0.5,0.5].
assert np.allclose(np.round(new_concat_w, 3), [0.500, 0.500, 0.500, 0.500])  # self-check.
```
▶ What you'll see: the new node has a valid four-coordinate layer input even though it never had an embedding ID.

```python
h_new_w = np.maximum(0, W_w @ new_concat_w)  # reuse the same shared weights.
print("new node embedding:", np.round(h_new_w, 3))  # inductive output.
plt.figure(figsize=(4.4, 3))  # compare old and new node embeddings.
plt.scatter([h0_w[0], h_new_w[0]], [h0_w[1], h_new_w[1]], s=120, color=["purple", "crimson"])
plt.text(h0_w[0] + 0.03, h0_w[1], "old node 0"); plt.text(h_new_w[0] + 0.03, h_new_w[1], "new node")
plt.title("7: same function embeds a new node"); plt.xlabel("h0"); plt.ylabel("h1"); plt.show()
```
▶ What you'll see: the new node lands in the same embedding space as the old nodes.

*Why it's done this way:* induction means the model learned `f(features, sampled neighbors)`, not a lookup table. New nodes only need features and links to be embedded; no retraining is required for the existence of the node itself.

### 8. Sampling variance falls as fanout grows

A sampled mean is random. With fanout 1, node 0's estimate could be any one neighbor's feature; with fanout 3, it is the full mean every time in this toy graph. Repeating the sampling experiment shows the estimator's variance shrinking as sample size increases.

```python
rng_w = np.random.default_rng(0)  # local generator for repeatable sampling trials.
fanouts_w = np.array([1, 2, 3])  # compare small to full fanout.
var_by_fanout_w = []  # store total variance of sampled mean coordinates.
for fanout_w in fanouts_w:  # run one Monte Carlo experiment per fanout.
    estimates_w = []  # sampled means for this fanout.
    for _ in range(300):  # enough trials to see variance clearly.
        draw_w = rng_w.choice(nbrs0_w, size=fanout_w, replace=False)  # sample without replacement.
        estimates_w.append(X_w[draw_w].mean(axis=0))  # mean feature estimate.
    estimates_w = np.array(estimates_w)  # convert list to array for variance.
    var_by_fanout_w.append(float(estimates_w.var(axis=0).sum()))  # total coordinate variance.
print("variance by fanout:", np.round(var_by_fanout_w, 4))  # should decrease.
assert var_by_fanout_w[0] > var_by_fanout_w[1] > var_by_fanout_w[2] - 1e-12  # variance falls.
```
▶ What you'll see: fanout 1 has the noisiest estimates, fanout 2 is quieter, and fanout 3 has zero variance here.

```python
plt.figure(figsize=(4.6, 3))  # visualize fanout versus variance.
plt.plot(fanouts_w, var_by_fanout_w, marker="o", color="crimson")  # variance curve.
plt.xticks(fanouts_w); plt.xlabel("sample fanout"); plt.ylabel("total variance")
plt.title("8: larger fanout reduces sampling noise"); plt.show()
```
▶ What you'll see: the curve drops as fanout approaches the full neighborhood.

*Why it's done this way:* sampling is a Monte Carlo estimate of the full neighborhood statistic. Larger samples average out neighbor-to-neighbor variation, but they also increase computation, so fanout is a variance-cost knob.

### ✍️ Toy 1 · Features plus neighbors define the local inputs

GraphSAGE starts from node feature rows and a neighbor list. The target node keeps its own row while the graph tells us which other rows may be aggregated.

```python
import numpy as np
import matplotlib.pyplot as plt

t1_rng = np.random.default_rng(0)  # -> seeded RNG for repeatability

t1_X = np.array([[2.0, 0.0], [0.0, 1.0], [1.0, 1.0], [0.0, 2.0]])  # -> 4 nodes, 2 features
t1_neighbors = np.array([1, 2])  # -> node 0 listens to nodes 1 and 2
t1_self = t1_X[0]  # -> [2.0, 0.0]
t1_neighbor_rows = t1_X[t1_neighbors]  # -> [[0.0, 1.0], [1.0, 1.0]]
print("feature matrix:", t1_X.tolist())  # -> feature matrix: [[2.0, 0.0], [0.0, 1.0], [1.0, 1.0], [0.0, 2.0]]
print("node 0 self row:", t1_self.tolist())  # -> node 0 self row: [2.0, 0.0]
print("node 0 neighbor ids:", t1_neighbors.tolist())  # -> node 0 neighbor ids: [1, 2]

assert t1_neighbor_rows.shape == (2, 2)

plt.figure(figsize=(4.6, 3.0))
plt.scatter(t1_X[:, 0], t1_X[:, 1], s=130, color="lightgray")
plt.scatter(t1_self[0], t1_self[1], s=150, color="crimson", label="target 0")

plt.xlabel("feature 0")
plt.ylabel("feature 1")
plt.legend()
plt.show()
```
▶ What you'll see: node 0 is highlighted separately from the two feature rows that its neighbor list selects.

### ✍️ Toy 2 · Full-neighbor mean aggregation

The mean aggregator sums every neighbor row and divides by the neighbor count, giving a fixed-size summary no matter how many neighbors the node has.

```python
import numpy as np

t2_rng = np.random.default_rng(0)  # -> seeded RNG for repeatability

t2_X = np.array([[0.0, 0.0], [2.0, 0.0], [0.0, 3.0], [2.0, 1.0]])  # -> 4 nodes, 2 features
t2_neighbors = np.array([1, 2, 3])  # -> three neighbors for node 0
t2_rows = t2_X[t2_neighbors]  # -> [[2.0, 0.0], [0.0, 3.0], [2.0, 1.0]]
t2_sum = t2_rows.sum(axis=0)  # -> [4.0, 4.0]
t2_count = t2_rows.shape[0]  # -> 3
t2_mean = t2_sum / t2_count  # -> [1.3333333333333333, 1.3333333333333333]
print("neighbor rows:", t2_rows.tolist())  # -> neighbor rows: [[2.0, 0.0], [0.0, 3.0], [2.0, 1.0]]
print("neighbor sum:", t2_sum.tolist())  # -> neighbor sum: [4.0, 4.0]
print("neighbor count:", int(t2_count))  # -> neighbor count: 3
print("neighbor mean:", np.round(t2_mean, 4).tolist())  # -> neighbor mean: [1.3333, 1.3333]
assert np.allclose(t2_mean, [4.0 / 3.0, 4.0 / 3.0])

plt.figure(figsize=(4.2, 3.0))
plt.bar(["feat 0", "feat 1"], t2_mean, color="seagreen")
plt.ylim(0, 1.6)
plt.title("Toy 2 · mean neighbor summary")
plt.ylabel("average value")
plt.show()
```
▶ What you'll see: both feature coordinates average to `1.3333` after dividing the neighbor sum by three.

### ✍️ Toy 3 · Fixed fanout samples approximate the full mean

Sampling a fixed fanout bounds the work. The sampled mean is still a neighborhood statistic, but it can differ from the exact full-neighbor mean.

```python
import numpy as np

t3_rng = np.random.default_rng(0)  # -> seeded RNG for repeatability

t3_neighbors = np.array([1, 2, 3, 4])  # -> four available neighbors

print("full neighbor ids:", t3_neighbors.tolist())  # -> full neighbor ids: [1, 2, 3, 4]

assert np.array_equal(t3_sampled_nodes, np.array([3, 4]))
```

### ✍️ Toy 4 · Concatenate self and neighborhood summaries

```python
import numpy as np

t4_rng = np.random.default_rng(0)  # -> seeded RNG for repeatability
```

### ✍️ Toy 5 · Shared weights plus ReLU produce an embedding

The same weight matrix can transform any concatenated GraphSAGE input. ReLU then clips negative coordinates to zero.

```python
import numpy as np

t5_rng = np.random.default_rng(0)  # -> seeded RNG for repeatability

t5_X = np.array([[1.0, 2.0], [2.0, 0.0], [0.0, 2.0]])  # -> 3 nodes, 2 features
t5_neighbors = np.array([1, 2])  # -> node 0 has two neighbors
t5_self = t5_X[0]  # -> [1.0, 2.0]
t5_neighbor_mean = t5_X[t5_neighbors].mean(axis=0)  # -> [1.0, 1.0]
t5_concat = np.concatenate([t5_self, t5_neighbor_mean])  # -> [1.0, 2.0, 1.0, 1.0]
t5_W = np.array([[1.0, -1.0, 0.5, 0.0], [-0.5, 0.5, 1.0, 1.0]])  # -> 2 output coordinates
t5_pre = t5_W @ t5_concat  # -> [-0.5, 2.5]
t5_h = np.maximum(0.0, t5_pre)  # -> [0.0, 2.5]
print("concatenated input:", t5_concat.tolist())  # -> concatenated input: [1.0, 2.0, 1.0, 1.0]
print("weight matrix:", t5_W.tolist())  # -> weight matrix: [[1.0, -1.0, 0.5, 0.0], [-0.5, 0.5, 1.0, 1.0]]
print("pre-activation:", t5_pre.tolist())  # -> pre-activation: [-0.5, 2.5]
print("ReLU embedding:", t5_h.tolist())  # -> ReLU embedding: [0.0, 2.5]
assert np.allclose(t5_h, [0.0, 2.5])

plt.figure(figsize=(4.4, 3.0))
plt.bar(["pre 0", "pre 1"], t5_pre, color="lightgray", label="linear")
plt.bar(["h 0", "h 1"], t5_h, color="purple", label="ReLU")
plt.axhline(0.0, color="black", linewidth=0.8)
```

### ✍️ Toy 8 · Larger fanout lowers sampling variance

**Goal.** Compare full expansion and sampled expansion over two hops, because production GraphSAGE uses sampling to keep batches tractable. We build it in 5 steps.

```python
neighbors_a5 = {0: [1, 2, 3, 4], 1: [0, 2, 5, 6], 2: [0, 1, 7, 8], 3: [0, 9], 4: [0, 10],
                5: [1], 6: [1], 7: [2], 8: [2], 9: [3], 10: [4]}  # toy graph with expanding neighborhoods.
roots_a5 = np.array([0, 1])  # target mini-batch.
print("root batch:", roots_a5)  # inspect starting nodes.
```
▶ What you'll see: two root nodes will be expanded for a two-layer computation graph.

```python
def expand_a5(frontier, fanout=None):  # expand one hop from a frontier.
    out = []  # collect neighbor ids.
    for node in frontier:  # loop over frontier nodes.
        ids = np.array(neighbors_a5[int(node)])  # get all neighbors.
        if fanout is not None:  # if sampling is requested.
            ids = ids[:min(fanout, len(ids))]  # deterministic first-k sample.
        out.extend(ids.tolist())  # add selected neighbors.
    return np.unique(out)  # remove duplicates.
full1_a5 = expand_a5(roots_a5, fanout=None)  # full one-hop expansion.
full2_a5 = expand_a5(full1_a5, fanout=None)  # full two-hop expansion.
print("full hop sizes:", len(full1_a5), len(full2_a5))  # inspect unsampled growth.
```

```python
samp1_a5 = expand_a5(roots_a5, fanout=2)  # sampled one-hop expansion.
samp2_a5 = expand_a5(samp1_a5, fanout=2)  # sampled two-hop expansion.
full_needed_a5 = np.unique(np.r_[roots_a5, full1_a5, full2_a5])  # all nodes needed without sampling.
samp_needed_a5 = np.unique(np.r_[roots_a5, samp1_a5, samp2_a5])  # all nodes needed with sampling.
print("sampled hop sizes:", len(samp1_a5), len(samp2_a5))  # inspect sampled growth.
print("needed full vs sampled:", len(full_needed_a5), len(samp_needed_a5))  # compare feature reads.
assert len(samp_needed_a5) <= len(full_needed_a5)  # verify sampling does not increase this compute graph.
```

```python
reduction_a5 = 1 - len(samp_needed_a5) / len(full_needed_a5)  # compute relative feature-read reduction.
print("feature-read reduction:", round(reduction_a5, 3))  # inspect scaling benefit.
```

```python
plt.figure(figsize=(5, 3))  # create a compute-growth plot.
plt.bar(["full needed", "sampled needed"], [len(full_needed_a5), len(samp_needed_a5)], color=["gray", "seagreen"])  # compare node counts.
plt.title("Advanced 5: sampling bounds batch expansion")  # title the plot.
plt.ylabel("unique nodes loaded")  # label computation proxy.
plt.show()  # display the comparison.
```
▶ What you'll see: sampled expansion loads fewer unique nodes than full two-hop expansion.

👀 Takeaway: neighbor sampling is the systems reason GraphSAGE can train on large graphs.
