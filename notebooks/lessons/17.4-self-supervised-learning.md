# 17.4 — Self-Supervised Learning

Self-supervised learning (SSL) trains an encoder without human labels by creating supervision from the input itself: predict a hidden part, match two augmented views, or preserve useful variation while ignoring nuisance changes. In this lesson, every example is built from NumPy arrays so the central question stays visible: does the pretext task force the representation to learn structure the later task will need, or can it win by a shortcut?

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build self-supervised learning one idea at a time. Run each cell in order and read the printed intermediate values — the pretext labels, similarities, losses, and collapse checks are all shown directly. This walkthrough is self-contained (it imports what it needs) and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays, linear algebra, and synthetic unlabeled data.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
np.random.seed(0)  # reproducibility for noise, views, and toy training loops.
```

### 1. Pretext labels come from the input itself

Self-supervision starts by inventing a task whose target is already inside the data. Here the unlabeled input is a scalar `x`; the hidden target is the line value `y = 0.7x + 0.2`. No human typed a label, but solving the task still requires discovering the line structure rather than memorizing an ID.

```python
x_w = np.array([-1.0, 0.0, 1.0])  # three unlabeled coordinates.
y_w = 0.7 * x_w + 0.2  # self-generated target from the input structure.
y_hat_w = 0.7 * x_w + 0.2  # a perfect pretext predictor for the hidden coordinate.
print("x:", x_w)  # inspect the inputs.
print("pretext target y:", np.round(y_w, 3))  # inspect generated labels.
print("squared errors:", np.round((y_w - y_hat_w) ** 2, 3))  # verify perfect recovery.
assert np.allclose(y_w, [-0.5, 0.2, 0.9])  # matches the lesson's worked numbers.
```
▶ What you'll see: the generated targets are `[-0.5, 0.2, 0.9]`, and the perfect pretext predictor has zero error.

```python
plt.figure(figsize=(4.2, 3.2))  # create a compact line plot.
plt.scatter(x_w, y_w, s=80, color="teal", label="self-made targets")  # plot generated targets.
plt.plot(x_w, y_hat_w, color="black", label="0.7x + 0.2")  # plot the recovered rule.
plt.title("1: a pretext task recovers structure")  # title the plot.
plt.xlabel("input x"); plt.ylabel("hidden y")  # label axes.
plt.legend(); plt.show()  # render the figure.
```
▶ What you'll see: all three generated labels sit exactly on the line, so the task rewards learning the shared rule.

*Why it's done this way:* the SSL objective has the form $m^{-1}\sum_i \ell(g_\theta(a(x_i)), t(x_i))$: an augmentation or masking function `a` hides part of `x`, a target function `t` extracts the answer from `x`, and the model must recover it. The task is useful only when the easiest solution is the same structure the later task needs; otherwise the model learns the shortcut instead.

### 2. Two views define what should stay invariant

A view is a corrupted or augmented copy of the same example. If two views of one point should map close together, the augmentation defines an invariance: here small coordinate noise should not change the identity of the underlying point, but changing the sign or swapping clusters would be too strong.

```python
base_w = np.array([[-1.0, 0.0], [-0.8, 0.2], [0.9, -0.1], [1.1, 0.1]])  # four unlabeled points in two clusters.
noise_w = np.array([[0.05, -0.02], [-0.03, 0.04], [0.02, 0.03], [-0.04, -0.02]])  # small view noise.
view1_w = base_w + noise_w  # first augmented view.
view2_w = base_w - noise_w  # second augmented view of the same examples.
print("view gap norms:", np.round(np.linalg.norm(view1_w - view2_w, axis=1), 3))  # positive-pair distances.
assert np.all(np.linalg.norm(view1_w - view2_w, axis=1) < 0.12)  # mild views stay nearby.
```
▶ What you'll see: each pair of views is close in Euclidean distance because the augmentation is mild.

```python
plt.figure(figsize=(4.4, 3.4))  # create a paired-view plot.
plt.scatter(view1_w[:, 0], view1_w[:, 1], color="steelblue", label="view 1")  # first views.
plt.scatter(view2_w[:, 0], view2_w[:, 1], color="darkorange", marker="^", label="view 2")  # second views.
for i_w in range(len(base_w)):  # draw links between positives.
    plt.plot([view1_w[i_w, 0], view2_w[i_w, 0]], [view1_w[i_w, 1], view2_w[i_w, 1]], color="gray", linewidth=1)  # positive link.
plt.title("2: two views of each example"); plt.legend(); plt.show()  # display.
```
▶ What you'll see: each blue point is tied to its orange counterpart; these links say what the encoder should treat as the same.

*Why it's done this way:* augmentations are not decoration; they are assumptions. Pulling two views together removes information that changes between the views and preserves information that remains shared. If the augmentation deletes task-relevant signal, SSL faithfully learns the wrong invariance.

### 3. Contrastive SSL uses positives and negatives

Contrastive learning, as in SimCLR, says a view should be close to its paired view and far from other examples in the same batch. The InfoNCE loss is a softmax classification problem: among all candidate keys, the positive key should receive the highest probability.

```python
def normalize_w(Z_w):  # row-normalize feature vectors for cosine similarity.
    return Z_w / np.maximum(np.linalg.norm(Z_w, axis=1, keepdims=True), 1e-12)  # safe division.

z1_w = normalize_w(view1_w)  # encode view 1 with identity features, then normalize.
z2_w = normalize_w(view2_w)  # encode view 2 similarly.
sims_w = z1_w @ z2_w.T  # cosine similarities between every query and every key.
print("similarity matrix:\n", np.round(sims_w, 3))  # diagonal should be the positives.
```
▶ What you'll see: diagonal entries are positive pairs; off-diagonal entries are negatives, some easy and some hard.

```python
tau_w = 0.5  # temperature controls softmax sharpness.
logits_w = sims_w[0] / tau_w  # compare query 0 to all keys.
exp_w = np.exp(logits_w - np.max(logits_w))  # stable exponentials.
prob_w = exp_w / exp_w.sum()  # softmax probabilities over candidates.
loss0_w = -np.log(prob_w[0])  # positive for query 0 is key 0.
print("query-0 probabilities:", np.round(prob_w, 3))  # probability assigned to each key.
print("InfoNCE loss for query 0:", round(float(loss0_w), 3))  # inspect loss.
assert int(np.argmax(prob_w)) == 0  # the positive wins for this toy query.
```
▶ What you'll see: the positive key receives the largest probability, so the loss is small but not zero.

```python
plt.figure(figsize=(4.2, 3.2))  # create a heatmap.
plt.imshow(sims_w, cmap="coolwarm", vmin=-1, vmax=1)  # visualize cosine similarities.
plt.colorbar(label="cosine")  # show numeric scale.
plt.title("3: contrastive similarities")  # title.
plt.xlabel("keys (view 2)"); plt.ylabel("queries (view 1)")  # labels.
plt.show()  # display heatmap.
```
▶ What you'll see: strong diagonal structure means positives are more similar than most negatives.

*Why it's done this way:* the denominator is the comparison set. A high positive score alone is not enough; it must be high relative to alternatives, otherwise all examples could share the same feature. Negatives preserve distinctions while positives define invariance, and the temperature decides how harshly the softmax punishes close competitors.

### 4. Collapse is the failure mode where every representation is the same

A representation collapses when all examples map to one vector. Then positive pairs match perfectly, but nothing distinguishes different inputs. Contrastive negatives prevent this because a collapsed feature gives every candidate the same similarity and therefore cannot identify the positive.

```python
collapsed_w = np.ones((4, 2))  # every example has the same representation.
collapsed_w = normalize_w(collapsed_w)  # normalize to unit length.
collapsed_sims_w = collapsed_w @ collapsed_w.T  # every pair has cosine 1.
print("collapsed similarities:\n", np.round(collapsed_sims_w, 3))  # inspect all-ones geometry.
print("feature variance:", np.round(np.var(collapsed_w, axis=0), 6))  # no diversity across examples.
assert np.allclose(np.var(collapsed_w, axis=0), 0.0)  # collapse has zero variance.
```
▶ What you'll see: every example is equally similar to every other example, and per-feature variance is zero.

```python
exp_c_w = np.exp(collapsed_sims_w[0] / tau_w - np.max(collapsed_sims_w[0] / tau_w))  # equal logits.
prob_c_w = exp_c_w / exp_c_w.sum()  # uniform softmax over four candidates.
loss_c_w = -np.log(prob_c_w[0])  # loss for the positive under collapse.
print("collapsed probabilities:", np.round(prob_c_w, 3))  # all candidates tied.
print("collapsed InfoNCE loss:", round(float(loss_c_w), 3))  # log(4).
assert round(float(loss_c_w), 3) == round(float(np.log(4)), 3)  # uniform four-way loss.
```
▶ What you'll see: the positive probability is only 0.25 because the model cannot tell examples apart.

```python
plt.figure(figsize=(4.2, 3.2))  # create a comparison plot.
plt.bar(["useful var", "collapsed var"], [float(np.var(z1_w, axis=0).sum()), float(np.var(collapsed_w, axis=0).sum())], color=["seagreen", "crimson"])  # compare diversity.
plt.title("4: collapse removes representation variance")  # title.
plt.ylabel("sum of feature variances")  # label.
plt.show()  # render.
```
▶ What you'll see: useful features have nonzero variance across examples; collapsed features have none.

*Why it's done this way:* matching positives alone has the trivial optimum "make everything identical." Contrastive losses avoid it by requiring identification among negatives. Non-contrastive methods must add other asymmetries or variance constraints to make the collapsed solution unstable or unattractive.

### 5. Non-contrastive SSL avoids collapse with asymmetry and variance pressure

BYOL-style methods do not compare against explicit negatives. Instead, an online branch predicts a target branch, often with stop-gradient and a predictor head; modern non-contrastive losses also monitor variance so dimensions do not die. This toy cell shows the logic without neural networks.

```python
online_w = normalize_w(np.array([[-0.9, 0.1], [-0.7, 0.3], [0.8, -0.2], [1.0, 0.2]]))  # online branch features.
target_w = normalize_w(np.array([[-1.0, 0.0], [-0.8, 0.2], [0.9, -0.1], [1.1, 0.1]]))  # stop-gradient target features.
P_w = np.array([[1.05, -0.05], [0.08, 0.95]])  # small predictor matrix.
pred_w = normalize_w(online_w @ P_w)  # predictor maps online features toward target features.
byol_loss_w = np.mean(np.sum((pred_w - target_w) ** 2, axis=1))  # mean squared match loss.
print("BYOL-style match loss:", round(float(byol_loss_w), 3))  # inspect alignment loss.
assert byol_loss_w < 0.05  # the predictor aligns the two branches on this toy data.
```
▶ What you'll see: the predictor makes online features close to target features without using a negative set.

```python
std_w = np.std(pred_w, axis=0)  # feature standard deviation across examples.
variance_penalty_w = np.mean(np.maximum(0.0, 0.5 - std_w) ** 2)  # penalize dimensions with too little spread.
print("feature std:", np.round(std_w, 3))  # inspect non-collapse signal.
print("variance penalty:", round(float(variance_penalty_w), 3))  # zero when both dimensions vary enough.
assert std_w[0] > 0.8 and std_w[1] > 0.05  # features are not all identical.
```
▶ What you'll see: the first dimension carries strong spread and the second carries smaller but nonzero spread.

```python
plt.figure(figsize=(4.4, 3.4))  # create a branch-alignment plot.
plt.scatter(target_w[:, 0], target_w[:, 1], color="black", label="target stop-grad")  # target branch.
plt.scatter(pred_w[:, 0], pred_w[:, 1], color="seagreen", marker="^", label="online predictor")  # predicted online branch.
plt.title("5: non-contrastive alignment without negatives")  # title.
plt.legend(); plt.show()  # display.
```
▶ What you'll see: predicted online points land near target points while still occupying more than one location.

*Why it's done this way:* stop-gradient makes the target a temporary anchor instead of letting both branches chase each other into a constant vector, and the predictor prevents the two branches from being perfectly symmetric. Variance checks make the collapse issue explicit: alignment is good only when the representation still spreads examples apart in useful dimensions.

### 6. Validate the pretext task by downstream structure, not pretext score alone

A pretext score can look healthy even when the learned feature is biased or solves a shortcut. The practical test is whether the representation helps the target setting. Here one feature captures the true cluster structure, while a shortcut feature separates by an irrelevant nuisance.

```python
labels_w = np.array([0, 0, 1, 1])  # downstream labels used only for evaluation.
true_feature_w = base_w[:, 0]  # structure that separates the two clusters.
shortcut_w = np.array([0.0, 1.0, 0.0, 1.0])  # nuisance pattern unrelated to the downstream labels.
score_true_w = abs(np.corrcoef(true_feature_w, labels_w)[0, 1])  # downstream alignment of true feature.
score_short_w = abs(np.corrcoef(shortcut_w, labels_w)[0, 1])  # downstream alignment of shortcut.
print("downstream correlation true feature:", round(float(score_true_w), 3))  # useful.
print("downstream correlation shortcut:", round(float(score_short_w), 3))  # useless.
assert score_true_w > 0.95 and score_short_w == 0.0  # the shortcut does not transfer.
```
▶ What you'll see: the structural feature aligns with downstream labels; the shortcut has zero correlation.

```python
plt.figure(figsize=(4.4, 3.2))  # create a feature comparison chart.
plt.bar(["structure", "shortcut"], [score_true_w, score_short_w], color=["seagreen", "crimson"])  # compare transfer value.
plt.ylabel("|correlation with downstream label|")  # label metric.
plt.title("6: validate the representation, not just the pretext")  # title.
plt.show()  # display.
```
▶ What you'll see: the pretext design is only valuable when it preserves information the downstream task needs.

*Why it's done this way:* self-supervision optimizes the task we invent, not the task we secretly care about. Validation must match the target setting, and overly strong alignment, masking, or regularization can remove useful information along with noise.

## 🛠️ Setup

```python
import numpy as np  # load NumPy for arrays, synthetic data, vectorized losses, and small numerical checks.
import matplotlib.pyplot as plt  # load Matplotlib for the line plots, scatters, bars, and heatmaps.
np.random.seed(0)  # make all examples reproducible across notebook runs.

def normalize(Z):  # row-normalize vectors so dot products become cosine similarities.
    Z = np.asarray(Z, dtype=float)  # convert to floating arrays for safe arithmetic.
    return Z / np.maximum(np.linalg.norm(Z, axis=1, keepdims=True), 1e-12)  # avoid division by zero.

def softmax(v):  # define a numerically stable softmax for small toy logits.
    v = np.asarray(v, dtype=float)  # convert to a float vector.
    e = np.exp(v - np.max(v))  # subtract the max so exponentials stay finite.
    return e / e.sum()  # normalize exponentials into probabilities.

def info_nce_loss(Q, K, tau=0.5):  # compute SimCLR-style loss when the positive is on the diagonal.
    S = normalize(Q) @ normalize(K).T  # cosine similarity matrix between queries and keys.
    losses = []  # collect one cross-entropy loss per query.
    for i in range(S.shape[0]):  # loop over queries.
        p = softmax(S[i] / tau)  # candidate distribution for this query.
        losses.append(-np.log(p[i]))  # diagonal key is the positive.
    return float(np.mean(losses)), S  # return average loss and the similarities for inspection.

def make_two_cluster(n=12, noise=0.08, seed=0):  # synthesize two unlabeled clusters with no sklearn.
    rng = np.random.default_rng(seed)  # local generator for reproducibility.
    left = rng.normal(loc=[-1.0, 0.0], scale=noise, size=(n // 2, 2))  # first cluster.
    right = rng.normal(loc=[1.0, 0.0], scale=noise, size=(n - n // 2, 2))  # second cluster.
    X = np.vstack([left, right])  # stack unlabeled points.
    y = np.array([0] * (n // 2) + [1] * (n - n // 2))  # downstream labels for evaluation only.
    return X, y  # return features and hidden labels.
```

### Basic 2 — Hide part of an example

X_b2 = np.array([[-1.0, -0.5], [0.0, 0.2], [1.0, 0.9]])  # two-coordinate examples following y=0.7x+0.2.

### Basic 5 — Identify positives and negatives

**Goal.** Build a batch similarity matrix, because contrastive SSL needs to know which candidate is the positive and which candidates are negatives. We build it in 2 steps.

Q_b5 = normalize(np.array([[1.0, 0.1], [0.9, 0.2], [-1.0, 0.0]]))  # query features.

pos_b5 = np.diag(S_b5)  # diagonal positive similarities.

### Basic 6 — Compute one InfoNCE probability

**Goal.** Turn similarities into a positive-pair probability, because InfoNCE is cross-entropy over the candidate keys. We build it in 2 steps.

```python
sims_b6 = np.array([0.994, 0.0, -1.0, 0.243])  # one query's candidate similarities.
tau_b6 = 0.5  # temperature from the worked contrastive example.
logits_b6 = sims_b6 / tau_b6  # scale similarities before softmax.
print("logits:", np.round(logits_b6, 3))  # inspect temperature-scaled scores.
```
▶ What you'll see: the positive similarity becomes the largest logit.

```python
prob_b6 = softmax(logits_b6)  # convert logits to probabilities.
loss_b6 = -np.log(prob_b6[0])  # positive candidate is index 0.
print("probabilities:", np.round(prob_b6, 3))  # inspect candidate probabilities.
print("loss:", round(float(loss_b6), 3))  # inspect cross-entropy.
assert round(float(prob_b6[0]), 3) == 0.726  # verify the canonical probability.
assert abs(float(loss_b6) - 0.320) < 0.002  # verify the canonical loss.
```
▶ What you'll see: the positive gets probability about 0.726 and loss about 0.320.

```python
plt.figure(figsize=(4, 3))  # create an InfoNCE candidate-probability chart.
colors_b6 = ["seagreen"] + ["gray"] * (len(prob_b6) - 1)  # highlight the positive candidate.
plt.bar(np.arange(len(prob_b6)), prob_b6, color=colors_b6)  # plot softmax probabilities.
plt.title("Basic 6: positive-pair probability")  # title.
plt.xlabel("candidate key"); plt.ylabel("softmax probability")  # labels.
plt.show()  # display.
```
▶ What you'll see: candidate 0 receives most of the probability mass because it has the highest similarity.

### Advanced 2 — Train a tiny contrastive projection from scratch

loss_start_a2 = projected_loss_a2(W_a2)  # initial loss.
losses_a2 = [loss_start_a2]  # record losses.

    losses_a4.append(float(np.mean(np.sum(diff_a4 ** 2, axis=1))))  # mean squared alignment loss.
    grad_a4 = (2 / len(X_a4)) * X_a4.T @ diff_a4  # gradient for W_online only.
    W_online_a4 -= 0.2 * grad_a4  # update online projection.
print("final alignment loss:", round(losses_a4[-1], 5))  # inspect convergence.
assert losses_a4[-1] < losses_a4[0]  # online branch moved toward target.
```

print("final feature std:", np.round(std_final_a4, 3))  # inspect non-collapse.
assert std_final_a4[0] > 0.7  # cluster dimension still has strong spread.
```

👀 Takeaway: stop-gradient makes one side a temporary teacher; collapse checks still matter because there are no negatives.

### Advanced 5 — Diagnose pretext shortcuts with transfer metrics

**Goal.** Train two pretext features and test downstream transfer, because a low pretext loss can still be a shortcut. We build it in 4 steps.
