# 25.3 — Differentiable Programming

Differentiable programming treats an ML model as ordinary code whose pieces are chosen so gradients can flow through them. In this lesson, hard thresholds, branches, choices, and small data-structure operations are softened into smooth computations, then optimized with backpropagation and gradient descent.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build differentiable programming one idea at a time. Run each cell in order and read the printed intermediate values — the code implements a tiny reverse-mode autodiff engine and then uses it to relax program-like decisions. This walkthrough is self-contained and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays, vectorized math, and reproducible toy data.
import matplotlib.pyplot as plt  # all walkthrough and example visualizations.
np.random.seed(0)  # make all examples reproducible.
```

### 1. Differentiable programming means trainable ordinary code

A useful program often contains a parameter that affects its output: a threshold, a gate, a loop weight, or a scoring rule. The differentiable-programming move is to write that computation as code, then choose smooth operations so a loss can tell the parameter how to move. Here the program is a threshold classifier, but we replace the hard comparison with a sigmoid.

```python
x_w = np.array([0., 1., 2., 3.])  # scalar inputs that a small program will classify.
y_w = np.array([0., 0., 1., 1.])  # desired labels: the change happens between 1 and 2.
t_w = 1.5  # program parameter: the threshold location.
k_w = 4.0  # sharpness: larger k makes the sigmoid closer to a hard step.
soft_w = 1 / (1 + np.exp(-k_w * (x_w - t_w)))  # differentiable threshold predictions.
hard_w = (x_w > t_w).astype(float)  # non-differentiable threshold predictions.
print("soft predictions:", np.round(soft_w, 6))
print("hard predictions:", hard_w)
assert np.allclose(np.round(soft_w, 6), [0.002473, 0.119203, 0.880797, 0.997527])
plt.figure(figsize=(5, 3))
plt.plot(x_w, soft_w, marker="o", label="soft sigmoid program")
plt.step(x_w, hard_w, where="mid", label="hard branch", color="crimson")
plt.scatter(x_w, y_w, color="black", zorder=3, label="labels")
plt.title("1: hard threshold softened into trainable code")
plt.xlabel("x"); plt.ylabel("program output"); plt.ylim(-0.05, 1.05); plt.legend()
plt.show()
```
▶ What you'll see: the sigmoid almost behaves like the hard threshold, but it changes smoothly around the boundary.

*Why it's done this way:* the smooth version keeps the program's intended threshold shape while giving gradient descent a slope to follow when the threshold is not yet in the right place.

### 2. A computation graph records how values depend on each other

Backpropagation needs to know which intermediate values produced the loss. A computation graph is that dependency record: leaves are inputs or parameters, internal nodes are operations, and arrows show how gradients flow backward by the chain rule.

```python
nodes_w = {"x": (0, 1), "t": (0, 0), "x-t": (1.4, 0.5), "k(x-t)": (2.9, 0.5), "sigmoid": (4.5, 0.5), "loss": (6.0, 0.5)}
edges_w = [("x", "x-t"), ("t", "x-t"), ("x-t", "k(x-t)"), ("k(x-t)", "sigmoid"), ("sigmoid", "loss")]
print("graph nodes:", list(nodes_w))
print("gradient path back to t: loss -> sigmoid -> k(x-t) -> x-t -> t")
plt.figure(figsize=(7, 2.8))
for a_w, b_w in edges_w:
    xa_w, ya_w = nodes_w[a_w]; xb_w, yb_w = nodes_w[b_w]
    plt.annotate("", xy=(xb_w - 0.22, yb_w), xytext=(xa_w + 0.22, ya_w), arrowprops=dict(arrowstyle="->", lw=1.5))
for name_w, (px_w, py_w) in nodes_w.items():
    plt.scatter([px_w], [py_w], s=800, color="lightsteelblue", edgecolor="black", zorder=3)
    plt.text(px_w, py_w, name_w, ha="center", va="center", fontsize=9)
plt.axis("off"); plt.title("2: computation graph for a soft threshold")
plt.show()
```
▶ What you'll see: the loss is connected to the threshold through every smooth operation in the program.

*Why it's done this way:* backpropagation is just local derivatives multiplied along graph edges, so we must express the program in differentiable graph pieces.

### 3. Reverse-mode autodiff from scratch

Reverse-mode autodiff stores a value, a gradient accumulator, and a backward rule for each operation. After the forward pass computes the loss, the backward pass visits nodes in reverse topological order and pushes gradients into their parents.

```python
class Value_w:
    def __init__(self, data, children=(), op=""):
        self.data = float(data); self.grad = 0.0; self._prev = set(children); self._backward = lambda: None; self.op = op
    def __add__(self, other):
        other = other if isinstance(other, Value_w) else Value_w(other)
        out = Value_w(self.data + other.data, (self, other), "+")
        def _backward():
            self.grad += out.grad; other.grad += out.grad
        out._backward = _backward; return out
    def __mul__(self, other):
        other = other if isinstance(other, Value_w) else Value_w(other)
        out = Value_w(self.data * other.data, (self, other), "*")
        def _backward():
            self.grad += other.data * out.grad; other.grad += self.data * out.grad
        out._backward = _backward; return out
    def __sub__(self, other):
        return self + (other * -1)
    def __neg__(self):
        return self * -1
    def exp(self):
        out = Value_w(np.exp(self.data), (self,), "exp")
        def _backward(): self.grad += out.data * out.grad
        out._backward = _backward; return out
    def sigmoid(self):
        s = 1 / (1 + np.exp(-self.data)); out = Value_w(s, (self,), "sigmoid")
        def _backward(): self.grad += s * (1 - s) * out.grad
        out._backward = _backward; return out
    def backward(self):
        topo = []
        seen = set()
        def build(v):
            if v not in seen:
                seen.add(v)
                for child in v._prev: build(child)
                topo.append(v)
        build(self); self.grad = 1.0
        for v in reversed(topo): v._backward()
        return topo
xv_w = Value_w(1.0); tv_w = Value_w(0.2); kv_w = Value_w(3.0); yv_w = Value_w(1.0)
predv_w = (kv_w * (xv_w - tv_w)).sigmoid()
lossv_w = (predv_w - yv_w) * (predv_w - yv_w)
topo_w = lossv_w.backward()
print("prediction:", round(predv_w.data, 4), "loss:", round(lossv_w.data, 4), "dL/dt:", round(tv_w.grad, 4))
assert tv_w.grad > 0
plt.figure(figsize=(5, 3))
plt.bar(["x", "t", "k", "pred", "loss"], [xv_w.grad, tv_w.grad, kv_w.grad, predv_w.grad, lossv_w.grad], color="teal")
plt.title("3: reverse-mode gradients stored on graph nodes")
plt.ylabel("gradient after backward")
plt.show()
```
▶ What you'll see: the threshold receives a nonzero gradient because the loss depends smoothly on it.

*Why it's done this way:* reverse mode is efficient for ML because one scalar loss can send gradients to many parameters in a single backward sweep.

### 4. Binary cross-entropy gives a smooth training signal

For soft binary predictions, binary cross-entropy (BCE) is a natural loss. It penalizes confident wrong probabilities strongly and is smooth as long as predictions stay away from exactly 0 or 1.

```python
p_w = soft_w
bce_terms_w = -(y_w * np.log(p_w) + (1 - y_w) * np.log(1 - p_w))
loss_w = float(np.mean(bce_terms_w))
print("BCE terms:", np.round(bce_terms_w, 6))
print("mean BCE:", loss_w)
assert abs(loss_w - 0.06470184809035148) < 1e-12
plt.figure(figsize=(5, 3))
plt.bar(["x=0", "x=1", "x=2", "x=3"], bce_terms_w, color="slateblue")
plt.title("4: BCE loss contributions for the soft program")
plt.ylabel("binary cross-entropy")
plt.show()
```
▶ What you'll see: all four examples have small loss because the soft threshold is almost correct.

*Why it's done this way:* BCE matches probabilistic outputs and produces large corrective gradients when a prediction is confidently wrong.

### 5. The loss surface tells optimization where the program should move

A differentiable program becomes trainable when changing its parameter changes the loss continuously. Sweeping the threshold shows the loss surface; gradient descent follows the slope of this curve instead of testing discrete programs one by one.

```python
def sigmoid_w(z):
    return 1 / (1 + np.exp(-z))
def bce_loss_w(t):
    pred = sigmoid_w(k_w * (x_w - t))
    pred = np.clip(pred, 1e-12, 1 - 1e-12)
    return float(np.mean(-(y_w * np.log(pred) + (1 - y_w) * np.log(1 - pred))))
ts_w = np.linspace(0, 3, 121)
losses_w = np.array([bce_loss_w(t) for t in ts_w])
best_t_w = float(ts_w[np.argmin(losses_w)])
print("L(1.0)=", bce_loss_w(1.0), "L(1.5)=", bce_loss_w(1.5), "L(2.0)=", bce_loss_w(2.0))
print("best grid threshold:", best_t_w)
assert abs(best_t_w - 1.5) < 1e-12
plt.figure(figsize=(5, 3))
plt.plot(ts_w, losses_w, color="purple")
plt.axvline(best_t_w, color="black", linestyle="--", label="best t")
plt.title("5: smooth loss surface over the threshold")
plt.xlabel("threshold t"); plt.ylabel("BCE"); plt.legend()
plt.show()
```
▶ What you'll see: the minimum sits at 1.5, halfway between the negative and positive examples.

*Why it's done this way:* a smooth loss surface converts program search into numerical optimization over parameters.

### 6. Gradients become parameter updates

A finite-difference gradient approximates the local slope by measuring the loss just to the right and left of the current parameter. If the slope is negative, increasing the parameter lowers loss, so gradient descent moves right.

```python
t0_w = 1.0
eps_w = 1e-4
grad_fd_w = (bce_loss_w(t0_w + eps_w) - bce_loss_w(t0_w - eps_w)) / (2 * eps_w)
t1_w = t0_w - 0.2 * grad_fd_w
print("finite-difference gradient at t=1:", grad_fd_w)
print("one update moves t to:", t1_w)
assert grad_fd_w < 0 and t1_w > t0_w
plt.figure(figsize=(5, 3))
near_w = np.linspace(0.75, 1.25, 80)
plt.plot(near_w, [bce_loss_w(t) for t in near_w], color="navy")
plt.scatter([t0_w, t1_w], [bce_loss_w(t0_w), bce_loss_w(t1_w)], color=["red", "green"], zorder=3)
plt.annotate("descent step", xy=(t1_w, bce_loss_w(t1_w)), xytext=(t0_w, bce_loss_w(t0_w)+0.08), arrowprops=dict(arrowstyle="->"))
plt.title("6: gradient sign chooses the update direction")
plt.xlabel("threshold t"); plt.ylabel("BCE")
plt.show()
```
▶ What you'll see: the update moves the threshold rightward because the loss curve slopes downward there.

*Why it's done this way:* optimization needs only local slope information, so a differentiable program can be trained without enumerating every possible threshold.

### 7. Hard branches are poor teachers for gradients

The hard threshold may evaluate perfectly over a wide interval, but that flatness gives no slope. A soft relaxation changes continuously, revealing near misses and useful direction even when the hard answer does not change.

```python
def hard_loss_w(t):
    pred = (x_w > t).astype(float)
    return float(np.mean((pred - y_w) ** 2))
zoom_w = np.linspace(0.5, 2.5, 161)
hard_losses_w = np.array([hard_loss_w(t) for t in zoom_w])
soft_losses_w = np.array([bce_loss_w(t) for t in zoom_w])
print("hard loss at 1.01 and 1.99:", hard_loss_w(1.01), hard_loss_w(1.99))
print("soft loss at 1.01 and 1.99:", round(bce_loss_w(1.01), 3), round(bce_loss_w(1.99), 3))
assert hard_loss_w(1.01) == 0 and hard_loss_w(1.99) == 0
plt.figure(figsize=(5, 3))
plt.plot(zoom_w, hard_losses_w, label="hard branch loss", color="crimson")
plt.plot(zoom_w, soft_losses_w, label="soft BCE loss", color="seagreen")
plt.title("7: hard flat regions vs soft gradient signal")
plt.xlabel("threshold t"); plt.ylabel("loss"); plt.legend()
plt.show()
```
▶ What you'll see: the hard loss is flat across intervals, while the soft loss changes smoothly.

*Why it's done this way:* flat regions can be fine for final decisions, but they do not tell a gradient optimizer how to improve a parameter.

### 8. Smooth control flow replaces a hard if with a weighted blend

A hard `if` chooses one branch and ignores the other. A soft-if computes a gate $g=\sigma(kz)$ and returns $g\cdot a+(1-g)\cdot b$, so both branches can receive gradient in proportion to the gate.

```python
z_w = np.linspace(-2, 2, 101)
a_w = z_w ** 2 + 0.5  # branch A: a curved computation.
b_w = -0.5 * z_w + 1.0  # branch B: a linear computation.
gate_w = sigmoid_w(3.0 * z_w)
soft_if_w = gate_w * a_w + (1 - gate_w) * b_w
hard_if_w = np.where(z_w > 0, a_w, b_w)
print("gate at z=-1,0,1:", np.round(sigmoid_w(3 * np.array([-1., 0., 1.])), 3))
assert abs(sigmoid_w(0) - 0.5) < 1e-12
plt.figure(figsize=(5, 3))
plt.plot(z_w, a_w, linestyle="--", label="branch a")
plt.plot(z_w, b_w, linestyle="--", label="branch b")
plt.plot(z_w, hard_if_w, color="crimson", label="hard if")
plt.plot(z_w, soft_if_w, color="seagreen", label="soft if")
plt.title("8: relaxed control flow blends both branches")
plt.xlabel("condition score z"); plt.ylabel("output"); plt.legend()
plt.show()
```
▶ What you'll see: the soft-if smoothly transitions between branches instead of jumping at zero.

*Why it's done this way:* blending preserves branch structure while allowing gradients to pass through the condition and into both branch computations.

### 9. Soft choices relax argmax and indexing

A hard argmax returns one index, which blocks gradients through the choice. A softmax turns scores into weights, and a soft-argmax or weighted lookup returns a differentiable average that still concentrates on the best score when temperature is low.

```python
scores_w = np.array([0.2, 1.4, 0.7, 2.0])
values_w = np.array([-1.0, 0.0, 2.0, 4.0])
temps_w = np.array([2.0, 1.0, 0.4, 0.15])
soft_values_w = []
for tau_w in temps_w:
    weights_w = np.exp(scores_w / tau_w - np.max(scores_w / tau_w))
    weights_w = weights_w / weights_w.sum()
    soft_values_w.append(float(weights_w @ values_w))
hard_value_w = float(values_w[np.argmax(scores_w)])
print("hard selected value:", hard_value_w)
print("soft selected values:", np.round(soft_values_w, 3))
assert abs(soft_values_w[-1] - hard_value_w) < 0.1
plt.figure(figsize=(5, 3))
plt.plot(temps_w, soft_values_w, marker="o", label="soft weighted lookup")
plt.axhline(hard_value_w, color="crimson", linestyle="--", label="hard argmax value")
plt.gca().invert_xaxis()
plt.title("9: soft lookup approaches hard argmax as temperature falls")
plt.xlabel("temperature τ"); plt.ylabel("selected value"); plt.legend()
plt.show()
```
▶ What you'll see: lower temperature makes the soft choice approach the hard selected value.

*Why it's done this way:* soft choices keep the semantics of choosing the best option approximately while exposing gradients to all candidate scores.

### 10. Relaxations are modeling choices, not free lunch

A relaxation can be too soft to match the intended program or too sharp to train. The sharpness parameter $k$ controls both faithfulness and gradient scale, so it is a real modeling knob.

```python
ks_w = np.array([0.5, 1.0, 2.0, 4.0, 12.0])
loss_by_k_w = []
grad_by_k_w = []
for kk_w in ks_w:
    pred_w = 1 / (1 + np.exp(-kk_w * (x_w - 1.0)))
    pred_w = np.clip(pred_w, 1e-12, 1 - 1e-12)
    loss_by_k_w.append(float(np.mean(-(y_w*np.log(pred_w)+(1-y_w)*np.log(1-pred_w)))))
    def local_loss(t):
        p = 1 / (1 + np.exp(-kk_w * (x_w - t)))
        p = np.clip(p, 1e-12, 1 - 1e-12)
        return float(np.mean(-(y_w*np.log(p)+(1-y_w)*np.log(1-p))))
    grad_by_k_w.append((local_loss(1.0 + 1e-4) - local_loss(1.0 - 1e-4)) / 2e-4)
print("loss by k:", np.round(loss_by_k_w, 3))
print("gradient by k:", np.round(grad_by_k_w, 3))
assert len(loss_by_k_w) == len(ks_w)
fig, ax = plt.subplots(1, 2, figsize=(8, 3))
ax[0].plot(ks_w, loss_by_k_w, marker="o"); ax[0].set_title("loss at t=1"); ax[0].set_xlabel("sharpness k")
ax[1].plot(ks_w, np.abs(grad_by_k_w), marker="o", color="darkorange"); ax[1].set_title("|gradient| at t=1"); ax[1].set_xlabel("sharpness k")
plt.suptitle("10: sharpness changes meaning and trainability")
plt.show()
```
▶ What you'll see: changing sharpness changes both the loss landscape and the gradient magnitude.

*Why it's done this way:* smoothing is not neutral; it trades faithfulness to the hard program against the optimizer's ability to learn.

## 🛠️ Setup

```python
import numpy as np  # arrays, numerical optimization, and deterministic experiments.
import matplotlib.pyplot as plt  # visual checks for graphs, losses, relaxations, and gradients.
np.random.seed(0)  # reproducibility for examples that use randomness.

def sigmoid(z):  # stable sigmoid for scalar or array inputs.
    z = np.asarray(z, dtype=float)
    return 1 / (1 + np.exp(-z))

def bce(pred, target):  # binary cross-entropy averaged over a batch.
    pred = np.clip(np.asarray(pred, dtype=float), 1e-12, 1 - 1e-12)
    target = np.asarray(target, dtype=float)
    return float(np.mean(-(target * np.log(pred) + (1 - target) * np.log(1 - pred))))

def softmax(scores, tau=1.0):  # temperature-controlled softmax for soft choices.
    scaled = np.asarray(scores, dtype=float) / tau
    shifted = scaled - np.max(scaled)
    e = np.exp(shifted)
    return e / np.sum(e)

def finite_diff(f, x, eps=1e-5):  # central finite-difference derivative for one scalar parameter.
    return float((f(x + eps) - f(x - eps)) / (2 * eps))

def threshold_loss(x, y, t, k=4.0):  # BCE loss for the differentiable threshold program.
    return bce(sigmoid(k * (x - t)), y)
```

#### B5. Estimate a gradient by finite differences

**Goal.** Approximate a derivative numerically, because a gradient is the local slope that tells the optimizer which way to move.

```python
x_b5 = np.array([0., 1., 2., 3.])
y_b5 = np.array([0., 0., 1., 1.])
f_b5 = lambda t_b5: threshold_loss(x_b5, y_b5, t_b5, 4.0)
t0_b5 = 1.0
grad_b5 = finite_diff(f_b5, t0_b5, 1e-4)
print("gradient at t=1:", grad_b5)
assert grad_b5 < 0
near_b5 = np.linspace(0.8, 1.2, 80)
plt.figure(figsize=(5, 3))
plt.plot(near_b5, [f_b5(t_b5) for t_b5 in near_b5], color="navy")
plt.scatter([t0_b5], [f_b5(t0_b5)], color="red", label="current t")
plt.title("B5: finite-difference slope at t=1")
plt.xlabel("t"); plt.ylabel("BCE"); plt.legend()
plt.show()
```

#### E1. Build a tiny reverse-mode autodiff engine

**Goal.** Implement scalar reverse-mode autodiff, because differentiable programming systems are built from values plus local backward rules.

```python
class Value_e1:
    def __init__(self, data, children=(), op=""):
        self.data = float(data); self.grad = 0.0; self._prev = set(children); self._backward = lambda: None; self.op = op
    def __add__(self, other):
        other = other if isinstance(other, Value_e1) else Value_e1(other)
        out = Value_e1(self.data + other.data, (self, other), "+")
        def _backward(): self.grad += out.grad; other.grad += out.grad
        out._backward = _backward; return out
    def __mul__(self, other):
        other = other if isinstance(other, Value_e1) else Value_e1(other)
        out = Value_e1(self.data * other.data, (self, other), "*")
        def _backward(): self.grad += other.data * out.grad; other.grad += self.data * out.grad
        out._backward = _backward; return out
    def __sub__(self, other): return self + other * -1
    def sigmoid(self):
        s = 1 / (1 + np.exp(-self.data)); out = Value_e1(s, (self,), "sigmoid")
        def _backward(): self.grad += s * (1 - s) * out.grad
        out._backward = _backward; return out
    def backward(self):
        topo, seen = [], set()
        def build(v):
            if v not in seen:
                seen.add(v)
                for child in v._prev: build(child)
                topo.append(v)
        build(self); self.grad = 1.0
        for v in reversed(topo): v._backward()
        return topo
x_e1 = Value_e1(1.0); t_e1 = Value_e1(0.0); k_e1 = Value_e1(4.0); y_e1 = Value_e1(1.0)
pred_e1 = (k_e1 * (x_e1 - t_e1)).sigmoid()
loss_e1 = (pred_e1 - y_e1) * (pred_e1 - y_e1)
loss_e1.backward()
print("prediction:", round(pred_e1.data, 4), "loss:", round(loss_e1.data, 6), "dL/dt:", round(t_e1.grad, 6))
assert t_e1.grad > 0
plt.figure(figsize=(5, 3))
plt.bar(["x", "t", "k"], [x_e1.grad, t_e1.grad, k_e1.grad], color="teal")
plt.title("E1: autodiff gradients on program inputs")
plt.ylabel("gradient")
plt.show()
```
▶ What you'll see: the custom autodiff engine computes a nonzero gradient for the threshold.

👀 Takeaway: reverse-mode autodiff is local derivative bookkeeping plus a reverse graph traversal.
