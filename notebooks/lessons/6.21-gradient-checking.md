# 6.21 — Gradient Checking

Gradient checking is the debugging habit of comparing the gradient your backprop code reports against a tiny finite-difference slope computed directly from the loss. The centered finite difference is slow but trustworthy for small tests, so it turns silent derivative bugs into concrete numbers before those bugs contaminate training.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build gradient checking one idea at a time. Run each cell in order and read the printed intermediate values — every piece of math is visible, including the perturbation, the two loss evaluations, and the final error score. This walkthrough is self-contained (it imports what it needs) and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays, vector arithmetic, and finite-difference bookkeeping.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
np.random.seed(0)  # reproducibility for small random checks.
```

### 1. Centered finite difference: slope from two nearby losses

The core object is the centered finite difference

$$\frac{\partial L}{\partial \theta_i}\approx\frac{L(\theta_i+h)-L(\theta_i-h)}{2h}.$$

It asks a local question: if we nudge one parameter a tiny amount forward and backward, how fast does the loss change around the current point? The symmetric form matters. A one-sided difference uses only one side of the point and carries larger truncation error; the centered version cancels more of that curvature error.

```python
def L_scalar_w(theta_w):  # a simple loss with known derivative: L(theta)=theta^2.
    return theta_w ** 2

theta_w = 2.0
h_w = 1e-4
forward_w = L_scalar_w(theta_w + h_w)
backward_w = L_scalar_w(theta_w - h_w)
print("L(theta+h):", round(forward_w, 6))
print("L(theta-h):", round(backward_w, 6))
```
▶ What you'll see: the two losses are almost equal because `h` is tiny, but their small difference carries slope information.

```python
numeric_grad_w = (forward_w - backward_w) / (2 * h_w)
analytic_grad_w = 2 * theta_w
print("numeric gradient:", round(numeric_grad_w, 6))
print("analytic gradient:", round(analytic_grad_w, 6))
assert round(numeric_grad_w, 6) == 4.0
```
▶ What you'll see: the finite-difference slope agrees with the exact derivative `2*theta = 4`.

```python
hs_w = np.logspace(-1, -8, 8)
errors_w = []
for step_w in hs_w:
    g_w = (L_scalar_w(theta_w + step_w) - L_scalar_w(theta_w - step_w)) / (2 * step_w)
    errors_w.append(abs(g_w - analytic_grad_w))
plt.figure(figsize=(4.6, 3))
plt.loglog(hs_w, errors_w, marker="o", color="purple")
plt.xlabel("h")
plt.ylabel("absolute error")
plt.title("1: centered difference error")
plt.gca().invert_xaxis()
plt.show()
```
▶ What you'll see: errors stay tiny for reasonable `h`; very tiny `h` can stop helping because floating-point subtraction loses precision.

*Why it's done this way:* the numerator estimates “rise” and `2h` is the full “run” from `theta-h` to `theta+h`. Symmetry cancels the first curvature bias term, so the remaining approximation error is usually much smaller than a forward-only check.

### 2. Checking a vector parameter one coordinate at a time

A neural-network parameter array is just many scalar parameters packed together. Gradient checking tests one coordinate at a time: hold every other coordinate fixed, perturb coordinate `i`, and compare the resulting numerical slope with the analytic gradient stored at the same coordinate.

```python
def vector_loss_w(theta_vec_w):
    return float(np.sum(theta_vec_w ** 2))  # L=sum theta_i^2, so grad=2 theta.

theta_vec_w = np.array([1.2, -0.4, 0.6])
analytic_vec_w = 2 * theta_vec_w
print("theta:", theta_vec_w)
print("analytic gradient:", analytic_vec_w)
```
▶ What you'll see: each coordinate has its own derivative, positive or negative depending on the sign of that parameter.

```python
num_vec_w = np.zeros_like(theta_vec_w)
for i_w in range(theta_vec_w.size):
    plus_w = theta_vec_w.copy()
    minus_w = theta_vec_w.copy()
    plus_w[i_w] += h_w
    minus_w[i_w] -= h_w
    num_vec_w[i_w] = (vector_loss_w(plus_w) - vector_loss_w(minus_w)) / (2 * h_w)
print("numeric gradient:", np.round(num_vec_w, 6))
print("difference:", np.round(num_vec_w - analytic_vec_w, 10))
assert np.allclose(num_vec_w, analytic_vec_w, atol=1e-8)
```
▶ What you'll see: every coordinate matches the analytic gradient, so the vector implementation is consistent.

```python
plt.figure(figsize=(4.6, 3))
x_w = np.arange(theta_vec_w.size)
plt.bar(x_w - 0.18, analytic_vec_w, width=0.36, label="analytic", color="seagreen")
plt.bar(x_w + 0.18, num_vec_w, width=0.36, label="numeric", color="orange")
plt.xticks(x_w, ["θ0", "θ1", "θ2"])
plt.title("2: coordinate-wise gradient check")
plt.legend()
plt.show()
```
▶ What you'll see: the paired bars overlap coordinate by coordinate.

*Why it's done this way:* the partial derivative means “change only this coordinate.” Copying the vector before each `+h` and `-h` perturbation prevents other coordinates from moving, so the numerical check measures exactly the same partial derivative as backprop.

### 3. Backprop through the lesson's affine + ReLU scratch pass

The lesson's scratch pass uses inputs `x=[1.5,-0.5]`, weights `[1.2,-0.4]`, and bias `0.6`, giving an affine signal `2.6` and a ReLU-gated signal `2.6`. Because the pre-activation is positive, ReLU's local derivative is 1, so the analytic gradients are easy: for loss `0.5*y^2`, `dL/dw = y*x` and `dL/db = y`.

```python
x_w = np.array([1.5, -0.5])
w_w = np.array([1.2, -0.4])
b_w = 0.6
z_w = float(w_w @ x_w + b_w)
y_w = max(0.0, z_w)
print("affine z:", round(z_w, 3))
print("ReLU y:", round(y_w, 3))
assert round(z_w, 3) == 2.6
```
▶ What you'll see: the raw signal is `2.6`, and ReLU leaves it unchanged because it is positive.

```python
def relu_loss_w(weight_w, bias_w):
    z_local_w = float(weight_w @ x_w + bias_w)
    y_local_w = max(0.0, z_local_w)
    return 0.5 * y_local_w ** 2

analytic_dw_w = y_w * x_w
analytic_db_w = y_w
print("analytic dL/dw:", np.round(analytic_dw_w, 3))
print("analytic dL/db:", round(analytic_db_w, 3))
assert np.allclose(np.round(analytic_dw_w, 3), [3.9, -1.3])
```
▶ What you'll see: each weight gradient equals the upstream signal `2.6` times its input coordinate.

```python
num_dw_w = np.zeros_like(w_w)
for i_w in range(w_w.size):
    wp_w = w_w.copy(); wm_w = w_w.copy()
    wp_w[i_w] += h_w; wm_w[i_w] -= h_w
    num_dw_w[i_w] = (relu_loss_w(wp_w, b_w) - relu_loss_w(wm_w, b_w)) / (2 * h_w)
num_db_w = (relu_loss_w(w_w, b_w + h_w) - relu_loss_w(w_w, b_w - h_w)) / (2 * h_w)
print("numeric dL/dw:", np.round(num_dw_w, 3))
print("numeric dL/db:", round(num_db_w, 3))
assert np.allclose(num_dw_w, analytic_dw_w, atol=1e-7)
assert abs(num_db_w - analytic_db_w) < 1e-7
```
▶ What you'll see: finite differences reproduce the backprop gradients for both weights and bias.

```python
plt.figure(figsize=(4.6, 3))
labels_w = ["w0", "w1", "b"]
plt.bar(labels_w, list(num_dw_w) + [num_db_w], color=["steelblue", "steelblue", "darkorange"])
plt.title("3: checked gradients for affine + ReLU")
plt.ylabel("gradient")
plt.show()
```
▶ What you'll see: the negative bar for `w1` appears because its input is `-0.5`, so increasing `w1` lowers the positive signal.

*Why it's done this way:* backprop is a chain rule calculation. The finite-difference check ignores the chain rule and asks the loss directly what happens after a perturbation. Agreement means the chain rule code and the actual loss surface are saying the same thing.

### 4. Relative error: a scale-aware pass/fail number

Raw differences can be misleading. A difference of `1e-5` is huge if the gradients are near `1e-6`, but irrelevant if gradients are near `1000`. Gradient checks usually report a relative error:

$$\frac{\lVert g_{analytic}-g_{numeric}\rVert}{\max(1,\lVert g_{analytic}\rVert,\lVert g_{numeric}\rVert)}.$$

```python
good_analytic_w = np.array([3.9, -1.3, 2.6])
good_numeric_w = np.array([3.90000001, -1.29999999, 2.60000002])
bad_numeric_w = np.array([3.9, 1.3, 2.6])  # sign bug in the second coordinate.
print("good numeric:", good_numeric_w)
print("bad numeric:", bad_numeric_w)
```
▶ What you'll see: the bad case looks close in magnitude but has the wrong sign for one coordinate.

```python
def relative_error_w(a_w, b_w):
    denom_w = max(1.0, np.linalg.norm(a_w), np.linalg.norm(b_w))
    return float(np.linalg.norm(a_w - b_w) / denom_w)

good_err_w = relative_error_w(good_analytic_w, good_numeric_w)
bad_err_w = relative_error_w(good_analytic_w, bad_numeric_w)
print("good relative error:", good_err_w)
print("bad relative error:", round(bad_err_w, 3))
assert good_err_w < 1e-7
assert bad_err_w > 0.5
```
▶ What you'll see: the correct gradient has tiny relative error, while the sign bug is unmistakable.

```python
plt.figure(figsize=(4.6, 3))
plt.semilogy(["good", "sign bug"], [good_err_w, bad_err_w], marker="o", color="crimson")
plt.axhline(1e-6, color="gray", linestyle="--", label="strict check")
plt.title("4: relative error separates pass from fail")
plt.ylabel("relative error (log scale)")
plt.legend()
plt.show()
```
▶ What you'll see: the good check sits far below the threshold; the sign bug sits many orders of magnitude higher.

*Why it's done this way:* relative error asks whether disagreement is large compared with the size of the gradients themselves. That makes one threshold useful across tiny gradients, ordinary gradients, and large gradients.

### 5. Choosing `h`: too large truncates, too small subtracts noise

The perturbation `h` is a numerical design choice. If `h` is too large, the finite difference averages over curvature instead of measuring a local slope. If `h` is too small, the two losses become nearly identical floating-point numbers, and subtracting them loses significant digits.

```python
def curved_loss_w(t_w):
    return np.sin(t_w) + 0.1 * t_w ** 3

def curved_grad_w(t_w):
    return np.cos(t_w) + 0.3 * t_w ** 2

t0_w = 1.7
true_grad_w = curved_grad_w(t0_w)
print("true gradient:", round(true_grad_w, 6))
```
▶ What you'll see: the analytic derivative gives a reference slope for the finite-difference sweep.

```python
h_grid_w = np.logspace(-1, -12, 12)
fd_errors_w = []
for step_w in h_grid_w:
    fd_w = (curved_loss_w(t0_w + step_w) - curved_loss_w(t0_w - step_w)) / (2 * step_w)
    fd_errors_w.append(abs(fd_w - true_grad_w))
print("best h:", h_grid_w[int(np.argmin(fd_errors_w))])
print("best abs error:", min(fd_errors_w))
assert min(fd_errors_w) < 1e-8
```
▶ What you'll see: the best `h` lands in the middle of the sweep, not at the largest or smallest value.

```python
plt.figure(figsize=(4.8, 3))
plt.loglog(h_grid_w, fd_errors_w, marker="o", color="navy")
plt.gca().invert_xaxis()
plt.xlabel("h")
plt.ylabel("absolute gradient error")
plt.title("5: h has a sweet spot")
plt.show()
```
▶ What you'll see: a U-shaped error curve — large `h` hurts on one side, floating-point cancellation hurts on the other.

*Why it's done this way:* gradient checking is numerical analysis, not magic. A practical `h` such as `1e-4` or `1e-5` is small enough to be local but not so small that the two loss values become indistinguishable in double precision.

### 6. What can fool a gradient check?

Gradient checking assumes the loss is deterministic and locally smooth. Random minibatches, dropout-like noise, or a nondifferentiable kink can make a correct implementation look wrong. The ReLU kink at zero is the simplest example: the centered finite difference reports an average slope across the kink, while backprop must choose a convention at exactly zero.

```python
def relu_scalar_w(t_w):
    return max(0.0, t_w)

for point_w in [-0.2, 0.0, 0.2]:
    fd_w = (relu_scalar_w(point_w + h_w) - relu_scalar_w(point_w - h_w)) / (2 * h_w)
    print("point", point_w, "centered slope", round(fd_w, 3))
```
▶ What you'll see: away from zero the slopes are 0 or 1, but exactly at the kink the centered check returns 0.5.

```python
theta_noise_w = 1.0
rng_noise_w = np.random.default_rng(0)
def noisy_loss_w(t_w):
    return (t_w - 2.0) ** 2 + 0.01 * rng_noise_w.normal()

noisy_forward_w = noisy_loss_w(theta_noise_w + h_w)
noisy_backward_w = noisy_loss_w(theta_noise_w - h_w)
noisy_fd_w = (noisy_forward_w - noisy_backward_w) / (2 * h_w)
print("noisy finite difference:", round(noisy_fd_w, 3))
print("true deterministic gradient:", -2.0)
```
▶ What you'll see: tiny random loss noise can explode after division by `2h`, so the numerical gradient becomes useless.

```python
points_w = np.linspace(-0.6, 0.6, 121)
relu_vals_w = np.maximum(0, points_w)
plt.figure(figsize=(4.8, 3))
plt.plot(points_w, relu_vals_w, color="teal")
plt.axvline(0, color="crimson", linestyle="--", label="nondifferentiable kink")
plt.title("6: ReLU is not smooth at zero")
plt.xlabel("input")
plt.ylabel("ReLU(input)")
plt.legend()
plt.show()
```
▶ What you'll see: the corner at zero is exactly where a centered check and a chosen backprop convention can disagree.

*Why it's done this way:* a check is valid only when the local mathematical assumptions match the computation. Freeze randomness, use a small deterministic batch, avoid kink points when possible, and compare with relative error rather than a single raw difference.

## 🛠️ Setup

```python
import numpy as np # load NumPy for arrays, finite differences, and from-scratch backprop checks.
import matplotlib.pyplot as plt # load Matplotlib for diagnostic plots and error curves.
np.random.seed(0) # keep stochastic examples reproducible.

def relu(x): # implement ReLU from scratch with NumPy.
    return np.maximum(0.0, x) # pass positive values through and clamp negative values to zero.

def centered_difference(loss_fn, theta, index=None, h=1e-5): # compute a centered finite-difference gradient.
    if index is None: # scalar parameter case.
        return (loss_fn(theta + h) - loss_fn(theta - h)) / (2 * h) # scalar centered difference.
    plus = theta.copy() # copy parameters for the forward perturbation.
    minus = theta.copy() # copy parameters for the backward perturbation.
    plus[index] += h # perturb only the selected coordinate upward.
    minus[index] -= h # perturb only the selected coordinate downward.
    return (loss_fn(plus) - loss_fn(minus)) / (2 * h) # coordinate partial derivative.

def relative_error(a, b): # compute a scale-aware gradient-check score.
    a = np.asarray(a, dtype=float) # convert the analytic gradient to floats.
    b = np.asarray(b, dtype=float) # convert the numeric gradient to floats.
    denom = max(1.0, np.linalg.norm(a), np.linalg.norm(b)) # avoid exploding when both gradients are tiny.
    return float(np.linalg.norm(a - b) / denom) # normalized disagreement.

def mse_loss(pred, target): # define half squared error for simple gradient examples.
    return 0.5 * float((pred - target) ** 2) # half factor makes derivative pred-target.
```

## 🟢 Basics (warm-up)

### Basic 1 — Centered slope of a square

**Goal.** Check the derivative of `L(θ)=θ²`, because a one-parameter loss makes the finite-difference idea impossible to hide. We build it in 2 steps.

```python
theta_b1 = 2.0 # choose the scalar parameter to test.
h_b1 = 1e-5 # choose a small symmetric perturbation.
loss_b1 = lambda t: t ** 2 # define the scalar loss.
print("theta:", theta_b1, "h:", h_b1) # inspect the check point and perturbation.
```
▶ What you'll see: the check will measure the slope at θ=2 with a tiny step size.

```python
g_num_b1 = centered_difference(loss_b1, theta_b1, h=h_b1) # compute [L(theta+h)-L(theta-h)]/(2h).
g_true_b1 = 2 * theta_b1 # compute the analytic derivative.
print("numeric:", round(g_num_b1, 6), "analytic:", round(g_true_b1, 6)) # compare both gradients.
assert abs(g_num_b1 - g_true_b1) < 1e-9 # verify the finite difference matches the exact derivative.
```
▶ What you'll see: both gradients are 4.0.

👀 Takeaway: centered finite differences can verify a derivative using only loss evaluations.

### Basic 2 — Forward versus centered difference

**Goal.** Compare one-sided and centered differences, because the centered formula usually removes more curvature bias. We build it in 3 steps.

```python
theta_b2 = 1.5 # choose a point on a curved loss.
h_b2 = 0.1 # intentionally use a visible step size so the difference is easy to see.
loss_b2 = lambda t: t ** 3 # derivative is 3 theta^2.
true_b2 = 3 * theta_b2 ** 2 # exact slope at the chosen point.
print("true derivative:", round(true_b2, 3)) # inspect the reference derivative.
```
▶ What you'll see: the exact slope is 6.75.

```python
forward_b2 = (loss_b2(theta_b2 + h_b2) - loss_b2(theta_b2)) / h_b2 # one-sided finite difference.
centered_b2 = (loss_b2(theta_b2 + h_b2) - loss_b2(theta_b2 - h_b2)) / (2 * h_b2) # centered finite difference.
print("forward:", round(forward_b2, 3), "centered:", round(centered_b2, 3)) # compare approximations.
assert abs(centered_b2 - true_b2) < abs(forward_b2 - true_b2) # centered is closer here.
```
▶ What you'll see: the centered approximation is closer to the true derivative than the forward approximation.

```python
plt.figure(figsize=(4, 3)) # create a compact approximation comparison.
plt.bar(["forward", "centered", "true"], [forward_b2, centered_b2, true_b2], color=["red", "teal", "gray"]) # compare slope estimates.
plt.title("Basic 2: finite-difference choices") # title the plot.
plt.ylabel("slope") # label the slope scale.
plt.show() # display the plot.
```
▶ What you'll see: the centered bar sits nearer to the true derivative bar.

👀 Takeaway: use centered differences for gradient checking unless there is a special reason not to.

### Basic 3 — One coordinate in a vector

**Goal.** Perturb only one entry of a vector, because a partial derivative changes one parameter while holding the rest fixed. We build it in 2 steps.

```python
theta_b3 = np.array([1.0, -2.0, 0.5]) # define a small parameter vector.
idx_b3 = 1 # choose the coordinate to check.
loss_b3 = lambda v: float(np.sum(v ** 2)) # L=sum theta_i^2.
print("theta before check:", theta_b3) # inspect the unperturbed vector.
```
▶ What you'll see: only coordinate 1 will be nudged for the numerical derivative.

```python
g_num_b3 = centered_difference(loss_b3, theta_b3, index=idx_b3, h=1e-5) # check the selected coordinate.
g_true_b3 = 2 * theta_b3[idx_b3] # exact partial derivative.
print("numeric partial:", round(g_num_b3, 6), "analytic partial:", round(g_true_b3, 6)) # compare.
assert abs(g_num_b3 - g_true_b3) < 1e-9 # verify the coordinate check.
```
▶ What you'll see: the checked partial derivative is −4.0.

👀 Takeaway: gradient checking tests vector parameters by isolating one coordinate at a time.

### Basic 4 — Full vector gradient check

**Goal.** Loop over every coordinate in a vector, because real parameter tensors need complete gradient arrays. We build it in 3 steps.

```python
theta_b4 = np.array([0.3, -0.7, 1.1, 2.0]) # define a four-parameter vector.
loss_b4 = lambda v: float(np.sum(v ** 2)) # same loss with known gradient.
g_true_b4 = 2 * theta_b4 # analytic gradient.
print("analytic gradient:", np.round(g_true_b4, 3)) # inspect the target gradient.
```
▶ What you'll see: each gradient entry is exactly twice the parameter value.

```python
g_num_b4 = np.zeros_like(theta_b4) # allocate numeric gradient storage.
for i_b4 in range(theta_b4.size): # check every coordinate separately.
    g_num_b4[i_b4] = centered_difference(loss_b4, theta_b4, index=i_b4, h=1e-5) # store one partial.
print("numeric gradient:", np.round(g_num_b4, 3)) # inspect the finite-difference gradient.
assert np.allclose(g_num_b4, g_true_b4, atol=1e-9) # verify all coordinates.
```
▶ What you'll see: numeric and analytic arrays match entry by entry.

```python
plt.figure(figsize=(4, 3)) # create a gradient comparison plot.
plt.plot(g_true_b4, marker="o", label="analytic", color="seagreen") # plot analytic entries.
plt.plot(g_num_b4, marker="x", linestyle="--", label="numeric", color="orange") # plot numeric entries.
plt.title("Basic 4: vector gradient check") # title the plot.
plt.legend() # show labels.
plt.show() # display the plot.
```
▶ What you'll see: the two lines overlap.

👀 Takeaway: a gradient array passes only when every coordinate agrees with the loss surface.

### Basic 5 — Relative error for a passing check

**Goal.** Convert gradient disagreement into a scale-aware number, because raw differences are hard to threshold across examples. We build it in 2 steps.

```python
g_true_b5 = np.array([2.0, -4.0, 1.0]) # define an analytic gradient.
g_num_b5 = g_true_b5 + np.array([1e-8, -2e-8, 1e-8]) # define a nearly identical numerical gradient.
print("raw difference norm:", np.linalg.norm(g_true_b5 - g_num_b5)) # inspect absolute disagreement.
```
▶ What you'll see: the raw difference is tiny but not exactly zero.

```python
err_b5 = relative_error(g_true_b5, g_num_b5) # compute the normalized error.
print("relative error:", err_b5) # inspect the pass/fail score.
assert err_b5 < 1e-7 # verify a tight pass.
```
▶ What you'll see: the relative error is far below a typical strict threshold.

👀 Takeaway: relative error gives a practical pass/fail score for gradient checks.

### Basic 6 — Relative error catches a sign bug

**Goal.** See a common derivative bug, because sign mistakes can leave magnitudes looking plausible. We build it in 2 steps.

```python
g_true_b6 = np.array([3.9, -1.3, 2.6]) # correct gradient from the affine+ReLU walkthrough.
g_bug_b6 = np.array([3.9, 1.3, 2.6]) # wrong sign on the second coordinate.

```

```python
err_b6 = relative_error(g_true_b6, g_bug_b6) # compute scale-aware mismatch.

```
▶ What you'll see: the error is much too large to pass.

👀 Takeaway: gradient checking is especially good at catching sign and transpose mistakes.

### Basic 7 — Check the lesson affine signal

**Goal.** Reproduce the lesson's two-input scratch pass, because the numbers make the gradient path visible. We build it in 2 steps.

```python
x_b7 = np.array([1.5, -0.5]) # define the lesson inputs.
w_b7 = np.array([1.2, -0.4]) # define the lesson weights.
b_b7 = 0.6 # define the lesson bias.
z_b7 = float(w_b7 @ x_b7 + b_b7) # compute the affine signal.
print("affine signal:", round(z_b7, 3)) # inspect 1.8 + 0.2 + 0.6.
assert round(z_b7, 3) == 2.6 # verify the lesson arithmetic.
```
▶ What you'll see: the affine signal is 2.6.

```python
y_b7 = float(relu(z_b7)) # apply ReLU to the scalar signal.

```
▶ What you'll see: ReLU returns 2.6 because the affine signal is positive.

👀 Takeaway: before checking gradients, inspect the forward signal that the gradient depends on.

### Basic 8 — Check one ReLU-weight derivative

**Goal.** Compare a single ReLU backprop derivative to finite differences, because a gated unit is the smallest neural-network gradient check. We build it in 3 steps.

```python
x_b8 = np.array([1.5, -0.5]) # inputs for the tiny unit.
w_b8 = np.array([1.2, -0.4]) # current weights.
b_b8 = 0.6 # current bias.
loss_b8 = lambda weight: 0.5 * float(relu(weight @ x_b8 + b_b8) ** 2) # loss as a function of weights only.
print("current loss:", round(loss_b8(w_b8), 3)) # inspect the scalar loss.
```
▶ What you'll see: the loss is half of 2.6².

```python
plt.scatter(points_a4, relu(points_a4), color="red") # mark checked points.
plt.axvline(0, color="gray", linestyle="--") # show kink location.
plt.title("Advanced 4: avoid checking exactly at ReLU kinks") # title the plot.
plt.xlabel("input") # label x-axis.
plt.ylabel("ReLU") # label y-axis.
plt.show() # display the plot.
```
▶ What you'll see: the corner at zero explains the disagreement.

👀 Takeaway: choose smooth check points or interpret ReLU-kink failures with care.

### Advanced 5 — Sample coordinates for a larger parameter vector

**Goal.** Check a random subset of coordinates, because full gradient checking is expensive for large models but sampled checks still catch many implementation bugs. We build it in 5 steps.

```python
rng_a5 = np.random.default_rng(5) # local reproducible generator.
theta_a5 = rng_a5.normal(size=20) # create a larger parameter vector.
A_a5 = rng_a5.normal(size=(8, 20)) # fixed design matrix for a quadratic loss.
y_a5 = rng_a5.normal(size=8) # fixed target vector.
print("parameter length:", theta_a5.size) # inspect scale of the check.
```
▶ What you'll see: this toy has 20 parameters, already larger than we want to print manually.

```python
def loss_a5(theta_local_a5):
    resid_a5 = A_a5 @ theta_local_a5 - y_a5 # residual vector.
    return 0.5 * float(resid_a5 @ resid_a5) # half squared error.

g_true_a5 = A_a5.T @ (A_a5 @ theta_a5 - y_a5) # analytic gradient for least squares.
check_idx_a5 = rng_a5.choice(theta_a5.size, size=6, replace=False) # sample coordinates to check.
print("checked indices:", check_idx_a5) # inspect sampled coordinates.
```
▶ What you'll see: six random coordinates will be checked instead of all twenty.

```python
g_num_sample_a5 = [] # store numerical gradients for sampled coordinates.
g_true_sample_a5 = [] # store analytic gradients for the same coordinates.
for idx_a5 in check_idx_a5: # loop over sampled parameter indices.
    g_num_sample_a5.append(centered_difference(loss_a5, theta_a5, index=idx_a5, h=1e-5)) # numeric partial.
    g_true_sample_a5.append(g_true_a5[idx_a5]) # analytic partial.
g_num_sample_a5 = np.array(g_num_sample_a5) # convert to array.
g_true_sample_a5 = np.array(g_true_sample_a5) # convert to array.
print("sample numeric:", np.round(g_num_sample_a5, 6)) # inspect numeric sampled gradients.
print("sample analytic:", np.round(g_true_sample_a5, 6)) # inspect analytic sampled gradients.
```
▶ What you'll see: sampled numerical and analytic values match closely.

```python
err_a5 = relative_error(g_true_sample_a5, g_num_sample_a5) # compute sampled relative error.
print("sampled relative error:", err_a5) # inspect pass/fail score.
assert err_a5 < 1e-9 # verify sampled coordinates pass.
```
▶ What you'll see: the sampled check passes with tiny error.
