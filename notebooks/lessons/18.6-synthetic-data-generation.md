# 18.6 — Synthetic Data Generation

Synthetic data generation creates new rows that are useful only when they preserve the learning question: the right ranges, moments, dependence, labels, and privacy distance from real records. In this lesson, you will build parametric samplers, class-conditional generators, copulas, SMOTE-style interpolation, and fidelity checks from first principles with NumPy, then inspect why each design choice matters.

### 1. Parametric sampling: fit a simple story, then sample from it

The smallest generator says, "real values look like samples from a distribution with a few parameters." For one numeric feature, a Gaussian story estimates a mean $\mu$ and standard deviation $\sigma$, then samples $\tilde x=\mu+\sigma z$ where $z\sim\mathcal N(0,1)$.
```python
real_w = np.array([1.8, 2.0, 2.1, 2.4, 2.5, 2.7, 3.0, 3.2])
mu_w = float(np.mean(real_w))
sigma_w = float(np.std(real_w))
print("mu:", round(mu_w, 3), "sigma:", round(sigma_w, 3))
assert round(mu_w, 3) == 2.463 and round(sigma_w, 3) == 0.458
```
▶ What you'll see: the fitted generator centers samples near 2.463 with spread about 0.458.
```python
z_w = np.array([-1.0, -0.2, 0.0, 0.7, 1.4])
synth_param_w = mu_w + sigma_w * z_w
print("synthetic values:", np.round(synth_param_w, 3))
assert np.allclose(np.round(synth_param_w, 3), [2.004, 2.371, 2.463, 2.783, 3.104])
```
▶ What you'll see: negative z values land below the mean, positive z values above it, with distances scaled by sigma.
```python
plt.figure(figsize=(5, 3))
plt.hist(real_w, bins=5, alpha=0.65, label="real", color="steelblue")
plt.hist(synth_param_w, bins=5, alpha=0.65, label="synthetic", color="darkorange")
plt.axvline(mu_w, color="black", linestyle="--", label="fitted μ")
plt.title("1: parametric Gaussian sampler")
plt.xlabel("feature value")
plt.ylabel("count")
plt.legend()
plt.show()
```
▶ What you'll see: real and synthetic values occupy similar center and spread, but only because the Gaussian story is simple.
*Why it's done this way:* The formula $\tilde x=\mu+\sigma z$ separates shape from scale. $z$ supplies generic standard-normal variation; multiplying by $\sigma$ stretches that variation into real units; adding $\mu$ shifts it to the observed center. The math preserves first and second moments, but not skew, hard bounds, or multiple modes.
### 2. Class-conditional generation: match the target question, not just the global average

For supervised learning, synthetic rows usually need labels. If positives are rare, an unconditional generator mostly learns the majority class and can erase the region we wanted to repair. A class-conditional generator fits one distribution per label and chooses the synthetic class mix deliberately.
```python
x0_w = np.array([0.2, 0.4, 0.5, 0.7, 0.8])
x1_w = np.array([2.7, 2.9])
mu0_w, sig0_w = float(np.mean(x0_w)), float(np.std(x0_w))
mu1_w, sig1_w = float(np.mean(x1_w)), float(np.std(x1_w))
print("class 0 μ,σ:", round(mu0_w, 3), round(sig0_w, 3), "class 1 μ,σ:", round(mu1_w, 3), round(sig1_w, 3))
assert round(mu0_w, 3) == 0.520 and round(mu1_w, 3) == 2.800
```
▶ What you'll see: the two classes live in very different regions, so one global generator would blur them.
```python
syn0_w = mu0_w + sig0_w * np.array([-0.8, -0.1, 0.5])
syn1_w = mu1_w + sig1_w * np.array([-0.5, 0.0, 0.5])
print("synthetic class 0:", np.round(syn0_w, 3))
print("synthetic class 1:", np.round(syn1_w, 3))
assert np.all(syn1_w > 2.7)
```
▶ What you'll see: class-conditional samples preserve separation instead of averaging the rare class into the majority.
```python
plt.figure(figsize=(5, 3))
plt.scatter(x0_w, np.zeros_like(x0_w), label="real y=0", color="steelblue", s=70)
plt.scatter(x1_w, np.ones_like(x1_w), label="real y=1", color="crimson", s=70)
plt.scatter(syn0_w, np.full_like(syn0_w, 0.08), marker="x", label="synthetic y=0", color="navy", s=90)
plt.scatter(syn1_w, np.full_like(syn1_w, 1.08), marker="x", label="synthetic y=1", color="darkred", s=90)
plt.yticks([0, 1], ["class 0", "class 1"])
plt.title("2: sample within each class")
plt.xlabel("feature value")
plt.legend()
plt.show()
```
▶ What you'll see: synthetic positives appear near real positives, not near the global mean.
*Why it's done this way:* The conditional distribution $q(x\mid y)$ answers a different question from $q(x)$. Matching the marginal mean can still destroy the conditional boundary. Fitting per-label parameters keeps $p(x\mid y=1)$ and $p(x\mid y=0)$ distinct, while the chosen number of rows controls intended balance.
### 3. Copula-style sampling: keep dependence while changing marginals

Feature-wise sampling can match every histogram and still break relationships. A simple Gaussian copula learns dependence in a standardized space, samples correlated latent normals, and maps each coordinate back through sorted real feature values. Dependence lives in ranks; marginals live in values.
```python
real2_w = np.array([[1.0, 1.2], [1.5, 1.7], [2.0, 2.2], [2.5, 2.8], [3.0, 3.4]])
corr_w = np.corrcoef(real2_w.T)
print("correlation matrix:\n", np.round(corr_w, 3))
assert round(float(corr_w[0, 1]), 3) == 0.999
```
▶ What you'll see: the real features are strongly positively related, so independent sampling would be visibly wrong.
```python
rho_w = float(corr_w[0, 1])
z1_w = np.array([-1.2, -0.4, 0.2, 0.9, 1.4])
eps_w = np.array([0.3, -0.2, 0.1, -0.4, 0.2])
z2_w = rho_w * z1_w + np.sqrt(1 - rho_w ** 2) * eps_w
print("latent corr:", round(float(np.corrcoef(z1_w, z2_w)[0, 1]), 3))
assert round(float(np.corrcoef(z1_w, z2_w)[0, 1]), 3) > 0.99
```
▶ What you'll see: the latent samples inherit nearly the same rank direction as the real features.
```python
rank1_w = np.argsort(np.argsort(z1_w))
rank2_w = np.argsort(np.argsort(z2_w))
synth_copula_w = np.column_stack([np.sort(real2_w[:, 0])[rank1_w], np.sort(real2_w[:, 1])[rank2_w]])
print("copula synthetic rows:\n", synth_copula_w)
assert synth_copula_w.shape == (5, 2)
```
▶ What you'll see: each synthetic column reuses real marginal values while row pairings follow sampled dependence.
```python
plt.figure(figsize=(4.5, 3.5))
plt.scatter(real2_w[:, 0], real2_w[:, 1], label="real", s=80, color="steelblue")
plt.scatter(synth_copula_w[:, 0], synth_copula_w[:, 1], label="synthetic copula", marker="x", s=90, color="darkorange")
plt.title("3: copula keeps feature dependence")
plt.xlabel("feature 1")
plt.ylabel("feature 2")
plt.legend()
plt.show()
```
▶ What you'll see: synthetic points lie along the same increasing relationship as the real data.
*Why it's done this way:* A copula factors a joint distribution into marginal distributions plus a dependence rule. The rank mapping preserves each feature's empirical values, while correlated latent normals decide which ranks appear together. This keeps monotone relationships even when raw scales are non-Gaussian.
### 4. SMOTE-style interpolation: create minority points inside the local class region

SMOTE starts with minority examples, finds nearby minority neighbors, and creates $\tilde x=x_i+\lambda(x_j-x_i)$ for $0<\lambda<1$. That equation places synthetic points on line segments inside the minority cloud instead of directly copying records.
```python
minority_w = np.array([[2.0, 2.0], [2.4, 2.2], [2.2, 2.7], [2.8, 2.5]])
base_w = minority_w[0]
dists_w = np.sqrt(np.sum((minority_w - base_w) ** 2, axis=1))
neighbor_idx_w = int(np.argsort(dists_w)[1])
print("distances from base:", np.round(dists_w, 3), "nearest neighbor index:", neighbor_idx_w)
assert neighbor_idx_w == 1
```
▶ What you'll see: the nearest minority neighbor is selected using only minority-class geometry.
```python
lam_w = np.array([0.25, 0.50, 0.75])
neighbor_w = minority_w[neighbor_idx_w]
smote_w = base_w + lam_w[:, None] * (neighbor_w - base_w)
print("SMOTE points:\n", np.round(smote_w, 3))
assert np.allclose(smote_w[1], [2.2, 2.1])
```
▶ What you'll see: every synthetic point lies between two real minority records, not on top of either one.
```python
plt.figure(figsize=(4.5, 3.5))
plt.scatter(minority_w[:, 0], minority_w[:, 1], label="real minority", s=80, color="crimson")
plt.plot([base_w[0], neighbor_w[0]], [base_w[1], neighbor_w[1]], color="gray", linestyle="--", label="neighbor segment")
plt.scatter(smote_w[:, 0], smote_w[:, 1], marker="x", s=90, label="SMOTE synthetic", color="black")
plt.title("4: SMOTE interpolates locally")
plt.xlabel("feature 1")
plt.ylabel("feature 2")
plt.legend()
plt.show()
```
▶ What you'll see: synthetic points fill a line segment inside the rare-class neighborhood.
*Why it's done this way:* The interpolation equation is a convex combination, $(1-\lambda)x_i+\lambda x_j$. With $0<\lambda<1$, the point stays inside the segment, making it less likely to cross a boundary than arbitrary noise. If neighbors straddle subclusters, though, SMOTE can fill an unrealistic bridge.
### 5. Fidelity, utility, and memorization checks: more rows are not automatically more information

A generator should be tested like a model. Moment checks ask whether summaries match; dependence checks ask whether relationships survived; nearest-neighbor distances warn when synthetic rows are suspiciously close to real records. These checks catch common failures before training.
```python
real_check_w = np.array([0.0, 1.0, 3.0, 6.0])
synth_check_w = np.array([0.05, 2.2, 5.0])
distance_matrix_w = np.abs(synth_check_w[:, None] - real_check_w[None, :])
nearest_w = np.min(distance_matrix_w, axis=1)
print("nearest distances:", np.round(nearest_w, 3), "minimum:", round(float(nearest_w.min()), 3))
assert np.allclose(nearest_w, [0.05, 0.8, 1.0])
```
▶ What you'll see: one synthetic row is only 0.05 from a real row, below a 0.10 warning threshold.
```python
real_moment_w = np.array([1.0, 2.0, 3.0, 4.0])
synth_moment_w = np.array([1.2, 1.9, 3.1, 3.8])
mean_gap_w = abs(float(np.mean(real_moment_w) - np.mean(synth_moment_w)))
std_gap_w = abs(float(np.std(real_moment_w) - np.std(synth_moment_w)))
print("mean gap:", round(mean_gap_w, 3), "std gap:", round(std_gap_w, 3))
assert round(mean_gap_w, 3) == 0.000 and round(std_gap_w, 3) == 0.106
```
▶ What you'll see: means match exactly, but spread still differs, so one metric is not enough.
```python
labels_real_w = np.array([0] * 40 + [1] * 5)
labels_aug_w = np.array([0] * 40 + [1] * 40)
print("real positives:", int(np.sum(labels_real_w == 1)), "augmented positives:", int(np.sum(labels_aug_w == 1)))
assert int(np.sum(labels_aug_w == 1)) == 40
plt.figure(figsize=(4.5, 3))
plt.bar(["real y=1", "after synthetic y=1", "real y=0"], [5, 40, 40], color=["crimson", "darkorange", "steelblue"])
plt.title("5: utility target can be class balance")
plt.ylabel("row count")
plt.show()
```
▶ What you'll see: synthetic positives can repair class balance, but distance checks still warn about possible copying.
*Why it's done this way:* Fidelity is multi-dimensional. Matching $\bar x$ tests location, matching $s$ tests spread, preserving correlations tests dependence, and nearest-neighbor distance tests memorization risk. Utility then asks whether rows improve the downstream goal without contaminating validation or leaking private records.

## 🟡 Easy
### Easy 1 — Build a two-feature parametric generator

**Goal.** sample correlated numeric features from a fitted mean vector and covariance matrix. We build it in one compact, inspectable cell.
```python
real_e1 = np.array([[1.0, 1.2], [1.5, 1.7], [2.0, 2.2], [2.5, 2.8], [3.0, 3.4]])
mu_e1 = np.mean(real_e1, axis=0); cov_e1 = np.cov(real_e1.T, bias=True)
vals_e1, vecs_e1 = np.linalg.eigh(cov_e1); sqrt_cov_e1 = vecs_e1 @ np.diag(np.sqrt(np.maximum(vals_e1,0))) @ vecs_e1.T
z_e1 = np.array([[-1.0, -0.5], [0.0, 0.0], [1.0, 0.5], [0.4, -0.8]]); synth_e1 = mu_e1 + z_e1 @ sqrt_cov_e1.T

plt.title("Easy 1: multivariate Gaussian sampler"); plt.legend(); plt.show()
```
▶ What you'll see: synthetic rows vary in both features while following the same direction of correlation.
👀 Takeaway: Multivariate sampling uses covariance to preserve feature relationships.
