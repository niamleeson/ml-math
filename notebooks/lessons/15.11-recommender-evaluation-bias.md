# 15.11 · Recommender Evaluation & Bias

Recommender evaluation is hard because logs are not neutral samples: they are traces of what an older policy chose to expose, where it placed each item, and which items already had momentum. In this lesson, we build exposure bias, position bias, inverse propensity scoring, offline/online mismatch, and feedback loops from tiny reproducible simulations.

Run each cell in order and read the printed intermediate values — the key estimators are shown numerically, including the lesson's IPS and position-bias numbers. This walkthrough is self-contained (it imports what it needs) and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays, masks, and seeded simulation for evaluation examples.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
np.random.seed(0)  # reproducibility for any global random draws.
```

### 1. Why logged data is biased: you only observe what was shown

A recommender log contains outcomes only for items the old system exposed. If a relevant item was never shown, it usually appears as missing evidence rather than as a positive label, so a naive offline metric can mistake the old system's choices for ground truth. The basic problem is selection: observations are conditional on exposure, not a random sample of all user-item pairs.

```python
true_rel_w = np.array([1, 1, 0, 1])  # The user's real relevance over four candidate items.
exposed_w = np.array([1, 0, 1, 0])  # The logging policy showed only items 0 and 2.
observed_clicks_w = true_rel_w * exposed_w  # We can only see positives among exposed items.
print("true relevance:", true_rel_w)  # Three relevant items exist in the population.
print("exposure mask:", exposed_w)  # Only positions/items selected by the logger are observed.
print("observed positives:", observed_clicks_w)  # Logs reveal only one of the three positives.
assert true_rel_w.sum() == 3 and observed_clicks_w.sum() == 1  # Reproduce the lesson grounding numbers.
```
▶ What you'll see: the log shows one positive even though the true relevance vector contains three positives.

```python
naive_positive_rate_w = observed_clicks_w.sum() / max(exposed_w.sum(), 1)  # Positive rate among shown items.
true_positive_rate_w = true_rel_w.mean()  # Positive rate across all candidates.
print("naive exposed-only positive rate:", round(naive_positive_rate_w, 3))  # 1/2.
print("true candidate positive rate:", round(true_positive_rate_w, 3))  # 3/4.
```
▶ What you'll see: the exposed-only rate answers a different question from the full-catalog rate.

```python
plt.figure(figsize=(5, 3))  # Compare real relevance with what the log reveals.
xs_w = np.arange(len(true_rel_w))  # Item indices for paired bars.
plt.bar(xs_w - 0.18, true_rel_w, width=0.36, label="true relevant", color="seagreen")  # Full truth.
plt.bar(xs_w + 0.18, observed_clicks_w, width=0.36, label="observed in log", color="darkorange")  # Logged truth.
plt.xticks(xs_w, [f"I{i}" for i in xs_w]); plt.ylim(0, 1.2)  # Label item positions.
plt.title("1: exposure hides relevant items"); plt.legend(); plt.show()  # Render the bias picture.
```
▶ What you'll see: item 1 and item 3 are relevant but invisible because they were not exposed.

*Why it's done this way: separating relevance from exposure makes the missing-data mechanism explicit; without that split, a model can learn that unshown means bad, when it often just means unknown.*

### 2. Position bias and the examination model

Even when every item has the same relevance, clicks can fall by rank because users examine top positions more often. The examination model writes click probability as $P(\text{click}\mid r)=P(\text{examined}\mid r)\,P(\text{relevant})$. A position-discounted examination curve therefore creates lower CTR at lower ranks without any change in item quality.

```python
relevance_prob_w = 0.5  # Every rank has the same underlying relevance probability.
exam_w = np.array([1.0, 0.6, 0.3, 0.15])  # Users are less likely to examine lower ranks.
ctr_by_rank_w = relevance_prob_w * exam_w  # Examination model: CTR = relevance × examination.
print("examination:", exam_w)  # Position-dependent visibility.
print("CTR by rank:", np.round(ctr_by_rank_w, 3))  # The lesson's (0.500, 0.300, 0.150, 0.075).
assert np.allclose(ctr_by_rank_w, [0.500, 0.300, 0.150, 0.075])  # Reproduce cited position-bias numbers.
```
▶ What you'll see: CTR halves and halves again because visibility falls, not because relevance changed.

```python
estimated_rel_w = np.divide(ctr_by_rank_w, exam_w, out=np.zeros_like(ctr_by_rank_w), where=exam_w > 0)  # Undo examination discount.
print("relevance recovered by CTR/examination:", np.round(estimated_rel_w, 3))  # Each rank returns to 0.5.
assert np.allclose(estimated_rel_w, 0.5)  # Dividing by known examination recovers equal relevance.
```
▶ What you'll see: correcting by the examination probability removes the artificial rank trend.

```python
plt.figure(figsize=(5, 3))  # Visualize position bias directly.
plt.plot(np.arange(1, 5), ctr_by_rank_w, marker="o", label="observed CTR", color="crimson")  # Biased clicks.
plt.plot(np.arange(1, 5), estimated_rel_w, marker="s", label="CTR / examination", color="steelblue")  # Corrected relevance.
plt.xlabel("rank position"); plt.ylabel("probability"); plt.ylim(0, 0.6)  # Keep the scale readable.
plt.title("2: position bias from examination"); plt.legend(); plt.show()  # Render rank curve.
```
▶ What you'll see: observed CTR slopes downward while corrected relevance is flat.

*Why it's done this way: the examination term isolates visibility from preference, so a lower-position click rate is not automatically interpreted as a worse item.*

### 3. Inverse Propensity Scoring (IPS) to debias offline estimates

A propensity $p_i=P(\text{shown}_i)$ is the probability that the logging policy exposed example $i$. IPS weights each observed reward by $1/p_i$:

$$\hat V_{IPS}=\frac{1}{N}\sum_i \frac{r_i\,\mathbb{1}[\text{action matched}_i]}{p_i}.$$

Dividing by propensity unbiases the mean because rare exposed examples represent many similar unexposed examples: in expectation, $\mathbb{E}[\mathbb{1}[\text{shown}]r/p]=p\,r/p=r$. The cost is variance, because tiny $p$ creates large weights.

```python
clicks_w = np.array([1.0, 0.0, 1.0])  # Logged rewards from the lesson.
props_w = np.array([0.5, 0.2, 0.1])  # Known exposure probabilities for those rewards.
weighted_w = np.divide(clicks_w, props_w, out=np.zeros_like(clicks_w), where=props_w > 0)  # r / p with a zero guard.
print("weighted rewards:", np.round(weighted_w, 3))  # 2, 0, 10.
assert np.allclose(weighted_w, [2.0, 0.0, 10.0])  # Reproduce the lesson's weighted rewards.
```
▶ What you'll see: the rare positive with propensity 0.1 becomes a weight-10 contribution.

```python
ips_w = weighted_w.mean()  # IPS average over logged examples.
naive_w = clicks_w.mean()  # Ordinary logged click mean.
print("IPS estimate:", round(ips_w, 3))  # (2+0+10)/3 = 4.
print("naive mean click:", round(naive_w, 3))  # (1+0+1)/3 = 0.667.
assert round(ips_w, 3) == 4.000 and round(naive_w, 3) == 0.667  # Reproduce cited IPS and naive numbers.
```
▶ What you'll see: IPS is much larger because a rare observed click stands in for many rarely exposed cases.

```python
plt.figure(figsize=(5, 3))  # Compare unweighted and propensity-weighted evidence.
plt.bar(["naive mean", "IPS"], [naive_w, ips_w], color=["gray", "seagreen"])  # Two estimators.
plt.ylabel("estimated value"); plt.title("3: IPS upweights rare exposure"); plt.show()  # Render the estimator comparison.
```
▶ What you'll see: the IPS bar is higher, and the printout shows exactly which rare example caused it.

*Why it's done this way: IPS uses known exposure probabilities to turn biased logged samples into an unbiased counterfactual average, but the same $1/p$ correction can be noisy when propensities are small.*

### 4. Offline vs online evaluation: why offline metrics can mislead

Offline metrics usually evaluate against labels collected by a previous policy. A new model that recommends novel but relevant items may look bad offline because those items were rarely exposed and therefore rarely labeled. Online evaluation measures actual user response under the new policy, so offline agreement with old logs and online reward can disagree.

```python
items_w = np.array(["popular", "niche", "fresh", "old"])  # Four candidate types.
logged_click_rate_w = np.array([0.42, 0.06, 0.02, 0.15])  # Old-policy observed labels favor exposed popular items.
true_online_reward_w = np.array([0.35, 0.30, 0.48, 0.12])  # True response if each item gets a fair chance.
print("best offline item:", items_w[np.argmax(logged_click_rate_w)])  # Popular wins old logs.
print("best online item:", items_w[np.argmax(true_online_reward_w)])  # Fresh wins online.
assert items_w[np.argmax(logged_click_rate_w)] == "popular" and items_w[np.argmax(true_online_reward_w)] == "fresh"
```
▶ What you'll see: the item that looks best in logs is not the item with the highest online reward.

```python
policy_old_w = np.array([0.7, 0.1, 0.05, 0.15])  # Old exposure distribution.
policy_new_w = np.array([0.2, 0.2, 0.5, 0.1])  # New model shifts traffic to the fresh item.
offline_proxy_w = float(policy_new_w @ logged_click_rate_w)  # Evaluate new policy using old observed rates.
online_reward_w = float(policy_new_w @ true_online_reward_w)  # Evaluate new policy under fair online rewards.
print("offline proxy for new policy:", round(offline_proxy_w, 3))  # Old labels undervalue fresh.
print("simulated online reward:", round(online_reward_w, 3))  # True expected reward is higher.
```
▶ What you'll see: the same policy has different value depending on whether old logs or online response define reward.

```python
plt.figure(figsize=(5, 3))  # Show mismatch by item.
plt.scatter(logged_click_rate_w, true_online_reward_w, s=90, color="purple")  # Offline vs online for each item.
for i_w, name_w in enumerate(items_w):  # Label each point.
    plt.text(logged_click_rate_w[i_w] + 0.005, true_online_reward_w[i_w], name_w)  # Item name.
plt.xlabel("old-log CTR"); plt.ylabel("true online reward"); plt.title("4: offline labels can mis-rank items"); plt.show()
```
▶ What you'll see: fresh has low old-log CTR but high online reward, the classic offline blind spot.

*Why it's done this way: offline evaluation is useful for fast iteration, but it estimates performance on the logged distribution; online tests are needed when a model changes what gets exposed.*

### 5. Popularity bias and feedback loops: rich-get-richer exposure

Popularity bias appears when already-popular items get more exposure, collect more interactions, and then look even more attractive in the next training round. This feedback loop can raise short-term clicks while reducing catalog coverage and diversity. Simulating rounds makes the mechanism visible: exposure creates data, data creates score, and score creates more exposure.

```python
rng_w = np.random.default_rng(1)  # Local generator for reproducible feedback-loop simulation.
quality_w = np.array([0.52, 0.50, 0.48, 0.46, 0.44])  # Items are fairly similar in true quality.
counts_w = np.array([80., 20., 10., 5., 2.])  # Initial historical popularity is highly unequal.
history_w = [counts_w.copy()]  # Store counts after each round.
print("initial exposure counts:", counts_w.astype(int))  # Inspect starting popularity imbalance.
```
▶ What you'll see: item 0 starts far ahead before the simulation even begins.

```python
for round_w in range(8):  # Repeat recommendation/training rounds.
    score_w = quality_w + 0.015 * np.log1p(counts_w)  # Popularity-boosted score used by the recommender.
    probs_w = score_w / score_w.sum()  # Convert scores into exposure shares.
    exposures_w = rng_w.multinomial(200, probs_w)  # Allocate this round's traffic.
    clicks_w_loop = rng_w.binomial(exposures_w, quality_w)  # Clicks come from true quality after exposure.
    counts_w += clicks_w_loop  # Future training data now contains more winner evidence.
    history_w.append(counts_w.copy())  # Save the trajectory.
history_w = np.array(history_w)  # Convert to rounds × items.
print("final exposure-derived counts:", history_w[-1].astype(int))  # Inspect concentration after rounds.
assert history_w[-1, 0] > history_w[-1, -1]  # The initial winner remains far ahead.
```
▶ What you'll see: the early leader keeps accumulating the most evidence.

```python
coverage_w = np.mean(history_w[-1] > 50)  # Fraction of catalog with substantial data.
share_top_w = history_w[-1, 0] / history_w[-1].sum()  # Final share held by the top item.
print("items with >50 interactions:", int(np.sum(history_w[-1] > 50)), "of", len(quality_w))  # Coverage count.
print("top item share:", round(float(share_top_w), 3))  # Concentration summary.
```
▶ What you'll see: evidence concentrates in a small part of the catalog.

```python
plt.figure(figsize=(5, 3))  # Plot the feedback-loop trajectory.
for j_w in range(history_w.shape[1]):  # Draw one line per item.
    plt.plot(history_w[:, j_w], marker="o", label=f"I{j_w}")  # Counts over rounds.
plt.xlabel("round"); plt.ylabel("cumulative clicks"); plt.title("5: popularity feedback loop"); plt.legend(); plt.show()
```
▶ What you'll see: the initially popular item dominates future data, even though item qualities are close.

*Why it's done this way: iterating exposure and retraining shows why popularity bias is dynamic — yesterday's recommendations shape tomorrow's labels.*

### ✍️ Toy 1 · Exposure masks hide relevant items

Logged clicks only exist for shown items. A relevant item that was not exposed is missing evidence,
not a negative label.

```python
import numpy as np
import matplotlib.pyplot as plt

t1_rng = np.random.default_rng(0)
t1_true = np.array([1, 1, 0, 1])  # -> [1, 1, 0, 1]
print("true relevance:", t1_true.tolist())  # -> [1, 1, 0, 1]
t1_exposed = np.array([1, 0, 1, 0])  # -> [1, 0, 1, 0]
print("exposure mask:", t1_exposed.tolist())  # -> [1, 0, 1, 0]
t1_observed = t1_true * t1_exposed  # -> [1, 0, 0, 0]
print("observed positives:", t1_observed.tolist())  # -> [1, 0, 0, 0]
t1_shown_count = int(t1_exposed.sum())  # -> 2
print("shown count:", t1_shown_count)  # -> 2
t1_observed_pos = int(t1_observed.sum())  # -> 1
print("observed positive count:", t1_observed_pos)  # -> 1
t1_naive_rate = t1_observed_pos / t1_shown_count  # -> 0.5
print("shown-only positive rate:", round(t1_naive_rate, 3))  # -> 0.5
t1_true_rate = float(t1_true.mean())  # -> 0.75
print("full-catalog positive rate:", round(t1_true_rate, 3))  # -> 0.75
assert t1_naive_rate == 0.5 and t1_true_rate == 0.75

plt.figure(figsize=(4.7, 2.8))

```
▶ What you'll see: two relevant items are invisible because the logging policy never exposed them.

### ✍️ Toy 2 · Examination probability creates position bias

If lower ranks are examined less often, observed CTR falls by position even when relevance is flat.
Dividing by examination probability recovers the flat relevance signal.

```python
import numpy as np

t2_rng = np.random.default_rng(0)
t2_relevance = 0.4  # -> 0.4
print("true relevance probability:", t2_relevance)  # -> 0.4
t2_exam = np.array([1.0, 0.5, 0.25])  # -> [1.0, 0.5, 0.25]
print("examination probabilities:", t2_exam.tolist())  # -> [1.0, 0.5, 0.25]
t2_ctr = t2_relevance * t2_exam  # -> [0.4, 0.2, 0.1]
t2_ctr_round = np.round(t2_ctr, 3)  # -> [0.4, 0.2, 0.1]
print("observed CTR by rank:", t2_ctr_round.tolist())  # -> [0.4, 0.2, 0.1]
t2_corrected = t2_ctr / t2_exam  # -> [0.4, 0.4, 0.4]
t2_corrected_round = np.round(t2_corrected, 3)  # -> [0.4, 0.4, 0.4]
print("CTR divided by examination:", t2_corrected_round.tolist())  # -> [0.4, 0.4, 0.4]
assert np.allclose(t2_corrected, [0.4, 0.4, 0.4])

plt.figure(figsize=(4.5, 2.8))
plt.plot([1, 2, 3], t2_ctr, marker="o", color="crimson", label="observed CTR")
plt.plot([1, 2, 3], t2_corrected, marker="s", color="steelblue", label="corrected")
plt.xlabel("rank")
plt.ylabel("probability")
plt.ylim(0, 0.5)
plt.legend()
plt.title("Toy 2 · position bias correction")
plt.show()
```
▶ What you'll see: observed CTR slopes down, while the corrected relevance line stays flat at 0.4.

### ✍️ Toy 3 · IPS upweights rare logged actions

Inverse Propensity Scoring divides each observed reward by its logging probability. Rare matched
actions therefore represent more unobserved cases.

```python
import numpy as np

t3_rng = np.random.default_rng(0)
t3_reward = np.array([1.0, 0.0, 1.0])  # -> [1.0, 0.0, 1.0]
print("logged rewards:", t3_reward.tolist())  # -> [1.0, 0.0, 1.0]
t3_prop = np.array([0.5, 0.25, 0.1])  # -> [0.5, 0.25, 0.1]
print("propensities:", t3_prop.tolist())  # -> [0.5, 0.25, 0.1]
t3_weight = 1.0 / t3_prop  # -> [2.0, 4.0, 10.0]
print("IPS weights:", t3_weight.tolist())  # -> [2.0, 4.0, 10.0]
t3_weighted_reward = t3_reward * t3_weight  # -> [2.0, 0.0, 10.0]
print("weighted rewards:", t3_weighted_reward.tolist())  # -> [2.0, 0.0, 10.0]
t3_naive = float(t3_reward.mean())  # -> 0.667
print("naive mean reward:", round(t3_naive, 3))  # -> 0.667
t3_ips = float(t3_weighted_reward.mean())  # -> 4.0
print("IPS estimate:", round(t3_ips, 3))  # -> 4.0
assert round(t3_naive, 3) == 0.667 and round(t3_ips, 3) == 4.0

plt.figure(figsize=(4.4, 2.8))
plt.bar(["naive", "IPS"], [t3_naive, t3_ips], color=["gray", "seagreen"])
plt.ylabel("estimate")
plt.title("Toy 3 · rare reward gets weight 10")
plt.show()
```
▶ What you'll see: the low-propensity positive reward dominates the IPS estimate.

### ✍️ Toy 4 · Offline logs can mis-rank an online policy

A new policy can look weak under old logged CTRs while being strong under true online response,
especially when it sends traffic to under-exposed fresh items.

```python
import numpy as np

t4_rng = np.random.default_rng(0)
```

### ✍️ Toy 5 · Popularity feedback loops concentrate evidence

If exposure probability depends on past counts, early leaders get more traffic, collect more clicks,
and remain easier for the next round to rank.

```python
import numpy as np

t5_rng = np.random.default_rng(0)
t5_quality = np.array([0.55, 0.52, 0.50])  # -> [0.55, 0.52, 0.5]
print("true quality:", t5_quality.tolist())  # -> [0.55, 0.52, 0.5]
t5_counts0 = np.array([20., 5., 1.])  # -> [20.0, 5.0, 1.0]
print("initial counts:", t5_counts0.tolist())  # -> [20.0, 5.0, 1.0]
t5_score0 = t5_quality * (t5_counts0 + 1.0)  # -> [11.55, 3.12, 1.0]
print("round 0 score:", np.round(t5_score0, 3).tolist())  # -> [11.55, 3.12, 1.0]
t5_probs0 = t5_score0 / t5_score0.sum()  # -> [0.737, 0.199, 0.064]
print("round 0 exposure probs:", np.round(t5_probs0, 3).tolist())  # -> [0.737, 0.199, 0.064]
t5_exposures0 = t5_rng.multinomial(30, t5_probs0)  # -> [21, 8, 1]
print("round 0 exposures:", t5_exposures0.tolist())  # -> [21, 8, 1]
t5_clicks0 = t5_rng.binomial(t5_exposures0, t5_quality)  # -> [15, 7, 1]
print("round 0 clicks:", t5_clicks0.tolist())  # -> [15, 7, 1]
t5_counts1 = t5_counts0 + t5_clicks0  # -> [35.0, 12.0, 2.0]
print("round 0 updated counts:", t5_counts1.tolist())  # -> [35.0, 12.0, 2.0]
t5_score1 = t5_quality * (t5_counts1 + 1.0)  # -> [19.8, 6.76, 1.5]
print("round 1 score:", np.round(t5_score1, 3).tolist())  # -> [19.8, 6.76, 1.5]
t5_probs1 = t5_score1 / t5_score1.sum()  # -> [0.706, 0.241, 0.053]
print("round 1 exposure probs:", np.round(t5_probs1, 3).tolist())  # -> [0.706, 0.241, 0.053]
t5_exposures1 = t5_rng.multinomial(30, t5_probs1)  # -> [18, 10, 2]
print("round 1 exposures:", t5_exposures1.tolist())  # -> [18, 10, 2]
t5_clicks1 = t5_rng.binomial(t5_exposures1, t5_quality)  # -> [9, 5, 2]
print("round 1 clicks:", t5_clicks1.tolist())  # -> [9, 5, 2]
t5_counts2 = t5_counts1 + t5_clicks1  # -> [44.0, 17.0, 4.0]
print("round 1 updated counts:", t5_counts2.tolist())  # -> [44.0, 17.0, 4.0]
t5_score2 = t5_quality * (t5_counts2 + 1.0)  # -> [24.75, 9.36, 2.5]
print("round 2 score:", np.round(t5_score2, 3).tolist())  # -> [24.75, 9.36, 2.5]
t5_probs2 = t5_score2 / t5_score2.sum()  # -> [0.676, 0.256, 0.068]
print("round 2 exposure probs:", np.round(t5_probs2, 3).tolist())  # -> [0.676, 0.256, 0.068]
t5_exposures2 = t5_rng.multinomial(30, t5_probs2)  # -> [18, 12, 0]
```

## Setup

```python
# !pip install numpy matplotlib  # Colab already has these; uncomment only if your runtime is missing them.
import numpy as np  # Import NumPy for arrays, probabilities, masks, and seeded simulation.
import matplotlib.pyplot as plt  # Import Matplotlib for bar charts, line charts, and diagnostic plots.
np.random.seed(0)  # Fix the global random seed so stochastic examples are repeatable.
def safe_div(num, den):  # Divide arrays while returning 0 where the denominator is 0.
    num = np.asarray(num, dtype=float)  # Convert numerator to a float array.
    den = np.asarray(den, dtype=float)  # Convert denominator to a float array.
    return np.divide(num, den, out=np.zeros_like(num, dtype=float), where=den != 0)  # Guard against divide-by-zero.
def ips_estimate(reward, propensity, match=None):  # Compute the ordinary IPS estimate.
    reward = np.asarray(reward, dtype=float)  # Convert rewards to floats.
    propensity = np.asarray(propensity, dtype=float)  # Convert propensities to floats.
    if match is None:  # If no action-match mask is supplied, every row matches.
        match = np.ones_like(reward, dtype=float)  # Use all examples.
    match = np.asarray(match, dtype=float)  # Convert the match indicator to floats.
    return float(np.mean(safe_div(reward * match, propensity)))  # Average r*match/p over rows.
def snips_estimate(reward, propensity, match=None):  # Compute self-normalized IPS.
    reward = np.asarray(reward, dtype=float)  # Convert rewards to floats.
    propensity = np.asarray(propensity, dtype=float)  # Convert propensities to floats.
    if match is None:  # If no match mask is supplied, use every row.
        match = np.ones_like(reward, dtype=float)  # All actions match.
    weights = safe_div(match, propensity)  # Importance weights 1/p for matched actions.
    denom = weights.sum()  # SNIPS denominator normalizes by total effective weight.
    return 0.0 if denom == 0 else float(np.sum(weights * reward) / denom)  # Guard against no matched actions.
def recall_at_k(hidden_positive_sets, rankings, k):  # Compute mean recall@k over users.
    vals = []  # Store one recall value per user.
    for positives, ranking in zip(hidden_positive_sets, rankings):  # Evaluate each user's ranking.
        positives = set(positives)  # Convert positives to a set for membership tests.
        topk = set(list(ranking)[:k])  # Keep only the first k recommended items.
        vals.append(0.0 if len(positives) == 0 else len(positives & topk) / len(positives))  # Recall definition.
    return float(np.mean(vals))  # Mean across users.
def coverage_at_k(rankings, k, catalog_size):  # Compute catalog coverage for top-k recommendation lists.
    shown = set()  # Track unique recommended item ids.
    for ranking in rankings:  # Loop over user recommendation lists.
        shown.update(list(ranking)[:k])  # Add top-k items.
    return len(shown) / catalog_size  # Fraction of catalog reached.
def intra_list_diversity(features, ranking, k):  # Average pairwise distance among top-k item features.
    top = np.asarray(list(ranking)[:k], dtype=int)  # Item ids in the list.
    if len(top) < 2:  # Diversity needs at least two items.
        return 0.0  # Return 0 for a one-item list.
    dists = []  # Store pairwise distances.
    for a in range(len(top)):  # First item position.
        for b in range(a + 1, len(top)):  # Second item position.
            dists.append(float(np.linalg.norm(features[top[a]] - features[top[b]])))  # Euclidean feature distance.
    return float(np.mean(dists))  # Average pairwise distance.
```

#### A1. IPS for a target policy with action matching

**Goal.** Estimate the value of a target policy from logged bandit data, because counterfactual evaluation only uses rows where the target action matches the logged action. We build it in 4 steps.

```python
rng_a1 = np.random.default_rng(21)  # Reproducible simulation.
item_reward_a1 = np.array([0.2, 0.5, 0.8])  # True click probabilities.
logging_p_a1 = np.array([0.6, 0.3, 0.1])  # Biased logging policy.
target_p_a1 = np.array([0.2, 0.3, 0.5])  # Target policy favors the best item.
logged_action_a1 = rng_a1.choice(3, size=80000, p=logging_p_a1)  # Logged actions.
reward_a1 = rng_a1.binomial(1, item_reward_a1[logged_action_a1])  # Logged rewards.
print("true target value:", round(float(target_p_a1 @ item_reward_a1), 3))  # Ground truth expected reward.
```
▶ What you'll see: the target policy's true value is computable in simulation.

```python
importance_a1 = target_p_a1[logged_action_a1] / logging_p_a1[logged_action_a1]  # Target probability divided by logging probability.
ips_a1 = float(np.mean(reward_a1 * importance_a1))  # General IPS estimate.
naive_a1 = float(np.mean(reward_a1))  # Logged-policy mean reward.
print("naive logged value:", round(naive_a1, 3))  # Biased toward logging policy.
print("IPS target value:", round(ips_a1, 3))  # Close to target truth.
assert abs(ips_a1 - float(target_p_a1 @ item_reward_a1)) < 0.02  # Stochastic tolerance.
```

```python
snips_a1 = float(np.sum(reward_a1 * importance_a1) / np.sum(importance_a1))  # Self-normalized target value.
print("SNIPS target value:", round(snips_a1, 3))  # Also close, usually more stable.
```

```python
plt.figure(figsize=(4.5, 3))  # Compare values.
plt.bar(["true target", "naive log", "IPS", "SNIPS"], [target_p_a1 @ item_reward_a1, naive_a1, ips_a1, snips_a1], color=["black", "gray", "teal", "purple"])
plt.xticks(rotation=20); plt.ylabel("reward"); plt.title("A1: counterfactual target-policy value"); plt.show()  # Render.
```
▶ What you'll see: IPS/SNIPS estimate the target policy better than the logged mean.

👀 Takeaway: off-policy evaluation weights each logged row by how much the target policy would have chosen the logged action.

#### A2. Bias-variance tradeoff from clipping

**Goal.** Sweep clipping thresholds and compare estimator spread across repeated logs, because smaller caps reduce variance but can add bias. We build it in 4 steps.

```python
rng_a2 = np.random.default_rng(22)  # Local reproducible generator.
reward_prob_a2 = np.array([0.2, 0.4, 0.7, 0.9])  # True item rewards.
log_p_a2 = np.array([0.75, 0.15, 0.08, 0.02])  # Logger rarely shows the best item.
target_p_a2 = np.ones(4) / 4  # Uniform target policy.
caps_a2 = np.array([5, 10, 25, 100])  # Candidate maximum weights.
print("true value:", round(float(target_p_a2 @ reward_prob_a2), 3))  # Target truth.
```
▶ What you'll see: the target value is the uniform average reward.

```python
estimates_a2 = {cap: [] for cap in caps_a2}  # Store repeated estimates by cap.
for rep_a2 in range(80):  # Repeat many independent logs.
    actions_a2 = rng_a2.choice(4, size=1200, p=log_p_a2)  # Biased logged actions.
    rewards_a2 = rng_a2.binomial(1, reward_prob_a2[actions_a2])  # Rewards for shown actions.
    raw_w_a2 = target_p_a2[actions_a2] / log_p_a2[actions_a2]  # Importance weights.
    for cap_a2 in caps_a2:  # Evaluate each clipping cap.
        estimates_a2[cap_a2].append(float(np.mean(rewards_a2 * np.minimum(raw_w_a2, cap_a2))))  # Capped IPS.
means_a2 = np.array([np.mean(estimates_a2[c]) for c in caps_a2])  # Mean estimate by cap.
stds_a2 = np.array([np.std(estimates_a2[c]) for c in caps_a2])  # Spread by cap.
print("means:", np.round(means_a2, 3))  # Bias view.
print("stds:", np.round(stds_a2, 3))  # Variance view.
```

```python
bias_a2 = means_a2 - float(target_p_a2 @ reward_prob_a2)  # Signed bias by cap.
print("bias:", np.round(bias_a2, 3))  # Inspect bias introduced by clipping.
```

```python
plt.figure(figsize=(5, 3))  # Plot mean with error bars.
plt.errorbar(caps_a2, means_a2, yerr=stds_a2, marker="o", capsize=4, color="crimson")  # Mean ± std by cap.
plt.axhline(target_p_a2 @ reward_prob_a2, color="black", linestyle="--", label="true")  # True value.
plt.xscale("log"); plt.xlabel("clip cap"); plt.ylabel("estimate"); plt.title("A2: clipping bias-variance tradeoff"); plt.legend(); plt.show()
```
▶ What you'll see: smaller caps are steadier but can sit farther from the true line.

👀 Takeaway: clipping chooses a practical bias-variance compromise rather than a universally best estimator.

#### A5. Simulate exploration reducing feedback-loop lock-in

**Goal.** Compare greedy popularity ranking with epsilon exploration, because random exposure can create fairer future training data. We build it in 5 steps.

```python
rng_a5 = np.random.default_rng(25)  # Local reproducible generator.
quality_a5 = np.array([0.50, 0.51, 0.52, 0.53, 0.54])  # The best item starts in the tail.
initial_a5 = np.array([90., 30., 12., 4., 1.])  # Historical counts heavily favor item 0.
rounds_a5 = 12  # Number of training/exposure rounds.
print("initial counts:", initial_a5.astype(int))  # Inspect skew before intervention.
```
▶ What you'll see: item 4 has the best quality but almost no historical data.

```python
def run_loop_a5(eps_a5):  # Simulate a feedback loop with epsilon random exposure.
    counts_a5 = initial_a5.copy()  # Start from the same historical data.
    hist_a5 = [counts_a5.copy()]  # Store the trajectory.
    for _ in range(rounds_a5):  # Iterate rounds.
        score_a5 = quality_a5 + 0.018 * np.log1p(counts_a5)  # Popularity-boosted score.
        greedy_p_a5 = np.zeros_like(score_a5)  # Greedy exposure distribution.
        greedy_p_a5[int(np.argmax(score_a5))] = 1.0  # Put all greedy traffic on the current winner.
        probs_a5 = (1 - eps_a5) * greedy_p_a5 + eps_a5 * np.ones_like(score_a5) / len(score_a5)  # Mix in exploration.
        exposures_a5 = rng_a5.multinomial(180, probs_a5)  # Allocate traffic.
        counts_a5 += rng_a5.binomial(exposures_a5, quality_a5)  # Add clicked evidence.
        hist_a5.append(counts_a5.copy())  # Save round.
    return np.array(hist_a5)  # Return trajectory.
print("helper ready")  # Confirm the simulator is defined.
```

```python

explore_a5 = run_loop_a5(0.20)  # 20% uniform exploration.
```
