# 21.11 — Case-Based Reasoning

Case-based reasoning (CBR) solves a new problem by remembering old solved problems: represent the new query as a case, retrieve similar past cases, reuse their solutions, revise the proposal after checking it, and retain the corrected experience. In this lesson, we build that whole loop from scratch with NumPy so the similarity metric, feature weights, k-nearest-neighbor retrieval, adaptation rules, and case-base maintenance decisions are all visible.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build case-based reasoning one idea at a time. Run each cell in order and read the printed intermediate values — every piece of the 4R cycle is made explicit. This walkthrough is self-contained and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays, distances, and small case-base computations.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
np.random.seed(0)  # reproducibility for any randomized toy data.
```

### 1. Cases are structured memories, not anonymous rows

A CBR system starts by deciding what a **case** contains. Here each old support incident stores two features: severity and data volume. It also stores the solution time that worked last time. This representation is the system's memory: if an important constraint is missing from the features, no similarity metric can recover it later.

```python
X_w = np.array([[1.0, 1.0],   # small, mild incident
                [2.0, 2.0],   # medium incident
                [3.0, 1.5],   # high severity but moderate volume
                [4.0, 3.5],   # large incident
                [5.0, 5.0]])  # very large incident
solutions_w = np.array([3.0, 5.0, 6.0, 9.0, 12.0])  # hours to resolution in old cases.
query_w = np.array([2.2, 2.0])  # a new incident to solve.
print("case features:\n", X_w)
print("old solution hours:", solutions_w)
```
▶ What you'll see: five remembered cases, each with two features and one reusable solution value.

```python
plt.figure(figsize=(4.4, 3.4))
plt.scatter(X_w[:, 0], X_w[:, 1], s=80, c=solutions_w, cmap="viridis", label="old cases")
plt.scatter([query_w[0]], [query_w[1]], s=150, marker="*", color="crimson", label="new query")
for i_w, xy_w in enumerate(X_w):
    plt.text(xy_w[0] + 0.05, xy_w[1], f"c{i_w}")
plt.colorbar(label="solution hours")
plt.xlabel("severity"); plt.ylabel("data volume")
plt.title("1: case base as points with solutions"); plt.legend(); plt.show()
```
▶ What you'll see: the query sits near cases c1 and c2, so memory should begin there rather than with an exact match.

*Why it's done this way:* CBR depends on a case schema before it depends on code. We store only features that make two incidents meaningfully comparable, and we store the solution field separately because retrieval answers “which experience is relevant?” before reuse answers “what solution should we try?”

### 2. Weighted similarity defines what “similar” means

Retrieval ranks old cases by distance to the query. A plain Euclidean distance treats all features equally, but CBR often needs feature weights because some mismatches matter more than others. We use weighted distance

$$d_i=\sqrt{\sum_j w_j(x_{ij}-q_j)^2}$$

so a severity mismatch can count more than a data-volume mismatch.

```python
weights_w = np.array([3.0, 1.0])  # severity matters three times as much as data volume.
diffs_w = X_w - query_w  # signed feature differences from every old case to the query.
weighted_sq_w = weights_w * diffs_w ** 2  # per-feature weighted squared mismatch.
print("query:", query_w)
print("weighted squared differences for c1:", np.round(weighted_sq_w[1], 3))
```
▶ What you'll see: for c1=(2,2), the only mismatch is severity 0.2, multiplied by weight 3.

```python
dist_w = np.sqrt(np.sum(weighted_sq_w, axis=1))  # one weighted Euclidean distance per case.
sim_w = 1.0 / (1.0 + dist_w)  # convert distances to bounded positive similarities.
print("weighted distances:", np.round(dist_w, 3))
print("similarities:", np.round(sim_w, 3))
assert round(float(dist_w[1]), 3) == 0.346
```
▶ What you'll see: case c1 is closest with distance 0.346, matching the lesson's weighted-distance calculation.

```python
plt.figure(figsize=(4.6, 3))
plt.bar([f"c{i}" for i in range(len(dist_w))], dist_w, color="steelblue")
plt.ylabel("weighted distance")
plt.title("2: lower distance means more similar"); plt.show()
```
▶ What you'll see: c1 has the shortest bar; feature weights make that ranking explicit.

*Why it's done this way:* similarity is not a neutral detail — it is the system's relevance judgment. Weighting severity more heavily says “a severity mismatch is more dangerous than the same-sized volume mismatch,” which is domain knowledge encoded as geometry.

### 3. k-nearest retrieval turns similarity into a candidate memory set

The **retrieve** step usually keeps the top `k` cases rather than only one. One neighbor can be brittle; several nearby cases let the system average evidence and notice disagreement. We sort distances, inspect the nearest cases, and draw the retrieval neighborhood.

```python
k_w = 3
order_w = np.argsort(dist_w)  # nearest first.
nn_w = order_w[:k_w]
print("nearest case ids:", nn_w)
print("nearest distances:", np.round(dist_w[nn_w], 3))
print("nearest solutions:", solutions_w[nn_w])
```
▶ What you'll see: the retrieved memory set is c1, c2, and c0, with c1 clearly the closest.

```python
plt.figure(figsize=(4.6, 3.6))
plt.scatter(X_w[:, 0], X_w[:, 1], s=75, color="lightgray", label="not retrieved")
plt.scatter(X_w[nn_w, 0], X_w[nn_w, 1], s=110, color="seagreen", label="retrieved kNN")
plt.scatter([query_w[0]], [query_w[1]], s=170, marker="*", color="crimson", label="query")
for j_w in nn_w:
    plt.plot([query_w[0], X_w[j_w, 0]], [query_w[1], X_w[j_w, 1]], color="seagreen", alpha=0.55)
plt.xlabel("severity"); plt.ylabel("data volume")
plt.title("3: 2D retrieval neighborhood"); plt.legend(); plt.show()
```
▶ What you'll see: green lines connect the query to its three nearest remembered cases; this is the local experience CBR will reuse.

*Why it's done this way:* kNN retrieval keeps reasoning local. Faraway cases may be true memories, but using them for adaptation would import experience from a different part of the problem space where the same solution may no longer apply.

### 4. Reuse, revise, and retain close the 4R cycle

After retrieval, CBR **reuses** the old solution. A simple reuse rule is a similarity-weighted average of retrieved solutions. Then a domain adaptation rule adjusts the proposal for a feature change: if each extra severity point adds about 2 hours, adapt from the nearest case by `old_solution + 2 × severity_change`. Finally, revision checks the proposal against feedback, and retention stores the corrected case.

```python
retrieved_sim_w = sim_w[nn_w]
retrieved_sol_w = solutions_w[nn_w]
weighted_reuse_w = float(np.sum(retrieved_sim_w * retrieved_sol_w) / np.sum(retrieved_sim_w))
print("retrieved similarities:", np.round(retrieved_sim_w, 3))
print("weighted reused solution:", round(weighted_reuse_w, 3))
```
▶ What you'll see: the reused solution is pulled most strongly toward c1 because c1 has the largest similarity.

```python
nearest_w = nn_w[0]
slope_w = 2.0
adapted_w = solutions_w[nearest_w] + slope_w * (query_w[0] - X_w[nearest_w, 0])
actual_w = 5.4
revision_error_w = abs(adapted_w - actual_w)
print("nearest old solution:", solutions_w[nearest_w])
print("adapted before revision:", round(adapted_w, 3))
print("revision error:", round(revision_error_w, 3))
assert round(float(adapted_w), 3) == 5.4
assert round(float(revision_error_w), 3) == 0.0
```
▶ What you'll see: the adaptation rule raises c1's 5 hours to 5.4 hours, exactly matching this toy feedback.

```python
X_retained_w = np.vstack([X_w, query_w])
solutions_retained_w = np.append(solutions_w, actual_w)
print("case-base size before:", len(X_w), "after retain:", len(X_retained_w))
print("retained last case:", X_retained_w[-1], solutions_retained_w[-1])

plt.figure(figsize=(5, 3))
plt.bar(["reuse avg", "adapted", "revised truth"], [weighted_reuse_w, adapted_w, actual_w],
        color=["gray", "darkorange", "seagreen"])
plt.ylabel("solution hours")
plt.title("4: adaptation before/after revision"); plt.show()
```
▶ What you'll see: reuse, adaptation, and revised truth are compared side-by-side; retention adds the corrected query as a new memory.

*Why it's done this way:* the 4R cycle separates responsibilities. Retrieval finds relevant experience, reuse proposes a solution, revision tests it against reality, and retention improves future performance exactly where the old case base was weak.

### 5. Maintenance protects competence as memory grows

A case base can become noisy or redundant. Maintenance asks two questions: does a case improve **competence** (coverage of query space), and is it redundant with another case? We keep a retained case when it improves local coverage or has a meaningfully different solution; otherwise, it only slows retrieval.

```python
candidate_w = np.array([2.15, 2.05])
candidate_solution_w = 5.35
all_dist_to_candidate_w = np.sqrt(np.sum(weights_w * (X_retained_w - candidate_w) ** 2, axis=1))
closest_existing_w = int(np.argmin(all_dist_to_candidate_w))
print("closest existing case:", closest_existing_w)
print("distance to closest:", round(float(all_dist_to_candidate_w[closest_existing_w]), 3))
print("solution gap:", round(abs(candidate_solution_w - solutions_retained_w[closest_existing_w]), 3))
```
▶ What you'll see: the candidate is very close to the retained query and has almost the same solution.

```python
novelty_threshold_w = 0.25
solution_gap_threshold_w = 0.5
keep_w = (all_dist_to_candidate_w[closest_existing_w] > novelty_threshold_w) or (abs(candidate_solution_w - solutions_retained_w[closest_existing_w]) > solution_gap_threshold_w)
print("retain candidate?", keep_w)
assert keep_w == False
```
▶ What you'll see: the candidate is rejected because it is both geometrically redundant and solution-redundant.

```python
grid_w = np.array([[a_w, b_w] for a_w in np.linspace(1, 5, 25) for b_w in np.linspace(1, 5, 25)])
cover_dist_w = np.min(np.sqrt(np.sum(weights_w * (grid_w[:, None, :] - X_retained_w[None, :, :]) ** 2, axis=2)), axis=1)
competence_w = float(np.mean(cover_dist_w < 0.75))
print("coverage competence:", round(competence_w, 3))

plt.figure(figsize=(4.8, 3.6))
plt.scatter(grid_w[:, 0], grid_w[:, 1], c=cover_dist_w, s=12, cmap="magma_r")
plt.scatter(X_retained_w[:, 0], X_retained_w[:, 1], color="cyan", edgecolor="black", s=70)
plt.colorbar(label="distance to nearest case")
plt.xlabel("severity"); plt.ylabel("data volume")
plt.title("5: competence as coverage of query space"); plt.show()
```
▶ What you'll see: bright covered regions lie near stored cases; dark gaps identify areas where new retained cases would be valuable.

*Why it's done this way:* retaining every experience makes retrieval slower and can overweight duplicates. Maintenance preserves competence by keeping cases that cover new regions or new outcomes, while pruning memories that add no new reasoning power.

## 🛠️ Setup

```python
import numpy as np  # Import NumPy for arrays, distances, ranking, and assertions.
import matplotlib.pyplot as plt  # Import Matplotlib for retrieval-neighborhood and adaptation plots.
np.random.seed(0)  # Fix the global random seed so every stochastic example is repeatable.

def weighted_distance(x, y, weights):  # Compute weighted Euclidean distance between two feature vectors.
    x = np.asarray(x, dtype=float)  # Convert the first point to a numeric vector.
    y = np.asarray(y, dtype=float)  # Convert the second point to a numeric vector.
    weights = np.asarray(weights, dtype=float)  # Convert feature weights to numeric values.
    return float(np.sqrt(np.sum(weights * (x - y) ** 2)))  # Return sqrt(sum_j w_j (x_j-y_j)^2).

def weighted_distances(X, q, weights):  # Compute weighted distances from many cases to one query.
    X = np.asarray(X, dtype=float)  # Convert the case matrix to floats.
    q = np.asarray(q, dtype=float)  # Convert the query vector to floats.
    weights = np.asarray(weights, dtype=float)  # Convert feature weights to floats.
    return np.sqrt(np.sum(weights * (X - q) ** 2, axis=1))  # Vectorized weighted distances.

def distance_to_similarity(d):  # Convert nonnegative distances into positive similarities.
    d = np.asarray(d, dtype=float)  # Convert distances to an array.
    return 1.0 / (1.0 + d)  # Nearby cases approach 1, far cases approach 0.

def knn_indices(X, q, weights, k):  # Retrieve k nearest cases under weighted distance.
    d = weighted_distances(X, q, weights)  # Compute all distances from query to case base.
    return np.argsort(d)[:k], d  # Return nearest indices and the full distance vector.

def weighted_average(values, weights):  # Average values with positive weights.
    values = np.asarray(values, dtype=float)  # Convert values to floats.
    weights = np.asarray(weights, dtype=float)  # Convert weights to floats.
    return float(np.sum(values * weights) / np.sum(weights)) if np.sum(weights) > 0 else float(np.mean(values))  # Normalize by total weight.

def adapt_linear(old_solution, old_x, new_x, slopes):  # Adapt a solution by a linear feature-difference rule.
    old_x = np.asarray(old_x, dtype=float)  # Convert old features to floats.
    new_x = np.asarray(new_x, dtype=float)  # Convert new features to floats.
    slopes = np.asarray(slopes, dtype=float)  # Convert adaptation slopes to floats.
    return float(old_solution + np.dot(slopes, new_x - old_x))  # Old solution plus slope-weighted feature change.
```

### Basic 9 — Adapt a copied solution

**Goal.** Adjust an old solution for the feature difference between old and new cases, because similar does not mean identical. We build it in 2 steps.
