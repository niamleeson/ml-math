# 7.25 — Optical Flow

Optical flow estimates a tiny motion vector for each pixel between two nearby video frames. In this lesson, we build the classical math from scratch: image gradients, brightness constancy, the aperture problem, Lucas-Kanade patch fitting, warping checks, and Horn-Schunck smoothness.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build optical flow one idea at a time. Run each cell in order and inspect the printed arrays and plots — every derivative, equation, and update is computed with NumPy so the motion field is not a black box. This walkthrough is self-contained and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays, gradients, linear algebra, and iterative updates.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
np.random.seed(0)  # reproducibility for small synthetic demos.
```

### 1. A flow field stores one vector per pixel

Optical flow is not one velocity for the whole image. It is a dense array whose last dimension stores horizontal motion `u` and vertical motion `v` at every pixel. A one-pixel rightward motion means every vector is `(u, v) = (1, 0)`, so the center vector tells us to compare frame 1 at `(y, x)` with frame 2 at `(y, x + 1)`.

```python
flow_w = np.zeros((3, 3, 2), dtype=float)  # 3 rows, 3 columns, and two motion components per pixel.
flow_w[..., 0] = 1.0  # horizontal component u = +1 everywhere.
print("flow shape:", flow_w.shape)
print("center vector (u,v):", flow_w[1, 1])
print("scalar entries:", flow_w.size)
assert flow_w.shape == (3, 3, 2) and flow_w.size == 18
```
▶ What you'll see: the flow tensor has 18 scalars; the center pixel stores `[1., 0.]` for rightward motion.

```python
Y_w, X_w = np.mgrid[0:3, 0:3]  # pixel grid for drawing arrows.
plt.figure(figsize=(3.6, 3.2))
plt.quiver(X_w, Y_w, flow_w[..., 0], flow_w[..., 1], angles="xy", scale_units="xy", scale=1, color="teal")
plt.gca().invert_yaxis(); plt.xticks(range(3)); plt.yticks(range(3))
plt.title("1: one-pixel rightward flow"); plt.xlabel("x column"); plt.ylabel("y row")
plt.show()
```
▶ What you'll see: every arrow points one cell to the right, with no vertical component.

*Why it's done this way:* images are indexed by rows and columns, but motion is usually written as `(u, v)` = `(horizontal, vertical)`. Keeping the two channels explicit prevents a silent convention bug where a rightward field is accidentally interpreted as downward motion.

### 2. Brightness constancy becomes a linear constraint

The classical assumption is that a small moving point keeps the same brightness: $I(x+u,y+v,t+1)\approx I(x,y,t)$. A first-order Taylor expansion gives $I_xu+I_yv+I_t=0$. This is a local line in the unknown motion `(u, v)`: the spatial gradients say which direction changes brightness, and the temporal derivative says how much brightness changed between frames.

```python
Ix_w, Iy_w, It_w = 2.0, 0.0, -2.0  # brightness grows with x, not y; frame 2 is shifted right.
u_w, v_w = 1.0, 0.0  # proposed rightward motion.
resid_w = Ix_w * u_w + Iy_w * v_w + It_w  # optical-flow constraint residual.
print("residual Ix*u + Iy*v + It:", resid_w)
assert resid_w == 0.0
```
▶ What you'll see: the residual is exactly zero for a one-pixel rightward motion.

```python
us_w = np.linspace(-1, 3, 81)
vs_w = np.linspace(-2, 2, 81)
UU_w, VV_w = np.meshgrid(us_w, vs_w)
res_grid_w = Ix_w * UU_w + Iy_w * VV_w + It_w
plt.figure(figsize=(4.2, 3.2))
plt.contour(UU_w, VV_w, res_grid_w, levels=[0], colors="crimson")
plt.scatter([u_w], [v_w], color="black", label="true (1,0)")
plt.title("2: brightness-constancy line"); plt.xlabel("u horizontal"); plt.ylabel("v vertical")
plt.legend(); plt.show()
```
▶ What you'll see: every point on the vertical line `u=1` satisfies the one-pixel equation because `Iy=0`.

*Why it's done this way:* the formula is a linearization of a nonlinear matching problem. It is useful because derivatives are cheap and local, but one equation cannot determine two velocity components; it only constrains motion along the image-gradient direction.

### 3. Gradients are computed from two frames

To use the constraint, we need $I_x$, $I_y$, and $I_t$. We approximate spatial derivatives with centered finite differences and temporal change with `frame2 - frame1`. On a synthetic ramp image shifted right by one pixel, the x-gradient is positive and the temporal derivative is negative where the same brightness arrives from the left.

```python
x_w = np.arange(6, dtype=float)
frame1_w = np.tile(x_w, (5, 1))  # horizontal ramp: intensity increases by 1 per column.
frame2_w = np.roll(frame1_w, shift=1, axis=1)  # content moves right by one pixel.
frame2_w[:, 0] = frame2_w[:, 1]  # avoid wraparound at the left boundary for the toy demo.
print("center row frame1:", frame1_w[2])
print("center row frame2:", frame2_w[2])
```
▶ What you'll see: the second row is the first row shifted right, except for the repaired boundary.

```python
Ix_img_w = np.zeros_like(frame1_w)
Ix_img_w[:, 1:-1] = (frame1_w[:, 2:] - frame1_w[:, :-2]) / 2.0
Iy_img_w = np.zeros_like(frame1_w)
Iy_img_w[1:-1, :] = (frame1_w[2:, :] - frame1_w[:-2, :]) / 2.0
It_img_w = frame2_w - frame1_w
print("Ix at center:", Ix_img_w[2, 3], "Iy at center:", Iy_img_w[2, 3], "It at center:", It_img_w[2, 3])
assert Ix_img_w[2, 3] == 1.0 and Iy_img_w[2, 3] == 0.0 and It_img_w[2, 3] == -1.0
```
▶ What you'll see: at the center, `Ix=1`, `Iy=0`, and `It=-1`, so `u=1` gives zero residual.

```python
fig, ax = plt.subplots(1, 3, figsize=(8, 2.6))
for a_w, M_w, title_w in zip(ax, [Ix_img_w, Iy_img_w, It_img_w], ["Ix", "Iy", "It"]):
    im_w = a_w.imshow(M_w, cmap="coolwarm", vmin=-1, vmax=1)
    a_w.set_title(title_w); a_w.set_xticks([]); a_w.set_yticks([])
fig.colorbar(im_w, ax=ax, shrink=0.75); plt.suptitle("3: finite-difference derivatives"); plt.show()
```
▶ What you'll see: `Ix` is bright in the interior, `Iy` is near zero, and `It` is negative where the ramp shifted right.

*Why it's done this way:* finite differences approximate the derivatives in the Taylor expansion. The derivative model only makes sense when the displacement is small enough that a local slope describes how intensity changes between neighboring pixels.

### 4. A single edge has the aperture problem

If `Iy=0`, the equation $2u-2=0$ fixes `u=1` but says nothing about `v`. That is the aperture problem: through a tiny window looking at a straight vertical edge, motion along the edge is invisible because brightness does not change in that direction.

```python
candidates_w = np.array([[1.0, 0.0], [1.0, 5.0], [1.0, -3.0], [0.0, 0.0]])
resids_w = Ix_w * candidates_w[:, 0] + Iy_w * candidates_w[:, 1] + It_w
print("candidate (u,v) and residual:")
for vec_w, r_w in zip(candidates_w, resids_w):
    print(vec_w, "->", r_w)
assert np.all(resids_w[:3] == 0.0)
```
▶ What you'll see: three different vertical velocities all satisfy the same one-pixel equation.

```python
plt.figure(figsize=(4.2, 3.2))
plt.scatter(candidates_w[:, 0], candidates_w[:, 1], c=resids_w, cmap="coolwarm", s=80)
plt.axvline(1.0, color="gray", linestyle="--")
plt.colorbar(label="constraint residual")
plt.title("4: many velocities fit one edge pixel"); plt.xlabel("u"); plt.ylabel("v")
plt.show()
```
▶ What you'll see: the zero-residual candidates lie on the same `u=1` line even though their vertical motions differ.

*Why it's done this way:* the gradient vector is perpendicular to the edge, so the equation only measures motion projected onto that gradient. Motion tangent to the edge changes no brightness locally, so the data cannot identify it without extra assumptions.

### 5. Lucas-Kanade solves a patch of equations

Lucas-Kanade adds a local-constant-flow assumption: nearby pixels in a small patch share the same `(u, v)`. Stacking their equations gives $A [u,v]^T \approx b$, where rows of `A` are `[Ix, Iy]` and `b=-It`. If the patch contains differently oriented gradients, least squares can recover both components.

```python
A_w = np.array([[2.0, 0.0], [0.0, 3.0], [2.0, 3.0], [1.0, 1.0]])  # gradients from four nearby pixels.
true_uv_w = np.array([1.0, 1.0])
b_w = A_w @ true_uv_w  # equals -It for a patch moving by (1,1).
print("A matrix:\n", A_w)
print("b = -It:", b_w)
```
▶ What you'll see: the patch provides multiple independent constraints, not just one edge equation.

```python
uv_lk_w, *_ = np.linalg.lstsq(A_w, b_w, rcond=None)
normal_w = A_w.T @ A_w
print("Lucas-Kanade estimate:", np.round(uv_lk_w, 3))
print("normal matrix determinant:", round(float(np.linalg.det(normal_w)), 3))
assert np.allclose(uv_lk_w, [1.0, 1.0])
```
▶ What you'll see: least squares recovers `(1,1)`, and the normal matrix has nonzero determinant.

```python
plt.figure(figsize=(4, 3.2))
plt.scatter(A_w[:, 0], A_w[:, 1], color="teal")
for k_w, row_w in enumerate(A_w):
    plt.text(row_w[0] + 0.05, row_w[1], f"p{k_w}")
plt.title("5: patch gradients span 2-D motion"); plt.xlabel("Ix"); plt.ylabel("Iy")
plt.show()
```
▶ What you'll see: the gradient points are not all on one line, which is why the two motion components become identifiable.

*Why it's done this way:* least squares finds the velocity that minimizes the sum of squared brightness-constancy residuals over a patch. The method works only when $A^TA$ is well-conditioned; otherwise the patch is just another aperture-problem edge.

### 6. Warping tests whether the flow reconstructs brightness

A flow field is useful because it can be checked by reconstruction: take each pixel in frame 1, move by `(u, v)`, sample frame 2, and compare brightness. Here we implement nearest-neighbor warping from scratch and verify that the center pixel with rightward flow samples the value one column to the right.

```python
frameA_w = np.arange(9, dtype=float).reshape(3, 3)
frameB_w = np.roll(frameA_w, shift=1, axis=1)  # content moves one column right, so sampling x+1 reconstructs frameA.
frameB_w[:, 0] = frameA_w[:, 0]
y_w, x_w = 1, 1
sample_x_w = int(round(x_w + flow_w[y_w, x_w, 0]))
sample_y_w = int(round(y_w + flow_w[y_w, x_w, 1]))
print("frameA center:", frameA_w[y_w, x_w], "sampled frameB:", frameB_w[sample_y_w, sample_x_w])
assert frameA_w[y_w, x_w] == frameB_w[sample_y_w, sample_x_w]
```
▶ What you'll see: the center value in frame 1 equals the value sampled from frame 2 at `(x+1,y)`.

```python
warped_w = np.zeros_like(frameA_w)
for yy_w in range(frameA_w.shape[0]):
    for xx_w in range(frameA_w.shape[1]):
        sx_w = int(np.clip(round(xx_w + flow_w[yy_w, xx_w, 0]), 0, frameA_w.shape[1] - 1))
        sy_w = int(np.clip(round(yy_w + flow_w[yy_w, xx_w, 1]), 0, frameA_w.shape[0] - 1))
        warped_w[yy_w, xx_w] = frameB_w[sy_w, sx_w]
err_w = warped_w - frameA_w
print("warped frame:\n", warped_w)
print("photometric SSE:", float(np.sum(err_w ** 2)))
```
▶ What you'll see: most pixels reconstruct perfectly; boundary clipping creates the only possible mismatch.

```python
fig, ax = plt.subplots(1, 3, figsize=(8, 2.6))
for a_w, M_w, title_w in zip(ax, [frameA_w, warped_w, err_w], ["frame 1", "warped frame 2", "error"]):
    a_w.imshow(M_w, cmap="viridis"); a_w.set_title(title_w); a_w.set_xticks([]); a_w.set_yticks([])
plt.suptitle("6: warping checks the flow field"); plt.show()
```
▶ What you'll see: the error image is near zero except where boundary information is missing.

*Why it's done this way:* brightness constancy is not only a training equation; it is a test. If the flow is correct and the pixel is not occluded, sampling the second frame along the vector should reproduce the first frame.

### 7. Horn-Schunck adds global smoothness

Horn-Schunck resolves ambiguity by asking for a flow field that both satisfies brightness constancy and varies smoothly across neighbors. Each iteration averages neighboring flow, then applies a correction along the local gradient. This spreads motion from textured regions into ambiguous nearby regions while still respecting the derivative constraint.

```python
Ix_hs_w = np.ones((5, 5))  # every pixel has a horizontal brightness gradient.
Iy_hs_w = np.zeros((5, 5))
It_hs_w = -np.ones((5, 5))  # rightward unit motion should satisfy Ix*u + It = 0.
u_hs_w = np.zeros((5, 5)); v_hs_w = np.zeros((5, 5))
alpha_w = 1.0
print("initial mean flow:", float(u_hs_w.mean()), float(v_hs_w.mean()))
```
▶ What you'll see: Horn-Schunck starts from zero flow everywhere.

```python
def avg4_w(M_w):
    P_w = np.pad(M_w, 1, mode="edge")
    return (P_w[:-2, 1:-1] + P_w[2:, 1:-1] + P_w[1:-1, :-2] + P_w[1:-1, 2:]) / 4.0

for iter_w in range(40):
    ubar_w = avg4_w(u_hs_w); vbar_w = avg4_w(v_hs_w)
    residual_w = Ix_hs_w * ubar_w + Iy_hs_w * vbar_w + It_hs_w
    denom_w = alpha_w ** 2 + Ix_hs_w ** 2 + Iy_hs_w ** 2
    u_hs_w = ubar_w - Ix_hs_w * residual_w / denom_w
    v_hs_w = vbar_w - Iy_hs_w * residual_w / denom_w
print("final mean u:", round(float(u_hs_w.mean()), 3), "final mean v:", round(float(v_hs_w.mean()), 3))
assert abs(float(u_hs_w.mean()) - 1.0) < 1e-3
```
▶ What you'll see: the mean horizontal flow converges to about 1, while vertical flow stays 0.

```python
plt.figure(figsize=(3.8, 3.2))
plt.imshow(u_hs_w, cmap="viridis", vmin=0, vmax=1); plt.colorbar(label="u")
plt.title("7: Horn-Schunck smooth u field"); plt.xticks([]); plt.yticks([]); plt.show()
```
▶ What you'll see: a smooth field of horizontal motion close to one pixel everywhere.

*Why it's done this way:* the data term alone is underdetermined at many pixels. Smoothness is a prior: neighboring points on the same surface often move similarly, so averaging stabilizes the solution while the gradient correction pulls it back toward brightness constancy.

### Basic 8 — Run least squares for an overdetermined patch

```python
true_left_a5 = np.array([1.0, 0.0]); true_right_a5 = np.array([0.0, 1.0]) # Define two different motions across a boundary.
grads_a5 = rng_a5.normal(size=(25, 2)) # Create mixed gradient directions for a 5x5 neighborhood.
grads_a5[:, 0] += 1.0 # Bias gradients to avoid tiny normal matrices.
print("gradient matrix shape:", grads_a5.shape) # Inspect available patch equations.
```
▶ What you'll see: there are 25 possible local equations around the target.

```python
motions_a5 = np.vstack([np.repeat(true_left_a5[None, :], 13, axis=0), np.repeat(true_right_a5[None, :], 12, axis=0)]) # Assign two motions to neighboring pixels.
b_a5 = np.sum(grads_a5 * motions_a5, axis=1) + rng_a5.normal(0, 0.03, size=25) # Build noisy -It values from mixed motions.
small_idx_a5 = np.arange(9) # Treat first 9 equations as a small mostly-left patch.
large_idx_a5 = np.arange(25) # Treat all equations as a large patch crossing the boundary.
print("small patch count:", len(small_idx_a5), "large patch count:", len(large_idx_a5)) # Inspect patch sizes.
```
▶ What you'll see: the large patch uses almost three times as many equations and crosses a motion boundary.

```python
uv_small_a5, *_ = np.linalg.lstsq(grads_a5[small_idx_a5], b_a5[small_idx_a5], rcond=None) # Fit the smaller local patch.
uv_large_a5, *_ = np.linalg.lstsq(grads_a5[large_idx_a5], b_a5[large_idx_a5], rcond=None) # Fit the larger mixed-motion patch.
print("small patch estimate:", np.round(uv_small_a5, 3)) # Inspect local estimate.
print("large patch estimate:", np.round(uv_large_a5, 3)) # Inspect mixed estimate.
assert np.linalg.norm(uv_small_a5 - true_left_a5) < np.linalg.norm(uv_large_a5 - true_left_a5) # Verify boundary blurring.
```
▶ What you'll see: the small patch stays closer to the left motion, while the large patch averages across motions.
