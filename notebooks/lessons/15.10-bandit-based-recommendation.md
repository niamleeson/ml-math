# 15.10 · Bandit-based Recommendation

Bandit-based recommendation turns ranking into online decision-making: recommend an item, observe a reward such as a click, and update the policy immediately. In this lesson, each arm is an item with an unknown reward probability, so the recommender must trade short-term exploitation against deliberate exploration.

### 1. The explore/exploit dilemma and regret

A bandit recommender repeatedly chooses one item (an **arm**) and sees only that arm's reward. Exploitation means choosing the item that currently looks best; exploration means trying uncertain items so the system can discover better long-term choices. The cost of learning is **regret**: if the best arm has mean reward $\mu^*$ and we choose arms with means $\mu_{a_t}$, then instantaneous regret is $\mu^*-\mu_{a_t}$ and cumulative regret is

$$R_T=\sum_{t=1}^{T}(\mu^*-\mu_{a_t}).$$

Regret is not "the model feels sorry"; it is the reward gap between what we got and what an oracle that always knew the best arm would have gotten. It makes exploration cost visible while still allowing exploration to be useful later.

```python
true_means_w = np.array([0.05, 0.08, 0.04, 0.10, 0.08])  # reward probability of the arm chosen on each round.
best_mean_w = 0.10  # oracle expected reward if it always chose the best arm.
inst_regret_w = best_mean_w - true_means_w  # per-round regret gap.
cum_regret_w = np.cumsum(inst_regret_w)  # cumulative regret over time.
print("instant regret:", np.round(inst_regret_w, 3))  # [0.05, 0.02, 0.06, 0.00, 0.02].
print("cumulative regret:", np.round(cum_regret_w, 3))  # content-grounded sequence.
assert np.allclose(np.round(cum_regret_w, 2), [0.05, 0.07, 0.13, 0.13, 0.15])  # lesson number.
```
▶ What you'll see: choosing weaker arms raises cumulative regret, while choosing the best arm leaves it flat.

```python
rng_w = np.random.default_rng(1)  # local generator for a single Bernoulli arm.
p_w, n_w, clicks_w = 0.08, 10, 0  # unknown click rate, trials so far, successes so far.
reward_w = int(rng_w.random() < p_w)  # pull the arm once and observe a click/non-click.
clicks_new_w, n_new_w = clicks_w + reward_w, n_w + 1  # update sufficient statistics.
mean_new_w = clicks_new_w / n_new_w  # empirical mean after the pull.
print("reward:", reward_w, "updated clicks/n:", clicks_new_w, "/", n_new_w)
print("updated empirical mean:", round(mean_new_w, 3))
assert reward_w == 0 and round(mean_new_w, 3) == 0.000  # seeded Bernoulli update.
```
▶ What you'll see: one no-click keeps the empirical click-rate estimate at 0, but also increases the evidence count.

```python
plt.figure(figsize=(4.5, 3))  # visualize regret accumulation.
plt.step(np.arange(1, len(cum_regret_w) + 1), cum_regret_w, where="mid", color="crimson")
plt.xlabel("round"); plt.ylabel("cumulative regret")
plt.title("1: regret is the cost of learning"); plt.show()
```
▶ What you'll see: regret climbs when the policy tries suboptimal arms and pauses when it selects the best arm.

*Why it's done this way: recommendation logs reveal only the item shown, so a bandit must sometimes spend reward to buy information; regret is the common currency for that spend.*

### 2. \epsilon-greedy recommendation

The simplest policy is $\epsilon$-greedy: with probability $1-\epsilon$, exploit the current best estimated arm, and with probability $\epsilon$, choose uniformly at random. For $K$ arms, every arm receives exploration probability $\epsilon/K$, and the current best arm receives that plus the exploitation mass. This is easy to reason about, but its exploration is blind: it may waste traffic on arms that are already well understood to be bad.

```python
values_w = np.array([0.05, 0.08, 0.04])  # current estimated reward of A, B, C.
eps_w = 0.20  # exploration rate.
K_w = len(values_w)  # number of arms.
best_w = int(np.argmax(values_w))  # greedy arm index.
probs_w = np.ones(K_w) * eps_w / K_w  # exploration mass spread uniformly.
probs_w[best_w] += 1 - eps_w  # exploitation mass goes to the current best arm.
print("epsilon-greedy probabilities:", np.round(probs_w, 3))
assert np.allclose(np.round(probs_w, 3), [0.067, 0.867, 0.067])  # content numbers.
```
▶ What you'll see: arm B gets about 0.867 probability; A and C still get 0.067 each for exploration.

```python
rng_w = np.random.default_rng(2)  # reproducible arm draw.
drawn_w = int(rng_w.choice(K_w, p=probs_w))  # sample an arm from the policy distribution.
print("drawn arm index:", drawn_w, "probability used:", round(probs_w[drawn_w], 3))
assert drawn_w == 1  # seeded draw chooses the greedy arm.
```
▶ What you'll see: the policy usually exploits B, but the distribution still leaves room for A or C.

```python
plt.figure(figsize=(4.5, 3))  # show action probabilities.
plt.bar(["A", "B", "C"], probs_w, color=["gray", "seagreen", "gray"])
plt.ylabel("selection probability"); plt.ylim(0, 1)
plt.title("2: epsilon-greedy mixes exploit + random explore"); plt.show()
```
▶ What you'll see: a tall bar for B plus small equal bars for all arms.

*Why it's done this way: $\epsilon$-greedy guarantees every eligible item gets some exposure, which helps cold-start discovery, but it does not aim exploration toward the most uncertain items.*

### 3. UCB (upper confidence bound — optimism under uncertainty)

Upper Confidence Bound (UCB) explores by adding an uncertainty bonus to each empirical mean:

$$a_t=\arg\max_a\left(\hat\mu_a+\sqrt{\frac{2\ln t}{n_a}}\right).$$

The bonus $\sqrt{\frac{2\ln t}{n_a}}$ is large when an arm has few pulls $n_a$ and shrinks as evidence accumulates. The $\ln t$ term lets uncertainty grow slowly with time, so an arm not tried for a long while can become worth checking again.

```python
means_w = np.array([0.05, 0.08, 0.04])  # empirical reward estimates.
pulls_w = np.array([100, 20, 5])  # how much evidence each arm has.
t_w = 125  # current round count.
bonus_w = np.sqrt(2 * np.log(t_w) / np.maximum(pulls_w, 1))  # UCB bonus with /0 guard.
scores_w = means_w + bonus_w  # optimistic score.
print("bonuses:", np.round(bonus_w, 3))
print("UCB scores:", np.round(scores_w, 3), "pick:", int(np.argmax(scores_w)))
assert np.allclose(np.round(bonus_w, 3), [0.311, 0.695, 1.390])  # content numbers.
assert np.allclose(np.round(scores_w, 3), [0.361, 0.775, 1.430])  # content numbers.
```
▶ What you'll see: arm C has the lowest mean but the highest UCB score because it has only five pulls.

```python
plt.figure(figsize=(4.8, 3))  # show mean and uncertainty bonus stacked.
plt.bar(["A", "B", "C"], means_w, label="mean", color="steelblue")
plt.bar(["A", "B", "C"], bonus_w, bottom=means_w, label="UCB bonus", color="orange", alpha=.75)
plt.ylabel("optimistic score"); plt.legend()
plt.title("3: UCB is optimism under uncertainty"); plt.show()
```
▶ What you'll see: C wins because its uncertainty stack is largest, not because its observed mean is best.

*Why it's done this way: UCB turns uncertainty into a concrete bonus, so exploration is justified by lack of evidence rather than by undirected randomness.*

### 4. Thompson sampling (Beta-Bernoulli posterior sampling)

For click/no-click rewards, a Bernoulli arm with a Beta prior is conjugate: after $s$ successes and $f$ failures, the posterior is $\mathrm{Beta}(\alpha+s,\beta+f)$. With a uniform prior $\alpha=\beta=1$, the posterior mean is $(s+1)/(s+f+2)$. Thompson sampling draws one plausible click rate from each posterior and chooses the arm with the largest draw, so uncertain arms win often exactly when their posterior still has plausible high values.

```python
successes_w = np.array([5, 8, 1])  # clicks for A, B, C.
failures_w = np.array([95, 92, 19])  # non-clicks for A, B, C.
alpha_w = 1 + successes_w  # Beta posterior alpha.
beta_w = 1 + failures_w  # Beta posterior beta.
post_mean_w = alpha_w / (alpha_w + beta_w)  # posterior mean click probability.
print("posterior alpha:", alpha_w, "beta:", beta_w)
print("posterior means:", np.round(post_mean_w, 3))
assert np.allclose(np.round(post_mean_w, 3), [0.059, 0.088, 0.091])  # content numbers.
```
▶ What you'll see: C has the largest posterior mean even with few clicks because its denominator is much smaller.

```python
rng_w = np.random.default_rng(3)  # reproducible Thompson draw.
samples_w = rng_w.beta(alpha_w, beta_w)  # one plausible CTR sample per arm.
choice_w = int(np.argmax(samples_w))  # choose the largest sampled rate.
print("Thompson samples:", np.round(samples_w, 3), "pick:", choice_w)
assert np.allclose(np.round(samples_w, 3), [0.108, 0.090, 0.036]) and choice_w == 0  # seeded sample.
```
▶ What you'll see: A wins this sampled round, while C will still sometimes win on other random posterior draws.

```python
plt.figure(figsize=(5, 3))  # plot sampled posterior clouds instead of requiring scipy.
for a_w, b_w, name_w in zip(alpha_w, beta_w, ["A", "B", "C"]):
    draws_w = rng_w.beta(a_w, b_w, size=1200)  # approximate the posterior shape.
    plt.hist(draws_w, bins=35, density=True, alpha=.35, label=name_w)
plt.xlabel("click probability"); plt.ylabel("posterior density")
plt.legend(); plt.title("4: Thompson samples from uncertainty"); plt.show()
```
▶ What you'll see: C's distribution is wider, so it can occasionally sample above better-known arms.

*Why it's done this way: posterior sampling balances explore/exploit automatically — high-mean arms win often, but uncertain arms win in proportion to how plausible it is that they are actually best.*

### 5. Contextual bandits (LinUCB-style, action value depends on context features)

Non-contextual bandits learn one reward estimate per item. A contextual bandit also observes user or request features $x_t$, so the value of arm $a$ is $x_t^\top\theta_a$ and the best arm can change by context. A LinUCB-style policy fits a small linear model per arm and adds an uncertainty bonus, letting the recommender choose different items for different users while still exploring uncertain feature regions.

```python
contexts_w = np.array([[1., 0.], [0., 1.], [1., 1.]])  # three user contexts: feature 0, feature 1, both.
theta_w = np.array([[0.10, 0.02], [0.03, 0.12]])  # arm-specific linear reward weights.
values_ctx_w = contexts_w @ theta_w.T  # rows=context, columns=arm score.
print("contextual values:\n", np.round(values_ctx_w, 3))
print("best arm per context:", np.argmax(values_ctx_w, axis=1))
assert np.allclose(np.round(values_ctx_w, 3), [[0.10, 0.03], [0.02, 0.12], [0.12, 0.15]])
```
▶ What you'll see: arm 0 is best for feature-0 users, arm 1 is best for feature-1 and mixed users.

```python
Ainv_w = np.array([np.eye(2) / 5, np.eye(2) / 2])  # arm 1 is less certain because its inverse design is larger.
alpha_ctx_w = 0.2  # exploration multiplier.
x_w = np.array([1., 1.])  # the current request context.
mean_ctx_w = theta_w @ x_w  # linear predictions for the current context.
bonus_ctx_w = np.array([alpha_ctx_w * np.sqrt(x_w @ Ainv_w[a] @ x_w) for a in range(2)])  # LinUCB bonus.
score_ctx_w = mean_ctx_w + bonus_ctx_w  # optimistic contextual score.
print("means:", np.round(mean_ctx_w, 3), "bonuses:", np.round(bonus_ctx_w, 3))
print("LinUCB scores:", np.round(score_ctx_w, 3), "pick:", int(np.argmax(score_ctx_w)))
assert np.allclose(np.round(bonus_ctx_w, 3), [0.126, 0.200])
```
▶ What you'll see: the arm score depends on the current user features, and uncertainty can change the final choice.

```python
plt.figure(figsize=(4.8, 3))  # visualize context-specific arm values.
plt.imshow(values_ctx_w, cmap="viridis", aspect="auto")
plt.colorbar(label="predicted reward")
plt.xticks([0, 1], ["arm 0", "arm 1"]); plt.yticks([0, 1, 2], ["x=[1,0]", "x=[0,1]", "x=[1,1]"])
plt.title("5: contextual values change by user features"); plt.show()
```
▶ What you'll see: the preferred arm is not globally fixed; it changes with the context row.

*Why it's done this way: recommendation quality often depends on who is asking, so contextual bandits share statistical strength through features instead of learning isolated global CTRs.*

## Setup

```python
# !pip install numpy matplotlib  # Colab already has these; uncomment only if your runtime is missing them.
import numpy as np  # Import NumPy for arrays, Bernoulli rewards, Beta draws, and vectorized simulation.
import matplotlib.pyplot as plt  # Import Matplotlib for bar charts and regret curves used to debug bandit policies.
np.random.seed(0)  # Fix the global seed so every stochastic example is repeatable.

def bernoulli_reward(p, rng):  # Draw a binary reward from a click probability.
    return int(rng.random() < p)  # Return 1 for click/success and 0 for no-click/failure.

def safe_mean(successes, pulls):  # Compute empirical means without dividing by zero.
    successes = np.asarray(successes, dtype=float)  # Convert successes to a float array.
    pulls = np.asarray(pulls, dtype=float)  # Convert pull counts to a float array.
    return np.divide(successes, pulls, out=np.zeros_like(successes), where=pulls > 0)  # Use 0 until an arm has evidence.

def epsilon_probs(values, epsilon):  # Convert value estimates into epsilon-greedy probabilities.
    values = np.asarray(values, dtype=float)  # Ensure argmax and length are predictable.
    k = len(values)  # Count arms.
    probs = np.ones(k) * epsilon / k  # Spread exploration mass uniformly.
    probs[int(np.argmax(values))] += 1 - epsilon  # Add exploitation mass to the current best arm.
    return probs  # Return one probability per arm.

def ucb_scores(means, pulls, t):  # Compute UCB scores with guards for new arms.
    means = np.asarray(means, dtype=float)  # Convert means to floats.
    pulls = np.asarray(pulls, dtype=float)  # Convert counts to floats.
    t = max(float(t), 2.0)  # Guard log so early rounds remain finite.
    bonus = np.where(pulls > 0, np.sqrt(2 * np.log(t) / np.maximum(pulls, 1)), np.inf)  # Unpulled arms get priority.
    return means + bonus, bonus  # Return both score and bonus for inspection.

def beta_params(successes, failures, alpha0=1, beta0=1):  # Update a Beta prior with Bernoulli data.
    return alpha0 + np.asarray(successes), beta0 + np.asarray(failures)  # Posterior alpha and beta.

def cumulative_regret(best_mean, chosen_means):  # Convert chosen arm means into cumulative regret.
    return np.cumsum(best_mean - np.asarray(chosen_means, dtype=float))  # Sum per-round reward gaps.
```

## 🟢 Basics

#### B1. Pull a Bernoulli recommendation arm

**Goal.** Simulate one item impression and observe a click/no-click reward, because bandits learn from the reward of the arm they actually chose. We build it in 2 steps.

```python
rng_b1 = np.random.default_rng(10)  # Create a reproducible generator for this example.
p_b1 = 0.30  # Set the unknown click probability of a toy item.
reward_b1 = bernoulli_reward(p_b1, rng_b1)  # Pull the arm once and observe a binary reward.
print("observed reward:", reward_b1)  # Inspect whether this impression clicked.
assert reward_b1 == 0  # Seeded draw is a no-click.
```
▶ What you'll see: one binary reward, reminding you that feedback is noisy even when the true click rate is 0.30.

```python
plt.figure(figsize=(4, 3))  # Start a compact bar chart.
plt.bar(["no click", "click"], [1 - p_b1, p_b1], color=["gray", "seagreen"])  # Show Bernoulli probabilities.
plt.ylabel("probability"); plt.ylim(0, 1)
plt.title("B1: Bernoulli reward model"); plt.show()  # Display the reward distribution.
```
▶ What you'll see: most pulls do not click, so single observations are weak evidence.

👀 Takeaway: a bandit sees only a noisy reward from the item it selected.

#### B2. Update an empirical mean

**Goal.** Update clicks, pulls, and estimated click rate after a new reward, because simple bandits summarize each arm by counts. We build it in 2 steps.

```python
clicks_b2, pulls_b2 = 3, 20  # Store current successes and impressions for one arm.
reward_b2 = 1  # New impression clicked.
clicks_new_b2 = clicks_b2 + reward_b2  # Add the new success.
pulls_new_b2 = pulls_b2 + 1  # Add the new impression.
mean_new_b2 = clicks_new_b2 / pulls_new_b2  # Compute the updated empirical CTR.
print("old mean:", round(clicks_b2 / pulls_b2, 3), "new mean:", round(mean_new_b2, 3))
assert round(mean_new_b2, 3) == 0.190  # 4/21.
```
▶ What you'll see: one click moves the estimate from 0.150 to 0.190.

```python
plt.figure(figsize=(4, 3))  # Compare old and new means.
plt.bar(["before", "after"], [clicks_b2 / pulls_b2, mean_new_b2], color=["gray", "steelblue"])
plt.ylabel("empirical CTR"); plt.ylim(0, .25)
plt.title("B2: update the arm mean"); plt.show()
```
▶ What you'll see: the estimate changes, but only modestly because 20 prior pulls already existed.

👀 Takeaway: each arm's empirical mean is just successes divided by pulls, updated online.


▶ What you'll see: a smooth decline, not an abrupt switch from exploration to exploitation.

👀 Takeaway: decay schedules spend exploration budget early while preserving some future discovery.

#### B9. Pick by context-specific value

**Goal.** Score arms for two different contexts, because contextual bandits can recommend different items to different users. We build it in 2 steps.

```python
theta_b9 = np.array([[0.10, 0.02], [0.03, 0.12]])  # Arm-specific linear weights.

values_b9 = contexts_b9 @ theta_b9.T  # Predicted reward for each context-arm pair.

assert np.allclose(np.round(values_b9, 3), [[0.10, 0.03], [0.02, 0.12]])
```
