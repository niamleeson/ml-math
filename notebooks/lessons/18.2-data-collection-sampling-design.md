# 18.2 — Data Collection & Sampling Design

Sampling design decides what population a dataset is allowed to represent. In this lesson, we build toy populations directly in NumPy, then compare simple random sampling, biased collection, stratification, clustering, and sample-size planning so the first modeling assumption — *who got into the data* — is visible before any model is trained.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build data collection and sampling design one idea at a time. Run each cell in order and read the printed intermediate values — every piece of math is spelled out so the sampling assumptions are never hidden. This walkthrough is self-contained and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays, random sampling, and direct weighted arithmetic.
import matplotlib.pyplot as plt  # visual checks for populations, samples, and uncertainty.
np.random.seed(0)  # reproducibility for all walkthrough draws.
```

### 1. Target population, sampling frame, and the population rate

Data collection starts by naming the **target population**: the real set you want statements about. A **sampling frame** is the list you can actually draw from. If important people are absent from the frame, no random algorithm can sample them. We will use two groups: group A has many quiet users with a low positive rate, and group B has fewer power users with a high positive rate.

```python
N_A_w, N_B_w = 800, 200  # target population group sizes.
p_A_w, p_B_w = 0.20, 0.70  # true positive rates inside each group.
N_w = N_A_w + N_B_w  # total target population size.
weights_w = np.array([N_A_w / N_w, N_B_w / N_w])  # target mixture weights.
print("target weights A,B:", weights_w)  # [0.8, 0.2].
print("group rates A,B:", [p_A_w, p_B_w])  # [0.2, 0.7].
assert np.allclose(weights_w, [0.8, 0.2])  # concrete target mixture.
```
▶ What you'll see: group A is 80% of the population and group B is 20%, but B has a much higher rate.

```python
pop_rate_w = weights_w[0] * p_A_w + weights_w[1] * p_B_w  # weighted average over groups.
count_pos_w = N_A_w * p_A_w + N_B_w * p_B_w  # equivalent positive-count calculation.
print("weighted population rate:", round(pop_rate_w, 3))  # 0.300.
print("positive-count rate:", round(count_pos_w / N_w, 3))  # 300/1000.
assert round(pop_rate_w, 3) == 0.300  # lesson number.
```
▶ What you'll see: the population rate is not the plain average of 0.2 and 0.7; it is the group-size weighted average 0.300.

```python
plt.figure(figsize=(4.4, 3))
plt.bar(["A weight", "B weight"], weights_w, color=["steelblue", "darkorange"])
plt.axhline(pop_rate_w, color="black", linestyle="--", label="population rate")
plt.ylim(0, 1); plt.ylabel("fraction"); plt.title("1: population mixture before sampling")
plt.legend(); plt.show()
```
▶ What you'll see: the 80/20 mixture is the target distribution; the dashed line reminds us that the final rate is a mixture-weighted quantity.

*Why it's done this way: a dataset estimates a population functional, and here the functional is $p=\sum_g (N_g/N)p_g$; writing the group weights first prevents us from accidentally replacing the target population with whichever rows were easiest to collect.*

### 2. Simple random sampling: probability sampling and standard error

In a **simple random sample**, every individual in the sampling frame has the same chance of selection. That makes the sample mean fluctuate around the population rate rather than around a distorted mixture. The fluctuation is random error, summarized for a binomial rate by

$$SE=\sqrt{\frac{p(1-p)}{n}}.$$

The numerator $p(1-p)$ is largest near uncertain 50/50 outcomes and smaller near 0 or 1; the denominator $n$ says averaging more independent draws reduces variance.

```python
labels_w = np.r_[np.ones(int(N_A_w * p_A_w)), np.zeros(N_A_w - int(N_A_w * p_A_w)),
                 np.ones(int(N_B_w * p_B_w)), np.zeros(N_B_w - int(N_B_w * p_B_w))]  # exact finite population labels.
groups_w = np.r_[np.repeat("A", N_A_w), np.repeat("B", N_B_w)]  # group label for each individual.
print("population size:", len(labels_w), "population mean:", round(labels_w.mean(), 3))
assert round(labels_w.mean(), 3) == 0.300  # exact constructed population rate.
```
▶ What you'll see: the synthetic population has 1,000 people and exactly 30% positives.

```python
n_w = 100  # sample size for one simple random sample.
idx_srs_w = np.random.choice(N_w, size=n_w, replace=False)  # equal probability without replacement.
sample_rate_w = labels_w[idx_srs_w].mean()  # sample estimate.
sample_B_share_w = np.mean(groups_w[idx_srs_w] == "B")  # realized group-B fraction.
print("SRS estimate:", round(sample_rate_w, 3), "B share:", round(sample_B_share_w, 3))
assert len(np.unique(idx_srs_w)) == n_w  # without replacement means no duplicated people.
```
▶ What you'll see: one simple random sample lands near, but not exactly on, the population rate because of chance.

```python
se_w = np.sqrt(pop_rate_w * (1 - pop_rate_w) / n_w)  # binomial standard error approximation.
half95_w = 1.96 * se_w  # normal-approximate 95% half-width.
print("SE at p=0.300,n=100:", round(se_w, 4))
print("approx 95% half-width:", round(half95_w, 4))
assert round(se_w, 4) == 0.0458 and round(half95_w, 4) == 0.0898
```
▶ What you'll see: the expected random wiggle at n=100 is about 0.046, so a 95% interval is roughly ±0.090.

```python
plt.figure(figsize=(4.6, 3))
plt.bar(["population", "one SRS"], [pop_rate_w, sample_rate_w], color=["gray", "seagreen"])
plt.errorbar([0], [pop_rate_w], yerr=[half95_w], fmt="none", ecolor="black", capsize=5, label="±1.96 SE")
plt.ylim(0, 0.5); plt.ylabel("positive rate"); plt.title("2: SRS varies around the target")
plt.legend(); plt.show()
```
▶ What you'll see: the sample bar is a noisy estimate of the population bar, not a new target.

*Why it's done this way: equal-probability sampling turns collection noise into a quantifiable estimator variance; the square-root formula explains why quadrupling n halves SE rather than quartering it.*

### 3. Sampling bias: the wrong mixture is centered on the wrong answer

A biased sample is not merely noisy. If the collection process over-captures group A and under-captures group B, the estimator is centered on the rate of that **sample mixture**, not the target population. More rows shrink random error around the wrong center.

```python
biased_weights_w = np.array([0.90, 0.10])  # sample design overrepresents group A and underrepresents group B.
biased_center_w = biased_weights_w[0] * p_A_w + biased_weights_w[1] * p_B_w  # expected rate under biased mixture.
print("target mixture rate:", round(pop_rate_w, 3))
print("biased 90/10 mixture rate:", round(biased_center_w, 3))
assert round(biased_center_w, 3) == 0.250  # (90*0.2 + 10*0.7)/100.
```
▶ What you'll see: changing only the group weights moves the expected estimate from 0.300 to 0.250.

```python
biased_A_w = np.random.choice(np.where(groups_w == "A")[0], size=90, replace=False)  # 90 A users.
biased_B_w = np.random.choice(np.where(groups_w == "B")[0], size=10, replace=False)  # 10 B users.
idx_bias_w = np.r_[biased_A_w, biased_B_w]  # biased sample of size 100.
rate_bias_w = labels_w[idx_bias_w].mean()  # realized biased estimate.
print("realized biased estimate:", round(rate_bias_w, 3))
print("realized B share:", round(np.mean(groups_w[idx_bias_w] == "B"), 3))
assert len(idx_bias_w) == 100 and np.mean(groups_w[idx_bias_w] == "B") == 0.10
```
▶ What you'll see: the collected data has exactly a 90/10 mixture, so it is allowed to estimate only that mixture well.

```python
plt.figure(figsize=(4.8, 3))
plt.bar(["target 80/20", "biased 90/10"], [pop_rate_w, biased_center_w], color=["seagreen", "crimson"])
plt.ylabel("expected estimate"); plt.ylim(0, 0.4); plt.title("3: bias shifts the center")
plt.show()
```
▶ What you'll see: the biased bar is systematically lower, not just a noisier version of the target bar.

*Why it's done this way: the estimator is a weighted average, so wrong weights create systematic error $\sum_g(\tilde w_g-w_g)p_g$; increasing n reduces variance but leaves that weight error unchanged.*

### 4. Stratified sampling: measure groups deliberately, then weight back

**Stratified sampling** splits the population into groups first, samples inside each group, and combines group estimates using the target weights. It can sample in proportion to the population (80/20 here) or oversample a rare group for precision. Oversampling is fine only if the final estimate uses the target weights rather than the oversampled mixture.

```python
n_A_w, n_B_w = 80, 20  # proportional stratified design for n=100.
idx_A_w = np.random.choice(np.where(groups_w == "A")[0], size=n_A_w, replace=False)
idx_B_w = np.random.choice(np.where(groups_w == "B")[0], size=n_B_w, replace=False)
rate_A_hat_w = labels_w[idx_A_w].mean(); rate_B_hat_w = labels_w[idx_B_w].mean()
strat_hat_w = weights_w[0] * rate_A_hat_w + weights_w[1] * rate_B_hat_w
print("stratum estimates A,B:", round(rate_A_hat_w, 3), round(rate_B_hat_w, 3))
print("weighted stratified estimate:", round(strat_hat_w, 3))
assert len(idx_A_w) == 80 and len(idx_B_w) == 20
```
▶ What you'll see: each group gets measured separately, then the target 80/20 weights rebuild the population estimate.

```python
over_A_w, over_B_w = 50, 50  # intentionally oversample B to measure it more precisely.
idx_A_over_w = np.random.choice(np.where(groups_w == "A")[0], size=over_A_w, replace=False)
idx_B_over_w = np.random.choice(np.where(groups_w == "B")[0], size=over_B_w, replace=False)
rate_A_over_w = labels_w[idx_A_over_w].mean(); rate_B_over_w = labels_w[idx_B_over_w].mean()
naive_over_w = np.r_[labels_w[idx_A_over_w], labels_w[idx_B_over_w]].mean()
weighted_over_w = weights_w[0] * rate_A_over_w + weights_w[1] * rate_B_over_w
print("naive oversampled mean:", round(naive_over_w, 3))
print("weighted-back estimate:", round(weighted_over_w, 3))
```
▶ What you'll see: the naive 50/50 mean is pulled toward the high-rate B group; weighting back returns the target mixture.

```python
plt.figure(figsize=(5, 3))
plt.bar(["target", "naive 50/50", "weighted back"], [pop_rate_w, naive_over_w, weighted_over_w],
        color=["gray", "crimson", "seagreen"])
plt.ylim(0, 0.55); plt.ylabel("rate estimate"); plt.title("4: oversampling requires weights")
plt.xticks(rotation=12); plt.show()
```
▶ What you'll see: oversampling improves group coverage, but the red naive estimate targets the wrong 50/50 population.

*Why it's done this way: stratification separates two jobs — data collection can allocate rows for precision, while analysis weights $N_g/N$ recover the population you promised to represent.*

### 5. Cluster sampling: sample groups of units, not units independently

Sometimes the natural unit of collection is a **cluster**: schools, sessions, households, stores, or query batches. Cluster sampling picks clusters first and then observes people inside them. It is cheaper operationally, but observations inside a cluster tend to resemble one another, so 100 rows from 10 clusters can carry less independent information than 100 scattered rows.

```python
rng_w = np.random.default_rng(1)  # local generator for cluster construction.
n_clusters_w, cluster_size_w = 50, 20  # 1,000 people arranged into clusters.
cluster_base_w = rng_w.beta(3, 7, size=n_clusters_w)  # each cluster has its own event probability.
cluster_labels_w = np.concatenate([rng_w.binomial(1, p, size=cluster_size_w) for p in cluster_base_w])
cluster_ids_w = np.repeat(np.arange(n_clusters_w), cluster_size_w)
print("cluster population mean:", round(cluster_labels_w.mean(), 3))
print("cluster-rate spread:", round(np.std(cluster_base_w), 3))
assert len(cluster_labels_w) == 1000 and len(cluster_ids_w) == 1000
```
▶ What you'll see: the same population size is now organized into 50 internally similar clusters.

```python
chosen_clusters_w = rng_w.choice(n_clusters_w, size=5, replace=False)  # sample 5 whole clusters.
idx_cluster_w = np.isin(cluster_ids_w, chosen_clusters_w)  # all people from selected clusters.
cluster_est_w = cluster_labels_w[idx_cluster_w].mean()  # cluster-sample estimate.
idx_srs2_w = rng_w.choice(len(cluster_labels_w), size=idx_cluster_w.sum(), replace=False)  # same row count by SRS.
srs2_est_w = cluster_labels_w[idx_srs2_w].mean()
print("rows collected:", int(idx_cluster_w.sum()))
print("cluster estimate:", round(cluster_est_w, 3), "SRS same-n estimate:", round(srs2_est_w, 3))
assert int(idx_cluster_w.sum()) == 100
```
▶ What you'll see: both methods collect 100 rows, but the cluster estimate depends heavily on which 5 clusters were chosen.

```python
rates_by_cluster_w = np.array([cluster_labels_w[cluster_ids_w == c].mean() for c in range(n_clusters_w)])
plt.figure(figsize=(5, 3))
plt.hist(rates_by_cluster_w, bins=12, color="slateblue", edgecolor="white")
plt.axvline(cluster_labels_w.mean(), color="black", linestyle="--", label="population mean")
plt.title("5: clusters have different local rates"); plt.xlabel("cluster positive rate"); plt.ylabel("count")
plt.legend(); plt.show()
```
▶ What you'll see: selected clusters can sit above or below the population mean, creating extra between-cluster variation.

*Why it's done this way: cluster sampling trades independence for feasibility; because units in the same cluster share causes, the effective information is closer to the number and diversity of clusters than to the raw row count alone.*

### 6. Sample size planning: how many rows for a desired half-width?

Sample size is a precision decision. For a binomial rate, the approximate 95% half-width is $1.96\sqrt{p(1-p)/n}$. Solving for $n$ gives

$$n \ge \frac{1.96^2 p(1-p)}{h^2},$$

where $h$ is the desired half-width. This handles random error only; it cannot fix the wrong sampling frame or wrong group weights.

```python
p_plan_w = 0.30  # planning estimate for the rate.
h_w = 0.05  # desired 95% half-width.
n_needed_w = int(np.ceil((1.96 ** 2) * p_plan_w * (1 - p_plan_w) / (h_w ** 2)))
print("n needed for ±0.05:", n_needed_w)
assert n_needed_w == 323  # ceil(3.8416*0.21/0.0025).
```
▶ What you'll see: about 323 independent samples are needed for a ±5 percentage point 95% interval around p≈0.30.

```python
for n_check_w in [100, 323, 400]:
    se_check_w = np.sqrt(p_plan_w * (1 - p_plan_w) / n_check_w)
    print(n_check_w, "half-width", round(1.96 * se_check_w, 4))
assert round(1.96 * np.sqrt(0.21 / 400), 4) == 0.0449
```
▶ What you'll see: n=400 has half the SE of n=100 because $\sqrt{400}=2\sqrt{100}$.

```python
n_grid_w = np.arange(50, 501, 25)
half_grid_w = 1.96 * np.sqrt(p_plan_w * (1 - p_plan_w) / n_grid_w)
plt.figure(figsize=(5, 3))
plt.plot(n_grid_w, half_grid_w, marker="o", color="darkorange")
plt.axhline(h_w, color="black", linestyle="--", label="target half-width")
plt.axvline(n_needed_w, color="seagreen", linestyle="--", label=f"n={n_needed_w}")
plt.title("6: precision improves with √n"); plt.xlabel("sample size n"); plt.ylabel("95% half-width")
plt.legend(); plt.show()
```
▶ What you'll see: the curve decreases quickly at first and then flattens; precision has diminishing returns.

*Why it's done this way: solving the SE formula backward makes sample-size planning explicit, but the calculation assumes independent probability samples from the right population — design validity comes before numerical precision.*

## 🛠️ Setup

```python
import numpy as np  # load NumPy for arrays, synthetic populations, random draws, and numerical checks.
import matplotlib.pyplot as plt  # load Matplotlib so samples, mixtures, and uncertainty are visible.
np.random.seed(0)  # make all examples reproducible across notebook runs.

def make_population(N_A=800, N_B=200, p_A=0.20, p_B=0.70):  # create an exact two-group toy population.
    y_A = np.r_[np.ones(int(N_A * p_A)), np.zeros(N_A - int(N_A * p_A))]  # labels for group A.
    y_B = np.r_[np.ones(int(N_B * p_B)), np.zeros(N_B - int(N_B * p_B))]  # labels for group B.
    y = np.r_[y_A, y_B].astype(float)  # concatenate labels into one population vector.
    g = np.r_[np.repeat(0, N_A), np.repeat(1, N_B)]  # encode A as 0 and B as 1.
    return y, g  # return labels and group ids.

def weighted_rate(group_rates, group_weights):  # compute a target-population mixture rate.
    return float(np.sum(np.asarray(group_rates, dtype=float) * np.asarray(group_weights, dtype=float)))  # sum_g w_g p_g.

def rate_se(p, n):  # approximate binomial standard error for an independent probability sample.
    return float(np.sqrt(p * (1 - p) / n))  # sqrt(p(1-p)/n).

def show_sample_mix(counts, title):  # tiny helper to visualize sample group counts.
    plt.figure(figsize=(4, 3))  # create a compact figure.
    plt.bar(["A", "B"], counts, color=["steelblue", "darkorange"])  # draw one bar per group.
    plt.title(title)  # label the sample design.
    plt.ylabel("sample count")  # label counts.
    plt.show()  # display the chart.
```

## 🟢 Basics (warm-up)

### Basic 1 — Build a two-group population

**Goal.** Create the toy population used throughout the lesson, because sampling design starts by saying who exists before saying who is measured. We build it in 2 steps.

```python
y_b1, g_b1 = make_population()  # create 800 A users and 200 B users with exact rates.
print("population size:", len(y_b1))  # inspect total N.
print("group counts:", np.bincount(g_b1))  # inspect N_A and N_B.
assert len(y_b1) == 1000 and np.all(np.bincount(g_b1) == np.array([800, 200]))
```
▶ What you'll see: the population has 1,000 rows split 800/200 across groups A and B.

```python
rate_A_b1 = y_b1[g_b1 == 0].mean()  # compute group A's true rate.
rate_B_b1 = y_b1[g_b1 == 1].mean()  # compute group B's true rate.
print("group rates:", round(rate_A_b1, 3), round(rate_B_b1, 3))  # inspect within-group rates.
plt.figure(figsize=(4, 3))
plt.bar(["A", "B"], [rate_A_b1, rate_B_b1], color=["steelblue", "darkorange"])
plt.ylim(0, 1); plt.ylabel("positive rate"); plt.title("Basic 1: group rates")
plt.show()
assert round(rate_A_b1, 3) == 0.200 and round(rate_B_b1, 3) == 0.700
```
▶ What you'll see: B is smaller but much more positive than A.

👀 Takeaway: representativeness is about matching both group sizes and group outcomes, not just collecting many rows.

### Basic 2 — Compute the target population rate

**Goal.** Compute a weighted rate from group sizes and rates, because the target population is a mixture. We build it in 2 steps.

```python
weights_b2 = np.array([800 / 1000, 200 / 1000])  # target group weights.
rates_b2 = np.array([0.20, 0.70])  # true group rates.
print("weights:", weights_b2, "rates:", rates_b2)  # inspect mixture ingredients.
assert np.allclose(weights_b2.sum(), 1.0)
```

```python
p_b2 = weighted_rate(rates_b2, weights_b2)  # compute sum_g w_g p_g.
print("population rate:", round(p_b2, 3))  # inspect weighted average.
plt.figure(figsize=(4, 3))
plt.bar(["A contribution", "B contribution"], weights_b2 * rates_b2, color=["steelblue", "darkorange"])
plt.title("Basic 2: contributions to population rate"); plt.ylabel("w_g × p_g")
plt.show()
assert round(p_b2, 3) == 0.300
```
▶ What you'll see: A contributes 0.16 and B contributes 0.14, summing to 0.30.

👀 Takeaway: the target rate is a weighted average, so changing group weights changes the answer.

### Basic 3 — Draw a simple random sample

**Goal.** Sample equal-probability rows without replacement, because simple random sampling makes the sample representative in expectation. We build it in 2 steps.

```python
y_b3, g_b3 = make_population()  # recreate the population for this example.
idx_b3 = np.random.choice(len(y_b3), size=100, replace=False)  # draw 100 unique people.
print("unique sampled rows:", len(np.unique(idx_b3)))  # verify no duplicates.
assert len(np.unique(idx_b3)) == 100
```

```python
rate_b3 = y_b3[idx_b3].mean()  # estimate the population rate from the sample.
share_B_b3 = np.mean(g_b3[idx_b3] == 1)  # inspect realized B share.
print("sample rate:", round(rate_b3, 3), "B share:", round(share_B_b3, 3))
show_sample_mix(np.bincount(g_b3[idx_b3], minlength=2), "Basic 3: one SRS mixture")
```
▶ What you'll see: the sample mixture is near 80/20 but can fluctuate because the draw is random.

👀 Takeaway: SRS is unbiased in expectation, not guaranteed identical to the population in every finite draw.

### Basic 4 — Compare population and sample estimates

**Goal.** Put a population rate next to one sample estimate, because sampling error is the gap left after the design is correct. We build it in 2 steps.

```python
y_b4, g_b4 = make_population()  # recreate the two-group population.
true_rate_b4 = y_b4.mean()  # exact population rate.
idx_b4 = np.random.choice(len(y_b4), size=100, replace=False)  # one simple random sample.
sample_rate_b4 = y_b4[idx_b4].mean()  # one sample estimate.
print("true:", round(true_rate_b4, 3), "sample:", round(sample_rate_b4, 3))
assert round(true_rate_b4, 3) == 0.300
```

```python
error_b4 = sample_rate_b4 - true_rate_b4  # signed sampling error.
print("sample error:", round(error_b4, 3))  # inspect how far this sample landed.
plt.figure(figsize=(4, 3))
plt.bar(["population", "sample"], [true_rate_b4, sample_rate_b4], color=["gray", "seagreen"])
plt.ylim(0, 0.5); plt.ylabel("positive rate"); plt.title("Basic 4: one estimate vs truth")
plt.show()
```
▶ What you'll see: the sample may sit above or below truth, even when the design is valid.

👀 Takeaway: random sampling error is expected; systematic mixture error is the bigger danger.

### Basic 5 — Compute standard error

**Goal.** Use the binomial standard-error formula, because probability samples let us quantify uncertainty. We build it in 2 steps.

```python
p_b5 = 0.30  # planning or true rate.
n_b5 = 100  # independent sample size.
se_b5 = rate_se(p_b5, n_b5)  # compute sqrt(p(1-p)/n).
print("SE:", round(se_b5, 4))
assert round(se_b5, 4) == 0.0458
```

```python
half_b5 = 1.96 * se_b5  # approximate 95% half-width.
print("95% half-width:", round(half_b5, 4))
plt.figure(figsize=(4, 3))
plt.errorbar([0], [p_b5], yerr=[half_b5], fmt="o", color="black", capsize=6)
plt.xlim(-1, 1); plt.ylim(0.15, 0.45); plt.xticks([]); plt.ylabel("rate")
plt.title("Basic 5: uncertainty around p")
plt.show()
assert round(half_b5, 4) == 0.0898
```
▶ What you'll see: at n=100, the normal-approximate interval around 0.30 is wide.

👀 Takeaway: standard error shrinks random error, but it says nothing about whether the sample frame was right.

### Basic 6 — See that quadrupling n halves SE

**Goal.** Compare n=100 and n=400, because the square root in the SE formula creates diminishing returns. We build it in 2 steps.

```python
p_b6 = 0.30  # fixed rate for both sample-size calculations.
ns_b6 = np.array([100, 400])  # quadruple the sample size.
ses_b6 = np.array([rate_se(p_b6, n) for n in ns_b6])  # compute both standard errors.
print("SEs:", np.round(ses_b6, 4))
assert round(ses_b6[0] / ses_b6[1], 1) == 2.0
```

```python
plt.figure(figsize=(4, 3))
plt.bar(["n=100", "n=400"], ses_b6, color=["orange", "seagreen"])
plt.ylabel("standard error"); plt.title("Basic 6: SE scales as 1/√n")
plt.show()
```
▶ What you'll see: the n=400 bar is half the n=100 bar, not one quarter.

👀 Takeaway: more rows help slowly; better sampling design can remove bias immediately.

### Basic 7 — Construct a biased sample mixture

**Goal.** Force a 90/10 sample from an 80/20 population, because biased collection changes the estimand. We build it in 2 steps.

```python
y_b7, g_b7 = make_population()  # recreate the target population.
idx_A_b7 = np.random.choice(np.where(g_b7 == 0)[0], size=90, replace=False)  # sample 90 A users.
idx_B_b7 = np.random.choice(np.where(g_b7 == 1)[0], size=10, replace=False)  # sample 10 B users.
```
