# 7.26 — Pose Estimation & Keypoints

Pose estimation turns an image of a person into a small graph of named joints: shoulder, elbow, wrist, hip, knee, and so on. In this lesson, we build the core math from scratch with NumPy: heatmaps as confidence surfaces, Gaussian supervision for gentle localization, hard and soft coordinate readout, stride-aware coordinate mapping, skeleton grouping, and keypoint evaluation.

### 1. Heatmaps: a joint becomes an image-shaped confidence surface

A bounding box says "person," but pose estimation needs a coordinate for each named joint. Instead of asking a model to jump straight to two numbers, we give each keypoint its own image-shaped heatmap: a grid where high values mean "this joint is likely here." The predicted coordinate is the row and column of the most confident cell.

```python
H_w, W_w = 5, 5  # a tiny heatmap grid: rows are y, columns are x.
joint_y_w, joint_x_w = 1, 3  # the annotated joint location in (row, column) order.
heat_w = np.zeros((H_w, W_w))  # start with no confidence anywhere.
heat_w[joint_y_w, joint_x_w] = 1.0  # put all confidence at the keypoint cell.
print("heatmap shape:", heat_w.shape)  # inspect the spatial output size.
print("joint (y,x):", (joint_y_w, joint_x_w))  # keep row/column order explicit.
```
▶ What you'll see: a 5×5 heatmap with the target joint stored at row 1, column 3.

```python
peak_flat_w = int(np.argmax(heat_w))  # find the linear index of the largest confidence.
peak_y_w, peak_x_w = np.unravel_index(peak_flat_w, heat_w.shape)  # convert it back to (y,x).
print("argmax flat index:", peak_flat_w)  # inspect NumPy's flattened index.
print("argmax (y,x):", (peak_y_w, peak_x_w))  # inspect the coordinate readout.
assert (peak_y_w, peak_x_w) == (1, 3)  # verify the lesson's checked peak.
```
▶ What you'll see: `argmax` recovers `(1, 3)`, exactly the annotated joint coordinate.

```python
plt.figure(figsize=(3.6, 3.2))  # create a compact heatmap figure.
plt.imshow(heat_w, cmap="magma", vmin=0, vmax=1)  # draw confidence as color.
plt.scatter([joint_x_w], [joint_y_w], c="cyan", s=90, marker="x")  # mark the keypoint.
plt.colorbar(label="confidence")  # show the confidence scale.
plt.title("1: one keypoint heatmap")  # title the plot.
plt.xlabel("x column"); plt.ylabel("y row")  # label axes in image convention.
plt.show()  # display the heatmap.
```
▶ What you'll see: one bright pixel at the wrist-like location; that peak is the coordinate prediction.

*Why it's done this way:* a heatmap preserves the spatial grid, so convolutional image features can remain local until the final coordinate readout. The model learns "where is the wrist?" as dense localization, not as an abrupt regression from an image to two numbers.

### 2. Gaussian targets: near misses should be less wrong than far misses

A one-hot heatmap says the target cell is 1 and every neighbor is 0. That is harsh: a prediction one pixel away is treated as completely wrong. Pose models usually train against a Gaussian bump centered on the joint, so nearby pixels receive high-but-lower confidence and far pixels fade smoothly.

```python
yy_w, xx_w = np.mgrid[0:5, 0:5]  # coordinate grids: yy has rows, xx has columns.
sigma_w = 1.0  # one-cell standard deviation for the target bump.
d2_w = (xx_w - joint_x_w) ** 2 + (yy_w - joint_y_w) ** 2  # squared distance to the joint.
gauss_w = np.exp(-d2_w / (2 * sigma_w ** 2))  # Gaussian heat target.
print("squared distance at peak:", d2_w[joint_y_w, joint_x_w])  # distance is 0.
print("heat at peak:", gauss_w[joint_y_w, joint_x_w])  # exp(0)=1.
```
▶ What you'll see: the center cell has distance 0 and heat 1.0.

```python
left_y_w, left_x_w = 1, 2  # one column left of the peak.
left_heat_w = float(gauss_w[left_y_w, left_x_w])  # read that neighbor's target value.
margin_w = float(gauss_w[joint_y_w, joint_x_w] - left_heat_w)  # peak minus neighbor.
print("neighbor heat exp(-1/2):", round(left_heat_w, 3))  # 0.607.
print("peak-to-neighbor margin:", round(margin_w, 3))  # 0.393.
assert round(left_heat_w, 3) == 0.607  # verify the checked Gaussian number.
assert round(margin_w, 3) == 0.393  # verify the checked margin.
```
▶ What you'll see: a one-pixel miss gets heat 0.607, not zero, so the target gives graded feedback.

```python
plt.figure(figsize=(3.6, 3.2))  # create a compact Gaussian plot.
plt.imshow(gauss_w, cmap="magma", vmin=0, vmax=1)  # visualize the smooth target.
plt.scatter([joint_x_w], [joint_y_w], c="cyan", marker="x", s=90)  # mark the center.
plt.colorbar(label="target heat")  # add numeric color scale.
plt.title("2: Gaussian keypoint target")  # title the target.
plt.xlabel("x column"); plt.ylabel("y row")  # label axes.
plt.show()  # display the heatmap.
```
▶ What you'll see: a bright center with a smooth halo; cells farther from the joint are progressively darker.

*Why it's done this way:* squared distance grows with spatial error, and the exponential converts that distance into a smooth confidence target. The gradient near the joint is informative because the model can tell whether it is close, while distant wrong locations still receive low target values.

### 3. Hard argmax and soft-argmax: two ways to read a coordinate

The simplest coordinate decoder is hard argmax: return the row and column of the largest heat value. A soft-argmax first normalizes the heatmap into probabilities, then returns the probability-weighted average coordinate. Hard argmax is crisp and stable; soft-argmax can preserve subpixel evidence when probability mass leans between cells.

```python
cols_w = np.array([2., 3., 4.])  # three nearby x columns.
prob_center_w = np.array([0.2, 0.6, 0.2])  # symmetric mass around column 3.
soft_center_w = float(np.sum(cols_w * prob_center_w))  # weighted average coordinate.
hard_center_w = float(cols_w[np.argmax(prob_center_w)])  # coordinate of the largest probability.
print("hard:", hard_center_w, "soft:", soft_center_w)  # compare readouts.
assert soft_center_w == 3.0  # 0.2*2 + 0.6*3 + 0.2*4 = 3.0.
```
▶ What you'll see: both hard and soft read out column 3.0 when the evidence is symmetric.

```python
prob_shift_w = np.array([0.1, 0.6, 0.3])  # the peak is still at column 3, but mass leans right.
soft_shift_w = float(np.sum(cols_w * prob_shift_w))  # weighted average preserves the lean.
hard_shift_w = float(cols_w[np.argmax(prob_shift_w)])  # hard argmax ignores the lean.
print("hard after shift:", hard_shift_w)  # still 3.
print("soft after shift:", round(soft_shift_w, 3))  # 3.2.
assert round(soft_shift_w, 3) == 3.2  # verify the lesson's checked soft coordinate.
```
▶ What you'll see: hard argmax stays at 3, while soft-argmax moves to 3.2.

```python
plt.figure(figsize=(4.2, 3))  # create a probability-bar figure.
plt.bar(cols_w - 0.12, prob_center_w, width=0.24, label="symmetric", color="steelblue")  # first distribution.
plt.bar(cols_w + 0.12, prob_shift_w, width=0.24, label="shifted", color="darkorange")  # shifted distribution.
plt.axvline(soft_shift_w, color="red", linestyle="--", label="soft=3.2")  # mark shifted soft readout.
plt.title("3: soft-argmax sees subcell bias")  # title the plot.
plt.xlabel("x column"); plt.ylabel("probability"); plt.legend()  # label and legend.
plt.show()  # display the comparison.
```
▶ What you'll see: the tallest bar remains at x=3, but extra right-side mass pulls the soft coordinate toward 3.2.

*Why it's done this way:* hard argmax solves a discrete maximum problem, so small changes away from the peak do not matter until another cell wins. Soft-argmax computes an expectation, so every probability contributes linearly to the coordinate and uncertainty direction is retained.

### 4. Heatmap resolution: output stride changes coordinate scale

Pose networks often output heatmaps smaller than the input image. If a 5×5 heatmap came from a 20×20 image, one heatmap step represents 4 input pixels. Mapping back must use the same stride and center convention used by the model; otherwise a perfect heatmap peak becomes a shifted image coordinate.

```python
image_size_w = 20  # pretend the original image is 20x20 pixels.
heat_size_w = 5  # the predicted heatmap is 5x5 cells.
stride_w = image_size_w // heat_size_w  # each heatmap step covers 4 input pixels.
coarse_y_w, coarse_x_w = peak_y_w * stride_w, peak_x_w * stride_w  # corner-aligned mapping.
print("stride:", stride_w)  # inspect output stride.
print("corner-aligned input coordinate:", (coarse_y_w, coarse_x_w))  # (4,12).
assert (coarse_y_w, coarse_x_w) == (4, 12)  # verify checked scale mapping.
```
▶ What you'll see: heatmap coordinate `(1,3)` maps to input coordinate `(4,12)` under a corner convention.

```python
center_y_w = (peak_y_w + 0.5) * stride_w  # center of the heatmap cell in input pixels.
center_x_w = (peak_x_w + 0.5) * stride_w  # center of the heatmap cell in input pixels.
diff_y_w = center_y_w - coarse_y_w  # convention difference in y.
diff_x_w = center_x_w - coarse_x_w  # convention difference in x.
print("center-offset input coordinate:", (center_y_w, center_x_w))  # (6,14).
print("difference:", (diff_y_w, diff_x_w))  # (2,2).
assert (center_y_w, center_x_w) == (6.0, 14.0)  # verify checked center mapping.
```
▶ What you'll see: the center convention is 2 input pixels away in both directions.

```python
plt.figure(figsize=(3.8, 3.8))  # create a coordinate-convention figure.
plt.xlim(0, image_size_w); plt.ylim(image_size_w, 0)  # image coordinates with y downward.
for g_w in range(0, image_size_w + 1, stride_w):  # draw stride grid lines.
    plt.axhline(g_w, color="lightgray", linewidth=0.8); plt.axvline(g_w, color="lightgray", linewidth=0.8)
plt.scatter([coarse_x_w], [coarse_y_w], c="red", s=80, label="corner")  # corner coordinate.
plt.scatter([center_x_w], [center_y_w], c="blue", s=80, label="center")  # center coordinate.
plt.title("4: stride mapping conventions")  # title the plot.
plt.xlabel("input x"); plt.ylabel("input y"); plt.legend()  # label axes.
plt.show()  # display mapping.
```
▶ What you'll see: two valid-looking points in the same heatmap cell; mixing conventions silently shifts keypoints.

*Why it's done this way:* heatmap coordinates live on a downsampled lattice, while evaluation and visualization usually expect input pixels. Multiplying by stride changes units, and the half-cell offset decides whether a cell index names the cell corner or the cell center.

### 5. Skeleton grouping: individual joints become a body graph

A pose is not just independent heatmap peaks. In crowded scenes, the best wrist peak and the best elbow peak might belong to different people. Skeleton grouping connects keypoints with limb geometry, so a set of joints is accepted when its distances and directions look plausible.

```python
shoulder_w = np.array([1., 1.])  # (y,x) shoulder.
elbow_w = np.array([1., 3.])  # (y,x) elbow.
wrist_w = np.array([1., 5.])  # (y,x) wrist.
upper_w = float(np.linalg.norm(elbow_w - shoulder_w))  # shoulder-to-elbow length.
fore_w = float(np.linalg.norm(wrist_w - elbow_w))  # elbow-to-wrist length.
straight_w = float(np.linalg.norm(wrist_w - shoulder_w))  # shoulder-to-wrist distance.
print("upper arm:", upper_w, "forearm:", fore_w, "straight shoulder-wrist:", straight_w)  # inspect lengths.
assert (upper_w, fore_w, straight_w) == (2.0, 2.0, 4.0)  # verify checked geometry.
```
▶ What you'll see: the three collinear joints form two length-2 limb segments and a length-4 whole arm.

```python
bad_wrist_w = np.array([4., 0.])  # a wrist candidate from another person.
bad_fore_w = float(np.linalg.norm(bad_wrist_w - elbow_w))  # elbow to wrong wrist.
ratio_w = bad_fore_w / fore_w  # compare wrong forearm length to expected length.
print("wrong forearm length:", round(bad_fore_w, 3))  # much longer than 2.
print("length ratio wrong/expected:", round(ratio_w, 3))  # 2.121.
assert round(ratio_w, 3) == 2.121  # concrete geometry check.
```
▶ What you'll see: the mismatched wrist creates a forearm more than twice the expected length.

```python
plt.figure(figsize=(4, 3.2))  # create a skeleton plot.
plt.plot([shoulder_w[1], elbow_w[1], wrist_w[1]], [shoulder_w[0], elbow_w[0], wrist_w[0]], "o-", label="plausible arm", color="seagreen")  # good chain.
plt.plot([elbow_w[1], bad_wrist_w[1]], [elbow_w[0], bad_wrist_w[0]], "o--", label="mismatched wrist", color="crimson")  # bad edge.
plt.gca().invert_yaxis()  # image rows increase downward.
plt.title("5: grouping joints into a skeleton")  # title the plot.
plt.xlabel("x column"); plt.ylabel("y row"); plt.legend()  # label axes.
plt.show()  # display skeleton candidates.
```
▶ What you'll see: the plausible arm is straight and compact; the mismatched wrist makes an implausible long diagonal limb.

*Why it's done this way:* heatmaps score local evidence per joint type, but a body is a graph with anatomical constraints. Grouping adds relational evidence, so high-scoring isolated peaks must also fit the limb lengths and connections of the same person.

### 6. PCK evaluation: a keypoint is correct only if localization error is small enough

Pose confidence alone is not the metric. A high score at the wrong location is still a localization error. A common evaluation idea is PCK, percentage of correct keypoints: count a predicted keypoint as correct if its distance from the ground truth is below a threshold scaled by the person size.

```python
gt_w = np.array([[1., 3.], [1., 1.], [1., 5.], [4., 3.]])  # ground-truth joints in (y,x).
pred_w = np.array([[1.2, 3.1], [1.3, 1.2], [2.4, 4.8], [6.0, 3.0]])  # predicted joints.
errors_w = np.linalg.norm(pred_w - gt_w, axis=1)  # Euclidean localization error per joint.
print("errors:", np.round(errors_w, 3))  # inspect each keypoint error.
assert np.allclose(np.round(errors_w, 3), [0.224, 0.361, 1.414, 2.0])  # concrete error check.
```
▶ What you'll see: two joints are very close, one is moderately off, and one is far away.

```python
person_scale_w = 4.0  # a simple body-size normalizer.
alpha_w = 0.5  # PCK@0.5 uses half the scale as the distance threshold.
thresh_w = alpha_w * person_scale_w  # allowed localization error.
correct_w = errors_w <= thresh_w  # keypoints inside the threshold count as correct.
pck_w = float(np.mean(correct_w))  # percentage correct keypoints.
print("threshold:", thresh_w)  # 2.0.
print("correct flags:", correct_w.astype(int))  # all four are within or on threshold.
print("PCK:", pck_w)  # 1.0.
assert pck_w == 1.0  # verify the metric calculation.
```
▶ What you'll see: with threshold 2.0, every prediction counts as correct, including the one exactly on the boundary.

```python
alpha_strict_w = 0.25  # stricter PCK threshold.
thresh_strict_w = alpha_strict_w * person_scale_w  # 1.0 pixel threshold.
pck_strict_w = float(np.mean(errors_w <= thresh_strict_w))  # stricter percentage correct.
print("strict threshold:", thresh_strict_w)  # 1.0.
print("strict PCK:", pck_strict_w)  # 0.5.
assert pck_strict_w == 0.5  # two of four joints pass.
plt.figure(figsize=(4, 3))  # create a metric sensitivity plot.
plt.bar(["PCK@0.5", "PCK@0.25"], [pck_w, pck_strict_w], color=["seagreen", "darkorange"])  # compare thresholds.
plt.ylim(0, 1.05); plt.ylabel("fraction correct")  # label metric scale.
plt.title("6: localization threshold matters")  # title the plot.
plt.show()  # display comparison.
```
▶ What you'll see: tightening the distance threshold drops PCK from 1.0 to 0.5.

*Why it's done this way:* PCK evaluates the coordinate, not just whether a heatmap looked confident. Scaling the threshold by person size makes a 2-pixel error less severe on a large person than on a tiny one, matching the geometry of the task.

### Basic 4 — Build a Gaussian keypoint target

### Basic 6 — Normalize a heatmap into probabilities

**Goal.** Convert positive heat values into a distribution, because soft-argmax needs probabilities that sum to one. We build it in 2 steps.


### Advanced 5 — Heatmap loss and a small gradient step

**Goal.** Move a predicted heatmap toward a Gaussian target, because training reduces per-pixel error across the confidence surface. We build it in 4 steps.

```python
yy_a5, xx_a5 = np.mgrid[0:5, 0:5]  # coordinate grids.
target_a5 = np.exp(-((xx_a5 - 3) ** 2 + (yy_a5 - 1) ** 2) / 2)  # target Gaussian centered at (1,3).
pred_a5 = np.exp(-((xx_a5 - 2) ** 2 + (yy_a5 - 1) ** 2) / 2)  # prediction shifted one cell left.
loss_before_a5 = float(np.mean((pred_a5 - target_a5) ** 2))  # mean squared heatmap error.
print("loss before:", round(loss_before_a5, 4))  # inspect initial mismatch.
assert loss_before_a5 > 0  # shifted maps are not identical.
```
▶ What you'll see: the prediction has positive mean squared error because its bump is shifted.

```python
eta_a5 = 0.5  # learning-rate scale for this direct heatmap update.
grad_a5 = 2 * (pred_a5 - target_a5) / pred_a5.size  # gradient of mean squared error with respect to predictions.
updated_a5 = pred_a5 - eta_a5 * grad_a5  # one gradient descent step on the heatmap values.
loss_after_a5 = float(np.mean((updated_a5 - target_a5) ** 2))  # recompute loss after the step.
print("loss after:", round(loss_after_a5, 4))  # inspect improvement.
assert loss_after_a5 < loss_before_a5  # gradient descent reduced the loss.
```

```python
fig_a5, ax_a5 = plt.subplots(1, 3, figsize=(8, 2.6))  # create before/target/after panels.
ax_a5[0].imshow(pred_a5, cmap="magma", vmin=0, vmax=1); ax_a5[0].set_title("before")  # shifted prediction.
ax_a5[1].imshow(target_a5, cmap="magma", vmin=0, vmax=1); ax_a5[1].set_title("target")  # ground truth target.
ax_a5[2].imshow(updated_a5, cmap="magma", vmin=0, vmax=1); ax_a5[2].set_title("after step")  # updated prediction.
plt.suptitle("Advanced 5: heatmap MSE update")  # title panels.
plt.show()  # display.
```
▶ What you'll see: the after-step heatmap becomes numerically closer to the target, even though one step is small.

```python
peak_before_a5 = np.unravel_index(int(np.argmax(pred_a5)), pred_a5.shape)  # peak before update.
```

👀 Takeaway: heatmap training optimizes dense values first; coordinate accuracy follows as the peak and surrounding confidence move into place.
