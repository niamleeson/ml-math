# 3.39 — Regression Metrics

Regression metrics turn prediction mistakes into numbers we can optimize and compare. In this lesson, you will build MSE, MAE, and R² from residuals, then use validation gaps, cost terms, and stabilization to decide which regression model deserves trust beyond the training table.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build regression metrics one idea at a time. Run each cell in order and read the printed intermediate values — every piece of math is spelled out so the score is never a black box. This walkthrough is self-contained and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays, residual arithmetic, and numerical checks.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
np.random.seed(0)  # reproducibility for tiny synthetic examples.
```

### 1. Residuals: the raw material of every regression metric

A regression model predicts numbers. The first thing we inspect is the **residual** $e_i=y_i-\hat y_i$: how far the prediction missed the true target, including the sign. Positive residuals mean the model predicted too low; negative residuals mean it predicted too high. Metrics differ only in how they turn these residuals into penalties.

```python
y_w = np.array([3.0, 5.0, 2.0, 7.0])          # true targets.
yhat_w = np.array([2.6, 5.5, 2.2, 6.0])       # model predictions.
resid_w = y_w - yhat_w                         # signed residuals: truth minus prediction.
print("truth:", y_w)
print("prediction:", yhat_w)
print("residuals:", resid_w)
assert np.allclose(resid_w, [0.4, -0.5, -0.2, 1.0])
```
▶ What you'll see: four signed errors; the last example is underpredicted by 1.0, while examples 2 and 3 are overpredicted.

```python
plt.figure(figsize=(5, 3))
plt.axhline(0, color="black", linewidth=0.8)
plt.bar(np.arange(len(resid_w)), resid_w, color=np.where(resid_w >= 0, "seagreen", "crimson"))
plt.title("1: signed residuals")
plt.xlabel("example")
plt.ylabel("y - ŷ")
plt.show()
```
▶ What you'll see: bars above zero for underprediction and below zero for overprediction.

*Why it's done this way:* the residual is the smallest unit of regression evaluation because it preserves both magnitude and direction. Later metrics intentionally remove or transform the sign — by squaring, taking absolute value, or comparing to a baseline — but those choices only make sense after the signed error is visible.

### 2. MSE: make large errors expensive

Mean squared error is $$MSE=\frac1m\sum_i e_i^2.$$ Squaring does two jobs: it makes every penalty nonnegative, and it makes a 2-unit miss cost four times as much as a 1-unit miss. That is useful when large mistakes are especially damaging.

```python
err_w = np.array([0.4, -0.5, -0.2, 1.0])       # reuse residuals explicitly.
sq_w = err_w ** 2                              # square each residual.
mse_w = float(np.mean(sq_w))                   # average squared errors.
print("squared errors:", sq_w)
print("MSE:", round(mse_w, 3))
assert round(mse_w, 3) == 0.363
```
▶ What you'll see: the 1.0 residual contributes 1.00 to the average, much more than the 0.2 residual contributes.

```python
x_w = np.linspace(-2, 2, 101)
plt.figure(figsize=(4.5, 3))
plt.plot(x_w, x_w ** 2, color="purple")
plt.scatter(err_w, sq_w, color="black")
plt.title("2: squared-error penalty")
plt.xlabel("residual e")
plt.ylabel("e²")
plt.show()
```
▶ What you'll see: a parabola centered at zero; points farther from zero rise quickly.

*Why it's done this way:* squaring creates a smooth bowl, so optimization methods can follow gradients toward smaller errors. The tradeoff is sensitivity: a single outlier can dominate the average because its penalty grows quadratically.

### 3. MAE: charge errors linearly

Mean absolute error is $$MAE=\frac1m\sum_i |e_i|.$$ It ignores direction like MSE, but it does not square. A 2-unit miss costs exactly twice a 1-unit miss, so MAE is easier to read in the target's original units and less dominated by outliers.

```python
abs_w = np.abs(err_w)                           # absolute residual magnitudes.
mae_w = float(np.mean(abs_w))                   # average absolute error.
print("absolute errors:", abs_w)
print("MAE:", round(mae_w, 3))
assert round(mae_w, 3) == 0.525
```
▶ What you'll see: all errors are positive magnitudes, and the average has the same units as the target.

```python
plt.figure(figsize=(4.5, 3))
plt.plot(x_w, np.abs(x_w), color="darkorange", label="|e|")
plt.plot(x_w, x_w ** 2, color="purple", linestyle="--", label="e²")
plt.title("3: absolute vs squared penalty")
plt.xlabel("residual e")
plt.ylabel("penalty")
plt.legend()
plt.show()
```
▶ What you'll see: the absolute-value line grows steadily, while squared error grows slowly near zero and fast for large misses.

*Why it's done this way:* MAE is the right instinct when each extra unit of error has roughly the same practical cost. It sacrifices the smooth derivative at exactly zero, but gains robustness and interpretability.

### 4. R²: compare against predicting the mean

R² asks whether the model improves on the simplest regression baseline: always predicting the mean of $y$. The formula is $$R^2=1-\frac{SS_{res}}{SS_{tot}},$$ where $SS_{res}=\sum_i(y_i-\hat y_i)^2$ and $SS_{tot}=\sum_i(y_i-\bar y)^2$. A value of 1 is perfect, 0 ties the mean baseline, and negative means worse than the mean.

```python
mean_y_w = float(np.mean(y_w))                  # baseline prediction for every example.
ss_res_w = float(np.sum((y_w - yhat_w) ** 2))   # model squared residual sum.
ss_tot_w = float(np.sum((y_w - mean_y_w) ** 2)) # baseline squared residual sum.
r2_w = 1 - ss_res_w / ss_tot_w                  # fraction of baseline variance explained.
print("mean baseline:", round(mean_y_w, 3))
print("SS_res:", round(ss_res_w, 3), "SS_tot:", round(ss_tot_w, 3))
print("R²:", round(r2_w, 3))
assert round(r2_w, 3) == 0.902
```
▶ What you'll see: the model's residual sum is much smaller than the mean baseline's residual sum, so R² is high.

```python
plt.figure(figsize=(5, 3))
plt.bar(["model SS_res", "mean SS_tot"], [ss_res_w, ss_tot_w], color=["seagreen", "gray"])
plt.title("4: R² compares model error to mean-baseline error")
plt.ylabel("sum of squared errors")
plt.show()
```
▶ What you'll see: the model bar is tiny compared with the baseline bar.

*Why it's done this way:* raw MSE has no universal scale; an MSE of 10 is excellent for house prices but terrible for shoe sizes. R² normalizes by the target's natural variability, making the score a relative improvement over a concrete baseline.

### 5. Empirical risk, cost, and the decision score

The lesson's verified toy losses are 0.213, 0.070, and 0.488. Empirical risk averages them: $R_S=0.257$. But model selection should include the method's cost — here 0.080 — because a prettier fit may be too flexible, expensive, or brittle. The decision score is therefore $R_S+cost$.

```python
losses_w = np.array([0.213, 0.070, 0.488])      # verified per-example toy losses.
risk_w = float(np.mean(losses_w))               # empirical risk = average loss.
cost_w = 0.080                                  # complexity/regularization/operational cost.
score_w = risk_w + cost_w                       # score used for selection.
print("empirical risk:", round(risk_w, 3))
print("decision score:", round(score_w, 3))
assert round(risk_w, 3) == 0.257
assert round(score_w, 3) == 0.337
```
▶ What you'll see: the raw average is 0.257, but the actual selection score is 0.337 after adding cost.

```python
plt.figure(figsize=(5, 3))
plt.bar(["raw risk", "+ cost", "score"], [risk_w, cost_w, score_w], color=["steelblue", "orange", "seagreen"])
plt.title("5: fit plus method cost")
plt.ylabel("score component")
plt.show()
```
▶ What you'll see: the final score is the raw training fit plus the guardrail term.

*Why it's done this way:* empirical risk is what the learner can directly minimize, but it is not the whole decision. A cost term encodes skepticism about flexibility or operational burden, preventing a model from winning solely by chasing training convenience.

### 6. Validation gaps and stabilization

A tempting alternative has score 0.389, so the current score 0.337 wins by 0.052. The relative gap is 13.4%, which says how large the win is on the alternative's scale. If a stabilizing knob reduces the current decision score by 20%, the stabilized score is 0.270, the best of the three candidates.

```python
alt_w = 0.389                                  # more flexible alternative score.
gap_w = alt_w - score_w                        # absolute advantage of current score.
relative_gap_w = gap_w / alt_w                 # scale-aware gap.
stable_w = 0.80 * score_w                      # 20% score reduction from stabilization.
print("gap:", round(gap_w, 3))
print("relative gap:", round(relative_gap_w, 3))
print("stabilized score:", round(stable_w, 3))
assert round(gap_w, 3) == 0.052
assert round(relative_gap_w, 3) == 0.134
assert round(stable_w, 3) == 0.270
```
▶ What you'll see: the absolute gap is small but measurable, and the stabilized version improves the score further.

```python
choices_w = np.array([score_w, alt_w, stable_w])
labels_w = ["baseline", "flexible alt", "stabilized"]
winner_w = int(np.argmin(choices_w))
print("winner:", labels_w[winner_w], "with score", round(float(choices_w[winner_w]), 3))
plt.figure(figsize=(5, 3))
plt.bar(labels_w, choices_w, color=["steelblue", "crimson", "seagreen"])
plt.title("6: lower full decision score wins")
plt.ylabel("decision score")
plt.xticks(rotation=10)
plt.show()
```
▶ What you'll see: the stabilized score is the lowest bar, so it is the version to carry forward in this toy case.

*Why it's done this way:* validation and gap thinking protect against over-reading tiny differences. The winner is not the model with the prettiest training fragment; it is the model with the best full score after the metric, cost, and stability assumptions are applied on the same scale.

## 🛠️ Setup

```python
import numpy as np  # load NumPy for residuals, averages, masks, and small simulations.
import matplotlib.pyplot as plt  # load Matplotlib for every plot in the worked examples.
np.random.seed(0)  # make random examples reproducible across notebook runs.

def mse(y, yhat):  # compute mean squared error from scratch.
    y = np.asarray(y, dtype=float)
    yhat = np.asarray(yhat, dtype=float)
    return float(np.mean((y - yhat) ** 2))

def mae(y, yhat):  # compute mean absolute error from scratch.
    y = np.asarray(y, dtype=float)
    yhat = np.asarray(yhat, dtype=float)
    return float(np.mean(np.abs(y - yhat)))

def r2_score(y, yhat):  # compute R² against the mean baseline from scratch.
    y = np.asarray(y, dtype=float)
    yhat = np.asarray(yhat, dtype=float)
    ss_res = float(np.sum((y - yhat) ** 2))
    ss_tot = float(np.sum((y - np.mean(y)) ** 2))
    return 0.0 if ss_tot == 0 else float(1 - ss_res / ss_tot)

def train_val_split_indices(n, val_every):  # deterministic split helper for tiny examples.
    idx = np.arange(n)
    val = idx[idx % val_every == 0]
    train = idx[idx % val_every != 0]
    return train, val
```

## 🟢 Basics (warm-up)

### Basic 1 — Compute residuals

**Goal.** Start with signed prediction errors, because MSE, MAE, and R² all begin from $y-\hat y$. We build it in 2 steps.

```python
y_b1 = np.array([2.0, 4.0, 6.0])  # true regression targets for three examples.
yhat_b1 = np.array([2.5, 3.0, 7.0])  # model predictions on the same examples.
res_b1 = y_b1 - yhat_b1  # signed residuals: positive means predicted too low.
print("residuals:", res_b1)
assert np.allclose(res_b1, [-0.5, 1.0, -1.0])
```

```python
plt.figure(figsize=(4, 3))
plt.axhline(0, color="black", linewidth=0.8)
plt.bar(["ex0", "ex1", "ex2"], res_b1, color=["crimson", "seagreen", "crimson"])
plt.title("Basic 1: signed residuals")
plt.ylabel("y - ŷ")
plt.show()
```
▶ What you'll see: one positive residual and two negative residuals, showing the direction of each miss.

👀 Takeaway: residual signs diagnose bias direction before a metric collapses errors into one number.

### Basic 2 — Square errors for MSE

**Goal.** Square residuals, because MSE makes all errors nonnegative and magnifies large misses. We build it in 2 steps.

```python
res_b2 = np.array([-0.5, 1.0, -1.0])  # reuse a tiny residual vector locally.
sq_b2 = res_b2 ** 2  # square each error.
print("squared errors:", sq_b2)
assert np.allclose(sq_b2, [0.25, 1.0, 1.0])
```

```python
mse_b2 = float(np.mean(sq_b2))  # average the squared errors.
print("MSE:", round(mse_b2, 3))
assert round(mse_b2, 3) == 0.750
plt.figure(figsize=(4, 3))
plt.bar(["e0²", "e1²", "e2²"], sq_b2, color="purple")
plt.title("Basic 2: squared-error pieces")
plt.ylabel("e²")
plt.show()
```
▶ What you'll see: the two 1-unit misses each contribute 1.0, while the half-unit miss contributes only 0.25.

👀 Takeaway: MSE is an average of squared residual penalties.

### Basic 3 — Compute RMSE for original units

**Goal.** Take the square root of MSE, because RMSE returns the error summary to the target's units. We build it in 2 steps.

```python
mse_b3 = 0.75  # use the verified MSE from Basic 2.
rmse_b3 = float(np.sqrt(mse_b3))  # square-root the mean squared error.
print("RMSE:", round(rmse_b3, 3))
assert round(rmse_b3, 3) == 0.866
```

```python
plt.figure(figsize=(4, 3))
plt.bar(["MSE", "RMSE"], [mse_b3, rmse_b3], color=["purple", "teal"])
plt.title("Basic 3: MSE vs RMSE")
plt.ylabel("value")
plt.show()
```
▶ What you'll see: RMSE is not a new penalty; it is the square-rooted MSE, easier to read in target units.

👀 Takeaway: RMSE keeps MSE's outlier sensitivity but reports in the same unit as $y$.

### Basic 4 — Compute MAE

**Goal.** Average absolute residuals, because MAE measures typical magnitude without squaring. We build it in 2 steps.

```python
res_b4 = np.array([-0.5, 1.0, -1.0])  # tiny residual vector.
abs_b4 = np.abs(res_b4)  # remove signs without squaring.
print("absolute errors:", abs_b4)
assert np.allclose(abs_b4, [0.5, 1.0, 1.0])
```

```python
mae_b4 = float(np.mean(abs_b4))  # average absolute errors.
print("MAE:", round(mae_b4, 3))
assert round(mae_b4, 3) == 0.833
plt.figure(figsize=(4, 3))
plt.bar(["|e0|", "|e1|", "|e2|"], abs_b4, color="darkorange")
plt.title("Basic 4: absolute-error pieces")
plt.ylabel("|e|")
plt.show()
```
▶ What you'll see: the absolute bars are directly the miss sizes in target units.

👀 Takeaway: MAE is a linear average of error magnitudes.

### Basic 5 — Compare MSE and MAE on an outlier

**Goal.** See how one large residual changes each metric, because MSE is more outlier-sensitive than MAE. We build it in 2 steps.

```python
res_b5 = np.array([0.2, -0.1, 3.0])  # two tiny errors and one large miss.
mse_b5 = float(np.mean(res_b5 ** 2))  # squared-error average.
mae_b5 = float(np.mean(np.abs(res_b5)))  # absolute-error average.
print("MSE:", round(mse_b5, 3), "MAE:", round(mae_b5, 3))
assert round(mse_b5, 3) == 3.017
assert round(mae_b5, 3) == 1.100
```

```python
plt.figure(figsize=(4, 3))
plt.bar(["MSE", "MAE"], [mse_b5, mae_b5], color=["purple", "darkorange"])
plt.title("Basic 5: outlier sensitivity")
plt.ylabel("metric value")
plt.show()
```
▶ What you'll see: MSE jumps much higher because the 3-unit residual becomes a 9-unit squared penalty.

👀 Takeaway: choose MSE when large misses should be disproportionately expensive; choose MAE when linear cost is more honest.

### Basic 6 — Compute the mean baseline

**Goal.** Build the R² baseline, because R² compares a model to always predicting the training target mean. We build it in 2 steps.

```python
y_b6 = np.array([1.0, 2.0, 4.0, 5.0])  # true targets.
mean_b6 = float(np.mean(y_b6))  # constant baseline prediction.
baseline_b6 = np.full_like(y_b6, mean_b6)  # mean prediction for every example.
print("mean baseline:", mean_b6)
assert mean_b6 == 3.0
```

```python
plt.figure(figsize=(4, 3))
plt.scatter(np.arange(len(y_b6)), y_b6, label="truth", color="black")
plt.plot(np.arange(len(y_b6)), baseline_b6, label="mean baseline", color="gray")
plt.title("Basic 6: mean baseline")
plt.legend()
plt.show()
```
▶ What you'll see: a flat baseline line at 3.0 across all examples.

👀 Takeaway: R² is anchored to a specific simple competitor, not to zero error in isolation.

### Basic 7 — Compute R² from sums of squares

**Goal.** Calculate $1-SS_{res}/SS_{tot}$ by hand, because R² is a relative error reduction. We build it in 3 steps.

```python
y_b7 = np.array([1.0, 2.0, 4.0, 5.0])  # true targets.
yhat_b7 = np.array([1.2, 2.1, 3.8, 4.9])  # strong predictions.
ss_res_b7 = float(np.sum((y_b7 - yhat_b7) ** 2))  # model residual sum of squares.
print("SS_res:", round(ss_res_b7, 3))
assert round(ss_res_b7, 3) == 0.100
```

```python
ss_tot_b7 = float(np.sum((y_b7 - np.mean(y_b7)) ** 2))  # mean-baseline residual sum.
r2_b7 = 1 - ss_res_b7 / ss_tot_b7  # relative improvement over mean baseline.
print("SS_tot:", round(ss_tot_b7, 3), "R²:", round(r2_b7, 3))
assert round(ss_tot_b7, 3) == 10.000
assert round(r2_b7, 3) == 0.990
```

```python
plt.figure(figsize=(4, 3))
plt.bar(["model", "mean baseline"], [ss_res_b7, ss_tot_b7], color=["seagreen", "gray"])
plt.title("Basic 7: sums of squares")
plt.ylabel("SSE")
plt.show()
```
▶ What you'll see: the model's SSE is tiny relative to the mean-baseline SSE.

👀 Takeaway: R² near 1 means the model explains nearly all variation relative to the mean baseline.

### Basic 8 — See negative R²

**Goal.** Show that R² can be negative, because a bad model can lose to the mean baseline. We build it in 2 steps.

👀 Takeaway: R² is not bounded below; negative values mean the mean baseline would have been better.

### Easy 1 — Evaluate two models with multiple metrics

**Goal.** Compare MSE, MAE, and R² for two prediction vectors, because metric choice can change which model looks better. We build it in 3 steps.

```python
y_e1 = np.array([2.0, 3.0, 5.0, 8.0, 13.0])  # true targets.
pred_a_e1 = np.array([2.2, 2.8, 5.1, 7.9, 12.7])  # model A predictions.
pred_b_e1 = np.array([2.0, 3.2, 4.6, 8.4, 13.8])  # model B predictions.
print("residuals A:", np.round(y_e1 - pred_a_e1, 2))
print("residuals B:", np.round(y_e1 - pred_b_e1, 2))
```

```python
metrics_a_e1 = np.array([mse(y_e1, pred_a_e1), mae(y_e1, pred_a_e1), r2_score(y_e1, pred_a_e1)])  # A metrics.
metrics_b_e1 = np.array([mse(y_e1, pred_b_e1), mae(y_e1, pred_b_e1), r2_score(y_e1, pred_b_e1)])  # B metrics.
print("A [MSE, MAE, R²]:", np.round(metrics_a_e1, 3))
print("B [MSE, MAE, R²]:", np.round(metrics_b_e1, 3))
assert np.allclose(np.round(metrics_a_e1, 3), [0.038, 0.180, 0.998])
assert np.allclose(np.round(metrics_b_e1, 3), [0.200, 0.360, 0.987])
```

```python
plt.figure(figsize=(5, 3))
x_e1 = np.arange(2)
plt.bar(x_e1 - 0.18, [metrics_a_e1[0], metrics_b_e1[0]], width=0.36, label="MSE")
plt.bar(x_e1 + 0.18, [metrics_a_e1[1], metrics_b_e1[1]], width=0.36, label="MAE")
plt.xticks(x_e1, ["model A", "model B"])
plt.title("Easy 1: error metrics")
plt.legend()
plt.show()
```
▶ What you'll see: model A has lower MSE and MAE, while both R² values are high because the target varies widely.

👀 Takeaway: always state the metric; it defines what kind of error the comparison respects.

### Easy 2 — Train/validation split for metric honesty

**Goal.** Compute train and validation MSE, because training error alone can overstate future performance. We build it in 3 steps.

```python
x_e2 = np.linspace(0, 9, 10)  # one-dimensional feature.
y_e2 = 2.0 * x_e2 + 1.0 + np.array([0.0, 0.2, -0.1, 0.1, -0.2, 0.0, 0.3, -0.3, 0.1, -0.1])  # near-linear targets.
train_e2, val_e2 = train_val_split_indices(len(x_e2), 4)  # deterministic validation every fourth point.
print("train idx:", train_e2, "val idx:", val_e2)
```

```python
coef_e2 = np.polyfit(x_e2[train_e2], y_e2[train_e2], deg=1)  # fit a line with NumPy only.
pred_e2 = np.polyval(coef_e2, x_e2)  # predict all points.
train_mse_e2 = mse(y_e2[train_e2], pred_e2[train_e2])  # training MSE.
val_mse_e2 = mse(y_e2[val_e2], pred_e2[val_e2])  # validation MSE.
print("line coef:", np.round(coef_e2, 3))
print("train MSE:", round(train_mse_e2, 3), "validation MSE:", round(val_mse_e2, 3))
assert round(train_mse_e2, 3) == 0.030
```

```python
plt.figure(figsize=(5, 3))
plt.scatter(x_e2[train_e2], y_e2[train_e2], label="train", color="steelblue")
plt.scatter(x_e2[val_e2], y_e2[val_e2], label="validation", color="crimson")
plt.plot(x_e2, pred_e2, color="black", label="fit")
plt.title("Easy 2: train vs validation points")
plt.legend()
```

### Advanced 1 — Bootstrap validation metric uncertainty

**Goal.** Estimate variability in validation MSE, because a tiny score gap can be sampling noise. We build it in 4 steps.

```python
y_a1 = np.array([3.0, 2.5, 4.2, 5.1, 4.8, 6.0, 7.2, 6.8])  # validation truths.

base_gap_a1 = mse(y_a1, pred2_a1) - mse(y_a1, pred1_a1)  # positive means model 1 wins.
print("observed MSE gap:", round(base_gap_a1, 3))
```

```python
rng_a1 = np.random.default_rng(0)  # local reproducible bootstrap generator.
gaps_a1 = []  # store bootstrap gaps.
for _ in range(300):  # resample validation examples with replacement.
    idx_a1 = rng_a1.integers(0, len(y_a1), len(y_a1))
    gaps_a1.append(mse(y_a1[idx_a1], pred2_a1[idx_a1]) - mse(y_a1[idx_a1], pred1_a1[idx_a1]))
gaps_a1 = np.array(gaps_a1)
print("bootstrap gap mean:", round(float(np.mean(gaps_a1)), 3))
```

```python
lo_a1, hi_a1 = np.percentile(gaps_a1, [5, 95])  # rough 90% interval.

assert len(gaps_a1) == 300
```

```python
plt.figure(figsize=(5, 3))
```

### Advanced 2 — Weighted MSE for uneven business costs

**Goal.** Give some examples more weight, because not every regression error has equal downstream cost. We build it in 3 steps.

```python
y_a2 = np.array([10.0, 20.0, 30.0, 40.0])  # true targets.
yhat_a2 = np.array([12.0, 18.0, 29.0, 45.0])  # predictions.

```

```python
unweighted_a2 = float(np.mean(err2_a2))  # ordinary MSE.
weighted_a2 = float(np.sum(w_a2 * err2_a2) / np.sum(w_a2))  # weighted MSE.
print("unweighted MSE:", round(unweighted_a2, 3), "weighted MSE:", round(weighted_a2, 3))

assert round(weighted_a2, 3) == 13.750
```

```python
plt.figure(figsize=(5, 3))
plt.bar(["unweighted", "weighted"], [unweighted_a2, weighted_a2], color=["gray", "crimson"])
plt.title("Advanced 2: weights change the objective")

plt.show()
```
▶ What you'll see: the weighted MSE is larger because the high-weight example has the largest miss.

👀 Takeaway: weights should reflect real costs, because they directly redefine what the metric optimizes.
