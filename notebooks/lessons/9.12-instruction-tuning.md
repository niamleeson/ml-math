# 9.12 — Instruction Tuning

Instruction tuning turns a pretrained language model into a helpful interface by training it on prompt-response pairs. In this lesson, we build supervised fine-tuning (SFT) from first principles with tiny NumPy arrays: how prompts condition responses, how token probabilities become loss, why prompt tokens are masked out, and how formatting and mixture weights change the behavior the model can learn.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build instruction tuning one idea at a time. Run each cell in order and read the printed intermediate values — every piece of math, especially response-only loss masking, is shown directly. This walkthrough is self-contained and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays, masks, logits, and numerical checks for all walkthrough cells.
import matplotlib.pyplot as plt  # compact visualizations for token losses and mixtures.
np.random.seed(0)  # reproducibility for any tiny stochastic examples.
```

### 1. Instruction data: prompt tokens condition, response tokens are targets

Instruction tuning begins with examples shaped like `(instruction + optional input) → response`. In a causal language model, the prompt tokens are visible context; the model then predicts the next response token at each response position. The important split is not just cosmetic: prompt text tells the model what task to do, while response text supplies the supervised behavior we want it to imitate.

```python
tokens_w = np.array(["<user>", "add", "2", "3", "<assistant>", "5", "</assistant>"])  # one toy chat sequence.
prompt_mask_w = np.array([1, 1, 1, 1, 1, 0, 0], dtype=bool)  # True for conditioning tokens.
response_mask_w = ~prompt_mask_w  # True for tokens that should receive SFT loss.
print("tokens:", tokens_w.tolist())  # inspect the full formatted example.
print("prompt tokens:", tokens_w[prompt_mask_w].tolist())  # tokens used as context.
print("response targets:", tokens_w[response_mask_w].tolist())  # tokens trained as the answer.
```
▶ What you'll see: the same sequence is split into prompt/context tokens and response/target tokens.

```python
colors_w = np.where(response_mask_w, 1, 0)  # 1 = response target, 0 = prompt context.
plt.figure(figsize=(6, 1.8))  # create a compact token-strip visualization.
plt.imshow(colors_w[None, :], cmap="coolwarm", aspect="auto")  # show which positions get loss.
plt.xticks(range(len(tokens_w)), tokens_w, rotation=30, ha="right")  # label every token.
plt.yticks([])  # hide the single dummy y-axis row.
plt.title("1: prompt context vs response targets")  # title the split.
plt.show()  # display the token strip.
```
▶ What you'll see: prompt tokens form the conditioning prefix; only the assistant answer side is highlighted for loss.

*Why it's done this way: a causal LM already knows how to condition on previous tokens, so SFT does not need a new architecture. It needs the dataset to say which suffix is the behavior to learn; otherwise the model wastes probability mass learning to reproduce the user's instruction instead of the assistant's answer.*

### 2. Logits, softmax, and next-token probability

The model produces logits, one real-valued score per vocabulary token. Softmax converts those scores into probabilities, and the probability assigned to the correct next token is the quantity SFT rewards. A logit increase is multiplicative in odds: adding `+1.5` to one token multiplies its odds by `exp(1.5) ≈ 4.48`, which is why format tokens can become much more likely after tuning.

```python
vocab_w = np.array(["4", "5", "6", "</assistant>"])  # a tiny candidate vocabulary.
logits_w = np.array([0.2, 1.6, -0.4, 0.0])  # model scores before softmax.
shifted_w = logits_w - np.max(logits_w)  # numerical stability: subtracting a constant preserves probabilities.
probs_w = np.exp(shifted_w) / np.sum(np.exp(shifted_w))  # softmax probabilities.
print("probabilities:", dict(zip(vocab_w, np.round(probs_w, 3))))  # inspect next-token distribution.
print("p(correct='5'):", round(float(probs_w[1]), 3))  # probability assigned to the correct token.
```
▶ What you'll see: token `5` receives the largest probability because it has the largest logit.

```python
gain_w = 1.5  # format-token or answer-token logit gain from training.
odds_multiplier_w = float(np.exp(gain_w))  # exp(logit gain) is the odds multiplier.
print("odds multiplier from +1.5 logit:", round(odds_multiplier_w, 3))  # 4.482 from the source lesson.
assert round(odds_multiplier_w, 3) == 4.482  # self-check the worked mechanic.
plt.figure(figsize=(4.5, 3))  # create a compact probability chart.
plt.bar(vocab_w, probs_w, color="teal")  # show the distribution over next tokens.
plt.title("2: softmax turns logits into probabilities")  # title the chart.
plt.ylabel("probability")  # label probability scale.
plt.show()  # display the bar chart.
```
▶ What you'll see: a peaked distribution over candidate next tokens, plus the exact `e^1.5 = 4.482` odds multiplier.

*Why it's done this way: cross-entropy works on probabilities, but the model's natural output is unconstrained logits. Softmax is the bridge: it turns arbitrary scores into a normalized distribution while preserving order and making logit differences directly control probability ratios.*

### 3. SFT loss is negative log-probability on response positions

For response tokens $R$, the supervised fine-tuning objective is

$$\mathcal{L}_{\mathrm{SFT}}=-\sum_{t\in R}\log p_\theta(y_t\mid x,y_{<t}).$$

If the model assigns probabilities `0.8, 0.5, 0.25` to three correct response tokens, the losses are `−log(0.8)`, `−log(0.5)`, and `−log(0.25)`. The sum is `2.303`, exactly the source mechanic. Low probability receives a large penalty because `−log(p)` rises sharply near zero.

```python
response_probs_w = np.array([0.8, 0.5, 0.25])  # probabilities assigned to correct response tokens.
token_losses_w = -np.log(response_probs_w)  # negative log likelihood per response token.
print("token losses:", np.round(token_losses_w, 3))  # [0.223, 0.693, 1.386].
print("sum SFT loss:", round(float(np.sum(token_losses_w)), 3))  # 2.303.
assert round(float(np.sum(token_losses_w)), 3) == 2.303  # verify the source lesson number.
```
▶ What you'll see: the least confident token, probability 0.25, contributes the biggest loss.

```python
plt.figure(figsize=(4.5, 3))  # create a compact response-loss plot.
plt.bar(["tok1 p=.8", "tok2 p=.5", "tok3 p=.25"], token_losses_w, color="purple")  # show per-token losses.
plt.title("3: -log probability penalizes low confidence")  # title the chart.
plt.ylabel("negative log-probability")  # label the loss scale.
plt.xticks(rotation=15)  # keep labels readable.
plt.show()  # display the bar chart.
```
▶ What you'll see: loss grows nonlinearly as the correct-token probability falls.

*Why it's done this way: maximizing the product of correct-token probabilities is equivalent to minimizing the sum of negative logs. Logs turn a sequence product into an additive objective, and the negative sign makes better probabilities smaller losses for gradient descent.*

### 4. Loss masking: prompt tokens must not train the model to echo the prompt

The most important implementation detail is the loss mask. Prompt tokens condition the model, but their losses are set to zero. If a sequence has 5 prompt tokens and 3 response tokens, only `3/8 = 37.5%` of positions receive loss. This is not a bookkeeping trick; it changes the behavior being optimized.

```python
all_probs_w = np.array([0.7, 0.6, 0.9, 0.4, 0.8, 0.8, 0.5, 0.25])  # correct-token probabilities for 8 positions.
mask_w = np.array([0, 0, 0, 0, 0, 1, 1, 1], dtype=float)  # first 5 prompt positions off, last 3 response positions on.
all_losses_w = -np.log(all_probs_w)  # loss each position would have if trained.
masked_losses_w = all_losses_w * mask_w  # zero out prompt-token loss.
print("loss mask:", mask_w.astype(int).tolist())  # inspect which positions count.
print("fraction trained:", f"{100 * mask_w.mean():.1f}%")  # 37.5% from the source lesson.
assert round(float(mask_w.mean()), 3) == 0.375  # verify 3/8 response positions.
```
▶ What you'll see: prompt positions have mask 0, while exactly three response positions have mask 1.

```python
prompt_loss_if_wrong_w = float(np.sum(all_losses_w[:5]))  # loss we would add if prompt tokens were mistakenly trained.
response_loss_right_w = float(np.sum(masked_losses_w))  # correct response-only SFT loss.
print("prompt loss if unmasked:", round(prompt_loss_if_wrong_w, 3))  # unnecessary echo-training pressure.
print("response-only loss:", round(response_loss_right_w, 3))  # the SFT objective.
plt.figure(figsize=(6, 3))  # create a per-position loss plot.
plt.bar(np.arange(8), all_losses_w, color="lightgray", label="would-be loss")  # show every token's raw loss.
plt.bar(np.arange(8), masked_losses_w, color="seagreen", label="masked SFT loss")  # show active loss only.
plt.title("4: masking removes prompt-token loss")  # title the masking plot.
plt.xlabel("token position")  # label positions.
plt.ylabel("loss")  # label loss magnitude.
plt.legend()  # distinguish raw and masked loss.
plt.show()  # display the plot.
```
▶ What you'll see: gray prompt losses exist mathematically, but green SFT loss appears only on response tokens.

*Why it's done this way: the conditional distribution we want is `answer given prompt`, not `prompt given previous prompt`. Masking implements that conditional objective. Without it, gradients push the model to model user instructions and delimiters as targets, which can increase prompt echoing and dilute the answer-learning signal.*

### 5. Mixture weights decide which behaviors dominate training

Instruction datasets are mixtures: chat, math, code, safety, formatting, and domain tasks. A combined loss is often a weighted average of component losses. With weights `0.7` chat and `0.3` code, losses `1.0` and `2.0` combine to `1.300`. The rare behavior can be drowned out if its weight is too small, even when its own loss is high.

```python
component_names_w = np.array(["chat", "code"])  # two dataset slices.
weights_w = np.array([0.7, 0.3])  # mixture weights.
losses_mix_w = np.array([1.0, 2.0])  # current loss in each slice.
combined_w = float(np.sum(weights_w * losses_mix_w))  # weighted combined loss.
print("weighted components:", np.round(weights_w * losses_mix_w, 3))  # contribution of each slice.
print("combined loss:", round(combined_w, 3))  # 1.300 from the source lesson.
assert round(combined_w, 3) == 1.300  # verify the source lesson number.
```
▶ What you'll see: chat contributes 0.7 and code contributes 0.6, even though code's raw loss is larger.

```python
code_weights_w = np.linspace(0.05, 0.95, 10)  # sweep possible code weights.
combined_curve_w = (1 - code_weights_w) * losses_mix_w[0] + code_weights_w * losses_mix_w[1]  # combined loss as mixture changes.
plt.figure(figsize=(4.5, 3))  # create a mixture-sweep plot.
plt.plot(code_weights_w, combined_curve_w, marker="o", color="darkorange")  # show how weighting changes objective.
plt.axvline(0.3, color="black", linestyle="--")  # mark the worked 30% code mixture.
plt.title("5: mixture weights change the optimized behavior")  # title the sweep.
plt.xlabel("code mixture weight")  # label mixture axis.
plt.ylabel("combined loss")  # label objective value.
plt.show()  # display the line chart.
```
▶ What you'll see: the total objective shifts linearly as one dataset slice receives more weight.

*Why it's done this way: gradient descent follows the weighted objective, not our intentions. If a behavior has small mixture weight, it contributes fewer gradient updates; if it has large weight, it can reshape the model even if the architecture is unchanged.*

### 6. Formatting tokens are part of the learned distribution

Instruction tuning usually uses a template such as `<user> ... <assistant> ...`. Those tokens are not decoration: they are part of the input distribution and can become strong cues for where the answer begins and ends. Changing the format at inference can remove the cue the model was trained to follow.

```python
format_tokens_w = np.array(["<user>", "instruction", "<assistant>", "answer", "</assistant>"])  # a simplified chat template.
format_ids_w = np.array([1, 0, 1, 0, 1], dtype=bool)  # mark structural tokens.
print("format tokens:", format_tokens_w[format_ids_w].tolist())  # inspect structural markers.
print("content tokens:", format_tokens_w[~format_ids_w].tolist())  # inspect natural-language content.
```
▶ What you'll see: structural markers surround the content and tell the model which role is speaking.

```python
base_odds_w = 1.0  # arbitrary baseline odds for emitting an assistant delimiter.
tuned_odds_w = base_odds_w * np.exp(1.5)  # a +1.5 logit gain multiplies odds.
print("base odds:", round(base_odds_w, 3), "tuned odds:", round(tuned_odds_w, 3))  # inspect the format-token effect.
plt.figure(figsize=(4, 3))  # create an odds comparison plot.
plt.bar(["before", "after +1.5 logit"], [base_odds_w, tuned_odds_w], color=["gray", "teal"])  # show odds change.
plt.title("6: format-token odds after tuning")  # title the plot.
plt.ylabel("relative odds")  # label odds scale.
plt.show()  # display the bar chart.
```
▶ What you'll see: the format marker becomes about 4.48× more likely in odds after a +1.5 logit gain.

*Why it's done this way: the model cannot distinguish “content” from “protocol” except through tokens and loss. A consistent template makes role boundaries predictable, so the same next-token machinery can learn when to answer, when to stop, and what style to use.*

### 7. Token budget turns examples into supervised signal

The amount of SFT signal is counted in response tokens, not just examples. Ten thousand examples with 200 response tokens each create `2,000,000` supervised response positions. Prompt tokens still cost compute as context, but masked prompt tokens do not directly add supervised loss terms.

```python
n_examples_w = 10_000  # number of instruction examples.
response_tokens_each_w = 200  # average response length.
supervised_tokens_w = n_examples_w * response_tokens_each_w  # response positions with loss.
print("supervised response tokens:", f"{supervised_tokens_w:,}")  # 2,000,000 from the source lesson.
assert supervised_tokens_w == 2_000_000  # verify the arithmetic.
```
▶ What you'll see: example count and response length multiply into the actual number of loss-bearing tokens.

```python
lengths_w = np.array([20, 50, 100, 200, 400])  # possible average response lengths.
signal_w = n_examples_w * lengths_w  # supervised tokens at each length.
plt.figure(figsize=(4.5, 3))  # create a token-budget plot.
plt.plot(lengths_w, signal_w / 1_000_000, marker="o", color="crimson")  # show supervised token count in millions.
plt.title("7: response length controls SFT signal")  # title the plot.
plt.xlabel("avg response tokens/example")  # label length axis.
plt.ylabel("supervised tokens (millions)")  # label supervised signal axis.
plt.show()  # display the line chart.
```
▶ What you'll see: supervised signal scales linearly with response length when the number of examples is fixed.

*Why it's done this way: SFT gradients are summed over response positions. Counting examples alone hides whether the model saw a million short answers or a million long reasoning traces; masking means only the response side contributes direct likelihood training.*

### ✍️ Toy 2 · Softmax assigns next-token probability

Instruction tuning still learns by raising the probability of the correct next token. A logit gain
multiplies odds by `exp(gain)`.

```python
import numpy as np
import matplotlib.pyplot as plt

_t2_rng = np.random.default_rng(0)                    # -> seeded generator for reproducibility
t2_vocab = np.array(["yes", "no", "maybe"])           # -> ['yes', 'no', 'maybe']
t2_logits = np.array([0.0, 1.0, -1.0])                # -> [0.0, 1.0, -1.0]
t2_shifted = t2_logits - np.max(t2_logits)           # -> [-1.0, 0.0, -2.0]
t2_weights = np.exp(t2_shifted)                      # -> [0.368, 1.0, 0.135]
t2_probs = t2_weights / np.sum(t2_weights)           # -> [0.245, 0.665, 0.09]
t2_correct_index = 1                                 # -> 1
t2_correct_prob = float(t2_probs[t2_correct_index])  # -> 0.665
t2_gain = 1.2                                        # -> 1.2
t2_odds_multiplier = float(np.exp(t2_gain))          # -> 3.32
print("shifted logits:", t2_shifted.tolist())         # -> [-1.0, 0.0, -2.0]
print("softmax probs:", np.round(t2_probs, 3).tolist()) # -> [0.245, 0.665, 0.09]
print("p(correct='no'):", round(t2_correct_prob, 3))  # -> 0.665
print("odds multiplier:", round(t2_odds_multiplier, 3)) # -> 3.32
assert round(t2_correct_prob, 3) == 0.665
assert round(t2_odds_multiplier, 3) == 3.320

plt.figure(figsize=(4.6, 2.8))
plt.bar(t2_vocab, t2_probs, color=["#9d9d9d", "#4c78a8", "#9d9d9d"])
plt.ylim(0, 1)
plt.ylabel("probability")
plt.title("Toy 2 · correct token gets the largest probability")
plt.show()
```
▶ What you'll see: `no` receives the largest next-token probability, and a +1.2 logit is a 3.32× odds gain.

### ✍️ Toy 6 · Formatting tokens become learned cues

Structural tokens such as `<assistant>` are part of the distribution. A learned logit gain makes those
markers much more likely in odds space.

```python
import numpy as np
import matplotlib.pyplot as plt

_t6_rng = np.random.default_rng(0)                    # -> seeded generator for reproducibility
t6_tokens = np.array(["<user>", "task", "<assistant>", "answer", "</assistant>"]) # -> formatted tokens
t6_structural = np.array([1, 0, 1, 0, 1], dtype=bool) # -> [True, False, True, False, True]
t6_structure_tokens = t6_tokens[t6_structural]       # -> ['<user>', '<assistant>', '</assistant>']
t6_content_tokens = t6_tokens[~t6_structural]        # -> ['task', 'answer']
t6_base_odds = 2.0                                   # -> 2.0
t6_logit_gain = 1.2                                  # -> 1.2
t6_tuned_odds = t6_base_odds * np.exp(t6_logit_gain) # -> 6.64
t6_multiplier = t6_tuned_odds / t6_base_odds         # -> 3.32
print("structure tokens:", t6_structure_tokens.tolist()) # -> ['<user>', '<assistant>', '</assistant>']
```

## 🛠️ Setup

```python
import numpy as np  # load NumPy for arrays, logits, softmax, masks, and numerical checks.
import matplotlib.pyplot as plt  # load Matplotlib for token strips, bar charts, and learning curves.
np.random.seed(0)  # make all examples reproducible across notebook runs.

def softmax(logits):  # Convert a vector of logits into probabilities.
    logits = np.asarray(logits, dtype=float)  # ensure stable floating-point arithmetic.
    shifted = logits - np.max(logits)  # subtracting a constant preserves softmax and prevents overflow.
    exp = np.exp(shifted)  # exponentiate shifted logits.
    return exp / np.sum(exp)  # normalize into a probability distribution.

def nll_from_probs(probs):  # Compute negative log-likelihood for correct-token probabilities.
    probs = np.asarray(probs, dtype=float)  # convert input to an array.
    return -np.log(np.clip(probs, 1e-12, 1.0))  # clip only to avoid log(0) in toy demos.

def masked_sft_loss(probs, mask, reduction="sum"):  # Compute SFT loss on masked response positions.
    losses = nll_from_probs(probs) * np.asarray(mask, dtype=float)  # zero prompt-token losses.
    active = float(np.sum(mask))  # count response positions.
    if reduction == "mean":  # optionally average over active tokens.
        return float(np.sum(losses) / active) if active else 0.0  # avoid divide-by-zero.
    return float(np.sum(losses))  # default to sequence summed NLL.

def show_token_mask(tokens, mask, title):  # Visualize which tokens receive loss.
    plt.figure(figsize=(max(5, 0.7 * len(tokens)), 1.8))  # make figure width match token count.
    plt.imshow(np.asarray(mask, dtype=float)[None, :], cmap="coolwarm", aspect="auto")  # color active positions.
    plt.xticks(range(len(tokens)), tokens, rotation=30, ha="right")  # label tokens on x-axis.
    plt.yticks([])  # hide dummy y-axis.
    plt.title(title)  # title the mask plot.
    plt.show()  # display the plot.
```

### Advanced 2 — Show prompt-echo pressure from a wrong mask

