# 9.13 — Reward Modeling

Reward modeling turns human preference comparisons into a scalar score that later alignment methods can optimize. In this lesson, you will build a tiny reward model from first principles with NumPy, inspect the Bradley-Terry probability behind pairwise preferences, and see why only reward gaps — not absolute reward offsets — determine the training signal.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build reward modeling one idea at a time. Run each cell in order and read the printed intermediate values — every piece of math, including the Bradley-Terry probability and pairwise loss, is derived and shown. This walkthrough is self-contained and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays, vectorized probabilities, and tiny gradient descent.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
np.random.seed(0)  # reproducibility for synthetic preference data.
```

### 1. Preferences become pairs, not absolute labels

A reward model usually does not start with a perfect numeric score for every answer. It starts with comparisons: for the same prompt, a human picked one response over another. We store each response as a small feature vector so the notebook can learn a reward function from scratch, but the key supervision is the pair `(chosen, rejected)`.

```python
responses_w = np.array([
    [0.9, 0.8, 0.1],  # concise, correct, unsafe
    [0.4, 1.0, 0.9],  # less concise, very correct, safe
    [0.8, 0.3, 0.8],  # concise, weak correctness, safe
    [0.2, 0.7, 0.7],  # verbose, fairly correct, safe
])
names_w = ["A", "B", "C", "D"]
print("features = [concise, correct, safe]")
print(np.round(responses_w, 2))
```
▶ What you'll see: four toy responses represented by three measurable properties, not by text.

```python
pairs_w = np.array([[1, 0], [1, 2], [3, 0], [2, 0]])  # each row is [chosen, rejected].
for chosen_w, rejected_w in pairs_w:
    print(f"human preferred {names_w[chosen_w]} over {names_w[rejected_w]}")
```
▶ What you'll see: the labels are relative judgments: B beats A and C, D beats A, C beats A.

*Why it's done this way:* preference labels are easier and more stable than asking humans for calibrated rewards. The model only needs to learn which response should score higher for the same context, so each pair supplies an inequality constraint: `r(chosen) > r(rejected)`.

### 2. A scalar reward is a learned score

The reward model maps response features to one number. In a large language system the features come from a neural network; here we use a linear score `r = x·w` so every term is visible. A bigger reward means the model believes the response is more preferred, but the absolute number is only a training convenience.

```python
w_w = np.array([0.4, 1.2, 1.0])  # weights for concise, correct, safe.
rewards_w = responses_w @ w_w
print("rewards:", dict(zip(names_w, np.round(rewards_w, 3))))
assert round(float(rewards_w[1] - rewards_w[0]), 3) == 0.840
```
▶ What you'll see: B receives a higher scalar reward than A because correctness and safety outweigh concision.

```python
plt.figure(figsize=(4.6, 3))
plt.bar(names_w, rewards_w, color="teal")
plt.title("1: scalar rewards from response features")
plt.ylabel("reward r(x, y)")
plt.show()
```
▶ What you'll see: one bar per response; the model has converted multiple features into one optimization target.

*Why it's done this way:* later RLHF needs a single scalar reward for each sampled response. A scalar collapses many desiderata into one ordering, and a dot product is the smallest inspectable version of the same idea used by a neural reward head.

### 3. Bradley-Terry turns reward gaps into probabilities

The Bradley-Terry model says the probability that the chosen response wins is `σ(r⁺ − r⁻)`, where `σ(z)=1/(1+exp(-z))`. The input is a reward gap, not two independent rewards. A gap of 0 means a 50/50 preference; a positive gap makes the chosen response more likely; a negative gap says the model currently ranks the pair backward.

```python
def sigmoid_w(z_w):
    return 1 / (1 + np.exp(-z_w))

gap_w = 1.5
prob_w = float(sigmoid_w(gap_w))
print("gap:", gap_w, "preference probability:", round(prob_w, 3))
assert round(prob_w, 3) == 0.818
```
▶ What you'll see: a reward gap of 1.5 becomes a preference probability of 0.818.

```python
gaps_w = np.linspace(-4, 4, 200)
probs_w = sigmoid_w(gaps_w)
plt.figure(figsize=(4.6, 3))
plt.plot(gaps_w, probs_w, color="purple")
plt.axvline(0, color="black", linewidth=0.8)
plt.axhline(0.5, color="gray", linestyle="--")
plt.title("2: Bradley-Terry probability σ(r⁺ − r⁻)")
plt.xlabel("reward gap")
plt.ylabel("P(chosen beats rejected)")
plt.show()
```
▶ What you'll see: the S-curve crosses 0.5 at gap 0 and saturates near 0 or 1 for large gaps.

*Why it's done this way:* a probability must stay between 0 and 1, and the sigmoid is the smooth monotone map that turns any real-valued reward difference into that range. Using the difference encodes the comparison directly: the model is trained to put chosen answers above rejected answers.

### 4. Pairwise loss punishes backward rankings

The reward-model loss for one pair is `-log σ(r⁺ − r⁻)`. If the chosen response already has a much larger reward, the probability is high and the loss is small. If the rejected response scores higher, the probability is low and the loss is large. This is logistic classification where the "logit" is the reward gap.

```python
gaps_demo_w = np.array([1.5, 0.0, -1.0])
probs_demo_w = sigmoid_w(gaps_demo_w)
losses_demo_w = -np.log(probs_demo_w)
print("probabilities:", np.round(probs_demo_w, 3))
print("pairwise losses:", np.round(losses_demo_w, 3))
assert round(float(losses_demo_w[0]), 3) == 0.201
assert round(float(losses_demo_w[2]), 3) == 1.313
```
▶ What you'll see: a correct gap has low loss, a tie has loss 0.693, and a reversed gap has high loss.

```python
loss_curve_w = -np.log(sigmoid_w(gaps_w))
plt.figure(figsize=(4.6, 3))
plt.plot(gaps_w, loss_curve_w, color="crimson")
plt.title("3: pairwise loss falls as the chosen gap grows")
plt.xlabel("reward gap r⁺ − r⁻")
plt.ylabel("-log σ(gap)")
plt.ylim(0, 5)
plt.show()
```
▶ What you'll see: loss drops toward 0 for large positive gaps and grows almost linearly for wrong negative gaps.

*Why it's done this way:* taking `-log(probability)` converts a probabilistic preference into an additive optimization objective. The gradient is strongest when the model is confidently wrong and small when the pair is already separated in the correct direction.

### 5. Offsets do not matter; gaps do

Because the loss uses `r⁺ − r⁻`, adding the same constant to every reward changes nothing. This is why reward models are identifiable only up to an offset: `[-1, 1]` and `[4, 6]` imply the same preference probability for a pair with the same gap.

```python
r_plus_w, r_minus_w = 2.0, 0.5
p_original_w = float(sigmoid_w(r_plus_w - r_minus_w))
p_shifted_w = float(sigmoid_w((r_plus_w + 5) - (r_minus_w + 5)))
print("original prob:", round(p_original_w, 3), "shifted prob:", round(p_shifted_w, 3))
assert round(p_original_w, 3) == round(p_shifted_w, 3) == 0.818
```
▶ What you'll see: adding +5 to both rewards leaves the Bradley-Terry probability unchanged.

```python
offsets_w = np.linspace(-5, 5, 51)
probs_offset_w = sigmoid_w((r_plus_w + offsets_w) - (r_minus_w + offsets_w))
plt.figure(figsize=(4.6, 3))
plt.plot(offsets_w, probs_offset_w, color="seagreen")
plt.title("4: common reward offsets are invisible")
plt.xlabel("constant added to both rewards")
plt.ylabel("preference probability")
plt.ylim(0, 1)
plt.show()
```
▶ What you'll see: a flat line — changing the offset does not change the comparison.

*Why it's done this way:* pairwise data can teach order, not an absolute origin for the reward scale. Any later system that uses rewards should care about relative improvement and calibration checks, not the arbitrary zero point learned by the reward head.

### 6. Training a tiny reward model from preference pairs

Now we learn the reward weights `w` by gradient descent. For one pair, `gap = (x⁺ − x⁻)·w`. The loss gradient is `(σ(gap) − 1)(x⁺ − x⁻)`: if the chosen response is not above the rejected response, the update pushes `w` toward features that distinguish the chosen answer.

```python
X_w = responses_w
pref_pairs_w = pairs_w
w_train_w = np.zeros(3)
eta_w = 0.8
loss_history_w = []
print("initial weights:", w_train_w)
```
▶ What you'll see: the reward model begins with all rewards tied at 0.

```python
for epoch_w in range(80):
    total_w = 0.0
    grad_w = np.zeros_like(w_train_w)
    for c_w, r_w in pref_pairs_w:
        diff_w = X_w[c_w] - X_w[r_w]
        gap_pair_w = float(diff_w @ w_train_w)
        prob_pair_w = float(sigmoid_w(gap_pair_w))
        total_w += -np.log(prob_pair_w)
        grad_w += (prob_pair_w - 1.0) * diff_w
    w_train_w -= eta_w * grad_w / len(pref_pairs_w)
    loss_history_w.append(total_w / len(pref_pairs_w))
print("learned weights:", np.round(w_train_w, 3))
print("loss start -> end:", round(loss_history_w[0], 3), "->", round(loss_history_w[-1], 3))
assert loss_history_w[-1] < loss_history_w[0]
```
▶ What you'll see: average pairwise loss falls below its initial 0.693 tie loss.

```python
trained_rewards_w = X_w @ w_train_w
trained_gaps_w = np.array([trained_rewards_w[c_w] - trained_rewards_w[r_w] for c_w, r_w in pref_pairs_w])
print("trained rewards:", dict(zip(names_w, np.round(trained_rewards_w, 3))))
print("trained pair gaps:", np.round(trained_gaps_w, 3))
plt.figure(figsize=(4.8, 3))
plt.plot(loss_history_w, color="navy")
plt.title("5: reward-model training loss")
plt.xlabel("epoch")
plt.ylabel("mean pairwise loss")
plt.show()
```
▶ What you'll see: loss decreases as the learned rewards separate chosen responses from rejected ones.

*Why it's done this way:* the gradient only sees feature differences between chosen and rejected answers. That is exactly the Bradley-Terry assumption: increase the reward gap for preferred responses, leave irrelevant common offsets alone, and aggregate many pair constraints into one scalar reward function.

### ✍️ Toy 3 · Bradley-Terry turns a reward gap into probability

The sigmoid of the chosen-minus-rejected reward gap is the model's probability that the chosen answer
wins.

```python
import numpy as np
import matplotlib.pyplot as plt

_t3_rng = np.random.default_rng(0)                    # -> seeded generator for reproducibility
def t3_sigmoid(t3_z):

t3_gap = 1.2                                          # -> 1.2
t3_prob = float(t3_sigmoid(t3_gap))                   # -> 0.769

t3_grid = np.linspace(-4, 4, 100)

plt.figure(figsize=(4.6, 2.8))
```

### ✍️ Toy 6 · Gradient steps separate preferred pairs

A tiny linear reward model starts with tied rewards. Bradley-Terry gradients move the weights so chosen
responses score above rejected ones and the mean pairwise loss falls.

```python
import numpy as np
import matplotlib.pyplot as plt

_t6_rng = np.random.default_rng(0)                    # -> seeded generator for reproducibility
def t6_sigmoid(t6_z):
    return 1 / (1 + np.exp(-t6_z))

t6_X = np.array([[0.9, 0.2], [0.3, 0.9], [0.7, 0.7]]) # -> three response feature vectors
t6_pairs = np.array([[1, 0], [2, 0], [1, 2]])         # -> chosen/rejected pairs
t6_w = np.zeros(2)                                    # -> [0.0, 0.0]
t6_eta = 0.9                                          # -> 0.9
t6_losses = []
print("initial weights:", t6_w.tolist())              # -> [0.0, 0.0]
for t6_epoch in range(8):
    t6_total = 0.0
    t6_grad = np.zeros_like(t6_w)
    for t6_chosen, t6_rejected in t6_pairs:
        t6_diff = t6_X[t6_chosen] - t6_X[t6_rejected]
        t6_gap = float(t6_diff @ t6_w)
        t6_prob = float(t6_sigmoid(t6_gap))
        t6_total = t6_total - np.log(t6_prob)
        t6_grad = t6_grad + (t6_prob - 1.0) * t6_diff
    t6_loss = t6_total / len(t6_pairs)
    t6_losses.append(t6_loss)
    t6_w = t6_w - t6_eta * t6_grad / len(t6_pairs)
t6_rewards = t6_X @ t6_w                              # -> [-0.714, 0.79, 0.116]
t6_gaps = np.array([t6_rewards[t6_c] - t6_rewards[t6_r] for t6_c, t6_r in t6_pairs]) # -> [1.503, 0.83, 0.673]
print("loss history:", np.round(t6_losses, 4).tolist()) # -> [0.6931, 0.6122, 0.546, 0.4914, 0.4461, 0.4082, 0.3761, 0.3486]
print("learned weights:", np.round(t6_w, 3).tolist()) # -> [-1.067, 1.233]
print("trained rewards:", np.round(t6_rewards, 3).tolist()) # -> [-0.714, 0.79, 0.116]
print("trained gaps:", np.round(t6_gaps, 3).tolist()) # -> [1.503, 0.83, 0.673]
assert t6_losses[-1] < t6_losses[0]
assert np.all(t6_gaps > 0)

plt.figure(figsize=(4.6, 2.8))
plt.plot(range(len(t6_losses)), t6_losses, marker="o", color="#4c78a8")
plt.xlabel("epoch")
plt.ylabel("mean pairwise loss")
plt.title("Toy 6 · reward-model loss falls")
plt.show()
```
▶ What you'll see: loss decreases, and every trained chosen-minus-rejected gap is positive.

## 🛠️ Setup

```python
import numpy as np
import matplotlib.pyplot as plt
np.random.seed(0)

def sigmoid(z):
    z = np.asarray(z, dtype=float)
    return 1 / (1 + np.exp(-z))

def reward_scores(X, w):
    return np.asarray(X, dtype=float) @ np.asarray(w, dtype=float)

def pairwise_loss_from_gap(gap):
    return -np.log(sigmoid(gap))

def preference_prob(r_plus, r_minus):
    return sigmoid(np.asarray(r_plus) - np.asarray(r_minus))
```

## 🟢 Basics (warm-up)

### Basic 1 — Store a preference pair

**Goal.** Represent one human comparison as chosen and rejected feature vectors, because reward modeling learns from relative preferences rather than absolute labels. We build it in 2 steps.

```python
chosen_b1 = np.array([0.4, 1.0, 0.9])
rejected_b1 = np.array([0.9, 0.8, 0.1])
print("chosen features:", chosen_b1)
print("rejected features:", rejected_b1)
```
▶ What you'll see: each response has features for concision, correctness, and safety.

```python
diff_b1 = chosen_b1 - rejected_b1
print("chosen - rejected:", diff_b1)
plt.figure(figsize=(4, 3))
plt.bar(["concise", "correct", "safe"], diff_b1, color="teal")
plt.axhline(0, color="black", linewidth=0.8)
plt.title("Basic 1: feature difference in a preference pair")
plt.show()
```
▶ What you'll see: the chosen answer is safer and more correct, but less concise.

👀 Takeaway: a preference pair tells the model which feature tradeoff should win.

### Basic 2 — Score responses with a reward vector

**Goal.** Convert response features into scalar rewards, because later alignment steps need one number per response. We build it in 2 steps.

```python
X_b2 = np.array([[0.9, 0.8, 0.1], [0.4, 1.0, 0.9]])
w_b2 = np.array([0.4, 1.2, 1.0])
print("X shape:", X_b2.shape, "w:", w_b2)
```
▶ What you'll see: two response vectors and one reward-weight vector.

```python
r_b2 = reward_scores(X_b2, w_b2)
print("rewards:", np.round(r_b2, 3))
assert np.allclose(np.round(r_b2, 3), [1.42, 2.26])
plt.figure(figsize=(4, 3))
plt.bar(["rejected", "chosen"], r_b2, color=["gray", "seagreen"])
plt.title("Basic 2: scalar reward scores")
plt.ylabel("reward")
plt.show()
```
▶ What you'll see: the chosen response receives the higher reward under these weights.

👀 Takeaway: the reward head collapses multiple response properties into one learned score.

### Basic 3 — Compute a reward gap

**Goal.** Subtract rejected reward from chosen reward, because Bradley-Terry uses the gap as its logit. We build it in 2 steps.

```python
r_plus_b3 = 2.26
r_minus_b3 = 1.42
print("r+:", r_plus_b3, "r-:", r_minus_b3)
```

### Advanced 5 — Train with a held-out preference set

**Goal.** Track training and validation pairwise loss, because lower training loss only matters when held-out comparisons improve too. We build it in 5 steps.

```python
X_a5 = np.array([[0.9, 0.8, 0.1], [0.4, 1.0, 0.9], [0.8, 0.3, 0.8], [0.2, 0.7, 0.7], [0.6, 0.9, 0.8]])
train_pairs_a5 = np.array([[1, 0], [1, 2], [3, 0], [4, 2]])
val_pairs_a5 = np.array([[4, 0], [1, 3]])
w_a5 = np.zeros(3)
print("train pairs:", train_pairs_a5.tolist(), "val pairs:", val_pairs_a5.tolist())
```
▶ What you'll see: validation pairs are not used for gradient updates.

```python
def mean_pair_loss_a5(X, w, pairs):
    vals = []
    for c, r in pairs:
        vals.append(float(pairwise_loss_from_gap((X[c] - X[r]) @ w)))
    return float(np.mean(vals))

train_curve_a5 = []
val_curve_a5 = []
for epoch_a5 in range(90):
    grad_a5 = np.zeros_like(w_a5)
    for c_a5, r_a5 in train_pairs_a5:
        diff_a5 = X_a5[c_a5] - X_a5[r_a5]
        grad_a5 += (float(sigmoid(diff_a5 @ w_a5)) - 1.0) * diff_a5
    w_a5 -= 0.7 * grad_a5 / len(train_pairs_a5)
    train_curve_a5.append(mean_pair_loss_a5(X_a5, w_a5, train_pairs_a5))
    val_curve_a5.append(mean_pair_loss_a5(X_a5, w_a5, val_pairs_a5))
print("final train/val:", round(train_curve_a5[-1], 3), round(val_curve_a5[-1], 3))
```

```python

for c_a5, r_a5 in val_pairs_a5:
    val_probs_a5.append(float(sigmoid((X_a5[c_a5] - X_a5[r_a5]) @ w_a5)))
print("validation probabilities:", np.round(val_probs_a5, 3))
assert train_curve_a5[-1] < train_curve_a5[0]
```
