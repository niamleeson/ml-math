# 11.19 — Soft Actor-Critic

Soft Actor-Critic (SAC) is reinforcement learning with a deliberate appetite for randomness: the agent optimizes reward **plus entropy**, so a good policy is not just high-scoring but also keeps useful options alive. In this lesson, you will build maximum-entropy RL from first principles with tiny NumPy tables, inspect the soft value and temperature terms, and see how SAC's critic and actor updates are shaped by bootstrapping, exploration pressure, and policy support.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build Soft Actor-Critic one idea at a time. Run each cell in order and read the printed intermediate values — every piece of math, including maximum-entropy return, soft value, temperature, critic targets, and policy improvement, is shown in small NumPy tables. This walkthrough is self-contained and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays, probabilities, and tabular Bellman backups.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
np.random.seed(0)  # reproducibility for sampling demonstrations.
```

### 1. The tiny MDP ledger: state, action, reward, next state

SAC still begins with ordinary reinforcement-learning bookkeeping: a state `s`, an action `a`, an immediate reward, and a next state. The difference is not the data structure; it is the objective placed on top of it. We will use a two-state, two-action world where action 0 is safer and action 1 sometimes opens a better future, so the agent must care about delayed consequence rather than only the current reward.

```python
states_w = ["start", "goalish"]  # two states keep the tables readable.
actions_w = ["safe", "risky"]  # two actions make every policy a pair of probabilities.
R_w = np.array([[1.0, 0.0],        # rewards from start: safe pays now, risky pays later.
                [0.4, 1.6]])       # rewards from goalish: risky is better.
next_state_w = np.array([[0, 1],   # safe stays at start; risky moves to goalish.
                         [1, 1]])  # both goalish actions keep us there.
print("reward table R[s,a]:\n", R_w)
print("next-state table:\n", next_state_w)
```
▶ What you'll see: rewards and transitions have shape 2×2, so every action-value table will also have shape 2×2.

```python
plt.figure(figsize=(4.4, 3.1))
plt.imshow(R_w, cmap="viridis", aspect="auto")
plt.colorbar(label="immediate reward")
plt.xticks(range(2), actions_w); plt.yticks(range(2), states_w)
plt.title("1: reward ledger R(s,a)"); plt.show()
```
▶ What you'll see: the safe action is immediately attractive at the start, while the risky action becomes attractive in the second state.

*Why it's done this way:* SAC is often described with neural networks, but the mathematical objects are just tables here: $Q(s,a)$ has one row per state and one column per action. Making the shapes explicit prevents a common RL bug — mixing a scalar reward, a state value $V(s)$, and an action value $Q(s,a)$ as if they were interchangeable.

### 2. Discounted consequence: reward is not return

The return is the discounted sum of future rewards, not the first reward alone. With discount $\gamma$, a reward one step later is multiplied by $\gamma$, two steps later by $\gamma^2$, and so on. That lets the agent value durable plans while still treating distant rewards as less certain and less immediate.

```python
rewards_path_w = np.array([1.0, 0.0, 2.0])  # the worked sequence from the source lesson.
gamma_w = 0.9  # future rewards count, but are discounted.
discounts_w = gamma_w ** np.arange(len(rewards_path_w))  # [1, gamma, gamma^2].
return_w = float(np.sum(discounts_w * rewards_path_w))
print("discounts:", np.round(discounts_w, 3))
print("discounted return:", round(return_w, 3))
assert round(return_w, 3) == 2.620
```
▶ What you'll see: the delayed reward of 2 contributes 1.620, so the total return is 2.620.

```python
plt.figure(figsize=(4.4, 3))
plt.bar(["t", "t+1", "t+2"], discounts_w * rewards_path_w, color="teal")
plt.title("2: each future reward is discounted")
plt.ylabel("contribution to G"); plt.show()
```
▶ What you'll see: the third bar is smaller than the raw reward 2 because it is multiplied by $0.9^2$.

*Why it's done this way:* RL needs a target that includes consequences caused by the current action. Discounting is the simplest mathematical compromise: future payoff still matters, but bootstrapping remains finite and immediate errors are not overwhelmed by far-away guesses.

### 3. Entropy: randomness becomes part of the objective

SAC is a maximum-entropy method. It adds $\alpha H(\pi(\cdot\mid s))$ to the value of being in a state, where $H(\pi)=-\sum_a \pi(a)\log\pi(a)$. A deterministic policy has entropy near 0; a spread-out policy has higher entropy. SAC treats that entropy bonus as useful because uncertainty can preserve exploration and improve robustness.

```python
pi_peaked_w = np.array([0.95, 0.05])  # nearly deterministic.
pi_mixed_w = np.array([0.5, 0.5])      # maximum entropy for two actions.
entropy_peaked_w = float(-np.sum(pi_peaked_w * np.log(pi_peaked_w)))
entropy_mixed_w = float(-np.sum(pi_mixed_w * np.log(pi_mixed_w)))
print("entropy peaked:", round(entropy_peaked_w, 3))
print("entropy mixed:", round(entropy_mixed_w, 3))
assert round(entropy_mixed_w, 3) == 0.693
```
▶ What you'll see: the balanced policy has entropy 0.693 nats, much larger than the peaked policy.

```python
plt.figure(figsize=(5, 3))
plt.bar(["peaked", "mixed"], [entropy_peaked_w, entropy_mixed_w], color=["crimson", "seagreen"])
plt.title("3: entropy rewards spread-out action probabilities")
plt.ylabel("H(π)"); plt.show()
```
▶ What you'll see: the mixed policy receives a larger entropy bonus because it keeps both actions alive.

*Why it's done this way:* Ordinary RL asks for high reward. Maximum-entropy RL asks for high reward **and** high action uncertainty unless the reward evidence justifies becoming confident. The logarithm appears because entropy measures expected surprise: assigning probability to multiple actions produces a positive bonus, while collapsing onto one action removes it.

### 4. Soft value: expected Q plus entropy bonus

For a fixed policy, the SAC state value is soft:

$$V^{\pi}_{\text{soft}}(s)=\sum_a \pi(a\mid s)\bigl(Q(s,a)-\alpha\log\pi(a\mid s)\bigr).$$

The first term is expected action value. The second term is the entropy bonus because $-\sum_a\pi(a)\log\pi(a)=H(\pi)$. So the same Q-table can yield a larger value under a more exploratory policy when $\alpha>0$.

```python
Q_state_w = np.array([2.0, 0.0])  # action values in one state.
pi_soft_w = np.array([0.731, 0.269])  # softmax-like policy from logits [1, 0].
alpha_w = 0.2  # temperature: reward paid per nat of entropy.
expected_q_w = float(np.sum(pi_soft_w * Q_state_w))
entropy_w = float(-np.sum(pi_soft_w * np.log(pi_soft_w)))
soft_value_w = expected_q_w + alpha_w * entropy_w
print("expected Q:", round(expected_q_w, 3))
print("entropy bonus:", round(alpha_w * entropy_w, 3))
print("soft value:", round(soft_value_w, 3))
assert round(expected_q_w, 3) == 1.462
```
▶ What you'll see: the expected Q is 1.462 and entropy adds a small positive bonus.

```python
plt.figure(figsize=(4.5, 3))
plt.bar(["E[Q]", "αH", "soft V"], [expected_q_w, alpha_w * entropy_w, soft_value_w], color=["teal", "orange", "purple"])
plt.title("4: soft value = expected Q + entropy")
plt.ylabel("value component"); plt.show()
```
▶ What you'll see: soft value is slightly taller than expected Q because stochasticity is rewarded.

*Why it's done this way:* Writing the value as $\sum_a\pi(a)(Q-\alpha\log\pi)$ is more than algebraic decoration. It makes the policy's own probability part of the return, so a critic trained with this target evaluates not just outcomes, but outcomes under a policy that is intentionally allowed to remain stochastic.

### 5. Temperature $\alpha$: how much randomness is worth

The temperature $\alpha$ controls the tradeoff between reward and entropy. When $\alpha=0$, SAC reduces to ordinary expected-value optimization. As $\alpha$ grows, the policy is paid more for being random, so a lower-reward but more uncertain policy can become attractive.

```python
alphas_w = np.array([0.0, 0.1, 0.5, 1.0])  # increasing entropy price.
soft_values_w = expected_q_w + alphas_w * entropy_w
print("alphas:", alphas_w)
print("soft values:", np.round(soft_values_w, 3))
assert round(float(soft_values_w[0]), 3) == 1.462
```
▶ What you'll see: the same policy becomes more valuable as $\alpha$ rises because its entropy is worth more.

```python
plt.figure(figsize=(4.6, 3))
plt.plot(alphas_w, soft_values_w, marker="o", color="darkorange")
plt.title("5: temperature scales the entropy bonus")
plt.xlabel("α"); plt.ylabel("soft value"); plt.show()
```
▶ What you'll see: a straight line because the entropy of this fixed policy is constant and only its price changes.

*Why it's done this way:* Temperature is a unit conversion between reward and nats of entropy. If $\alpha$ is too small, SAC becomes nearly greedy and may stop exploring early. If $\alpha$ is too large, the agent can keep randomizing even when one action is clearly better. That is why practical SAC often tunes $\alpha$ toward a target entropy.

### 6. Soft Bellman backup: bootstrapping from a soft next value

The critic target in tabular SAC has the same Bellman shape as Q-learning, but the next value is soft:

$$y=r+\gamma V_{\text{soft}}(s').$$

The target still bootstraps from the learner's current estimate of the next state, which lowers variance compared with waiting for full returns, but it also means bad estimates can be copied forward if the step size is too aggressive.

```python
r_w = 1.0
next_v_w = 0.8
gamma_w = 0.9
y_w = r_w + gamma_w * next_v_w
q_old_w = 0.4
step_w = 0.5
q_new_w = q_old_w + step_w * (y_w - q_old_w)
print("one-step target y:", round(y_w, 3))
print("updated Q:", round(q_new_w, 3))
assert round(y_w, 3) == 1.720 and round(q_new_w, 3) == 1.060
```
▶ What you'll see: the target is 1.720 and the old Q moves halfway to 1.060.

```python
plt.figure(figsize=(4.5, 3))
plt.bar(["old Q", "target y", "new Q"], [q_old_w, y_w, q_new_w], color=["gray", "green", "teal"])
plt.title("6: critic moves toward a bootstrapped target")
plt.ylabel("Q estimate"); plt.show()
```
▶ What you'll see: the new estimate lies between the old estimate and the target because the step size is 0.5.

*Why it's done this way:* Bootstrapping is a bias-variance tradeoff. The target is biased when $V_{\text{soft}}(s')$ is wrong, but much lower variance than waiting for entire sampled episodes. SAC stabilizes this idea in practice with target networks and clipped double critics; in this notebook, we expose the one-step arithmetic first.

### 7. Soft policy improvement: better actions get probability, but not all of it

Given a Q row, the entropy-regularized best policy is proportional to $\exp(Q(s,a)/\alpha)$. This is the softmax bridge from values to action probabilities. Large Q still wins, but the temperature decides how sharply probability mass concentrates.

```python
Q_improve_w = np.array([2.0, 0.0])  # two action values.
alpha_policy_w = 1.0  # use a large temperature to match the source softmax example.
shifted_w = Q_improve_w / alpha_policy_w - np.max(Q_improve_w / alpha_policy_w)
pi_improve_w = np.exp(shifted_w) / np.sum(np.exp(shifted_w))
expected_reward_w = float(np.sum(pi_improve_w * np.array([2.0, 0.0])))
print("policy probabilities:", np.round(pi_improve_w, 3))
print("expected reward:", round(expected_reward_w, 3))
assert np.allclose(np.round(pi_improve_w, 3), [0.881, 0.119])
```
▶ What you'll see: the higher-Q action gets most, but not all, of the probability.

```python
plt.figure(figsize=(4.4, 3))
plt.bar(actions_w, pi_improve_w, color="seagreen")
plt.title("7: softmax turns Q into a stochastic policy")
plt.ylabel("π(a|s)"); plt.ylim(0, 1); plt.show()
```
▶ What you'll see: the safe-looking action dominates, while the other action remains sampled sometimes.

*Why it's done this way:* Greedy improvement would place probability 1 on the largest Q and 0 elsewhere. SAC's soft improvement instead solves a reward-plus-entropy problem, so the policy is allowed to hedge when values are close or when high temperature says exploration is still valuable.

### 8. Actor and critic together: a tiny SAC-style training loop

SAC alternates two ideas: update the critic toward a soft Bellman target, then update the actor toward the soft policy implied by the critic. In a tabular notebook, we can do that directly: compute $V_{\text{soft}}$ from the current policy, update Q values from sampled transitions, then refresh the policy with a softmax over Q.

```python
Q_train_w = np.zeros((2, 2))  # critic table starts ignorant.
pi_train_w = np.ones((2, 2)) / 2  # actor starts uniformly random.
alpha_train_w = 0.4
gamma_train_w = 0.9
eta_train_w = 0.25
losses_w = []
print("initial Q:\n", Q_train_w)
print("initial policy:\n", pi_train_w)
```
▶ What you'll see: both states begin with equal action probabilities and zero critic values.

```python
for sweep_w in range(80):
    for s_w in range(2):
        for a_w in range(2):
            sp_w = next_state_w[s_w, a_w]
            v_next_w = float(np.sum(pi_train_w[sp_w] * (Q_train_w[sp_w] - alpha_train_w * np.log(pi_train_w[sp_w]))))
            target_w = R_w[s_w, a_w] + gamma_train_w * v_next_w
            Q_train_w[s_w, a_w] += eta_train_w * (target_w - Q_train_w[s_w, a_w])
    logits_w = Q_train_w / alpha_train_w
    logits_w = logits_w - logits_w.max(axis=1, keepdims=True)
    pi_train_w = np.exp(logits_w) / np.exp(logits_w).sum(axis=1, keepdims=True)
    losses_w.append(float(np.mean((Q_train_w - R_w) ** 2)))
print("trained Q:\n", np.round(Q_train_w, 3))
print("trained policy:\n", np.round(pi_train_w, 3))
assert pi_train_w[1, 1] > 0.9
```
▶ What you'll see: the second state's risky action becomes very likely, while the start state keeps some probability on both options.

```python
plt.figure(figsize=(5, 3))
plt.plot(losses_w, color="purple")
plt.title("8: repeated soft backups change the critic")
plt.xlabel("sweep"); plt.ylabel("mean (Q - immediate R)^2"); plt.show()

plt.figure(figsize=(4.6, 3.2))
plt.imshow(pi_train_w, cmap="viridis", aspect="auto", vmin=0, vmax=1)
plt.colorbar(label="action probability")
plt.xticks(range(2), actions_w); plt.yticks(range(2), states_w)
plt.title("8: final soft actor policy"); plt.show()
```
▶ What you'll see: the critic changes as it bootstraps, and the final heatmap shows a stochastic but value-aware actor.

*Why it's done this way:* This loop is not full industrial SAC, but it contains the core logic: soft targets evaluate a stochastic policy, and soft policy improvement turns critic differences into probability differences. The actor is not random because of noise injection; it is random because entropy is in the objective.

```python
rewards_b2 = np.array([1.0, 0.0, 2.0]) # define a three-step reward stream.
```

### Basic 3 — Bootstrap one Q estimate

### Basic 8 — Compute a soft Bellman target

**Goal.** Replace the next value in a Bellman target with a soft value, because SAC critics bootstrap from reward plus entropy-aware future consequence. We build it in 2 steps.


▶ What you'll see: the exploratory policy gives the critic much more evidence about the second action.

👀 Takeaway: entropy is not cosmetic; it changes what data enters the replay buffer and which actions can be evaluated safely.

### Advanced 5 — Trace reward-entropy tradeoffs across policies

**Goal.** Plot expected reward, entropy, and soft objective for many policies, because SAC chooses a stochastic optimum when entropy is valuable. We build it in 5 steps.

```python
p_grid_a5 = np.linspace(0.01, 0.99, 99) # probability of action 0.
Q_a5 = np.array([2.0, 1.0]) # action 0 has higher reward value.
alpha_a5 = 0.8 # large enough to make entropy visibly matter.
print("Q values:", Q_a5, "alpha:", alpha_a5) # inspect objective ingredients.
```
▶ What you'll see: action 0 is better by reward alone.

```python
policies_a5 = np.column_stack([p_grid_a5, 1 - p_grid_a5]) # build all two-action policies.
expected_q_a5 = policies_a5 @ Q_a5 # compute expected Q for each policy.
entropy_a5 = -np.sum(policies_a5 * np.log(policies_a5), axis=1) # compute entropy for each policy.
soft_obj_a5 = expected_q_a5 + alpha_a5 * entropy_a5 # compute SAC objective.
best_idx_a5 = int(np.argmax(soft_obj_a5)) # find best soft policy.
print("best p(a0):", round(float(p_grid_a5[best_idx_a5]), 3)) # inspect entropy-regularized optimum.
assert 0.7 < p_grid_a5[best_idx_a5] < 0.9 # verify optimum is stochastic, not p=0.99.
```

```python
greedy_idx_a5 = int(np.argmax(expected_q_a5)) # find reward-only best policy on the grid.
print("reward-only best p(a0):", round(float(p_grid_a5[greedy_idx_a5]), 3)) # inspect greedy tendency.
print("soft best objective:", round(float(soft_obj_a5[best_idx_a5]), 3)) # inspect objective value.
```

```python
plt.figure(figsize=(5, 3)) # create objective curves.
plt.plot(p_grid_a5, expected_q_a5, label="E[Q]", color="gray") # plot reward-only term.

plt.plot(p_grid_a5, soft_obj_a5, label="E[Q]+αH", color="purple") # plot SAC objective.
plt.axvline(p_grid_a5[best_idx_a5], color="purple", linestyle="--", label="soft optimum") # mark soft optimum.
plt.title("Advanced 5: maximum-entropy objective") # title the plot.

plt.ylabel("objective value") # label objective axis.

```
