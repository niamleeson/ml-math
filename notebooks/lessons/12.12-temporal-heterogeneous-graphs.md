# 12.12 — Temporal & Heterogeneous Graphs

Temporal and heterogeneous graphs extend the usual one-matrix graph view by making **when** an edge happened and **what kind** of edge it was part of the model input. In this lesson, we build time-filtered neighborhoods, decayed temporal weights, typed relation matrices, and meta-path counts from scratch with NumPy so the rules that prevent leakage and preserve semantics are visible cell by cell.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build temporal and heterogeneous graph ideas one piece at a time. Run each cell in order and read the printed intermediate values — every snapshot, mask, relation matrix, and meta-path product is spelled out so nothing is a black box. This walkthrough is self-contained and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays, masks, matrix products, and small graph tensors.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
np.random.seed(0)  # reproducibility for any sampled toy graph.
```

### 1. Temporal edges and snapshots

A temporal graph does not start as one adjacency matrix. It starts as events `(source, target, time)`, and a snapshot at time `t` contains only edges with event time `<= t`. That one inequality is the core anti-leakage rule: if we predict at time 2, an edge at time 3 is future information, not training evidence.

```python
edges_w = np.array([[0, 1, 0],   # 0 followed/contacted 1 at time 0.
                    [1, 2, 1],   # 1 contacted 2 at time 1.
                    [2, 0, 2],   # 2 contacted 0 at time 2.
                    [0, 2, 3]])  # 0 contacted 2 at time 3: future for t=2.
n_nodes_w = 3
print("temporal edges (u, v, time):\n", edges_w)
```
▶ What you'll see: four directed edge events, with the last event intentionally after the prediction time.

```python
def snapshot_w(edges, n_nodes, t):
    A = np.zeros((n_nodes, n_nodes), dtype=int)
    for u, v, tau in edges:
        if tau <= t:
            A[u, v] = 1
    return A

A2_w = snapshot_w(edges_w, n_nodes_w, 2)
A3_w = snapshot_w(edges_w, n_nodes_w, 3)
print("A at time 2:\n", A2_w)
print("A at time 3:\n", A3_w)
assert A2_w[0, 2] == 0 and A3_w[0, 2] == 1
```
▶ What you'll see: edge `(0,2)` is absent at time 2 and present at time 3.

```python
Delta_w = A3_w - A2_w
print("new edges from t=2 to t=3:\n", Delta_w)
print("directed change count:", int(np.abs(Delta_w).sum()))
assert Delta_w[0, 2] == 1
assert int(np.abs(Delta_w).sum()) == 1
plt.figure(figsize=(7, 2.6))
for k, (M, title) in enumerate([(A2_w, "snapshot t=2"), (A3_w, "snapshot t=3"), (Delta_w, "new edge Δ")]):
    plt.subplot(1, 3, k + 1)
    plt.imshow(M, cmap="viridis", vmin=0, vmax=1)
    plt.title(title)
    plt.xticks(range(n_nodes_w)); plt.yticks(range(n_nodes_w))
plt.tight_layout(); plt.show()
```
▶ What you'll see: the difference heatmap lights up exactly one future edge, `(0,2)`.

*Why it's done this way:* a snapshot is an adjacency matrix built by a time predicate, not by reshuffling rows. The formula `A_t[u,v]=1{edge_time(u,v)≤t}` lets the model see the graph state available at prediction time and makes leakage detectable as entries that appear only in later snapshots.

### 2. Time-aware aggregation and exponential decay

A temporal neighborhood can count recent and old edges equally, but many systems want recency to matter. We attach an age `current_time - edge_time` and weight each edge by `exp(-lambda * age)`. The exponential is convenient because each extra unit of age multiplies evidence by the same constant.

```python
current_t_w = 3
lam_w = 0.5
ages_w = current_t_w - edges_w[:, 2]
weights_w = np.exp(-lam_w * ages_w)
print("ages:", ages_w)
print("decay weights:", np.round(weights_w, 3))
assert round(float(np.exp(-0.5)), 3) == 0.607
```
▶ What you'll see: an edge with age 1 receives weight 0.607, while older edges receive smaller weights.

```python
W_w = np.zeros((n_nodes_w, n_nodes_w), dtype=float)
for (u, v, tau), weight in zip(edges_w, weights_w):
    if tau <= current_t_w:
        W_w[u, v] += weight
print("decayed temporal adjacency:\n", np.round(W_w, 3))
print("node 0 decayed out-neighborhood:", np.round(W_w[0], 3))
```
▶ What you'll see: node 0 has two outgoing neighbors, but the newer edge to node 2 has much larger weight.

```python
x_w = np.array([1.0, 2.0, 4.0])
raw_msg_w = A3_w @ x_w
recency_msg_w = W_w @ x_w
print("raw snapshot messages:", np.round(raw_msg_w, 3))
print("decayed messages:", np.round(recency_msg_w, 3))
plt.figure(figsize=(4.6, 3))
plt.bar(np.arange(n_nodes_w) - 0.18, raw_msg_w, width=0.36, label="raw count")
plt.bar(np.arange(n_nodes_w) + 0.18, recency_msg_w, width=0.36, label="decayed")
plt.title("2: temporal aggregation changes messages")
plt.xlabel("source node"); plt.ylabel("aggregated neighbor value")
plt.legend(); plt.show()
```
▶ What you'll see: decayed aggregation keeps the same neighbors but reduces the influence of old interactions.

*Why it's done this way:* multiplication by a weighted adjacency is still ordinary message passing, but the weights encode the assumption that old evidence is less predictive. The exponential term is positive, smooth, and monotone, so it preserves edge direction while making recency a continuous modeling choice instead of a hard cutoff.

### 3. Heterogeneous graphs as typed relation matrices

A heterogeneous graph has node types and relation types. A user-clicks-item edge and a user-follows-user edge should not be collapsed into one square matrix because their rows, columns, and semantics differ. We store one matrix per typed relation: for example, user→item has shape `3×2`, while user→user has shape `3×3`.

```python
users_w = ["u0", "u1", "u2"]
items_w = ["i0", "i1"]
A_ui_w = np.array([[1, 0],
                   [1, 1],
                   [0, 1]], dtype=int)  # user clicked/bought item.
A_uu_w = np.array([[0, 1, 0],
                   [0, 0, 1],
                   [1, 0, 0]], dtype=int)  # user follows user.
print("user-item shape:", A_ui_w.shape)
print("user-user shape:", A_uu_w.shape)
assert A_ui_w.shape == (3, 2) and A_uu_w.shape == (3, 3)
```
▶ What you'll see: different relation types naturally produce different matrix shapes.

```python
plt.figure(figsize=(6.4, 2.8))
plt.subplot(1, 2, 1); plt.imshow(A_ui_w, cmap="Blues", vmin=0, vmax=1)
plt.title("A^(user,item)"); plt.xlabel("items"); plt.ylabel("users")
plt.xticks(range(2), items_w); plt.yticks(range(3), users_w)
plt.subplot(1, 2, 2); plt.imshow(A_uu_w, cmap="Greens", vmin=0, vmax=1)
plt.title("A^(user,user)"); plt.xlabel("users"); plt.ylabel("users")
plt.xticks(range(3), users_w); plt.yticks(range(3), users_w)
plt.tight_layout(); plt.show()
```
▶ What you'll see: the two heatmaps have different axes, which is exactly why one untyped adjacency would be misleading.

```python
collapsed_w = np.zeros((5, 5), dtype=int)
collapsed_w[:3, 3:] = A_ui_w
collapsed_w[:3, :3] = A_uu_w
print("collapsed matrix mixes relation meanings:\n", collapsed_w)
```
▶ What you'll see: a single 5×5 matrix can store the edges, but it no longer says whether a 1 means follows or clicks.

*Why it's done this way:* relation-specific matrices preserve domain and codomain. That matters mathematically because only compatible typed matrices can be multiplied, and it matters semantically because the model should be able to learn different parameters for following a person versus interacting with an item.

### 4. Meta-path composition over typed relations

A meta-path is a typed route such as User→Item→User. Matrix multiplication composes the relation matrices along that route. For `U-I-U`, the product `A_ui @ A_ui.T` counts how many items two users share, because each middle item contributes one product term.

```python
M_uiu_w = A_ui_w @ A_ui_w.T
print("U-I-U shared-item counts:\n", M_uiu_w)
print("users 0 and 1 shared items:", M_uiu_w[0, 1])
print("users 0 and 2 shared items:", M_uiu_w[0, 2])
assert M_uiu_w[0, 1] == 1 and M_uiu_w[0, 2] == 0
```
▶ What you'll see: users 0 and 1 share one item, while users 0 and 2 share none.

```python
M_uui_w = A_uu_w @ A_ui_w
print("U-U-I counts (items liked by followed users):\n", M_uui_w)
plt.figure(figsize=(7, 2.8))
plt.subplot(1, 2, 1); plt.imshow(M_uiu_w, cmap="Purples")
plt.title("U-I-U: shared items"); plt.xlabel("user"); plt.ylabel("user")
plt.subplot(1, 2, 2); plt.imshow(M_uui_w, cmap="Oranges")
plt.title("U-U-I: followed-user items"); plt.xlabel("item"); plt.ylabel("user")
plt.tight_layout(); plt.show()
```
▶ What you'll see: two valid meta-paths give different matrices because they ask different typed questions.

```python
query_time_w = 2
candidate_w = (0, 2, 3)
is_future_edge_w = candidate_w[2] > query_time_w
already_seen_w = snapshot_w(edges_w, n_nodes_w, query_time_w)[candidate_w[0], candidate_w[1]] == 1
print("candidate edge:", candidate_w)
print("future at query time?", is_future_edge_w, "already seen?", already_seen_w)
assert is_future_edge_w and not already_seen_w
```
▶ What you'll see: at time 2, edge `(0,2)` at time 3 is a valid temporal negative because it has not happened yet.

*Why it's done this way:* a meta-path is not just a longer random walk; it is a typed algebraic query. The dimensions force the route to be meaningful, while the product counts the number of compatible middle-node witnesses. Temporal link prediction then adds a time filter so positives and negatives are defined only with information available at the query time.

**Goal.** Store a graph as timestamped edge events, because temporal modeling starts before any adjacency matrix exists. We build it in 2 steps.

```python

plt.figure(figsize=(4, 3))
```

### Basic 2 — Create a snapshot at a query time

**Goal.** Convert events into the adjacency visible at time 2, because prediction should only use past and present edges. We build it in 2 steps.

```python
edges_b2 = np.array([[0, 1, 0], [1, 2, 1], [2, 0, 2], [0, 2, 3]], dtype=int)
n_nodes_b2 = 3
t_query_b2 = 2
A_b2 = np.zeros((n_nodes_b2, n_nodes_b2), dtype=int)
for u_b2, v_b2, t_b2 in edges_b2:
    if t_b2 <= t_query_b2:
        A_b2[u_b2, v_b2] = 1
print("snapshot at t=2:\n", A_b2)
```
▶ What you'll see: the edge with time 3 is not included.

```python
assert A_b2[0, 2] == 0
plt.figure(figsize=(4, 3))

plt.show()
```
▶ What you'll see: three directed edges are visible at the query time.

👀 Takeaway: a snapshot is an anti-leakage filter over edge times.

### Basic 3 — Measure graph change between snapshots

**Goal.** Compare two snapshots, because temporal learning often uses additions and deletions as signals. We build it in 2 steps.

```python
edges_b3 = np.array([[0, 1, 0], [1, 2, 1], [2, 0, 2], [0, 2, 3]], dtype=int)
def make_snapshot_b3(t_limit_b3):

A2_b3 = make_snapshot_b3(2)
A3_b3 = make_snapshot_b3(3)
Delta_b3 = A3_b3 - A2_b3

```

▶ What you'll see: only `(0,2)` changed between the two snapshots.

### Basic 5 — Apply exponential decay

**Goal.** Convert ages into recency weights, because old edges may be less informative than new ones. We build it in 3 steps.

```python
ages_b5 = np.array([3, 2, 1, 0], dtype=float)

```


### Basic 6 — Aggregate decayed messages

**Goal.** Build a weighted temporal adjacency and multiply by node features, because message passing can use recency-weighted edges. We build it in 3 steps.

```python
edges_b6 = np.array([[0, 1, 0], [1, 2, 1], [2, 0, 2], [0, 2, 3]], dtype=int)
now_b6 = 3
W_b6 = np.zeros((3, 3), dtype=float)
for u_b6, v_b6, t_b6 in edges_b6:
    W_b6[u_b6, v_b6] += np.exp(-0.5 * (now_b6 - t_b6))
print("W:\n", np.round(W_b6, 3))
```
▶ What you'll see: edges in the same snapshot have different numeric strengths.

```python
x_b6 = np.array([1.0, 2.0, 4.0])
msg_b6 = W_b6 @ x_b6
print("decayed messages:", np.round(msg_b6, 3))
assert round(float(msg_b6[0]), 3) == 4.446
```

```python
plt.figure(figsize=(4, 3))
plt.bar(["node0", "node1", "node2"], msg_b6, color="seagreen")
plt.title("Basic 6: decayed neighbor messages")
plt.ylabel("weighted sum")
plt.show()
```
▶ What you'll see: node 0 receives a large contribution from its recent edge to node 2.

👀 Takeaway: temporal message passing is ordinary matrix multiplication after edges receive time-aware weights.

### Basic 10 — Identify temporal negatives

**Goal.** Decide whether an edge is absent at query time but appears later, because temporal link prediction must not train on future positives as if they were past facts. We build it in 2 steps.

```python
edges_b10 = np.array([[0, 1, 0], [1, 2, 1], [2, 0, 2], [0, 2, 3]], dtype=int)
query_t_b10 = 2
candidate_b10 = (0, 2)
seen_b10 = any((u_b10 == candidate_b10[0] and v_b10 == candidate_b10[1] and t_b10 <= query_t_b10) for u_b10, v_b10, t_b10 in edges_b10)
future_b10 = any((u_b10 == candidate_b10[0] and v_b10 == candidate_b10[1] and t_b10 > query_t_b10) for u_b10, v_b10, t_b10 in edges_b10)
print("seen by t=2:", seen_b10, "appears later:", future_b10)
assert (not seen_b10) and future_b10
```
▶ What you'll see: `(0,2)` is absent at the query time but becomes positive later.

```python
labels_b10 = ["seen by t", "future positive"]
values_b10 = [int(seen_b10), int(future_b10)]
plt.figure(figsize=(4, 3))
plt.bar(labels_b10, values_b10, color=["gray", "crimson"])
plt.title("Basic 10: temporal candidate status")
plt.ylim(0, 1.2)
plt.show()
```
▶ What you'll see: only the future-positive flag is active.

👀 Takeaway: temporal negatives are defined relative to the time of prediction, not the final graph.

### Easy 1 — Roll snapshots through time

**Goal.** Build a sequence of adjacency snapshots, because temporal models often consume ordered graph states. We build it in 3 steps.

```python
edges_e1 = np.array([[0, 1, 0], [1, 2, 1], [2, 0, 2], [0, 2, 3]], dtype=int)
times_e1 = np.arange(4)
snapshots_e1 = []

```

👀 Takeaway: rolling snapshots are cumulative views of the event stream under a time cutoff.

### Easy 2 — Compare hard windows with decay

**Goal.** Contrast a recent-only window with exponential decay, because both are time-aware but make different assumptions. We build it in 3 steps.

```python
edges_e2 = np.array([[0, 1, 0], [1, 2, 1], [2, 0, 2], [0, 2, 3]], dtype=int)
now_e2 = 3
window_e2 = 1
A_window_e2 = np.zeros((3, 3), dtype=float)
A_decay_e2 = np.zeros((3, 3), dtype=float)
print("keep hard-window edges with age <=", window_e2)
```
▶ What you'll see: the hard window uses a strict cutoff.

```python
for u_e2, v_e2, t_e2 in edges_e2:
    age_e2 = now_e2 - t_e2
    if age_e2 <= window_e2:
        A_window_e2[u_e2, v_e2] = 1.0
    A_decay_e2[u_e2, v_e2] = np.exp(-0.5 * age_e2)
print("hard window:\n", A_window_e2)
print("decay:\n", np.round(A_decay_e2, 3))
```

```python
print("hard edge mass:", round(float(A_window_e2.sum()), 3), "decay mass:", round(float(A_decay_e2.sum()), 3))
assert round(float(A_decay_e2[2, 0]), 3) == 0.607
plt.figure(figsize=(6, 2.8))
plt.subplot(1, 2, 1); plt.imshow(A_window_e2, cmap="Greens", vmin=0, vmax=1); plt.title("window")
plt.subplot(1, 2, 2); plt.imshow(A_decay_e2, cmap="Reds"); plt.title("decay")
plt.tight_layout(); plt.show()
```
▶ What you'll see: the window drops old edges entirely, while decay keeps them with smaller weights.

👀 Takeaway: hard windows choose relevance by cutoff; decay chooses relevance by smooth age weighting.

### Advanced 1 — Detect leakage by comparing train and future snapshots
