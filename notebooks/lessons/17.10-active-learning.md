# 17.10 — Active Learning

Active learning is the label-budget version of supervised learning: instead of labeling random examples, the model asks for the next label that should teach it the most. In this lesson, we build uncertainty sampling, margins, query-by-committee, diversity, and learning-curve evaluation from scratch with NumPy so the selection rule is always visible.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build active learning one idea at a time. Run each cell in order and read the printed intermediate values — every piece of math is spelled out so the querying rule is not a black box. This walkthrough is self-contained (it imports what it needs) and uses a `_w` suffix on its variables so it never clashes with the examples below.

import numpy as np  # arrays, vectorized math, and small training loops.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
np.random.seed(0)  # reproducibility for synthetic pools and initial labeled sets.

### 1. Pool-based active learning: labels are the expensive resource

Active learning begins with a large unlabeled pool and a tiny labeled seed. The learner repeatedly trains on the labeled set, scores the unlabeled pool, queries a few labels, and retrains. The important distinction is that the model already has the feature vectors for every pool point; what it does not have is the expensive human label.

```python
rng_w = np.random.default_rng(0)  # local reproducible generator for the walkthrough pool.
X_pool_w = rng_w.normal(size=(160, 2))  # unlabeled feature vectors available to the learner.
y_hidden_w = (X_pool_w[:, 0] + 0.75 * X_pool_w[:, 1] > 0).astype(int)  # hidden oracle labels.
seed_idx_w = np.array([5, 22, 71, 104])  # four labels we pretend are already known.
labeled_w = seed_idx_w.copy()  # active learning starts from this tiny labeled set.
unlabeled_w = np.setdiff1d(np.arange(len(X_pool_w)), labeled_w)  # everything else is unlabeled.
print("pool size:", len(X_pool_w), "labeled:", len(labeled_w), "unlabeled:", len(unlabeled_w))  # inspect budget state.
assert len(labeled_w) == 4 and len(unlabeled_w) == 156  # concrete count check.
```
▶ What you'll see: almost every feature vector is available but unlabeled; only four labels can train the first model.

```python
plt.figure(figsize=(4.4, 3.4))  # create a compact pool plot.
plt.scatter(X_pool_w[unlabeled_w, 0], X_pool_w[unlabeled_w, 1], c="lightgray", s=20, label="unlabeled pool")  # show unlabeled points.
plt.scatter(X_pool_w[labeled_w, 0], X_pool_w[labeled_w, 1], c=y_hidden_w[labeled_w], cmap="coolwarm", edgecolor="k", s=80, label="labeled seed")  # show known labels.
plt.title("1: tiny labeled seed inside a large pool")  # title the plot.
plt.xlabel("x0"); plt.ylabel("x1"); plt.legend()  # label axes and legend.
plt.show()  # display the pool.
```
▶ What you'll see: a few colored seed labels surrounded by many gray candidates whose labels are hidden.

*Why it's done this way:* Pool-based active learning separates **features** from **labels**. The learner can compute geometry and predictions for every point, but each label costs budget. That is why the query rule matters: the same final model class can learn faster if early labels are chosen to reduce the most ambiguity.

### 2. Uncertainty sampling with entropy and margin

A probabilistic classifier says how much probability it assigns to each class. For binary classes with probability vector $(p,1-p)$, entropy is $H(p)=-p\log p-(1-p)\log(1-p)$; it is largest at $p=0.5$ because the model is maximally undecided. The top-two margin is the difference between the two largest probabilities; a small margin means the winner barely beats the runner-up.

```python
probs_w = np.array([[0.90, 0.10], [0.60, 0.40], [0.50, 0.50], [0.34, 0.33]])  # worked probability vectors.
entropy_w = -np.sum(probs_w * np.log(probs_w), axis=1)  # compute H(p) row by row.
margin_w = np.abs(probs_w[:, 0] - probs_w[:, 1])  # binary top-two margin.
print("entropy:", np.round(entropy_w, 3))  # inspect uncertainty scores.
print("margin:", np.round(margin_w, 3))  # inspect confidence gaps.
assert np.allclose(np.round(entropy_w[:3], 3), [0.325, 0.673, 0.693])  # lesson entropy checks.
assert round(float(margin_w[3]), 3) == 0.010  # lesson margin check for 0.34 vs 0.33.
```
▶ What you'll see: entropy rises from confident `(0.9,0.1)` to undecided `(0.5,0.5)`, while the smallest margin is 0.010.

```python
plt.figure(figsize=(4.8, 3.2))  # create a compact uncertainty plot.
plt.plot(probs_w[:, 0], entropy_w, marker="o", label="entropy")  # plot entropy against class-1 probability.
plt.plot(probs_w[:, 0], 1 - margin_w, marker="s", label="1 - margin")  # plot inverse margin on the same scale idea.
plt.xlabel("probability of class 1")  # label probability axis.
plt.title("2: uncertainty peaks near a tie")  # title the plot.
plt.legend(); plt.show()  # display the comparison.
```
▶ What you'll see: both scores emphasize examples where the class probabilities are close together.

*Why it's done this way:* Entropy measures the expected information in the label: a near-certain prediction has little surprise left, while a 50/50 prediction can flip the decision boundary. Margin is a cheaper proxy for the same idea — if the best class barely wins, one label can change which region the model trusts.

### 3. Query-by-committee: ask where reasonable models disagree

Query-by-committee (QBC) trains several plausible models on the same small labeled set and queries points where their predictions disagree. Disagreement is different from single-model uncertainty: a point can look confident to one model but controversial across models, especially early when many decision boundaries fit the few labels.

```python
def sigmoid_w(z_w):  # logistic link for a tiny classifier.
    return 1 / (1 + np.exp(-z_w))  # convert scores to probabilities.

def add_bias_w(X_w):  # append a bias column to features.
    return np.c_[np.ones(len(X_w)), X_w]  # first column handles the intercept.

def fit_logreg_w(X_w, y_w, seed_w, steps_w=500, lr_w=0.12):  # small full-batch logistic regression.
    rng_inner_w = np.random.default_rng(seed_w)  # different committee members get different starts.
    Xb_w = add_bias_w(X_w)  # include intercept.
    w_w = 0.2 * rng_inner_w.normal(size=Xb_w.shape[1])  # initialize weights.
    for _ in range(steps_w):  # gradient descent loop.
        p_w = sigmoid_w(Xb_w @ w_w)  # predicted probability of class 1.
        grad_w = Xb_w.T @ (p_w - y_w) / len(y_w)  # cross-entropy gradient.
        w_w -= lr_w * grad_w  # descend the gradient.
    return w_w  # trained weights.

bootstraps_w = [np.random.default_rng(s_w).choice(labeled_w, size=len(labeled_w), replace=True) for s_w in [1, 2, 3, 4, 5]]  # resample the tiny labeled set.
committee_w = np.vstack([fit_logreg_w(X_pool_w[b_w], y_hidden_w[b_w], s_w, steps_w=80) for s_w, b_w in zip([1, 2, 3, 4, 5], bootstraps_w)])  # five plausible models from bootstrapped labels.
print("committee shape:", committee_w.shape)  # inspect number of members and parameters.
assert committee_w.shape == (5, 3)  # five models, bias plus two feature weights.
```
▶ What you'll see: the committee stores five linear decision rules trained from the same four labels.

```python
pool_probs_w = sigmoid_w(add_bias_w(X_pool_w[unlabeled_w]) @ committee_w.T)  # member probabilities for each unlabeled point.
votes_w = (pool_probs_w >= 0.5).astype(int)  # convert probabilities to class votes.
vote_fraction_w = votes_w.mean(axis=1)  # fraction of committee predicting class 1.
disagree_w = 1 - np.maximum(vote_fraction_w, 1 - vote_fraction_w)  # vote entropy proxy: 0 means unanimous, 0.5 means split.
qbc_pick_w = unlabeled_w[int(np.argmax(disagree_w))]  # most disagreed-on point.
print("max disagreement:", round(float(disagree_w.max()), 3), "picked index:", int(qbc_pick_w))  # inspect query.
assert round(float(disagree_w.max()), 3) >= 0.4  # a 2-vs-3 split gives at least 0.4.
```
▶ What you'll see: the committee chooses a pool point with a close vote split rather than a unanimous easy point.

```python
plt.figure(figsize=(4.6, 3.5))  # create a disagreement plot.
plt.scatter(X_pool_w[unlabeled_w, 0], X_pool_w[unlabeled_w, 1], c=disagree_w, cmap="magma", s=24)  # color by committee disagreement.
plt.scatter(X_pool_w[qbc_pick_w, 0], X_pool_w[qbc_pick_w, 1], facecolors="none", edgecolors="cyan", s=160, linewidths=2, label="QBC query")  # mark query.
plt.colorbar(label="vote disagreement")  # show score scale.
plt.title("3: query-by-committee disagreement")  # title the plot.
plt.legend(); plt.show()  # display the visualization.
```
▶ What you'll see: QBC highlights points where plausible boundaries from the small seed disagree.

*Why it's done this way:* With few labels, there is not one obviously correct boundary. A committee approximates a distribution over reasonable hypotheses. Querying where hypotheses disagree targets labels that eliminate many boundaries at once, which is why QBC can be stronger than asking a single model for its own uncertainty.

### 4. Diversity: do not spend the whole budget on redundant points

The most uncertain points often cluster near the same boundary segment. If we query a batch, selecting the top uncertainties can waste labels on near-duplicates. A simple diversity penalty asks for high uncertainty **and** distance from points already selected in the batch, so the batch covers multiple parts of the decision boundary.

```python
mean_prob_w = pool_probs_w.mean(axis=1)  # average committee probability as one uncertainty model.
uncert_w = 1 - np.abs(mean_prob_w - 0.5) * 2  # 1 at p=0.5 and 0 at p=0 or 1.
top_uncertain_w = unlabeled_w[np.argsort(uncert_w)[-5:][::-1]]  # naive top-5 uncertainty batch.
print("top uncertainty indices:", top_uncertain_w)  # inspect naive batch.
print("top uncertainty scores:", np.round(uncert_w[np.argsort(uncert_w)[-5:][::-1]], 3))  # inspect scores.
assert len(top_uncertain_w) == 5  # concrete batch-size check.
```
▶ What you'll see: the naive batch contains the five most uncertain points, regardless of how close they are to each other.

```python
chosen_local_w = []  # store positions within the unlabeled array.
remaining_local_w = list(range(len(unlabeled_w)))  # candidates for greedy diverse selection.
for _ in range(5):  # choose a five-point batch.
    best_local_w, best_score_w = None, -1.0  # initialize the best candidate.
    for j_w in remaining_local_w:  # scan remaining candidates.
        if not chosen_local_w:  # first point uses pure uncertainty.
            div_w = 1.0  # no redundancy yet.
        else:
            dists_w = np.linalg.norm(X_pool_w[unlabeled_w[j_w]] - X_pool_w[unlabeled_w[chosen_local_w]], axis=1)  # distances to selected points.
            div_w = float(np.min(dists_w))  # nearest selected distance encourages spread.
        score_w = float(uncert_w[j_w] + 0.25 * div_w)  # combine uncertainty and diversity.
        if score_w > best_score_w:  # keep the best candidate.
            best_local_w, best_score_w = j_w, score_w  # update best.
    chosen_local_w.append(best_local_w)  # add the selected candidate.
    remaining_local_w.remove(best_local_w)  # remove it from future choices.
diverse_batch_w = unlabeled_w[chosen_local_w]  # map local positions to pool indices.
print("diverse batch indices:", diverse_batch_w)  # inspect selected batch.
assert len(np.unique(diverse_batch_w)) == 5  # no duplicate labels in the batch.
```
▶ What you'll see: the diverse batch still prefers uncertain points but spreads them across the pool.

```python
plt.figure(figsize=(4.8, 3.6))  # create a batch comparison plot.
plt.scatter(X_pool_w[unlabeled_w, 0], X_pool_w[unlabeled_w, 1], c=uncert_w, cmap="viridis", s=22)  # color by uncertainty.
plt.scatter(X_pool_w[top_uncertain_w, 0], X_pool_w[top_uncertain_w, 1], facecolors="none", edgecolors="red", s=120, label="top uncertainty")  # naive picks.
plt.scatter(X_pool_w[diverse_batch_w, 0], X_pool_w[diverse_batch_w, 1], marker="x", c="white", s=90, label="diverse batch")  # diverse picks.
plt.colorbar(label="uncertainty")  # score scale.
plt.title("4: uncertainty plus diversity")  # title the plot.
plt.legend(); plt.show()  # display comparison.
```
▶ What you'll see: red circles may bunch together, while white x marks cover more of the uncertain region.

*Why it's done this way:* Uncertainty answers “which point could change the boundary?” Diversity adds “which queried labels give non-overlapping information?” The distance term is a crude representativeness correction: it avoids paying for the same local boundary fact several times in one batch.

### 5. Learning curves: compare active querying with random querying

An active-learning rule is useful only if it improves accuracy per label compared with random querying. We therefore track test accuracy as the label budget grows. The curve is the real evidence: early gains mean the query rule is using labels efficiently; no gap means the heuristic is not buying us anything on that data.

```python
def run_query_loop_w(strategy_w, seed_w=0, rounds_w=12):  # compare a strategy against the same hidden oracle.
    rng_loop_w = np.random.default_rng(seed_w)  # reproducible initial labels and random picks.
    X_w = rng_loop_w.normal(size=(220, 2))  # synthetic pool.
    y_w = (X_w[:, 0] - 0.8 * X_w[:, 1] + 0.15 * rng_loop_w.normal(size=len(X_w)) > 0).astype(int)  # hidden oracle.
    test_w = rng_loop_w.normal(size=(300, 2))  # fixed test features.
    ytest_w = (test_w[:, 0] - 0.8 * test_w[:, 1] > 0).astype(int)  # clean test labels.
    labeled_w = np.r_[np.where(y_w == 0)[0][:2], np.where(y_w == 1)[0][:2]]  # balanced four-label seed.
    unlabeled_w = np.setdiff1d(np.arange(len(X_w)), labeled_w)  # remaining pool.
    acc_w = []  # store accuracy after each query.
    for _ in range(rounds_w):  # grow the labeled set one query at a time.
        w_w = fit_logreg_w(X_w[labeled_w], y_w[labeled_w], seed_w=7, steps_w=400, lr_w=0.15)  # train current model.
        pred_w = (sigmoid_w(add_bias_w(test_w) @ w_w) >= 0.5).astype(int)  # test predictions.
        acc_w.append(float(np.mean(pred_w == ytest_w)))  # record accuracy.
        pool_p_w = sigmoid_w(add_bias_w(X_w[unlabeled_w]) @ w_w)  # probabilities on unlabeled pool.
        if strategy_w == "uncertainty":  # active querying.
            pick_local_w = int(np.argmin(np.abs(pool_p_w - 0.5)))  # closest to decision boundary.
        else:  # random baseline.
            pick_local_w = int(rng_loop_w.integers(len(unlabeled_w)))  # random candidate.
        labeled_w = np.r_[labeled_w, unlabeled_w[pick_local_w]]  # reveal that label.
        unlabeled_w = np.delete(unlabeled_w, pick_local_w)  # remove it from the pool.
    return np.array(acc_w)  # accuracy curve.

active_curve_w = run_query_loop_w("uncertainty", seed_w=2)  # active-learning curve.
random_curve_w = run_query_loop_w("random", seed_w=2)  # same seed random baseline.
print("active first/final:", round(active_curve_w[0], 3), round(active_curve_w[-1], 3))  # inspect active curve.
print("random first/final:", round(random_curve_w[0], 3), round(random_curve_w[-1], 3))  # inspect random curve.
assert len(active_curve_w) == 12 and len(random_curve_w) == 12  # concrete curve length check.
```
▶ What you'll see: both curves start from four labels, then move as one new label is queried each round.

```python
plt.figure(figsize=(5.2, 3.4))  # create the learning-curve plot.
plt.plot(4 + np.arange(len(active_curve_w)), active_curve_w, marker="o", label="uncertainty sampling")  # active curve.
plt.plot(4 + np.arange(len(random_curve_w)), random_curve_w, marker="s", label="random querying")  # random baseline.
plt.xlabel("number of labeled examples")  # budget axis.
plt.ylabel("test accuracy")  # performance axis.
plt.ylim(0.4, 1.02)  # bounded accuracy scale.
plt.title("5: active learning curve vs random")  # title the comparison.
plt.legend(); plt.show()  # display curves.
```
▶ What you'll see: look for the active curve sitting above random at small budgets; that gap is label efficiency.

*Why it's done this way:* Active learning optimizes a sequence, not a single score. The model can be uncertain for the wrong reason, so validation against a random baseline is mandatory. A learning curve exposes whether the heuristic actually turns labels into accuracy faster.

### ✍️ Toy 5 · Diversity avoids redundant batch labels

A batch of high-uncertainty points can collapse onto one small region. Add nearest-selected distance to
spread the batch after the first uncertainty pick.

## 🛠️ Setup

```python
import numpy as np  # load NumPy for arrays, probability scores, and from-scratch optimization.
import matplotlib.pyplot as plt  # load Matplotlib for scatter plots, score bars, and learning curves.
np.random.seed(0)  # make stochastic examples reproducible across notebook runs.

def sigmoid(z):  # define the logistic link used by the tiny classifiers.
    return 1 / (1 + np.exp(-np.clip(z, -30, 30)))  # clip scores to avoid overflow while preserving probabilities.

def add_bias(X):  # add an intercept column to a 2-D feature matrix.
    return np.c_[np.ones(len(X)), X]  # first coordinate is always 1 for the bias term.

def fit_logreg(X, y, steps=600, lr=0.12, seed=0):  # train logistic regression with full-batch gradient descent.
    rng = np.random.default_rng(seed)  # local seed keeps examples deterministic.
    Xb = add_bias(X)  # include intercept in the linear score.
    w = 0.15 * rng.normal(size=Xb.shape[1])  # initialize small weights.
    for _ in range(steps):  # repeat gradient steps.
        p = sigmoid(Xb @ w)  # predicted probabilities.
        grad = Xb.T @ (p - y) / len(y)  # cross-entropy gradient.
        w -= lr * grad  # descend the gradient.
    return w  # return trained weights.

def predict_proba(X, w):  # compute class-1 probabilities for a trained logistic model.
    return sigmoid(add_bias(X) @ w)  # linear score followed by sigmoid.

def entropy_binary(p):  # compute binary entropy for probabilities of class 1.
    p = np.clip(np.asarray(p, dtype=float), 1e-12, 1 - 1e-12)  # avoid log(0).
    return -(p * np.log(p) + (1 - p) * np.log(1 - p))  # H(p, 1-p).

def margin_binary(p):  # compute top-two margin for binary probabilities.
    return np.abs(np.asarray(p, dtype=float) - 0.5) * 2  # |p-(1-p)|.

def make_pool(n=160, seed=0, noise=0.12):  # synthesize a two-class pool with hidden labels.
    rng = np.random.default_rng(seed)  # local reproducible generator.
    X = rng.normal(size=(n, 2))  # candidate feature vectors.
    score = X[:, 0] + 0.7 * X[:, 1] + noise * rng.normal(size=n)  # noisy linear oracle score.
    y = (score > 0).astype(int)  # hidden binary labels from the oracle.
    return X, y  # return pool features and hidden labels.

def accuracy(X, y, w):  # compute classification accuracy for a logistic model.
    return float(np.mean((predict_proba(X, w) >= 0.5).astype(int) == y))  # threshold probabilities at 0.5.
```

### Advanced 5 — Compare uncertainty, QBC, and random

**Goal.** Run three strategies on the same pool, because different query rules can win on different data regimes. We build it in 3 steps.

```python
def strategy_curve_a5(strategy_a5, seed_a5=55):  # run one strategy on one pool.
    rng_a5 = np.random.default_rng(seed_a5)  # reproducible random choices.
    X_a5, y_a5 = make_pool(n=190, seed=seed_a5)  # training pool.
    Xtest_a5, ytest_a5 = make_pool(n=320, seed=seed_a5 + 500, noise=0.0)  # test set.
    labeled_a5 = np.r_[np.where(y_a5 == 0)[0][:4], np.where(y_a5 == 1)[0][:4]]  # seed.
    unlabeled_a5 = np.setdiff1d(np.arange(len(X_a5)), labeled_a5)  # pool.
    curve_a5 = []  # accuracy curve.
    for t_a5 in range(13):  # thirteen query rounds.
        w_a5 = fit_logreg(X_a5[labeled_a5], y_a5[labeled_a5], seed=seed_a5 + t_a5, steps=450)  # main model.
        curve_a5.append(accuracy(Xtest_a5, ytest_a5, w_a5))  # evaluate.
        if strategy_a5 == "random":  # random baseline.
            pick_local_a5 = int(rng_a5.integers(len(unlabeled_a5)))  # random query.
        elif strategy_a5 == "qbc":  # committee disagreement.
            boots_a5 = [rng_a5.choice(labeled_a5, size=len(labeled_a5), replace=True) for _ in range(5)]  # bootstrap current labels for committee diversity.
            C_a5 = np.vstack([fit_logreg(X_a5[b_a5], y_a5[b_a5], seed=100 + m_a5 + t_a5, steps=160) for m_a5, b_a5 in enumerate(boots_a5)])  # committee.
            probs_a5 = sigmoid(add_bias(X_a5[unlabeled_a5]) @ C_a5.T)  # member probabilities.
            votes_a5 = (probs_a5 >= 0.5).astype(int)  # member votes.
            frac_a5 = votes_a5.mean(axis=1)  # vote share.
            pick_local_a5 = int(np.argmax(1 - np.maximum(frac_a5, 1 - frac_a5)))  # max disagreement.
        else:  # uncertainty sampling.
            p_a5 = predict_proba(X_a5[unlabeled_a5], w_a5)  # probabilities.
            pick_local_a5 = int(np.argmax(entropy_binary(p_a5)))  # max entropy.
        labeled_a5 = np.r_[labeled_a5, unlabeled_a5[pick_local_a5]]  # add query.
        unlabeled_a5 = np.delete(unlabeled_a5, pick_local_a5)  # remove query.
    return np.array(curve_a5)  # return accuracy curve.

unc_a5 = strategy_curve_a5("uncertainty", seed_a5=55)  # uncertainty strategy.
qbc_a5 = strategy_curve_a5("qbc", seed_a5=55)  # QBC strategy.
rand_a5 = strategy_curve_a5("random", seed_a5=55)  # random strategy.
print("final accuracies:", round(float(unc_a5[-1]), 3), round(float(qbc_a5[-1]), 3), round(float(rand_a5[-1]), 3))  # inspect final results.
assert len(unc_a5) == len(qbc_a5) == len(rand_a5) == 13  # verify common budget grid.
```
▶ What you'll see: all three strategies are evaluated on the same number of queried labels.
