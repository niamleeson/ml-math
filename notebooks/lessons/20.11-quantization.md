# 20.11 — Quantization

Quantization stores real-valued weights and activations on a smaller integer grid, usually to cut memory bandwidth and speed up inference. The central idea is simple — choose a scale, round to integers, then dequantize when needed — but the engineering quality depends on calibration, clipping, per-channel ranges, and whether the model is merely converted after training or trained to tolerate the rounding.

### 1. Symmetric quantization: scale, round, dequantize

A real number cannot be stored exactly in int8. Symmetric quantization chooses one positive scale `s` so the integer grid `[-127, 127]` covers the largest absolute weight. We store `q = round(x / s)`, then approximate the original with `x_hat = s * q`. The grid is centered at zero, which is convenient for weights because trained weight distributions are often roughly centered.

```python
x_w = np.array([-1.8, -0.4, 0.0, 0.73, 1.8])  # toy real weights with max absolute value 1.8.
qmax_w = 127  # signed int8 uses -127..127 for the symmetric math demo.
scale_w = np.max(np.abs(x_w)) / qmax_w  # one real step per integer level.
print("scale:", round(scale_w, 5))  # 1.8 / 127 = 0.01417.
assert round(scale_w, 5) == 0.01417  # concrete check from the lesson content.
```
▶ What you'll see: the symmetric int8 scale is `0.01417`, meaning adjacent stored integers differ by about 0.014 real units.

```python
q_w = np.clip(np.round(x_w / scale_w), -qmax_w, qmax_w).astype(int)  # map reals to the nearest integer grid points.
xhat_w = scale_w * q_w  # dequantize back to approximate real values.
print("q:", q_w)  # inspect stored integers.
print("x_hat:", np.round(xhat_w, 3))  # inspect reconstructed values.
assert int(q_w[3]) == 52  # 0.73 / 0.01417 rounds to 52.
assert round(float(xhat_w[3]), 3) == 0.737  # the lesson's dequantized value.
```
▶ What you'll see: `0.73` becomes integer `52`, then dequantizes to about `0.737`.

```python
err_w = xhat_w - x_w  # quantization error for each value.
plt.figure(figsize=(4.4, 3))
plt.stem(range(len(x_w)), err_w, basefmt="k-")
plt.axhline(0, color="black", linewidth=0.8)
plt.title("1: symmetric int8 rounding error")
plt.xlabel("weight index")
plt.ylabel("x_hat - x")
plt.show()
```
▶ What you'll see: values exactly on the grid have zero error; values between grid points move by at most half a scale.

*Why it's done this way:* Dividing by `s` expresses each real value in units of the grid spacing; rounding picks the nearest representable integer, which minimizes absolute error for that value under a uniform grid. Multiplying by `s` reverses the units. The largest absolute value sets `s` because otherwise the endpoints would overflow the int8 range.

### 2. Affine quantization: zero-point for asymmetric ranges

Activations are often not centered. ReLU outputs, for example, may live mostly between `0` and a positive maximum. Affine quantization uses a scale plus a zero-point: `q = round(x / s + z)`, `x_hat = s * (q - z)`. The zero-point makes the real value 0 land exactly on an integer, even when the representable real range is asymmetric.

```python
act_w = np.array([0.0, 0.2, 0.73, 1.1, 2.2])  # nonnegative toy activations.
qmin_w, qmax_aff_w = 0, 255  # uint8 activation grid.
xmin_w, xmax_w = float(act_w.min()), 1.8  # calibration range intentionally clips the 2.2 outlier.
scale_aff_w = (xmax_w - xmin_w) / (qmax_aff_w - qmin_w)  # real range divided by integer range.
zp_w = int(np.round(qmin_w - xmin_w / scale_aff_w))  # integer that represents real zero.
print("scale:", round(scale_aff_w, 5), "zero_point:", zp_w)
assert round(scale_aff_w, 5) == 0.00706 and zp_w == 0
```
▶ What you'll see: the unsigned grid has a smaller step than the symmetric demo because 256 levels cover only `[0, 1.8]`.

```python
q_aff_w = np.clip(np.round(act_w / scale_aff_w + zp_w), qmin_w, qmax_aff_w).astype(int)  # affine quantize.
xhat_aff_w = scale_aff_w * (q_aff_w - zp_w)  # affine dequantize.
print("q:", q_aff_w)
print("x_hat:", np.round(xhat_aff_w, 3))
print("clipped error at 2.2:", round(float(act_w[-1] - xhat_aff_w[-1]), 3))
assert round(float(act_w[-1] - xhat_aff_w[-1]), 1) == 0.4
```
▶ What you'll see: `2.2` clips to the calibrated maximum `1.8`, creating a large `0.4` error before rounding even matters.

*Why it's done this way:* The zero-point shifts the integer grid so real zero can be represented exactly; that matters because zeros appear constantly in padded tensors and ReLU activations. The scale controls resolution, while clipping controls coverage. A wide range avoids clipping but makes each integer step coarse; a tight range improves common values but sacrifices outliers.

### 3. Symmetric versus asymmetric is a modeling choice

The same data can be quantized with a symmetric signed grid or an asymmetric unsigned grid. Symmetric quantization is simple and fast for zero-centered weights. Asymmetric quantization spends levels only on the observed range, which can reduce error for nonnegative activations.

```python
relu_w = np.linspace(0, 1.8, 9)  # values that look like clipped ReLU activations.
s_sym_w = 1.8 / 127  # signed symmetric scale wastes negative levels for nonnegative data.
q_sym_w = np.clip(np.round(relu_w / s_sym_w), -127, 127).astype(int)
hat_sym_w = s_sym_w * q_sym_w
s_asym_w = 1.8 / 255  # unsigned affine scale uses all 256 levels on the nonnegative range.
q_asym_w = np.clip(np.round(relu_w / s_asym_w), 0, 255).astype(int)
hat_asym_w = s_asym_w * q_asym_w
print("symmetric step:", round(s_sym_w, 5), "asymmetric step:", round(s_asym_w, 5))
assert s_asym_w < s_sym_w
```
▶ What you'll see: the asymmetric step is about half as large because it does not reserve negative integers.

```python
rmse_sym_w = float(np.sqrt(np.mean((hat_sym_w - relu_w) ** 2)))
rmse_asym_w = float(np.sqrt(np.mean((hat_asym_w - relu_w) ** 2)))
print("RMSE symmetric:", round(rmse_sym_w, 6), "RMSE asymmetric:", round(rmse_asym_w, 6))
plt.figure(figsize=(4.6, 3))
plt.bar(["symmetric", "asymmetric"], [rmse_sym_w, rmse_asym_w], color=["gray", "seagreen"])
plt.title("3: asymmetric helps one-sided activations")
plt.ylabel("RMSE")
plt.show()
```
▶ What you'll see: asymmetric quantization has lower or equal error for this nonnegative range.

*Why it's done this way:* Quantization error is roughly proportional to grid spacing. If half the signed grid represents negative values that never occur, those levels are wasted. Asymmetric quantization uses an offset so all integer levels serve the actual activation interval.

### 4. Per-tensor versus per-channel scales

One scale for an entire tensor is easy, but it can waste resolution when different output channels have very different ranges. Per-channel quantization gives each row or output channel its own scale, so small channels do not inherit a huge step size from a large channel.

```python
W_w = np.array([[0.02, -0.03, 0.01, 0.04],
                [1.20, -1.50, 0.90, -1.10],
                [0.30, -0.25, 0.28, -0.31]])  # rows are output channels with unlike ranges.
s_tensor_w = np.max(np.abs(W_w)) / 127  # one scale for every weight.
q_tensor_w = np.clip(np.round(W_w / s_tensor_w), -127, 127).astype(int)
hat_tensor_w = s_tensor_w * q_tensor_w
print("per-tensor scale:", round(s_tensor_w, 5))
```
▶ What you'll see: the global scale is controlled by the large second row.

```python
s_chan_w = np.max(np.abs(W_w), axis=1, keepdims=True) / 127  # one scale per output row.
q_chan_w = np.clip(np.round(W_w / s_chan_w), -127, 127).astype(int)
hat_chan_w = s_chan_w * q_chan_w
row_rmse_tensor_w = np.sqrt(np.mean((hat_tensor_w - W_w) ** 2, axis=1))
row_rmse_chan_w = np.sqrt(np.mean((hat_chan_w - W_w) ** 2, axis=1))
print("row RMSE tensor:", np.round(row_rmse_tensor_w, 5))
print("row RMSE channel:", np.round(row_rmse_chan_w, 5))
assert row_rmse_chan_w[0] < row_rmse_tensor_w[0]
```
▶ What you'll see: the small first row improves the most under per-channel quantization.

```python
xpos_w = np.arange(W_w.shape[0])
plt.figure(figsize=(5, 3))
plt.bar(xpos_w - 0.18, row_rmse_tensor_w, width=0.36, label="per-tensor", color="crimson")
plt.bar(xpos_w + 0.18, row_rmse_chan_w, width=0.36, label="per-channel", color="seagreen")
plt.title("4: per-channel protects small channels")
plt.xlabel("output channel")
plt.ylabel("RMSE")
plt.legend()
plt.show()
```
▶ What you'll see: per-channel scales reduce error especially where a global scale would be too coarse.

*Why it's done this way:* Matrix outputs are sums over input features for each output channel. If one output channel has tiny weights and another has large weights, a shared step size is mathematically mismatched. Per-channel scaling keeps the relative quantization step small for every channel.

### 5. Calibration chooses the range before rounding

Calibration estimates the real range from representative data. The key tradeoff is visible with percentiles: a high percentile keeps outliers but gives coarse steps; a lower percentile clips outliers but improves resolution for the mass of values.

```python
rng_w = np.random.default_rng(0)
sample_w = np.r_[rng_w.normal(0, 0.35, 500), np.array([2.2, -2.0])]  # common values plus rare outliers.
ranges_w = np.array([np.max(np.abs(sample_w)), np.percentile(np.abs(sample_w), 99), np.percentile(np.abs(sample_w), 95)])
labels_w = ["max", "p99", "p95"]
print("calibration ranges:", dict(zip(labels_w, np.round(ranges_w, 3))))
assert ranges_w[0] == 2.2
```
▶ What you'll see: max calibration uses the outlier `2.2`, while percentile calibration chooses smaller ranges.

```python
errs_cal_w = []
clip_rates_w = []
for r_w in ranges_w:
    s_w = r_w / 127
    q_w = np.clip(np.round(sample_w / s_w), -127, 127)
    hat_w = s_w * q_w
    errs_cal_w.append(float(np.sqrt(np.mean((hat_w - sample_w) ** 2))))
    clip_rates_w.append(float(np.mean(np.abs(sample_w) > r_w)))
print("RMSE:", np.round(errs_cal_w, 4))
print("clip rates:", np.round(clip_rates_w, 4))
```
▶ What you'll see: tighter ranges can reduce rounding error for most values but introduce nonzero clipping.

```python
plt.figure(figsize=(5, 3))
plt.plot(labels_w, errs_cal_w, marker="o", label="RMSE")
plt.plot(labels_w, clip_rates_w, marker="s", label="clip rate")
plt.title("5: calibration range tradeoff")
plt.ylabel("value")
plt.legend()
plt.show()
```
▶ What you'll see: the best calibration is a balance, not automatically the widest range.

*Why it's done this way:* The quantizer minimizes neither clipping nor rounding alone. Total error is the sum of both effects: values inside the range suffer rounding error up to about half a step; values outside the range suffer clipping error that can be much larger.

### 6. Dynamic versus static activation quantization

Dynamic quantization computes activation scales from the current batch at inference time. Static quantization precomputes scales from calibration data and reuses them. Dynamic adapts to changing ranges; static avoids range-computation overhead and enables fixed integer kernels.

```python
batch_small_w = np.array([[0.1, 0.4, 0.2], [0.0, 0.3, 0.5]])
batch_large_w = 4 * batch_small_w  # same shape, larger runtime activations.
static_max_w = 0.5  # calibration saw only small activations.
def quant_uint8_w(a_w, max_w):
    s_w = max_w / 255
    q_w = np.clip(np.round(a_w / s_w), 0, 255).astype(int)
    return s_w * q_w
print("static max:", static_max_w, "runtime max:", float(batch_large_w.max()))
```
▶ What you'll see: the runtime batch is much larger than the static calibration range.

```python
hat_static_w = quant_uint8_w(batch_large_w, static_max_w)  # clips because range is stale.
hat_dynamic_w = quant_uint8_w(batch_large_w, float(batch_large_w.max()))  # adapts to this batch.
rmse_static_w = float(np.sqrt(np.mean((hat_static_w - batch_large_w) ** 2)))
rmse_dynamic_w = float(np.sqrt(np.mean((hat_dynamic_w - batch_large_w) ** 2)))
print("static RMSE:", round(rmse_static_w, 3), "dynamic RMSE:", round(rmse_dynamic_w, 3))
assert rmse_dynamic_w < rmse_static_w
```
▶ What you'll see: static quantization clips the larger batch, while dynamic quantization has much lower error.

*Why it's done this way:* Activations are data-dependent. If their range shifts after calibration, a fixed scale can be wrong. Dynamic scales reduce this mismatch, but production systems may prefer static scales because fixed ranges are easier to fuse into optimized kernels.

### 7. Post-training quantization versus QAT with a straight-through estimator

Post-training quantization (PTQ) converts a trained model after the fact. Quantization-aware training (QAT) inserts fake quantization during training so the model learns weights that survive rounding. The difficulty is that `round` has zero derivative almost everywhere, so QAT often uses a straight-through estimator (STE): forward pass rounds, backward pass pretends the derivative is 1 inside the range.

```python
w_true_w = 0.73
s_qat_w = 1.8 / 127
def fake_quant_w(v_w):
    q_w = np.clip(np.round(v_w / s_qat_w), -127, 127)
    return s_qat_w * q_w
w_q_w = fake_quant_w(w_true_w)
print("fake-quantized 0.73:", round(float(w_q_w), 3))
assert round(float(w_q_w), 3) == 0.737
```
▶ What you'll see: fake quantization reproduces the same rounded value as inference quantization.

```python
target_w = 1.0
x_train_w = 1.0
w_qat_w = 0.2
for step_w in range(20):
    y_w = fake_quant_w(w_qat_w) * x_train_w  # forward uses rounded weight.
    grad_w = 2 * (y_w - target_w) * x_train_w  # STE: pretend d fake_quant(w)/dw = 1.
    w_qat_w -= 0.1 * grad_w
print("trained real weight:", round(w_qat_w, 3), "quantized forward weight:", round(float(fake_quant_w(w_qat_w)), 3))
assert abs(float(fake_quant_w(w_qat_w)) - 1.0) < 0.02
```
▶ What you'll see: the stored real weight moves until its rounded forward value is close to the target.

*Why it's done this way:* PTQ assumes the trained weights already tolerate rounding. QAT changes the training objective: the model is optimized through the quantized forward path. STE is a practical compromise because the true derivative of rounding is unusable for gradient descent.

### 8. Quantization error, SQNR, and a tiny quantized MLP

A useful summary is signal-to-quantization-noise ratio, `SQNR = 10 log10(signal power / noise power)`. Higher bits usually mean smaller steps, lower noise, and higher SQNR. For a model, we care about whether this noise changes outputs enough to flip predictions.

```python
bits_w = np.array([2, 3, 4, 6, 8])
weights_w = np.random.default_rng(1).normal(0, 0.6, 200)
rmse_bits_w = []
sqnr_bits_w = []
for b_w in bits_w:
    qmax_b_w = 2 ** (b_w - 1) - 1
    s_b_w = np.max(np.abs(weights_w)) / qmax_b_w
    hat_b_w = s_b_w * np.clip(np.round(weights_w / s_b_w), -qmax_b_w, qmax_b_w)
    noise_w = weights_w - hat_b_w
    rmse_bits_w.append(float(np.sqrt(np.mean(noise_w ** 2))))
    sqnr_bits_w.append(float(10 * np.log10(np.mean(weights_w ** 2) / np.mean(noise_w ** 2))))
print("RMSE by bits:", np.round(rmse_bits_w, 4))
print("SQNR by bits:", np.round(sqnr_bits_w, 2))
assert rmse_bits_w[-1] < rmse_bits_w[0]
```
▶ What you'll see: RMSE falls and SQNR rises as the bit width increases.

```python
plt.figure(figsize=(5, 3))
plt.plot(bits_w, rmse_bits_w, marker="o", color="crimson")
plt.title("8: bits-vs-error curve")
plt.xlabel("bits")
plt.ylabel("weight RMSE")
plt.show()
```
▶ What you'll see: the curve drops quickly at low bits and flattens by int8; look for the elbow where extra bits buy little error reduction.

```python
X_mlp_w = np.array([[0.2, 0.8], [0.9, 0.1], [0.7, 0.6], [0.1, 0.2]])
W1_mlp_w = np.array([[1.2, -0.7, 0.4], [-0.5, 1.0, 0.8]])
b1_mlp_w = np.array([0.05, -0.02, 0.03])
W2_mlp_w = np.array([[0.9], [-1.1], [0.6]])
def relu_w(z_w):
    return np.maximum(z_w, 0)
def qsym_w(A_w, bits_w=8):
    qmax_w = 2 ** (bits_w - 1) - 1
    s_w = np.max(np.abs(A_w)) / qmax_w if np.max(np.abs(A_w)) > 0 else 1.0
    q_w = np.clip(np.round(A_w / s_w), -qmax_w, qmax_w)
    return s_w * q_w
float_out_w = relu_w(X_mlp_w @ W1_mlp_w + b1_mlp_w) @ W2_mlp_w
quant_out_w = relu_w(X_mlp_w @ qsym_w(W1_mlp_w) + b1_mlp_w) @ qsym_w(W2_mlp_w)
print("float outputs:", np.round(float_out_w.ravel(), 3))
print("quantized-weight outputs:", np.round(quant_out_w.ravel(), 3))
assert float(np.max(np.abs(float_out_w - quant_out_w))) < 0.02
```
▶ What you'll see: this tiny MLP's int8-weight outputs stay close to the float outputs.

*Why it's done this way:* SQNR compares noise power to useful signal power, so it is scale-aware: the same absolute error is worse for a tiny signal than for a large one. The MLP check matters because local weight error only matters in production if it propagates into meaningful output error.

### ✍️ Toy 1 · Lower precision cuts storage

Quantization is motivated by a simple byte count: fewer bits per parameter means less memory traffic
before any math changes.

```python
import numpy as np
import matplotlib.pyplot as plt

t1_rng = np.random.default_rng(0)
t1_params = 12
print("parameter count:", t1_params)  # -> 12
t1_fp32_bits = 32
print("fp32 bits per parameter:", t1_fp32_bits)  # -> 32
t1_int8_bits = 8
print("int8 bits per parameter:", t1_int8_bits)  # -> 8
t1_fp32_bytes = t1_params * t1_fp32_bits / 8
print("fp32 bytes:", round(float(t1_fp32_bytes), 1))  # -> 48.0
t1_int8_bytes = t1_params * t1_int8_bits / 8
print("int8 bytes:", round(float(t1_int8_bytes), 1))  # -> 12.0
t1_saving = 1 - t1_int8_bytes / t1_fp32_bytes
print("storage saving:", round(float(t1_saving), 2))  # -> 0.75
t1_ratio = t1_fp32_bytes / t1_int8_bytes
print("compression ratio:", round(float(t1_ratio), 1))  # -> 4.0
assert t1_ratio == 4.0

plt.figure(figsize=(4.4, 2.8))
plt.bar(["fp32", "int8"], [t1_fp32_bytes, t1_int8_bytes], color=["#bab0ac", "#4c78a8"])
plt.ylabel("bytes")
plt.title("Toy 1 · int8 uses one quarter the bytes")
plt.show()
```
▶ What you'll see: the int8 bar is 12 bytes instead of 48 bytes for the same 12 parameters.

### ✍️ Toy 2 · Symmetric quantization rounds to a signed grid

Symmetric quantization chooses one scale from the largest absolute value, divides by that scale,
rounds to integers, and multiplies back to dequantize.

```python
import numpy as np

t2_rng = np.random.default_rng(0)
t2_x = np.array([-1.0, -0.3, 0.0, 0.45, 1.0])
print("real values:", t2_x.tolist())  # -> [-1.0, -0.3, 0.0, 0.45, 1.0]
t2_qmax = 7
print("qmax:", t2_qmax)  # -> 7
t2_scale = np.max(np.abs(t2_x)) / t2_qmax
print("scale:", round(float(t2_scale), 4))  # -> 0.1429
t2_scaled = t2_x / t2_scale
print("scaled values:", np.round(t2_scaled, 2).tolist())  # -> [-7.0, -2.1, 0.0, 3.15, 7.0]
t2_rounded = np.round(t2_scaled)
print("rounded grid values:", t2_rounded.astype(int).tolist())  # -> [-7, -2, 0, 3, 7]
t2_q = np.clip(t2_rounded, -t2_qmax, t2_qmax).astype(int)
print("clipped integers:", t2_q.tolist())  # -> [-7, -2, 0, 3, 7]
t2_hat = t2_scale * t2_q
print("dequantized values:", np.round(t2_hat, 3).tolist())  # -> [-1.0, -0.286, 0.0, 0.429, 1.0]
t2_err = t2_hat - t2_x
print("quantization error:", np.round(t2_err, 3).tolist())  # -> [0.0, 0.014, 0.0, -0.021, 0.0]
assert t2_q.tolist() == [-7, -2, 0, 3, 7]

plt.figure(figsize=(4.8, 2.8))
plt.plot(t2_x, marker="o", label="real")
plt.plot(t2_hat, marker="x", label="dequantized")
plt.xlabel("index")
plt.ylabel("value")
plt.title("Toy 2 · signed grid approximation")
plt.legend()
plt.show()
```
▶ What you'll see: grid endpoints are exact, while in-between values move to the nearest signed level.

### ✍️ Toy 3 · Affine quantization uses a zero-point

Affine quantization shifts the integer grid so real zero lands on an integer even when the covered
range is asymmetric.

```python
import numpy as np

t3_rng = np.random.default_rng(0)
t3_x = np.array([-1.0, 0.0, 0.7, 2.0])
print("real values:", t3_x.tolist())  # -> [-1.0, 0.0, 0.7, 2.0]
t3_qmin = 0
print("qmin:", t3_qmin)  # -> 0
t3_qmax = 15
print("qmax:", t3_qmax)  # -> 15
t3_xmin = -1.0
print("calibration min:", t3_xmin)  # -> -1.0
t3_xmax = 2.0
print("calibration max:", t3_xmax)  # -> 2.0
t3_scale = (t3_xmax - t3_xmin) / (t3_qmax - t3_qmin)
print("scale:", round(float(t3_scale), 3))  # -> 0.2
t3_zero = int(np.round(t3_qmin - t3_xmin / t3_scale))
print("zero-point:", t3_zero)  # -> 5
t3_q = np.clip(np.round(t3_x / t3_scale + t3_zero), t3_qmin, t3_qmax).astype(int)
print("affine integers:", t3_q.tolist())  # -> [0, 5, 8, 15]
t3_hat = t3_scale * (t3_q - t3_zero)
print("dequantized values:", np.round(t3_hat, 3).tolist())  # -> [-1.0, 0.0, 0.6, 2.0]
t3_err = t3_hat - t3_x
print("affine error:", np.round(t3_err, 3).tolist())  # -> [0.0, 0.0, -0.1, 0.0]
assert t3_q[1] == t3_zero

plt.figure(figsize=(4.8, 2.8))
plt.scatter(t3_q, t3_hat, color="#4c78a8")
plt.axvline(t3_zero, color="black", linestyle="--", label="zero-point")
plt.xlabel("integer q")
plt.ylabel("dequantized value")
plt.title("Toy 3 · q=5 represents real zero")
plt.legend()
plt.show()
```
▶ What you'll see: real zero maps exactly to integer 5, while 0.7 rounds down to 0.6.

### ✍️ Toy 4 · Asymmetric grids spend levels on one-sided data

For nonnegative activations, a signed symmetric grid wastes negative levels. An unsigned asymmetric
grid can make the step size smaller over the same nonnegative range.

```python
import numpy as np
```

### ✍️ Toy 6 · Calibration trades rounding against clipping

A wide calibration range avoids clipping but gives coarse steps. A tight range gives fine steps for
common values but clips outliers.


## 🛠️ Setup

```python
import numpy as np  # Import NumPy for arrays, rounding, clipping, calibration, and tiny neural networks.
import matplotlib.pyplot as plt  # Import Matplotlib for histograms, heatmaps, bars, and error curves.
np.random.seed(0)  # Fix the global random seed so every stochastic example is repeatable.

def symmetric_quantize(x, bits=8):  # Quantize a real array with a signed symmetric integer grid.
    x = np.asarray(x, dtype=float)  # Convert inputs to floats so scale arithmetic is predictable.
    qmax = 2 ** (bits - 1) - 1  # Largest positive signed integer for the chosen bit width.
    max_abs = float(np.max(np.abs(x))) if x.size else 0.0  # Measure the range to be covered.
    scale = max_abs / qmax if max_abs > 0 else 1.0  # Use a safe scale for all-zero tensors.
    q = np.clip(np.round(x / scale), -qmax, qmax).astype(int)  # Round to the nearest integer and clip to range.
    return q, scale  # Return stored integers and the real units per integer step.

def symmetric_dequantize(q, scale):  # Convert symmetric integer values back to approximate real values.
    return scale * np.asarray(q, dtype=float)  # Reapply the scale to undo integer units.

def affine_quantize(x, bits=8, xmin=None, xmax=None):  # Quantize with an unsigned affine grid and zero-point.
    x = np.asarray(x, dtype=float)  # Convert inputs to a float array.
    qmin, qmax = 0, 2 ** bits - 1  # Unsigned integer bounds.
    xmin = float(np.min(x)) if xmin is None else float(xmin)  # Use observed minimum unless calibration overrides it.
    xmax = float(np.max(x)) if xmax is None else float(xmax)  # Use observed maximum unless calibration overrides it.
    scale = (xmax - xmin) / (qmax - qmin) if xmax > xmin else 1.0  # Real step size for the affine grid.
    zero_point = int(np.clip(np.round(qmin - xmin / scale), qmin, qmax))  # Integer location of real zero.
    q = np.clip(np.round(x / scale + zero_point), qmin, qmax).astype(int)  # Shift, round, and clip.
    return q, scale, zero_point  # Return enough information to dequantize.

def affine_dequantize(q, scale, zero_point):  # Convert affine integers back to approximate real values.
    return scale * (np.asarray(q, dtype=float) - zero_point)  # Remove zero-point then scale.

def rmse(a, b):  # Compute root mean squared error for two arrays.
    return float(np.sqrt(np.mean((np.asarray(a) - np.asarray(b)) ** 2)))  # Average squared error then square-root.

def sqnr_db(signal, approx):  # Compute signal-to-quantization-noise ratio in decibels.
    signal = np.asarray(signal, dtype=float)  # Convert the signal to floats.
    noise = signal - np.asarray(approx, dtype=float)  # Quantization noise is the reconstruction residual.
    return float(10 * np.log10(np.mean(signal ** 2) / np.mean(noise ** 2))) if np.mean(noise ** 2) > 0 else np.inf  # Guard exact reconstructions.

def relu(x):  # Define the only nonlinearity used in the toy MLP.
    return np.maximum(x, 0)  # ReLU keeps positives and zeros out negatives.
```
▶ What you'll see: setup defines reusable helpers for quantize/dequantize, RMSE, SQNR, and the tiny MLP nonlinearity.

### Advanced 1 — Train through fake quantization with STE

**Goal.** Fit a one-weight model using quantized forward passes, because QAT lets training adapt to rounding. We build it in 4 steps.

```python
w_a1 = 0.1  # Start from a poor slope.
print("initial quantized weight:", round(scale_a1 * round(w_a1 / scale_a1), 3))
```

```python

    q_a1 = np.clip(np.round(v_a1 / scale_a1), -127, 127)
    return scale_a1 * q_a1
losses_a1 = []
for step_a1 in range(80):
    wq_a1 = fake_q_a1(w_a1)  # Forward pass uses rounded weight.
    pred_a1 = wq_a1 * x_a1  # Compute predictions with fake-quantized weight.

```
▶ What you'll see: the shadow float weight lands where its rounded value behaves like the true slope.


```python
qH_a2, sH_a2, zH_a2 = affine_quantize(H_float_a2, bits=8, xmin=0.0, xmax=float(H_float_a2.max()))  # Quantize hidden activations dynamically.
```

### Advanced 3 — Measure per-channel benefit on a linear layer

**Goal.** Compare output error from per-tensor and per-channel weight quantization, because output channels with different ranges should not share one resolution. We build it in 4 steps.

```python
X_a3 = np.array([[1.0, -0.5, 0.2], [0.3, 0.7, -1.0]])  # Two examples.
W_a3 = np.array([[0.02, 1.4, -0.25], [-0.03, -1.2, 0.30], [0.01, 0.8, -0.28]])  # Columns are output channels with unlike ranges.
Y_float_a3 = X_a3 @ W_a3  # Reference float linear output.
print("float Y:\n", np.round(Y_float_a3, 3))
```
▶ What you'll see: three output channels with different numeric scales.

```python
q_t_a3, s_t_a3 = symmetric_quantize(W_a3, bits=8)  # One scale for the whole weight matrix.
Y_t_a3 = X_a3 @ symmetric_dequantize(q_t_a3, s_t_a3)  # Output with per-tensor reconstructed weights.
err_t_a3 = rmse(Y_float_a3, Y_t_a3)  # Measure output error.
print("per-tensor output RMSE:", round(err_t_a3, 6))
```
▶ What you'll see: the global scale creates one output RMSE number for the layer.

```python
scales_c_a3 = np.max(np.abs(W_a3), axis=0, keepdims=True) / 127  # One scale per output column.
q_c_a3 = np.clip(np.round(W_a3 / scales_c_a3), -127, 127).astype(int)  # Quantize each output channel separately.
W_c_hat_a3 = scales_c_a3 * q_c_a3  # Dequantize with column scales.
Y_c_a3 = X_a3 @ W_c_hat_a3  # Output with per-channel reconstructed weights.

assert err_c_a3 <= err_t_a3
```
▶ What you'll see: per-channel output RMSE is no worse, and usually lower.


▶ What you'll see: the lower bar shows the benefit of allocating resolution per output channel.

👀 Takeaway: per-channel quantization matters because layer outputs inherit weight reconstruction errors through matrix multiplication.

### Advanced 5 — Sweep mixed precision for an MLP

**Goal.** Quantize the same tiny MLP at several bit widths, because mixed precision chooses where lower bits are acceptable. We build it in 5 steps.

```python
X_a5 = np.array([[0.2, 0.8], [0.9, 0.1], [0.7, 0.6], [0.1, 0.2]])  # Reuse the toy examples.
W1_a5 = np.array([[1.2, -0.7, 0.4], [-0.5, 1.0, 0.8]])  # First layer.
b1_a5 = np.array([0.05, -0.02, 0.03])  # Bias.
W2_a5 = np.array([[0.9], [-1.1], [0.6]])  # Output layer.
float_a5 = relu(X_a5 @ W1_a5 + b1_a5) @ W2_a5  # Reference float output.
bits_a5 = np.array([2, 3, 4, 6, 8])  # Candidate weight precisions.
print("candidate bits:", bits_a5)
```
▶ What you'll see: the sweep ranges from very aggressive 2-bit weights to int8.

```python
out_errs_a5 = []  # Store output RMSE for each precision.
bytes_a5 = []  # Store idealized weight storage in bytes.
for bit_a5 in bits_a5:
    q1_a5, s1_a5 = symmetric_quantize(W1_a5, bits=int(bit_a5))
    q2_a5, s2_a5 = symmetric_quantize(W2_a5, bits=int(bit_a5))
    y_a5 = relu(X_a5 @ symmetric_dequantize(q1_a5, s1_a5) + b1_a5) @ symmetric_dequantize(q2_a5, s2_a5)
    out_errs_a5.append(rmse(float_a5, y_a5))
    bytes_a5.append((W1_a5.size + W2_a5.size) * bit_a5 / 8)
print("output RMSE:", np.round(out_errs_a5, 4))
assert out_errs_a5[-1] < out_errs_a5[0]
```
▶ What you'll see: output error generally falls as weights get more bits.

```python
plt.figure(figsize=(5, 3))
plt.plot(bits_a5, out_errs_a5, marker="o", color="crimson")
plt.title("Advanced 5: MLP bits-vs-output-error")
plt.xlabel("weight bits")
plt.ylabel("output RMSE")
plt.show()
```
▶ What you'll see: this is the model-level version of the bits-vs-error curve; look for the lowest precision before error jumps.

```python
plt.figure(figsize=(5, 3))

plt.show()
```
▶ What you'll see: moving left saves storage but increases error, creating a Pareto frontier.

```python

```
▶ What you'll see: a concrete precision is selected from an explicit output-error tolerance.

👀 Takeaway: mixed-precision deployment is a budgeted optimization problem: use the fewest bits that keep model-level error acceptable.
