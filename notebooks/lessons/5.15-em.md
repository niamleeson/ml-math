# 5.15 — Expectation-Maximization

Expectation-Maximization (EM) is the workhorse pattern for maximum likelihood when part of the data is hidden: first infer a soft distribution over the hidden variables with the current parameters, then refit the parameters as if those soft completions were observed. In this lesson, we build EM from scratch with only NumPy and Matplotlib, using tiny coin-mixture and Gaussian-mixture examples so every responsibility, soft count, likelihood, and update is visible.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build expectation-maximization one idea at a time. Run each cell in order and inspect the printed intermediate values — the point is to see how hidden labels become soft counts, how soft counts become ordinary estimates, and why each E/M pair should improve the observed-data likelihood. This walkthrough is self-contained and uses a `_w` suffix so it never clashes with the exercises below.

```python
import numpy as np  # arrays, logs, exponentials, and small EM loops.
import matplotlib.pyplot as plt  # visual diagnostics for responsibilities and likelihood.
np.random.seed(0)  # reproducibility for every stochastic cell.
```

### 1. Hidden assignments: the data we wish we had

EM starts with observed data `x` and hidden data `z`. In a two-coin mixture, each row is a sequence of 10 flips, but the coin identity that generated each row is hidden. If those identities were known, estimating the heads probability of each coin would be ordinary counting. Because they are hidden, EM will replace unknown hard labels with probabilities called responsibilities.

```python
heads_w = np.array([8, 7, 2, 1, 6], dtype=float)  # observed heads in five 10-flip sequences.
tails_w = 10 - heads_w  # observed tails; every row has 10 flips.
print("heads:", heads_w.astype(int))  # inspect the observed sufficient statistic.
print("tails:", tails_w.astype(int))  # inspect the complementary count.
```
▶ What you'll see: five short sequences summarized by heads/tails counts, but no coin labels.

```python
known_labels_w = np.array([1, 1, 0, 0, 1])  # pretend labels are known just to see the easy problem.
theta_known_w = []  # store complete-data MLEs.
for k_w in [0, 1]:  # estimate each coin separately.
    mask_w = known_labels_w == k_w  # rows assigned to this coin.
    theta_known_w.append(heads_w[mask_w].sum() / (10 * mask_w.sum()))  # heads / total flips.
print("complete-data coin biases:", np.round(theta_known_w, 3))
```
▶ What you'll see: if labels were known, the MLE is just heads divided by total flips per coin.

```python
plt.figure(figsize=(4.6, 3))
plt.bar(np.arange(len(heads_w)), heads_w / 10, color="steelblue")
plt.axhline(theta_known_w[0], color="orange", linestyle="--", label="coin 0 if labels known")
plt.axhline(theta_known_w[1], color="green", linestyle="--", label="coin 1 if labels known")
plt.title("1: observed heads fractions, hidden coin labels")
plt.xlabel("sequence")
plt.ylabel("heads fraction")
plt.legend()
plt.show()
```
▶ What you'll see: high-head and low-head rows visually suggest two coins, but EM must infer that split softly.

*Why it's done this way:* The complete-data likelihood factors into simple counts, so the M-step will be easy once the E-step supplies fractional labels. EM is useful precisely because it turns a missing-label problem into repeated weighted versions of the easy complete-data problem.

### 2. E-step: responsibilities from Bayes' rule

For current parameters, the E-step computes `r_ik = p(z_i=k | x_i, theta_old)`. This is Bayes' rule: score each hidden explanation by prior mixture weight times likelihood, then normalize the scores so they sum to 1. A row with 8 heads strongly favors a high-bias coin because `0.8^8 * 0.2^2` is much larger than `0.3^8 * 0.7^2`.

```python
theta_w = np.array([0.3, 0.8])  # current heads probabilities for low and high coins.
pi_w = np.array([0.5, 0.5])  # current mixture weights.
h_w, t_w = heads_w[0], tails_w[0]  # focus on the first sequence: 8 heads, 2 tails.
unnorm_w = pi_w * (theta_w ** h_w) * ((1 - theta_w) ** t_w)  # prior times likelihood.
print("unnormalized scores:", np.round(unnorm_w, 8))
print("score ratio high/low:", round(unnorm_w[1] / unnorm_w[0], 1))
```
▶ What you'll see: the high-bias coin score dwarfs the low-bias score for the 8-head sequence.

```python
resp_first_w = unnorm_w / unnorm_w.sum()  # normalize local scores into probabilities.
print("responsibility for first row:", np.round(resp_first_w, 4))
assert resp_first_w[1] > 0.99  # the high-bias coin is nearly certain for this row.
```
▶ What you'll see: responsibility is near 1 for the high-bias coin and near 0 for the low-bias coin.

```python
scores_w = np.column_stack([pi_w[k] * theta_w[k] ** heads_w * (1 - theta_w[k]) ** tails_w for k in [0, 1]])
resp_w = scores_w / scores_w.sum(axis=1, keepdims=True)  # responsibilities for every row.
print("responsibilities [low, high]:\n", np.round(resp_w, 3))
plt.figure(figsize=(5, 3))
plt.imshow(resp_w, cmap="viridis", aspect="auto", vmin=0, vmax=1)
plt.colorbar(label="responsibility")
plt.xticks([0, 1], ["low coin", "high coin"])
plt.yticks(range(len(heads_w)), [f"seq {i}" for i in range(len(heads_w))])
plt.title("2: E-step soft labels")
plt.show()
```
▶ What you'll see: high-head rows become bright in the high-coin column, low-head rows in the low-coin column, and uncertain rows split mass.

*Why it's done this way:* Bayes normalization is the step that converts local plausibility scores into usable probabilities. Without the denominator, large rows would have arbitrary scale; with it, each row contributes exactly one unit of label mass split according to current belief.

### 3. M-step: refit with expected sufficient statistics

The M-step maximizes the expected complete-data log-likelihood. For Bernoulli coins, that means replacing hard counts with soft counts: expected heads for coin `k` is `sum_i r_ik h_i`, and expected flips for coin `k` is `10 * sum_i r_ik`. The update is therefore the same counting formula as the complete-data MLE, but with fractional row membership.

```python
soft_sequences_w = resp_w.sum(axis=0)  # expected number of sequences assigned to each coin.
soft_heads_w = resp_w.T @ heads_w  # expected heads credited to each coin.
soft_flips_w = 10 * soft_sequences_w  # expected total flips credited to each coin.
print("soft sequence counts:", np.round(soft_sequences_w, 3))
print("soft heads:", np.round(soft_heads_w, 3))
```
▶ What you'll see: responsibilities assign fractional sequences and fractional heads to each coin.

```python
theta_new_w = soft_heads_w / soft_flips_w  # M-step Bernoulli MLE from expected counts.
pi_new_w = soft_sequences_w / len(heads_w)  # M-step mixture-weight MLE.
print("updated pi:", np.round(pi_new_w, 3))
print("updated theta:", np.round(theta_new_w, 3))
assert theta_new_w[0] < theta_new_w[1]
```
▶ What you'll see: the low coin moves toward low heads rates and the high coin moves toward high heads rates.

```python
plt.figure(figsize=(4.8, 3))
plt.bar(["theta low old", "theta low new", "theta high old", "theta high new"],
        [theta_w[0], theta_new_w[0], theta_w[1], theta_new_w[1]], color=["gray", "orange", "gray", "green"])
plt.xticks(rotation=25)
plt.ylim(0, 1)
plt.ylabel("heads probability")
plt.title("3: M-step refits from soft counts")
plt.show()
```
▶ What you'll see: parameter estimates move toward the empirical clusters suggested by the soft labels.

*Why it's done this way:* The expected complete-data log-likelihood for Bernoulli observations is a weighted sum of `h log theta + t log(1-theta)`. Differentiating that weighted expression and setting the derivative to zero gives `theta = weighted heads / weighted flips`, so the M-step is not a heuristic — it is the exact MLE for the completed-in-expectation data.

### 4. Observed likelihood: the quantity EM is designed to raise

EM does not promise that every diagnostic improves. Its monotonicity statement is about the observed-data likelihood `p(x | theta)`, where the hidden labels have been summed out. For the coin mixture, each row likelihood is `sum_k pi_k theta_k^h (1-theta_k)^t`, and the log-likelihood sums logs of those row probabilities.

```python
def coin_loglik_w(heads, tails, pi, theta):
    row_scores = np.column_stack([pi[k] * theta[k] ** heads * (1 - theta[k]) ** tails for k in range(len(theta))])
    return float(np.sum(np.log(row_scores.sum(axis=1))))

ll_old_w = coin_loglik_w(heads_w, tails_w, pi_w, theta_w)
ll_new_w = coin_loglik_w(heads_w, tails_w, pi_new_w, theta_new_w)
print("observed log-likelihood old:", round(ll_old_w, 6))
print("observed log-likelihood new:", round(ll_new_w, 6))
assert ll_new_w >= ll_old_w
```
▶ What you'll see: after one E/M pair, the observed log-likelihood is no smaller than before.

```python
ll_path_w = [ll_old_w]  # record repeated EM likelihoods.
pi_loop_w, theta_loop_w = pi_w.copy(), theta_w.copy()
for step_w in range(8):
    score_loop_w = np.column_stack([pi_loop_w[k] * theta_loop_w[k] ** heads_w * (1 - theta_loop_w[k]) ** tails_w for k in [0, 1]])
    r_loop_w = score_loop_w / score_loop_w.sum(axis=1, keepdims=True)
    pi_loop_w = r_loop_w.sum(axis=0) / len(heads_w)
    theta_loop_w = (r_loop_w.T @ heads_w) / (10 * r_loop_w.sum(axis=0))
    ll_path_w.append(coin_loglik_w(heads_w, tails_w, pi_loop_w, theta_loop_w))
print("likelihood path:", np.round(ll_path_w, 4))
```
▶ What you'll see: the log-likelihood climbs and then flattens as the parameters settle.

```python
plt.figure(figsize=(4.8, 3))
plt.plot(ll_path_w, marker="o", color="purple")
plt.title("4: observed log-likelihood rises")
plt.xlabel("EM iteration")
plt.ylabel("log p(x | theta)")
plt.show()
```
▶ What you'll see: a monotone nondecreasing curve, the signature EM is doing its intended job.

*Why it's done this way:* The E-step constructs a lower bound that is tight at the old parameters, and the M-step maximizes that bound. Raising a tight lower bound cannot lower the true observed log-likelihood at that point, which is the mathematical design decision behind EM.

### 5. Soft responsibilities versus hard assignments

A tempting shortcut is to assign each row to its most likely coin, then count. That can work when responsibilities are nearly 0 or 1, but it throws away uncertainty. EM deliberately keeps soft counts so an ambiguous row affects both parameter estimates in proportion to how plausible each explanation is.

```python
hard_labels_w = np.argmax(resp_w, axis=1)  # classify each row to the currently most likely coin.
hard_theta_w = np.array([heads_w[hard_labels_w == k].sum() / (10 * np.sum(hard_labels_w == k)) for k in [0, 1]])
print("hard labels:", hard_labels_w)
print("hard theta:", np.round(hard_theta_w, 3))
print("soft theta:", np.round(theta_new_w, 3))
```
▶ What you'll see: hard and soft estimates are close for confident rows, but not identical because soft EM keeps uncertainty.

```python
ambig_heads_w = np.array([8, 5, 2], dtype=float)
ambig_tails_w = 10 - ambig_heads_w
ambig_scores_w = np.column_stack([pi_w[k] * theta_w[k] ** ambig_heads_w * (1 - theta_w[k]) ** ambig_tails_w for k in [0, 1]])
ambig_resp_w = ambig_scores_w / ambig_scores_w.sum(axis=1, keepdims=True)
print("ambiguous responsibilities:\n", np.round(ambig_resp_w, 3))
```
▶ What you'll see: the 5-head row is not certain, so hardening would discard meaningful probability mass.

```python
plt.figure(figsize=(4.8, 3))
plt.bar(["low soft", "high soft"], ambig_resp_w[1], color=["orange", "green"])
plt.ylim(0, 1)
plt.title("5: one ambiguous row contributes to both coins")
plt.ylabel("responsibility for 5 heads")
plt.show()
```
▶ What you'll see: the ambiguous row gives partial credit to both hidden explanations instead of choosing one too early.

*Why it's done this way:* Responsibilities are expectations of hidden indicators. Expected sufficient statistics preserve uncertainty, while hard labels replace a probability distribution with a single brittle guess and can drag the M-step toward the wrong local optimum.

### 6. Initialization and local optima

EM is a hill-climber, not a global optimizer. Different starting parameters can lead to swapped labels, slow progress, or poorer local optima. The monotonicity guarantee only says each run climbs from where it started; it does not say every start reaches the best peak.

```python
starts_w = [np.array([0.2, 0.9]), np.array([0.9, 0.2]), np.array([0.45, 0.55])]
finals_w = []
for theta_start_w in starts_w:
    pi_run_w = np.array([0.5, 0.5])
    theta_run_w = theta_start_w.copy()
    for _ in range(20):
        score_run_w = np.column_stack([pi_run_w[k] * theta_run_w[k] ** heads_w * (1 - theta_run_w[k]) ** tails_w for k in [0, 1]])
        r_run_w = score_run_w / score_run_w.sum(axis=1, keepdims=True)
        pi_run_w = r_run_w.sum(axis=0) / len(heads_w)
        theta_run_w = (r_run_w.T @ heads_w) / (10 * r_run_w.sum(axis=0))
    finals_w.append(theta_run_w)
print("final theta from different starts:\n", np.round(np.array(finals_w), 3))
```
▶ What you'll see: starts can converge to similar separated coins, swapped versions, or weaker separation depending on initialization.

```python
final_lls_w = np.array([coin_loglik_w(heads_w, tails_w, np.array([0.5, 0.5]), th_w) for th_w in finals_w])
print("final log-likelihoods using equal pi for comparison:", np.round(final_lls_w, 3))
plt.figure(figsize=(5, 3))
for j_w, th_w in enumerate(finals_w):
    plt.scatter([j_w, j_w], th_w, s=90)
plt.xticks(range(len(starts_w)), ["start 1", "start 2", "start 3"])
plt.ylim(0, 1)
plt.ylabel("final theta")
plt.title("6: EM depends on initialization")
plt.show()
```
▶ What you'll see: multiple runs may end at different parameter locations, so practitioners use restarts.

*Why it's done this way:* EM optimizes a nonconvex observed likelihood for mixture models. Random restarts and likelihood comparisons are practical safeguards because the E-step is exact only for the current model, not a guarantee that the current basin is globally best.

## 🟢 Basics (warm-up)

### Basic 1 — Summarize hidden-label coin data

**Goal.** Represent observed coin-flip sequences as sufficient statistics, because EM works with what is observed while treating source labels as hidden.

```python
heads_b1 = np.array([8, 7, 2, 1, 6], dtype=float)
tails_b1 = 10 - heads_b1
print("heads:", heads_b1.astype(int))
print("tails:", tails_b1.astype(int))
assert int(heads_b1.sum() + tails_b1.sum()) == 50
```
▶ What you'll see: five sequences compressed into heads and tails counts.

```python
plt.figure(figsize=(4, 3))
plt.bar(np.arange(5), heads_b1 / 10, color="steelblue")
plt.ylim(0, 1)
plt.title("Basic 1: observed heads fraction")
plt.xlabel("sequence")
plt.ylabel("heads fraction")
plt.show()
```
▶ What you'll see: two low-head rows and several high-head rows, hinting at hidden coin types.

👀 Takeaway: EM begins with observed sufficient statistics and hidden assignments.

### Basic 2 — Compute one complete-data MLE

**Goal.** Estimate a Bernoulli probability when labels are known, because the EM M-step will reuse the same formula with soft labels.

```python
heads_b2 = np.array([8, 7, 2, 1, 6], dtype=float)
labels_b2 = np.array([1, 1, 0, 0, 1])
coin1_heads_b2 = heads_b2[labels_b2 == 1].sum()
coin1_flips_b2 = 10 * np.sum(labels_b2 == 1)
print("coin 1 heads:", coin1_heads_b2, "coin 1 flips:", coin1_flips_b2)
```
▶ What you'll see: the high-bias coin receives only the rows assigned to it.

```python
theta_b2 = coin1_heads_b2 / coin1_flips_b2
print("MLE theta for coin 1:", round(theta_b2, 3))
assert round(theta_b2, 3) == 0.700
```
▶ What you'll see: known labels make the MLE ordinary heads divided by flips.

👀 Takeaway: EM's M-step is ordinary maximum likelihood after replacing labels by expected labels.

### Basic 3 — Score a hidden explanation

**Goal.** Compute prior times likelihood for one hidden coin, because responsibilities are normalized explanation scores.

```python
h_b3, t_b3 = 8.0, 2.0
theta_b3 = 0.8
pi_b3 = 0.5
score_b3 = pi_b3 * theta_b3 ** h_b3 * (1 - theta_b3) ** t_b3
print("score for high coin:", round(score_b3, 8))
assert round(score_b3, 8) == 0.00335544
```
▶ What you'll see: a tiny probability because it is a probability of a full 10-flip pattern summary up to a shared combinatorial factor.

```python
plt.figure(figsize=(4, 3))
plt.bar(["prior", "likelihood", "score"], [pi_b3, theta_b3 ** h_b3 * (1 - theta_b3) ** t_b3, score_b3], color="teal")
plt.title("Basic 3: prior × likelihood")
plt.show()
```
▶ What you'll see: multiplying by the prior scales the likelihood into an unnormalized posterior score.

👀 Takeaway: the E-step starts with one unnormalized score per hidden explanation.

### Basic 4 — Normalize two scores into responsibilities

**Goal.** Turn unnormalized hidden-label scores into probabilities, because each row must distribute one unit of belief across latent classes.

```python
scores_b4 = np.array([0.5 * 0.3 ** 8 * 0.7 ** 2, 0.5 * 0.8 ** 8 * 0.2 ** 2])
resp_b4 = scores_b4 / scores_b4.sum()
print("scores:", np.round(scores_b4, 8))
print("responsibilities:", np.round(resp_b4, 4))
assert resp_b4[1] > 0.99
```
▶ What you'll see: the high coin receives almost all posterior responsibility for eight heads.

```python
plt.figure(figsize=(4, 3))
plt.bar(["low coin", "high coin"], resp_b4, color=["orange", "green"])
plt.ylim(0, 1)
plt.title("Basic 4: normalized responsibilities")
plt.show()
```
▶ What you'll see: probabilities sum to 1 after local normalization.

👀 Takeaway: responsibilities are Bayes-normalized soft labels.

### Basic 5 — Build an E-step matrix

**Goal.** Compute responsibilities for every row and coin, because EM updates parameters from all soft labels at once.

```python
heads_b5 = np.array([8, 7, 2, 1, 6], dtype=float)
tails_b5 = 10 - heads_b5
pi_b5 = np.array([0.5, 0.5])
theta_b5 = np.array([0.3, 0.8])
scores_b5 = np.column_stack([pi_b5[k] * theta_b5[k] ** heads_b5 * (1 - theta_b5[k]) ** tails_b5 for k in [0, 1]])
resp_b5 = scores_b5 / scores_b5.sum(axis=1, keepdims=True)
print("responsibility rows sum to:", np.round(resp_b5.sum(axis=1), 3))
assert np.allclose(resp_b5.sum(axis=1), 1.0)
```
▶ What you'll see: every row's responsibilities sum to one.

```python
plt.figure(figsize=(4, 3))
plt.imshow(resp_b5, cmap="viridis", vmin=0, vmax=1, aspect="auto")
plt.colorbar(label="responsibility")
plt.xticks([0, 1], ["low", "high"])
plt.title("Basic 5: E-step matrix")
plt.show()
```
▶ What you'll see: each row carries a soft assignment to the two coins.

👀 Takeaway: the E-step is vectorized Bayes' rule over all data points.

### Basic 6 — Convert responsibilities into soft counts

**Goal.** Sum fractional assignments, because the M-step needs expected sufficient statistics rather than hard class membership.

```python
soft_rows_b6 = resp_b5.sum(axis=0)
soft_heads_b6 = resp_b5.T @ heads_b5
print("soft row counts:", np.round(soft_rows_b6, 3))
print("soft heads:", np.round(soft_heads_b6, 3))
assert round(float(soft_rows_b6.sum()), 3) == 5.000
```
▶ What you'll see: five total rows are split fractionally between the two coins.

```python
plt.figure(figsize=(4, 3))
plt.bar(["low rows", "high rows"], soft_rows_b6, color=["orange", "green"])
plt.title("Basic 6: expected row counts")
plt.ylabel("soft count")
plt.show()
```
▶ What you'll see: soft counts need not be integers.

👀 Takeaway: expected counts are enough statistics for the Bernoulli mixture M-step.

### Basic 7 — Perform the Bernoulli M-step

**Goal.** Update coin biases from expected heads and expected flips, because weighted Bernoulli MLE has a closed form.

```python
soft_flips_b7 = 10 * soft_rows_b6
theta_new_b7 = soft_heads_b6 / soft_flips_b7
pi_new_b7 = soft_rows_b6 / len(heads_b5)
print("pi new:", np.round(pi_new_b7, 3))
print("theta new:", np.round(theta_new_b7, 3))
assert theta_new_b7[0] < theta_new_b7[1]
```
▶ What you'll see: mixture weights and heads probabilities update from fractional counts.

```python
plt.figure(figsize=(4, 3))
plt.bar(["low θ", "high θ"], theta_new_b7, color=["orange", "green"])
plt.ylim(0, 1)
plt.title("Basic 7: M-step theta")
plt.show()
```
▶ What you'll see: the two fitted coins separate into low- and high-head probabilities.

👀 Takeaway: the M-step is complete-data MLE with expected sufficient statistics.

### Basic 8 — Compute observed log-likelihood

**Goal.** Sum over hidden labels inside each row likelihood, because EM optimizes the observed data probability.

```python
row_lik_b8 = scores_b5.sum(axis=1)
ll_b8 = float(np.sum(np.log(row_lik_b8)))
print("row likelihoods:", np.round(row_lik_b8, 8))
print("observed log-likelihood:", round(ll_b8, 6))
assert ll_b8 < 0
```
▶ What you'll see: the observed likelihood is a sum over possible coins, not a likelihood for chosen labels.

```python
plt.figure(figsize=(4, 3))
plt.bar(np.arange(len(row_lik_b8)), np.log(row_lik_b8), color="purple")
plt.title("Basic 8: per-row log likelihood")
plt.xlabel("sequence")
plt.ylabel("log probability")
plt.show()
```
▶ What you'll see: each row contributes a negative log probability to the total.

👀 Takeaway: EM's monotonicity guarantee concerns observed log-likelihood with hidden variables marginalized out.

### Basic 9 — Compare hard and soft labels

**Goal.** Show how hard assignments discard uncertainty, because EM deliberately uses fractional responsibilities instead.

```python
hard_b9 = np.argmax(resp_b5, axis=1)
soft_high_b9 = resp_b5[:, 1]
print("hard high labels:", hard_b9)
print("soft high responsibilities:", np.round(soft_high_b9, 3))
```
▶ What you'll see: hard labels are only zeros and ones, while soft responsibilities keep degrees of belief.

```python
plt.figure(figsize=(4, 3))
plt.plot(soft_high_b9, marker="o", label="soft high responsibility")
plt.step(np.arange(len(hard_b9)), hard_b9, where="mid", label="hard label", color="red")
plt.ylim(-0.05, 1.05)
plt.title("Basic 9: hard vs soft")
plt.legend()
plt.show()
```
▶ What you'll see: hard labels jump abruptly where soft probabilities can be gradual.

👀 Takeaway: soft labels let uncertain rows update more than one component.

### Basic 10 — Run two EM iterations

**Goal.** Repeat E and M steps, because EM is an alternating procedure rather than a one-shot formula.

```python
pi_b10 = np.array([0.5, 0.5])
theta_b10 = np.array([0.3, 0.8])
lls_b10 = []
for iter_b10 in range(2):
    scores_b10 = np.column_stack([pi_b10[k] * theta_b10[k] ** heads_b5 * (1 - theta_b10[k]) ** tails_b5 for k in [0, 1]])
    lls_b10.append(float(np.sum(np.log(scores_b10.sum(axis=1)))))
    resp_b10 = scores_b10 / scores_b10.sum(axis=1, keepdims=True)
    pi_b10 = resp_b10.sum(axis=0) / len(heads_b5)
    theta_b10 = (resp_b10.T @ heads_b5) / (10 * resp_b10.sum(axis=0))
print("theta after two iterations:", np.round(theta_b10, 3))
print("logged likelihoods before each update:", np.round(lls_b10, 4))
```
▶ What you'll see: parameters update repeatedly from fresh responsibilities.

```python
plt.figure(figsize=(4, 3))
plt.plot(lls_b10, marker="o", color="teal")
plt.title("Basic 10: EM likelihood checkpoints")
plt.xlabel("iteration")
plt.ylabel("log-likelihood")
plt.show()
```
▶ What you'll see: likelihood checkpoints move upward after the first update.

👀 Takeaway: EM alternates inference and fitting until likelihood changes are small.

```python
print("final theta:", np.round(theta_e1, 3))

```
▶ What you'll see: likelihood is monotone and the coins settle into low/high heads rates.

### Advanced 1 — Stabilize responsibilities with log-sum-exp

**Goal.** Compute responsibilities in log space, because products of many probabilities can underflow for long sequences.

```python
heads_a1 = np.array([80, 20], dtype=float)
tails_a1 = 100 - heads_a1
pi_a1 = np.array([0.5, 0.5])

```
▶ What you'll see: long sequences produce very negative log scores.

```python

```
▶ What you'll see: stable normalization still returns valid probabilities.
