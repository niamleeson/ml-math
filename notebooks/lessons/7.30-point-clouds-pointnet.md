# 7.30 — Point Clouds & PointNet

Point clouds represent 3D objects as unordered samples in space, so a model must treat the input as a set rather than a sequence. In this lesson, you will build the PointNet idea from first principles: normalize coordinates, apply the same point function to every row, pool with a symmetric max, and inspect both the power and the limits of that global shape descriptor.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build PointNet one idea at a time. Run each cell in order and read the printed intermediate values — every geometric and pooling step is spelled out so the model never feels like a black box. This walkthrough is self-contained and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays, vectorized point functions, and small numerical checks.
import matplotlib.pyplot as plt  # all walkthrough visualizations, including 3D scatter plots.
np.random.seed(0)  # reproducibility for any randomized point ordering.
```

### 1. A point cloud is an unordered set of 3D samples

A point cloud stores an object as rows of coordinates. Each row is one sampled location $p_i=[x_i,y_i,z_i]\in\mathbb{R}^3$, but the row number is not part of the object: shuffling the file should not turn the same shape into a different class. We start with the checked four-point cloud from the lesson block so every later calculation has concrete geometry.

```python
P_w = np.array([[0., 0., 0.],
                [1., 0., 0.],
                [0., 1., 0.],
                [0., 0., 1.]])  # four samples in 3D: origin plus unit-axis points.
print("point cloud shape:", P_w.shape)  # rows are points, columns are x/y/z.
print(P_w)  # inspect the raw coordinate samples.
assert P_w.shape == (4, 3)  # checked lesson fact: four rows and three coordinates.
```
▶ What you'll see: a 4×3 array; the geometry is four sampled positions, not four time steps.

```python
fig_w = plt.figure(figsize=(4.4, 3.6))  # create a compact 3D figure.
ax_w = fig_w.add_subplot(111, projection="3d")  # add 3D axes for x/y/z coordinates.
ax_w.scatter(P_w[:, 0], P_w[:, 1], P_w[:, 2], s=80, color="teal")  # draw each point.
for i_w, p_w in enumerate(P_w):  # label row indices to emphasize that they are storage labels.
    ax_w.text(p_w[0], p_w[1], p_w[2], f"p{i_w}")  # annotate the point.
ax_w.set_xlabel("x"); ax_w.set_ylabel("y"); ax_w.set_zlabel("z")  # label coordinates.
ax_w.set_title("1: four 3D samples")  # title the plot.
plt.show()  # display the 3D scatter.
```
▶ What you'll see: one point at the origin and three points on the coordinate axes; look for the shape, not the row order.

*Why it's done this way: PointNet begins from coordinates because scans naturally produce $(x,y,z)$ samples, but the array rows are just a storage convention. Any correct shape function must depend on the set of locations, not on which point happened to be row 0.*

### 2. Normalize coordinates before learning shape

Raw scanner coordinates can encode where the object sat and how large the capture units were. A common first step is to center the cloud at its centroid and scale it to a unit radius. This does not make the model rotation-invariant, but it removes translation and scale effects so the point function can focus on relative shape.

```python
P_raw_w = np.array([[2., 1., 0.],
                    [4., 1., 0.],
                    [2., 3., 0.],
                    [2., 1., 2.]])  # same axis-corner shape shifted and scaled.
centroid_w = P_raw_w.mean(axis=0)  # average x/y/z position.
centered_w = P_raw_w - centroid_w  # subtract the centroid from every point.
print("centroid:", np.round(centroid_w, 3))  # inspect the translation removed.
print("centered mean:", np.round(centered_w.mean(axis=0), 6))  # should be zero.
assert np.allclose(centered_w.mean(axis=0), np.zeros(3))  # centering removed translation.
```
▶ What you'll see: the centered cloud has coordinate mean exactly 0 in x, y, and z.

```python
radius_w = float(np.max(np.linalg.norm(centered_w, axis=1)))  # farthest centered point distance.
P_norm_w = centered_w / radius_w  # scale so the farthest point has radius 1.
print("max radius before:", round(radius_w, 3))  # inspect the original scale.
print("max radius after:", round(float(np.max(np.linalg.norm(P_norm_w, axis=1))), 3))  # inspect normalized scale.
assert round(float(np.max(np.linalg.norm(P_norm_w, axis=1))), 3) == 1.0  # unit-radius check.
```
▶ What you'll see: all points now fit inside a unit ball, with the farthest point exactly at radius 1.

```python
fig_w = plt.figure(figsize=(6, 3))  # compare raw and normalized clouds side by side.
ax1_w = fig_w.add_subplot(121, projection="3d")  # raw coordinate frame.
ax2_w = fig_w.add_subplot(122, projection="3d")  # normalized coordinate frame.
ax1_w.scatter(P_raw_w[:, 0], P_raw_w[:, 1], P_raw_w[:, 2], color="orange", s=55)  # raw points.
ax2_w.scatter(P_norm_w[:, 0], P_norm_w[:, 1], P_norm_w[:, 2], color="teal", s=55)  # normalized points.
ax1_w.set_title("raw"); ax2_w.set_title("centered + scaled")  # titles.
for ax_w2 in [ax1_w, ax2_w]:  # label all axes.
    ax_w2.set_xlabel("x"); ax_w2.set_ylabel("y"); ax_w2.set_zlabel("z")
plt.show()  # display both 3D scatters.
```
▶ What you'll see: the same relative shape moves from an arbitrary scanner frame into a centered, comparable frame.

*Why it's done this way: subtracting the centroid removes translation because every coordinate is expressed relative to the cloud's average location; dividing by the maximum radius removes scale because all distances are measured as fractions of the cloud size.*

### 3. A shared point function gives every row the same treatment

PointNet applies the same function $h$ to every point. In a neural network, $h$ would be a learned shared MLP; here we implement a tiny hand-made version with NumPy so the logic is visible. The key is sharing: the weights attach to coordinate patterns, not row indices.

```python
points_w = np.array([[1., 0., 0.],
                     [0., 1., 0.]])  # two points from the lesson block.
features_w = np.column_stack([points_w[:, 0] + 2 * points_w[:, 1], points_w[:, 2]])  # h([x,y,z])=[x+2y,z].
print("h(points):\n", features_w)  # inspect per-point features.
assert np.allclose(features_w, np.array([[1., 0.], [2., 0.]]))  # checked lesson values.
```
▶ What you'll see: $h([1,0,0])=[1,0]$ and $h([0,1,0])=[2,0]$.

```python
perm_w = np.array([1, 0])  # reverse the point order.
features_perm_w = np.column_stack([points_w[perm_w, 0] + 2 * points_w[perm_w, 1], points_w[perm_w, 2]])  # same h on shuffled points.
print("shuffled h(points):\n", features_perm_w)  # inspect features after reordering.
assert np.allclose(features_perm_w, features_w[perm_w])  # features move with points, not row labels.
```
▶ What you'll see: the feature rows swap in exactly the same way as the input rows.

```python
plt.figure(figsize=(4.4, 3))  # create a feature-space scatter plot.
plt.scatter(features_w[:, 0], features_w[:, 1], s=90, color="purple")  # plot h outputs.
for i_w, f_w in enumerate(features_w):  # label each transformed point.
    plt.text(f_w[0] + 0.03, f_w[1] + 0.02, f"h(p{i_w})")  # annotate feature point.
plt.xlabel("feature 0 = x + 2y"); plt.ylabel("feature 1 = z")  # label learned-feature axes.
plt.title("3: shared point features")  # title the plot.
plt.show()  # display feature scatter.
```
▶ What you'll see: points become feature vectors; the same formula extracted both features.

*Why it's done this way: if row 0 had one set of weights and row 1 had another, a file shuffle would change the computed features. Sharing $h$ forces the model to ask what each point looks like, not where it appeared in the list.*

### 4. Symmetric max pooling builds a global shape descriptor

After computing per-point features, PointNet collapses them with a symmetric operation. The lesson's checked feature table is $\begin{bmatrix}1&3\\2&1\\0&5\end{bmatrix}$, and coordinate-wise max pooling returns $[2,5]$. Each coordinate says the strongest evidence for that learned feature appeared somewhere in the cloud.

```python
H_w = np.array([[1., 3.],
                [2., 1.],
                [0., 5.]])  # three point features with two feature channels.
g_w = H_w.max(axis=0)  # coordinate-wise symmetric max over points.
print("feature table H:\n", H_w)  # inspect point features.
print("max pooled g:", g_w)  # inspect global descriptor.
assert np.allclose(g_w, np.array([2., 5.]))  # checked lesson pooled feature.
```
▶ What you'll see: feature 0 is won by row 1 and feature 1 is won by row 2, producing `[2, 5]`.

```python
winners_w = H_w.argmax(axis=0)  # identify which point supplied each max feature.
print("winning point per feature:", winners_w)  # feature 0 winner and feature 1 winner.
plt.figure(figsize=(4.4, 3))  # create a heatmap for point-feature activations.
plt.imshow(H_w, cmap="viridis", aspect="auto")  # color = activation size.
plt.scatter(np.arange(H_w.shape[1]), winners_w, marker="x", s=120, color="red")  # mark max winners.
plt.colorbar(label="feature activation")  # add activation legend.
plt.title("4: max pooling picks strongest evidence")  # title the heatmap.
plt.xlabel("feature channel"); plt.ylabel("point row")  # label axes.
plt.show()  # display the heatmap.
```
▶ What you'll see: red X markers sit on the cells that survive into the global descriptor.

*Why it's done this way: max is symmetric because the maximum of a set of numbers does not depend on their order. Coordinate-wise max also lets different points contribute different feature channels, so the descriptor records feature presence anywhere in the object.*

### 5. Permutation invariance is the core PointNet proof

Now we perform the exact reorder from the lesson block: rows $[2,0,1]$. The feature table changes order, but the pooled vector stays $[2,5]$. That numerical equality is the core proof idea behind PointNet's set design.

```python
order_w = np.array([2, 0, 1])  # checked row permutation.
H_perm_w = H_w[order_w]  # reorder rows but keep the same feature rows.
g_perm_w = H_perm_w.max(axis=0)  # max pool after reordering.
print("permuted H:\n", H_perm_w)  # inspect reordered features.
print("pooled original:", g_w, "pooled permuted:", g_perm_w)  # compare descriptors.
assert np.allclose(g_perm_w, g_w)  # permutation did not change the global feature.
```
▶ What you'll see: the rows move, but the pooled descriptor remains `[2, 5]`.

```python
linear_order_sensitive_w = np.array([1., 10., 100.]) @ H_w  # row-index weighted sum: intentionally wrong for sets.
linear_perm_w = np.array([1., 10., 100.]) @ H_perm_w  # same row weights after permutation.
print("order-sensitive original:", linear_order_sensitive_w)  # inspect bad descriptor.
print("order-sensitive permuted:", linear_perm_w)  # inspect changed bad descriptor.
assert not np.allclose(linear_order_sensitive_w, linear_perm_w)  # row-index logic breaks invariance.
```
▶ What you'll see: an index-weighted operation changes under shuffling, unlike max pooling.

```python
plt.figure(figsize=(4.6, 3))  # create a descriptor comparison plot.
plt.bar(["max original", "max permuted"], [g_w.sum(), g_perm_w.sum()], color=["teal", "seagreen"])  # invariant summary.
plt.bar(["indexed original", "indexed permuted"], [linear_order_sensitive_w.sum(), linear_perm_w.sum()], color=["crimson", "indianred"])  # non-invariant summary.
plt.title("5: symmetric vs row-indexed summaries")  # title the comparison.
plt.ylabel("sum of descriptor coordinates")  # use a scalar display of each descriptor.
plt.xticks(rotation=15)  # make labels readable.
plt.show()  # display the bars.
```
▶ What you'll see: the two max bars match exactly, while the row-indexed bars differ dramatically.

*Why it's done this way: a function on sets must satisfy $f(P)=f(\pi P)$ for any permutation $\pi$. Shared $h$ plus symmetric max satisfies that equation; row-indexed weights do not.*

### 6. Max pooling detects existence but loses counts and local geometry

Max pooling is powerful because it detects whether a learned feature appears anywhere. The tradeoff is that it forgets multiplicity: duplicating the strongest feature leaves the max unchanged. It also forgets which features were neighbors unless extra local architecture is added.

```python
A_w = np.array([[2., 5.],
                [1., 3.]])  # two feature vectors.
B_w = np.array([[2., 5.],
                [2., 5.],
                [1., 3.]])  # duplicate the strongest feature vector.
max_A_w = A_w.max(axis=0)  # max descriptor for A.
max_B_w = B_w.max(axis=0)  # max descriptor for B.
print("max A:", max_A_w, "max B:", max_B_w)  # compare descriptors.
assert np.allclose(max_A_w, np.array([2., 5.])) and np.allclose(max_B_w, np.array([2., 5.]))  # checked pitfall.
```
▶ What you'll see: duplicating `[2,5]` changes the count but not the max-pooled descriptor.

```python
mean_A_w = A_w.mean(axis=0)  # mean pooling preserves some density information.
mean_B_w = B_w.mean(axis=0)  # duplicate changes the mean.
print("mean A:", np.round(mean_A_w, 3), "mean B:", np.round(mean_B_w, 3))  # inspect what max hid.
assert not np.allclose(mean_A_w, mean_B_w)  # mean notices duplication while max does not.
```
▶ What you'll see: mean pooling changes when a strong feature is duplicated; max pooling does not.

```python
plt.figure(figsize=(4.6, 3))  # create a pooling comparison plot.
plt.plot(max_A_w, marker="o", label="max A", color="teal")  # max for A.
plt.plot(max_B_w, marker="o", linestyle="--", label="max B", color="seagreen")  # same max for B.
plt.plot(mean_A_w, marker="s", label="mean A", color="orange")  # mean for A.
plt.plot(mean_B_w, marker="s", linestyle="--", label="mean B", color="crimson")  # changed mean for B.
plt.xticks([0, 1], ["feature 0", "feature 1"])  # label feature channels.
plt.title("6: max ignores multiplicity")  # title the plot.
plt.legend()  # show pooling labels.
plt.show()  # display line comparison.
```
▶ What you'll see: the max curves overlap, while the mean curves separate after duplication.

*Why it's done this way: PointNet chooses max because it gives a clean permutation-invariant existence detector. The cost is that pure max cannot count repeated parts or encode fine neighborhoods, which is why later point-cloud models add local grouping.*

### ✍️ Toy 2 · Centering and unit-radius scaling remove position and size

Normalization subtracts the centroid, then divides every centered point by the farthest centered distance.

```python
import numpy as np

t2_rng = np.random.default_rng(0)
t2_raw = np.array([[2.0, 0.0, 0.0],
                   [4.0, 0.0, 0.0],
                   [2.0, 2.0, 0.0],
                   [2.0, 0.0, 2.0]])
t2_centroid = t2_raw.mean(axis=0)  # -> [2.5, 0.5, 0.5]
t2_centered = t2_raw - t2_centroid
t2_centered_mean = t2_centered.mean(axis=0)  # -> [0.0, 0.0, 0.0]
t2_distances = np.linalg.norm(t2_centered, axis=1)  # -> [0.866, 1.658, 1.658, 1.658]
t2_radius = float(t2_distances.max())  # -> 1.658
t2_unit = t2_centered / t2_radius
t2_unit_radius = float(np.linalg.norm(t2_unit, axis=1).max())  # -> 1.0
print("centroid:", t2_centroid.tolist())  # -> [2.5, 0.5, 0.5]
print("centered mean:", np.round(t2_centered_mean, 6).tolist())  # -> [0.0, 0.0, 0.0]
print("centered distances:", np.round(t2_distances, 3).tolist())  # -> [0.866, 1.658, 1.658, 1.658]
print("radius:", round(t2_radius, 3))  # -> 1.658
print("max unit radius:", round(t2_unit_radius, 3))  # -> 1.0

plt.figure(figsize=(4.2, 3))
plt.scatter(t2_centered[:, 0], t2_centered[:, 1], s=80, color="orange", label="centered")
plt.scatter(t2_unit[:, 0], t2_unit[:, 1], s=40, color="teal", label="unit")
plt.axhline(0, color="gray", linewidth=0.8)
plt.axvline(0, color="gray", linewidth=0.8)
plt.xlabel("x")
plt.ylabel("y")
plt.title("Toy 2 · center then scale")
plt.legend()
plt.show()
assert np.allclose(t2_centered_mean, np.zeros(3)) and round(t2_unit_radius, 3) == 1.0
```
▶ What you'll see: the same relative cloud is recentred at the origin and shrunk into a unit ball.

### ✍️ Toy 3 · A shared point function treats every row the same

The same coordinate formula is applied to each point, so shuffling rows only shuffles the resulting feature rows.

```python
import numpy as np

t3_rng = np.random.default_rng(0)
t3_points = np.array([[1.0, 0.0, 0.0],

t3_features = np.column_stack([t3_feat0, t3_feat1])  # -> [[1,-1],[4,0],[0,3]]

print("features:", t3_features.tolist())  # -> [[1.0, -1.0], [4.0, 0.0], [0.0, 3.0]]
print("order:", t3_order.tolist())  # -> [2, 0, 1]
print("shuffled features:", t3_shuffled_features.tolist())  # -> [[0.0, 3.0], [1.0, -1.0], [4.0, 0.0]]

    plt.text(t3_features[t3_i, 0] + 0.05, t3_features[t3_i, 1], f"p{t3_i}")
```

### ✍️ Toy 5 · Symmetric max ignores row permutations

A permutation changes the table order, but a symmetric max descriptor stays fixed; row-indexed weights do not.

```python
import numpy as np

t5_rng = np.random.default_rng(0)
t5_features = np.array([[1.0, 2.0],
                        [3.0, 0.0],
                        [2.0, 5.0]])
t5_order = np.array([2, 0, 1])
t5_permuted = t5_features[t5_order]
t5_max = t5_features.max(axis=0)  # -> [3.0, 5.0]
t5_max_permuted = t5_permuted.max(axis=0)  # -> [3.0, 5.0]
t5_row_weights = np.array([1.0, 10.0, 100.0])
t5_indexed = t5_row_weights @ t5_features  # -> [231.0, 502.0]
t5_indexed_permuted = t5_row_weights @ t5_permuted  # -> [312.0, 25.0]
print("permuted table:", t5_permuted.tolist())  # -> [[2.0, 5.0], [1.0, 2.0], [3.0, 0.0]]
print("max original:", t5_max.tolist())  # -> [3.0, 5.0]
print("max permuted:", t5_max_permuted.tolist())  # -> [3.0, 5.0]
print("row-indexed original:", t5_indexed.tolist())  # -> [231.0, 502.0]
print("row-indexed permuted:", t5_indexed_permuted.tolist())  # -> [312.0, 25.0]

plt.figure(figsize=(4.6, 3))
plt.bar(["max orig", "max perm", "idx orig", "idx perm"], [t5_max.sum(), t5_max_permuted.sum(), t5_indexed.sum(), t5_indexed_permuted.sum()], color=["teal", "teal", "orange", "orange"])
plt.ylabel("sum of descriptor entries")
plt.title("Toy 5 · symmetric vs row-indexed")
plt.xticks(rotation=15)
plt.show()
assert np.allclose(t5_max, t5_max_permuted) and not np.allclose(t5_indexed, t5_indexed_permuted)
```
▶ What you'll see: the max bars match, while row-indexed summaries change after the shuffle.

### ✍️ Toy 6 · Max pooling misses duplicate counts

If the strongest feature is duplicated, max pooling still reports only that it exists, not how many times it appeared.

```python
import numpy as np

t6_rng = np.random.default_rng(0)
t6_A = np.array([[2.0, 5.0],
                 [1.0, 1.0]])
t6_B = np.array([[2.0, 5.0],
                 [2.0, 5.0],
                 [1.0, 1.0]])
t6_max_A = t6_A.max(axis=0)  # -> [2.0, 5.0]
t6_max_B = t6_B.max(axis=0)  # -> [2.0, 5.0]
t6_mean_A = t6_A.mean(axis=0)  # -> [1.5, 3.0]
```

### Advanced 2 — Train a tiny linear shared feature map by hand

**Goal.** Learn point-feature weights with finite-difference gradients, because PointNet's shared MLP parameters are optimized from a task loss. We build it in 5 steps.

```python
P_a2 = np.array([[0., 0., 0.], [1., 0., 0.], [0., 1., 0.], [0., 0., 1.]])  # Canonical cloud.
target_a2 = np.array([1.0, 2.0])  # Desired max-pooled descriptor for this toy task.
W_a2 = np.array([[0.2, 0.1], [0.1, 0.4], [0.3, -0.2]])  # Shared linear feature weights.
print("initial W:\n", W_a2)  # Inspect trainable parameters.
```
▶ What you'll see: one shared 3×2 matrix maps each point to two features.

```python
def loss_a2(W_in_a2):
    H_in_a2 = P_a2 @ W_in_a2  # Shared linear features for all points.
    g_in_a2 = H_in_a2.max(axis=0)  # Symmetric max descriptor.
    return float(np.sum((g_in_a2 - target_a2) ** 2))  # Squared descriptor loss.

start_loss_a2 = loss_a2(W_a2)  # Evaluate before training.
print("start loss:", round(start_loss_a2, 4))  # Inspect starting error.
```

```python
eps_a2 = 1e-4  # Small finite-difference step.
eta_a2 = 0.2  # Learning rate for the toy gradient step.
losses_a2 = []  # Store loss history.
for step_a2 in range(30):  # Run a small number of gradient-descent steps.
    grad_a2 = np.zeros_like(W_a2)  # Prepare finite-difference gradient.
    for i_a2 in range(W_a2.shape[0]):  # Loop over rows of W.
        for j_a2 in range(W_a2.shape[1]):  # Loop over columns of W.
            W_plus_a2 = W_a2.copy(); W_plus_a2[i_a2, j_a2] += eps_a2  # Perturb one parameter upward.
            W_minus_a2 = W_a2.copy(); W_minus_a2[i_a2, j_a2] -= eps_a2  # Perturb one parameter downward.
            grad_a2[i_a2, j_a2] = (loss_a2(W_plus_a2) - loss_a2(W_minus_a2)) / (2 * eps_a2)  # Central difference.
    W_a2 = W_a2 - eta_a2 * grad_a2  # Descend the loss.
    losses_a2.append(loss_a2(W_a2))  # Record current loss.
print("end loss:", round(losses_a2[-1], 6))  # Inspect final error.
assert losses_a2[-1] < start_loss_a2  # Training improved the descriptor.
```

```python
H_final_a2 = P_a2 @ W_a2  # Compute final point features.
g_final_a2 = H_final_a2.max(axis=0)  # Compute final descriptor.
print("final g:", np.round(g_final_a2, 3), "target:", target_a2)  # Compare final descriptor to target.
```

```python
plt.figure(figsize=(4.6, 3))  # Create a training curve.
plt.plot(losses_a2, color="teal")  # Plot finite-difference loss values.
plt.title("Advanced 2: learning shared weights")  # Title plot.
plt.xlabel("step"); plt.ylabel("descriptor loss")  # Label axes.
plt.show()  # Display curve.
```
▶ What you'll see: the loss decreases as the shared linear map makes the max descriptor closer to the target.

👀 Takeaway: PointNet features are shared across points, but their weights are still learned from task feedback.
