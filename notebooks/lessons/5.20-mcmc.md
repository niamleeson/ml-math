# 5.20 — Markov Chain Monte Carlo

Markov Chain Monte Carlo (MCMC) draws samples from a distribution we cannot sample from directly by building a Markov chain whose long-run visit frequencies match the target. In this lesson, we keep targets tiny enough to audit by hand, then scale the same logic to continuous random-walk Metropolis and Gibbs sampling.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build MCMC one idea at a time. Run each cell in order and read the printed intermediate values — every acceptance ratio, chain transition, and diagnostic is exposed so the sampler never feels like magic. This walkthrough is self-contained (it imports what it needs) and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays, random choices, histograms, and small linear algebra.
```

### 1. Unnormalized targets: ratios are enough

MCMC is useful when we know a target distribution only up to a normalizing constant. Suppose four states have unnormalized scores `[1, 2, 4, 3]`. The normalized probabilities are those scores divided by their sum, but the Metropolis-Hastings acceptance rule will only need score ratios like `4/2`, so the missing constant cancels.

```python
scores_w = np.array([1., 2., 4., 3.])  # unnormalized target π(x) for states 0,1,2,3.
Z_w = scores_w.sum()  # normalizing constant; MCMC often cannot compute this in hard problems.
probs_w = scores_w / Z_w  # normalized distribution for this tiny audit example.
print("scores:", scores_w)
print("Z:", Z_w, "normalized:", probs_w)
assert np.allclose(probs_w, [0.1, 0.2, 0.4, 0.3])
```
▶ What you'll see: the scores normalize to `[0.1, 0.2, 0.4, 0.3]`, the concrete distribution cited in the lesson.

```python
ratio_scores_w = scores_w[2] / scores_w[1]  # π(2)/π(1), using unnormalized scores.
ratio_probs_w = probs_w[2] / probs_w[1]  # p(2)/p(1), using normalized probabilities.
print("score ratio 2/1:", ratio_scores_w)
print("probability ratio 2/1:", ratio_probs_w)
assert ratio_scores_w == ratio_probs_w == 2.0
```
▶ What you'll see: the ratio is identical before and after normalization.

```python
plt.figure(figsize=(4.4, 3))
plt.bar(np.arange(4) - 0.18, scores_w, width=0.36, label="unnormalized scores", color="gray")
plt.bar(np.arange(4) + 0.18, probs_w, width=0.36, label="normalized probabilities", color="seagreen")
plt.xticks(range(4), ["0", "1", "2", "3"]); plt.title("1: scores and probabilities share ratios")
plt.legend(); plt.show()
```
▶ What you'll see: the bars have different scales, but state 2 is twice state 1 in both views.

*Why it's done this way:* Bayesian posteriors often have the form `prior × likelihood / evidence`; the evidence is a global normalizer that is expensive to compute. MH avoids that cost because its accept/reject test compares two states, and any constant multiplying every target value cancels from the ratio.

### 2. A Markov chain as a local proposal machine

A Markov chain moves from the current state to a proposed next state using only the current state, not the whole past. Here the proposal is a symmetric nearest-neighbor random walk on states 0–3: from the middle it tries left or right equally, and at boundaries it stays within the state space.

```python
def propose_symmetric_w(x):  # propose a local reflected random-walk move on {0,1,2,3}.
    xp = x + np.random.choice([-1, 1])  # try one step left or right.
    return x if xp < 0 or xp > 3 else xp  # out-of-bounds proposals become self-proposals.

starts_w = np.array([0, 1, 2, 3])
proposals_w = np.array([propose_symmetric_w(int(x)) for x in starts_w])
print("one proposal from each state:", proposals_w)
```
▶ What you'll see: boundary states move inward; middle states try one local step left or right.

```python
T_prop_w = np.array([[0.5, 0.5, 0., 0.],
                     [0.5, 0., 0.5, 0.],
                     [0., 0.5, 0., 0.5],
                     [0., 0., 0.5, 0.5]])
print("proposal rows sum to:", T_prop_w.sum(axis=1))
assert np.allclose(T_prop_w.sum(axis=1), 1.0)
```
▶ What you'll see: each row is a valid conditional distribution for the next proposal.

```python
plt.figure(figsize=(4.4, 3.2))
plt.imshow(T_prop_w, cmap="Blues", vmin=0, vmax=1)
plt.colorbar(label="q(x'|x)"); plt.xlabel("proposed state x'"); plt.ylabel("current state x")
plt.title("2: local proposal kernel"); plt.show()
```
▶ What you'll see: nonzero mass sits only on neighboring states, showing the chain's local movement.

*Why it's done this way:* Local proposals are easy to generate even when direct independent samples from the posterior are hard. The cost is correlation: consecutive samples are nearby, so the acceptance rule must make the long-run proportions right rather than making draws independent.

### 3. Metropolis-Hastings acceptance for symmetric proposals

With a symmetric proposal, the proposal probabilities cancel, leaving `min(1, π(x')/π(x))`. A move from state 1 to state 2 compares scores `4/2`, accepts with probability 1, and therefore favors moves into higher target density while still sometimes allowing downhill moves.

```python
x_w, xp_w = 1, 2  # current state and proposed state.
accept_12_w = min(1.0, scores_w[xp_w] / scores_w[x_w])  # symmetric MH acceptance.
print("acceptance 1→2:", accept_12_w)
assert accept_12_w == 1.0
```
▶ What you'll see: the worked arithmetic `min(1, 0.4/0.2)=1` appears as `min(1, 4/2)=1` with unnormalized scores.

```python
accept_21_w = min(1.0, scores_w[1] / scores_w[2])  # reverse downhill move.
print("acceptance 2→1:", accept_21_w)
assert accept_21_w == 0.5
```
▶ What you'll see: the reverse move is accepted half the time, so the chain can leave high-density states but not too often.

```python
moves_w = ["1→2", "2→1", "2→3", "3→2"]
accs_w = [min(1.0, scores_w[2] / scores_w[1]), min(1.0, scores_w[1] / scores_w[2]),
          min(1.0, scores_w[3] / scores_w[2]), min(1.0, scores_w[2] / scores_w[3])]
plt.figure(figsize=(4.8, 3))
plt.bar(moves_w, accs_w, color="darkorange")
plt.ylim(0, 1.05); plt.ylabel("acceptance probability"); plt.title("3: uphill accepts, downhill may reject")
plt.show()
```
▶ What you'll see: moves into higher score accept with probability 1, while downhill moves are throttled.

*Why it's done this way:* The acceptance probability enforces detailed balance: high-probability states are entered easily and exited reluctantly, exactly enough that long-run traffic between any pair balances in the target proportions.

### 4. Running the chain and checking stationary proportions

Now we repeatedly propose a local move and accept or reject it. The samples are not independent, but after enough steps their histogram should approach `[0.1, 0.2, 0.4, 0.3]`. Rejections are not failures; they are self-transitions that keep the chain in a state when moving would overrepresent low-density regions.

```python
def mh_discrete_w(scores, n_steps=20000, start=0):
    x = start
    chain = np.empty(n_steps, dtype=int)
    accepted = 0
    for t in range(n_steps):
        xp = propose_symmetric_w(x)
        a = min(1.0, scores[xp] / scores[x])
        if np.random.rand() < a:
            x = xp
            accepted += 1
        chain[t] = x
    return chain, accepted / n_steps

chain_w, acc_rate_w = mh_discrete_w(scores_w, n_steps=30000, start=0)
print("acceptance rate:", round(acc_rate_w, 3))
print("first 12 states:", chain_w[:12])
assert 0.55 < acc_rate_w < 0.9
```
▶ What you'll see: the chain wanders locally and accepts a healthy fraction of proposals.

```python
freq_w = np.bincount(chain_w[5000:], minlength=4) / len(chain_w[5000:])
print("post burn-in frequencies:", np.round(freq_w, 3))
print("target probabilities:", probs_w)
assert np.max(np.abs(freq_w - probs_w)) < 0.03
```
▶ What you'll see: empirical visits land close to `[0.1, 0.2, 0.4, 0.3]`.

```python
plt.figure(figsize=(4.6, 3))
plt.bar(np.arange(4) - 0.18, probs_w, width=0.36, label="target", color="black")
plt.bar(np.arange(4) + 0.18, freq_w, width=0.36, label="MCMC", color="seagreen")
plt.xticks(range(4)); plt.ylabel("probability"); plt.title("4: visit frequencies approximate π")
plt.legend(); plt.show()
```
▶ What you'll see: the MCMC histogram nearly overlays the exact target probabilities.

*Why it's done this way:* Stationarity replaces independence. If the transition rule leaves π unchanged and the chain can explore the whole space, time averages from one long correlated run estimate expectations under π.

### 5. Proposal asymmetry: the q-ratio matters

The full MH rule includes `q(x | x') / q(x' | x)`. This term is 1 only for symmetric proposals. If a proposal is biased to move right, the reverse proposal probability must correct the acceptance probability or the chain will over-visit rightward states.

```python
Q_asym_w = np.array([[0.10, 0.90, 0.00],
                     [0.20, 0.10, 0.70],
                     [0.00, 0.60, 0.40]])  # q(next | current) for states 0,1,2.
target3_w = np.array([0.2, 0.5, 0.3])
print("proposal rows sum:", Q_asym_w.sum(axis=1))
assert np.allclose(Q_asym_w.sum(axis=1), 1.0)
```
▶ What you'll see: the proposal is valid but asymmetric, with state 1 much more likely to propose 2 than 2 proposes 1.

```python
x_asym_w, xp_asym_w = 1, 2
naive_asym_w = min(1.0, target3_w[xp_asym_w] / target3_w[x_asym_w])
correct_asym_w = min(1.0, (target3_w[xp_asym_w] * Q_asym_w[xp_asym_w, x_asym_w]) /
                     (target3_w[x_asym_w] * Q_asym_w[x_asym_w, xp_asym_w]))
print("naive symmetric-style acceptance:", round(naive_asym_w, 3))
print("correct MH acceptance:", round(correct_asym_w, 3))
assert round(naive_asym_w, 3) == 0.6 and round(correct_asym_w, 3) == 0.514
```
▶ What you'll see: ignoring the q-ratio would accept too often in the direction the proposal already prefers.

```python
plt.figure(figsize=(4.6, 3))
plt.bar(["naive", "with q-ratio"], [naive_asym_w, correct_asym_w], color=["crimson", "seagreen"])
plt.ylim(0, 1); plt.ylabel("acceptance for 1→2"); plt.title("5: asymmetric proposals need correction")
plt.show()
```
▶ What you'll see: the corrected acceptance is lower because proposing 1→2 is easier than proposing 2→1.

*Why it's done this way:* The target ratio says how much the destination is preferred; the proposal ratio says whether the proposal mechanism itself already favors that direction. MH must correct both so stationary traffic is determined by π, not by proposal bias.

### 6. Burn-in, mixing, and autocorrelation

Early samples remember the starting state. Slow local movement also makes nearby draws correlated, so 10,000 stored states are not the same as 10,000 independent samples. We inspect a running mean and an autocorrelation curve to see both issues directly.

```python
long_chain_w, _ = mh_discrete_w(scores_w, n_steps=20000, start=0)
indicator_w = (long_chain_w == 2).astype(float)  # estimate P(X=2), whose target is 0.4.
running_w = np.cumsum(indicator_w) / np.arange(1, len(indicator_w) + 1)
print("running estimate at 10, 1000, 20000:", np.round(running_w[[9, 999, -1]], 3))
assert abs(running_w[-1] - 0.4) < 0.03
```
▶ What you'll see: the early estimate can be biased by the start, while the long-run estimate settles near 0.4.

```python
plt.figure(figsize=(5, 3))
plt.plot(running_w[:3000], color="purple")
plt.axhline(0.4, color="black", linestyle="--", label="target P(X=2)")
plt.xlabel("step"); plt.ylabel("running estimate"); plt.title("6: burn-in fades initialization bias")
plt.legend(); plt.show()
```
▶ What you'll see: the curve is noisy at first, then stabilizes around the target line.

```python
state_values_w = long_chain_w.astype(float)  # use numeric state values to measure trace dependence.
centered_w = state_values_w - state_values_w.mean()  # center before correlating lagged copies.
lags_w = np.arange(1, 21)
autocorr_w = np.array([np.corrcoef(centered_w[:-lag], centered_w[lag:])[0, 1] for lag in lags_w])
print("lag-1 autocorrelation:", round(float(autocorr_w[0]), 3))
assert autocorr_w[0] > 0
```
▶ What you'll see: positive lag-1 autocorrelation, meaning neighboring samples carry overlapping information.

```python
plt.figure(figsize=(5, 3))
plt.stem(lags_w, autocorr_w)
plt.xlabel("lag"); plt.ylabel("autocorrelation"); plt.title("6: adjacent MCMC samples are correlated")
plt.show()
```
▶ What you'll see: autocorrelation decays with lag rather than vanishing immediately.

*Why it's done this way:* Burn-in discards the part most affected by initialization, while autocorrelation warns us that effective sample size is smaller than raw chain length. Both diagnostics ask whether the chain has explored enough to make summaries trustworthy.

### 7. Gibbs sampling as exact conditional MCMC

Gibbs sampling is an MCMC special case: update one variable at a time by drawing exactly from its conditional distribution. For a tiny joint table, `P(X=1 | Y=1)=4/(1+4)=0.800`, so no accept/reject step is needed for that coordinate.

```python
joint_w = np.array([[3., 1.],
                    [2., 4.]])  # rows X=0,1; columns Y=0,1; unnormalized joint scores.
prob_x1_y1_w = joint_w[1, 1] / joint_w[:, 1].sum()
print("P(X=1 | Y=1):", round(prob_x1_y1_w, 3))
assert round(prob_x1_y1_w, 3) == 0.800
```
▶ What you'll see: the conditional uses only the Y=1 column and normalizes `[1, 4]`.

```python
def gibbs_tiny_w(n_steps=12000, start=(0, 0)):
    x, y = start
    out = np.empty((n_steps, 2), dtype=int)
    for t in range(n_steps):
        px = joint_w[:, y] / joint_w[:, y].sum()
        x = int(np.random.rand() > px[0])
        py = joint_w[x, :] / joint_w[x, :].sum()
        y = int(np.random.rand() > py[0])
        out[t] = [x, y]
    return out

gibbs_chain_w = gibbs_tiny_w()
print("first five Gibbs states:\n", gibbs_chain_w[:5])
```
▶ What you'll see: the chain alternates conditional draws for X and Y.

```python
gibbs_counts_w = np.zeros((2, 2))
for xg_w, yg_w in gibbs_chain_w[1000:]:
    gibbs_counts_w[xg_w, yg_w] += 1
gibbs_freq_w = gibbs_counts_w / gibbs_counts_w.sum()
joint_target_w = joint_w / joint_w.sum()
print("Gibbs frequencies:\n", np.round(gibbs_freq_w, 3))
print("target joint:\n", np.round(joint_target_w, 3))
assert np.max(np.abs(gibbs_freq_w - joint_target_w)) < 0.03
```
▶ What you'll see: the Gibbs histogram approaches the normalized joint distribution.

```python
fig, ax = plt.subplots(1, 2, figsize=(6.5, 2.8))
ax[0].imshow(joint_target_w, cmap="viridis", vmin=0, vmax=0.45); ax[0].set_title("target joint")
ax[1].imshow(gibbs_freq_w, cmap="viridis", vmin=0, vmax=0.45); ax[1].set_title("Gibbs visits")
for a_w in ax:
    a_w.set_xlabel("Y"); a_w.set_ylabel("X")
plt.suptitle("7: exact conditionals give an MCMC chain"); plt.show()
```
▶ What you'll see: Gibbs visits mirror the target joint table.

*Why it's done this way:* Sampling from exact conditionals already builds the right local balance into each coordinate update. Gibbs is especially natural in graphical models where each conditional is easier than the full joint posterior.

## 🛠️ Setup

```python
import numpy as np  # load NumPy for arrays, random simulation, histograms, and numerical checks.
import matplotlib.pyplot as plt  # load Matplotlib for trace plots, histograms, and diagnostics.
np.random.seed(0)  # make all examples reproducible.

def normalize(weights):  # convert nonnegative unnormalized scores into probabilities.
    weights = np.asarray(weights, dtype=float)  # ensure floating-point division.
    return weights / weights.sum()  # divide by the normalizing constant.

def mh_accept(pi_x, pi_xp, q_forward=1.0, q_reverse=1.0):  # compute the MH acceptance probability.
    return min(1.0, (pi_xp * q_reverse) / (pi_x * q_forward))  # target ratio times proposal correction.

def discrete_hist(chain, n_states):  # estimate visit frequencies for a discrete chain.
    return np.bincount(np.asarray(chain, dtype=int), minlength=n_states) / len(chain)  # normalized counts.

def autocorr_1d(x, max_lag):  # compute simple autocorrelation values for lags 1..max_lag.
    x = np.asarray(x, dtype=float)  # use floats for centering and correlation.
    x = x - x.mean()  # remove the mean before correlating.
    return np.array([np.corrcoef(x[:-lag], x[lag:])[0, 1] for lag in range(1, max_lag + 1)])  # lag correlations.

def normal_score(x, mean=0.0, sd=1.0):  # unnormalized Normal density; constant is omitted intentionally.
    z = (x - mean) / sd  # standardize the location.
    return np.exp(-0.5 * z * z)  # proportional to N(mean, sd^2).
```

## 🟢 Basics (warm-up)

### Basic 1 — Normalize a tiny target

**Goal.** Turn unnormalized scores into probabilities, because MCMC targets are often known only up to a constant. We build it in 2 steps.

```python
scores_b1 = np.array([1., 2., 4., 3.])  # unnormalized π values for four states.
print("scores_b1:", scores_b1)  # inspect the raw relative weights.
```
▶ What you'll see: four positive scores, not yet probabilities.

```python
probs_b1 = normalize(scores_b1)  # divide by the sum to audit the exact target.
print("probs_b1:", probs_b1)  # inspect the normalized probabilities.
assert np.allclose(probs_b1, [0.1, 0.2, 0.4, 0.3])  # verify the canonical target proportions.
plt.figure(figsize=(4, 3)); plt.bar(range(4), probs_b1, color="seagreen")
plt.title("Basic 1: normalized target"); plt.xlabel("state"); plt.ylabel("probability"); plt.show()
```
▶ What you'll see: state 2 has the largest probability, state 0 the smallest.

👀 Takeaway: MCMC can use unnormalized scores, but normalizing a toy target helps us verify the answer.

### Basic 2 — Compute one MH acceptance ratio

**Goal.** Calculate the acceptance probability for moving from state 1 to state 2, because MH turns target ratios into accept/reject decisions. We build it in 2 steps.

```python
scores_b2 = np.array([1., 2., 4., 3.])  # target scores for states 0..3.
x_b2 = 1  # current state.
xp_b2 = 2  # proposed state.
print("current score:", scores_b2[x_b2], "proposed score:", scores_b2[xp_b2])  # inspect numerator and denominator.
```
▶ What you'll see: the proposed state has twice the current score.

```python
accept_b2 = mh_accept(scores_b2[x_b2], scores_b2[xp_b2])  # symmetric proposal acceptance.
print("acceptance probability:", accept_b2)  # inspect min(1, 4/2).
assert accept_b2 == 1.0  # uphill move accepts.
```
▶ What you'll see: `min(1, 0.4/0.2)=1` appears without needing the normalizing constant.

👀 Takeaway: symmetric MH accepts all moves to higher target score and sometimes accepts moves downward.

### Basic 3 — Downhill moves sometimes reject

**Goal.** Reverse the previous move, because a sampler must be able to leave high-density states without leaving too often. We build it in 2 steps.

```python
scores_b3 = np.array([1., 2., 4., 3.])  # target scores.
x_b3 = 2  # current high-score state.
xp_b3 = 1  # proposed lower-score state.
ratio_b3 = scores_b3[xp_b3] / scores_b3[x_b3]  # proposed/current target ratio.
print("downhill ratio:", ratio_b3)  # inspect the raw ratio.
```
▶ What you'll see: the reverse ratio is one half.

```python
accept_b3 = mh_accept(scores_b3[x_b3], scores_b3[xp_b3])  # acceptance for 2→1.
print("acceptance probability:", accept_b3)  # inspect the throttled probability.
assert accept_b3 == 0.5  # verify the exact downhill acceptance.
plt.figure(figsize=(4, 3)); plt.bar(["2→1 accept", "reject"], [accept_b3, 1 - accept_b3], color=["orange", "gray"])
plt.title("Basic 3: downhill accept/reject split"); plt.ylim(0, 1); plt.show()
```
▶ What you'll see: half the probability accepts, half stays at state 2.

👀 Takeaway: rejection is a valid self-transition that protects the target distribution.

### Basic 4 — Simulate a few Markov steps

**Goal.** Generate a short local chain, because MCMC samples are a path rather than independent draws. We build it in 2 steps.

```python
scores_b4 = np.array([1., 2., 4., 3.])  # target scores for the toy chain.
x_b4 = 0  # start far from the highest-probability state.
chain_b4 = []  # store visited states.
print("start:", x_b4)  # inspect the initial condition.
```
▶ What you'll see: the chain starts at state 0.

```python
for step_b4 in range(12):  # run a tiny MH chain.
    xp_b4_try = x_b4 + np.random.choice([-1, 1])  # try one local step.
    xp_b4 = x_b4 if xp_b4_try < 0 or xp_b4_try > 3 else xp_b4_try  # reflect boundaries as self-proposals.
    a_b4 = mh_accept(scores_b4[x_b4], scores_b4[xp_b4])  # symmetric acceptance.
    if np.random.rand() < a_b4:  # accept with probability a.
        x_b4 = xp_b4  # move to the proposal.
    chain_b4.append(x_b4)  # store the current state after accept/reject.
print("12 states:", chain_b4)  # inspect the path.
plt.figure(figsize=(5, 2.7)); plt.plot(chain_b4, marker="o", color="purple")
plt.yticks(range(4)); plt.title("Basic 4: short MH trace"); plt.xlabel("step"); plt.ylabel("state"); plt.show()
```
▶ What you'll see: a jagged trace that moves locally and may repeat states after rejection.

👀 Takeaway: an MCMC chain explores by sequential local dependence, so adjacent samples are related.

### Basic 5 — Estimate target frequencies from a chain

**Goal.** Run long enough to compare visit frequencies with the known toy target, because stationary proportions are the promise of MCMC. We build it in 3 steps.

```python
scores_b5 = np.array([1., 2., 4., 3.])  # target scores.
x_b5 = 0  # starting state.
chain_b5 = np.empty(20000, dtype=int)  # preallocate chain storage.
print("steps:", len(chain_b5))  # inspect chain length.
```
▶ What you'll see: the chain will store 20,000 correlated states.

```python
for t_b5 in range(len(chain_b5)):  # run random-walk MH.
    xp_b5_try = x_b5 + np.random.choice([-1, 1])  # try one local step.
    xp_b5 = x_b5 if xp_b5_try < 0 or xp_b5_try > 3 else xp_b5_try  # reflect boundaries as self-proposals.
    if np.random.rand() < mh_accept(scores_b5[x_b5], scores_b5[xp_b5]):  # accept/reject.
        x_b5 = xp_b5  # update current state if accepted.
    chain_b5[t_b5] = x_b5  # record the state.
freq_b5 = discrete_hist(chain_b5[2000:], 4)  # discard a small burn-in before counting.
print("frequencies:", np.round(freq_b5, 3))  # inspect empirical proportions.
assert np.max(np.abs(freq_b5 - normalize(scores_b5))) < 0.04  # verify close to target.
```
▶ What you'll see: frequencies close to `[0.1, 0.2, 0.4, 0.3]`.

```python
target_b5 = normalize(scores_b5)  # exact normalized target for comparison.
plt.figure(figsize=(4.6, 3)); plt.bar(np.arange(4)-0.18, target_b5, 0.36, label="target", color="black")
plt.bar(np.arange(4)+0.18, freq_b5, 0.36, label="chain", color="seagreen")
plt.title("Basic 5: target vs MCMC frequencies"); plt.xlabel("state"); plt.ylabel("probability"); plt.legend(); plt.show()
```
▶ What you'll see: the empirical bars nearly match the exact target bars.

👀 Takeaway: one long dependent chain can estimate a distribution's probabilities.

### Basic 6 — Use burn-in to reduce start-up bias

**Goal.** Compare early and later estimates, because initial states can distort the beginning of a chain. We build it in 2 steps.

```python
indicator_b6 = (chain_b5 == 2).astype(float)  # reuse Basic 5 chain to estimate P(state=2).
early_b6 = indicator_b6[:50].mean()  # very early estimate.
late_b6 = indicator_b6[2000:].mean()  # post-burn-in estimate.
print("early estimate:", round(early_b6, 3), "late estimate:", round(late_b6, 3))  # compare estimates.
assert abs(late_b6 - 0.4) < 0.04  # late estimate should match target P(state=2).
```
▶ What you'll see: the late estimate is much more trustworthy than the first 50 states.

### Easy 1 — Random-walk Metropolis for a continuous Normal target

**Goal.** Sample from an unnormalized continuous target with a Gaussian random walk, because many posteriors live on continuous parameters. We build it in 3 steps.

```python
n_e1 = 25000  # number of MH steps.
step_sd_e1 = 1.0  # proposal standard deviation.
x_e1 = 5.0  # deliberately start far from the N(0,1) center.

accepted_e1 = 0  # count accepted proposals.

```
▶ What you'll see: the chain starts in the tail and proposes local Normal jumps.

```python

    xp_e1 = x_e1 + np.random.normal(0.0, step_sd_e1)  # symmetric proposal.
    a_e1 = mh_accept(normal_score(x_e1), normal_score(xp_e1))  # normalizing constant cancels.
```
