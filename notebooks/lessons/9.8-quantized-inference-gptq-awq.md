# 9.8 — Quantized Inference (GPTQ, AWQ)

Quantized inference stores trained model weights with fewer bits, then dequantizes them just enough to run matrix multiplications at inference time. In this lesson, you will build int8 and int4 quantization from first principles, inspect scale and zero-point arithmetic, and see why GPTQ and AWQ are not magic formats but careful ways to spend a tiny error budget where it hurts least.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build quantized inference one idea at a time. Run each cell in order and read the printed intermediate values — every piece of math, including scale choice, rounding error, groupwise quantization, GPTQ-style second-order weighting, and AWQ-style channel protection, is derived with tiny NumPy arrays.

```python
import numpy as np
import matplotlib.pyplot as plt
np.random.seed(0)
```

### 1. Low-bit integers are a codebook for real weights

A neural network weight is normally a real number, but inference only needs an approximation that preserves the output well enough. Quantization replaces each weight with an integer code `q`, then reconstructs it with $\hat w=s(q-z)$. The bit width sets how many integer levels are available: int8 has 256 levels, while int4 has only 16, so int4 must use its levels much more carefully.

```python
bits_w = np.array([8, 4])
levels_w = 2 ** bits_w
print("levels for int8 and int4:", levels_w)
assert levels_w.tolist() == [256, 16]
```
▶ What you'll see: int8 has sixteen times as many representable codes as int4.

```python
weights_w = np.array([-0.8, -0.2, 0.0, 0.37, 0.9])
qmin_w, qmax_w = 0, 15
s_w, z_w = 0.1, 8
q_w = np.clip(np.round(weights_w / s_w) + z_w, qmin_w, qmax_w).astype(int)
hat_w = s_w * (q_w - z_w)
print("w:     ", weights_w)
print("q:     ", q_w)
print("w_hat: ", np.round(hat_w, 3))
print("abs error:", np.round(np.abs(weights_w - hat_w), 3))
assert q_w[3] == 12 and round(float(hat_w[3]), 3) == 0.4
```
▶ What you'll see: the weight 0.37 maps to code 12 and comes back as 0.40, giving the lesson's 0.03 absolute error.

```python
plt.figure(figsize=(5, 3))
plt.scatter(weights_w, hat_w, color="teal", s=70)
plt.plot([-1, 1], [-1, 1], color="gray", linestyle="--")
plt.xlabel("original weight")
plt.ylabel("dequantized weight")
plt.title("1: quantization replaces reals by nearby grid points")
plt.show()
```
▶ What you'll see: points lie near the diagonal, but only on grid values spaced by the scale.

*Why it's done this way:* the integer code is cheap to store, but the matrix multiply still needs real-valued meaning. The scale $s$ is the grid spacing; the zero point $z$ tells which integer represents real zero. Rounding chooses the closest grid point, and clipping prevents impossible codes outside $[0,2^b-1]$.

### 2. Scale and zero point decide the error budget

The formula hides the most important engineering choice: how wide the grid is. A scale that is too large wastes precision because neighboring grid points are far apart. A scale that is too small clips large weights because the grid cannot reach them. The zero point matters when the weight range is asymmetric around zero, because real zero should be exactly representable when possible.

```python
w2_w = np.array([-0.7, -0.1, 0.05, 0.37, 1.0])
bits2_w = 4
qmin2_w, qmax2_w = 0, 2 ** bits2_w - 1
scale2_w = (w2_w.max() - w2_w.min()) / (qmax2_w - qmin2_w)
zero2_w = int(np.round(qmin2_w - w2_w.min() / scale2_w))
print("scale:", round(float(scale2_w), 4), "zero_point:", zero2_w)
assert round(float(scale2_w), 4) == 0.1133 and zero2_w == 6
```
▶ What you'll see: the asymmetric range chooses a noncentral zero point so zero lands close to an integer code.

```python
q2_w = np.clip(np.round(w2_w / scale2_w) + zero2_w, qmin2_w, qmax2_w).astype(int)
hat2_w = scale2_w * (q2_w - zero2_w)
err2_w = w2_w - hat2_w
print("codes:", q2_w)
print("reconstruction:", np.round(hat2_w, 3))
print("signed errors:", np.round(err2_w, 3))
assert np.max(np.abs(err2_w)) <= scale2_w / 2 + 1e-12
```
▶ What you'll see: every unclipped value is within half a scale step of its reconstruction.

```python
plt.figure(figsize=(5, 3))
plt.bar(np.arange(len(err2_w)), err2_w, color="purple")
plt.axhline(scale2_w / 2, color="gray", linestyle="--", label="± half scale")
plt.axhline(-scale2_w / 2, color="gray", linestyle="--")
plt.title("2: signed quantization error")
plt.xlabel("weight index")
plt.ylabel("w - w_hat")
plt.legend()
plt.show()
```
▶ What you'll see: errors sit inside the half-step band because rounding picked the nearest grid point.

*Why it's done this way:* nearest-neighbor rounding bounds ordinary quantization error by $s/2$ when there is no clipping. That is why scale is not bookkeeping; it is the error budget per weight. Zero point is equally mathematical: it translates a real interval onto integer codes so that the grid covers the observed range.

### 3. Weight-only quantized inference dequantizes inside a linear layer

Transformer inference is dominated by matrix multiplications. Weight-only quantization stores the weight matrix in low-bit integers but reconstructs approximate weights when computing $Y=X\hat W$. This saves model memory while keeping activations in ordinary floating-point arrays in the toy notebook.

```python
X_w = np.array([[1.0, -0.5, 0.2], [0.0, 1.5, -1.0]])
W_w = np.array([[0.8, -0.4], [-0.3, 0.6], [0.2, -0.9]])
Y_fp_w = X_w @ W_w
print("full precision output:\n", np.round(Y_fp_w, 3))
assert np.allclose(np.round(Y_fp_w, 3), [[0.99, -0.88], [-0.65, 1.8]])
```
▶ What you'll see: the baseline linear layer output before any quantization.

```python
absmax_w = np.max(np.abs(W_w))
scale3_w = absmax_w / 7
q3_w = np.clip(np.round(W_w / scale3_w), -8, 7).astype(int)
W_hat_w = scale3_w * q3_w
Y_q_w = X_w @ W_hat_w
print("int4 signed codes:\n", q3_w)
print("quantized output:\n", np.round(Y_q_w, 3))
print("output error:\n", np.round(Y_fp_w - Y_q_w, 3))
assert q3_w.min() >= -8 and q3_w.max() <= 7
```
▶ What you'll see: the integer matrix is tiny, but the output remains close to the full-precision result.

```python
plt.figure(figsize=(5, 3))
plt.bar(np.arange(Y_fp_w.size) - 0.18, Y_fp_w.ravel(), width=0.36, label="fp")
plt.bar(np.arange(Y_q_w.size) + 0.18, Y_q_w.ravel(), width=0.36, label="int4 dequant")
plt.title("3: linear output before and after weight quantization")
plt.ylabel("activation value")
plt.legend()
plt.show()
```
▶ What you'll see: paired bars are close but not identical, showing how weight error becomes activation error.

*Why it's done this way:* matrix multiplication is linear, so replacing $W$ by $\hat W=W+\Delta W$ changes the output by $X\Delta W$. The same weight error is harmless for small input activations and harmful for large ones, which is the bridge to GPTQ and AWQ.

### 4. Groupwise quantization spends scales locally

A single scale for a whole matrix can be dominated by one large value. Modern LLM quantizers usually use groupwise scales: split a row or column into small groups and quantize each group with its own scale. That costs a few extra scale values but reduces error for groups whose weights occupy a smaller numeric range.

```python
row_w = np.array([0.04, -0.05, 0.06, -0.04, 1.1, -0.9, 0.8, -1.0])
scale_global_w = np.max(np.abs(row_w)) / 7
q_global_w = np.clip(np.round(row_w / scale_global_w), -8, 7).astype(int)
hat_global_w = scale_global_w * q_global_w
global_mse_w = float(np.mean((row_w - hat_global_w) ** 2))
print("global scale:", round(float(scale_global_w), 4), "global MSE:", round(global_mse_w, 6))
```
▶ What you'll see: the global scale is set by the large weights, so tiny weights get coarse treatment.

```python
groups_w = row_w.reshape(2, 4)
scales_group_w = np.max(np.abs(groups_w), axis=1) / 7
q_group_w = np.clip(np.round(groups_w / scales_group_w[:, None]), -8, 7).astype(int)
hat_group_w = (scales_group_w[:, None] * q_group_w).reshape(-1)
group_mse_w = float(np.mean((row_w - hat_group_w) ** 2))
print("group scales:", np.round(scales_group_w, 4))
print("groupwise MSE:", round(group_mse_w, 6))
assert group_mse_w < global_mse_w
```
▶ What you'll see: the small-weight group receives a much smaller scale and lower reconstruction error.

```python
plt.figure(figsize=(5, 3))
plt.bar(["global", "groupwise"], [global_mse_w, group_mse_w], color=["crimson", "seagreen"])
plt.title("4: groupwise scales reduce local error")
plt.ylabel("mean squared weight error")
plt.show()
```
▶ What you'll see: groupwise quantization has lower MSE because it no longer lets one range serve every weight.

*Why it's done this way:* a scale is a shared grid spacing. If unrelated weights share one grid, small values may round to a poor set of codes. Grouping is a compromise: many local grids, but not one expensive scale per weight.

### 5. GPTQ weights errors by activation importance

GPTQ is a post-training quantization idea: given calibration activations, choose quantized weights so the layer output changes as little as possible. A tiny diagonal version says an error in weight coordinate $j$ costs roughly $h_j(\Delta w_j)^2$, where $h_j$ is an activation-derived curvature or second-moment term. Larger $h_j$ means mistakes on that coordinate are amplified more often.

```python
w5_w = np.array([0.18, 0.42, -0.33, 1.25])
h5_w = np.array([4000.0, 1.0, 8.0, 0.5])
scale5_w = np.max(np.abs(w5_w)) / 7
q5_w = np.clip(np.round(w5_w / scale5_w), -8, 7).astype(int)
hat5_w = scale5_w * q5_w
err5_w = w5_w - hat5_w
weighted_cost_w = h5_w * err5_w ** 2
print("errors:", np.round(err5_w, 4))
print("hessian-like weights:", h5_w)
print("weighted costs:", np.round(weighted_cost_w, 5))
assert int(np.argmax(weighted_cost_w)) == 0
```
▶ What you'll see: the largest weighted cost can come from a modest raw error when its activation weight is large.

```python
salient_idx_w = int(np.argmax(weighted_cost_w))
hat_gptq_toy_w = hat5_w.copy()
hat_gptq_toy_w[salient_idx_w] = w5_w[salient_idx_w]
plain_cost_w = float(np.sum(weighted_cost_w))
protected_cost_w = float(np.sum(h5_w * (w5_w - hat_gptq_toy_w) ** 2))
print("plain weighted cost:", round(plain_cost_w, 6))
print("protected weighted cost:", round(protected_cost_w, 6))
assert protected_cost_w < plain_cost_w
```
▶ What you'll see: preserving the most expensive coordinate sharply reduces output-aware cost.

```python
plt.figure(figsize=(5, 3))
plt.bar(np.arange(len(w5_w)), weighted_cost_w, color="darkorange")
plt.title("5: GPTQ-style activation-weighted error")
plt.xlabel("weight coordinate")
plt.ylabel("h_j · error²")
plt.show()
```
▶ What you'll see: one coordinate dominates the weighted error even though it is not simply the largest weight.

*Why it's done this way:* minimizing raw weight MSE is the wrong objective if inputs use some coordinates much more than others. GPTQ's second-order view approximates output damage, so the quantizer protects weights whose errors are multiplied by high-variance calibration activations.

### 6. AWQ protects salient activation channels before quantizing

AWQ starts from a related observation: channels with large activations can make small weight errors highly visible. A practical toy version marks channels as salient using activation magnitudes, keeps them high precision or rescales them, and quantizes the rest. The point is not that large weights are always sacred; the dangerous product is activation size times weight error.

```python
W6_w = np.array([[0.2, 2.0, -0.1], [0.3, -1.5, 0.2], [0.1, 1.8, -0.2]])
act6_w = np.array([0.4, 6.0, 0.5])
salient6_w = act6_w > 2.0
print("activation means:", act6_w)
print("salient channels:", salient6_w.astype(int))
assert salient6_w.tolist() == [False, True, False]
```
▶ What you'll see: the middle channel is marked salient because calibration activations are much larger there.

```python
scale6_w = np.max(np.abs(W6_w)) / 7
q6_w = np.clip(np.round(W6_w / scale6_w), -8, 7).astype(int)
Wq6_w = scale6_w * q6_w
W_awq_w = Wq6_w.copy()
W_awq_w[:, salient6_w] = W6_w[:, salient6_w]
x6_w = np.array([0.4, 6.0, 0.5])
y_fp6_w = x6_w @ W6_w
y_plain6_w = x6_w @ Wq6_w
y_awq6_w = x6_w @ W_awq_w
print("plain output error norm:", round(float(np.linalg.norm(y_fp6_w - y_plain6_w)), 5))
print("AWQ-style protected error norm:", round(float(np.linalg.norm(y_fp6_w - y_awq6_w)), 5))
assert np.linalg.norm(y_fp6_w - y_awq6_w) < np.linalg.norm(y_fp6_w - y_plain6_w)
```
▶ What you'll see: protecting the high-activation channel reduces output error for the calibration-like input.

```python
plt.figure(figsize=(5, 3))
plt.bar(["plain int4", "AWQ-style protected"], [np.linalg.norm(y_fp6_w - y_plain6_w), np.linalg.norm(y_fp6_w - y_awq6_w)], color=["crimson", "seagreen"])
plt.title("6: protect channels that activations amplify")
plt.ylabel("output error norm")
plt.show()
```
▶ What you'll see: the AWQ-style bar is lower because the channel with activation 6.0 was not allowed to accumulate quantization error.

*Why it's done this way:* quantization error matters after multiplication by activations. AWQ uses calibration data to find channels where the product $x_j\Delta W_j$ would be large, then spends extra precision or scaling there instead of treating every weight equally.

### ✍️ Toy 1 · Integer codebooks reconstruct nearby weights

A low-bit code stores a small integer; scale and zero point turn that integer back into a nearby real weight.

```python
import numpy as np
import matplotlib.pyplot as plt

t1_rng = np.random.default_rng(0)
t1_bits = np.array([2, 4])
print("bit widths:", t1_bits.tolist())  # -> [2, 4]
t1_levels = 2 ** t1_bits
print("integer levels:", t1_levels.tolist())  # -> [4, 16]
t1_weights = np.array([-0.4, 0.0, 0.3, 0.8])
print("weights:", t1_weights.tolist())  # -> [-0.4, 0.0, 0.3, 0.8]
t1_scale = 0.4
print("scale:", t1_scale)  # -> 0.4
t1_zero = 1
print("zero point:", t1_zero)  # -> 1
t1_q = np.clip(np.round(t1_weights / t1_scale) + t1_zero, 0, 3).astype(int)
print("integer codes:", t1_q.tolist())  # -> [0, 1, 2, 3]
t1_hat = t1_scale * (t1_q - t1_zero)
print("reconstructed weights:", t1_hat.tolist())  # -> [-0.4, 0.0, 0.4, 0.8]
t1_error = t1_weights - t1_hat
print("signed error:", np.round(t1_error, 3).tolist())  # -> [0.0, 0.0, -0.1, 0.0]

plt.figure(figsize=(4.8, 3))
plt.scatter(t1_weights, t1_hat, color="teal", s=70)
plt.plot([-0.5, 0.9], [-0.5, 0.9], color="gray", linestyle="--")
plt.title("Toy 1 · weights snap to a grid")
plt.xlabel("weight")
plt.ylabel("reconstruction")
plt.show()
assert t1_q.tolist() == [0, 1, 2, 3]
```
▶ What you'll see: every reconstruction lies on the scale-0.4 grid, so 0.3 snaps to 0.4.

### ✍️ Toy 2 · Scale and zero point set the rounding budget

The observed min and max choose a grid spacing; rounding should keep each unclipped value within half a scale step.

```python
import numpy as np

t2_rng = np.random.default_rng(0)
t2_weights = np.array([-1.0, -0.25, 0.5])
print("weights:", t2_weights.tolist())  # -> [-1.0, -0.25, 0.5]
t2_bits = 3
print("bits:", t2_bits)  # -> 3
t2_qmin = 0
print("qmin:", t2_qmin)  # -> 0
t2_qmax = 2 ** t2_bits - 1
print("qmax:", t2_qmax)  # -> 7
t2_scale = (np.max(t2_weights) - np.min(t2_weights)) / (t2_qmax - t2_qmin)
print("scale:", round(float(t2_scale), 4))  # -> 0.2143
t2_zero = int(np.round(t2_qmin - np.min(t2_weights) / t2_scale))
print("zero point:", t2_zero)  # -> 5
t2_q = np.clip(np.round(t2_weights / t2_scale) + t2_zero, t2_qmin, t2_qmax).astype(int)
print("codes:", t2_q.tolist())  # -> [0, 4, 7]
t2_hat = t2_scale * (t2_q - t2_zero)
print("reconstruction:", np.round(t2_hat, 3).tolist())  # -> [-1.071, -0.214, 0.429]
t2_error = t2_weights - t2_hat
print("signed error:", np.round(t2_error, 3).tolist())  # -> [0.071, -0.036, 0.071]
t2_half_step = t2_scale / 2
print("half step:", round(float(t2_half_step), 4))  # -> 0.1071

plt.figure(figsize=(4.8, 3))
plt.bar(np.arange(len(t2_error)), t2_error, color="purple")
plt.axhline(t2_half_step, color="gray", linestyle="--", label="± half step")
plt.axhline(-t2_half_step, color="gray", linestyle="--")
plt.title("Toy 2 · errors stay inside half a step")
plt.xlabel("weight index")
plt.ylabel("error")
plt.legend()
plt.show()
assert np.max(np.abs(t2_error)) <= t2_half_step + 1e-12
```
▶ What you'll see: every signed error fits between the dashed ±half-step lines.

### ✍️ Toy 3 · Weight-only inference dequantizes before matmul

The quantized matrix is stored as small integers, then multiplied as reconstructed real weights in the linear layer.

```python
import numpy as np

t3_rng = np.random.default_rng(0)
t3_X = np.array([[1.0, 2.0]])
print("input X:", t3_X.tolist())  # -> [[1.0, 2.0]]
t3_W = np.array([[0.5, -0.25], [1.0, 0.75]])
print("full precision W:\n", t3_W)  # -> [[ 0.5  -0.25] [ 1.    0.75]]
t3_Y_fp = t3_X @ t3_W
print("full precision output:", np.round(t3_Y_fp, 3).tolist())  # -> [[2.5, 1.25]]
t3_scale = np.max(np.abs(t3_W)) / 3
print("signed scale:", round(float(t3_scale), 4))  # -> 0.3333
t3_q = np.clip(np.round(t3_W / t3_scale), -4, 3).astype(int)
print("integer W codes:\n", t3_q)  # -> [[ 2 -1] [ 3  2]]
t3_W_hat = t3_scale * t3_q
print("dequantized W:\n", np.round(t3_W_hat, 3))  # -> [[ 0.667 -0.333] [ 1.     0.667]]
t3_Y_q = t3_X @ t3_W_hat
print("quantized output:", np.round(t3_Y_q, 3).tolist())  # -> [[2.667, 1.0]]
t3_output_error = t3_Y_fp - t3_Y_q
print("output error:", np.round(t3_output_error, 3).tolist())  # -> [[-0.167, 0.25]]

plt.figure(figsize=(4.8, 3))
plt.bar(np.arange(2) - 0.18, t3_Y_fp.ravel(), width=0.36, label="fp", color="gray")
plt.bar(np.arange(2) + 0.18, t3_Y_q.ravel(), width=0.36, label="dequant", color="teal")
plt.xticks(np.arange(2), ["out0", "out1"])
plt.title("Toy 3 · linear output after dequant")
plt.ylabel("activation")
plt.legend()
plt.show()
assert t3_q.min() >= -4 and t3_q.max() <= 3
```
▶ What you'll see: the dequantized output is close to the full-precision output but not identical.

### ✍️ Toy 4 · Groupwise scales reduce local reconstruction error

A global scale is forced to cover both tiny and large weights; groupwise scales let each local range choose its own grid.

```python
import numpy as np

t4_rng = np.random.default_rng(0)
t4_row = np.array([0.05, -0.04, 0.06, -0.05, 0.8, -0.7, 0.6, -0.9])
print("row weights:", t4_row.tolist())  # -> [0.05, -0.04, 0.06, -0.05, 0.8, -0.7, 0.6, -0.9]
t4_global_scale = np.max(np.abs(t4_row)) / 3
print("global scale:", round(float(t4_global_scale), 4))  # -> 0.3
t4_q_global = np.clip(np.round(t4_row / t4_global_scale), -4, 3).astype(int)
print("global codes:", t4_q_global.tolist())  # -> [0, 0, 0, 0, 3, -2, 2, -3]
t4_hat_global = t4_global_scale * t4_q_global
t4_global_mse = float(np.mean((t4_row - t4_hat_global) ** 2))
print("global MSE:", round(t4_global_mse, 6))  # -> 0.003775
t4_groups = t4_row.reshape(2, 4)
print("groups:\n", t4_groups)  # -> [[ 0.05 -0.04  0.06 -0.05] [ 0.8  -0.7   0.6  -0.9 ]]
t4_group_scales = np.max(np.abs(t4_groups), axis=1) / 3
print("group scales:", np.round(t4_group_scales, 4).tolist())  # -> [0.02, 0.3]
t4_q_group = np.clip(np.round(t4_groups / t4_group_scales[:, None]), -4, 3).astype(int)
print("group codes:\n", t4_q_group)  # -> [[ 2 -2  3 -2] [ 3 -2  2 -3]]
t4_hat_group = (t4_group_scales[:, None] * t4_q_group).reshape(-1)
t4_group_mse = float(np.mean((t4_row - t4_hat_group) ** 2))
print("groupwise MSE:", round(t4_group_mse, 6))  # -> 0.002525

plt.figure(figsize=(4.4, 3))
plt.bar(["global", "groupwise"], [t4_global_mse, t4_group_mse], color=["crimson", "seagreen"])
plt.title("Toy 4 · local scales spend error better")
plt.ylabel("MSE")
plt.show()
assert t4_group_mse < t4_global_mse
```
▶ What you'll see: groupwise quantization lowers MSE because the small-weight group gets a much finer scale.

### ✍️ Toy 5 · GPTQ-style weighting protects costly coordinates

The same raw rounding error matters more on coordinates with larger activation-derived weights.

```python
import numpy as np

t5_rng = np.random.default_rng(0)
t5_w = np.array([0.12, 0.55, -0.32, 0.95])
print("weights:", t5_w.tolist())  # -> [0.12, 0.55, -0.32, 0.95]
t5_h = np.array([25.0, 1.0, 4.0, 0.5])
print("activation weights:", t5_h.tolist())  # -> [25.0, 1.0, 4.0, 0.5]
t5_scale = np.max(np.abs(t5_w)) / 3
print("scale:", round(float(t5_scale), 4))  # -> 0.3167
t5_q = np.clip(np.round(t5_w / t5_scale), -4, 3).astype(int)
print("codes:", t5_q.tolist())  # -> [0, 2, -1, 3]
t5_hat = t5_scale * t5_q
print("reconstruction:", np.round(t5_hat, 3).tolist())  # -> [0.0, 0.633, -0.317, 0.95]
t5_error = t5_w - t5_hat
print("raw errors:", np.round(t5_error, 3).tolist())  # -> [0.12, -0.083, -0.003, 0.0]
t5_weighted_cost = t5_h * t5_error ** 2
```

## 🛠️ Setup

```python
import numpy as np
import matplotlib.pyplot as plt
np.random.seed(0)

def affine_quantize(x, bits=4, symmetric=False):
    x = np.asarray(x, dtype=float)
    if symmetric:
        qmin, qmax = -(2 ** (bits - 1)), 2 ** (bits - 1) - 1
        scale = np.max(np.abs(x)) / qmax if np.max(np.abs(x)) != 0 else 1.0
        zero = 0
        q = np.clip(np.round(x / scale), qmin, qmax).astype(int)
    else:
        qmin, qmax = 0, 2 ** bits - 1
        xmin, xmax = float(np.min(x)), float(np.max(x))
        scale = (xmax - xmin) / (qmax - qmin) if xmax != xmin else 1.0
        zero = int(np.clip(np.round(qmin - xmin / scale), qmin, qmax))
        q = np.clip(np.round(x / scale) + zero, qmin, qmax).astype(int)
    return q, float(scale), int(zero)

def affine_dequantize(q, scale, zero=0):
    return scale * (np.asarray(q, dtype=float) - zero)

def signed_dequantize(q, scale):
    return scale * np.asarray(q, dtype=float)

def memory_gb(params, bits):
    return params * bits / 8 / 1e9
```

### Advanced 5 — Check accumulated logit drift

**Goal.** Propagate quantization through two linear layers, because small layer errors can accumulate into changed logits. We build it in 4 steps.

