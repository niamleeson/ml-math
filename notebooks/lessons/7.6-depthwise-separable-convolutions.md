# 7.6 — Depthwise Separable Convolutions

Depthwise separable convolution is the MobileNet trick that splits a costly convolution into two cheaper questions: **where should each channel look spatially?** and **how should channels mix afterward?** In this lesson, you will build the operation from scratch with NumPy, count the exact multiplications, visualize the intermediate tensors, and see why the factorization gives a large speedup while also imposing a real expressiveness constraint.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build depthwise separable convolution one idea at a time. Run each cell in order and read the printed intermediate values — every piece of shape arithmetic and multiply counting is spelled out so the efficient block is not a black box. This walkthrough is self-contained (it imports what it needs) and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays, loops, and small numerical checks for convolution.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
np.random.seed(0)  # reproducibility for toy feature maps and filters.
```

### 1. A standard convolution mixes space and channels at once

A normal convolutional filter has a small spatial window for **every input channel** and produces one output channel by summing all those channel-specific spatial responses. With a `3×3` kernel, `C=3` input channels, and `C'=8` output channels, each output pixel needs `3×3×3×8 = 216` multiplications. That is powerful because every output channel can choose a different spatial pattern for every input channel, but it is expensive because spatial filtering and channel mixing are paid for together.

```python
D_w, C_w, Cout_w = 3, 3, 8  # kernel size, input channels, output channels.
std_mults_w = D_w * D_w * C_w * Cout_w  # D^2 C C' multiplies per output pixel.
print("standard conv multiplies per output pixel:", std_mults_w)
assert std_mults_w == 216  # 3*3*3*8.
```
▶ What you'll see: the toy standard convolution costs 216 multiplications for each output pixel.

```python
H_w, W_w = 5, 5  # output grid size for a small feature map.
std_map_mults_w = H_w * W_w * std_mults_w  # repeat the per-pixel cost at every location.
print("standard conv multiplies on 5x5 output:", std_map_mults_w)
assert std_map_mults_w == 5400
plt.figure(figsize=(4.2, 3))
plt.bar(["per pixel", "5x5 map"], [std_mults_w, std_map_mults_w], color="crimson")
plt.title("1: standard convolution cost repeats everywhere")
plt.ylabel("multiplications")
plt.show()
```
▶ What you'll see: the per-pixel cost is already large, and the feature-map cost multiplies it by 25 locations.

*Why it's done this way: a standard kernel stores one spatial template for every input-output channel pair. The formula $D^2CC'$ is exactly “spatial weights per pair” times “number of channel pairs,” so the cost grows multiplicatively in spatial area and channel mixing capacity.*

### 2. The depthwise step filters each channel independently

Depthwise convolution refuses to mix channels during the spatial step. Instead, it learns one `D×D` filter per input channel, applies each filter only to its matching channel, and keeps the channel count unchanged. For `D=3` and `C=3`, that is only `3×3×3 = 27` multiplications per output pixel. The output still has three channels, but each one has learned where to look inside its own map.

```python
X_w = np.arange(5 * 5 * 3, dtype=float).reshape(5, 5, 3) / 10.0  # one tiny HxWxC feature tensor.
Kdw_w = np.array([[[1, 0, -1], [1, 0, -1], [1, 0, -1]],
                  [[0, 1, 0], [1, -4, 1], [0, 1, 0]],
                  [[1, 1, 1], [0, 0, 0], [-1, -1, -1]]], dtype=float)  # one 3x3 filter per channel.
print("X shape:", X_w.shape, "depthwise filters shape:", Kdw_w.shape)
```
▶ What you'll see: the input has shape `(5, 5, 3)`, and the depthwise filters have shape `(3, 3, 3)` — one spatial filter per channel.

```python
def depthwise_valid_w(X, K):  # apply one spatial filter to each matching channel.
    H, W, C = X.shape
    D = K.shape[0]
    Y = np.zeros((H - D + 1, W - D + 1, C))
    for i in range(Y.shape[0]):
        for j in range(Y.shape[1]):
            patch = X[i:i + D, j:j + D, :]
            Y[i, j, :] = np.sum(patch * K, axis=(0, 1))
    return Y
Ydw_w = depthwise_valid_w(X_w, Kdw_w)
print("depthwise output shape:", Ydw_w.shape)
print("top-left depthwise response:", np.round(Ydw_w[0, 0], 3))
assert Ydw_w.shape == (3, 3, 3)
```
▶ What you'll see: the spatial size shrinks to `3×3`, but the channel count remains `3`.

```python
fig, ax = plt.subplots(1, 3, figsize=(8, 2.5))
for c_w in range(3):
    ax[c_w].imshow(Ydw_w[:, :, c_w], cmap="coolwarm")
    ax[c_w].set_title(f"depthwise channel {c_w}")
    ax[c_w].axis("off")
plt.suptitle("2: each channel is filtered alone")
plt.show()
```
▶ What you'll see: three separate response maps; no channel has borrowed values from another yet.

*Why it's done this way: separating the spatial operation changes the cost from $D^2CC'$ to $D^2C$ because each channel pays for exactly one spatial filter. The price is that red/green/blue, or feature channel 0/1/2, cannot interact during this step.*

### 3. The pointwise step mixes channels with 1×1 filters

After depthwise filtering, channels still need to talk. A `1×1` convolution does exactly that: at each spatial position, it takes the `C` channel values and forms `C'` learned linear combinations. There is no spatial neighborhood now — only channel mixing — so the cost is `C×C'` multiplications per pixel. In the toy case, that is `3×8 = 24`.

```python
Wpw_w = np.array([[1.0, 0.5, -0.5, 0.0, 1.0, -1.0, 0.25, 0.75],
                  [0.0, 1.0, 0.5, -0.5, 1.0, 0.5, -1.0, 0.25],
                  [0.5, -0.5, 1.0, 1.0, 0.0, 0.25, 0.75, -1.0]])  # C by C' channel mixer.
pointwise_mults_w = C_w * Cout_w
print("pointwise weight shape:", Wpw_w.shape)
print("pointwise multiplies per pixel:", pointwise_mults_w)
assert pointwise_mults_w == 24
```
▶ What you'll see: the `1×1` layer maps 3 channels to 8 channels with only 24 multiplications per location.

```python
Ysep_w = Ydw_w @ Wpw_w  # at every spatial location, multiply the 3-channel vector by the CxC' matrix.
print("separable output shape:", Ysep_w.shape)
print("top-left first four outputs:", np.round(Ysep_w[0, 0, :4], 3))
assert Ysep_w.shape == (3, 3, 8)
```
▶ What you'll see: the spatial grid stays `3×3`, but the pointwise layer creates 8 output channels.

```python
plt.figure(figsize=(5, 3))
plt.imshow(Wpw_w, cmap="viridis", aspect="auto")
plt.colorbar(label="mixing weight")
plt.title("3: 1x1 pointwise channel-mixing matrix")
plt.xlabel("output channel")
plt.ylabel("depthwise channel")
plt.show()
```
▶ What you'll see: each output channel is a different weighted mixture of the three depthwise channels.

*Why it's done this way: a `1×1` convolution is the cheapest possible channel mixer because it ignores neighboring pixels and only multiplies the current channel vector by a learned matrix. That is why its cost is $CC'$ instead of $D^2CC'$.*

### 4. The full separable block saves work by adding costs instead of multiplying them

A depthwise separable block is the depthwise spatial step plus the pointwise channel-mixing step. Its per-pixel multiply count is $D^2C + CC'$, not $D^2CC'$. In the toy case, that is `27 + 24 = 51`, which is only about `23.6%` of the standard convolution cost and saves about `76.4%` of multiplications.

```python
depthwise_mults_w = D_w * D_w * C_w
separable_mults_w = depthwise_mults_w + pointwise_mults_w
ratio_w = separable_mults_w / std_mults_w
reduction_w = 1 - ratio_w
print("depthwise:", depthwise_mults_w, "pointwise:", pointwise_mults_w, "separable:", separable_mults_w)
print("ratio:", round(ratio_w, 6), "reduction:", round(reduction_w, 6))
assert separable_mults_w == 51
assert round(ratio_w, 6) == 0.236111
```
▶ What you'll see: separable convolution uses 51 multiplies per output pixel instead of 216.

```python
sep_map_mults_w = H_w * W_w * separable_mults_w
saved_map_mults_w = std_map_mults_w - sep_map_mults_w
print("separable multiplies on 5x5 output:", sep_map_mults_w)
print("saved multiplies:", saved_map_mults_w)
assert sep_map_mults_w == 1275
assert saved_map_mults_w == 4125
plt.figure(figsize=(4.6, 3))
plt.bar(["standard", "separable"], [std_map_mults_w, sep_map_mults_w], color=["crimson", "seagreen"])
plt.title("4: the saving repeats over the map")
plt.ylabel("multiplications on 5x5 output")
plt.show()
```
▶ What you'll see: the `5×5` map drops from 5400 to 1275 multiplications.

*Why it's done this way: the operation is cheaper because it changes one dense joint problem into two smaller problems whose costs are added. Algebraically, replacing $D^2CC'$ with $D^2C+CC'$ removes the expensive “spatial area times every output channel” coupling.*

### 5. The factorization constraint is the source of both speedup and possible accuracy loss

A standard convolution can learn a different `3×3` spatial pattern for every input-output channel pair. A separable block cannot: for each input channel, the same depthwise spatial response is reused across all output channels, and the pointwise layer only rescales and combines those responses afterward. This is a low-rank-style factorization of the standard kernel tensor.

```python
Kstd_w = np.random.default_rng(0).normal(size=(3, 3, 3, 8))  # D x D x C x C' standard kernel tensor.
param_std_w = Kstd_w.size
param_sep_w = Kdw_w.size + Wpw_w.size
print("standard parameters:", param_std_w)
print("separable parameters:", param_sep_w)
assert param_std_w == 216 and param_sep_w == 51
```
▶ What you'll see: the parameter count matches the multiply count for one output pixel in this toy setup.

```python
c_in_w = 0  # inspect one input channel's spatial kernels across output channels.
std_slices_w = Kstd_w[:, :, c_in_w, :4]
fig, ax = plt.subplots(1, 4, figsize=(8, 2.2))
for o_w in range(4):
    ax[o_w].imshow(std_slices_w[:, :, o_w], cmap="coolwarm")
    ax[o_w].set_title(f"std out {o_w}")
    ax[o_w].axis("off")
plt.suptitle("5: standard conv can use different spatial kernels per output")
plt.show()
```
▶ What you'll see: four output channels can have four unrelated spatial patterns for the same input channel.

```python
sep_effective_w = Kdw_w[:, :, c_in_w, None] * Wpw_w[c_in_w, :4][None, None, :]  # separable effective kernels for one input channel.
fig, ax = plt.subplots(1, 4, figsize=(8, 2.2))
for o_w in range(4):
    ax[o_w].imshow(sep_effective_w[:, :, o_w], cmap="coolwarm")
    ax[o_w].set_title(f"sep out {o_w}")
    ax[o_w].axis("off")
plt.suptitle("5: separable kernels are scaled copies before channel summation")
plt.show()
```
▶ What you'll see: the separable spatial pattern for one input channel is reused as scaled copies across outputs.

*Why it's done this way: the factorization works when “where to look” and “how to mix channels” can be separated. It can fail when an output channel needs a unique spatial pattern for a particular input channel, because separable convolution has deliberately removed those degrees of freedom.*

### 6. Efficiency depends on channel width, output width, and intermediate memory

The arithmetic ratio is not a fixed constant; it changes with `D`, `C`, and `C'`. The formula $\frac{D^2C+CC'}{D^2CC'}=\frac{1}{C'}+\frac{1}{D^2}$ shows why the saving is strongest when there are many output channels. But hardware speed is not only multiplication count: the depthwise output must be written or kept as an intermediate tensor, so memory movement can reduce the practical gain.

```python
Cout_grid_w = np.array([4, 8, 16, 32, 64])
ratios_w = (D_w * D_w * C_w + C_w * Cout_grid_w) / (D_w * D_w * C_w * Cout_grid_w)
print("C' grid:", Cout_grid_w)
print("separable/std ratios:", np.round(ratios_w, 3))
assert round(float(ratios_w[1]), 6) == 0.236111
```
▶ What you'll see: the ratio falls as the number of output channels grows.

```python
plt.figure(figsize=(5, 3))
plt.plot(Cout_grid_w, ratios_w, marker="o", color="navy")
plt.axhline(1 / (D_w * D_w), color="gray", linestyle="--", label="1/D² limit")
plt.title("6: savings improve as output channels grow")
plt.xlabel("output channels C'")
plt.ylabel("separable / standard multiplies")
plt.legend()
plt.show()
```
▶ What you'll see: the ratio approaches the spatial floor `1/9`, but remains above it because pointwise mixing still costs work.

```python
intermediate_values_w = Ydw_w.size
final_values_w = Ysep_w.size
print("depthwise intermediate values:", intermediate_values_w)
print("final output values:", final_values_w)
assert intermediate_values_w == 27 and final_values_w == 72
```
▶ What you'll see: even in a tiny example, the separable block creates an intermediate tensor before the final output.

*Why it's done this way: multiply counts explain the algorithmic bargain, while the intermediate tensor explains a practical caveat. Efficient CNN design must account for both arithmetic and data movement, especially on small devices where memory bandwidth can dominate.*

### ✍️ Toy 1 · Standard convolution mixes space and channels

A standard convolution output pixel is one sum over **spatial positions and input channels**. Here one `2×2×2` patch meets one `2×2×2` filter and collapses to a single number.

```python
import numpy as np
import matplotlib.pyplot as plt

t1_rng = np.random.default_rng(0)  # seeded for reproducibility.
t1_patch = np.array([[[1, 0], [2, 1]], [[0, 1], [1, 3]]])  # tiny 2x2x2 input patch.
t1_kernel = np.array([[[1, -1], [1, 0]], [[0, 2], [-1, 1]]])  # one standard conv filter.
print("patch shape:", t1_patch.shape)  # -> (2, 2, 2)
print("kernel shape:", t1_kernel.shape)  # -> (2, 2, 2)
t1_products = t1_patch * t1_kernel  # -> [[[1, 0], [2, 0]], [[0, 2], [-1, 3]]]
print("patch * kernel:", t1_products.tolist())  # -> [[[1, 0], [2, 0]], [[0, 2], [-1, 3]]]
t1_channel_sums = t1_products.sum(axis=(0, 1))  # -> [2, 5]
print("sum per input channel:", t1_channel_sums.tolist())  # -> [2, 5]
t1_response = int(t1_channel_sums.sum())  # -> 7
print("standard conv response:", t1_response)  # -> 7
assert t1_response == 7

plt.figure(figsize=(4.6, 2.8))
plt.bar(["channel 0", "channel 1", "total"], [t1_channel_sums[0], t1_channel_sums[1], t1_response], color=["#4c78a8", "#f58518", "#54a24b"])
plt.title("Toy 1 · one standard output mixes everything")
plt.ylabel("summed product")
plt.show()
```
▶ What you'll see: two channel contributions, `2` and `5`, added into one standard-convolution response `7`.

### ✍️ Toy 2 · Depthwise convolution filters channels separately

Depthwise convolution keeps channel lanes separate: channel 0 uses its own spatial filter, channel 1 uses its own filter, and no cross-channel addition happens yet.

```python
import numpy as np

t2_rng = np.random.default_rng(0)  # seeded for reproducibility.
t2_x = np.zeros((3, 3, 2), dtype=int)  # tiny 3x3 image with 2 channels.
t2_x[:, :, 0] = np.array([[1, 2, 0], [0, 1, 3], [2, 1, 0]])
t2_x[:, :, 1] = np.array([[0, 1, 2], [2, 1, 0], [1, 0, 1]])
t2_k = np.zeros((2, 2, 2), dtype=int)  # one 2x2 filter per channel.
t2_k[:, :, 0] = np.array([[1, 0], [0, -1]])
t2_k[:, :, 1] = np.array([[0, 1], [1, 0]])
print("input shape:", t2_x.shape)  # -> (3, 3, 2)
print("filter shape:", t2_k.shape)  # -> (2, 2, 2)
t2_out = np.zeros((2, 2, 2), dtype=int)  # -> shape (2, 2, 2)
for t2_r in range(2):
    for t2_c in range(2):
        t2_patch = t2_x[t2_r:t2_r + 2, t2_c:t2_c + 2, :]
        t2_out[t2_r, t2_c, :] = (t2_patch * t2_k).sum(axis=(0, 1))
print("depthwise channel 0:\n", t2_out[:, :, 0])  # -> [[0, -1], [-1, 1]]
print("depthwise channel 1:\n", t2_out[:, :, 1])  # -> [[3, 3], [2, 0]]
t2_channel_totals = t2_out.sum(axis=(0, 1))  # -> [-1, 8]
print("channel totals stay separate:", t2_channel_totals.tolist())  # -> [-1, 8]
assert np.array_equal(t2_out[:, :, 0], np.array([[0, -1], [-1, 1]]))
assert np.array_equal(t2_out[:, :, 1], np.array([[3, 3], [2, 0]]))

fig, ax = plt.subplots(1, 2, figsize=(5.2, 2.4))
ax[0].imshow(t2_out[:, :, 0], cmap="coolwarm", vmin=-3, vmax=3)
ax[0].set_title("channel 0 only")
ax[1].imshow(t2_out[:, :, 1], cmap="coolwarm", vmin=-3, vmax=3)
ax[1].set_title("channel 1 only")
for t2_a in ax:
    t2_a.set_xticks([])
    t2_a.set_yticks([])
plt.suptitle("Toy 2 · depthwise keeps lanes separate")
plt.show()
```
▶ What you'll see: two separate `2×2` response maps, one per input channel, with no channel mixing.

### ✍️ Toy 3 · Pointwise convolution mixes channels at each pixel

A `1×1` pointwise convolution ignores neighboring pixels and multiplies each channel vector by a small mixing matrix.

```python
import numpy as np

t3_rng = np.random.default_rng(0)  # seeded for reproducibility.
t3_stack = np.array([[[1.0, 0.0, 2.0], [0.0, 1.0, 1.0]], [[2.0, 1.0, 0.0], [1.0, 2.0, 1.0]]])  # 2x2x3 depthwise output.
t3_mixer = np.array([[1.0, 0.5], [-1.0, 1.0], [0.5, -0.5]])  # 3 input channels -> 2 output channels.
print("stack shape:", t3_stack.shape)  # -> (2, 2, 3)
print("pointwise mixer shape:", t3_mixer.shape)  # -> (3, 2)
t3_top_left = t3_stack[0, 0, :]  # -> [1.0, 0.0, 2.0]
print("top-left channel vector:", t3_top_left.tolist())  # -> [1.0, 0.0, 2.0]
t3_top_left_mixed = t3_top_left @ t3_mixer  # -> [2.0, -0.5]
print("top-left mixed vector:", t3_top_left_mixed.tolist())  # -> [2.0, -0.5]
t3_mixed = t3_stack @ t3_mixer  # -> [[[2.0, -0.5], [-0.5, 0.5]], [[1.0, 2.0], [-0.5, 2.0]]]
print("full pointwise output:", t3_mixed.tolist())  # -> [[[2.0, -0.5], [-0.5, 0.5]], [[1.0, 2.0], [-0.5, 2.0]]]
assert t3_mixed.shape == (2, 2, 2)
assert np.allclose(t3_top_left_mixed, [2.0, -0.5])

plt.figure(figsize=(4.4, 2.8))
plt.imshow(t3_mixer, cmap="viridis", aspect="auto")
plt.colorbar(label="weight")
plt.title("Toy 3 · 1×1 channel mixer")
plt.xlabel("output channel")
plt.ylabel("input channel")
plt.show()
```
▶ What you'll see: each spatial location keeps its coordinates but the 3-channel vector becomes a 2-channel vector.

### ✍️ Toy 4 · Separable cost adds depthwise and pointwise work

The separable block pays once for spatial filtering and once for channel mixing, so its cost is `D²C + CC'` instead of `D²CC'`.

```python
import numpy as np

t4_rng = np.random.default_rng(0)  # seeded for reproducibility.
t4_D = 3  # -> 3
t4_C = 2  # -> 2
t4_Cout = 4  # -> 4
print("D, C, Cout:", t4_D, t4_C, t4_Cout)  # -> 3 2 4
t4_standard = t4_D * t4_D * t4_C * t4_Cout  # -> 72
print("standard multiplies:", t4_standard)  # -> 72
t4_depthwise = t4_D * t4_D * t4_C  # -> 18
print("depthwise multiplies:", t4_depthwise)  # -> 18
t4_pointwise = t4_C * t4_Cout  # -> 8
print("pointwise multiplies:", t4_pointwise)  # -> 8
t4_separable = t4_depthwise + t4_pointwise  # -> 26
print("separable multiplies:", t4_separable)  # -> 26
t4_saved = t4_standard - t4_separable  # -> 46
print("saved multiplies:", t4_saved)  # -> 46
t4_ratio = t4_separable / t4_standard  # -> 0.3611111111111111
print("separable / standard:", round(float(t4_ratio), 4))  # -> 0.3611
assert t4_standard == 72
assert t4_separable == 26

plt.figure(figsize=(4.6, 2.8))
plt.bar(["standard", "depthwise", "pointwise", "separable"], [t4_standard, t4_depthwise, t4_pointwise, t4_separable], color=["#e45756", "#4c78a8", "#f58518", "#54a24b"])
plt.title("Toy 4 · separable cost is an addition")
plt.ylabel("multiplies per output pixel")
plt.show()
```
▶ What you'll see: `18 + 8 = 26` separable multiplies replace `72` standard multiplies.

### ✍️ Toy 5 · Separable kernels reuse scaled spatial patterns

For one input channel, separable convolution can only make output-channel kernels that are scaled copies of the same depthwise spatial filter.

```python
import numpy as np

t5_rng = np.random.default_rng(0)  # seeded for reproducibility.
t5_depth_filter = np.array([[1.0, 2.0], [0.0, 1.0]])  # one depthwise spatial pattern.
t5_point_weights = np.array([2.0, -1.0])  # two pointwise scalars for two outputs.
print("depthwise filter:\n", t5_depth_filter)  # -> [[1. 2.] [0. 1.]]
print("pointwise weights:", t5_point_weights.tolist())  # -> [2.0, -1.0]
t5_sep_kernels = t5_depth_filter[:, :, None] * t5_point_weights[None, None, :]  # -> [[[2.0, -1.0], [4.0, -2.0]], [[0.0, -0.0], [2.0, -1.0]]]
print("separable output-0 kernel:\n", t5_sep_kernels[:, :, 0])  # -> [[2. 4.] [0. 2.]]
print("separable output-1 kernel:\n", t5_sep_kernels[:, :, 1])  # -> [[-1. -2.] [-0. -1.]]
t5_recovered0 = t5_sep_kernels[:, :, 0] / t5_point_weights[0]  # -> [[1.0, 2.0], [0.0, 1.0]]
print("scaled back output 0:\n", t5_recovered0)  # -> [[1. 2.] [0. 1.]]
t5_std_a = np.array([[1.0, 0.0], [0.0, 1.0]])  # one arbitrary standard kernel.
t5_std_b = np.array([[0.0, 1.0], [1.0, 0.0]])  # another arbitrary standard kernel.
t5_best_scale = float((t5_std_a * t5_std_b).sum() / (t5_std_a * t5_std_a).sum())  # -> 0.0
print("best scalar from std A to std B:", t5_best_scale)  # -> 0.0
t5_l1_error = float(np.abs(t5_best_scale * t5_std_a - t5_std_b).sum())  # -> 2.0
print("standard-kernel scaled-copy error:", t5_l1_error)  # -> 2.0
assert np.allclose(t5_recovered0, t5_depth_filter)
assert t5_l1_error > 0.0

fig, ax = plt.subplots(1, 3, figsize=(6.8, 2.3))
ax[0].imshow(t5_depth_filter, cmap="coolwarm")
ax[0].set_title("shared pattern")
ax[1].imshow(t5_sep_kernels[:, :, 0], cmap="coolwarm")
ax[1].set_title("× 2")
ax[2].imshow(t5_sep_kernels[:, :, 1], cmap="coolwarm")
ax[2].set_title("× -1")
for t5_a in ax:
    t5_a.set_xticks([])
    t5_a.set_yticks([])
plt.suptitle("Toy 5 · separable kernels are scaled copies")
plt.show()
```
▶ What you'll see: the two separable kernels have the same spatial pattern up to scale, unlike arbitrary standard kernels.

### ✍️ Toy 6 · Width and intermediate memory change the efficiency story

The separable/standard ratio falls as output channels grow, but the depthwise result still exists as an intermediate tensor.

```python
import numpy as np

t6_rng = np.random.default_rng(0)  # seeded for reproducibility.
```

## 🛠️ Setup

```python
import numpy as np # load NumPy for tensors, convolution loops, shape arithmetic, and numerical checks.
import matplotlib.pyplot as plt # load Matplotlib so feature maps, filters, and cost curves can be inspected visually.
np.random.seed(0) # make every random example reproducible across notebook runs.

def conv2d_valid_single(X, K): # apply one 2-D valid convolution/correlation kernel to one 2-D array.
    H, W = X.shape # read the input height and width.
    D = K.shape[0] # read the square kernel size.
    Y = np.zeros((H - D + 1, W - D + 1)) # allocate the valid-output grid.
    for i in range(Y.shape[0]): # slide over output rows.
        for j in range(Y.shape[1]): # slide over output columns.
            Y[i, j] = np.sum(X[i:i + D, j:j + D] * K) # multiply the local patch by the kernel and sum.
    return Y # return one filtered feature map.

def depthwise_valid(X, K): # apply one spatial filter per input channel.
    H, W, C = X.shape # read the feature-tensor shape.
    D = K.shape[0] # read the kernel size.
    Y = np.zeros((H - D + 1, W - D + 1, C)) # preserve channels after spatial filtering.
    for c in range(C): # process channels independently.
        Y[:, :, c] = conv2d_valid_single(X[:, :, c], K[:, :, c]) # filter channel c with filter c.
    return Y # return depthwise spatial responses.

def pointwise_mix(X, W): # apply a 1x1 channel-mixing matrix at every spatial location.
    return X @ W # NumPy broadcasts matrix multiplication over the HxW locations.

def standard_valid(X, K): # apply a standard valid convolution with kernel shape D x D x C x C_out.
    H, W, C = X.shape # read input shape.
    D, _, _, C_out = K.shape # read kernel and output-channel sizes.
    Y = np.zeros((H - D + 1, W - D + 1, C_out)) # allocate output tensor.
    for i in range(Y.shape[0]): # slide over rows.
        for j in range(Y.shape[1]): # slide over columns.
            patch = X[i:i + D, j:j + D, :] # collect the local spatial patch across all channels.
            for o in range(C_out): # compute every output channel.
                Y[i, j, o] = np.sum(patch * K[:, :, :, o]) # mix space and channels in one sum.
    return Y # return the standard-convolution output.

def cost_counts(D, C, C_out, H=1, W=1): # compute standard and separable multiplication counts.
    std = H * W * D * D * C * C_out # standard convolution cost.
    sep = H * W * (D * D * C + C * C_out) # depthwise plus pointwise cost.
    return std, sep # return both counts for comparison.
```

**Goal.** Compute the per-pixel cost of a standard convolution, because the efficient block only makes sense after we know what it replaces. We build it in 2 steps.
