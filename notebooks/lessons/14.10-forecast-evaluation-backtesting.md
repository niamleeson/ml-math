# 14.10 — Forecast Evaluation & Backtesting

Forecast evaluation asks whether a model would have helped when decisions were actually made. In this lesson, you will build forecast metrics, chronological backtests, and interval checks from scratch with NumPy, so every score is tied to the real information available at prediction time.

### 1. Forecast errors and point metrics

A point forecast gives one number \(\hat y_t\) for each future actual \(y_t\). The raw ingredient behind most accuracy scores is the error \(e_t=y_t-\hat y_t\). MAE averages \(|e_t|\), RMSE squares first and then square-roots, MAPE divides by the actual value, and sMAPE divides by the average magnitude of actual and forecast. Each formula answers a different cost question.

```python
y_w = np.array([10., 12., 15.])  # actual outcomes.
yhat_w = np.array([11., 13., 14.])  # point forecasts made earlier.
err_w = y_w - yhat_w  # signed errors: positive means under-forecast.
print("errors:", err_w)  # inspect direction and size.
print("absolute errors:", np.abs(err_w))  # metric input after direction is removed.
```
▶ What you'll see: all misses have absolute size 1, although the last error has the opposite sign.

```python
mae_w = float(np.mean(np.abs(err_w)))  # average absolute miss.
rmse_w = float(np.sqrt(np.mean(err_w ** 2)))  # square, average, then square-root.
mape_w = float(100 * np.mean(np.abs(err_w / y_w)))  # percent miss relative to actual.
smape_w = float(100 * np.mean(2 * np.abs(err_w) / (np.abs(y_w) + np.abs(yhat_w))))  # symmetric percent miss.
print("MAE:", round(mae_w, 3), "RMSE:", round(rmse_w, 3))  # compare unit-scale metrics.
print("MAPE:", round(mape_w, 3), "sMAPE:", round(smape_w, 3))  # compare percentage metrics.
assert round(mae_w, 3) == 1.000 and round(rmse_w, 3) == 1.000 and round(mape_w, 3) == 8.333
```
▶ What you'll see: MAE and RMSE agree here because every absolute error is exactly 1.

```python
plt.figure(figsize=(4.6, 3))  # compact comparison plot.
plt.plot(y_w, marker="o", label="actual")  # actual path.
plt.plot(yhat_w, marker="s", label="forecast")  # forecast path.
for i_w in range(len(y_w)):  # draw one vertical error segment per time point.
    plt.plot([i_w, i_w], [y_w[i_w], yhat_w[i_w]], color="crimson", linewidth=2)  # error magnitude.
plt.title("1: actuals, forecasts, and errors"); plt.legend(); plt.show()
```
▶ What you'll see: three vertical gaps of equal height, so MAE and RMSE both report one unit.

*Why it's done this way:* MAE uses absolute value because positive and negative misses should not cancel. RMSE squares before averaging, so a miss of 4 counts sixteen times as much as a miss of 1 before the final square root returns to original units. MAPE and sMAPE normalize by scale, but their denominators are part of the modeling assumption: MAPE asks “percent of actual,” while sMAPE softens asymmetry by using both actual and forecast magnitudes.

### 2. Scaled errors with MASE

A raw MAE of 5 may be excellent for a series around 10,000 and terrible for a series around 8. MASE solves that comparison problem by dividing the model MAE by an in-sample naive forecast MAE. The denominator is the average one-step change in the training history, so MASE below 1 means the model beat a naive “last value” forecast scale.

```python
train_w = np.array([8., 10., 12., 15.])  # training history available before evaluation.
naive_errors_w = np.abs(train_w[1:] - train_w[:-1])  # one-step naive misses inside training.
scale_w = float(np.mean(naive_errors_w))  # MASE denominator.
print("naive absolute differences:", naive_errors_w)  # [2, 2, 3].
print("naive scale:", round(scale_w, 6))  # 2.333333.
assert round(scale_w, 6) == 2.333333
```
▶ What you'll see: the series usually moves about 2.33 units from one step to the next.

```python
mase_w = mae_w / scale_w  # model MAE divided by naive in-sample scale.
print("MASE:", round(mase_w, 6))  # 1 / 2.333333 = 0.428571.
assert round(mase_w, 6) == 0.428571
```
▶ What you'll see: MASE is below 1, so this toy forecast beats the naive movement scale.

```python
plt.figure(figsize=(4.6, 3))
plt.bar(["model MAE", "naive scale"], [mae_w, scale_w], color=["seagreen", "gray"])
plt.title(f"2: MASE = {mase_w:.3f}"); plt.ylabel("absolute error units"); plt.show()
```
▶ What you'll see: the model error bar is less than half the naive-scale bar.

*Why it's done this way:* MASE keeps the numerator in real error units but normalizes by a simple benchmark computed only from training data. That makes scores comparable across series and avoids MAPE's near-zero explosion. The naive denominator is not magic; it is the cost of a minimal forecast that says “tomorrow equals today,” so the ratio has the concrete interpretation of beating or losing to that baseline.

### 3. Chronological splits and rolling-origin backtesting

Forecast validation must respect time. A random split can train on future regimes and test on the past, which is impossible in deployment. Rolling-origin backtesting replays history: train on data up to an origin, forecast the next horizon, record errors, then move the origin forward.

```python
t_w = np.arange(24)  # monthly index.
series_w = 20 + 0.5 * t_w + 3 * np.sin(2 * np.pi * t_w / 12) + np.random.normal(0, 0.4, size=t_w.size)  # trend + seasonality + noise.
print("first five values:", np.round(series_w[:5], 2))  # inspect the synthetic series.
print("last five values:", np.round(series_w[-5:], 2))  # later values are higher because of trend.
```
▶ What you'll see: a small upward-trending seasonal series, not independent shuffled rows.

```python
def trend_forecast_w(history, horizon):  # fit a line to history and extrapolate h steps.
    x = np.arange(len(history))  # time positions seen so far.
    slope, intercept = np.polyfit(x, history, 1)  # ordinary least-squares line via NumPy.
    future_x = np.arange(len(history), len(history) + horizon)  # future time positions.
    return intercept + slope * future_x  # extrapolated forecasts.

origins_w = np.array([12, 15, 18])  # first forecast starts after 12 months.
horizon_w = 3  # forecast three months ahead at each origin.
print("origins:", origins_w, "horizon:", horizon_w)  # inspect backtest design.
```
▶ What you'll see: three chronological folds, each forecasting the next three points.

```python
fold_preds_w, fold_actuals_w = [], []  # collect all fold predictions and truths.
for origin_w in origins_w:  # replay history at each origin.
    pred_w = trend_forecast_w(series_w[:origin_w], horizon_w)  # train only on the past.
    actual_w = series_w[origin_w:origin_w + horizon_w]  # next horizon as validation.
    fold_preds_w.append(pred_w); fold_actuals_w.append(actual_w)  # save fold.
    print(f"origin {origin_w}: pred", np.round(pred_w, 2), "actual", np.round(actual_w, 2))  # inspect fold.
```
▶ What you'll see: each fold uses a longer training prefix and evaluates only the future window.

```python
plt.figure(figsize=(6, 3.2))
plt.plot(series_w, marker="o", color="black", label="actual series")
for origin_w in origins_w:
    plt.axvspan(0, origin_w - 1, color="seagreen", alpha=0.06)  # training prefix.
    plt.axvspan(origin_w, origin_w + horizon_w - 1, color="orange", alpha=0.14)  # validation horizon.
plt.title("3: rolling-origin backtest windows"); plt.xlabel("time"); plt.legend(); plt.show()
```
▶ What you'll see: green prefixes grow over time, while orange validation windows always sit to the right of their training data.

*Why it's done this way:* A forecast is a procedure, not just a formula. Rolling-origin evaluation scores the exact procedure that would have been possible at each historical decision date. Expanding windows are useful when older data remains relevant; rolling fixed-width windows are useful when only recent history should matter. In both cases, the origin is the wall that future data may not cross.

### 4. Horizon-aware error summaries

A one-step forecast and a three-step forecast answer different questions because uncertainty compounds as the horizon grows. Backtests should therefore keep the horizon dimension visible instead of flattening everything too early. We can still aggregate, but first we inspect errors by lead time.

```python
preds_w = np.vstack(fold_preds_w)  # rows = folds, columns = horizons.
actuals_w = np.vstack(fold_actuals_w)  # matching actual matrix.
errors_w = actuals_w - preds_w  # signed fold-by-horizon errors.
print("error matrix:\n", np.round(errors_w, 2))  # inspect every fold and lead time.
print("shape:", errors_w.shape)  # 3 folds x 3 horizons.
```
▶ What you'll see: a small matrix where each column is a different forecast lead time.

```python
mae_by_h_w = np.mean(np.abs(errors_w), axis=0)  # MAE separately for h=1,2,3.
rmse_by_h_w = np.sqrt(np.mean(errors_w ** 2, axis=0))  # RMSE separately for h=1,2,3.
print("MAE by horizon:", np.round(mae_by_h_w, 3))  # inspect lead-time errors.
print("RMSE by horizon:", np.round(rmse_by_h_w, 3))  # large misses matter more.
assert mae_by_h_w.shape == (3,) and rmse_by_h_w.shape == (3,)
```
▶ What you'll see: separate scores for one-, two-, and three-step-ahead forecasts.

```python
plt.figure(figsize=(5, 3))
plt.plot([1, 2, 3], mae_by_h_w, marker="o", label="MAE")
plt.plot([1, 2, 3], rmse_by_h_w, marker="s", label="RMSE")
plt.xticks([1, 2, 3]); plt.xlabel("forecast horizon"); plt.ylabel("error")
plt.title("4: error can change with horizon"); plt.legend(); plt.show()
```
▶ What you'll see: the curve shows whether errors grow, shrink, or change shape across lead times.

*Why it's done this way:* Flattening all horizons into one score hides which decision is failing. Inventory planning, staffing, and capacity decisions often care about a particular lead time. Computing metrics by horizon preserves that geometry; only after reading it should you average into a single headline score.

### 5. Prediction intervals and coverage

Point accuracy is not enough when the decision depends on risk. A prediction interval says “the future should land between this lower and upper bound about X% of the time.” Coverage is the fraction of actuals that fall inside the intervals. A calibrated 80% interval should cover about 80% in repeated use, while still being as narrow as possible.

```python
center_w = preds_w  # use the backtest point forecasts as interval centers.
resid_scale_w = float(np.std(errors_w.ravel(), ddof=1))  # empirical residual spread from the backtest.
width_w = 1.28 * resid_scale_w  # approximate central 80% width under a normal residual story.
lower_w = center_w - width_w  # lower interval bound.
upper_w = center_w + width_w  # upper interval bound.
print("residual scale:", round(resid_scale_w, 3), "interval half-width:", round(width_w, 3))  # inspect interval size.
```
▶ What you'll see: one residual-based half-width used around every backtest forecast.

```python
covered_w = (actuals_w >= lower_w) & (actuals_w <= upper_w)  # interval hit indicator.
coverage_w = float(np.mean(covered_w))  # empirical coverage across all fold-horizon points.
avg_width_w = float(np.mean(upper_w - lower_w))  # sharpness summary.
print("covered matrix:\n", covered_w.astype(int))  # 1 means actual landed inside the interval.
print("coverage:", round(coverage_w, 3), "average width:", round(avg_width_w, 3))  # calibration and sharpness.
assert 0.0 <= coverage_w <= 1.0 and avg_width_w > 0
```
▶ What you'll see: a hit/miss matrix and one coverage number between 0 and 1.

```python
flat_t_w = []  # x positions for validation points.
flat_y_w = []  # actuals.
flat_lo_w = []  # lower intervals.
flat_hi_w = []  # upper intervals.
for row_w, origin_w in enumerate(origins_w):
    for h_w in range(horizon_w):
        flat_t_w.append(origin_w + h_w); flat_y_w.append(actuals_w[row_w, h_w]); flat_lo_w.append(lower_w[row_w, h_w]); flat_hi_w.append(upper_w[row_w, h_w])
plt.figure(figsize=(6, 3.2))
plt.plot(series_w, color="lightgray", label="series")
flat_center_w = (np.array(flat_lo_w) + np.array(flat_hi_w)) / 2  # interval centers for nonnegative error bars.
flat_half_w = (np.array(flat_hi_w) - np.array(flat_lo_w)) / 2  # interval half-widths.
plt.errorbar(flat_t_w, flat_center_w, yerr=flat_half_w, fmt="o", color="purple", capsize=3, label="80% intervals")
plt.scatter(flat_t_w, flat_y_w, color="black", s=18, label="actuals")  # actuals outside bars are misses.
plt.title("5: interval coverage on backtest points"); plt.xlabel("time"); plt.legend(); plt.show()
```
▶ What you'll see: actual validation points with vertical interval bars; misses sit outside their bars.

*Why it's done this way:* Coverage checks the truthfulness of uncertainty statements, not just their attractiveness. A model can get perfect coverage with absurdly wide intervals, so coverage must be read with width or sharpness. The statistical reason for the hit indicator is simple: each interval claim is a Bernoulli event (covered or not), and the empirical mean estimates the long-run frequency of honest uncertainty.

## 🟢 Basics (warm-up)

### Basic 1 — Compute signed forecast errors

**Goal.** Start from actuals and forecasts and compute signed errors, because every accuracy metric is built from \(y_t-\hat y_t\). We build it in 2 steps.

```python
y_b1 = np.array([10., 12., 15.]) # store three actual outcomes.
yhat_b1 = np.array([11., 13., 14.]) # store the three forecasts made before observing them.
err_b1 = y_b1 - yhat_b1 # compute signed error: actual minus forecast.
print("errors:", err_b1) # inspect under- and over-forecast direction.
```
▶ What you'll see: the first two forecasts are high by 1, and the last forecast is low by 1.

```python
plt.figure(figsize=(4, 3)) # create a compact diagnostic plot.
plt.axhline(0, color="black", linewidth=0.8) # zero error reference line.
plt.bar(np.arange(len(err_b1)), err_b1, color=["crimson" if e < 0 else "seagreen" for e in err_b1]) # show signed errors.
plt.title("Basic 1: signed errors") # title the error plot.
plt.xlabel("time index") # label time positions.
plt.ylabel("y - forecast") # label signed error units.
plt.show() # display the bar chart.
```
▶ What you'll see: bars below zero are over-forecasts and bars above zero are under-forecasts.

👀 Takeaway: signed errors preserve direction, but most headline metrics transform them so opposite signs cannot cancel.

### Basic 2 — Compute MAE

**Goal.** Average absolute errors, because MAE measures the typical miss in the same units as the series. We build it in 2 steps.

```python
y_b2 = np.array([10., 12., 15.]) # actual values.
yhat_b2 = np.array([11., 13., 14.]) # forecast values.
abs_err_b2 = np.abs(y_b2 - yhat_b2) # remove error direction before averaging.
print("absolute errors:", abs_err_b2) # inspect the metric ingredients.
```
▶ What you'll see: every miss has size 1.

```python
mae_b2 = float(np.mean(abs_err_b2)) # compute mean absolute error.
print("MAE:", round(mae_b2, 3)) # inspect the typical absolute miss.
assert round(mae_b2, 3) == 1.000 # verify the worked number.
plt.figure(figsize=(4, 3)) # create a compact MAE plot.
plt.bar(["e0", "e1", "e2", "MAE"], list(abs_err_b2) + [mae_b2], color=["gray", "gray", "gray", "seagreen"]) # compare individual misses to their average.
plt.title("Basic 2: MAE averages |error|") # title the plot.
plt.ylabel("absolute error") # label units.
plt.show() # display the bar chart.
```
▶ What you'll see: the MAE bar equals each individual miss in this toy example.

👀 Takeaway: MAE is easy to explain because it is the average distance between forecast and actual.

### Basic 3 — Compute RMSE

**Goal.** Square errors before averaging, because RMSE penalizes rare large misses more strongly than MAE. We build it in 3 steps.

```python
y_b3 = np.array([10., 12., 15., 30.]) # actuals with one larger value.
yhat_b3 = np.array([11., 13., 14., 24.]) # forecasts with one large miss.
err_b3 = y_b3 - yhat_b3 # compute signed errors.
print("errors:", err_b3) # inspect the residual pattern.
```
▶ What you'll see: three one-unit misses and one six-unit miss.

```python
sq_b3 = err_b3 ** 2 # square each error so large misses grow quadratically.
rmse_b3 = float(np.sqrt(np.mean(sq_b3))) # average squared errors and return to original units.
print("squared errors:", sq_b3) # inspect the quadratic penalty.
print("RMSE:", round(rmse_b3, 3)) # inspect the final score.
assert round(rmse_b3, 3) == 3.122 # verify sqrt((1+1+1+36)/4).
```
▶ What you'll see: the printed values or plot expose the intermediate calculation before the next step.


```python
plt.figure(figsize=(4, 3)) # create a compact penalty comparison.
plt.bar(["|e| small", "|e| large", "e² small", "e² large"], [1, 6, 1, 36], color=["gray", "gray", "orange", "orange"]) # show linear vs squared growth.
plt.xticks(rotation=20) # keep labels readable.
plt.title("Basic 3: squaring amplifies large misses") # title the plot.
plt.show() # display the chart.
```
▶ What you'll see: the six-unit miss becomes a 36-unit squared penalty.

👀 Takeaway: RMSE is useful when occasional large forecast errors are disproportionately costly.

### Basic 4 — Compute MAPE safely

**Goal.** Express errors as percentages of actuals, because some decisions care about relative error rather than raw units. We build it in 3 steps.

```python
y_b4 = np.array([10., 12., 15.]) # actual values away from zero.
yhat_b4 = np.array([11., 13., 14.]) # forecasts.
den_b4 = np.where(y_b4 == 0, np.nan, y_b4) # avoid dividing by zero actuals.
percent_b4 = 100 * np.abs((y_b4 - yhat_b4) / den_b4) # absolute percentage errors.
print("absolute percentage errors:", np.round(percent_b4, 3)) # inspect each percent miss.
```
▶ What you'll see: percentage errors are largest when the same one-unit miss happens on the smallest actual.

```python
mape_b4 = float(np.nanmean(percent_b4)) # average percentages while ignoring undefined zero-actual cases.
print("MAPE:", round(mape_b4, 3)) # inspect the percentage score.
assert round(mape_b4, 3) == 8.333 # verify the canonical tiny-forecast number.
```
▶ What you'll see: the printed values or plot expose the intermediate calculation before the next step.


```python
plt.figure(figsize=(4, 3)) # create a compact percent-error plot.
plt.bar(["t0", "t1", "t2"], percent_b4, color="royalblue") # show percentage misses.
plt.title("Basic 4: MAPE components") # title the plot.
plt.ylabel("absolute percentage error") # label percent scale.
plt.show() # display the bar chart.
```
▶ What you'll see: equal unit errors produce unequal percentage errors because the denominators differ.

👀 Takeaway: MAPE is scale-free, but actuals near zero can make it undefined or explosively large.

### Basic 5 — Compute sMAPE

**Goal.** Normalize by the average magnitude of actual and forecast, because sMAPE reduces some asymmetry of plain MAPE. We build it in 2 steps.

```python
y_b5 = np.array([10., 12., 15.]) # actual values.
yhat_b5 = np.array([11., 13., 14.]) # forecasts.
den_b5 = np.abs(y_b5) + np.abs(yhat_b5) # combined magnitude denominator.
smape_terms_b5 = np.where(den_b5 == 0, 0.0, 200 * np.abs(y_b5 - yhat_b5) / den_b5) # symmetric percentage terms.
print("sMAPE terms:", np.round(smape_terms_b5, 3)) # inspect each term.
```
▶ What you'll see: sMAPE terms are close to, but not identical to, MAPE terms.

```python
smape_b5 = float(np.mean(smape_terms_b5)) # average symmetric percent errors.
print("sMAPE:", round(smape_b5, 3)) # inspect the score.
assert round(smape_b5, 3) == 8.140 # verify the worked number.
plt.figure(figsize=(4, 3)) # create a compact plot.
plt.bar(["t0", "t1", "t2"], smape_terms_b5, color="darkorange") # show sMAPE components.
plt.title("Basic 5: sMAPE components") # title the plot.
plt.ylabel("symmetric percent error") # label percent scale.
plt.show() # display the bar chart.
```
▶ What you'll see: each term uses both the actual and forecast magnitude in its denominator.

👀 Takeaway: sMAPE is still a percentage metric, but its denominator encodes a different notion of relative error.

### Basic 6 — Compute a naive forecast

**Goal.** Predict each value as the previous observed value, because naive forecasts are the baseline behind MASE and many sanity checks. We build it in 2 steps.

```python
series_b6 = np.array([8., 10., 12., 15., 16.]) # tiny chronological series.
naive_pred_b6 = series_b6[:-1] # predict next value with the previous value.
actual_b6 = series_b6[1:] # values being predicted.
print("naive predictions:", naive_pred_b6) # inspect last-value forecasts.
print("actual next values:", actual_b6) # inspect their targets.
```
▶ What you'll see: every forecast is just the value one step earlier.

```python
naive_err_b6 = actual_b6 - naive_pred_b6 # one-step naive errors.
print("naive errors:", naive_err_b6) # inspect changes in the series.
plt.figure(figsize=(4, 3)) # create a compact line plot.
plt.plot(series_b6, marker="o", label="series") # plot original series.
plt.plot(np.arange(1, len(series_b6)), naive_pred_b6, marker="s", label="naive forecast") # align naive forecasts with predicted times.
plt.title("Basic 6: last-value naive forecast") # title the plot.
plt.legend(); plt.show() # display with legend.
```
▶ What you'll see: the naive forecast lags the series by one time step.

👀 Takeaway: a naive forecast is simple, chronological, and often surprisingly hard to beat.

### Basic 7 — Compute the MASE denominator

**Goal.** Average in-sample naive absolute errors, because MASE needs a scale computed from training history only. We build it in 2 steps.

```python
train_b7 = np.array([8., 10., 12., 15.]) # training history.
naive_abs_b7 = np.abs(train_b7[1:] - train_b7[:-1]) # absolute one-step changes.
print("naive absolute errors:", naive_abs_b7) # inspect denominator components.
```
▶ What you'll see: the training series changed by 2, 2, then 3 units.

```python
scale_b7 = float(np.mean(naive_abs_b7)) # average naive absolute error.
print("MASE scale:", round(scale_b7, 6)) # inspect denominator.
assert round(scale_b7, 6) == 2.333333 # verify the lesson denominator.
plt.figure(figsize=(4, 3)) # create a denominator plot.
plt.bar(["Δ1", "Δ2", "Δ3", "mean"], list(naive_abs_b7) + [scale_b7], color=["gray", "gray", "gray", "purple"]) # compare changes and average.
plt.title("Basic 7: MASE denominator") # title the chart.
plt.show() # display the bar chart.
```
▶ What you'll see: the denominator is the average size of historical one-step movement.

👀 Takeaway: MASE compares model error to the series' own naive movement scale.

### Basic 8 — Compute MASE

**Goal.** Divide model MAE by the naive scale, because scaled errors are comparable across series magnitudes. We build it in 2 steps.

```python
mae_b8 = 1.0 # model MAE from the tiny forecast.
scale_b8 = (2 + 2 + 3) / 3 # naive in-sample scale from the training history.
mase_b8 = mae_b8 / scale_b8 # scaled absolute error.
print("MAE:", mae_b8, "scale:", round(scale_b8, 6)) # inspect numerator and denominator.
```
▶ What you'll see: the model's one-unit MAE is smaller than the naive scale.

```python
print("MASE:", round(mase_b8, 6)) # inspect the scaled metric.
assert round(mase_b8, 6) == 0.428571 # verify canonical MASE.
plt.figure(figsize=(4, 3)) # create a compact interpretation plot.
plt.axhline(1, color="black", linestyle="--", label="naive parity") # MASE=1 reference.
plt.bar(["model"], [mase_b8], color="seagreen") # plot model MASE.
plt.ylim(0, 1.2); plt.title("Basic 8: MASE below 1 beats naive"); plt.legend(); plt.show()
```
▶ What you'll see: the model bar is below the dashed MASE=1 baseline.

👀 Takeaway: MASE below 1 means the model's average miss is smaller than the naive benchmark's scale.

### Basic 9 — Make one chronological train-test split

**Goal.** Split a series into past training data and future test data, because forecasts must not train on observations after the decision date. We build it in 2 steps.

```python
series_b9 = np.arange(10, 22, dtype=float) # simple increasing series.
cut_b9 = 8 # first eight points are available for training.
train_b9 = series_b9[:cut_b9] # past data.
test_b9 = series_b9[cut_b9:] # future data.
print("train:", train_b9) # inspect training prefix.
print("test:", test_b9) # inspect future holdout.
```
▶ What you'll see: the test values come strictly after every training value.

    avg_width_a4.append(float(np.mean(hi_a4 - lo_a4))) # average width.

def asym_loss_a5(y, yhat, under_cost=3.0, over_cost=1.0): # define piecewise linear business loss.
    err_a5 = y - yhat # positive means under-forecast.
    return np.where(err_a5 > 0, under_cost * err_a5, over_cost * np.abs(err_a5)) # under misses cost more.
