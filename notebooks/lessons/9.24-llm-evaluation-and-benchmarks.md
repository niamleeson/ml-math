# 9.24 — LLM Evaluation & Benchmarks

LLM evaluation turns fuzzy model behavior into measurable quantities with uncertainty, sampling rules, contamination checks, preference comparisons, and deployment costs. In this lesson, every metric is built from tiny NumPy arrays so the benchmark is not a magic leaderboard number: it is a set of assumptions about what counts as success, how noisy the estimate is, and which failure modes the score can or cannot see.

Before the terse worked examples, we build LLM evaluation one idea at a time. Run each cell in order and read the printed intermediate values — every piece of math is shown so benchmark scores feel like auditable arithmetic rather than scoreboard folklore. This walkthrough is self-contained and uses a `_w` suffix on its variables so it never clashes with the examples below.

import numpy as np  # arrays, simulation, bootstrap resampling, and small numerical checks.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
from collections import Counter  # small counting helper for labels and error types.
np.random.seed(0)  # reproducibility for resampling and toy sampling experiments.

### 1. Benchmark accuracy and a normal confidence interval

A benchmark starts as a list of tasks with binary outcomes: `1` if the model solved the task under the stated grading rule and `0` otherwise. The headline accuracy is the sample mean $\hat p = \frac{1}{n}\sum_i y_i$. Because the tasks are only a sample from a larger universe, we attach a 95% normal confidence interval $\hat p \pm 1.96\sqrt{\hat p(1-\hat p)/n}$. The square-root term is the standard error of a Bernoulli mean: it shrinks like $1/\sqrt n$ and is largest when the outcome is most uncertain.

```python
correct_w = np.array([1] * 72 + [0] * 28)  # 72 solved tasks and 28 failed tasks.
n_w = correct_w.size  # total benchmark size.
p_hat_w = float(correct_w.mean())  # empirical success probability.
print("n:", n_w, "correct:", int(correct_w.sum()), "accuracy:", round(p_hat_w, 3))
assert n_w == 100 and round(p_hat_w, 3) == 0.720
```
▶ What you'll see: 72 successes out of 100 tasks, giving accuracy 0.720.

```python
se_w = np.sqrt(p_hat_w * (1 - p_hat_w) / n_w)  # Bernoulli standard error.
half_w = 1.96 * se_w  # normal 95% half-width.
ci_w = (p_hat_w - half_w, p_hat_w + half_w)  # lower and upper endpoints.
print("standard error:", round(se_w, 4), "half-width:", round(half_w, 3))
print("95% CI:", np.round(ci_w, 3))
assert round(half_w, 3) == 0.088
```
▶ What you'll see: the 95% interval is roughly 0.632 to 0.808, so small leaderboard gaps may be noise.

```python
sizes_w = np.array([25, 100, 400, 1600])  # benchmark sizes to compare.
halves_w = 1.96 * np.sqrt(p_hat_w * (1 - p_hat_w) / sizes_w)  # CI half-width at same accuracy.
plt.figure(figsize=(4.5, 3))
plt.plot(sizes_w, halves_w, marker="o", color="teal")
plt.xscale("log")
plt.title("1: confidence intervals shrink like 1/sqrt(n)")
plt.xlabel("number of tasks")
plt.ylabel("95% CI half-width")
plt.show()
```
▶ What you'll see: quadrupling the task count roughly halves the uncertainty band.

*Why it's done this way:* accuracy is a sample mean, so its noise is governed by binomial variance $p(1-p)/n$. The normal interval is not magic; it says that if many equally-sized benchmark samples were drawn, about 95% of their sample means would land within about 1.96 standard errors of the true success rate.

### 2. Bootstrap confidence intervals when formulas are awkward

The normal interval assumes a simple independent Bernoulli score. Many LLM metrics are messier: tasks have weights, categories, or non-binary scores. A bootstrap confidence interval estimates uncertainty by resampling the benchmark tasks with replacement, recomputing the metric many times, and reading off quantiles. It keeps the benchmark's empirical mix of easy and hard tasks while asking, "how much would the score move if this task set had been slightly different?"

```python
scores_w = np.array([1.0] * 45 + [0.5] * 20 + [0.0] * 35)  # partial-credit toy rubric.
mean_score_w = float(scores_w.mean())  # benchmark mean under the rubric.
print("mean partial-credit score:", round(mean_score_w, 3))
assert round(mean_score_w, 3) == 0.550
```
▶ What you'll see: partial credit gives a score of 0.550, not just pass/fail accuracy.

```python
B_w = 1000  # number of bootstrap resamples.
boot_means_w = []  # store one recomputed score per resample.
for _ in range(B_w):
    idx_w = np.random.randint(0, scores_w.size, size=scores_w.size)  # sample task indices with replacement.
    boot_means_w.append(float(scores_w[idx_w].mean()))  # recompute the metric on the resampled benchmark.
boot_means_w = np.array(boot_means_w)
boot_ci_w = np.percentile(boot_means_w, [2.5, 97.5])  # percentile bootstrap interval.
print("bootstrap CI:", np.round(boot_ci_w, 3))
assert boot_means_w.shape == (1000,)
```
▶ What you'll see: a plausible interval for the partial-credit mean, computed without a closed-form variance formula.

```python
plt.figure(figsize=(4.6, 3))
plt.hist(boot_means_w, bins=25, color="slateblue", edgecolor="white")
plt.axvline(mean_score_w, color="black", linestyle="--", label="observed mean")
plt.axvline(boot_ci_w[0], color="crimson", linestyle=":", label="95% endpoints")
plt.axvline(boot_ci_w[1], color="crimson", linestyle=":")
plt.title("2: bootstrap distribution of benchmark means")
plt.xlabel("resampled mean score")
plt.ylabel("count")
plt.legend()
plt.show()
```
▶ What you'll see: the histogram is the empirical sampling distribution; the red lines mark its middle 95%.

*Why it's done this way:* bootstrapping treats the observed task set as a stand-in for the population and measures how unstable the metric is under task resampling. It is useful when the score is still an average over tasks but the per-task values are not simple Bernoulli outcomes.

### 3. pass@k for sampled coding or reasoning outputs

Some LLM tasks allow multiple attempts. If a model generates $n$ candidates and $c$ pass the unit tests, pass@$k$ estimates the probability that at least one passing answer appears among $k$ sampled candidates. Under sampling without replacement from the observed candidate set, the failure event is "all $k$ chosen candidates are from the $n-c$ failures," so

$$\mathrm{pass@}k = 1 - \frac{\binom{n-c}{k}}{\binom{n}{k}}.$$

```python
n_w, c_w, k_w = 10, 3, 3  # 10 generated candidates, 3 passing, evaluate 3 attempts.
fails_w = n_w - c_w  # candidates that do not pass.
print("n:", n_w, "c:", c_w, "k:", k_w, "failures:", fails_w)
assert (n_w, c_w, k_w, fails_w) == (10, 3, 3, 7)
```
▶ What you'll see: the only way pass@3 fails is choosing 3 from the 7 bad candidates.

```python
def comb_small_w(n, k):  # small combination helper using products, not scipy.
    if k < 0 or k > n:
        return 0.0
    k = min(k, n - k)
    num = np.prod(np.arange(n - k + 1, n + 1)) if k > 0 else 1.0
    den = np.prod(np.arange(1, k + 1)) if k > 0 else 1.0
    return float(num / den)

pass3_w = 1 - comb_small_w(fails_w, k_w) / comb_small_w(n_w, k_w)
print("pass@3:", round(pass3_w, 3))
assert round(pass3_w, 3) == 0.708
```
▶ What you'll see: pass@3 is 0.708, much larger than single-sample accuracy 0.300 for these candidates.

```python
ks_w = np.arange(1, 8)  # possible attempt budgets.
pass_curve_w = np.array([1 - comb_small_w(n_w - c_w, kk) / comb_small_w(n_w, kk) for kk in ks_w])
plt.figure(figsize=(4.6, 3))
plt.plot(ks_w, pass_curve_w, marker="o", color="darkorange")
plt.title("3: pass@k rises with the attempt budget")
plt.xlabel("k sampled attempts")
plt.ylabel("pass@k")
plt.ylim(0, 1.05)
plt.show()
```
▶ What you'll see: more allowed samples sharply raise success probability, so pass@k must always report k.

*Why it's done this way:* pass@k measures a product policy — the model plus a sampling budget plus an oracle that can identify passing candidates. It is not comparable to one-shot accuracy unless the attempt budget, candidate count, sampling temperature, and grading rule are held fixed.

### 4. Pairwise preferences and Elo ratings

For open-ended answers, exact-match accuracy may be too crude, so evaluators compare two systems head-to-head. A pairwise win rate is just wins divided by decided comparisons, but Elo turns many pairwise outcomes into a rating scale. The expected score for model A against model B is $E_A=1/(1+10^{(R_B-R_A)/400})$; after an outcome $S_A\in\{0,0.5,1\}$, update $R_A\leftarrow R_A+K(S_A-E_A)$ and symmetrically for B.

```python
wins_w, losses_w = 30, 20  # decided pairwise judgments for A vs B.
win_rate_w = wins_w / (wins_w + losses_w)
print("pairwise win rate:", round(win_rate_w, 3))
assert round(win_rate_w, 3) == 0.600
```
▶ What you'll see: 30 wins and 20 losses give a direct preference rate of 0.600.

```python
rating_a_w, rating_b_w, K_w = 1500.0, 1500.0, 32.0  # equal starting ratings and standard toy K.
outcomes_w = np.array([1] * 3 + [0] * 2)  # the same 3-2 preference ratio, in sequence.
for s_w in outcomes_w:
    exp_a_w = 1 / (1 + 10 ** ((rating_b_w - rating_a_w) / 400))  # expected A score.
    rating_a_w += K_w * (s_w - exp_a_w)  # reward surprise wins, penalize surprise losses.
    rating_b_w += K_w * ((1 - s_w) - (1 - exp_a_w))  # symmetric zero-sum update.
print("Elo A:", round(rating_a_w, 1), "Elo B:", round(rating_b_w, 1))
assert round(rating_a_w + rating_b_w, 1) == 3000.0
```
▶ What you'll see: A ends above 1500 because it wins more often than it loses.

```python
ratings_grid_w = np.linspace(-400, 400, 81)  # A rating minus B rating.
expected_w = 1 / (1 + 10 ** (-ratings_grid_w / 400))
plt.figure(figsize=(4.6, 3))
plt.plot(ratings_grid_w, expected_w, color="seagreen")
plt.axhline(0.5, color="black", linewidth=0.8)
plt.title("4: Elo expected score curve")
plt.xlabel("rating_A - rating_B")
plt.ylabel("expected A score")
plt.show()
```
▶ What you'll see: a 0-point gap predicts a 50% score; larger gaps imply increasingly expected wins.

*Why it's done this way:* pairwise judgments reduce open-ended quality to relative choices, and Elo adds calibration: beating a strong model moves you more than beating a weak one because the update is based on surprise, not just the raw outcome.

### 5. Contamination and benchmark leakage

A benchmark only measures generalization if test items were not effectively in training. Contamination means some tasks, solutions, or near-duplicates appeared in pretraining, fine-tuning, prompt examples, or evaluation tuning. Even a small contaminated slice can inflate the headline score if those items are easier because they were memorized.

```python
task_ids_w = np.arange(100)  # 100 benchmark tasks.
contaminated_ids_w = np.array([3, 17, 42, 58, 91])  # five leaked tasks found by an audit.
contam_rate_w = contaminated_ids_w.size / task_ids_w.size
print("contaminated tasks:", contaminated_ids_w.size, "rate:", f"{100 * contam_rate_w:.1f}%")
assert round(contam_rate_w, 2) == 0.05
```
▶ What you'll see: 5 contaminated tasks in a 100-task benchmark is 5% leakage.

```python
clean_correct_w = np.array([1] * 67 + [0] * 28)  # clean subset: 67/95 correct.
leaked_correct_w = np.ones(5)  # contaminated items are all solved in this toy audit.
reported_acc_w = float(np.r_[clean_correct_w, leaked_correct_w].mean())
clean_acc_w = float(clean_correct_w.mean())
print("reported accuracy:", round(reported_acc_w, 3), "clean-only accuracy:", round(clean_acc_w, 3))
assert round(reported_acc_w, 3) == 0.720
```
▶ What you'll see: the reported 0.720 drops to about 0.705 after removing leaked tasks.

```python
labels_w = np.array(["clean"] * 95 + ["contaminated"] * 5)
counts_w = Counter(labels_w)
plt.figure(figsize=(4.4, 3))
plt.bar(list(counts_w.keys()), list(counts_w.values()), color=["steelblue", "crimson"])
plt.title("5: benchmark audit labels")
plt.ylabel("task count")
plt.show()
```
▶ What you'll see: the contaminated bar is small, but it is still enough to move a close comparison.

*Why it's done this way:* leakage changes what the evaluation means. The model may be recalling a seen item rather than solving a new one, so contamination audits protect the interpretation of the score, not merely the arithmetic.

### 6. Cost-weighted evaluation

A deployed LLM is not just correct or incorrect; it also spends latency, tokens, dollars, and human attention. A simple utility score can make this tradeoff explicit, for example $\text{utility}=\text{quality}-\alpha\cdot\text{cost}$. The exact units depend on the product, but the key idea is that missing cost from the metric makes the evaluation blind to expensive wins.

```python
quality_w = 0.80  # task success or human preference score.
cost_w = 20.0  # milliseconds, cents, or normalized token units in this toy example.
alpha_w = 0.01  # utility penalty per cost unit.
utility_w = quality_w - alpha_w * cost_w
print("utility:", round(utility_w, 3))
assert round(utility_w, 3) == 0.600
```
▶ What you'll see: quality 0.80 becomes utility 0.60 after pricing cost 20 at 0.01 each.

```python
models_w = np.array(["small", "medium", "large"])
quality_vec_w = np.array([0.70, 0.80, 0.84])
cost_vec_w = np.array([5.0, 20.0, 55.0])
utility_vec_w = quality_vec_w - alpha_w * cost_vec_w
print("utilities:", dict(zip(models_w, np.round(utility_vec_w, 3))))
assert np.argmax(utility_vec_w) == 0
```
▶ What you'll see: the highest-quality model is not necessarily the highest-utility model.

```python
x_w = np.arange(models_w.size)
plt.figure(figsize=(5, 3))
plt.bar(x_w - 0.18, quality_vec_w, width=0.36, label="quality", color="seagreen")
plt.bar(x_w + 0.18, utility_vec_w, width=0.36, label="quality - cost penalty", color="darkorange")
plt.xticks(x_w, models_w)
plt.title("6: cost can change the winner")
plt.ylabel("score")
plt.legend()
plt.show()
```
▶ What you'll see: the large model's quality bar is highest, but its utility bar falls after the cost penalty.

*Why it's done this way:* evaluation should match the deployment decision. If latency or dollars matter in production, they need to appear in the score; otherwise the benchmark optimizes a different problem than the one the system must solve.

## 🛠️ Setup

```python
import numpy as np  # load NumPy for arrays, simulation, bootstrap resampling, and metric arithmetic.
import matplotlib.pyplot as plt  # load Matplotlib for every visual check in the lesson.
from collections import Counter  # load Counter for compact counts of categories and error labels.
np.random.seed(0)  # make all random examples reproducible across runs.

def normal_ci(acc, n):  # compute a normal 95% confidence interval for a Bernoulli accuracy.
    se = np.sqrt(acc * (1 - acc) / n)  # standard error of a sample proportion.
    half = 1.96 * se  # 95% normal half-width.
    return acc - half, acc + half  # return lower and upper endpoints.

def bootstrap_mean_ci(values, B=500):  # compute a percentile bootstrap interval for a mean.
    values = np.asarray(values, dtype=float)  # make indexing and averaging predictable.
    means = []  # collect one resampled mean per bootstrap draw.
    for _ in range(B):  # repeat the resampling experiment many times.
        idx = np.random.randint(0, values.size, size=values.size)  # sample task indices with replacement.
        means.append(float(values[idx].mean()))  # recompute the benchmark mean.
    return np.percentile(means, [2.5, 97.5]), np.array(means)  # return the interval and full bootstrap distribution.

def comb_small(n, k):  # compute n choose k with simple products for small benchmark demos.
    if k < 0 or k > n:  # impossible choices have zero combinations.
        return 0.0  # return zero for invalid k.
    k = min(k, n - k)  # use the shorter side for numerical neatness.
    num = np.prod(np.arange(n - k + 1, n + 1)) if k > 0 else 1.0  # numerator product.
    den = np.prod(np.arange(1, k + 1)) if k > 0 else 1.0  # denominator product.
    return float(num / den)  # divide to get the combination count.

def pass_at_k(n, c, k):  # estimate probability that at least one of k samples passes.
    return 1 - comb_small(n - c, k) / comb_small(n, k)  # one minus the probability all k are failures.

def elo_expected(ra, rb):  # compute Elo expected score for model A against model B.
    return 1 / (1 + 10 ** ((rb - ra) / 400))  # logistic curve in base 10 with 400-point scale.

def elo_update(ra, rb, score_a, K=32):  # apply one zero-sum Elo update from A's outcome.
    ea = elo_expected(ra, rb)  # expected score before seeing the result.
    ra_new = ra + K * (score_a - ea)  # update A by surprise times K.
    rb_new = rb + K * ((1 - score_a) - (1 - ea))  # update B symmetrically.
    return ra_new, rb_new  # return updated ratings.

def show_bar(names, values, title, ylabel="score"):  # tiny plotting helper for compact metric comparisons.
    plt.figure(figsize=(4.5, 3))  # create a compact figure.
    plt.bar(names, values, color="steelblue")  # draw one bar per named metric or model.
    plt.title(title)  # label the plot.
    plt.ylabel(ylabel)  # label the numeric axis.
    plt.show()  # display the figure.
```

### Basic 1 — Count benchmark accuracy

**Goal.** Turn solved/failed task labels into an accuracy, because every benchmark headline begins as a count divided by a total. We build it in 2 steps.

```python
outcomes_b1 = np.array([1, 1, 0, 1, 0, 1, 1, 0, 1, 1], dtype=float)  # 1 means solved and 0 means failed.
print("outcomes:", outcomes_b1.astype(int))  # inspect the grading vector before averaging.
```
▶ What you'll see: ten binary task results for a toy LLM benchmark.

```python
acc_b1 = float(outcomes_b1.mean())  # average binary outcomes to get accuracy.
print("accuracy:", round(acc_b1, 3), "correct:", int(outcomes_b1.sum()), "of", outcomes_b1.size)  # inspect the headline.
assert round(acc_b1, 3) == 0.700  # verify 7/10.
show_bar(["accuracy"], [acc_b1], "Basic 1: benchmark accuracy")  # visualize the one-number score.
```
▶ What you'll see: accuracy is 0.700 because 7 of 10 tasks were solved.

👀 Takeaway: accuracy is a sample mean of binary grading decisions, not a property of the model alone.

### Basic 2 — Add a normal confidence interval

lo_b2, hi_b2 = normal_ci(acc_b2, n_b2)  # compute the normal approximation interval.

plt.figure(figsize=(4, 3))  # create one compact error-bar figure.

lower_err_b3 = accs_b3 - cis_b3[:, 0]  # distance from estimate to lower endpoint.

### Basic 4 — Compute pass@1 from sampled candidates

**Goal.** Treat one sampled answer as one attempt, because pass@1 is the single-sample success rate among generated candidates. We build it in 2 steps.

```python
candidate_pass_b4 = np.array([1, 0, 0, 1, 0, 0, 0, 1, 0, 0])  # ten candidate answers for one coding task.
c_b4 = int(candidate_pass_b4.sum())  # count candidates that pass tests.
n_b4 = candidate_pass_b4.size  # count total candidates.
print("passing candidates:", c_b4, "of", n_b4)  # inspect candidate quality.
assert c_b4 == 3 and n_b4 == 10  # verify the toy setup.
```
▶ What you'll see: 3 of 10 sampled solutions pass the tests.

```python
pass1_b4 = pass_at_k(n_b4, c_b4, 1)  # compute pass@1 from the combinatorial formula.
print("pass@1:", round(pass1_b4, 3))  # inspect single-attempt success.
assert round(pass1_b4, 3) == 0.300  # verify c/n for k=1.
show_bar(["pass@1"], [pass1_b4], "Basic 4: one sampled attempt")  # visualize the one-attempt score.
```
▶ What you'll see: pass@1 equals 0.300, the fraction of passing candidates.

👀 Takeaway: pass@1 is a candidate-level success probability for one draw.

### Basic 5 — Compute pass@3

**Goal.** Allow three attempts and compute the probability that at least one passes, because multi-sample evaluation changes the metric. We build it in 2 steps.

```python
n_b5, c_b5, k_b5 = 10, 3, 3  # ten candidates, three correct, choose three attempts.
all_choices_b5 = comb_small(n_b5, k_b5)  # total possible groups of k candidates.
bad_choices_b5 = comb_small(n_b5 - c_b5, k_b5)  # groups made only of failures.
print("all groups:", int(all_choices_b5), "all-bad groups:", int(bad_choices_b5))  # inspect the failure-count logic.
```
▶ What you'll see: 35 of the 120 three-candidate groups contain no passing answer.

```python
pass3_b5 = pass_at_k(n_b5, c_b5, k_b5)  # compute one minus all-bad probability.
print("pass@3:", round(pass3_b5, 3))  # inspect multi-attempt success.
assert round(pass3_b5, 3) == 0.708  # verify the lesson value.
show_bar(["pass@1", "pass@3"], [0.3, pass3_b5], "Basic 5: attempt budget matters")  # compare attempt budgets.
```
▶ What you'll see: pass@3 is much larger than pass@1 for the same candidate pool.

👀 Takeaway: pass@k is a metric for a sampling policy, not just a model.

judgments_b6 = np.array(["A", "A", "B", "A", "tie", "B", "A", "A", "B", "A"])  # toy judge preferences.

decided_b6 = counts_b6["A"] + counts_b6["B"]  # ignore ties for a simple decided win rate.

### Basic 7 — One Elo update

**Goal.** Update ratings after one pairwise result, because Elo rewards outcomes relative to expectations. We build it in 2 steps.

```python
ra_b7, rb_b7 = 1500.0, 1500.0  # equal starting ratings.
expected_b7 = elo_expected(ra_b7, rb_b7)  # expected A score before the match.
print("expected A score:", round(expected_b7, 3))  # inspect the pre-match probability.
assert expected_b7 == 0.5  # equal ratings imply 50% expected score.
```
