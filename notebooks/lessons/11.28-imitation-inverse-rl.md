# 11.28 — Imitation & Inverse RL

Imitation learning starts from expert demonstrations instead of hand-written rewards, while inverse reinforcement learning (IRL) asks what reward could make those demonstrations sensible. In this lesson, you will build behavioral cloning, inspect why distribution shift breaks it, and implement a tiny maximum-entropy IRL loop from scratch using only NumPy and Matplotlib.

```python
import numpy as np  # arrays, linear algebra, tabular policies, and small optimizers.
```

### 1. A tiny MDP and expert demonstrations

Imitation and IRL need a world before they need an algorithm. We use a five-state line world with two actions: move left or move right. The expert's hidden goal is to reach the right end, but the learner only receives demonstrations `(state, action)`, not the reward table. This makes the setting different from ordinary supervised learning: every action also changes which state will be seen next.

```python
n_states_w, n_actions_w = 5, 2  # states 0..4 and actions 0=left, 1=right.
LEFT_w, RIGHT_w = 0, 1  # readable action ids.
features_w = np.eye(n_states_w)  # one-hot state features for tabular rewards.
print("states:", np.arange(n_states_w))
print("actions: left=0, right=1")
```
▶ What you'll see: a tiny discrete world where each state has its own one-hot feature.

```python
def step_w(s_w, a_w):  # deterministic line-world transition.
    if a_w == RIGHT_w:
        return min(n_states_w - 1, s_w + 1)
    return max(0, s_w - 1)

def expert_action_w(s_w):  # the hidden expert rule: keep moving right until the goal.
    return RIGHT_w if s_w < n_states_w - 1 else LEFT_w

for s_w in range(n_states_w):
    print(f"s={s_w}, expert a={expert_action_w(s_w)}, next={step_w(s_w, expert_action_w(s_w))}")
```
▶ What you'll see: from states 0–3 the expert moves right; at the terminal-like right edge it moves left because right would not reveal anything new.

```python
demos_w = []
for episode_w in range(8):  # collect short demonstrations starting from the far left.
    s_w = 0
    for t_w in range(4):
        a_w = expert_action_w(s_w)
        demos_w.append((s_w, a_w))
        s_w = step_w(s_w, a_w)
print("number of demonstration pairs:", len(demos_w))
print("first 8 pairs:", demos_w[:8])
assert len(demos_w) == 32
```
▶ What you'll see: the dataset repeats the path `(0,right),(1,right),(2,right),(3,right)` because the expert always starts at state 0.

```python
counts_w = np.zeros((n_states_w, n_actions_w))
for s_w, a_w in demos_w:
    counts_w[s_w, a_w] += 1
plt.figure(figsize=(4.5, 3))
plt.imshow(counts_w, cmap="Blues", aspect="auto")
plt.colorbar(label="demo count")
plt.xticks([0, 1], ["left", "right"]); plt.yticks(range(n_states_w))
plt.title("1: expert state-action counts"); plt.xlabel("action"); plt.ylabel("state")
plt.show()
```
▶ What you'll see: bright right-action counts in states 0–3 and no data for state 4.

*Why it's done this way:* a demonstration dataset is a distribution induced by the expert policy, not an arbitrary labeled table. The learner will be very confident where the expert visited often and completely unsupported where the expert never went, which is the seed of distribution shift.

### 2. Behavioral cloning as supervised policy learning

Behavioral cloning (BC) treats each demonstration pair as a supervised label: from state `s`, predict expert action `a`. In a tabular world, the maximum-likelihood policy is just normalized action counts per state. We add small smoothing so unseen actions do not get exactly zero probability, then use the policy to roll out new behavior.

```python
alpha_w = 0.5  # Laplace smoothing so every action keeps nonzero support.
pi_bc_w = (counts_w + alpha_w) / (counts_w.sum(axis=1, keepdims=True) + alpha_w * n_actions_w)
print("BC policy rows [P(left), P(right)]:\n", np.round(pi_bc_w, 3))
assert round(float(pi_bc_w[0, RIGHT_w]), 3) == 0.944
```
▶ What you'll see: states 0–3 assign about 0.944 probability to moving right; unseen state 4 is uniform.

```python
def rollout_policy_w(pi_w, start_w=0, horizon_w=6):
    s_w = start_w
    states_w, actions_w = [s_w], []
    for t_w in range(horizon_w):
        a_w = int(np.argmax(pi_w[s_w]))
        actions_w.append(a_w)
        s_w = step_w(s_w, a_w)
        states_w.append(s_w)
    return states_w, actions_w

states_bc_w, actions_bc_w = rollout_policy_w(pi_bc_w)
print("BC states:", states_bc_w)
print("BC actions:", actions_bc_w)
```
▶ What you'll see: greedy BC moves right through the demonstrated states, then chooses left at state 4 because smoothing made the unseen row tie and `argmax` picks action 0.

```python
plt.figure(figsize=(5, 2.8))
plt.plot(states_bc_w, marker="o", color="seagreen")
plt.ylim(-0.2, 4.2); plt.yticks(range(5))
plt.xlabel("time"); plt.ylabel("state")
plt.title("2: behavioral cloning rollout")
plt.show()
```
▶ What you'll see: the path climbs to the goal state and then bounces back because BC had no real label at the goal.

*Why it's done this way:* maximum likelihood for a categorical policy counts how often each action was chosen in each state, then normalizes. Smoothing is a probability-modeling choice: it avoids impossible actions, but it cannot invent expert knowledge for states the demonstration distribution never covered.

### 3. Distribution shift: small mistakes create new inputs

In ordinary supervised learning, a wrong prediction does not change the next input in the dataset. In control, it does. If a cloned policy makes one early left move, it may visit states and histories the expert almost never visited, so its future labels become less reliable. We simulate a noisy cloned policy to see how an error compounds.

```python
pi_noisy_w = pi_bc_w.copy()
pi_noisy_w[1] = np.array([0.35, 0.65])  # a small but meaningful chance of the wrong action at state 1.
print("state 1 noisy policy [left,right]:", pi_noisy_w[1])
assert np.allclose(pi_noisy_w[1], [0.35, 0.65])
```
▶ What you'll see: the policy is still more likely to go right, but it now sometimes steps backward.

```python
def sample_rollouts_w(pi_w, episodes_w=200, horizon_w=6):
    visits_w = np.zeros(n_states_w)
    returns_w = []
    for ep_w in range(episodes_w):
        s_w = 0
        for t_w in range(horizon_w):
            visits_w[s_w] += 1
            a_w = int(np.random.choice(n_actions_w, p=pi_w[s_w]))
            s_w = step_w(s_w, a_w)
        returns_w.append(1.0 if s_w == n_states_w - 1 else 0.0)
    return visits_w / visits_w.sum(), np.array(returns_w)

visit_bc_w, success_bc_w = sample_rollouts_w(pi_bc_w)
visit_noisy_w, success_noisy_w = sample_rollouts_w(pi_noisy_w)
print("BC success:", round(float(success_bc_w.mean()), 3))
print("noisy success:", round(float(success_noisy_w.mean()), 3))
```
▶ What you'll see: a modest local action error lowers the chance of ending at the rightmost state.

```python
plt.figure(figsize=(5, 3))
plt.bar(np.arange(n_states_w) - 0.18, visit_bc_w, width=0.36, label="BC", color="seagreen")
plt.bar(np.arange(n_states_w) + 0.18, visit_noisy_w, width=0.36, label="noisy BC", color="indianred")
plt.title("3: distribution shift changes visited states")
plt.xlabel("state"); plt.ylabel("visit fraction"); plt.legend()
plt.show()
```
▶ What you'll see: the noisy policy spends more time in earlier states because one wrong move changes the future state distribution.

*Why it's done this way:* BC minimizes one-step classification error under the expert's state distribution. Deployment evaluates long-horizon behavior under the learner's state distribution. Those are different expectations, so tiny supervised errors can compound into large control errors.

### 4. Maximum-entropy IRL: infer rewards from feature counts

Inverse RL reverses the usual direction: instead of learning a policy from known rewards, infer rewards that make expert behavior likely. Maximum-entropy IRL says demonstrations should have high reward, but among all high-reward behaviors we prefer the most random policy possible. In a softmax tabular policy, this means expected feature counts under the learned policy should match expert feature counts.

```python
expert_feat_w = np.zeros(n_states_w)
for s_w, a_w in demos_w:
    expert_feat_w += features_w[s_w]
expert_feat_w = expert_feat_w / len(demos_w)
print("expert state feature frequencies:", np.round(expert_feat_w, 3))
assert np.allclose(np.round(expert_feat_w, 3), [0.25, 0.25, 0.25, 0.25, 0.0])
```
▶ What you'll see: demonstrations spend equal time in states 0–3 and never record state 4 as a decision point.

```python
def soft_value_iteration_w(reward_w, gamma_w=0.9, iters_w=80):
    V_w = np.zeros(n_states_w)
    for k_w in range(iters_w):
        Q_w = np.zeros((n_states_w, n_actions_w))
        for s_w in range(n_states_w):
            for a_w in range(n_actions_w):
                sp_w = step_w(s_w, a_w)
                Q_w[s_w, a_w] = reward_w[s_w] + gamma_w * V_w[sp_w]
        V_w = np.log(np.exp(Q_w).sum(axis=1))
    pi_w = np.exp(Q_w - V_w[:, None])
    return V_w, Q_w, pi_w

reward_w = np.zeros(n_states_w)
V0_w, Q0_w, pi0_w = soft_value_iteration_w(reward_w)
print("initial soft policy:\n", np.round(pi0_w, 3))
```
▶ What you'll see: with zero rewards, the soft-optimal policy is almost symmetric except near boundaries.

```python
def expected_features_w(pi_w, episodes_w=300, horizon_w=4):
    feat_w = np.zeros(n_states_w)
    for ep_w in range(episodes_w):
        s_w = 0
        for t_w in range(horizon_w):
            feat_w += features_w[s_w]
            a_w = int(np.random.choice(n_actions_w, p=pi_w[s_w]))
            s_w = step_w(s_w, a_w)
    return feat_w / (episodes_w * horizon_w)

model_feat0_w = expected_features_w(pi0_w)
print("model feature frequencies before IRL:", np.round(model_feat0_w, 3))
print("expert - model:", np.round(expert_feat_w - model_feat0_w, 3))
```
▶ What you'll see: the random-ish policy over-visits early states and under-visits later expert states.

```python
lr_w = 2.0
history_w = []
reward_w = np.zeros(n_states_w)
for it_w in range(25):
    V_w, Q_w, pi_irl_w = soft_value_iteration_w(reward_w)
    model_feat_w = expected_features_w(pi_irl_w, episodes_w=250, horizon_w=4)
    grad_w = expert_feat_w - model_feat_w
    reward_w += lr_w * grad_w
    history_w.append(np.linalg.norm(grad_w))
print("learned reward:", np.round(reward_w, 3))
print("final policy:\n", np.round(pi_irl_w, 3))
assert history_w[-1] < history_w[0]
```
▶ What you'll see: rewards become larger for states that the expert visits more than the model, and the final policy puts more mass on moving right.

```python
plt.figure(figsize=(5, 3))
plt.plot(history_w, marker="o", color="purple")
plt.title("4: max-ent IRL feature mismatch shrinks")
plt.xlabel("IRL update"); plt.ylabel("||expert features - model features||")
plt.show()

plt.figure(figsize=(5, 3))
plt.bar(range(n_states_w), reward_w, color="darkorange")
plt.title("4: inferred state rewards")
plt.xlabel("state"); plt.ylabel("reward weight")
plt.show()
```
▶ What you'll see: the mismatch curve trends downward, and inferred rewards favor states needed to reproduce the expert's right-moving occupancy.

*Why it's done this way:* in max-entropy IRL, the gradient of demonstration log-likelihood is `expert feature counts − model feature counts`. If the learned policy visits a feature too rarely, its reward weight rises; if it visits a feature too often, its weight falls. Entropy keeps the policy probabilistic so reward inference does not collapse to one arbitrary trajectory.

### ✍️ Toy 2 · Behavioral cloning normalizes counts

Tabular behavioral cloning turns counts into action probabilities, with smoothing to avoid exact zeros.

```python
import numpy as np

t2_greedy_actions = np.argmax(t2_policy, axis=1)           # -> [1, 1, 1, 0]
t2_state = 0                                               # -> 0

    t2_states.append(t2_state)
print("BC policy:", np.round(t2_policy, 3).tolist())       # -> [[0.167, 0.833], [0.167, 0.833], [0.167, 0.833], [0.5, 0.5]]
```

### ✍️ Toy 5 · Soft value backup makes a stochastic policy

A soft Bellman backup computes action scores, log-sum-exp values, and a softmax policy from the same small table.

```python
import numpy as np

t5_rng = np.random.default_rng(0)
t5_reward = np.array([0.0, 0.2, 0.4])                      # -> [0.0, 0.2, 0.4]
t5_old_value = np.array([0.0, 0.5, 1.0])                   # -> [0.0, 0.5, 1.0]
t5_next_state = np.array([[0, 1], [0, 2], [1, 2]])         # -> [[0, 1], [0, 2], [1, 2]]
```

## 🛠️ Setup

```python
import numpy as np # load NumPy for tabular policies, feature counts, and small optimization loops.
import matplotlib.pyplot as plt # load Matplotlib for policy, rollout, and reward visualizations.
np.random.seed(0) # make all stochastic examples reproducible.

def softmax(x): # convert scores into probabilities in a numerically stable way.
    x = np.asarray(x, dtype=float) # ensure vector arithmetic uses floats.
    z = x - np.max(x) # subtract the max so exponentials stay finite.
    e = np.exp(z) # exponentiate shifted scores.
    return e / np.sum(e) # normalize into a probability vector.

def line_step(s, a, n=5): # deterministic line-world transition with actions 0=left and 1=right.
    return min(n - 1, s + 1) if int(a) == 1 else max(0, s - 1) # clip movement at the boundaries.

def greedy_rollout(pi, start=0, horizon=6): # roll out the most likely action from a tabular policy.
    s = int(start) # store the current state.
    states = [s] # record visited states.
    actions = [] # record chosen actions.
    for _ in range(horizon): # simulate a fixed-length trajectory.
        a = int(np.argmax(pi[s])) # choose the highest-probability action.
        actions.append(a) # store the action.
        s = line_step(s, a, pi.shape[0]) # advance the environment.
        states.append(s) # store the next state.
    return np.array(states), np.array(actions) # return arrays for easy plotting.

def make_expert_demos(episodes=6, horizon=4, n=5): # create repeated expert demonstrations in the line world.
    demos = [] # collect state-action pairs.
    for _ in range(episodes): # repeat identical starts to make counts easy to inspect.
        s = 0 # start at the far left.
        for _ in range(horizon): # expert acts for a short horizon.
            a = 1 if s < n - 1 else 0 # expert moves right until the edge.
            demos.append((s, a)) # save the supervised imitation pair.
            s = line_step(s, a, n) # move to the next state.
    return demos # return the demonstration dataset.

def counts_to_policy(demos, n_states=5, n_actions=2, alpha=0.5): # estimate tabular behavioral cloning probabilities.
    counts = np.zeros((n_states, n_actions)) # initialize state-action counts.
    for s, a in demos: # scan demonstrations.
        counts[int(s), int(a)] += 1 # increment the observed state-action cell.
    denom = counts.sum(axis=1, keepdims=True) + alpha * n_actions # compute per-state normalizers.
    pi = np.divide(counts + alpha, denom, out=np.ones_like(counts) / n_actions, where=denom > 0) # use uniform probabilities for zero-support rows.
    return pi, counts # return smoothed policy and raw counts.

def plot_policy(pi, title): # visualize a two-action tabular policy.
    plt.figure(figsize=(4.5, 3)) # create a compact heatmap.
    plt.imshow(pi, cmap="viridis", vmin=0, vmax=1, aspect="auto") # draw action probabilities as colors.
    plt.colorbar(label="probability") # add a probability scale.
    plt.xticks([0, 1], ["left", "right"]) # label the action columns.
    plt.yticks(range(pi.shape[0])) # label states.
    plt.title(title) # name the plot.
    plt.xlabel("action") # label x-axis.
    plt.ylabel("state") # label y-axis.
    plt.show() # display the figure.
```

### Easy 5 — Run a compact max-ent IRL loop

**Goal.** Fit reward weights until model state frequencies move toward expert frequencies, because feature matching is the central max-ent IRL signal. We build it in 4 steps.

```python
    V_e5 = np.zeros(5) # initialize soft values for this reward.
    for vi_e5 in range(50): # soft value iteration.
        Q_e5 = np.zeros((5, 2)) # allocate Q table.
        for s_e5 in range(5): # loop states.
            for a_e5 in range(2): # loop actions.

    model_feat_e5 = np.zeros(5) # estimate model occupancy by deterministic expectation propagation.
    dist_e5 = np.zeros(5); dist_e5[0] = 1.0 # start distribution at state 0.
```

### Advanced 5 — Recover a reward that improves imitation

**Goal.** Compare rollout success before and after IRL reward learning, because inferred rewards should induce a policy closer to expert behavior. We build it in 5 steps.


▶ What you'll see: the expert target emphasizes the four states along the right-moving path.

```python
for outer_a5 in range(30): # train reward weights.
    V_a5 = np.zeros(5) # reset soft values.
    for inner_a5 in range(70): # plan under current reward.
        Q_a5 = np.zeros((5, 2)) # action-value table.
        for s_a5 in range(5): # states.
            for a_a5 in range(2): # actions.
                Q_a5[s_a5, a_a5] = reward_a5[s_a5] + 0.9 * V_a5[line_step(s_a5, a_a5, n=5)] # soft Bellman score.
        V_a5 = np.log(np.exp(Q_a5).sum(axis=1)) # soft value.
    pi_a5 = np.exp(Q_a5 - V_a5[:, None]) # policy under current reward.
    dist_a5 = np.zeros(5); dist_a5[0] = 1.0 # exact start distribution.
    feat_a5 = np.zeros(5) # expected features.
    for t_a5 in range(4): # demonstration horizon.
        feat_a5 += dist_a5 / 4.0 # accumulate current occupancy.
        nxt_a5 = np.zeros(5) # next distribution.
        for s_a5 in range(5): # current states.
            for a_a5 in range(2): # actions.
                nxt_a5[line_step(s_a5, a_a5, n=5)] += dist_a5[s_a5] * pi_a5[s_a5, a_a5] # probability flow.
        dist_a5 = nxt_a5 # advance distribution.
    grad_a5 = expert_feat_a5 - feat_a5 # reward gradient.
    reward_a5 += 1.2 * grad_a5 # gradient ascent update.
    errs_a5.append(float(np.linalg.norm(grad_a5))) # save mismatch.
```
