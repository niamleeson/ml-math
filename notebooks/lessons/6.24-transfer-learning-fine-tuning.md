# 6.24 — Transfer Learning & Fine-Tuning

Transfer learning starts from features learned on a large source task, then adapts them to a smaller target task without spending the same optimization budget from scratch. In this lesson, we build the idea with NumPy only: a base feature extractor, a small task head, frozen versus unfrozen updates, separate learning rates, scale control, and the practical memory/parameter bookkeeping that makes fine-tuning a design choice instead of magic.

## 📖 Concept walkthrough — build each idea from scratch

Before the worked examples, we build transfer learning and fine-tuning one idea at a time. Run each cell in order and inspect the printed numbers: every vector, score, loss, and update is visible. The walkthrough is self-contained (it imports what it needs) and uses a `_w` suffix so it never clashes with the exercises below.

```python
import numpy as np  # arrays, matrix multiplies, and gradients from scratch.
import matplotlib.pyplot as plt  # visual inspection for features, losses, and update sizes.
np.random.seed(0)  # reproducible tiny examples.
```

### 1. A pretrained base turns raw inputs into reusable features

Transfer learning splits a model into two parts: a **base** that converts raw input into a representation, and a **head** that maps that representation to the new task. The base is valuable because it already learned useful directions somewhere else. Here the base is one affine map followed by ReLU, so the whole mechanism is small enough to audit by hand.

```python
x_w = np.array([1.5, -0.5])  # two raw input features for one example.
W_base_w = np.array([[1.8, -0.7], [-0.4, 1.2], [0.6, 0.5]])  # three pretrained feature detectors.
b_base_w = np.array([0.3, -0.1, 0.2])  # pretrained offsets.
z_w = W_base_w @ x_w + b_base_w  # affine signal before the nonlinearity.
print("pre-activation z:", np.round(z_w, 3))
assert round(float(z_w[0]), 3) == 3.35
```
▶ What you'll see: the first detector computes `1.8·1.5 + (-0.7)·(-0.5) + 0.3 = 3.35`, matching the lesson arithmetic.

```python
h_w = np.maximum(0, z_w)  # ReLU keeps positive signals and clips negative ones.
print("transferred feature h:", np.round(h_w, 3))
plt.figure(figsize=(4.4, 3))
plt.bar(["f0", "f1", "f2"], h_w, color="teal")
plt.title("1: base features after ReLU")
plt.ylabel("activation")
plt.show()
```
▶ What you'll see: feature 0 is strongly active, feature 1 is clipped to 0, and feature 2 stays moderately active.

*Why it's done this way:* the affine map forms learned directions in input space, and ReLU turns them into gated evidence. Transfer learning works because the new task does not relearn those directions from scratch; it reuses `h` as a compact summary, then only asks how the target labels should read that summary.

### 2. A new head turns transferred features into task probabilities

The head is usually small because the base has already done the expensive representation work. For a two-class target task, the head computes logits, then softmax converts logits into a calibrated comparison. Only differences between logits matter: a score is useful because it beats another score, not because it is meaningful by itself.

```python
W_head_w = np.array([[0.8, -0.3, 0.5], [-0.2, 0.4, 0.1]])  # two target-class rows.
b_head_w = np.array([0.4, 0.0])  # class offsets.
logits_w = W_head_w @ h_w + b_head_w  # target-task scores from transferred features.
print("logits:", np.round(logits_w, 3))
assert round(float(logits_w[0]), 3) == 3.505
assert round(float(logits_w[1]), 3) == -0.585
```
▶ What you'll see: class 0 receives the large transferred signal, while class 1 stays low.

```python
shift_w = logits_w - np.max(logits_w)  # stable softmax: subtract max before exponentiating.
probs_w = np.exp(shift_w) / np.sum(np.exp(shift_w))  # normalized class probabilities.
loss_w = -np.log(probs_w[0])  # cross-entropy for true class 0.
print("probabilities:", np.round(probs_w, 3), "loss:", round(float(loss_w), 3))
plt.figure(figsize=(4.4, 3))
plt.bar(["class 0", "class 1"], probs_w, color=["seagreen", "gray"])
plt.title("2: softmax reads the transferred features")
plt.ylabel("probability")
plt.ylim(0, 1)
plt.show()
```
▶ What you'll see: class 0 has a high probability because its logit is much larger than class 1's logit.

*Why it's done this way:* softmax exponentiates score gaps, so a larger target logit becomes a larger probability and a smaller loss. The subtraction by `max(logits)` changes neither probability nor math; it only prevents unnecessarily large exponentials.

### 3. Fine-tuning uses different learning rates for base and head

Fine-tuning updates both parts, but not equally. The head is new and should move quickly; the base is pretrained and should move gently so it adapts without destroying useful features. The lesson formula is

$$\theta_{base}\leftarrow\theta_{base}-\eta_{base}g_{base},\qquad \theta_{head}\leftarrow\theta_{head}-\eta_{head}g_{head}.$$

```python
theta_base_w = 2.0  # one scalar standing in for a pretrained base parameter.
theta_head_w = 2.0  # one scalar standing in for a new head parameter.
g_base_w = 1.65  # gradient on the pretrained parameter.
g_head_w = 1.65  # same gradient size, different learning-rate policy.
eta_base_w, eta_head_w = 0.009, 0.09  # base moves 10x more gently than the head.
print("before:", theta_base_w, theta_head_w)
```
▶ What you'll see: both parameters start at the same value so the learning-rate effect is isolated.

```python
new_base_w = theta_base_w - eta_base_w * g_base_w  # gentle pretrained update.
new_head_w = theta_head_w - eta_head_w * g_head_w  # faster new-head update.
print("after base/head:", round(new_base_w, 3), round(new_head_w, 3))
assert round(new_head_w, 3) == 1.851
plt.figure(figsize=(4.4, 3))
plt.bar(["base move", "head move"], [theta_base_w - new_base_w, theta_head_w - new_head_w], color=["steelblue", "darkorange"])
plt.title("3: discriminative learning rates")
plt.ylabel("absolute parameter movement")
plt.show()
```
▶ What you'll see: the head update is 10× larger even though the gradient was identical.

*Why it's done this way:* pretrained weights encode broadly useful features, so a large update can cause forgetting. Separate learning rates are a mathematical constraint on how much each subsystem may change per gradient step.

### 4. Freezing the base trains only the new head

Freezing is the extreme version of a small base learning rate: set the base step to zero. This is useful when the target dataset is tiny or when we first want the head to learn a sensible readout before letting gradients touch the representation.

```python
base_before_w = np.array([1.8, -0.7, 0.6])  # pretend these are three base weights.
head_before_w = np.array([0.8, -0.3, 0.5])  # one head row.
g_base_vec_w = np.array([0.4, -0.2, 0.1])  # base gradient from backprop.
g_head_vec_w = np.array([-0.6, 0.3, -0.2])  # head gradient from backprop.
print("base before:", base_before_w)
print("head before:", head_before_w)
```
▶ What you'll see: both base and head have gradients, but policy decides which parameters actually move.

```python
base_frozen_w = base_before_w - 0.0 * g_base_vec_w  # freeze: no base movement.
head_trained_w = head_before_w - 0.1 * g_head_vec_w  # train the head normally.
print("base after freezing:", np.round(base_frozen_w, 3))
print("head after training:", np.round(head_trained_w, 3))
assert np.allclose(base_frozen_w, base_before_w)
```
▶ What you'll see: the base is exactly unchanged, while the head moves in the negative-gradient direction.

```python
plt.figure(figsize=(4.6, 3))
plt.bar(["base change", "head change"], [np.linalg.norm(base_frozen_w - base_before_w), np.linalg.norm(head_trained_w - head_before_w)], color=["gray", "seagreen"])
plt.title("4: freezing protects the base")
plt.ylabel("L2 change")
plt.show()
```
▶ What you'll see: the base-change bar is zero, which is the whole point of a frozen feature extractor.

*Why it's done this way:* gradients describe what would reduce the current loss, but the optimizer is allowed to ignore some gradients. Freezing is a deliberate bias: preserve source-task representation first, adapt the cheap new head first.

### 5. Normalization keeps transferred activations on a usable scale

A transferred feature can be numerically too large or too small for the new head. Normalization recenters and rescales a signal, which changes the effective gradient scale seen by the downstream model. The lesson's concrete value is `(3.350 - 1.000) / sqrt(0.250 + 0.00001) ≈ 4.700`.

```python
signal_w = 3.35  # activation from the scratch pass.
mean_w = 1.0  # running source-domain mean.
var_w = 0.25  # running source-domain variance.
eps_w = 1e-5  # numerical stabilizer.
normalized_w = (signal_w - mean_w) / np.sqrt(var_w + eps_w)
print("normalized signal:", round(float(normalized_w), 3))
assert round(float(normalized_w), 3) == 4.7
```
▶ What you'll see: the signal is 4.7 standard deviations above the stored mean, so it is unusually high.

```python
signals_w = np.array([0.2, 1.0, 3.35, 4.0])
normalized_many_w = (signals_w - mean_w) / np.sqrt(var_w + eps_w)
plt.figure(figsize=(4.6, 3))
plt.plot(signals_w, normalized_many_w, marker="o", color="purple")
plt.axhline(0, color="black", linewidth=0.8)
plt.title("5: normalization is affine rescaling")
plt.xlabel("raw activation")
plt.ylabel("normalized activation")
plt.show()
```
▶ What you'll see: every raw activation is shifted by the mean and divided by the same standard deviation.

*Why it's done this way:* optimization depends on scale. A feature that is 10× larger can create 10× larger downstream gradients. Normalization makes the head see features in comparable units, so learning rates mean roughly what we think they mean.

### 6. Parameter and activation memory decide what is practical

Fine-tuning is not only a statistical choice; it is a hardware choice. Updating a base means storing activations for backprop and optimizer state for many parameters. Even a tiny activation block with two vectors of length 128 in 32-bit floats uses exactly 1 KB; real models multiply that by batch, layers, and checkpoints.

```python
vectors_w = 2  # two activation vectors.
width_w = 128  # each vector has 128 float32 values.
bytes_per_float_w = 4  # float32 storage.
kb_w = vectors_w * width_w * bytes_per_float_w / 1024
print("activation memory KB:", round(kb_w, 3))
assert round(kb_w, 3) == 1.0
```
▶ What you'll see: the arithmetic is small here, but it exposes the exact unit conversion.

```python
base_params_w = 1_000_000
head_params_w = 10_000
adam_bytes_per_param_w = 12  # parameter + two Adam moment buffers, simplified float32 accounting.
full_mb_w = (base_params_w + head_params_w) * adam_bytes_per_param_w / 1024**2
head_only_mb_w = head_params_w * adam_bytes_per_param_w / 1024**2
print("full optimizer MB:", round(full_mb_w, 2), "head-only MB:", round(head_only_mb_w, 2))
plt.figure(figsize=(4.4, 3))
plt.bar(["full tune", "head only"], [full_mb_w, head_only_mb_w], color=["crimson", "teal"])
plt.title("6: optimizer state cost")
plt.ylabel("MB")
plt.show()
```
▶ What you'll see: optimizer memory is dominated by the base, so freezing can be a large practical saving.

*Why it's done this way:* the same math that updates parameters also demands memory to store parameters, gradients, and optimizer statistics. Transfer learning often succeeds because it can reuse a costly base while training only a small part of the system.

## 🟢 Basics (warm-up)

### Basic 1 — Compute a pretrained affine signal

**Goal.** Build the first signal in a feature extractor, because transfer learning begins by applying learned weights to new inputs. We build it in 2 steps.

```python
x_b1 = np.array([1.5, -0.5])
w_b1 = np.array([1.8, -0.7])
b_b1 = 0.3
parts_b1 = w_b1 * x_b1
print("coordinate products:", np.round(parts_b1, 3))
```
▶ What you'll see: the two input coordinates contribute `2.7` and `0.35` before the bias is added.

```python
z_b1 = float(np.sum(parts_b1) + b_b1)
print("affine signal:", round(z_b1, 3))
assert round(z_b1, 3) == 3.35
plt.figure(figsize=(4, 3))
plt.bar(["w0*x0", "w1*x1", "bias"], [parts_b1[0], parts_b1[1], b_b1], color="teal")
plt.title("Basic 1: affine pieces")
plt.ylabel("contribution")
plt.show()
```
▶ What you'll see: positive evidence plus bias produces the lesson signal 3.35.

👀 Takeaway: a pretrained feature detector is just a learned weighted sum before any nonlinearity.

### Basic 2 — Apply the ReLU gate

**Goal.** Convert pre-activations into gated features, because later layers should receive active evidence and ignore negative detector responses. We build it in 2 steps.

```python
z_b2 = np.array([3.35, -1.3, 0.85])
print("pre-activations:", z_b2)
```
▶ What you'll see: one detector is negative, so ReLU will silence it.

```python
h_b2 = np.maximum(0, z_b2)
print("ReLU features:", h_b2)
assert np.allclose(h_b2, [3.35, 0.0, 0.85])
plt.figure(figsize=(4, 3))
plt.bar(["f0", "f1", "f2"], h_b2, color="seagreen")
plt.title("Basic 2: ReLU-gated features")
plt.ylabel("activation")
plt.show()
```
▶ What you'll see: the negative response becomes exactly zero.

👀 Takeaway: ReLU makes transferred features sparse, positive pieces of evidence.

### Basic 3 — Stack feature detectors into a base

**Goal.** Compute several pretrained features at once, because a base extractor is many detectors arranged as a matrix. We build it in 2 steps.

```python
x_b3 = np.array([1.5, -0.5])
W_b3 = np.array([[1.8, -0.7], [-0.4, 1.2], [0.6, 0.5]])
b_b3 = np.array([0.3, -0.1, 0.2])
print("W shape:", W_b3.shape, "x shape:", x_b3.shape)
```
▶ What you'll see: a 3×2 base maps a length-2 input to three feature coordinates.

```python
z_b3 = W_b3 @ x_b3 + b_b3
h_b3 = np.maximum(0, z_b3)
print("features:", np.round(h_b3, 3))
assert round(float(h_b3[0]), 3) == 3.35
plt.figure(figsize=(4, 3))
plt.imshow(W_b3, cmap="coolwarm", aspect="auto")
plt.colorbar(label="weight")
plt.title("Basic 3: pretrained base weights")
plt.xlabel("input coordinate")
plt.ylabel("feature detector")
plt.show()
```
▶ What you'll see: the heatmap shows each detector as one row of learned weights.

👀 Takeaway: matrix multiplication applies all pretrained detectors in one vectorized pass.

### Basic 4 — Build a small target head

**Goal.** Map transferred features to target logits, because the new task usually needs a new readout layer. We build it in 2 steps.

```python
h_b4 = np.array([3.35, 0.0, 0.85])
W_head_b4 = np.array([[0.8, -0.3, 0.5], [-0.2, 0.4, 0.1]])
b_head_b4 = np.array([0.245, 0.0])
print("head shape:", W_head_b4.shape)
```
▶ What you'll see: two rows of head weights produce two target-class scores.

```python
logits_b4 = W_head_b4 @ h_b4 + b_head_b4
print("logits:", np.round(logits_b4, 3))
assert round(float(logits_b4[0]), 3) == 3.35
plt.figure(figsize=(4, 3))
plt.bar(["class0", "class1"], logits_b4, color=["teal", "gray"])
plt.title("Basic 4: target-task logits")
plt.ylabel("logit")
plt.show()
```
▶ What you'll see: class 0 has the much larger score for this example.

👀 Takeaway: transfer learning often trains a small head on top of reusable base features.

### Basic 5 — Convert logits to softmax probabilities

**Goal.** Normalize target scores into probabilities, because classification loss compares probability assigned to the true class. We build it in 3 steps.

```python
logits_b5 = np.array([3.35, 0.4])
shift_b5 = logits_b5 - np.max(logits_b5)
print("shifted logits:", np.round(shift_b5, 3))
```
▶ What you'll see: the largest logit becomes zero, which is numerically safer for exponentials.

```python
exp_b5 = np.exp(shift_b5)
probs_b5 = exp_b5 / np.sum(exp_b5)
print("probabilities:", np.round(probs_b5, 3))
assert round(float(probs_b5[0]), 3) == 0.95
```
▶ What you'll see: the lesson comparison gives about 95% probability to class 0.

```python
plt.figure(figsize=(4, 3))
plt.bar(["class0", "class1"], probs_b5, color=["seagreen", "gray"])
plt.title("Basic 5: softmax probability")
plt.ylim(0, 1)
plt.ylabel("probability")
plt.show()
```
▶ What you'll see: the class-0 bar dominates because `exp(3.35)` is much larger than `exp(0.4)`.

👀 Takeaway: softmax turns logit differences into a normalized comparison.

### Basic 6 — Compute cross-entropy for one label

**Goal.** Measure how surprised the model is by the true class, because gradients come from loss. We build it in 2 steps.

```python
probs_b6 = np.array([0.950154, 0.049846])
y_b6 = 0
loss_b6 = -np.log(probs_b6[y_b6])
print("cross-entropy:", round(float(loss_b6), 3))
assert round(float(loss_b6), 3) == 0.051
```
▶ What you'll see: high probability on the true class gives a small loss.

```python
p_grid_b6 = np.linspace(0.05, 0.99, 80)
loss_grid_b6 = -np.log(p_grid_b6)
plt.figure(figsize=(4, 3))
plt.plot(p_grid_b6, loss_grid_b6, color="purple")

plt.ylabel("loss")
plt.show()
```
▶ What you'll see: loss falls steeply as the true-class probability approaches 1.

👀 Takeaway: cross-entropy rewards confident correct probabilities and strongly punishes confident misses.

### Basic 8 — Compare base and head learning rates

**Goal.** Show discriminative learning rates, because fine-tuning should usually move pretrained base weights more gently than new head weights. We build it in 2 steps.

```python
g_b8 = np.array([1.65, 1.65])
```

👀 Takeaway: fine-tuning adapts different parts of a network at different speeds.

## 🟡 Easy

### Easy 1 — Train only a new head on frozen features

**Goal.** Learn a classifier head while keeping features fixed, because frozen-base transfer is the safest first adaptation step. We build it in 4 steps.

```python
X_e1 = np.array([[1.5, -0.5], [1.0, -1.0], [-0.5, 1.5], [-1.0, 1.0]])
y_e1 = np.array([0, 0, 1, 1])
W_base_e1 = np.array([[1.8, -0.7], [-0.4, 1.2], [0.6, 0.5]])
b_base_e1 = np.array([0.3, -0.1, 0.2])
H_e1 = np.maximum(0, X_e1 @ W_base_e1.T + b_base_e1)
print("frozen features shape:", H_e1.shape)
```
▶ What you'll see: four examples become four 3-dimensional transferred feature vectors.

```python
W_head_e1 = np.zeros((2, 3))
b_head_e1 = np.zeros(2)
eta_e1 = 0.2
print("initial head norm:", np.linalg.norm(W_head_e1))
```
▶ What you'll see: the head begins with no preference for either class.

```python
losses_e1 = []
for step_e1 in range(120):
    logits_e1 = H_e1 @ W_head_e1.T + b_head_e1
    logits_e1 = logits_e1 - np.max(logits_e1, axis=1, keepdims=True)
    probs_e1 = np.exp(logits_e1) / np.sum(np.exp(logits_e1), axis=1, keepdims=True)
    loss_e1 = -np.mean(np.log(probs_e1[np.arange(len(y_e1)), y_e1]))
    grad_logits_e1 = probs_e1.copy()
    grad_logits_e1[np.arange(len(y_e1)), y_e1] -= 1
    grad_logits_e1 /= len(y_e1)
    W_head_e1 -= eta_e1 * (grad_logits_e1.T @ H_e1)
    b_head_e1 -= eta_e1 * np.sum(grad_logits_e1, axis=0)
    losses_e1.append(loss_e1)
print("loss start/end:", round(losses_e1[0], 3), round(losses_e1[-1], 3))
assert losses_e1[-1] < losses_e1[0]
```
▶ What you'll see: the head loss decreases while the base features remain fixed.

```python
plt.figure(figsize=(5, 3))
plt.plot(losses_e1, color="teal")
plt.title("Easy 1: frozen-feature head training")
plt.xlabel("step")
plt.ylabel("cross-entropy")
plt.show()
```
▶ What you'll see: a smooth downward curve because the small head can read the fixed features.

👀 Takeaway: frozen transfer adapts the task readout without risking pretrained feature drift.

### Easy 2 — Unfreeze the base with a smaller learning rate

**Goal.** Fine-tune base and head together with different step sizes, because careful base movement can improve a target task without forgetting everything. We build it in 4 steps.

```python
X_e2 = np.array([[1.5, -0.5], [1.0, -1.0], [-0.5, 1.5], [-1.0, 1.0]])
y_e2 = np.array([0, 0, 1, 1])
W_base_e2 = np.array([[1.8, -0.7], [-0.4, 1.2], [0.6, 0.5]], dtype=float)
```

```python

    Z_e2 = X_e2 @ W_base_e2.T + b_base_e2
    H_e2 = np.maximum(0, Z_e2)
    logits_e2 = H_e2 @ W_head_e2.T + b_head_e2
    logits_e2 -= np.max(logits_e2, axis=1, keepdims=True)
    probs_e2 = np.exp(logits_e2) / np.sum(np.exp(logits_e2), axis=1, keepdims=True)
    loss_e2 = -np.mean(np.log(probs_e2[np.arange(len(y_e2)), y_e2]))
    dlogits_e2 = probs_e2.copy()
    dlogits_e2[np.arange(len(y_e2)), y_e2] -= 1
    dlogits_e2 /= len(y_e2)
    dH_e2 = dlogits_e2 @ W_head_e2
```
