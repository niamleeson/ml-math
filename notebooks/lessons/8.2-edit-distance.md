# 8.2 — Edit Distance

Edit distance turns spelling disagreement into the cheapest sequence of character repairs. In this lesson, we build the dynamic-programming table from scratch, inspect the edit operations it permits, change the cost model on purpose, and use the final distance as the engine behind fuzzy matching.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build edit distance one idea at a time. Run each cell in order and read the printed intermediate values — every piece of math is spelled out so the dynamic-programming table is not a black box. This walkthrough is self-contained (it imports what it needs) and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays for edit tables and distance vectors.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
np.random.seed(0)  # reproducibility for any small simulations.
```

### 1. Prefixes turn a string problem into a table

Edit distance compares two full strings by comparing every pair of prefixes first. For source `cat` and target `cut`, entry `D[i,j]` means: the cheapest cost to turn the first `i` source characters into the first `j` target characters. The row and column for the empty string are not decoration — they encode the only possible repairs from or to nothing.

```python
source_w = "cat"
target_w = "cut"
rows_w = [""] + [source_w[:i] for i in range(1, len(source_w) + 1)]
cols_w = [""] + [target_w[:j] for j in range(1, len(target_w) + 1)]
print("source prefixes:", rows_w)
print("target prefixes:", cols_w)
```
▶ What you'll see: both strings are expanded into prefixes, including the empty prefix.

```python
D_w = np.zeros((len(source_w) + 1, len(target_w) + 1), dtype=int)
D_w[:, 0] = np.arange(len(source_w) + 1)
D_w[0, :] = np.arange(len(target_w) + 1)
print(D_w)
assert D_w[3, 0] == 3 and D_w[0, 3] == 3
```
▶ What you'll see: the first column counts deletions from `cat` to empty; the first row counts insertions from empty to `cut`.

```python
plt.figure(figsize=(4, 3))
plt.imshow(D_w, cmap="Blues", vmin=0)
plt.colorbar(label="boundary cost")
plt.xticks(range(len(cols_w)), [c or "∅" for c in cols_w])
plt.yticks(range(len(rows_w)), [r or "∅" for r in rows_w])
plt.title("1: edit-distance boundary values")
plt.xlabel("target prefix")
plt.ylabel("source prefix")
plt.show()
```
▶ What you'll see: cost rises one step at a time along the top row and left column.

*Why it's done this way:* dynamic programming needs known base cases. If one prefix is empty, there is no choice: each remaining character must be inserted or deleted, so the cost is exactly the prefix length. Those boundary values anchor every later minimum.

### 2. The recurrence chooses the cheapest last edit

Once shorter prefixes are solved, each new cell asks what the final edit could have been. We can delete the last source character, insert the last target character, or match/substitute the two last characters. The recurrence is

$$D_{i,j}=\min\{D_{i-1,j}+1,\;D_{i,j-1}+1,\;D_{i-1,j-1}+\mathbf{1}[a_i\ne b_j]\}.$$

```python
D_w = np.zeros((4, 4), dtype=int)
D_w[:, 0] = np.arange(4)
D_w[0, :] = np.arange(4)
for i_w in range(1, 4):
    for j_w in range(1, 4):
        delete_w = D_w[i_w - 1, j_w] + 1
        insert_w = D_w[i_w, j_w - 1] + 1
        sub_w = D_w[i_w - 1, j_w - 1] + (source_w[i_w - 1] != target_w[j_w - 1])
        D_w[i_w, j_w] = min(delete_w, insert_w, sub_w)
print(D_w)
assert D_w.tolist() == [[0, 1, 2, 3], [1, 0, 1, 2], [2, 1, 1, 2], [3, 2, 2, 1]]
```
▶ What you'll see: the final table gives distance 1 for `cat` → `cut`.

```python
i_w, j_w = 2, 2  # prefixes "ca" and "cu".
choices_w = {
    "delete a": D_w[i_w - 1, j_w] + 1,
    "insert u": D_w[i_w, j_w - 1] + 1,
    "sub a→u": D_w[i_w - 1, j_w - 1] + 1,
}
print(choices_w)
print("chosen:", min(choices_w, key=choices_w.get), "cost", D_w[i_w, j_w])
```
▶ What you'll see: substitution is the cheapest last move for changing `ca` into `cu`.

```python
plt.figure(figsize=(4, 3))
plt.imshow(D_w, cmap="viridis")
plt.colorbar(label="minimum cost")
plt.xticks(range(4), ["∅", "c", "u", "t"])
plt.yticks(range(4), ["∅", "c", "a", "t"])
for i_w in range(4):
    for j_w in range(4):
        plt.text(j_w, i_w, D_w[i_w, j_w], ha="center", va="center", color="white")
plt.title("2: completed DP matrix")
plt.xlabel("target character")
plt.ylabel("source character")
plt.show()
```
▶ What you'll see: the diagonal stays cheap where characters match, and the center cell records the one substitution.

*Why it's done this way:* every optimal edit script has a last operation. By trying all possible last operations and reusing the best solved prefix costs, the recurrence proves optimality instead of guessing a plausible repair.

### 3. Insert, delete, and substitute are shortest-path edges

The same table can be read as a graph. Each grid cell is a prefix state; moving down deletes a source character, moving right inserts a target character, and moving diagonally matches or substitutes. The distance is the shortest path from the top-left state to the bottom-right state.

```python
def edit_table_w(a_w, b_w, sub_cost_w=1):
    T_w = np.zeros((len(a_w) + 1, len(b_w) + 1), dtype=int)
    T_w[:, 0] = np.arange(len(a_w) + 1)
    T_w[0, :] = np.arange(len(b_w) + 1)
    for i_w in range(1, len(a_w) + 1):
        for j_w in range(1, len(b_w) + 1):
            cost_w = 0 if a_w[i_w - 1] == b_w[j_w - 1] else sub_cost_w
            T_w[i_w, j_w] = min(T_w[i_w - 1, j_w] + 1, T_w[i_w, j_w - 1] + 1, T_w[i_w - 1, j_w - 1] + cost_w)
    return T_w

for word_w in ["cats", "cut", "at"]:
    print("cat ->", word_w, "distance", edit_table_w("cat", word_w)[-1, -1])
```
▶ What you'll see: insertion, substitution, and deletion each cost 1 under the unit-cost model.

```python
T_w = edit_table_w("cat", "cats")
path_w = []
i_w, j_w = 3, 4
while i_w > 0 or j_w > 0:
    path_w.append((i_w, j_w))
    if j_w > 0 and T_w[i_w, j_w] == T_w[i_w, j_w - 1] + 1:
        j_w -= 1
    elif i_w > 0 and T_w[i_w, j_w] == T_w[i_w - 1, j_w] + 1:
        i_w -= 1
    else:
        i_w -= 1; j_w -= 1
path_w.append((0, 0))
path_w = path_w[::-1]
print("path:", path_w)
assert T_w[-1, -1] == 1
```
▶ What you'll see: the path mostly follows matches, then moves right once to insert `s`.

```python
plt.figure(figsize=(4, 3))
plt.imshow(T_w, cmap="Greens")
plt.colorbar(label="cost")
ys_w, xs_w = zip(*path_w)
plt.plot(xs_w, ys_w, color="crimson", marker="o")
plt.xticks(range(5), ["∅", "c", "a", "t", "s"])
plt.yticks(range(4), ["∅", "c", "a", "t"])
plt.title("3: shortest path through the grid")
plt.xlabel("target prefix")
plt.ylabel("source prefix")
plt.show()
```
▶ What you'll see: the red path reaches the endpoint with exactly one horizontal insertion step.

*Why it's done this way:* shortest-path thinking makes the recurrence intuitive. The table is not just storing numbers; it is storing the best distance to each state so later states can extend only the cheapest prefix routes.

### 4. Backtracing recovers an optimal edit script

The endpoint distance tells us how many edits are needed, but applications often need the edit script too. Backtracing walks from the endpoint to the origin, choosing predecessor cells that explain the current cost.

```python
def edit_script_w(a_w, b_w):
    T_w = edit_table_w(a_w, b_w)
    i_w, j_w = len(a_w), len(b_w)
    ops_w = []
    while i_w > 0 or j_w > 0:
        if i_w > 0 and j_w > 0 and a_w[i_w - 1] == b_w[j_w - 1] and T_w[i_w, j_w] == T_w[i_w - 1, j_w - 1]:
            ops_w.append(("match", a_w[i_w - 1], b_w[j_w - 1]))
            i_w -= 1; j_w -= 1
        elif i_w > 0 and j_w > 0 and T_w[i_w, j_w] == T_w[i_w - 1, j_w - 1] + 1:
            ops_w.append(("sub", a_w[i_w - 1], b_w[j_w - 1]))
            i_w -= 1; j_w -= 1
        elif j_w > 0 and T_w[i_w, j_w] == T_w[i_w, j_w - 1] + 1:
            ops_w.append(("insert", "", b_w[j_w - 1]))
            j_w -= 1
        else:
            ops_w.append(("delete", a_w[i_w - 1], ""))
            i_w -= 1
    return ops_w[::-1], T_w

ops_w, kitten_table_w = edit_script_w("kitten", "sitting")
print(ops_w)
print("distance:", kitten_table_w[-1, -1])
assert kitten_table_w[-1, -1] == 3
```
▶ What you'll see: an optimal path substitutes `k→s`, substitutes `e→i`, and inserts `g`.

```python
edits_only_w = [op_w for op_w in ops_w if op_w[0] != "match"]
print("edits only:", edits_only_w)
assert len(edits_only_w) == 3
```
▶ What you'll see: the three non-match operations are exactly the distance.

```python
plt.figure(figsize=(5, 3))
plt.imshow(kitten_table_w, cmap="magma")
plt.colorbar(label="minimum cost")
plt.title("4: kitten → sitting DP matrix")
plt.xlabel("target prefix length")
plt.ylabel("source prefix length")
plt.show()
```
▶ What you'll see: the endpoint is 3; look for broad diagonal structure with a final extra target column.

*Why it's done this way:* the DP value proves the minimum cost, and backtracing explains which final-operation choices achieved it. Multiple scripts can tie, so a deterministic backtrace is an explanation of one optimum, not necessarily the only optimum.

### 5. The cost model is a modeling assumption

Unit costs say insertions, deletions, and substitutions are equally plausible. That is not a law of nature. If substitutions are made expensive, the algorithm may prefer a delete-plus-insert route instead.

```python
sub_costs_w = np.array([1, 2, 3])
dists_w = np.array([edit_table_w("cat", "cut", sub_cost_w=int(c_w))[-1, -1] for c_w in sub_costs_w])
print("substitution costs:", sub_costs_w)
print("distances:", dists_w)
assert dists_w.tolist() == [1, 2, 2]
```
▶ What you'll see: once substitution costs more than delete+insert, the distance stops increasing at 2.

```python
for c_w, d_w in zip(sub_costs_w, dists_w):
    route_w = "substitute a→u" if c_w <= 2 else "delete a, insert u"
    print(f"sub_cost={c_w}: distance={d_w}, preferred route≈{route_w}")
```
▶ What you'll see: the number changes because the application changed the prices of mistakes.

```python
plt.figure(figsize=(4, 3))
plt.plot(sub_costs_w, dists_w, marker="o", color="darkorange")
plt.xticks(sub_costs_w)
plt.xlabel("substitution cost")
plt.ylabel("edit distance")
plt.title("5: changing the cost model")
plt.show()
```
▶ What you'll see: the curve rises from 1 to 2 and then flattens because delete+insert is cheaper than a cost-3 substitution.

*Why it's done this way:* edit distance is only meaningful relative to its costs. The recurrence finds the cheapest path under the prices you choose, so those prices encode which typos or transformations your system considers plausible.

### 6. Fuzzy retrieval is a radius query over distances

A fuzzy matcher computes distances from one query to many candidates, then keeps candidates whose endpoint cost is below a chosen radius. This is useful for spelling correction and approximate vocabulary lookup, but the threshold must match the task.

```python
query_w = "color"
candidates_w = np.array(["colour", "colon", "cold", "caller", "color"])
distances_w = np.array([edit_table_w(query_w, cand_w)[-1, -1] for cand_w in candidates_w])
print(list(zip(candidates_w, distances_w)))
assert distances_w.tolist() == [1, 1, 2, 3, 0]
```
▶ What you'll see: `color` is exact distance 0, while `caller` is farther away at distance 3.

```python
radius_w = 2
accepted_w = candidates_w[distances_w <= radius_w]
print("accepted within radius 2:", accepted_w.tolist())
print("rejected:", candidates_w[distances_w > radius_w].tolist())
assert len(accepted_w) == 4
```
▶ What you'll see: four of five candidates pass a radius-2 fuzzy lookup.

```python
plt.figure(figsize=(5, 3))
colors_w = np.where(distances_w <= radius_w, "seagreen", "crimson")
plt.bar(candidates_w, distances_w, color=colors_w)
plt.axhline(radius_w, color="black", linestyle="--", label="radius 2")
plt.ylabel("edit distance from color")
plt.title("6: fuzzy matching as thresholding")
plt.legend()
plt.show()
```
▶ What you'll see: green bars are accepted by the threshold; `caller` is rejected above the dashed line.

*Why it's done this way:* after distances are numbers, retrieval becomes ranking or thresholding. The caution is semantic: one-edit words can mean unrelated things, so edit distance measures surface repair, not conceptual similarity.

Every interior cell compares deletion, insertion, and match/substitution. For `gum → gun`, the last
cell chooses the single substitution `m→n`.

```python
import numpy as np

# seeded for reproducibility, even though this deterministic toy does not draw random numbers.
t2_rng = np.random.default_rng(0)
t2_source = "gum"
print("source:", t2_source)  # -> gum
t2_target = "gun"
```

### ✍️ Toy 3 · Insert, delete, and substitute each make one-step repairs

Under unit costs, the three primitive edit edges each add exactly one cost when isolated on a tiny
word pair.

```python
import numpy as np

# seeded for reproducibility, even though this deterministic toy does not draw random numbers.
t3_rng = np.random.default_rng(0)
```

### ✍️ Toy 4 · Backtracing turns a distance into an edit script

The endpoint gives the minimum cost, while the backtrace explains one optimal sequence of edits
that attains it.

```python
import numpy as np

# seeded for reproducibility, even though this deterministic toy does not draw random numbers.
t4_rng = np.random.default_rng(0)

def t4_table(t4_a, t4_b):
    t4_T = np.zeros((len(t4_a) + 1, len(t4_b) + 1), dtype=int)
    t4_T[:, 0] = np.arange(len(t4_a) + 1)
    t4_T[0, :] = np.arange(len(t4_b) + 1)
    for t4_i in range(1, len(t4_a) + 1):
        for t4_j in range(1, len(t4_b) + 1):
            t4_cost = int(t4_a[t4_i - 1] != t4_b[t4_j - 1])
            t4_T[t4_i, t4_j] = min(t4_T[t4_i - 1, t4_j] + 1, t4_T[t4_i, t4_j - 1] + 1, t4_T[t4_i - 1, t4_j - 1] + t4_cost)
    return t4_T

t4_source = "flaw"
print("source:", t4_source)  # -> flaw
t4_target = "lawn"
print("target:", t4_target)  # -> lawn
t4_T = t4_table(t4_source, t4_target)
print("DP table:", t4_T.tolist())  # -> [[0, 1, 2, 3, 4], [1, 1, 2, 3, 4], [2, 1, 2, 3, 4], [3, 2, 1, 2, 3], [4, 3, 2, 1, 2]]
t4_i = len(t4_source)
t4_j = len(t4_target)
t4_ops = []
while t4_i > 0 or t4_j > 0:
    if t4_i > 0 and t4_j > 0 and t4_source[t4_i - 1] == t4_target[t4_j - 1] and t4_T[t4_i, t4_j] == t4_T[t4_i - 1, t4_j - 1]:
        t4_ops.append(("match", t4_source[t4_i - 1], t4_target[t4_j - 1]))
        t4_i -= 1
        t4_j -= 1
    elif t4_i > 0 and t4_j > 0 and t4_T[t4_i, t4_j] == t4_T[t4_i - 1, t4_j - 1] + 1:
        t4_ops.append(("sub", t4_source[t4_i - 1], t4_target[t4_j - 1]))
        t4_i -= 1
        t4_j -= 1
    elif t4_j > 0 and t4_T[t4_i, t4_j] == t4_T[t4_i, t4_j - 1] + 1:
        t4_ops.append(("insert", "", t4_target[t4_j - 1]))
        t4_j -= 1
    else:
        t4_ops.append(("delete", t4_source[t4_i - 1], ""))
        t4_i -= 1
t4_ops = t4_ops[::-1]
print("edit script:", t4_ops)  # -> [('delete', 'f', ''), ('match', 'l', 'l'), ('match', 'a', 'a'), ('match', 'w', 'w'), ('insert', '', 'n')]
t4_edits = [t4_op for t4_op in t4_ops if t4_op[0] != "match"]
print("non-match edits:", t4_edits)  # -> [('delete', 'f', ''), ('insert', '', 'n')]
t4_distance = int(t4_T[-1, -1])
print("distance:", t4_distance)  # -> 2

plt.figure(figsize=(4.8, 2.8))
plt.imshow(t4_T, cmap="magma")
plt.colorbar(label="cost")
plt.title("Toy 4 · flaw → lawn table")
plt.xlabel("target prefix length")
plt.ylabel("source prefix length")
plt.show()
assert t4_distance == 2 and len(t4_edits) == 2
```
▶ What you'll see: one optimal explanation deletes `f`, keeps `law`, and inserts `n`.

### ✍️ Toy 5 · The cost model changes the optimal repair

Edit distance minimizes the prices you choose. Once substitution costs more than delete-plus-insert,
the distance stops rising because the algorithm takes the cheaper two-step route.
