# 11.30 — Meta-RL

Meta-RL trains an RL learner across a distribution of related tasks so it can adapt quickly when the current task changes. In this lesson, we build the idea from scratch with tiny bandit and tabular examples: returns measure delayed consequence, policies turn scores into action probabilities, inner-loop data adapts to one task, and the outer loop learns an update strategy that works well on new tasks.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build Meta-RL one idea at a time. Run each cell in order and read the printed intermediate values — every piece of math is inspectable, including fast adaptation, a task distribution, and two classic meta-RL views: RL² and MAML. This walkthrough is self-contained and uses a `_w` suffix on its variables so it never clashes with the examples below.

### 1. A task distribution, not one fixed task

Ordinary RL often starts with one environment. Meta-RL starts one level higher: tasks themselves are sampled from a distribution. In this toy lesson, each task is a two-armed bandit with a different hidden reward probability for each arm. The agent does not know which task it is in, so good behavior means using early experience to infer the current task quickly.

```python
tasks_w = np.array([[0.80, 0.20],   # task 0: arm 0 is good.
                    [0.20, 0.80],   # task 1: arm 1 is good.
                    [0.65, 0.35],   # task 2: arm 0 is mildly good.
                    [0.35, 0.65]])  # task 3: arm 1 is mildly good.
print("task table shape:", tasks_w.shape)  # 4 tasks x 2 actions.
print(tasks_w)  # each row is P(reward=1 | action) for one task.
assert tasks_w.shape == (4, 2)
```
▶ What you'll see: four related tasks with the same action space but different best arms.

```python
best_actions_w = np.argmax(tasks_w, axis=1)  # the hidden best action for each task.
print("best action per task:", best_actions_w)  # [0, 1, 0, 1].
plt.figure(figsize=(4.6, 3))
plt.imshow(tasks_w, cmap="viridis", vmin=0, vmax=1, aspect="auto")
plt.colorbar(label="P(reward=1)")
plt.xticks([0, 1], ["arm 0", "arm 1"]); plt.yticks(range(4), [f"task {i}" for i in range(4)])
plt.title("1: a distribution over related bandit tasks"); plt.show()
```
▶ What you'll see: tasks come in mirrored pairs; the meta-learner must infer which row it sampled.

*Why it's done this way:* Meta-RL optimizes expected performance over $\tau\sim p(\tau)$, not just over one MDP. The repeated structure across rows is the signal that can be reused: if early rewards suggest arm 1 is good, the agent should adapt toward arm 1 without relearning the entire problem from scratch.

### 2. Returns and value backups are the consequence ledger

Even in a tiny task, an action is not only an immediate reward; it changes what evidence and future rewards become available. The return $G_t=\sum_k\gamma^k r_{t+k}$ is the discounted ledger of those consequences. Bootstrapping uses a one-step target $y=r+\gamma V(s')$, trading lower variance for bias because the target includes the learner's own current estimate.

```python
rewards_w = np.array([1.0, 0.0, 2.0])  # a short reward stream.
gamma_w = 0.9  # future rewards count, but less than immediate rewards.
discounts_w = gamma_w ** np.arange(len(rewards_w))  # [1, gamma, gamma^2].
return_w = float(np.sum(discounts_w * rewards_w))  # discounted return.
print("discounts:", np.round(discounts_w, 3))
print("three-step return:", round(return_w, 3))
assert round(return_w, 3) == 2.620
```
▶ What you'll see: the delayed reward of 2 counts as 1.62 after two discount steps.

```python
r_w, next_v_w, old_q_w, alpha_w = 1.0, 0.8, 0.4, 0.5  # one observed transition and one old estimate.
target_w = r_w + gamma_w * next_v_w  # bootstrap target y = r + gamma V(s').
new_q_w = old_q_w + alpha_w * (target_w - old_q_w)  # move partway toward the target.
print("target:", round(target_w, 3), "updated Q:", round(new_q_w, 3))
assert round(target_w, 3) == 1.720 and round(new_q_w, 3) == 1.060
```
▶ What you'll see: the estimate moves halfway from 0.4 toward 1.72, landing at 1.06.

```python
plt.figure(figsize=(4.4, 3))
plt.bar(["old Q", "target", "new Q"], [old_q_w, target_w, new_q_w], color=["gray", "black", "seagreen"])
plt.ylabel("value"); plt.title("2: bootstrapping moves toward consequence"); plt.show()
```
▶ What you'll see: the new estimate sits between old belief and the one-step target.

*Why it's done this way:* Complete returns wait for full trajectories and can be noisy; one-step targets update immediately but depend on imperfect estimates. Meta-RL inherits this target-choice problem: the adaptation rule must decide how much to trust fresh evidence versus its learned prior.

### 3. Policies turn learned scores into action probabilities

A policy maps information to action probabilities. With logits $z$, softmax gives $\pi(a)=e^{z_a}/\sum_b e^{z_b}$, so changing one score changes probability mass and therefore expected reward. This is the bridge from value estimates to behavior.

```python
logits_w = np.array([1.0, 0.0])  # action scores before normalization.
exp_w = np.exp(logits_w - np.max(logits_w))  # stable softmax numerator.
pi_w = exp_w / exp_w.sum()  # probabilities that sum to 1.
print("policy probabilities:", np.round(pi_w, 3))
assert np.allclose(np.round(pi_w, 3), [0.731, 0.269])
```
▶ What you'll see: a one-logit advantage gives arm 0 about 73.1% probability.

```python
reward_means_w = np.array([2.0, 0.0])  # expected rewards under the two actions.
expected_reward_w = float(pi_w @ reward_means_w)  # policy-weighted consequence.
print("expected reward:", round(expected_reward_w, 3))
assert round(expected_reward_w, 3) == 1.462
```
▶ What you'll see: probability mass on the better action turns into expected reward 1.462.

```python
logit_grid_w = np.linspace(-3, 3, 80)
prob0_w = 1 / (1 + np.exp(-logit_grid_w))  # two-action softmax probability for action 0.
plt.figure(figsize=(4.6, 3))
plt.plot(logit_grid_w, prob0_w, color="purple")
plt.axvline(1.0, color="gray", linestyle="--")
plt.title("3: logits control action probability"); plt.xlabel("logit0 - logit1"); plt.ylabel("P(action 0)"); plt.show()
```
▶ What you'll see: a smooth S-curve; policy updates shift probability gradually, not as an all-or-nothing switch.

*Why it's done this way:* Softmax keeps exploration alive while still favoring high-score actions. In meta-RL, the policy input may include recent rewards and actions, so probability mass can move after only a few task-specific observations.

### 4. Fast adaptation inside one sampled task

The inner loop is task-specific learning. Here we sample one hidden bandit task, try both arms once, update Beta-Bernoulli beliefs, and then choose the arm with the larger posterior mean. This is a tiny hand-built adaptation rule: prior plus a few rewards becomes a task-specific policy.

```python
task_id_w = 0  # pretend this is the new task sampled from p(task).
true_probs_w = tasks_w[task_id_w]  # hidden reward probabilities for this task.
alpha_prior_w = np.array([1.0, 1.0])  # Beta successes + 1 for each arm.
beta_prior_w = np.array([1.0, 1.0])  # Beta failures + 1 for each arm.
print("hidden task reward probs:", true_probs_w)
print("prior means:", alpha_prior_w / (alpha_prior_w + beta_prior_w))
```
▶ What you'll see: before data, both arms have posterior mean 0.5.

```python
probe_actions_w = np.array([0, 0, 1, 1])  # a small exploratory adaptation batch.
probe_rewards_w = np.array([1, 1, 0, 0])  # deterministic sample chosen to make the update inspectable.
alpha_post_w = alpha_prior_w.copy(); beta_post_w = beta_prior_w.copy()
for a_w, r_w in zip(probe_actions_w, probe_rewards_w):
    alpha_post_w[a_w] += r_w  # successes raise alpha.
    beta_post_w[a_w] += 1 - r_w  # failures raise beta.
posterior_means_w = alpha_post_w / (alpha_post_w + beta_post_w)
print("posterior means after probes:", np.round(posterior_means_w, 3))
assert np.allclose(np.round(posterior_means_w, 3), [0.75, 0.25])
```
▶ What you'll see: after four probes, the adapted belief strongly favors arm 0.

```python
adapted_action_w = int(np.argmax(posterior_means_w))
print("adapted greedy action:", adapted_action_w)
plt.figure(figsize=(4.4, 3))
plt.bar(["arm 0", "arm 1"], posterior_means_w, color=["seagreen", "gray"])
plt.ylim(0, 1); plt.ylabel("posterior mean"); plt.title("4: fast task-specific adaptation"); plt.show()
assert adapted_action_w == 0
```
▶ What you'll see: the posterior bar for arm 0 is much taller, so the adapted policy chooses it.

*Why it's done this way:* Fast adaptation is not magic; it is an update rule with a useful prior. The prior says tasks are similar enough that a few observations are meaningful, and the posterior mean is the mathematical compromise between prior counts and task-specific evidence.

### 5. MAML-style meta-learning: learn an initialization that adapts well

MAML frames meta-RL as learning parameters $\theta$ that become good after one or a few inner updates. To keep the math transparent, we use a one-parameter bandit policy: $\theta$ is the logit advantage for arm 0. A task-specific gradient step moves $\theta$ toward the arm that paid off; the meta-objective asks whether the post-step parameter performs well on held-out rewards from the same task.

```python
def sigmoid_w(x_w):
    return 1 / (1 + np.exp(-x_w))

def maml_inner_step_w(theta_w, chosen_arm_w, reward_w, lr_w=0.8):
    p0_w = sigmoid_w(theta_w)  # policy probability of arm 0.
    indicator_w = 1.0 if chosen_arm_w == 0 else 0.0
    grad_logp_w = indicator_w - p0_w  # derivative of log pi(a) wrt theta.
    return theta_w + lr_w * reward_w * grad_logp_w  # reinforce rewarded action.

theta0_w = 0.0  # meta-initialization: no arm preference.
theta_after_w = maml_inner_step_w(theta0_w, chosen_arm_w=0, reward_w=1.0)
print("theta before:", theta0_w, "theta after one rewarded arm-0 step:", round(theta_after_w, 3))
assert round(theta_after_w, 3) == 0.400
```
▶ What you'll see: one rewarded arm-0 sample moves the logit advantage from 0.0 to 0.4.

```python
def expected_bandit_reward_w(theta_w, probs_w):
    p0_w = sigmoid_w(theta_w)
    return float(p0_w * probs_w[0] + (1 - p0_w) * probs_w[1])

before_reward_w = expected_bandit_reward_w(theta0_w, tasks_w[0])
after_reward_w = expected_bandit_reward_w(theta_after_w, tasks_w[0])
print("expected reward before/after:", round(before_reward_w, 3), round(after_reward_w, 3))
assert after_reward_w > before_reward_w
```
▶ What you'll see: expected reward rises on task 0 after the inner update.

```python
theta_grid_w = np.linspace(-2, 2, 80)
post_rewards_w = []
for th_w in theta_grid_w:
    th0_w = maml_inner_step_w(th_w, 0, 1.0)
    th1_w = maml_inner_step_w(th_w, 1, 1.0)
    post_rewards_w.append(0.5 * expected_bandit_reward_w(th0_w, tasks_w[0]) +
                          0.5 * expected_bandit_reward_w(th1_w, tasks_w[1]))
post_rewards_w = np.array(post_rewards_w)
best_theta_w = float(theta_grid_w[np.argmax(post_rewards_w)])
print("best symmetric initialization on grid:", round(best_theta_w, 3))
plt.figure(figsize=(4.8, 3))
plt.plot(theta_grid_w, post_rewards_w, color="teal")
plt.axvline(best_theta_w, color="crimson", linestyle="--")
plt.title("5: meta-objective after one adaptation step"); plt.xlabel("initial theta"); plt.ylabel("post-update expected reward"); plt.show()
```
▶ What you'll see: the best initialization is near neutral because tasks can favor either arm.

*Why it's done this way:* MAML does not merely learn a good fixed policy; it learns a starting point whose gradient is informative. A neutral initialization is valuable here because it can move either direction after one reward, while an overcommitted initialization would adapt slowly on the opposite task.

### 6. RL²: learn to use history as the adaptation state

RL² views the entire learning algorithm as part of the policy's recurrent state. Instead of writing an explicit posterior table, the policy receives previous action and reward, stores them in memory, and conditions the next action on that history. We can mimic the idea with a tiny hand-written recurrent statistic: a running score `memory = rewards_after_arm0 - rewards_after_arm1`.

```python
history_actions_w = np.array([0, 1, 0, 1, 0])  # previous actions within one episode.
history_rewards_w = np.array([1, 0, 1, 0, 1])  # previous rewards from the sampled task.
memory_w = 0.0
mem_trace_w = []
for a_w, r_w in zip(history_actions_w, history_rewards_w):
    memory_w += r_w if a_w == 0 else -r_w  # rewarded arm 0 raises memory; rewarded arm 1 lowers it.
    mem_trace_w.append(memory_w)
print("memory trace:", mem_trace_w)
assert mem_trace_w[-1] == 3.0
```
▶ What you'll see: the memory becomes positive because rewards followed arm 0.

```python
policy_p0_w = sigmoid_w(1.2 * memory_w)  # recurrent state becomes a policy logit.
print("P(next action is arm 0):", round(policy_p0_w, 3))
assert round(policy_p0_w, 3) == 0.973
plt.figure(figsize=(4.6, 3))
plt.plot(range(1, len(mem_trace_w) + 1), mem_trace_w, marker="o", color="purple")
plt.axhline(0, color="black", linewidth=0.7)
plt.title("6: RL²-style memory summarizes within-task evidence"); plt.xlabel("within-task step"); plt.ylabel("memory"); plt.show()
```
▶ What you'll see: the memory trace climbs above zero, making the next policy strongly prefer arm 0.

*Why it's done this way:* RL² learns a recurrent update rule from data rather than hand-coding Bayes or Q-learning. The hidden state is allowed to become the task belief, so adaptation happens in activations at test time instead of in explicitly changed model weights.

## 🛠️ Setup

```python
import numpy as np  # Import NumPy for arrays, probabilities, gradients, and toy RL simulations.
import matplotlib.pyplot as plt  # Import Matplotlib for bandit, policy, and learning-curve visualizations.
np.random.seed(0)  # Fix the global random seed so all stochastic examples are reproducible.

def softmax(logits):  # Convert action logits into a probability distribution.
    logits = np.asarray(logits, dtype=float)  # Ensure numeric array behavior.
    exps = np.exp(logits - np.max(logits))  # Subtract max for numerical stability.
    return exps / exps.sum()  # Normalize exponentials so probabilities sum to one.

def discounted_return(rewards, gamma):  # Compute G = sum gamma^t r_t for a reward sequence.
    rewards = np.asarray(rewards, dtype=float)  # Convert inputs to floats.
    return float(np.sum((gamma ** np.arange(len(rewards))) * rewards))  # Weighted sum of rewards.

def sigmoid(x):  # Logistic function for a two-action policy parameter.
    return 1 / (1 + np.exp(-x))  # Map a logit advantage to probability of action 0.

def bandit_expected(theta, probs):  # Expected reward of a two-arm sigmoid policy.
    p0 = sigmoid(theta)  # Probability of choosing arm 0.
    return float(p0 * probs[0] + (1 - p0) * probs[1])  # Policy-weighted reward probability.

def beta_means(alpha, beta):  # Posterior means for independent Bernoulli arms.
    return alpha / (alpha + beta)  # E[p] for Beta(alpha, beta).
```

rewards_b2 = np.array([1.0, 0.0, 2.0])  # Define a short reward sequence.

### Basic 7 — Update a Beta belief for one arm

**Goal.** Track successes and failures for a Bernoulli arm, because fast adaptation can be expressed as posterior belief updating. We build it in 2 steps.

```python
alpha_b7 = 1.0  # Prior success count plus one.
beta_b7 = 1.0  # Prior failure count plus one.
rewards_b7 = np.array([1, 1, 0])  # Observed rewards for one arm.
print("prior mean:", alpha_b7 / (alpha_b7 + beta_b7))  # Inspect neutral prior.
```

alpha_post_b7 = alpha_b7 + np.sum(rewards_b7)  # Add successes.
beta_post_b7 = beta_b7 + len(rewards_b7) - np.sum(rewards_b7)  # Add failures.
mean_post_b7 = alpha_post_b7 / (alpha_post_b7 + beta_post_b7)  # Posterior mean.

plt.bar(["prior", "posterior"], [0.5, mean_post_b7], color=["gray", "green"])  # Show belief movement.

plt.title("Basic 7: Beta belief update")  # Title the plot.
plt.show()  # Display the chart.
```
▶ What you'll see: two successes and one failure move the mean from 0.5 to 0.6.

👀 Takeaway: a Bayesian update is one transparent form of fast task adaptation.

### Basic 8 — Choose after probing both arms

**Goal.** Adapt a policy from a tiny probe batch, because Meta-RL must use early experience to choose better later. We build it in 2 steps.

    mem_a5 += r_a5 if a_a5 == 0 else -r_a5  # Update RL²-style memory.
    memory_trace_a5.append(mem_a5)  # Store memory.
    posterior_gap_a5.append(means_a5[0] - means_a5[1])  # Store belief gap.
print("final memory:", memory_trace_a5[-1], "final posterior gap:", round(posterior_gap_a5[-1], 3))  # Inspect summaries.
```
