# 21.4 — Description Logics

Description logics (DLs) are the careful, decidable core behind ontology reasoners: concepts are sets of individuals, roles are binary relations, and axioms let us classify new facts while checking consistency. In this lesson, we build a tiny ALC-style reasoner from scratch so each inference is visible: concepts and roles, TBox versus ABox, constructors such as intersection and existential restriction, subsumption, tableau satisfiability, and the open-world assumption.

### 1. Concepts, roles, and individuals as sets and pairs

A description logic interpretation starts with **individuals** (objects in the world), **concepts** (sets of individuals), and **roles** (binary relations between individuals). If `Professor` is a concept, its extension is the set of people classified as professors. If `hasChild` is a role, its extension is a set of ordered pairs like `(ann, cal)`. Reasoning begins by making these extensions explicit.

```python
people_w = ["Ada", "Bo", "Cy", "Dee"]  # individuals in the toy domain.
concepts_w = {
    "Professor": {"Ada", "Cy"},
    "Student": {"Bo", "Cy"},
    "Person": {"Ada", "Bo", "Cy", "Dee"},
    "Employee": {"Ada", "Cy"},
}
roles_w = {"hasChild": {("Ada", "Dee"), ("Bo", "Cy")}}  # role pairs.
print("domain:", people_w)
print("Professor extension:", sorted(concepts_w["Professor"]))
print("hasChild pairs:", sorted(roles_w["hasChild"]))
```
▶ What you'll see: concepts are ordinary sets of individuals, while roles are ordered pairs connecting individuals.

```python
M_w = np.array([[1 if p in concepts_w[c] else 0 for c in ["Professor", "Student", "Employee"]] for p in people_w])
plt.figure(figsize=(4.4, 3))
plt.imshow(M_w, cmap="Greens", aspect="auto")
plt.xticks(range(3), ["Professor", "Student", "Employee"])
plt.yticks(range(4), people_w)
plt.title("1: concept membership matrix")
plt.colorbar(label="is member")
plt.show()
```
▶ What you'll see: Cy belongs to multiple concepts, showing that DL concepts are not mutually exclusive unless axioms say so.

*Why it's done this way:* Set membership is the semantic anchor for every later rule. By representing concepts as sets and roles as pairs, subsumption becomes subset checking, conjunction becomes set intersection, and existential restrictions become relation traversal.

### 2. TBox versus ABox: schema rules versus facts

DL knowledge bases split meaning into a **TBox** and an **ABox**. The TBox contains terminology such as `Professor ⊑ Person` or `Professor ⊑ Employee`; it defines the class hierarchy. The ABox contains assertions about named individuals such as `Professor(Ada)` or `hasChild(Bo,Cy)`. A reasoner combines them by propagating TBox implications over ABox facts.

```python
tbox_w = [("Professor", "Person"), ("Professor", "Employee"), ("Student", "Person")]
abox_types_w = {"Ada": {"Professor"}, "Bo": {"Student"}, "Cy": {"Professor", "Student"}, "Dee": set()}
print("TBox inclusions:", tbox_w)
print("ABox before closure:", {k: sorted(v) for k, v in abox_types_w.items()})
```
▶ What you'll see: the TBox stores general inclusions, while the ABox stores individual type claims.

```python
closed_w = {name: set(types) for name, types in abox_types_w.items()}
changed_w = True
while changed_w:
    changed_w = False
    for ind_w, types_w in closed_w.items():
        for sub_w, sup_w in tbox_w:
            if sub_w in types_w and sup_w not in types_w:
                types_w.add(sup_w)
                changed_w = True
print("ABox after TBox closure:", {k: sorted(v) for k, v in closed_w.items()})
assert "Person" in closed_w["Ada"] and "Employee" in closed_w["Cy"]
```
▶ What you'll see: Ada and Cy inherit `Person` and `Employee` from `Professor`, while Bo inherits `Person` from `Student`.

*Why it's done this way:* Separating schema from facts lets one general axiom classify many individuals. We do not duplicate `Person(Ada)` in every dataset; we state the hierarchy once and let closure compute the consequences.

### 3. ALC constructors: AND, OR, NOT, EXISTS, and FORALL

ALC builds complex descriptions from atomic concepts. `AND` means intersection, `OR` means union, `NOT` means complement, `EXISTS R.C` means individuals with at least one `R`-successor in `C`, and `FORALL R.C` means all known `R`-successors are in `C` under a finite interpretation. We can evaluate each constructor directly over sets.

```python
def And_w(*cs): return ("and",) + cs

def Or_w(*cs): return ("or",) + cs

def Not_w(c): return ("not", c)

def Exists_w(r, c): return ("exists", r, c)

def Forall_w(r, c): return ("forall", r, c)

def eval_w(expr_w, domain_w, concept_ext_w, role_ext_w):
    if isinstance(expr_w, str):
        return set(concept_ext_w.get(expr_w, set()))
    op_w = expr_w[0]
    if op_w == "and":
        out_w = set(domain_w)
        for part_w in expr_w[1:]:
            out_w &= eval_w(part_w, domain_w, concept_ext_w, role_ext_w)
        return out_w
    if op_w == "or":
        out_w = set()
        for part_w in expr_w[1:]:
            out_w |= eval_w(part_w, domain_w, concept_ext_w, role_ext_w)
        return out_w
    if op_w == "not":
        return set(domain_w) - eval_w(expr_w[1], domain_w, concept_ext_w, role_ext_w)
    if op_w == "exists":
        r_w, c_w = expr_w[1], expr_w[2]
        target_w = eval_w(c_w, domain_w, concept_ext_w, role_ext_w)
        return {a_w for a_w, b_w in role_ext_w.get(r_w, set()) if b_w in target_w}
    if op_w == "forall":
        r_w, c_w = expr_w[1], expr_w[2]
        target_w = eval_w(c_w, domain_w, concept_ext_w, role_ext_w)
        return {a_w for a_w in domain_w if all(b_w in target_w for x_w, b_w in role_ext_w.get(r_w, set()) if x_w == a_w)}
```
▶ What you'll see: no output yet; the cell defines the constructor evaluator used by the next cells.

```python
student_employee_w = And_w("Student", "Employee")
parent_of_student_w = Exists_w("hasChild", "Student")
all_children_people_w = Forall_w("hasChild", "Person")
print("Student AND Employee:", sorted(eval_w(student_employee_w, people_w, concepts_w, roles_w)))
print("EXISTS hasChild.Student:", sorted(eval_w(parent_of_student_w, people_w, concepts_w, roles_w)))
print("FORALL hasChild.Person:", sorted(eval_w(all_children_people_w, people_w, concepts_w, roles_w)))
assert eval_w(student_employee_w, people_w, concepts_w, roles_w) == {"Cy"}
assert eval_w(parent_of_student_w, people_w, concepts_w, roles_w) == {"Bo"}
```
▶ What you'll see: Cy is both student and employee; Bo has a child who is a student; everyone with only person-valued children satisfies the universal restriction.

*Why it's done this way:* ALC limits the grammar to constructors whose set semantics are simple and whose satisfiability can be decided. That restriction is the tradeoff: less freedom than full first-order logic, but reliable classification algorithms.

### 4. Subsumption as set containment and hierarchy drawing

A concept `C` is **subsumed** by concept `D`, written `C ⊑ D`, when every possible instance of `C` is also an instance of `D`. In a finite interpretation, that is just `C^I ⊆ D^I`. Ontology classifiers scale this idea: compute which named concepts sit below which others, then expose the hierarchy for search and validation.

```python
def subsumes_w(sub_w, sup_w, domain_w, concept_ext_w, role_ext_w):
    left_w = eval_w(sub_w, domain_w, concept_ext_w, role_ext_w)
    right_w = eval_w(sup_w, domain_w, concept_ext_w, role_ext_w)
    return left_w <= right_w, left_w, right_w

checks_w = [("Professor", "Person"), ("Student", "Employee"), (And_w("Student", "Employee"), "Person")]
for sub_w, sup_w in checks_w:
    ok_w, left_w, right_w = subsumes_w(sub_w, sup_w, people_w, concepts_w, roles_w)
    print(f"{sub_w} ⊑ {sup_w}?", ok_w, "because", sorted(left_w), "⊆", sorted(right_w))
assert subsumes_w("Professor", "Person", people_w, concepts_w, roles_w)[0]
assert not subsumes_w("Student", "Employee", people_w, concepts_w, roles_w)[0]
```
▶ What you'll see: `Professor ⊑ Person` holds, but `Student ⊑ Employee` fails because Bo is a student and not an employee.

```python
edges_w = [("Thing", "Person"), ("Person", "Professor"), ("Person", "Student"), ("Person", "Employee")]
pos_w = {"Thing": (1.5, 3), "Person": (1.5, 2), "Professor": (0.3, 1), "Student": (1.5, 1), "Employee": (2.7, 1)}
plt.figure(figsize=(5, 3.4))
for parent_w, child_w in edges_w:
    x1_w, y1_w = pos_w[parent_w]
    x2_w, y2_w = pos_w[child_w]
    plt.plot([x1_w, x2_w], [y1_w, y2_w], color="gray")
for node_w, (x_w, y_w) in pos_w.items():
    plt.scatter([x_w], [y_w], s=700, color="lightblue", edgecolor="black")
    plt.text(x_w, y_w, node_w, ha="center", va="center")
plt.axis("off")
plt.title("4: a tiny concept-subsumption hierarchy")
plt.show()
```
▶ What you'll see: `Professor`, `Student`, and `Employee` appear below `Person`, reflecting inherited membership.

*Why it's done this way:* Subsumption is the classifier's main product. Drawing it as a hierarchy makes inheritance explainable: if a query asks for `Person`, every descendant concept can safely contribute results.

### 5. Tableau satisfiability: expanding constraints until clash or open branch

A concept is **satisfiable** if some interpretation can contain an individual that belongs to it. A tableau reasoner tries to build that interpretation syntactically: split `AND` constraints into both parts, branch on `OR`, create a fresh successor for `EXISTS R.C`, and push `FORALL R.C` constraints to known `R`-successors. A branch closes if it contains both `A` and `NOT A` for some atom.

```python
def atom_w(name_w): return name_w

def nnf_w(c_w):
    if isinstance(c_w, str):
        return c_w
    op_w = c_w[0]
    if op_w == "not":
        x_w = c_w[1]
        if isinstance(x_w, str):
            return ("not", x_w)
        if x_w[0] == "not":
            return nnf_w(x_w[1])
        if x_w[0] == "and":
            return Or_w(*[nnf_w(Not_w(p_w)) for p_w in x_w[1:]])
        if x_w[0] == "or":
            return And_w(*[nnf_w(Not_w(p_w)) for p_w in x_w[1:]])
        if x_w[0] == "exists":
            return Forall_w(x_w[1], nnf_w(Not_w(x_w[2])))
        if x_w[0] == "forall":
            return Exists_w(x_w[1], nnf_w(Not_w(x_w[2])))
    if op_w in ("and", "or"):
        return (op_w,) + tuple(nnf_w(p_w) for p_w in c_w[1:])
    if op_w in ("exists", "forall"):
        return (op_w, c_w[1], nnf_w(c_w[2]))

def has_clash_w(labels_w):
    for node_w, labs_w in labels_w.items():
        atoms_w = {x_w for x_w in labs_w if isinstance(x_w, str)}
        negs_w = {x_w[1] for x_w in labs_w if isinstance(x_w, tuple) and x_w[0] == "not" and isinstance(x_w[1], str)}
        if atoms_w & negs_w:
            return True, node_w, sorted(atoms_w & negs_w)[0]
    return False, None, None
```
▶ What you'll see: no output yet; these helpers normalize negation and detect contradictions.

```python
def tableau_w(start_w, max_steps_w=30):
    stack_w = [({0: {nnf_w(start_w)}}, [], ["start with node 0"])]
    last_closed_w = None
    while stack_w:
        labels_w, edges_w, log_w = stack_w.pop()
        for step_w in range(max_steps_w):
            clash_w, node_w, atom_name_w = has_clash_w(labels_w)
            if clash_w:
                last_closed_w = (labels_w, edges_w, log_w + [f"clash at node {node_w}: {atom_name_w} and not {atom_name_w}"])
                break
            changed_w = False
            branched_w = False
            for n_w in list(labels_w):
                for c_w in list(labels_w[n_w]):
                    if isinstance(c_w, tuple) and c_w[0] == "and":
                        labels_w[n_w].remove(c_w)
                        labels_w[n_w].update(c_w[1:])
                        log_w.append(f"AND expands at node {n_w}")
                        changed_w = True
                        break
                    if isinstance(c_w, tuple) and c_w[0] == "or":
                        for part_w in reversed(c_w[1:]):
                            labels_branch_w = {k_w: set(v_w) for k_w, v_w in labels_w.items()}
                            labels_branch_w[n_w].remove(c_w)
                            labels_branch_w[n_w].add(part_w)
                            stack_w.append((labels_branch_w, list(edges_w), log_w + [f"OR branches at node {n_w}"]))
                        branched_w = True
                        changed_w = True
                        break
                    if isinstance(c_w, tuple) and c_w[0] == "exists":
                        r_w, filler_w = c_w[1], c_w[2]
                        new_w = max(labels_w) + 1
                        labels_w[new_w] = {filler_w}
                        edges_w.append((n_w, r_w, new_w))
                        labels_w[n_w].remove(c_w)
                        log_w.append(f"EXISTS creates node {new_w} via {r_w}")
                        changed_w = True
                        break
                    if isinstance(c_w, tuple) and c_w[0] == "forall":
                        r_w, filler_w = c_w[1], c_w[2]
                        pushed_w = False
                        for a_w, rr_w, b_w in edges_w:
                            if a_w == n_w and rr_w == r_w and filler_w not in labels_w[b_w]:
                                labels_w[b_w].add(filler_w)
                                pushed_w = True
                        if pushed_w:
                            log_w.append(f"FORALL pushes along {r_w}")
                            changed_w = True
                            break
                if changed_w:
                    break
            if branched_w:
                break
            if not changed_w:
                return True, labels_w, edges_w, log_w + ["open saturated branch"]
        else:
            last_closed_w = (labels_w, edges_w, log_w + ["step limit reached"])
    labels_w, edges_w, log_w = last_closed_w
    return False, labels_w, edges_w, log_w
```
▶ What you'll see: no output yet; the tableau function applies expansion rules until it finds a clash or an open branch.

```python
unsat_w = And_w("Cat", Not_w("Cat"))
sat_w = And_w(Exists_w("hasPet", "Cat"), Forall_w("hasPet", "Animal"))
for name_w, expr_w in [("Cat AND not Cat", unsat_w), ("hasPet some Cat AND all pets Animal", sat_w)]:
    ok_w, labels2_w, edges2_w, log2_w = tableau_w(expr_w)
    print(name_w, "satisfiable?", ok_w)
    print("  log:", " | ".join(log2_w))
assert tableau_w(unsat_w)[0] is False
assert tableau_w(sat_w)[0] is True
```
▶ What you'll see: the contradiction closes immediately, while the existential/universal example creates a successor and stays open.

```python
ok_tree_w, labels_tree_w, edges_tree_w, log_tree_w = tableau_w(sat_w)
pos_tree_w = {0: (0, 1), 1: (1.8, 0)}
plt.figure(figsize=(5, 2.8))
for a_w, r_w, b_w in edges_tree_w:
    plt.plot([pos_tree_w[a_w][0], pos_tree_w[b_w][0]], [pos_tree_w[a_w][1], pos_tree_w[b_w][1]], color="gray")
    plt.text(0.9, 0.55, r_w, ha="center")
for n_w, labs_w in labels_tree_w.items():
    x_w, y_w = pos_tree_w[n_w]
    label_w = "\n".join([str(z_w) for z_w in labs_w])
    plt.scatter([x_w], [y_w], s=900, color="mistyrose", edgecolor="black")
    plt.text(x_w, y_w, f"x{n_w}\n{label_w}", ha="center", va="center", fontsize=8)
plt.axis("off")
plt.title("5: tableau expansion tree")
plt.show()
```
▶ What you'll see: one root creates one role successor; the universal rule labels that successor with `Animal`.

*Why it's done this way:* Tableau reasoning searches for a model rather than enumerating a fixed database. If every possible branch clashes, the concept is impossible; if at least one saturated branch stays open, the concept has a model.

### 6. The open-world assumption: unknown is not false

Description logics normally use the **open-world assumption**: absence of a fact does not prove its negation. If we do not know whether Ada has a doctor child, `EXISTS hasChild.Doctor(Ada)` is not false; it is simply not entailed. This is different from a closed database query, where missing rows are often treated as false.

```python
known_doctors_w = {"Cy"}
known_children_w = {("Ada", "Dee")}  # Ada has one known child, but the knowledge base may be incomplete.
closed_world_has_doctor_child_w = any(parent_w == "Ada" and child_w in known_doctors_w for parent_w, child_w in known_children_w)
print("closed-world answer from current rows:", closed_world_has_doctor_child_w)
```
▶ What you'll see: the current rows do not prove that Ada has a doctor child.

```python
candidate_model_w = set(known_children_w) | {("Ada", "Cy")}
open_world_consistent_w = known_children_w <= candidate_model_w and "Cy" in known_doctors_w
print("open-world model can add Ada→Cy?", open_world_consistent_w)
assert open_world_consistent_w
plt.figure(figsize=(4.8, 2.8))
plt.bar(["known rows", "possible model"], [len(known_children_w), len(candidate_model_w)], color=["gray", "teal"])
plt.title("6: open world allows additional facts")
plt.ylabel("hasChild pairs")
plt.show()
```
▶ What you'll see: a larger model can contain all known facts plus an extra child relation, so the missing row was not evidence of falsity.

*Why it's done this way:* Ontologies often describe incomplete enterprise or web data. Open-world semantics avoids overclaiming: reasoners report what is entailed by the axioms, not everything that happens to be absent from today's dataset.

### ✍️ Toy 2 · TBox closure propagates schema facts into the ABox

TBox inclusions are general rules; ABox closure applies them to named individuals until no new types
appear.

```python
import numpy as np  # closure-count bars.

t2_rng = np.random.default_rng(0)  # seeded generator for reproducibility.
t2_tbox = [("Professor", "Person"), ("Student", "Person"), ("Professor", "Employee")]  # inclusions.
t2_abox = {"Ada": {"Professor"}, "Bo": {"Student"}, "Cy": set()}  # initial assertions.
t2_before = {t2_key: sorted(t2_val) for t2_key, t2_val in t2_abox.items()}  # printable start.
t2_closed = {t2_key: set(t2_val) for t2_key, t2_val in t2_abox.items()}  # mutable closure.
t2_changed = True  # loop flag.
while t2_changed:
    t2_changed = False
    for t2_ind, t2_types in t2_closed.items():
        for t2_sub, t2_sup in t2_tbox:
            if t2_sub in t2_types and t2_sup not in t2_types:
                t2_types.add(t2_sup)
                t2_changed = True
t2_after = {t2_key: sorted(t2_val) for t2_key, t2_val in t2_closed.items()}  # printable closure.
t2_added = np.array([len(t2_closed[t2_ind]) - len(t2_abox[t2_ind]) for t2_ind in ["Ada", "Bo", "Cy"]])  # inferred type counts.
print("TBox:", t2_tbox)  # -> [('Professor', 'Person'), ('Student', 'Person'), ('Professor', 'Employee')]
print("ABox before:", t2_before)  # -> {'Ada': ['Professor'], 'Bo': ['Student'], 'Cy': []}
print("ABox after:", t2_after)  # -> {'Ada': ['Employee', 'Person', 'Professor'], 'Bo': ['Person', 'Student'], 'Cy': []}
print("added counts:", t2_added.tolist())  # -> [2, 1, 0]
assert "Employee" in t2_closed["Ada"] and "Person" in t2_closed["Bo"] and t2_added.tolist() == [2, 1, 0]

plt.figure(figsize=(4.4, 2.8))
plt.bar(["Ada", "Bo", "Cy"], t2_added, color="darkorange")
plt.ylabel("inferred types")
plt.title("Toy 2 · TBox closure additions")
plt.tight_layout()
plt.show()
```
▶ What you'll see: Ada gains two schema-implied types and Bo gains one.

### ✍️ Toy 3 · ALC constructors are set operations

AND intersects concepts, NOT complements them, EXISTS follows role pairs, and FORALL checks every
known successor.

```python
import numpy as np  # constructor output sizes.

t3_rng = np.random.default_rng(0)  # seeded generator for reproducibility.
t3_domain = ["Ada", "Bo", "Cy"]  # finite domain.  # -> ['Ada', 'Bo', 'Cy']
t3_student = {"Bo", "Cy"}  # Student extension.  # -> {'Bo', 'Cy'}
t3_employee = {"Ada", "Cy"}  # Employee extension.  # -> {'Ada', 'Cy'}
t3_person = {"Ada", "Bo", "Cy"}  # Person extension.  # -> {'Ada', 'Bo', 'Cy'}
t3_has_child = {("Ada", "Cy"), ("Bo", "Ada")}  # role pairs.
t3_and = t3_student & t3_employee  # Student AND Employee.  # -> {'Cy'}
t3_not_student = set(t3_domain) - t3_student  # NOT Student.  # -> {'Ada'}
t3_exists = {t3_parent for t3_parent, t3_child in t3_has_child if t3_child in t3_student}  # EXISTS hasChild.Student.  # -> {'Ada'}
t3_forall = {t3_obj for t3_obj in t3_domain if all(t3_child in t3_person for t3_parent, t3_child in t3_has_child if t3_parent == t3_obj)}  # FORALL hasChild.Person.
```

## 🛠️ Setup

```python
import numpy as np # load NumPy for arrays, small matrices, and deterministic checks.
import matplotlib.pyplot as plt # load Matplotlib so concept extensions, hierarchies, and tableau trees can be inspected visually.
np.random.seed(0) # make all examples reproducible across notebook runs.

def And(*cs): return ("and",) + tuple(cs) # Build an ALC conjunction C ⊓ D from child concepts.
def Or(*cs): return ("or",) + tuple(cs) # Build an ALC disjunction C ⊔ D from child concepts.
def Not(c): return ("not", c) # Build an ALC negation ¬C.
def Exists(r, c): return ("exists", r, c) # Build an existential restriction ∃r.C.
def Forall(r, c): return ("forall", r, c) # Build a universal restriction ∀r.C.

def eval_concept(expr, domain, concepts, roles): # Evaluate an ALC concept as a set in one finite interpretation.
    if isinstance(expr, str): # Atomic concept case.
        return set(concepts.get(expr, set())) # Return the named extension, or empty if unknown in this finite model.
    op = expr[0] # Read the constructor tag.
    if op == "and": # Conjunction means intersection.
        out = set(domain) # Start from the full domain for repeated intersection.
        for part in expr[1:]: out &= eval_concept(part, domain, concepts, roles) # Keep only individuals in every part.
        return out # Return C ⊓ D extension.
    if op == "or": # Disjunction means union.
        out = set() # Start empty for repeated union.
        for part in expr[1:]: out |= eval_concept(part, domain, concepts, roles) # Add individuals from any part.
        return out # Return C ⊔ D extension.
    if op == "not": return set(domain) - eval_concept(expr[1], domain, concepts, roles) # Complement relative to the domain.
    if op == "exists": # Existential restriction follows role edges to a filler concept.
        r, filler = expr[1], expr[2] # Unpack the role name and filler concept.
        target = eval_concept(filler, domain, concepts, roles) # Evaluate the filler set.
        return {a for a, b in roles.get(r, set()) if b in target} # Keep sources with at least one filler successor.
    if op == "forall": # Universal restriction checks all known successors in the finite model.
        r, filler = expr[1], expr[2] # Unpack role and filler.
        target = eval_concept(filler, domain, concepts, roles) # Evaluate the required successor set.
        return {a for a in domain if all(b in target for x, b in roles.get(r, set()) if x == a)} # Vacuously true when no successors are known.

def subsumes(sub, sup, domain, concepts, roles): # Check finite-model subsumption by subset containment.
    return eval_concept(sub, domain, concepts, roles) <= eval_concept(sup, domain, concepts, roles) # Return whether sub^I is contained in sup^I.

def close_abox(types, tbox): # Propagate simple atomic inclusions over individual type assertions.
    out = {name: set(vals) for name, vals in types.items()} # Copy input facts so callers keep their originals.
    changed = True # Track whether another closure pass is needed.
    while changed: # Repeat until no new inherited type appears.
        changed = False # Assume this pass is stable unless an axiom fires.
        for vals in out.values(): # For every individual's type set.
            for sub, sup in tbox: # For every simple inclusion sub ⊑ sup.
                if sub in vals and sup not in vals: # If the individual has the subclass but not the superclass.
                    vals.add(sup); changed = True # Add the inherited superclass and continue.
    return out # Return the closed ABox.

def nnf(c): # Convert a concept to negation-normal form for the tableau examples.
    if isinstance(c, str): return c # Atomic concepts are already normalized.
    op = c[0] # Read the constructor tag.
    if op == "not": # Push negation inward.
        x = c[1] # Inspect the negated expression.
        if isinstance(x, str): return ("not", x) # Atomic negation is allowed in NNF.
        if x[0] == "not": return nnf(x[1]) # Double negation cancels.
        if x[0] == "and": return Or(*[nnf(Not(p)) for p in x[1:]]) # De Morgan: ¬(C⊓D)=¬C⊔¬D.
        if x[0] == "or": return And(*[nnf(Not(p)) for p in x[1:]]) # De Morgan: ¬(C⊔D)=¬C⊓¬D.
        if x[0] == "exists": return Forall(x[1], nnf(Not(x[2]))) # ¬∃r.C = ∀r.¬C.
        if x[0] == "forall": return Exists(x[1], nnf(Not(x[2]))) # ¬∀r.C = ∃r.¬C.
    if op in ("and", "or"): return (op,) + tuple(nnf(p) for p in c[1:]) # Normalize every Boolean child.
    if op in ("exists", "forall"): return (op, c[1], nnf(c[2])) # Normalize the role filler.

def tableau(concept, max_steps=40): # Run a tiny ALC tableau, including real branching for OR concepts.
    stack = [({0: {nnf(concept)}}, [], ["start"])] # Store branches as labels, edges, and explanation log.
    last_closed = None # Remember a closed branch to return if every branch closes.
    while stack: # Explore branches until an open saturated branch is found or all close.
        labels, edges, log = stack.pop() # Take one branch from the search stack.
        for _ in range(max_steps): # Bound each toy branch so mistakes cannot loop forever.
            for n, labs in labels.items(): # Look for an atomic clash on any node.
                atoms = {x for x in labs if isinstance(x, str)} # Positive atom labels.
                negs = {x[1] for x in labs if isinstance(x, tuple) and x[0] == "not" and isinstance(x[1], str)} # Negated atom labels.
                if atoms & negs: # Closed branch: A and ¬A.
                    last_closed = (labels, edges, log + ["clash"]) # Save the closed branch.
                    break # Stop expanding this branch.
            else: # No clash was found, so try one expansion rule.
                changed = False # Track whether a rule fired.
                branched = False # Track whether OR created new stack branches.
                for n in list(labels): # Search nodes for the next expandable formula.
                    for c in list(labels[n]): # Search this node's labels.
                        if isinstance(c, tuple) and c[0] == "and": # C⊓D adds all parts to the same node.
                            labels[n].remove(c); labels[n].update(c[1:]); log.append("and"); changed = True; break
                        if isinstance(c, tuple) and c[0] == "or": # C⊔D branches into one branch per option.
                            for part in reversed(c[1:]): # Reverse so the first option is explored first when popped.
                                branch_labels = {k: set(v) for k, v in labels.items()} # Copy labels for this branch.
                                branch_labels[n].remove(c); branch_labels[n].add(part) # Choose one disjunct on the copied branch.
                                stack.append((branch_labels, list(edges), log + ["or"])) # Queue the branch for later expansion.
                            changed = True; branched = True; break
                        if isinstance(c, tuple) and c[0] == "exists": # ∃r.C creates a fresh r-successor labeled C.
                            new = max(labels) + 1; labels[new] = {c[2]}; edges.append((n, c[1], new)); labels[n].remove(c); log.append("exists"); changed = True; break
                        if isinstance(c, tuple) and c[0] == "forall": # ∀r.C pushes C to all known r-successors.
                            pushed = False # Track whether any successor gained a label.
                            for a, r, b in edges: # Inspect existing role edges.
                                if a == n and r == c[1] and c[2] not in labels[b]: labels[b].add(c[2]); pushed = True # Push filler to matching successor.
                            if pushed: log.append("forall"); changed = True; break
                    if changed: break # Restart scanning after each rule application.
                if branched: break # Continue with the queued OR branches.
                if not changed: return True, labels, edges, log + ["open"] # Saturated without clash means satisfiable.
                continue # Keep expanding the current branch.
            break # A clash closed this branch.
        else: # The step limit ended this branch without an open result.
            last_closed = (labels, edges, log + ["limit"]) # Save the bounded branch.
    labels, edges, log = last_closed # Every branch closed or hit the limit.
    return False, labels, edges, log # Return unsatisfiable when no open branch survived.
```
