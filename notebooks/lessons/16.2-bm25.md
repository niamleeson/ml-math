# 16.2 — BM25

BM25 ranks keyword-matching documents by combining three simple signals: rare query terms matter more, repeated matches help with diminishing returns, and long documents are corrected so they do not win merely by having more words. In this lesson, we build that scoring rule from scratch with NumPy and small inline corpora, then inspect every number behind the ranking.

Before the terse worked examples, we build BM25 one idea at a time. ### 1. Documents become term counts, document lengths, and document frequencies

BM25 does not read raw text directly. It starts from the same sparse evidence an inverted index stores: `tf(t,d)`, the count of term `t` in document `d`; `df(t)`, the number of documents containing `t`; and `|d|`, the document length. We will use four tiny documents so every constant can be checked by hand.

```python
corpus_w = [
    "neural search search",
    "search retrieval",
    "neural graph retrieval",
    "search search graph retrieval",
]
docs_w = [doc.split() for doc in corpus_w]
query_w = "neural search".split()
print("tokenized docs:", docs_w)
print("query:", query_w)
```
▶ What you'll see: four tokenized documents and a two-term query, with `search` repeated in documents 1 and 4.

```python
tfs_w = [Counter(doc) for doc in docs_w]
lengths_w = np.array([len(doc) for doc in docs_w], dtype=float)
avgdl_w = float(lengths_w.mean())
print("term counts:", tfs_w)
print("lengths:", lengths_w, "avgdl:", round(avgdl_w, 3))
assert round(avgdl_w, 3) == 3.000
```
▶ What you'll see: document lengths `[3, 2, 3, 4]`, so the average document length is exactly 3.

```python
df_w = defaultdict(int)
for counts_w in tfs_w:
    for term_w in counts_w:
        df_w[term_w] += 1
print("document frequencies:", dict(sorted(df_w.items())))
assert df_w["search"] == 3 and df_w["neural"] == 2
```
▶ What you'll see: `search` appears in 3 documents, while `neural` appears in 2.

*Why it's done this way:* BM25 is a ranking function on top of index statistics. Separating term frequency, document frequency, and length lets the formula ask three different questions: how strongly did this document match, how informative is the matched term, and is the document long enough to need a penalty?

### 2. IDF turns rarity into a stable additive weight

The IDF part of BM25 is

$$idf(t)=\log\left(1+\frac{N-df_t+0.5}{df_t+0.5}\right).$$

The numerator is larger for rare terms and smaller for common terms. The `+0.5` smoothing keeps edge cases finite, and the outer `log(1 + ...)` makes the rarity bonus grow gently instead of exploding.

```python
N_w = len(docs_w)
def bm25_idf_w(term):
    df_t_w = df_w.get(term, 0)
    return float(np.log(1 + (N_w - df_t_w + 0.5) / (df_t_w + 0.5)))

for term_w in ["search", "neural", "graph", "missing"]:
    print(term_w, "df=", df_w.get(term_w, 0), "idf=", round(bm25_idf_w(term_w), 3))
assert round(bm25_idf_w("search"), 3) == 0.357
assert round(bm25_idf_w("neural"), 3) == 0.693
```
▶ What you'll see: `neural` gets IDF 0.693, almost twice `search` at 0.357, because it appears in fewer documents.

```python
terms_w = ["search", "neural", "graph", "retrieval"]
idfs_w = np.array([bm25_idf_w(t) for t in terms_w])
plt.figure(figsize=(4.8, 3))
plt.bar(terms_w, idfs_w, color="teal")
plt.title("2: BM25 IDF rewards rarer terms")
plt.ylabel("idf(t)")
plt.xticks(rotation=15)
plt.show()
```
▶ What you'll see: `search` has the shortest bar because it is the most common query-relevant word.

*Why it's done this way:* summing raw term matches would treat `search` and `neural` as equally informative. IDF encodes the probability-like idea that a term occurring in fewer documents narrows the candidate set more, while the log makes that evidence additive and numerically stable.

### 3. Term frequency saturates instead of growing linearly

BM25 does not give ten repetitions ten times the credit of one repetition. For a document of average length, the term-frequency multiplier is

$$\frac{tf(k_1+1)}{tf+k_1}.$$

With the common default `k1=1.2`, the first hit is worth a lot, the second helps, and later hits flatten out.

```python
k1_w = 1.2
tf_values_w = np.array([0, 1, 2, 5, 10], dtype=float)
sat_w = tf_values_w * (k1_w + 1) / (tf_values_w + k1_w)
print("tf values:", tf_values_w)
print("saturation multipliers:", np.round(sat_w, 3))
assert np.allclose(np.round(sat_w[[1, 2, 3]], 3), [1.000, 1.375, 1.774])
```
▶ What you'll see: `tf=1` gives 1.000, `tf=2` gives 1.375, and `tf=5` gives only 1.774.

```python
tf_curve_w = np.arange(0, 16)
sat_curve_w = tf_curve_w * (k1_w + 1) / (tf_curve_w + k1_w)
linear_w = tf_curve_w.astype(float)
plt.figure(figsize=(5, 3))
plt.plot(tf_curve_w, sat_curve_w, marker="o", label="BM25 saturated tf")
plt.plot(tf_curve_w, linear_w, linestyle="--", label="raw count")
plt.title("3: term-frequency saturation")
plt.xlabel("tf(t,d)")
plt.ylabel("multiplier before IDF")
plt.legend()
plt.show()
```
▶ What you'll see: the BM25 curve bends quickly while the raw-count line keeps rising; look for the flattening after the first few repeats.

*Why it's done this way:* repeated evidence is real — two mentions usually beat one — but linear counts reward keyword stuffing. The denominator includes `tf`, so each additional occurrence increases both numerator and denominator, making the marginal gain shrink.

### 4. Length normalization uses `b` to compare short and long documents fairly

A long document has more positions where a query word can appear by accident. BM25 corrects the denominator with

$$k_1\left(1-b+b\frac{|d|}{avgdl}\right).$$

If `b=0`, length disappears. If `b=1`, length correction is strongest. The default `b=0.75` is a compromise: long documents are discounted, but not erased.

```python
b_w = 0.75
def tf_weight_w(tf, dl, k1=1.2, b=0.75, avgdl=avgdl_w):
    norm = 1 - b + b * dl / avgdl
    return float(tf * (k1 + 1) / (tf + k1 * norm)) if tf > 0 else 0.0

for dl_w in [2, 3, 4, 8]:
    print("dl=", dl_w, "tf=1 weight=", round(tf_weight_w(1, dl_w), 3))
assert round(tf_weight_w(1, 2), 3) == 1.158
assert round(tf_weight_w(1, 4), 3) == 0.880
```
▶ What you'll see: the same one occurrence gets more weight in a short document than in a long document.

```python
length_grid_w = np.arange(1, 11)
weights_len_w = np.array([tf_weight_w(2, dl) for dl in length_grid_w])
plt.figure(figsize=(5, 3))
plt.plot(length_grid_w, weights_len_w, marker="o", color="darkorange")
plt.axvline(avgdl_w, color="black", linestyle="--", label="avgdl")
plt.title("4: length normalization discounts long docs")
plt.xlabel("document length |d|")
plt.ylabel("tf weight for tf=2")
plt.legend()
plt.show()
```
▶ What you'll see: with the same `tf=2`, the score falls as document length grows beyond the average.

*Why it's done this way:* without length normalization, long documents collect accidental matches and can dominate rankings. The `b` parameter decides how much of the denominator is a length penalty versus a fixed saturation penalty.

### 5. Full BM25 scoring sums per-term evidence into a ranking

A full BM25 score adds the contribution of each query term. A document that matches both query terms can beat one that matches only the rare term, but a repeated common term alone should not automatically beat a single rare-term match.

```python
def bm25_score_w(query, counts, dl, k1=1.2, b=0.75):
    score = 0.0
    pieces = []
    for term in query:
        tf = counts.get(term, 0)
        idf = bm25_idf_w(term)
        norm = 1 - b + b * dl / avgdl_w
        part = 0.0 if tf == 0 else idf * (tf * (k1 + 1)) / (tf + k1 * norm)
        pieces.append((term, tf, round(part, 3)))
        score += part
    return float(score), pieces

for i_w, counts_w in enumerate(tfs_w, start=1):
    score_w, pieces_w = bm25_score_w(query_w, counts_w, lengths_w[i_w - 1])
    print(f"d{i_w}", "pieces=", pieces_w, "total=", round(score_w, 3))
```
▶ What you'll see: d1 scores about 1.184 because it has both `neural` and repeated `search`; d3 scores 0.693 from `neural` alone.

```python
scores_w = np.array([bm25_score_w(query_w, c, dl)[0] for c, dl in zip(tfs_w, lengths_w)])
order_w = np.argsort(scores_w)[::-1]
print("scores:", np.round(scores_w, 3))
print("ranking:", [f"d{i+1}" for i in order_w])
assert [i + 1 for i in order_w] == [1, 3, 4, 2]
assert np.allclose(np.round(scores_w, 3), [1.184, 0.413, 0.693, 0.448])
```
▶ What you'll see: the ranking is `d1 > d3 > d4 > d2`, matching the lesson math.

```python
plt.figure(figsize=(5, 3))
plt.bar([f"d{i+1}" for i in range(4)], scores_w, color="seagreen")
plt.title("5: BM25 ranks query matches")
plt.ylabel("BM25 score")
plt.show()
```
▶ What you'll see: d1 has the tallest bar; d4's repeated common term remains below d3's rare-term match.

*Why it's done this way:* BM25 is additive across query terms, so each term contributes independent evidence. IDF decides how valuable a term is, saturation decides how much repetition helps, and length normalization keeps the evidence comparable across documents.

### ✍️ Toy 5 · Sum BM25 pieces into a ranking

A full BM25 document score multiplies IDF by saturated, length-normalized term evidence and sums
query terms.

```python
import numpy as np

t5_rng = np.random.default_rng(0)
print("rng seed:", 0)  # -> 0
t5_vocab = np.array(["cat", "dog", "mat"])
```

## 🛠️ Setup

```python
import numpy as np # load NumPy for arrays, logs, sorting, and numeric assertions.
import matplotlib.pyplot as plt # load Matplotlib for every BM25 diagnostic plot.
from collections import Counter, defaultdict # load standard-library counters for term frequencies and document frequencies.
np.random.seed(0) # make every example deterministic.

corpus = ["neural search search", "search retrieval", "neural graph retrieval", "search search graph retrieval"] # define the inline toy corpus used by most examples.
docs = [doc.split() for doc in corpus] # tokenize by whitespace so the counts are inspectable.
query = "neural search".split() # define the canonical two-term query from the lesson.

def term_counts(doc_tokens): # count terms in one tokenized document.
    return Counter(doc_tokens) # return a Counter so tf(t,d) is easy to read.

def corpus_stats(tokenized_docs): # compute BM25 corpus constants from tokenized documents.
    counts = [term_counts(doc) for doc in tokenized_docs] # compute one term-count table per document.
    lengths = np.array([len(doc) for doc in tokenized_docs], dtype=float) # compute document lengths |d|.
    df = defaultdict(int) # initialize document-frequency storage.
    for c in counts: # visit each document's unique terms.
        for term in c: # count the document once per term, not once per occurrence.
            df[term] += 1 # increment df(t).
    return counts, lengths, float(lengths.mean()), df # return all constants needed by BM25.

def bm25_idf(term, N, df): # compute BM25's smoothed IDF.
    df_t = df.get(term, 0) # read document frequency, using zero for unseen terms.
    return float(np.log(1 + (N - df_t + 0.5) / (df_t + 0.5))) # apply the Robertson-Sparck Jones style smoothed IDF.

def bm25_tf_weight(tf, dl, avgdl, k1=1.2, b=0.75): # compute the non-IDF BM25 term-frequency fraction.
    if tf <= 0: # no occurrence means no contribution.
        return 0.0 # return exactly zero for missing query terms.
    norm = 1 - b + b * dl / avgdl # compute the length-normalized denominator factor.
    return float(tf * (k1 + 1) / (tf + k1 * norm)) # return saturated tf weight.

def bm25_score(query_terms, counts, dl, avgdl, N, df, k1=1.2, b=0.75): # score one document for one query.
    total = 0.0 # accumulate additive per-term evidence.
    for term in query_terms: # score each query term independently.
        total += bm25_idf(term, N, df) * bm25_tf_weight(counts.get(term, 0), dl, avgdl, k1, b) # add IDF times saturated tf.
    return float(total) # return the document score.

def rank_bm25(query_terms, tokenized_docs, k1=1.2, b=0.75): # score and rank every document in a corpus.
    counts, lengths, avgdl, df = corpus_stats(tokenized_docs) # compute corpus constants.
    N = len(tokenized_docs) # count documents.
    scores = np.array([bm25_score(query_terms, c, dl, avgdl, N, df, k1, b) for c, dl in zip(counts, lengths)]) # score all documents.
    order = np.argsort(scores)[::-1] # sort by score descending.
    return scores, order # return scores and ranking indices.
```

### Advanced 3 — Tune `b` on a tiny relevance set

**Goal.** Choose a length-normalization setting with validation data, because too much or too little length correction can change ranking quality. We build it in 4 steps.

```python

query_a3 = "neural search".split() # define the validation query.
relevant_a3 = np.array([1, 1, 0, 1]) # mark which documents are relevant for this toy query.
b_grid_a3 = np.array([0.0, 0.25, 0.75, 1.0]) # test length-normalization strengths.
print("relevance labels:", relevant_a3) # inspect labels.
```
▶ What you'll see: three documents are relevant, but one relevant document is much longer.

```python
ap_values_a3 = [] # store average precision by b.
for b_a3 in b_grid_a3: # evaluate each b.
    scores_a3, order_a3 = rank_bm25(query_a3, docs_a3, b=b_a3) # score with this length normalization.
    hits_a3 = relevant_a3[order_a3] # reorder relevance labels by ranking.
    precisions_a3 = np.cumsum(hits_a3) / (np.arange(len(hits_a3)) + 1) # precision at every rank.

```

### Advanced 5 — Combine BM25 with a simple dense-like score

**Goal.** Build a tiny hybrid ranker, because BM25 is often used as the sparse lexical half of a system that also has semantic scores. We build it in 4 steps.

```python

print("semantic:", semantic_a5) # inspect semantic scores.
```
▶ What you'll see: BM25 likes d1 most, while the semantic score likes d3 most.

```python

sem_norm_a5 = (semantic_a5 - semantic_a5.min()) / (semantic_a5.max() - semantic_a5.min()) # normalize semantic scores to [0,1].

```

```python

```

