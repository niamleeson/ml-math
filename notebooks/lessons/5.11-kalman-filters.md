# 5.11 — Kalman Filters

Kalman filters track a hidden state through time when both the motion model and the sensor are noisy. The central idea is Bayesian recursion for linear-Gaussian systems: predict the next Gaussian state from dynamics, then update it with a measurement using a Kalman gain that acts like a mathematically justified trust coefficient.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build Kalman filtering one idea at a time. Run each cell in order and read the printed intermediate values — every piece of math is spelled out so the prediction, uncertainty growth, gain, and update are all inspectable. This walkthrough is self-contained (it imports what it needs) and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays, linear algebra, and reproducible simulation.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
np.random.seed(0)  # reproducibility for synthetic motion and sensor noise.
```

### 1. The tracking problem: hidden state versus noisy measurement

A Kalman filter starts with two different objects: the **hidden state** we wish we knew, and the **measurement** a sensor actually reports. In a 1-D toy problem the state is position, the process noise wiggles the true motion, and the measurement noise corrupts the sensor reading. The filter exists because neither the motion model nor the sensor alone is trustworthy.

```python
T_w = 30  # number of time steps in the toy trajectory.
true_velocity_w = 1.0  # the underlying object moves about one unit per step.
process_std_w = 0.20  # motion disturbances make the true path imperfectly linear.
measurement_std_w = 0.90  # the sensor is much noisier than the motion.
steps_w = np.arange(T_w)  # time index for plotting.
print("T:", T_w, "process std:", process_std_w, "measurement std:", measurement_std_w)
```
▶ What you'll see: the sensor noise standard deviation is larger than the process noise, so measurements should be useful but not blindly trusted.

```python
process_noise_w = np.random.normal(0, process_std_w, T_w)  # random disturbance in the true motion.
true_pos_w = np.cumsum(true_velocity_w + process_noise_w)  # hidden state path; cumulative motion.
measurements_w = true_pos_w + np.random.normal(0, measurement_std_w, T_w)  # noisy sensor readings.
print("first 5 true positions:", np.round(true_pos_w[:5], 3))
print("first 5 measurements:", np.round(measurements_w[:5], 3))
assert len(true_pos_w) == T_w and len(measurements_w) == T_w
```
▶ What you'll see: the measurements wobble around the hidden position and are sometimes visibly too high or too low.

```python
plt.figure(figsize=(6, 3))
plt.plot(steps_w, true_pos_w, label="hidden true position", color="black")
plt.scatter(steps_w, measurements_w, label="noisy measurements", color="crimson", s=24)
plt.title("1: hidden state versus noisy sensor")
plt.xlabel("time")
plt.ylabel("position")
plt.legend()
plt.show()
```
▶ What you'll see: a mostly smooth black trajectory and scattered red sensor readings around it.

*Why it's done this way:* separating hidden state from observation is the modeling move. The state evolves by dynamics; the sensor only observes a noisy projection of it. A Kalman filter will carry a probability distribution for the hidden state instead of pretending the latest measurement is the truth.

### 2. Prediction: move the mean and grow the uncertainty

Before seeing the next measurement, the filter predicts where the state should be. In one dimension with constant velocity, the predicted mean is `old mean + velocity`. The predicted variance is `old variance + process variance`: uncertainty grows because even a perfect previous estimate becomes less certain after noisy motion.

```python
mean0_w = 0.0  # previous belief about position.
P0_w = 1.0  # previous variance; larger means less certain.
known_velocity_w = 1.0  # simple motion model: move right by one unit.
Q_w = 0.2  # process variance from the lesson block.
mean_pred_w = mean0_w + known_velocity_w  # predicted mean after motion.
P_pred_w = P0_w + Q_w  # predicted variance after adding process uncertainty.
print("predicted mean:", mean_pred_w)
print("predicted variance:", round(P_pred_w, 3))
assert round(P_pred_w, 3) == 1.200
```
▶ What you'll see: the mean moves from 0 to 1, while variance increases from 1.0 to 1.2.

```python
xs_w = np.linspace(-3, 5, 300)  # grid for showing Gaussian beliefs.
prior_pdf_w = np.exp(-0.5 * ((xs_w - mean0_w) ** 2) / P0_w) / np.sqrt(2 * np.pi * P0_w)
pred_pdf_w = np.exp(-0.5 * ((xs_w - mean_pred_w) ** 2) / P_pred_w) / np.sqrt(2 * np.pi * P_pred_w)
plt.figure(figsize=(6, 3))
plt.plot(xs_w, prior_pdf_w, label="previous belief", color="gray")
plt.plot(xs_w, pred_pdf_w, label="after prediction", color="teal")
plt.title("2: prediction shifts and widens the Gaussian")
plt.xlabel("position")
plt.ylabel("density")
plt.legend()
plt.show()
```
▶ What you'll see: the prediction curve shifts right and becomes wider/lower because process noise was added.

*Why it's done this way:* for independent Gaussian noises, variances add. The motion model changes the mean because it says where the state should move; the process noise changes the covariance because it admits the model could be wrong. Forgetting the `+ Q` term makes the filter overconfident.

### 3. Measurement update: the Kalman gain as a trust coefficient

After prediction, the filter sees a measurement. The **innovation** is the surprise, `measurement - predicted measurement`. The Kalman gain decides what fraction of that surprise to apply. In 1-D with direct measurement, the gain is

$$K = \frac{P^-}{P^- + R}.$$

If prediction variance `P^-` is large relative to measurement variance `R`, the gain is large and the sensor is trusted. If measurement variance is large, the gain is small and the model is trusted.

```python
z_w = 1.4  # one noisy measurement from the lesson arithmetic.
R_w = 0.5  # measurement variance from the lesson arithmetic.
innovation_w = z_w - 0.0  # lesson arithmetic uses predicted mean 0 for the update demonstration.
K_w = P_pred_w / (P_pred_w + R_w)  # Kalman gain for direct 1-D observation.
print("innovation:", innovation_w)
print("Kalman gain:", round(K_w, 6))
assert round(K_w, 6) == 0.705882
```
▶ What you'll see: the gain is about 0.706, meaning the update takes about 70.6% of the measurement surprise.

```python
mean_upd_w = 0.0 + K_w * innovation_w  # posterior mean = prediction + gain * surprise.
P_upd_w = (1 - K_w) * P_pred_w  # posterior variance after learning from the measurement.
print("updated mean:", round(mean_upd_w, 6))
print("updated variance:", round(P_upd_w, 6))
assert round(mean_upd_w, 6) == 0.988235
assert round(P_upd_w, 6) == 0.352941
```
▶ What you'll see: the posterior mean moves from 0 toward 1.4, and the variance drops below both 1.2 and 0.5.

```python
labels_w = ["prediction", "measurement", "update"]
means_w = [0.0, z_w, mean_upd_w]
plt.figure(figsize=(5, 3))
plt.bar(labels_w, means_w, color=["gray", "crimson", "teal"])
plt.title("3: update lands between prediction and measurement")
plt.ylabel("position")
plt.show()
```
▶ What you'll see: the update sits between the prediction and the measurement, closer to the measurement because the gain is above 0.5.

*Why it's done this way:* multiplying the innovation by `K` is Bayesian precision weighting in recursive form. The denominator `P^- + R` is total uncertainty in the mismatch; the numerator `P^-` says how much of that mismatch should be blamed on the prior prediction rather than the sensor.

### 4. Recursion: predict and update at every time step

A Kalman filter is not a one-shot formula. It repeats two steps: predict from the previous posterior, then update with the current measurement. The output at time `t` becomes the input belief for time `t+1`, just like HMM filtering but with Gaussian means and variances instead of discrete probability vectors.

```python
means_filter_w = []  # filtered posterior means over time.
vars_filter_w = []  # filtered posterior variances over time.
mu_w = 0.0  # initial position belief.
P_w2 = 1.0  # initial variance belief.
Q_loop_w = process_std_w ** 2  # process variance used by the recursive filter.
R_loop_w = measurement_std_w ** 2  # measurement variance used by the recursive filter.
print("Q:", round(Q_loop_w, 3), "R:", round(R_loop_w, 3))
```
▶ What you'll see: the loop uses variances, not standard deviations, because covariance is what propagates linearly.

```python
for t_w in range(T_w):
    mu_pred_w = mu_w + known_velocity_w  # prediction mean from constant-velocity motion.
    P_pred_loop_w = P_w2 + Q_loop_w  # prediction variance grows by process variance.
    K_loop_w = P_pred_loop_w / (P_pred_loop_w + R_loop_w)  # gain from current uncertainty ratio.
    mu_w = mu_pred_w + K_loop_w * (measurements_w[t_w] - mu_pred_w)  # measurement update.
    P_w2 = (1 - K_loop_w) * P_pred_loop_w  # posterior uncertainty after update.
    means_filter_w.append(mu_w)
    vars_filter_w.append(P_w2)
means_filter_w = np.array(means_filter_w)
vars_filter_w = np.array(vars_filter_w)
print("first 5 filtered means:", np.round(means_filter_w[:5], 3))
print("last variance:", round(float(vars_filter_w[-1]), 3))
assert vars_filter_w[-1] < vars_filter_w[0]
```
▶ What you'll see: filtered means follow the measurements but are smoother, and variance settles after repeated updates.

```python
plt.figure(figsize=(6, 3))
plt.plot(steps_w, true_pos_w, label="true", color="black")
plt.scatter(steps_w, measurements_w, label="measurements", color="crimson", s=18, alpha=0.7)
plt.plot(steps_w, means_filter_w, label="Kalman filtered", color="teal", linewidth=2)
plt.title("4: recursive filtering over time")
plt.xlabel("time")
plt.ylabel("position")
plt.legend()
plt.show()
```
▶ What you'll see: the filtered line tracks the true path more smoothly than the raw measurements.

*Why it's done this way:* the posterior after one measurement is the prior for the next prediction. That recursion is what gives the filter memory: it does not average all observations equally, but carries exactly the sufficient Gaussian statistics needed for the next Bayesian update.

### 5. Matrices: position and velocity in one state vector

Real tracking often needs more than position. A 2-D state can hold position and velocity, while the measurement observes only position. The transition matrix

$$A=\begin{bmatrix}1&\Delta t\\0&1\end{bmatrix}$$

says position advances by velocity, and velocity persists. The observation matrix `H = [1, 0]` says the sensor sees position but not velocity directly.

```python
dt_w = 1.0
A_w = np.array([[1.0, dt_w], [0.0, 1.0]])  # constant-velocity transition.
H_w = np.array([[1.0, 0.0]])  # sensor reads position only.
x_w = np.array([[0.0], [1.0]])  # state column: position 0, velocity 1.
P_mat_w = np.eye(2)  # initial covariance for position and velocity.
Q_mat_w = np.array([[0.05, 0.0], [0.0, 0.02]])  # uncertainty injected into both state components.
print("A:\n", A_w)
print("H:\n", H_w)
```
▶ What you'll see: `A` couples velocity into position, while `H` selects only the first state coordinate.

```python
x_pred_mat_w = A_w @ x_w  # matrix prediction for mean.
P_pred_mat_w = A_w @ P_mat_w @ A_w.T + Q_mat_w  # matrix covariance prediction.
print("predicted state:", x_pred_mat_w.ravel())
print("predicted covariance:\n", np.round(P_pred_mat_w, 3))
assert np.allclose(x_pred_mat_w.ravel(), [1.0, 1.0])
```
▶ What you'll see: predicted position becomes 1 while velocity stays 1; covariance gains off-diagonal coupling.

```python
z_mat_w = np.array([[1.4]])  # position measurement.
R_mat_w = np.array([[0.5]])  # scalar measurement covariance as a 1x1 matrix.
S_w = H_w @ P_pred_mat_w @ H_w.T + R_mat_w  # innovation covariance.
K_mat_w = P_pred_mat_w @ H_w.T @ np.linalg.inv(S_w)  # 2x1 Kalman gain.
y_mat_w = z_mat_w - H_w @ x_pred_mat_w  # innovation in measurement space.
x_upd_mat_w = x_pred_mat_w + K_mat_w @ y_mat_w  # update both position and velocity.
print("Kalman gain:", np.round(K_mat_w.ravel(), 3))
print("updated state:", np.round(x_upd_mat_w.ravel(), 3))
assert K_mat_w.shape == (2, 1)
```
▶ What you'll see: the position measurement updates velocity too because position and velocity uncertainty are correlated.

*Why it's done this way:* matrices let the same scalar logic handle coupled state variables. The covariance carries which variables are statistically linked, so observing position can revise velocity even when velocity is never measured directly.

### 6. Noise tuning: Q and R control lag versus jitter

The process variance `Q` says how much the model expects motion to surprise it. The measurement variance `R` says how noisy the sensor is. Their ratio controls the gain: high `Q` or low `R` makes the filter responsive; low `Q` or high `R` makes it smoother but more lagged.

```python
P_demo_w = 1.0
Q_values_w = np.array([0.01, 0.1, 1.0])
R_fixed_w = 0.5
gains_from_Q_w = (P_demo_w + Q_values_w) / (P_demo_w + Q_values_w + R_fixed_w)
print("Q values:", Q_values_w)
print("gains:", np.round(gains_from_Q_w, 3))
assert gains_from_Q_w[0] < gains_from_Q_w[-1]
```
▶ What you'll see: increasing process noise increases the gain, so the filter listens more to measurements.

```python
R_values_w = np.array([0.1, 0.5, 2.0])
Q_fixed_w = 0.2
gains_from_R_w = (P_demo_w + Q_fixed_w) / (P_demo_w + Q_fixed_w + R_values_w)
print("R values:", R_values_w)
print("gains:", np.round(gains_from_R_w, 3))
assert gains_from_R_w[0] > gains_from_R_w[-1]
```
▶ What you'll see: increasing measurement noise decreases the gain, so the filter trusts prediction more.

```python
plt.figure(figsize=(5, 3))
plt.plot(Q_values_w, gains_from_Q_w, marker="o", label="sweep Q, fixed R")
plt.plot(R_values_w, gains_from_R_w, marker="s", label="sweep R, fixed Q")
plt.xscale("log")
plt.title("6: noise assumptions set the gain")
plt.xlabel("variance value")
plt.ylabel("Kalman gain")
plt.legend()
plt.show()
```
▶ What you'll see: gain rises with Q and falls with R, making noise tuning visible as a trust tradeoff.

*Why it's done this way:* `Q` and `R` are not cosmetic hyperparameters; they are the numerical expression of model trust and sensor trust. Bad values directly cause lag, jitter, or overconfidence because they change the Bayesian weighting.

### Basic 1 — Represent a Gaussian belief

**Goal.** Store a position estimate as a mean and variance, because a Kalman filter tracks uncertainty instead of only one best guess. We build it in 2 steps.

```python
mu_b1 = 0.0  # current best estimate of position.
P_b1 = 1.0  # current variance; standard deviation is sqrt(P).
print("mean:", mu_b1)
print("variance:", P_b1, "std:", np.sqrt(P_b1))
assert P_b1 > 0
```
▶ What you'll see: one scalar stores location and one positive scalar stores uncertainty.

```python
x_grid_b1 = np.linspace(-4, 4, 200)  # candidate positions for plotting the belief.
pdf_b1 = np.exp(-0.5 * ((x_grid_b1 - mu_b1) ** 2) / P_b1) / np.sqrt(2 * np.pi * P_b1)  # Gaussian density.
plt.figure(figsize=(4, 3))
plt.plot(x_grid_b1, pdf_b1, color="teal")
plt.title("Basic 1: Gaussian belief")
plt.xlabel("position")
plt.ylabel("density")
plt.show()
```
▶ What you'll see: a bell curve centered at 0 with width controlled by the variance.

👀 Takeaway: the filter's belief is a compact Gaussian summary: mean for location, variance for confidence.

▶ What you'll see: the predicted variance bar is taller because process noise was added.

```python
plt.figure(figsize=(4, 3))
```

### Basic 7 — Run two filtering steps

**Goal.** Repeat prediction and update twice, because Kalman filtering is a recursion rather than an isolated correction. We build it in 3 steps.

```python
measurements_b7 = np.array([1.4, 2.2])  # two sensor readings.
mu_b7 = 0.0  # initial mean.
P_b7 = 1.0  # initial variance.
Q_b7 = 0.2  # process variance.
R_b7 = 0.5  # measurement variance.
print("measurements:", measurements_b7)
```
▶ What you'll see: two measurements will be consumed in chronological order.

```python
filtered_b7 = []  # store posterior means.
variances_b7 = []  # store posterior variances.
for z_b7 in measurements_b7:
    mu_pred_loop_b7 = mu_b7  # no velocity in this tiny arithmetic example.
    P_pred_loop_b7 = P_b7 + Q_b7  # prediction variance.
    K_loop_b7 = P_pred_loop_b7 / (P_pred_loop_b7 + R_b7)  # gain.
    mu_b7 = mu_pred_loop_b7 + K_loop_b7 * (z_b7 - mu_pred_loop_b7)  # update mean.
    P_b7 = (1 - K_loop_b7) * P_pred_loop_b7  # update variance.
    filtered_b7.append(mu_b7)
    variances_b7.append(P_b7)
print("filtered means:", np.round(filtered_b7, 3))
print("filtered variances:", np.round(variances_b7, 3))
assert variances_b7[1] < 0.5
```
▶ What you'll see: the second posterior depends on the first posterior, not just the second measurement.

```python
plt.figure(figsize=(4, 3))
plt.plot([1, 2], measurements_b7, marker="o", label="measurement", color="crimson")
plt.plot([1, 2], filtered_b7, marker="s", label="filtered", color="teal")
plt.title("Basic 7: recursive updates")
plt.xlabel("step")
plt.ylabel("position")
plt.legend()
plt.show()
```
▶ What you'll see: the filtered sequence is smoother than simply copying each measurement.

👀 Takeaway: each posterior becomes the starting belief for the next time step.

### Advanced 5 — Compare filtered uncertainty to empirical error

**Goal.** Check whether the uncertainty band is calibrated, because a probabilistic tracker should know when it is unsure. We build it in 5 steps.

```python
runs_a5 = 80
T_a5 = 20
R_a5 = 0.64
Q_a5 = 0.04
final_errors_a5 = []
final_stds_a5 = []
print("Monte Carlo runs:", runs_a5)
```
▶ What you'll see: many repeated simulations will compare actual errors with reported standard deviations.

```python
for run_a5 in range(runs_a5):
    true_a5 = np.cumsum(1.0 + np.random.normal(0, np.sqrt(Q_a5), T_a5))
    z_a5 = true_a5 + np.random.normal(0, np.sqrt(R_a5), T_a5)
    mu_a5 = 0.0
    P_a5 = 1.0
    for t_a5 in range(T_a5):
        mu_pred_a5 = mu_a5 + 1.0
        P_pred_a5 = P_a5 + Q_a5
        K_a5 = P_pred_a5 / (P_pred_a5 + R_a5)
        mu_a5 = mu_pred_a5 + K_a5 * (z_a5[t_a5] - mu_pred_a5)
        P_a5 = (1 - K_a5) * P_pred_a5
    final_errors_a5.append(mu_a5 - true_a5[-1])
    final_stds_a5.append(np.sqrt(P_a5))
final_errors_a5 = np.array(final_errors_a5)
final_stds_a5 = np.array(final_stds_a5)
print("mean final std:", round(float(np.mean(final_stds_a5)), 3))
assert np.mean(final_stds_a5) > 0
```
▶ What you'll see: each run ends with a predicted standard deviation from the filter.

```python
within_2std_a5 = np.mean(np.abs(final_errors_a5) <= 2 * final_stds_a5)
empirical_rmse_a5 = np.sqrt(np.mean(final_errors_a5 ** 2))
mean_std_a5 = np.mean(final_stds_a5)
print("coverage within ±2 std:", round(within_2std_a5, 3))
print("empirical RMSE:", round(empirical_rmse_a5, 3), "mean reported std:", round(mean_std_a5, 3))
assert within_2std_a5 > 0.8
```
▶ What you'll see: most final errors fall inside the filter's ±2 standard-deviation band.

