# 1.3 · PAC Learning

PAC learning turns “my training error is small” into a guarantee about true error. In the finite realizable case, it tells us how many labeled examples make empirical risk minimization (ERM) within $\epsilon$ of optimal with probability at least $1-\delta$.

## 📖 Concept walkthrough — build it from scratch

Before the terse worked examples, we build Probably Approximately Correct learning one idea at a time. Run each cell in order and read the printed intermediate values — the probability knobs, the logarithms, and the sample-complexity arithmetic are all shown. This walkthrough is self-contained (it imports what it needs) and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays, logarithms, ceilings, and simple simulations.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
np.random.seed(0)  # reproducibility for every randomized demonstration.
```

### 1. From ERM to a guarantee

ERM chooses the hypothesis with the smallest training error, but a training set is only a random sample from the world. PAC learning adds two user-chosen knobs: accuracy $\epsilon$ and failure probability $\delta$. “Approximately correct” means true error is within $\epsilon$ of the best hypothesis in $\mathcal{H}$; “probably” means that statement holds with probability at least $1-\delta$ over the random draw of the sample.

```python
H_size_w = 100  # Number of candidate hypotheses in the finite class.
epsilon_w = 0.10  # Allowed excess true error above the best hypothesis.
delta_w = 0.05  # Allowed probability that the guarantee fails.
confidence_w = 1 - delta_w  # PAC success probability.
print("|H|:", H_size_w)  # Inspect the class size.
print("epsilon:", epsilon_w, "delta:", delta_w, "confidence:", confidence_w)  # Inspect the PAC knobs.
```
▶ What you'll see: the lesson's baseline class has 100 hypotheses, asks for $0.1$ accuracy, and wants 95% confidence.

```python
labels_w = ["success = at least 1-delta", "failure = at most delta"]  # Name the probability slices.
probs_w = [confidence_w, delta_w]  # Store the two parts of the PAC probability statement.
print(dict(zip(labels_w, probs_w)))  # Print the success and failure probabilities.
```
▶ What you'll see: PAC does not promise certainty; it budgets a small failure chance $\delta=0.05$.

```python
plt.figure(figsize=(4.2, 3.2))  # Create a compact probability bar chart.
plt.bar(labels_w, probs_w, color=["seagreen", "indianred"])  # Draw success and failure masses.
plt.ylim(0, 1)  # Keep probabilities on the natural 0-to-1 scale.
plt.ylabel("probability")  # Label the vertical axis.
plt.title("1: PAC probability split")  # Title the figure with the walkthrough id.
plt.xticks(rotation=15, ha="right")  # Rotate labels so they fit.
plt.show()  # Display the visualization.
```
▶ What you'll see: most probability mass is on the good event, but a small red slice remains.

*Why it's done this way: PAC separates what we control ($\epsilon,\delta$) from what is random (the sample), so a learning claim becomes a probability statement instead of a hunch.*

### 2. The finite realizable sample-complexity formula

For a finite hypothesis class in the realizable case — meaning some $h\in\mathcal{H}$ has zero true error — ERM is PAC if

$$m \;\ge\; \frac{1}{\epsilon}\Big(\log|\mathcal{H}|+\log\frac{1}{\delta}\Big).$$

The two logarithms are the price of searching over many hypotheses and demanding high confidence. The outer $1/\epsilon$ is the price of accuracy: making $\epsilon$ smaller is expensive because it asks the sample to distinguish finer differences in true error.

```python
log_H_w = np.log(H_size_w)  # Compute ln|H| for the hypothesis-count term.
log_conf_w = np.log(1 / delta_w)  # Compute ln(1/delta) for the confidence term.
sum_logs_w = log_H_w + log_conf_w  # Combine the two logarithmic prices.
print("ln|H| =", round(log_H_w, 3))  # Lesson number: ln 100 = 4.605.
print("ln(1/delta) =", round(log_conf_w, 3))  # Lesson number: ln 20 = 2.996.
print("sum =", round(sum_logs_w, 3))  # Lesson number: 7.601.
assert round(log_H_w, 3) == 4.605  # Verify the cited number.
assert round(log_conf_w, 3) == 2.996  # Verify the cited number.
assert round(sum_logs_w, 3) == 7.601  # Verify the cited number.
```
▶ What you'll see: the two log terms add to 7.601.

```python
m_raw_w = sum_logs_w / epsilon_w  # Divide by epsilon to get the real-valued lower bound.
m_needed_w = int(np.ceil(m_raw_w))  # Round up because a sample count must be an integer.
print("raw m bound =", round(m_raw_w, 1))  # Lesson number: 76.0.
print("integer examples needed =", m_needed_w)  # Need 77 examples because m must be at least the bound.
assert round(m_raw_w, 1) == 76.0  # Verify the cited division.
assert m_needed_w == 77  # Verify the cited integer sample count.
```
▶ What you'll see: 77 labeled points suffice for the baseline PAC guarantee.

```python
parts_w = [log_H_w / epsilon_w, log_conf_w / epsilon_w]  # Split the sample bound into its two additive sources.
plt.figure(figsize=(4.2, 3.2))  # Create a compact contribution chart.
plt.bar(["class size", "confidence"], parts_w, color=["steelblue", "darkorange"])  # Show each term after division by epsilon.
plt.ylabel("samples in the bound")  # Label the sample contribution axis.
plt.title("2: m = (log terms)/epsilon")  # Title the formula decomposition.
plt.show()  # Display the chart.
```
▶ What you'll see: the class-size and confidence log terms together create the 76.0 raw bound.

*Why it's done this way: the formula is a union-bound guarantee over all bad hypotheses, so finite $|\mathcal{H}|$ appears inside a logarithm while the accuracy tolerance $\epsilon$ scales the whole price.*

### 3. Turning the PAC knobs

The baseline example is useful only after we feel each knob. Halving $\epsilon$ doubles the sample bound because $\epsilon$ sits outside as $1/\epsilon$. Enlarging $|\mathcal{H}|$ by $100\times$ is much cheaper because it only adds $\log 100$. Asking for more confidence also grows logarithmically through $\log\frac{1}{\delta}$.

```python
def finite_realizable_m_w(H_size, epsilon, delta):  # Define the finite realizable PAC sample bound.
    epsilon = max(float(epsilon), 1e-12)  # Guard against division by zero in demonstrations.
    delta = min(max(float(delta), 1e-12), 1 - 1e-12)  # Guard the logarithm from 0 or 1 endpoints.
    return int(np.ceil((np.log(H_size) + np.log(1 / delta)) / epsilon))  # Return the integer sample count.

m_base_w = finite_realizable_m_w(100, 0.10, 0.05)  # Baseline from the lesson.
m_tight_w = finite_realizable_m_w(100, 0.05, 0.05)  # Halve epsilon while holding other knobs fixed.
m_bigH_w = finite_realizable_m_w(10000, 0.10, 0.05)  # Enlarge the class by 100x.
m_conf_w = finite_realizable_m_w(100, 0.10, 0.01)  # Demand 99% confidence.
print("baseline:", m_base_w)  # 77 examples.
print("epsilon=0.05:", m_tight_w)  # 153 examples.
print("|H|=10000:", m_bigH_w)  # 123 examples.
print("delta=0.01:", m_conf_w)  # 93 examples.
assert (m_base_w, m_tight_w, m_bigH_w, m_conf_w) == (77, 153, 123, 93)  # Verify lesson numbers.
```
▶ What you'll see: tightening accuracy is the most expensive one-knob change.

```python
scenarios_w = ["base", "epsilon/2", "100x H", "delta=.01"]  # Name the four settings.
counts_w = [m_base_w, m_tight_w, m_bigH_w, m_conf_w]  # Store the four sample counts.
extra_w = np.array(counts_w) - m_base_w  # Compute additional samples beyond baseline.
print("extra samples over baseline:", dict(zip(scenarios_w, extra_w)))  # Inspect marginal costs.
```
▶ What you'll see: halving $\epsilon$ adds 76 samples, while a $100\times$ bigger class adds only 46.

```python
plt.figure(figsize=(4.8, 3.2))  # Create a compact comparison plot.
plt.bar(scenarios_w, counts_w, color=["gray", "crimson", "steelblue", "darkorange"])  # Compare sample counts.
plt.ylabel("required examples")  # Label the vertical axis.
plt.title("3: turning PAC knobs")  # Title the knob-sweep figure.
plt.show()  # Display the chart.
```
▶ What you'll see: the red accuracy bar jumps highest.

*Why it's done this way: PAC exposes the economic shape of learning — accuracy is linear in $1/\epsilon$, while confidence and finite class size are only logarithmic.*

### 4. Why class size is cheap: logarithms

A striking lesson detail is how flat the dependence on $|\mathcal{H}|$ is. With $\epsilon=0.1$, the class-size term $\log|\mathcal{H}|/\epsilon$ grows by exactly $\log 2/\epsilon\approx 6.93$ samples every time the class doubles. That means doubling the hypothesis budget again and again has a constant sample cost.

```python
H_values_w = np.array([50, 100, 200, 400])  # The lesson's doubling sequence.
class_terms_w = np.log(H_values_w) / 0.10  # Hold epsilon fixed and isolate the class-size term.
increments_w = np.diff(class_terms_w)  # Compute the added samples per doubling.
print("class terms:", np.round(class_terms_w, 1))  # Lesson numbers: 39.1, 46.1, 53.0, 59.9.
print("doubling increments:", np.round(increments_w, 2))  # Each is ln 2 / 0.1 = 6.93.
assert np.allclose(np.round(class_terms_w, 1), [39.1, 46.1, 53.0, 59.9])  # Verify cited class terms.
assert np.allclose(np.round(increments_w, 2), [6.93, 6.93, 6.93])  # Verify cited increments.
```
▶ What you'll see: every doubling adds the same ~6.93 examples to the class-size part.

```python
doubling_price_w = np.log(2) / 0.10  # Compute the theoretical per-doubling price.
print("ln 2 / epsilon =", round(doubling_price_w, 2))  # Print the closed-form increment.
assert round(doubling_price_w, 2) == 6.93  # Verify the cited constant.
```
▶ What you'll see: the constant per-doubling price is exactly $\frac{\log 2}{\epsilon}$.

```python
plt.figure(figsize=(4.6, 3.2))  # Create a compact curve plot.
plt.plot(H_values_w, class_terms_w, marker="o", color="purple")  # Show log growth as H doubles.
plt.xscale("log", base=2)  # Use a base-2 log axis so doublings are evenly spaced.
plt.xlabel("|H| (log2 scale)")  # Label the class-size axis.
plt.ylabel("log|H| / epsilon")  # Label the isolated class-size sample term.
plt.title("4: each doubling costs ~6.93 samples")  # Title the logarithm visualization.
plt.show()  # Display the plot.
```
▶ What you'll see: equal vertical steps for equal doublings.

*Why it's done this way: logarithms turn multiplicative growth in candidate hypotheses into additive sample cost, which is why expressive finite classes can still be learnable.*

### 5. Realizable versus agnostic: the common pitfall

The formula above assumes the realizable case: some hypothesis in $\mathcal{H}$ has zero true error. If no model is perfect, PAC bounds become agnostic and the dependence typically worsens to $1/\epsilon^2$. This is not a tiny technicality — the same accuracy target can become an order of magnitude more expensive.

```python
agnostic_proxy_w = int(np.ceil((np.log(H_size_w) + np.log(1 / delta_w)) / (epsilon_w ** 2)))  # Simple agnostic-style scale demo.
realizable_w = finite_realizable_m_w(H_size_w, epsilon_w, delta_w)  # Reuse the realizable count.
ratio_w = agnostic_proxy_w / realizable_w  # Compare the two scales.
print("realizable 1/epsilon count:", realizable_w)  # 77 examples.
print("agnostic-style 1/epsilon^2 count:", agnostic_proxy_w)  # Much larger count.
print("ratio:", round(ratio_w, 1))  # About 9.9x larger.
assert realizable_w == 77  # Verify the realizable baseline.
assert agnostic_proxy_w == 761  # Verify the squared-accuracy arithmetic.
```
▶ What you'll see: changing $1/\epsilon$ to $1/\epsilon^2$ changes 77 into 761.

```python
eps_grid_w = np.array([0.20, 0.10, 0.05])  # Accuracy tolerances to compare.
real_curve_w = (log_H_w + log_conf_w) / eps_grid_w  # Realizable scaling.
agn_curve_w = (log_H_w + log_conf_w) / (eps_grid_w ** 2)  # Agnostic-style scaling.
print("realizable raw:", np.round(real_curve_w, 1))  # Inspect 1/epsilon growth.
print("agnostic raw:", np.round(agn_curve_w, 1))  # Inspect 1/epsilon^2 growth.
```
▶ What you'll see: halving $\epsilon$ doubles the realizable bound but quadruples the agnostic-style bound.

```python
plt.figure(figsize=(4.6, 3.2))  # Create a compact scaling plot.
plt.plot(eps_grid_w, real_curve_w, marker="o", label="1/epsilon", color="seagreen")  # Plot realizable scaling.
plt.plot(eps_grid_w, agn_curve_w, marker="o", label="1/epsilon^2", color="crimson")  # Plot agnostic-style scaling.
plt.gca().invert_xaxis()  # Put stricter accuracy to the right visually.
plt.xlabel("epsilon (smaller is stricter)")  # Label the accuracy axis.
plt.ylabel("raw sample bound")  # Label the sample axis.
plt.title("5: realizable vs agnostic scaling")  # Title the pitfall figure.
plt.legend()  # Show which curve is which.
plt.show()  # Display the plot.
```
▶ What you'll see: the squared-accuracy curve rises much faster.

*Why it's done this way: the finite realizable theorem is powerful but conditional; when the best hypothesis still makes errors, a different theorem with a harsher $\epsilon$ dependence is needed.*

#### B2. Split the bound into class and confidence pieces

**Goal.** See that the baseline count is the sum of two log prices divided by $\epsilon$. We build it in 2 steps.
