# 3.41 — Model Selection: AIC, BIC & MDL

Model selection is the discipline of choosing the model that should survive beyond the training table, not merely the one that flatters the training data. In this lesson, you will build empirical risk, likelihood, AIC, BIC, and MDL from scratch in NumPy, inspect every score component, and see why good selection always compares fit against complexity on a consistent scale.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build model selection one idea at a time. Run each cell in order and read the printed intermediate values — every score is decomposed into raw fit, penalty or coding cost, and final decision value. This walkthrough is self-contained and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays, random numbers, and small numerical checks.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
np.random.seed(0)  # reproducibility for synthetic samples and resampling demos.
```

### 1. Empirical risk: the training score is an average, not a verdict

Model selection starts with empirical risk: compute a loss on each observed example, then average those losses. This is the quantity a learner can directly see. It is useful, but incomplete, because a flexible model can make this number smaller by adapting to quirks that will not repeat.

```python
losses_w = np.array([0.235, 0.096, 0.522])  # three verified per-example losses from the lesson.
risk_w = float(np.mean(losses_w))           # empirical risk R_S = average loss.
print("losses:", losses_w)                 # inspect every contribution before averaging.
print("empirical risk:", round(risk_w, 3)) # (0.235 + 0.096 + 0.522) / 3 = 0.284.
assert round(risk_w, 3) == 0.284            # canonical lesson number.
```
▶ What you'll see: the three losses average to 0.284, the raw training quantity the method tries to reduce.

```python
plt.figure(figsize=(4.4, 3))
plt.bar(["ex1", "ex2", "ex3"], losses_w, color="steelblue")
plt.axhline(risk_w, color="crimson", linestyle="--", label="mean risk")
plt.title("1: empirical risk averages observed losses")
plt.ylabel("loss")
plt.legend()
plt.show()
```
▶ What you'll see: one high-loss example pulls the mean upward; the dashed line is the score seen by ERM.

*Why it's done this way:* empirical risk is an unbiased-looking summary only when the examples represent the future task. Averaging keeps the score on a per-example scale, so a dataset with twice as many rows is not automatically judged worse just because it has twice as many loss terms.

### 2. Penalized selection: fit plus cost is the decision score

The lesson's central guardrail is that selection should not optimize raw fit alone. If a method pays a complexity, regularization, or operational cost of 0.100, the decision score is the empirical risk plus that cost. Lower is better only after both pieces live on the same scale.

```python
cost_w = 0.100                                # complexity/regularization/operational cost.
score_w = risk_w + cost_w                     # full selection score.
print("risk:", round(risk_w, 3), "cost:", cost_w)
print("decision score:", round(score_w, 3))  # 0.284 + 0.100 = 0.384.
assert round(score_w, 3) == 0.384             # canonical lesson number.
```
▶ What you'll see: the attractive raw risk becomes a larger and more honest 0.384 after cost is included.

```python
plt.figure(figsize=(4.4, 3))
plt.bar(["risk", "cost", "risk+cost"], [risk_w, cost_w, score_w], color=["teal", "orange", "purple"])
plt.title("2: selection score includes the cost")
plt.ylabel("score units")
plt.show()
```
▶ What you'll see: the final bar is the only bar that should be used for model comparison.

*Why it's done this way:* a cost term is a numerical expression of distrust in flexibility. It says, "I will believe extra fit only if it pays for the extra freedom used to obtain it," which is the same bias-complexity bargain behind regularization.

### 3. Likelihood and negative log-likelihood: fit on a probability scale

AIC and BIC use likelihood instead of arbitrary loss. For a Gaussian regression model with fixed noise scale, maximizing likelihood is equivalent to minimizing squared residuals, but the score is written as negative log-likelihood so probability products become sums.

```python
y_w = np.array([1.0, 1.4, 2.1, 2.6, 3.2])             # observed response values.
yhat_simple_w = np.array([1.1, 1.5, 1.9, 2.4, 3.0])   # predictions from a simple model.
sigma_w = 0.35                                        # assumed Gaussian noise standard deviation.
resid_w = y_w - yhat_simple_w                         # residuals are what likelihood judges.
print("residuals:", np.round(resid_w, 3))
print("SSE:", round(float(np.sum(resid_w ** 2)), 3))
```
▶ What you'll see: small residuals produce a small sum of squared errors.

```python
n_w = len(y_w)  # sample size.
nll_w = 0.5 * n_w * np.log(2 * np.pi * sigma_w ** 2) + 0.5 * np.sum((resid_w / sigma_w) ** 2)
loglik_w = -float(nll_w)                       # log L at these predictions.
print("negative log-likelihood:", round(nll_w, 3))
print("log likelihood:", round(loglik_w, 3))
assert round(float(nll_w), 3) == -0.083         # density likelihoods may exceed 1, so NLL can be negative.
```
▶ What you'll see: the NLL is −0.083 because a continuous density can be greater than 1 near a precise prediction.

```python
xs_w = np.linspace(-1.0, 1.0, 200)
gauss_w = (1 / (np.sqrt(2 * np.pi) * sigma_w)) * np.exp(-0.5 * (xs_w / sigma_w) ** 2)
plt.figure(figsize=(4.4, 3))
plt.plot(xs_w, gauss_w, color="navy")
plt.scatter(resid_w, (1 / (np.sqrt(2 * np.pi) * sigma_w)) * np.exp(-0.5 * (resid_w / sigma_w) ** 2), color="crimson")
plt.title("3: likelihood rewards residuals near zero")
plt.xlabel("residual")
plt.ylabel("Gaussian density")
plt.show()
```
▶ What you'll see: residuals near zero sit high on the density curve, increasing log likelihood.

*Why it's done this way:* multiplying probabilities across examples is numerically fragile and hard to compare, while summing log probabilities is stable. The negative sign converts "larger likelihood is better" into the same "smaller score is better" convention as loss.

### 4. AIC and BIC: reward likelihood, charge parameters

AIC and BIC both start with the same fit term, $-2\ln L$, then add a parameter penalty. AIC charges $2k$; BIC charges $k\ln n$, which grows with sample size. Both are only meaningful when the candidate models are fit to the same data under comparable likelihood assumptions.

```python
logL_w = -3.2                         # maximized log likelihood for a candidate model.
k_w = 3                               # number of fitted parameters.
n_w = 40                              # sample size.
aic_w = 2 * k_w - 2 * logL_w          # AIC = 2k - 2 log L.
bic_w = k_w * np.log(n_w) - 2 * logL_w # BIC = k log n - 2 log L.
print("AIC:", round(aic_w, 3))
print("BIC:", round(bic_w, 3))
assert round(aic_w, 3) == 12.4
assert round(bic_w, 3) == 17.467
```
▶ What you'll see: BIC is larger than AIC here because ln(40) > 2, so each parameter costs more.

```python
ks_w = np.arange(1, 8)
aic_pen_w = 2 * ks_w
bic_pen_w = ks_w * np.log(n_w)
plt.figure(figsize=(4.6, 3))
plt.plot(ks_w, aic_pen_w, marker="o", label="AIC penalty 2k")
plt.plot(ks_w, bic_pen_w, marker="o", label="BIC penalty k ln n")
plt.title("4: parameter penalties at n=40")
plt.xlabel("parameter count k")
plt.ylabel("penalty")
plt.legend()
plt.show()
```
▶ What you'll see: BIC's line is steeper than AIC's line for this sample size.

*Why it's done this way:* the likelihood term rewards a model for explaining the data, while the penalty asks how many adjustable knobs were needed. AIC is oriented toward predictive efficiency; BIC is more conservative as data accumulates because its parameter charge increases with $n$.

### 5. MDL: choose the shortest description of model plus errors

Minimum Description Length (MDL) says that learning is compression: describe the model, then describe the data left unexplained by the model. A model that fits well but needs a long description may lose to a simpler model with slightly worse residuals.

```python
model_bits_w = np.array([10.0, 18.0, 30.0])       # bits to describe three candidate models.
error_bits_w = np.array([32.0, 20.0, 12.0])       # bits to describe residual mistakes.
mdl_w = model_bits_w + error_bits_w               # total code length.
print("model bits:", model_bits_w)
print("error bits:", error_bits_w)
print("MDL totals:", mdl_w)
assert np.argmin(mdl_w) == 1                      # middle model has shortest total code.
```
▶ What you'll see: the flexible model reduces error bits, but its model bits can overpay for that gain.

```python
x_w = np.arange(3)
plt.figure(figsize=(5, 3))
plt.bar(x_w, model_bits_w, label="model bits", color="teal")
plt.bar(x_w, error_bits_w, bottom=model_bits_w, label="error bits", color="orange")
plt.xticks(x_w, ["small", "middle", "large"])
plt.title("5: MDL = model code + error code")
plt.ylabel("bits")
plt.legend()
plt.show()
```
▶ What you'll see: the shortest stacked bar is the selected model, not necessarily the lowest error-only model.

*Why it's done this way:* compression is a concrete version of Occam's razor. If a pattern is real, a concise model can explain it and reduce the residual code; if a pattern is noise, memorizing it costs more bits than it saves.

### 6. Gaps, uncertainty, and stability

After computing full scores, the decision is still not just "lowest number wins". We also inspect the gap: if the improvement is tiny relative to resampling variation, the apparent winner may not be stable. The lesson's verified flexible alternative has score 0.424, so the baseline score 0.384 wins by 0.040, a 9.4% relative gap.

```python
baseline_w = score_w                  # 0.384 from risk + cost.
flexible_w = 0.424                    # tempting alternative from the lesson.
gap_w = flexible_w - baseline_w       # lower baseline wins by this much.
rel_gap_w = gap_w / flexible_w        # gap on the alternative's scale.
print("gap:", round(gap_w, 3))
print("relative gap:", round(rel_gap_w, 3))
assert round(gap_w, 3) == 0.040
assert round(rel_gap_w, 3) == 0.094
```
▶ What you'll see: the baseline is lower, but the absolute margin is only 0.040.

```python
stable_w = 0.80 * baseline_w                  # stabilizing knob reduces the score by 20%.
scores_w = np.array([baseline_w, flexible_w, stable_w])
labels_w = ["baseline", "flexible", "stabilized"]
winner_w = int(np.argmin(scores_w))
print("scores:", np.round(scores_w, 3))
print("winner:", labels_w[winner_w])
assert round(float(stable_w), 3) == 0.307
assert labels_w[winner_w] == "stabilized"
```
▶ What you'll see: the stabilized score is 0.307, the lowest of the three verified options.

```python
plt.figure(figsize=(4.8, 3))
plt.bar(labels_w, scores_w, color=["gray", "crimson", "seagreen"])
plt.title("6: compare complete decision scores")
plt.ylabel("lower is better")
plt.show()
```
▶ What you'll see: the green stabilized bar is lowest, while the flexible model loses after cost is counted.

*Why it's done this way:* gaps translate score differences into decision evidence. A model selection rule should prefer the lowest complete score, but the human should still ask whether that advantage is large enough to survive data splits, bootstrap resamples, or operational uncertainty.

### ✍️ Toy 1 · Empirical risk averages losses

Empirical risk is the mean of per-example losses. Start with six small losses, then compute the total and the average on the same scale.

```python
import numpy as np
```

### ✍️ Toy 3 · Gaussian NLL sums residual evidence

Likelihood scoring turns residuals into Gaussian densities, then sums negative log-density terms into one fit score.

```python
import numpy as np

t3_rng = np.random.default_rng(0)
t3_y = np.array([1.0, 1.5, 2.0, 2.5, 3.0, 3.5])
print("observed y:", t3_y.tolist())  # -> [1.0, 1.5, 2.0, 2.5, 3.0, 3.5]
t3_pred = np.array([1.1, 1.4, 2.2, 2.3, 3.1, 3.4])
print("predictions:", t3_pred.tolist())  # -> [1.1, 1.4, 2.2, 2.3, 3.1, 3.4]
t3_resid = t3_y - t3_pred
print("residuals:", np.round(t3_resid, 3).tolist())  # -> [-0.1, 0.1, -0.2, 0.2, -0.1, 0.1]
t3_sigma = 0.5
print("sigma:", t3_sigma)  # -> 0.5
t3_sse = float(np.sum(t3_resid ** 2))
print("SSE:", round(t3_sse, 3))  # -> 0.12
t3_density = (1 / (np.sqrt(2 * np.pi) * t3_sigma)) * np.exp(-0.5 * (t3_resid / t3_sigma) ** 2)
print("residual densities:", np.round(t3_density, 3).tolist())  # -> [0.782, 0.782, 0.737, 0.737, 0.782, 0.782]
t3_nll = 0.5 * t3_y.size * np.log(2 * np.pi * t3_sigma ** 2) + 0.5 * np.sum((t3_resid / t3_sigma) ** 2)
print("negative log-likelihood:", round(float(t3_nll), 3))  # -> 1.595

plt.figure(figsize=(4.8, 2.8))
plt.scatter(t3_resid, t3_density, color="crimson", s=80)
plt.axvline(0.0, color="black", linestyle="--", label="perfect residual")
plt.xlabel("residual")
plt.ylabel("Gaussian density")
plt.title("Toy 3 · likelihood rewards small residuals")
plt.legend()
plt.show()

assert round(float(t3_nll), 3) == 1.595
```
▶ What you'll see: residuals closer to zero have higher density, and their total NLL is `1.595`.

### ✍️ Toy 4 · AIC and BIC charge parameters

AIC and BIC share the same fit term, `-2 log L`, but attach different parameter penalties.

```python
import numpy as np

t4_rng = np.random.default_rng(0)
t4_k = np.array([1, 2, 4])
print("parameter counts:", t4_k.tolist())  # -> [1, 2, 4]
t4_logL = np.array([-13.0, -10.5, -9.6])
print("log likelihoods:", t4_logL.tolist())  # -> [-13.0, -10.5, -9.6]
t4_n = 12
print("sample size:", t4_n)  # -> 12
t4_fit = -2 * t4_logL
print("-2 log L:", np.round(t4_fit, 3).tolist())  # -> [26.0, 21.0, 19.2]
t4_aic = t4_fit + 2 * t4_k

t4_bic = t4_fit + t4_k * np.log(t4_n)
print("BIC:", np.round(t4_bic, 3).tolist())  # -> [28.485, 25.97, 29.14]
t4_aic_winner = int(t4_k[np.argmin(t4_aic)])
print("AIC winner k:", t4_aic_winner)  # -> 2
t4_bic_winner = int(t4_k[np.argmin(t4_bic)])
print("BIC winner k:", t4_bic_winner)  # -> 2

plt.figure(figsize=(4.8, 2.8))
plt.plot(t4_k, t4_aic, marker="o", label="AIC")
plt.plot(t4_k, t4_bic, marker="s", label="BIC")
plt.xlabel("parameter count k")
plt.ylabel("score")
plt.title("Toy 4 · fit plus parameter penalty")
plt.legend()
plt.show()

assert t4_aic_winner == 2 and t4_bic_winner == 2
```
▶ What you'll see: the middle model pays enough parameters to improve fit, but not so many that penalties dominate.

### Basic 4 — Measure the score gap

**Goal.** Compute absolute and relative gaps, because a tiny win may not be stable under resampling or new data. We build it in 2 steps.

```python
baseline_b4 = 0.384 # lower score from the baseline.
flexible_b4 = 0.424 # higher score from the alternative.
```

```python
    aic_vals_a2 = [] # AIC values for this n.

    for degree_a2 in degrees_a2: # fit each candidate degree.
        coef_a2 = np.polyfit(x_a2, y_a2, int(degree_a2)) # fit polynomial.
        rss_a2 = float(np.sum((y_a2 - np.polyval(coef_a2, x_a2)) ** 2)) # residual sum of squares.
        rss_a2 = max(rss_a2, 1e-12) # guard log from exact zero in tiny synthetic cases.
        k_a2 = int(degree_a2) + 1 # parameter count.
        aic_vals_a2.append(n_a2 * np.log(rss_a2 / n_a2) + 2 * k_a2) # AIC up to a constant.
        bic_vals_a2.append(n_a2 * np.log(rss_a2 / n_a2) + k_a2 * np.log(n_a2)) # BIC up to a constant.
    aic_choice_a2.append(int(degrees_a2[int(np.argmin(aic_vals_a2))])) # save AIC-selected degree.
    bic_choice_a2.append(int(degrees_a2[int(np.argmin(bic_vals_a2))])) # save BIC-selected degree.
print("AIC choices:", aic_choice_a2) # inspect choices.
print("BIC choices:", bic_choice_a2) # inspect choices.
```

```python
aic_choice_a2 = np.array(aic_choice_a2) # convert for plotting.
bic_choice_a2 = np.array(bic_choice_a2) # convert for plotting.
assert np.all(bic_choice_a2 <= 4) # sanity-check candidate range.
print("choice differences:", aic_choice_a2 - bic_choice_a2) # inspect where AIC is more flexible.
```
▶ What you'll see: AIC may choose equal or higher degree than BIC because its penalty is lighter for larger n.

```python
penalty_table_a2 = np.vstack([2 * np.arange(1, 6), np.log(ns_a2[-1]) * np.arange(1, 6)]) # compare penalties at largest n.
print("AIC penalties at n=80:", np.round(penalty_table_a2[0], 2)) # inspect AIC penalty.
print("BIC penalties at n=80:", np.round(penalty_table_a2[1], 2)) # inspect BIC penalty.
```

▶ What you'll see: the selected degree can differ because AIC and BIC encode different complexity charges.

👀 Takeaway: information criteria are not interchangeable; their penalties reflect different selection philosophies.

### Advanced 3 — Use held-out log likelihood for a Gaussian model

**Goal.** Select a noise scale by validation negative log-likelihood, because likelihood-based selection must judge both prediction error and uncertainty calibration. We build it in 4 steps.

```python
resid_val_a3 = np.array([-0.20, 0.05, 0.15, -0.10, 0.25, -0.05, 0.12, -0.18]) # validation residuals from a fixed predictor.
sigmas_a3 = np.array([0.08, 0.15, 0.25, 0.40, 0.70]) # candidate Gaussian noise scales.
print("validation residuals:", resid_val_a3) # inspect errors to be scored by likelihood.
```
▶ What you'll see: residuals are small but not zero, so too-small sigma will be overconfident.

```python
nll_a3 = [] # validation negative log-likelihood values.
for sigma_a3 in sigmas_a3: # score each uncertainty choice.
    nll_val_a3 = 0.5 * len(resid_val_a3) * np.log(2 * np.pi * sigma_a3 ** 2) + 0.5 * np.sum((resid_val_a3 / sigma_a3) ** 2) # Gaussian NLL.
    nll_a3.append(float(nll_val_a3)) # store score.
nll_a3 = np.array(nll_a3) # convert to array.
print("NLL:", np.round(nll_a3, 3)) # inspect likelihood scores.
```

```python
best_sigma_a3 = float(sigmas_a3[int(np.argmin(nll_a3))]) # choose lowest NLL.
print("best sigma:", best_sigma_a3) # inspect calibrated noise scale.
assert best_sigma_a3 == 0.15 # fixed residuals make this the selected value.
```
▶ What you'll see: very small sigma is punished because it assigns low probability to moderate residuals.


▶ What you'll see: NLL is high for overconfident sigma and also rises when sigma is too broad.

👀 Takeaway: likelihood rewards accurate predictions and honest uncertainty, not just small residuals.

### Advanced 4 — Cross-validation for a regularization knob

**Goal.** Choose ridge regularization by K-fold validation, because a penalty strength is itself a model-selection decision. We build it in 5 steps.

```python
rng_a4 = np.random.default_rng(30) # reproducible simulation.
x_a4 = np.linspace(-2, 2, 24) # inputs.
X_a4 = np.vstack([np.ones_like(x_a4), x_a4, x_a4 ** 2, x_a4 ** 3, x_a4 ** 4]).T # polynomial design matrix with five columns.
y_a4 = 1.0 + 0.5 * x_a4 - 0.35 * x_a4 ** 2 + 0.12 * rng_a4.normal(size=len(x_a4)) # noisy quadratic signal.
lambdas_a4 = np.array([0.0, 0.01, 0.1, 1.0, 10.0]) # ridge strengths.
print("design shape:", X_a4.shape) # inspect model matrix.
```
▶ What you'll see: a five-parameter polynomial basis will be regularized by different λ values.

```python
fold_ids_a4 = np.arange(len(x_a4)) % 4 # deterministic four-fold split.
cv_mse_a4 = [] # store mean validation MSE per lambda.
for lam_a4 in lambdas_a4: # evaluate each regularization strength.
    fold_losses_a4 = [] # losses across folds.
    for fold_a4 in range(4): # leave one fold out.
        train_a4 = fold_ids_a4 != fold_a4 # training mask.
        valid_a4 = fold_ids_a4 == fold_a4 # validation mask.
        XtX_a4 = X_a4[train_a4].T @ X_a4[train_a4] # training Gram matrix.
        penalty_a4 = lam_a4 * np.eye(X_a4.shape[1]) # ridge penalty matrix.
        penalty_a4[0, 0] = 0.0 # do not penalize intercept.
        coef_a4 = np.linalg.solve(XtX_a4 + penalty_a4, X_a4[train_a4].T @ y_a4[train_a4]) # ridge solution.
        pred_a4 = X_a4[valid_a4] @ coef_a4 # validation predictions.
        fold_losses_a4.append(float(np.mean((y_a4[valid_a4] - pred_a4) ** 2))) # fold MSE.
    cv_mse_a4.append(float(np.mean(fold_losses_a4))) # average fold score.
print("CV MSE:", np.round(cv_mse_a4, 4)) # inspect validation scores.
```

```python
best_lam_a4 = float(lambdas_a4[int(np.argmin(cv_mse_a4))]) # select lowest cross-validation MSE.
print("best lambda:", best_lam_a4) # inspect selected penalty.
assert best_lam_a4 in set(lambdas_a4.tolist()) # verify selected value is from the grid.
```
▶ What you'll see: a nonzero λ can win by reducing unstable high-order coefficients.

```python
coefs_a4 = [] # store fitted coefficients for visualization.
for lam_plot_a4 in [0.0, best_lam_a4, 10.0]: # compare unregularized, selected, and strong penalty.
    penalty_plot_a4 = lam_plot_a4 * np.eye(X_a4.shape[1]) # penalty matrix.
    penalty_plot_a4[0, 0] = 0.0 # leave intercept unpenalized.
    coef_plot_a4 = np.linalg.solve(X_a4.T @ X_a4 + penalty_plot_a4, X_a4.T @ y_a4) # ridge coefficients on all data.
    coefs_a4.append(coef_plot_a4) # store coefficient vector.
print("coefficient norms:", [round(float(np.linalg.norm(c[1:])), 3) for c in coefs_a4]) # inspect shrinkage of non-intercept coefficients.
```

```python
plt.figure(figsize=(5, 3)) # create CV curve.
plt.semilogx(lambdas_a4 + 1e-4, cv_mse_a4, marker="o", color="teal") # plot lambda on near-log scale with offset for zero.
plt.axvline(best_lam_a4 + 1e-4, color="crimson", linestyle="--", label="selected") # mark selected lambda.
plt.title("Advanced 4: cross-validation selects regularization") # title plot.
plt.xlabel("lambda (offset for log scale)") # label x axis.
plt.ylabel("4-fold validation MSE") # label y axis.
plt.legend() # show selected marker.
plt.show() # display figure.
```
▶ What you'll see: the curve identifies the penalty strength with the best held-out performance.

👀 Takeaway: regularization strength is selected by future-facing validation, not by training loss alone.

### Advanced 5 — Nested selection avoids optimistic reporting

**Goal.** Separate model choice from final evaluation, because using the same validation scores to both choose and report performance is optimistic. We build it in 5 steps.

```python
rng_a5 = np.random.default_rng(40) # reproducible simulation.
x_all_a5 = np.linspace(-3, 3, 45) # full input grid.
y_all_a5 = np.cos(x_all_a5) + 0.10 * rng_a5.normal(size=len(x_all_a5)) # noisy nonlinear target.
train_idx_a5 = np.arange(0, 30) # model-building rows.
test_idx_a5 = np.arange(30, 45) # untouched final evaluation rows.
degrees_a5 = np.arange(1, 8) # candidate capacities.
print("train/test sizes:", len(train_idx_a5), len(test_idx_a5)) # inspect split sizes.
```
▶ What you'll see: the final test rows are held back from model selection.

```python
x_train_a5 = x_all_a5[train_idx_a5] # training inputs.
y_train_a5 = y_all_a5[train_idx_a5] # training labels.
x_test_a5 = x_all_a5[test_idx_a5] # final test inputs.
y_test_a5 = np.cos(x_test_a5) # noiseless final target for clearer evaluation.
inner_train_a5 = np.arange(len(x_train_a5)) % 3 != 0 # inner training subset.
inner_val_a5 = ~inner_train_a5 # inner validation subset.
print("inner validation count:", int(np.sum(inner_val_a5))) # inspect selection validation size.
```

```python
inner_val_mse_a5 = [] # store validation score per degree.
for degree_a5 in degrees_a5: # fit each candidate on inner training rows.
    coef_a5 = np.polyfit(x_train_a5[inner_train_a5], y_train_a5[inner_train_a5], int(degree_a5)) # fit candidate.
    pred_val_a5 = np.polyval(coef_a5, x_train_a5[inner_val_a5]) # predict inner validation rows.
    inner_val_mse_a5.append(float(np.mean((y_train_a5[inner_val_a5] - pred_val_a5) ** 2))) # store validation MSE.
selected_degree_a5 = int(degrees_a5[int(np.argmin(inner_val_mse_a5))]) # choose by inner validation.
print("inner validation MSE:", np.round(inner_val_mse_a5, 3)) # inspect selection scores.
print("selected degree:", selected_degree_a5) # inspect chosen capacity.
```

```python
coef_final_a5 = np.polyfit(x_train_a5, y_train_a5, selected_degree_a5) # refit selected degree on all model-building data.
test_pred_a5 = np.polyval(coef_final_a5, x_test_a5) # predict untouched test rows.
test_mse_a5 = float(np.mean((y_test_a5 - test_pred_a5) ** 2)) # final evaluation error.
reported_val_a5 = float(np.min(inner_val_mse_a5)) # optimistic selected validation score.
print("selected validation MSE:", round(reported_val_a5, 3)) # inspect inner score.
print("untouched test MSE:", round(test_mse_a5, 3)) # inspect final score.
assert test_mse_a5 >= 0.0 # sanity-check valid MSE.
```
▶ What you'll see: the selected validation score and untouched test score are different quantities.

```python

y_plot_a5 = np.cos(x_plot_a5) # true curve for reference.
y_fit_a5 = np.polyval(coef_final_a5, x_plot_a5) # selected model curve.

```

```python

plt.ylabel("y") # label y axis.

```
▶ What you'll see: the final test region was not used to choose the degree, so its error is a cleaner report.

👀 Takeaway: honest model selection uses one process to choose the model and an untouched evaluation set to report performance.
