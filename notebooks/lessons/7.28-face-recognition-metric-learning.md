# 7.28 — Face Recognition & Metric Learning

Face recognition maps a face crop into an embedding space where identity is judged by geometry: same-person embeddings should point in nearly the same direction, different-person embeddings should be separated by angular margins, and deployment turns those similarities into calibrated verification decisions. In this lesson, we build the embedding math from scratch with NumPy, then implement contrastive, triplet, and ArcFace-style losses without deep-learning frameworks.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build face-recognition metric learning one idea at a time. Run each cell in order and read the printed intermediate values — every score, margin, and threshold is exposed so the geometry is not a black box. This walkthrough is self-contained (it imports what it needs) and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays, vector norms, dot products, softmax math, and reproducible examples.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
np.random.seed(0)  # reproducibility for synthetic embeddings and toy training loops.
```

### 1. Face embeddings replace raw pixels with identity geometry

A face recognizer does not compare raw pixels. Lighting, crop, pose, and expression can move pixels more than identity does, so a model first maps each face crop to a short **embedding** vector. The metric-learning goal is simple: embeddings of the same identity should cluster, while embeddings of different identities should be far apart in the geometry we will later threshold.

```python
raw_pixel_w = np.array([0.1, 0.9, 0.2, 0.8, 0.3, 0.7])  # a tiny fake "face crop" flattened to pixels.
embedding_w = np.array([3.0, 4.0])  # a fake learned identity embedding for that crop.
print("raw pixel length:", raw_pixel_w.size)  # pixels are nuisance-heavy.
print("embedding:", embedding_w)  # the learned representation is compact.
```
▶ What you'll see: many raw coordinates are replaced by a small vector whose coordinates are meant to carry identity-relevant information.

```python
faces_w = np.array([[0.6, 0.8], [0.58, 0.82], [-0.8, 0.6], [-0.82, 0.57]])  # two identities, two samples each.
labels_w = np.array([0, 0, 1, 1])  # identity labels used only for this toy visualization.
plt.figure(figsize=(4.4, 3.4))  # create a compact embedding plot.
for lab_w, color_w in [(0, "teal"), (1, "orange")]:  # draw each identity cluster.
    pts_w = faces_w[labels_w == lab_w]  # select that identity's embeddings.
    plt.scatter(pts_w[:, 0], pts_w[:, 1], s=90, color=color_w, label=f"identity {lab_w}")  # plot points.
plt.axhline(0, color="gray", linewidth=0.5); plt.axvline(0, color="gray", linewidth=0.5)  # reference axes.
plt.title("1: embeddings cluster by identity"); plt.xlabel("embedding dim 0"); plt.ylabel("embedding dim 1")
plt.legend(); plt.show()
```
▶ What you'll see: samples from the same identity sit near each other, while the other identity points in a different direction.

*Why it's done this way:* recognition must work for identities not present as classifier classes at enrollment time. A reusable embedding space solves that: once a face is converted to a vector, verification only needs geometry between vectors, not retraining a classifier for every new person.

### 2. L2 normalization turns similarity into an angular comparison

A raw embedding has both direction and length. If we compare raw dot products, a model can make a vector longer to look more similar without making its **direction** more identity-like. L2 normalization divides by the vector norm, placing embeddings on the unit circle or hypersphere. After that, the dot product equals cosine similarity, so the score measures angle.

```python
u_w = np.array([3.0, 4.0])  # checked example from the lesson text.
norm_u_w = np.linalg.norm(u_w)  # sqrt(3^2 + 4^2) = 5.
uhat_w = u_w / norm_u_w  # normalize to unit length.
print("norm:", norm_u_w)  # inspect the vector length.
print("normalized:", uhat_w)  # [0.6, 0.8].
print("unit norm:", round(np.linalg.norm(uhat_w), 3))  # should be 1.
assert np.allclose(uhat_w, [0.6, 0.8])  # verify the checked normalization.
```
▶ What you'll see: `[3, 4]` becomes `[0.6, 0.8]`, and the normalized vector has length exactly 1.

```python
long_same_dir_w = np.array([6.0, 8.0])  # same direction as u_w, larger magnitude.
other_dir_w = np.array([1.0, 0.0])  # a unit vector on the x-axis.
raw_scores_w = np.array([u_w @ other_dir_w, long_same_dir_w @ other_dir_w])  # raw dot products depend on length.
cos_scores_w = np.array([(u_w / np.linalg.norm(u_w)) @ other_dir_w, (long_same_dir_w / np.linalg.norm(long_same_dir_w)) @ other_dir_w])  # normalized dot products.
print("raw dot scores:", raw_scores_w)  # length changes the score.
print("cosine scores:", cos_scores_w)  # direction-only scores match.
```
▶ What you'll see: the raw dot doubles from 3 to 6, while cosine stays 0.6 because the direction did not change.

```python
plt.figure(figsize=(4.2, 3.4))  # visualize raw and unit vectors.
for vec_w, name_w, col_w in [(u_w, "raw [3,4]", "gray"), (uhat_w, "unit [0.6,0.8]", "teal")]:  # draw arrows.
    plt.arrow(0, 0, vec_w[0], vec_w[1], head_width=0.12, color=col_w, length_includes_head=True)
    plt.text(vec_w[0], vec_w[1], name_w)  # label arrowhead.
plt.xlim(-0.2, 4.2); plt.ylim(-0.2, 4.4); plt.gca().set_aspect("equal", adjustable="box")
plt.title("2: normalization keeps direction, removes length"); plt.show()
```
▶ What you'll see: the unit arrow points in the same direction as the raw arrow but lies on the unit circle.

*Why it's done this way:* identity verification should ask "do these embeddings point in the same identity direction?" not "which embedding has a larger norm?" Normalization removes the shortcut of norm inflation and makes cosine a controlled angular score.

### 3. Cosine similarity and thresholds make verification decisions

Verification compares two normalized embeddings with $s(a,b)=\hat f_a^\top\hat f_b$. The score is continuous; a deployment threshold converts it into "same person" or "different person." The same score can be accepted in a low-security setting and rejected in a high-security setting, so thresholding is a calibration decision, not a law of nature.

```python
v_w = np.array([1.0, 0.0])  # unit vector along the first axis.
sim_uv_w = float(uhat_w @ v_w)  # cosine because both vectors are unit length.
angle_uv_w = float(np.degrees(np.arccos(np.clip(sim_uv_w, -1, 1))))  # convert cosine to angle.
print("cosine similarity:", round(sim_uv_w, 3))  # 0.6.
print("angle degrees:", round(angle_uv_w, 2))  # about 53.13 degrees.
assert round(sim_uv_w, 3) == 0.600 and round(angle_uv_w, 2) == 53.13  # checked values.
```
▶ What you'll see: a cosine of 0.6 corresponds to a fairly large angle of about 53.13°.

```python
thresholds_w = np.array([0.5, 0.7])  # two operating points.
decisions_w = sim_uv_w >= thresholds_w  # accept when score clears the threshold.
print("thresholds:", thresholds_w)  # inspect operating points.
print("accept decisions:", decisions_w)  # True at 0.5, False at 0.7.
```
▶ What you'll see: the exact same pair is accepted at threshold 0.5 and rejected at threshold 0.7.

```python
plt.figure(figsize=(4.4, 3))  # show score and thresholds.
plt.bar(["pair score"], [sim_uv_w], color="teal")  # draw the similarity.
for t_w in thresholds_w:  # draw both thresholds.
    plt.axhline(t_w, linestyle="--", label=f"threshold {t_w}")
plt.ylim(0, 1); plt.ylabel("cosine similarity"); plt.title("3: verification threshold changes the decision")
plt.legend(); plt.show()
```
▶ What you'll see: the score bar lies between the two threshold lines, so policy determines the decision.

*Why it's done this way:* embeddings produce evidence, not policy. The threshold encodes the acceptable tradeoff between false accepts and false rejects for a particular population, camera, and product risk level.

### 4. Contrastive loss pulls positives together and pushes negatives apart

Contrastive learning trains on pairs. For a same-identity pair, the loss penalizes low similarity; for a different-identity pair, it penalizes similarity above a margin. A negative pair with cosine 0.3 may already be safely separated if the allowed maximum is 0.4, but a negative pair at 0.6 violates the margin and gets pushed away.

```python
def contrastive_cosine_loss_w(sim_w, same_w, margin_w=0.4):  # pairwise loss on cosine similarity.
    if same_w:  # positive pair: want similarity near 1.
        return (1.0 - sim_w) ** 2  # squared pull-together penalty.
    return max(0.0, sim_w - margin_w) ** 2  # negative pair: only penalize forbidden closeness.

neg_close_w = 0.6  # impostor too close.
neg_safe_w = 0.3  # impostor safely below margin.
print("close negative loss:", contrastive_cosine_loss_w(neg_close_w, False, 0.4))  # (0.6-0.4)^2.
print("safe negative loss:", contrastive_cosine_loss_w(neg_safe_w, False, 0.4))  # 0.
assert round(contrastive_cosine_loss_w(neg_close_w, False, 0.4), 3) == 0.040  # checked penalty.
```
▶ What you'll see: the impostor at 0.6 pays 0.04, while the impostor at 0.3 pays zero.

```python
sims_grid_w = np.linspace(-0.2, 1.0, 80)  # possible cosine scores.
pos_loss_w = np.array([contrastive_cosine_loss_w(s_w, True, 0.4) for s_w in sims_grid_w])  # positive-pair loss curve.
neg_loss_w = np.array([contrastive_cosine_loss_w(s_w, False, 0.4) for s_w in sims_grid_w])  # negative-pair loss curve.
plt.figure(figsize=(4.8, 3.2))  # plot loss shapes.
plt.plot(sims_grid_w, pos_loss_w, label="positive pair", color="teal")
plt.plot(sims_grid_w, neg_loss_w, label="negative pair", color="crimson")
plt.axvline(0.4, linestyle="--", color="gray", label="negative margin")
plt.xlabel("cosine similarity"); plt.ylabel("loss"); plt.title("4: contrastive loss by pair type")
plt.legend(); plt.show()
```
▶ What you'll see: positives are happiest near similarity 1, while negatives are ignored once they fall below the margin.

*Why it's done this way:* the loss spends capacity where geometry is wrong. Pulling every positive toward 1 builds tight identity clusters; pushing only margin-violating negatives avoids wasting updates on impostors that are already far enough away.

### 5. Triplet loss ranks an anchor closer to its positive than its negative

Triplet loss uses three embeddings: an anchor, a same-identity positive, and a different-identity negative. It does not merely ask whether a pair is good in isolation; it asks for a **ranking gap**. With distances, the target is $d(a,p)+m < d(a,n)$, so the negative must be farther from the anchor by at least the margin.

```python
anchor_w = np.array([1.0, 0.0])  # normalized anchor embedding.
positive_w = np.array([0.8, 0.6])  # same identity, moderately close.
negative_w = np.array([0.6, 0.8])  # different identity, too close for comfort.
d_ap_w = float(np.linalg.norm(anchor_w - positive_w))  # anchor-positive distance.
d_an_w = float(np.linalg.norm(anchor_w - negative_w))  # anchor-negative distance.
triplet_margin_w = 0.3  # required distance gap.
triplet_loss_w = max(0.0, d_ap_w - d_an_w + triplet_margin_w)  # hinge ranking loss.
print("d(anchor, positive):", round(d_ap_w, 3))
print("d(anchor, negative):", round(d_an_w, 3))
print("triplet loss:", round(triplet_loss_w, 3))
```
▶ What you'll see: the loss is positive when the negative is not far enough beyond the positive.

```python
negative_far_w = np.array([-1.0, 0.0])  # an obviously different identity direction.
d_an_far_w = float(np.linalg.norm(anchor_w - negative_far_w))  # far negative distance.
triplet_far_loss_w = max(0.0, d_ap_w - d_an_far_w + triplet_margin_w)  # should be zero.
print("far negative distance:", round(d_an_far_w, 3))
print("far negative triplet loss:", round(triplet_far_loss_w, 3))
assert round(triplet_far_loss_w, 3) == 0.000  # no update once the margin is satisfied.
```
▶ What you'll see: a far negative creates zero loss because the desired ordering already holds.

```python
plt.figure(figsize=(4.2, 3.6))  # visualize the triplet.
for vec_w, name_w, col_w in [(anchor_w, "anchor", "black"), (positive_w, "positive", "teal"), (negative_w, "negative", "crimson"), (negative_far_w, "far neg", "gray")]:
    plt.scatter(vec_w[0], vec_w[1], s=90, color=col_w); plt.text(vec_w[0] + 0.03, vec_w[1] + 0.03, name_w)
plt.gca().set_aspect("equal", adjustable="box"); plt.xlim(-1.2, 1.2); plt.ylim(-0.2, 1.1)
plt.title("5: triplet geometry around an anchor"); plt.show()
```
▶ What you'll see: the same-identity point should be inside the anchor's neighborhood, while negatives should be pushed outside the margin.

*Why it's done this way:* face verification is comparative: the correct match should be closer than impostors. The hinge form focuses learning on triplets whose ranking is still ambiguous, which is why hard-negative mining matters in real systems.

### 6. ArcFace trains angular margins for classification-style supervision

Face systems are often trained with identity labels but deployed by verification. ArcFace bridges that gap by normalizing embeddings and class weights, computing class logits from cosines, and making the correct class harder by replacing $\cos\theta_y$ with $\cos(\theta_y+m)$. The margin is applied during training so identities occupy cleaner angular regions before thresholding.

```python
cos_theta_w = 0.8  # correct-class cosine before margin.
effective_cos_w = 0.6  # toy checked effective cosine after adding angular margin.
scale_w = 10.0  # logit scale used after normalized cosine logits.
unmargined_logit_w = scale_w * cos_theta_w  # 8.
margined_logit_w = scale_w * effective_cos_w  # 6.
print("unmargined correct logit:", unmargined_logit_w)
print("margined correct logit:", margined_logit_w)
print("logit drop:", unmargined_logit_w - margined_logit_w)
assert unmargined_logit_w == 8.0 and margined_logit_w == 6.0  # checked numbers.
```
▶ What you'll see: the correct logit drops by 2, forcing the model to reduce the correct-class angle to regain confidence.

```python
def softmax_w(logits_w):  # stable softmax from scratch.
    z_w = logits_w - np.max(logits_w)  # subtract max to avoid overflow.
    ez_w = np.exp(z_w)  # exponentiate shifted logits.
    return ez_w / ez_w.sum()  # normalize to probabilities.

other_logits_w = np.array([3.0, 1.0])  # two impostor-class logits.
probs_plain_w = softmax_w(np.r_[unmargined_logit_w, other_logits_w])  # probability before margin.
probs_margin_w = softmax_w(np.r_[margined_logit_w, other_logits_w])  # probability after margin.
print("P(correct) plain:", round(float(probs_plain_w[0]), 3))
print("P(correct) margined:", round(float(probs_margin_w[0]), 3))
```
▶ What you'll see: the margin lowers the training probability of the correct class unless the angle becomes smaller.

```python
angles_w = np.linspace(0, 80, 100)  # correct-class angles in degrees.
margin_deg_w = 20  # visual angular margin.
plain_cos_w = np.cos(np.radians(angles_w))  # ordinary cosine logit shape.
margin_cos_w = np.cos(np.radians(angles_w + margin_deg_w))  # ArcFace-style harder target.
plt.figure(figsize=(4.8, 3.2))
plt.plot(angles_w, plain_cos_w, label="cos θ", color="teal")
plt.plot(angles_w, margin_cos_w, label="cos(θ + m)", color="crimson")
plt.xlabel("correct-class angle θ (degrees)"); plt.ylabel("effective cosine")
plt.title("6: ArcFace lowers the correct-class logit"); plt.legend(); plt.show()
```
▶ What you'll see: for the same angle, the margined curve is lower, so classification confidence requires tighter angular alignment.

*Why it's done this way:* a plain classifier can separate training identities without making verification geometry robust for new identities. ArcFace makes the label-supervised task explicitly angular, matching how the embedding will be used at verification time.

### 7. Calibration measures false accepts and false rejects

A verification threshold creates two errors: a false accept when an impostor score is above threshold, and a false reject when a genuine score is below threshold. No single threshold is universally correct; lowering it improves convenience but can admit impostors, while raising it improves security but rejects more genuine users.

```python
genuine_w = np.array([0.9, 0.8, 0.6])  # same-person scores.
impostor_w = np.array([0.7, 0.4, 0.2])  # different-person scores.
thr_w = 0.65  # checked threshold.
false_accepts_w = int(np.sum(impostor_w >= thr_w))  # impostors accepted as same.
false_rejects_w = int(np.sum(genuine_w < thr_w))  # genuine pairs rejected.
print("false accepts:", false_accepts_w, "of", impostor_w.size)
print("false rejects:", false_rejects_w, "of", genuine_w.size)
assert false_accepts_w == 1 and false_rejects_w == 1  # checked calibration example.
```
▶ What you'll see: at threshold 0.65, the impostor score 0.7 is falsely accepted and the genuine score 0.6 is falsely rejected.

```python
threshold_grid_w = np.linspace(0.2, 0.9, 8)  # candidate operating points.
far_w = np.array([np.mean(impostor_w >= t_w) for t_w in threshold_grid_w])  # false accept rate.
frr_w = np.array([np.mean(genuine_w < t_w) for t_w in threshold_grid_w])  # false reject rate.
print("thresholds:", np.round(threshold_grid_w, 2))
print("FAR:", np.round(far_w, 2))
print("FRR:", np.round(frr_w, 2))
```
▶ What you'll see: as the threshold rises, false accepts fall and false rejects rise.

```python
plt.figure(figsize=(4.8, 3.2))  # plot the calibration tradeoff.
plt.plot(threshold_grid_w, far_w, marker="o", label="false accept rate", color="crimson")
plt.plot(threshold_grid_w, frr_w, marker="s", label="false reject rate", color="teal")
plt.axvline(thr_w, linestyle="--", color="gray", label="threshold 0.65")
plt.xlabel("verification threshold"); plt.ylabel("rate"); plt.title("7: threshold calibration tradeoff")
plt.legend(); plt.show()
```
▶ What you'll see: the two curves move in opposite directions, showing why deployment must choose an operating point deliberately.

*Why it's done this way:* the embedding model only supplies scores. Calibration translates scores into actions under product, security, fairness, and population-shift constraints, which is why face systems must be evaluated beyond training accuracy.

### ✍️ Toy 4 · Contrastive loss pulls positives and pushes close negatives

Positive pairs pay when similarity is below 1. Negative pairs pay only when they violate the margin.

```python
import numpy as np

t4_rng = np.random.default_rng(0)
print("rng seed:", 0)  # -> 0
def t4_contrastive(t4_sim, t4_same, t4_margin=0.3):
    if t4_same:
        return (1.0 - t4_sim) ** 2
    return max(0.0, t4_sim - t4_margin) ** 2

t4_pos_sim = 0.75
t4_neg_close = 0.55
t4_neg_safe = 0.10
t4_margin = 0.30
t4_pos_loss = t4_contrastive(t4_pos_sim, True, t4_margin)
t4_close_loss = t4_contrastive(t4_neg_close, False, t4_margin)
t4_safe_loss = t4_contrastive(t4_neg_safe, False, t4_margin)
print("positive loss:", round(t4_pos_loss, 4))  # -> 0.0625
print("close negative loss:", round(t4_close_loss, 4))  # -> 0.0625
```

## 🛠️ Setup

```python
import numpy as np # load NumPy for arrays, vector normalization, dot products, losses, and numerical checks.
import matplotlib.pyplot as plt # load Matplotlib so embeddings, margins, and threshold tradeoffs can be inspected visually.
np.random.seed(0) # make all examples reproducible across notebook runs.

def l2_normalize(x): # Normalize vectors row-wise or vector-wise so cosine becomes a dot product.
    x = np.asarray(x, dtype=float) # Convert input to a float array for safe arithmetic.
    denom = np.linalg.norm(x, axis=-1, keepdims=True) # Compute L2 norms along the embedding dimension.
    return x / np.maximum(denom, 1e-12) # Divide by the norm while guarding against zero vectors.

def cosine_score(a, b): # Compute cosine similarity for two embeddings by normalizing then dotting.
    ah = l2_normalize(a) # Normalize the first embedding.
    bh = l2_normalize(b) # Normalize the second embedding.
    return float(np.sum(ah * bh)) # Return the dot product of unit vectors.

def softmax_np(logits): # Compute softmax probabilities from scratch.
    z = np.asarray(logits, dtype=float) - np.max(logits) # Shift logits for numerical stability.
    e = np.exp(z) # Exponentiate shifted logits.
    return e / np.sum(e) # Normalize exponentials into probabilities.
```

### Advanced 1 — Train a tiny embedding table with contrastive updates

**Goal.** Optimize four embeddings with a simple contrastive-style gradient, because metric learning changes geometry by repeatedly pulling positives and pushing hard negatives. We build it in 4 steps.

```python
emb_a1 = l2_normalize(np.array([[1.0, 0.1], [0.8, 0.6], [-0.2, 1.0], [-0.6, 0.8]])) # Initialize four unit embeddings.
labels_a1 = np.array([0, 0, 1, 1]) # Two identities with two samples each.
pairs_a1 = [(0, 1), (0, 2), (1, 3), (2, 3)] # Include positive and negative pairs.
print("initial embeddings:\n", np.round(emb_a1, 3)) # Inspect starting geometry.
```
▶ What you'll see: each identity has two samples, but some negatives are not well separated yet.

```python
loss_curve_a1 = [] # Store loss after each epoch.
margin_a1 = 0.2 # Maximum allowed negative cosine.
eta_a1 = 0.15 # Small update step for this toy optimization.
for epoch_a1 in range(80): # Repeat simple hand-coded updates.
    total_a1 = 0.0 # Accumulate epoch loss.
    for i_a1, j_a1 in pairs_a1: # Loop through pairs.
        same_a1 = labels_a1[i_a1] == labels_a1[j_a1] # Check whether pair is positive.
        sim_a1 = float(emb_a1[i_a1] @ emb_a1[j_a1]) # Current cosine because vectors are normalized.
        if same_a1: # Pull positives together.
            grad_a1 = (1.0 - sim_a1) * (emb_a1[j_a1] - emb_a1[i_a1]) # Simple symmetric attraction direction.
            emb_a1[i_a1] += eta_a1 * grad_a1; emb_a1[j_a1] -= eta_a1 * grad_a1 # Move them toward each other.
            total_a1 += (1.0 - sim_a1) ** 2 # Add positive loss.
        elif sim_a1 > margin_a1: # Push only hard negatives.
            emb_a1[i_a1] -= eta_a1 * emb_a1[j_a1]; emb_a1[j_a1] -= eta_a1 * emb_a1[i_a1] # Separate directions.
            total_a1 += (sim_a1 - margin_a1) ** 2 # Add negative loss.
        emb_a1 = l2_normalize(emb_a1) # Renormalize after each update.
    loss_curve_a1.append(total_a1) # Save epoch loss.
print("loss start -> end:", round(loss_curve_a1[0], 3), "->", round(loss_curve_a1[-1], 3)) # Inspect improvement.
assert loss_curve_a1[-1] < loss_curve_a1[0] # Verify training reduced the toy objective.
```

```python
sims_after_a1 = emb_a1 @ emb_a1.T # Compute all pairwise cosines after training.
print("pairwise cosines after:\n", np.round(sims_after_a1, 3)) # Inspect geometry.
```

```python
plt.figure(figsize=(4.5, 3)) # Create a learning curve.
plt.plot(loss_curve_a1, color="purple") # Plot objective over epochs.
plt.title("Advanced 1: contrastive toy training"); plt.xlabel("epoch"); plt.ylabel("toy loss"); plt.show() # Display convergence.
```
▶ What you'll see: the toy loss decreases as positives align and hard negatives separate.

👀 Takeaway: metric-learning losses are geometric update rules over embeddings, even when real systems learn those embeddings with deep networks.
