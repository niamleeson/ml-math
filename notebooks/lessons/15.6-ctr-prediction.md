# 15.6 · CTR Prediction

Click-through-rate (CTR) prediction estimates the probability that a user will click an item in a particular context. In this lesson, we build that probability from sparse categorical signals, interactions, embeddings, and calibration checks so the final number can be trusted as a probability — not just as a rank score.

## 📖 Concept walkthrough — build it from scratch

Before the terse worked examples, we build CTR prediction one idea at a time. Run each cell in order and read the printed intermediate values — every probability, loss, cross, and calibration check is exposed. This walkthrough is self-contained (it imports what it needs) and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays, vectorized math, and tiny CTR simulations.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
np.random.seed(0)  # reproducibility for any random examples.

def sigmoid_w(z):  # stable logistic link for logits that may be very positive or negative.
    z = np.asarray(z, dtype=float)  # convert scalars/lists to a NumPy array.
    out = np.empty_like(z)  # allocate the probability output.
    pos = z >= 0  # positive logits can use the direct form safely.
    out[pos] = 1 / (1 + np.exp(-z[pos]))  # σ(z) for z >= 0.
    ez = np.exp(z[~pos])  # for negative z, exp(z) is safe and avoids overflow.
    out[~pos] = ez / (1 + ez)  # algebraically identical σ(z).
    return float(out) if out.shape == () else out  # return a scalar when the input was scalar.

def log_loss_w(y, p):  # binary cross-entropy with clipping to avoid log(0).
    y = np.asarray(y, dtype=float)  # labels are 0/1 clicks.
    p = np.clip(np.asarray(p, dtype=float), 1e-12, 1 - 1e-12)  # guard both logs.
    return -float(np.mean(y * np.log(p) + (1 - y) * np.log(1 - p)))  # average negative log likelihood.
```

### 1. Sparse categorical features: one-hot vectors and hashing

CTR examples usually arrive as categories: country, device, ad id, user segment, hour, and thousands or millions of other IDs. A linear model needs numbers, so the classic **wide** representation turns each active category into a 1 in a huge sparse vector. One-hot encoding is exact and readable; feature hashing is the scalable compromise when the vocabulary is too large to store explicitly.

```python
features_w = ["country=US", "device=mobile", "ad=42"]  # one request's active categorical facts.
vocab_w = ["country=US", "country=CA", "device=mobile", "device=desktop", "ad=42", "ad=99"]  # tiny known vocabulary.
x_onehot_w = np.array([1.0 if f in features_w else 0.0 for f in vocab_w])  # exact sparse wide vector.
print("vocab:", vocab_w)  # inspect the coordinate meanings.
print("one-hot x:", x_onehot_w.astype(int))  # inspect the active coordinates.
```
▶ What you'll see: only `country=US`, `device=mobile`, and `ad=42` are active.

```python
weights_w = np.array([0.7, -0.2, 0.4, -0.1, 0.3, -0.5])  # learned weight for each exact feature.
logit_onehot_w = -1.2 + float(weights_w @ x_onehot_w)  # base logit plus active feature weights.
p_onehot_w = sigmoid_w(logit_onehot_w)  # convert the score into a probability.
print("logit:", round(logit_onehot_w, 3), "probability:", round(p_onehot_w, 3))  # -1.2+0.7+0.4+0.3=0.2.
```
▶ What you'll see: the three active feature weights add to the intercept to make a CTR probability.

```python
def hash_index_w(name, buckets):  # deterministic small teaching hash, not Python's randomized hash().
    return sum(ord(c) for c in name) % buckets  # map any feature string into a bucket.

buckets_w = 4  # deliberately tiny so collisions are visible.
x_hash_w = np.zeros(buckets_w)  # hashed sparse vector.
for f in features_w:  # hash each active feature.
    x_hash_w[hash_index_w(f, buckets_w)] += 1.0  # collisions add in the same bucket.
print("hashed x:", x_hash_w.astype(int))  # inspect compressed representation.
print("bucket ids:", [hash_index_w(f, buckets_w) for f in features_w])  # show where each feature landed.
```
▶ What you'll see: a shorter vector that may combine multiple original features in one bucket.

```python
plt.figure(figsize=(5, 3))  # compare exact and hashed feature vectors.
plt.bar(range(len(x_onehot_w)), x_onehot_w, alpha=.7, label="one-hot")  # exact coordinates.
plt.bar(np.arange(buckets_w) + len(x_onehot_w) + 1, x_hash_w, alpha=.7, label="hashed")  # compressed buckets.
plt.title("1: one-hot exactness vs hashing compression")  # required titled figure.
plt.ylabel("active count")  # 0/1 for one-hot; counts for hashed collisions.
plt.legend(); plt.show()  # display the comparison.
```
▶ What you'll see: one-hot is wider and collision-free; hashing is smaller but can merge signals.

*Why it's done this way: CTR data is mostly categorical and mostly sparse, so one-hot/hashing lets a linear model score only the active facts instead of dense feature tables.*

### 2. Logistic regression CTR model and log-loss

A CTR model must output a probability in $[0,1]$. Logistic regression first computes a real-valued logit $z=b+w^\top x$, then applies the sigmoid

$$p=\sigma(z)=\frac{1}{1+e^{-z}}.$$

The training loss is binary log-loss,

$$L=-\frac{1}{n}\sum_i \left[y_i\log(p_i)+(1-y_i)\log(1-p_i)\right],$$

which is the negative log-likelihood of the observed clicks. It strongly punishes confident wrong probabilities, which is exactly what a probability model should do.

```python
base_w, user_w, item_w = -1.2, 0.7, 0.4  # cited lesson ingredients.
z_w = base_w + user_w + item_w  # linear logit before the sigmoid.
p_w = sigmoid_w(z_w)  # CTR probability.
print("z =", round(z_w, 3))  # -0.100.
print("p = σ(z) =", round(p_w, 3))  # 0.475.
assert round(z_w, 3) == -0.100  # reproduce cited number.
assert round(p_w, 3) == 0.475  # reproduce cited number.
```
▶ What you'll see: $z=-0.100$ becomes $p=0.475$, matching the lesson math.

```python
y_click_w = 1.0  # suppose the user clicked.
loss_click_w = log_loss_w([y_click_w], [p_w])  # log-loss for one clicked example.
loss_no_click_w = log_loss_w([0.0], [p_w])  # loss if the same probability was assigned to a non-click.
print("loss if clicked:", round(loss_click_w, 3))  # -log(0.475).
print("loss if not clicked:", round(loss_no_click_w, 3))  # -log(1-0.475).
```
▶ What you'll see: the same prediction is judged differently depending on whether the click happened.

```python
p_grid_w = np.linspace(0.01, 0.99, 200)  # possible predicted probabilities.
loss_pos_w = -np.log(p_grid_w)  # y=1 loss curve.
loss_neg_w = -np.log(1 - p_grid_w)  # y=0 loss curve.
plt.figure(figsize=(5, 3))  # show why confident mistakes are expensive.
plt.plot(p_grid_w, loss_pos_w, label="clicked y=1")  # decreasing curve.
plt.plot(p_grid_w, loss_neg_w, label="not clicked y=0")  # increasing curve.
plt.axvline(p_w, color="black", linestyle="--", linewidth=1)  # mark the worked prediction.
plt.title("2: log-loss rewards calibrated probabilities")  # required titled figure.
plt.xlabel("predicted CTR p"); plt.ylabel("loss"); plt.legend(); plt.show()  # display.
```
▶ What you'll see: predicting near 0 for a click or near 1 for a non-click explodes the loss.

*Why it's done this way: $w^\top x$ is easy to train and interpret, while $\sigma$ converts the unbounded score into the probability scale that CTR systems consume.*

### 3. Feature crosses: why interactions matter

A main-effect linear model adds country weight plus device weight, so it assumes the effect of mobile is the same in every country. CTR often violates that assumption: `US×mobile` may be strong even if `US` and `mobile` are only mildly useful alone. A crossed feature gives the model one coordinate for the pair, so it can memorize a real interaction without forcing either main effect to carry it.

```python
z_no_cross_w = -2.0 + 0.5 + 0.4  # base + country + device.
p_no_cross_w = sigmoid_w(z_no_cross_w)  # probability without pair-specific lift.
z_cross_w = z_no_cross_w + 1.2  # add the cited crossed-feature weight.
p_cross_w = sigmoid_w(z_cross_w)  # probability with the interaction.
print("without cross:", round(z_no_cross_w, 3), round(p_no_cross_w, 3))  # -1.100, 0.250.
print("with cross:", round(z_cross_w, 3), round(p_cross_w, 3))  # 0.100, 0.525.
assert round(z_no_cross_w, 3) == -1.100 and round(p_no_cross_w, 3) == 0.250  # cited.
assert round(z_cross_w, 3) == 0.100 and round(p_cross_w, 3) == 0.525  # cited.
```
▶ What you'll see: one crossed coordinate more than doubles the predicted CTR.

```python
countries_w = ["US", "CA"]  # two countries.
devices_w = ["mobile", "desktop"]  # two devices.
main_logits_w = np.array([[-2.0 + 0.5 + 0.4, -2.0 + 0.5 - 0.1],  # US rows.
                          [-2.0 - 0.2 + 0.4, -2.0 - 0.2 - 0.1]])  # CA rows.
cross_logits_w = main_logits_w.copy()  # start with the additive model.
cross_logits_w[0, 0] += 1.2  # only US×mobile gets the interaction lift.
print("main-effect probabilities:\n", np.round(sigmoid_w(main_logits_w), 3))  # additive surface.
print("with US×mobile cross:\n", np.round(sigmoid_w(cross_logits_w), 3))  # interaction surface.
```
▶ What you'll see: only the targeted pair changes; the other country/device combinations stay put.

```python
fig, ax = plt.subplots(1, 2, figsize=(7, 3))  # side-by-side heatmaps.
for a, M, title in [(ax[0], sigmoid_w(main_logits_w), "main effects"), (ax[1], sigmoid_w(cross_logits_w), "with cross")]:
    im = a.imshow(M, vmin=0, vmax=.6, cmap="viridis")  # draw probabilities on the same scale.
    a.set_xticks(range(2), devices_w); a.set_yticks(range(2), countries_w)  # readable labels.
    a.set_title(title)  # panel title.
fig.colorbar(im, ax=ax.ravel().tolist(), label="CTR")  # shared color scale.
plt.suptitle("3: feature cross captures a pair-specific lift"); plt.show()  # required titled figure.
```
▶ What you'll see: the crossed model has one bright interaction cell that a purely additive model cannot isolate.

*Why it's done this way: explicit crosses let a wide model memorize high-value pair rules, but they must be controlled because possible pairs grow explosively.*

### 4. Embeddings for high-cardinality IDs

Ad IDs, user IDs, query IDs, and creator IDs can have millions of values. Instead of one independent weight per ID or every possible cross, an embedding table maps each ID to a short learned vector. Dot products between embeddings are the scalable version of crosses: they let IDs interact through reusable latent dimensions, continuing the factor idea from matrix factorization.

```python
E_w = np.array([[0.2, 0.5],  # embedding e0.
                [0.4, 0.1],  # embedding e1.
                [0.3, 0.6]])  # embedding e2.
d01_w = float(E_w[0] @ E_w[1])  # cited pairwise dot.
d02_w = float(E_w[0] @ E_w[2])  # cited pairwise dot.
d12_w = float(E_w[1] @ E_w[2])  # cited pairwise dot.
fm_sum_w = d01_w + d02_w + d12_w  # FM interaction sum.
print("dots:", round(d01_w, 3), round(d02_w, 3), round(d12_w, 3))  # 0.130, 0.360, 0.180.
print("FM interaction sum:", round(fm_sum_w, 3))  # 0.670.
assert round(d01_w, 3) == 0.130 and round(d02_w, 3) == 0.360 and round(d12_w, 3) == 0.180  # cited.
assert round(fm_sum_w, 3) == 0.670  # cited.
```
▶ What you'll see: three embedding vectors create three pairwise interaction scores.

```python
linear_w, deep_w = -0.300, 0.250  # cited DeepFM-style linear and deep pieces.
z_deepfm_w = linear_w + fm_sum_w + deep_w  # one-line wide+FM+deep logit.
p_deepfm_w = sigmoid_w(z_deepfm_w)  # CTR probability.
print("z =", round(z_deepfm_w, 3), "p =", round(p_deepfm_w, 3))  # 0.620, 0.650.
assert round(z_deepfm_w, 3) == 0.620  # cited.
assert round(p_deepfm_w, 3) == 0.650  # cited.
```
▶ What you'll see: linear, FM interaction, and deep terms combine into a calibrated probability candidate.

```python
plt.figure(figsize=(4.6, 3))  # visualize embedding interactions.
plt.bar(["e0·e1", "e0·e2", "e1·e2"], [d01_w, d02_w, d12_w], color="darkorange")  # pairwise dots.
plt.axhline(0, color="black", linewidth=.8)  # zero reference.
plt.title("4: embedding dots act like learned crosses")  # required titled figure.
plt.ylabel("interaction logit contribution"); plt.show()  # display.
```
▶ What you'll see: `e0·e2` is the strongest learned interaction in this tiny example.

*Why it's done this way: embeddings share statistical strength across IDs, so rare categories can generalize through nearby vectors instead of relying on one brittle one-hot weight.*

### 5. Calibration, AUC, and log-loss are different promises

A CTR probability should mean what it says: among examples predicted at 0.20, about 20% should click. That is **calibration**. AUC only checks ranking — whether clicked examples tend to score above non-clicked examples — while log-loss checks the probability scale and punishes overconfident mistakes.

```python
y_w = np.array([0, 0, 1, 1, 0, 1, 0, 1])  # observed clicks.
p_cal_w = np.array([0.05, 0.10, 0.20, 0.30, 0.35, 0.55, 0.70, 0.80])  # predicted CTRs.
print("mean predicted CTR:", round(float(p_cal_w.mean()), 3))  # average predicted probability.
print("empirical CTR:", round(float(y_w.mean()), 3))  # actual click rate.
```
▶ What you'll see: global averages are close-ish, but calibration must also be checked by score bucket.

```python
bins_w = np.array([0.0, 0.25, 0.5, 0.75, 1.0])  # four probability buckets.
centers_w, pred_means_w, emp_means_w = [], [], []  # store reliability-curve points.
for lo_w, hi_w in zip(bins_w[:-1], bins_w[1:]):  # loop over buckets.
    m_w = (p_cal_w >= lo_w) & (p_cal_w < hi_w if hi_w < 1 else p_cal_w <= hi_w)  # bucket membership.
    if m_w.any():  # only plot nonempty buckets.
        centers_w.append((lo_w + hi_w) / 2); pred_means_w.append(float(p_cal_w[m_w].mean())); emp_means_w.append(float(y_w[m_w].mean()))  # average prediction vs actual.
print("bucket predicted:", np.round(pred_means_w, 3))  # x-values.
print("bucket empirical:", np.round(emp_means_w, 3))  # y-values.
```
▶ What you'll see: some buckets under- or over-predict the empirical click rate.

```python
plt.figure(figsize=(4.4, 3.4))  # reliability diagram.
plt.plot([0, 1], [0, 1], "--", color="gray", label="perfect calibration")  # ideal line.
plt.plot(pred_means_w, emp_means_w, marker="o", label="model")  # bucket actual vs predicted.
plt.title("5: reliability curve checks probability scale")  # required titled figure.
plt.xlabel("mean predicted CTR"); plt.ylabel("empirical CTR"); plt.legend(); plt.show()  # display.
```
▶ What you'll see: ranking can look plausible even when probability buckets do not sit on the diagonal.

```python
def auc_w(y, score):  # pairwise AUC: fraction of positive-negative pairs ranked correctly.
    y = np.asarray(y); score = np.asarray(score)  # arrays for indexing.
    pos = score[y == 1]; neg = score[y == 0]  # split positives and negatives.
    wins = sum((p > n) + 0.5 * (p == n) for p in pos for n in neg)  # count wins and ties.
    return float(wins / (len(pos) * len(neg)))  # normalize by all pos-neg pairs.

p_rank_w = np.array([0.25, 0.30, 0.55, 0.60, 0.35, 0.65, 0.40, 0.70])  # good ordering, moderate scale.
p_badscale_w = np.clip(2.0 * p_rank_w, 1e-6, 0.999999)  # same order but overconfident scale.
print("AUCs:", round(auc_w(y_w, p_rank_w), 3), round(auc_w(y_w, p_badscale_w), 3))  # identical ranking.
print("log-losses:", round(log_loss_w(y_w, p_rank_w), 3), round(log_loss_w(y_w, p_badscale_w), 3))  # probability scale differs.
```
▶ What you'll see: multiplying scores can preserve AUC while worsening log-loss and calibration.

*Why it's done this way: CTR systems often bid, pace, or allocate inventory using the probability itself, so a model that ranks well but lies about $p$ can still hurt the product.*

```python
# !pip install numpy matplotlib  # Colab already has these; uncomment only if your runtime is missing them.
import numpy as np  # Import NumPy for arrays, vectorized CTR scoring, and small numerical checks.
import matplotlib.pyplot as plt  # Import Matplotlib for sparse vectors, score curves, reliability diagrams, and ranking plots.
np.random.seed(0)  # Fix the global random seed so every example is repeatable.

def sigmoid(z):  # Define a numerically stable sigmoid σ(z).
    z = np.asarray(z, dtype=float)  # Convert the input to a floating NumPy array.
    out = np.empty_like(z)  # Allocate output probabilities.
    pos = z >= 0  # Mark logits where exp(-z) is safe.
    out[pos] = 1 / (1 + np.exp(-z[pos]))  # Use the standard formula for nonnegative logits.
    ez = np.exp(z[~pos])  # Use exp(z) for negative logits to avoid overflow.
    out[~pos] = ez / (1 + ez)  # Return the algebraically equivalent probability.
    return float(out) if out.shape == () else out  # Preserve scalar outputs for scalar inputs.

def log_loss(y, p):  # Define binary cross-entropy averaged over examples.
    y = np.asarray(y, dtype=float)  # Convert labels to floats.
    p = np.clip(np.asarray(p, dtype=float), 1e-12, 1 - 1e-12)  # Clip probabilities so log(0) never occurs.
    return -float(np.mean(y * np.log(p) + (1 - y) * np.log(1 - p)))  # Return mean negative log-likelihood.

def one_hot(active, vocab):  # Encode active categorical features against a fixed vocabulary.
    return np.array([1.0 if f in active else 0.0 for f in vocab])  # One coordinate per vocabulary entry.

def hash_index(name, buckets):  # Deterministic teaching hash for feature hashing examples.
    return sum(ord(c) for c in name) % buckets  # Map a feature name into a bucket index.

def auc_score(y, score):  # Compute AUC by comparing every positive to every negative.
    y = np.asarray(y); score = np.asarray(score)  # Convert to arrays for boolean indexing.
    pos = score[y == 1]; neg = score[y == 0]  # Split scores by label.
    wins = sum((p > n) + 0.5 * (p == n) for p in pos for n in neg)  # Count correctly ordered pairs and ties.
    return float(wins / (len(pos) * len(neg)))  # Normalize to [0, 1].

def calibration_points(y, p, bins):  # Build reliability-curve points for nonempty bins.
    y = np.asarray(y); p = np.asarray(p)  # Convert inputs to arrays.
    xs, ys, ns = [], [], []  # Store mean prediction, empirical CTR, and count.
    for lo, hi in zip(bins[:-1], bins[1:]):  # Iterate over adjacent bin edges.
        m = (p >= lo) & (p < hi if hi < 1 else p <= hi)  # Select examples in this bin.
        if np.any(m):  # Skip empty bins to avoid NaNs.
            xs.append(float(p[m].mean())); ys.append(float(y[m].mean())); ns.append(int(m.sum()))  # Record summary stats.
    return np.array(xs), np.array(ys), np.array(ns)  # Return arrays for plotting.
```
