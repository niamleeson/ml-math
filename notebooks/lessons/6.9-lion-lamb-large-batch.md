# 6.9 — Lion, LAMB & Large-Batch Training

Lion, LAMB, and large-batch training are all answers to the same scaling problem: when a neural network trains with huge minibatches and many parameter blocks, the optimizer must control both **direction** and **update size** so one layer does not trample the geometry learned by another. In this lesson, you will build the pieces from scratch in NumPy: minibatch gradient noise, momentum, Lion's sign step, LAMB's trust ratio, and the scale bookkeeping that makes large-batch runs stable on hardware.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build large-batch optimization one idea at a time. Run each cell in order and read the printed intermediate values — every piece of math is spelled out so the optimizer is not a black box. This walkthrough is self-contained (it imports what it needs) and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays, vector math, synthetic gradients, and optimizer updates.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
np.random.seed(0)  # reproducibility for minibatch sampling and toy optimizer paths.
```

### 1. Large batches estimate the same gradient with less noise

A minibatch gradient is an estimate of the full-data gradient. Small batches are cheap but noisy; large batches average many examples, so their estimate varies less. That is why large-batch training can use more hardware parallelism — but also why the optimizer must be careful: a low-noise direction can produce a very large, very confident step if the learning rate is not scaled and controlled.

```python
rng_w = np.random.default_rng(0)  # local generator for reproducible per-example gradients.
true_grad_w = np.array([1.5, -0.5])  # the population gradient direction we wish we knew exactly.
per_example_w = true_grad_w + rng_w.normal(0, [1.2, 0.8], size=(4096, 2))  # noisy example gradients.
full_grad_w = per_example_w.mean(axis=0)  # full-batch estimate from all examples.
print("full gradient:", np.round(full_grad_w, 3))  # inspect the near-true average.
assert np.allclose(np.round(full_grad_w, 1), np.array([1.5, -0.5]))  # verify the intended direction.
```
▶ What you'll see: the full average is close to `[1.5, -0.5]`, even though each example is noisy.

```python
batch_sizes_w = np.array([4, 16, 64, 256, 1024])  # compare small to large minibatches.
estimates_w = []  # store many estimated gradients for each batch size.
for b_w in batch_sizes_w:  # sweep batch size.
    draws_w = []  # estimates for this batch size.
    for _ in range(300):  # repeated minibatch samples reveal variance.
        idx_w = rng_w.integers(0, len(per_example_w), size=b_w)  # sample examples with replacement.
        draws_w.append(per_example_w[idx_w].mean(axis=0))  # average their gradients.
    estimates_w.append(np.array(draws_w))  # keep all draws.
std_norm_w = np.array([np.linalg.norm(x.std(axis=0)) for x in estimates_w])  # noise magnitude.
print("gradient-noise norms:", np.round(std_norm_w, 3))  # inspect variance shrinkage.
assert std_norm_w[0] > std_norm_w[-1]  # large batch has lower estimator noise.
```
▶ What you'll see: the noise norm falls as batch size grows; averaging cancels independent example noise.

```python
plt.figure(figsize=(5, 3))  # create a compact noise-vs-batch plot.
plt.plot(batch_sizes_w, std_norm_w, marker="o", color="teal")  # plot estimator noise.
plt.xscale("log")  # batch sizes grow multiplicatively.
plt.title("1: minibatch gradient noise shrinks")  # title the plot.
plt.xlabel("batch size")  # label the batch-size axis.
plt.ylabel("std norm of gradient estimate")  # label the noise axis.
plt.show()  # display the curve.
```
▶ What you'll see: a downward curve — the signal becomes less stochastic as the batch becomes larger.

*Why it's done this way:* A minibatch mean has variance roughly proportional to $1/B$, so increasing batch size makes the update direction more reliable. But reliability is not the same as safety: if the update vector is applied without scale control, every layer receives a confident shove whether or not its parameter norm can absorb it.

### 2. Momentum smooths gradient direction before a step

Momentum stores a moving average $m_t=\beta m_{t-1}+(1-\beta)g_t$. Instead of reacting to one noisy gradient, the optimizer asks what direction has persisted over time. This is the raw material for both Adam-like methods and Lion: a direction estimate that remembers the past while still adapting to the current batch.

```python
grads_w = np.array([[1.8, -0.4], [1.3, -0.8], [1.6, -0.2], [1.2, -0.7]])  # four noisy batch gradients.
beta_w = 0.9  # high beta means long memory.
m_w = np.zeros(2)  # start with no momentum.
print("initial momentum:", m_w)  # inspect the starting state.
```
▶ What you'll see: momentum begins at zero because no previous gradients have been seen.

```python
moments_w = []  # store momentum after each batch.
for g_w in grads_w:  # process gradients in order.
    m_w = beta_w * m_w + (1 - beta_w) * g_w  # exponential moving average.
    moments_w.append(m_w.copy())  # save the state.
print("moments:\n", np.round(moments_w, 3))  # inspect the smoothed directions.
assert np.allclose(np.round(moments_w[-1], 3), np.array([0.501, -0.182]))  # verify the final EMA.
```
▶ What you'll see: the first coordinate stays positive and the second stays negative, but both are smoother than individual gradients.

```python
plt.figure(figsize=(5, 3))  # create a line plot of momentum coordinates.
plt.plot(np.array(moments_w)[:, 0], marker="o", label="m[0]")  # first coordinate.
plt.plot(np.array(moments_w)[:, 1], marker="s", label="m[1]")  # second coordinate.
plt.axhline(0, color="black", linewidth=0.7)  # zero reference.
plt.title("2: momentum accumulates persistent direction")  # title the plot.
plt.xlabel("batch step")  # label time.
plt.ylabel("momentum value")  # label state value.
plt.legend()  # show coordinate labels.
plt.show()  # display the plot.
```
▶ What you'll see: momentum moves gradually instead of jumping to each raw gradient.

*Why it's done this way:* The EMA is a weighted sum of recent gradients, with weights decaying geometrically into the past. That makes a repeated direction survive random batch noise, while a one-off fluctuation is diluted by the $\beta m_{t-1}$ memory term.

### 3. Lion uses the sign of momentum as the update direction

Lion's distinctive move is to update parameters using the **sign** of a momentum-like vector: $\theta_t=\theta_{t-1}-\eta\,\mathrm{sign}(m_t)$. The magnitude of each coordinate is discarded; only whether the smoothed direction is positive, negative, or zero remains. This makes the coordinate step size simple and bounded.

```python
theta_w = np.array([2.0, -1.0, 0.25])  # current parameters.
m_lion_w = np.array([0.8, -0.05, 3.2])  # momentum-like direction estimate.
eta_w = 0.09  # learning rate from the lesson arithmetic.
print("theta before:", theta_w)  # inspect starting parameters.
print("sign(m):", np.sign(m_lion_w))  # inspect Lion's direction-only update.
```
▶ What you'll see: the small negative coordinate and the large positive coordinate both become unit-sized signs.

```python
theta_next_w = theta_w - eta_w * np.sign(m_lion_w)  # Lion sign update.
print("theta after Lion step:", np.round(theta_next_w, 3))  # inspect the new parameters.
assert np.allclose(np.round(theta_next_w, 3), np.array([1.91, -0.91, 0.16]))  # verify numbers.
```
▶ What you'll see: every nonzero coordinate moves by exactly 0.09 in its signed direction.

```python
plt.figure(figsize=(5, 3))  # create a before/after bar plot.
x_w = np.arange(len(theta_w))  # coordinate positions.
plt.bar(x_w - 0.18, theta_w, width=0.36, label="before", color="gray")  # original parameters.
plt.bar(x_w + 0.18, theta_next_w, width=0.36, label="after", color="teal")  # updated parameters.
plt.title("3: Lion takes bounded sign steps")  # title the plot.
plt.xlabel("coordinate")  # label coordinates.
plt.ylabel("parameter value")  # label values.
plt.legend()  # show labels.
plt.show()  # display the bars.
```
▶ What you'll see: each coordinate shifts by the same absolute amount, no matter how large its momentum magnitude was.

*Why it's done this way:* The sign operation is a constraint on update magnitude. It says that a coordinate with a reliable positive direction should move down by one learning-rate unit, but it should not move ten times farther merely because its raw gradient scale is ten times larger. Direction is trusted; magnitude is clipped away.

### 4. LAMB rescales each layer with a trust ratio

LAMB starts from a raw update vector $u$ and rescales it by a trust ratio $r=\lVert\theta\rVert/\lVert u\rVert$. The step becomes $\eta r u$, so the update norm is tied to the parameter norm. This matters in large-batch training because layers can have very different scales; the same raw update norm can be tiny for one layer and destructive for another.

```python
theta_layer_w = np.array([3.0, 4.0])  # layer parameters with norm 5.
u_raw_w = np.array([0.6, 0.8])  # raw update direction with norm 1.
eta_lamb_w = 0.09  # learning rate.
theta_norm_w = np.linalg.norm(theta_layer_w)  # parameter scale.
u_norm_w = np.linalg.norm(u_raw_w)  # raw update scale.
trust_w = theta_norm_w / u_norm_w  # LAMB trust ratio.
print("||theta||:", round(theta_norm_w, 3), "||u||:", round(u_norm_w, 3), "trust ratio:", round(trust_w, 3))  # inspect scales.
assert round(trust_w, 3) == 5.0  # verify the simple 5/1 ratio.
```
▶ What you'll see: a layer with norm 5 and update norm 1 receives trust ratio 5.

```python
step_lamb_w = eta_lamb_w * trust_w * u_raw_w  # scaled LAMB step.
theta_lamb_next_w = theta_layer_w - step_lamb_w  # update parameters.
print("LAMB step:", np.round(step_lamb_w, 3))  # inspect scaled step.
print("theta after:", np.round(theta_lamb_next_w, 3))  # inspect result.
assert np.allclose(np.round(step_lamb_w, 3), np.array([0.27, 0.36]))  # verify eta*5*u.
```
▶ What you'll see: the raw `[0.6, 0.8]` update is scaled to `[0.27, 0.36]` after the learning rate.

```python
layers_w = [np.array([3.0, 4.0]), np.array([0.3, 0.4])]  # same direction, different parameter scales.
trusts_w = [np.linalg.norm(th_w) / np.linalg.norm(u_raw_w) for th_w in layers_w]  # layerwise ratios.
print("trust ratios for large/small layers:", np.round(trusts_w, 3))  # compare scales.
plt.figure(figsize=(4, 3))  # create a trust-ratio plot.
plt.bar(["large layer", "small layer"], trusts_w, color=["teal", "orange"])  # plot layerwise scaling.
plt.title("4: LAMB is layerwise scale control")  # title the plot.
plt.ylabel("trust ratio")  # label the scale factor.
plt.show()  # display the bars.
```
▶ What you'll see: the smaller layer receives a smaller ratio, so the same raw update is not blindly reused at every scale.

*Why it's done this way:* A layer's parameter norm is a local ruler. LAMB asks the update to be proportional to that ruler instead of letting absolute gradient scale decide everything. The ratio is therefore a geometry-preserving constraint: update direction comes from the optimizer, but update length is matched to the layer.

### 5. Large-batch schedules need warmup and scale bookkeeping

Large batches reduce gradient noise, so practitioners often increase the learning rate to keep progress per epoch large. But starting immediately at the large rate can shock the network before momentum, normalization, and trust ratios have stabilized. Warmup slowly raises $\eta$, while normalization and memory accounting remind us that every mathematical choice has a numerical and hardware consequence.

```python
eta_base_w = 0.09  # target learning rate from the lesson arithmetic.
warmup_steps_w = 5  # number of warmup steps.
schedule_w = eta_base_w * (np.arange(1, warmup_steps_w + 1) / warmup_steps_w)  # linear warmup.
print("warmup learning rates:", np.round(schedule_w, 3))  # inspect schedule.
assert round(schedule_w[-1], 3) == 0.09  # final warmup reaches target rate.
```
▶ What you'll see: the learning rate starts small and reaches 0.09 only after five steps.

```python
score_w = 1.8 * 1.5 + (-0.4) * (-0.5) + 0.6  # scratch affine signal from the source lesson.
gated_w = max(0.0, score_w)  # ReLU gate.
prob_w = np.exp(gated_w) / (np.exp(gated_w) + np.exp(0.4))  # two-class softmax probability.
normalized_w = (gated_w - 1.0) / np.sqrt(0.25 + 1e-5)  # scale bookkeeping.
mem_kb_w = 3 * 128 * 4 / 1024  # 3 vectors of length 128 in float32.
print("score:", round(score_w, 3), "prob:", round(prob_w, 3), "normalized:", round(normalized_w, 3), "memory KB:", round(mem_kb_w, 3))
assert round(score_w, 3) == 3.5 and round(prob_w, 3) == 0.957 and round(normalized_w, 3) == 5.0 and round(mem_kb_w, 3) == 1.5
```
▶ What you'll see: the lesson's scratch pass produces score 3.5, softmax probability 0.957, normalized value 5.0, and 1.5 KB of activation memory.

```python
plt.figure(figsize=(5, 3))  # create a schedule plot.
plt.plot(np.arange(1, warmup_steps_w + 1), schedule_w, marker="o", color="purple")  # plot warmup.
plt.axhline(eta_base_w, color="gray", linestyle="--", label="target η")  # target reference.
plt.title("5: warmup reaches the large-batch learning rate")  # title the plot.
plt.xlabel("step")  # label steps.
plt.ylabel("learning rate")  # label learning rate.
plt.legend()  # show target label.
plt.show()  # display the schedule.
```
▶ What you'll see: a ramp rather than a jump, which gives the training dynamics time to settle.

*Why it's done this way:* Large-batch training is a coupled system: batch size changes gradient noise, learning rate changes step length, normalization changes effective scale, and memory limits which batch sizes are possible. Warmup makes the transition gradual, while sign and trust-ratio rules constrain the update once the large-batch regime begins.

### ✍️ Toy 1 · Larger batches have lower gradient noise

A batch mean averages noisy per-example gradients, so repeated estimates vary less as batch size grows.

```python
import numpy as np
import matplotlib.pyplot as plt

t1_rng = np.random.default_rng(0)  # -> seeded Generator(PCG64)
t1_per_example = np.array([0.2, 1.8, 0.7, 1.2, 1.6, 0.5, 1.1, 0.9])  # -> [0.2, 1.8, 0.7, 1.2, 1.6, 0.5, 1.1, 0.9]
print("per-example gradients:", t1_per_example.tolist())  # -> [0.2, 1.8, 0.7, 1.2, 1.6, 0.5, 1.1, 0.9]
t1_full_mean = np.mean(t1_per_example)  # -> 1.0
print("full mean gradient:", round(float(t1_full_mean), 3))  # -> 1.0
t1_batch_sizes = np.array([1, 2, 4, 8])  # -> [1, 2, 4, 8]
print("batch sizes:", t1_batch_sizes.tolist())  # -> [1, 2, 4, 8]
t1_stds = []
for t1_batch in t1_batch_sizes:
    t1_draws = []
    for t1_repeat in range(200):
        t1_idx = t1_rng.integers(0, t1_per_example.size, size=t1_batch)
        t1_draw = np.mean(t1_per_example[t1_idx])
        t1_draws.append(t1_draw)
    t1_stds.append(np.std(t1_draws))
t1_stds = np.array(t1_stds)  # -> [0.477, 0.354, 0.232, 0.169]
print("std of batch means:", np.round(t1_stds, 3).tolist())  # -> [0.477, 0.354, 0.232, 0.169]
assert t1_stds[0] > t1_stds[-1]
assert round(float(t1_full_mean), 3) == 1.0

plt.figure(figsize=(4.8, 2.8))
plt.plot(t1_batch_sizes, t1_stds, marker="o", color="teal")
plt.xlabel("batch size")
plt.ylabel("std of gradient estimate")
plt.title("Toy 1 · averaging reduces noise")
plt.show()
```
▶ What you'll see: the standard deviation falls from `0.477` at batch size 1 to `0.169` at batch size 8.

### ✍️ Toy 2 · Momentum smooths direction

A moving average keeps repeated gradient direction while damping single-step variation.

```python
import numpy as np

t2_rng = np.random.default_rng(0)  # -> seeded Generator(PCG64)
t2_grads = np.array([1.8, 1.2, 1.6, 1.4, 1.5, 1.3])  # -> [1.8, 1.2, 1.6, 1.4, 1.5, 1.3]
print("gradients:", t2_grads.tolist())  # -> [1.8, 1.2, 1.6, 1.4, 1.5, 1.3]
t2_beta = 0.8  # -> 0.8
print("beta:", t2_beta)  # -> 0.8
t2_m = 0.0  # -> 0.0
print("initial momentum:", t2_m)  # -> 0.0
t2_moments = []
for t2_grad in t2_grads:
    t2_m = t2_beta * t2_m + (1.0 - t2_beta) * t2_grad
    t2_moments.append(t2_m)
t2_moments = np.array(t2_moments)  # -> [0.36, 0.528, 0.7424, 0.87392, 0.999136, 1.059309]
print("momentum history:", np.round(t2_moments, 3).tolist())  # -> [0.36, 0.528, 0.742, 0.874, 0.999, 1.059]
t2_delta = t2_grads - t2_moments  # -> [1.44, 0.672, 0.8576, 0.52608, 0.500864, 0.240691]
print("raw minus smoothed:", np.round(t2_delta, 3).tolist())  # -> [1.44, 0.672, 0.858, 0.526, 0.501, 0.241]
assert round(float(t2_moments[-1]), 3) == 1.059
assert t2_moments[-1] < t2_grads.max()

plt.figure(figsize=(4.8, 2.8))
plt.plot(t2_grads, marker="o", label="gradient", color="gray")
plt.plot(t2_moments, marker="s", label="momentum", color="teal")
plt.xlabel("step")
plt.title("Toy 2 · EMA direction")
plt.legend()
plt.show()
```
▶ What you'll see: momentum climbs smoothly to `1.059` instead of jumping to each raw gradient.

### ✍️ Toy 3 · Lion uses the sign of momentum

Lion discards momentum magnitude and moves each nonzero coordinate by one learning-rate unit.

```python
import numpy as np

t3_rng = np.random.default_rng(0)  # -> seeded Generator(PCG64)

```

### ✍️ Toy 4 · LAMB applies a layer trust ratio

LAMB scales an update so its norm is tied to the parameter norm of that layer.

```python
import numpy as np

t4_rng = np.random.default_rng(0)  # -> seeded Generator(PCG64)
t4_theta = np.array([3.0, 4.0, 0.0, 0.0, 0.0, 0.0])  # -> [3.0, 4.0, 0.0, 0.0, 0.0, 0.0]
print("layer theta:", t4_theta.tolist())  # -> [3.0, 4.0, 0.0, 0.0, 0.0, 0.0]
t4_update = np.array([0.6, 0.8, 0.0, 0.0, 0.0, 0.0])  # -> [0.6, 0.8, 0.0, 0.0, 0.0, 0.0]
print("raw update:", t4_update.tolist())  # -> [0.6, 0.8, 0.0, 0.0, 0.0, 0.0]
t4_eta = 0.09  # -> 0.09
print("learning rate:", t4_eta)  # -> 0.09
t4_theta_norm = np.linalg.norm(t4_theta)  # -> 5.0
print("theta norm:", round(float(t4_theta_norm), 3))  # -> 5.0
t4_update_norm = np.linalg.norm(t4_update)  # -> 1.0
print("update norm:", round(float(t4_update_norm), 3))  # -> 1.0
t4_trust = t4_theta_norm / t4_update_norm  # -> 5.0
print("trust ratio:", round(float(t4_trust), 3))  # -> 5.0
t4_step = t4_eta * t4_trust * t4_update  # -> [0.27, 0.36, 0.0, 0.0, 0.0, 0.0]
print("LAMB step:", np.round(t4_step, 3).tolist())  # -> [0.27, 0.36, 0.0, 0.0, 0.0, 0.0]
t4_theta_next = t4_theta - t4_step  # -> [2.73, 3.64, 0.0, 0.0, 0.0, 0.0]
print("theta after:", np.round(t4_theta_next, 3).tolist())  # -> [2.73, 3.64, 0.0, 0.0, 0.0, 0.0]
t4_small_theta = np.array([0.3, 0.4, 0.0, 0.0, 0.0, 0.0])  # -> [0.3, 0.4, 0.0, 0.0, 0.0, 0.0]
print("small layer theta:", t4_small_theta.tolist())  # -> [0.3, 0.4, 0.0, 0.0, 0.0, 0.0]
t4_small_trust = np.linalg.norm(t4_small_theta) / t4_update_norm  # -> 0.5
print("small layer trust:", round(float(t4_small_trust), 3))  # -> 0.5
assert round(float(t4_trust), 3) == 5.0
assert round(float(t4_small_trust), 3) == 0.5

plt.figure(figsize=(4.6, 2.8))
plt.bar(["large layer", "small layer"], [t4_trust, t4_small_trust], color=["teal", "orange"])
plt.ylabel("trust ratio")
plt.title("Toy 4 · LAMB layer scale")
plt.show()
```
▶ What you'll see: the large layer gets trust ratio `5.0`, while the small layer gets `0.5`.

### ✍️ Toy 5 · Warmup ramps the learning rate

Warmup reaches the target learning rate gradually instead of jumping there on step one.

```python
import numpy as np

t5_rng = np.random.default_rng(0)  # -> seeded Generator(PCG64)
t5_target = 0.09  # -> 0.09
print("target learning rate:", t5_target)  # -> 0.09
t5_steps = 6  # -> 6
print("warmup steps:", t5_steps)  # -> 6
t5_index = np.arange(1, t5_steps + 1)  # -> [1, 2, 3, 4, 5, 6]
print("step index:", t5_index.tolist())  # -> [1, 2, 3, 4, 5, 6]
t5_schedule = t5_target * t5_index / t5_steps  # -> [0.015, 0.03, 0.045, 0.06, 0.075, 0.09]
print("warmup schedule:", np.round(t5_schedule, 3).tolist())  # -> [0.015, 0.03, 0.045, 0.06, 0.075, 0.09]
t5_increments = np.diff(np.r_[0.0, t5_schedule])  # -> [0.015, 0.015, 0.015, 0.015, 0.015, 0.015]
```

### Advanced 1 — Sweep batch size and learning-rate scaling

**Goal.** Train the same regression problem with scaled learning rates, because large-batch training often pairs bigger batches with larger learning rates and warmup. We build it in 4 steps.

```python

batches_a1 = np.array([8, 32, 128])  # Batch sizes to sweep.
print("batches:", batches_a1)  # Inspect sweep.
```
▶ What you'll see: three batch sizes from small to large.

```python
final_losses_a1 = []  # Store final MSE per setting.
final_weights_a1 = []  # Store fitted weights and biases.
for batch_a1 in batches_a1:  # Train one model per batch.
    w_a1, b_a1 = 0.0, 0.0  # Initialize linear model.
    eta_a1 = 0.03 * np.sqrt(batch_a1 / 8)  # Conservative square-root LR scaling.
    for step_a1 in range(180):  # Run minibatch SGD.
        idx_a1 = rng_a1.integers(0, len(x_a1), size=batch_a1)  # Sample batch.
        pred_a1 = w_a1 * x_a1[idx_a1] + b_a1  # Predict batch.

        b_a1 -= eta_a1 * np.mean(2 * err_a1)  # Update bias.
    full_loss_a1 = float(np.mean((w_a1 * x_a1 + b_a1 - y_a1) ** 2))  # Full-data MSE.
    final_losses_a1.append(full_loss_a1)  # Store loss.
    final_weights_a1.append([w_a1, b_a1])  # Store parameters.

assert min(final_losses_a1) < 0.02  # Verify at least one setting fits well.
```

```python

```


### Advanced 5 — Combine Adam-style update direction with LAMB trust ratio

**Goal.** Build a miniature LAMB optimizer from scratch, because the real method first forms an adaptive raw update and then applies layerwise trust scaling. We build it in 5 steps.

```python
theta_a5 = np.array([3.0, 4.0])  # Layer parameters.
g_a5 = np.array([0.3, 0.4])  # Current gradient.
m_a5 = np.zeros(2)  # First-moment state.
v_a5 = np.zeros(2)  # Second-moment state.
print("theta:", theta_a5, "gradient:", g_a5)  # Inspect inputs.
```
▶ What you'll see: gradient points in the same direction as the layer for easy arithmetic.

```python
beta1_a5, beta2_a5 = 0.9, 0.99  # Adam-style decay rates.
m_a5 = beta1_a5 * m_a5 + (1 - beta1_a5) * g_a5  # First moment.
v_a5 = beta2_a5 * v_a5 + (1 - beta2_a5) * (g_a5 ** 2)  # Second moment.
mhat_a5 = m_a5 / (1 - beta1_a5)  # Bias-correct first moment at t=1.
vhat_a5 = v_a5 / (1 - beta2_a5)  # Bias-correct second moment at t=1.
print("mhat:", np.round(mhat_a5, 3), "vhat:", np.round(vhat_a5, 3))  # Inspect Adam states.
```

```python
raw_update_a5 = mhat_a5 / (np.sqrt(vhat_a5) + 1e-8)  # Adam-style raw update direction.
trust_a5 = np.linalg.norm(theta_a5) / np.linalg.norm(raw_update_a5)  # LAMB trust ratio.
print("raw update:", np.round(raw_update_a5, 3), "trust:", round(trust_a5, 3))  # Inspect combined pieces.
assert np.allclose(np.round(raw_update_a5, 3), np.array([1.0, 1.0]))  # Verify normalized raw update.
```

```python
eta_a5 = 0.09  # Learning rate.
step_a5 = eta_a5 * trust_a5 * raw_update_a5  # Final LAMB step.
theta_next_a5 = theta_a5 - step_a5  # Apply update.
print("step:", np.round(step_a5, 3), "theta next:", np.round(theta_next_a5, 3))  # Inspect final update.
assert round(np.linalg.norm(step_a5), 3) == 0.45  # Final step norm is eta * ||theta||.
```

```python
plt.figure(figsize=(5, 3))  # Create a final-step plot.
plt.bar(["||theta||", "||raw u||", "||final step||"], [np.linalg.norm(theta_a5), np.linalg.norm(raw_update_a5), np.linalg.norm(step_a5)], color=["gray", "orange", "teal"])  # Compare norms.
plt.title("Advanced 5: Adam direction + LAMB scale")  # Title the plot.
plt.ylabel("norm")  # Label y-axis.
plt.show()  # Display bars.
```
▶ What you'll see: the raw adaptive direction is normalized first, then LAMB scales its final norm to 0.45.

👀 Takeaway: LAMB separates *which way to move* from *how large the layer's move should be*.
