# 15.1 · Collaborative Filtering

Collaborative filtering (CF) recommends items from patterns in a user×item interaction matrix, not from item descriptions. In this lesson, `0` always means **unobserved/unknown**, so we carefully mask missing entries before using neighbors to predict ratings.

## 📖 Concept walkthrough — build it from scratch

Before the terse worked examples, we build collaborative filtering one idea at a time. Run each cell in order and read the printed intermediate values — every piece of math is spelled out so nothing is a black box. This walkthrough is self-contained (it imports what it needs) and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays + linear algebra for ratings and similarities.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
np.random.seed(0)  # reproducibility for anything random.
```

### 1. The user×item matrix and the missing-value problem

Collaborative filtering starts from a table where each **row is a user**, each **column is an item**, and each cell is a rating (or click/watch). Most cells are empty because nobody interacts with everything — and the whole job of a recommender is to fill a chosen empty cell. We store an empty cell as `0`, but `0` here means **"unobserved"**, NOT "rated zero / disliked". Keeping that distinction straight is the single most important habit in CF.

```python
R_w = np.array([[5., 4., 0., 1.],   # Ava
                [4., 5., 0., 1.],   # Ben
                [1., 1., 5., 4.],   # Cam
                [0., 1., 4., 5.]])  # Dee
users_w = ["Ava", "Ben", "Cam", "Dee"]  # row labels for readable output.
items_w = ["I0", "I1", "I2", "I3"]       # column labels.
print("shape:", R_w.shape)               # 4 users x 4 items.
print(R_w)                               # inspect raw ratings; 0 = unobserved.
```
▶ What you'll see: a 4×4 table where the two zeros (Ava→I2 and Dee→I0) are the gaps we might predict.

```python
observed_w = R_w > 0                       # boolean mask: True where a rating exists.
print("observed cells:\n", observed_w.astype(int))  # 1 = known, 0 = unknown.
print("density:", round(observed_w.mean(), 3))       # fraction of the table we actually know.
```
▶ What you'll see: 14 of 16 cells are known here (a dense toy); real matrices are the opposite.

```python
plt.figure(figsize=(4.2, 3.2))                          # small heatmap for the matrix.
plt.imshow(R_w, cmap="viridis")                          # color encodes rating value.
plt.colorbar(label="rating (0 = unobserved)")            # legend for the colors.
plt.xticks(range(4), items_w); plt.yticks(range(4), users_w)  # label axes with names.
plt.title("1: user×item rating matrix"); plt.show()       # render the table.
```
▶ What you'll see: Ava/Ben are bright on I0,I1 (a taste cluster); Cam/Dee are bright on I2,I3 (another).

*Why it's done this way: treating a blank as `0` and feeding it to arithmetic would invent fake "dislike" evidence; the mask above is what lets every later step use only real ratings.*

### 2. How similar are two users? (cosine over the target's rated items)

To borrow a neighbor's opinion we first need a number for "how alike are two users." We use **cosine similarity**: the cosine of the angle between two rating vectors. Two users who rate the same items in the same direction point the same way (cosine near 1); opposite tastes point apart (cosine near −1). The formula is

$$s(u,v)=\frac{R_u\cdot R_v}{\lVert R_u\rVert\,\lVert R_v\rVert}=\frac{\sum_i R_{ui}R_{vi}}{\sqrt{\sum_i R_{ui}^2}\,\sqrt{\sum_i R_{vi}^2}}.$$

Read it in three pieces. The **numerator** $R_u\cdot R_v=\sum_i R_{ui}R_{vi}$ (the dot product) is large when both users give high ratings to the *same* items — it is the raw "agreement." The **denominator** is the product of the two vector lengths $\lVert R_u\rVert=\sqrt{\sum_i R_{ui}^2}$; dividing by it cancels overall rating scale, so a user who simply rates everything high can't look artificially similar to everyone. The result always lands in $[-1,1]$.

The one design decision that makes CF work: **over which items do we compute those sums?** We compute them over the **items the target user has rated** (here Ava's items). That is the evidence base we are trying to extend to a new item, so every neighbor is judged on the same yardstick — Ava's tastes. We must NOT include the item we're predicting (I2) or items outside Ava's history, because a rating there can only distort the geometry with evidence Ava can't corroborate.

```python
ava_w = R_w[0]                            # Ava's full rating row (the target user).
anchor_w = np.where(ava_w > 0)[0]         # the columns Ava has actually rated: I0, I1, I3.
print("Ava:", ava_w)                       # inspect Ava's row.
print("anchor columns (Ava's rated items):", anchor_w)  # the yardstick for similarity.
```
▶ What you'll see: Ava rated I0, I1, I3 — those three columns are our comparison yardstick.

```python
def sim_over_w(x, y, cols):                # cosine restricted to a fixed set of columns.
    xc, yc = x[cols], y[cols]              # slice both users to the anchor columns.
    d = np.linalg.norm(xc) * np.linalg.norm(yc)  # product of the two vector lengths.
    return float(np.dot(xc, yc) / d) if d else 0.0  # cosine; guard against /0.

cam_w = R_w[2]                             # Cam's row.
num_ac_w = float(np.dot(ava_w[anchor_w], cam_w[anchor_w]))  # numerator over the anchor.
print("Ava@anchor:", ava_w[anchor_w], " Cam@anchor:", cam_w[anchor_w])  # [5,4,1] vs [1,1,4].
print("dot (numerator):", num_ac_w)        # 5*1 + 4*1 + 1*4 = 13.
```
▶ What you'll see: the numerator is `[5,4,1]·[1,1,4] = 13`, using only Ava's rated items.

```python
cos_ac_w = sim_over_w(ava_w, cam_w, anchor_w)   # full cosine over the anchor.
print("|Ava@anchor| =", round(np.linalg.norm(ava_w[anchor_w]), 3))  # sqrt(25+16+1)=sqrt42=6.481.
print("|Cam@anchor| =", round(np.linalg.norm(cam_w[anchor_w]), 3))  # sqrt(1+1+16)=sqrt18=4.243.
print("s(Ava,Cam) =", round(cos_ac_w, 3))        # 13 / (6.481*4.243) = 13/27.495.
assert round(cos_ac_w, 3) == 0.473                # matches the lesson number.
```
▶ What you'll see: `13 / 27.495 = 0.473` — Ava and Cam are moderately aligned.

Now the payoff of anchoring: compare the *correct* anchored cosine to the *wrong* full-vector cosine that also counts item I2 (which Cam rated but Ava never did).

```python
allcols_w = np.arange(R_w.shape[1])              # every column, including the unobserved I2.
right_w = sim_over_w(ava_w, cam_w, anchor_w)     # correct: only Ava's rated items.
wrong_w = sim_over_w(ava_w, cam_w, allcols_w)    # wrong: I2 leaks in (Ava=0, Cam=5).
print("anchored cosine (right):", round(right_w, 3))    # 0.473.
print("full-vector cosine (wrong):", round(wrong_w, 3)) # distorted by Cam's I2=5.
```
▶ What you'll see: the wrong version differs because Cam's I2 rating inflates Cam's length with evidence Ava can't match, pulling the similarity down.

```python
plt.figure(figsize=(4.4, 3))                              # compare the two similarities.
plt.bar(["anchored (right)", "full-vector (wrong)"], [right_w, wrong_w],
        color=["seagreen", "indianred"])                  # green = correct, red = buggy.
plt.ylabel("cosine similarity"); plt.ylim(0, 1)           # same scale for a fair look.
plt.title("2: anchoring changes the similarity"); plt.show()
```
▶ What you'll see: two different bars — the unobserved cell you let in genuinely changes the geometry.

*Why it's done this way: cosine turns "do these users agree?" into one weight in [-1,1], and dividing by the norms compares taste direction, not who rates louder — but only if we restrict to the target user's rated items so no phantom rating leaks in.*

### 3. Predicting a blank as a similarity-weighted average

To predict Ava's missing rating for item I2, we look at the users who *did* rate I2 (Cam and Dee), and take a **weighted average** of their I2 ratings, weighting each neighbor by how similar they are to Ava (using the anchored cosine from concept 2). Similar neighbors count more; weak neighbors barely move the estimate. Formally

$$\hat r_{ui}=\frac{\sum_{v}s(u,v)\,r_{vi}}{\sum_{v}s(u,v)}.$$

The denominator $\sum_v s(u,v)$ is what makes it an *average* rather than a sum: it renormalizes so that adding more equally-similar neighbors doesn't inflate the score. Think of each similarity as a "share of the vote," and the rating each neighbor casts is their $r_{vi}$.

```python
target_u_w, target_i_w = 0, 2          # predict Ava (row 0), item I2 (col 2).
raters_w = np.where(R_w[:, target_i_w] > 0)[0]  # users who actually rated I2.
print("users who rated I2:", [users_w[k] for k in raters_w])  # Cam and Dee.
```
▶ What you'll see: only Cam and Dee provide evidence for I2.

```python
sims_w, rates_w = [], []                          # collect (similarity, their rating).
for v in raters_w:                                # loop over neighbors who rated I2.
    s = sim_over_w(R_w[target_u_w], R_w[v], anchor_w)  # anchored similarity of Ava to neighbor.
    sims_w.append(s); rates_w.append(R_w[v, target_i_w])  # store weight and their I2 rating.
    print(f"{users_w[v]}: sim={s:.3f}, rating(I2)={R_w[v, target_i_w]}")  # inspect each.
sims_w, rates_w = np.array(sims_w), np.array(rates_w)  # to arrays for the average.
assert np.allclose(np.round(sims_w, 3), [0.473, 0.272])  # lesson similarities to Cam, Dee.
```
▶ What you'll see: Cam is the stronger neighbor (sim 0.473, rated I2 a 5); Dee is weaker (sim 0.272, rated it 4).

```python
pred_w = float(np.dot(sims_w, rates_w) / sims_w.sum())  # weighted average = prediction.
print("numerator  sum s*r =", round(float(np.dot(sims_w, rates_w)), 3))  # 0.473*5+0.272*4.
print("denominator sum s  =", round(float(sims_w.sum()), 3))              # 0.473+0.272.
print("predicted rating r(Ava,I2) =", round(pred_w, 3))                    # ~4.635.
assert round(pred_w, 3) == 4.635                                            # lesson number.
```
▶ What you'll see: `(0.473·5 + 0.272·4) / (0.473+0.272) = 4.635`, pulled toward Cam's 5.

```python
plt.figure(figsize=(4.6, 3))                              # show each neighbor's contribution.
plt.bar([users_w[v] for v in raters_w], sims_w * rates_w, color="steelblue")  # s*r per neighbor.
plt.axhline(0, color="k", lw=.6)                          # baseline.
plt.ylabel("weight × rating"); plt.title(f"3: contributions → r̂={pred_w:.3f}"); plt.show()
```
▶ What you'll see: Cam's bar dominates, so the prediction lands near 5 rather than 4.

*Why it's done this way: a weighted average lets confident (similar) neighbors speak louder while the denominator keeps the result on the rating scale, no matter how many neighbors chime in.*

### 4. Item–item CF: the same blank, the other axis

There is a second, equally valid way to fill the same cell: instead of "users like Ava," ask "items like the ones Ava already rated." We compute similarity between **item columns** and predict Ava's I2 from her own ratings on items similar to I2. Crucially, this averages a **different set of evidence**, so it generally gives a *different* answer — a reminder that the neighborhood definition, not just the code, decides the recommendation.

```python
def item_sim_w(i, j):                            # similarity between two item COLUMNS.
    a, b = R_w[:, i], R_w[:, j]                   # the two columns.
    m = (a > 0) & (b > 0)                         # users who rated BOTH items.
    if m.sum() == 0:                             # no co-raters -> no evidence.
        return 0.0
    d = np.linalg.norm(a[m]) * np.linalg.norm(b[m])
    return float(np.dot(a[m], b[m]) / d) if d else 0.0

ava_rated_w = np.where(R_w[target_u_w] > 0)[0]   # items Ava already rated: I0,I1,I3.
print("Ava rated items:", [items_w[j] for j in ava_rated_w])  # her evidence items.
```
▶ What you'll see: Ava's own ratings on I0, I1, I3 will stand in for I2.

```python
isims_w, irates_w = [], []                        # (item-similarity, Ava's rating).
for j in ava_rated_w:                             # loop over items Ava rated.
    s = item_sim_w(target_i_w, j)                 # how similar item j is to I2.
    isims_w.append(s); irates_w.append(R_w[target_u_w, j])  # weight and her rating.
    print(f"sim(I2,{items_w[j]})={s:.3f}, Ava's rating={R_w[target_u_w, j]}")  # inspect.
isims_w, irates_w = np.array(isims_w), np.array(irates_w)
assert np.allclose(np.round(isims_w, 3), [1.000, 0.994, 0.976])  # lesson similarities.
```
▶ What you'll see: I2 looks almost identical to I0/I1/I3 by co-rating pattern (sims ≈ 1).

```python
pred_item_w = float(np.dot(isims_w, irates_w) / isims_w.sum())  # weighted average again.
print("item-item prediction r(Ava,I2) =", round(pred_item_w, 3))  # ~3.351.
assert round(pred_item_w, 3) == 3.351                              # lesson number.

plt.figure(figsize=(4.6, 3))
plt.bar(["user-user", "item-item"], [pred_w, pred_item_w], color=["steelblue", "darkorange"])
plt.ylabel("predicted r(Ava,I2)"); plt.title("4: same cell, two neighborhoods"); plt.show()
```
▶ What you'll see: user-user says ≈4.64 but item-item says ≈3.35 — the axis you pick matters.

*Why it's done this way: item neighborhoods are often more stable (popular items accumulate many co-ratings), so switching axes is a real modeling choice, not a cosmetic one.*

### 5. Mean-centering: "likes it more than usual?"

Raw ratings mix two things: a user's **general generosity** and their **specific preference**. A user who rates everything 5 looks similar to everyone, yet tells us little. **Mean-centering** subtracts each user's average rating first, so we compare *deviations from their own baseline* — "does this user like this item more than they usually like things?" — instead of absolute scores.

```python
generous_w = np.array([5., 5., 5., 4.])   # rates almost everything near the top.
picky_w    = np.array([2., 4., 1., 5.])    # uses the whole scale, strong opinions.
print("generous mean:", round(generous_w.mean(), 3))  # ~4.75, barely any variation.
print("picky mean:", round(picky_w.mean(), 3))         # 3.0, wide spread.
```
▶ What you'll see: the generous user's ratings hug one value; the picky user's vary a lot.

```python
gc_w = generous_w - generous_w.mean()   # center the generous user on their own mean.
pc_w = picky_w - picky_w.mean()          # center the picky user on their own mean.
print("centered generous:", np.round(gc_w, 2))  # tiny residuals -> little signal.
print("centered picky:", np.round(pc_w, 2))       # large residuals -> real preference.
```
▶ What you'll see: after centering, the generous user's values collapse toward 0 — exactly the "no real signal" we want to down-weight.

```python
ava_mean_w = R_w[0][R_w[0] > 0].mean()   # Ava's mean over her observed ratings.
print("Ava's mean rating:", round(ava_mean_w, 3))  # (5+4+1)/3.
assert round(ava_mean_w, 3) == 3.333               # lesson number.

fig, ax = plt.subplots(1, 2, figsize=(7, 2.8))
ax[0].bar(items_w, generous_w, color="indianred"); ax[0].axhline(generous_w.mean(), ls="--", c="k")
ax[0].set_title("raw ratings"); ax[1].bar(items_w, gc_w, color="seagreen"); ax[1].axhline(0, c="k", lw=.6)
ax[1].set_title("mean-centered"); plt.suptitle("5: centering removes a generous baseline"); plt.show()
```
▶ What you'll see: centering flattens the generous user (small deviations) while a picky user keeps strong ±deviations that carry the actual taste.

*Why it's done this way: without centering, generous raters dominate the weighted average through scale alone; centering makes the model compare preferences, not personalities.*

### 6. Sparsity and the cold-start wall

Everything above needs **overlap**: shared items to compare users, co-raters to compare items. Real matrices are extreme — often 99.9%+ empty — so overlap is scarce and, for anything brand new, absent. A freshly launched item has an **all-zero column**: no user has rated it, so it has no neighbors and CF simply cannot score it. This "cold-start" wall is *why* later lessons add content features and hybrids.

```python
n_users_w, n_items_w = 10_000, 100_000        # a realistic catalog size.
possible_w = n_users_w * n_items_w             # every user×item pair.
observed_frac_w = 0.001                         # only 0.1% ever interacted.
sparsity_w = 1 - observed_frac_w                # fraction of empty cells.
print("possible pairs:", f"{possible_w:,}")     # 1,000,000,000.
print("sparsity:", f"{sparsity_w:.1%}")          # 99.9% unknown.
assert round(sparsity_w, 3) == 0.999             # the cited number.
```
▶ What you'll see: a billion possible ratings, 99.9% of them blank — neighbors are rare by default.

```python
R_cold_w = np.array([[5., 4., 0.],   # add a brand-new item as a 3rd column (all zeros).
                     [4., 5., 0.],
                     [1., 1., 0.]])
new_col_w = R_cold_w[:, 2]                        # the new item's column.
n_raters_w = int((new_col_w > 0).sum())           # how many ratings it has.
print("new item ratings:", n_raters_w)            # zero.
print("can CF score it?", "no — no neighbors" if n_raters_w == 0 else "yes")  # cold start.
```
▶ What you'll see: the new item has zero raters, so the weighted-average denominator would be 0 — undefined.

```python
plt.figure(figsize=(4.4, 3))
plt.imshow(R_cold_w, cmap="viridis"); plt.colorbar(label="rating")
plt.xticks(range(3), ["I0", "I1", "NEW"]); plt.yticks(range(3), ["u0", "u1", "u2"])
plt.title("6: the all-zero cold-start column"); plt.show()
```
▶ What you'll see: the rightmost column is uniformly dark (unobserved) — invisible to collaborative evidence.

*Why it's done this way: seeing exactly where CF breaks (no overlap, cold items) is what motivates matrix factorization's shared latent space and the content/hybrid fixes in later lessons.*

```python
import numpy as np  # Import NumPy for arrays, linear algebra, masks, and reproducible simulation.
import matplotlib.pyplot as plt  # Import Matplotlib for the heatmaps, bars, scatters, and lines used for debugging CF.
np.random.seed(0)  # Fix the global random seed so every stochastic example is repeatable.
def cosine(a, b):  # Define full-vector cosine for dense vectors where every coordinate is meaningful.
    a = np.asarray(a, dtype=float)  # Convert the first input to a float array so arithmetic is predictable.
    b = np.asarray(b, dtype=float)  # Convert the second input to a float array so arithmetic is predictable.
    denom = np.linalg.norm(a) * np.linalg.norm(b)  # Compute the product of vector lengths used to normalize the dot product.
    return 0.0 if denom == 0 else float(np.dot(a, b) / denom)  # Return 0 for empty evidence; otherwise return cosine similarity.
def masked_cosine(a, b):  # Define CF cosine that only compares positions observed by both vectors.
    a = np.asarray(a, dtype=float)  # Convert the first rating vector to floats for masking and dot products.
    b = np.asarray(b, dtype=float)  # Convert the second rating vector to floats for masking and dot products.
    mask = (a > 0) & (b > 0)  # Keep only shared observed coordinates because zeros mean unknown, not dislike.
    if np.sum(mask) == 0:  # Check whether the two vectors have any common evidence.
        return 0.0  # Return 0 similarity when there is no overlap to compare.
    denom = np.linalg.norm(a[mask]) * np.linalg.norm(b[mask])  # Normalize using only the shared observed coordinates.
    return 0.0 if denom == 0 else float(np.dot(a[mask], b[mask]) / denom)  # Guard against divide-by-zero and return the masked cosine.
def anchor_cosine(a, b, cols):  # Define the lesson's target-context cosine over a chosen set of evidence columns.
    a = np.asarray(a, dtype=float)  # Convert the anchor user vector to floats.
    b = np.asarray(b, dtype=float)  # Convert the neighbor user vector to floats.
    cols = np.asarray(cols, dtype=int)  # Convert the evidence column list to integer indices.
    denom = np.linalg.norm(a[cols]) * np.linalg.norm(b[cols])  # Normalize over the same visible evidence columns.
    return 0.0 if denom == 0 else float(np.dot(a[cols], b[cols]) / denom)  # Return 0 for no evidence; otherwise return the context cosine.
def show_matrix(M, title):  # Define a small heatmap helper so matrices are easy to inspect.
    plt.figure(figsize=(4, 3))  # Start a compact figure that fits well in a notebook cell.
    plt.imshow(M, cmap="viridis", aspect="auto")  # Draw the matrix as color, with rows and columns kept readable.
    plt.colorbar(label="value")  # Add a colorbar so the colors can be interpreted numerically.
    plt.title(title)  # Add a title describing the matrix being shown.
    plt.xlabel("items")  # Label columns as items because CF matrices are user by item.
    plt.ylabel("users")  # Label rows as users because each row is a user profile.
    plt.show()  # Display the figure in the notebook.
```

#### B3. Compute a raw dot product

**Goal.** Measure unnormalized agreement between two user rows, because cosine similarity starts with a dot product before correcting for vector length. We build it in 2 steps.

```python
u_b3 = np.array([5., 4., 0., 1.])  # Define Ava's row with one unknown item.
v_b3 = np.array([4., 5., 0., 1.])  # Define Ben's row with the same unknown item.
products_b3 = u_b3 * v_b3  # Multiply coordinate by coordinate to see each item's contribution.
print("coordinate products:", products_b3)  # Inspect which items create the agreement signal.
```
▶ What you'll see: item 0, item 1, and item 3 contribute positive agreement while item 2 contributes nothing.

```python
dot_b3 = np.dot(u_b3, v_b3)  # Sum the coordinate products into one raw agreement score.
print("raw dot product:", dot_b3)  # Inspect the unnormalized agreement value.
plt.figure(figsize=(4, 3))  # Create a compact bar chart figure.
plt.bar(["I0", "I1", "I2", "I3"], products_b3, color="teal")  # Show each coordinate's contribution to the dot product.
```

#### A5. Sweep neighborhood size k

**Goal.** Evaluate k-nearest-neighbor CF for several k values, because small k can be noisy while large k can include weak neighbors. We build it in 3 steps.

```python
R_A5 = np.array([[5., 4., 0., 1., 0.], [4., 5., 0., 1., 2.], [1., 1., 5., 4., 5.], [0., 1., 4., 5., 4.], [5., 0., 1., 0., 1.], [2., 2., 5., 4., 0.]])  # Create a slightly larger matrix for kNN testing.
truths_A5 = np.array([[0, 2, 4.5], [1, 2, 4.0], [4, 3, 2.0]])  # Define tiny synthetic validation triples as user, item, truth.
ks_A5 = np.array([1, 2, 3, 4])  # Test neighborhood sizes from very local to broader.
print("k values:", ks_A5)  # Inspect the sweep settings.
```
▶ What you'll see: the validation set lets us compare several neighborhood sizes.

```python
rmse_A5 = []  # Store one RMSE value per k.
for k_A5 in ks_A5:  # Loop over candidate neighborhood sizes.
    preds_A5 = []  # Store predictions for this k.
    for u_A5, i_A5, truth_A5 in truths_A5:  # Loop over validation triples.
        u_A5 = int(u_A5)  # Convert the user index from float array storage to int.
        i_A5 = int(i_A5)  # Convert the item index from float array storage to int.
        raters_A5 = np.where(R_A5[:, i_A5] > 0)[0]  # Find users who rated the target item.
        raters_A5 = raters_A5[raters_A5 != u_A5]  # Exclude the target user from neighbors.
        sims_A5 = np.array([masked_cosine(R_A5[u_A5], R_A5[v_A5]) for v_A5 in raters_A5])  # Compute similarities to candidate raters.
        top_A5 = np.argsort(sims_A5)[::-1][:k_A5]  # Keep the k most similar raters.
        pred_A5 = np.sum(sims_A5[top_A5] * R_A5[raters_A5[top_A5], i_A5]) / np.sum(sims_A5[top_A5]) if np.sum(sims_A5[top_A5]) > 0 else np.mean(R_A5[R_A5 > 0])  # Predict with kNN or fall back to global mean.
        preds_A5.append(pred_A5)  # Save this validation prediction.
    rmse_A5.append(np.sqrt(np.mean((np.array(preds_A5) - truths_A5[:, 2]) ** 2)))  # Compute RMSE for this k.
print("RMSE by k:", np.round(rmse_A5, 3))  # Inspect the bias-variance sweep results.
```
