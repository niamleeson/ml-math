# 9.2 — Decoder-Only Models (GPT Family)

Decoder-only models such as GPT take the Transformer decoder idea and train it on one repeated rule: predict the next token from the prefix only. In this lesson, you will build causal masks, attention, a tiny decoder block, next-token loss, and autoregressive generation from scratch with NumPy so the left-to-right factorization is visible in every array.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build decoder-only language modeling one idea at a time. Run each cell in order and read the printed intermediate values — every piece of math, especially the causal mask, is spelled out so future-token leakage cannot hide. This walkthrough is self-contained (it imports what it needs) and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays + linear algebra for tokens, masks, attention, and loss.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
np.random.seed(0)  # reproducibility for toy weights and sampling.
```
▶ What you'll see: the two libraries used everywhere in the notebook are loaded once.

### 1. Tokens, embeddings, and the prefix-only question

A decoder-only language model does not receive a separate encoder input. It receives one sequence of token ids, converts each token into a vector, and asks the same question at every position: **given the prefix so far, what token comes next?** The training data supplies labels by shifting the sequence one step to the left.

```python
vocab_w = ["<bos>", "I", "like", "math", "."]  # tiny vocabulary.
tokens_w = np.array([0, 1, 2, 3, 4])              # <bos> I like math .
inputs_w = tokens_w[:-1]                           # positions used as model inputs.
targets_w = tokens_w[1:]                           # next-token labels.
print("input token ids:", inputs_w)
print("target token ids:", targets_w)
print("input words:", [vocab_w[i] for i in inputs_w])
print("target words:", [vocab_w[i] for i in targets_w])
assert inputs_w.tolist() == [0, 1, 2, 3]
assert targets_w.tolist() == [1, 2, 3, 4]
```
▶ What you'll see: each input token is paired with the token immediately after it.

```python
E_w = np.array([[0.0, 0.0], [1.0, 0.2], [0.8, 0.7], [0.2, 1.0], [0.0, 0.3]])  # token embeddings.
X_w = E_w[inputs_w]                                                            # lookup vectors.
print("embedded inputs shape:", X_w.shape)
print(np.round(X_w, 2))
plt.figure(figsize=(4, 3))
plt.scatter(X_w[:, 0], X_w[:, 1], s=90, color="teal")
for j_w, tok_w in enumerate(inputs_w):
    plt.text(X_w[j_w, 0] + 0.02, X_w[j_w, 1], vocab_w[tok_w])
plt.title("1: tokens become vectors")
plt.xlabel("embedding dim 0"); plt.ylabel("embedding dim 1"); plt.show()
```
▶ What you'll see: four input tokens become four 2-D vectors; the model will transform these vectors into next-token logits.

*Why it's done this way:* shifting turns raw text into supervised examples without hand labels. Position 0 predicts token 1, position 1 predicts token 2, and so on, which implements the factorization $p(x_{1:T})=\prod_t p(x_t\mid x_{<t})$ as ordinary classification at every time step.

### 2. The causal mask: the rule that blocks future leakage

Self-attention normally compares every query position with every key position. A decoder-only model must instead use a **lower-triangular causal mask**: row $t$ may see columns $0,1,\dots,t$, but not columns $t+1,\dots,T-1$. For length $T=4$, that permits $1+2+3+4=10$ query-key pairs instead of all $16$.

```python
T_w = 4
causal_w = np.tril(np.ones((T_w, T_w), dtype=int))  # 1 means attention is allowed.
print(causal_w)
print("allowed pairs:", int(causal_w.sum()), "of", T_w * T_w)
assert int(causal_w.sum()) == 10
```
▶ What you'll see: a lower-triangular matrix where each row can see itself and all earlier tokens.

```python
scores_w = np.arange(T_w * T_w, dtype=float).reshape(T_w, T_w) / 10.0  # toy attention scores.
masked_scores_w = np.where(causal_w == 1, scores_w, -1e9)              # future positions become impossible.
print("raw scores row 2:", scores_w[2])
print("masked row 2:", masked_scores_w[2])
plt.figure(figsize=(7, 3))
plt.subplot(1, 2, 1); plt.imshow(scores_w, cmap="viridis"); plt.title("raw scores")
plt.subplot(1, 2, 2); plt.imshow(masked_scores_w > -1e8, cmap="Greys"); plt.title("allowed mask")
plt.show()
```
▶ What you'll see: row 2 keeps columns 0, 1, 2 and blocks column 3, so the fourth token cannot influence position 2.

*Why it's done this way:* the mask is not a cosmetic triangle. Without it, the model can use the answer token while learning to predict it, making training loss look excellent while violating the left-to-right probability model needed for generation.

### 3. Causal self-attention as weighted prefix averaging

Attention builds a new vector at each position by scoring query-key matches, softmaxing over the **allowed prefix**, and averaging value vectors. The scaled dot product is $QK^\top/\sqrt{d}$; the $\sqrt d$ keeps dot products from growing too large as vector dimension grows.

```python
Q_w = X_w @ np.array([[1.0, 0.2], [0.1, 0.9]])
K_w = X_w @ np.array([[0.7, 0.3], [0.2, 1.0]])
V_w = X_w @ np.array([[1.0, -0.2], [0.3, 0.8]])
raw_attn_w = Q_w @ K_w.T / np.sqrt(Q_w.shape[1])
masked_attn_w = np.where(causal_w == 1, raw_attn_w, -1e9)
print("raw attention scores:\n", np.round(raw_attn_w, 3))
print("masked row 3:", np.round(masked_attn_w[3], 3))
```
▶ What you'll see: the last row can score all four prefix tokens, while earlier rows contain impossible future entries after masking.

```python
def softmax_w(z):
    z = z - np.max(z)
    e = np.exp(z)
    return e / e.sum()
weights_w = np.vstack([softmax_w(masked_attn_w[t_w]) for t_w in range(T_w)])
context_w = weights_w @ V_w
print("attention weights:\n", np.round(weights_w, 3))
print("row sums:", np.round(weights_w.sum(axis=1), 3))
assert np.allclose(weights_w.sum(axis=1), np.ones(T_w))
plt.figure(figsize=(4.5, 3.4))
plt.imshow(weights_w, cmap="magma", vmin=0, vmax=1)
plt.colorbar(label="attention weight")
plt.title("3: causal attention weights")
plt.xlabel("key position"); plt.ylabel("query position"); plt.show()
```
▶ What you'll see: each row sums to 1, and all probability mass stays on the prefix side of the triangle.

*Why it's done this way:* softmax converts compatibility scores into convex averaging weights. The causal mask is applied **before** softmax so forbidden future positions receive zero probability, not merely small influence.

### 4. A tiny decoder block: attention, residuals, normalization, and MLP

A GPT block repeats a pattern: causal self-attention mixes prefix information, a residual connection preserves the old representation, layer normalization stabilizes scale, and a small MLP transforms features position-by-position. We implement a tiny one-block version directly with arrays.

```python
def layernorm_w(Z, eps=1e-6):
    mu = Z.mean(axis=-1, keepdims=True)
    var = ((Z - mu) ** 2).mean(axis=-1, keepdims=True)
    return (Z - mu) / np.sqrt(var + eps)
attn_out_w = context_w
resid1_w = X_w + attn_out_w
norm1_w = layernorm_w(resid1_w)
print("residual+attention shape:", resid1_w.shape)
print("layernorm row means:", np.round(norm1_w.mean(axis=1), 6))
assert np.allclose(norm1_w.mean(axis=1), 0, atol=1e-5)
```
▶ What you'll see: every token vector keeps its shape, and layernorm recenters each row near mean 0.

```python
W1_w = np.array([[1.0, -0.4, 0.2], [0.3, 0.8, -0.5]])
W2_w = np.array([[0.7, 0.1], [-0.2, 0.6], [0.4, -0.3]])
hidden_w = np.maximum(0, norm1_w @ W1_w)  # ReLU MLP hidden layer.
block_w = layernorm_w(norm1_w + hidden_w @ W2_w)
print("block output shape:", block_w.shape)
print("first block vector:", np.round(block_w[0], 3))
plt.figure(figsize=(4.4, 3))
plt.imshow(block_w, cmap="coolwarm", aspect="auto")
plt.colorbar(label="activation")
plt.title("4: one tiny decoder block output")
plt.xlabel("feature"); plt.ylabel("position"); plt.show()
```
▶ What you'll see: each position now carries a transformed representation that used only its prefix.

*Why it's done this way:* attention shares information across time, the MLP changes the feature basis at each time, residuals protect gradients and old information, and normalization keeps repeated blocks numerically stable.

### 5. Next-token logits, softmax probabilities, and cross-entropy

The block output is mapped to one logit per vocabulary token. Softmax turns logits into probabilities; cross-entropy takes $-\log$ of the probability assigned to the true next token. For logits $[2,1,0]$, the probabilities are about $[0.665,0.245,0.090]$.

```python
logits_demo_w = np.array([2.0, 1.0, 0.0])
probs_demo_w = np.exp(logits_demo_w - logits_demo_w.max())
probs_demo_w = probs_demo_w / probs_demo_w.sum()
print("probabilities:", np.round(probs_demo_w, 3))
print("top-token mass:", round(float(probs_demo_w[0]), 3))
assert np.allclose(np.round(probs_demo_w, 3), [0.665, 0.245, 0.09])
```
▶ What you'll see: the largest logit receives most, but not all, probability mass.

```python
W_vocab_w = np.array([[0.2, 0.6, -0.3, 0.9, -0.1],
                      [-0.4, 0.1, 0.8, -0.2, 0.5]])
logits_w = block_w @ W_vocab_w
probs_w = np.exp(logits_w - logits_w.max(axis=1, keepdims=True))
probs_w = probs_w / probs_w.sum(axis=1, keepdims=True)
true_probs_w = probs_w[np.arange(T_w), targets_w]
loss_w = -np.log(true_probs_w).mean()
print("true-token probabilities:", np.round(true_probs_w, 3))
print("mean next-token loss:", round(float(loss_w), 3))
assert true_probs_w.shape == (4,)
plt.figure(figsize=(5, 3))
plt.bar([vocab_w[i] for i in targets_w], -np.log(true_probs_w), color="purple")
plt.title("5: per-position cross-entropy")
plt.ylabel("-log p(true next token)"); plt.show()
```
▶ What you'll see: positions where the true next token has low probability contribute taller loss bars.

*Why it's done this way:* maximizing the product of next-token probabilities is equivalent to minimizing the sum of negative log probabilities. Logs turn products into sums, which is numerically stable and gives additive training loss across positions.

### 6. Autoregressive generation and temperature

At inference time a decoder-only model generates one token, appends it to the prefix, and repeats. Temperature rescales logits before softmax: $T<1$ sharpens choices, $T>1$ spreads mass. With logits $[2,1,0]$ and temperature $0.5$, the top probability rises to about $0.867$.

```python
def softmax_temp_w(logits, temp=1.0):
    z = logits / temp
    z = z - z.max()
    e = np.exp(z)
    return e / e.sum()
sharp_w = softmax_temp_w(np.array([2.0, 1.0, 0.0]), temp=0.5)
flat_w = softmax_temp_w(np.array([2.0, 1.0, 0.0]), temp=2.0)
print("T=0.5:", np.round(sharp_w, 3))
print("T=2.0:", np.round(flat_w, 3))
assert round(float(sharp_w[0]), 3) == 0.867
```
▶ What you'll see: lower temperature concentrates probability on the top token, while higher temperature leaves more uncertainty.

```python
bigram_logits_w = np.array([[0.0, 2.0, 0.5, -1.0, -1.5],
                            [-1.0, -0.5, 2.0, 0.3, -1.0],
                            [-1.0, -0.5, 0.1, 2.0, -0.2],
                            [-1.0, -0.8, -0.2, 0.0, 2.0],
                            [2.0, -1.0, -1.0, -1.0, -1.0]])
generated_w = [0]
for step_w in range(6):
    p_w = softmax_temp_w(bigram_logits_w[generated_w[-1]], temp=0.8)
    generated_w.append(int(np.argmax(p_w)))
print("generated ids:", generated_w)
print("generated words:", [vocab_w[i] for i in generated_w])
assert len(generated_w) == 7
```
▶ What you'll see: six new tokens require six sequential model decisions; each new token becomes part of the next prefix.

```python
x_w = np.arange(3)
plt.figure(figsize=(5, 3))
plt.bar(x_w - 0.18, sharp_w, width=0.36, label="T=0.5", color="teal")
plt.bar(x_w + 0.18, flat_w, width=0.36, label="T=2.0", color="orange")
plt.xticks(x_w, [f"tok {i}" for i in x_w])
plt.ylim(0, 1)
plt.title("6: temperature reshapes next-token probabilities")
plt.ylabel("probability")
plt.legend()
plt.show()
```
▶ What you'll see: low temperature makes the top token dominate, while high temperature spreads probability to alternatives.

*Why it's done this way:* generation cannot be fully parallel over future tokens because token $t+1$ depends on the sampled or chosen token at $t$. The causal training setup matches this inference loop exactly.

### 7. Sequence probability, length bias, and evaluation

The probability of a complete generated sequence is the product of its next-token probabilities. Products shrink with length, so raw sequence probability unfairly punishes longer outputs; average log probability or perplexity is usually a fairer comparison.

```python
step_probs_w = np.array([0.8, 0.5, 0.25])
seq_prob_w = float(np.prod(step_probs_w))
seq_nll_w = float(-np.sum(np.log(step_probs_w)))
print("sequence probability:", round(seq_prob_w, 3))
print("negative log likelihood:", round(seq_nll_w, 3))
assert round(seq_prob_w, 3) == 0.1
```
▶ What you'll see: multiplying three reasonable probabilities already gives a small sequence probability of 0.100.

```python
short_w = np.array([0.6, 0.6])
long_w = np.array([0.6, 0.6, 0.6, 0.6])
raw_probs_w = np.array([np.prod(short_w), np.prod(long_w)])
avg_log_w = np.array([np.mean(np.log(short_w)), np.mean(np.log(long_w))])
perplex_w = np.exp(-avg_log_w)
print("raw probabilities:", np.round(raw_probs_w, 4))
print("per-token perplexities:", np.round(perplex_w, 3))
plt.figure(figsize=(5, 3))
plt.bar(["short raw", "long raw"], raw_probs_w, color=["teal", "orange"])
plt.title("7: raw probability shrinks with length")
plt.ylabel("sequence probability"); plt.show()
```
▶ What you'll see: the longer sequence has lower raw probability even though every token is equally likely; length-normalized scores treat them equally.

*Why it's done this way:* language models define a product over token conditionals, but evaluation should measure the intended behavior. Raw products answer “how likely is this exact whole string,” while per-token log scores answer “how well did the model predict each step.”

### ✍️ Toy 2 · Causal mask keeps only the prefix

The lower triangle is the legality map: row `t` can use columns `0..t` and blocks everything after it.

```python
import numpy as np

t2_seed = 0  # -> 0
```

### ✍️ Toy 3 · Mask before softmax, then average values

Forbidden future scores become impossible before softmax. Their probability becomes exactly zero in the
weighted prefix average.

```python
import numpy as np

t3_seed = 0  # -> 0
t3_rng = np.random.default_rng(0)  # -> reproducible generator
print("seed:", t3_seed)  # -> 0
t3_scores = np.array([0.2, 1.0, 0.5, 2.0])  # -> [0.2, 1.0, 0.5, 2.0]
print("raw scores:", t3_scores.tolist())  # -> [0.2, 1.0, 0.5, 2.0]
t3_prefix_mask = np.array([1, 1, 1, 0])  # -> [1, 1, 1, 0]
print("prefix mask:", t3_prefix_mask.tolist())  # -> [1, 1, 1, 0]
t3_masked_scores = np.where(t3_prefix_mask == 1, t3_scores, -1e9)  # -> [0.2, 1.0, 0.5, -1000000000.0]
print("masked scores:", t3_masked_scores.tolist())  # -> [0.2, 1.0, 0.5, -1000000000.0]
t3_shifted = t3_masked_scores - np.max(t3_masked_scores)  # -> [-0.8, 0.0, -0.5, -1000000001.0]
print("shifted scores:", np.round(t3_shifted, 3).tolist())  # -> [-0.8, 0.0, -0.5, -1000000001.0]
t3_exp = np.exp(t3_shifted)  # -> [0.449, 1.0, 0.607, 0.0]
t3_exp = np.where(t3_prefix_mask == 1, t3_exp, 0.0)  # -> [0.449, 1.0, 0.607, 0.0]
print("exp scores:", np.round(t3_exp, 3).tolist())  # -> [0.449, 1.0, 0.607, 0.0]
t3_weights = t3_exp / np.sum(t3_exp)  # -> [0.219, 0.486, 0.295, 0.0]
print("attention weights:", np.round(t3_weights, 3).tolist())  # -> [0.219, 0.486, 0.295, 0.0]
t3_values = np.array([[1.0, 0.0], [0.0, 1.0], [1.0, 1.0], [9.0, 9.0]])  # -> value rows
print("values:", t3_values.tolist())  # -> [[1.0, 0.0], [0.0, 1.0], [1.0, 1.0], [9.0, 9.0]]
t3_context = t3_weights @ t3_values  # -> [0.514, 0.781]
print("context vector:", np.round(t3_context, 3).tolist())  # -> [0.514, 0.781]

plt.figure(figsize=(4.2, 2.8))
plt.bar(["pos0", "pos1", "pos2", "future"], t3_weights, color=["teal", "teal", "teal", "crimson"])
plt.ylabel("probability")
plt.title("Toy 3 · future weight is zero")
plt.show()
assert round(float(t3_weights.sum()), 3) == 1.0
assert float(t3_weights[3]) == 0.0
```
▶ What you'll see: the future bar is exactly zero, so the `9,9` future value cannot leak into the context.

### ✍️ Toy 4 · Residual, layernorm, and MLP update each row

A tiny decoder block keeps shape while attention output, residual addition, normalization, and an MLP
change the features.

```python
import numpy as np

t4_seed = 0  # -> 0
t4_rng = np.random.default_rng(0)  # -> reproducible generator
print("seed:", t4_seed)  # -> 0
t4_x = np.array([[1.0, 0.0], [0.0, 1.0]])  # -> two token states
print("input states:", t4_x.tolist())  # -> [[1.0, 0.0], [0.0, 1.0]]
t4_attn = np.array([[0.5, 0.5], [0.2, 0.8]])  # -> causal attention weights
print("attention weights:", t4_attn.tolist())  # -> [[0.5, 0.5], [0.2, 0.8]]
t4_values = np.array([[1.0, 0.0], [0.0, 1.0]])  # -> values
print("values:", t4_values.tolist())  # -> [[1.0, 0.0], [0.0, 1.0]]
t4_attn_out = t4_attn @ t4_values  # -> [[0.5, 0.5], [0.2, 0.8]]
print("attention output:", np.round(t4_attn_out, 3).tolist())  # -> [[0.5, 0.5], [0.2, 0.8]]
t4_resid = t4_x + t4_attn_out  # -> [[1.5, 0.5], [0.2, 1.8]]
print("residual sum:", np.round(t4_resid, 3).tolist())  # -> [[1.5, 0.5], [0.2, 1.8]]
t4_mean = np.mean(t4_resid, axis=1, keepdims=True)  # -> [[1.0], [1.0]]
print("row means:", np.round(t4_mean, 3).tolist())  # -> [[1.0], [1.0]]
t4_centered = t4_resid - t4_mean  # -> [[0.5, -0.5], [-0.8, 0.8]]
print("centered rows:", np.round(t4_centered, 3).tolist())  # -> [[0.5, -0.5], [-0.8, 0.8]]
t4_var = np.mean(t4_centered ** 2, axis=1, keepdims=True)  # -> [[0.25], [0.64]]
print("row variances:", np.round(t4_var, 3).tolist())  # -> [[0.25], [0.64]]
t4_norm = t4_centered / np.sqrt(t4_var)  # -> [[1.0, -1.0], [-1.0, 1.0]]
print("normalized rows:", np.round(t4_norm, 3).tolist())  # -> [[1.0, -1.0], [-1.0, 1.0]]
t4_W1 = np.array([[1.0, -0.5], [0.5, 1.0]])  # -> MLP weights
print("MLP W1:", t4_W1.tolist())  # -> [[1.0, -0.5], [0.5, 1.0]]
t4_pre = t4_norm @ t4_W1  # -> [[0.5, -1.5], [-0.5, 1.5]]
```

### ✍️ Toy 7 · Sequence probability shrinks with length

Multiplying token probabilities gives raw sequence probability. Per-token log scores remove the unfair
length penalty when every step is equally likely.

```python
import numpy as np
```

```python
probs_a5 = [np.array([0.7, 0.7]), np.array([0.75, 0.75, 0.75, 0.75])] # token probabilities for each candidate.
print("candidate lengths:", [len(p) for p in probs_a5]) # inspect lengths being compared.
```
▶ What you'll see: the second continuation has twice as many token factors.

```python
raw_a5 = np.array([np.prod(p) for p in probs_a5]) # compute full-sequence probabilities.
avg_log_a5 = np.array([np.mean(np.log(p)) for p in probs_a5]) # compute length-normalized log scores.
print("raw probabilities:", np.round(raw_a5, 4)) # inspect product scores.
print("average log probabilities:", np.round(avg_log_a5, 3)) # inspect per-token scores.
```
▶ What you'll see: raw probability favors the shorter candidate, while average log probability can favor the better per-token candidate.

```python
raw_winner_a5 = candidates_a5[int(np.argmax(raw_a5))] # select by raw sequence probability.
norm_winner_a5 = candidates_a5[int(np.argmax(avg_log_a5))] # select by average log probability.
print("raw winner:", raw_winner_a5) # inspect raw-probability ranking.
print("length-normalized winner:", norm_winner_a5) # inspect normalized ranking.
assert raw_winner_a5 == "short" # verify product length bias.
assert norm_winner_a5 == "long" # verify better per-token probability wins after normalization.
```
▶ What you'll see: the ranking flips when scores are normalized per token.

```python
x_a5 = np.arange(2) # x positions for grouped bars.
```

▶ What you'll see: the long candidate has lower product but higher per-token probability.

👀 Takeaway: always match the sequence scoring rule to the behavior you want to evaluate.
