# 16.6 — Hybrid Retrieval

Hybrid retrieval combines sparse lexical matching with dense semantic matching, then spends slower re-ranking compute only on a small candidate shortlist. In this lesson, we build the whole stack from scratch with tiny NumPy arrays: normalize incompatible scores, fuse sparse and dense evidence, use reciprocal rank fusion when scores are not calibrated, and re-rank only the candidates that survived retrieval.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build hybrid retrieval one idea at a time. Run each cell in order and read the printed intermediate values — every score, rank, normalization, fusion weight, and shortlist decision is visible. This walkthrough is self-contained (it imports what it needs) and uses a `_w` suffix on its variables so it never clashes with the examples below.

### 1. Two retrievers fail in different ways

Hybrid retrieval starts from a practical observation: sparse retrieval and dense retrieval make different mistakes. A sparse system is excellent when the query contains exact terms like product names, error codes, or rare identifiers. A dense system is useful when the wording changes but the meaning stays related. We first create two tiny ranked lists so the complementarity is visible before doing any fusion.

```python
docs_w = np.array(["d1: exact API code", "d2: semantic tutorial", "d3: exact+semantic", "d4: background note"])  # four toy documents.
sparse_raw_w = np.array([8.0, 2.0, 6.0, 1.0])  # BM25-like lexical scores on a large scale.
dense_raw_w = np.array([0.10, 0.90, 0.50, 0.30])  # cosine-like embedding scores on a small scale.
print("documents:", docs_w.tolist())  # inspect the candidates.
print("raw sparse:", sparse_raw_w)  # exact-match evidence.
print("raw dense :", dense_raw_w)  # semantic evidence.
```
▶ What you'll see: sparse likes d1 and d3; dense likes d2 and d3, so neither retriever tells the full story alone.

```python
sparse_rank_w = np.argsort(sparse_raw_w)[::-1]  # highest sparse score first.
dense_rank_w = np.argsort(dense_raw_w)[::-1]  # highest dense score first.
print("sparse order:", docs_w[sparse_rank_w].tolist())  # lexical ranking.
print("dense order :", docs_w[dense_rank_w].tolist())  # semantic ranking.
assert docs_w[sparse_rank_w[0]].startswith("d1")  # exact lexical winner.
assert docs_w[dense_rank_w[0]].startswith("d2")  # semantic winner.
```
▶ What you'll see: the top result changes from d1 to d2 depending on which signal you trust.

```python
x_w = np.arange(len(docs_w))  # bar positions.
plt.figure(figsize=(5.8, 3))  # compact comparison figure.
plt.bar(x_w - 0.18, sparse_raw_w / sparse_raw_w.max(), width=0.36, label="sparse scaled for display")  # show sparse shape.
plt.bar(x_w + 0.18, dense_raw_w / dense_raw_w.max(), width=0.36, label="dense scaled for display")  # show dense shape.
plt.xticks(x_w, ["d1", "d2", "d3", "d4"])  # document ids.
plt.ylabel("relative evidence")  # display scale.
plt.title("1: sparse and dense evidence disagree")  # title.
plt.legend()  # identify bars.
plt.show()  # render.
```
▶ What you'll see: d3 has both signals, d1 is mostly sparse, and d2 is mostly dense.

*Why it's done this way:* hybrid retrieval is not a cosmetic average of two lists; it exists because lexical precision and semantic recall cover different failure modes. The right mental model is candidate union: keep documents each retriever can uniquely discover, then decide how to compare them fairly.

### 2. Normalize scores before arithmetic

A BM25-like score and a cosine-like score do not live on the same numerical scale. If we average raw values, the larger scale wins regardless of relevance. Min-max normalization maps each retriever's scores into `[0, 1]` so a weighted sum can express a modeling choice instead of an accidental units choice.

```python
def minmax_w(x):  # normalize one score vector to [0, 1].
    x = np.asarray(x, dtype=float)  # ensure numeric array arithmetic.
    span = x.max() - x.min()  # score range within this retriever.
    return np.zeros_like(x) if span == 0 else (x - x.min()) / span  # guard constant scores.

sparse_norm_w = minmax_w(sparse_raw_w)  # normalized lexical evidence.
dense_norm_w = minmax_w(dense_raw_w)  # normalized semantic evidence.
print("normalized sparse:", np.round(sparse_norm_w, 3))  # now comparable.
print("normalized dense :", np.round(dense_norm_w, 3))  # now comparable.
```
▶ What you'll see: both score columns now span 0 to 1 even though their original units were different.

```python
raw_avg_w = 0.5 * sparse_raw_w + 0.5 * dense_raw_w  # wrong: units are incompatible.
norm_avg_w = 0.5 * sparse_norm_w + 0.5 * dense_norm_w  # right: comparable inputs.
print("raw-average order :", docs_w[np.argsort(raw_avg_w)[::-1]].tolist())  # dominated by sparse scale.
print("norm-average order:", docs_w[np.argsort(norm_avg_w)[::-1]].tolist())  # balanced evidence.
assert docs_w[np.argsort(raw_avg_w)[::-1][0]].startswith("d1")  # raw BM25 scale dominates.
assert docs_w[np.argsort(norm_avg_w)[::-1][0]].startswith("d3")  # balanced candidate wins.
```
▶ What you'll see: raw averaging crowns d1; normalized averaging crowns d3 because it has both kinds of evidence.

```python
plt.figure(figsize=(5.2, 3))  # compact diagnostic.
plt.plot(["d1", "d2", "d3", "d4"], raw_avg_w, marker="o", label="raw average")  # incompatible average.
plt.plot(["d1", "d2", "d3", "d4"], norm_avg_w, marker="s", label="normalized average")  # calibrated average.
plt.title("2: normalization changes the fused order")  # title.
plt.ylabel("score")  # score axis.
plt.legend()  # labels.
plt.show()  # render.
```
▶ What you'll see: the two curves pick different winners; that is the calibration warning made visible.

*Why it's done this way:* weighted sums assume equal units. Min-max normalization is simple but mathematically important: subtracting the minimum sets a common zero, and dividing by the range sets a common maximum, so `alpha` controls evidence preference rather than score scale.

### 3. Weighted score fusion with alpha

Once sparse and dense scores are comparable, a simple hybrid score is

$$s_h(d)=\alpha s_b(d)+(1-\alpha)s_e(d).$$

The parameter `alpha` is the knob: larger values favor exact lexical evidence, smaller values favor semantic evidence. We compute the formula term by term and inspect how changing `alpha` moves the ranking.

```python
alpha_w = 0.5  # equal trust in sparse and dense normalized scores.
hybrid_w = alpha_w * sparse_norm_w + (1 - alpha_w) * dense_norm_w  # convex combination.
for name_w, sb_w, se_w, sh_w in zip(docs_w, sparse_norm_w, dense_norm_w, hybrid_w):  # inspect each document.
    print(name_w[:2], "=", round(alpha_w * sb_w, 3), "+", round((1 - alpha_w) * se_w, 3), "->", round(sh_w, 3))  # term breakdown.
assert round(float(hybrid_w[2]), 3) == 0.607  # d3 has balanced evidence.
```
▶ What you'll see: d3 receives a strong contribution from both terms, while d1 and d2 mostly rely on one side.

```python
alphas_w = np.array([0.2, 0.5, 0.8])  # semantic-heavy, balanced, sparse-heavy.
orders_w = []  # store winners.
for a_w in alphas_w:  # sweep alpha.
    score_w = a_w * sparse_norm_w + (1 - a_w) * dense_norm_w  # fused scores.
    winner_w = docs_w[np.argmax(score_w)][:2]  # top document id.
    orders_w.append(winner_w)  # save for display.
    print("alpha", a_w, "scores", np.round(score_w, 3), "winner", winner_w)  # inspect.
assert orders_w == ["d2", "d3", "d1"]  # semantic, balanced, lexical regimes.
```
▶ What you'll see: alpha changes the winner from dense-only d2 to balanced d3 to sparse-only d1.

```python
plt.figure(figsize=(5.4, 3))  # compact alpha sweep.
for j_w, label_w in enumerate(["d1", "d2", "d3", "d4"]):  # one line per document.
    plt.plot(alphas_w, [a_w * sparse_norm_w[j_w] + (1 - a_w) * dense_norm_w[j_w] for a_w in alphas_w], marker="o", label=label_w)  # score curve.
plt.xlabel("alpha: sparse weight")  # x-axis.
plt.ylabel("hybrid score")  # y-axis.
plt.title("3: alpha chooses lexical vs semantic emphasis")  # title.
plt.legend(ncol=4)  # compact legend.
plt.show()  # render.
```
▶ What you'll see: d2 falls as alpha grows, d1 rises, and d3 is strong in the middle.

*Why it's done this way:* the formula is a convex combination, so the fused score stays between the normalized inputs. That makes `alpha` interpretable: it is not an arbitrary coefficient but the fraction of trust assigned to sparse evidence for this query or product setting.

### 4. Reciprocal Rank Fusion without calibrated scores

Sometimes score calibration is unreliable: maybe one retriever returns BM25 scores, another returns ANN distances, and another returns only ranks. Reciprocal Rank Fusion (RRF) avoids score units entirely. Each document gets

$$\text{RRF}(d)=\sum_m \frac{1}{k+\operatorname{rank}_m(d)},$$

where rank 1 is best and `k` softens the advantage of top positions.

```python
sparse_list_w = ["d1", "d3", "d4"]  # sparse top-k ranking only; d2 was not admitted by sparse.
dense_list_w = ["d2", "d3", "d4"]  # dense top-k ranking only; d1 was not admitted by dense.
k_rrf_w = 60  # common RRF smoothing constant.
rank_maps_w = []  # rank lookup for each retriever.
for ranking_w in [sparse_list_w, dense_list_w]:  # build rank maps.
    rank_maps_w.append({doc_w: rank_w + 1 for rank_w, doc_w in enumerate(ranking_w)})  # 1-based ranks.
print("sparse ranks:", rank_maps_w[0])  # inspect lexical ranks.
print("dense ranks :", rank_maps_w[1])  # inspect semantic ranks.
```
▶ What you'll see: d3 is rank 2 in both systems, while d1 and d2 each win one system and are missing from the other top-k list.

```python
rrf_w = defaultdict(float)  # accumulated RRF scores.
for ranks_w in rank_maps_w:  # loop over retrievers.
    for doc_w, r_w in ranks_w.items():  # loop over documents in that ranking.
        rrf_w[doc_w] += 1.0 / (k_rrf_w + r_w)  # reciprocal rank contribution.
rrf_order_w = sorted(rrf_w, key=lambda d_w: rrf_w[d_w], reverse=True)  # fused order.
print("RRF scores:", {d_w: round(rrf_w[d_w], 5) for d_w in rrf_order_w})  # inspect.
print("RRF order:", rrf_order_w)  # final order.
assert rrf_order_w[0] == "d3"  # consistently high beats one-list-only wins.
```
▶ What you'll see: d3 wins because two second-place votes beat a first-place plus fourth-place split.

```python
plt.figure(figsize=(5, 3))  # compact bar chart.
plt.bar(rrf_order_w, [rrf_w[d_w] for d_w in rrf_order_w], color="seagreen")  # RRF scores.
plt.title("4: RRF rewards consistent high ranks")  # title.
plt.ylabel("sum 1/(k+rank)")  # score definition.
plt.show()  # render.
```
▶ What you'll see: the score differences are small but ordered; RRF is rank-based, not magnitude-based.

*Why it's done this way:* reciprocal ranks convert positions into comparable evidence. The smoothing constant `k` prevents a single rank-1 result from overwhelming everything, so a document that is reliably near the top of multiple lists can beat a volatile one-retriever winner.

### 5. Re-rank only the shortlist

Hybrid retrieval is usually a two-stage system. Sparse+dense fusion cheaply creates a candidate shortlist with high recall; a slower model then re-ranks only that shortlist for precision. In this toy lesson, the re-ranker is just a hand-written score vector, but the math mirrors a cross-encoder stage.

```python
shortlist_size_w = 3  # keep only the top hybrid candidates.
shortlist_w = np.argsort(hybrid_w)[::-1][:shortlist_size_w]  # candidate generation output.
rerank_scores_w = np.array([0.30, 0.95, 0.55, 0.20])  # expensive pairwise model scores for each doc.
print("hybrid shortlist:", docs_w[shortlist_w].tolist())  # candidates the re-ranker is allowed to see.
print("re-ranker scores on shortlist:", np.round(rerank_scores_w[shortlist_w], 3))  # expensive scores.
assert 1 in shortlist_w and 2 in shortlist_w  # dense-only and balanced candidates survived.
```
▶ What you'll see: the shortlist keeps d2 and d3, so the re-ranker can separate them.

```python
lam_w = 0.4  # weight retained for the first-stage hybrid score.
final_scores_w = np.full(len(docs_w), -np.inf)  # docs outside the shortlist are not re-ranked.
final_scores_w[shortlist_w] = lam_w * hybrid_w[shortlist_w] + (1 - lam_w) * rerank_scores_w[shortlist_w]  # final fusion.
final_order_w = np.argsort(final_scores_w)[::-1]  # final ranking.
print("final scores:", np.round(final_scores_w, 3))  # inspect finite shortlist scores.
print("final order:", docs_w[final_order_w].tolist())  # output ranking.
assert docs_w[final_order_w[0]].startswith("d2")  # re-ranker promotes d2.
```
▶ What you'll see: d2 rises above d3 because the re-ranker strongly prefers it.

```python
n_docs_w = 1_000_000  # large corpus size.
short_w = 100  # production-like shortlist size.
savings_w = n_docs_w / short_w  # fewer expensive passes.
print("cross-encoder passes all docs:", n_docs_w)  # impossible stage.
print("cross-encoder passes shortlist:", short_w)  # feasible stage.
print("compute reduction:", int(savings_w), "x")  # arithmetic reason for staging.
assert int(savings_w) == 10000  # concrete number from the lesson logic.
```
▶ What you'll see: re-ranking 100 candidates instead of 1,000,000 is a 10,000× reduction.

```python
plt.figure(figsize=(5, 3))  # compact staged-ranking view.
plt.bar(["hybrid d2", "hybrid d3", "final d2", "final d3"], [hybrid_w[1], hybrid_w[2], final_scores_w[1], final_scores_w[2]], color=["gray", "gray", "teal", "teal"])  # before/after.
plt.title("5: re-ranking separates shortlist ties")  # title.
plt.ylabel("score")  # score axis.
plt.xticks(rotation=20)  # readable labels.
plt.show()  # render.
```
▶ What you'll see: d2 and d3 are close after hybrid retrieval, but final scores separate them.

*Why it's done this way:* candidate generation optimizes recall under cheap compute, while re-ranking optimizes precision under expensive compute. The shortlist cutoff is therefore a mathematical contract: anything excluded cannot be recovered later, so it must be large enough for recall before precision is improved.

## 🛠️ Setup

```python
import numpy as np # load NumPy for arrays, normalization, ranking, and numerical checks.
import matplotlib.pyplot as plt # load Matplotlib for every bar chart, heatmap, and line plot.
from collections import defaultdict # load defaultdict for rank-fusion accumulators.
np.random.seed(0) # make all examples reproducible.

def minmax(x): # normalize a score vector into [0, 1] for score fusion.
    x = np.asarray(x, dtype=float) # convert to a float array so subtraction and division are predictable.
    span = x.max() - x.min() # compute the within-retriever score range.
    return np.zeros_like(x) if span == 0 else (x - x.min()) / span # avoid divide-by-zero for constant scores.

def order_labels(scores, labels): # return labels sorted by descending score.
    scores = np.asarray(scores, dtype=float) # ensure NumPy sorting works consistently.
    return [labels[i] for i in np.argsort(scores)[::-1]] # argsort ascending then reverse for highest first.

def reciprocal_rank_fusion(rankings, k=60): # fuse ranked lists without using raw scores.
    scores = defaultdict(float) # accumulate one reciprocal-rank contribution per retriever.
    for ranking in rankings: # loop over each retriever's ranked list.
        for rank, doc in enumerate(ranking, start=1): # use 1-based ranks because rank 1 is best.
            scores[doc] += 1.0 / (k + rank) # add the RRF contribution for this retriever.
    return dict(scores) # return a plain dictionary for inspection.

def plot_scores(labels, scores, title): # small helper for repeated score bar charts.
    plt.figure(figsize=(5, 3)) # create a compact figure.
    plt.bar(labels, scores, color="teal") # draw one score bar per document.
    plt.title(title) # label the plot.
    plt.ylabel("score") # label the score axis.
    plt.show() # display the figure.
```

pool_b7 = [] # keep insertion order while avoiding duplicates.

👀 Takeaway: candidate union protects recall by keeping documents found by either retriever.

### Basic 9 — Fuse two rankings with RRF
