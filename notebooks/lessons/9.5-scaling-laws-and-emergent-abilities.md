# 9.5 — Scaling Laws & Emergent Abilities

Scaling laws describe a surprisingly regular pattern in modern language models: validation loss often falls like a smooth power law as we add parameters and data, while benchmark abilities can look sudden because we measure them through thresholds. In this lesson, you will build toy scaling curves from scratch, fit them on log-log axes, allocate compute with the Chinchilla-style data/model tradeoff, and see why "emergence" can be a smooth capability crossing a sharp metric boundary.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build scaling laws one idea at a time. Run each cell in order and read the printed intermediate values — every piece of math, including the power-law fitting and Chinchilla allocation logic, is shown with tiny NumPy arrays. This walkthrough is self-contained and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays, logarithms, least-squares fits, and deterministic toy data.
import matplotlib.pyplot as plt  # visualizations for scaling curves and thresholds.
np.random.seed(0)  # reproducibility for any simulated observations.
```

### 1. Loss decomposes into irreducible, model-size, and data-size terms

A basic scaling law says validation loss can be approximated as

$$L(N,D)=L_\infty+aN^{-\alpha}+bD^{-\beta}.$$

Read this as three pieces. $L_\infty$ is the irreducible floor: even infinite compute cannot remove uncertainty in the data distribution. The model-size term $aN^{-\alpha}$ shrinks as parameter count $N$ grows; the data term $bD^{-\beta}$ shrinks as token count $D$ grows. The negative exponents are the power-law part: multiplying scale by a fixed factor subtracts a fixed fraction of the remaining excess loss.

```python
L_inf_w = 1.0  # irreducible loss floor.
a_w, alpha_w = 2.0, 0.5  # model-size coefficient and exponent.
b_w, beta_w = 3.0, 0.5  # data-size coefficient and exponent.
N_w, D_w = 400.0, 900.0  # toy model parameters and data tokens.
model_term_w = a_w * N_w ** (-alpha_w)  # 2 / sqrt(400) = 0.100.
data_term_w = b_w * D_w ** (-beta_w)  # 3 / sqrt(900) = 0.100.
loss_w = L_inf_w + model_term_w + data_term_w  # total validation loss.
print("model term:", round(model_term_w, 3), "data term:", round(data_term_w, 3))
print("total loss:", round(loss_w, 3))
assert round(model_term_w, 3) == 0.100
assert round(data_term_w, 3) == 0.100
assert round(loss_w, 3) == 1.200
```
▶ What you'll see: the two reducible terms each contribute 0.100, so the total is 1.200 above a floor of 1.0.

```python
N_grid_w = np.array([100, 200, 400, 800, 1600], dtype=float)  # model sizes to compare.
model_terms_w = a_w * N_grid_w ** (-alpha_w)  # hold data fixed and vary only N.
print("N grid:", N_grid_w.astype(int))
print("model terms:", np.round(model_terms_w, 3))
assert round(float(model_terms_w[0]), 3) == 0.200
assert round(float(model_terms_w[2]), 3) == 0.100
```
▶ What you'll see: increasing N from 100 to 400 halves the model-size term from 0.200 to 0.100.

```python
D_grid_w = np.array([225, 400, 900, 1600, 3600], dtype=float)  # data sizes to compare.
data_terms_w = b_w * D_grid_w ** (-beta_w)  # hold model size fixed and vary only D.
plt.figure(figsize=(5, 3))
plt.plot(N_grid_w, model_terms_w, marker="o", label="aN^{-α}")
plt.plot(D_grid_w, data_terms_w, marker="s", label="bD^{-β}")
plt.xscale("log"); plt.yscale("log")
plt.xlabel("scale (N or D)"); plt.ylabel("excess loss term")
plt.title("1: power-law terms are straight on log-log axes")
plt.legend(); plt.show()
```
▶ What you'll see: both curves are straight lines on log-log axes because a power law becomes linear after taking logs.

*Why it's done this way: the formula separates what scaling can reduce from what it cannot. The exponent says how fast a bottleneck shrinks; the coefficient says how large that bottleneck is at the current scale.*

### 2. Fitting a power law from log-log data

If excess loss obeys $y=cx^{-\gamma}$, then taking logs gives

$$\log y=\log c-\gamma\log x.$$

That is a straight line. So fitting a power law from scratch means subtract the loss floor, take logs, solve a tiny least-squares line fit, then convert slope and intercept back into an exponent and coefficient. This is why scaling-law papers love log-log plots: the slope is the exponent.

```python
N_fit_w = np.array([100, 400, 1600, 6400], dtype=float)  # measured model sizes.
true_c_w, true_gamma_w = 2.0, 0.5  # known toy coefficient and exponent.
excess_fit_w = true_c_w * N_fit_w ** (-true_gamma_w)  # floor-subtracted losses.
print("excess loss:", np.round(excess_fit_w, 4))
assert round(float(excess_fit_w[0]), 3) == 0.200
assert round(float(excess_fit_w[-1]), 3) == 0.025
```
▶ What you'll see: every 4× increase in N cuts the excess loss in half because the exponent is 0.5.

```python
xlog_w = np.log(N_fit_w)  # predictor for the line.
ylog_w = np.log(excess_fit_w)  # response for the line.
A_w = np.column_stack([np.ones_like(xlog_w), xlog_w])  # columns for intercept and slope.
intercept_w, slope_w = np.linalg.lstsq(A_w, ylog_w, rcond=None)[0]  # least-squares line.
gamma_hat_w = -slope_w  # log y = log c - gamma log x.
c_hat_w = np.exp(intercept_w)  # exponentiate intercept to recover coefficient.
print("c_hat:", round(c_hat_w, 3), "gamma_hat:", round(gamma_hat_w, 3))
assert round(c_hat_w, 3) == 2.000
assert round(gamma_hat_w, 3) == 0.500
```
▶ What you'll see: the fitted coefficient and exponent recover the toy law exactly.

```python
fit_excess_w = c_hat_w * N_fit_w ** (-gamma_hat_w)  # predicted excess loss from fitted law.
plt.figure(figsize=(5, 3))
plt.loglog(N_fit_w, excess_fit_w, "o", label="observed")
plt.loglog(N_fit_w, fit_excess_w, "-", label="fitted power law")
plt.xlabel("parameters N"); plt.ylabel("excess loss")
plt.title("2: fitting slope on log-log data")
plt.legend(); plt.show()
```
▶ What you'll see: the fitted line runs through the points; its log-log slope is −0.5.

*Why it's done this way: least squares solves the linearized problem directly, and the minus sign on the slope matters because loss decreases as scale increases.*

### 3. Chinchilla-style compute allocation balances N and D

Scaling only parameters is wasteful if the data term stays large. Chinchilla-style reasoning says that under a compute budget, roughly proportional to $N\times D$ for dense transformer training, we should choose both model size and token count so neither bottleneck dominates. In this toy law, the balanced point minimizes

$$aN^{-\alpha}+bD^{-\beta}\quad\text{subject to}\quad ND=C.$$

We can solve it by a grid search: try candidate $N$, set $D=C/N$, and choose the lowest loss.

```python
C_w = 360000.0  # toy compute budget proportional to N * D.
N_candidates_w = np.array([100, 200, 400, 600, 900, 1200, 1800, 2400], dtype=float)
D_candidates_w = C_w / N_candidates_w  # compute constraint forces D once N is chosen.
excess_candidates_w = a_w * N_candidates_w ** (-alpha_w) + b_w * D_candidates_w ** (-beta_w)
best_idx_w = int(np.argmin(excess_candidates_w))
print("best N:", int(N_candidates_w[best_idx_w]), "best D:", int(D_candidates_w[best_idx_w]))
print("best excess loss:", round(float(excess_candidates_w[best_idx_w]), 3))
assert int(N_candidates_w[best_idx_w]) == 400
assert int(D_candidates_w[best_idx_w]) == 900
```
▶ What you'll see: with this budget and coefficients, the best grid point is N=400 and D=900.

```python
terms_at_best_w = np.array([a_w * N_candidates_w[best_idx_w] ** (-alpha_w),
                            b_w * D_candidates_w[best_idx_w] ** (-beta_w)])
print("best model/data terms:", np.round(terms_at_best_w, 3))
assert np.allclose(np.round(terms_at_best_w, 3), [0.100, 0.100])
```
▶ What you'll see: the best point balances the two terms at 0.100 each, so neither is the obvious bottleneck.

```python
plt.figure(figsize=(5, 3))
plt.plot(N_candidates_w, excess_candidates_w, marker="o", color="purple")
plt.axvline(N_candidates_w[best_idx_w], color="red", linestyle="--", label="best N")
plt.xlabel("parameters N under fixed compute")
plt.ylabel("excess loss")
plt.title("3: Chinchilla-style compute allocation")
plt.legend(); plt.show()
```
▶ What you'll see: the curve is U-shaped; too-small models waste data, and too-large models starve on too few tokens.

*Why it's done this way: fixed compute creates a tradeoff, not a free lunch. Increasing N forces D down, so the optimum is where marginal gains from more parameters and more tokens are balanced.*

### 4. Emergent abilities can be thresholded smooth curves

An ability may look sudden when a benchmark reports pass/fail. Suppose hidden capability margin grows smoothly as loss falls or scale rises, and a task score is a sigmoid

$$s(m)=\frac{1}{1+e^{-m}}.$$

The underlying margin can change smoothly, while the reported metric jumps when it crosses a threshold such as 50% accuracy. That is not fake; it means the measurement is nonlinear and thresholded.

```python
margin_w = 1.5  # toy capability margin from the lesson block.
score_w = 1 / (1 + np.exp(-margin_w))  # sigmoid score.
print("sigmoid score:", round(score_w, 3))
assert round(score_w, 3) == 0.818
```
▶ What you'll see: a margin of 1.5 maps to a strong score of 0.818.

```python
scales_w = np.array([1, 2, 4, 8, 16, 32, 64], dtype=float)
margin_curve_w = np.log2(scales_w) - 3.0  # smooth margin crosses zero near scale 8.
score_curve_w = 1 / (1 + np.exp(-margin_curve_w))
pass_curve_w = (score_curve_w >= 0.5).astype(int)  # thresholded benchmark success.
print("scores:", np.round(score_curve_w, 3))
print("pass/fail:", pass_curve_w)
assert pass_curve_w.tolist() == [0, 0, 0, 1, 1, 1, 1]
```
▶ What you'll see: scores rise smoothly, but the pass/fail metric flips suddenly at the threshold.

```python
plt.figure(figsize=(5, 3))
plt.plot(scales_w, score_curve_w, marker="o", label="smooth score")
plt.step(scales_w, pass_curve_w, where="mid", label="thresholded pass/fail")
plt.xscale("log", base=2); plt.ylim(-0.05, 1.05)
plt.xlabel("model scale"); plt.ylabel("reported ability")
plt.title("4: smooth capability, sharp metric")
plt.legend(); plt.show()
```
▶ What you'll see: the smooth curve climbs gradually, while the step curve looks emergent because of the threshold.

*Why it's done this way: sigmoid scoring turns a continuous margin into a bounded probability-like value, and thresholding that value can create an apparent phase change even when learning itself is continuous.*

### 5. Data quality and distribution shift change the curve you are on

A power law is not destiny. It describes performance for a fixed data distribution, objective, and evaluation setup. If data quality improves, the coefficient or effective data count can improve; if evaluation shifts to harder data, the irreducible floor or coefficient can rise. The same $N$ and $D$ then land on a different curve.

```python
N_quality_w = np.array([200, 400, 800, 1600], dtype=float)
D_quality_w = 900.0
loss_clean_w = L_inf_w + a_w * N_quality_w ** (-alpha_w) + b_w * D_quality_w ** (-beta_w)
loss_noisy_w = 1.15 + 2.6 * N_quality_w ** (-alpha_w) + 3.8 * D_quality_w ** (-beta_w)
print("clean losses:", np.round(loss_clean_w, 3))
print("shifted/noisy losses:", np.round(loss_noisy_w, 3))
assert round(float(loss_clean_w[1]), 3) == 1.200
assert round(float(loss_noisy_w[1]), 3) == 1.407
```
▶ What you'll see: the shifted/noisy curve is higher even at the same model and data sizes.

```python
gap_w = loss_noisy_w - loss_clean_w
print("loss gap from data/eval change:", np.round(gap_w, 3))
plt.figure(figsize=(5, 3))
plt.plot(N_quality_w, loss_clean_w, marker="o", label="clean/easy distribution")
plt.plot(N_quality_w, loss_noisy_w, marker="s", label="shifted/noisy distribution")
plt.xscale("log", base=2)
plt.xlabel("parameters N"); plt.ylabel("validation loss")
plt.title("5: scaling law depends on the data distribution")
plt.legend(); plt.show()
```
▶ What you'll see: both curves improve with N, but the harder distribution stays above the clean one.

*Why it's done this way: scaling curves are empirical summaries conditioned on a setup; changing data quality or evaluation changes the constants, so extrapolating blindly can overpromise.*

### ✍️ Toy 1 · Decompose scaling loss into floor, model, and data terms

A scaling-law loss is a sum of an irreducible floor plus separate reducible bottlenecks from model size
and data size.

```python
import numpy as np
import matplotlib.pyplot as plt

t1_seed = 0  # -> 0
t1_rng = np.random.default_rng(0)  # -> reproducible generator
print("seed:", t1_seed)  # -> 0
t1_L_inf = 1.0  # -> 1.0
print("loss floor:", t1_L_inf)  # -> 1.0
t1_a = 2.0  # -> 2.0
print("model coefficient:", t1_a)  # -> 2.0
t1_alpha = 0.5  # -> 0.5
print("model exponent:", t1_alpha)  # -> 0.5
t1_b = 3.0  # -> 3.0
print("data coefficient:", t1_b)  # -> 3.0
t1_beta = 0.5  # -> 0.5
print("data exponent:", t1_beta)  # -> 0.5
t1_N = 400.0  # -> 400.0
print("model size N:", t1_N)  # -> 400.0
t1_D = 900.0  # -> 900.0
print("data size D:", t1_D)  # -> 900.0
t1_model_term = t1_a * t1_N ** (-t1_alpha)  # -> 0.1
print("model term:", round(t1_model_term, 3))  # -> 0.1
t1_data_term = t1_b * t1_D ** (-t1_beta)  # -> 0.1
print("data term:", round(t1_data_term, 3))  # -> 0.1
t1_loss = t1_L_inf + t1_model_term  # -> 1.1
t1_loss = t1_loss + t1_data_term  # -> 1.2
print("total loss:", round(t1_loss, 3))  # -> 1.2

plt.figure(figsize=(4.4, 2.8))
plt.bar(["floor", "model", "data"], [t1_L_inf, t1_model_term, t1_data_term], color=["gray", "teal", "orange"])
plt.ylabel("loss contribution")
plt.title("Toy 1 · loss pieces")
plt.show()
assert round(t1_model_term, 3) == 0.1
assert round(t1_data_term, 3) == 0.1
assert round(t1_loss, 3) == 1.2
```
▶ What you'll see: the floor dominates, while model and data each add 0.100 of reducible excess loss.

### ✍️ Toy 2 · Fit a power law with a line on log-log data

Taking logs turns `excess = c N^{-γ}` into a straight line whose negative slope is the exponent.

```python
import numpy as np

t2_seed = 0  # -> 0
t2_rng = np.random.default_rng(0)  # -> reproducible generator
print("seed:", t2_seed)  # -> 0
t2_N = np.array([100.0, 400.0, 1600.0])  # -> [100.0, 400.0, 1600.0]
print("model sizes:", t2_N.tolist())  # -> [100.0, 400.0, 1600.0]
t2_true_c = 2.0  # -> 2.0
print("true coefficient:", t2_true_c)  # -> 2.0
t2_true_gamma = 0.5  # -> 0.5
print("true exponent:", t2_true_gamma)  # -> 0.5
t2_excess = t2_true_c * t2_N ** (-t2_true_gamma)  # -> [0.2, 0.1, 0.05]
print("excess losses:", np.round(t2_excess, 3).tolist())  # -> [0.2, 0.1, 0.05]
t2_xlog = np.log(t2_N)  # -> [4.605, 5.991, 7.378]
print("log N:", np.round(t2_xlog, 3).tolist())  # -> [4.605, 5.991, 7.378]
t2_ylog = np.log(t2_excess)  # -> [-1.609, -2.303, -2.996]
print("log excess:", np.round(t2_ylog, 3).tolist())  # -> [-1.609, -2.303, -2.996]
t2_design = np.column_stack([np.ones_like(t2_xlog), t2_xlog])  # -> intercept and slope columns
print("design matrix:", np.round(t2_design, 3).tolist())  # -> [[1.0, 4.605], [1.0, 5.991], [1.0, 7.378]]
t2_coeffs = np.linalg.lstsq(t2_design, t2_ylog, rcond=None)[0]  # -> [0.6931471805599445, -0.5]
print("line coefficients:", np.round(t2_coeffs, 3).tolist())  # -> [0.693, -0.5]
t2_c_hat = float(np.exp(t2_coeffs[0]))  # -> 2.0
print("fitted coefficient:", round(t2_c_hat, 3))  # -> 2.0
t2_gamma_hat = float(-t2_coeffs[1])  # -> 0.5
print("fitted exponent:", round(t2_gamma_hat, 3))  # -> 0.5
t2_fit = t2_c_hat * t2_N ** (-t2_gamma_hat)  # -> [0.2, 0.1, 0.05]
print("fitted excess:", np.round(t2_fit, 3).tolist())  # -> [0.2, 0.1, 0.05]

plt.figure(figsize=(4.4, 2.8))
plt.loglog(t2_N, t2_excess, "o", label="observed")
plt.loglog(t2_N, t2_fit, "-", label="fit")
plt.xlabel("N")
plt.ylabel("excess loss")
plt.title("Toy 2 · log-log fit")
plt.legend()
plt.show()
assert round(t2_c_hat, 3) == 2.0
assert round(t2_gamma_hat, 3) == 0.5
```
▶ What you'll see: the fitted log-log line exactly recovers coefficient 2.0 and exponent 0.5.

### ✍️ Toy 3 · Grid-search compute allocation balances N and D

With fixed compute `C = N·D`, increasing model size reduces available data. The best point balances the
two excess terms.

```python
import numpy as np

t3_seed = 0  # -> 0
t3_rng = np.random.default_rng(0)  # -> reproducible generator
print("seed:", t3_seed)  # -> 0
t3_C = 360000.0  # -> 360000.0
print("compute budget:", t3_C)  # -> 360000.0
t3_N = np.array([200.0, 400.0, 800.0])  # -> [200.0, 400.0, 800.0]
print("candidate N:", t3_N.tolist())  # -> [200.0, 400.0, 800.0]
t3_D = t3_C / t3_N  # -> [1800.0, 900.0, 450.0]
print("forced D:", t3_D.tolist())  # -> [1800.0, 900.0, 450.0]
t3_model_terms = 2.0 * t3_N ** (-0.5)  # -> [0.141, 0.1, 0.071]
print("model terms:", np.round(t3_model_terms, 3).tolist())  # -> [0.141, 0.1, 0.071]
t3_data_terms = 3.0 * t3_D ** (-0.5)  # -> [0.071, 0.1, 0.141]
print("data terms:", np.round(t3_data_terms, 3).tolist())  # -> [0.071, 0.1, 0.141]
t3_excess = t3_model_terms + t3_data_terms  # -> [0.212, 0.2, 0.212]
print("excess losses:", np.round(t3_excess, 3).tolist())  # -> [0.212, 0.2, 0.212]
t3_best_index = int(np.argmin(t3_excess))  # -> 1
print("best index:", t3_best_index)  # -> 1
t3_best_N = float(t3_N[t3_best_index])  # -> 400.0
print("best N:", t3_best_N)  # -> 400.0
t3_best_D = float(t3_D[t3_best_index])  # -> 900.0
print("best D:", t3_best_D)  # -> 900.0

plt.figure(figsize=(4.4, 2.8))
plt.plot(t3_N, t3_excess, marker="o", color="purple")

```
▶ What you'll see: the center candidate has equal model/data terms and the lowest excess loss.

can sit on a higher curve.

```python
import numpy as np
```

## 🛠️ Setup

```python
import numpy as np # load NumPy for arrays, logarithms, least-squares fits, and deterministic simulations.
import matplotlib.pyplot as plt # load Matplotlib for line plots, log-log plots, heatmaps, and threshold visualizations.
np.random.seed(0) # make every random example reproducible across notebook runs.

def scaling_loss(N, D, L_inf=1.0, a=2.0, alpha=0.5, b=3.0, beta=0.5): # compute L∞ + aN^-α + bD^-β.
    N = np.asarray(N, dtype=float) # convert model sizes to arrays so scalar and vector inputs both work.
    D = np.asarray(D, dtype=float) # convert data sizes to arrays for vectorized arithmetic.
    return L_inf + a * N ** (-alpha) + b * D ** (-beta) # return total loss from floor plus model and data terms.

def fit_power_law(x, y): # fit y = c x^-gamma from positive x and y values.
    x = np.asarray(x, dtype=float) # convert the scale values to floats before taking logs.
    y = np.asarray(y, dtype=float) # convert the excess-loss values to floats before taking logs.
    A = np.column_stack([np.ones_like(x), np.log(x)]) # build intercept and log-scale columns.
    intercept, slope = np.linalg.lstsq(A, np.log(y), rcond=None)[0] # solve log y = intercept + slope log x.
    return float(np.exp(intercept)), float(-slope) # return coefficient c and positive exponent gamma.

def sigmoid(z): # map a real capability margin to a bounded score.
    z = np.asarray(z, dtype=float) # convert to float array so scalar and vector inputs both work.
    return 1 / (1 + np.exp(-z)) # compute the logistic function.

def compute_optimal_grid(C, N_grid, L_inf=1.0, a=2.0, alpha=0.5, b=3.0, beta=0.5): # choose N,D under ND=C.
    N_grid = np.asarray(N_grid, dtype=float) # convert candidate model sizes to floats.
    D_grid = C / N_grid # enforce the dense-training compute constraint.
    losses = scaling_loss(N_grid, D_grid, L_inf, a, alpha, b, beta) # evaluate total loss for every candidate.
    idx = int(np.argmin(losses)) # locate the smallest-loss candidate.
    return idx, N_grid, D_grid, losses # return the best index plus all arrays for inspection and plotting.
```

### Advanced 5 — Plan under a target loss and target ability

**Goal.** Search for the cheapest allocation that satisfies both a loss target and an ability target, because practical training plans care about cost and behavior together. We build it in 5 steps.

```python
N_grid_a5 = np.array([100, 200, 400, 800, 1600, 3200], dtype=float) # candidate model sizes.
D_grid_a5 = np.array([225, 450, 900, 1800, 3600], dtype=float) # candidate data sizes.
target_loss_a5 = 1.22 # require validation loss no worse than this.
target_score_a5 = 0.75 # require ability score at least this high.
print("targets:", target_loss_a5, target_score_a5) # inspect planning constraints.
```

```python
plans_a5 = [] # collect feasible plans as tuples.
for N_a5 in N_grid_a5: # loop over model sizes.
    for D_a5 in D_grid_a5: # loop over data sizes.
        loss_a5 = float(scaling_loss(N_a5, D_a5)) # compute predicted validation loss.
        margin_a5 = 8.0 * (1.25 - loss_a5) # convert loss to a toy capability margin.
        score_a5 = float(sigmoid(margin_a5)) # compute smooth ability score.
        cost_a5 = N_a5 * D_a5 # dense-training cost proxy.
        if loss_a5 <= target_loss_a5 and score_a5 >= target_score_a5: # keep plans meeting both constraints.
            plans_a5.append((cost_a5, N_a5, D_a5, loss_a5, score_a5)) # store feasible plan.
print("feasible plans:", len(plans_a5)) # inspect how many candidates worked.
```

```python

```

