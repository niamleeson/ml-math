# 19.13 — Differential Privacy

Differential privacy (DP) is a promise about a randomized computation: changing one person's row should not greatly change the probability of any released result. In this lesson, we build that promise from neighboring datasets, sensitivity, calibrated noise, private gradient descent, and composition so the privacy-utility tradeoff is visible in code instead of hidden behind a slogan.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build differential privacy one idea at a time. This walkthrough is self-contained (it imports what it needs) and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays, random noise, and small numerical checks.
```

### 1. Neighboring datasets and the DP probability ratio

Differential privacy starts with a worst-case comparison. Two datasets are **neighbors** if they differ in one person's row; a randomized mechanism $M$ is private if every output is almost equally likely on both neighbors:

$$P(M(D)=o)\le e^\varepsilon P(M(D')=o)+\delta.$$

Small $\varepsilon$ means the likelihood ratio is close to 1, so observing the output gives limited evidence about whether that one row was present. The $\delta$ term allows a small failure probability for mechanisms such as Gaussian noise.

```python
D_w = np.array([1, 0, 1, 1, 0, 1])       # one toy database: six people, binary attribute.
Dp_w = np.array([1, 0, 1, 0, 0, 1])      # neighboring database: only row 3 changed.
changed_w = np.where(D_w != Dp_w)[0]     # find the changed person.
print("D :", D_w)
print("D':", Dp_w)
print("changed rows:", changed_w, "count:", len(changed_w))
assert len(changed_w) == 1
```
▶ What you'll see: the two databases are identical except for one row, which is the exact unit DP protects.

```python
eps_w = 0.7                                      # privacy knob: smaller means stricter.
ratio_bound_w = float(np.exp(eps_w))             # e^epsilon bounds probability multiplication when delta=0.
print("epsilon:", eps_w, "e^epsilon:", round(ratio_bound_w, 3))
assert round(ratio_bound_w, 3) == 2.014
```
▶ What you'll see: with ε = 0.7, one person's row may multiply an output probability by at most about 2.014 under pure DP.

```python
p_Dp_w = np.linspace(0, 1, 101)                  # possible probabilities under D'.
upper_w = np.minimum(1, ratio_bound_w * p_Dp_w)  # pure-DP upper bound under D.
plt.figure(figsize=(4.4, 3))
plt.plot(p_Dp_w, upper_w, color="teal", label="allowed P(M(D)=o)")
plt.plot(p_Dp_w, p_Dp_w, color="gray", linestyle="--", label="equal probabilities")
plt.xlabel("P(M(D')=o)"); plt.ylabel("upper bound for P(M(D)=o)")
plt.title("1: ε-DP limits probability ratios"); plt.legend(); plt.show()
```
▶ What you'll see: the allowed probability under `D` can rise above the equal-probability line, but only by the controlled factor $e^\varepsilon$.

*Why it's done this way: DP is stated over output probabilities, not over a single output value, because the adversary sees a randomized release; bounding the ratio for every output limits how much one row can change any inference.*

### 2. Sensitivity: the largest one-row change

Noise is meaningless until it is calibrated to **sensitivity**. For a deterministic query $f$, the global sensitivity is

$$\Delta f=\max_{D\sim D'} \lVert f(D)-f(D')\rVert,$$

the largest possible change over neighboring datasets. Counting a binary event has sensitivity 1: one person can add or remove at most one count. A mean has sensitivity `(max-min)/n` when values are clipped to a fixed range, because one row can move from the minimum to the maximum.

```python
count_D_w = int(D_w.sum())                       # count query on D.
count_Dp_w = int(Dp_w.sum())                     # count query on neighboring D'.
change_count_w = abs(count_D_w - count_Dp_w)     # observed one-row change.
print("count(D):", count_D_w, "count(D'):", count_Dp_w, "change:", change_count_w)
assert change_count_w == 1
```
▶ What you'll see: flipping one binary row changes the count by exactly 1 in this neighbor pair.

```python
n_w = 6
lo_w, hi_w = 0.0, 1.0
mean_sens_w = (hi_w - lo_w) / n_w                # bounded mean sensitivity.
print("bounded mean sensitivity:", round(mean_sens_w, 3))
assert round(mean_sens_w, 3) == 0.167
```
▶ What you'll see: for six bounded rows, one person can change the mean by at most 1/6.

```python
ns_w = np.arange(2, 51)
sens_w = 1 / ns_w
plt.figure(figsize=(4.5, 3))
plt.plot(ns_w, sens_w, color="purple")
plt.xlabel("n rows"); plt.ylabel("mean sensitivity")
plt.title("2: averaging lowers one-row influence"); plt.show()
```
▶ What you'll see: sensitivity shrinks as the dataset grows, so the same privacy level needs less noise for larger averages.

*Why it's done this way: DP protects against the worst possible row, so the noise scale must cover the largest one-row effect, not the average effect in a friendly sample.*

### 3. Laplace mechanism for pure ε-DP

For numeric queries with L1 sensitivity $\Delta f$, the Laplace mechanism releases

$$M(D)=f(D)+\text{Laplace}(0,\Delta f/\varepsilon).$$

The scale $b=\Delta f/\varepsilon$ is larger when the query is more sensitive or the privacy budget is stricter. Its density has exponential tails, and the ratio of two shifted densities is bounded by $e^\varepsilon$ when the shift is at most $\Delta f$.

```python
eps_lap_w = 0.5
sens_lap_w = 1.0
scale_lap_w = sens_lap_w / eps_lap_w             # Laplace scale b.
print("Laplace scale b:", scale_lap_w)
assert scale_lap_w == 2.0
```
▶ What you'll see: ε = 0.5 and sensitivity 1 require Laplace noise with scale 2.

```python
rng_lap_w = np.random.default_rng(0)
noise_lap_w = rng_lap_w.laplace(0, scale_lap_w, size=4000)
print("sample mean noise:", round(float(noise_lap_w.mean()), 3))
print("sample mean absolute noise:", round(float(np.mean(np.abs(noise_lap_w))), 3))
assert 1.8 < np.mean(np.abs(noise_lap_w)) < 2.2
```
▶ What you'll see: the noise is centered near 0, and its average absolute size is close to the Laplace scale.

```python
x_lap_w = np.linspace(-8, 8, 400)
def lap_pdf_w(x, mu, b):
    return np.exp(-np.abs(x - mu) / b) / (2 * b)
pdf_D_w = lap_pdf_w(x_lap_w, count_D_w, scale_lap_w)
pdf_Dp_w = lap_pdf_w(x_lap_w, count_Dp_w, scale_lap_w)
ratio_w = np.max(pdf_D_w / pdf_Dp_w)
print("max density ratio on grid:", round(float(ratio_w), 3), "bound:", round(float(np.exp(eps_lap_w)), 3))
assert ratio_w <= np.exp(eps_lap_w) + 1e-6
plt.figure(figsize=(4.8, 3))
plt.plot(x_lap_w, pdf_D_w, label="count(D)+Lap")
plt.plot(x_lap_w, pdf_Dp_w, label="count(D')+Lap")
plt.title("3: shifted Laplace densities"); plt.xlabel("released count"); plt.ylabel("density")
plt.legend(); plt.show()
```
▶ What you'll see: the two noisy-count distributions overlap heavily; their vertical gap is bounded everywhere by $e^\varepsilon$.

*Why it's done this way: the Laplace density decays exactly exponentially, so moving the true answer by at most sensitivity changes density by at most $\exp(\Delta f/b)=\exp(\varepsilon)$.*

### 4. Gaussian mechanism and the δ slack

Gaussian noise is common for vector queries and DP-SGD. A simple calibration for $(\varepsilon,\delta)$-DP is

$$\sigma \ge \frac{\Delta f\sqrt{2\log(1.25/\delta)}}{\varepsilon}.$$

The Gaussian has lighter center behavior but nonzero tails, so the guarantee includes $\delta$: a small probability budget for rare outputs where the pure ratio bound can fail.

```python
eps_gauss_w = 1.0
delta_gauss_w = 1e-5
sens_gauss_w = 1.0
sigma_gauss_w = sens_gauss_w * np.sqrt(2 * np.log(1.25 / delta_gauss_w)) / eps_gauss_w
print("Gaussian sigma:", round(float(sigma_gauss_w), 3))
assert round(float(sigma_gauss_w), 3) == 4.845
```
▶ What you'll see: a tiny δ makes σ several times larger than sensitivity.

```python
rng_gauss_w = np.random.default_rng(1)
noise_gauss_w = rng_gauss_w.normal(0, sigma_gauss_w, size=5000)
print("noise std estimate:", round(float(noise_gauss_w.std()), 3))
assert 4.6 < noise_gauss_w.std() < 5.1
```
▶ What you'll see: sampled Gaussian noise has standard deviation close to the calibrated σ.

```python
eps_grid_w = np.array([0.25, 0.5, 1.0, 2.0])
sigma_grid_w = sens_gauss_w * np.sqrt(2 * np.log(1.25 / delta_gauss_w)) / eps_grid_w
print("sigma grid:", np.round(sigma_grid_w, 3))
plt.figure(figsize=(4.6, 3))
plt.plot(eps_grid_w, sigma_grid_w, marker="o", color="darkorange")
plt.xlabel("epsilon"); plt.ylabel("required sigma")
plt.title("4: stricter ε needs more Gaussian noise"); plt.show()
```
▶ What you'll see: required Gaussian noise drops roughly like `1/epsilon`, making the privacy-utility tradeoff explicit.

*Why it's done this way: δ is not decoration; it is the part of the privacy budget assigned to rare Gaussian tail events, so it must be chosen small and reported with ε.*

### 5. DP-SGD: clip each person's gradient, then add noise

Training can leak membership through gradients. DP-SGD limits each example's influence by clipping its gradient to norm $C$, averages the clipped gradients, and adds Gaussian noise proportional to $C$. The clipping step creates a known sensitivity; the noise step hides which clipped gradient was contributed.

```python
X_w = np.array([-2., -1., 0., 1., 2.])[:, None]
y_w = np.array([0., 0., 0., 1., 1.])
w_w = np.array([0.4])
logits_w = X_w[:, 0] * w_w[0]
probs_w = 1 / (1 + np.exp(-logits_w))
per_grad_w = ((probs_w - y_w)[:, None] * X_w)   # one logistic-loss gradient per person.
print("per-example gradients:", np.round(per_grad_w[:, 0], 3))
```
▶ What you'll see: each row contributes its own gradient, and some rows push harder than others.

```python
C_w = 0.5
norms_w = np.linalg.norm(per_grad_w, axis=1)
scales_w = np.minimum(1.0, C_w / (norms_w + 1e-12))
clipped_w = per_grad_w * scales_w[:, None]
print("original norms:", np.round(norms_w, 3))
print("clipped norms:", np.round(np.linalg.norm(clipped_w, axis=1), 3))
assert np.max(np.linalg.norm(clipped_w, axis=1)) <= C_w + 1e-9
```
▶ What you'll see: every per-example gradient norm is capped at 0.5 before averaging.

```python
noise_multiplier_w = 1.0
rng_sgd_w = np.random.default_rng(2)
avg_grad_w = clipped_w.mean(axis=0)
noise_sgd_w = rng_sgd_w.normal(0, noise_multiplier_w * C_w / len(X_w), size=avg_grad_w.shape)
private_grad_w = avg_grad_w + noise_sgd_w
print("clipped mean grad:", np.round(avg_grad_w, 4))
print("private noisy grad:", np.round(private_grad_w, 4))
```
▶ What you'll see: the released update is the clipped average plus noise scaled to the clipping bound and batch size.

```python
plt.figure(figsize=(4.7, 3))
plt.bar(np.arange(len(X_w)) - .18, norms_w, width=.36, label="raw norm", color="crimson")
plt.bar(np.arange(len(X_w)) + .18, np.linalg.norm(clipped_w, axis=1), width=.36, label="clipped norm", color="seagreen")
plt.axhline(C_w, color="black", linestyle="--", label="C")
plt.title("5: DP-SGD clips per-person influence"); plt.xlabel("example"); plt.ylabel("gradient norm")
plt.legend(); plt.show()
```
▶ What you'll see: large raw gradients are pulled down to the clipping line before any averaging or noise.

*Why it's done this way: without clipping, one unusual row could create an arbitrarily large update, so no fixed Gaussian noise would be enough; clipping makes the sensitivity finite and tunable.*

### 6. Composition: privacy loss accumulates

A privacy budget is spent every time we release a private result. The simplest accounting says $k$ pure-DP releases with budgets $\varepsilon_1,\dots,\varepsilon_k$ compose to $\sum_i\varepsilon_i$; for approximate DP, the $\delta$ values also accumulate. This is conservative, but it teaches the key habit: repeated queries are not free.

```python
eps_parts_w = np.array([0.2, 0.3, 0.1, 0.4])
delta_parts_w = np.array([1e-6, 1e-6, 2e-6, 1e-6])
eps_total_w = float(eps_parts_w.sum())
delta_total_w = float(delta_parts_w.sum())
print("epsilon parts:", eps_parts_w, "total:", eps_total_w)
print("delta total:", delta_total_w)
assert round(eps_total_w, 3) == 1.0
```
▶ What you'll see: four small releases add up to ε = 1.0 and δ = 5e-6.

```python
cum_eps_w = np.cumsum(eps_parts_w)
plt.figure(figsize=(4.6, 3))
plt.step(np.arange(1, len(cum_eps_w)+1), cum_eps_w, where="mid", color="teal")
plt.axhline(1.0, color="red", linestyle="--", label="budget")
plt.xlabel("release number"); plt.ylabel("cumulative ε")
plt.title("6: composition spends privacy budget"); plt.legend(); plt.show()
```
▶ What you'll see: every private release moves the cumulative privacy loss upward until the budget is exhausted.

```python
eps_trade_w = np.linspace(0.2, 3.0, 40)
scale_trade_w = 1 / eps_trade_w
expected_abs_error_w = scale_trade_w             # Laplace E|noise| = b for sensitivity 1.
plt.figure(figsize=(4.6, 3))
plt.plot(eps_trade_w, expected_abs_error_w, color="purple")
plt.xlabel("epsilon"); plt.ylabel("expected |Laplace noise|")
plt.title("6: privacy-utility tradeoff for counts"); plt.show()
```
▶ What you'll see: smaller ε gives stronger privacy but larger expected error; larger ε gives a more accurate but less private release.

*Why it's done this way: privacy loss is a resource, not a label on a single query; composition forces the system designer to account for all releases together.*

### ✍️ Toy 2 · ε becomes a probability multiplier

Pure DP limits a probability under one neighbor by the factor `exp(ε)`, capped at 1 because probabilities cannot exceed 1.

```python
import numpy as np

t2_rng = np.random.default_rng(0)
t2_eps = 0.5
print("epsilon:", t2_eps)  # -> epsilon: 0.5
t2_ratio = np.exp(t2_eps)
print("e^epsilon:", round(float(t2_ratio), 3))  # -> e^epsilon: 1.649
t2_p_neighbor = np.array([0.1, 0.3, 0.8])
print("P under neighbor:", t2_p_neighbor.tolist())  # -> P under neighbor: [0.1, 0.3, 0.8]
t2_p_cap = np.minimum(1.0, t2_ratio * t2_p_neighbor)
print("allowed P under D:", np.round(t2_p_cap, 3).tolist())  # -> allowed P under D: [0.165, 0.495, 1.0]
assert np.all(t2_p_cap <= 1.0)

plt.figure(figsize=(4.4, 2.8))
plt.bar(["o1", "o2", "o3"], t2_p_cap, color="teal")
plt.axhline(1.0, color="black", linestyle="--")
plt.ylabel("probability cap")
plt.title("Toy 2 · ε-DP caps output probabilities")
plt.show()
```
▶ What you'll see: each neighbor probability is multiplied by about `1.649`, except the last one saturates at 1.

### ✍️ Toy 3 · Count sensitivity sets count noise scale

A binary count can move by at most one when one person's row changes, so its global sensitivity is 1.

```python
import numpy as np

t3_rng = np.random.default_rng(0)
t3_D = np.array([1, 0, 1, 0, 1])
print("D:", t3_D.tolist())  # -> D: [1, 0, 1, 0, 1]
t3_Dp = np.array([1, 0, 1, 0, 0])
print("D':", t3_Dp.tolist())  # -> D': [1, 0, 1, 0, 0]

t3_change = abs(t3_count - t3_count_p)

t3_sensitivity = 1

```
▶ What you'll see: the two counts differ by 1, which is exactly the noise-calibrating sensitivity.

### ✍️ Toy 7 · DP-SGD clips then noises a gradient

DP-SGD caps each per-example gradient norm before averaging, then adds Gaussian noise to the average.

```python
import numpy as np

t7_rng = np.random.default_rng(0)
t7_X = np.array([-2.0, -1.0, 1.0, 2.0])[:, None]
print("x:", t7_X[:, 0].tolist())  # -> x: [-2.0, -1.0, 1.0, 2.0]
t7_y = np.array([0.0, 0.0, 1.0, 1.0])
print("y:", t7_y.tolist())  # -> y: [0.0, 0.0, 1.0, 1.0]
t7_w = np.array([0.3])
print("weight:", t7_w.tolist())  # -> weight: [0.3]
t7_logits = t7_X[:, 0] * t7_w[0]
print("logits:", np.round(t7_logits, 3).tolist())  # -> logits: [-0.6, -0.3, 0.3, 0.6]
t7_probs = 1 / (1 + np.exp(-t7_logits))
print("probabilities:", np.round(t7_probs, 3).tolist())  # -> probabilities: [0.354, 0.426, 0.574, 0.646]
t7_grads = (t7_probs - t7_y)[:, None] * t7_X
```

### Easy 4 — Run a tiny DP-SGD loop from scratch

**Goal.** Train a one-parameter logistic model with clipping and noise, because DP-SGD is the standard private training pattern. We build it in 4 steps.

```python
X_e4 = np.array([-2., -1., -0.5, 0.5, 1., 2.])[:, None] # Create one-dimensional toy features.
y_e4 = np.array([0., 0., 0., 1., 1., 1.]) # Create binary labels.
w_e4 = np.array([0.0]) # Initialize the logistic weight.
print("initial weight:", w_e4) # Inspect the starting model.
```
▶ What you'll see: the model starts with zero weight, so predictions begin at 0.5.

```python
clip_e4 = 0.6 # Set per-example clipping norm.
noise_multiplier_e4 = 0.4 # Choose modest noise for a visible but stable demo.
lr_e4 = 0.8 # Choose learning rate.
rng_e4 = np.random.default_rng(14) # Create reproducible DP-SGD noise.
losses_e4 = [] # Store loss values for plotting.
print("clip:", clip_e4, "noise multiplier:", noise_multiplier_e4, "lr:", lr_e4) # Inspect hyperparameters.
```

```python
for step_e4 in range(80): # Run a small number of private gradient steps.
    logits_e4 = X_e4[:, 0] * w_e4[0] # Compute logits for every example.
    probs_e4 = 1 / (1 + np.exp(-logits_e4)) # Convert logits to probabilities.
    per_grad_e4 = ((probs_e4 - y_e4)[:, None] * X_e4) # Compute one gradient per example.
    norms_e4 = np.linalg.norm(per_grad_e4, axis=1) # Compute per-example gradient norms.
    scales_e4 = np.minimum(1.0, clip_e4 / (norms_e4 + 1e-12)) # Compute clipping scales.
    clipped_e4 = per_grad_e4 * scales_e4[:, None] # Clip each person's gradient.
    noise_e4 = rng_e4.normal(0, noise_multiplier_e4 * clip_e4 / len(X_e4), size=1) # Draw Gaussian noise for the averaged gradient.
    private_grad_e4 = clipped_e4.mean(axis=0) + noise_e4 # Add noise to the clipped mean gradient.
    w_e4 -= lr_e4 * private_grad_e4 # Take a descent step.
    prob_loss_e4 = 1 / (1 + np.exp(-(X_e4[:, 0] * w_e4[0]))) # Recompute probabilities after the update.
    loss_e4 = -np.mean(y_e4 * np.log(prob_loss_e4 + 1e-12) + (1 - y_e4) * np.log(1 - prob_loss_e4 + 1e-12)) # Compute logistic loss.
    losses_e4.append(loss_e4) # Store the loss.
print("final weight:", round(float(w_e4[0]), 3), "final loss:", round(float(losses_e4[-1]), 3)) # Inspect training result.
assert losses_e4[-1] < losses_e4[0] # Verify the private loop learned on this toy data.
```

```python
plt.figure(figsize=(5, 3)) # Create a loss curve.
plt.plot(losses_e4, color="teal") # Plot noisy private training loss.
plt.title("Easy 4: tiny DP-SGD training loop") # Title the plot.
plt.xlabel("step") # Label training steps.
plt.ylabel("logistic loss") # Label loss.
plt.show() # Display the curve.
```
▶ What you'll see: despite noisy updates, the loss trends downward on this separable toy problem.

👀 Takeaway: DP-SGD is ordinary gradient descent plus the crucial clip-then-noise mechanism.

```python

    return np.exp(-np.abs(x - mu) / b) / (2 * b) # Return density at x.

pdf_Dp_a1 = lap_pdf_a1(x_a1, count_Dp_a1, scale_a1) # Density under D'.
```

### Advanced 2 — Tune clipping in DP-SGD

