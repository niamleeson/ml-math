# 20.15 — Vector Databases & ANN

Vector databases make embedding search usable in production: instead of comparing one query to every stored vector every time, they build indexes that trade exactness for latency, memory, and recall. In this lesson, we build the core ANN ideas from scratch with NumPy so every shortcut is visible: what gets skipped, why it gets faster, and how recall@k measures the price.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build approximate nearest-neighbor search one idea at a time. Run each cell in order and inspect the printed quantities: exact brute-force search gives the truth set, then LSH, IVF, product quantization, and small-world graphs deliberately shrink the candidate set. This walkthrough is self-contained and uses a `_w` suffix so it never clashes with the examples below.

```python
import numpy as np  # arrays, vector math, and small from-scratch algorithms.
import matplotlib.pyplot as plt  # visual debugging for neighborhoods and tradeoff curves.
np.random.seed(0)  # reproducibility for all synthetic vectors and index randomness.
```

### 1. Brute-force kNN, cosine, and L2 distance

The most honest vector search index is no index at all: compare the query to every vector, sort the scores, and return the top `k`. We will use this exact search as ground truth. For normalized embeddings, cosine similarity is just a dot product; for unnormalized embeddings, L2 distance and cosine can rank different neighbors because vector length changes the geometry.

```python
rng_w = np.random.default_rng(0)  # local generator for a two-cluster toy dataset.
cluster_a_w = rng_w.normal(loc=[0.0, 0.0], scale=0.35, size=(20, 2))  # first semantic cluster.
cluster_b_w = rng_w.normal(loc=[2.5, 2.0], scale=0.35, size=(20, 2))  # second semantic cluster.
X2_w = np.vstack([cluster_a_w, cluster_b_w])  # 40 two-dimensional vectors.
q2_w = np.array([0.15, -0.05])  # a query near cluster A.
print("dataset shape:", X2_w.shape, "query:", q2_w)  # inspect the search problem.
```
▶ What you'll see: a small 2-D vector collection and one query point near the first cluster.

```python
def l2_knn_w(X, q, k):  # exact nearest neighbors by Euclidean distance.
    d = np.linalg.norm(X - q, axis=1)  # distance from q to every row.
    order = np.argsort(d)[:k]  # smallest distances are nearest.
    return order, d[order]  # return ids and their distances.

idx_l2_w, dist_l2_w = l2_knn_w(X2_w, q2_w, 5)  # exact top-5 by L2.
print("L2 ids:", idx_l2_w)  # inspect neighbor identities.
print("L2 distances:", np.round(dist_l2_w, 3))  # inspect how close they are.
assert len(idx_l2_w) == 5 and np.all(dist_l2_w[:-1] <= dist_l2_w[1:])  # sorted top-k.
```
▶ What you'll see: five nearby points from the cluster around the query, sorted from closest to farther.

```python
def normalize_w(A):  # row-normalize vectors for cosine search.
    return A / np.maximum(np.linalg.norm(A, axis=1, keepdims=True), 1e-12)  # avoid divide-by-zero.

def cosine_knn_w(X, q, k):  # exact nearest neighbors by cosine similarity.
    Xn = normalize_w(X)  # put database vectors on the unit sphere.
    qn = q / max(np.linalg.norm(q), 1e-12)  # put query on the unit sphere.
    sims = Xn @ qn  # cosine(q,x) = q^T x for unit vectors.
    order = np.argsort(-sims)[:k]  # largest similarities are nearest.
    return order, sims[order]  # return ids and scores.

idx_cos_w, sim_cos_w = cosine_knn_w(X2_w + np.array([3.0, 3.0]), q2_w + np.array([3.0, 3.0]), 5)  # shifted positive vectors.
print("cosine ids:", idx_cos_w)  # inspect cosine top-5.
print("cosine sims:", np.round(sim_cos_w, 3))  # cosine scores are bounded by [-1,1].
assert np.all(sim_cos_w <= 1.0000001)  # cosine similarity cannot exceed 1.
```
▶ What you'll see: cosine returns high-similarity neighbors, but its ranking is based on angle rather than raw distance.

```python
plt.figure(figsize=(4.6, 3.8))  # plot the exact 2-D neighborhood.
plt.scatter(X2_w[:, 0], X2_w[:, 1], c="lightgray", label="database")  # all vectors.
plt.scatter(X2_w[idx_l2_w, 0], X2_w[idx_l2_w, 1], c="seagreen", s=80, label="exact top-5")  # exact neighbors.
plt.scatter([q2_w[0]], [q2_w[1]], c="crimson", marker="*", s=160, label="query")  # query.
plt.title("1: brute-force L2 kNN neighborhood"); plt.xlabel("x0"); plt.ylabel("x1"); plt.legend(); plt.show()
```
▶ What you'll see: the exact top-5 are the visible points closest to the query; brute force is correct but scans every vector.

*Why it's done this way:* exact kNN defines the answer ANN methods are trying to approximate. L2 measures absolute displacement, while cosine divides out norms so only direction remains: $\cos(q,x)=q^\top x/(\|q\|\|x\|)$. Normalizing before a dot product is not a coding trick; it changes the math from “large coordinates win” to “small angle wins.”

### 2. LSH with random hyperplanes

Locality-sensitive hashing (LSH) turns a vector into a short bit string. Each random hyperplane asks one yes/no question: is the vector on this side of the plane or the other? Vectors with similar directions are likely to answer many random questions the same way, so search can scan only the bucket with the query's code instead of the full database.

```python
rng_lsh_w = np.random.default_rng(1)  # reproducible hyperplanes.
X_lsh_w = normalize_w(rng_lsh_w.normal(size=(80, 8)))  # unit vectors in 8-D.
q_lsh_w = X_lsh_w[7] + 0.05 * rng_lsh_w.normal(size=8)  # query near one stored vector.
q_lsh_w = q_lsh_w / np.linalg.norm(q_lsh_w)  # unit query for angular search.
planes_w = rng_lsh_w.normal(size=(4, 8))  # four random hyperplanes for a readable bucket.
print("vectors:", X_lsh_w.shape, "hyperplanes:", planes_w.shape)  # inspect index size.
```
▶ What you'll see: 80 unit vectors and 4 random tests that will define LSH buckets.

```python
def codes_w(X, planes):  # convert vectors to binary random-hyperplane signatures.
    bits = (X @ planes.T) >= 0  # True if vector lies on the positive side of each plane.
    return np.packbits(bits.astype(np.uint8), axis=1)  # compact but still comparable.

codes_db_w = codes_w(X_lsh_w, planes_w)  # database signatures.
code_q_w = codes_w(q_lsh_w[None, :], planes_w)[0]  # query signature.
match_w = np.all(codes_db_w == code_q_w, axis=1)  # same bucket as query.
candidates_lsh_w = np.where(match_w)[0]  # candidate ids.
print("same-bucket candidates:", candidates_lsh_w.tolist())  # inspect reduced candidate set.
print("candidate count:", len(candidates_lsh_w), "of", len(X_lsh_w))  # scan reduction.
assert len(candidates_lsh_w) < len(X_lsh_w)  # LSH searches fewer than all vectors here.
```
▶ What you'll see: only a handful of vectors share the query's exact bit signature.

```python
exact_lsh_w, _ = cosine_knn_w(X_lsh_w, q_lsh_w, 5)  # exact angular neighbors.
if len(candidates_lsh_w) == 0:  # rare empty-bucket fallback for tiny demos.
    approx_lsh_w = np.array([], dtype=int)  # no candidates.
else:
    sims_c_w = X_lsh_w[candidates_lsh_w] @ q_lsh_w  # score only bucket candidates.
    approx_lsh_w = candidates_lsh_w[np.argsort(-sims_c_w)[:5]]  # approximate top-5.
recall_lsh_w = len(set(exact_lsh_w) & set(approx_lsh_w)) / 5  # recovered true neighbors.
print("exact top-5:", exact_lsh_w.tolist())  # ground truth.
print("LSH top candidates:", approx_lsh_w.tolist())  # approximate result.
print("recall@5:", round(recall_lsh_w, 2))  # quality of the shortcut.
assert 0.0 <= recall_lsh_w <= 1.0  # recall is a fraction.
```
▶ What you'll see: LSH is faster because it scores fewer candidates, but it may miss true top-5 neighbors.

*Why it's done this way:* a random hyperplane preserves angular locality probabilistically: nearby directions have a high chance of falling on the same side, while unrelated directions flip bits more often. The bucket is therefore a cheap candidate generator, not a proof of nearestness; exact scoring still happens inside the candidate set.

### 3. IVF with k-means partitions and probe lists

An inverted file (IVF) index first learns coarse centroids, assigns each vector to its nearest centroid, and stores one posting list per centroid. At query time, we do not scan all lists. We probe the few centroids closest to the query, then run exact search only inside those lists.

```python
rng_ivf_w = np.random.default_rng(2)  # reproducible blobs and centroids.
centers_true_w = np.array([[0, 0], [3, 0], [0, 3], [3, 3]], dtype=float)  # four natural regions.
X_ivf_w = np.vstack([c + 0.35 * rng_ivf_w.normal(size=(35, 2)) for c in centers_true_w])  # 140 vectors.
q_ivf_w = np.array([1.5, 1.5])  # query near a coarse-list boundary.
print("IVF dataset:", X_ivf_w.shape)  # inspect data size.
```
▶ What you'll see: a dataset with four visible regions and a query near the middle boundary.

```python
def kmeans_w(X, n_clusters, steps=12, seed=0):  # tiny from-scratch k-means.
    rng = np.random.default_rng(seed)  # deterministic initialization.
    centroids = X[rng.choice(len(X), n_clusters, replace=False)].copy()  # choose starting centers.
    for _ in range(steps):  # alternate assignment and update.
        d = np.linalg.norm(X[:, None, :] - centroids[None, :, :], axis=2)  # point-to-centroid distances.
        labels = np.argmin(d, axis=1)  # nearest centroid id for each vector.
        for j in range(n_clusters):  # recompute each centroid as mean of assigned points.
            if np.any(labels == j):
                centroids[j] = X[labels == j].mean(axis=0)
    return centroids, labels  # trained coarse quantizer.

centroids_w, labels_w = kmeans_w(X_ivf_w, 4, seed=3)  # build IVF coarse lists.
list_sizes_w = np.array([np.sum(labels_w == j) for j in range(4)])  # posting-list sizes.
print("list sizes:", list_sizes_w)  # inspect memory distribution.
assert list_sizes_w.sum() == len(X_ivf_w)  # every vector belongs to exactly one list.
```
▶ What you'll see: each vector is assigned to one coarse list; list sizes sum to the database size.

```python
def ivf_search_w(X, q, centroids, labels, nprobe, k):  # IVF approximate search.
    cd = np.linalg.norm(centroids - q, axis=1)  # distance from query to each coarse centroid.
    probe = np.argsort(cd)[:nprobe]  # closest lists to inspect.
    cand = np.where(np.isin(labels, probe))[0]  # vector ids in those lists.
    d = np.linalg.norm(X[cand] - q, axis=1)  # exact distance only inside candidates.
    top = cand[np.argsort(d)[:k]]  # candidate-local top-k.
    return top, cand, probe  # result, candidate ids, and probed list ids.

exact_ivf_w, _ = l2_knn_w(X_ivf_w, q_ivf_w, 5)  # brute-force truth.
approx_ivf_w, cand_ivf_w, probe_ivf_w = ivf_search_w(X_ivf_w, q_ivf_w, centroids_w, labels_w, 1, 5)  # one-list search.
recall_ivf_w = len(set(exact_ivf_w) & set(approx_ivf_w)) / 5  # recall@5.
print("probed lists:", probe_ivf_w.tolist(), "scanned:", len(cand_ivf_w))  # speed proxy.
print("recall@5 with nprobe=1:", recall_ivf_w)  # quality proxy.
assert len(cand_ivf_w) < len(X_ivf_w)  # IVF scans a subset.
```
▶ What you'll see: probing one list scans far fewer vectors; recall depends on whether true neighbors landed in that list.

```python
plt.figure(figsize=(4.8, 3.8))  # visualize the coarse index.
plt.scatter(X_ivf_w[:, 0], X_ivf_w[:, 1], c=labels_w, cmap="tab10", s=25)  # color by IVF list.
plt.scatter(centroids_w[:, 0], centroids_w[:, 1], c="black", marker="x", s=90, label="centroids")  # coarse centers.
plt.scatter([q_ivf_w[0]], [q_ivf_w[1]], c="crimson", marker="*", s=160, label="query")  # query.
plt.title("3: IVF lists from k-means"); plt.legend(); plt.show()
```
▶ What you'll see: k-means partitions space into coarse lists, and the query probes the nearest centroid region first.

*Why it's done this way:* IVF uses the triangle-like intuition that points near the query usually live in lists whose centroids are near the query. `nprobe` is the dial: more lists means more scanned candidates and usually higher recall; fewer lists means lower latency and more misses near boundaries.

### 4. Product quantization for compressed scoring

Product quantization (PQ) compresses each vector by splitting its dimensions into subspaces and replacing each subvector with the id of its nearest small codeword. Instead of storing every float, we store short codes. At query time, we approximate distance by looking up the query-to-codeword distance in each subspace and summing those pieces.

```python
rng_pq_w = np.random.default_rng(4)  # reproducible high-dimensional data.
X_pq_w = rng_pq_w.normal(size=(120, 8))  # 120 vectors in 8 dimensions.
q_pq_w = X_pq_w[10] + 0.15 * rng_pq_w.normal(size=8)  # query near vector 10.
M_w, Ks_w = 2, 8  # two subspaces, eight codewords per subspace.
print("PQ data:", X_pq_w.shape, "subspaces:", M_w, "codewords each:", Ks_w)  # inspect compression plan.
```
▶ What you'll see: an 8-D dataset split into two 4-D chunks, each quantized separately.

```python
def train_pq_w(X, M, Ks):  # from-scratch product quantizer.
    dsub = X.shape[1] // M  # dimensions per subspace.
    books, codes = [], []  # codebooks and integer codes.
    for m in range(M):  # train one k-means codebook per subspace.
        sub = X[:, m*dsub:(m+1)*dsub]  # slice sub-vectors.
        C, lab = kmeans_w(sub, Ks, steps=15, seed=10 + m)  # codewords and assignments.
        books.append(C); codes.append(lab)  # store subspace result.
    return books, np.vstack(codes).T  # codes shape: n_vectors x M.

books_w, codes_pq_w = train_pq_w(X_pq_w, M_w, Ks_w)  # train compression.
print("codes shape:", codes_pq_w.shape)  # one short code per vector per subspace.
print("first vector code:", codes_pq_w[0].tolist())  # inspect compressed representation.
assert codes_pq_w.shape == (120, 2)  # 120 vectors x 2 subcodes.
```
▶ What you'll see: each 8-D vector becomes two small integers instead of eight floats.

```python
def pq_distances_w(q, books, codes):  # asymmetric distance computation: real query, compressed database.
    M = len(books); dsub = q.shape[0] // M  # infer split.
    total = np.zeros(codes.shape[0])  # one approximate distance per vector.
    for m, C in enumerate(books):  # add subspace lookup distances.
        qs = q[m*dsub:(m+1)*dsub]  # query chunk.
        table = np.sum((C - qs) ** 2, axis=1)  # distance from query chunk to every codeword.
        total += table[codes[:, m]]  # lookup each vector's chosen codeword distance.
    return total  # approximate squared L2 distance.

exact_pq_w, _ = l2_knn_w(X_pq_w, q_pq_w, 5)  # true top-5.
approx_order_pq_w = np.argsort(pq_distances_w(q_pq_w, books_w, codes_pq_w))[:5]  # PQ approximate top-5.
recall_pq_w = len(set(exact_pq_w) & set(approx_order_pq_w)) / 5  # recall@5.
print("exact:", exact_pq_w.tolist(), "PQ:", approx_order_pq_w.tolist())  # compare ids.
print("PQ recall@5:", round(recall_pq_w, 2))  # quality after compression.
assert 0.0 <= recall_pq_w <= 1.0  # recall is bounded.
```
▶ What you'll see: PQ can retrieve some true neighbors while using compressed codes rather than full vectors.

*Why it's done this way:* splitting dimensions makes codebooks exponentially cheaper. One 8-D codebook with many codewords is expensive; two 4-D codebooks combine like a product, representing many possible reconstructed vectors with a few stored integers. The cost is quantization error: distances are approximate because codewords stand in for original subvectors.

### 5. HNSW-style small-world graph search

Graph ANN stores neighbor links between vectors. Search starts from an entry point, repeatedly walks to closer neighbors, and keeps a small frontier. The small-world idea is that a few useful links let greedy search jump across the space, then local links refine the result near the query.

```python
rng_g_w = np.random.default_rng(5)  # reproducible graph data.
X_g_w = np.vstack([rng_g_w.normal([0, 0], 0.35, size=(25, 2)), rng_g_w.normal([3, 3], 0.35, size=(25, 2))])  # two clusters.
q_g_w = np.array([2.9, 2.8])  # query near the second cluster.
print("graph vectors:", X_g_w.shape)  # inspect graph size.
```
▶ What you'll see: a small 2-D database where graph links can be drawn and inspected.

```python
def build_knn_graph_w(X, degree=5):  # simple base-layer graph: connect each point to exact nearest neighbors.
    nbrs = []  # adjacency list.
    for i in range(len(X)):  # for every vector.
        d = np.linalg.norm(X - X[i], axis=1)  # distances to all points.
        order = np.argsort(d)[1:degree+1]  # skip self, keep nearest neighbors.
        nbrs.append(order.tolist())  # store outgoing links.
    return nbrs  # graph used for greedy search.

graph_w = build_knn_graph_w(X_g_w, degree=5)  # build small-world-like local graph.
print("neighbors of node 0:", graph_w[0])  # inspect adjacency.
assert len(graph_w) == len(X_g_w) and len(graph_w[0]) == 5  # one list per vector.
```
▶ What you'll see: every point has five graph links to nearby points.

```python
def greedy_graph_search_w(X, graph, q, entry=0, ef=12, k=5):  # HNSW-style frontier search.
    visited = {entry}  # nodes already expanded.
    frontier = [entry]  # candidate nodes to expand.
    while frontier and len(visited) < ef:  # ef controls how much graph we inspect.
        cur = min(frontier, key=lambda i: np.linalg.norm(X[i] - q))  # closest frontier node.
        frontier.remove(cur)  # expand it once.
        for nb in graph[cur]:  # inspect linked neighbors.
            if nb not in visited:  # avoid repeats.
                visited.add(nb); frontier.append(nb)  # add to search frontier.
    cand = np.array(sorted(visited))  # candidate ids reached by graph walk.
    d = np.linalg.norm(X[cand] - q, axis=1)  # exact distances inside reached set.
    return cand[np.argsort(d)[:k]], cand  # top-k and all visited.

exact_g_w, _ = l2_knn_w(X_g_w, q_g_w, 5)  # exact truth.
approx_g_w, visited_g_w = greedy_graph_search_w(X_g_w, graph_w, q_g_w, entry=0, ef=20, k=5)  # graph search.
recall_g_w = len(set(exact_g_w) & set(approx_g_w)) / 5  # recall@5.
print("visited:", len(visited_g_w), "of", len(X_g_w), "recall@5:", recall_g_w)  # speed and quality.
print("exact:", exact_g_w.tolist(), "graph:", approx_g_w.tolist())  # compare ids.
assert len(visited_g_w) <= 20  # ef bounded the work.
```
▶ What you'll see: the graph visits only part of the database, then returns an approximate neighborhood.

*Why it's done this way:* graph search replaces global sorting with local navigation. The `ef` parameter is a computation budget: a wider frontier explores more alternatives and improves recall, but every extra visited node costs distance computations. Real HNSW adds hierarchy and long links; this toy keeps the same search logic visible.

### 6. Recall@k versus speed tradeoff

ANN systems are production tradeoffs. We measure speed with a proxy such as number of scanned candidates, and quality with recall@k: if exact top-`k` contains `k` true neighbors and ANN recovers `r` of them, recall@k is `r/k`. Increasing IVF probes should scan more vectors and usually recover more exact neighbors.

```python
probes_w = np.array([1, 2, 3, 4])  # IVF probe counts to compare.
recalls_w, scans_w = [], []  # store quality and work.
exact_trade_w, _ = l2_knn_w(X_ivf_w, q_ivf_w, 10)  # exact top-10 truth.
for nprobe_w in probes_w:  # sweep number of probed lists.
    approx_w, cand_w, _ = ivf_search_w(X_ivf_w, q_ivf_w, centroids_w, labels_w, int(nprobe_w), 10)  # approximate search.
    recalls_w.append(len(set(exact_trade_w) & set(approx_w)) / 10)  # recall@10.
    scans_w.append(len(cand_w))  # candidate count as latency proxy.
print("probes:", probes_w.tolist())  # inspect search budgets.
print("scanned candidates:", scans_w)  # speed proxy.
print("recall@10:", np.round(recalls_w, 2).tolist())  # quality proxy.
assert recalls_w[-1] == 1.0 and scans_w[-1] == len(X_ivf_w)  # probing all lists equals exact candidate coverage.
```
▶ What you'll see: more probes scan more vectors; probing all lists recovers exact search because every vector is considered.

```python
fig, ax1 = plt.subplots(figsize=(5.2, 3.4))  # one chart with recall and scans.
ax1.plot(probes_w, recalls_w, marker="o", color="seagreen", label="recall@10")  # quality curve.
ax1.set_xlabel("# IVF lists probed"); ax1.set_ylabel("recall@10", color="seagreen"); ax1.set_ylim(0, 1.05)  # recall axis.
ax2 = ax1.twinx()  # second axis for scanned vectors.
ax2.plot(probes_w, scans_w, marker="s", color="crimson", label="scanned")  # work curve.
ax2.set_ylabel("vectors scanned", color="crimson")  # speed proxy axis.
plt.title("6: recall rises with probe budget"); plt.show()
```
▶ What you'll see: the green curve improves as the red curve gets more expensive — the central ANN budget tradeoff.

*Why it's done this way:* recall names what speed optimizations lose. A system that scans one candidate is very fast but may be useless; a system that scans everything has perfect recall but no ANN benefit. Production vector search is choosing the point on this curve that satisfies latency, memory, and relevance budgets.

## 🛠️ Setup

```python
import numpy as np  # load NumPy for vectors, distances, random data, and tiny from-scratch ANN algorithms.
import matplotlib.pyplot as plt  # load Matplotlib for neighborhoods, partitions, and tradeoff curves.
np.random.seed(0)  # make all stochastic examples reproducible.

def normalize(X):  # Row-normalize a matrix or normalize a single vector safely.
    X = np.asarray(X, dtype=float)  # Convert input to floats so division behaves predictably.
    if X.ndim == 1:  # Handle one vector.
        return X / max(np.linalg.norm(X), 1e-12)  # Avoid divide-by-zero.
    return X / np.maximum(np.linalg.norm(X, axis=1, keepdims=True), 1e-12)  # Normalize each row.

def exact_l2(X, q, k):  # Exact top-k by Euclidean distance.
    d = np.linalg.norm(X - q, axis=1)  # Compute distance from q to every vector.
    order = np.argsort(d)[:k]  # Sort all vectors and keep nearest k.
    return order, d[order]  # Return ids and distances.

def exact_cosine(X, q, k):  # Exact top-k by cosine similarity.
    Xn = normalize(X)  # Unit database vectors.
    qn = normalize(q)  # Unit query vector.
    sims = Xn @ qn  # Cosine scores.
    order = np.argsort(-sims)[:k]  # Highest cosine first.
    return order, sims[order]  # Return ids and similarities.

def recall_at_k(true_ids, found_ids, k):  # Compute recall@k for ANN results.
    return len(set(true_ids[:k]) & set(found_ids[:k])) / k  # Fraction of true top-k recovered.

def tiny_kmeans(X, n_clusters, steps=12, seed=0):  # Small NumPy-only k-means for IVF and PQ.
    rng = np.random.default_rng(seed)  # Local reproducible initialization.
    C = X[rng.choice(len(X), n_clusters, replace=False)].copy()  # Pick initial centroids.
    for _ in range(steps):  # Alternate assignment and centroid update.
        d = np.linalg.norm(X[:, None, :] - C[None, :, :], axis=2)  # All point-centroid distances.
        labels = np.argmin(d, axis=1)  # Assign each point to nearest centroid.
        for j in range(n_clusters):  # Update each centroid.
            if np.any(labels == j):  # Keep non-empty clusters stable.
                C[j] = X[labels == j].mean(axis=0)  # Mean of assigned vectors.
    return C, labels  # Return centroids and assignments.
```

## 🟢 Basics (warm-up)

### Basic 1 — Build a toy embedding table

**Goal.** Create a tiny vector database and one query, because ANN search starts from embeddings arranged as rows. We build it in 2 steps.

```python
rng_b1 = np.random.default_rng(1)  # Create a local generator for this example.
X_b1 = rng_b1.normal(size=(12, 2))  # Store twelve two-dimensional embeddings.
```

### Easy 5 — Greedy graph search budget

```python
    d_e5 = np.linalg.norm(X_e5 - X_e5[i_e5], axis=1)  # Distances to all nodes.
```

```python
def graph_search_e5(X, graph, q, budget):  # Simple greedy frontier search.
    visited = {0}; frontier = [0]  # Start from node 0.
    while frontier and len(visited) < budget:  # Stop when budget is used.
        cur = min(frontier, key=lambda i: np.linalg.norm(X[i] - q))  # Expand closest frontier node.
        frontier.remove(cur)  # Remove it from frontier.
        for nb in graph[cur]:  # Add unseen neighbors.
            if nb not in visited and len(visited) < budget:
                visited.add(nb); frontier.append(nb)  # Track candidate.
    cand = np.array(sorted(visited))  # Candidate ids.
    return cand[np.argsort(np.linalg.norm(X[cand] - q, axis=1))[:5]], cand  # Top-5 and visited.

true_e5, _ = exact_l2(X_e5, q_e5, 5)  # Exact truth.

```

### Advanced 3 — Multi-table LSH improves recall

**Goal.** Use several independent LSH tables, because one hash bucket can miss neighbors that another random partition catches. We build it in 4 steps.

```python
rng_a3 = np.random.default_rng(13)  # Reproducible unit vectors.
X_a3 = normalize(rng_a3.normal(size=(120, 10)))  # Cosine database.
q_a3 = normalize(X_a3[9] + 0.08 * rng_a3.normal(size=10))  # Query near row 9.
true_a3, _ = exact_cosine(X_a3, q_a3, 10)  # Exact top-10.
print("database:", X_a3.shape)  # Inspect data size.
```
▶ What you'll see: a 10-D angular search problem.

```python
def lsh_candidates_a3(X, q, tables, bits, seed):  # Build several random-hyperplane tables and union buckets.
    rng = np.random.default_rng(seed)  # Local generator.
    cand = set()  # Candidate union across tables.
    for _ in range(tables):  # Independent hash tables.
        planes = rng.normal(size=(bits, X.shape[1]))  # Random hyperplanes.
        db = (X @ planes.T) >= 0  # Database signatures.
        qb = (q @ planes.T) >= 0  # Query signature.
        ids = np.where(np.all(db == qb, axis=1))[0]  # Same-bucket ids.
        cand.update(ids.tolist())  # Union candidates.
    return np.array(sorted(cand), dtype=int)  # Candidate array.

print("helper ready")  # Confirm function definition.
```

```python
tables_a3 = np.array([1, 2, 4, 8])  # Number of independent tables.
rec_a3, scan_a3 = [], []  # Store metrics.
for t_a3 in tables_a3:  # Evaluate each table count.
    cand_a3 = lsh_candidates_a3(X_a3, q_a3, int(t_a3), bits=7, seed=30)  # Candidate union.
    if len(cand_a3) == 0:  # Empty candidate guard.
        found_a3 = np.array([], dtype=int)  # No candidates.
    else:
        found_a3 = cand_a3[np.argsort(-(X_a3[cand_a3] @ q_a3))[:10]]  # Score candidates exactly by cosine.
    rec_a3.append(recall_at_k(true_a3, found_a3, 10) if len(found_a3) else 0.0)  # Recall.

print("scanned:", scan_a3, "recall:", rec_a3)  # Inspect tradeoff.
```

```python
def graph_search_a4(X, graph, q, ef, k=10):  # Greedy frontier search with ef budget.
    visited = {0}; frontier = [0]  # Fixed entry point.
    while frontier and len(visited) < ef:  # Expand until budget.
        cur = min(frontier, key=lambda i: np.linalg.norm(X[i] - q))  # Closest candidate.
        frontier.remove(cur)  # Mark expanded.

                if len(visited) >= ef: break  # Respect budget.
    cand = np.array(sorted(visited))  # Visited ids.
    return cand[np.argsort(np.linalg.norm(X[cand] - q, axis=1))[:k]], cand  # Results and work.
```
