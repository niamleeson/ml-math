# 17.6 — Multi-Task Learning

Multi-task learning (MTL) trains related tasks together by sharing part of the model while giving each task its own output head. In this lesson, you will build a shared-trunk, multi-head neural network from scratch with NumPy, inspect weighted losses, and see why helpful sharing becomes harmful when task gradients fight.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build multi-task learning one idea at a time. Run each cell in order and read the printed intermediate values — every shared representation, head-specific prediction, task weight, and gradient is shown directly. This walkthrough is self-contained and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays, random numbers, and hand-written neural-network math.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
np.random.seed(0)  # reproducibility for synthetic tasks and initial weights.
```

### 1. Related tasks share a hidden cause

Multi-task learning only makes sense when tasks have something worth sharing. We start with one input $x$ and two labels that both depend on the same latent nonlinear feature: a regression target and a binary classification target. The regression task asks for a smooth number; the classification task asks whether the same hidden signal is positive. Separate models could relearn that hidden feature twice, while a shared trunk can learn it once and let two heads reuse it.

```python
n_w = 80  # number of synthetic examples.
x_w = np.linspace(-2.0, 2.0, n_w)[:, None]  # one input feature as an n×1 matrix.
z_w = np.sin(2.0 * x_w[:, 0]) + 0.25 * x_w[:, 0]  # shared latent structure behind both tasks.
y_reg_w = z_w + 0.08 * np.random.randn(n_w)  # task 1: noisy regression label.
y_cls_w = (z_w > 0).astype(float)  # task 2: binary label from the same latent signal.
print("x shape:", x_w.shape, "reg mean:", round(float(y_reg_w.mean()), 3), "class rate:", round(float(y_cls_w.mean()), 3))
assert x_w.shape == (80, 1)
```
▶ What you'll see: one input matrix, one continuous label, and one binary label with a roughly balanced positive rate.

```python
plt.figure(figsize=(5, 3))
plt.plot(x_w[:, 0], z_w, color="black", label="shared latent z")
plt.scatter(x_w[:, 0], y_reg_w, s=18, alpha=0.7, label="regression labels")
plt.scatter(x_w[:, 0], y_cls_w - 1.4, s=18, alpha=0.7, label="classification labels shifted")
plt.title("1: two tasks from one hidden signal")
plt.xlabel("x"); plt.legend(); plt.show()
```
▶ What you'll see: the regression cloud follows the black curve, and the class labels flip where that curve crosses zero.

*Why it's done this way:* MTL is a bias: it assumes the best internal representation for one task is also useful for another. By generating both labels from the same $z(x)$, we create the exact condition where sharing should reduce variance — the trunk can spend parameters learning the reusable curve instead of letting each task estimate it independently.

### 2. Shared trunk plus task-specific heads

A multi-task network splits into a shared trunk and separate heads. The trunk computes a representation $h=f_\theta(x)$ used by every task. Each task then has its own head: $\hat y_1=g_{w_1}(h)$ for regression and $\hat y_2=g_{w_2}(h)$ for classification. Sharing stops before the heads because tasks need different output formats and losses.

```python
rng_w = np.random.default_rng(1)
W1_w = rng_w.normal(scale=0.7, size=(1, 4))  # shared trunk weights from x to 4 hidden units.
b1_w = np.zeros(4)  # shared trunk bias.
wr_w = rng_w.normal(scale=0.4, size=4)  # regression head weights.
br_w = 0.0  # regression head bias.
wc_w = rng_w.normal(scale=0.4, size=4)  # classification head weights.
bc_w = 0.0  # classification head bias.
print("shared trunk shape:", W1_w.shape, "reg head:", wr_w.shape, "cls head:", wc_w.shape)
```
▶ What you'll see: the trunk has one set of parameters, while the two heads have separate parameter vectors.

```python
H_w = np.tanh(x_w @ W1_w + b1_w)  # shared representation h = tanh(xW+b).
reg_pred_w = H_w @ wr_w + br_w  # regression head output.
logits_w = H_w @ wc_w + bc_w  # classification head logit.
cls_pred_w = 1.0 / (1.0 + np.exp(-logits_w))  # sigmoid probability.
print("H shape:", H_w.shape, "reg pred shape:", reg_pred_w.shape, "cls pred range:", (round(float(cls_pred_w.min()), 3), round(float(cls_pred_w.max()), 3)))
assert H_w.shape == (80, 4)
```
▶ What you'll see: every example becomes a 4-number shared representation, then each head turns it into its own output type.

```python
plt.figure(figsize=(5, 3))
plt.plot(x_w[:, 0], H_w[:, 0], label="shared unit 0")
plt.plot(x_w[:, 0], H_w[:, 1], label="shared unit 1")
plt.title("2: trunk features reused by both heads")
plt.xlabel("x"); plt.ylabel("hidden activation"); plt.legend(); plt.show()
```
▶ What you'll see: hidden units are smooth nonlinear basis functions that both heads can combine differently.

*Why it's done this way:* the trunk is where representation learning happens, so gradients from all tasks update the same $\theta$. The heads stay separate because a regression head should output an unconstrained number while a classifier head should output a probability. Sharing too late would force incompatible outputs; sharing too early would waste the common signal.

### 3. Weighted multi-task loss

Training uses one objective: $L=\sum_t \alpha_t L_t(\theta,w_t)$. For two tasks, $L=\alpha L_1+(1-\alpha)L_2$. The weights are not decoration; they decide which task shapes the shared representation most. The lesson's arithmetic example is $L_1=0.04$, $L_2=0.09$, $\alpha=0.7$, so $L=0.7\cdot0.04+0.3\cdot0.09=0.055$.

```python
L1_demo_w = 0.04  # regression-style task loss.
L2_demo_w = 0.09  # classification-style task loss.
alpha_demo_w = 0.7  # task-1 weight.
weighted_demo_w = alpha_demo_w * L1_demo_w + (1 - alpha_demo_w) * L2_demo_w
print("0.7*0.04 =", alpha_demo_w * L1_demo_w)
print("0.3*0.09 =", (1 - alpha_demo_w) * L2_demo_w)
print("weighted loss =", round(weighted_demo_w, 3))
assert round(weighted_demo_w, 3) == 0.055
```
▶ What you'll see: the weighted objective is 0.055, with nearly equal numeric contributions from the two tasks.

```python
mse_w = float(np.mean((reg_pred_w - y_reg_w) ** 2))  # regression loss from current random model.
bce_w = float(-np.mean(y_cls_w * np.log(cls_pred_w + 1e-9) + (1 - y_cls_w) * np.log(1 - cls_pred_w + 1e-9)))  # binary cross-entropy.
alpha_w = 0.6
joint_w = alpha_w * mse_w + (1 - alpha_w) * bce_w
print("MSE:", round(mse_w, 3), "BCE:", round(bce_w, 3), "joint:", round(joint_w, 3))
assert joint_w > 0
```
▶ What you'll see: the two losses can live on different numerical scales, so the chosen weights change the joint objective.

```python
alphas_w = np.linspace(0, 1, 6)
joints_w = alphas_w * mse_w + (1 - alphas_w) * bce_w
plt.figure(figsize=(5, 3))
plt.plot(alphas_w, joints_w, marker="o", color="purple")
plt.title("3: alpha moves the joint objective")
plt.xlabel("α weight on regression"); plt.ylabel("α MSE + (1-α) BCE"); plt.show()
```
▶ What you'll see: the objective changes smoothly from pure classification loss to pure regression loss as α moves from 0 to 1.

*Why it's done this way:* a shared parameter receives the weighted sum of task gradients, so loss weights directly choose the compromise representation. If one task has a larger raw loss scale, it can dominate even when it is not more important. Weighting is therefore both a mathematical objective and a product decision about which errors matter.

### 4. Backpropagating both heads into the shared trunk

For a shared parameter, backpropagation adds task contributions. If $L=\alpha L_r+(1-\alpha)L_c$, then the trunk gradient is $\nabla_\theta L=\alpha\nabla_\theta L_r+(1-\alpha)\nabla_\theta L_c$. Below we compute one full-batch gradient by hand: regression sends residuals through its head, classification sends probability errors through its head, and both meet at the trunk.

```python
n_float_w = float(n_w)
dreg_w = (2.0 / n_float_w) * (reg_pred_w - y_reg_w)  # derivative of mean squared error wrt regression prediction.
dlogit_w = (cls_pred_w - y_cls_w) / n_float_w  # derivative of mean BCE wrt classification logit.
dH_reg_w = dreg_w[:, None] * wr_w[None, :]  # regression gradient arriving at shared hidden units.
dH_cls_w = dlogit_w[:, None] * wc_w[None, :]  # classification gradient arriving at shared hidden units.
print("mean |dH_reg|:", round(float(np.mean(np.abs(dH_reg_w))), 5), "mean |dH_cls|:", round(float(np.mean(np.abs(dH_cls_w))), 5))
```
▶ What you'll see: both heads send a gradient signal into the same hidden representation, often with different magnitudes.

```python
dZ_reg_w = dH_reg_w * (1 - H_w ** 2)  # tanh derivative for regression pathway.
dZ_cls_w = dH_cls_w * (1 - H_w ** 2)  # tanh derivative for classification pathway.
gW_reg_w = x_w.T @ dZ_reg_w  # trunk weight gradient from regression.
gW_cls_w = x_w.T @ dZ_cls_w  # trunk weight gradient from classification.
gW_joint_w = alpha_w * gW_reg_w + (1 - alpha_w) * gW_cls_w  # weighted shared-trunk gradient.
print("||grad reg||:", round(float(np.linalg.norm(gW_reg_w)), 4))
print("||grad cls||:", round(float(np.linalg.norm(gW_cls_w)), 4))
print("||grad joint||:", round(float(np.linalg.norm(gW_joint_w)), 4))
```
▶ What you'll see: the joint trunk update is literally a weighted blend of the two task-specific trunk gradients.

```python
plt.figure(figsize=(5, 3))
plt.bar(["reg", "cls", "joint"], [np.linalg.norm(gW_reg_w), np.linalg.norm(gW_cls_w), np.linalg.norm(gW_joint_w)], color=["teal", "orange", "purple"])
plt.title("4: task gradients combine in shared parameters")
plt.ylabel("gradient norm"); plt.show()
```
▶ What you'll see: the joint bar sits between or near the task bars depending on direction and weight.

*Why it's done this way:* separate heads only update their own parameters from their own losses, but the trunk is accountable to every task. The chain rule makes each head translate its output error into a hidden-feature error, and the weighted sum tells the trunk which direction best reduces the joint objective.

### 5. Gradient conflict and negative transfer

Sharing helps when task gradients point in similar directions. It hurts when they point against each other. The cosine $\cos(g_1,g_2)=g_1\cdot g_2/(\|g_1\|\|g_2\|)$ diagnoses the conflict: positive means agreement, near zero means unrelated, and negative means a tug-of-war. A healthy scalar loss can hide that one task is improving by damaging another.

```python
g1_w = gW_reg_w.ravel()
g2_w = gW_cls_w.ravel()
cos_grad_w = float(np.dot(g1_w, g2_w) / (np.linalg.norm(g1_w) * np.linalg.norm(g2_w)))
print("gradient cosine between tasks:", round(cos_grad_w, 3))
assert -1.0 <= cos_grad_w <= 1.0
```
▶ What you'll see: one number summarizes whether the current regression and classification updates agree in the shared trunk.

```python
g_good_w = np.array([1.0, 0.2])
g_bad_w = np.array([-0.8, -0.1])
cos_bad_w = float(np.dot(g_good_w, g_bad_w) / (np.linalg.norm(g_good_w) * np.linalg.norm(g_bad_w)))
print("toy conflicting cosine:", round(cos_bad_w, 3))
assert cos_bad_w < -0.95
```
▶ What you'll see: the toy gradients are almost opposite, so any shared update must compromise.

```python
plt.figure(figsize=(4.5, 3.5))
plt.quiver([0, 0], [0, 0], [g_good_w[0], g_bad_w[0]], [g_good_w[1], g_bad_w[1]], angles="xy", scale_units="xy", scale=1, color=["teal", "crimson"])
plt.xlim(-1.1, 1.2); plt.ylim(-0.4, 0.4)
plt.axhline(0, color="gray", linewidth=0.5); plt.axvline(0, color="gray", linewidth=0.5)
plt.title("5: conflicting task gradients")
plt.xlabel("shared parameter 0"); plt.ylabel("shared parameter 1"); plt.show()
```
▶ What you'll see: the arrows point in opposite directions, illustrating why one shared trunk can become a tug-of-war.

*Why it's done this way:* gradient cosine separates “tasks have different losses” from “tasks want incompatible representations.” When gradients conflict, increasing sharing or overweighting one task can cause negative transfer: the shared update lowers one task's loss while raising the other's. The fix is not automatic — it may require less sharing, different weights, gradient surgery, or task-specific capacity.

### ✍️ Toy 1 · Two labels share one hidden signal

Multi-task learning starts with related labels. Here one latent line creates both a regression
number and a binary class label.

```python
import numpy as np
import matplotlib.pyplot as plt

t1_rng = np.random.default_rng(0)
print("rng seed:", 0)  # -> 0
t1_x = np.array([-1.0, 0.0, 1.0, 2.0])
print("x:", t1_x.tolist())  # -> [-1.0, 0.0, 1.0, 2.0]
t1_z = 2.0 * t1_x - 1.0
print("shared signal z:", t1_z.tolist())  # -> [-3.0, -1.0, 1.0, 3.0]
t1_reg_noise = np.array([0.0, 0.2, -0.2, 0.0])
print("regression noise:", t1_reg_noise.tolist())  # -> [0.0, 0.2, -0.2, 0.0]
t1_y_reg = t1_z + t1_reg_noise
print("regression labels:", t1_y_reg.tolist())  # -> [-3.0, -0.8, 0.8, 3.0]
t1_y_cls = (t1_z > 0.0).astype(int)
print("classification labels:", t1_y_cls.tolist())  # -> [0, 0, 1, 1]
t1_check = np.array_equal(t1_y_cls, np.array([0, 0, 1, 1]))
print("class changes where z is positive:", bool(t1_check))  # -> True
assert t1_check

plt.figure(figsize=(4.8, 2.8))
plt.plot(t1_x, t1_z, color="black", marker="o", label="shared z")
plt.scatter(t1_x, t1_y_reg, color="teal", label="regression label")
plt.scatter(t1_x, t1_y_cls - 4.0, color="crimson", label="class label shifted")
plt.axhline(0.0, color="gray", linewidth=0.7)
plt.xlabel("x")
plt.title("Toy 1 · one signal feeds two tasks")
plt.legend()
plt.show()
```
▶ What you'll see: the class label flips exactly where the shared signal becomes positive.

### ✍️ Toy 2 · Shared trunk feeds separate heads

The trunk makes one hidden representation; the regression and classification heads read it in
different ways.

```python
import numpy as np

t2_rng = np.random.default_rng(0)
print("rng seed:", 0)  # -> 0
t2_x = np.array([[-1.0], [0.0], [2.0]])
print("x shape:", t2_x.shape)  # -> (3, 1)
t2_W = np.array([[1.0, -0.5]])
print("trunk W:", t2_W.tolist())  # -> [[1.0, -0.5]]
t2_b = np.array([0.0, 1.0])
print("trunk b:", t2_b.tolist())  # -> [0.0, 1.0]
t2_affine = t2_x @ t2_W + t2_b
print("trunk affine:", np.round(t2_affine, 3).tolist())  # -> [[-1.0, 1.5], [0.0, 1.0], [2.0, 0.0]]
t2_H = np.tanh(t2_affine)
print("shared H:", np.round(t2_H, 3).tolist())  # -> [[-0.762, 0.905], [0.0, 0.762], [0.964, 0.0]]
t2_wr = np.array([2.0, -1.0])
print("reg head weights:", t2_wr.tolist())  # -> [2.0, -1.0]
t2_reg = t2_H @ t2_wr + 0.5
print("reg prediction:", np.round(t2_reg, 3).tolist())  # -> [-1.928, -0.262, 2.428]
t2_wc = np.array([-1.0, 1.0])
print("cls head weights:", t2_wc.tolist())  # -> [-1.0, 1.0]
t2_logit = t2_H @ t2_wc
print("class logits:", np.round(t2_logit, 3).tolist())  # -> [1.667, 0.762, -0.964]
t2_prob = 1.0 / (1.0 + np.exp(-t2_logit))
print("class probabilities:", np.round(t2_prob, 3).tolist())  # -> [0.841, 0.682, 0.276]
assert t2_H.shape == (3, 2)

plt.figure(figsize=(4.6, 2.8))
plt.plot(t2_x.ravel(), t2_H[:, 0], marker="o", label="hidden 0")
plt.plot(t2_x.ravel(), t2_H[:, 1], marker="s", label="hidden 1")
plt.xlabel("x")
plt.ylabel("shared activation")
plt.title("Toy 2 · both heads reuse H")
plt.legend()
plt.show()
```
▶ What you'll see: the same two hidden columns are reused to make two different outputs.

### ✍️ Toy 3 · Task weights blend losses

A multi-task objective is arithmetic: compute each task loss, choose a weight, then form the
weighted sum.

```python
import numpy as np

t3_rng = np.random.default_rng(0)
print("rng seed:", 0)  # -> 0
t3_reg_true = np.array([1.5, 1.0, 2.5])
print("reg truth:", t3_reg_true.tolist())  # -> [1.5, 1.0, 2.5]
t3_reg_pred = np.array([1.0, 2.0, 3.0])
print("reg pred:", t3_reg_pred.tolist())  # -> [1.0, 2.0, 3.0]
t3_resid = t3_reg_pred - t3_reg_true
print("reg residuals:", t3_resid.tolist())  # -> [-0.5, 1.0, 0.5]
t3_sq = t3_resid ** 2
print("squared errors:", t3_sq.tolist())  # -> [0.25, 1.0, 0.25]
t3_mse = float(np.mean(t3_sq))
print("MSE:", round(t3_mse, 3))  # -> 0.5
t3_cls_true = np.array([1.0, 0.0, 1.0])
print("class truth:", t3_cls_true.tolist())  # -> [1.0, 0.0, 1.0]
t3_cls_prob = np.array([0.8, 0.4, 0.6])
print("class probabilities:", t3_cls_prob.tolist())  # -> [0.8, 0.4, 0.6]
t3_bce_terms = -(t3_cls_true * np.log(t3_cls_prob) + (1.0 - t3_cls_true) * np.log(1.0 - t3_cls_prob))
print("BCE terms:", np.round(t3_bce_terms, 3).tolist())  # -> [0.223, 0.511, 0.511]
t3_bce = float(np.mean(t3_bce_terms))
print("BCE:", round(t3_bce, 3))  # -> 0.415
t3_alpha = 0.6
print("alpha:", t3_alpha)  # -> 0.6
t3_joint = t3_alpha * t3_mse + (1.0 - t3_alpha) * t3_bce
print("joint loss:", round(t3_joint, 3))  # -> 0.466
assert round(t3_joint, 3) == 0.466

plt.figure(figsize=(4.6, 2.8))
plt.bar(["MSE", "BCE", "joint"], [t3_mse, t3_bce, t3_joint], color=["teal", "orange", "purple"])
plt.ylabel("loss")
plt.title("Toy 3 · weighted multi-task loss")
plt.show()
```
▶ What you'll see: the joint loss sits between the regression MSE and classification BCE.

### ✍️ Toy 4 · Head gradients add in the trunk

Both heads send gradients back into the same hidden units. The shared trunk receives their weighted
sum.

```python
import numpy as np

t4_rng = np.random.default_rng(0)
print("rng seed:", 0)  # -> 0
t4_x = np.array([[-1.0], [1.0]])
print("x:", t4_x.ravel().tolist())  # -> [-1.0, 1.0]
t4_H = np.array([[0.0, 0.5], [1.0, -0.5]])
print("shared H:", t4_H.tolist())  # -> [[0.0, 0.5], [1.0, -0.5]]
t4_reg_pred = np.array([0.4, 0.8])
print("reg pred:", t4_reg_pred.tolist())  # -> [0.4, 0.8]
t4_reg_true = np.array([0.0, 1.0])
print("reg truth:", t4_reg_true.tolist())  # -> [0.0, 1.0]
t4_wr = np.array([1.0, -1.0])
print("reg head:", t4_wr.tolist())  # -> [1.0, -1.0]
t4_cls_prob = np.array([0.25, 0.75])
print("class prob:", t4_cls_prob.tolist())  # -> [0.25, 0.75]
t4_cls_true = np.array([0.0, 1.0])
print("class truth:", t4_cls_true.tolist())  # -> [0.0, 1.0]
t4_wc = np.array([0.5, 0.5])
print("class head:", t4_wc.tolist())  # -> [0.5, 0.5]
t4_n = float(len(t4_x))
print("n:", t4_n)  # -> 2.0
t4_dreg = (2.0 / t4_n) * (t4_reg_pred - t4_reg_true)
print("dL/d reg_pred:", np.round(t4_dreg, 3).tolist())  # -> [0.4, -0.2]
t4_dlogit = (t4_cls_prob - t4_cls_true) / t4_n
print("dL/d class_logit:", t4_dlogit.tolist())  # -> [0.125, -0.125]
t4_dH_reg = t4_dreg[:, None] * t4_wr[None, :]
print("hidden grad from reg:", np.round(t4_dH_reg, 4).tolist())  # -> [[0.4, -0.4], [-0.2, 0.2]]
t4_dH_cls = t4_dlogit[:, None] * t4_wc[None, :]
print("hidden grad from cls:", np.round(t4_dH_cls, 4).tolist())  # -> [[0.0625, 0.0625], [-0.0625, -0.0625]]
t4_alpha = 0.5
print("alpha:", t4_alpha)  # -> 0.5
t4_dH_joint = t4_alpha * t4_dH_reg + (1.0 - t4_alpha) * t4_dH_cls
print("joint hidden grad:", np.round(t4_dH_joint, 4).tolist())  # -> [[0.2312, -0.1688], [-0.1312, 0.0687]]
t4_tanh_slope = 1.0 - t4_H ** 2
print("tanh slope:", np.round(t4_tanh_slope, 4).tolist())  # -> [[1.0, 0.75], [0.0, 0.75]]
t4_dZ_joint = t4_dH_joint * t4_tanh_slope
print("joint pre-activation grad:", np.round(t4_dZ_joint, 4).tolist())  # -> [[0.2312, -0.1266], [-0.0, 0.0516]]
t4_gW = t4_x.T @ t4_dZ_joint
print("shared W gradient:", np.round(t4_gW, 4).tolist())  # -> [[-0.2312, 0.1781]]
assert np.allclose(np.round(t4_gW, 4), [[-0.2312, 0.1781]])

plt.figure(figsize=(4.6, 2.8))
plt.bar(["W0", "W1"], t4_gW.ravel(), color=["teal", "orange"])
plt.axhline(0.0, color="black", linewidth=0.7)
plt.ylabel("gradient")
plt.title("Toy 4 · shared gradient after both heads")
plt.show()
```
▶ What you'll see: the final shared-weight gradient is the weighted blend after both heads backpropagate.

### ✍️ Toy 5 · Negative cosine exposes conflict

When two task gradients point against each other, the shared update can help one task while hurting
the other.

```python
import numpy as np

t5_rng = np.random.default_rng(0)
print("rng seed:", 0)  # -> 0
t5_g_reg = np.array([1.0, 0.0])
print("reg gradient:", t5_g_reg.tolist())  # -> [1.0, 0.0]
t5_g_cls = np.array([-2.0, 0.5])
print("class gradient:", t5_g_cls.tolist())  # -> [-2.0, 0.5]
t5_dot = float(np.dot(t5_g_reg, t5_g_cls))
print("dot product:", round(t5_dot, 3))  # -> -2.0
t5_norm_reg = float(np.linalg.norm(t5_g_reg))
print("reg norm:", round(t5_norm_reg, 3))  # -> 1.0
t5_norm_cls = float(np.linalg.norm(t5_g_cls))
print("class norm:", round(t5_norm_cls, 3))  # -> 2.062
```

```python
x_e1 = np.linspace(-1.5, 1.5, 40)[:, None]  # Create one-feature inputs.
```

### Easy 2 — One full-batch gradient step

**Goal.** Take one gradient step for a tiny multi-task network, because shared learning is just backpropagation with summed task gradients. We build it in 4 steps.

```python
x_e2 = np.linspace(-1, 1, 30)[:, None]  # Create inputs.
yr_e2 = 0.8 * x_e2[:, 0] + 0.2  # Regression labels.
yc_e2 = (x_e2[:, 0] > 0).astype(float)  # Classification labels.
W_e2 = np.array([[0.4, -0.3]])  # Shared trunk weights.
b_e2 = np.zeros(2)  # Shared trunk bias.
wr_e2 = np.array([0.5, -0.2])  # Regression head.
wc_e2 = np.array([-0.1, 0.6])  # Classification head.
print("examples:", len(x_e2))
```
▶ What you'll see: two supervised tasks defined over the same inputs.

```python
H_e2 = np.tanh(x_e2 @ W_e2 + b_e2)  # Forward through shared trunk.
reg_e2 = H_e2 @ wr_e2  # Regression predictions.
prob_e2 = 1 / (1 + np.exp(-(H_e2 @ wc_e2)))  # Classification probabilities.
mse_e2 = np.mean((reg_e2 - yr_e2) ** 2)  # Regression loss.
bce_e2 = -np.mean(yc_e2 * np.log(prob_e2 + 1e-9) + (1 - yc_e2) * np.log(1 - prob_e2 + 1e-9))  # Classification loss.
print("before losses:", round(float(mse_e2), 3), round(float(bce_e2), 3))
```

```python
alpha_e2 = 0.5  # Equal task weighting.
n_e2 = float(len(x_e2))
dreg_e2 = (2 / n_e2) * (reg_e2 - yr_e2)  # dMSE/dreg.
dlogit_e2 = (prob_e2 - yc_e2) / n_e2  # dBCE/dlogit.
dH_e2 = alpha_e2 * dreg_e2[:, None] * wr_e2[None, :] + (1 - alpha_e2) * dlogit_e2[:, None] * wc_e2[None, :]  # Combined hidden gradient.
dZ_e2 = dH_e2 * (1 - H_e2 ** 2)  # Backprop through tanh.
gW_e2 = x_e2.T @ dZ_e2  # Shared trunk gradient.
gwr_e2 = H_e2.T @ (alpha_e2 * dreg_e2)  # Regression head gradient.
gwc_e2 = H_e2.T @ ((1 - alpha_e2) * dlogit_e2)  # Classification head gradient.
print("gradient norms:", round(float(np.linalg.norm(gW_e2)), 4), round(float(np.linalg.norm(gwr_e2)), 4), round(float(np.linalg.norm(gwc_e2)), 4))
```

```python
eta_e2 = 0.3  # Learning rate for one demonstrative step.
W2_e2 = W_e2 - eta_e2 * gW_e2  # Update shared trunk.
wr2_e2 = wr_e2 - eta_e2 * gwr_e2  # Update regression head.
wc2_e2 = wc_e2 - eta_e2 * gwc_e2  # Update classification head.
H2_e2 = np.tanh(x_e2 @ W2_e2 + b_e2)
reg2_e2 = H2_e2 @ wr2_e2
prob2_e2 = 1 / (1 + np.exp(-(H2_e2 @ wc2_e2)))
joint_before_e2 = alpha_e2 * mse_e2 + (1 - alpha_e2) * bce_e2
joint_after_e2 = alpha_e2 * np.mean((reg2_e2 - yr_e2) ** 2) + (1 - alpha_e2) * (-np.mean(yc_e2 * np.log(prob2_e2 + 1e-9) + (1 - yc_e2) * np.log(1 - prob2_e2 + 1e-9)))
print("joint before/after:", round(float(joint_before_e2), 4), round(float(joint_after_e2), 4))
assert joint_after_e2 < joint_before_e2
plt.figure(figsize=(4, 3)); plt.bar(["before", "after"], [joint_before_e2, joint_after_e2], color=["gray", "teal"]); plt.title("Easy 2: one MTL update"); plt.show()
```
▶ What you'll see: one combined gradient step lowers the weighted joint loss.

👀 Takeaway: a shared trunk update is the chain-rule sum of task-specific learning signals.

### Easy 3 — Sweep task weights

**Goal.** Train the same small model with several α values, because task weights decide the compromise between tasks. We build it in 3 steps.

```python
x_e3 = np.linspace(-1.5, 1.5, 60)[:, None]
yr_e3 = np.sin(2 * x_e3[:, 0])
yc_e3 = (yr_e3 > 0).astype(float)
alphas_e3 = np.array([0.2, 0.5, 0.8])
print("alphas:", alphas_e3)
```
▶ What you'll see: the same related tasks will be trained under three weighting choices.

```python

bce_final_e3 = []
for alpha_e3 in alphas_e3:
    rng_e3 = np.random.default_rng(3)
    W_e3 = 0.4 * rng_e3.normal(size=(1, 5)); b_e3 = np.zeros(5)
    wr_e3 = 0.4 * rng_e3.normal(size=5); wc_e3 = 0.4 * rng_e3.normal(size=5)
    for step_e3 in range(250):
        H_e3 = np.tanh(x_e3 @ W_e3 + b_e3)
        reg_e3 = H_e3 @ wr_e3
        prob_e3 = 1 / (1 + np.exp(-(H_e3 @ wc_e3)))
        dreg_e3 = (2 / len(x_e3)) * (reg_e3 - yr_e3)
        dlogit_e3 = (prob_e3 - yc_e3) / len(x_e3)
        dH_e3 = alpha_e3 * dreg_e3[:, None] * wr_e3[None, :] + (1 - alpha_e3) * dlogit_e3[:, None] * wc_e3[None, :]
        dZ_e3 = dH_e3 * (1 - H_e3 ** 2)
        old_wr_e3 = wr_e3.copy(); old_wc_e3 = wc_e3.copy()
        W_e3 -= 0.08 * (x_e3.T @ dZ_e3); b_e3 -= 0.08 * dZ_e3.sum(axis=0)
        wr_e3 -= 0.08 * (H_e3.T @ (alpha_e3 * dreg_e3)); wc_e3 -= 0.08 * (H_e3.T @ ((1 - alpha_e3) * dlogit_e3))
    H_e3 = np.tanh(x_e3 @ W_e3 + b_e3); reg_e3 = H_e3 @ wr_e3; prob_e3 = 1 / (1 + np.exp(-(H_e3 @ wc_e3)))
    mse_final_e3.append(float(np.mean((reg_e3 - yr_e3) ** 2)))
    bce_final_e3.append(float(-np.mean(yc_e3 * np.log(prob_e3 + 1e-9) + (1 - yc_e3) * np.log(1 - prob_e3 + 1e-9))))
print("MSE:", np.round(mse_final_e3, 3), "BCE:", np.round(bce_final_e3, 3))
```

```python

```
▶ What you'll see: emphasizing regression usually lowers MSE at the cost of less classification emphasis.

👀 Takeaway: α is a tradeoff knob that should be tuned against the real evaluation goal.

```python
    dH_e4 = 0.5 * dreg_e4[:, None] * wr_e4[None, :] + 0.5 * dlogit_e4[:, None] * wc_e4[None, :]
    dZ_e4 = dH_e4 * (1 - H_e4 ** 2)
    W_e4 -= 0.07 * (x_e4.T @ dZ_e4); b_e4 -= 0.07 * dZ_e4.sum(axis=0)
    wr_e4 -= 0.07 * (H_e4.T @ (0.5 * dreg_e4)); wc_e4 -= 0.07 * (H_e4.T @ (0.5 * dlogit_e4))
H_e4 = np.tanh(x_e4 @ W_e4 + b_e4); shared_mse_e4 = float(np.mean((H_e4 @ wr_e4 - yr_e4) ** 2))
shared_bce_e4 = float(-np.mean(yc_e4 * np.log(1/(1+np.exp(-(H_e4 @ wc_e4))) + 1e-9) + (1-yc_e4)*np.log(1-1/(1+np.exp(-(H_e4 @ wc_e4))) + 1e-9)))
```

### Easy 5 — Detect harmful sharing with validation

### Advanced 1 — Train a shared trunk with two heads from scratch

**Goal.** Fit a small nonlinear multi-task network end to end, because the complete MTL loop is forward pass, weighted loss, backpropagation, and repeated updates. We build it in 5 steps.

```python

```
▶ What you'll see: one shared 6-unit trunk and two separate linear heads.


### Advanced 2 — Inspect gradient conflicts during training

**Goal.** Track gradient cosine over training, because task agreement can change as representations improve. We build it in 4 steps.


### Advanced 3 — Project away a conflicting gradient component

**Goal.** Implement a tiny gradient-surgery step, because one response to conflict is to remove the part of one task gradient that directly opposes another. We build it in 3 steps.

```python
g1_a3 = np.array([1.0, 0.2])  # Task 1 wants to move mostly right.
g2_a3 = np.array([-0.8, -0.4])  # Task 2 partly opposes task 1.
```

```python
cos_after_a3 = float(np.dot(g1_fixed_a3, g2_a3) / (np.linalg.norm(g1_fixed_a3) * np.linalg.norm(g2_a3)))
```
