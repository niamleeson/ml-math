# 15.2 · Matrix Factorization

Matrix factorization (MF) explains a sparse user-item rating table by giving each user and item a short latent vector, then scoring a pair with a dot product. In this lesson, you will build MF from first principles, inspect every intermediate value, and see why the low-rank bottleneck helps recommenders generalize instead of memorizing cells.

## 📖 Concept walkthrough — build it from scratch

Before the terse worked examples, we build matrix factorization one idea at a time. Run each cell in order and read the printed intermediate values — every piece of math, including the gradient, is derived and shown. This walkthrough is self-contained and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays + linear algebra for factors and dot products.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
np.random.seed(0)  # reproducibility for inits and SGD.
```

### 1. The sparse rating matrix and the low-rank idea

MF starts from the same user×item table as collaborative filtering, but asks a bolder question: can we explain *all* the ratings with just a **few hidden dimensions**? If users really differ along, say, two underlying taste axes, then each user is two numbers, each item is two numbers, and a rating is how well they line up. Forcing the data through this narrow "low-rank" bottleneck is what stops the model from merely memorizing cells and makes it *generalize* to blanks.

```python
R_w = np.array([[5., 4., 0., 1.],   # Ava
                [4., 5., 0., 1.],   # Ben
                [1., 1., 5., 4.],   # Cam
                [0., 1., 4., 5.]])  # Dee
print("shape:", R_w.shape)          # 4 users x 4 items.
print("observed entries:", int((R_w > 0).sum()), "of", R_w.size)  # 0 = unobserved.
```
▶ What you'll see: a 4×4 matrix with two blanks; MF will fill them from learned factors, not neighbors.

```python
plt.figure(figsize=(4.2, 3.2))                    # heatmap of the rating matrix.
plt.imshow(R_w, cmap="viridis")                    # color = rating value.
plt.colorbar(label="rating (0 = unobserved)")      # legend.
plt.title("1: the rating matrix to factor"); plt.show()
```
▶ What you'll see: a clear block structure — Ava/Ben on one pair of items, Cam/Dee on the other — hinting that ~2 hidden factors explain it.

*Why it's done this way: a full m×n table has m·n free numbers; a rank-k factorization has only (m+n)·k. That compression is the model's bet that a few reusable causes drive most preferences.*

### 2. Latent factors: users and items as short vectors

We give every user a vector $p_u\in\mathbb{R}^k$ and every item a vector $q_i\in\mathbb{R}^k$ (here $k=2$). Each coordinate is a **latent factor** — a learned axis of taste. Nobody labels these axes; the training procedure discovers whatever two directions best explain the ratings. We can still *interpret* them after the fact (axis 0 might behave like "action vs. drama"), but the model only promises they are *predictive*, not human-named.

```python
p0_w = np.array([1.2, 0.2])   # user 0's factors: strong on axis 0, weak on axis 1.
q0_w = np.array([4.0, 0.2])   # item 0's factors: strong on axis 0.
q2_w = np.array([0.2, 3.7])   # item 2's factors: strong on axis 1 instead.
print("user p0:", p0_w)        # a point in 2-D taste space.
print("item q0:", q0_w, " item q2:", q2_w)  # two items on opposite axes.
```
▶ What you'll see: user 0 and item 0 both lean on axis 0; item 2 leans on axis 1.

```python
plt.figure(figsize=(4, 3.4))                                  # plot latent space.
for vec, name, col in [(p0_w, "p0 (user)", "crimson"),
                       (q0_w, "q0 (item)", "steelblue"),
                       (q2_w, "q2 (item)", "darkorange")]:     # draw each vector.
    plt.arrow(0, 0, vec[0], vec[1], head_width=0.15, color=col, length_includes_head=True)
    plt.text(vec[0], vec[1], name)                             # label the arrowhead.
plt.xlim(-.5, 4.5); plt.ylim(-.5, 4); plt.xlabel("latent axis 0"); plt.ylabel("latent axis 1")
plt.title("2: users & items in latent space"); plt.show()
```
▶ What you'll see: p0 points nearly the same direction as q0 (small angle) but nearly perpendicular to q2 (large angle) — that angle is what scores a rating.

*Why it's done this way: representing users and items in the *same* space lets a single dot product compare any pair, even ones that never co-occurred — the escape from CF's overlap requirement.*

### 3. Dot-product scoring

The predicted rating is the dot product $\hat r_{ui}=p_u^\top q_i=\sum_{f} p_{uf}\,q_{if}$. It is large when the two vectors point the same way (aligned taste) and small when they are perpendicular. Reading it factor-by-factor, $p_{uf}q_{if}$ is "how much user and item agree on axis $f$," and the score sums those per-axis agreements.

```python
contrib_w = p0_w * q2_w                    # elementwise: per-axis agreement of user0 with item2.
r02_w = float(p0_w @ q2_w)                  # dot product = sum of the per-axis agreements.
print("per-axis contributions:", contrib_w)  # [1.2*0.2, 0.2*3.7] = [0.24, 0.74].
print("r(0,2) = sum =", round(r02_w, 3))     # 0.24 + 0.74 = 0.98.
assert round(r02_w, 3) == 0.980              # lesson number.
```
▶ What you'll see: even though item 2 is strong on axis 1, user 0 is weak there, so the score stays low (0.98).

```python
r00_w = float(p0_w @ q0_w)                  # user0 vs item0: aligned on axis 0.
print("r(0,0) =", round(r00_w, 3))           # 1.2*4.0 + 0.2*0.2 = 4.84.
assert round(r00_w, 3) == 4.840              # lesson number.
```
▶ What you'll see: user 0 and item 0 are aligned, so the score is high (4.84) — the same user, opposite verdicts on two items.

```python
Q_w = np.vstack([q0_w, np.array([0.3, 0.5]), q2_w, np.array([3.5, 0.4])])  # 4 item vectors as rows.
row_pred_w = p0_w @ Q_w.T                    # predict user0's rating for EVERY item at once.
print("user0 predicted row:", np.round(row_pred_w, 3))  # one dot product per item.
plt.figure(figsize=(4.4, 3)); plt.bar(range(4), row_pred_w, color="teal")
plt.xticks(range(4), ["I0", "I1", "I2", "I3"]); plt.ylabel("predicted rating")
plt.title("3: p0 · Qᵀ scores the whole row"); plt.show()
```
▶ What you'll see: one matrix–vector product scores all items for a user — this is why MF retrieval is cheap.

*Why it's done this way: the dot product collapses two vectors into one affinity number, and doing it as $p_u^\top Q^\top$ scores an entire catalog in a single vectorized step.*

### 4. The objective: squared error over OBSERVED entries only

Training means choosing $P,Q$ so predictions match the *known* ratings. We minimize squared error, but **only over the observed set $\Omega$** — the cells we actually have. We also add an L2 penalty $\lambda(\lVert p_u\rVert^2+\lVert q_i\rVert^2)$ to keep the factors small and avoid overfitting:

$$L=\sum_{(u,i)\in\Omega}\big(r_{ui}-p_u^\top q_i\big)^2+\lambda\big(\lVert p_u\rVert^2+\lVert q_i\rVert^2\big).$$

Why squared error? Squaring makes every miss positive, punishes big misses far more than small ones, and gives a smooth bowl-shaped loss that is easy to descend. Why observed-only? A blank means "unknown," not "rating 0." If we summed over blanks as zeros, we'd be training the model to predict *0* for everything a user hasn't touched yet — that is exposure modeling, a different task.

```python
r_w = 5.0                                   # one observed rating.
preds_w = np.linspace(0, 8, 41)              # sweep possible predictions.
loss_curve_w = (r_w - preds_w) ** 2          # squared error for each guess.
print("min loss at prediction =", preds_w[np.argmin(loss_curve_w)])  # bowl bottom at r=5.
plt.figure(figsize=(4.2, 3)); plt.plot(preds_w, loss_curve_w, color="purple")
plt.axvline(r_w, ls="--", c="k"); plt.xlabel("prediction"); plt.ylabel("squared error")
plt.title("4: squared-error bowl (min at the true rating)"); plt.show()
```
▶ What you'll see: a parabola with its minimum exactly at the observed rating — descending it pulls predictions toward truth.

```python
mask_w = R_w > 0                             # Ω: the observed entries.
print("training cells (Ω):", int(mask_w.sum()), "— blanks are EXCLUDED, not treated as 0")
```
▶ What you'll see: only the observed cells enter the loss; the blanks are left for the model to fill.

*Why it's done this way: squaring gives a smooth, convex-per-factor bowl to descend, and restricting to Ω keeps "unknown" from being silently taught as "disliked."*

### 5. The gradient and one SGD step (derived)

To reduce the loss we nudge each factor in the direction that lowers it — the negative gradient. For one observed cell with error $e=r_{ui}-p_u^\top q_i$, the loss term is $e^2+\lambda\lVert p_u\rVert^2+\dots$. Differentiating with respect to $p_u$:

$$\frac{\partial}{\partial p_u}\big(r_{ui}-p_u^\top q_i\big)^2 = 2\big(r_{ui}-p_u^\top q_i\big)\cdot(-q_i) = -2e\,q_i,\qquad \frac{\partial}{\partial p_u}\lambda\lVert p_u\rVert^2 = 2\lambda p_u.$$

So the gradient is $-2e\,q_i+2\lambda p_u$, and gradient **descent** moves *opposite* to it. Folding the 2 into the step size $\eta$, the update is $p_u \leftarrow p_u+\eta\,(e\,q_i-\lambda p_u)$, and symmetrically $q_i \leftarrow q_i+\eta\,(e\,p_u-\lambda q_i)$. Intuitively: if we under-predicted ($e>0$), push $p_u$ toward $q_i$ so their dot product rises next time; the $-\lambda p_u$ term gently shrinks the vector to stay small.

```python
p_w = np.array([0.8, 0.2])   # current user factor.
q_w = np.array([3.0, 0.4])   # current item factor.
r_obs_w, eta_w, lam_w = 5.0, 0.05, 0.1   # observed rating, step size, regularization.
pred_w = float(p_w @ q_w)                 # current prediction.
e_w = r_obs_w - pred_w                     # error = how far we under/over-shot.
print("prediction:", round(pred_w, 3), " error e:", round(e_w, 3))  # 2.48, 2.52.
assert round(pred_w, 3) == 2.480 and round(e_w, 3) == 2.520          # lesson numbers.
```
▶ What you'll see: we under-predicted (e = +2.52), so the step should raise the score.

```python
grad_p_w = e_w * q_w - lam_w * p_w          # the (folded-2) gradient direction for p.
grad_q_w = e_w * p_w - lam_w * q_w          # symmetric direction for q.
print("update direction for p:", np.round(grad_p_w, 3))  # e*q - lam*p.
print("update direction for q:", np.round(grad_q_w, 3))  # e*p - lam*q.
```
▶ What you'll see: both directions point to enlarge the aligned components (because e>0), slightly damped by regularization.

```python
p_new_w = p_w + eta_w * grad_p_w            # one SGD step on p.
q_new_w = q_w + eta_w * grad_q_w            # one SGD step on q.
new_pred_w = float(p_new_w @ q_new_w)        # prediction after the step.
print("p':", np.round(p_new_w, 3), " q':", np.round(q_new_w, 3))  # (1.174,0.249),(3.086,0.423).
print("new prediction:", round(new_pred_w, 3), "(was 2.48, target 5)")  # 3.728.
assert np.allclose(np.round(p_new_w, 3), [1.174, 0.249])             # lesson p'.
assert np.allclose(np.round(q_new_w, 3), [3.086, 0.423])             # lesson q'.
assert round(new_pred_w, 3) == 3.728                                  # lesson new prediction.

plt.figure(figsize=(4.2, 3)); plt.bar(["before", "after", "target"], [pred_w, new_pred_w, r_obs_w],
        color=["gray", "seagreen", "black"]); plt.ylabel("prediction")
plt.title("5: one SGD step moves toward the rating"); plt.show()
```
▶ What you'll see: a single step lifts the prediction from 2.48 to 3.73 — closer to the observed 5.

*Why it's done this way: the gradient tells us exactly which way each factor must move to reduce this cell's error; stepping opposite to it (descent) is the whole engine of learning.*

### 6. Training loop and convergence

Repeating that step over all observed cells, many times, is stochastic gradient descent. Watching the total loss fall confirms the factors are actually learning; when it flattens, they've captured the structure they can. Afterward, $P Q^\top$ **fills the blanks** as a side effect of having explained the observed cells.

```python
rng_w = np.random.default_rng(0)             # reproducible initialization.
P_w = 0.1 * rng_w.normal(size=(4, 2))         # small random user factors.
Q_w = 0.1 * rng_w.normal(size=(4, 2))         # small random item factors.
obs_w = list(zip(*np.where(R_w > 0)))          # list of observed (u,i) cells to train on.
print("training on", len(obs_w), "observed cells")  # Ω only.
```
▶ What you'll see: factors start as tiny random noise; training will shape them.

```python
losses_w = []                                 # record total loss each epoch.
for epoch_w in range(400):                    # many passes over the data.
    for (u_w, i_w) in obs_w:                   # one SGD step per observed cell.
        e = R_w[u_w, i_w] - P_w[u_w] @ Q_w[i_w]        # this cell's error.
        P_w[u_w] += 0.02 * (e * Q_w[i_w] - 0.05 * P_w[u_w])  # update user factor.
        Q_w[i_w] += 0.02 * (e * P_w[u_w] - 0.05 * Q_w[i_w])  # update item factor.
    tot = sum((R_w[u, i] - P_w[u] @ Q_w[i]) ** 2 for (u, i) in obs_w)  # squared error on Ω.
    losses_w.append(tot)                        # store for the curve.
print("loss start -> end:", round(losses_w[0], 3), "->", round(losses_w[-1], 4))  # goes down.
assert losses_w[-1] < losses_w[0]               # training reduced the loss.
```
▶ What you'll see: the total observed-error shrinks from a large value to nearly 0.

```python
plt.figure(figsize=(4.4, 3)); plt.plot(losses_w, color="purple")   # the learning curve.
plt.xlabel("epoch"); plt.ylabel("total squared error on Ω")
plt.title("6: SGD loss decreasing"); plt.show()
```
▶ What you'll see: a fast drop then a plateau — the signature of converged training.

```python
R_hat_w = P_w @ Q_w.T                          # reconstruction fills EVERY cell, blanks included.
print("Ava's predicted I2 (was blank):", round(R_hat_w[0, 2], 3))  # a real number now.
plt.figure(figsize=(4.2, 3.2)); plt.imshow(R_hat_w, cmap="viridis"); plt.colorbar(label="predicted")
plt.title("6: reconstruction P·Qᵀ fills the blanks"); plt.show()
```
▶ What you'll see: the two formerly-blank cells now carry sensible predicted ratings.

*Why it's done this way: SGD over observed cells is cheap and scales to millions of ratings; the low-rank factors it learns generalize to the blanks for free.*

### 7. Rank and regularization: the capacity dial

Two knobs control how much the model can express. **Rank** $k$ is the number of latent axes: too small and it can't fit the structure (underfit); large enough and it reconstructs the observed matrix exactly. We can see this cleanly with a truncated SVD, which gives the *best possible* rank-$k$ reconstruction. **Regularization** $\lambda$ is the opposing force: it shrinks factors so a high-capacity model still generalizes instead of memorizing noise — the same bias–complexity tradeoff as everywhere else in ML.

```python
R_full_w = np.where(R_w == 0, 1, R_w)          # fill the 2 blanks with a weak "1" to make a fully-observed demo matrix.
U_w, s_w, Vt_w = np.linalg.svd(R_full_w, full_matrices=False)  # SVD gives optimal low-rank pieces.
print("singular values:", np.round(s_w, 3))     # how much structure each axis carries.
```
▶ What you'll see: the first singular value dominates, the second is moderate, the rest are tiny — most structure lives in ~2 axes.

```python
ranks_w, errs_w = [1, 2, 4], []                 # reconstruct at increasing rank.
for k_w in ranks_w:                             # for each bottleneck width.
    Rk_w = U_w[:, :k_w] @ np.diag(s_w[:k_w]) @ Vt_w[:k_w, :]  # best rank-k reconstruction.
    errs_w.append(float(np.linalg.norm(R_full_w - Rk_w)))     # Frobenius reconstruction error.
print("rank errors:", [round(e, 3) for e in errs_w])  # ~7.141, ~1.414, ~0.000.
assert abs(errs_w[0] - 7.141) < 1e-2 and abs(errs_w[1] - 1.414) < 1e-2 and errs_w[2] < 1e-6  # lesson numbers.
```
▶ What you'll see: error falls sharply from rank 1 → 2, and hits ~0 at rank 4 (full rank) — exactly the "few reusable causes" claim.

```python
plt.figure(figsize=(4.2, 3)); plt.plot(ranks_w, errs_w, marker="o", color="darkorange")
plt.xlabel("rank k"); plt.ylabel("reconstruction error"); plt.xticks(ranks_w)
plt.title("7: error drops as the bottleneck widens"); plt.show()
```
▶ What you'll see: a steep decline then zero — more latent axes = more faithful reconstruction, at the cost of generalization.

*Why it's done this way: rank sets how much the model *can* express and λ restrains how much it *should*; tuning the two is how MF stays between underfitting and memorizing.*

#### B5. Measure one prediction error

**Goal.** Compute the residual e = r − p·q for one observed cell, because SGD learns by reacting to errors on known ratings. We build it in 2 steps.

```python
p_b5 = np.array([0.8, 0.2]) # choose a current user factor before learning.
q_b5 = np.array([3.0, 0.4]) # choose a current item factor before learning.
r_b5 = 5.0 # set the observed rating for this user-item pair.
print("p:", p_b5, "q:", q_b5, "rating:", r_b5) # inspect the training example.
```

```python
pred_b5 = float(p_b5 @ q_b5) # compute the current predicted rating.
err_b5 = r_b5 - pred_b5 # compute the signed residual that drives updates.
print("prediction:", round(pred_b5, 3), "error:", round(err_b5, 3)) # inspect the miss before learning.
plt.figure(figsize=(4, 3)) # create a diagnostic bar chart.
plt.bar(["observed r", "predicted p·q", "error r-p·q"], [r_b5, pred_b5, err_b5], color=["green", "orange", "red"]) # compare target, prediction, and residual.
```

#### E1. Train MF with observed-only SGD

**Goal.** Fit P and Q on only observed entries Ω, because blank cells are unknown rather than automatic zeros. We build it in 4 steps.

```python

```

```python
eta_e1 = 0.03 # choose a modest learning rate for stable SGD.
lam_e1 = 0.02 # choose a small regularization strength.
steps_e1 = 800 # choose enough passes for the tiny toy problem.

print("eta:", eta_e1, "lambda:", lam_e1, "steps:", steps_e1) # inspect training hyperparameters.
```

```python

    users_e1, items_e1 = np.where(mask_e1) # list observed coordinates for this pass.
    k_e1 = step_e1 % len(users_e1) # cycle deterministically through observed cells.
    u_e1 = users_e1[k_e1] # choose the current observed user.
    i_e1 = items_e1[k_e1] # choose the current observed item.
    pred_e1 = float(P_e1[u_e1] @ Q_e1[i_e1]) # predict the current observed rating.
    err_e1 = R_e1[u_e1, i_e1] - pred_e1 # compute the observed residual.
    old_p_e1 = P_e1[u_e1].copy() # save old p so q update uses simultaneous-style values.
    old_q_e1 = Q_e1[i_e1].copy() # save old q so p update uses simultaneous-style values.
```

#### A1. Sweep regularization strength

**Goal.** Compare train and validation RMSE across λ values, because too little regularization can overfit and too much can underfit. We build it in 5 steps.

```python
R_a1 = np.array([[5, 4, 0, 1], [4, 5, 0, 1], [1, 1, 5, 4], [0, 1, 4, 5]], dtype=float) # define the toy matrix.
val_cells_a1 = [(0, 1), (2, 3)] # choose two observed ratings to hold out.
train_mask_a1 = observed_mask(R_a1) # start from all observed entries.
for cell_a1 in val_cells_a1: # remove validation entries from training.
    train_mask_a1[cell_a1] = False # mark the current validation cell as not trained.
print("validation cells:", val_cells_a1) # inspect the held-out coordinates.
```

```python
lams_a1 = np.array([0.0, 0.01, 0.05, 0.2, 0.8]) # choose regularization strengths from low to high.
train_rmse_a1 = [] # prepare storage for training errors.
val_rmse_a1 = [] # prepare storage for validation errors.
print("lambda grid:", lams_a1) # inspect the sweep values.
```

```python
for lam_a1 in lams_a1: # train one model per lambda.
    rng_a1 = np.random.default_rng(10) # reset initialization so lambda is the changed variable.
    P_a1 = 0.1 * rng_a1.normal(size=(4, 2)) # initialize user factors.
    Q_a1 = 0.1 * rng_a1.normal(size=(4, 2)) # initialize item factors.
    for step_a1 in range(1800): # run observed-only SGD for this lambda.
        users_a1, items_a1 = np.where(train_mask_a1) # list training entries.
        k_a1 = step_a1 % len(users_a1) # cycle through entries deterministically.
        u_a1 = users_a1[k_a1] # select the current user.
        i_a1 = items_a1[k_a1] # select the current item.
        err_a1 = R_a1[u_a1, i_a1] - float(P_a1[u_a1] @ Q_a1[i_a1]) # compute residual.
        old_p_a1 = P_a1[u_a1].copy() # save old user vector.
        old_q_a1 = Q_a1[i_a1].copy() # save old item vector.
        P_a1[u_a1] = old_p_a1 + 0.03 * (err_a1 * old_q_a1 - lam_a1 * old_p_a1) # update user factors.
        Q_a1[i_a1] = old_q_a1 + 0.03 * (err_a1 * old_p_a1 - lam_a1 * old_q_a1) # update item factors.
    pred_a1 = predict(P_a1, Q_a1) # compute predictions for this trained model.
    train_rmse_a1.append(float(np.sqrt(np.mean(((R_a1 - pred_a1)[train_mask_a1]) ** 2)))) # store train RMSE.
    val_rmse_a1.append(float(np.sqrt(np.mean([(R_a1[c_a1] - pred_a1[c_a1]) ** 2 for c_a1 in val_cells_a1])))) # store validation RMSE.
print("train RMSE:", np.round(train_rmse_a1, 3)) # inspect training errors.
print("validation RMSE:", np.round(val_rmse_a1, 3)) # inspect validation errors.
```

```python
best_idx_a1 = int(np.argmin(val_rmse_a1)) # find the lambda with lowest validation RMSE.
best_lam_a1 = float(lams_a1[best_idx_a1]) # read the best lambda value.
print("best lambda:", best_lam_a1) # inspect the selected regularization strength.
```

```python
plt.figure(figsize=(5, 3)) # create the regularization sweep figure.
plt.plot(lams_a1, train_rmse_a1, marker="o", label="train RMSE") # plot training error by lambda.
plt.plot(lams_a1, val_rmse_a1, marker="o", label="validation RMSE") # plot validation error by lambda.
plt.axvline(best_lam_a1, color="red", linestyle="--", label="best λ") # mark the selected lambda.
plt.title("A1: regularization sweep") # title the U-curve plot.
plt.xlabel("λ") # label the regularization axis.
plt.ylabel("RMSE") # label the error axis.
plt.legend() # show curve labels.
plt.show() # display the line chart.
```
▶ What you'll see: training error usually rises with λ, while validation error can have a best middle value.

👀 Takeaway: λ is a capacity knob that should be tuned with validation data, not guessed from training loss alone.

#### A2. Compare learning rates

**Goal.** Show stable versus unstable SGD behavior, because the learning rate controls whether factor updates converge or overshoot. We build it in 4 steps.

```python
R_a2 = np.array([[5, 4, 0, 1], [4, 5, 0, 1], [1, 1, 5, 4], [0, 1, 4, 5]], dtype=float) # define the toy matrix.
mask_a2 = observed_mask(R_a2) # mark observed entries.
rates_a2 = [0.03, 0.5] # compare a stable and an intentionally too-large learning rate.
curves_a2 = [] # prepare storage for loss curves.
print("learning rates:", rates_a2) # inspect the rates being compared.
```

```python
for eta_a2 in rates_a2: # run one training loop per learning rate.
    rng_a2 = np.random.default_rng(20) # reset initialization for fair comparison.
    P_a2 = 0.1 * rng_a2.normal(size=(4, 2)) # initialize user factors.
    Q_a2 = 0.1 * rng_a2.normal(size=(4, 2)) # initialize item factors.
    losses_a2 = [] # store this learning rate's losses.
    for step_a2 in range(160): # run a short training sequence.
        users_a2, items_a2 = np.where(mask_a2) # list observed entries.
        k_a2 = step_a2 % len(users_a2) # cycle through entries.
        u_a2 = users_a2[k_a2] # choose user.
        i_a2 = items_a2[k_a2] # choose item.
        pred_cell_a2 = float(P_a2[u_a2] @ Q_a2[i_a2]) # compute current cell prediction.
        err_a2 = R_a2[u_a2, i_a2] - pred_cell_a2 # compute current residual.
        old_p_a2 = P_a2[u_a2].copy() # save old user vector.
        old_q_a2 = Q_a2[i_a2].copy() # save old item vector.
        P_a2[u_a2] = np.clip(old_p_a2 + eta_a2 * (err_a2 * old_q_a2 - 0.02 * old_p_a2), -20, 20) # update and clip p to keep the demo finite.
        Q_a2[i_a2] = np.clip(old_q_a2 + eta_a2 * (err_a2 * old_p_a2 - 0.02 * old_q_a2), -20, 20) # update and clip q to keep the demo finite.
        if step_a2 % 4 == 0: # record losses at a readable cadence.
            pred_all_a2 = predict(P_a2, Q_a2) # compute all predictions.
            losses_a2.append(float(np.mean(((R_a2 - pred_all_a2)[mask_a2]) ** 2))) # store observed mean squared error.
    curves_a2.append(losses_a2) # store the finished curve.
print("final losses:", [round(c[-1], 3) for c in curves_a2]) # inspect where each rate ended.
```

```python
safe_curve_a2 = np.array(curves_a2[0]) # convert the stable curve to an array.
large_curve_a2 = np.array(curves_a2[1]) # convert the high-rate curve to an array.

```

```python

plt.plot(safe_curve_a2, label="η=0.03 stable", color="teal") # plot the stable curve.

plt.yscale("log") # use log scale so both curves fit visibly.
plt.title("A2: learning rate controls SGD stability") # title the comparison plot.
plt.xlabel("recorded checkpoint") # label the checkpoint axis.
plt.ylabel("observed MSE, log scale") # label the loss axis.
plt.legend() # show curve labels.
plt.show() # display the line chart.
```
▶ What you'll see: the modest learning rate decreases loss, while the large one jumps and oscillates despite clipping.

👀 Takeaway: SGD step size must be large enough to learn but small enough not to overshoot the objective.
