# 22.5 — Beam Search

Beam search builds sequences without keeping the entire search tree. Instead of committing to one greedy prefix, it keeps the best `k` partial candidates at each depth, expands only those candidates, and deliberately forgets the rest. In this lesson, you will implement that compromise from scratch, inspect exactly which branches survive, and see why beam width and scoring rules change the final answer.

## 📖 Concept walkthrough — build each idea from scratch

Before the worked examples, we build beam search one idea at a time. Run each cell in order and read the printed intermediate values — the search frontier, pruning decisions, cumulative log-scores, and length-normalized scores are all shown directly. This walkthrough is self-contained and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays, sorting helpers, and small numerical checks.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
from collections import defaultdict  # group candidates by depth for tree plots.
np.random.seed(0)  # reproducibility for any small simulations.

TOKENS_w = ["A", "B"]  # keep the alphabet tiny so every branch can be inspected.
SCORES_w = {  # toy additive log-scores; larger is better, like less-negative log probability.
    "": {"A": 5.0, "B": 4.0},
    "A": {"A": 0.0, "B": 1.0},
    "B": {"A": 6.0, "B": 0.0},
    "AA": {"A": 0.0, "B": 0.0},
    "AB": {"A": 0.0, "B": 0.0},
    "BA": {"A": 0.0, "B": 0.0},
    "BB": {"A": 0.0, "B": 0.0},
}

def expand_w(prefix, score):  # create all one-token continuations from one partial sequence.
    return [(prefix + tok, score + SCORES_w.get(prefix, {tok: 0.0}).get(tok, 0.0)) for tok in TOKENS_w]

def draw_tree_w(levels, kept_by_depth, title):  # draw a small layered search tree with beam decisions.
    plt.figure(figsize=(6, 3.6))
    xs = defaultdict(int)
    positions = {}
    for depth, candidates in enumerate(levels):
        n = len(candidates)
        for j, (seq, score) in enumerate(candidates):
            x = j - (n - 1) / 2
            y = -depth
            positions[seq] = (x, y)
            kept = seq in kept_by_depth.get(depth, set())
            color = "seagreen" if kept else "lightgray"
            edge = "black" if kept else "gray"
            plt.scatter([x], [y], s=850, color=color, edgecolor=edge, zorder=3)
            label = "∅" if seq == "" else seq
            plt.text(x, y, f"{label}\n{score:.1f}", ha="center", va="center", fontsize=9)
            if seq:
                parent = seq[:-1]
                if parent in positions:
                    px, py = positions[parent]
                    plt.plot([px, x], [py, y], color="gray", linewidth=1, zorder=1)
    plt.title(title)
    plt.axis("off")
    plt.show()
```

### 1. The wide-frontier problem

Tree search grows fast because every partial sequence can branch into many successors. Exhaustive search is safe, but the frontier doubles every depth in this toy binary model. Beam search starts from this pain: if keeping every prefix is too expensive and keeping one prefix is too brittle, keep a small fixed number instead.

```python
levels_w = [[("", 0.0)]]  # depth 0 starts with the empty sequence.
for depth_w in range(3):  # expand every current prefix exhaustively.
    next_level_w = []
    for prefix_w, score_w in levels_w[-1]:
        next_level_w.extend(expand_w(prefix_w, score_w))
    levels_w.append(next_level_w)
print("frontier sizes by depth:", [len(x) for x in levels_w])
assert [len(x) for x in levels_w] == [1, 2, 4, 8]
```
▶ What you'll see: the number of partial candidates grows as 1, 2, 4, 8 even for a two-token alphabet.

```python
plt.figure(figsize=(4.5, 3))
plt.plot(range(len(levels_w)), [len(x) for x in levels_w], marker="o", color="crimson")
plt.title("1: exhaustive frontier growth")
plt.xlabel("depth")
plt.ylabel("number of partial sequences")
plt.xticks(range(len(levels_w)))
plt.show()
```
▶ What you'll see: frontier size rises exponentially with depth, which is exactly what beam search tries to cap.

*Why it's done this way: beam search is motivated by a memory budget; it accepts that some branches must be forgotten so the frontier stays small enough to continue decoding.*

### 2. Beam search keeps the top k at each layer

At depth `t`, beam search expands only the current beam `B_t`, sorts the successors by score, and keeps the best `k`. The retained set is still a frontier, but it is capped by width `k` rather than by the full branching factor raised to depth.

```python
beam_w = [("", 0.0)]  # current beam B_0.
width_w = 2  # keep two partial candidates at each layer.
kept_by_depth_w = {0: {""}}
levels_beam_w = [[("", 0.0)]]
for depth_w in range(2):
    candidates_w = []
    for prefix_w, score_w in beam_w:
        candidates_w.extend(expand_w(prefix_w, score_w))
    levels_beam_w.append(sorted(candidates_w, key=lambda x: x[0]))
    beam_w = sorted(candidates_w, key=lambda x: x[1], reverse=True)[:width_w]
    kept_by_depth_w[depth_w + 1] = {seq_w for seq_w, _ in beam_w}
    print(f"depth {depth_w + 1} kept:", beam_w)
assert kept_by_depth_w[1] == {"A", "B"}
assert kept_by_depth_w[2] == {"BA", "AB"}
```
▶ What you'll see: width 2 keeps both `A` and `B` at depth 1, then keeps `BA` and `AB` at depth 2.

```python
draw_tree_w(levels_beam_w, kept_by_depth_w, "2: kept beam branches vs pruned branches")
plt.show()  # Keep this visualization cell ending with an explicit show call.
```
▶ What you'll see: green nodes are retained beam entries; gray nodes are generated but pruned.

*Why it's done this way: sorting by the current score is the heuristic commitment; capping the sorted list at k is the memory constraint.*

### 3. Width 1 is greedy search in layered clothing

If the beam width is 1, the algorithm keeps exactly one prefix after every expansion. That is greedy search: it chooses the best immediate partial candidate and never lets an alternative branch stay alive for a later payoff.

```python
beam1_w = [("", 0.0)]
trace1_w = []
for depth_w in range(2):
    candidates_w = []
    for prefix_w, score_w in beam1_w:
        candidates_w.extend(expand_w(prefix_w, score_w))
    candidates_w = sorted(candidates_w, key=lambda x: x[1], reverse=True)
    trace1_w.append(candidates_w)
    beam1_w = candidates_w[:1]
    print(f"after depth {depth_w + 1}:", beam1_w)
assert beam1_w[0] == ("AB", 6.0)
```
▶ What you'll see: the search keeps `A` first because 5 beats 4, then finishes at `AB` with score 6.

```python
levels_greedy_w = [[("", 0.0)], trace1_w[0], trace1_w[1]]
kept_greedy_w = {0: {""}, 1: {"A"}, 2: {"AB"}}
draw_tree_w(levels_greedy_w, kept_greedy_w, "3: width 1 behaves like greedy search")
plt.show()  # Keep this visualization cell ending with an explicit show call.
```
▶ What you'll see: the `B` branch is pruned before its strong `BA` continuation can appear.

*Why it's done this way: width 1 is useful for showing the limiting case — beam search only differs from greedy when it keeps at least one backup candidate.*

### 4. Width 2 can preserve a delayed payoff

The branch `B` looks slightly worse at depth 1, but its successor `BA` receives a large second-step score. A width-2 beam preserves `B` long enough to discover that delayed payoff, so it can beat the greedy result.

```python
beam2_w = [("", 0.0)]
best_scores_w = []
for depth_w in range(2):
    candidates_w = []
    for prefix_w, score_w in beam2_w:
        candidates_w.extend(expand_w(prefix_w, score_w))
    beam2_w = sorted(candidates_w, key=lambda x: x[1], reverse=True)[:2]
    best_scores_w.append(beam2_w[0][1])
    print(f"depth {depth_w + 1} beam:", beam2_w)
assert beam2_w[0] == ("BA", 10.0)
```
▶ What you'll see: `BA` becomes the best sequence because the extra beam slot kept `B` alive.

```python
plt.figure(figsize=(4.6, 3))
plt.bar(["greedy width 1", "beam width 2"], [6.0, 10.0], color=["gray", "seagreen"])
plt.title("4: width 2 finds the delayed payoff")
plt.ylabel("final cumulative score")
plt.show()
```
▶ What you'll see: the wider beam reaches score 10, while greedy stops at score 6.

*Why it's done this way: the second beam slot is insurance against a locally weaker prefix whose future continuation is much better.*

### 5. Pruning is irreversible

Once a candidate is removed from the beam, later layers do not get to expand it. This is the central risk: beam search saves memory by discarding proof obligations along with states, so it is not guaranteed to recover the globally best path.

```python
all_depth2_w = sorted(levels_w[2], key=lambda x: x[1], reverse=True)  # exhaustive depth-2 candidates.
beam1_survivors_w = {"AB"}
pruned_w = [(seq_w, score_w) for seq_w, score_w in all_depth2_w if seq_w not in beam1_survivors_w]
print("exhaustive depth-2 candidates:", all_depth2_w)
print("not in width-1 beam:", pruned_w)
assert any(seq_w == "BA" and score_w == 10.0 for seq_w, score_w in pruned_w)
```
▶ What you'll see: `BA` is excellent globally, but it is unreachable after width-1 pruning removed `B` at depth 1.

```python
names_w = [seq_w for seq_w, _ in all_depth2_w]
scores_w = [score_w for _, score_w in all_depth2_w]
colors_w = ["seagreen" if seq_w in beam1_survivors_w else "lightgray" for seq_w in names_w]
plt.figure(figsize=(5, 3))
plt.bar(names_w, scores_w, color=colors_w, edgecolor="black")
plt.title("5: pruned branches can contain better futures")
plt.ylabel("cumulative score at depth 2")
plt.show()
```
▶ What you'll see: the gray `BA` bar is taller than the green survivor, revealing the cost of irreversible pruning.

*Why it's done this way: irreversible pruning is the price paid for bounded memory; increasing k reduces the risk but does not turn beam search into exhaustive proof.*

### 6. Length normalization changes what “best” means

Raw cumulative scores tend to favor candidates that collect more positive terms, while per-token averages favor compact high-quality candidates. For variable-length decoding, the scoring definition is not cosmetic — it decides which sequences survive pruning and which final output wins.

```python
seqs_len_w = ["AB", "BABAA"]
raw_scores_w = np.array([6.0, 9.0])
lengths_w = np.array([len(s) for s in seqs_len_w])
norm_scores_w = raw_scores_w / lengths_w
print("raw scores:", dict(zip(seqs_len_w, raw_scores_w)))
print("normalized scores:", dict(zip(seqs_len_w, np.round(norm_scores_w, 3))))
assert raw_scores_w[1] > raw_scores_w[0] and norm_scores_w[0] > norm_scores_w[1]
```
▶ What you'll see: the long sequence wins by raw score 9, while the short sequence wins by normalized score 3.0.

```python
x_w = np.arange(len(seqs_len_w))
plt.figure(figsize=(5, 3))
plt.bar(x_w - 0.18, raw_scores_w, width=0.36, label="raw cumulative", color="darkorange")
plt.bar(x_w + 0.18, norm_scores_w, width=0.36, label="score / length", color="royalblue")
plt.xticks(x_w, seqs_len_w)
plt.title("6: length normalization changes the winner")
plt.ylabel("score")
plt.legend()
plt.show()
```
▶ What you'll see: the winner flips depending on whether you compare raw totals or per-step averages.

*Why it's done this way: sequence models must choose a scoring rule that matches the task; otherwise beam search may optimize length instead of quality.*

### 7. Beam width is a quality–cost knob

A larger beam keeps more alternatives and usually improves the chance of finding a high-scoring sequence, but it also expands more successors. The retained frontier is capped by `k`, while each layer can still generate up to `k × branching_factor` candidates before pruning.

```python
widths_w = np.array([1, 2, 3, 4])
quality_w = []
generated_w = []
for width_w in widths_w:
    beam_w = [("", 0.0)]
    gen_count_w = 0
    for depth_w in range(2):
        candidates_w = []
        for prefix_w, score_w in beam_w:
            new_w = expand_w(prefix_w, score_w)
            candidates_w.extend(new_w)
            gen_count_w += len(new_w)
        beam_w = sorted(candidates_w, key=lambda x: x[1], reverse=True)[:width_w]
    quality_w.append(beam_w[0][1])
    generated_w.append(gen_count_w)
print("best score by width:", dict(zip(widths_w, quality_w)))
print("generated successors:", dict(zip(widths_w, generated_w)))
assert quality_w[0] == 6.0 and quality_w[1] == 10.0
```
▶ What you'll see: width 2 improves quality over width 1, but it also generates more candidates.

```python
fig, ax1 = plt.subplots(figsize=(5, 3))
ax1.plot(widths_w, quality_w, marker="o", color="seagreen", label="best score")
ax1.set_xlabel("beam width k")
ax1.set_ylabel("best final score", color="seagreen")
ax2 = ax1.twinx()
ax2.plot(widths_w, generated_w, marker="s", color="crimson", label="generated")
ax2.set_ylabel("successors generated", color="crimson")
plt.title("7: beam width trades quality for work")
plt.show()
```
▶ What you'll see: score improves early, while generated work keeps rising with beam width.

*Why it's done this way: k is the main budget knob — it decides how many hypotheses survive and how much successor generation the decoder can afford.*

## 🛠️ Setup

```python
import numpy as np  # Import NumPy for arrays, sorting, and numerical checks.
import matplotlib.pyplot as plt  # Import Matplotlib for tree diagrams, score curves, and tradeoff plots.
from collections import defaultdict  # Import defaultdict for grouping nodes by depth in tree visualizations.
np.random.seed(0)  # Fix the global seed so every example is repeatable.

def toy_next(prefix):  # Define a tiny scored sequence model: returns token -> additive log-score.
    table = {"": {"A": 5.0, "B": 4.0}, "A": {"A": 0.0, "B": 1.0}, "B": {"A": 6.0, "B": 0.0}}
    return table.get(prefix, {"A": 0.0, "B": 0.0})  # Unlisted prefixes have neutral continuations for simple demos.

def expand(prefix, score):  # Expand one partial sequence by every available next token.
    return [(prefix + tok, score + add) for tok, add in toy_next(prefix).items()]  # Return new prefixes with cumulative scores.

def beam_search(width, depth, normalize=False):  # Run plain beam search over the toy model.
    beam = [("", 0.0)]  # Start from the empty prefix with score 0.
    history = [[("", 0.0)]]  # Store kept beams by depth for plotting and debugging.
    generated = 0  # Count successors generated before pruning.
    for _ in range(depth):  # Repeat one expansion per layer.
        candidates = []  # Store all successors of the current beam.
        for prefix, score in beam:  # Expand each retained prefix.
            new_items = expand(prefix, score)  # Generate successors from the toy model.
            candidates.extend(new_items)  # Add them to the candidate pool.
            generated += len(new_items)  # Account for pre-pruning work.
        key = (lambda item: item[1] / max(1, len(item[0]))) if normalize else (lambda item: item[1])  # Choose raw or normalized ranking.
        beam = sorted(candidates, key=key, reverse=True)[:width]  # Keep the top-k candidates by the selected score.
        history.append(beam.copy())  # Save the retained beam at this depth.
    return beam, history, generated  # Return final beam, per-depth beams, and work count.

def plot_candidates(names, scores, kept, title):  # Draw kept and pruned candidates as a relevant score bar chart.
    colors = ["seagreen" if name in kept else "lightgray" for name in names]  # Highlight kept beam entries.
    plt.figure(figsize=(5, 3))  # Create a compact figure for notebook readability.
    plt.bar(names, scores, color=colors, edgecolor="black")  # Plot scores for each candidate.
    plt.title(title)  # Describe the beam-search decision being visualized.
    plt.ylabel("cumulative score")  # Scores are cumulative additive log-scores in the toy model.
    plt.show()  # Display the plot.

def plot_layered_tree(levels, kept_by_depth, title):  # Draw a small search tree with kept/pruned highlighting.
    plt.figure(figsize=(6, 3.5))  # Create a readable layered tree figure.
    positions = {}  # Store node positions so child edges can point to parents.
    for depth, nodes in enumerate(levels):  # Visit each depth layer.
        n = len(nodes)  # Count nodes at this depth.
        for j, (seq, score) in enumerate(nodes):  # Draw each candidate node.
            x = j - (n - 1) / 2  # Spread nodes horizontally around zero.
            y = -depth  # Put deeper nodes lower in the plot.
            positions[seq] = (x, y)  # Store position for children.
            kept = seq in kept_by_depth.get(depth, set())  # Check whether beam kept this node.
            color = "seagreen" if kept else "lightgray"  # Green means kept; gray means pruned/generated only.
            plt.scatter([x], [y], s=780, color=color, edgecolor="black", zorder=3)  # Draw the node.
            plt.text(x, y, f"{seq or '∅'}\n{score:.1f}", ha="center", va="center", fontsize=9)  # Label sequence and score.
            if seq and seq[:-1] in positions:  # Draw an edge to the parent if it exists.
                px, py = positions[seq[:-1]]  # Parent position.
                plt.plot([px, x], [py, y], color="gray", linewidth=1, zorder=1)  # Parent-child edge.
    plt.title(title)  # Title the tree diagram.
    plt.axis("off")  # Hide axes because node positions are structural, not numerical.
    plt.show()  # Display the plot.
```

## 🟢 Basics

#### B1. Expand the start state

**Goal.** Generate the first layer of candidates, because beam search begins by scoring all one-token continuations from the empty prefix. We build it in 2 steps.

```python
start_b1 = ("", 0.0)  # Define the empty prefix and its cumulative score.
first_b1 = expand(start_b1[0], start_b1[1])  # Expand the empty prefix into one-token candidates.
print("first candidates:", first_b1)  # Inspect the two possible first tokens and their scores.
assert first_b1 == [("A", 5.0), ("B", 4.0)]  # Verify the toy model's start scores.
```

```python
names_b1 = [seq for seq, _ in first_b1]  # Extract candidate labels for plotting.
scores_b1 = [score for _, score in first_b1]  # Extract cumulative scores for plotting.
plot_candidates(names_b1, scores_b1, {"A", "B"}, "B1: first-layer candidates")  # Visualize the scored frontier.
plt.show()  # Keep this visualization cell ending with an explicit show call.
```
▶ What you'll see: both `A` and `B` are available, with `A` slightly ahead at the first layer.

👀 Takeaway: beam search works with partial candidates and their cumulative scores, not just completed outputs.

#### B2. Keep the top-1 beam

**Goal.** Apply width `k=1` after the first expansion, because the smallest beam keeps only the best current prefix. We build it in 2 steps.

👀 Takeaway: width 1 is greedy because every layer has exactly one survivor.

#### B3. Keep the top-2 beam

**Goal.** Apply width `k=2`, because a wider beam preserves a backup prefix instead of committing immediately. We build it in 2 steps.

```python
candidates_b3 = expand("", 0.0)  # Generate the same first layer.
```

▶ What you'll see: both first-step candidates remain green, which allows both subtrees to be expanded next.

👀 Takeaway: the beam width is the number of partial hypotheses allowed to stay alive.

#### B4. Expand a retained beam

**Goal.** Expand every prefix inside the current beam, because the next candidate pool is made from successors of survivors only. We build it in 3 steps.

```python
beam_b4 = [("A", 5.0), ("B", 4.0)]  # Start from the width-2 beam after depth 1.
print("current beam:", beam_b4)  # Inspect the retained prefixes before expansion.
```

```python
candidates_b4 = []  # Store all successors of retained prefixes.
for prefix_b4, score_b4 in beam_b4:  # Expand both survivors.
```

```python
names_b4 = [s for s, _ in sorted(candidates_b4)]  # Extract labels in readable order.
```

▶ What you'll see: four depth-2 candidates appear because width 2 still branches before pruning.

👀 Takeaway: the beam caps retained memory, but successor generation can still be `k × branching_factor` per layer.

#### B6. Prune to beam width

**Goal.** Keep only the top `k` candidates after sorting, because pruning is the step that enforces the memory budget. We build it in 2 steps.

```python
width_b6 = 2  # Choose a beam width of two.
sorted_b6 = [("BA", 10.0), ("AB", 6.0), ("AA", 5.0), ("BB", 4.0)]  # Use candidates already sorted by score.
beam_b6 = sorted_b6[:width_b6]  # Keep the first k entries and discard the rest.
print("new beam:", beam_b6)  # Inspect the retained depth-2 beam.
assert {s for s, _ in beam_b6} == {"BA", "AB"}  # Verify the top two survive.
```

```python
plot_candidates([s for s, _ in sorted_b6], [v for _, v in sorted_b6], {s for s, _ in beam_b6}, "B6: prune to width 2")  # Visualize retained vs pruned candidates.
plt.show()  # Keep this visualization cell ending with an explicit show call.
```
▶ What you'll see: `BA` and `AB` remain green; `AA` and `BB` are gray and will never be expanded.

👀 Takeaway: beam pruning is simple top-k selection, but its consequences are permanent.

```python
    if prefix == "B" * payoff_depth:  # Delayed payoff appears only after staying on B long enough.
        return {"A": 8.0, "B": 0.0}
    return {"A": 1.0, "B": 1.0}  # Otherwise both continuations look ordinary.
print("model starts:", delayed_model_a5("", 3))  # Inspect start scores.
```

```python
def delayed_search_a5(width, payoff_depth, total_depth):  # Run beam search on the delayed-payoff model.
    beam_a5 = [("", 0.0)]  # Start from empty prefix.
    for _ in range(total_depth):  # Decode a fixed number of layers.
        cand_a5 = []  # Candidate pool.
        for prefix_a5, score_a5 in beam_a5:  # Expand retained prefixes.
            for tok_a5, add_a5 in delayed_model_a5(prefix_a5, payoff_depth).items():  # Get next-token scores.
                cand_a5.append((prefix_a5 + tok_a5, score_a5 + add_a5))  # Add successor.
        beam_a5 = sorted(cand_a5, key=lambda x: x[1], reverse=True)[:width]  # Keep top k.
    return beam_a5[0]  # Return best final sequence.
```
