# 16.8 — Retrieval Evaluation

Retrieval evaluation turns ranked search results into numbers that match what users actually see. In this lesson, we build precision@k, recall@k, average precision, MAP, reciprocal rank, MRR, DCG, and nDCG from scratch with tiny judged result lists, so every denominator, cutoff, and discount is visible.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build retrieval evaluation one idea at a time. Run each cell in order and read the printed intermediate values — every piece of math is spelled out so rank, relevance, and cutoff choices never feel like a black box. This walkthrough is self-contained and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays, sorting, cumulative sums, and metric arithmetic.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
np.random.seed(0)  # reproducibility for any random demos.
```

### 1. Ranked lists and relevance judgments

A retriever returns an ordered list, not a class label. We therefore start with two objects: a ranking (the documents shown from top to bottom) and qrels (which documents are judged relevant for the query). Turning the ranking into a relevance vector gives us the metric input: `1` when a shown document is relevant, `0` otherwise.

```python
ranking_w = np.array(["d3", "d8", "d2", "d5", "d1"])  # returned order: rank 1 through rank 5.
relevant_w = {"d3", "d2", "d5"}  # binary qrels for this query.
rel_w = np.array([1 if doc in relevant_w else 0 for doc in ranking_w])  # relevance at each rank.
print("ranking:", ranking_w)
print("relevance vector:", rel_w)
assert rel_w.tolist() == [1, 0, 1, 1, 0]
```
▶ What you'll see: the returned list becomes `[1, 0, 1, 1, 0]`, meaning the second result is the only early mistake.

```python
plt.figure(figsize=(5, 2.5))
plt.bar(np.arange(1, len(rel_w) + 1), rel_w, color=["seagreen" if x else "lightgray" for x in rel_w])
plt.xticks(np.arange(1, len(rel_w) + 1), ranking_w)
plt.ylim(0, 1.2); plt.xlabel("rank"); plt.ylabel("relevant?")
plt.title("1: judgments aligned to the ranked list"); plt.show()
```
▶ What you'll see: green bars show relevant documents, and their positions are what every later metric rewards or discounts.

*Why it's done this way:* retrieval metrics measure the visible prefix of a ranked list. The qrels live in document-id space, but the user experience lives in rank space, so the first mathematical move is to align judgments to positions.

### 2. Precision@k and recall@k

Precision@k asks how clean the top `k` results are. Recall@k asks how much of the known relevant set the top `k` recovered. With binary relevance $rel_i$, the formulas are $P@k=\frac{1}{k}\sum_{i=1}^{k}rel_i$ and $R@k=\frac{\sum_{i=1}^{k}rel_i}{\text{\# relevant documents}}$.

```python
k_w = 3
hits_at_k_w = int(rel_w[:k_w].sum())
p_at_3_w = hits_at_k_w / k_w
r_at_3_w = hits_at_k_w / len(relevant_w)
print("hits@3:", hits_at_k_w)
print("P@3:", round(p_at_3_w, 3), "R@3:", round(r_at_3_w, 3))
assert round(p_at_3_w, 3) == 0.667 and round(r_at_3_w, 3) == 0.667
```
▶ What you'll see: two of the top three are relevant, so both precision@3 and recall@3 are 0.667 in this toy query.

```python
ks_w = np.arange(1, len(rel_w) + 1)
prec_curve_w = np.cumsum(rel_w) / ks_w
rec_curve_w = np.cumsum(rel_w) / len(relevant_w)
print("P@k:", np.round(prec_curve_w, 3))
print("R@k:", np.round(rec_curve_w, 3))
```
▶ What you'll see: precision can go down when nonrelevant results enter, while recall never decreases.

```python
plt.figure(figsize=(5, 3))
plt.plot(ks_w, prec_curve_w, marker="o", label="precision@k")
plt.plot(ks_w, rec_curve_w, marker="s", label="recall@k")
plt.xlabel("cutoff k"); plt.ylim(0, 1.05); plt.xticks(ks_w)
plt.title("2: precision-recall as the viewing window grows"); plt.legend(); plt.show()
```
▶ What you'll see: look for precision dipping at rank 2 and recall stepping upward only when a relevant document appears.

*Why it's done this way:* the precision denominator is the display budget `k`, so it punishes clutter in the visible page. The recall denominator is the number of relevant documents, so it measures completeness. A cutoff is therefore a product decision: `@3` and `@100` answer different questions.

### 3. Average precision and MAP

Average precision (AP) averages precision only at ranks where a new relevant document is found. Mean average precision (MAP) then averages AP across queries. This rewards systems that retrieve every relevant document early, not merely somewhere in a long list.

```python
hit_positions_w = np.where(rel_w == 1)[0]
prec_at_hits_w = prec_curve_w[hit_positions_w]
ap_w = float(prec_at_hits_w.sum() / len(relevant_w))
print("hit ranks:", hit_positions_w + 1)
print("precision at hits:", np.round(prec_at_hits_w, 3))
print("AP:", round(ap_w, 3))
assert round(ap_w, 3) == 0.806
```
▶ What you'll see: AP averages 1.000 at rank 1, 0.667 at rank 3, and 0.750 at rank 4.

```python
rels_many_w = [np.array([1, 0, 1, 1, 0]), np.array([0, 1, 0, 0]), np.array([1, 1, 0])]
totals_many_w = np.array([3, 2, 2])
ap_values_w = []
for rel_one_w, total_one_w in zip(rels_many_w, totals_many_w):
    p_curve_one_w = np.cumsum(rel_one_w) / np.arange(1, len(rel_one_w) + 1)
    ap_one_w = float((p_curve_one_w * rel_one_w).sum() / total_one_w)
    ap_values_w.append(ap_one_w)
map_w = float(np.mean(ap_values_w))
print("AP values:", np.round(ap_values_w, 3))
print("MAP:", round(map_w, 3))
assert round(map_w, 3) == 0.685
```
▶ What you'll see: one query can be strong while another is weak; MAP summarizes the query set mean.

```python
plt.figure(figsize=(5, 3))
plt.bar(["q1", "q2", "q3"], ap_values_w, color="steelblue")
plt.axhline(map_w, color="crimson", linestyle="--", label=f"MAP={map_w:.3f}")
plt.ylim(0, 1.05); plt.ylabel("average precision"); plt.title("3: AP per query and MAP"); plt.legend(); plt.show()
```
▶ What you'll see: the dashed MAP line hides variation, so always inspect per-query or slice behavior too.

*Why it's done this way:* AP uses precision at hit positions because each relevant document should arrive after as little junk as possible. Dividing by the total number of relevant documents also penalizes missing relevant documents that never appear in the ranking.

### 4. Reciprocal rank and MRR

Reciprocal rank focuses only on the first relevant result. For a query whose first hit is at rank $r$, $RR=1/r$; if there is no hit, it is 0. MRR averages that value across queries, which makes it ideal for tasks where one good answer near the top is enough.

```python
first_hit_w = int(np.where(rel_w == 1)[0][0] + 1) if np.any(rel_w == 1) else 0
rr_w = 1 / first_hit_w if first_hit_w else 0.0
print("first relevant rank:", first_hit_w)
print("RR:", round(rr_w, 3))
assert rr_w == 1.0
```
▶ What you'll see: because the first result is relevant, reciprocal rank is perfect even though the list still has mistakes.

```python
rels_rr_w = [np.array([1, 0, 1]), np.array([0, 0, 1]), np.array([0, 0, 0]), np.array([0, 1, 1])]
rrs_w = []
for rel_one_w in rels_rr_w:
    hits_w = np.where(rel_one_w == 1)[0]
    rrs_w.append(0.0 if len(hits_w) == 0 else 1 / float(hits_w[0] + 1))
mrr_w = float(np.mean(rrs_w))
print("RR values:", np.round(rrs_w, 3))
print("MRR:", round(mrr_w, 3))
assert round(mrr_w, 3) == 0.458
```
▶ What you'll see: a first hit at rank 3 contributes 0.333, no hit contributes 0, and MRR averages those user experiences.

```python
plt.figure(figsize=(5, 3))
plt.bar(["q1", "q2", "q3", "q4"], rrs_w, color="darkorange")
plt.axhline(mrr_w, color="black", linestyle="--", label=f"MRR={mrr_w:.3f}")
plt.ylim(0, 1.05); plt.ylabel("reciprocal rank"); plt.title("4: first-hit quality"); plt.legend(); plt.show()
```
▶ What you'll see: MRR is dominated by where the first relevant result appears, not by later recall.

*Why it's done this way:* in navigational search, QA, or autocomplete, the user may stop at the first correct result. Reciprocal rank encodes that stopping behavior with a steep penalty for pushing the first hit down.

### 5. DCG and nDCG

Discounted cumulative gain lets relevance be graded, not just binary. At rank $i$, the gain is often $2^{rel_i}-1$, and the discount is $\log_2(i+1)$, so early high-grade documents matter most. nDCG divides DCG by the ideal DCG for the same judgments, giving a 0-to-1 score.

```python
graded_w = np.array([3, 0, 2, 1, 0])  # relevance grades in ranked order.
ranks_w = np.arange(1, len(graded_w) + 1)
gains_w = 2 ** graded_w - 1
discounts_w = np.log2(ranks_w + 1)
dcg_w = float(np.sum(gains_w / discounts_w))
print("gains:", gains_w)
print("discounts:", np.round(discounts_w, 3))
print("DCG@5:", round(dcg_w, 3))
assert round(dcg_w, 3) == 8.931
```
▶ What you'll see: the grade-3 document at rank 1 contributes 7 by itself because gain grows exponentially with grade.

```python
ideal_w = np.sort(graded_w)[::-1]
idcg_w = float(np.sum((2 ** ideal_w - 1) / discounts_w))
ndcg_w = dcg_w / idcg_w if idcg_w > 0 else 0.0
print("ideal grades:", ideal_w)
print("IDCG@5:", round(idcg_w, 3), "nDCG@5:", round(ndcg_w, 3))
assert round(ndcg_w, 3) == 0.951
```
▶ What you'll see: the score is high but not perfect because grade 2 was delayed behind a nonrelevant result.

```python
plt.figure(figsize=(5, 3))
plt.bar(ranks_w - 0.15, gains_w / discounts_w, width=0.3, label="actual", color="slateblue")
plt.bar(ranks_w + 0.15, (2 ** ideal_w - 1) / discounts_w, width=0.3, label="ideal", color="lightgray")
plt.xlabel("rank"); plt.ylabel("discounted gain"); plt.title("5: DCG compared with ideal DCG"); plt.legend(); plt.show()
```
▶ What you'll see: compare each actual bar to the ideal bar at the same rank; the gap is the ranking loss nDCG normalizes.

*Why it's done this way:* logarithmic discount assumes lower ranks are still useful but progressively less visible. Normalization by IDCG makes queries with different numbers and grades of relevant documents comparable.

### 6. Cutoffs, incomplete judgments, and slices

A metric is never just a formula; it is also a cutoff, a judgment policy, and an averaging choice. Treating unjudged documents as nonrelevant may be practical, but it can punish good documents that were never labeled. Mean scores can also hide failures on important query slices.

```python
ranking_slice_w = np.array(["d9", "d3", "d2", "d7", "d5"])
judged_relevant_w = {"d3", "d2", "d5"}
judged_nonrel_w = {"d7"}
rel_unjudged_zero_w = np.array([1 if d in judged_relevant_w else 0 for d in ranking_slice_w])
judged_mask_w = np.array([d in judged_relevant_w or d in judged_nonrel_w for d in ranking_slice_w])
print("ranking:", ranking_slice_w)
print("unjudged treated as 0:", rel_unjudged_zero_w)
print("judged mask:", judged_mask_w.astype(int))
```
▶ What you'll see: `d9` is unjudged, so a naive metric treats it like a bad result even though we do not know.

```python
slice_names_w = np.array(["head", "tail", "exact-id"])
slice_map_w = np.array([0.82, 0.41, 0.95])
overall_w = float(np.mean(slice_map_w))
print("slice MAP:", dict(zip(slice_names_w, np.round(slice_map_w, 2))))
print("overall MAP:", round(overall_w, 3))
assert round(overall_w, 3) == 0.727
```
▶ What you'll see: a respectable overall mean can coexist with poor tail-query quality.

```python
plt.figure(figsize=(5, 3))
plt.bar(slice_names_w, slice_map_w, color=["seagreen", "crimson", "steelblue"])
plt.axhline(overall_w, color="black", linestyle="--", label="overall")
plt.ylim(0, 1.05); plt.ylabel("MAP"); plt.title("6: mean metrics can hide slice failures"); plt.legend(); plt.show()
```
▶ What you'll see: the tail bar sits far below the overall line; that is the failure a single mean would hide.

*Why it's done this way:* evaluation should mirror the product window and the label collection process. Cutoff controls what the user sees, unjudged handling controls what evidence means, and slice reporting prevents a dominant query type from masking regressions elsewhere.

## 🛠️ Setup

```python
import numpy as np  # Import NumPy for arrays, cumulative sums, sorting, and metric checks.
import matplotlib.pyplot as plt  # Import Matplotlib for precision-recall curves, bars, and metric diagnostics.
np.random.seed(0)  # Fix the random seed so every example is reproducible.

def binary_relevance(ranking, relevant):  # Convert a ranked document list into 1/0 relevance labels.
    return np.array([1 if doc in relevant else 0 for doc in ranking], dtype=int)  # Mark relevant hits as 1.

def precision_at_k(rel, k):  # Compute P@k from a binary relevance vector.
    rel = np.asarray(rel, dtype=float)  # Ensure numeric arithmetic.
    return float(np.sum(rel[:k]) / k)  # Divide top-k hits by the display cutoff.

def recall_at_k(rel, k, total_relevant):  # Compute R@k from a binary relevance vector.
    return 0.0 if total_relevant == 0 else float(np.sum(rel[:k]) / total_relevant)  # Divide hits by all known relevant docs.

def average_precision(rel, total_relevant=None):  # Compute AP from scratch.
    rel = np.asarray(rel, dtype=float)  # Convert to numeric vector.
    total = int(np.sum(rel)) if total_relevant is None else int(total_relevant)  # Use known relevant count.
    if total == 0:  # Handle queries with no relevant labels.
        return 0.0  # Define AP as 0 in this teaching notebook.
    precisions = np.cumsum(rel) / np.arange(1, len(rel) + 1)  # Precision at every rank.
    return float(np.sum(precisions * rel) / total)  # Average precision at relevant ranks, including missed relevant docs.

def reciprocal_rank(rel):  # Compute first-hit reciprocal rank.
    hits = np.where(np.asarray(rel) > 0)[0]  # Find ranks with relevant documents.
    return 0.0 if len(hits) == 0 else float(1 / (hits[0] + 1))  # Return 1/rank for the first hit.

def dcg_at_k(grades, k):  # Compute discounted cumulative gain at k.
    grades = np.asarray(grades, dtype=float)[:k]  # Keep the visible prefix.
    ranks = np.arange(1, len(grades) + 1)  # Rank numbers start at 1.
    gains = 2 ** grades - 1  # Exponential gain rewards higher relevance grades.
    return float(np.sum(gains / np.log2(ranks + 1)))  # Log discount reduces later ranks.

def ndcg_at_k(grades, k):  # Compute normalized DCG at k.
    actual = dcg_at_k(grades, k)  # DCG for the returned order.
    ideal = dcg_at_k(np.sort(np.asarray(grades))[::-1], k)  # DCG for the best possible order.
    return 0.0 if ideal == 0 else float(actual / ideal)  # Normalize to [0, 1] when possible.
```

## 🟢 Basics (warm-up)

### Basic 1 — Turn qrels into a relevance vector

**Goal.** Align document judgments with returned rank positions, because every retrieval metric starts from relevance by rank.

```python
ranking_b1 = np.array(["d3", "d8", "d2", "d5", "d1"])  # Define the returned order.
relevant_b1 = {"d3", "d2", "d5"}  # Define binary qrels inline.
rel_b1 = binary_relevance(ranking_b1, relevant_b1)  # Convert ids to 1/0 labels.
print("rel_b1:", rel_b1)  # Inspect the metric input vector.
assert rel_b1.tolist() == [1, 0, 1, 1, 0]  # Verify the canonical toy list.
```
▶ What you'll see: the ranked list becomes a compact binary relevance vector.

```python
plt.figure(figsize=(5, 2.5))  # Create a compact rank-position plot.
plt.bar(np.arange(1, 6), rel_b1, color=["green" if x else "lightgray" for x in rel_b1])  # Show hits and misses.

plt.title("Basic 1: relevance by rank"); plt.ylim(0, 1.2); plt.show()  # Display the visualization.
```
▶ What you'll see: relevant documents appear at ranks 1, 3, and 4.

👀 Takeaway: document-level qrels must be aligned to rank positions before metric formulas apply.

### Basic 2 — Count hits at a cutoff

**Goal.** Count relevant documents in the visible prefix, because precision and recall both begin with hits@k.

```python
rel_b2 = np.array([1, 0, 1, 1, 0])  # Recreate the toy relevance vector locally.
k_b2 = 3  # Choose a top-3 viewing window.
hits_b2 = int(np.sum(rel_b2[:k_b2]))  # Count relevant documents in the prefix.

```
▶ What you'll see: the top three contain two relevant documents.


▶ What you'll see: the visible window contains two hits and one miss.

### Basic 3 — Compute precision@k

**Goal.** Measure how clean the top-k page is, because users see only a limited number of results.


```python
plt.figure(figsize=(4, 2.5))  # Create a cutoff comparison plot.

```
▶ What you'll see: the top-three page is cleaner than the top-five page.

👀 Takeaway: precision@k divides by what was shown, so it penalizes nonrelevant results in the viewing window.

### Basic 4 — Compute recall@k

```python
plt.figure(figsize=(4, 2.5))  # Create a recall comparison plot.
```

### Basic 8 — Compute reciprocal rank

```python
plt.figure(figsize=(4, 2.5))  # Create a first-hit plot.
```

### Advanced 1 — Bootstrap confidence intervals for MAP

**Goal.** Estimate uncertainty by resampling queries, because small query sets make metric differences noisy.

```python
ap_a1 = np.array([0.82, 0.40, 0.91, 0.55, 0.20, 0.75, 0.62, 0.48])  # Define per-query AP values.

boot_a1 = []  # Store bootstrap MAP values.
for _ in range(1000):  # Resample the query set many times.
    sample_a1 = rng_a1.choice(ap_a1, size=len(ap_a1), replace=True)  # Sample queries with replacement.
    boot_a1.append(float(np.mean(sample_a1)))  # Store the resampled mean.
ci_a1 = np.percentile(boot_a1, [2.5, 97.5])  # Compute a simple percentile interval.

```

### Advanced 2 — Compare systems with a paired randomization test

**Goal.** Test a per-query metric delta, because retrieval systems should be compared on the same queries, not independent averages.

```python
ap_A_a2 = np.array([0.80, 0.42, 0.90, 0.50, 0.30, 0.72])  # System A AP per query.
ap_B_a2 = np.array([0.75, 0.45, 0.82, 0.55, 0.25, 0.70])  # System B AP on the same queries.
delta_obs_a2 = float(np.mean(ap_A_a2 - ap_B_a2))  # Observed paired mean difference.
print("observed MAP delta A-B:", round(delta_obs_a2, 3))  # Inspect the system delta.
assert round(delta_obs_a2, 3) == 0.020  # Verify the paired difference.
```
▶ What you'll see: A is ahead by a small average amount on these paired queries.

```python
rng_a2 = np.random.default_rng(1)  # Create reproducible random signs.
diffs_a2 = ap_A_a2 - ap_B_a2  # Store paired differences.
null_a2 = []  # Store randomized deltas under no system identity.
for _ in range(2000):  # Run sign-flip randomization.
    signs_a2 = rng_a2.choice([-1, 1], size=len(diffs_a2))  # Randomly swap A/B within each query.
    null_a2.append(float(np.mean(signs_a2 * diffs_a2)))  # Store null delta.
p_value_a2 = float(np.mean(np.abs(null_a2) >= abs(delta_obs_a2)))  # Two-sided p-value.
print("randomization p-value:", round(p_value_a2, 3))  # Inspect evidence strength.
assert 0 <= p_value_a2 <= 1  # Verify it is a probability.
```
▶ What you'll see: a small p-value would mean the paired delta is hard to explain by random signs.

```python
plt.figure(figsize=(5, 3))  # Create a null distribution plot.
```

▶ What you'll see: compare the red observed line to the gray null distribution.

### Advanced 4 — Optimize a hybrid weight using nDCG
