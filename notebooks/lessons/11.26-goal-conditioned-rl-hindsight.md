# 11.26 — Goal-Conditioned RL & Hindsight

Goal-conditioned reinforcement learning teaches one policy to answer a family of questions: "what should I do if this is the goal?" Hindsight Experience Replay (HER) then makes sparse-reward data less wasteful by relabeling failed attempts as successful attempts for goals the agent actually reached.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build goal-conditioned RL and hindsight replay one idea at a time. Run each cell in order and read the printed intermediate values — every piece of math is visible, including why relabeling a goal changes the reward target without changing the transition. This walkthrough is self-contained and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays, tables, and small simulations for goal-conditioned RL.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
np.random.seed(0)  # reproducibility for sampled actions and replay examples.
```

### 1. A goal is part of the state description

Ordinary tabular RL might learn one value for each physical state. Goal-conditioned RL learns a value for each `(state, goal)` pair, because the same position can be good for one goal and bad for another. In a one-dimensional grid, state `s=2` is finished when the goal is `2`, but still unfinished when the goal is `4`.

```python
states_w = np.arange(5)  # five grid positions: 0, 1, 2, 3, 4.
goals_w = np.arange(5)  # any position can be requested as the goal.
S_w, G_w = np.meshgrid(states_w, goals_w, indexing="ij")  # build all state-goal pairs.
distance_w = np.abs(S_w - G_w)  # shortest path length on this line world.
print("distance table rows=state cols=goal:\n", distance_w)  # inspect the task family.
```
▶ What you'll see: zeros lie on the diagonal because a state is solved only for the matching goal.

```python
plt.figure(figsize=(4.5, 3.2))  # make a compact heatmap.
plt.imshow(distance_w, cmap="magma_r", aspect="auto")  # lighter means closer to the requested goal.
plt.colorbar(label="|state - goal|")  # interpret colors as distances.
plt.xlabel("goal"); plt.ylabel("state")  # show that both axes matter.
plt.title("1: every goal changes what a state means"); plt.show()  # display the task table.
```
▶ What you'll see: each column is a different task, even though the physical grid is unchanged.

*Why it's done this way:* the policy must receive the goal because optimal action is not a function of state alone. At state 2, a policy for goal 0 should move left, while a policy for goal 4 should move right. Mathematically we replace `Q(s,a)` with `Q(s,g,a)`, which is a table with shape `|S| × |G| × |A|`; the extra goal axis is the price of representing many tasks with one learner.

### 2. Sparse goal rewards create mostly failed-looking data

A common goal-conditioned reward is `0` when the next state equals the goal and `-1` otherwise. That reward is sparse: until the agent reaches the exact requested goal, all transitions look equally bad. The signal is correct, but most random exploration produces long stretches of `-1`.

```python
def step_line_w(s_w, a_w, n_w=5):  # deterministic one-dimensional transition.
    return int(np.clip(s_w + a_w, 0, n_w - 1))  # actions are -1 or +1, clipped at walls.

def goal_reward_w(next_s_w, goal_w):  # sparse goal-achievement reward.
    return 0.0 if next_s_w == goal_w else -1.0  # solved transitions avoid the step penalty.

s0_w, goal_w = 0, 4  # start far from the requested goal.
actions_w = np.array([1, -1, 1, 1])  # an exploratory path that does not reach 4.
states_path_w = [s0_w]  # record visited states.
rewards_w = []  # record rewards under the original requested goal.
for a_w in actions_w:
    ns_w = step_line_w(states_path_w[-1], a_w)  # move in the line world.
    rewards_w.append(goal_reward_w(ns_w, goal_w))  # score the transition for goal 4.
    states_path_w.append(ns_w)  # append the new state.
print("visited states:", states_path_w)  # inspect the trajectory.
print("rewards for goal 4:", rewards_w)  # inspect sparse feedback.
```
▶ What you'll see: the agent visits `[0,1,0,1,2]` and receives `-1` at every step for goal 4.

```python
plt.figure(figsize=(5, 2.8))  # create a small trajectory plot.
plt.plot(states_path_w, marker="o", color="steelblue")  # show physical movement.
plt.axhline(goal_w, color="crimson", linestyle="--", label="requested goal 4")  # mark the goal.
plt.yticks(states_w); plt.xlabel("time"); plt.ylabel("state")  # label axes.
plt.title("2: exploration misses a sparse goal"); plt.legend(); plt.show()  # display.
```
▶ What you'll see: the path moves, but it never touches the requested goal line.

*Why it's done this way:* the sparse reward matches the real success criterion: only exact goal achievement should count as solved. The downside is variance. A transition from 1 to 2 is useful progress toward goal 4, but the immediate target `r + γ max_a Q(s',g,a)` still starts from `-1`, so early learning has little positive structure unless exploration actually hits goals.

### 3. Bellman backups are indexed by the goal

The one-step Q-learning target for a goal-conditioned table is

$$y = r(s,a,s',g) + \gamma \max_{a'} Q(s', g, a').$$

The physical transition `(s,a,s')` is the same no matter which goal we ask about, but the reward and bootstrap column depend on `g`. That is why replay can later reuse one transition with many goals.

```python
nS_w, nG_w, nA_w = 5, 5, 2  # states, goals, actions(left/right).
actions_list_w = np.array([-1, 1])  # action index 0 is left, index 1 is right.
Q_w = np.zeros((nS_w, nG_w, nA_w))  # Q[state, goal, action].
Q_w[3, 4] = np.array([-0.8, -0.2])  # near goal 4, moving right currently looks better.
s_w, a_idx_w, g_w = 2, 1, 4  # from state 2, choose right, with requested goal 4.
ns_w = step_line_w(s_w, actions_list_w[a_idx_w], nS_w)  # next state is 3.
r_w = goal_reward_w(ns_w, g_w)  # not at 4 yet, so reward is -1.
target_w = r_w + 0.9 * np.max(Q_w[ns_w, g_w])  # Bellman target for this goal.
print("transition:", (s_w, actions_list_w[a_idx_w], ns_w, "goal", g_w))  # inspect transition.
print("reward:", r_w, "target:", round(target_w, 3))  # inspect target.
assert round(target_w, 3) == -1.18  # -1 + 0.9*(-0.2).
```
▶ What you'll see: the target is `-1.18`, because the next state is still one step away but its best future estimate is `-0.2`.

```python
alpha_w = 0.5  # move halfway toward the target.
old_q_w = Q_w[s_w, g_w, a_idx_w]  # current estimate for this state-goal-action.
Q_w[s_w, g_w, a_idx_w] = old_q_w + alpha_w * (target_w - old_q_w)  # tabular Q update.
print("old Q:", old_q_w, "new Q:", round(Q_w[s_w, g_w, a_idx_w], 3))  # inspect the update.
assert round(Q_w[s_w, g_w, a_idx_w], 3) == -0.59  # halfway from 0 to -1.18.
```
▶ What you'll see: the table entry for `(state=2, goal=4, action=right)` moves from `0` to `-0.59`.

```python
plt.figure(figsize=(4.8, 3))  # visualize how the backup combines old value, target, and update.
plt.bar(["old Q", "target", "updated Q"], [old_q_w, target_w, Q_w[s_w, g_w, a_idx_w]], color=["gray", "crimson", "seagreen"])  # compare the three quantities.
plt.axhline(0, color="black", linewidth=0.6)  # mark the optimistic zero baseline.
plt.ylabel("value"); plt.title("3: Bellman backup for one goal slice"); plt.show()  # display the goal-indexed update.
```
▶ What you'll see: the updated Q value moves partway from the old estimate toward the target for goal 4.

*Why it's done this way:* bootstrapping uses the learner's own estimate of remaining consequence, so the update can propagate success backward before a full return is observed many times. The goal index matters twice: it chooses the reward definition and the slice `Q[:, g, :]` used for future value. Mixing goals in that slice would train the wrong task.

### 4. Hindsight relabeling turns achieved states into goals

HER keeps the same physical transitions but changes the goal label to something the trajectory actually achieved. If the original episode tried for goal 4 but ended at state 2, then transitions can be relabeled with goal 2. The final transition into state 2 becomes a success under the hindsight goal.

```python
achieved_goal_w = states_path_w[-1]  # HER can choose a future achieved state as the new goal.
her_rewards_w = []  # rewards after relabeling the same transitions with achieved_goal_w.
for t_w, a_w in enumerate(actions_w):
    next_state_w = states_path_w[t_w + 1]  # same next state as the original data.
    her_rewards_w.append(goal_reward_w(next_state_w, achieved_goal_w))  # reward under relabeled goal.
print("original goal:", goal_w, "hindsight goal:", achieved_goal_w)  # compare labels.
print("original rewards:", rewards_w)  # all failures for goal 4.
print("HER rewards:", her_rewards_w)  # final transition succeeds for goal 2.
assert her_rewards_w[-1] == 0.0  # the last next state equals the hindsight goal.
```
▶ What you'll see: the same path that failed at goal 4 contains a successful final transition for goal 2.

```python
plt.figure(figsize=(5, 2.8))  # create a compact relabeling plot.
plt.plot(states_path_w, marker="o", label="visited states", color="steelblue")  # same trajectory.
plt.axhline(goal_w, color="crimson", linestyle="--", label="original goal 4")  # missed goal.
plt.axhline(achieved_goal_w, color="seagreen", linestyle=":", label="hindsight goal 2")  # achieved goal.
plt.yticks(states_w); plt.xlabel("time"); plt.ylabel("state")  # label axes.
plt.title("4: HER changes the goal label, not the path"); plt.legend(); plt.show()  # display.
```
▶ What you'll see: the path misses the red goal but ends exactly on the green hindsight goal.

*Why it's done this way:* the transition dynamics `P(s'|s,a)` do not depend on what goal label we write in the replay buffer. Therefore `(s,a,s')` remains honest data after relabeling. Only the supervised target changes: the reward is recomputed as `r(s,a,s',g_hindsight)`, and the bootstrap reads `Q(s', g_hindsight, :)`. This is not pretending the agent intended the new goal; it is extracting a valid lesson about how to reach that achieved goal.

### 5. A replay buffer can mix original and hindsight targets

A replay buffer stores transitions, then samples them repeatedly for updates. HER augments each stored transition with additional goal labels, commonly future states from the same episode. The learner sees both failures for the commanded goal and successes for achieved goals, which improves coverage of the goal-conditioned table.

```python
buffer_w = []  # each item will be (state, action_index, next_state, goal, reward, label).
for t_w, a_w in enumerate(actions_w):
    s_t_w = states_path_w[t_w]  # current state from the episode.
    ns_t_w = states_path_w[t_w + 1]  # next state from the episode.
    a_i_w = int(np.where(actions_list_w == a_w)[0][0])  # convert action value to index.
    buffer_w.append((s_t_w, a_i_w, ns_t_w, goal_w, goal_reward_w(ns_t_w, goal_w), "original"))  # commanded goal.
    future_goal_w = states_path_w[-1]  # simple HER strategy: final achieved state.
    buffer_w.append((s_t_w, a_i_w, ns_t_w, future_goal_w, goal_reward_w(ns_t_w, future_goal_w), "hindsight"))  # relabeled.
print("buffer size:", len(buffer_w))  # original + hindsight transitions.
print("first three entries:", buffer_w[:3])  # inspect records.
```
▶ What you'll see: every physical step appears twice, once with the original goal and once with the hindsight goal.

```python
labels_w = [row_w[-1] for row_w in buffer_w]  # extract original/hindsight labels.
successes_w = np.array([row_w[4] == 0.0 for row_w in buffer_w])  # success under that row's goal.
print("success count original:", int(sum(s and lab == "original" for s, lab in zip(successes_w, labels_w))))  # original successes.
print("success count hindsight:", int(sum(s and lab == "hindsight" for s, lab in zip(successes_w, labels_w))))  # HER successes.
plt.figure(figsize=(4.6, 3))  # create a count plot.
plt.bar(["original", "hindsight"], [sum(l == "original" for l in labels_w), sum(l == "hindsight" for l in labels_w)], color=["gray", "seagreen"])  # buffer mix.
plt.title("5: replay contains both goal labels"); plt.ylabel("transitions"); plt.show()  # display.
```
▶ What you'll see: original and hindsight rows are balanced here, but hindsight contributes the successful transition.

*Why it's done this way:* replay already improves sample efficiency by reusing transitions; HER adds a second efficiency gain by asking more than one valid question of each transition. The original rows preserve the task distribution, while hindsight rows densify the reward signal. In practice, the mix ratio is a modeling choice: too little HER wastes failures, but too much HER can bias training toward easy achieved goals instead of commanded goals.

### 6. Goal-conditioned policies choose actions from value differences

Once `Q(s,g,a)` has been learned, the greedy policy selects the action with the largest value for the requested goal. In the line world, a hand-built negative-distance Q table makes the greedy policy move toward the goal: right if `g>s`, left if `g<s`, and either action at the goal because both are equally unnecessary.

```python
Q_policy_w = np.zeros((nS_w, nG_w, nA_w))  # hand-built values for demonstration.
for s_w2 in states_w:
    for g_w2 in goals_w:
        for ai_w2, a_w2 in enumerate(actions_list_w):
            ns_w2 = step_line_w(s_w2, a_w2, nS_w)  # next state after the action.
            Q_policy_w[s_w2, g_w2, ai_w2] = -abs(ns_w2 - g_w2)  # closer next states have larger value.
print("Q at state 1, goal 4 [left,right]:", Q_policy_w[1, 4])  # right should be better.
print("Q at state 3, goal 0 [left,right]:", Q_policy_w[3, 0])  # left should be better.
```
▶ What you'll see: at `(1,4)`, right has value `-2` versus left `-4`; at `(3,0)`, left wins.

```python
greedy_actions_w = np.argmax(Q_policy_w, axis=2)  # best action index for every state-goal pair.
print("greedy action index table rows=state cols=goal:\n", greedy_actions_w)  # 0=left, 1=right.
plt.figure(figsize=(4.5, 3.2))  # create a policy heatmap.
plt.imshow(greedy_actions_w, cmap="coolwarm", aspect="auto", vmin=0, vmax=1)  # color left vs right.
plt.colorbar(ticks=[0, 1], label="0=left, 1=right")  # action legend.
plt.xlabel("goal"); plt.ylabel("state"); plt.title("6: greedy action depends on the goal"); plt.show()  # display.
```
▶ What you'll see: cells below the diagonal move left, cells above the diagonal move right.

*Why it's done this way:* the policy is just a decision rule over the goal-conditioned value table. Because the same physical state appears in many columns, changing the requested goal can flip the chosen action. That is the central benefit: one learned object can solve a family of tasks by conditioning on `g` instead of training a separate policy for each target.

## 🛠️ Setup

```python
import numpy as np  # load NumPy for tabular RL arrays, random simulation, and numerical checks.
import matplotlib.pyplot as plt  # load Matplotlib for trajectories, heatmaps, bars, and learning curves.
np.random.seed(0)  # make all stochastic examples reproducible.

def line_step(s, action, n=5):  # move left or right in a clipped one-dimensional grid.
    return int(np.clip(s + action, 0, n - 1))  # stay inside the world boundaries.

def goal_reward(next_state, goal):  # sparse goal-conditioned reward used throughout the lesson.
    return 0.0 if int(next_state) == int(goal) else -1.0  # success avoids the per-step penalty.

def q_target(Q, next_state, goal, reward, gamma=0.9):  # one-step goal-conditioned Bellman target.
    return float(reward + gamma * np.max(Q[int(next_state), int(goal)]))  # bootstrap from the same goal slice.

def epsilon_greedy(Q, state, goal, epsilon=0.1):  # choose an action index from a Q[state, goal, action] table.
    if np.random.rand() < epsilon:  # occasionally explore.
        return int(np.random.randint(Q.shape[2]))  # random action index.
    return int(np.argmax(Q[int(state), int(goal)]))  # otherwise exploit the best current action.

def make_episode(start, goal, actions, n=5):  # create a deterministic trajectory from an action sequence.
    states = [int(start)]  # store the starting state.
    rewards = []  # store rewards under the requested goal.
    for action in actions:  # apply each action.
        ns = line_step(states[-1], int(action), n)  # compute next state.
        rewards.append(goal_reward(ns, goal))  # compute sparse reward.
        states.append(ns)  # append next state.
    return states, rewards  # return the full path and reward list.

def add_her_final(states, actions, original_goal):  # build original and final-goal hindsight replay rows.
    rows = []  # each row is state, action, next_state, goal, reward, label.
    final_goal = int(states[-1])  # simple HER strategy: use the final achieved state.
    for t, action in enumerate(actions):  # loop over transitions.
        s, ns = int(states[t]), int(states[t + 1])  # current and next state.
        rows.append((s, int(action), ns, int(original_goal), goal_reward(ns, original_goal), "original"))  # commanded goal row.
        rows.append((s, int(action), ns, final_goal, goal_reward(ns, final_goal), "hindsight"))  # relabeled row.
    return rows  # return the augmented replay rows.
```

### Basic 5 — Calculate one Bellman target

**Goal.** Compute `r + γ max Q(s',g,:)`, because bootstrapping is how sparse successes propagate backward. We build it in 2 steps.

```python
Q_b5 = np.zeros((5, 5, 2))  # create a small value table.
Q_b5[3, 4] = np.array([-0.8, -0.2])  # from state 3 for goal 4, right is currently better.
state_b5, action_b5, goal_b5 = 2, 1, 4  # choose state 2, action right, requested goal 4.
next_state_b5 = line_step(state_b5, action_b5, n=5)  # move to state 3.
reward_b5 = goal_reward(next_state_b5, goal_b5)  # not done yet.
print("next state:", next_state_b5, "reward:", reward_b5)  # inspect transition feedback.
```
▶ What you'll see: moving right from 2 reaches 3 and still receives -1 for goal 4.

```python
target_b5 = q_target(Q_b5, next_state_b5, goal_b5, reward_b5, gamma=0.9)  # compute target.
print("Bellman target:", round(target_b5, 3))  # inspect backup value.
assert round(target_b5, 3) == -1.18  # -1 + 0.9*(-0.2).
```
▶ What you'll see: the target combines immediate penalty with the best estimated next action for the same goal.

bootstrap_b5 = 0.9 * np.max(Q_b5[next_state_b5, goal_b5])  # isolate the discounted next-state term.

### Advanced 5 — Train and test a simple HER learner end-to-end

**Goal.** Combine exploration, HER replay, and evaluation on the line world, because the full algorithm is a loop of collecting data, relabeling it, and updating goal-conditioned values. We build it in 4 steps.

Q_a5 = np.zeros((5, 5, 2))  # initialize goal-conditioned values.

    s_a5 = start_a5  # current state.
    states_ep_a5 = [s_a5]  # episode states.
    acts_ep_a5 = []  # episode actions.
    for _ in range(4):
        action_a5 = int(np.random.choice(action_values_a5))  # random exploration.
        acts_ep_a5.append(action_a5)  # store action.
        s_a5 = line_step(s_a5, action_a5)  # apply dynamics.
