# 27.4 — Embodied AI & Robotics Learning

Embodied AI studies agents that learn while acting in a physical or simulated world. A robot does not merely classify an input: its action changes the next state, the next sensor reading, and the future rewards it can collect.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build embodied learning one idea at a time. Run each cell in order and inspect the plots — every idea connects a small equation to a toy 2D robot, arm, sensor, or learning loop. This walkthrough is self-contained (it imports what it needs) and uses a `_w` suffix on variables so it never clashes with the examples below.

### 1. Embodiment means perception-action feedback

A static predictor receives an input and returns an answer. An embodied agent receives a state estimate, chooses an action, changes the world, senses the new world, and repeats. The crucial difference is feedback: today's action creates tomorrow's data. In a 2D navigation toy, the policy action is a velocity vector, the transition adds it to position, and the next sensor reading is the new relative goal direction.

```python
pos_w = np.array([0.0, 0.0])  # robot starts at the origin.
goal_w = np.array([4.0, 3.0])  # target location in a 2D room.
traj_w = [pos_w.copy()]  # record the closed-loop path.
for t_w in range(8):  # take several feedback-controlled steps.
    sensor_w = goal_w - pos_w  # simple state estimate: vector from robot to goal.
    action_w = 0.35 * sensor_w / (np.linalg.norm(sensor_w) + 1e-9)  # move toward the sensed goal.
    pos_w = pos_w + action_w  # transition: the robot's action changes its future state.
    traj_w.append(pos_w.copy())  # save the new state for plotting.
traj_w = np.array(traj_w)  # convert path list to an array for plotting.
print("final distance:", round(float(np.linalg.norm(goal_w - pos_w)), 3))  # inspect remaining error.
assert traj_w.shape == (9, 2)  # verify we stored start plus 8 transitions.
plt.figure(figsize=(4.5, 3.6))  # create a compact 2D trajectory plot.
plt.plot(traj_w[:, 0], traj_w[:, 1], marker="o", label="robot trajectory")  # show the closed-loop path.
plt.scatter([goal_w[0]], [goal_w[1]], c="red", marker="*", s=140, label="goal")  # mark the target.
plt.quiver(traj_w[:-1, 0], traj_w[:-1, 1], np.diff(traj_w[:, 0]), np.diff(traj_w[:, 1]), angles="xy", scale_units="xy", scale=1, width=0.004)  # show actions as arrows.
plt.axis("equal"); plt.xlabel("x"); plt.ylabel("y"); plt.title("1: action changes the next observation"); plt.legend(); plt.show()  # render the plot.
```
▶ What you'll see: the robot advances toward the goal, and every arrow starts from the state produced by the previous arrow.

*Why it's done this way: the feedback loop is the core of embodied AI — perception chooses action, action changes state, and the changed state becomes the next training example.*

### 2. Reinforcement learning assigns credit through future value

A robot often receives delayed reward: a step may have zero immediate reward but still be good because it moves toward a valuable future state. A one-step temporal-difference update uses \(\delta_t=r_t+\gamma V(s_{t+1})-V(s_t)\). With \(r_t=0\), \(\gamma=0.9\), \(V(s_{t+1})=1.5\), \(V(s_t)=1.0\), and \(\eta=0.2\), the update is \(1.000+0.2(1.350-1.000)=1.070\).

```python
positions_w = np.linspace(0, 5, 6)  # one-dimensional states along a hallway to a goal.
V_w = np.array([0.2, 0.6, 1.0, 1.5, 2.0, 2.5])  # current value estimates for those states.
s_w, sp_w = 2, 3  # transition from state index 2 to the better successor 3.
r_w, gamma_w, eta_w = 0.0, 0.9, 0.2  # reward, discount, and learning rate from the lesson math.
target_w = r_w + gamma_w * V_w[sp_w]  # bootstrap target from the successor value.
delta_w = target_w - V_w[s_w]  # temporal-difference error.
V_new_w = V_w.copy(); V_new_w[s_w] = V_w[s_w] + eta_w * delta_w  # update only the visited state.
print("target:", round(target_w, 3), "delta:", round(delta_w, 3), "updated V:", round(V_new_w[s_w], 3))  # inspect the arithmetic.
assert round(V_new_w[s_w], 3) == 1.07  # verify the worked update.
plt.figure(figsize=(5, 3))  # create a value-function comparison plot.
plt.plot(positions_w, V_w, marker="o", label="before")  # old value function.
plt.plot(positions_w, V_new_w, marker="s", label="after TD update")  # new value function.
plt.scatter([positions_w[s_w], positions_w[sp_w]], [V_w[s_w], V_w[sp_w]], c=["orange", "green"], s=90, label="transition")  # mark the sampled transition.
plt.xlabel("hallway state"); plt.ylabel("V(s)"); plt.title("2: successor value lifts current value"); plt.legend(); plt.show()  # render the plot.
```
▶ What you'll see: only the visited state moves upward because its successor was better than expected.

*Why it's done this way: TD learning lets robots learn from ongoing interaction without waiting for the entire episode to finish every time.*

### 3. Exploration keeps action selection from freezing too early

Physical contact tasks punish overconfidence: a greedy controller may never try a useful push, grip, or recovery move. A softmax policy turns action values into probabilities, \(\pi(a)\propto e^{\beta Q(a)}\). With \(Q=[1.2,0.7,0.4]\) and \(\beta=2\), the probabilities are approximately \([0.637,0.234,0.129]\): the best action is favored but not forced.

```python
Q_w = np.array([1.2, 0.7, 0.4])  # action values for forward, left, right.
beta_w = 2.0  # inverse temperature: larger means greedier action choice.
exp_w = np.exp(beta_w * Q_w)  # exponentiate preferences.
pi_w = exp_w / np.sum(exp_w)  # normalize into probabilities.
print("softmax probabilities:", np.round(pi_w, 3))  # inspect exploration distribution.
assert np.allclose(np.round(pi_w, 3), np.array([0.637, 0.234, 0.129]))  # verify the lesson math.
start_w = np.array([0.0, 0.0])  # draw the three candidate moves from the same robot state.
actions_w = np.array([[1.0, 0.0], [0.6, 0.55], [0.6, -0.55]])  # forward, left, right velocity directions.
plt.figure(figsize=(4.6, 3.6))  # create a policy-arrow plot.
for k_w, name_w in enumerate(["forward", "left", "right"]):  # plot each candidate action.
    plt.arrow(start_w[0], start_w[1], actions_w[k_w, 0], actions_w[k_w, 1], width=0.015 + 0.05 * pi_w[k_w], alpha=0.75, length_includes_head=True, label=f"{name_w}: {pi_w[k_w]:.3f}")  # arrow thickness shows probability.
plt.scatter([0], [0], c="black", s=60); plt.xlim(-0.2, 1.25); plt.ylim(-0.8, 0.8); plt.xlabel("x"); plt.ylabel("y"); plt.title("3: softmax policy keeps alternatives alive"); plt.legend(); plt.show()  # render policy arrows.
```
▶ What you'll see: the forward arrow is thickest, but side actions still have visible probability mass.

*Why it's done this way: exploration preserves information gathering, which is essential when the policy has not yet experienced enough contacts, slips, or failures.*

### 4. Imitation learning is useful but brittle off the demonstrations

When reward is sparse or unsafe to discover, demonstrations can teach an initial policy. Behavior cloning minimizes \((\hat a-a^\star)^2\); for \(a^\star=0.80\) and \(\hat a=0.62\), the loss is \(0.0324\). But imitation only trains states present in the demonstrations, so recovery states can remain unsupported.

```python
x_demo_w = np.linspace(0, 4, 9)  # demonstrated positions along a corridor.
a_star_w = 0.8 - 0.12 * x_demo_w  # expert slows as it approaches the goal.
a_hat_w = 0.62 - 0.08 * x_demo_w  # imperfect cloned policy.
loss0_w = (a_hat_w[0] - a_star_w[0]) ** 2  # first demonstration loss matches the lesson arithmetic.
print("first cloning loss:", round(float(loss0_w), 4))  # inspect (0.62 - 0.80)^2.
assert round(float(loss0_w), 4) == 0.0324  # verify the worked loss.
plt.figure(figsize=(5, 3))  # create an action-vs-state plot.
plt.plot(x_demo_w, a_star_w, marker="o", label="expert action")  # demonstrated action curve.
plt.plot(x_demo_w, a_hat_w, marker="s", label="cloned policy")  # learned policy curve.
plt.axvspan(4.2, 5.0, color="red", alpha=0.12, label="unseen recovery states")  # show unsupported region.
plt.xlabel("state: distance along path"); plt.ylabel("forward action"); plt.title("4: cloning matches demos, not all recoveries"); plt.legend(); plt.show()  # render the plot.
```
▶ What you'll see: the cloned action curve follows the expert on the demonstrated states but says nothing about the shaded recovery region.

*Why it's done this way: imitation is a strong warm start, but embodied learners still need feedback, data aggregation, or RL to recover from states the expert never visited in the dataset.*

### 5. Sim-to-real gaps are distribution shifts

A simulator can train cheaply, but real robots differ in friction, latency, lighting, sensor noise, and contact. If grasp success is \(92/100\) in simulation and \(73/100\) on hardware, the gap is \(0.190\). Domain randomization widens the simulated distribution so the learned policy sees many plausible worlds before deployment.

```python
rng_w = np.random.default_rng(4)  # reproducible randomized domains.
sim_success_w = 92 / 100  # simulated grasp success from the lesson math.
real_success_w = 73 / 100  # hardware grasp success from the lesson math.
gap_w = sim_success_w - real_success_w  # sim-to-real drop.
friction_w = rng_w.uniform(0.4, 1.2, 120)  # randomized surface friction values.
latency_w = rng_w.uniform(0.0, 0.18, 120)  # randomized actuation/sensing delay values.
score_w = 0.92 - 0.22 * np.abs(friction_w - 0.8) - 0.85 * latency_w  # toy success model under randomized domains.
print("sim:", round(sim_success_w, 3), "real:", round(real_success_w, 3), "gap:", round(gap_w, 3))  # inspect gap.
assert round(gap_w, 3) == 0.19  # verify the worked gap.
plt.figure(figsize=(5, 3.5))  # create a domain-randomization scatter plot.
plt.scatter(friction_w, latency_w, c=score_w, cmap="viridis", s=35)  # show randomized domains colored by predicted success.
plt.colorbar(label="toy success")  # make color interpretable.
plt.scatter([0.55], [0.16], c="red", marker="x", s=120, label="hard real domain")  # mark a shifted real condition.
plt.xlabel("friction"); plt.ylabel("latency"); plt.title("5: domain randomization spreads simulated worlds"); plt.legend(); plt.show()  # render the plot.
```
▶ What you'll see: randomized simulated domains cover a spread of frictions and latencies, with a hard real condition near the edge.

*Why it's done this way: broadening simulation reduces brittleness by training the policy against a family of plausible transition and observation models instead of one perfect world.*

### 6. Closed-loop control compounds corrections

Embodied systems benefit from correcting while moving. If a controller removes 40% of the remaining error each step from 10 cm, the residual error is multiplied by 0.6: 10, 6, 3.6, 2.16, and so on. That geometric shrinkage is why sensing during action can be more reliable than one open-loop guess.

```python
err_w = [10.0]  # initial endpoint error in centimeters.
for _ in range(8):  # repeated feedback corrections.
    err_w.append(err_w[-1] * 0.6)  # each step leaves 60% of the previous error.
err_w = np.array(err_w)  # convert to array for plotting.
print("first three corrected errors:", np.round(err_w[1:4], 3))  # inspect 6.0, 3.6, 2.16.
assert np.allclose(np.round(err_w[1:4], 3), np.array([6.0, 3.6, 2.16]))  # verify lesson arithmetic.
steps_w = np.arange(len(err_w))  # correction step indices.
plt.figure(figsize=(5, 3))  # create an error-decay plot.
plt.plot(steps_w, err_w, marker="o", color="crimson")  # show geometric error reduction.
plt.xlabel("feedback correction step"); plt.ylabel("remaining error (cm)"); plt.title("6: closed-loop correction compounds"); plt.ylim(0, 10.5); plt.show()  # render the plot.
```
▶ What you'll see: the error falls quickly at first and then tapers as the robot approaches the target.

*Why it's done this way: feedback control turns sensing into repeated small corrections, so embodied policies can recover from imperfect predictions and disturbances.*

## 🛠️ Setup

```python
import numpy as np  # arrays, linear algebra, randomness, and compact simulations.
import matplotlib.pyplot as plt  # trajectory, sensor, learning-curve, policy, and arm visualizations.
np.random.seed(0)  # make every example reproducible.

def move_toward(pos, goal, step=0.35):  # compute a bounded velocity toward a goal.
    direction = np.asarray(goal, dtype=float) - np.asarray(pos, dtype=float)  # vector from robot to target.
    norm = np.linalg.norm(direction)  # length of the direction vector.
    return np.zeros_like(direction) if norm == 0 else step * direction / norm  # avoid divide-by-zero at the goal.

def rollout_to_goal(start, goal, steps=12, step=0.35, noise=0.0, seed=0):  # simulate a simple 2D point robot.
    rng = np.random.default_rng(seed)  # local generator so examples are deterministic.
    pos = np.asarray(start, dtype=float).copy()  # copy the initial position.
    traj = [pos.copy()]  # store the starting state.
    for _ in range(steps):  # repeat closed-loop actions.
        action = move_toward(pos, goal, step) + rng.normal(0.0, noise, size=2)  # goal-seeking action plus optional actuation noise.
        pos = pos + action  # transition to the next state.
        traj.append(pos.copy())  # record the state.
    return np.array(traj)  # return a path array with shape (steps+1, 2).

def softmax(q, beta=1.0):  # convert action values into exploration probabilities.
    z = beta * np.asarray(q, dtype=float)  # scale preferences by inverse temperature.
    z = z - np.max(z)  # stabilize exponentials.
    e = np.exp(z)  # exponentiate stabilized preferences.
    return e / np.sum(e)  # normalize into probabilities.

def two_link_arm(theta, lengths=(1.0, 0.7)):  # forward kinematics for a planar two-link arm.
    t1, t2 = float(theta[0]), float(theta[1])  # read joint angles.
    l1, l2 = lengths  # read link lengths.
    elbow = np.array([l1 * np.cos(t1), l1 * np.sin(t1)])  # first link endpoint.
    wrist = elbow + np.array([l2 * np.cos(t1 + t2), l2 * np.sin(t1 + t2)])  # second link endpoint.
    return np.vstack([[0.0, 0.0], elbow, wrist])  # base, elbow, wrist points.

def plot_room(traj, goal, title):  # draw a 2D trajectory and goal.
    plt.figure(figsize=(4.5, 3.6))  # compact trajectory figure.
    plt.plot(traj[:, 0], traj[:, 1], marker="o", label="trajectory")  # plot robot states.
    plt.scatter([goal[0]], [goal[1]], c="red", marker="*", s=130, label="goal")  # plot the target.
    plt.axis("equal"); plt.xlabel("x"); plt.ylabel("y"); plt.title(title); plt.legend(); plt.show()  # display the plot.
```

### Basic 1 — Draw a perception-action trajectory

**Goal.** Simulate a point robot moving toward a goal, because embodied learning starts with actions that change future observations. We build it in 2 steps.

```python
start_b1 = np.array([0.0, 0.0])  # starting position of the robot.
goal_b1 = np.array([3.0, 2.0])  # desired target location.
traj_b1 = rollout_to_goal(start_b1, goal_b1, steps=10, step=0.35, noise=0.0, seed=1)  # run a deterministic feedback rollout.
print("path shape:", traj_b1.shape, "final distance:", round(float(np.linalg.norm(goal_b1 - traj_b1[-1])), 3))  # inspect rollout summary.
assert traj_b1.shape == (11, 2)  # verify start plus ten actions were recorded.
plt.figure(figsize=(4.5, 3.6))  # create a trajectory figure for this example.
plt.plot(traj_b1[:, 0], traj_b1[:, 1], marker="o", label="trajectory")  # draw the robot path.

plt.axis("equal"); plt.xlabel("x"); plt.ylabel("y"); plt.title("Basic 1: closed-loop 2D robot path"); plt.legend(); plt.show()  # display the trajectory.
```
▶ What you'll see: the robot follows a sequence of states toward the target instead of making one isolated prediction.

👀 Takeaway: an embodied policy creates the next input by acting in the world.

### Basic 2 — Convert sensor readings into state

**Goal.** Compute a noisy range sensor to a goal, because robots often learn from imperfect observations rather than exact state. We build it in 2 steps.

```python
rng_b2 = np.random.default_rng(2)  # local generator for reproducible sensor noise.
robot_b2 = np.array([1.0, 0.8])  # current robot position.
```

👀 Takeaway: state estimates are built from sensors, and sensor noise is part of the learning problem.

### Basic 3 — Apply one temporal-difference update

**Goal.** Update a state value from a successor, because embodied RL uses future outcomes to assign credit to current states. We build it in 2 steps.

```python
V_b3 = np.array([0.5, 1.0, 1.5])  # value estimates for three nearby states.
r_b3, gamma_b3, eta_b3 = 0.0, 0.9, 0.2  # reward, discount, and learning rate.
target_b3 = r_b3 + gamma_b3 * V_b3[2]  # bootstrap from successor value.
delta_b3 = target_b3 - V_b3[1]  # temporal-difference error for the visited state.
V_after_b3 = V_b3.copy(); V_after_b3[1] += eta_b3 * delta_b3  # update the visited value.
print("TD target:", round(target_b3, 3), "delta:", round(delta_b3, 3), "new value:", round(V_after_b3[1], 3))  # inspect the calculation.
assert round(float(V_after_b3[1]), 3) == 1.07  # verify the lesson value update.
plt.figure(figsize=(4.6, 3))  # create a before-after value plot.
plt.plot([0, 1, 2], V_b3, marker="o", label="before")  # old values.
plt.plot([0, 1, 2], V_after_b3, marker="s", label="after")  # updated values.
plt.xlabel("state index"); plt.ylabel("V(s)"); plt.title("Basic 3: one TD value update"); plt.legend(); plt.show()  # display the value update.
```
▶ What you'll see: the middle state's value rises because its successor was valuable.

👀 Takeaway: TD learning turns future value into today's training target.

### Basic 8 — Compare simulation and hardware success

### Easy 1 — Learn a tabular navigation policy

**Goal.** Run a tiny policy-learning loop on a grid, because embodied RL improves actions through repeated episodes and rewards. We build it in 3 steps.

```python

actions_e1 = np.array([[1, 0], [-1, 0], [0, 1], [0, -1]])  # right, left, up, down moves.

    s_e1 = np.array([0, 0])  # reset robot to lower-left corner.

        probs_e1 = softmax(Q_e1[s_e1[0], s_e1[1]], beta=2.0) if ep_e1 > 10 else np.ones(4) / 4  # explore early, then softmax.
        a_idx_e1 = int(rng_e1.choice(4, p=probs_e1))  # sample an action.
        ns_e1 = np.clip(s_e1 + actions_e1[a_idx_e1], 0, grid_e1 - 1)  # transition with wall clipping.
```
