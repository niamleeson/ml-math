# 19.7 — Bias Mitigation

Bias mitigation changes the data, objective, or decision rule so a model is not judged by average accuracy alone. In this lesson we build the three intervention points from scratch — pre-processing with reweighing, in-processing with a fairness penalty, and post-processing with group-aware thresholds — using only NumPy and small synthetic data where every tradeoff can be inspected.

## 📖 Concept walkthrough — build each idea from scratch

Before the worked examples, we build the mitigation pipeline one idea at a time. Run each cell in order and read the printed intermediate values: we will first create biased data and metrics, then intervene before training, during training, and after scores are produced. The walkthrough is self-contained and uses a `_w` suffix so it never clashes with the examples below.

```python
import numpy as np  # arrays, vectorized simulation, and logistic-regression math.
import matplotlib.pyplot as plt  # visual checks for distributions, losses, and tradeoffs.
np.random.seed(0)  # reproducibility for the synthetic audit.
```

### 1. Biased data and the fairness quantities we will mitigate

Bias mitigation needs a specific failure to push against. We synthesize a protected group `g`, a feature `x`, a true label `y`, and a biased model score. Group 1 receives a score boost that is not explained by the label; that creates a higher selection rate even when accuracy still looks acceptable.

```python
n_w = 240  # keep the audit small enough to inspect but large enough for stable rates.
g_w = np.r_[np.zeros(n_w // 2, dtype=int), np.ones(n_w // 2, dtype=int)]  # protected group: 0 or 1.
x_signal_w = np.r_[np.random.normal(-0.15, 1.0, n_w // 2), np.random.normal(0.15, 1.0, n_w // 2)]  # one predictive feature.
logit_true_w = -0.25 + 1.15 * x_signal_w  # true outcome mechanism uses x, not the protected group directly.
p_true_w = 1 / (1 + np.exp(-logit_true_w))  # convert logits to probabilities.
y_w = (np.random.random(n_w) < p_true_w).astype(int)  # sample binary labels.
score_biased_w = 1 / (1 + np.exp(-(-0.35 + 1.0 * x_signal_w + 0.55 * g_w)))  # biased score includes a group boost.
print("label rates by group:", round(y_w[g_w == 0].mean(), 3), round(y_w[g_w == 1].mean(), 3))
print("mean biased score by group:", round(score_biased_w[g_w == 0].mean(), 3), round(score_biased_w[g_w == 1].mean(), 3))
```
▶ What you'll see: group 1 has a noticeably higher average score, partly from the artificial group boost.

```python
def rates_w(scores, y, g, t0=0.5, t1=0.5):
    pred = np.zeros_like(y)
    pred[g == 0] = (scores[g == 0] >= t0).astype(int)
    pred[g == 1] = (scores[g == 1] >= t1).astype(int)
    sel0 = pred[g == 0].mean(); sel1 = pred[g == 1].mean()
    tpr0 = pred[(g == 0) & (y == 1)].mean(); tpr1 = pred[(g == 1) & (y == 1)].mean()
    acc = (pred == y).mean()
    return acc, sel0, sel1, abs(sel1 - sel0), abs(tpr1 - tpr0)

base_metrics_w = rates_w(score_biased_w, y_w, g_w)
print("accuracy, sel0, sel1, DP gap, TPR gap:", np.round(base_metrics_w, 3))
assert base_metrics_w[3] > 0.10
```
▶ What you'll see: the demographic-parity gap is nontrivial, so the model needs more than an accuracy report.

```python
plt.figure(figsize=(5, 3))
plt.hist(score_biased_w[g_w == 0], bins=16, alpha=0.7, label="group 0")
plt.hist(score_biased_w[g_w == 1], bins=16, alpha=0.7, label="group 1")
plt.axvline(0.5, color="black", linestyle="--", label="threshold")
plt.title("1: biased score distributions")
plt.xlabel("model score")
plt.ylabel("count")
plt.legend()
plt.show()
```
▶ What you'll see: group 1's score histogram is shifted right, so a shared 0.5 threshold selects more of that group.

*Why it's done this way:* fairness metrics turn a vague worry into a scalar penalty `Δ(θ)`. Demographic parity uses selection-rate difference because it audits the decision flow; equal opportunity uses TPR difference because it audits whether qualified positives are accepted at similar rates. We keep both visible because a mitigation can improve one while hurting the other.

### 2. Pre-processing: reweighing the training distribution

Reweighing changes the empirical risk before training. The classic cell weight is

$$w(g,y)=\frac{P(g)P(y)}{P(g,y)}.$$

If a group-label cell is overrepresented, its denominator is large and its weight shrinks; if it is rare, its weight grows. The model then sees a weighted sample where group and label are closer to independent.

```python
def reweighing_weights_w(g, y):
    weights = np.zeros_like(y, dtype=float)
    for gv in [0, 1]:
        for yv in [0, 1]:
            cell = (g == gv) & (y == yv)
            pg = np.mean(g == gv)
            py = np.mean(y == yv)
            pgy = np.mean(cell)
            weights[cell] = (pg * py) / pgy if pgy > 0 else 0.0
    return weights

w_rw_w = reweighing_weights_w(g_w, y_w)
print("cell weights:")
for gv in [0, 1]:
    for yv in [0, 1]:
        print(f"g={gv}, y={yv}:", round(float(w_rw_w[(g_w == gv) & (y_w == yv)][0]), 3))
assert 0.85 < w_rw_w.mean() < 1.15
```
▶ What you'll see: rare cells receive weights above 1 and common cells receive weights below 1, with mean weight near 1.

```python
def weighted_cell_table_w(g, y, weights):
    table = np.zeros((2, 2))
    for gv in [0, 1]:
        for yv in [0, 1]:
            table[gv, yv] = weights[(g == gv) & (y == yv)].sum()
    return table

raw_table_w = weighted_cell_table_w(g_w, y_w, np.ones_like(y_w, dtype=float))
rw_table_w = weighted_cell_table_w(g_w, y_w, w_rw_w)
print("raw group-label counts:\n", raw_table_w.astype(int))
print("reweighted group-label mass:\n", np.round(rw_table_w, 1))
```
▶ What you'll see: the weighted table is more balanced across protected-group and label cells than the raw counts.

```python
X_w = np.c_[np.ones(n_w), x_signal_w, g_w]  # include an intercept, signal, and protected group feature.

def sigmoid_w(z):
    return 1 / (1 + np.exp(-np.clip(z, -30, 30)))

def train_logreg_w(X, y, sample_weight=None, lam=0.0, steps=900, lr=0.08):
    theta = np.zeros(X.shape[1])
    sw = np.ones(len(y)) if sample_weight is None else sample_weight.astype(float)
    sw = sw / sw.mean()
    for _ in range(steps):
        p = sigmoid_w(X @ theta)
        grad = X.T @ (sw * (p - y)) / len(y) + lam * np.r_[0.0, theta[1:]]
        theta -= lr * grad
    return theta

theta_plain_w = train_logreg_w(X_w, y_w)
theta_rw_w = train_logreg_w(X_w, y_w, w_rw_w)
print("plain theta:", np.round(theta_plain_w, 3))
print("reweighted theta:", np.round(theta_rw_w, 3))
```
▶ What you'll see: reweighing changes the fitted coefficients because some cells now count more in the loss.

```python
plain_metrics_w = rates_w(sigmoid_w(X_w @ theta_plain_w), y_w, g_w)
rw_metrics_w = rates_w(sigmoid_w(X_w @ theta_rw_w), y_w, g_w)
print("plain accuracy/DP:", round(plain_metrics_w[0], 3), round(plain_metrics_w[3], 3))
print("reweighted accuracy/DP:", round(rw_metrics_w[0], 3), round(rw_metrics_w[3], 3))
plt.figure(figsize=(4.8, 3))
plt.bar(["plain DP", "reweighted DP"], [plain_metrics_w[3], rw_metrics_w[3]], color=["gray", "seagreen"])
plt.title("2: pre-processing changes the learned rule")
plt.ylabel("demographic-parity gap")
plt.show()
```
▶ What you'll see: the DP gap changes because the risk function no longer treats every raw row equally.

*Why it's done this way:* empirical risk is an average over the training distribution. Reweighing edits that average without changing labels or features: it estimates what the loss would have looked like if group and label frequencies were less entangled. The danger is variance — if a rare cell gets a huge weight, one noisy point can dominate the gradient.

### 3. In-processing: constrained training with a fairness penalty

In-processing keeps the model trainable but adds a fairness cost to the objective:

$$J(\theta)=R_S(\theta)+\lambda\Delta(\theta).$$

Here `R_S` is logistic loss and `Δ` is the squared difference between average predicted probabilities for the two groups. Increasing `λ` makes the optimizer pay more for group-level score separation.

```python
def train_fair_logreg_w(X, y, g, fairness_lam=0.0, steps=1200, lr=0.08):
    theta = np.zeros(X.shape[1])
    idx0, idx1 = (g == 0), (g == 1)
    for _ in range(steps):
        p = sigmoid_w(X @ theta)
        grad_loss = X.T @ (p - y) / len(y)
        diff = p[idx1].mean() - p[idx0].mean()
        d_diff_dz = np.zeros(len(y))
        d_diff_dz[idx1] = p[idx1] * (1 - p[idx1]) / idx1.sum()
        d_diff_dz[idx0] = -p[idx0] * (1 - p[idx0]) / idx0.sum()
        grad_fair = X.T @ (2 * diff * d_diff_dz)
        theta -= lr * (grad_loss + fairness_lam * grad_fair)
    return theta

lams_w = np.array([0.0, 0.5, 2.0, 8.0])
thetas_fair_w = [train_fair_logreg_w(X_w, y_w, g_w, fairness_lam=lam) for lam in lams_w]
print("fairness lambdas:", lams_w)
print("group coefficients:", np.round([th[2] for th in thetas_fair_w], 3))
```
▶ What you'll see: larger λ usually shrinks the direct protected-group coefficient because it creates score separation.

```python
accs_w, dps_w, tprs_w = [], [], []
for th in thetas_fair_w:
    m = rates_w(sigmoid_w(X_w @ th), y_w, g_w)
    accs_w.append(m[0]); dps_w.append(m[3]); tprs_w.append(m[4])
print("accuracy:", np.round(accs_w, 3))
print("DP gap:", np.round(dps_w, 3))
assert min(dps_w) <= dps_w[0]
```
▶ What you'll see: the fairness penalty reduces the score/decision gap for some λ values, often with an accuracy cost.

```python
plt.figure(figsize=(5, 3))
plt.plot(dps_w, accs_w, marker="o", color="purple")
for lam, x, yv in zip(lams_w, dps_w, accs_w):
    plt.text(x + 0.003, yv, f"λ={lam:g}")
plt.gca().invert_xaxis()
plt.title("3: fairness-accuracy tradeoff")
plt.xlabel("DP gap (left is better)")
plt.ylabel("accuracy")
plt.show()
```
▶ What you'll see: moving left means a smaller fairness gap; watch whether the curve gives up accuracy to get there.

*Why it's done this way:* the optimizer only follows gradients of what we put in the objective. Adding `λΔ` makes unfair score separation expensive in the same units as prediction loss. The knob `λ` is therefore not decoration; it decides the exchange rate between average fit and fairness pressure, so it must be tuned on validation data.

### 4. Post-processing: threshold adjustment after scores exist

Post-processing leaves scores fixed and changes the decision rule. A single threshold may produce unequal selection because score distributions differ by group. Group-specific thresholds can reduce a fairness gap, but they also separate probability estimation from the final decision.

```python
scores_post_w = sigmoid_w(X_w @ theta_plain_w)
grid_w = np.linspace(0.25, 0.75, 51)
best_w = None
records_w = []
for t0 in grid_w:
    for t1 in grid_w:
        acc, sel0, sel1, dp, tpr = rates_w(scores_post_w, y_w, g_w, t0, t1)
        records_w.append((t0, t1, acc, dp, tpr))
        if dp <= 0.03:
            if best_w is None or acc > best_w[2]:
                best_w = (t0, t1, acc, dp, tpr)
print("best thresholds with DP<=0.03:", np.round(best_w, 3))
assert best_w[3] <= 0.03
```
▶ What you'll see: the two groups can use different thresholds to make selection rates nearly match.

```python
single_w = rates_w(scores_post_w, y_w, g_w, 0.5, 0.5)
adjusted_w = rates_w(scores_post_w, y_w, g_w, best_w[0], best_w[1])
print("single threshold acc/DP/TPRgap:", np.round([single_w[0], single_w[3], single_w[4]], 3))
print("adjusted threshold acc/DP/TPRgap:", np.round([adjusted_w[0], adjusted_w[3], adjusted_w[4]], 3))
```
▶ What you'll see: DP improves by construction, while accuracy and TPR gap may move in either direction.

```python
rec_w = np.array(records_w)
plt.figure(figsize=(5, 3))
plt.scatter(rec_w[:, 3], rec_w[:, 2], c=rec_w[:, 4], cmap="viridis", s=18)
plt.colorbar(label="TPR gap")
plt.scatter([single_w[3]], [single_w[0]], color="red", label="single 0.5")
plt.scatter([adjusted_w[3]], [adjusted_w[0]], color="white", edgecolor="black", label="adjusted")
plt.title("4: post-processing threshold sweep")
plt.xlabel("DP gap")
plt.ylabel("accuracy")
plt.legend()
plt.show()
```
▶ What you'll see: many threshold pairs trace a fairness-accuracy frontier; color shows that fixing DP does not automatically fix TPR.

*Why it's done this way:* thresholds are decision rules, not probability models. Adjusting them is useful when a trained score must pass a release gate, but it changes who is accepted at the same predicted probability. That is why calibration monitoring is paired with post-processing in production audits.

## 🛠️ Setup

```python
import numpy as np  # NumPy handles arrays, random simulation, metrics, and optimization loops.
import matplotlib.pyplot as plt  # Matplotlib gives small visual checks for every mitigation step.
np.random.seed(0)  # Keep all examples reproducible.

def sigmoid(z):  # Stable sigmoid for probabilities.
    return 1 / (1 + np.exp(-np.clip(z, -30, 30)))

def make_bias_data(n=200, seed=0):  # Create a toy biased binary-classification audit dataset.
    rng = np.random.default_rng(seed)
    g = np.r_[np.zeros(n // 2, dtype=int), np.ones(n - n // 2, dtype=int)]
    x = np.r_[rng.normal(-0.15, 1.0, n // 2), rng.normal(0.15, 1.0, n - n // 2)]
    p = sigmoid(-0.25 + 1.15 * x)
    y = (rng.random(n) < p).astype(int)
    X = np.c_[np.ones(n), x, g]
    return X, x, g, y

def metrics(scores, y, g, t0=0.5, t1=0.5):  # Return accuracy and two fairness gaps for group-specific thresholds.
    pred = np.zeros_like(y)
    pred[g == 0] = (scores[g == 0] >= t0).astype(int)
    pred[g == 1] = (scores[g == 1] >= t1).astype(int)
    acc = float((pred == y).mean())
    sel0 = float(pred[g == 0].mean()); sel1 = float(pred[g == 1].mean())
    tpr0 = float(pred[(g == 0) & (y == 1)].mean()); tpr1 = float(pred[(g == 1) & (y == 1)].mean())
    return acc, sel0, sel1, abs(sel1 - sel0), abs(tpr1 - tpr0)

def train_lr(X, y, weights=None, steps=700, lr=0.08):  # Train logistic regression from scratch.
    theta = np.zeros(X.shape[1])
    w = np.ones(len(y)) if weights is None else weights.astype(float)
    w = w / w.mean()
    for _ in range(steps):
        p = sigmoid(X @ theta)
        theta -= lr * (X.T @ (w * (p - y)) / len(y))
    return theta

def reweigh(g, y):  # Compute w(g,y)=P(g)P(y)/P(g,y) for binary group and label.
    w = np.zeros_like(y, dtype=float)
    for gv in [0, 1]:
        for yv in [0, 1]:
            cell = (g == gv) & (y == yv)
            w[cell] = np.mean(g == gv) * np.mean(y == yv) / np.mean(cell)
    return w
```

### Basic 7 — Train with reweighted loss

### Easy 3 — Train with a soft fairness penalty

**Goal.** Implement `J = logistic loss + λ(score gap)^2` from scratch. We build it in 3 steps.


```python
def train_penalty_e3(lam_e3):
    theta_e3 = np.zeros(X_e3.shape[1])
    for _ in range(1000):
        p_e3 = sigmoid(X_e3 @ theta_e3)
        grad_loss_e3 = X_e3.T @ (p_e3 - y_e3) / len(y_e3)
        diff_e3 = p_e3[idx1_e3].mean() - p_e3[idx0_e3].mean()

    return theta_e3
```
