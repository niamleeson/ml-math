# 12.1 — Graph Representation & Tasks

Graph learning starts by deciding how relational data becomes arrays: an adjacency matrix for who touches whom, a feature matrix for what each node knows, and labels attached to nodes, edges, or whole graphs. In this lesson, zeros are handled carefully because a zero in an adjacency matrix can mean a known non-edge or merely an unobserved pair.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build graph representation one idea at a time. Run each cell in order and read the printed intermediate values — every piece of graph math is shown with NumPy arrays so the notation never becomes a black box. This walkthrough is self-contained and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays, matrix products, masks, and small graph calculations.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
np.random.seed(0)  # reproducibility for layouts and synthetic examples.
```

### 1. Edges become an adjacency matrix

A graph has nodes and edges. For a small undirected graph, we can store those edges in an adjacency matrix $A$, where $A_{ij}=1$ means node `i` is connected to node `j`. Because the graph is undirected, every edge appears twice in the matrix: once as $(i,j)$ and once as $(j,i)$.

```python
edges_w = [(0, 1), (0, 2), (1, 2), (1, 3)]  # four undirected roads between four nodes.
n_w = 4  # number of nodes in the toy graph.
A_w = np.zeros((n_w, n_w), dtype=int)  # start with no known edges.
for i_w, j_w in edges_w:  # add each undirected edge in both directions.
    A_w[i_w, j_w] = 1
    A_w[j_w, i_w] = 1
print(A_w)
```
▶ What you'll see: a symmetric 4×4 adjacency matrix with zeros on the diagonal.

```python
deg_w = A_w.sum(axis=1)  # degree = row sum = number of neighbors.
print("degrees:", deg_w)
print("edge count from upper triangle:", int(np.triu(A_w, 1).sum()))
assert np.array_equal(deg_w, np.array([2, 3, 2, 1]))
assert int(np.triu(A_w, 1).sum()) == 4
```
▶ What you'll see: the row sums are `[2, 3, 2, 1]`, and the upper triangle counts exactly four edges.

```python
pos_w = np.array([[0.0, 0.0], [1.0, 0.1], [0.3, 0.9], [1.7, 0.4]])  # hand-made node layout.
plt.figure(figsize=(4.2, 3.2))
for i_w, j_w in edges_w:
    plt.plot(pos_w[[i_w, j_w], 0], pos_w[[i_w, j_w], 1], color="gray", linewidth=2)
plt.scatter(pos_w[:, 0], pos_w[:, 1], s=280, c=deg_w, cmap="viridis")
for k_w, (x_w, y_w) in enumerate(pos_w):
    plt.text(x_w, y_w, str(k_w), ha="center", va="center", color="white", weight="bold")
plt.colorbar(label="degree"); plt.axis("off"); plt.title("1: graph layout colored by degree"); plt.show()
```
▶ What you'll see: node 1 is brightest because it has three incident edges; node 3 is dimmest with one.

*Why it's done this way:* The adjacency matrix is the linear-algebra version of an edge list. Row sums work because each `1` in a row contributes one neighbor, and counting only the upper triangle avoids double-counting undirected edges that appear in symmetric pairs.

### 2. Node features and node labels live by row

The adjacency says who is connected, but graph ML also needs what each node knows. A feature matrix $X\in\mathbb{R}^{n\times d}$ stores one row per node and one column per feature. A node label vector $y_v\in\mathbb{R}^n$ stores one target per node.

```python
X_w = np.array([[1.0, 0.0],   # node 0: mostly feature 0
                [1.0, 1.0],   # node 1: both features
                [0.0, 1.0],   # node 2: mostly feature 1
                [0.2, 0.8]])  # node 3: closer to feature 1
node_y_w = np.array([0, 0, 1, 1])  # one class label per node.
print("X shape:", X_w.shape)
print("node labels shape:", node_y_w.shape)
assert X_w.shape == (4, 2)
assert node_y_w.shape == (4,)
```
▶ What you'll see: the feature table has 4 rows and 2 columns, while node labels have one value per row.

```python
neighbor_feature_sum_w = A_w @ X_w  # each row sums features from neighboring nodes.
print("neighbor feature sums:\n", neighbor_feature_sum_w)
print("node 0 neighbors:", np.where(A_w[0] == 1)[0])
assert np.allclose(neighbor_feature_sum_w[0], X_w[1] + X_w[2])
```
▶ What you'll see: node 0's row equals node 1 plus node 2's feature vectors.

```python
plt.figure(figsize=(4.2, 3.2))
plt.scatter(X_w[:, 0], X_w[:, 1], c=node_y_w, cmap="coolwarm", s=220, edgecolor="black")
for k_w in range(4):
    plt.text(X_w[k_w, 0] + 0.02, X_w[k_w, 1] + 0.02, f"node {k_w}")
plt.xlabel("feature 0"); plt.ylabel("feature 1"); plt.title("2: node features colored by node label"); plt.show()
```
▶ What you'll see: nodes with label 0 sit toward feature 0, while label 1 nodes sit toward feature 1.

*Why it's done this way:* Putting node features in rows aligns $A$ and $X$ so matrix multiplication has graph meaning: $(AX)_i=\sum_{j\in N(i)}X_j$. That shape convention is why later message passing can be written as one matrix product instead of many Python loops.

### 3. Node, edge, and graph tasks attach labels at different levels

The same raw graph can support different prediction tasks. A node task predicts one output per row of $X$, an edge task predicts one output per candidate pair, and a graph task predicts one output for the entire structure after pooling graph-level features.

```python
edge_pairs_w = np.array(edges_w)  # observed positive edges as endpoint pairs.
edge_y_w = np.array([1, 1, 1, 1])  # edge labels could be existence, type, or weight.
graph_y_w = np.array([1])  # one graph-level label for the whole toy graph.
print("node targets:", node_y_w.shape)
print("edge targets:", edge_y_w.shape)
print("graph targets:", graph_y_w.shape)
assert len(node_y_w) == n_w and len(edge_y_w) == len(edges_w) and len(graph_y_w) == 1
```
▶ What you'll see: the three label arrays have different shapes because they answer different questions.

```python
graph_features_w = np.array([len(edges_w), deg_w.mean(), deg_w.max()])  # |E|, average degree, max degree.
print("graph features [|E|, mean degree, max degree]:", graph_features_w)
assert np.allclose(graph_features_w, np.array([4, 2, 3]))
```
▶ What you'll see: the graph-level summary is `[4, 2, 3]`, matching the lesson numbers.

```python
plt.figure(figsize=(4.6, 3))
plt.bar(["node labels", "edge labels", "graph labels"], [len(node_y_w), len(edge_y_w), len(graph_y_w)], color=["teal", "orange", "purple"])
plt.ylabel("number of targets"); plt.title("3: task level changes target shape"); plt.show()
```
▶ What you'll see: node and edge tasks have several targets, while the graph task has one.

*Why it's done this way:* The representation is not only the arrays; it is also the target granularity. A model for node classification should output `n` predictions, while graph classification must pool node/edge evidence into one vector before predicting, or its output shape is mathematically wrong.

### 4. Matrix powers count walks and support link scores

The square $A^2$ has a useful interpretation: $(A^2)_{ij}=\sum_k A_{ik}A_{kj}$ counts two-hop walks from `i` to `j`. For link prediction, this is the common-neighbor score: two nodes are more likely to connect if many nodes touch both.

```python
A2_w = A_w @ A_w  # two-step walk counts.
print(A2_w)
print("common neighbors for nodes 2 and 3:", A2_w[2, 3])
assert A2_w[2, 3] == 1
```
▶ What you'll see: entry `(2,3)` is 1 because nodes 2 and 3 share node 1 as a common neighbor.

```python
missing_pairs_w = []
for i_w in range(n_w):
    for j_w in range(i_w + 1, n_w):
        if A_w[i_w, j_w] == 0:
            missing_pairs_w.append((i_w, j_w, A2_w[i_w, j_w]))
print("candidate non-edges with common-neighbor scores:", missing_pairs_w)
```
▶ What you'll see: each currently absent pair receives a score based on length-2 paths.

```python
plt.figure(figsize=(4.2, 3.2))
plt.imshow(A2_w, cmap="magma")
plt.colorbar(label="two-hop walks")
plt.title("4: A² counts common neighbors"); plt.xlabel("target node"); plt.ylabel("source node"); plt.show()
```
▶ What you'll see: brighter off-diagonal cells are pairs with stronger two-hop evidence.

*Why it's done this way:* Matrix multiplication sums over the middle node `k`. The product $A_{ik}A_{kj}$ is 1 exactly when `k` connects to both endpoints, so the sum counts shared intermediates. This is why simple graph heuristics can be written as linear algebra.

### 5. Zeros can mean known non-edges or unobserved pairs

A zero in $A$ is safe as a negative only if the pair was actually observed and found absent. In many graphs, especially recommendation, biology, and fraud graphs, missing edges are partly unobserved. Training every zero as a negative can teach false absence.

```python
observed_pair_mask_w = np.array([[0, 1, 1, 1],
                                 [1, 0, 1, 1],
                                 [1, 1, 0, 0],
                                 [1, 1, 0, 0]], dtype=bool)  # False means pair was not checked.
known_negative_w = (A_w == 0) & observed_pair_mask_w & (~np.eye(n_w, dtype=bool))
unobserved_pair_w = (A_w == 0) & (~observed_pair_mask_w) & (~np.eye(n_w, dtype=bool))
print("known negative pairs:", int(known_negative_w.sum() // 2))
print("unobserved pairs:", int(unobserved_pair_w.sum() // 2))
assert int(known_negative_w.sum() // 2) == 1
```
▶ What you'll see: only one absent undirected pair is a known negative; another is merely unobserved.

```python
all_zero_pairs_w = int(((A_w == 0) & (~np.eye(n_w, dtype=bool))).sum() // 2)
print("all zero off-diagonal pairs:", all_zero_pairs_w)
print("safe negatives:", int(known_negative_w.sum() // 2))
```
▶ What you'll see: treating all zeros as negatives doubles the negative evidence in this tiny example.

```python
plt.figure(figsize=(4.2, 3.2))
status_w = A_w + 2 * known_negative_w + 3 * unobserved_pair_w
plt.imshow(status_w, cmap="viridis")
plt.colorbar(label="0 self/blank, 1 edge, 2 known non-edge, 3 unobserved")
plt.title("5: not every zero has the same meaning"); plt.show()
```
▶ What you'll see: known non-edges and unobserved pairs have different colors even though both are zeros in `A`.

*Why it's done this way:* A supervised loss needs labels, not just blanks. If a zero is unobserved, using it as target 0 changes the learning problem by adding false negative labels; the mask is the mathematical object that tells the loss which pairs are allowed to count.

▶ What you'll see: two kinds of zero entries are visually separated.

👀 Takeaway: losses should use an observation mask so unobserved pairs are not silently trained as negatives.

## 🟡 Easy

### Easy 1 — Compute common-neighbor link scores

**Goal.** Score absent pairs with common neighbors, because $A^2$ gives a simple link-prediction baseline. We build it in 3 steps.

```python
A_e1 = np.array([[0, 1, 1, 0], [1, 0, 1, 1], [1, 1, 0, 0], [0, 1, 0, 0]]) # recreate the toy adjacency.
A2_e1 = A_e1 @ A_e1 # compute two-hop walk counts for common-neighbor scores.
candidates_e1 = [] # collect absent undirected pairs.
for i_e1 in range(4): # loop over source endpoint.
    for j_e1 in range(i_e1 + 1, 4): # loop over target endpoint once.
        if A_e1[i_e1, j_e1] == 0: # keep only currently absent links.
            candidates_e1.append((i_e1, j_e1)) # store the candidate pair.
```
