# 17.12 — Federated Learning

Federated learning trains a shared model without centralizing the training rows. The server sends a model to clients, clients improve it on local data, and the server aggregates the returned updates; in this lesson we build that loop from scratch with NumPy, including FedAvg, non-IID client drift, and differential-privacy-style clipping plus noise.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build federated learning one idea at a time. Run each cell in order and inspect the intermediate arrays — every update is a two-number linear model, so the server/client boundary and the math stay visible. This walkthrough is self-contained and uses a `_w` suffix so it never clashes with the examples below.

```python
import numpy as np  # arrays, gradients, aggregation, and random toy clients.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
np.random.seed(0)  # reproducibility.
```

### 1. Clients hold local data; the model travels

Federated learning starts with data partitioned by owner. We will fit a tiny model, `y_hat = w*x + b`, but each client owns its own `(x, y)` rows. In a real system those rows would remain on phones, hospitals, branches, or silos; only model parameters or updates return to the server.

```python
sizes_w = [10, 30, 60]  # client example counts.
slopes_w = [1.0, 1.8, 2.4]  # each client has a different local pattern.
rng_w = np.random.default_rng(0)  # reproducible local datasets.
clients_w = []  # list of (x, y) arrays.
for n_w, slope_w in zip(sizes_w, slopes_w):
    x_w = rng_w.normal(size=n_w)  # features on this client.
    y_w = slope_w * x_w + 0.3 + 0.1 * rng_w.normal(size=n_w)  # labels on this client.
    clients_w.append((x_w, y_w))
print("client sizes:", [len(x_w) for x_w, _ in clients_w])
print("total examples:", sum(len(x_w) for x_w, _ in clients_w))
assert sum(len(x_w) for x_w, _ in clients_w) == 100
```
▶ What you'll see: three clients with 10, 30, and 60 examples, so client 2 has most of the data volume.

```python
plt.figure(figsize=(5, 3))
for k_w, (x_w, y_w) in enumerate(clients_w):
    plt.scatter(x_w, y_w, s=18, alpha=0.7, label=f"client {k_w}: n={len(x_w)}")
plt.title("1: client datasets stay local")
plt.xlabel("x"); plt.ylabel("y")
plt.legend(); plt.show()
```
▶ What you'll see: three local data clouds; the steeper cloud belongs to the largest client.

*Why it's done this way:* The global empirical objective is still an average over examples, but the examples are grouped by client. That grouping is why client counts matter later: a client with 60 rows represents more empirical loss than a client with 10 rows unless we intentionally choose a client-fair objective instead.

### 2. A client computes an ordinary local gradient

Local training is just gradient descent on one client's loss. For `theta = [w, b]`, the client minimizes mean squared error, `mean((w*x + b - y)^2)`. The gradients are `2*mean(error*x)` for the slope and `2*mean(error)` for the bias; no central dataset is needed.

```python
def loss_grad_w(theta_w, x_w, y_w):
    pred_w = theta_w[0] * x_w + theta_w[1]  # local predictions.
    err_w = pred_w - y_w  # signed residuals.
    loss_w = float(np.mean(err_w ** 2))  # local MSE.
    grad_w = np.array([2 * np.mean(err_w * x_w), 2 * np.mean(err_w)])  # dL/dw, dL/db.
    return loss_w, grad_w

theta0_w = np.array([0.0, 0.0])  # broadcast model.
loss0_w, grad0_w = loss_grad_w(theta0_w, clients_w[0][0], clients_w[0][1])
print("client 0 loss:", round(loss0_w, 3))
print("client 0 gradient:", np.round(grad0_w, 3))
```
▶ What you'll see: the zero model has nonzero loss and a gradient telling client 0 how to move.

```python
eta_w = 0.2  # local learning rate.
theta1_w = theta0_w - eta_w * grad0_w  # one client-side gradient step.
loss1_w, _ = loss_grad_w(theta1_w, clients_w[0][0], clients_w[0][1])
print("theta before:", theta0_w)
print("theta after:", np.round(theta1_w, 3))
print("loss before -> after:", round(loss0_w, 3), "->", round(loss1_w, 3))
assert loss1_w < loss0_w
```
▶ What you'll see: one local step lowers that client's own loss.

```python
xline_w = np.linspace(-2.5, 2.5, 80)
plt.figure(figsize=(5, 3))
plt.scatter(clients_w[0][0], clients_w[0][1], s=25, alpha=0.8, label="client 0 data")
plt.plot(xline_w, theta0_w[0] * xline_w + theta0_w[1], color="gray", label="before")
plt.plot(xline_w, theta1_w[0] * xline_w + theta1_w[1], color="seagreen", label="after one local step")
plt.title("2: local training moves the model")
plt.xlabel("x"); plt.ylabel("y")
plt.legend(); plt.show()
```
▶ What you'll see: the green line tilts toward client 0's data.

*Why it's done this way:* Federated learning does not invent a new gradient formula; it moves the computation to the data owner. The privacy boundary is about what leaves the client: model updates, not rows, labels, or per-example residuals.

### 3. FedAvg aggregates client models by example count

After local training, the server needs one global model. FedAvg uses

\[
w^{r+1}=\sum_k \frac{n_k}{\sum_j n_j} w_k^{r+1}.
\]

The coefficient `n_k / N` means a larger client's returned model represents more examples in the empirical objective.

```python
def local_train_w(theta_w, x_w, y_w, steps_w=5, eta_w=0.2):
    local_w = theta_w.copy()
    for _ in range(steps_w):
        _, grad_w = loss_grad_w(local_w, x_w, y_w)
        local_w = local_w - eta_w * grad_w
    return local_w

local_models_w = np.array([local_train_w(theta0_w, x_w, y_w) for x_w, y_w in clients_w])
counts_w = np.array([len(x_w) for x_w, _ in clients_w], dtype=float)
weights_w = counts_w / counts_w.sum()
print("local models:\n", np.round(local_models_w, 3))
print("FedAvg weights:", weights_w)
assert np.allclose(weights_w, [0.1, 0.3, 0.6])
```
▶ What you'll see: each client returns a different model; the largest client gets weight 0.6.

```python
fedavg_w = weights_w @ local_models_w  # weighted average of returned models.
equalavg_w = local_models_w.mean(axis=0)  # client-balanced comparison.
manual_w = np.array([10, 30, 60]) / 100 @ np.array([[1., 0.], [0., 1.], [2., 2.]])
print("FedAvg model:", np.round(fedavg_w, 3))
print("unweighted model:", np.round(equalavg_w, 3))
print("manual content-block example:", manual_w)
assert np.allclose(manual_w, [1.3, 1.5])
```
▶ What you'll see: the concrete content-block arithmetic gives `(1.3, 1.5)`, while equal averaging would give `(1.0, 1.0)`.

```python
plt.figure(figsize=(5, 3))
plt.bar(["client0", "client1", "client2", "FedAvg", "equal"], list(local_models_w[:, 0]) + [fedavg_w[0], equalavg_w[0]], color=["gray", "gray", "gray", "seagreen", "orange"])
plt.title("3: aggregation changes the global slope")
plt.ylabel("slope parameter")
plt.xticks(rotation=20); plt.show()
```
▶ What you'll see: FedAvg is pulled closer to the large client than the equal-client average.

*Why it's done this way:* If the target objective is average loss over all rows, then client losses combine as `sum_k (n_k/N) L_k`. FedAvg mirrors that decomposition. Equal averaging is not wrong, but it optimizes a different objective: equal weight per client rather than equal weight per example.

### 4. Communication rounds repeat broadcast, local train, aggregate

A full federated run repeats the same loop: the server broadcasts `theta`, clients train locally for a few steps, and the server averages their returned models. Tracking the weighted global loss shows whether communication rounds are improving the shared model.

```python
def total_loss_w(theta_w, clients_w):
    num_w = 0.0
    den_w = 0
    for x_w, y_w in clients_w:
        loss_w, _ = loss_grad_w(theta_w, x_w, y_w)
        num_w += len(x_w) * loss_w
        den_w += len(x_w)
    return num_w / den_w

theta_round_w = theta0_w.copy()
losses_w = [total_loss_w(theta_round_w, clients_w)]
print("round 0 loss:", round(losses_w[-1], 3))
```
▶ What you'll see: the starting global loss is high.

```python
for round_w in range(20):
    returned_w = np.array([local_train_w(theta_round_w, x_w, y_w, steps_w=2, eta_w=0.15) for x_w, y_w in clients_w])
    theta_round_w = weights_w @ returned_w
    losses_w.append(total_loss_w(theta_round_w, clients_w))
print("final theta:", np.round(theta_round_w, 3))
print("loss start -> end:", round(losses_w[0], 3), "->", round(losses_w[-1], 3))
assert losses_w[-1] < losses_w[0]
```
▶ What you'll see: the weighted global MSE decreases over rounds.

```python
plt.figure(figsize=(5, 3))
plt.plot(losses_w, marker="o", color="purple")
plt.title("4: FedAvg loss over communication rounds")
plt.xlabel("round"); plt.ylabel("weighted MSE")
plt.show()
```
▶ What you'll see: loss drops quickly early and then flattens.

*Why it's done this way:* More local work reduces communication but makes each client move farther using only local information. Repeated aggregation is the correction mechanism that turns separate local progress into one shared model.

### 5. Non-IID clients create client drift

Clients are often not independent samples from the same distribution. A hospital, region, or device cohort may have systematically different data, so its local optimum differs from the global compromise. Local steps then create **client drift**: returned models spread apart before the server averages them.

```python
rng_drift_w = np.random.default_rng(1)
def make_clients_w(slopes_w):
    out_w = []
    for slope_w in slopes_w:
        x_w = rng_drift_w.normal(size=40)
        y_w = slope_w * x_w + 0.2 + 0.1 * rng_drift_w.normal(size=40)
        out_w.append((x_w, y_w))
    return out_w

iid_w = make_clients_w([1.9, 2.0, 2.1])
non_w = make_clients_w([0.5, 2.0, 3.5])
print("IID slopes are close; non-IID slopes are far apart")
```
▶ What you'll see: two scenarios with the same client sizes but different heterogeneity.

```python
def drift_w(client_set_w, local_steps_w):
    returned_w = np.array([local_train_w(np.array([0.0, 0.0]), x_w, y_w, steps_w=local_steps_w, eta_w=0.08) for x_w, y_w in client_set_w])
    center_w = returned_w.mean(axis=0)
    return float(np.mean(np.linalg.norm(returned_w - center_w, axis=1)))

step_grid_w = np.array([1, 3, 10, 25])
iid_drift_w = np.array([drift_w(iid_w, s_w) for s_w in step_grid_w])
non_drift_w = np.array([drift_w(non_w, s_w) for s_w in step_grid_w])
print("IID drift:", np.round(iid_drift_w, 3))
print("non-IID drift:", np.round(non_drift_w, 3))
assert non_drift_w[-1] > iid_drift_w[-1]
```
▶ What you'll see: non-IID drift grows larger, especially after many local steps.

```python
plt.figure(figsize=(5, 3))
plt.plot(step_grid_w, iid_drift_w, marker="o", label="IID-ish")
plt.plot(step_grid_w, non_drift_w, marker="s", label="non-IID")
plt.title("5: local steps amplify client drift")
plt.xlabel("local steps before aggregation")
plt.ylabel("mean distance among returned models")
plt.legend(); plt.show()
```
▶ What you'll see: the non-IID curve sits higher because clients walk toward different optima.

*Why it's done this way:* FedAvg treats local updates as useful approximations to global progress. Non-IID data makes those approximations biased toward different client objectives. More local steps save communication, but they also allow those biases to compound before aggregation.

### 6. Differential privacy clips and noises updates

Keeping raw rows local is not the same as guaranteeing privacy: an update can still reveal something. A simple DP-style pattern clips each client update to a maximum norm and adds Gaussian noise to the aggregate. Clipping bounds any one client's influence; noise hides exact participation at the cost of optimization accuracy.

```python
updates_w = local_models_w - theta0_w  # client deltas from the first round.
clip_w = 1.0  # maximum update norm.
norms_w = np.linalg.norm(updates_w, axis=1)
scales_w = np.minimum(1.0, clip_w / (norms_w + 1e-12))
clipped_w = updates_w * scales_w[:, None]
print("norms before:", np.round(norms_w, 3))
print("norms after:", np.round(np.linalg.norm(clipped_w, axis=1), 3))
assert np.all(np.linalg.norm(clipped_w, axis=1) <= clip_w + 1e-9)
```
▶ What you'll see: updates longer than 1.0 are rescaled to norm 1.0.

```python
rng_priv_w = np.random.default_rng(2)
clean_w = weights_w @ clipped_w
noise_w = rng_priv_w.normal(scale=0.15, size=2)
noisy_w = clean_w + noise_w
print("clean clipped aggregate:", np.round(clean_w, 3))
print("noise added:", np.round(noise_w, 3))
print("noisy aggregate:", np.round(noisy_w, 3))
```
▶ What you'll see: the noisy aggregate is close to the clean clipped aggregate but not identical.

```python
plt.figure(figsize=(5, 3))
plt.arrow(0, 0, clean_w[0], clean_w[1], color="seagreen", head_width=0.03, length_includes_head=True)
plt.arrow(0, 0, noisy_w[0], noisy_w[1], color="crimson", head_width=0.03, length_includes_head=True)
plt.scatter([clean_w[0], noisy_w[0]], [clean_w[1], noisy_w[1]], color=["seagreen", "crimson"])
plt.title("6: DP noise perturbs the aggregate update")
plt.xlabel("slope update"); plt.ylabel("bias update")
plt.legend(["clean clipped", "noisy private"])
plt.axis("equal"); plt.show()
```
▶ What you'll see: the red noisy vector is displaced from the green clean vector.

*Why it's done this way:* Privacy noise must be calibrated to sensitivity, and clipping is what bounds sensitivity. The tradeoff is mathematical and practical: stronger clipping and larger noise reduce leakage, but they also bias or randomize the update that optimization wanted to take.

```python
import numpy as np

t1_rng = np.random.default_rng(0)
```

### ✍️ Toy 2 · One client computes a local gradient

A client can compute mean-squared-error gradients using only its local rows. One gradient step moves the
broadcast model toward that client's line.

```python
import numpy as np

t2_rng = np.random.default_rng(0)
t2_x = np.array([0.0, 1.0, 2.0])
t2_y = np.array([1.0, 3.0, 5.0])
t2_theta = np.array([0.0, 0.0])
t2_pred = t2_theta[0] * t2_x + t2_theta[1]
t2_err = t2_pred - t2_y
t2_loss = float(np.mean(t2_err ** 2))
t2_grad = np.array([2 * np.mean(t2_err * t2_x), 2 * np.mean(t2_err)])
t2_eta = 0.1
t2_theta_after = t2_theta - t2_eta * t2_grad
t2_pred_after = t2_theta_after[0] * t2_x + t2_theta_after[1]
t2_err_after = t2_pred_after - t2_y
t2_loss_after = float(np.mean(t2_err_after ** 2))
print("local x:", t2_x.tolist())  # -> [0.0, 1.0, 2.0]
print("local y:", t2_y.tolist())  # -> [1.0, 3.0, 5.0]
print("theta before:", t2_theta.tolist())  # -> [0.0, 0.0]
print("predictions before:", t2_pred.tolist())  # -> [0.0, 0.0, 0.0]
print("residuals before:", t2_err.tolist())  # -> [-1.0, -3.0, -5.0]
print("loss before:", round(t2_loss, 3))  # -> 11.667
print("local gradient:", np.round(t2_grad, 3).tolist())  # -> [-8.667, -6.0]
print("learning rate:", t2_eta)  # -> 0.1
print("theta after:", np.round(t2_theta_after, 3).tolist())  # -> [0.867, 0.6]
print("predictions after:", np.round(t2_pred_after, 3).tolist())  # -> [0.6, 1.467, 2.333]
print("loss after:", round(t2_loss_after, 3))  # -> 3.207
assert t2_loss_after < t2_loss

plt.figure(figsize=(4.8, 3.0))
plt.scatter(t2_x, t2_y, s=90, label="client rows")
plt.plot(t2_x, t2_pred, color="gray", label="before")
plt.plot(t2_x, t2_pred_after, color="seagreen", label="after")
plt.xlabel("x")
plt.ylabel("y")
plt.title("Toy 2 · local step lowers local loss")
plt.legend()
plt.show()
```
▶ What you'll see: the updated line is closer to the client's three points.

### ✍️ Toy 3 · FedAvg weights by client size

FedAvg is a weighted average of returned client models. Larger clients receive larger weights when the
objective is average loss over rows.

```python
import numpy as np

t3_rng = np.random.default_rng(0)
t3_local_models = np.array([[1.0, 0.0], [2.0, 0.5], [4.0, 1.0]])
t3_counts = np.array([2.0, 3.0, 5.0])
t3_weights = t3_counts / t3_counts.sum()
t3_fedavg = t3_weights @ t3_local_models
t3_equalavg = t3_local_models.mean(axis=0)
print("local models:", t3_local_models.tolist())  # -> [[1.0, 0.0], [2.0, 0.5], [4.0, 1.0]]
print("client counts:", t3_counts.tolist())  # -> [2.0, 3.0, 5.0]
print("FedAvg weights:", t3_weights.tolist())  # -> [0.2, 0.3, 0.5]
print("FedAvg model:", t3_fedavg.tolist())  # -> [2.8, 0.65]
print("equal-client model:", np.round(t3_equalavg, 3).tolist())  # -> [2.333, 0.5]
assert np.allclose(t3_fedavg, [2.8, 0.65])

plt.figure(figsize=(4.6, 2.8))
plt.bar(["c0", "c1", "c2", "FedAvg", "equal"], list(t3_local_models[:, 0]) + [t3_fedavg[0], t3_equalavg[0]], color=["gray", "gray", "gray", "seagreen", "orange"])
plt.ylabel("slope parameter")
plt.title("Toy 3 · larger clients pull the average")
plt.xticks(rotation=20)
plt.show()
```
▶ What you'll see: the FedAvg slope is closer to the largest client's slope than the equal average is.

### ✍️ Toy 4 · Rounds repeat local move then aggregate

Communication rounds repeatedly broadcast the current scalar model, let clients move toward their local
targets, and average the returned scalars.

```python
import numpy as np

t4_rng = np.random.default_rng(0)
t4_targets = np.array([1.0, 2.0, 3.0])
t4_weights = np.array([0.25, 0.25, 0.50])
t4_eta = 0.5
t4_theta = 0.0
t4_thetas = [t4_theta]
t4_losses = []
for t4_round in range(4):
    t4_loss = float(np.sum(t4_weights * (t4_theta - t4_targets) ** 2))
    t4_losses.append(t4_loss)
    t4_returned = t4_theta + t4_eta * (t4_targets - t4_theta)
    t4_theta = float(t4_weights @ t4_returned)
    t4_thetas.append(t4_theta)
t4_final_loss = float(np.sum(t4_weights * (t4_theta - t4_targets) ** 2))
t4_losses.append(t4_final_loss)
print("client target scalars:", t4_targets.tolist())  # -> [1.0, 2.0, 3.0]
print("aggregation weights:", t4_weights.tolist())  # -> [0.25, 0.25, 0.5]
print("local step size:", t4_eta)  # -> 0.5
print("server theta trajectory:", np.round(t4_thetas, 3).tolist())  # -> [0.0, 1.125, 1.688, 1.969, 2.109]
print("weighted losses:", np.round(t4_losses, 3).tolist())  # -> [5.75, 1.953, 1.004, 0.767, 0.707]
assert t4_losses[-1] < t4_losses[0]

plt.figure(figsize=(4.8, 2.8))
plt.plot(np.arange(len(t4_losses)), t4_losses, marker="o", color="purple")
plt.xlabel("round")
plt.ylabel("weighted loss")
plt.title("Toy 4 · repeated rounds reduce loss")
plt.show()
```
▶ What you'll see: the weighted loss drops quickly, then flattens near the weighted compromise.

### ✍️ Toy 5 · Non-IID clients drift apart

Returned local models spread more when clients have different local optima. Measure average distance
from the client-model center in IID-ish and non-IID settings.

```python
import numpy as np

t5_rng = np.random.default_rng(0)
t5_iid_models = np.array([[1.0, 0.1], [1.1, 0.0], [0.9, -0.1]])
t5_non_iid_models = np.array([[0.0, 0.0], [2.0, 0.2], [4.0, -0.2]])
t5_iid_center = t5_iid_models.mean(axis=0)
t5_non_iid_center = t5_non_iid_models.mean(axis=0)
t5_iid_dist = np.linalg.norm(t5_iid_models - t5_iid_center, axis=1)
t5_non_iid_dist = np.linalg.norm(t5_non_iid_models - t5_non_iid_center, axis=1)
t5_iid_drift = float(t5_iid_dist.mean())
t5_non_iid_drift = float(t5_non_iid_dist.mean())
print("IID-ish models:", t5_iid_models.tolist())  # -> [[1.0, 0.1], [1.1, 0.0], [0.9, -0.1]]
print("non-IID models:", t5_non_iid_models.tolist())  # -> [[0.0, 0.0], [2.0, 0.2], [4.0, -0.2]]
```

### ✍️ Toy 6 · Clipping bounds updates before noise

Privacy-style aggregation clips long client updates to a fixed norm before adding Gaussian noise to the
aggregate. The bound makes each client's influence finite.

```python
import numpy as np

t6_rng = np.random.default_rng(0)
t6_updates = np.array([[0.6, 0.8], [2.0, 0.0], [0.3, 0.4]])
t6_norms = np.linalg.norm(t6_updates, axis=1)
t6_clip = 1.0
t6_scales = np.minimum(1.0, t6_clip / (t6_norms + 1e-12))
t6_clipped = t6_updates * t6_scales[:, None]
t6_weights = np.array([0.2, 0.5, 0.3])
t6_clean = t6_weights @ t6_clipped
t6_noise = t6_rng.normal(0.0, 0.05, size=2)
t6_noisy = t6_clean + t6_noise
print("client updates:", t6_updates.tolist())  # -> [[0.6, 0.8], [2.0, 0.0], [0.3, 0.4]]
print("update norms:", np.round(t6_norms, 3).tolist())  # -> [1.0, 2.0, 0.5]
print("clip norm:", t6_clip)  # -> 1.0
print("clip scales:", np.round(t6_scales, 3).tolist())  # -> [1.0, 0.5, 1.0]
print("clipped updates:", np.round(t6_clipped, 3).tolist())  # -> [[0.6, 0.8], [1.0, 0.0], [0.3, 0.4]]
print("aggregation weights:", t6_weights.tolist())  # -> [0.2, 0.5, 0.3]
print("clean clipped aggregate:", np.round(t6_clean, 3).tolist())  # -> [0.71, 0.28]
print("Gaussian noise:", np.round(t6_noise, 3).tolist())  # -> [0.006, -0.007]
print("noisy aggregate:", np.round(t6_noisy, 3).tolist())  # -> [0.716, 0.273]
assert np.all(np.linalg.norm(t6_clipped, axis=1) <= t6_clip + 1e-9)

plt.figure(figsize=(4.8, 3.0))
plt.arrow(0, 0, t6_clean[0], t6_clean[1], color="seagreen", head_width=0.03, length_includes_head=True)
plt.arrow(0, 0, t6_noisy[0], t6_noisy[1], color="crimson", head_width=0.03, length_includes_head=True)
plt.scatter([t6_clean[0], t6_noisy[0]], [t6_clean[1], t6_noisy[1]], color=["seagreen", "crimson"])
plt.xlabel("slope update")
plt.ylabel("bias update")
plt.title("Toy 6 · noise perturbs a clipped aggregate")

```

### Advanced 1 — Sweep local steps and drift

**Goal.** Vary local work before aggregation, because more local steps can worsen non-IID drift. We build it in 4 steps.


▶ What you'll see: a range from nearly synchronous to many local steps.

```python

    err_a1 = theta_a1[0] * x_a1 + theta_a1[1] - y_a1

def returned_a1(step_count_a1):

print("helpers ready")
```

### Advanced 2 — Compare IID and non-IID training curves

**Goal.** Run the same FedAvg code on IID-ish and non-IID clients, because heterogeneity changes optimization behavior. We build it in 5 steps.

```python
def grad_a2(theta_a2, x_a2, y_a2):
    err_a2 = theta_a2[0] * x_a2 + theta_a2[1] - y_a2
    return np.array([2 * np.mean(err_a2 * x_a2), 2 * np.mean(err_a2)])

    return float(np.mean([np.mean((theta_a2[0] * x_a2 + theta_a2[1] - y_a2) ** 2) for x_a2, y_a2 in clients_a2]))
```


### Advanced 5 — Client sampling variance

**Goal.** Aggregate random subsets of clients, because real FL rounds often involve partial participation. We build it in 5 steps.
