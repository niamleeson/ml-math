# 5.22 — Dirichlet Processes

A Dirichlet process (DP) is a Bayesian prior for clustering when we do not want to choose the number of clusters in advance. The prior has countably many possible atoms, but any finite dataset uses only finitely many of them; the key mechanics are rich-get-richer assignment, a persistent new-cluster option controlled by α, and a base distribution that says what a brand-new cluster should look like.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build Dirichlet processes one idea at a time. Run each cell in order and read the printed intermediate values — every probability is normalized in the open so the “infinite clusters” idea never becomes a black box. This walkthrough is self-contained (it imports what it needs) and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays, random choices, and small numerical checks.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
np.random.seed(0)  # reproducibility for simulated restaurant seating.
```

### 1. Clustering when K is not fixed

Ordinary mixture models make us choose a fixed number of clusters K before seeing the data. A Dirichlet process starts from a different promise: keep a prior with endlessly many possible clusters, but let a finite dataset occupy only the clusters it actually needs. We will represent the occupied clusters by their current counts, because the predictive rule depends only on those counts and α.

```python
counts_w = np.array([3, 1])  # two currently occupied clusters with 3 and 1 observations.
alpha_w = 2.0  # concentration: the persistent weight assigned to opening a new cluster.
n_w = int(counts_w.sum())  # total observations currently seated in occupied clusters.
print("occupied cluster counts:", counts_w)  # inspect finite occupancy.
print("n:", n_w, "alpha:", alpha_w)  # inspect evidence size and prior-new weight.
```
▶ What you'll see: only two clusters are occupied, even though the DP prior can always offer another one.

```python
plt.figure(figsize=(4.4, 3))  # compact count visualization.
plt.bar(["cluster 0", "cluster 1", "new option"], [counts_w[0], counts_w[1], alpha_w], color=["teal", "teal", "orange"])  # show evidence weights plus prior-new weight.
plt.title("1: occupied clusters plus a new-cluster option")  # label the DP ingredients.
plt.ylabel("unnormalized weight")  # counts and alpha are local weights before normalization.
plt.show()  # display the bar chart.
```
▶ What you'll see: the new option has weight α=2, so it remains possible even before any observations join it.

*Why it's done this way:* a finite mixture would store K probabilities for K predeclared clusters. A DP predictive rule stores only occupied counts plus α; that is the finite computation that stands in for the countably infinite prior.

### 2. The Chinese restaurant predictive rule

The Chinese restaurant process view says the next observation joins an existing cluster with probability proportional to its count, or starts a new cluster with probability proportional to α. The formula is

$$P(z_{n+1}=k\mid z_{1:n})=\frac{n_k}{n+\alpha},\qquad P(z_{n+1}=\text{new})=\frac{\alpha}{n+\alpha}.$$

The denominator is not mysterious: it is just the sum of all local weights, `sum(counts) + alpha`, so the probabilities add to 1.

```python
weights_w = np.append(counts_w, alpha_w)  # existing-cluster weights plus the new-cluster weight.
den_w = n_w + alpha_w  # normalizer: total count plus alpha.
probs_w = weights_w / den_w  # convert weights into predictive probabilities.
print("weights:", weights_w)  # [3, 1, 2].
print("denominator:", den_w)  # 6.
print("probabilities:", np.round(probs_w, 3))  # [0.500, 0.167, 0.333].
assert np.allclose(np.round(probs_w, 3), [0.500, 0.167, 0.333])  # verify the lesson arithmetic.
```
▶ What you'll see: `[3/6, 1/6, 2/6] = [0.500, 0.167, 0.333]`.

```python
plt.figure(figsize=(4.4, 3))  # compare normalized probabilities.
plt.bar(["cluster 0", "cluster 1", "new"], probs_w, color=["seagreen", "seagreen", "darkorange"])  # plot the predictive distribution.
plt.ylim(0, 0.6)  # keep the probability scale easy to read.
plt.title("2: CRP predictive probabilities")  # title the normalized result.
plt.ylabel("probability")  # y-axis is now a probability, not a raw count.
plt.show()  # display the predictive distribution.
```
▶ What you'll see: cluster 0 is most likely because it already has the largest count, while new still has one-third probability.

*Why it's done this way:* counts are evidence accumulated from the data, α is prior pressure toward novelty, and dividing by `n+α` turns those two kinds of weight into one valid probability distribution.

### 3. Rich-get-richer is probability, not magic

“Rich-get-richer” means a bigger cluster receives a bigger predictive probability because its count is larger. If cluster 0 has count 3 and cluster 1 has count 1, cluster 0 is three times as likely as cluster 1 before considering the new option. This is reinforcement: early assignments can make a cluster easier to reuse later.

```python
ratio_w = probs_w[0] / probs_w[1]  # compare cluster 0 and cluster 1 predictive probabilities.
print("P(cluster 0):", round(probs_w[0], 3))  # 0.5.
print("P(cluster 1):", round(probs_w[1], 3))  # 0.167.
print("probability ratio:", round(ratio_w, 1))  # 3.0.
assert round(ratio_w, 1) == 3.0  # count ratio 3:1 becomes probability ratio 3:1.
```
▶ What you'll see: the probability ratio exactly matches the count ratio, because both existing clusters share the same denominator.

```python
new_counts_w = counts_w.copy()  # copy counts before seating one more observation.
new_counts_w[0] += 1  # pretend the next observation joined cluster 0.
new_probs_w = np.append(new_counts_w, alpha_w) / (new_counts_w.sum() + alpha_w)  # recompute the predictive probabilities.
print("after cluster 0 gains one:", new_counts_w)  # [4, 1].
print("new probabilities:", np.round(new_probs_w, 3))  # cluster 0 becomes even more likely.
```
▶ What you'll see: cluster 0's probability rises after it receives another observation.

```python
plt.figure(figsize=(4.8, 3))  # grouped comparison of before and after.
x_w = np.arange(3)  # three choices: cluster 0, cluster 1, new.
plt.bar(x_w - 0.18, probs_w, width=0.36, label="before", color="gray")  # original probabilities.
plt.bar(x_w + 0.18, new_probs_w, width=0.36, label="after c0 + 1", color="seagreen")  # reinforced probabilities.
plt.xticks(x_w, ["c0", "c1", "new"])  # readable labels.
plt.title("3: reinforcement from one extra assignment")  # title the rich-get-richer effect.
plt.ylabel("probability")  # compare probability mass.
plt.legend()  # show before/after labels.
plt.show()  # display the plot.
```
▶ What you'll see: the c0 bar grows, while all probabilities renormalize because the denominator also changed.

*Why it's done this way:* the DP does not pre-score clusters by semantic quality. It uses exchangeable evidence: a cluster with more assigned observations has more posterior mass because more data have already supported that atom.

### 4. α controls the new-cluster tendency

The concentration parameter α is the weight of the new-cluster option. It does not make clusters “better” or “more meaningful”; it changes how often the prior is willing to open a new one. With fixed n, larger α makes novelty more probable; with fixed α, the new-cluster probability shrinks as n grows.

```python
alpha_grid_w = np.array([0.2, 1.0, 2.0, 5.0, 10.0])  # different prior novelty strengths.
new_prob_grid_w = alpha_grid_w / (n_w + alpha_grid_w)  # P(new) for the same current data size n=4.
print("alphas:", alpha_grid_w)  # inspect α values.
print("P(new | n=4):", np.round(new_prob_grid_w, 3))  # larger α means more novelty.
```
▶ What you'll see: P(new) rises from small to large as α increases.

```python
n_grid_w = np.array([0, 1, 2, 5, 10, 50, 100])  # dataset sizes after n customers.
alpha_fixed_w = 2.0  # the lesson's worked alpha.
new_over_n_w = alpha_fixed_w / (alpha_fixed_w + n_grid_w)  # P(new) = 2/(2+n).
print("n values:", n_grid_w)  # inspect data sizes.
print("P(new) with alpha=2:", np.round(new_over_n_w, 3))  # verify decay with n.
assert round(float(new_over_n_w[-1]), 3) == 0.020  # 2/(2+100) = 0.0196.
```
▶ What you'll see: the new-cluster option persists but becomes less likely as more observations accumulate.

```python
plt.figure(figsize=(5, 3))  # line plot for the decay.
plt.plot(n_grid_w, new_over_n_w, marker="o", color="darkorange")  # plot P(new) against n.
plt.title("4: P(new)=α/(α+n) for α=2")  # title with the formula.
plt.xlabel("current observations n")  # x-axis is data size.
plt.ylabel("new-cluster probability")  # y-axis is novelty probability.
plt.show()  # display the decay curve.
```
▶ What you'll see: a steep early drop and a long tail — new clusters remain possible, just less probable.

*Why it's done this way:* α is a prior pseudo-count for an unseen atom. As real counts grow, observed evidence dominates; as α grows, prior willingness to create novelty stays stronger.

### 5. The base distribution says what “new” means

The CRP probabilities decide whether a new cluster is opened, but not what parameter that cluster has. The base distribution supplies the parameter for a new atom. In a toy one-dimensional setting, we can make the base distribution over cluster means have mean 0.5, so a brand-new cluster predicts like a moderate unknown cluster until data arrive.

```python
cluster_means_w = np.array([0.2, 0.8])  # current atom parameters for the two occupied clusters.
base_mean_w = 0.5  # expected parameter value for a brand-new cluster under the base distribution.
print("existing atom means:", cluster_means_w)  # inspect learned/occupied atom parameters.
print("base mean for a new atom:", base_mean_w)  # inspect what novelty predicts before data.
```
▶ What you'll see: existing clusters have concrete means, while a new cluster is summarized by the base expectation.

```python
predictive_mean_w = float((counts_w[0] * cluster_means_w[0] + counts_w[1] * cluster_means_w[1] + alpha_w * base_mean_w) / den_w)  # weighted DP predictive mean.
print("predictive mean:", round(predictive_mean_w, 3))  # (3*0.2 + 1*0.8 + 2*0.5)/6 = 0.4.
assert round(predictive_mean_w, 3) == 0.400  # verify the lesson arithmetic.
```
▶ What you'll see: the predictive mean is 0.400, blending evidence from occupied atoms with the base distribution.

```python
plt.figure(figsize=(4.8, 3))  # visualize weighted ingredients.
plt.bar(["3×0.2", "1×0.8", "2×0.5"], [counts_w[0] * cluster_means_w[0], counts_w[1] * cluster_means_w[1], alpha_w * base_mean_w], color=["teal", "teal", "orange"])  # numerator pieces.
plt.title("5: numerator pieces for the DP predictive mean")  # title the arithmetic.
plt.ylabel("weighted contribution")  # contribution before division by 6.
plt.show()  # display the weighted pieces.
```
▶ What you'll see: the base-distribution term contributes exactly like α pseudo-observations at mean 0.5.

*Why it's done this way:* the base distribution is the prior over atom parameters, so it shapes novelty. Ignoring it explains where new clusters come from probabilistically but not what those clusters predict.

### 6. Finite data occupy finitely many clusters

A common pitfall is saying a DP means the data have infinitely many clusters. The prior has countably many possible atoms, but a dataset of n observations can occupy at most n clusters. In expectation, the number grows slowly; for α=2 and n=100 it is between 8 and 9, not anywhere near 100.

```python
def expected_clusters_w(alpha, n):  # compute E[K_n] = sum_{i=1}^n alpha/(alpha+i-1).
    i = np.arange(1, n + 1)  # customer indices from 1 to n.
    return float(np.sum(alpha / (alpha + i - 1)))  # sum opening probabilities.

expected_100_w = expected_clusters_w(2.0, 100)  # expected occupied clusters at n=100.
print("E[K_100] for alpha=2:", round(expected_100_w, 3))  # between 8 and 9.
assert 8.0 < expected_100_w < 9.0  # verify the lesson statement.
```
▶ What you'll see: the expected number of occupied clusters is about 8.395.

```python
ns_w = np.arange(1, 101)  # dataset sizes from 1 to 100.
Ek_w = np.array([expected_clusters_w(2.0, int(n)) for n in ns_w])  # expected occupied clusters for each size.
print("E[K_10], E[K_100]:", round(Ek_w[9], 3), round(Ek_w[-1], 3))  # inspect slow growth.
```
▶ What you'll see: expected clusters grow, but much slower than the number of observations.

```python
plt.figure(figsize=(5, 3))  # plot expected cluster growth.
plt.plot(ns_w, Ek_w, color="purple")  # draw E[K_n].
plt.plot(ns_w, ns_w, color="gray", linestyle="--", label="maximum n")  # show the absolute upper bound.
plt.title("6: finite data use finitely many DP clusters")  # title the finite-occupancy point.
plt.xlabel("observations n")  # x-axis is dataset size.
plt.ylabel("expected occupied clusters")  # y-axis is E[K_n].
plt.legend()  # show upper-bound label.
plt.show()  # display the curve.
```
▶ What you'll see: the DP curve stays far below the `K=n` upper bound.

*Why it's done this way:* each new observation has a nonzero chance to open a cluster, but that chance decays like α/(α+n). Summing those chances gives slow, finite growth rather than infinite occupancy in finite data.

### ✍️ Toy 2 · CRP weights normalize into probabilities

The Chinese restaurant predictive rule divides every existing count and the new-cluster weight by
`n + alpha`.

```python
import numpy as np                              # arrays + checks (safe to repeat).

t2_rng = np.random.default_rng(0)               # seeded generator for reproducibility.
t2_counts = np.array([4, 2, 1])                 # occupied counts

plt.ylabel("probability")
plt.title("Toy 2 · normalize counts plus alpha")
```

## 🟢 Basics (warm-up)

### Basic 1 — Normalize cluster weights

**Goal.** Convert occupied counts plus α into probabilities, because the DP predictive rule is just normalized local weight. We build it in 2 steps.

```python
counts_b1 = np.array([3, 1])  # store occupied cluster counts.
alpha_b1 = 2.0  # store the new-cluster weight.
weights_b1 = np.append(counts_b1, alpha_b1)  # append the new option to the existing counts.
print("weights:", weights_b1)  # inspect unnormalized evidence and prior weight.
```
▶ What you'll see: `[3, 1, 2]`, where the final entry is α rather than an observed count.

```python
probs_b1 = weights_b1 / weights_b1.sum()  # normalize weights into probabilities.
print("probabilities:", np.round(probs_b1, 3))  # inspect the CRP predictive probabilities.
```

### Advanced 1 — Approximate the CRP distribution of K

**Goal.** Simulate many CRP paths to estimate the distribution of occupied cluster counts, because a DP prior induces uncertainty over K rather than choosing one K. We build it in 4 steps.

```python
def final_k_a1(alpha_a1, n_a1, seed_a1):  # simulate one CRP path and return final occupied clusters.
    rng_a1 = np.random.default_rng(seed_a1)  # local deterministic random generator.
    counts_a1 = np.array([], dtype=int)  # start with no occupied clusters.
    for _ in range(n_a1):  # seat n observations.
```

### Advanced 4 — Use CRP weights with data likelihoods

**Goal.** Combine DP prior weights with likelihood scores, because clustering observations uses both how popular a cluster is and how well it explains the new data point. We build it in 4 steps.

```python
x_a4 = 0.62  # new one-dimensional observation to assign.
counts_a4 = np.array([3, 1])  # occupied-cluster prior counts.
means_a4 = np.array([0.2, 0.8])  # occupied cluster means.
base_mean_a4 = 0.5  # base mean for the new cluster.
alpha_a4 = 2.0  # new-cluster prior weight.
sigma_a4 = 0.20  # shared likelihood scale for a simple Gaussian-shaped score.
print("x:", x_a4, "means:", means_a4, "base:", base_mean_a4)  # inspect assignment ingredients.
```
▶ What you'll see: the observation lies closer to cluster 1 and the base mean than to cluster 0.

```python
centers_a4 = np.append(means_a4, base_mean_a4)  # possible centers: old atoms plus new-base expectation.
prior_weights_a4 = np.append(counts_a4, alpha_a4)  # CRP local prior weights.
like_a4 = np.exp(-0.5 * ((x_a4 - centers_a4) / sigma_a4) ** 2)  # unnormalized Gaussian-shaped likelihoods without SciPy.
print("likelihood scores:", np.round(like_a4, 3))  # inspect data fit for each option.
```

```python
posterior_scores_a4 = prior_weights_a4 * like_a4  # combine DP prior weight and data likelihood.
posterior_probs_a4 = posterior_scores_a4 / posterior_scores_a4.sum()  # normalize assignment probabilities.
print("posterior assignment probabilities:", np.round(posterior_probs_a4, 3))  # inspect final assignment rule.
assert abs(float(posterior_probs_a4.sum()) - 1.0) < 1e-12  # probabilities are normalized.
```

```python
plt.figure(figsize=(5, 3))  # create assignment comparison.
xpos_a4 = np.arange(3)  # positions for old0, old1, new.
plt.bar(xpos_a4 - 0.18, prior_weights_a4 / prior_weights_a4.sum(), width=0.36, label="CRP prior", color="gray")  # prior-only probabilities.
plt.bar(xpos_a4 + 0.18, posterior_probs_a4, width=0.36, label="with likelihood", color="teal")  # posterior probabilities.
plt.xticks(xpos_a4, ["c0", "c1", "new"])  # label options.
plt.title("Advanced 4: prior × likelihood")  # title the inference step.
plt.ylabel("probability")  # label probability.
plt.legend()  # show bars.
plt.show()  # display the comparison.
```
▶ What you'll see: cluster popularity helps, but a poor data likelihood can reduce a popular cluster's final assignment probability.

👀 Takeaway: DP mixture assignment is not counts alone; posterior clustering multiplies CRP weights by how well each cluster explains the data.
