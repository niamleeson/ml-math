# 24.1 — Genetic Algorithms

Genetic algorithms (GAs) search when the objective is a black box: we can score a candidate, but we may not have gradients, smoothness, or even a continuous representation. In this lesson, a population of candidates improves by fitness-based selection, crossover, mutation, and elitism while we watch both performance and diversity.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build genetic algorithms one idea at a time. Run each cell in order and read the printed intermediate values — every moving part of the evolutionary loop is shown explicitly. This walkthrough is self-contained and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays, random sampling, and vectorized fitness calculations.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
np.random.seed(0)  # reproducibility for every random choice in the walkthrough.
```

### 1. Black-box fitness on a rugged search landscape

A genetic algorithm begins with a **fitness function**: a scalar score we want to maximize. The important assumption is not that the function is biological; it is that the function can be evaluated without giving us a convenient gradient. Here the candidate is one real number `x`, and the landscape has a broad quadratic pull toward `x=3` plus a small ripple. We can score any point, but the algorithm will only see scores for the population it samples.

```python
def fitness_w(x):  # Define a black-box objective to maximize.
    x = np.asarray(x, dtype=float)  # Convert scalars or arrays to NumPy values.
    return -(x - 3.0) ** 2 + 10.0 + 0.7 * np.sin(3.0 * x)  # Smooth hill plus local wiggles.

xs_w = np.linspace(-1.0, 7.0, 300)  # Create many x-values only for visualization.
ys_w = fitness_w(xs_w)  # Evaluate the landscape on the plotting grid.
best_grid_x_w = xs_w[np.argmax(ys_w)]  # Find the best grid point for a reference line.
print("best grid x:", round(float(best_grid_x_w), 3), "fitness:", round(float(np.max(ys_w)), 3))  # Inspect the target region.
assert 2.0 < best_grid_x_w < 4.0  # Verify the maximum is in the intended basin near x=3.
```
▶ What you'll see: the best grid point is near the central hill, but the ripple means the landscape is not a perfectly simple bowl.

```python
plt.figure(figsize=(5, 3))  # Create a compact landscape plot.
plt.plot(xs_w, ys_w, color="navy")  # Draw the full objective only so we can understand the toy problem.
plt.axvline(best_grid_x_w, color="crimson", linestyle="--", label="best grid point")  # Mark the visual optimum.
plt.title("1: black-box fitness landscape")  # Title the concept figure.
plt.xlabel("candidate x")  # Label candidate values.
plt.ylabel("fitness F(x)")  # Label the score to maximize.
plt.legend()  # Show the optimum marker label.
plt.show()  # Display the landscape.
```
▶ What you'll see: a high central region with small local wiggles — exactly the kind of surface where population search is useful.

*Why it's done this way: GAs only require a score, so the same loop can optimize discontinuous, noisy, or choice-based candidates where gradient descent is not available.*

### 2. A population is a distribution of guesses

Instead of keeping one current solution, a GA keeps a **population**. This spreads the evaluation budget across many guesses, which matters because the first good basin may not be the best basin. We start with eight candidates sampled uniformly across the search interval, evaluate all of them, and inspect both their scores and their spread.

```python
rng_w = np.random.default_rng(1)  # Use a local generator so this concept is reproducible.
pop_w = rng_w.uniform(-1.0, 7.0, size=8)  # Sample an initial population of candidate x-values.
fit_w = fitness_w(pop_w)  # Score every candidate independently.
print("population:", np.round(pop_w, 3))  # Inspect the candidates.
print("fitness:", np.round(fit_w, 3))  # Inspect the scores that selection will use.
assert len(pop_w) == len(fit_w) == 8  # Verify every candidate has one fitness value.
```
▶ What you'll see: the population covers several regions, and candidates nearer the central hill already score better.

```python
plt.figure(figsize=(5, 3))  # Create a landscape-plus-population figure.
plt.plot(xs_w, ys_w, color="lightgray", label="fitness landscape")  # Draw the background objective.
plt.scatter(pop_w, fit_w, s=70, color="teal", zorder=3, label="population")  # Draw evaluated candidates.
plt.title("2: population samples the landscape")  # Title the population view.
plt.xlabel("candidate x")  # Label candidate values.
plt.ylabel("fitness")  # Label candidate scores.
plt.legend()  # Show plot labels.
plt.show()  # Display the evaluated population.
```
▶ What you'll see: the algorithm sees scattered scored candidates, not a continuous curve or a derivative.

*Why it's done this way: a population stores search diversity as actual candidate spread, giving selection and mutation raw material to improve without committing to one trajectory too early.*

### 3. Probabilistic selection turns fitness into reproduction chances

Selection says better candidates should reproduce more often, but not always. A common rule shifts all fitness values positive and normalizes them into probabilities:

$$p_i=\frac{F(x_i)-\min_j F(x_j)+1}{\sum_k (F(x_k)-\min_j F(x_j)+1)}.$$

The `+1` keeps even weak candidates alive with a small chance, which protects diversity from winner-take-all collapse.

```python
x_sel_w = np.array([0.0, 2.0, 4.0, 6.0])  # Use the verified tiny landscape candidates.
fit_sel_w = -(x_sel_w - 3.0) ** 2 + 10.0  # Use the simple lesson fitness for exact probabilities.
weights_w = fit_sel_w - np.min(fit_sel_w) + 1.0  # Shift fitness so every candidate has positive weight.
prob_w = weights_w / np.sum(weights_w)  # Normalize weights into selection probabilities.
print("fitness:", fit_sel_w)  # Inspect raw fitness values.
print("selection probabilities:", np.round(prob_w, 3))  # Inspect reproduction probabilities.
assert np.allclose(prob_w, np.array([0.05, 0.45, 0.45, 0.05]))  # Verify the lesson probabilities.
```
▶ What you'll see: candidates at 2 and 4 get 45% each, while edge candidates keep 5% each.

```python
plt.figure(figsize=(5, 3))  # Create a probability bar chart.
plt.bar(["x=0", "x=2", "x=4", "x=6"], prob_w, color="seagreen")  # Show selection probabilities.
plt.title("3: fitness-proportionate selection")  # Title the selection plot.
plt.ylabel("parent probability")  # Label the normalized probability axis.
plt.ylim(0, 0.55)  # Keep the scale readable.
plt.show()  # Display the probabilities.
```
▶ What you'll see: high-fitness candidates receive more reproduction tickets, but low-fitness candidates are not silenced.

*Why it's done this way: probabilistic selection balances exploitation of good candidates with occasional exploration from weaker candidates that may carry useful genetic material.*

### 4. Crossover recombines partial discoveries

Crossover builds a child from two parents. For real-valued candidates, the simplest crossover is averaging. If one parent is on the left side of the optimum and one is on the right, the average can land closer to the peak than either parent. Crossover is not magic; it is a structured way to reuse useful pieces instead of restarting every child from scratch.

```python
parents_w = np.array([2.0, 4.0])  # Choose two strong parents around the optimum.
child_cross_w = np.mean(parents_w)  # Average crossover creates a midpoint child.
fitness_parts_w = np.array([-(parents_w[0] - 3.0) ** 2 + 10.0, -(parents_w[1] - 3.0) ** 2 + 10.0, -(child_cross_w - 3.0) ** 2 + 10.0])  # Score parents and child.
print("parents:", parents_w, "child after crossover:", child_cross_w)  # Inspect the recombination result.
print("fitness parent/parent/child:", fitness_parts_w)  # Inspect whether the child improves.
assert child_cross_w == 3.0 and fitness_parts_w[-1] == 10.0  # Verify midpoint crossover reaches the peak in this simple case.
```
▶ What you'll see: averaging parents 2 and 4 creates child 3, which is optimal for the simple quadratic.

```python
plt.figure(figsize=(5, 3))  # Create a crossover illustration.
plt.plot(x_sel_w, fit_sel_w, color="lightgray", marker="o", label="simple fitness")  # Draw the four-point landscape.
plt.scatter(parents_w, fitness_parts_w[:2], s=90, color="steelblue", label="parents")  # Mark the selected parents.
plt.scatter([child_cross_w], [fitness_parts_w[2]], s=110, color="crimson", marker="*", label="crossover child")  # Mark the child.
plt.title("4: crossover can land between good parents")  # Title the crossover plot.
plt.xlabel("candidate x")  # Label candidate values.
plt.ylabel("fitness")  # Label score.
plt.legend()  # Show point meanings.
plt.show()  # Display the recombination figure.
```
▶ What you'll see: the child lands between the parents and at the top of this toy hill.

*Why it's done this way: crossover exploits structure discovered by the population, combining parent information instead of relying entirely on random mutation.*

### 5. Mutation preserves exploration after crossover

Mutation perturbs a child after crossover. It is the main force that introduces new values not already present in the population. The scale matters: tiny mutation cannot escape a local basin, while huge mutation destroys inherited structure. We add a fixed `+0.5` mutation to the averaged child so the arithmetic matches the lesson's worked example.

```python
mutation_w = 0.5  # Use the verified mutation size from the lesson text.
child_mut_w = child_cross_w + mutation_w  # Mutate the crossover child.
child_fit_w = -(child_mut_w - 3.0) ** 2 + 10.0  # Score the mutated child on the simple fitness.
print("crossover child:", child_cross_w, "mutation:", mutation_w, "mutated child:", child_mut_w)  # Inspect the mutation.
print("mutated child fitness:", child_fit_w)  # Inspect the resulting score.
assert child_mut_w == 3.5 and child_fit_w == 9.75  # Verify the lesson arithmetic.
```
▶ What you'll see: the mutated child moves from 3.0 to 3.5 and still has high fitness 9.75.

```python
plt.figure(figsize=(5, 3))  # Create a mutation illustration.
plt.plot(xs_w, -(xs_w - 3.0) ** 2 + 10.0, color="lightgray")  # Draw the simple quadratic used for the arithmetic.
plt.scatter([child_cross_w], [10.0], s=90, color="steelblue", label="after crossover")  # Mark the unmutated child.
plt.arrow(child_cross_w, 9.7, mutation_w, 0, head_width=0.15, color="crimson", length_includes_head=True)  # Show the mutation step horizontally.
plt.scatter([child_mut_w], [child_fit_w], s=90, color="crimson", label="after mutation")  # Mark the mutated child.
plt.title("5: mutation perturbs the child")  # Title the mutation plot.
plt.xlabel("candidate x")  # Label candidate values.
plt.ylabel("fitness")  # Label score.
plt.legend()  # Show point labels.
plt.show()  # Display the mutation figure.
```
▶ What you'll see: mutation moves the child away from the inherited midpoint while keeping it in the good basin.

*Why it's done this way: mutation is the exploration engine, adding controlled randomness so the population can recover from premature convergence.*

### 6. Elitism protects the best-so-far candidate

Because selection, crossover, and mutation are stochastic, a generation can accidentally lose the best candidate it has discovered. **Elitism** copies one or more top candidates directly into the next generation before filling the remaining slots with children. This is a safety rule: exploration can be noisy, but progress should not vanish by bad luck.

```python
pop_elite_w = np.array([0.2, 1.5, 2.9, 5.5, 6.8])  # Create a small population with one excellent candidate.
fit_elite_w = -(pop_elite_w - 3.0) ** 2 + 10.0  # Score the population on the simple fitness.
elite_idx_w = int(np.argmax(fit_elite_w))  # Find the best candidate.
elite_w = pop_elite_w[elite_idx_w]  # Copy the elite candidate.
children_noisy_w = np.array([1.8, 2.2, 3.7, 4.5, 6.0])  # Pretend stochastic reproduction made these children.
next_elite_w = children_noisy_w.copy()  # Start from the noisy children.
next_elite_w[0] = elite_w  # Preserve the best old candidate by overwriting one child.
print("elite x:", elite_w, "elite fitness:", round(float(fit_elite_w[elite_idx_w]), 3))  # Inspect the protected candidate.
print("next generation with elitism:", next_elite_w)  # Inspect the resulting generation.
assert np.max(-(next_elite_w - 3.0) ** 2 + 10.0) >= np.max(fit_elite_w)  # Verify elitism preserves best fitness.
```
▶ What you'll see: the near-optimal `x=2.9` is copied even if the children alone would not keep it.

```python
plt.figure(figsize=(5, 3))  # Create a best-fitness comparison plot.
plt.bar(["old best", "children only", "with elitism"], [np.max(fit_elite_w), np.max(-(children_noisy_w - 3.0) ** 2 + 10.0), np.max(-(next_elite_w - 3.0) ** 2 + 10.0)], color=["teal", "gray", "seagreen"])  # Compare best scores.
plt.title("6: elitism prevents losing the best candidate")  # Title the elitism plot.
plt.ylabel("best fitness")  # Label best score.
plt.show()  # Display the comparison.
```
▶ What you'll see: the elitist generation keeps the old best score even when noisy children alone would drop it.

*Why it's done this way: elitism makes best-so-far performance monotonic while still allowing the non-elite slots to explore.*

### 7. The full evolutionary loop shifts both fitness and diversity

A GA is the repeated loop: evaluate fitness, select parents, create children by crossover, mutate, and preserve elites. We track best fitness, mean fitness, and population diversity so we can tell whether the population is improving or merely collapsing into clones.

```python
rng_loop_w = np.random.default_rng(2)  # Create a reproducible generator for the full loop.
pop_loop_w = rng_loop_w.uniform(-1.0, 7.0, size=20)  # Initialize 20 candidates across the search interval.
best_hist_w, mean_hist_w, div_hist_w = [], [], []  # Store best fitness, mean fitness, and diversity per generation.
for gen_w in range(18):  # Run the verified-size 18-generation demo.
    fit_loop_w = fitness_w(pop_loop_w)  # Evaluate the current generation.
    best_hist_w.append(float(np.max(fit_loop_w)))  # Record best fitness.
    mean_hist_w.append(float(np.mean(fit_loop_w)))  # Record mean fitness.
    div_hist_w.append(float(np.std(pop_loop_w)))  # Record population spread as diversity.
    weights_loop_w = fit_loop_w - np.min(fit_loop_w) + 1.0  # Shift scores positive for selection.
    probs_loop_w = weights_loop_w / np.sum(weights_loop_w)  # Normalize to probabilities.
    elite_loop_w = pop_loop_w[int(np.argmax(fit_loop_w))]  # Preserve the current best candidate.
    children_loop_w = [elite_loop_w]  # Start next generation with the elite.
    while len(children_loop_w) < len(pop_loop_w):  # Fill the rest with crossover and mutation.
        p1_w, p2_w = rng_loop_w.choice(pop_loop_w, size=2, replace=True, p=probs_loop_w)  # Select two parents probabilistically.
        child_w = 0.5 * (p1_w + p2_w) + rng_loop_w.normal(0.0, 0.35)  # Average crossover plus Gaussian mutation.
        children_loop_w.append(float(np.clip(child_w, -1.0, 7.0)))  # Keep candidates inside the search interval.
    pop_loop_w = np.array(children_loop_w)  # Replace the population.
print("best start -> end:", round(best_hist_w[0], 3), "->", round(best_hist_w[-1], 3))  # Inspect best improvement.
print("mean start -> end:", round(mean_hist_w[0], 3), "->", round(mean_hist_w[-1], 3))  # Inspect average improvement.
assert best_hist_w[-1] >= best_hist_w[0] and mean_hist_w[-1] > mean_hist_w[0]  # Verify improvement across the run.
```
▶ What you'll see: best and mean fitness improve across generations while diversity changes as selection concentrates the population.

```python
plt.figure(figsize=(5, 3))  # Create a convergence plot.
plt.plot(best_hist_w, marker="o", label="best fitness")  # Plot best candidate score.
plt.plot(mean_hist_w, marker="s", label="mean fitness")  # Plot population average score.
plt.title("7: GA convergence over generations")  # Title the convergence figure.
plt.xlabel("generation")  # Label the generation axis.
plt.ylabel("fitness")  # Label the score axis.
plt.legend()  # Show curve labels.
plt.show()  # Display the convergence plot.
```
▶ What you'll see: best fitness climbs quickly and mean fitness follows as the whole population shifts toward good regions.

```python
plt.figure(figsize=(5, 3))  # Create a diversity plot.
plt.plot(div_hist_w, marker="o", color="darkorange")  # Plot population standard deviation over time.
plt.title("7: population diversity over generations")  # Title the diversity figure.
plt.xlabel("generation")  # Label generation.
plt.ylabel("std of candidate x")  # Label spread.
plt.show()  # Display the diversity curve.
```
▶ What you'll see: diversity usually shrinks as selection exploits better regions, with mutation keeping some spread alive.

*Why it's done this way: plotting both fitness and diversity exposes the core GA tradeoff — exploit good candidates enough to improve, but preserve enough variation to keep searching.*

### ✍️ Toy 1 · Black-box fitness scores candidates

A GA only needs to ask “how good is this candidate?” Here a seeded mini-population probes a simple
hill, and the best score identifies the current champion.

```python
import numpy as np                              # arrays and seeded toy choices.
import matplotlib.pyplot as plt                 # one picture per toy.

t1_rng = np.random.default_rng(0)               # seeded generator  # -> seed 0
t1_grid = np.array([0.0, 1.0, 2.0, 3.0, 4.0])   # candidate pool     # -> [0, 1, 2, 3, 4]
t1_x = t1_rng.permutation(t1_grid)              # evaluation order   # -> [2, 4, 3, 0, 1]
t1_center = 3.0                                 # hill center        # -> 3.0
t1_fit = 10.0 - (t1_x - t1_center) ** 2         # black-box scores   # -> [9, 9, 10, 1, 6]
t1_best_idx = int(np.argmax(t1_fit))            # champion index     # -> 2
t1_best_x = float(t1_x[t1_best_idx])            # champion value     # -> 3.0
print("candidates:", t1_x.tolist())            # -> [2.0, 4.0, 3.0, 0.0, 1.0]
print("fitness:", t1_fit.tolist())             # -> [9.0, 9.0, 10.0, 1.0, 6.0]
print("best x:", t1_best_x)                    # -> 3.0
assert t1_best_x == 3.0                         # the score is maximized at the hill center.

plt.figure(figsize=(4.8, 2.8))
plt.plot(t1_grid, 10.0 - (t1_grid - t1_center) ** 2, color="lightgray", marker="o")
plt.scatter(t1_x, t1_fit, s=80, color="teal", label="scored candidates")
plt.scatter([t1_best_x], [t1_fit[t1_best_idx]], s=120, color="crimson", label="best")
plt.xlabel("candidate x"); plt.ylabel("fitness"); plt.legend()
plt.title("Toy 1 · fitness is just a score query"); plt.show()
```
▶ What you'll see: the candidate at `x = 3` has the largest printed score and the red marker.

### ✍️ Toy 2 · Population spread measures diversity

A population is more than a list of scores: its spread is search diversity. Compute the center,
offsets, and mean absolute offset by hand.

```python
import numpy as np                              # arrays and reductions.

t2_rng = np.random.default_rng(0)               # seeded generator  # -> seed 0
t2_pop = np.array([0.0, 1.0, 3.0, 6.0])         # tiny population    # -> [0, 1, 3, 6]
t2_fit = 10.0 - (t2_pop - 3.0) ** 2             # scores             # -> [1, 6, 10, 1]
t2_center = float(np.mean(t2_pop))              # population center  # -> 2.5
t2_offsets = t2_pop - t2_center                 # signed offsets     # -> [-2.5, -1.5, 0.5, 3.5]
t2_spread = float(np.mean(np.abs(t2_offsets)))  # mean abs spread    # -> 2.0
print("population:", t2_pop.tolist())          # -> [0.0, 1.0, 3.0, 6.0]
print("fitness:", t2_fit.tolist())             # -> [1.0, 6.0, 10.0, 1.0]
print("center:", t2_center)                    # -> 2.5
print("offsets:", t2_offsets.tolist())         # -> [-2.5, -1.5, 0.5, 3.5]
print("mean absolute spread:", t2_spread)      # -> 2.0
assert t2_spread == 2.0                         # the population is still broad.

plt.figure(figsize=(4.8, 2.8))
plt.scatter(t2_pop, np.zeros_like(t2_pop), s=90, color="teal", label="candidates")
plt.axvline(t2_center, color="black", linestyle="--", label="center")
plt.xlabel("candidate x"); plt.yticks([]); plt.legend()
plt.title("Toy 2 · spread is population diversity"); plt.show()
```
▶ What you'll see: four points span both sides of the dashed center, giving spread `2.0`.

### ✍️ Toy 3 · Fitness weights become parent probabilities

Fitness-proportionate selection shifts scores positive, normalizes them, and samples parents from
those probabilities without making selection deterministic.

```python
import numpy as np                              # arrays and categorical sampling.

t3_rng = np.random.default_rng(0)               # seeded generator       # -> seed 0
t3_names = np.array(["A", "B", "C", "D"])     # four candidates         # -> A, B, C, D
t3_fit = np.array([1.0, 3.0, 5.0, 1.0])         # raw fitness            # -> [1, 3, 5, 1]
t3_min = float(np.min(t3_fit))                  # weakest score          # -> 1.0
t3_weights = t3_fit - t3_min + 1.0              # positive weights       # -> [1, 3, 5, 1]
t3_prob = t3_weights / np.sum(t3_weights)       # parent probabilities   # -> [0.1, 0.3, 0.5, 0.1]
t3_parents = t3_rng.choice(t3_names, size=4, replace=True, p=t3_prob)  # sampled parents  # -> [C, B, A, A]
print("fitness:", t3_fit.tolist())             # -> [1.0, 3.0, 5.0, 1.0]
print("weights:", t3_weights.tolist())         # -> [1.0, 3.0, 5.0, 1.0]
print("probabilities:", np.round(t3_prob, 3).tolist())  # -> [0.1, 0.3, 0.5, 0.1]
print("sampled parents:", t3_parents.tolist()) # -> ['C', 'B', 'A', 'A']
assert np.isclose(np.sum(t3_prob), 1.0)         # probabilities must sum to one.

plt.figure(figsize=(4.8, 2.8))
plt.bar(t3_names, t3_prob, color="seagreen")
plt.ylabel("selection probability"); plt.ylim(0, 0.6)
plt.title("Toy 3 · better fitness gets more tickets"); plt.show()
```
▶ What you'll see: candidate `C` has the tallest bar but weaker candidates still have nonzero chances.

### ✍️ Toy 4 · Crossover averages parent values

### ✍️ Toy 5 · Mutation nudges a child

Mutation adds new material after crossover. A seeded draw chooses a small step, then the child moves
and gets rescored.

```python
import numpy as np                              # arrays and seeded mutation.

t5_rng = np.random.default_rng(0)               # seeded generator       # -> seed 0
t5_child = 3.0                                  # child before mutation  # -> 3.0
t5_choices = np.array([-0.5, 0.0, 0.5])         # allowed mutation steps  # -> [-0.5, 0, 0.5]
t5_step = float(t5_rng.choice(t5_choices))      # sampled mutation       # -> 0.5
t5_mutant = t5_child + t5_step                  # mutated child          # -> 3.5
t5_fit = float(10.0 - (t5_mutant - 3.0) ** 2)   # mutated fitness        # -> 9.75
print("step choices:", t5_choices.tolist())    # -> [-0.5, 0.0, 0.5]
print("sampled mutation:", t5_step)            # -> 0.5
print("mutated child:", t5_mutant)             # -> 3.5
print("mutated fitness:", t5_fit)              # -> 9.75
assert np.isclose(t5_fit, 9.75)                 # the nudge stays in the good basin.

plt.figure(figsize=(4.8, 2.8))
t5_grid = np.linspace(2.0, 4.2, 80)
```

## 🛠️ Setup

```python
import numpy as np  # Import NumPy for arrays, sampling, vectorized fitness, and numerical checks.
import matplotlib.pyplot as plt  # Import Matplotlib for fitness landscapes, probability bars, diversity curves, and convergence plots.
from math import comb  # Import a standard-library combinatoric helper for a later schema-count example.
np.random.seed(0)  # Fix the global random seed so stochastic examples are reproducible.

def simple_fitness(x):  # Define the lesson's tiny quadratic maximization objective.
    x = np.asarray(x, dtype=float)  # Accept scalars or arrays as float candidates.
    return -(x - 3.0) ** 2 + 10.0  # Return high scores near x=3.

def rugged_fitness(x):  # Define a slightly wiggly black-box landscape for full GA runs.
    x = np.asarray(x, dtype=float)  # Convert input to an array for vectorized evaluation.
    return -(x - 3.0) ** 2 + 10.0 + 0.7 * np.sin(3.0 * x)  # Combine a broad hill with local wiggles.

def selection_probabilities(fitness_values):  # Convert fitness scores to shifted fitness-proportionate probabilities.
    fitness_values = np.asarray(fitness_values, dtype=float)  # Ensure numerical array behavior.
    weights = fitness_values - np.min(fitness_values) + 1.0  # Shift so every candidate has positive weight.
    return weights / np.sum(weights)  # Normalize weights into probabilities.

def one_point_crossover(a, b, cut):  # Combine two binary parents with a one-point crossover cut.
    a = np.asarray(a, dtype=int)  # Convert parent a to integer bits.
    b = np.asarray(b, dtype=int)  # Convert parent b to integer bits.
    return np.concatenate([a[:cut], b[cut:]])  # Take the left prefix from a and right suffix from b.

def bit_flip_mutation(bits, flips):  # Flip selected bit positions in a binary chromosome.
    child = np.asarray(bits, dtype=int).copy()  # Copy so mutation does not alter the input parent.
    child[np.asarray(flips, dtype=int)] = 1 - child[np.asarray(flips, dtype=int)]  # Flip each requested bit.
    return child  # Return the mutated chromosome.

def population_diversity(pop):  # Measure spread for either 1-D or multi-D real-valued populations.
    pop = np.asarray(pop, dtype=float)  # Convert population to a numeric array.
    return float(np.mean(np.std(pop, axis=0))) if pop.ndim == 2 else float(np.std(pop))  # Average per-coordinate standard deviation.
```

#### A5. Compare GA to random search under the same budget

**Goal.** Evaluate GA against pure random search, because evolutionary structure is only useful if it spends evaluations better than sampling blindly. We build it in 5 steps.
