# 1.2 · Bias-Complexity Tradeoff

A richer hypothesis class can reduce bias because it can express more shapes, but that same richness makes finite samples easier to overfit. In this lesson, we split excess risk into approximation error and estimation error, then use tiny numerical experiments to see why the best model class depends on the amount of data you actually have.

## 📖 Concept walkthrough — build it from scratch

Before the terse worked examples, we build the bias-complexity tradeoff one idea at a time. Run each cell in order and read the printed intermediate values — the decomposition, the square-root estimation term, and the model-class choice are all made visible with small arrays. This walkthrough is self-contained (it imports what it needs) and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays, square roots, polynomial fitting, and reproducible simulation.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
np.random.seed(0)  # reproducibility for every random sample in the walkthrough.
```

### 1. Excess risk has two jobs to do

The learned model $\hat h$ can be worse than the Bayes predictor for two different reasons. First, the whole class $\mathcal{H}$ may be too simple, so even its best member $h^\star=\arg\min_{h\in\mathcal{H}}R(h)$ cannot reach the Bayes risk $R^\star$. Second, finite data may make ERM choose $\hat h$ that is worse than $h^\star$.

$$R(\hat h)-R^\star=\underbrace{\big(R(h^\star)-R^\star\big)}_{\text{approximation}}+\underbrace{\big(R(\hat h)-R(h^\star)\big)}_{\text{estimation}}.$$

```python
R_bayes_w = 0.10  # irreducible Bayes risk R* that no hypothesis class can beat.
R_best_in_class_w = 0.30  # risk of h* inside a deliberately small class.
R_learned_w = 0.52  # risk of the ERM solution h-hat from a finite sample.
print("Bayes risk R*:", R_bayes_w)  # inspect the unreachable floor.
print("best in class R(h*):", R_best_in_class_w)  # inspect the class limitation.
print("learned risk R(hat h):", R_learned_w)  # inspect the finite-sample result.
```
▶ What you'll see: three risk levels: the Bayes floor, the best model available in the class, and the model actually learned.

```python
approx_w = R_best_in_class_w - R_bayes_w  # class limitation: R(h*) - R*.
est_w = R_learned_w - R_best_in_class_w  # finite-sample search cost: R(hat h) - R(h*).
excess_w = R_learned_w - R_bayes_w  # total excess risk over the Bayes floor.
print("approximation:", round(approx_w, 3))  # 0.20.
print("estimation:", round(est_w, 3))  # 0.22.
print("sum:", round(approx_w + est_w, 3), "excess:", round(excess_w, 3))  # exact split.
assert round(approx_w, 3) == 0.200 and round(est_w, 3) == 0.220  # verify the worked split.
```
▶ What you'll see: the two pieces add exactly to total excess risk, so they are not competing explanations — they are a bookkeeping identity.

```python
plt.figure(figsize=(4.6, 3))  # compact bar chart for the decomposition.
plt.bar(["Bayes floor", "approx", "estimation"], [R_bayes_w, approx_w, est_w], color=["gray", "steelblue", "darkorange"])  # show floor and two excess pieces.
plt.ylabel("risk units")  # label the vertical scale.
plt.title("1: excess risk decomposes into two terms")  # title the figure with concept id.
plt.show()  # display the decomposition.
```
▶ What you'll see: approximation and estimation are stacked conceptually above the unavoidable Bayes floor.

*Why it's done this way: separating the two errors prevents the classic mistake of blaming a model class for a problem caused by data scarcity, or blaming data scarcity for a class that simply cannot express the truth.*

### 2. Complexity lowers approximation but raises estimation

A bigger class is a larger menu: it can contain a model closer to the truth, so approximation error tends to fall. But a bigger menu is also harder to search with finite data, so estimation error tends to rise. A simple upper-bound-shaped proxy for the estimation term is

$$\sqrt{\frac{\text{complexity}}{2m}},$$

where $m$ is sample size. This is not a universal equality; it is a useful learning-theory shape that grows with class complexity and shrinks like $1/\sqrt{m}$.

```python
m_w = 100  # fixed sample size from the lesson text.
complexities_w = np.array([10, 100, 1000], dtype=float)  # small, medium, and large class sizes.
approx_terms_w = np.array([0.20, 0.08, 0.02])  # richer classes fit the target better.
est_terms_w = np.sqrt(complexities_w / (2 * m_w))  # square-root estimation proxy.
print("complexities:", complexities_w.astype(int))  # inspect class sizes.
print("approx terms:", approx_terms_w)  # inspect decreasing approximation error.
print("est terms:", np.round(est_terms_w, 3))  # inspect increasing estimation error.
```
▶ What you'll see: approximation goes down as complexity grows, while estimation goes up sharply at fixed $m=100$.

```python
totals_w = approx_terms_w + est_terms_w  # total excess-risk proxy for each class.
print("total errors:", np.round(totals_w, 3))  # [0.424, 0.787, 2.256].
assert np.allclose(np.round(est_terms_w, 3), [0.224, 0.707, 2.236])  # reproduce cited estimation numbers.
assert np.allclose(np.round(totals_w, 3), [0.424, 0.787, 2.256])  # reproduce cited totals.
```
▶ What you'll see: the smallest class wins even though it has the largest approximation error.

```python
x_w = np.arange(len(complexities_w))  # x locations for grouped bars.
plt.figure(figsize=(5, 3.2))  # compact tradeoff plot.
plt.bar(x_w - 0.18, approx_terms_w, width=0.36, label="approximation", color="steelblue")  # show bias-like term.
plt.bar(x_w + 0.18, est_terms_w, width=0.36, label="estimation", color="darkorange")  # show complexity cost.
plt.plot(x_w, totals_w, marker="o", color="black", label="total")  # show what model selection cares about.
plt.xticks(x_w, ["10", "100", "1000"])  # label by complexity.
plt.xlabel("complexity")  # label horizontal axis.
plt.ylabel("error proxy")  # label vertical axis.
plt.title("2: at m=100, complexity is expensive")  # title the figure.
plt.legend()  # identify the two terms.
plt.show()  # display the tradeoff.
```
▶ What you'll see: the orange bars rise faster than the blue bars fall, so the black total line gets worse.

*Why it's done this way: reading totals rather than a single column is the whole lesson — expressiveness you cannot support with data is a liability, not a gift.*

### 3. More data makes complexity affordable

The estimation proxy scales as $1/\sqrt{m}$, so multiplying the data by four cuts the estimation term in half. That means the right class is not fixed forever: a class that overfits at $m=100$ can become attractive when $m$ is much larger.

```python
m_values_w = np.array([100, 400, 1600], dtype=float)  # one class evaluated at growing sample sizes.
medium_complexity_w = 100.0  # the medium class from the lesson table.
medium_approx_w = 0.08  # its approximation error.
medium_est_w = np.sqrt(medium_complexity_w / (2 * m_values_w))  # estimation at each m.
print("m values:", m_values_w.astype(int))  # inspect sample sizes.
print("medium estimation:", np.round(medium_est_w, 3))  # 0.707, 0.354, 0.177.
assert round(float(medium_est_w[-1]), 3) == 0.177  # reproduce the cited m=1600 number.
```
▶ What you'll see: the medium class's estimation term falls from 0.707 to 0.177 as data grows from 100 to 1600.

```python
medium_total_w = medium_approx_w + medium_est_w  # total proxy at each sample size.
print("medium total:", np.round(medium_total_w, 3))  # inspect how data lowers total error.
print("quadrupling m halves estimation:", round(float(medium_est_w[0] / medium_est_w[1]), 3))  # should be 2.
assert round(float(medium_est_w[0] / medium_est_w[1]), 3) == 2.000  # verify the square-root scaling.
```
▶ What you'll see: every fourfold increase in $m$ halves estimation error, leaving approximation unchanged.

```python
plt.figure(figsize=(4.8, 3))  # compact data-scaling plot.
plt.plot(m_values_w, medium_est_w, marker="o", label="estimation", color="darkorange")  # plot finite-sample term.
plt.plot(m_values_w, medium_total_w, marker="o", label="total", color="black")  # plot total including approximation.
plt.axhline(medium_approx_w, color="steelblue", linestyle="--", label="approximation")  # show fixed class bias.
plt.xscale("log")  # make multiplicative sample growth visually even.
plt.xlabel("sample size m")  # label sample axis.
plt.ylabel("error proxy")  # label vertical axis.
plt.title("3: more data lowers estimation error")  # title the figure.
plt.legend()  # identify curves.
plt.show()  # display the plot.
```
▶ What you'll see: the orange curve falls toward zero while the blue approximation line stays put.

*Why it's done this way: data does not make a straight line bend, but it does make a richer class safer to use; model capacity should grow with sample size.*

### 4. A tiny fitting demo: underfit versus overfit

The same tradeoff appears in ordinary curve fitting. A line has high approximation error on a curved target, a moderate polynomial can capture the shape, and a very high-degree polynomial can chase sample noise. We will fit several polynomial degrees to a noisy sample and evaluate them on a dense grid against the noiseless target.

```python
x_train_w = np.linspace(-1, 1, 12)  # small training sample where estimation error matters.
y_true_train_w = np.sin(3 * x_train_w)  # noiseless target values at training points.
noise_w = 0.12 * np.random.randn(len(x_train_w))  # reproducible measurement noise.
y_train_w = y_true_train_w + noise_w  # observed labels seen by ERM.
x_grid_w = np.linspace(-1, 1, 200)  # dense grid for true-risk-style evaluation.
y_true_grid_w = np.sin(3 * x_grid_w)  # noiseless target on the grid.
print("first noisy labels:", np.round(y_train_w[:4], 3))  # inspect a few observations.
```
▶ What you'll see: the training labels are close to a sine curve but not exactly on it.

```python
degrees_w = [1, 3, 9]  # simple, medium, and very flexible polynomial classes.
train_mse_w = []  # store empirical risk on the sample.
true_mse_w = []  # store grid risk against the noiseless target.
preds_grid_w = []  # keep predictions for plotting.
for degree_w in degrees_w:  # fit each class by least squares ERM.
    coef_w = np.polyfit(x_train_w, y_train_w, degree_w)  # choose the best polynomial on the sample.
    pred_train_w = np.polyval(coef_w, x_train_w)  # predictions on training points.
    pred_grid_w = np.polyval(coef_w, x_grid_w)  # predictions on dense test grid.
    train_mse_w.append(float(np.mean((pred_train_w - y_train_w) ** 2)))  # empirical error.
    true_mse_w.append(float(np.mean((pred_grid_w - y_true_grid_w) ** 2)))  # out-of-sample proxy.
    preds_grid_w.append(pred_grid_w)  # save curve.
print("train MSE:", np.round(train_mse_w, 4))  # high degree usually wins training error.
print("true-grid MSE:", np.round(true_mse_w, 4))  # medium degree is safer here.
assert train_mse_w[-1] <= train_mse_w[0]  # richer class fits the sample at least as well as the line.
```
▶ What you'll see: training error falls with degree, but true-grid error does not have to follow it.

```python
plt.figure(figsize=(5.2, 3.4))  # compact curve-fitting plot.
plt.scatter(x_train_w, y_train_w, color="black", label="noisy sample")  # show observed data.
plt.plot(x_grid_w, y_true_grid_w, color="gray", linewidth=2, label="truth")  # show target curve.
for degree_w, pred_w in zip(degrees_w, preds_grid_w):  # draw each fitted class.
    plt.plot(x_grid_w, pred_w, label=f"degree {degree_w}")  # visualize model complexity.
plt.ylim(-1.6, 1.6)  # keep overfit wiggles readable.
plt.title("4: fitting the sample is not the same as learning the truth")  # title the figure.
plt.legend(fontsize=8)  # identify curves.
plt.show()  # display the plot.
```
▶ What you'll see: the line misses curvature, the medium polynomial follows the target, and the high-degree curve can chase noise near the edges.

*Why it's done this way: polynomial degree is a concrete capacity knob, so it makes the abstract approximation-versus-estimation split visible as curves you can inspect.*

### 5. Model selection balances the two terms

The practical rule is not "pick the biggest class" or "pick the simplest class." It is: estimate the total cost at the sample size you have, then pick the class with the lowest total. In theory language, this is the instinct behind Structural Risk Minimization and regularization.

```python
labels_w = np.array(["small", "medium", "large"])  # names for the three classes.
complexities2_w = np.array([10, 100, 1000], dtype=float)  # same complexity ladder.
approx2_w = np.array([0.20, 0.08, 0.02])  # same approximation ladder.
ms_w = np.array([100, 1600, 10000], dtype=float)  # compare different data regimes.
print("classes:", labels_w)  # inspect class names.
print("sample sizes:", ms_w.astype(int))  # inspect data regimes.
```
▶ What you'll see: the same three classes will be judged at three different sample sizes.

```python
total_grid_w = approx2_w[None, :] + np.sqrt(complexities2_w[None, :] / (2 * ms_w[:, None]))  # rows=m, cols=class.
winners_w = labels_w[np.argmin(total_grid_w, axis=1)]  # pick lowest total for each m.
print("total grid:\n", np.round(total_grid_w, 3))  # inspect every candidate.
print("winners:", winners_w)  # see how the chosen class changes with data.
assert winners_w[0] == "small" and winners_w[-1] == "medium"  # at these numbers, data moves the choice.
```
▶ What you'll see: small wins when data is scarce; medium becomes better once estimation shrinks enough.

```python
plt.figure(figsize=(5, 3.2))  # compact model-selection plot.
for j_w, label_w in enumerate(labels_w):  # plot one curve per class.
    plt.plot(ms_w, total_grid_w[:, j_w], marker="o", label=label_w)  # show total error versus m.
plt.xscale("log")  # compare sample sizes multiplicatively.
plt.xlabel("sample size m")  # label x-axis.
plt.ylabel("approx + estimation")  # label y-axis.
plt.title("5: the best class depends on m")  # title the figure.
plt.legend()  # identify class curves.
plt.show()  # display the model-selection curves.
```
▶ What you'll see: the winner is a moving target because only the estimation term changes with data.

*Why it's done this way: complexity control is a data-dependent design problem; the right answer is the class whose approximation and estimation errors are balanced for the sample size in front of you.*

```python
# !pip install numpy matplotlib  # Colab already has these; uncomment only if your runtime is missing them.
import numpy as np  # Import NumPy for arrays, square roots, polynomial fitting, and simulation.
import matplotlib.pyplot as plt  # Import Matplotlib for the line plots, bar charts, and scatter plots used below.
np.random.seed(0)  # Fix randomness so every example gives repeatable numbers.

def estimation(complexity, m):  # Define the lesson's square-root estimation-error proxy.
    complexity = np.asarray(complexity, dtype=float)  # Convert complexity to floats so vectorized division is predictable.
    return np.sqrt(complexity / (2 * m))  # Return sqrt(complexity / 2m), guarding is unnecessary for positive m examples.

def total_error(approx, complexity, m):  # Define total excess-error proxy for one or many classes.
    return np.asarray(approx, dtype=float) + estimation(complexity, m)  # Add approximation and estimation terms.

def show_tradeoff(approx, est, labels, title):  # Define a compact helper for side-by-side tradeoff bars.
    x = np.arange(len(labels))  # Create x positions for each model class.
    plt.figure(figsize=(5, 3))  # Start a compact figure.
    plt.bar(x - 0.18, approx, width=0.36, label="approx", color="steelblue")  # Draw approximation bars.
    plt.bar(x + 0.18, est, width=0.36, label="est", color="darkorange")  # Draw estimation bars.
    plt.plot(x, np.asarray(approx) + np.asarray(est), marker="o", color="black", label="total")  # Draw total error.
    plt.xticks(x, labels)  # Label each complexity class.
    plt.ylabel("error proxy")  # Label the vertical scale.
    plt.title(title)  # Add the requested figure title.
    plt.legend()  # Show labels for the two terms and total.
    plt.show()  # Display the figure.
```

## 🟢 Basics (warm-up)

#### B1. Split one excess risk into two pieces

**Goal.** Compute approximation and estimation error from three risk values, because the tradeoff starts with a decomposition rather than a vague feeling about overfitting. We build it in 2 steps.

```python
R_star_b1 = 0.10  # Set Bayes risk R*, the irreducible floor.
R_hstar_b1 = 0.30  # Set risk of the best model h* inside the class.
R_hat_b1 = 0.52  # Set risk of the learned model h-hat.
print("risks:", R_star_b1, R_hstar_b1, R_hat_b1)  # Inspect the three levels before subtracting.
```
▶ What you'll see: risk increases from the Bayes floor to best-in-class to learned model.

```python
approx_b1 = R_hstar_b1 - R_star_b1  # Compute R(h*) - R*.
est_b1 = R_hat_b1 - R_hstar_b1  # Compute R(hat h) - R(h*).
print("approximation:", round(approx_b1, 3), "estimation:", round(est_b1, 3))  # Inspect the two terms.
plt.figure(figsize=(4, 3))  # Create a compact decomposition chart.
plt.bar(["approx", "est"], [approx_b1, est_b1], color=["steelblue", "orange"])  # Draw both parts of excess risk.
plt.title("B1: excess-risk pieces")  # Title the plot.
plt.ylabel("risk difference")  # Label the vertical axis.
plt.show()  # Display the bar chart.
```
▶ What you'll see: approximation is the class gap; estimation is the finite-sample gap.

👀 Takeaway: total excess risk is the sum of a representation problem and a data problem.

#### B2. Identify approximation error
