# 14.4 — Exponential Smoothing & Holt-Winters

Exponential smoothing forecasts a time series by updating a few human-readable states — level, trend, and season — as each new observation arrives. Instead of fitting one large lag equation, we keep a controlled memory: recent data pulls the state partway toward itself, while older belief survives through the previous state.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build exponential smoothing one idea at a time. Run each cell in order and read the printed intermediate values — every state update is spelled out so the recursions do not feel like magic. This walkthrough is self-contained (it imports what it needs) and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays for series, states, and numerical checks.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
np.random.seed(0)  # reproducibility for toy noise.
```

### 1. Recency-weighted averages: controlled memory

The core idea is a weighted average between the new observation and the previous belief. If the old level is 10, the new observation is 14, and the smoothing weight is `alpha = 0.25`, the update moves only one quarter of the way toward 14. The remaining three quarters preserve continuity from the old state.

```python
old_level_w = 10.0                         # yesterday's smoothed belief about the series level.
y_new_w = 14.0                             # today's observed value.
alpha_w = 0.25                             # the recency weight assigned to the new observation.
new_level_w = alpha_w * y_new_w + (1 - alpha_w) * old_level_w  # convex weighted average.
print("old level:", old_level_w, "new observation:", y_new_w)  # inspect endpoints.
print("updated level:", round(new_level_w, 3))                 # 0.25*14 + 0.75*10 = 11.
assert round(new_level_w, 3) == 11.000                          # concrete arithmetic check.
```
▶ What you'll see: the updated belief is 11, not 14, because the old level still carries 75% of the weight.

```python
alphas_w = np.array([0.1, 0.25, 0.5, 0.9])  # compare slow to fast smoothers.
updates_w = alphas_w * y_new_w + (1 - alphas_w) * old_level_w  # same weighted average for each alpha.
print("alphas:", alphas_w)                 # inspect the reaction settings.
print("updated levels:", np.round(updates_w, 3))  # higher alpha moves closer to the new observation.
```
▶ What you'll see: small alpha barely moves the state, while alpha 0.9 almost copies the observation.

```python
plt.figure(figsize=(4.6, 3))                              # compact response plot.
plt.plot(alphas_w, updates_w, marker="o", color="teal")  # show how alpha controls motion.
plt.axhline(old_level_w, color="gray", linestyle="--", label="old level")  # reference old belief.
plt.axhline(y_new_w, color="crimson", linestyle="--", label="new observation")  # reference new data.
plt.title("1: alpha controls how far belief moves")       # title the diagnostic plot.
plt.xlabel("alpha")                                      # label the smoothing weight.
plt.ylabel("updated level")                              # label the resulting state.
plt.legend()                                              # show the two references.
plt.show()                                                # display the plot.
```
▶ What you'll see: the line rises from the old level toward the observation as alpha increases.

*Why it's done this way:* The update is a convex combination: the weights are `alpha` and `1 - alpha`, so they sum to 1 and keep the state on the same scale as the data. Mathematically, this is the smallest possible online smoother: one number stores the past, one weight decides how much the newest residual should correct it.

### 2. Simple exponential smoothing (SES): level only

Simple exponential smoothing keeps one state, the level $\ell_t$. The recursion is $\ell_t = \alpha y_t + (1-\alpha)\ell_{t-1}$, and the next forecast is just the current level. This is appropriate when the series wanders around a stable mean without a persistent trend or repeating seasonal offset.

```python
y_ses_w = np.array([10., 12., 13., 12.])  # tiny series from the lesson math.
alpha_ses_w = 0.5                         # equal weight on new observation and old level.
levels_ses_w = [y_ses_w[0]]               # initialize level at the first observation.
print("initial level:", levels_ses_w[0])  # inspect l_0.
```
▶ What you'll see: the recursion starts with level 10.

```python
for t_w in range(1, len(y_ses_w)):  # update once per new observation.
    prev_w = levels_ses_w[-1]       # previous smoothed belief.
    new_w = alpha_ses_w * y_ses_w[t_w] + (1 - alpha_ses_w) * prev_w  # SES update.
    levels_ses_w.append(new_w)      # store the state path for inspection.
    print(f"l_{t_w} = {alpha_ses_w}*{y_ses_w[t_w]:.0f} + {1-alpha_ses_w}*{prev_w:.0f} = {new_w:.3f}")
levels_ses_w = np.array(levels_ses_w)  # convert list to array for plotting.
assert np.allclose(levels_ses_w, [10., 11., 12., 12.])  # concrete lesson numbers.
```
▶ What you'll see: the levels are 10, 11, 12, 12 — each update is softened by the previous belief.

```python
plt.figure(figsize=(5, 3))                              # compact line plot.
plt.plot(y_ses_w, marker="o", label="observed y")      # raw data.
plt.plot(levels_ses_w, marker="s", label="SES level")  # smoothed state.
plt.title("2: SES follows the level, not every wiggle")  # title.
plt.xlabel("time")                                     # time index.
plt.ylabel("value")                                    # series scale.
plt.legend()                                           # show raw and smoothed lines.
plt.show()                                             # display the plot.
```
▶ What you'll see: the smoothed level lags and softens the observations instead of jumping fully to each point.

*Why it's done this way:* Expanding the recursion shows why it is called exponential smoothing: $\ell_t$ contains $\alpha y_t$, then $\alpha(1-\alpha)y_{t-1}$, then $\alpha(1-\alpha)^2 y_{t-2}$, and so on. Older observations never disappear immediately; their weight decays geometrically.

### 3. Forecasting with SES and choosing alpha

SES forecasts every future horizon as the final level, because the model has no trend or seasonal state. The practical modeling question is not whether alpha is "good" in the abstract; it is which alpha wins chronological validation on recent held-out points.

```python
rng_w = np.random.default_rng(0)                              # reproducible noise.
t_w = np.arange(36)                                           # monthly time index.
y_alpha_w = 20 + 0.08 * t_w + rng_w.normal(0, 0.7, size=t_w.size)  # almost-level series with noise.
train_w, test_w = y_alpha_w[:28], y_alpha_w[28:]              # chronological split.
print("train length:", len(train_w), "test length:", len(test_w))  # inspect split.
```
▶ What you'll see: the last eight points are held out as future data, not randomly mixed into training.

```python
def ses_fit_w(y_w, alpha_w):                       # fit SES levels for one alpha.
    levels_w = [float(y_w[0])]                     # initialize at the first observation.
    for value_w in y_w[1:]:                        # process observations online.
        levels_w.append(alpha_w * value_w + (1 - alpha_w) * levels_w[-1])  # level recursion.
    return np.array(levels_w)                      # return full state path.

alpha_grid_w = np.array([0.1, 0.3, 0.6, 0.9])      # compare slow and fast memory.
mae_w = []                                         # store validation errors.
for a_w in alpha_grid_w:                           # score each alpha.
    levels_w = ses_fit_w(train_w, a_w)             # fit only on training history.
    forecast_w = np.repeat(levels_w[-1], len(test_w))  # SES flat multi-step forecast.
    mae_w.append(np.mean(np.abs(test_w - forecast_w))) # mean absolute validation error.
print("MAE by alpha:", np.round(mae_w, 3))         # inspect chronological validation.
best_alpha_w = float(alpha_grid_w[int(np.argmin(mae_w))])  # choose the winner.
print("best alpha:", best_alpha_w)                 # inspect selected smoothing speed.
assert best_alpha_w in alpha_grid_w                 # concrete sanity check.
```
▶ What you'll see: the best alpha is the one with the smallest future error on the chronological split.

```python
best_levels_w = ses_fit_w(train_w, best_alpha_w)               # refit state path for the chosen alpha.
best_forecast_w = np.repeat(best_levels_w[-1], len(test_w))    # flat forecast from final level.
plt.figure(figsize=(6, 3))                                     # compact forecast plot.
plt.plot(np.arange(len(train_w)), train_w, label="train", color="steelblue")  # historical data.
plt.plot(np.arange(len(train_w), len(y_alpha_w)), test_w, label="future truth", color="black")  # holdout.
plt.plot(np.arange(len(train_w), len(y_alpha_w)), best_forecast_w, "--", label="SES forecast", color="crimson")  # forecast.
plt.title("3: SES forecast is the final level")                # title.
plt.xlabel("time")                                            # time index.
plt.ylabel("value")                                           # series scale.
plt.legend()                                                   # show lines.
plt.show()                                                     # display plot.
```
▶ What you'll see: the forecast is a horizontal line; SES can track a level but cannot extrapolate slope.

*Why it's done this way:* Alpha controls the bias-variance tradeoff. A high alpha reduces lag when the level really changes, but it also treats noisy residuals like signal. A low alpha filters noise but adapts slowly. Chronological validation tests the only thing that matters: whether that memory setting forecasts future points well.

### 4. Holt's method: level plus trend

Holt's linear method adds a trend state $b_t$. The level update uses the previous forecasted level $\ell_{t-1}+b_{t-1}$, and the trend update smooths the newest slope $\ell_t-\ell_{t-1}$. The one-step forecast becomes $\ell_t + b_t$ and an $h$-step forecast becomes $\ell_t + h b_t$.

```python
level_old_w = 10.0                         # previous level l_{t-1}.
trend_old_w = 1.0                          # previous trend b_{t-1}.
y_holt_w = 12.0                            # new observation.
alpha_holt_w, beta_holt_w = 0.5, 0.25      # level and trend smoothing weights.
level_new_w = alpha_holt_w * y_holt_w + (1 - alpha_holt_w) * (level_old_w + trend_old_w)  # level update.
trend_new_w = beta_holt_w * (level_new_w - level_old_w) + (1 - beta_holt_w) * trend_old_w  # trend update.
next_forecast_w = level_new_w + trend_new_w  # one-step-ahead forecast.
print("new level:", round(level_new_w, 3))   # 11.5.
print("new trend:", round(trend_new_w, 3))   # 1.125.
print("next forecast:", round(next_forecast_w, 3))  # 12.625.
assert round(level_new_w, 3) == 11.500 and round(trend_new_w, 3) == 1.125  # lesson numbers.
```
▶ What you'll see: the level moves toward 12, the trend moves toward the latest slope 1.5, and the next forecast is 12.625.

```python
y_trend_w = 5 + 0.8 * np.arange(18) + np.random.normal(0, 0.35, 18)  # toy upward series.
levels_holt_w = [y_trend_w[0]]                                      # initialize level.
trends_holt_w = [y_trend_w[1] - y_trend_w[0]]                        # initialize trend from first difference.
for value_w in y_trend_w[1:]:                                       # process each point online.
    old_l_w, old_b_w = levels_holt_w[-1], trends_holt_w[-1]          # previous states.
    l_w = 0.45 * value_w + (1 - 0.45) * (old_l_w + old_b_w)          # Holt level.
    b_w = 0.25 * (l_w - old_l_w) + (1 - 0.25) * old_b_w              # Holt trend.
    levels_holt_w.append(l_w); trends_holt_w.append(b_w)             # store states.
levels_holt_w = np.array(levels_holt_w); trends_holt_w = np.array(trends_holt_w)  # arrays.
print("final level:", round(levels_holt_w[-1], 3), "final trend:", round(trends_holt_w[-1], 3))  # inspect state.
assert trends_holt_w[-1] > 0.4                                      # positive trend sanity check.
```
▶ What you'll see: the learned trend is positive because the synthetic series rises over time.

```python
h_w = np.arange(1, 7)                                 # six future horizons.
holt_forecast_w = levels_holt_w[-1] + h_w * trends_holt_w[-1]  # linear extrapolation.
plt.figure(figsize=(6, 3))                            # compact forecast plot.
plt.plot(y_trend_w, marker="o", label="observed")     # historical series.
plt.plot(np.arange(len(y_trend_w), len(y_trend_w) + len(h_w)), holt_forecast_w,
         marker="s", linestyle="--", label="Holt forecast")  # trend forecast.
plt.title("4: Holt extrapolates the smoothed trend")   # title.
plt.xlabel("time")                                    # time index.
plt.ylabel("value")                                   # series scale.
plt.legend()                                          # show lines.
plt.show()                                            # display plot.
```
▶ What you'll see: the forecast continues upward instead of staying flat like SES.

*Why it's done this way:* The trend is not a single coefficient fit once to all history. It is a state that updates online, so a recent change in slope can gradually modify future forecasts. The level uses $\ell_{t-1}+b_{t-1}$ because, before seeing $y_t$, that is the model's best prediction of where the level should have moved.

### 5. Holt-Winters: rotating seasonal offsets

Additive Holt-Winters adds a seasonal state $s_t$ for each position in a cycle of length $m$. For monthly data with yearly seasonality, $m=12$; here we use $m=4$ so the mechanics fit on screen. The forecast combines level, trend, and the seasonal offset for the future cycle position.

```python
m_w = 4                                                  # season length.
base_w = 20 + 0.6 * np.arange(24)                         # trend component.
season_pattern_w = np.array([2.0, -1.0, -2.0, 1.0])        # additive seasonal offsets sum to zero.
y_hw_w = base_w + np.tile(season_pattern_w, 6) + np.random.normal(0, 0.2, 24)  # toy seasonal series.
print("first season:", np.round(y_hw_w[:m_w], 2))          # inspect one cycle.
print("seasonal pattern:", season_pattern_w)               # inspect true offsets.
```
▶ What you'll see: every fourth point repeats the same kind of high/low offset around a rising trend.

```python
def initial_hw_states_w(y_w, m_w):                         # initialize additive states from first two seasons.
    first_w, second_w = y_w[:m_w], y_w[m_w:2*m_w]            # first two full cycles.
    trend_w = (np.mean(second_w) - np.mean(first_w)) / m_w   # average per-step growth between cycles.
    level_w = float(np.mean(first_w))                       # initial level as first-cycle average.
    season_w = first_w - level_w                            # first-cycle deviations from level.
    return level_w, trend_w, season_w.astype(float)         # return initial states.

level0_hw_w, trend0_hw_w, seasons0_hw_w = initial_hw_states_w(y_hw_w, m_w)  # initialize.
print("initial level:", round(level0_hw_w, 3))              # inspect level.
print("initial trend:", round(trend0_hw_w, 3))              # inspect trend.
print("initial seasons:", np.round(seasons0_hw_w, 3))       # inspect offsets.
assert len(seasons0_hw_w) == m_w                             # one offset per seasonal position.
```
▶ What you'll see: initialization estimates one level, one trend, and four rotating seasonal offsets.

```python
def holt_winters_add_w(y_w, m_w, alpha_w=0.35, beta_w=0.12, gamma_w=0.25):  # additive Holt-Winters recursion.
    level_w, trend_w, season_w = initial_hw_states_w(y_w, m_w)              # start states.
    levels_w, trends_w = [], []                                             # state history.
    fitted_w = np.full(len(y_w), np.nan)                                    # one-step fitted values.
    for t_w in range(len(y_w)):                                             # process observations online.
        idx_w = t_w % m_w                                                   # current seasonal slot.
        if t_w >= m_w:                                                      # enough history to use same-season offset.
            fitted_w[t_w] = level_w + trend_w + season_w[idx_w]             # forecast before update.
            old_level_w = level_w                                           # keep previous level for trend update.
            level_w = alpha_w * (y_w[t_w] - season_w[idx_w]) + (1 - alpha_w) * (level_w + trend_w)  # deseasonalized level.
            trend_w = beta_w * (level_w - old_level_w) + (1 - beta_w) * trend_w                     # smoothed slope.
            season_w[idx_w] = gamma_w * (y_w[t_w] - level_w) + (1 - gamma_w) * season_w[idx_w]      # same-slot residual.
        levels_w.append(level_w); trends_w.append(trend_w)                  # store states.
    return np.array(levels_w), np.array(trends_w), season_w.copy(), fitted_w # return learned states.

levels_hw_w, trends_hw_w, seasons_hw_w, fitted_hw_w = holt_winters_add_w(y_hw_w, m_w)  # fit from scratch.
print("final level:", round(levels_hw_w[-1], 3), "final trend:", round(trends_hw_w[-1], 3))  # inspect final states.
print("final seasons:", np.round(seasons_hw_w, 3))        # inspect learned seasonal bank.
assert abs(np.sum(seasons_hw_w)) < 2.0                     # additive seasons remain centered-ish.
```
▶ What you'll see: the seasonal bank keeps one offset for each of the four cycle positions.

```python
future_h_w = np.arange(1, 9)                                                      # forecast two more seasons.
future_hw_w = np.array([levels_hw_w[-1] + h_w * trends_hw_w[-1] + seasons_hw_w[(len(y_hw_w) + h_w - 1) % m_w]
                        for h_w in future_h_w])                                  # additive HW forecast.
plt.figure(figsize=(7, 3))                                                        # compact forecast plot.
plt.plot(y_hw_w, label="observed", color="steelblue")                           # history.
plt.plot(np.arange(len(y_hw_w), len(y_hw_w) + len(future_hw_w)), future_hw_w,
         "--o", label="Holt-Winters forecast", color="crimson")                 # future forecast.
plt.title("5: Holt-Winters continues trend plus season")                          # title.
plt.xlabel("time")                                                               # time index.
plt.ylabel("value")                                                              # series scale.
plt.legend()                                                                      # show lines.
plt.show()                                                                        # display plot.
```
▶ What you'll see: the forecast rises with the trend while alternating through the learned seasonal highs and lows.

*Why it's done this way:* The level update subtracts the current seasonal offset so the level is not polluted by predictable seasonality. The seasonal update uses $y_t-\ell_t$ because the seasonal state should explain what remains after the current level (and trend dynamics) have been accounted for. The array of `m` offsets rotates so every Monday, month, or quarter position learns from its own past residuals.

### 6. Initialization, additive assumptions, and validation pitfalls

Smoothing methods are simple, but the details matter. Initial level, initial trend, and initial seasonal states can dominate short histories; high alpha can chase noise; and additive seasonality assumes the seasonal amplitude stays roughly constant rather than scaling with the level.

```python
y_short_w = np.array([10., 12., 13., 12., 12.5])         # short history where initialization matters.
alpha_init_w = 0.35                                      # moderate smoothing.
levels_good_w = [y_short_w[0]]                           # sensible initialization.
levels_bad_w = [20.0]                                    # bad initial level.
for value_w in y_short_w[1:]:                            # run both recursions.
    levels_good_w.append(alpha_init_w * value_w + (1 - alpha_init_w) * levels_good_w[-1])  # good init.
    levels_bad_w.append(alpha_init_w * value_w + (1 - alpha_init_w) * levels_bad_w[-1])    # bad init.
print("good-init levels:", np.round(levels_good_w, 3))   # inspect normal path.
print("bad-init levels:", np.round(levels_bad_w, 3))     # inspect lingering bad start.
assert levels_bad_w[-1] > levels_good_w[-1]              # bad initialization still matters.
```
▶ What you'll see: the bad initial level remains too high even after several updates.

```python
t_mult_w = np.arange(32)                                  # time index.
level_mult_w = 10 + 0.7 * t_mult_w                         # growing baseline.
percent_season_w = np.tile([0.20, -0.10, -0.20, 0.10], 8)  # percentage seasonal effect.
y_mult_w = level_mult_w * (1 + percent_season_w)           # multiplicative-looking series.
amp_first_w = y_mult_w[:4].max() - y_mult_w[:4].min()      # early seasonal amplitude.
amp_last_w = y_mult_w[-4:].max() - y_mult_w[-4:].min()     # late seasonal amplitude.
print("early amplitude:", round(amp_first_w, 3), "late amplitude:", round(amp_last_w, 3))  # compare spread.
assert amp_last_w > amp_first_w                            # amplitude scales with level.
```
▶ What you'll see: the seasonal swing grows as the level grows, which violates additive constant-amplitude seasonality.

```python
plt.figure(figsize=(6, 3))                                      # compact pitfall plot.
plt.plot(y_mult_w, marker="o", markersize=3, label="percentage seasonality")  # multiplicative-looking data.
plt.title("6: additive seasonality struggles when amplitude grows")             # title.
plt.xlabel("time")                                                              # time index.
plt.ylabel("value")                                                             # series scale.
plt.legend()                                                                     # show line label.
plt.show()                                                                       # display plot.
```
▶ What you'll see: the seasonal peaks and troughs get wider over time, so a fixed additive offset is the wrong shape.

*Why it's done this way:* Smoothing recursions are path-dependent: early states are the seed from which later states grow. Validation must therefore be chronological, and seasonal form must match the data scale. If the seasonal effect is a fixed number of units, additive offsets are natural; if it is a fixed percentage, a log transform or multiplicative model is usually more coherent.

## 🛠️ Setup

```python
import numpy as np # load NumPy for arrays, recursions, and numerical checks.
import matplotlib.pyplot as plt # load Matplotlib for line plots, bars, and forecast visualizations.
np.random.seed(0) # make all random examples reproducible across runs.

def ses(y, alpha): # fit simple exponential smoothing and return the level path.
    y = np.asarray(y, dtype=float) # convert input to a float array for stable arithmetic.
    levels = [float(y[0])] # initialize the level at the first observation.
    for value in y[1:]: # process each later observation online.
        levels.append(alpha * value + (1 - alpha) * levels[-1]) # update level by a recency-weighted average.
    return np.array(levels) # return levels for inspection and forecasting.

def holt(y, alpha, beta): # fit Holt's linear method and return level and trend paths.
    y = np.asarray(y, dtype=float) # convert input to floats.
    levels = [float(y[0])] # initialize level at first point.
    trends = [float(y[1] - y[0])] # initialize trend from first difference.
    for value in y[1:]: # process observations online.
        old_level = levels[-1] # save previous level for trend update.
        old_trend = trends[-1] # save previous trend for level prediction.
        level = alpha * value + (1 - alpha) * (old_level + old_trend) # update level toward observed value and prior forecast.
        trend = beta * (level - old_level) + (1 - beta) * old_trend # update trend toward newest level change.
        levels.append(level) # store new level.
        trends.append(trend) # store new trend.
    return np.array(levels), np.array(trends) # return state paths.

def init_additive_season(y, m): # initialize additive Holt-Winters states from two cycles when possible.
    y = np.asarray(y, dtype=float) # convert to floats.
    first = y[:m] # first season.
    second = y[m:2*m] if len(y) >= 2 * m else y[:m] # second season if available.
    level = float(np.mean(first)) # start level as first-cycle average.
    trend = float((np.mean(second) - np.mean(first)) / m) # average per-step change between first two cycles.
    season = first - level # additive offsets around the first-cycle level.
    return level, trend, season.astype(float) # return level, trend, and one offset per seasonal slot.

def holt_winters_additive(y, m, alpha, beta, gamma): # fit additive Holt-Winters from scratch.
    y = np.asarray(y, dtype=float) # convert input to floats.
    level, trend, season = init_additive_season(y, m) # initialize the three state types.
    levels, trends = [], [] # storage for state paths.
    fitted = np.full(len(y), np.nan) # one-step fitted values after the first season.
    for t, value in enumerate(y): # process observations online.
        slot = t % m # current seasonal position.
        if t >= m: # use seasonal recursion once one full season exists.
            fitted[t] = level + trend + season[slot] # one-step forecast made before seeing value.
            old_level = level # save previous level for trend update.
            level = alpha * (value - season[slot]) + (1 - alpha) * (level + trend) # update deseasonalized level.
            trend = beta * (level - old_level) + (1 - beta) * trend # update smoothed trend.
            season[slot] = gamma * (value - level) + (1 - gamma) * season[slot] # update same-slot seasonal residual.
        levels.append(level) # store level.
        trends.append(trend) # store trend.
    return np.array(levels), np.array(trends), season.copy(), fitted # return all states and fitted values.

def hw_forecast(level, trend, season, start_t, horizons): # forecast future additive Holt-Winters values.
    m = len(season) # seasonal period from the offset bank.
    hs = np.arange(1, horizons + 1) # future horizons 1..H.
    return np.array([level + h * trend + season[(start_t + h - 1) % m] for h in hs]) # trend plus rotating seasonal offset.
```

## 🟢 Basics (warm-up)

### Basic 1 — Compute one smoothing update

**Goal.** Update a level from one new observation, because every exponential smoothing model is built from this weighted-average move. We build it in 2 steps.

```python
old_level_b1 = 10.0 # define the previous smoothed level.
y_new_b1 = 14.0 # define the new observed value.
alpha_b1 = 0.25 # choose the recency weight for the observation.
print("old level:", old_level_b1, "new y:", y_new_b1, "alpha:", alpha_b1) # inspect the ingredients.
```
▶ What you'll see: the update will mix an old belief of 10 with a new observation of 14.


```python
def hw_with_custom_init_a4(y_a4, m_a4, level_a4, trend_a4, season_a4, alpha_a4=0.35, beta_a4=0.1, gamma_a4=0.2): # custom-init HW for diagnosis.
    level_a4 = float(level_a4); trend_a4 = float(trend_a4); season_a4 = season_a4.astype(float).copy() # copy states.
    fitted_a4 = np.full(len(y_a4), np.nan) # one-step fitted values.
    for t_a4, value_a4 in enumerate(y_a4): # process observations.
        slot_a4 = t_a4 % m_a4 # seasonal slot.
        if t_a4 >= m_a4: # score after first cycle.
            fitted_a4[t_a4] = level_a4 + trend_a4 + season_a4[slot_a4] # pre-update forecast.
            old_level_a4 = level_a4 # save previous level.
            level_a4 = alpha_a4 * (value_a4 - season_a4[slot_a4]) + (1 - alpha_a4) * (level_a4 + trend_a4) # update level.
            trend_a4 = beta_a4 * (level_a4 - old_level_a4) + (1 - beta_a4) * trend_a4 # update trend.
            season_a4[slot_a4] = gamma_a4 * (value_a4 - level_a4) + (1 - gamma_a4) * season_a4[slot_a4] # update season.
    return fitted_a4 # return fitted values only.

fit_good_a4 = hw_with_custom_init_a4(y_a4, m_a4, level_good_a4, trend_good_a4, season_good_a4) # fit with good starts.
fit_bad_a4 = hw_with_custom_init_a4(y_a4, m_a4, level_good_a4, trend_good_a4, season_bad_a4) # fit with bad season starts.
print("custom fits ready") # confirm both paths ran.
```

### Advanced 5 — Rolling-origin backtest a seasonal forecaster

**Goal.** Evaluate Holt-Winters with rolling origins, because one train/test split can hide whether errors are stable across time. We build it in 5 steps.

```python
horizon_a5 = 4 # forecast one season ahead at each origin.
print("origins:", origins_a5) # inspect rolling cutoffs.
```

