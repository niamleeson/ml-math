# 25.2 — Inductive Logic Programming

Inductive logic programming (ILP) learns readable first-order rules from examples. Instead of returning a vector of weights, it searches over clauses such as `grandparent(X,Z) :- parent(X,Y), parent(Y,Z)` and asks which rule covers the positive examples while avoiding the negative ones.

## 📖 Concept walkthrough — build each idea from scratch

Before the worked examples, we build ILP one idea at a time. Run each cell in order and read the printed intermediate values: facts, substitutions, coverage, subsumption, and FOIL-style information gain are all implemented directly with NumPy, Matplotlib, and the Python standard library. The walkthrough uses a `_w` suffix so it never clashes with the examples below.

```python
import numpy as np  # arrays for counts, scores, and plotting data.
import matplotlib.pyplot as plt  # visual checks for rule search and coverage.
from math import log2  # FOIL information gain uses base-2 logs.
from itertools import product  # build small finite hypothesis spaces.
np.random.seed(0)  # make all randomized demonstrations reproducible.
```

### 1. First-order facts, variables, and clauses

ILP starts with first-order logic. A **fact** is a ground atom such as `parent("ann", "bob")`. A **rule** has variables such as `X`, `Y`, and `Z`, and a body of predicates that must all be satisfied. The target rule here is the two-hop grandparent clause: `grandparent(X,Z) :- parent(X,Y), parent(Y,Z)`.

```python
people_w = ["ann", "bob", "cara", "dan"]  # finite domain for this toy ILP world.
parent_w = {("ann", "bob"), ("bob", "cara"), ("cara", "dan")}  # known background facts.
positive_w = {("ann", "cara"), ("bob", "dan")}  # target atoms the rule should prove.
negative_w = {("ann", "dan"), ("bob", "cara"), ("cara", "ann")}  # counterexamples.

def parent2_w(x, z):
    witnesses = [y for y in people_w if (x, y) in parent_w and (y, z) in parent_w]
    return witnesses

print("parent facts:", sorted(parent_w))
print("witness for grandparent(ann,cara):", parent2_w("ann", "cara"))
assert parent2_w("ann", "cara") == ["bob"]
```
▶ What you'll see: the rule proves `grandparent(ann,cara)` by binding the shared variable `Y` to `bob`.

```python
xs_w = np.array([0, 1, 2])
ys_w = np.array([0, 1, 2])
plt.figure(figsize=(5, 3))
plt.scatter(xs_w, ys_w, s=180, color=["teal", "orange", "purple"])
for x_w, y_w, label_w in zip(xs_w, ys_w, ["parent(ann,bob)", "parent(bob,cara)", "grandparent(ann,cara)"]):
    plt.text(x_w, y_w + 0.08, label_w, ha="center")
plt.arrow(0.18, 0.12, 0.55, 0.55, head_width=0.06, color="gray", length_includes_head=True)
plt.arrow(1.18, 1.12, 0.55, 0.55, head_width=0.06, color="gray", length_includes_head=True)
plt.xticks([]); plt.yticks([]); plt.title("1: two parent facts compose into one rule proof")
plt.show()
```
▶ What you'll see: two background facts chain through the same intermediate person.

*Why it's done this way:* first-order variables let the rule transfer beyond memorized names; the shared `Y` is the mechanism that makes a two-hop relation possible.

### 2. Coverage turns logic into a learning signal

A candidate rule is useful only if it covers many positives and few negatives. Coverage is a supervised-learning score, but it is computed by logical proof: `r ⊨ e` means the rule and facts entail example `e`.

```python
candidates_w = {
    "parent(X,Z)": lambda x, z: (x, z) in parent_w,
    "parent(X,Y)&parent(Y,Z)": lambda x, z: len(parent2_w(x, z)) > 0,
    "X != Z": lambda x, z: x != z,
}
coverage_w = []
for name_w, fn_w in candidates_w.items():
    cp_w = sum(fn_w(*e_w) for e_w in positive_w)
    cn_w = sum(fn_w(*e_w) for e_w in negative_w)
    coverage_w.append((name_w, cp_w, cn_w, cp_w - cn_w))
print("candidate, cov+, cov-, score:")
for row_w in coverage_w:
    print(row_w)
assert coverage_w[1][1:] == (2, 0, 2)
```
▶ What you'll see: the two-hop rule covers both positives and no negatives, so its score is best.

```python
x_w = np.arange(len(coverage_w))
pos_counts_w = [r_w[1] for r_w in coverage_w]
neg_counts_w = [r_w[2] for r_w in coverage_w]
plt.figure(figsize=(7, 3))
plt.bar(x_w - 0.18, pos_counts_w, width=0.36, label="positive coverage", color="seagreen")
plt.bar(x_w + 0.18, neg_counts_w, width=0.36, label="negative coverage", color="indianred")
plt.xticks(x_w, [r_w[0] for r_w in coverage_w], rotation=12)
plt.ylabel("examples covered"); plt.title("2: coverage selects the two-hop rule")
plt.legend(); plt.tight_layout(); plt.show()
```
▶ What you'll see: the overbroad rule covers positives but also covers every negative.

*Why it's done this way:* positives reward explanatory power, while negatives prevent the learner from choosing lazy rules that prove too much.

### 3. Negative examples carve away overbroad rules

If we only count positives, `X != Z` looks as good as the true grandparent rule. Negative examples add the missing pressure: they force a rule to be selective, not merely broad.

```python
pos_only_scores_w = np.array([r_w[1] for r_w in coverage_w])
with_neg_scores_w = np.array([r_w[3] for r_w in coverage_w])
print("positive-only scores:", pos_only_scores_w.tolist())
print("cov+ - cov- scores:", with_neg_scores_w.tolist())
assert pos_only_scores_w[1] == pos_only_scores_w[2]
assert with_neg_scores_w[1] > with_neg_scores_w[2]
```
▶ What you'll see: positive-only scoring ties the true rule with the overbroad rule.

```python
plt.figure(figsize=(6, 3))
plt.plot(pos_only_scores_w, marker="o", label="positives only", color="gray")
plt.plot(with_neg_scores_w, marker="o", label="positives minus negatives", color="navy")
plt.xticks(range(3), [r_w[0] for r_w in coverage_w], rotation=12)
plt.ylabel("score"); plt.title("3: negatives break the false tie")
plt.legend(); plt.tight_layout(); plt.show()
```
▶ What you'll see: adding negative coverage separates the true rule from the broad rule.

*Why it's done this way:* ILP is a search problem; negative examples shrink the search space toward rules that mean the right thing.

### 4. Subsumption organizes rules from general to specific

A rule **subsumes** another rule when it is at least as general. In this tiny language, a rule with fewer required literals covers a superset of examples. `X != Z` is very general; adding `parent(X,Y)` and then `parent(Y,Z)` specializes it.

```python
all_pairs_w = list(product(people_w, people_w))
rule_sets_w = {
    "any pair": set(all_pairs_w),
    "X != Z": {p_w for p_w in all_pairs_w if p_w[0] != p_w[1]},
    "parent(X,Z)": {p_w for p_w in all_pairs_w if (p_w[0], p_w[1]) in parent_w},
    "two-hop": {p_w for p_w in all_pairs_w if len(parent2_w(*p_w)) > 0},
}
def subsumes_w(a, b):
    return rule_sets_w[b].issubset(rule_sets_w[a])
print("does X != Z subsume two-hop?", subsumes_w("X != Z", "two-hop"))
print("does two-hop subsume X != Z?", subsumes_w("two-hop", "X != Z"))
assert subsumes_w("X != Z", "two-hop") and not subsumes_w("two-hop", "X != Z")
```
▶ What you'll see: the broad rule subsumes the more specific two-hop rule, not the other way around.

```python
plt.figure(figsize=(6, 4))
levels_w = {"any pair": (0, 3), "X != Z": (0, 2), "parent(X,Z)": (-1.3, 1), "two-hop": (1.3, 1)}
for name_w, (xv_w, yv_w) in levels_w.items():
    plt.text(xv_w, yv_w, name_w + f"\n{len(rule_sets_w[name_w])} pairs", ha="center", va="center",
             bbox=dict(boxstyle="round", facecolor="white", edgecolor="black"))
for a_w, b_w in [("any pair", "X != Z"), ("X != Z", "parent(X,Z)"), ("X != Z", "two-hop")]:
    xa_w, ya_w = levels_w[a_w]; xb_w, yb_w = levels_w[b_w]
    plt.arrow(xa_w, ya_w - 0.28, xb_w - xa_w, yb_w - ya_w + 0.45, head_width=0.08, color="gray", length_includes_head=True)
plt.xlim(-2.4, 2.4); plt.ylim(0.3, 3.5); plt.axis("off")
plt.title("4: subsumption lattice, general → specific")
plt.show()
```
▶ What you'll see: moving downward in the lattice adds restrictions and reduces coverage.

*Why it's done this way:* subsumption gives ILP a geometry for symbolic search: specialize when a rule covers negatives, generalize when it misses positives.

### 5. FOIL gain chooses the next literal greedily

FOIL specializes a rule one literal at a time. A candidate literal is good when it keeps many positive bindings while discarding negative bindings. A common score is

$$Gain = t\left[\log_2\frac{p_1}{p_1+n_1} - \log_2\frac{p_0}{p_0+n_0}\right],$$

where `p0,n0` are coverage counts before adding the literal, `p1,n1` are after, and `t` is the number of positive bindings retained.

```python
def safe_log_fraction_w(p_w, n_w):
    return -99.0 if p_w == 0 else log2(p_w / (p_w + n_w))

def foil_gain_w(p0_w, n0_w, p1_w, n1_w, t_w):
    return t_w * (safe_log_fraction_w(p1_w, n1_w) - safe_log_fraction_w(p0_w, n0_w))

literal_stats_w = {
    "parent(X,Y)": (2, 1, 2),
    "parent(Y,Z)": (2, 0, 2),
    "X != Z": (2, 3, 2),
}
gains_w = []
for lit_w, (p1_w, n1_w, t_w) in literal_stats_w.items():
    gains_w.append(foil_gain_w(2, 3, p1_w, n1_w, t_w))
print("FOIL gains:", dict(zip(literal_stats_w, np.round(gains_w, 3))))
assert gains_w[1] > gains_w[0] and gains_w[1] > gains_w[2]
```
▶ What you'll see: the literal that removes all negatives has the largest information gain.

```python
plt.figure(figsize=(6, 3))
plt.bar(list(literal_stats_w.keys()), gains_w, color=["steelblue", "seagreen", "gray"])
plt.ylabel("FOIL gain"); plt.title("5: literal choice by information gain")
plt.xticks(rotation=12); plt.tight_layout(); plt.show()
```
▶ What you'll see: FOIL prefers the literal that makes the rule purer.

*Why it's done this way:* the log fraction measures rule precision before and after specialization; multiplying by retained positives rewards improvements that still explain data.

### 6. Learned rules generalize by reasoning over new facts

Once the rule is learned, new predictions come from proof, not retraining. If a new `parent(bob, dan)` fact appears, `grandparent(ann, dan)` becomes provable because the same two-hop rule can bind `Y = bob`.

```python
before_w = parent_w.copy()
after_w = parent_w | {("bob", "dan")}
def two_hop_with_w(facts_w, x_w, z_w):
    return any((x_w, y_w) in facts_w and (y_w, z_w) in facts_w for y_w in people_w)
query_w = ("ann", "dan")
print("before proves ann->dan?", two_hop_with_w(before_w, *query_w))
print("after proves ann->dan?", two_hop_with_w(after_w, *query_w))
assert not two_hop_with_w(before_w, *query_w)
assert two_hop_with_w(after_w, *query_w)
```
▶ What you'll see: the same learned clause changes its answer when the background facts change.

```python
plt.figure(figsize=(5, 3))
plt.bar(["before new fact", "after new fact"], [0, 1], color=["gray", "seagreen"])
plt.ylim(0, 1.2); plt.ylabel("proved grandparent(ann,dan)")
plt.title("6: reasoning absorbs a new fact")
plt.show()
```
▶ What you'll see: the query flips from unproved to proved after one background fact is added.

*Why it's done this way:* ILP separates the learned rule from the fact database, so a correct clause can generalize immediately as facts evolve.

## 🛠️ Setup

```python
import numpy as np # arrays for coverage tables, gains, and plots.
import matplotlib.pyplot as plt # visualizations for every example.
from math import log2 # FOIL gain uses base-2 information terms.
from itertools import product, combinations # small finite searches over people and predicates.
np.random.seed(0) # reproducible ordering and random demonstrations.

PEOPLE = ["ann", "bob", "cara", "dan"] # tiny domain of constants.
PARENT = {("ann", "bob"), ("bob", "cara"), ("cara", "dan")} # background facts.
POS = {("ann", "cara"), ("bob", "dan")} # positive grandparent examples.
NEG = {("ann", "dan"), ("bob", "cara"), ("cara", "ann")} # negative examples.
ALL_PAIRS = list(product(PEOPLE, PEOPLE)) # all possible target atoms over the domain.

def parent2(facts, x, z): # return witnesses y for parent(x,y) and parent(y,z).
    return [y for y in PEOPLE if (x, y) in facts and (y, z) in facts]

def covers_rule(rule_name, x, z, facts=PARENT): # evaluate a named candidate target rule.
    if rule_name == "any":
        return True
    if rule_name == "not_equal":
        return x != z
    if rule_name == "parent":
        return (x, z) in facts
    if rule_name == "two_hop":
        return len(parent2(facts, x, z)) > 0
    if rule_name == "reverse_parent":
        return (z, x) in facts
    raise ValueError("unknown rule")

def coverage(rule_name, positives=POS, negatives=NEG, facts=PARENT): # count positive and negative coverage.
    cp = sum(covers_rule(rule_name, *e, facts=facts) for e in positives)
    cn = sum(covers_rule(rule_name, *e, facts=facts) for e in negatives)
    return int(cp), int(cn)

def score_rule(rule_name, positives=POS, negatives=NEG, facts=PARENT): # simple ILP score.
    cp, cn = coverage(rule_name, positives, negatives, facts)
    return cp - cn

def rule_set(rule_name, facts=PARENT): # all target pairs covered by a named rule.
    return {pair for pair in ALL_PAIRS if covers_rule(rule_name, *pair, facts=facts)}

def subsumes(rule_a, rule_b, facts=PARENT): # rule_a is more general if it covers every pair rule_b covers.
    return rule_set(rule_b, facts).issubset(rule_set(rule_a, facts))

def safe_log_fraction(p, n): # log2 precision with a finite guard when p is zero.
    return -99.0 if p == 0 else log2(p / (p + n))

def foil_gain(p0, n0, p1, n1, t): # FOIL's greedy specialization score.
    return t * (safe_log_fraction(p1, n1) - safe_log_fraction(p0, n0))

def accuracy(rule_name, positives=POS, negatives=NEG, facts=PARENT): # target classification accuracy.
    total = len(positives) + len(negatives)
    correct_pos = sum(covers_rule(rule_name, *e, facts=facts) for e in positives)
    correct_neg = sum(not covers_rule(rule_name, *e, facts=facts) for e in negatives)
    return (correct_pos + correct_neg) / total

def learn_best_rule(candidates, positives=POS, negatives=NEG, facts=PARENT): # tiny exhaustive ILP learner.
    scored = [(score_rule(r, positives, negatives, facts), coverage(r, positives, negatives, facts), r) for r in candidates]
    scored.sort(key=lambda row: (row[0], row[1][0], -row[1][1]), reverse=True)
    return scored[0], scored
```

#### B9. Specialize a broad rule

**Goal.** Compare coverage before and after adding literals, because specialization should reduce negative coverage while retaining positives. We build it in 1 step.

```python
path_b9 = ["not_equal", "parent", "two_hop"] # a toy path from broad toward useful clauses.
```

#### A1. Implement a tiny FOIL-style learner

**Goal.** Greedily add the literal with the highest FOIL gain, because classic ILP often searches by specializing a clause until negatives disappear. We build it in 1 step.

```python
candidate_literals_a1 = ["parent(X,Y)", "parent(Y,Z)", "X != Z"] # finite specialization choices.
remaining_negs_a1 = 3 # start with three negatives covered by the empty body.
body_a1 = [] # learned body starts empty.
trace_a1 = [] # store chosen literal and negative coverage.
current_p_a1, current_n_a1 = 2, 3 # broad rule coverage.
for round_a1 in range(2):
    table_a1 = {"parent(X,Y)": (2, 1, 2), "parent(Y,Z)": (2, 0, 2), "X != Z": (2, 3, 2)} if round_a1 == 0 else {"parent(X,Y)": (2, 0, 2), "X != Z": (2, 0, 2)}
    gains_a1 = {lit_a1: foil_gain(current_p_a1, current_n_a1, *stats_a1) for lit_a1, stats_a1 in table_a1.items() if lit_a1 not in body_a1}
    chosen_a1 = max(gains_a1, key=gains_a1.get)
    p1_a1, n1_a1, _ = table_a1[chosen_a1]
    body_a1.append(chosen_a1); current_p_a1, current_n_a1 = p1_a1, n1_a1
    trace_a1.append((chosen_a1, current_p_a1, current_n_a1))
    if current_n_a1 == 0:
        break
print("learned body:", body_a1, "trace:", trace_a1) # inspect greedy construction.
assert current_n_a1 == 0 and current_p_a1 == 2 # verify the learned body is consistent in this toy run.
plt.figure(figsize=(6, 3)) # visualize negative removal over greedy steps.

plt.title("A1: FOIL-style specialization removes negatives")
plt.xticks(rotation=15); plt.tight_layout(); plt.show()
```
▶ What you'll see: the greedy learner stops once the current rule covers no negatives.
