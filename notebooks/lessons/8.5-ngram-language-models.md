# 8.5 — N-gram Language Models

N-gram language models predict the next token by counting what followed the same short history before. In this lesson, you will build unigram, bigram, and trigram models from scratch, see why maximum-likelihood count ratios are the natural estimates, add smoothing so unseen continuations do not kill a sentence, and measure whole-sequence quality with perplexity.

Before the terse worked examples, we build n-gram language modeling one idea at a time. This walkthrough is self-contained (it imports what it needs) and uses a `_w` suffix on its variables so it never clashes with the examples below.

### 1. Tokens, vocabulary, and unigram base rates

A language model starts by choosing the events it will assign probabilities to. Here the events are word tokens. A **unigram** model ignores context and estimates $P(w)$ from token frequencies. In the corpus `a b a b a c`, the vocabulary is `[a,b,c]`, counts are `[3,2,1]`, and the base rate of `a` is $3/6=0.5$.

```python
tokens_w = "a b a b a c".split()  # a tiny corpus where every token is visible.
vocab_w = sorted(set(tokens_w))  # the event space V that probabilities must sum over.
counts_w = Counter(tokens_w)  # count how often each token occurs.
print("tokens:", tokens_w)
print("vocabulary:", vocab_w)
print("counts:", [counts_w[v] for v in vocab_w])
```
▶ What you'll see: six tokens, three vocabulary types, and the count pattern `[3, 2, 1]`.

```python
total_w = len(tokens_w)  # denominator for unigram probabilities.
unigram_probs_w = np.array([counts_w[v] / total_w for v in vocab_w])  # MLE P(w)=count/total.
print("unigram probabilities:", np.round(unigram_probs_w, 3))
print("P(a):", unigram_probs_w[vocab_w.index("a")])
assert unigram_probs_w[vocab_w.index("a")] == 0.5
```
▶ What you'll see: `a` receives probability 0.5 because it occupies half the corpus.

```python
plt.figure(figsize=(4.4, 3))
plt.bar(vocab_w, unigram_probs_w, color="teal")
plt.title("1: unigram base rates")
plt.ylabel("P(token)")
plt.ylim(0, 0.6)
plt.show()
```
▶ What you'll see: `a` has the tallest bar, but the plot contains no information about what follows `a`.

*Why it's done this way:* maximum likelihood chooses the probabilities that make the observed tokens as probable as possible under a fixed unigram model. Because every occurrence of `a` contributes a factor $P(a)$ to the likelihood, the best estimate gives `a` exactly its empirical share, $c(a)/N$; the limitation is that context has been deliberately thrown away.

### 2. Bigram histories turn counts into conditional probabilities

A bigram model keeps one token of memory. Instead of one global count for each word, it counts rows of the form `(history, next)`. The conditional probability after history $h$ is a row-normalized count: $P(w\mid h)=c(h,w)/\sum_v c(h,v)$. This denominator is local to the history row, not the full corpus.

```python
pairs_w = list(zip(tokens_w[:-1], tokens_w[1:]))  # adjacent history-next pairs.
bigram_counts_w = defaultdict(Counter)  # history -> Counter(next tokens).
for h_w, nxt_w in pairs_w:
    bigram_counts_w[h_w][nxt_w] += 1
print("bigram pairs:", pairs_w)
print("continuations after a:", dict(bigram_counts_w["a"]))
```
▶ What you'll see: after `a`, the corpus continues with `b`, `b`, and `c`.

```python
row_a_counts_w = np.array([bigram_counts_w["a"][v] for v in vocab_w])  # counts over [a,b,c].
row_a_probs_w = row_a_counts_w / row_a_counts_w.sum()  # raw conditional row.
print("row counts after a:", row_a_counts_w.tolist())
print("P(.|a):", np.round(row_a_probs_w, 3))
assert np.allclose(row_a_probs_w, [0, 2/3, 1/3])
```
▶ What you'll see: after `a`, `b` has probability 0.667 and `c` has probability 0.333.

```python
plt.figure(figsize=(4.4, 3))
plt.bar(vocab_w, row_a_probs_w, color="seagreen")
plt.title("2: conditional distribution after history 'a'")
plt.ylabel("P(next | a)")
plt.ylim(0, 0.75)
plt.show()
```
▶ What you'll see: the local grammar says `a → b` is twice as common as `a → c`.

*Why it's done this way:* conditioning partitions the evidence by history. Dividing by the row sum answers “given that the current history is `a`, which next token happened?” Dividing by the corpus length would mix in unrelated histories and would no longer produce a conditional distribution whose row sums to one.

### 3. Maximum likelihood is the count ratio hiding in the product

For one fixed history row, suppose the model assigns probabilities $p_a,p_b,p_c$ to the next token after `a`. The observed row is `[0,2,1]`, so its likelihood is $p_b^2p_c$. The product is maximized when probabilities match the observed proportions `[0, 2/3, 1/3]`.

```python
candidate_pb_w = np.linspace(0.01, 0.98, 80)  # candidate P(b|a) values.
likelihood_w = []
for pb_w in candidate_pb_w:
    pc_w = 1 - pb_w  # keep P(a|a)=0 for this one-dimensional slice.
    likelihood_w.append((pb_w ** 2) * pc_w)  # row likelihood for b,b,c.
likelihood_w = np.array(likelihood_w)
best_pb_w = candidate_pb_w[np.argmax(likelihood_w)]
print("best grid P(b|a):", round(float(best_pb_w), 3))
print("count-ratio P(b|a):", round(2/3, 3))
```
▶ What you'll see: the best grid value lands near the count ratio 0.667.

```python
plt.figure(figsize=(4.6, 3))
plt.plot(candidate_pb_w, likelihood_w, color="purple")
plt.axvline(2/3, color="black", linestyle="--", label="count ratio 2/3")
plt.title("3: likelihood peaks at empirical frequency")
plt.xlabel("candidate P(b | a)")
plt.ylabel("likelihood for b,b,c")
plt.legend()
plt.show()
```
▶ What you'll see: the likelihood curve peaks exactly where the empirical row proportion says it should.

*Why it's done this way:* the count ratio is not an arbitrary heuristic. Under a multinomial row with fixed history, maximizing the product of assigned probabilities subject to the row summing to one yields $p_w=c(h,w)/c(h)$. The ratio is the probability vector that spends mass in the same proportions as the evidence.

### 4. Add-alpha smoothing prevents zero-probability collapse

Raw bigram MLE assigns zero probability to any continuation not seen after a history. That is dangerous: one unseen transition makes a whole sentence probability zero. Add-$\alpha$ smoothing changes the row to $P(w\mid h)=\frac{c(h,w)+\alpha}{\sum_v c(h,v)+\alpha|V|}$, spending a little probability on unseen events by taking some mass from seen ones.

```python
alpha_w = 1.0  # add-one smoothing.
smoothed_counts_w = row_a_counts_w + alpha_w  # add alpha to every vocabulary cell.
smoothed_den_w = row_a_counts_w.sum() + alpha_w * len(vocab_w)  # row count plus alpha for each type.
smoothed_probs_w = smoothed_counts_w / smoothed_den_w
print("raw counts after a:", row_a_counts_w.tolist())
print("smoothed counts:", smoothed_counts_w.tolist())
print("smoothed P(.|a):", np.round(smoothed_probs_w, 3))
assert np.allclose(smoothed_probs_w, [1/6, 3/6, 2/6])
```
▶ What you'll see: the unseen `a → a` transition receives probability 0.167 instead of 0.

```python
x_w = np.arange(len(vocab_w))
plt.figure(figsize=(4.8, 3))
plt.bar(x_w - 0.18, row_a_probs_w, width=0.36, label="raw", color="crimson")
plt.bar(x_w + 0.18, smoothed_probs_w, width=0.36, label="add-one", color="seagreen")
plt.xticks(x_w, vocab_w)
plt.title("4: smoothing redistributes row mass")
plt.ylabel("P(next | a)")
plt.legend()
plt.show()
```
▶ What you'll see: smoothing raises unseen `a` and lowers the previously dominant `b`.

*Why it's done this way:* add-$\alpha$ behaves like pretending each continuation was observed $\alpha$ extra times before seeing data. The denominator must add $\alpha|V|$ because we added $\alpha$ to every vocabulary cell. This preserves a valid probability row while trading a little bias for much lower variance on rare rows.

### 5. Sentence probability multiplies local conditional probabilities

An n-gram model prices a sequence by chaining local next-token probabilities. For `a b a c`, the bigram factors are $P(b\mid a)$, $P(a\mid b)$, and $P(c\mid a)$. With raw counts they are $2/3$, $1$, and $1/3$, so the sequence probability is their product.

```python
def bigram_prob_w(history, word, alpha=0.0):
    row = bigram_counts_w[history]
    numer = row[word] + alpha
    denom = sum(row.values()) + alpha * len(vocab_w)
    return numer / denom if denom else 1 / len(vocab_w)

seq_w = "a b a c".split()
factors_w = np.array([bigram_prob_w(seq_w[i-1], seq_w[i]) for i in range(1, len(seq_w))])
print("sequence:", seq_w)
print("bigram factors:", np.round(factors_w, 3))
assert np.allclose(factors_w, [2/3, 1.0, 1/3])
```
▶ What you'll see: the three local probabilities are `[0.667, 1.000, 0.333]`.

```python
seq_prob_w = float(np.prod(factors_w))
log_prob_w = float(np.sum(np.log(factors_w)))
print("sequence probability:", round(seq_prob_w, 6))
print("log probability:", round(log_prob_w, 6))
assert round(seq_prob_w, 6) == 0.222222
```
▶ What you'll see: multiplying local probabilities gives 0.222222; logs store the same product as a safer sum.

*Why it's done this way:* the n-gram assumption approximates a long conditional chain by keeping only the most recent history. Multiplication is required because every transition must happen; logs are used in practice because many small probabilities underflow, while sums of logs remain numerically stable.

### 6. Perplexity turns sequence likelihood into average branching factor

Perplexity is $\exp(-\text{mean log probability})$ over predicted tokens. Low perplexity means the model assigned high probability to the actual next tokens. For `a b a c`, the raw bigram perplexity is about 1.651, meaning the model behaves as if it had roughly 1.65 plausible choices at each step.

```python
mean_neg_log_w = -float(np.mean(np.log(factors_w)))  # average surprise per predicted token.
perplexity_w = float(np.exp(mean_neg_log_w))  # convert surprise back to branching-factor scale.
print("mean negative log:", round(mean_neg_log_w, 6))
print("perplexity:", perplexity_w)
assert abs(perplexity_w - 1.6509636244473134) < 1e-12
```
▶ What you'll see: perplexity is exactly the lesson value `1.6509636244473134`.

```python
plt.figure(figsize=(4.6, 3))
plt.bar(["P(b|a)", "P(a|b)", "P(c|a)"], factors_w, color="darkorange")
plt.axhline(1/perplexity_w, color="black", linestyle="--", label="geometric mean prob")
plt.title("6: factors behind perplexity")
plt.ylabel("conditional probability")
plt.xticks(rotation=15)
plt.legend()
plt.show()
```
▶ What you'll see: the low `P(c|a)` factor raises perplexity because it makes one step surprising.

*Why it's done this way:* products shrink with sequence length, so raw sequence probability unfairly penalizes longer strings. Averaging log probabilities normalizes per predicted token; exponentiating makes the result interpretable as an effective number of choices per step.

### 7. Greedy and sampled generation expose what the counts learned

After training counts, the model can generate by repeatedly choosing a next token. Greedy decoding picks the largest probability each time; sampling draws according to the full row distribution. Greedy is deterministic and can get stuck in count loops, while sampling shows the uncertainty that smoothing kept alive.

```python
def next_distribution_w(history, alpha=1.0):
    row = bigram_counts_w[history]
    counts = np.array([row[v] for v in vocab_w], dtype=float)
    probs = (counts + alpha) / (counts.sum() + alpha * len(vocab_w))
    return probs

greedy_w = ["a"]
for _ in range(4):
    probs = next_distribution_w(greedy_w[-1], alpha=1.0)
    greedy_w.append(vocab_w[int(np.argmax(probs))])
print("greedy path:", greedy_w)
assert greedy_w == ["a", "b", "a", "b", "a"]
```
▶ What you'll see: greedy generation loops `a, b, a, b, a` because those are the strongest local transitions.

```python
np.random.seed(0)
sampled_w = ["a"]
for _ in range(8):
    probs = next_distribution_w(sampled_w[-1], alpha=1.0)
    sampled_w.append(str(np.random.choice(vocab_w, p=probs)))
print("sampled path:", sampled_w)
```
▶ What you'll see: a plausible but not necessarily greedy path; rare continuations can appear because their smoothed probability is nonzero.

```python
plt.figure(figsize=(4.6, 3))
plt.bar(vocab_w, next_distribution_w("a", alpha=1.0), color="steelblue")
plt.title("7: sampling distribution after 'a'")
plt.ylabel("smoothed P(next | a)")
plt.ylim(0, 0.6)
plt.show()
```
▶ What you'll see: `b` is most likely after `a`, but `a` and `c` remain possible.

*Why it's done this way:* generation reuses the same conditional rows learned for scoring. Greedy answers “what is the local mode?” whereas sampling answers “what sequences does the full distribution place mass on?” The difference matters because an n-gram model has no global plan beyond local counts.

## 🛠️ Setup

```python
import numpy as np  # load NumPy for arrays, logs, random choice, and numerical checks.
import matplotlib.pyplot as plt  # load Matplotlib for bars, heatmaps, and learning curves.
from collections import Counter, defaultdict  # use standard-library counters for n-gram tables.
np.random.seed(0)  # make random sampling examples reproducible.

def make_ngrams(tokens, n):  # collect (history tuple, next token) pairs for an n-gram model.
    return [(tuple(tokens[i-n+1:i]), tokens[i]) for i in range(n - 1, len(tokens))]  # history length is n-1.

def build_ngram_counts(tokens, n):  # build a mapping from histories to next-token counters.
    table = defaultdict(Counter)  # missing histories create empty counters.
    for hist, nxt in make_ngrams(tokens, n):  # iterate over all observed training pairs.
        table[hist][nxt] += 1  # increment the continuation count for that history.
    return table  # return history -> Counter(next).

def prob_next(table, vocab, history, word, alpha=0.0):  # compute add-alpha P(word | history).
    history = tuple(history)  # normalize history so one token and many tokens work the same way.
    row = table[history]  # retrieve continuation counts; empty if unseen.
    denom = sum(row.values()) + alpha * len(vocab)  # row evidence plus pseudo-count mass.
    if denom == 0:  # no evidence and no smoothing would be undefined.
        return 1.0 / len(vocab)  # fall back to a uniform distribution over the event space.
    return (row[word] + alpha) / denom  # add-alpha conditional probability.

def distribution(table, vocab, history, alpha=0.0):  # return a full row distribution as a NumPy array.
    return np.array([prob_next(table, vocab, history, word, alpha) for word in vocab], dtype=float)  # one probability per vocabulary word.

def sequence_perplexity(tokens, table, vocab, n, alpha=0.0):  # compute n-gram perplexity for a token sequence.
    logs = []  # store log probabilities for predicted positions.
    for i in range(n - 1, len(tokens)):  # start once enough history is available.
        hist = tuple(tokens[i-n+1:i])  # extract the previous n-1 tokens.
        p = prob_next(table, vocab, hist, tokens[i], alpha)  # score the actual next token.
        logs.append(np.log(p))  # add log probability to avoid multiplying tiny numbers.
    return float(np.exp(-np.mean(logs)))  # average surprise converted to perplexity.

def show_row(probs, labels, title):  # draw a compact probability-row bar chart.
    plt.figure(figsize=(4.5, 3))  # create a small notebook-friendly figure.
    plt.bar(labels, probs, color="teal")  # show one bar per token.
    plt.ylim(0, max(0.05, float(np.max(probs)) * 1.2))  # leave headroom above the tallest bar.
    plt.ylabel("probability")  # label the probability scale.
    plt.title(title)  # identify the row being shown.
    plt.show()  # display the figure.
```

### Basic 8 — Compute sequence probability

**Goal.** Multiply local bigram probabilities for `a b a c`, because a sequence probability is a chain of next-token choices. We build it in 2 steps.

```python
tokens_b8 = "a b a b a c".split()  # training tokens.
table_b8 = build_ngram_counts(tokens_b8, 2)  # raw bigram table.
vocab_b8 = sorted(set(tokens_b8))  # vocabulary.
seq_b8 = "a b a c".split()  # sequence to score.
factors_b8 = np.array([prob_next(table_b8, vocab_b8, (seq_b8[i-1],), seq_b8[i], 0.0) for i in range(1, len(seq_b8))])  # score each transition.
print("factors:", np.round(factors_b8, 3))  # inspect local probabilities.
```
