# 8.4 — Bag-of-Words & TF-IDF

Bag-of-words turns text into a vector by fixing vocabulary columns and counting which words appear; TF-IDF then rescales those counts so common words do not drown out rarer, more diagnostic terms. In this lesson, you will build the document-term matrix, term frequency, smoothed inverse document frequency, TF-IDF weights, and cosine retrieval from pure Python and NumPy so every number is inspectable.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build bag-of-words and TF-IDF one idea at a time. Run each cell in order and read the printed intermediate values — every piece of math is shown before it becomes a helper. This walkthrough is self-contained (it imports what it needs) and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays + linear algebra for document vectors.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
from collections import Counter  # transparent word-count dictionaries.
np.random.seed(0)  # reproducibility for any small simulations.
```

### 1. Tokenize text and fix vocabulary axes

A model cannot multiply paragraphs, so the first move is to turn each document into tokens and fix one shared vocabulary order. That order is not cosmetic: the vector `[0, 1, 0, 0, 1]` means `cat sat` only because column 1 is `cat` and column 4 is `sat`. Once the axes are fixed, every document and query must use the same columns.

```python
corpus_w = ["cat sat", "cat ate fish", "dog sat"]  # the tiny corpus from the lesson.
tokens_w = [doc.lower().split() for doc in corpus_w]  # simple whitespace tokenization.
vocab_w = sorted(set(word for doc in tokens_w for word in doc))  # deterministic column order.
print("tokens:", tokens_w)  # inspect the words each row contains.
print("vocabulary columns:", vocab_w)  # inspect the fixed coordinate system.
```
▶ What you'll see: three token lists and five vocabulary columns: ate, cat, dog, fish, sat.

```python
plt.figure(figsize=(5, 2.6))  # compact vocabulary-position plot.
plt.bar(vocab_w, np.arange(1, len(vocab_w) + 1), color="slateblue")  # show column positions.
plt.title("1: vocabulary order becomes vector axes")  # label the concept.
plt.ylabel("column index + 1")  # human-readable index height.
plt.show()  # display the axis map.
```
▶ What you'll see: each word occupies one stable column; changing this order would change every vector.

*Why it's done this way: a vector space needs shared axes before documents can be compared. Sorting is not mathematically required, but using one deterministic order prevents train/serve vocabulary mismatches where the same numbers secretly mean different words.*

### 2. Build the bag-of-words count matrix

Bag-of-words deliberately forgets order and keeps counts. Each row is a document, each column is a vocabulary word, and each entry says how many times that word appears in that document. For the tiny corpus, all counts happen to be 0 or 1, but the method also handles repeated words.

```python
word_to_col_w = {word: j for j, word in enumerate(vocab_w)}  # map each word to its column.
X_counts_w = np.zeros((len(tokens_w), len(vocab_w)), dtype=float)  # document-term matrix.
for i_w, doc_w in enumerate(tokens_w):  # fill one row per document.
    for word_w in doc_w:  # count each token in that document.
        X_counts_w[i_w, word_to_col_w[word_w]] += 1  # add one count to the word's column.
print("count matrix:\n", X_counts_w.astype(int))  # inspect the BoW matrix.
print("shape:", X_counts_w.shape)  # 3 documents by 5 vocabulary terms.
assert X_counts_w.shape == (3, 5)  # verify the lesson shape.
```
▶ What you'll see: rows `[0,1,0,0,1]`, `[1,1,0,1,0]`, and `[0,0,1,0,1]`.

```python
plt.figure(figsize=(5, 3))  # compact heatmap.
plt.imshow(X_counts_w, cmap="viridis", aspect="auto")  # color = count.
plt.colorbar(label="count")  # read colors as numbers.
plt.xticks(range(len(vocab_w)), vocab_w)  # label columns with vocabulary words.
plt.yticks(range(len(corpus_w)), ["d0", "d1", "d2"])  # label document rows.
plt.title("2: bag-of-words count matrix")  # title the heatmap.
plt.show()  # display the matrix.
```
▶ What you'll see: a sparse 3×5 matrix; document 1 is the only row with `fish`.

*Why it's done this way: the matrix converts text into ordinary numerical rows while preserving transparency. We lose syntax, but gain columns whose values can be inspected, plotted, multiplied, and fed to simple ML models.*

### 3. Binary presence drops repetition information

Sometimes only presence matters: did the word appear at least once? A binary bag-of-words matrix turns every nonzero count into 1. That is useful for features such as keyword flags, but it intentionally cannot distinguish one mention from ten.

```python
X_binary_w = (X_counts_w > 0).astype(float)  # presence/absence version of BoW.
active_per_doc_w = X_binary_w.sum(axis=1)  # number of present words per document.
print("binary matrix:\n", X_binary_w.astype(int))  # inspect presence features.
print("active entries per document:", active_per_doc_w.astype(int))  # 2, 3, 2.
assert int(X_binary_w.sum()) == 7  # seven active entries out of fifteen.
```
▶ What you'll see: the same nonzero pattern as the count matrix, with seven active entries.

```python
repeat_doc_w = "cat cat cat sat".split()  # a document where repetition matters.
repeat_counts_w = Counter(repeat_doc_w)  # count tokens transparently.
repeat_binary_w = {word: int(count > 0) for word, count in repeat_counts_w.items()}  # presence only.
print("counts:", dict(repeat_counts_w))  # cat appears three times.
print("binary presence:", repeat_binary_w)  # cat only records as present.
```
▶ What you'll see: counts remember `cat: 3`, while binary presence compresses it to `cat: 1`.

*Why it's done this way: binarizing is a modeling choice. It reduces sensitivity to spammy repetition, but discards within-document strength, so later TF will keep graded frequency instead of flattening it.*

### 4. Term frequency normalizes for document length

Raw counts favor long documents because they have more chances to contain every word. Term frequency divides each count by the document length, turning counts into within-document proportions. For `cat cat sat`, `cat` has frequency `2/3`, so it is twice as prominent as `sat`.

```python
long_doc_w = "cat cat sat".split()  # a length-3 document.
long_counts_w = Counter(long_doc_w)  # raw counts.
long_vec_w = np.array([long_counts_w.get(word, 0) for word in vocab_w], dtype=float)  # align to vocab.
long_tf_w = long_vec_w / len(long_doc_w)  # divide by document length.
print("count vector:", long_vec_w.astype(int))  # [0,2,0,0,1].
print("term frequency:", np.round(long_tf_w, 3))  # [0,.667,0,0,.333].
assert round(float(long_tf_w[word_to_col_w["cat"]]), 3) == 0.667  # verify cat TF.
assert round(float(long_tf_w[word_to_col_w["sat"]]), 3) == 0.333  # verify sat TF.
```
▶ What you'll see: `cat` receives 0.667 and `sat` receives 0.333.

```python
plt.figure(figsize=(5, 3))  # compare raw and normalized values.
plt.bar(np.arange(len(vocab_w)) - 0.18, long_vec_w, width=0.36, label="count", color="gray")  # raw counts.
plt.bar(np.arange(len(vocab_w)) + 0.18, long_tf_w, width=0.36, label="tf", color="teal")  # normalized frequencies.
plt.xticks(range(len(vocab_w)), vocab_w)  # vocabulary labels.
plt.title("4: counts versus term frequency")  # title the comparison.
plt.legend()  # show bar meanings.
plt.show()  # display the grouped bars.
```
▶ What you'll see: TF keeps `cat` twice as large as `sat`, but puts the row on a length-normalized scale.

*Why it's done this way: dividing by length asks “what fraction of this document is this term?” instead of “how many tokens did this document have?” That protects retrieval from rewarding verbosity by default.*

### 5. IDF rewards rarer vocabulary columns

Term frequency is local; inverse document frequency is global. IDF looks across the corpus and assigns larger weights to words that appear in fewer documents. We use the smoothed convention from the lesson, $\log((1+N)/(1+df_t))+1$, so every seen term has a finite, positive weight.

```python
N_w = X_counts_w.shape[0]  # number of documents.
df_w = (X_counts_w > 0).sum(axis=0)  # document frequency for each term.
idf_w = np.log((1 + N_w) / (1 + df_w)) + 1  # smoothed inverse document frequency.
print("df:", dict(zip(vocab_w, df_w.astype(int))))  # inspect corpus-wide counts.
print("idf:", dict(zip(vocab_w, np.round(idf_w, 3))))  # inspect rarity weights.
assert round(float(idf_w[word_to_col_w["cat"]]), 3) == 1.288  # df cat = 2.
assert round(float(idf_w[word_to_col_w["fish"]]), 3) == 1.693  # df fish = 1.
```
▶ What you'll see: `fish` gets 1.693 while `cat` gets 1.288 because `fish` appears in fewer documents.

```python
plt.figure(figsize=(5, 3))  # IDF bar chart.
plt.bar(vocab_w, idf_w, color="darkorange")  # each column's rarity weight.
plt.title("5: smoothed IDF by term")  # title the plot.
plt.ylabel("log((1+N)/(1+df)) + 1")  # label the formula.
plt.show()  # display IDF values.
```
▶ What you'll see: rarer columns have taller bars; common columns are still positive because of the `+1` offset.

*Why it's done this way: IDF is a corpus-level correction for diagnosticity. It does not understand meaning; it only encodes the useful statistical hunch that words appearing everywhere are less discriminative than words appearing in fewer rows.*

### 6. TF-IDF combines local frequency and global rarity

TF-IDF multiplies term frequency by IDF: $w_{d,t}=tf_{d,t}\,idf_t$. A term must matter inside the document and be selective across the corpus to receive a large weight. This is why `fish` can become a strong coordinate for the document that contains it.

```python
row_lengths_w = X_counts_w.sum(axis=1, keepdims=True)  # token count per document.
TF_w = np.divide(X_counts_w, row_lengths_w, out=np.zeros_like(X_counts_w), where=row_lengths_w != 0)  # row-normalize counts.
TFIDF_w = TF_w * idf_w  # multiply each column by its IDF.
print("TF matrix:\n", np.round(TF_w, 3))  # inspect local frequencies.
print("TF-IDF matrix:\n", np.round(TFIDF_w, 3))  # inspect weighted features.
assert round(float(TFIDF_w[1, word_to_col_w["fish"]]), 3) == 0.564  # (1/3)*1.693.
```
▶ What you'll see: document 1 has nonzero TF-IDF on `ate`, `cat`, and `fish`, with rare terms weighted higher.

```python
plt.figure(figsize=(5, 3))  # heatmap of TF-IDF rows.
plt.imshow(TFIDF_w, cmap="magma", aspect="auto")  # color = TF-IDF weight.
plt.colorbar(label="tf-idf")  # read colors as weights.
plt.xticks(range(len(vocab_w)), vocab_w)  # vocabulary labels.
plt.yticks(range(len(corpus_w)), ["d0", "d1", "d2"])  # document labels.
plt.title("6: TF-IDF document-term matrix")  # title the matrix.
plt.show()  # display the weighted matrix.
```
▶ What you'll see: rare terms such as `ate`, `dog`, and `fish` glow more strongly than equally frequent but less rare terms.

*Why it's done this way: multiplication is an AND-like scoring rule: a coordinate is large only when the word is locally present and globally informative. A high IDF cannot help a document that lacks the word, and a high count is moderated when the word appears in many documents.*

### 7. Cosine similarity retrieves by weighted overlap

After TF-IDF, documents and queries are vectors in the same vocabulary space. Cosine similarity compares direction instead of raw length, so a short query can retrieve a longer document if their weighted coordinates overlap. For the query `cat fish`, the document containing both words should win.

```python
query_w = "cat fish".split()  # retrieval query.
query_counts_w = np.array([query_w.count(word) for word in vocab_w], dtype=float)  # align query to vocab.
query_tf_w = query_counts_w / query_counts_w.sum()  # query term frequency.
query_tfidf_w = query_tf_w * idf_w  # weight query with the same corpus IDF.
print("query TF-IDF:", np.round(query_tfidf_w, 3))  # inspect query vector.
```
▶ What you'll see: only `cat` and `fish` are nonzero in the query vector.

```python
def cosine_w(a, b):  # guarded cosine for walkthrough vectors.
    denom = np.linalg.norm(a) * np.linalg.norm(b)  # product of vector lengths.
    return 0.0 if denom == 0 else float(np.dot(a, b) / denom)  # direction similarity.

scores_w = np.array([cosine_w(row_w, query_tfidf_w) for row_w in TFIDF_w])  # score each document.
print("cosine scores:", np.round(scores_w, 3))  # [0.428, 0.782, 0.000].
print("best document:", int(np.argmax(scores_w)), corpus_w[int(np.argmax(scores_w))])  # d1 wins.
assert np.allclose(np.round(scores_w, 3), np.array([0.428, 0.782, 0.000]))  # verify lesson scores.
```
▶ What you'll see: scores `[0.428, 0.782, 0.000]`; `cat ate fish` ranks first.

```python
plt.figure(figsize=(5, 3))  # retrieval score plot.
plt.bar(["d0", "d1", "d2"], scores_w, color="seagreen")  # one cosine per document.
plt.title("7: TF-IDF cosine retrieval for 'cat fish'")  # title the plot.
plt.ylabel("cosine similarity")  # label score scale.
plt.ylim(0, 1)  # cosine range for nonnegative vectors.
plt.show()  # display the ranking.
```
▶ What you'll see: document 1 has the tallest bar because it overlaps both query terms.

*Why it's done this way: cosine normalizes away vector length after TF-IDF weighting, so ranking depends on weighted direction. The zero for the dog document means no shared vocabulary with the query, not a deep semantic judgment about dogs and fish.*

### 8. What bag-of-words discards: order and unseen words

Bag-of-words has no coordinate for word position, so `dog bites man` and `man bites dog` become identical under the same vocabulary. It also ignores words not in the fixed vocabulary at serving time, unless you explicitly add an unknown-token strategy.

```python
sent1_w = "dog bites man".split()  # sentence one.
sent2_w = "man bites dog".split()  # same words, different order.
order_vocab_w = sorted(set(sent1_w + sent2_w))  # fixed columns.
vec1_w = np.array([sent1_w.count(word) for word in order_vocab_w])  # BoW for sentence one.
vec2_w = np.array([sent2_w.count(word) for word in order_vocab_w])  # BoW for sentence two.
print("vocab:", order_vocab_w)  # inspect axes.
print("vectors equal?", np.array_equal(vec1_w, vec2_w), vec1_w.tolist(), vec2_w.tolist())  # order is lost.
assert np.array_equal(vec1_w, vec2_w)  # same BoW despite different meaning.
```
▶ What you'll see: the two sentences produce the same vector even though their roles differ.

```python
serve_doc_w = "cat whale sat".split()  # contains an unseen word, whale.
serve_vec_w = np.array([serve_doc_w.count(word) for word in vocab_w])  # only known columns survive.
dropped_w = [word for word in serve_doc_w if word not in word_to_col_w]  # words with no column.
print("served vector:", serve_vec_w.astype(int))  # cat and sat remain.
print("dropped unseen tokens:", dropped_w)  # whale has no learned column.
```
▶ What you'll see: `whale` is dropped because the 8.4 vocabulary has no `whale` axis.

*Why it's done this way: fixed sparse vectors are simple and inspectable, but the simplicity is purchased by discarding sequence and out-of-vocabulary information. N-grams, embeddings, and hybrid retrieval systems are later ways to buy some of that information back.*

## 🛠️ Setup

```python
import numpy as np  # load NumPy for document matrices, vector math, and assertions.
import matplotlib.pyplot as plt  # load Matplotlib for heatmaps, bar charts, and retrieval plots.
from collections import Counter  # load Counter for readable pure-Python token counts.
np.random.seed(0)  # make all examples reproducible.

def tokenize(text):  # split lowercase toy text into tokens.
    return text.lower().split()  # simple whitespace tokenization for controlled examples.

def build_vocab(docs):  # create a deterministic vocabulary from a list of documents.
    return sorted(set(word for doc in docs for word in tokenize(doc)))  # one sorted column per distinct token.

def count_matrix(docs, vocab):  # build a document-term count matrix from scratch.
    word_to_col = {word: j for j, word in enumerate(vocab)}  # map tokens to fixed columns.
    X = np.zeros((len(docs), len(vocab)), dtype=float)  # allocate one row per document.
    for i, doc in enumerate(docs):  # fill one document row at a time.
        for word in tokenize(doc):  # scan the document's tokens.
            if word in word_to_col:  # ignore unseen words when a fixed vocab is supplied.
                X[i, word_to_col[word]] += 1  # add one count to the matching column.
    return X  # return the count matrix.

def tf_matrix(X):  # normalize counts into term frequencies.
    lengths = X.sum(axis=1, keepdims=True)  # count tokens per row.
    return np.divide(X, lengths, out=np.zeros_like(X), where=lengths != 0)  # avoid division by zero for empty rows.

def smoothed_idf(X):  # compute the lesson's IDF convention.
    N = X.shape[0]  # number of documents.
    df = (X > 0).sum(axis=0)  # number of documents containing each term.
    return np.log((1 + N) / (1 + df)) + 1  # smoothed IDF.

def cosine(a, b):  # guarded cosine similarity.
    denom = np.linalg.norm(a) * np.linalg.norm(b)  # product of vector lengths.
    return 0.0 if denom == 0 else float(np.dot(a, b) / denom)  # return 0 when either vector is empty.
```

### Basic 7 — Compute document frequency

### Advanced 5 — Simulate sparsity and zero cosine scores

**Goal.** Measure how often random queries have no vocabulary overlap, because cosine zero means no shared weighted columns rather than conceptual unrelatedness. We build it in 4 steps.

```python
vocab_a5 = [f"w{i_a5}" for i_a5 in range(20)]  # synthetic vocabulary.
docs_a5 = [" ".join(np.random.choice(vocab_a5, size=3, replace=False)) for _ in range(12)]  # sparse synthetic documents.
X_a5 = count_matrix(docs_a5, vocab_a5)  # count matrix with many zeros.
TFIDF_a5 = tf_matrix(X_a5) * smoothed_idf(X_a5)  # weighted sparse rows.
print("matrix shape:", TFIDF_a5.shape)  # inspect rows and columns.
print("density:", round(float(np.mean(X_a5 > 0)), 3))  # inspect sparsity.
```
▶ What you'll see: only a small fraction of document-term cells are nonzero.

```python

idf_a5 = smoothed_idf(X_a5)  # reuse corpus IDF for queries.

    q_counts_a5 = count_matrix([query_a5], vocab_a5)[0]  # query counts.
    q_vec_a5 = (q_counts_a5 / q_counts_a5.sum()) * idf_a5  # query TF-IDF.
    scores_query_a5 = np.array([cosine(row_a5, q_vec_a5) for row_a5 in TFIDF_a5])  # document scores.
    zero_counts_a5.append(int(np.sum(np.round(scores_query_a5, 12) == 0)))  # count exact no-overlap scores.

```
