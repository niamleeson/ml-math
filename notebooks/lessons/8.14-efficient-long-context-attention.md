# 8.14 — Efficient & Long-Context Attention

Efficient long-context attention keeps the Transformer idea from Lesson 8.12 — tokens mix information by attending to other tokens — but asks which links are worth storing and how exact dense attention can be computed without a giant memory table. In this lesson, you will build dense, local, global, random, and streaming attention pieces from scratch so the difference between *changing the attention pattern* and *changing the implementation* stays clear.

### 1. Dense attention and the quadratic memory wall

Dense self-attention lets every query token compare against every key token. For a sequence of length $T$, that means the score matrix has shape $T\times T$, so the number of scalar scores is $T^2$. The power is obvious: every token has a one-hop path to every other token. The cost is just as obvious once we count the entries: doubling length creates four times as many scores.

```python
lengths_w = np.array([128, 256, 512, 1024])  # common context lengths to compare.
dense_scores_w = lengths_w ** 2  # dense self-attention stores one score for every ordered pair.
print("lengths:", lengths_w)  # inspect the sequence lengths.
print("dense score counts:", dense_scores_w)  # inspect T^2 for each length.
assert dense_scores_w[-1] == 1_048_576  # 1024^2 is the canonical million-score example.
```
▶ What you'll see: increasing length from 128 to 1024 raises the score table from 16,384 entries to 1,048,576.

```python
ratio_w = dense_scores_w[-1] / dense_scores_w[0]  # compare 1024-token cost to 128-token cost.
print("1024 vs 128 score ratio:", int(ratio_w))  # eight times length means sixty-four times scores.
assert int(ratio_w) == 64  # concrete square-law check.
plt.figure(figsize=(4.6, 3))
plt.plot(lengths_w, dense_scores_w, marker="o", color="crimson")
plt.title("1: dense attention follows T²")
plt.xlabel("sequence length T")
plt.ylabel("stored attention scores")
plt.show()
```
▶ What you'll see: the curve bends upward because attention scores grow quadratically, not linearly.

*Why it's done this way: dense attention stores every pairwise compatibility $q_i\cdot k_j$ so softmax can choose any source token for any destination token. That all-pairs design is exactly why the memory table has $T^2$ entries; the algorithm buys maximum connectivity by paying for every possible directed edge.*

### 2. Local window attention replaces the square with a band

A local window keeps only nearby edges. With radius $w$, token $i$ may attend to token $j$ only when $|i-j|\le w$. Interior rows have $2w+1$ allowed entries, while boundary rows have fewer. The approximation changes the model class: distant tokens are not merely computed later — their direct edges are removed.

```python
T_w, radius_w = 32, 2  # small sequence and local radius for an inspectable mask.
idx_w = np.arange(T_w)  # token positions 0..31.
local_mask_w = np.abs(idx_w[:, None] - idx_w[None, :]) <= radius_w  # True only inside the band.
print("dense slots:", T_w * T_w)  # full 32x32 score matrix size.
print("local true entries:", int(local_mask_w.sum()))  # actual band size including boundary losses.
assert int(local_mask_w.sum()) == 154  # boundary-aware count from the lesson source.
```
▶ What you'll see: dense attention would store 1024 scores, but the radius-2 band stores only 154 allowed edges.

```python
row_w = 10  # an interior query row.
allowed_w = np.where(local_mask_w[row_w])[0]  # keys visible to that query.
print("row 10 allowed positions:", allowed_w)  # should be 8..12.
print("is position 12 visible?", bool(local_mask_w[10, 12]))  # distance exactly 2.
assert local_mask_w[10, 12] and len(allowed_w) == 5  # row 10 sees 2 left + self + 2 right.
plt.figure(figsize=(4.2, 3.4))
plt.imshow(local_mask_w, cmap="Greys", aspect="auto")
plt.title("2: local attention mask, w=2")
plt.xlabel("key position")
plt.ylabel("query position")
plt.show()
```
▶ What you'll see: a narrow diagonal band; the first and last rows are shorter because they hit sequence boundaries.

*Why it's done this way: the band is a sparse graph prior. Nearby tokens usually carry syntax, phrase, and short-range context, so keeping $O(Tw)$ edges can preserve local computation while avoiding $O(T^2)$ storage. The cost is that information must travel layer by layer across the band instead of jumping across the document in one step.*

### 3. Global tokens create long-distance shortcuts

Local windows are cheap, but a purely local graph cannot connect the first and last token in one layer. Longformer-style global tokens solve that by filling selected rows and columns: everyone can attend to the global token, and the global token can attend to everyone. This adds a hub without restoring the full dense matrix.

```python
Tg_w, wg_w = 20, 1  # a shorter sequence with radius-1 local attention.
pos_w = np.arange(Tg_w)  # positions 0..19.
global_mask_w = np.abs(pos_w[:, None] - pos_w[None, :]) <= wg_w  # start with a local band.
global_mask_w[0, :] = True  # token 0 attends to every token.
global_mask_w[:, 0] = True  # every token attends to token 0.
print("global-mask true entries:", int(global_mask_w.sum()))  # count local band plus hub edges.
print("M[19,0], M[0,19]:", bool(global_mask_w[19, 0]), bool(global_mask_w[0, 19]))  # two long links.
assert int(global_mask_w.sum()) == 94  # canonical count after adding row and column 0.
```
▶ What you'll see: the mask contains 94 true entries, and both far links involving token 0 are present.

```python
plt.figure(figsize=(4.2, 3.4))
plt.imshow(global_mask_w, cmap="Greys", aspect="auto")
plt.title("3: local band plus global token 0")
plt.xlabel("key position")
plt.ylabel("query position")
plt.show()
```
▶ What you'll see: a diagonal band plus a bright first row and first column, making token 0 a document-wide hub.

*Why it's done this way: a global token changes graph diameter. Instead of requiring many local hops for distant regions to communicate, the path can be token $i\rightarrow$ global $\rightarrow$ token $j$. This is still sparse because only selected hubs get dense rows/columns, but it restores important nonlocal routes.*

### 4. Random sparse links improve reachability

BigBird-style attention adds random edges to local and global structure. A random edge is not chosen because it understands syntax; it is useful because sparse random graphs tend to shorten paths between distant parts of the sequence. With a fixed seed, the pattern is reproducible and inspectable.

```python
Tr_w, links_w = 24, 3  # 24 query rows, each with 3 random key destinations.
rng_w = np.random.default_rng(0)  # fixed generator so the sparse graph is reproducible.
random_mask_w = np.zeros((Tr_w, Tr_w), dtype=bool)  # start with no random edges.
for i_w in range(Tr_w):  # add exactly three random links per query row.
    cols_w = rng_w.choice(Tr_w, size=links_w, replace=False)  # distinct random destinations.
    random_mask_w[i_w, cols_w] = True  # mark the chosen sparse edges.
row_counts_w = random_mask_w.sum(axis=1)  # count links per row.
print("total random edges:", int(random_mask_w.sum()))  # should be 24*3.
print("first five row counts:", row_counts_w[:5])  # each row gets exactly 3.
assert int(random_mask_w.sum()) == 72 and np.all(row_counts_w[:5] == 3)  # concrete sparse-link check.
```
▶ What you'll see: every row has 3 random outgoing links, for 72 total links.

```python
plt.figure(figsize=(4.2, 3.4))
plt.imshow(random_mask_w, cmap="Greys", aspect="auto")
plt.title("4: reproducible random sparse links")
plt.xlabel("key position")
plt.ylabel("query position")
plt.show()
```
▶ What you'll see: scattered allowed edges rather than a band; the pattern is sparse but spread across the sequence.

*Why it's done this way: local edges preserve nearby structure, global edges add hubs, and random edges add extra graph reachability. The logic is graph-theoretic: over multiple layers, shorter paths let information percolate between distant regions without paying for every edge in every layer.*

### 5. FlashAttention streams exact dense softmax

Sparse masks change which attention entries exist. FlashAttention is different: it keeps dense attention mathematically exact but computes softmax in blocks so the full score matrix does not have to be stored. The key numerical trick is the stable softmax identity: subtract a maximum before exponentiating, and update the maximum and denominator as more blocks arrive.

```python
logits_w = np.array([10.0, 9.0, 8.0, 1.0])  # one row of dense attention scores.
full_probs_w = np.exp(logits_w - np.max(logits_w))  # stable numerator using the global max.
full_probs_w = full_probs_w / full_probs_w.sum()  # dense softmax probabilities.
print("full softmax:", np.round(full_probs_w, 6))  # exact target answer.
assert np.allclose(np.round(full_probs_w, 6), [0.665186, 0.244708, 0.090023, 0.000082])  # stable dense result.
```
▶ What you'll see: almost all probability goes to the first three logits, while the logit 1 token gets tiny mass.

```python
m_stream_w = -np.inf  # running maximum across chunks.
d_stream_w = 0.0  # running denominator in the current max's scale.
chunks_w = [logits_w[:2], logits_w[2:]]  # stream two blocks rather than one full row.
for chunk_w in chunks_w:  # update running max and denominator block by block.
    old_m_w = m_stream_w  # save previous max for rescaling the old denominator.
    m_stream_w = max(m_stream_w, float(np.max(chunk_w)))  # new global max so far.
    d_stream_w = d_stream_w * np.exp(old_m_w - m_stream_w) + np.sum(np.exp(chunk_w - m_stream_w))  # rescaled denominator.
print("streaming max:", m_stream_w)  # should be the true global maximum 10.
print("streaming denominator:", round(float(d_stream_w), 6))  # exp(0)+exp(-1)+exp(-2)+exp(-9).
assert round(float(d_stream_w), 6) == 1.503338  # exact stable denominator to 6 decimals.
```
▶ What you'll see: the stream finds the same global max and denominator without storing all chunk scores at once.

```python
stream_probs_w = np.exp(logits_w - m_stream_w) / d_stream_w  # recover probabilities using streamed stats.
print("streamed softmax:", np.round(stream_probs_w, 6))  # compare to dense softmax.
assert np.allclose(stream_probs_w, full_probs_w)  # Flash-style streaming preserves the answer.
plt.figure(figsize=(4.6, 3))
plt.bar(["dense", "streamed"], [full_probs_w[0], stream_probs_w[0]], color=["gray", "teal"])
plt.title("5: exact dense probability is preserved")
plt.ylabel("probability of token 0")
plt.show()
```
▶ What you'll see: dense and streamed probabilities match; the algorithm changed memory traffic, not the mathematical result.

*Why it's done this way: softmax is invariant to subtracting a shared constant, so the running maximum prevents overflow. Rescaling the old denominator when a larger maximum appears lets blocks be combined exactly. That is the FlashAttention distinction: stream exact dense attention through fast memory instead of approximating it by deleting edges.*

## 🛠️ Setup

```python
import numpy as np  # Import NumPy for masks, dot products, softmax arithmetic, and small simulations.
import matplotlib.pyplot as plt  # Import Matplotlib for heatmaps, bars, and line plots used to inspect attention.
np.random.seed(0)  # Fix the global random seed so stochastic sparse-link examples are repeatable.

def stable_softmax(x):  # Define a numerically stable softmax for 1-D arrays.
    x = np.asarray(x, dtype=float)  # Convert inputs to floats so exponentials are predictable.
    shifted = x - np.max(x)  # Subtract the maximum to avoid overflow without changing probabilities.
    exp_shifted = np.exp(shifted)  # Exponentiate the shifted logits.
    return exp_shifted / np.sum(exp_shifted)  # Normalize exponentials into probabilities.

def local_attention_mask(T, w):  # Define a local window mask with radius w.
    idx = np.arange(T)  # Create token positions.
    return np.abs(idx[:, None] - idx[None, :]) <= w  # Allow keys within distance w of each query.

def apply_attention(Q, K, V, mask=None):  # Compute single-head attention from scratch.
    scores = Q @ K.T / np.sqrt(Q.shape[1])  # Compute scaled dot-product scores.
    if mask is not None:  # If a sparse pattern is supplied, remove disallowed keys.
        scores = np.where(mask, scores, -1e9)  # Use a huge negative number so softmax gives nearly zero.
    weights = np.vstack([stable_softmax(row) for row in scores])  # Apply row-wise stable softmax.
    return weights @ V, weights  # Return mixed values and the attention weights for inspection.

def show_mask(mask, title):  # Define a small heatmap helper for attention masks.
    plt.figure(figsize=(4, 3))  # Start a compact figure.
    plt.imshow(mask, cmap="Greys", aspect="auto")  # Draw True entries as visible allowed edges.
    plt.title(title)  # Label the mask.
    plt.xlabel("key position")  # Columns are keys.
    plt.ylabel("query position")  # Rows are queries.
    plt.show()  # Display the mask.
```

### Basic 10 — Distinguish approximation from implementation

**Goal.** Compare a sparse mask with streamed softmax, because sparse attention changes the answer while Flash-style streaming preserves dense softmax. We build it in 3 steps.

```python
logits_b10 = np.array([10.0, 9.0, 8.0, 1.0])  # One dense score row.
dense_probs_b10 = stable_softmax(logits_b10)  # Exact dense probabilities.
sparse_mask_b10 = np.array([True, True, False, False])  # A sparse pattern that deletes two keys.
sparse_probs_b10 = stable_softmax(np.where(sparse_mask_b10, logits_b10, -1e9))  # Sparse masked probabilities.
print("dense:", np.round(dense_probs_b10, 6))  # Inspect dense answer.
print("sparse:", np.round(sparse_probs_b10, 6))  # Inspect changed answer.
```
▶ What you'll see: deleting keys 2 and 3 renormalizes probability onto keys 0 and 1.

```python
m_b10 = max(float(np.max(logits_b10[:2])), float(np.max(logits_b10[2:])))  # Global maximum from streamed chunks.
den_b10 = np.sum(np.exp(logits_b10[:2] - m_b10)) + np.sum(np.exp(logits_b10[2:] - m_b10))  # Denominator accumulated by chunks.
```

```python
def shortest_hops_e5(mask_e5, start_e5, target_e5):  # Breadth-first search on the attention graph.
    seen_e5 = {start_e5}  # Track visited nodes.
    frontier_e5 = {start_e5}  # Current wave of nodes.
    for hops_e5 in range(6):  # Limit search because the toy graph is tiny.
        if target_e5 in frontier_e5:  # Stop once target is reached.
```
