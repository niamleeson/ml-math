# 3.7 — Polynomial & Basis-Function Regression

Polynomial and basis-function regression keeps the learning problem linear in its coefficients while letting the curve bend in input space. We choose transformed columns like $1,x,x^2$ or smooth bumps $\phi_j(x)$, fit the coefficient vector by least squares, and judge the result by validation error plus any complexity cost rather than by the prettiest training curve alone.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build polynomial and basis-function regression one idea at a time. Run each cell in order and read the printed intermediate values — every piece of math is spelled out so the design matrix, the coefficient solve, the validation gap, and the stabilizing cost are not black boxes. This walkthrough is self-contained and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays, basis columns, linear algebra, and numerical checks.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
np.random.seed(0)  # reproducibility for the synthetic data.
```
▶ What you'll see: the only two libraries used in the lesson are loaded, and the seed makes every example repeatable.

### 1. Turning one input into many basis columns

Ordinary straight-line regression can only learn $\beta_0+\beta_1x$. Polynomial regression changes the *inputs*, not the fitting machinery: each scalar $x$ becomes a row of features such as $[1,x,x^2,x^3]$. The model is still linear in the coefficients $\beta$, but nonlinear as a function of $x$.

```python
x_w = np.array([-2., -1., 0., 1., 2.])  # five scalar inputs.
degree_w = 3  # include 1, x, x^2, and x^3.
Phi_w = np.column_stack([x_w ** power_w for power_w in range(degree_w + 1)])  # polynomial design matrix.
print("x values:", x_w)
print("polynomial design matrix:\n", Phi_w)
assert Phi_w.shape == (5, 4)
```
▶ What you'll see: each input has become four columns, and the first column is all ones for the intercept.

```python
plt.figure(figsize=(5, 3))
for col_w in range(Phi_w.shape[1]):
    plt.plot(x_w, Phi_w[:, col_w], marker="o", label=f"x^{col_w}")
plt.title("1: polynomial basis columns")
plt.xlabel("x")
plt.ylabel("basis value")
plt.legend()
plt.show()
```
▶ What you'll see: $x^2$ bends upward while $x^3$ changes sign, giving the linear solver curved ingredients.

*Why it's done this way:* the learner only knows how to combine columns as $\Phi\beta$, so we put the nonlinearity into $\Phi$. The coefficient vector remains a linear parameter vector, which preserves the least-squares solve, while the prediction curve can bend because the columns themselves are nonlinear functions of $x$.

### 2. Fitting coefficients by least squares

Once the basis matrix $\Phi$ is built, fitting is the same empirical-risk problem as linear regression: choose $\beta$ to minimize the average squared residuals. The normal equation $\hat\beta=(\Phi^T\Phi)^{-1}\Phi^Ty$ is the stationary point of $\lVert y-\Phi\beta\rVert_2^2$ when the columns are independent; `np.linalg.lstsq` computes the same least-squares solution more safely.

```python
y_w = np.array([5.1, 2.0, 1.0, 2.1, 5.0])  # nearly y = 1 + x^2.
Phi2_w = np.column_stack([np.ones_like(x_w), x_w, x_w ** 2])  # intercept, linear, quadratic.
beta_w = np.linalg.lstsq(Phi2_w, y_w, rcond=None)[0]  # least-squares coefficients.
print("beta:", np.round(beta_w, 3))
assert np.allclose(np.round(beta_w, 3), [1.026, -0.010, 1.007])
```
▶ What you'll see: the fitted coefficients are almost intercept 1, linear slope 0, and quadratic weight 1.

```python
yhat_w = Phi2_w @ beta_w  # fitted values on the training inputs.
losses_w = (y_w - yhat_w) ** 2  # per-example squared losses.
print("per-example losses:", np.round(losses_w, 4))
print("training MSE:", round(float(np.mean(losses_w)), 4))
assert round(float(np.mean(losses_w)), 4) == 0.0021
```
▶ What you'll see: the residuals are tiny because a quadratic basis matches the data-generating shape.

```python
grid_w = np.linspace(-2.3, 2.3, 120)
G2_w = np.column_stack([np.ones_like(grid_w), grid_w, grid_w ** 2])
plt.figure(figsize=(5, 3))
plt.scatter(x_w, y_w, color="black", label="data")
plt.plot(grid_w, G2_w @ beta_w, color="teal", label="quadratic fit")
plt.title("2: least-squares polynomial fit")
plt.xlabel("x")
plt.ylabel("y")
plt.legend()
plt.show()
```
▶ What you'll see: the curve passes close to every point while remaining a smooth parabola.

*Why it's done this way:* minimizing squared loss asks for predictions close to the observed targets in Euclidean distance. Because the prediction is $\Phi\beta$, the derivative of the squared loss is linear in $\beta$, so a linear-algebra solve can find the best coefficients after the nonlinear feature expansion has been chosen.

### 3. Polynomial degree is model capacity

Increasing the degree adds columns and therefore flexibility. A degree-1 model may underfit a curved pattern; a very high-degree model may chase noise. The important comparison is not only training loss, but whether the improvement survives on validation inputs that were not used to fit the coefficients.

```python
x_train_w = np.linspace(-3, 3, 9)
y_true_train_w = 0.5 * x_train_w ** 2 - 1.0
noise_w = np.array([0.2, -0.1, 0.1, -0.2, 0.0, 0.15, -0.05, 0.1, -0.15])
y_train_w = y_true_train_w + noise_w
x_val_w = np.linspace(-2.5, 2.5, 6)
y_val_w = 0.5 * x_val_w ** 2 - 1.0
print("train points:", len(x_train_w), "validation points:", len(x_val_w))
```
▶ What you'll see: we have enough training points for several polynomial degrees and a separate validation grid.

```python
degrees_w = np.array([1, 2, 5, 8])
train_mse_w = []
val_mse_w = []
for degree_w in degrees_w:
    Xtr_w = np.column_stack([x_train_w ** p_w for p_w in range(degree_w + 1)])
    Xva_w = np.column_stack([x_val_w ** p_w for p_w in range(degree_w + 1)])
    b_w = np.linalg.lstsq(Xtr_w, y_train_w, rcond=None)[0]
    train_mse_w.append(float(np.mean((y_train_w - Xtr_w @ b_w) ** 2)))
    val_mse_w.append(float(np.mean((y_val_w - Xva_w @ b_w) ** 2)))
print("train MSE:", np.round(train_mse_w, 4))
print("validation MSE:", np.round(val_mse_w, 4))
assert train_mse_w[-1] < train_mse_w[1]
```
▶ What you'll see: training error keeps dropping, but validation error identifies whether the extra bend is useful.

```python
plt.figure(figsize=(5, 3))
plt.plot(degrees_w, train_mse_w, marker="o", label="train")
plt.plot(degrees_w, val_mse_w, marker="s", label="validation")
plt.title("3: degree controls capacity")
plt.xlabel("polynomial degree")
plt.ylabel("MSE")
plt.legend()
plt.show()
```
▶ What you'll see: the validation curve, not the training curve alone, is the honest capacity guide.

*Why it's done this way:* each added basis column expands the hypothesis family, so empirical risk cannot usually increase on the training set. Generalization is different: a model can fit accidental sample wiggles, so validation estimates the future cost of that flexibility.

### 4. Basis functions do not have to be powers

The formula $\hat y=\sum_j\beta_j\phi_j(x)$ allows any chosen features $\phi_j(x)$. Gaussian radial basis functions are localized bumps: each one responds strongly near its center and weakly far away. They make a curve by mixing local pieces rather than global powers.

```python
x_basis_w = np.linspace(-3, 3, 80)
centers_w = np.array([-2., 0., 2.])
width_w = 1.0
B_w = np.column_stack([np.exp(-0.5 * ((x_basis_w - c_w) / width_w) ** 2) for c_w in centers_w])
print("basis matrix shape:", B_w.shape)
print("middle row basis values:", np.round(B_w[40], 3))
assert B_w.shape == (80, 3)
```
▶ What you'll see: each row holds three bump activations, one for each center.

```python
plt.figure(figsize=(5, 3))
for j_w, c_w in enumerate(centers_w):
    plt.plot(x_basis_w, B_w[:, j_w], label=f"center {c_w:g}")
plt.title("4: Gaussian basis functions")
plt.xlabel("x")
plt.ylabel("φ_j(x)")
plt.legend()
plt.show()
```
▶ What you'll see: three overlapping bumps that can be added with positive or negative weights to form a smooth curve.

*Why it's done this way:* polynomial columns are global, so changing one coefficient affects the whole input range. Local basis functions encode the belief that nearby inputs should share information more strongly than distant inputs, while the final fit remains linear in the coefficients.

### 5. Selection uses raw fit plus cost

The content block's arithmetic makes the selection rule explicit: compute the empirical loss, add a complexity or operational cost, compare against alternatives, and prefer the lowest full decision score. For this lesson's toy numbers, the three per-example losses are 0.257, 0.109, and 0.488; the cost is 0.060.

```python
losses_score_w = np.array([0.257, 0.109, 0.488])
raw_w = float(np.mean(losses_score_w))
cost_w = 0.060
score_w = raw_w + cost_w
print("raw empirical risk:", round(raw_w, 3))
print("decision score:", round(score_w, 3))
assert round(raw_w, 3) == 0.285
assert round(score_w, 3) == 0.345
```
▶ What you'll see: the raw fit is 0.285, but the score used for selection is 0.345 after cost.

```python
alternative_w = 0.389
display_score_w = round(score_w, 3)
gap_w = alternative_w - display_score_w
relative_gap_w = gap_w / alternative_w
stable_w = 0.80 * display_score_w
print("gap:", round(gap_w, 3), "relative gap:", round(relative_gap_w, 3))
print("stabilized score:", round(stable_w, 3))
assert round(gap_w, 3) == 0.044
assert round(relative_gap_w, 3) == 0.113
assert round(stable_w, 3) == 0.276
```
▶ What you'll see: the stabilized score is lower than both the baseline and the tempting alternative.

```python
labels_w = ["raw+cost", "flexible alt", "stabilized"]
scores_w = np.array([score_w, alternative_w, stable_w])
plt.figure(figsize=(5, 3))
plt.bar(labels_w, scores_w, color=["gray", "orange", "seagreen"])
plt.ylabel("decision score")
plt.title("5: select by the full score")
plt.show()
```
▶ What you'll see: the green bar wins because selection includes the cost/stability term, not only training fit.

*Why it's done this way:* the model with the prettiest training number may have bought that number with fragile flexibility. Adding cost puts the comparison on the same decision scale as the modeling goal: choose the curve that is expected to behave best after accounting for complexity and uncertainty.

### 6. Scaling and conditioning keep the solve stable

Polynomial powers can become numerically extreme. If $x$ ranges from 0 to 100, then $x^5$ can be ten billion, and columns of wildly different sizes make $\Phi^T\Phi$ ill-conditioned. Centering/scaling $x$ before building powers keeps columns comparable and coefficients easier to estimate.

```python
x_raw_w = np.linspace(0, 100, 12)
x_scaled_w = (x_raw_w - x_raw_w.mean()) / x_raw_w.std()
Phi_raw_w = np.column_stack([x_raw_w ** p_w for p_w in range(6)])
Phi_scaled_w = np.column_stack([x_scaled_w ** p_w for p_w in range(6)])
cond_raw_w = np.linalg.cond(Phi_raw_w)
cond_scaled_w = np.linalg.cond(Phi_scaled_w)
print("raw condition number:", f"{cond_raw_w:.2e}")
print("scaled condition number:", f"{cond_scaled_w:.2e}")
assert cond_scaled_w < cond_raw_w
```
▶ What you'll see: scaling shrinks the condition number by many orders of magnitude.

```python
plt.figure(figsize=(5, 3))
plt.bar(["raw powers", "scaled powers"], [np.log10(cond_raw_w), np.log10(cond_scaled_w)], color=["crimson", "teal"])
plt.ylabel("log10(condition number)")
plt.title("6: scaling improves numerical stability")
plt.show()
```
▶ What you'll see: the scaled design has a much smaller log-condition number, which means the solve is less sensitive to tiny perturbations.

*Why it's done this way:* least squares solves a geometric projection. When basis columns almost duplicate each other or live on incompatible scales, small data noise can cause large coefficient swings. Scaling does not change the idea of polynomial regression; it makes the linear algebra match the idea reliably.

### ✍️ Toy 2 · Least squares fits basis coefficients

Once the basis matrix is built, fitting coefficients is ordinary least squares on `Φβ`.

```python
import numpy as np                              # least-squares solve.

t2_rng = np.random.default_rng(0)               # seeded generator for reproducibility.
t2_x = np.array([-2., -1., 0., 1., 2., 3.])     # 6 inputs                   # -> [-2. -1.  0.  1.  2.  3.]
print("x:", t2_x.tolist())                     # -> [-2.0, -1.0, 0.0, 1.0, 2.0, 3.0]
t2_y = np.array([5.0, 2.2, 1.0, 1.8, 5.1, 10.0])  # curved targets           # -> [ 5.   2.2  1.   1.8  5.1 10. ]
print("y:", t2_y.tolist())                     # -> [5.0, 2.2, 1.0, 1.8, 5.1, 10.0]
t2_Phi = np.column_stack([np.ones_like(t2_x), t2_x, t2_x ** 2])  # quadratic basis  # -> shape (6, 3)
print("Phi:", t2_Phi.tolist())                 # -> [[1.0, -2.0, 4.0], [1.0, -1.0, 1.0], [1.0, 0.0, 0.0], [1.0, 1.0, 1.0], [1.0, 2.0, 4.0], [1.0, 3.0, 9.0]]
t2_beta = np.linalg.lstsq(t2_Phi, t2_y, rcond=None)[0]  # fitted coefficients  # -> [ 1.     -0.0232  1.0089]
print("beta:", np.round(t2_beta, 4).tolist())  # -> [1.0, -0.0232, 1.0089]
t2_yhat = t2_Phi @ t2_beta                      # fitted values              # -> [ 5.0821  2.0321  1.      1.9857  4.9893 10.0107]
print("fitted values:", np.round(t2_yhat, 4).tolist())  # -> [5.0821, 2.0321, 1.0, 1.9857, 4.9893, 10.0107]
t2_resid = t2_y - t2_yhat                       # residuals                  # -> [-0.0821  0.1679 -0.     -0.1857  0.1107 -0.0107]
print("residuals:", np.round(t2_resid, 4).tolist())     # -> [-0.0821, 0.1679, -0.0, -0.1857, 0.1107, -0.0107]
t2_losses = t2_resid ** 2                       # squared losses             # -> [0.0067 0.0282 0.     0.0345 0.0123 0.0001]
print("losses:", np.round(t2_losses, 4).tolist())       # -> [0.0067, 0.0282, 0.0, 0.0345, 0.0123, 0.0001]
t2_mse = t2_losses.mean()                       # training MSE               # -> 0.013630952380952403
print("MSE:", round(float(t2_mse), 4))          # -> 0.0136
assert round(float(t2_mse), 4) == 0.0136

plt.figure(figsize=(4.8, 2.8))
plt.scatter(t2_x, t2_y, color="black", label="data")
plt.plot(t2_x, t2_yhat, color="teal", label="quadratic fit")
plt.xlabel("x")
plt.ylabel("y")
plt.title("Toy 2 · least-squares basis fit")
plt.legend()
plt.show()
```
▶ What you'll see: the fitted quadratic nearly follows the six curved points.

### ✍️ Toy 3 · Degree controls train/validation error

Adding powers usually lowers training error, but validation error tells whether the extra flexibility
is useful or just chasing noise.

```python
import numpy as np                              # degree sweep.

t3_rng = np.random.default_rng(0)               # seeded generator for reproducibility.
t3_x_train = np.array([-3., -2., -1., 0., 1., 2., 3.])  # 7 training inputs   # -> [-3. -2. -1.  0.  1.  2.  3.]
print("train x:", t3_x_train.tolist())          # -> [-3.0, -2.0, -1.0, 0.0, 1.0, 2.0, 3.0]
t3_noise = np.array([0.3, -0.2, 0.1, 0.0, -0.1, 0.2, -0.3])  # small noise     # -> [ 0.3 -0.2  0.1  0.  -0.1  0.2 -0.3]
print("noise:", t3_noise.tolist())             # -> [0.3, -0.2, 0.1, 0.0, -0.1, 0.2, -0.3]
t3_y_train = 0.5 * t3_x_train ** 2 + 1.0 + t3_noise  # noisy quadratic       # -> [5.8 2.8 1.6 1.  1.4 3.2 5.2]
print("train y:", np.round(t3_y_train, 3).tolist())  # -> [5.8, 2.8, 1.6, 1.0, 1.4, 3.2, 5.2]
t3_x_val = np.array([-2.5, -1.5, -0.5, 0.5, 1.5, 2.5])  # 6 validation inputs  # -> [-2.5 -1.5 -0.5  0.5  1.5  2.5]
print("validation x:", t3_x_val.tolist())       # -> [-2.5, -1.5, -0.5, 0.5, 1.5, 2.5]
t3_y_val = 0.5 * t3_x_val ** 2 + 1.0            # noiseless validation target  # -> [4.125 2.125 1.125 1.125 2.125 4.125]
print("validation y:", np.round(t3_y_val, 3).tolist())  # -> [4.125, 2.125, 1.125, 1.125, 2.125, 4.125]
t3_degrees = np.array([1, 2, 5])                # compare line, quadratic, wiggly  # -> [1 2 5]
print("degrees:", t3_degrees.tolist())         # -> [1, 2, 5]
t3_train_mse = []                               # training MSE values        # -> []
t3_val_mse = []                                 # validation MSE values      # -> []
for t3_degree in t3_degrees:
    t3_X_train = np.column_stack([t3_x_train ** t3_power for t3_power in range(t3_degree + 1)])
    t3_X_val = np.column_stack([t3_x_val ** t3_power for t3_power in range(t3_degree + 1)])
    t3_beta = np.linalg.lstsq(t3_X_train, t3_y_train, rcond=None)[0]
    t3_train_mse.append(float(np.mean((t3_y_train - t3_X_train @ t3_beta) ** 2)))
    t3_val_mse.append(float(np.mean((t3_y_val - t3_X_val @ t3_beta) ** 2)))
t3_train_mse = np.array(t3_train_mse)           # train errors               # -> [3.0327 0.0327 0.    ]
print("train MSE:", np.round(t3_train_mse, 4).tolist())  # -> [3.0327, 0.0327, 0.0]
t3_val_mse = np.array(t3_val_mse)               # validation errors          # -> [1.8543 0.0054 0.0209]
print("validation MSE:", np.round(t3_val_mse, 4).tolist())  # -> [1.8543, 0.0054, 0.0209]
t3_best_degree = int(t3_degrees[int(np.argmin(t3_val_mse))])  # validation winner  # -> 2
print("best validation degree:", t3_best_degree)  # -> 2
assert t3_best_degree == 2

plt.figure(figsize=(4.8, 2.8))
plt.plot(t3_degrees, t3_train_mse, marker="o", label="train")
plt.plot(t3_degrees, t3_val_mse, marker="s", label="validation")
plt.xlabel("degree")
plt.ylabel("MSE")
plt.title("Toy 3 · capacity check")
plt.legend()
plt.show()
```
▶ What you'll see: degree 5 drives training error to zero, but degree 2 has the lowest validation error.

### ✍️ Toy 4 · Gaussian bumps make local basis columns

Basis functions do not have to be powers. Gaussian bumps create local columns that respond most near
their centers.

```python
import numpy as np                              # Gaussian basis columns.

t4_rng = np.random.default_rng(0)               # seeded generator for reproducibility.
t4_x = np.linspace(-3, 3, 7)                    # 7 inputs                   # -> [-3. -2. -1.  0.  1.  2.  3.]
print("x:", t4_x.tolist())                     # -> [-3.0, -2.0, -1.0, 0.0, 1.0, 2.0, 3.0]
t4_centers = np.array([-2., 0., 2.])            # 3 bump centers             # -> [-2.  0.  2.]
print("centers:", t4_centers.tolist())         # -> [-2.0, 0.0, 2.0]
t4_width = 1.0                                  # bump width                 # -> 1.0
print("width:", t4_width)                      # -> 1.0
t4_B = np.column_stack([np.exp(-0.5 * ((t4_x - t4_center) / t4_width) ** 2) for t4_center in t4_centers])  # basis matrix  # -> shape (7, 3)
print("basis matrix:", np.round(t4_B, 3).tolist())  # -> [[0.607, 0.011, 0.0], [1.0, 0.135, 0.0], [0.607, 0.607, 0.011], [0.135, 1.0, 0.135], [0.011, 0.607, 0.607], [0.0, 0.135, 1.0], [0.0, 0.011, 0.607]]
t4_weights = np.array([1.0, -0.5, 0.8])         # mix the bumps              # -> [ 1.  -0.5  0.8]
print("weights:", t4_weights.tolist())         # -> [1.0, -0.5, 0.8]
t4_curve = t4_B @ t4_weights                    # basis-function prediction  # -> [ 0.601  0.933  0.312 -0.256  0.193  0.733  0.48 ]
print("mixed curve:", np.round(t4_curve, 3).tolist())  # -> [0.601, 0.933, 0.312, -0.256, 0.193, 0.733, 0.48]
assert t4_B.shape == (7, 3)

plt.figure(figsize=(4.8, 2.8))
for t4_j in range(t4_B.shape[1]):
    plt.plot(t4_x, t4_B[:, t4_j], linestyle="--", label=f"center {t4_centers[t4_j]:g}")
plt.plot(t4_x, t4_curve, color="black", marker="o", label="weighted mix")
plt.xlabel("x")
plt.ylabel("basis value")
plt.title("Toy 4 · local Gaussian basis")
plt.legend()
plt.show()
```
▶ What you'll see: three local bumps combine into one smooth curve through a weighted sum.

### ✍️ Toy 5 · Selection adds complexity cost

A flexible curve's raw fit is not the same as its decision score. Add the cost, then compare with the
alternative and the stabilized score.

```python
import numpy as np                              # cost-aware selection.

t5_rng = np.random.default_rng(0)               # seeded generator for reproducibility.
t5_losses = np.array([0.18, 0.07, 0.22, 0.10, 0.14, 0.09])  # 6 losses        # -> [0.18 0.07 0.22 0.1  0.14 0.09]
print("losses:", t5_losses.tolist())           # -> [0.18, 0.07, 0.22, 0.1, 0.14, 0.09]
t5_raw = t5_losses.mean()                       # raw empirical risk         # -> 0.13333333333333333
print("raw risk:", round(float(t5_raw), 4))     # -> 0.1333
t5_cost = 0.06                                  # complexity cost            # -> 0.06

t5_alternative = 0.21                           # alternative full score     # -> 0.21
print("alternative score:", t5_alternative)    # -> 0.21
t5_stabilized = 0.8 * t5_score                  # stabilizing reduction      # -> 0.15466666666666667
print("stabilized score:", round(float(t5_stabilized), 4))  # -> 0.1547
t5_scores = np.array([t5_score, t5_alternative, t5_stabilized])  # comparable scores  # -> [0.1933 0.21   0.1547]
t5_labels = np.array(["raw+cost", "alternative", "stabilized"])  # labels     # -> ['raw+cost' 'alternative' 'stabilized']
t5_winner = t5_labels[int(np.argmin(t5_scores))]  # lowest score             # -> stabilized
print("winner:", t5_winner)                    # -> stabilized
assert t5_winner == "stabilized"

plt.ylabel("decision score")
plt.title("Toy 5 · cost-aware selection")
plt.show()
```
▶ What you'll see: the stabilized score wins only after the raw empirical risk is placed on the same scale as the cost.

### ✍️ Toy 6 · Scaling improves conditioning

Large raw powers can make polynomial columns numerically awkward. Centering and scaling before taking
powers sharply reduces the condition number.

```python
import numpy as np                              # conditioning diagnostics.

t6_rng = np.random.default_rng(0)               # seeded generator for reproducibility.
t6_x_raw = np.array([0., 20., 40., 60., 80., 100.])  # 6 wide-range inputs    # -> [  0.  20.  40.  60.  80. 100.]
print("raw x:", t6_x_raw.tolist())             # -> [0.0, 20.0, 40.0, 60.0, 80.0, 100.0]
t6_x_mean = t6_x_raw.mean()                     # raw mean                   # -> 50.0
print("mean:", round(float(t6_x_mean), 3))      # -> 50.0
t6_x_std = t6_x_raw.std()                       # raw standard deviation     # -> 34.15650255319866
print("std:", round(float(t6_x_std), 3))        # -> 34.157
t6_x_scaled = (t6_x_raw - t6_x_mean) / t6_x_std # centered and scaled inputs # -> [-1.464 -0.878 -0.293  0.293  0.878  1.464]
print("scaled x:", np.round(t6_x_scaled, 3).tolist())  # -> [-1.464, -0.878, -0.293, 0.293, 0.878, 1.464]
t6_Phi_raw = np.column_stack([t6_x_raw ** t6_power for t6_power in range(4)])  # raw powers  # -> shape (6, 4)
print("raw first row:", t6_Phi_raw[0].tolist())        # -> [1.0, 0.0, 0.0, 0.0]
print("raw last row:", t6_Phi_raw[-1].tolist())        # -> [1.0, 100.0, 10000.0, 1000000.0]
t6_Phi_scaled = np.column_stack([t6_x_scaled ** t6_power for t6_power in range(4)])  # scaled powers  # -> shape (6, 4)
print("scaled first row:", np.round(t6_Phi_scaled[0], 3).tolist())  # -> [1.0, -1.464, 2.143, -3.137]
print("scaled last row:", np.round(t6_Phi_scaled[-1], 3).tolist())  # -> [1.0, 1.464, 2.143, 3.137]
t6_cond_raw = np.linalg.cond(t6_Phi_raw)        # raw condition number       # -> 1125234.147352623
print("raw condition:", f"{t6_cond_raw:.2e}") # -> 1.13e+06
t6_cond_scaled = np.linalg.cond(t6_Phi_scaled)  # scaled condition number    # -> 6.567083097737145
print("scaled condition:", round(float(t6_cond_scaled), 3))  # -> 6.567
assert t6_cond_scaled < t6_cond_raw

plt.ylabel("log10(condition number)")
plt.title("Toy 6 · scaling stabilizes powers")
plt.show()
```
▶ What you'll see: the raw condition number is about `1.13e+06`, while the scaled design is about `6.567`.

### Easy 4 — Use ridge stabilization on polynomial columns

**Goal.** Add a small L2 penalty to the coefficient solve, because high-degree polynomial columns can produce brittle coefficients. We build it in 3 steps.

```python
x_e4 = np.linspace(-1, 1, 8)
y_e4 = 1 + x_e4 + 0.2 * np.array([1, -1, 1, -1, 1, -1, 1, -1])
degree_e4 = 7
X_e4 = np.column_stack([x_e4 ** p_e4 for p_e4 in range(degree_e4 + 1)])
print("design shape:", X_e4.shape)
```
▶ What you'll see: degree 7 creates as many coefficients as data points, a setup that can interpolate noise.

```python
ols_e4 = np.linalg.lstsq(X_e4, y_e4, rcond=None)[0]
lam_e4 = 0.5
ridge_e4 = np.linalg.solve(X_e4.T @ X_e4 + lam_e4 * np.eye(X_e4.shape[1]), X_e4.T @ y_e4)
print("OLS norm:", round(float(np.linalg.norm(ols_e4)), 3))
print("ridge norm:", round(float(np.linalg.norm(ridge_e4)), 3))
assert np.linalg.norm(ridge_e4) < np.linalg.norm(ols_e4)
```
▶ What you'll see: ridge shrinks the coefficient vector, which usually means a less wiggly curve.

```python
grid_e4 = np.linspace(-1, 1, 150)
G_e4 = np.column_stack([grid_e4 ** p_e4 for p_e4 in range(degree_e4 + 1)])
plt.figure(figsize=(5, 3))
plt.scatter(x_e4, y_e4, color="black", s=18)
plt.plot(grid_e4, G_e4 @ ols_e4, label="OLS")
plt.plot(grid_e4, G_e4 @ ridge_e4, label="ridge", color="green")
plt.title("Easy 4: stabilizing high-degree fit")
plt.legend()
plt.show()
```
▶ What you'll see: the ridge curve is smoother because large coefficient combinations are penalized.

👀 Takeaway: regularization trades a little raw fit for stability when the basis is too flexible.

## 🔴 Advanced

### Advanced 1 — Bias-variance sweep with noisy data

**Goal.** Simulate many noisy training sets and compare degree choices, because high-degree bases can have high variance even when their average fit is flexible. We build it in 4 steps.

```python
rng_a1 = np.random.default_rng(0)
x_a1 = np.linspace(-1, 1, 15)
x_test_a1 = np.linspace(-1, 1, 100)
y_true_a1 = lambda z_a1: np.sin(2 * np.pi * z_a1)
degrees_a1 = np.array([1, 3, 9])
print("degrees:", degrees_a1)
```
▶ What you'll see: the experiment compares a line, a moderate curve, and a very flexible curve.

```python
preds_a1 = {d_a1: [] for d_a1 in degrees_a1}
for rep_a1 in range(40):
    y_a1 = y_true_a1(x_a1) + 0.25 * rng_a1.normal(size=len(x_a1))
    for d_a1 in degrees_a1:
        X_a1 = np.column_stack([x_a1 ** p_a1 for p_a1 in range(d_a1 + 1)])
        T_a1 = np.column_stack([x_test_a1 ** p_a1 for p_a1 in range(d_a1 + 1)])
        beta_a1 = np.linalg.lstsq(X_a1, y_a1, rcond=None)[0]
        preds_a1[d_a1].append(T_a1 @ beta_a1)
print("replications per degree:", len(preds_a1[1]))
assert len(preds_a1[9]) == 40
```
▶ What you'll see: each degree is refit across many noisy samples.

```python
bias2_a1 = []
var_a1 = []
truth_test_a1 = y_true_a1(x_test_a1)
for d_a1 in degrees_a1:
    P_a1 = np.vstack(preds_a1[d_a1])
    mean_pred_a1 = P_a1.mean(axis=0)
    bias2_a1.append(float(np.mean((mean_pred_a1 - truth_test_a1) ** 2)))
    var_a1.append(float(np.mean(np.var(P_a1, axis=0))))
print("bias^2:", np.round(bias2_a1, 3))
print("variance:", np.round(var_a1, 3))
assert var_a1[-1] > var_a1[0]
```
▶ What you'll see: the high-degree model varies more across training samples.

```python
plt.figure(figsize=(5, 3))
plt.plot(degrees_a1, bias2_a1, marker="o", label="bias²")
plt.plot(degrees_a1, var_a1, marker="s", label="variance")
plt.title("Advanced 1: basis capacity tradeoff")
plt.xlabel("degree")
plt.legend()
plt.show()
```
▶ What you'll see: increasing degree can reduce bias while increasing variance.

👀 Takeaway: flexible bases need validation or regularization because low bias can come with unstable fits.

### Advanced 2 — Cross-validate the regularization strength

**Goal.** Choose a ridge penalty for a polynomial model, because stabilization should be selected from held-out performance. We build it in 4 steps.

```python
x_a2 = np.linspace(-2, 2, 20)
y_a2 = 1 - 0.5 * x_a2 + 0.3 * x_a2 ** 3 + 0.15 * np.sin(5 * x_a2)
train_idx_a2 = np.arange(0, 20, 2)
val_idx_a2 = np.arange(1, 20, 2)
print("train/val sizes:", len(train_idx_a2), len(val_idx_a2))
```
▶ What you'll see: alternating points form a simple validation split.

```python
D_a2 = 8
X_all_a2 = np.column_stack([x_a2 ** p_a2 for p_a2 in range(D_a2 + 1)])
lams_a2 = np.array([0.0, 0.001, 0.01, 0.1, 1.0])
val_mse_a2 = []
coef_norm_a2 = []
print("lambda grid:", lams_a2)
```
▶ What you'll see: the grid ranges from no penalty to strong shrinkage.

```python
for lam_a2 in lams_a2:
    A_a2 = X_all_a2[train_idx_a2].T @ X_all_a2[train_idx_a2] + lam_a2 * np.eye(D_a2 + 1)
    b_a2 = X_all_a2[train_idx_a2].T @ y_a2[train_idx_a2]
    beta_a2 = np.linalg.solve(A_a2, b_a2)
    pred_val_a2 = X_all_a2[val_idx_a2] @ beta_a2
    val_mse_a2.append(float(np.mean((y_a2[val_idx_a2] - pred_val_a2) ** 2)))
    coef_norm_a2.append(float(np.linalg.norm(beta_a2)))
best_lam_a2 = float(lams_a2[int(np.argmin(val_mse_a2))])
print("validation MSE:", np.round(val_mse_a2, 4))
print("best lambda:", best_lam_a2)
assert coef_norm_a2[-1] < coef_norm_a2[0]
```
▶ What you'll see: stronger regularization shrinks coefficients, and validation picks the useful amount.

```python
plt.figure(figsize=(5, 3))
plt.semilogx(lams_a2 + 1e-6, val_mse_a2, marker="o")
plt.axvline(best_lam_a2 + 1e-6, color="red", linestyle="--")
plt.title("Advanced 2: ridge validation sweep")
plt.xlabel("λ")
plt.ylabel("validation MSE")
plt.show()
```
▶ What you'll see: the selected penalty is the one with the lowest validation error, not necessarily the smallest training error.

👀 Takeaway: regularization is a tunable stability knob that should be chosen on future-like data.

### Advanced 3 — Compare polynomial and Gaussian bases

**Goal.** Fit the same data with global powers and local bumps, because basis choice encodes different assumptions about smoothness. We build it in 4 steps.

```python
x_a3 = np.linspace(-3, 3, 30)
y_a3 = np.exp(-0.5 * (x_a3 + 1) ** 2) - 0.8 * np.exp(-0.5 * (x_a3 - 1.2) ** 2)

print("data range:", x_a3.min(), x_a3.max())
```

▶ What you'll see: the target has two localized hills/dips, which favors local features.

```python
P_a3 = np.column_stack([x_a3 ** p_a3 for p_a3 in range(6)])
Pg_a3 = np.column_stack([grid_a3 ** p_a3 for p_a3 in range(6)])
beta_poly_a3 = np.linalg.lstsq(P_a3, y_a3, rcond=None)[0]
pred_poly_a3 = Pg_a3 @ beta_poly_a3
print("polynomial coefficient norm:", round(float(np.linalg.norm(beta_poly_a3)), 3))
```
▶ What you'll see: the polynomial uses global powers to approximate a local shape.

```python
centers_a3 = np.linspace(-3, 3, 9)
width_a3 = 0.7
B_a3 = np.column_stack([np.ones_like(x_a3)] + [np.exp(-0.5 * ((x_a3 - c_a3) / width_a3) ** 2) for c_a3 in centers_a3])
Bg_a3 = np.column_stack([np.ones_like(grid_a3)] + [np.exp(-0.5 * ((grid_a3 - c_a3) / width_a3) ** 2) for c_a3 in centers_a3])
```

### Advanced 5 — End-to-end model selection pipeline

**Goal.** Build polynomial candidates, compute validation risk, add a cost, and choose the minimum full score, because the full lesson is a repeatable selection procedure. We build it in 5 steps.

```python
x_a5 = np.linspace(-2, 2, 16)
y_a5 = 0.8 - 0.4 * x_a5 + 0.7 * x_a5 ** 2 + 0.05 * np.sin(6 * x_a5)
train_a5 = np.arange(0, 16, 2)
val_a5 = np.arange(1, 16, 2)
degrees_a5 = np.array([1, 2, 4, 6])
print("candidate degrees:", degrees_a5)
```
▶ What you'll see: four candidate polynomial families will compete on validation-plus-cost.

```python
val_risk_a5 = []
cost_a5 = []
models_a5 = []
for d_a5 in degrees_a5:
    X_a5 = np.column_stack([x_a5 ** p_a5 for p_a5 in range(d_a5 + 1)])
    beta_a5 = np.linalg.lstsq(X_a5[train_a5], y_a5[train_a5], rcond=None)[0]
    risk_a5 = float(np.mean((y_a5[val_a5] - X_a5[val_a5] @ beta_a5) ** 2))
    val_risk_a5.append(risk_a5)
    cost_a5.append(0.01 * d_a5)
    models_a5.append(beta_a5)
print("validation risks:", np.round(val_risk_a5, 4))
```
▶ What you'll see: every candidate gets a validation risk on the same held-out points.

```python
score_a5 = np.array(val_risk_a5) + np.array(cost_a5)
best_idx_a5 = int(np.argmin(score_a5))
best_degree_a5 = int(degrees_a5[best_idx_a5])
print("costs:", np.round(cost_a5, 3))
print("full scores:", np.round(score_a5, 4))
print("best degree:", best_degree_a5)
assert best_degree_a5 in degrees_a5
```
▶ What you'll see: the chosen degree is the one with the lowest complete decision score.

```python
grid_a5 = np.linspace(-2, 2, 160)

plt.show()
```
▶ What you'll see: the selected curve balances fit to the held-out points with the complexity cost.


▶ What you'll see: the shortest bar is the model that the pipeline carries forward.

👀 Takeaway: polynomial and basis-function regression is not just curve fitting; it is basis design, coefficient fitting, validation, and cost-aware selection.
