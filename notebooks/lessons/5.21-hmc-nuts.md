# 5.21 — Hamiltonian Monte Carlo & NUTS

Hamiltonian Monte Carlo (HMC) improves random-walk MCMC for continuous posteriors by adding momentum, following gradient-guided trajectories, and correcting the small numerical error with a Metropolis accept/reject step. NUTS keeps the same Hamiltonian geometry but automatically stops trajectories when they begin to turn back, removing one painful hand-tuned trajectory-length knob.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build Hamiltonian Monte Carlo and NUTS one idea at a time. Run each cell in order and inspect every number — the goal is to see why gradients, energy, leapfrog integration, Metropolis correction, and U-turn stopping fit together. This walkthrough is self-contained and uses a `_w` suffix so it never clashes with the examples below.

### 1. Posterior density becomes potential energy

HMC rewrites a target density \(\pi(q)\) as a landscape \(U(q)=-\log \pi(q)\). High posterior density means low potential energy, and the gradient \(\nabla U(q)\) points uphill. For a standard normal target, constants can be ignored, so \(U(q)=\tfrac12 q^2\) and \(\nabla U(q)=q\).

```python
q_grid_w = np.linspace(-3, 3, 121)  # candidate positions on a 1-D posterior.
U_w = 0.5 * q_grid_w**2  # potential energy for a standard normal, up to an additive constant.
grad_U_w = q_grid_w  # derivative of 0.5*q^2.
print("U(1.0):", 0.5 * 1.0**2)  # one concrete potential value.
print("grad U(1.0):", 1.0)  # positive gradient points toward larger energy.
assert 0.5 * 1.0**2 == 0.5
```
▶ What you'll see: position `q=1` has potential energy `0.5` and uphill slope `1`.

```python
plt.figure(figsize=(4.6, 3))
plt.plot(q_grid_w, U_w, color="navy", label="U(q)=q²/2")
plt.scatter([1.0], [0.5], color="crimson", zorder=3, label="q=1")
plt.title("1: posterior as potential energy")
plt.xlabel("position q"); plt.ylabel("potential U(q)"); plt.legend(); plt.show()
```
▶ What you'll see: a bowl-shaped energy landscape whose lowest point is the posterior mode.

*Why it's done this way:* taking `-log` converts multiplication of probabilities into addition of energies and turns a difficult density scale into local slopes. HMC needs those slopes because moving downhill in `U` is moving toward high posterior probability, while moving uphill is moving away from it.

### 2. Momentum and kinetic energy make movement possible

If HMC only followed \(-\nabla U\), it would slide to the mode and stop. Instead it samples an auxiliary momentum \(p\), adds kinetic energy \(K(p)=\tfrac12 p^2\), and moves in the joint energy \(H(q,p)=U(q)+K(p)\). Momentum lets the sampler coast through high-density regions instead of jittering like a random walk.

```python
q0_w = 1.0  # current position.
p0_w = 0.3  # current momentum.
U0_w = 0.5 * q0_w**2  # potential energy at q0.
K0_w = 0.5 * p0_w**2  # kinetic energy at p0.
H0_w = U0_w + K0_w  # total Hamiltonian energy.
print("U:", round(U0_w, 3), "K:", round(K0_w, 3), "H:", round(H0_w, 3))
assert round(H0_w, 3) == 0.545
```
▶ What you'll see: total energy combines position cost `0.500` and motion cost `0.045`.

```python
plt.figure(figsize=(4.4, 3))
plt.bar(["U(q)", "K(p)", "H"], [U0_w, K0_w, H0_w], color=["steelblue", "darkorange", "seagreen"])
plt.title("2: Hamiltonian energy = potential + kinetic")
plt.ylabel("energy"); plt.show()
```
▶ What you'll see: kinetic energy is small here, but it is the piece that lets the state move across the landscape.

*Why it's done this way:* adding momentum creates a larger joint distribution \(\pi(q)\mathcal{N}(p;0,M)\). If a proposal preserves this joint energy, then positions with the correct posterior density are visited without needing tiny blind random-walk steps.

### 3. Leapfrog integration moves while nearly preserving energy

The leapfrog integrator alternates a half momentum step, a full position step, and another half momentum step:
\(p\leftarrow p-\epsilon\nabla U(q)/2\), \(q\leftarrow q+\epsilon p\), \(p\leftarrow p-\epsilon\nabla U(q)/2\). It is used because it is reversible and volume-preserving, the two properties that make a Metropolis correction valid.

```python
eps_w = 0.2  # step size.
p_half_w = p0_w - 0.5 * eps_w * q0_w  # p_{1/2}=0.3-0.1*1=0.2.
q1_w = q0_w + eps_w * p_half_w  # q_1=1+0.2*0.2=1.04.
p1_w = p_half_w - 0.5 * eps_w * q1_w  # final half-step uses the new gradient.
print("p_half:", round(p_half_w, 3), "q1:", round(q1_w, 3), "p1:", round(p1_w, 3))
assert round(p_half_w, 3) == 0.2 and round(q1_w, 3) == 1.04
```
▶ What you'll see: the worked arithmetic from the lesson block appears exactly: `p_half=0.2`, `q1=1.040`.

```python
H1_w = 0.5 * q1_w**2 + 0.5 * p1_w**2  # Hamiltonian after one leapfrog step.
dH_w = H1_w - H0_w  # numerical energy error.
print("H before:", round(H0_w, 6), "H after:", round(H1_w, 6), "ΔH:", round(dH_w, 6))
assert abs(dH_w) < 0.01
```
▶ What you'll see: energy changes by much less than `0.01`, so the numerical path is almost exact.

```python
plt.figure(figsize=(4.4, 3))
plt.plot([q0_w, q1_w], [p0_w, p1_w], marker="o", color="purple")
plt.title("3: one leapfrog move in (q,p)")
plt.xlabel("q"); plt.ylabel("p"); plt.show()
```
▶ What you'll see: a small, directed move in phase space rather than an independent random jump.

*Why it's done this way:* the first half-step lets momentum react to the current slope, the full step uses that momentum to move position, and the last half-step symmetrizes the update. That symmetry is why reversing momentum and running the same step can trace back, which ordinary Euler integration cannot reliably do.

### 4. Metropolis correction fixes the remaining energy error

Leapfrog is not exact, so HMC accepts the proposed state with probability \(\min(1,\exp(-\Delta H))\), where \(\Delta H=H_{new}-H_{old}\). If energy is nearly preserved, acceptance is near one; if a bad step invents too much energy, the proposal is rejected.

```python
accept_w = min(1.0, float(np.exp(-dH_w)))  # MH correction using energy error.
print("ΔH:", round(dH_w, 6), "acceptance probability:", round(accept_w, 4))
assert accept_w > 0.99
```
▶ What you'll see: acceptance exceeds `0.99`, matching the small-energy-error story.

```python
bad_dH_w = np.array([0.0, 0.1, 1.0, 3.0])  # increasingly bad numerical energy errors.
acc_curve_w = np.exp(-bad_dH_w)  # acceptance when ΔH is positive.
print("acceptance curve:", np.round(acc_curve_w, 3))
plt.figure(figsize=(4.6, 3))
plt.plot(bad_dH_w, acc_curve_w, marker="o", color="crimson")
plt.title("4: larger energy errors reject more")
plt.xlabel("positive ΔH"); plt.ylabel("acceptance probability"); plt.show()
```
▶ What you'll see: acceptance falls from `1.0` to about `0.05` as the integrator makes larger mistakes.

*Why it's done this way:* the Metropolis step restores exactness. Leapfrog proposes long, informed moves; the acceptance ratio corrects for the fact that finite step sizes only approximately preserve the Hamiltonian.

### 5. Step size and trajectory length are real tuning knobs

A tiny step size preserves energy but moves slowly; a huge step size moves fast but breaks energy preservation. Even with a good step size, too few leapfrog steps degenerates into random-walk behavior, while too many can loop back toward where the chain started.

```python
def leapfrog_path_w(q, p, eps, L):
    qs = [q]
    for _ in range(L):
        p = p - 0.5 * eps * q
        q = q + eps * p
        p = p - 0.5 * eps * q
        qs.append(q)
    return np.array(qs), q, p

for eps_test_w in [0.05, 0.2, 0.8]:
    qs_w, q_end_w, p_end_w = leapfrog_path_w(1.0, 0.3, eps_test_w, 10)
    H_end_w = 0.5 * q_end_w**2 + 0.5 * p_end_w**2
    print("eps", eps_test_w, "distance", round(abs(q_end_w - 1.0), 3), "|ΔH|", round(abs(H_end_w - H0_w), 3))
```
▶ What you'll see: moderate steps move farther while still keeping energy error small; very large steps risk larger error.

```python
plt.figure(figsize=(4.8, 3))
for eps_plot_w in [0.05, 0.2, 0.8]:
    qs_plot_w, _, _ = leapfrog_path_w(1.0, 0.3, eps_plot_w, 20)
    plt.plot(qs_plot_w, marker="o", ms=3, label=f"eps={eps_plot_w}")
plt.title("5: step size changes path behavior")
plt.xlabel("leapfrog step"); plt.ylabel("q"); plt.legend(); plt.show()
```
▶ What you'll see: tiny steps crawl, moderate steps travel smoothly, and large steps visibly oscillate.

*Why it's done this way:* HMC's efficiency comes from following a trajectory, not from one giant blind proposal. The step size controls numerical accuracy, and the number of steps controls how far the chain travels before the Metropolis correction sees the proposal.

### 6. NUTS stops when the path turns back

NUTS keeps building a trajectory until it detects a U-turn: the displacement from the start has negative dot product with the current momentum. In one dimension, the check is \((q_t-q_0)p_t < 0\). A negative value means the simulated particle is moving back toward the starting point, so more steps would waste computation and create redundant proposals.

```python
qs_nuts_w, q_tmp_w, p_tmp_w = leapfrog_path_w(0.0, 1.0, 0.25, 16)  # start at the mode with positive momentum.
turn_values_w = []
q_w, p_w = 0.0, 1.0
for step_w in range(16):
    p_w = p_w - 0.5 * 0.25 * q_w
    q_w = q_w + 0.25 * p_w
    p_w = p_w - 0.5 * 0.25 * q_w
    turn_values_w.append((q_w - 0.0) * p_w)
first_turn_w = int(np.where(np.array(turn_values_w) < 0)[0][0] + 1)
print("first U-turn step:", first_turn_w, "dot value:", round(turn_values_w[first_turn_w - 1], 3))
assert first_turn_w > 1
```
▶ What you'll see: the first negative displacement-times-momentum value marks the no-U-turn stopping point.

```python
plt.figure(figsize=(5, 3))
plt.plot(range(1, 17), turn_values_w, marker="o", color="teal")
plt.axhline(0, color="black", linewidth=0.8)
plt.axvline(first_turn_w, color="crimson", linestyle="--", label="stop")
plt.title("6: NUTS U-turn diagnostic")
plt.xlabel("leapfrog step"); plt.ylabel("(q_t - q_0) p_t"); plt.legend(); plt.show()
```
▶ What you'll see: the curve crosses below zero exactly where NUTS would stop extending that direction.

*Why it's done this way:* trajectory length is hard to tune by hand because the right length depends on local posterior geometry. The U-turn rule uses only geometry already available from leapfrog, so NUTS adapts path length without changing the target distribution.

## 🛠️ Setup

```python
import numpy as np # load NumPy for arrays, gradients, random numbers, and numerical checks.
import matplotlib.pyplot as plt # load Matplotlib for every diagnostic visualization.
np.random.seed(0) # make examples reproducible.

def U_std(q): # define standard-normal potential energy up to an additive constant.
    return 0.5 * np.asarray(q) ** 2 # return q squared over 2.

def grad_U_std(q): # define the gradient of the standard-normal potential.
    return np.asarray(q) # derivative of q^2/2 is q.

def H_std(q, p): # define Hamiltonian energy with unit mass.
    return float(0.5 * q**2 + 0.5 * p**2) # add potential and kinetic energy.

def leapfrog_1d(q, p, eps, L): # run L leapfrog steps for the standard-normal target.
    qs = [float(q)] # store positions for plotting.
    ps = [float(p)] # store momenta for plotting.
    for _ in range(L): # repeat symplectic integration steps.
        p = p - 0.5 * eps * grad_U_std(q) # half momentum update from the current gradient.
        q = q + eps * p # full position update using unit mass.
        p = p - 0.5 * eps * grad_U_std(q) # half momentum update from the new gradient.
        qs.append(float(q)); ps.append(float(p)) # record the new phase-space point.
    return np.array(qs), np.array(ps) # return the full path.

def normal_logpdf_unnorm(x, mean=0.0, sd=1.0): # define an unnormalized normal log density.
    z = (np.asarray(x) - mean) / sd # standardize positions.
    return -0.5 * z**2 # ignore the constant because MH ratios cancel it.
```
