# 20.4 — Data & Model Versioning / Registry

A production model is not just an array of weights. It is an artifact tied to exact data, schema, code choices, metrics, approvals, and serving state. In this lesson, we build those pieces from scratch in memory: hashes name content, Merkle roots summarize many pieces, lineage explains where artifacts came from, semantic versions communicate compatibility, and a tiny registry promotes or rolls back model versions by moving pointers instead of copying mystery files.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build data and model versioning one idea at a time. Run each cell in order and inspect the printed hashes, graphs, and stage pointers — every production idea is represented with NumPy arrays and plain Python data structures. This walkthrough is self-contained and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import hashlib  # content-addressable IDs and Merkle roots.
import json  # canonical serialization for dictionaries and metadata.
from collections import defaultdict, deque  # lineage graph traversal.
import numpy as np  # toy datasets, model weights, metrics, and array summaries.
import matplotlib.pyplot as plt  # registry, lineage, and metric visualizations.

```
▶ What you'll see: the only tools used are NumPy, Matplotlib, and the Python standard library.

### 1. Content-addressable hashes name data by what it is

A file path can lie: `train.csv` can keep the same name while rows or schema change. A content-addressable ID is different. We serialize the schema and array bytes into a canonical byte string, hash those bytes, and use the digest as the version name. If one value changes, the name changes; if two copies have the same content, they share the same name.

```python
X_w = np.array([[0.0, 1.0], [1.0, 1.5], [2.0, 3.0]], dtype=np.float64)  # three toy rows.
y_w = np.array([0.0, 1.0, 1.0], dtype=np.float64)  # tiny binary-ish target.
schema_w = {"columns": ["hours", "practice"], "target": "passed", "dtype": "float64"}  # input contract.
print("X shape:", X_w.shape, "y shape:", y_w.shape)  # inspect the data being named.
print("schema:", schema_w)  # inspect the contract that must be part of the version.
```
▶ What you'll see: a tiny dataset plus the schema that says what each column means.

```python
def canonical_bytes_w(obj):  # turn supported objects into deterministic bytes.
    if isinstance(obj, np.ndarray):  # arrays need shape, dtype, and raw bytes.
        header = json.dumps({"shape": obj.shape, "dtype": str(obj.dtype)}, sort_keys=True).encode()
        return header + b"|" + np.ascontiguousarray(obj).tobytes()  # stable across object identity.
    return json.dumps(obj, sort_keys=True, separators=(",", ":")).encode()  # stable dictionary order.

def digest_w(*parts):  # hash any number of byte-compatible parts.
    h = hashlib.sha256()  # SHA-256 is the standard content hash in many systems.
    for part in parts:  # include separators so adjacent parts cannot blur together.
        b = canonical_bytes_w(part)
        h.update(len(b).to_bytes(8, "big")); h.update(b)
    return h.hexdigest()  # long hex name.

data_hash_w = digest_w(schema_w, X_w, y_w)  # content name for the dataset + contract.
print("data hash prefix:", data_hash_w[:12])  # short prefix is readable in logs.
print("full hash length:", len(data_hash_w))  # SHA-256 hex has 64 chars.
assert len(data_hash_w) == 64  # concrete check: this is a real SHA-256 digest.
```
▶ What you'll see: a 64-character digest; the prefix is the short version name people usually read.

```python
X_changed_w = X_w.copy()  # make a nearly identical dataset.
X_changed_w[2, 1] += 0.01  # change one value by one hundredth.
changed_hash_w = digest_w(schema_w, X_changed_w, y_w)  # re-hash the altered content.
print("original prefix:", data_hash_w[:12])  # old content name.
print("changed  prefix:", changed_hash_w[:12])  # new content name.
print("hashes equal?", data_hash_w == changed_hash_w)  # one tiny content change should rename it.
assert data_hash_w != changed_hash_w  # content-addressing detects the edit.
```
▶ What you'll see: the two prefixes differ even though the array shape and filename idea did not.

```python
plt.figure(figsize=(5, 3))  # visualize how a tiny byte-level edit becomes a new version name.
plt.bar([data_hash_w[:8], changed_hash_w[:8]], [X_w.size, X_changed_w.size], color=["seagreen", "orange"])  # same shape, different identities.
plt.title("1: same shape, different content hashes")
plt.ylabel("array elements")
plt.xlabel("dataset hash prefix")
plt.show()
```
▶ What you'll see: both bars are the same size, but the x-axis names differ because one value changed.

*Why it's done this way:* the hash is not a checksum decoration; it is the version identifier. By hashing schema plus rows, the registry can distinguish “same path, different contract” from “same exact data copied twice.” The length prefixes in `digest_w` make the serialization unambiguous, so two different sequences of parts cannot accidentally produce the same byte stream before hashing.

### 2. A content-addressable store deduplicates by hash

Once hashes name artifacts, storage can become a dictionary from digest to object. Adding the same artifact twice should not create two versions; it should return the existing digest. This is deduplication by content, not by filename, owner, or time.

```python
store_w = {}  # in-memory object store: digest -> object.

def put_w(obj):  # store an object under its content hash.
    key = digest_w(obj)  # compute the content address.
    existed = key in store_w  # check whether identical bytes are already present.
    store_w.setdefault(key, obj)  # keep the first identical copy.
    return key, existed, len(store_w)  # return address, dedup flag, and store size.

key1_w, existed1_w, size1_w = put_w({"weights": [1.0, 2.0], "bias": 0.3})  # first copy.
key2_w, existed2_w, size2_w = put_w({"bias": 0.3, "weights": [1.0, 2.0]})  # same content, different dict order.
print("first existed?", existed1_w, "size:", size1_w)  # new object.
print("second existed?", existed2_w, "size:", size2_w)  # deduplicated object.
assert key1_w == key2_w and size2_w == 1  # canonical JSON makes dict order irrelevant.
```
▶ What you'll see: the second put reports that the object already existed and store size stays 1.

```python
key3_w, existed3_w, size3_w = put_w({"weights": [1.0, 2.1], "bias": 0.3})  # slightly different model.
print("old prefix:", key1_w[:10])  # first artifact prefix.
print("new prefix:", key3_w[:10])  # changed artifact prefix.
print("store size:", size3_w)  # now there are two unique contents.
assert key3_w != key1_w and size3_w == 2  # changed content gets a new address.
```
▶ What you'll see: changing one weight creates a new digest while identical copies still collapse together.

```python
plt.figure(figsize=(5, 3))  # visualize store growth across duplicate and changed puts.
plt.step(["first put", "duplicate put", "changed put"], [size1_w, size2_w, size3_w], where="mid", color="purple", linewidth=2)
plt.scatter(["first put", "duplicate put", "changed put"], [size1_w, size2_w, size3_w], color=["seagreen", "gray", "orange"], s=80)
plt.title("2: content-addressable store size")
plt.ylabel("unique artifacts")
plt.ylim(0, 3)
plt.show()
```
▶ What you'll see: the duplicate put stays flat while the changed artifact increases the unique object count.

*Why it's done this way:* deduplication falls out of content-addressing. The system does not need a special “is this duplicate?” heuristic; if two canonical byte streams hash to the same digest, they are treated as the same artifact. In real systems the object may be a large blob, but the principle is the same as this in-memory dictionary.

### 3. Merkle trees summarize many artifacts and localize changes

A model release depends on many pieces: schema, data shards, training code, parameters, and metrics. A Merkle tree hashes leaves first, then hashes pairs upward until one root remains. The root is a compact name for the entire bundle, while the leaf hashes let us identify exactly which part changed.

```python
leaves_w = [
    ("schema", digest_w(schema_w)),
    ("train-shard-0", digest_w(X_w[:2], y_w[:2])),
    ("train-shard-1", digest_w(X_w[2:], y_w[2:])),
    ("trainer", digest_w({"loss": "logistic", "epochs": 80})),
]  # named release ingredients.
for name_w, h_w in leaves_w:  # inspect each leaf digest.
    print(name_w, h_w[:10])  # short digest prefixes are enough for the walkthrough.
```
▶ What you'll see: four leaf hashes, one for each component of the release bundle.

```python
def merkle_root_w(named_hashes):  # build a binary Merkle root from (name, hash) leaves.
    level = [digest_w(name, h) for name, h in named_hashes]  # bind names to hashes so positions matter.
    levels = [level]  # keep levels for visualization.
    while len(level) > 1:  # reduce until one root remains.
        if len(level) % 2 == 1:  # duplicate the last node when the level has odd width.
            level = level + [level[-1]]
        level = [digest_w(level[i], level[i + 1]) for i in range(0, len(level), 2)]  # parent hashes.
        levels.append(level)  # store this level.
    return level[0], levels  # root and all intermediate levels.

root_w, levels_w = merkle_root_w(leaves_w)  # summarize the release bundle.
print("Merkle root:", root_w[:16])  # compact bundle identifier.
print("level widths:", [len(level_w) for level_w in levels_w])  # 4 leaves -> 2 parents -> 1 root.
assert [len(level_w) for level_w in levels_w] == [4, 2, 1]  # concrete tree shape.
```
▶ What you'll see: the whole bundle has one root, and the tree narrows from 4 to 2 to 1.

```python
leaves_changed_w = leaves_w.copy()  # start from the same bundle.
leaves_changed_w[2] = ("train-shard-1", digest_w(X_changed_w[2:], y_w[2:]))  # change one shard leaf.
root_changed_w, levels_changed_w = merkle_root_w(leaves_changed_w)  # re-compute the root.
changed_leaf_names_w = [name for (name, h0), (_, h1) in zip(leaves_w, leaves_changed_w) if h0 != h1]  # localize leaf changes.
print("old root:", root_w[:16])  # previous bundle root.
print("new root:", root_changed_w[:16])  # new bundle root.
print("changed leaves:", changed_leaf_names_w)  # exact component that changed.
assert root_w != root_changed_w and changed_leaf_names_w == ["train-shard-1"]  # one leaf changes the root.
```
▶ What you'll see: the root changes, but the diff points to `train-shard-1` as the only changed leaf.

```python
plt.figure(figsize=(5.5, 3.2))  # draw the three Merkle levels.
for depth_w, level_w in enumerate(levels_w):  # place each level on a row.
    xs_w = np.linspace(0, 1, len(level_w))  # spread nodes horizontally.
    ys_w = np.full(len(level_w), -depth_w)  # root appears below leaves.
    plt.scatter(xs_w, ys_w, s=450, color="lightsteelblue", edgecolor="black")  # draw nodes.
    for x_w, y_w, h_w in zip(xs_w, ys_w, level_w):  # label each node by digest prefix.
        plt.text(x_w, y_w, h_w[:6], ha="center", va="center", fontsize=8)  # readable hash label.
for i_w in range(4):  # connect leaves to parents.
    plt.plot([np.linspace(0, 1, 4)[i_w], np.linspace(0, 1, 2)[i_w // 2]], [0, -1], color="gray")
for i_w in range(2):  # connect parents to root.
    plt.plot([np.linspace(0, 1, 2)[i_w], 0], [-1, -2], color="gray")
plt.axis("off"); plt.title("3: Merkle tree for a release bundle"); plt.show()
```
▶ What you'll see: four leaf nodes roll up into two parents and then one root; look for hash prefixes at every node.

*Why it's done this way:* a Merkle root lets a registry name a whole release with one digest while preserving explainability. When the root changes, we do not have to compare every byte of every component manually; unchanged subtrees keep the same hash, and changed leaves reveal the minimal provenance difference.

### 4. Lineage graphs explain how artifacts were produced

Versioning answers “what artifact is this?” Lineage answers “where did it come from?” We store artifacts as nodes in a directed acyclic graph (DAG): data and code feed a run, the run emits a model, and evaluation emits metrics. Drawing the graph makes rollback and audit questions concrete.

```python
code_hash_w = digest_w({"trainer": "linear", "seed": 0})  # code/config identity.
model_hash_w = digest_w({"weights": [0.6, 1.1], "bias": -0.2})  # model identity.
metrics_hash_w = digest_w({"auc": 0.812, "loss": 0.42})  # metric artifact identity.
nodes_w = {"data:" + data_hash_w[:8]: (0.0, 1.0), "code:" + code_hash_w[:8]: (0.0, 0.0), "run:0007": (1.0, 0.5), "model:" + model_hash_w[:8]: (2.0, 0.8), "metrics:" + metrics_hash_w[:8]: (2.0, 0.2)}  # node labels and drawing positions.
edges_w = [("data:" + data_hash_w[:8], "run:0007"), ("code:" + code_hash_w[:8], "run:0007"), ("run:0007", "model:" + model_hash_w[:8]), ("run:0007", "metrics:" + metrics_hash_w[:8])]  # provenance edges.
print("nodes:", list(nodes_w))  # inspect lineage nodes.
print("edges:", edges_w)  # inspect directed dependencies.
assert len(nodes_w) == 5 and len(edges_w) == 4  # concrete graph size.
```
▶ What you'll see: data and code point to a run, and the run points to model and metrics artifacts.

```python
def ancestors_w(target, edges):  # find all upstream dependencies of a target node.
    parents = defaultdict(list)  # child -> parent list.
    for a, b in edges:  # reverse the lineage edges.
        parents[b].append(a)
    seen, q = set(), deque([target])  # breadth-first search upstream.
    while q:  # traverse until no parents remain.
        cur = q.popleft()
        for p in parents[cur]:  # visit each direct parent.
            if p not in seen:
                seen.add(p); q.append(p)
    return seen  # all upstream nodes.

model_node_w = [n for n in nodes_w if n.startswith("model:")][0]  # choose the model artifact.
upstream_w = ancestors_w(model_node_w, edges_w)  # find its lineage.
print("model:", model_node_w)  # target node.
print("upstream dependencies:", sorted(upstream_w))  # audit trail.
assert any(n.startswith("data:") for n in upstream_w) and "run:0007" in upstream_w  # model traces to data and run.
```
▶ What you'll see: the model's ancestors include the run plus the data and code that created that run.

```python
plt.figure(figsize=(6, 3.5))  # draw the lineage DAG.
for a_w, b_w in edges_w:  # draw arrows before nodes.
    x0_w, y0_w = nodes_w[a_w]; x1_w, y1_w = nodes_w[b_w]
    plt.annotate("", xy=(x1_w, y1_w), xytext=(x0_w, y0_w), arrowprops=dict(arrowstyle="->", color="gray", lw=1.5))
for name_w, (x_w, y_w) in nodes_w.items():  # draw labeled nodes.
    color_w = "lightgreen" if name_w.startswith("model") else "lightyellow" if name_w.startswith("run") else "lightblue"
    plt.scatter([x_w], [y_w], s=900, color=color_w, edgecolor="black")
    plt.text(x_w, y_w, name_w, ha="center", va="center", fontsize=8)
plt.xlim(-0.3, 2.4); plt.ylim(-0.3, 1.3); plt.axis("off"); plt.title("4: lineage DAG: data/code → run → artifacts"); plt.show()
```
▶ What you'll see: a left-to-right DAG; look for arrows proving the model was produced by a specific run from specific inputs.

*Why it's done this way:* lineage is a graph because production questions are graph questions: “Which data trained this model?”, “Which models used this schema?”, and “What must be rolled back together?” Keeping the graph acyclic prevents circular provenance stories that cannot be audited.

### 5. Semantic versions communicate compatibility, not just chronology

A digest is perfect for identity but hard for humans to plan around. Semantic versions add communication: `PATCH` means safe bug fix, `MINOR` means backward-compatible capability, and `MAJOR` means a breaking contract change. The content hash still proves identity; the semantic version tells consumers what kind of change to expect.

```python
def bump_w(version, kind):  # apply a semantic version bump.
    major, minor, patch = map(int, version.split("."))  # parse x.y.z.
    if kind == "patch":
        patch += 1  # bug fix, same public contract.
    elif kind == "minor":
        minor += 1; patch = 0  # compatible new feature resets patch.
    elif kind == "major":
        major += 1; minor = 0; patch = 0  # breaking change resets smaller counters.
    else:
        raise ValueError("kind must be patch, minor, or major")
    return f"{major}.{minor}.{patch}"  # return x.y.z.

v0_w = "2.4.7"  # current model package version.
print("patch:", bump_w(v0_w, "patch"))  # metadata fix.
print("minor:", bump_w(v0_w, "minor"))  # compatible feature addition.
print("major:", bump_w(v0_w, "major"))  # breaking schema change.
assert bump_w(v0_w, "patch") == "2.4.8" and bump_w(v0_w, "major") == "3.0.0"  # concrete semantics.
```
▶ What you'll see: patch changes only the last number, while a major bump resets the smaller numbers.

```python
def classify_change_w(old_schema, new_schema):  # infer the required semantic bump from feature contracts.
    old_cols, new_cols = old_schema["columns"], new_schema["columns"]  # compare ordered inputs.
    if old_cols == new_cols:
        return "patch"  # no contract change.
    if old_cols == new_cols[:len(old_cols)]:
        return "minor"  # append-only columns can be backward compatible with defaults.
    return "major"  # reorder, remove, or change meaning is breaking.

same_schema_w = {"columns": ["hours", "practice"], "target": "passed"}
append_schema_w = {"columns": ["hours", "practice", "prior_score"], "target": "passed"}
reorder_schema_w = {"columns": ["practice", "hours"], "target": "passed"}
print("same ->", classify_change_w(same_schema_w, same_schema_w))  # patch.
print("append ->", classify_change_w(same_schema_w, append_schema_w))  # minor.
print("reorder ->", classify_change_w(same_schema_w, reorder_schema_w))  # major.
assert classify_change_w(same_schema_w, reorder_schema_w) == "major"  # feature order matters.
```
▶ What you'll see: changing column order is treated as breaking even though the names are familiar.

```python
change_labels_w = ["same", "append", "reorder"]  # schema scenarios from the classifier above.
change_kinds_w = [classify_change_w(same_schema_w, same_schema_w), classify_change_w(same_schema_w, append_schema_w), classify_change_w(same_schema_w, reorder_schema_w)]
change_scores_w = [{"patch": 1, "minor": 2, "major": 3}[kind_w] for kind_w in change_kinds_w]  # map compatibility to visual severity.
plt.figure(figsize=(5, 3))
plt.bar(change_labels_w, change_scores_w, color=["green", "orange", "red"])
plt.yticks([1, 2, 3], ["patch", "minor", "major"])
plt.title("5: semantic version severity by schema change")
plt.ylabel("required bump")
plt.show()
```
▶ What you'll see: append-only schema change sits in the middle, while reordering requires a major bump.

*Why it's done this way:* semantic versioning is a contract language. A registry needs both machine identity (hashes) and human compatibility signals (versions). Treating feature order as breaking is conservative but valuable: many serving systems pass arrays positionally, so the same two names in a different order can silently corrupt predictions.

### 6. A model registry promotes by stage pointer and rolls back by pointer

A registry stores immutable model versions and mutable stage pointers like `Staging`, `Production`, and `Archived`. Promotion should compare a candidate to the champion with a threshold, check compatibility, then move a pointer. Rollback should also move a pointer — not retrain, not copy, and not guess.

```python
registry_w = {"versions": {}, "stages": {"Staging": None, "Production": None, "Archived": []}}  # tiny in-memory registry.

def register_w(name, version, model_hash, data_hash, metric, schema_cols):  # add immutable model metadata.
    key = f"{name}:{version}"  # human-readable version key.
    registry_w["versions"][key] = {"model_hash": model_hash, "data_hash": data_hash, "auc": metric, "schema_cols": tuple(schema_cols)}  # record lineage and contract.
    return key  # return registry key.

champ_w = register_w("math-pass", "2.4.7", digest_w({"w": [0.4, 0.8]}), data_hash_w, 0.804, ["hours", "practice"])  # current champion.
cand_w = register_w("math-pass", "2.5.0", digest_w({"w": [0.6, 1.1]}), changed_hash_w, 0.812, ["hours", "practice"])  # candidate.
registry_w["stages"]["Production"] = champ_w  # serve the champion.
registry_w["stages"]["Staging"] = cand_w  # evaluate the candidate.
print("Production:", registry_w["stages"]["Production"])  # current served pointer.
print("Staging:", registry_w["stages"]["Staging"])  # candidate pointer.
assert registry_w["versions"][cand_w]["auc"] - registry_w["versions"][champ_w]["auc"] == 0.008000000000000007  # concrete delta.
```
▶ What you'll see: the registry has two immutable versions and two mutable stage pointers.

```python
def compatible_w(champion_key, candidate_key):  # verify serving input compatibility.
    c0 = registry_w["versions"][champion_key]["schema_cols"]  # champion input contract.
    c1 = registry_w["versions"][candidate_key]["schema_cols"]  # candidate input contract.
    return c0 == c1  # exact match for this simple serving system.

def promote_if_better_w(candidate_key, threshold=0.005):  # champion comparison gate.
    prod = registry_w["stages"]["Production"]  # current champion pointer.
    delta = registry_w["versions"][candidate_key]["auc"] - registry_w["versions"][prod]["auc"]  # candidate lift.
    ok = delta >= threshold and compatible_w(prod, candidate_key)  # metric and schema gates.
    if ok:
        registry_w["stages"]["Archived"].append(prod)  # remember old champion for rollback.
        registry_w["stages"]["Production"] = candidate_key  # promote by moving pointer.
        registry_w["stages"]["Staging"] = None  # staging is cleared.
    return ok, delta  # report decision and release quantity.

ok_w, delta_w = promote_if_better_w(cand_w)  # try promotion.
print("delta AUC:", round(delta_w, 3), "promoted?", ok_w)  # inspect gate.
print("new Production:", registry_w["stages"]["Production"])  # pointer moved.
assert ok_w and registry_w["stages"]["Production"] == cand_w  # candidate cleared the 0.005 threshold.
```
▶ What you'll see: AUC improves by 0.008, clearing the 0.005 rule, so Production points to version 2.5.0.

```python
def rollback_w():  # move Production back to the latest archived version.
    previous = registry_w["stages"]["Archived"].pop()  # known safe prior pointer.
    current = registry_w["stages"]["Production"]  # currently served version.
    registry_w["stages"]["Archived"].append(current)  # keep the rolled-back version in history.
    registry_w["stages"]["Production"] = previous  # rollback by pointer move.
    return previous  # report restored champion.

restored_w = rollback_w()  # simulate incident rollback.
print("restored Production:", restored_w)  # previous version is serving again.
print("current stages:", registry_w["stages"])  # inspect stage state.
assert registry_w["stages"]["Production"] == champ_w  # rollback restored the old champion exactly.
```
▶ What you'll see: Production returns to 2.4.7 without retraining or changing artifact content.

```python
plt.figure(figsize=(5.5, 3))  # visualize metrics by version and the stage pointer.
keys_w = [champ_w, cand_w]  # versions in chronological order.
aucs_w = [registry_w["versions"][k]["auc"] for k in keys_w]  # metric values.
plt.bar(keys_w, aucs_w, color=["seagreen" if k == registry_w["stages"]["Production"] else "lightgray" for k in keys_w])  # color current production.
plt.axhline(registry_w["versions"][champ_w]["auc"] + 0.005, color="red", linestyle="--", label="promotion threshold from champion")  # threshold line.
plt.ylim(0.79, 0.82); plt.ylabel("AUC"); plt.xticks(rotation=10); plt.title("6: registry metric gate and Production pointer"); plt.legend(); plt.show()
```
▶ What you'll see: candidate 2.5.0 clears the dashed threshold, but after rollback the green Production bar is back on 2.4.7.

*Why it's done this way:* the registry separates immutable artifacts from mutable serving intent. Models are never edited in place; only stage pointers move. That makes promotion auditable, rollback fast, and incident response safer because the previous known artifact is still addressable by its original hash and version.

### ✍️ Toy 1 · Content digests change when content changes

A toy digest can be a weighted sum modulo a prime. It is not cryptographic, but it shows the content
addressing mechanic: one changed value gets a new name.

```python
import numpy as np
import matplotlib.pyplot as plt

t1_rng = np.random.default_rng(0)                # seeded generator for reproducibility.
t1_schema_code = np.array([2, 64])               # two columns, float64 code         # -> [ 2 64]
t1_X = np.array([[0.0, 1.0], [1.0, 1.5], [2.0, 3.0]])           # tiny data matrix     # -> [[0.  1. ] [1.  1.5] [2.  3. ]]
t1_y = np.array([0.0, 1.0, 1.0])                 # tiny target                      # -> [0. 1. 1.]
```

## 🛠️ Setup

```python
import hashlib  # compute content hashes for data, models, and Merkle nodes.
import json  # serialize dictionaries in a deterministic order.
from collections import defaultdict, deque  # build and traverse tiny lineage graphs.
import numpy as np  # create toy datasets, weights, metrics, and vectorized checks.
import matplotlib.pyplot as plt  # draw hash comparisons, DAGs, and registry state.
np.random.seed(0)  # make all random examples deterministic.

def canonical_bytes(obj):  # convert common in-memory objects to stable bytes.
    if isinstance(obj, np.ndarray):  # arrays need shape and dtype in addition to raw bytes.
        header = json.dumps({"shape": obj.shape, "dtype": str(obj.dtype)}, sort_keys=True).encode()
        return header + b"|" + np.ascontiguousarray(obj).tobytes()
    return json.dumps(obj, sort_keys=True, separators=(",", ":")).encode()

def digest(*parts):  # compute a SHA-256 digest over one or more canonical parts.
    h = hashlib.sha256()
    for part in parts:
        b = canonical_bytes(part)
        h.update(len(b).to_bytes(8, "big")); h.update(b)
    return h.hexdigest()

def merkle_root(named_hashes):  # compute a binary Merkle root from (name, hash) leaves.
    level = [digest(name, h) for name, h in named_hashes]
    levels = [level]
    while len(level) > 1:
        if len(level) % 2 == 1:
            level = level + [level[-1]]
        level = [digest(level[i], level[i + 1]) for i in range(0, len(level), 2)]
        levels.append(level)
    return level[0], levels

def show_bar(labels, values, title, ylabel="value"):  # tiny reusable bar-chart helper.
    plt.figure(figsize=(5, 3))
    plt.bar(labels, values, color="steelblue")
    plt.title(title); plt.ylabel(ylabel); plt.xticks(rotation=10)
    plt.show()
```

👀 Takeaway: lineage DAGs support both reproducibility audits and blast-radius analysis.

### Advanced 3 — Enforce retention while preserving Production

**Goal.** Keep only a fixed number of old versions while never deleting the served version, because registries need cost control without breaking rollback safety. We build it in 4 steps.

```python
versions_a3 = {f"v{i}": {"size_mb": 180, "created": i} for i in range(1, 8)}  # seven immutable versions.
stages_a3 = {"Production": "v7", "Archived": ["v1", "v2", "v3", "v4", "v5", "v6"]}  # current stage state.
keep_a3 = 5  # retention limit for total versions kept.
print("versions before:", sorted(versions_a3))  # inspect catalog.
```
▶ What you'll see: seven versions exist, each costing 180 MB.

```python
protected_a3 = {stages_a3["Production"]}  # never delete Production.
candidates_a3 = sorted([v_a3 for v_a3 in versions_a3 if v_a3 not in protected_a3], key=lambda v_a3: versions_a3[v_a3]["created"])  # oldest removable first.
to_delete_a3 = candidates_a3[:max(0, len(versions_a3) - keep_a3)]  # enough deletions to satisfy retention.
print("delete candidates:", to_delete_a3)  # inspect planned cleanup.
assert to_delete_a3 == ["v1", "v2"]  # seven kept to five means delete two oldest non-production versions.
```
▶ What you'll see: v1 and v2 are chosen because they are oldest and not Production.

```python
for v_a3 in to_delete_a3:  # apply retention.
    versions_a3.pop(v_a3)  # remove version metadata.
    if v_a3 in stages_a3["Archived"]:
        stages_a3["Archived"].remove(v_a3)  # remove from archive pointer list too.
print("versions after:", sorted(versions_a3))  # inspect kept versions.
assert stages_a3["Production"] in versions_a3 and len(versions_a3) == keep_a3  # Production preserved and limit met.
```
▶ What you'll see: five versions remain, including the served version v7.

```python
cost_before_a3 = 7 * 180  # MB before retention.
cost_after_a3 = len(versions_a3) * 180  # MB after retention.
show_bar(["before", "after"], [cost_before_a3, cost_after_a3], "A3: retention storage cost", "MB")  # visualize cost reduction.
assert cost_after_a3 == 900  # lesson arithmetic: 5 * 180 = 900 MB.
```
▶ What you'll see: storage drops from 1260 MB to 900 MB while Production remains safe.

👀 Takeaway: retention is a policy over registry metadata, with stage pointers acting as deletion guards.

### Advanced 4 — Reject a schema-incompatible candidate

**Goal.** Block promotion even when metrics improve, because a model that expects missing or reordered features can fail at serving time. We build it in 4 steps.

```python
registry_a4 = {"versions": {"v7": {"auc": 0.812, "schema": ("hours", "practice")}, "v8": {"auc": 0.830, "schema": ("practice", "hours")}}, "stages": {"Production": "v7", "Staging": "v8"}}  # candidate has better metric but reordered inputs.
print("Production schema:", registry_a4["versions"]["v7"]["schema"])  # inspect champion contract.
print("Staging schema:", registry_a4["versions"]["v8"]["schema"])  # inspect candidate contract.
```
▶ What you'll see: the two schemas contain the same names in a different order.

```python
prod_a4 = registry_a4["stages"]["Production"]  # champion.
cand_a4 = registry_a4["stages"]["Staging"]  # candidate.
delta_a4 = registry_a4["versions"][cand_a4]["auc"] - registry_a4["versions"][prod_a4]["auc"]  # metric lift.
missing_a4 = set(registry_a4["versions"][prod_a4]["schema"]) - set(registry_a4["versions"][cand_a4]["schema"])  # missing names.
order_ok_a4 = registry_a4["versions"][prod_a4]["schema"] == registry_a4["versions"][cand_a4]["schema"]  # exact serving order.
print("delta:", round(delta_a4, 3), "missing features:", missing_a4, "order_ok:", order_ok_a4)  # inspect gates.
assert round(delta_a4, 3) == 0.018 and len(missing_a4) == 0 and not order_ok_a4  # better metric but breaking order.
```
▶ What you'll see: AUC improves, no feature names are missing, but positional order is not compatible.

```python
promote_a4 = delta_a4 >= 0.005 and order_ok_a4  # require metric and exact contract.
print("promote?", promote_a4)  # inspect decision.
assert promote_a4 is False  # schema mismatch blocks release.
```
▶ What you'll see: promotion is rejected despite the better metric.

```python
plt.figure(figsize=(5, 3))  # show why the decision can surprise people.
plt.bar(["v7 champion", "v8 candidate"], [registry_a4["versions"]["v7"]["auc"], registry_a4["versions"]["v8"]["auc"]], color=["green", "red"])  # metric bars.
plt.title("A4: metric win blocked by schema incompatibility"); plt.ylabel("AUC"); plt.show()
```
▶ What you'll see: the red candidate bar is higher, but color reminds you it is blocked by the schema gate.

👀 Takeaway: model registries govern compatibility as well as quality; both gates must pass.

### Advanced 5 — End-to-end mini registry with promotion and rollback

**Goal.** Connect hashing, lineage, metrics, stages, and rollback in one tiny release flow, because production ML works only when these ideas compose. We build it in 5 steps.

```python
X_a5 = np.array([[0.0, 1.0], [1.0, 2.0], [2.0, 2.5], [3.0, 4.0]], dtype=np.float64)  # toy training features.
y_a5 = np.array([0.0, 0.0, 1.0, 1.0], dtype=np.float64)  # toy labels.
schema_a5 = {"columns": ["hours", "practice"], "target": "passed"}  # serving contract.
data_hash_a5 = digest(schema_a5, X_a5, y_a5)  # content-addressed data version.
print("data hash:", data_hash_a5[:12])  # inspect dataset ID.
```
▶ What you'll see: one dataset hash names both rows and schema.

```python
models_a5 = {"v6": {"w": np.array([0.4, 0.8]), "b": -0.3, "auc": 0.804}, "v7": {"w": np.array([0.6, 1.1]), "b": -0.5, "auc": 0.812}}  # champion and candidate.
for key_a5, rec_a5 in models_a5.items():  # attach model hashes.
    rec_a5["model_hash"] = digest({"w": rec_a5["w"].round(6).tolist(), "b": rec_a5["b"]})
print("model hashes:", {k_a5: v_a5["model_hash"][:8] for k_a5, v_a5 in models_a5.items()})  # inspect artifact IDs.
assert models_a5["v6"]["model_hash"] != models_a5["v7"]["model_hash"]  # different weights mean different artifacts.
```
▶ What you'll see: v6 and v7 have separate model hashes.

```python
release_roots_a5 = {}  # version -> Merkle root.
for key_a5, rec_a5 in models_a5.items():  # build release bundles.
    leaves_a5 = [("schema", digest(schema_a5)), ("data", data_hash_a5), ("model", rec_a5["model_hash"]), ("metrics", digest({"auc": rec_a5["auc"]}))]
    release_roots_a5[key_a5], _ = merkle_root(leaves_a5)  # one root per release.
print("release roots:", {k_a5: v_a5[:10] for k_a5, v_a5 in release_roots_a5.items()})  # inspect roots.
assert release_roots_a5["v6"] != release_roots_a5["v7"]  # metric/model leaf changes the release root.
```
▶ What you'll see: each model version has a bundle root summarizing data, schema, model, and metrics.

```python
registry_a5 = {"versions": {k_a5: {"auc": v_a5["auc"], "root": release_roots_a5[k_a5], "schema": tuple(schema_a5["columns"])} for k_a5, v_a5 in models_a5.items()}, "stages": {"Production": "v6", "Staging": "v7", "Archived": []}}  # registry metadata.
delta_a5 = registry_a5["versions"]["v7"]["auc"] - registry_a5["versions"]["v6"]["auc"]  # metric lift.
if delta_a5 >= 0.005 and registry_a5["versions"]["v7"]["schema"] == registry_a5["versions"]["v6"]["schema"]:  # gates.
    registry_a5["stages"]["Archived"].append("v6")
    registry_a5["stages"]["Production"] = "v7"
    registry_a5["stages"]["Staging"] = None
print("after promotion:", registry_a5["stages"], "delta", round(delta_a5, 3))  # inspect promoted state.
assert registry_a5["stages"]["Production"] == "v7" and round(delta_a5, 3) == 0.008  # verify gate result.
```
▶ What you'll see: v7 becomes Production because it improves by 0.008 and keeps the same schema.

```python
rolled_from_a5 = registry_a5["stages"]["Production"]  # currently serving version.
rollback_to_a5 = registry_a5["stages"]["Archived"].pop()  # previous known-safe version.
registry_a5["stages"]["Archived"].append(rolled_from_a5)  # preserve rolled-back version.
registry_a5["stages"]["Production"] = rollback_to_a5  # restore old champion.
print("after rollback:", registry_a5["stages"])  # inspect final state.
plt.figure(figsize=(5, 3))  # visualize AUC and final Production pointer.
plt.bar(["v6", "v7"], [registry_a5["versions"]["v6"]["auc"], registry_a5["versions"]["v7"]["auc"]], color=["green" if registry_a5["stages"]["Production"] == "v6" else "gray", "green" if registry_a5["stages"]["Production"] == "v7" else "gray"])
plt.title("A5: final Production pointer after rollback"); plt.ylabel("AUC"); plt.show()
assert registry_a5["stages"]["Production"] == "v6"  # rollback restored the old champion.
```
▶ What you'll see: even though v7 has the higher metric, the final green Production bar is v6 after rollback.

👀 Takeaway: the complete registry loop is immutable identity plus mutable stage pointers, with metric gates and rollback preserving operational safety.
