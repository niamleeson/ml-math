# 4.25 — Kernel Density Estimation

Kernel Density Estimation (KDE) turns raw unlabeled samples into a smooth probability density by placing a small, normalized bump on every data point and adding the bumps together. In this lesson, you will build KDE from first principles with NumPy, inspect the distance weights that decide local influence, and see why the bandwidth `h` is the modeling choice that controls what structure the algorithm is able to reveal.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build kernel density estimation one idea at a time. Run each cell in order and read the printed intermediate values — every piece of math, including the Gaussian weights and the bandwidth effect, is shown so the density estimate is never a black box. This walkthrough is self-contained (it imports what it needs) and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays, distances, exponentials, and numerical integration.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
np.random.seed(0)  # reproducibility for synthetic samples.
```

### 1. From isolated samples to a density question

KDE starts with unlabeled samples, not bin counts or class labels. A sample is only a location; the density question is: "where would new points plausibly appear?" A histogram is a useful first picture, but its answer depends on arbitrary bin edges. KDE replaces hard bins with smooth local influence so nearby samples contribute gradually instead of either fully counting or not counting at all.

```python
x_w = np.array([-2.1, -1.8, -1.4, 0.2, 0.4, 0.7, 1.9, 2.2])  # one-dimensional unlabeled samples.
grid_w = np.linspace(-3.0, 3.0, 301)  # query locations where we will estimate density.
print("samples:", x_w)  # inspect the observed data.
print("grid shape:", grid_w.shape)  # inspect how many density queries we will make.
```
▶ What you'll see: eight points arranged in three loose regions, plus a dense grid of 301 query locations.

```python
counts_w, edges_w = np.histogram(x_w, bins=4, range=(-3, 3), density=True)  # a hard-bin density estimate.
print("histogram bin edges:", np.round(edges_w, 2))  # inspect the arbitrary bin boundaries.
print("histogram heights:", np.round(counts_w, 3))  # inspect piecewise-constant density values.
assert len(counts_w) == 4  # four bins create four flat density levels.
```
▶ What you'll see: the density jumps at bin edges even though the underlying sample locations changed smoothly.

```python
plt.figure(figsize=(5, 3))  # create a compact diagnostic plot.
plt.hist(x_w, bins=4, range=(-3, 3), density=True, alpha=0.45, color="gray", edgecolor="black")  # hard-bin density.
plt.scatter(x_w, np.zeros_like(x_w), color="crimson", zorder=3, label="samples")  # show the raw points.
plt.title("1: histogram is a hard local summary")  # title the first picture.
plt.xlabel("x")  # label the coordinate axis.
plt.ylabel("density")  # label the density scale.
plt.legend()  # show the sample marker label.
plt.show()  # display the figure.
```
▶ What you'll see: point masses on the x-axis and rectangular bins above them; shifting bin edges would change the rectangles.

*Why it's done this way:* a density must integrate to 1, so a histogram divides counts by bin width and sample count. The problem is not normalization; it is geometry. Hard bins use an all-or-nothing notion of closeness: two points separated by a bin edge do not share influence, while two points far apart inside the same bin do. KDE keeps the probability normalization but replaces the discontinuous bin rule with a smooth distance-based rule.

### 2. A Gaussian kernel turns distance into local influence

A kernel is a small bump centered on one sample. For a query point `q` and sample `x_i`, the Gaussian kernel uses squared distance: $$\exp\left(-\frac{(q-x_i)^2}{2h^2}\right).$$ The bandwidth `h` is the locality scale. If `h` is small, influence dies quickly with distance; if `h` is large, faraway samples still matter.

```python
q_w = 0.0  # choose one query location.
h_w = 0.5  # choose a locality scale.
d_w = q_w - x_w  # signed distances from the query to every sample.
raw_w = np.exp(-(d_w ** 2) / (2 * h_w ** 2))  # unnormalized Gaussian influence values.
print("distances from q=0:", np.round(d_w, 2))  # inspect geometry first.
print("raw kernel weights:", np.round(raw_w, 3))  # inspect distance-to-influence conversion.
```
▶ What you'll see: samples near 0 have large weights, while samples near ±2 have tiny weights.

```python
plt.figure(figsize=(5, 3))  # create a compact weight plot.
plt.bar([f"{v:.1f}" for v in x_w], raw_w, color="steelblue")  # show influence from each sample.
plt.title("2: Gaussian influence at query q=0")  # title the plot.
plt.xlabel("sample location")  # label each sample coordinate.
plt.ylabel("exp(-d² / 2h²)")  # label the kernel formula value.
plt.show()  # display the figure.
```
▶ What you'll see: the tallest bars belong to samples closest to the query; distance is the only evidence used.

*Why it's done this way:* squared distance makes left and right deviations equally costly and makes larger deviations shrink influence faster than smaller ones. Dividing by `2h²` expresses distance in bandwidth units: a point one bandwidth away has weight `exp(-1/2)≈0.607`, exactly the numeric pass in the source lesson. The exponential keeps all weights positive, so every sample contributes smoothly but locality still dominates.

### 3. Normalized influence weights answer "who owns this query?"

The source lesson's central computation normalizes Gaussian influences: $$p_i=\frac{\exp(-d_i^2/2h^2)}{\sum_j\exp(-d_j^2/2h^2)}.$$ These `p_i` are not the KDE density yet; they are a soft assignment of the query's influence across samples. They sum to 1, so they can be read as shares of responsibility.

```python
demo_d_w = np.array([1.0, 0.0, 1.0])  # the tiny numeric pass from the lesson.
h_demo_w = 1.0  # bandwidth for the worked calculation.
raw_demo_w = np.exp(-(demo_d_w ** 2) / (2 * h_demo_w ** 2))  # [e^-0.5, e^0, e^-0.5].
p_demo_w = raw_demo_w / raw_demo_w.sum()  # normalize raw influences into shares.
print("raw:", np.round(raw_demo_w, 3), "sum:", round(float(raw_demo_w.sum()), 3))  # inspect numerator and denominator.
print("normalized p:", np.round(p_demo_w, 3))  # inspect the soft ownership weights.
assert round(float(p_demo_w[1]), 3) == 0.452  # the middle point receives 1 / 2.213 of influence.
```
▶ What you'll see: the middle point gets normalized influence 0.452, while the two distance-1 points tie.

```python
p_w = raw_w / raw_w.sum()  # normalize the query q=0 weights from concept 2.
print("sum of normalized weights:", round(float(p_w.sum()), 6))  # verify probability-like normalization.
print("largest owner sample:", x_w[int(np.argmax(p_w))], "with p=", round(float(np.max(p_w)), 3))  # inspect strongest contributor.
assert abs(float(p_w.sum()) - 1.0) < 1e-12  # normalized weights must sum to one.
```
▶ What you'll see: the ownership weights sum to exactly 1, and the closest sample owns the largest share.

```python
plt.figure(figsize=(5, 3))  # create a compact normalized-weight plot.
plt.bar([f"{v:.1f}" for v in x_w], p_w, color="seagreen")  # show normalized shares.
plt.title("3: normalized influence weights pᵢ at q=0")  # title the plot.
plt.xlabel("sample location")  # label sample coordinates.
plt.ylabel("share of influence")  # label probability-like weights.
plt.show()  # display the figure.
```
▶ What you'll see: the same local pattern as raw weights, now scaled so all bars sum to one.

*Why it's done this way:* raw exponentials measure compatibility but do not say how influence is divided among competitors. The denominator creates a local probability distribution over samples for this one query. This normalization is useful whenever the algorithm must choose which neighbor, representative, or component explains a point; it prevents the absolute number of nearby points from being confused with relative ownership.

### 4. KDE density adds normalized bumps, not ownership shares

For an actual one-dimensional KDE, each sample contributes a normalized Gaussian density bump: $$\hat f(q)=\frac{1}{n}\sum_i \frac{1}{h\sqrt{2\pi}}\exp\left(-\frac{(q-x_i)^2}{2h^2}\right).$$ The extra factor `1/(h sqrt(2π))` makes each bump integrate to 1, and the `1/n` average makes the whole estimate integrate to 1.

```python
h_kde_w = 0.35  # choose a bandwidth for the full KDE curve.
diff_w = grid_w[:, None] - x_w[None, :]  # shape: queries by samples.
kernels_w = np.exp(-(diff_w ** 2) / (2 * h_kde_w ** 2)) / (h_kde_w * np.sqrt(2 * np.pi))  # normalized Gaussian bumps.
density_w = kernels_w.mean(axis=1)  # average one bump per sample.
print("kernel matrix shape:", kernels_w.shape)  # inspect query-by-sample bookkeeping.
print("density min/max:", round(float(density_w.min()), 4), round(float(density_w.max()), 4))  # inspect density scale.
```
▶ What you'll see: a 301×8 matrix of bump values and a positive density curve over the grid.

```python
area_w = np.trapz(density_w, grid_w)  # approximate integral over the displayed grid.
print("approximate area under KDE:", round(float(area_w), 3))  # should be close to 1 on a wide enough grid.
assert 0.97 < area_w < 1.01  # the displayed grid captures almost all Gaussian mass.
```
▶ What you'll see: the area is close to 1, confirming the curve behaves like a probability density.

```python
plt.figure(figsize=(5, 3))  # create a compact KDE plot.
plt.plot(grid_w, density_w, color="navy", label="KDE")  # draw the estimated density.
plt.scatter(x_w, np.zeros_like(x_w), color="crimson", zorder=3, label="samples")  # show sample locations.
plt.title("4: KDE averages normalized Gaussian bumps")  # title the plot.
plt.xlabel("x")  # label coordinate axis.
plt.ylabel("estimated density")  # label density axis.
plt.legend()  # show curve and point labels.
plt.show()  # display the figure.
```
▶ What you'll see: a smooth density with three humps near the three regions of observed samples.

*Why it's done this way:* normalized ownership weights `p_i` are query-relative and sum over samples to 1; KDE density values instead must integrate over space to 1. That is why the Gaussian normalizing constant appears in the density formula. Averaging normalized bumps says every observed sample represents `1/n` of the empirical probability mass, then bandwidth spreads that mass into nearby space.

### 5. Bandwidth is the smoothness dial

The bandwidth `h` decides which structures KDE can see. Too small a bandwidth produces a spiky curve that memorizes individual samples; too large a bandwidth washes separate groups into one broad mound. The algorithm is therefore a lens, not an oracle: it reveals structure at the scale you ask it to inspect.

```python
hs_w = np.array([0.12, 0.35, 0.9])  # compare undersmoothed, moderate, and oversmoothed bandwidths.
curves_w = []  # store density curves for plotting.
for h_loop_w in hs_w:  # compute one KDE curve per bandwidth.
    diff_loop_w = grid_w[:, None] - x_w[None, :]  # query-sample distances.
    dens_loop_w = np.exp(-(diff_loop_w ** 2) / (2 * h_loop_w ** 2)).mean(axis=1) / (h_loop_w * np.sqrt(2 * np.pi))  # KDE formula.
    curves_w.append(dens_loop_w)  # save this bandwidth's curve.
print("bandwidths:", hs_w)  # inspect the smoothness settings.
print("peak heights:", [round(float(c.max()), 3) for c in curves_w])  # smaller h gives taller peaks.
```
▶ What you'll see: peak height falls as bandwidth grows because the same probability mass is spread wider.

```python
plt.figure(figsize=(5, 3))  # create a bandwidth comparison figure.
for h_loop_w, curve_loop_w in zip(hs_w, curves_w):  # draw each curve.
    plt.plot(grid_w, curve_loop_w, label=f"h={h_loop_w}")  # label by bandwidth.
plt.scatter(x_w, np.zeros_like(x_w), color="black", s=18, zorder=3)  # show samples along the axis.
plt.title("5: bandwidth controls KDE smoothness")  # title the plot.
plt.xlabel("x")  # label coordinate axis.
plt.ylabel("estimated density")  # label density axis.
plt.legend()  # show bandwidth labels.
plt.show()  # display the figure.
```
▶ What you'll see: `h=0.12` creates needle-like bumps, `h=0.35` separates the groups, and `h=0.9` merges structure.

*Why it's done this way:* `h` appears in two places. In the exponent, larger `h` makes the same distance look smaller, so more samples influence each query. In the normalizing constant, larger `h` lowers the bump height so total mass stays 1. Those two effects are exactly the bias-variance tradeoff: small `h` has low bias and high variance; large `h` has high bias and low variance.

### 6. Scaling and multidimensional distances change the density lens

In multiple dimensions, KDE uses a distance from the query to each sample. If one feature has much larger units, squared distance is dominated by that feature and the kernel effectively ignores the others. Scaling is therefore not a cosmetic preprocessing step; it changes which points count as close.

```python
X_w = np.array([[0.0, 0.0], [0.2, 10.0], [0.4, 20.0], [2.0, 22.0], [2.2, 24.0]])  # two features with very different units.
query2_w = np.array([0.3, 12.0])  # query near the first three points in raw y-units.
raw_dist_w = np.linalg.norm(X_w - query2_w, axis=1)  # Euclidean distance before scaling.
print("raw distances:", np.round(raw_dist_w, 2))  # inspect dominance by the second feature.
```
▶ What you'll see: distances mostly track the large-scale second coordinate.

```python
mean_w = X_w.mean(axis=0)  # feature means for standardization.
std_w = X_w.std(axis=0)  # feature standard deviations for standardization.
Z_w = (X_w - mean_w) / std_w  # standardized samples.
zq_w = (query2_w - mean_w) / std_w  # standardized query.
scaled_dist_w = np.linalg.norm(Z_w - zq_w, axis=1)  # distances after equalizing feature scale.
print("scaled distances:", np.round(scaled_dist_w, 2))  # inspect changed neighborhood geometry.
assert int(np.argmin(raw_dist_w)) == 1 and int(np.argmin(scaled_dist_w)) == 1  # nearest stays stable here.
```
▶ What you'll see: the nearest point remains the same, but the relative gaps change because both features now matter.

```python
weights_raw_w = np.exp(-(raw_dist_w ** 2) / (2 * 8.0 ** 2))  # use a large raw-space bandwidth for raw units.
weights_scaled_w = np.exp(-(scaled_dist_w ** 2) / (2 * 0.9 ** 2))  # use a standardized-space bandwidth.
weights_raw_w = weights_raw_w / weights_raw_w.sum()  # normalize raw-space influence shares.
weights_scaled_w = weights_scaled_w / weights_scaled_w.sum()  # normalize scaled-space influence shares.
plt.figure(figsize=(5, 3))  # create a comparison plot.
plt.plot(weights_raw_w, marker="o", label="raw units")  # show raw influence distribution.
plt.plot(weights_scaled_w, marker="s", label="scaled units")  # show scaled influence distribution.
plt.title("6: scaling changes normalized influence")  # title the plot.
plt.xlabel("sample index")  # label sample index.
plt.ylabel("influence share")  # label normalized weight.
plt.legend()  # show line labels.
plt.show()  # display the figure.
```
▶ What you'll see: the query distributes influence differently once feature scales are made comparable.

*Why it's done this way:* the Gaussian kernel only sees squared distances. If distance is numerically dominated by a high-unit feature, the density estimate is really a density over that feature alone. Standardizing features makes a one-standard-deviation movement comparable across coordinates, so the bandwidth `h` has a meaningful geometric interpretation.

### ✍️ Toy 1 · Histogram density normalizes bin counts

Before smoothing, a histogram already shows the density requirement: heights times bin widths should
sum to one.

```python
import numpy as np
import matplotlib.pyplot as plt

t1_rng = np.random.default_rng(0)                  # reproducible toy seed.
t1_x = np.array([-1.8, -1.2, -0.2, 0.1, 0.4, 1.1, 1.4, 1.8])  # 8 one-dimensional samples.
t1_counts, t1_edges = np.histogram(t1_x, bins=4, range=(-2, 2), density=True)  # density histogram.
t1_widths = np.diff(t1_edges)                      # bin widths       # -> [1. 1. 1. 1.]
t1_area = float(np.sum(t1_counts * t1_widths))      # total density area # -> 1.0
print("samples:", t1_x.tolist())                  # -> [-1.8, -1.2, -0.2, 0.1, 0.4, 1.1, 1.4, 1.8]
print("bin edges:", np.round(t1_edges, 2).tolist())  # -> [-2.0, -1.0, 0.0, 1.0, 2.0]
print("histogram heights:", np.round(t1_counts, 3).tolist())  # -> [0.25, 0.125, 0.25, 0.375]
print("bin widths:", t1_widths.tolist())           # -> [1.0, 1.0, 1.0, 1.0]
print("area:", round(t1_area, 3))                  # -> 1.0
assert abs(t1_area - 1.0) < 1e-12

plt.figure(figsize=(4.8, 2.8))
plt.hist(t1_x, bins=4, range=(-2, 2), density=True, alpha=0.5, edgecolor="black", color="gray")
plt.scatter(t1_x, np.zeros_like(t1_x), color="crimson", zorder=3)
plt.xlabel("x")
plt.ylabel("density")
plt.title("Toy 1 · histogram area equals 1")
plt.show()
```
▶ What you'll see: four hard bins with total area `1.0`, plus the raw samples on the axis.

### ✍️ Toy 2 · A Gaussian kernel turns distance into influence

For one query point, squared distance controls how much each sample contributes before normalization.

```python
import numpy as np

t2_rng = np.random.default_rng(0)                  # reproducible toy seed.
```

### ✍️ Toy 5 · Bandwidth changes peakiness and roughness

Small bandwidths put narrow spikes near samples; large bandwidths spread the same mass into a smoother
curve.

```python
import numpy as np

t5_rng = np.random.default_rng(0)                  # reproducible toy seed.
t5_x = np.array([-1.2, -0.8, 0.0, 0.3, 1.0, 1.4]) # sample locations.
t5_grid = np.linspace(-3.0, 3.0, 121)              # query grid.
t5_hs = np.array([0.18, 0.45, 0.9])                # small, medium, large bandwidths.
t5_curves = []                                     # density curves.
t5_peaks = []                                      # maximum height per curve.
t5_roughness = []                                  # total absolute wiggle per curve.
for t5_h in t5_hs:
    t5_diff = t5_grid[:, None] - t5_x[None, :]
    t5_curve = np.exp(-(t5_diff ** 2) / (2 * t5_h ** 2)).mean(axis=1) / (t5_h * np.sqrt(2 * np.pi))
    t5_curves.append(t5_curve)
    t5_peaks.append(float(t5_curve.max()))
    t5_roughness.append(float(np.sum(np.abs(np.diff(t5_curve)))))
t5_peak_round = [round(v, 3) for v in t5_peaks]    # peak heights  # -> [0.522, 0.326, 0.288]
t5_rough_round = [round(v, 3) for v in t5_roughness]  # roughness   # -> [2.39, 0.68, 0.538]
print("bandwidths:", t5_hs.tolist())               # -> [0.18, 0.45, 0.9]
print("peak heights:", t5_peak_round)              # -> [0.522, 0.326, 0.288]
print("curve roughness:", t5_rough_round)          # -> [2.39, 0.68, 0.538]
assert t5_peaks[0] > t5_peaks[-1] and t5_roughness[0] > t5_roughness[-1]

plt.figure(figsize=(4.8, 2.8))
for t5_h, t5_curve in zip(t5_hs, t5_curves):
    plt.plot(t5_grid, t5_curve, label=f"h={t5_h}")
plt.scatter(t5_x, np.zeros_like(t5_x), color="black", s=18)
plt.xlabel("x")
plt.ylabel("density")
plt.title("Toy 5 · bandwidth sweep")
plt.legend()
plt.show()
```
▶ What you'll see: the smallest bandwidth is tallest and wiggliest; the largest is smoother and lower.

### ✍️ Toy 6 · Feature scaling changes multidimensional ownership

In two dimensions, Gaussian weights depend on Euclidean distance. Standardizing features can change
which samples own the query.

```python
import numpy as np

t6_rng = np.random.default_rng(0)                  # reproducible toy seed.
t6_X = np.array([[0.0,  0.0],
                 [0.2, 10.0],
                 [0.4, 20.0],
                 [2.0, 21.0],
                 [2.2, 22.0],
                 [2.4, 24.0]])                    # two features with different units.
t6_q = np.array([0.3, 12.0])                       # query point.
t6_raw_dist = np.linalg.norm(t6_X - t6_q, axis=1)  # raw-space distances # -> [12.004 2.002 8.001 9.159 10.179 12.182]
```

### Advanced 1 — Leave-one-out log likelihood for bandwidth

**Goal.** Choose bandwidth by scoring each sample under a KDE fit to the other samples, because training density alone rewards tiny bandwidths that memorize points. We build it in 4 steps.

```python
x_a1 = np.array([-2.0, -1.8, -1.5, 0.2, 0.5, 0.7, 2.0]) # define samples.
hs_a1 = np.array([0.12, 0.25, 0.45, 0.8, 1.2]) # choose bandwidth candidates.
print("candidate h:", hs_a1) # inspect the search grid.
```
▶ What you'll see: a range from very local to very smooth bandwidths.

```python
scores_a1 = [] # store leave-one-out average log density.
for h_a1 in hs_a1: # loop over candidate bandwidths.
    logs_a1 = [] # store one held-out log density per sample.
    for i_a1 in range(len(x_a1)): # hold out each sample once.
        train_a1 = np.delete(x_a1, i_a1) # remove the current sample from the KDE fit.
        dens_a1 = np.exp(-((x_a1[i_a1] - train_a1) ** 2) / (2 * h_a1 ** 2)).mean() / (h_a1 * np.sqrt(2 * np.pi)) # density from other samples.
        logs_a1.append(np.log(dens_a1 + 1e-12)) # add tiny floor to avoid log zero.
    scores_a1.append(float(np.mean(logs_a1))) # average held-out log density.
print("LOO scores:", np.round(scores_a1, 3)) # inspect validation criterion.
```
▶ What you'll see: very small bandwidth is penalized because held-out points can be far from narrow bumps.

```python
best_idx_a1 = int(np.argmax(scores_a1)) # choose bandwidth with highest leave-one-out log likelihood.
best_h_a1 = float(hs_a1[best_idx_a1]) # read best bandwidth.
print("best h:", best_h_a1) # inspect selected smoothness.
assert best_h_a1 in hs_a1 # verify the selected value came from the grid.
```
▶ What you'll see: one bandwidth wins under held-out density rather than visual preference.

```python
plt.figure(figsize=(5, 3)) # create validation curve.
plt.plot(hs_a1, scores_a1, marker="o", color="purple") # plot score versus h.
plt.axvline(best_h_a1, color="crimson", linestyle="--", label=f"best h={best_h_a1}") # mark selected h.
plt.title("Advanced 1: bandwidth by held-out log density") # title the plot.
plt.xlabel("bandwidth h") # label x-axis.
plt.ylabel("mean leave-one-out log density") # label criterion.
plt.legend() # show best-h marker.
plt.show() # display the curve.
```
▶ What you'll see: the selected bandwidth balances memorization and oversmoothing.

👀 Takeaway: bandwidth should be tuned with held-out density or domain goals, not just training fit.

### Advanced 2 — Boundary bias on nonnegative data

**Goal.** Show KDE leaking mass below zero for nonnegative data, because symmetric kernels do not know about natural boundaries. We build it in 4 steps.

```python
x_a2 = np.array([0.05, 0.12, 0.2, 0.35, 0.5, 0.9]) # define nonnegative measurements.
grid_a2 = np.linspace(-0.6, 1.4, 401) # include impossible negative region for inspection.
h_a2 = 0.18 # choose bandwidth.
density_a2 = np.exp(-((grid_a2[:, None] - x_a2[None, :]) ** 2) / (2 * h_a2 ** 2)).mean(axis=1) / (h_a2 * np.sqrt(2 * np.pi)) # ordinary KDE.
print("min sample:", x_a2.min()) # inspect boundary location.
```
▶ What you'll see: all observed values are nonnegative.

```python
neg_mass_a2 = np.trapz(density_a2[grid_a2 < 0], grid_a2[grid_a2 < 0]) # integrate estimated mass below zero.
print("estimated mass below 0:", round(float(neg_mass_a2), 3)) # inspect boundary leakage.
assert neg_mass_a2 > 0.05 # verify noticeable mass leaks into impossible region.
```
▶ What you'll see: a nontrivial amount of probability is assigned below the physical boundary.

```python
x_reflect_a2 = np.concatenate([x_a2, -x_a2]) # reflect samples across zero as a simple boundary correction demo.
density_reflect_a2 = 2 * np.exp(-((grid_a2[:, None] - x_reflect_a2[None, :]) ** 2) / (2 * h_a2 ** 2)).mean(axis=1) / (h_a2 * np.sqrt(2 * np.pi)) # reflected KDE doubled on original scale.
print("reflected density at 0:", round(float(density_reflect_a2[np.argmin(np.abs(grid_a2))]), 3)) # inspect corrected boundary height.
```
▶ What you'll see: reflection increases density near zero rather than letting half the bump disappear outside the domain.

```python
plt.figure(figsize=(5, 3)) # create boundary comparison plot.
plt.plot(grid_a2, density_a2, label="ordinary KDE", color="red") # draw ordinary KDE.
plt.plot(grid_a2, density_reflect_a2, label="reflected demo", color="teal") # draw reflected correction demo.
plt.axvline(0, color="black", linestyle="--") # mark boundary.

plt.legend() # show labels.
plt.show() # display the plot.
```
▶ What you'll see: ordinary KDE puts mass left of zero; the reflected demo respects the boundary shape better near zero.

👀 Takeaway: KDE assumptions include the support of the data, so bounded variables may need transformations or boundary corrections.

### Advanced 3 — Two-dimensional KDE on a grid

**Goal.** Estimate density over two features, because KDE generalizes by using multivariate distances and a dimension-aware normalization constant. We build it in 4 steps.

```python
rng_a3 = np.random.default_rng(0) # create reproducible randomness.
X_a3 = np.vstack([rng_a3.normal([-1.0, -1.0], 0.25, size=(20, 2)), rng_a3.normal([1.0, 1.0], 0.3, size=(20, 2))]) # create two 2D clusters.

```
▶ What you'll see: forty two-dimensional samples.

```python
g1_a3 = np.linspace(-2, 2, 80) # x-axis grid.

points_a3 = np.column_stack([xx_a3.ravel(), yy_a3.ravel()]) # flatten grid into query points.
print("query points:", points_a3.shape[0]) # inspect number of density queries.
```
▶ What you'll see: 6,400 two-dimensional query locations.

```python
diff_a3 = points_a3[:, None, :] - X_a3[None, :, :] # query by sample by feature differences.
```

### Advanced 5 — Compare KDE with a Gaussian parametric model

**Goal.** Fit both a single Gaussian and a KDE to multimodal data, because KDE can represent several modes without assuming one bell curve. We build it in 4 steps.
