# 8.18 — POS Tagging & Morphology

POS tagging names each token's syntactic job, while morphology records word-internal clues such as suffix, tense, number, and person. In this lesson, we build a tiny tagger from scratch: first local suffix and emission evidence, then transition scores and Viterbi decoding so context can overturn an ambiguous word.

### 1. Suffix morphology: word shape as a feature

A tagger should not treat every word as an unrelated ID. The ending of a word often carries grammar: `walked` looks past-like, `walking` looks gerund-like, and `brightest` looks adjective-like. We start with a compact integer feature so the model can share evidence across words with the same ending instead of memorizing each spelling.

```python
words_w = ["walk", "walked", "walking", "runner", "brightest"]  # toy word forms.
suffix_codes_w = {"ed": 1, "ing": 2, "er": 3, "est": 4}  # hand-built morphology codes.
features_w = []  # store one integer morphology feature per word.
for word_w in words_w:
    code_w = 0  # 0 means no listed suffix matched.
    for suf_w, value_w in suffix_codes_w.items():
        if word_w.endswith(suf_w):
            code_w = value_w
    features_w.append(code_w)
print(list(zip(words_w, features_w)))
assert features_w[:3] == [0, 1, 2]
```
▶ What you'll see: `walk` has code 0, `walked` has 1, and `walking` has 2, matching the lesson's bare/past/gerund split.

```python
plt.figure(figsize=(5, 3))
plt.bar(words_w, features_w, color="teal")
plt.title("1: suffix morphology feature")
plt.ylabel("suffix code")
plt.xticks(rotation=20)
plt.show()
```
▶ What you'll see: words sharing an ending would share the same bar height, which is exactly the parameter-sharing signal a model can reuse.

*Why it's done this way:* a suffix feature is crude but powerful because it turns character evidence into a numeric input. The math idea is feature sharing: if many `-ed` tokens are verbs, an unseen `blinked` can inherit that evidence even before the model has seen the full word.

### 2. Emission scores: local POS probabilities

A POS emission classifier turns token features into scores for tags such as `NOUN`, `VERB`, and `ADJ`. Scores are not probabilities yet; softmax exponentiates them and divides by their sum so they become positive and add to 1.

```python
tags_w = ["NOUN", "VERB", "ADJ"]
scores_w = np.array([0.2, 2.0, 0.1])  # local evidence for one token, e.g. "walking".
shifted_w = scores_w - np.max(scores_w)  # numerical stability: same probabilities, smaller exponents.
probs_w = np.exp(shifted_w) / np.sum(np.exp(shifted_w))
print("scores:", scores_w)
print("softmax:", np.round(probs_w, 6))
print("best tag:", tags_w[int(np.argmax(probs_w))])
assert np.allclose(np.round(probs_w, 6), [0.125715, 0.760533, 0.113752])
```
▶ What you'll see: the local classifier assigns probability 0.760533 to `VERB`, with a large margin over `NOUN`.

```python
plt.figure(figsize=(4.5, 3))
plt.bar(tags_w, probs_w, color=["gray", "seagreen", "gray"])
plt.ylim(0, 1)
plt.title("2: emission probabilities")
plt.ylabel("p(tag | token)")
plt.show()
```
▶ What you'll see: one tall `VERB` bar, but not probability 1; context can still override it.

*Why it's done this way:* softmax converts arbitrary real-valued evidence into a normalized distribution. Subtracting the maximum does not change the ratios because every exponent is divided by the same constant, but it prevents overflow and keeps the computation inspectable.

### 3. Morphology bundles: more than one grammatical fact

A coarse POS tag can be too little. A verb may also carry tense, number, and person. We represent a morphology bundle as several binary features so downstream grammar-sensitive tasks can use partial information instead of requiring an exact all-or-nothing label.

```python
bundle_names_w = ["Number=Sing", "Tense=Past", "Person=3"]
bundle_w = np.array([1, 1, 0])  # singular and past are active; third-person is inactive.
active_w = [name_w for name_w, val_w in zip(bundle_names_w, bundle_w) if val_w == 1]
print("bundle:", dict(zip(bundle_names_w, bundle_w)))
print("active features:", active_w)
print("active count:", int(bundle_w.sum()))
assert int(bundle_w.sum()) == 2
```
▶ What you'll see: the bundle records two active facts, `Number=Sing` and `Tense=Past`.

```python
plt.figure(figsize=(5, 3))
plt.bar(bundle_names_w, bundle_w, color="darkorange")
plt.ylim(0, 1.2)
plt.title("3: morphology bundle bits")
plt.xticks(rotation=20)
plt.show()
```
▶ What you'll see: bundle features are separate switches, so a prediction can be partly right.

*Why it's done this way:* decomposing morphology into bits changes the loss geometry. A model that predicts POS and tense correctly but misses person should not be treated the same as one that misses everything; feature bundles make partial grammatical competence measurable.

### 4. Transition scores: neighboring tags are not independent

Local emissions classify one token at a time, but grammar is sequential. A determiner is often followed by a noun or adjective, while two determiners in a row are unlikely. We store this context in a transition matrix `A[previous_tag, current_tag]` and add those scores to local emissions.

```python
small_tags_w = ["DET", "NOUN"]
A_small_w = np.array([[0.1, 1.5],
                      [1.0, 0.2]])
print("transition DET→DET:", A_small_w[0, 0])
print("transition DET→NOUN:", A_small_w[0, 1])
print("preference gap:", A_small_w[0, 1] - A_small_w[0, 0])
assert round(float(A_small_w[0, 1] - A_small_w[0, 0]), 1) == 1.4
```
▶ What you'll see: after `DET`, the transition to `NOUN` is 1.4 score points better than another `DET`.

```python
plt.figure(figsize=(4, 3))
plt.imshow(A_small_w, cmap="viridis")
plt.colorbar(label="transition score")
plt.xticks(range(2), small_tags_w)
plt.yticks(range(2), small_tags_w)
plt.title("4: A[previous, current]")
plt.show()
```
▶ What you'll see: the bright cell in the first row says `DET→NOUN` is preferred.

*Why it's done this way:* sequence scoring adds local token evidence and pairwise neighbor evidence: $s(y)=\sum_t e_t(y_t)+\sum_{t>1}A_{y_{t-1},y_t}$. Addition is used because these are log-like scores; products of probabilities become sums after taking logs.

### 5. HMM probabilities from counts

A Hidden Markov Model makes the same sequence idea probabilistic: transitions model $p(y_t\mid y_{t-1})$ and emissions model $p(x_t\mid y_t)$. We estimate both from labeled toy sentences with add-one smoothing so no legal event has probability zero.

```python
train_w = [
    (["the", "dog", "runs"], ["DET", "NOUN", "VERB"]),
    (["a", "cat", "runs"], ["DET", "NOUN", "VERB"]),
    (["the", "bright", "dog"], ["DET", "ADJ", "NOUN"]),
]
hmm_tags_w = ["DET", "ADJ", "NOUN", "VERB"]
vocab_w = sorted({tok_w for sent_w, _ in train_w for tok_w in sent_w})
print("tags:", hmm_tags_w)
print("vocab:", vocab_w)
assert len(vocab_w) == 6
```
▶ What you'll see: a tiny supervised corpus that knows both tokens and tags.

```python
trans_counts_w = defaultdict(Counter)
emit_counts_w = defaultdict(Counter)
start_counts_w = Counter()
for toks_w, ys_w in train_w:
    start_counts_w[ys_w[0]] += 1
    for t_w, y_w in enumerate(ys_w):
        emit_counts_w[y_w][toks_w[t_w]] += 1
        if t_w > 0:
            trans_counts_w[ys_w[t_w - 1]][y_w] += 1
print("start counts:", dict(start_counts_w))
print("DET transitions:", dict(trans_counts_w["DET"]))
print("NOUN emissions:", dict(emit_counts_w["NOUN"]))
```
▶ What you'll see: all training sentences start with `DET`, and `DET` is followed by either `NOUN` or `ADJ`.

```python
alpha_w = 1.0
start_prob_w = np.array([(start_counts_w[tag_w] + alpha_w) / (len(train_w) + alpha_w * len(hmm_tags_w)) for tag_w in hmm_tags_w])
trans_prob_w = np.zeros((len(hmm_tags_w), len(hmm_tags_w)))
for i_w, prev_w in enumerate(hmm_tags_w):
    total_w = sum(trans_counts_w[prev_w].values())
    for j_w, cur_w in enumerate(hmm_tags_w):
        trans_prob_w[i_w, j_w] = (trans_counts_w[prev_w][cur_w] + alpha_w) / (total_w + alpha_w * len(hmm_tags_w))
print("p(start):", np.round(start_prob_w, 3))
print("p(NOUN | DET):", round(float(trans_prob_w[0, 2]), 3))
assert round(float(trans_prob_w[0, 2]), 3) == 0.429
```
▶ What you'll see: smoothing makes `p(NOUN|DET)=0.429`, not 2/3, because unseen transitions also get probability mass.

*Why it's done this way:* HMM parameters are normalized count tables. Smoothing is a mathematical safety valve: without it, one unseen transition would multiply the whole sequence probability by zero, which is too brittle for small or shifted data.

### 6. Viterbi decoding: best tag sequence, not best tag per token

Viterbi is dynamic programming for the best HMM path. At each time and current tag, it stores the best log-score of any path ending there plus a backpointer to the previous tag that achieved it. This avoids enumerating all $K^T$ tag sequences.

```python
sentence_w = ["the", "bright", "dog"]
emit_prob_w = np.zeros((len(hmm_tags_w), len(sentence_w)))
for i_w, tag_w in enumerate(hmm_tags_w):
    total_w = sum(emit_counts_w[tag_w].values())
    for t_w, tok_w in enumerate(sentence_w):
        emit_prob_w[i_w, t_w] = (emit_counts_w[tag_w][tok_w] + alpha_w) / (total_w + alpha_w * (len(vocab_w) + 1))
print("emission table rows=tags, cols=tokens:\n", np.round(emit_prob_w, 3))
assert emit_prob_w.shape == (4, 3)
```
▶ What you'll see: `bright` has strongest learned emission under `ADJ`, but every tag keeps nonzero probability.

```python
log_start_w = np.log(start_prob_w)
log_trans_w = np.log(trans_prob_w)
log_emit_w = np.log(emit_prob_w)
T_w, K_w = len(sentence_w), len(hmm_tags_w)
dp_w = np.full((T_w, K_w), -np.inf)
back_w = np.zeros((T_w, K_w), dtype=int)
dp_w[0] = log_start_w + log_emit_w[:, 0]
for t_w in range(1, T_w):
    for cur_w in range(K_w):
        candidates_w = dp_w[t_w - 1] + log_trans_w[:, cur_w]
        back_w[t_w, cur_w] = int(np.argmax(candidates_w))
        dp_w[t_w, cur_w] = candidates_w[back_w[t_w, cur_w]] + log_emit_w[cur_w, t_w]
print("final log scores:", np.round(dp_w[-1], 3))
print("best final tag:", hmm_tags_w[int(np.argmax(dp_w[-1]))])
```
▶ What you'll see: final scores are log probabilities; less negative means a better complete path.

```python
best_last_w = int(np.argmax(dp_w[-1]))
path_idx_w = [best_last_w]
for t_w in range(T_w - 1, 0, -1):
    path_idx_w.append(int(back_w[t_w, path_idx_w[-1]]))
path_idx_w = path_idx_w[::-1]
path_w = [hmm_tags_w[i_w] for i_w in path_idx_w]
print(list(zip(sentence_w, path_w)))
assert path_w == ["DET", "ADJ", "NOUN"]
plt.figure(figsize=(5, 3))
plt.imshow(dp_w, cmap="magma", aspect="auto")
plt.colorbar(label="best log score")
plt.xticks(range(K_w), hmm_tags_w)
plt.yticks(range(T_w), sentence_w)
plt.title("6: Viterbi dynamic-programming table")
plt.show()
```
▶ What you'll see: the decoded path is `DET ADJ NOUN`, and the heatmap shows the best path score ending at each tag and time.

*Why it's done this way:* Viterbi exploits optimal substructure. The best path ending in tag $k$ at time $t$ must extend the best earlier path ending in some previous tag $j$; storing only those best prefixes reduces decoding from exponential enumeration to $O(TK^2)$.

## 🛠️ Setup

```python
import numpy as np  # arrays, vectorized math, log probabilities, and dynamic programming tables.
import matplotlib.pyplot as plt  # small heatmaps and bar charts for inspecting tagger behavior.
from collections import Counter, defaultdict  # count-based toy estimators for emissions and transitions.
np.random.seed(0)  # keep random demos reproducible.

def softmax(logits):  # convert scores into a probability distribution.
    logits = np.asarray(logits, dtype=float)  # ensure numeric array behavior.
    shifted = logits - np.max(logits)  # stabilize exponentials without changing probabilities.
    exp = np.exp(shifted)  # exponentiate stabilized scores.
    return exp / np.sum(exp)  # normalize so probabilities sum to one.

def suffix_code(word):  # encode a few morphology suffixes as compact integer features.
    codes = {"ed": 1, "ing": 2, "er": 3, "est": 4, "s": 5}  # suffix-to-code lookup.
    for suf, code in codes.items():  # scan known suffixes.
        if word.endswith(suf):  # check whether the word carries this ending.
            return code  # return the first matching code.
    return 0  # no known suffix matched.

def viterbi_decode(tokens, tags, start_log, trans_log, emit_log_table):  # decode the highest-scoring tag path.
    T, K = len(tokens), len(tags)  # sentence length and number of possible tags.
    dp = np.full((T, K), -np.inf)  # best log score for paths ending at each tag.
    back = np.zeros((T, K), dtype=int)  # previous-tag backpointers.
    dp[0] = start_log + emit_log_table[:, 0]  # initialize with start and first-token emission scores.
    for t in range(1, T):  # fill later token positions.
        for cur in range(K):  # choose a current tag.
            candidates = dp[t - 1] + trans_log[:, cur]  # extend every previous tag into the current tag.
            back[t, cur] = int(np.argmax(candidates))  # remember the best previous tag.
            dp[t, cur] = candidates[back[t, cur]] + emit_log_table[cur, t]  # store best score plus current emission.
    last = int(np.argmax(dp[-1]))  # choose the best final tag.
    path = [last]  # start backtracking from the best final tag.
    for t in range(T - 1, 0, -1):  # walk backward through positions.
        path.append(int(back[t, path[-1]]))  # append the previous tag on the best path.
    path = path[::-1]  # reverse into left-to-right order.
    return [tags[i] for i in path], dp, back  # return readable tags plus diagnostic tables.

def show_heatmap(M, title, xlabels=None, ylabels=None):  # small matrix visualization helper.
    plt.figure(figsize=(5, 3))  # compact notebook figure.
    plt.imshow(M, cmap="viridis", aspect="auto")  # draw matrix values as colors.
    plt.colorbar(label="value")  # show numeric color scale.
    if xlabels is not None:  # label columns when names are provided.
        plt.xticks(range(len(xlabels)), xlabels, rotation=20)
    if ylabels is not None:  # label rows when names are provided.
        plt.yticks(range(len(ylabels)), ylabels)
    plt.title(title)  # title the current diagnostic plot.
    plt.show()  # display the plot.
```

### Basic 9 — Apply add-one smoothing

**Goal.** Avoid zero probabilities for unseen words, because a single unknown token should not destroy a whole sequence probability. We build it in 2 steps.

```python
vocab_b9 = ["the", "a", "dog", "UNK"]  # include an unknown-word bucket.
count_dog_b9 = emit_counts_b8["NOUN"]["dog"]  # observed dog-as-noun count.
total_noun_b9 = sum(emit_counts_b8["NOUN"].values())  # total NOUN emissions.
```

### Easy 1 — Train a tiny HMM from counts

**Goal.** Estimate start, transition, and emission probabilities from labeled sentences, because HMM tagging is just normalized supervised counting plus smoothing. We build it in 3 steps.

```python
train_e1 = [(["the", "dog", "runs"], ["DET", "NOUN", "VERB"]), (["a", "cat", "runs"], ["DET", "NOUN", "VERB"]), (["the", "bright", "dog"], ["DET", "ADJ", "NOUN"])]

```
▶ What you'll see: the toy corpus vocabulary plus an unknown-token bucket.

```python

emit_counts_e1 = defaultdict(Counter)

    start_counts_e1[ys_e1[0]] += 1
    for t_e1, y_e1 in enumerate(ys_e1):
        emit_counts_e1[y_e1][toks_e1[t_e1]] += 1
        if t_e1 > 0:
            trans_counts_e1[ys_e1[t_e1 - 1]][y_e1] += 1
```
