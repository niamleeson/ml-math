# 17.8 — Zero-Shot Learning

Zero-shot learning predicts classes that had no training examples by replacing a learned class-specific weight with a class description: attributes, text embeddings, or another semantic vector. In this lesson, you will build that idea from scratch with NumPy: encode inputs and class descriptions into one space, score compatibility with cosine similarity, handle unseen classes, and inspect why calibration matters.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build zero-shot learning one idea at a time. Run each cell in order and read the printed intermediate values — every score is computed from plain arrays, not from a pretrained library. This walkthrough uses a `_w` suffix on variables so it never clashes with the examples below.

```python
import numpy as np  # arrays + linear algebra for embeddings, attributes, and cosine scores.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
np.random.seed(0)  # reproducibility for toy encoders and synthetic points.
```

### 1. Class descriptions become classifier weights

A normal classifier learns one weight vector per class from labeled examples. Zero-shot learning cannot do that for unseen classes, so it uses a **semantic description** instead: a vector of attributes like `[striped, aquatic]` or a text embedding. The class description becomes the object we compare an input to.

```python
classes_w = np.array(["zebra", "dolphin", "tiger"])  # three possible class names.
A_w = np.array([[1.0, 0.0],   # zebra: striped, not aquatic.
                [0.0, 1.0],   # dolphin: aquatic, not striped.
                [0.8, 0.0]])  # tiger: also striped, but weaker in this toy description.
print("class attributes [striped, aquatic]:")
for name_w, attr_w in zip(classes_w, A_w):
    print(name_w, attr_w)
```
▶ What you'll see: every class is represented by a numeric description, even before any examples exist for that class.

```python
plt.figure(figsize=(4.4, 3.4))
plt.scatter(A_w[:, 0], A_w[:, 1], s=110, color=["black", "steelblue", "orange"])
for i_w, name_w in enumerate(classes_w):
    plt.text(A_w[i_w, 0] + 0.03, A_w[i_w, 1] + 0.03, name_w)
plt.xlim(-0.1, 1.15); plt.ylim(-0.1, 1.15)
plt.xlabel("striped attribute"); plt.ylabel("aquatic attribute")
plt.title("1: class descriptions live in semantic space")
plt.show()
```
▶ What you'll see: zebra and tiger sit on the striped axis, while dolphin sits on the aquatic axis.

*Why it's done this way:* the model cannot estimate a separate weight vector for an unseen class from data, so the attribute vector is the weight. This makes the hypothesis test “does this input look like the class description?” rather than “did I see this class during training?”

### 2. Encode an input into the same semantic space

Zero-shot scoring only makes sense if the input vector and class description have the same coordinates. In a large model, an image encoder might output a semantic embedding. Here we build a tiny linear encoder by hand: raw features `[has_stripes_pixels, has_water_context]` are mapped to the same `[striped, aquatic]` attribute space.

```python
x_w = np.array([0.8, 0.2])  # a toy input: strong stripe evidence, weak water evidence.
W_enc_w = np.array([[1.0, 0.0],
                    [0.0, 1.0]])  # identity encoder for the first pass.
z_w = x_w @ W_enc_w  # input embedding f(x) in the semantic attribute space.
print("raw input x:", x_w)
print("encoded f(x):", z_w)
assert np.allclose(z_w, [0.8, 0.2])
```
▶ What you'll see: the input embedding keeps the same two interpretable coordinates.

```python
plt.figure(figsize=(4.4, 3.4))
plt.arrow(0, 0, z_w[0], z_w[1], head_width=0.04, color="crimson", length_includes_head=True)
plt.text(z_w[0] + 0.03, z_w[1], "f(x)")
plt.scatter(A_w[:, 0], A_w[:, 1], s=80, color="gray")
for i_w, name_w in enumerate(classes_w):
    plt.text(A_w[i_w, 0] + 0.03, A_w[i_w, 1] + 0.03, name_w)
plt.xlim(-0.1, 1.15); plt.ylim(-0.1, 1.15)
plt.xlabel("striped"); plt.ylabel("aquatic")
plt.title("2: input and classes share coordinates")
plt.show()
```
▶ What you'll see: the input points near the striped class descriptions, not near the aquatic one.

*Why it's done this way:* comparison requires commensurable coordinates. If the input encoder produced arbitrary pixels while class vectors were attributes, a dot product would multiply unrelated units; alignment is the mathematical bridge that makes transfer possible.

### 3. Compatibility scoring with cosine similarity

The core zero-shot formula is a compatibility score: $s(x,k)=\cos(f(x),a_k)$. Cosine divides by vector lengths, so a class does not win merely because its description has larger magnitude; it wins because it points in the same semantic direction as the input.

```python
def cosine_w(u_w, v_w):
    denom_w = np.linalg.norm(u_w) * np.linalg.norm(v_w)
    return 0.0 if denom_w == 0 else float(np.dot(u_w, v_w) / denom_w)

scores_w = np.array([cosine_w(z_w, a_w) for a_w in A_w])
print("cosine scores:", dict(zip(classes_w, np.round(scores_w, 3))))
assert round(scores_w[0], 3) == 0.970
assert round(scores_w[1], 3) == 0.243
```
▶ What you'll see: zebra scores 0.970 and dolphin scores 0.243, matching the lesson's worked cosine calculation.

```python
plt.figure(figsize=(4.6, 3))
plt.bar(classes_w, scores_w, color=["black", "steelblue", "orange"])
plt.ylim(0, 1.05); plt.ylabel("cos(f(x), a_k)")
plt.title("3: compatibility scores")
plt.show()
```
▶ What you'll see: the striped classes score high because their description direction matches the input embedding.

*Why it's done this way:* cosine implements “same direction” instead of “same size.” The numerator rewards shared attributes; the denominator removes scale, so the score is about semantic alignment rather than description length.

### 4. Scores become probabilities with a temperature scale

A compatibility vector ranks classes, but many systems want probabilities. We multiply scores by a scale and apply softmax. A larger scale makes the largest score more decisive; a smaller scale keeps uncertainty visible.

```python
scale_w = 3.0
logits_w = scale_w * scores_w
exp_w = np.exp(logits_w - np.max(logits_w))
probs_w = exp_w / exp_w.sum()
print("scaled logits:", np.round(logits_w, 3))
print("probabilities:", dict(zip(classes_w, np.round(probs_w, 3))))
assert round(float(np.exp(3 * 0.970) / (np.exp(3 * 0.970) + np.exp(3 * 0.243))), 3) == 0.899
```
▶ What you'll see: with only zebra and dolphin, the top probability would be 0.898; adding tiger splits some striped probability.

```python
scales_w = np.array([0.5, 1.0, 3.0, 8.0])
top_probs_w = []
for sc_w in scales_w:
    lg_w = sc_w * scores_w
    pr_w = np.exp(lg_w - np.max(lg_w)); pr_w = pr_w / pr_w.sum()
    top_probs_w.append(pr_w[0])
print("zebra probability by scale:", np.round(top_probs_w, 3))
plt.figure(figsize=(4.6, 3))
plt.plot(scales_w, top_probs_w, marker="o", color="purple")
plt.xlabel("softmax scale"); plt.ylabel("P(zebra)")
plt.title("4: scale sharpens probabilities")
plt.show()
```
▶ What you'll see: the rank can stay the same while confidence rises as the scale grows.

*Why it's done this way:* softmax exponentiates relative score gaps. The scale is therefore a calibration knob: it does not create semantic evidence, but it controls how strongly score differences are interpreted as probability differences.

### 5. Unseen classes are scored by descriptions, not examples

Now make the split explicit. Suppose zebra and dolphin were seen during training, while tiger was never labeled. A standard two-class classifier could only return the seen labels. A zero-shot model can still score tiger because `a_tiger` exists.

```python
seen_w = np.array([True, True, False])  # tiger is held out as an unseen class.
seen_scores_w = scores_w[seen_w]
seen_pred_w = classes_w[seen_w][np.argmax(seen_scores_w)]
zero_shot_pred_w = classes_w[np.argmax(scores_w)]
print("seen-only prediction:", seen_pred_w)
print("zero-shot prediction over all descriptions:", zero_shot_pred_w)
```
▶ What you'll see: a standard seen-only classifier ignores tiger; zero-shot can include it in the candidate set.

```python
candidate_sets_w = ["seen only", "seen + unseen"]
best_scores_w = [np.max(scores_w[seen_w]), np.max(scores_w)]
plt.figure(figsize=(4.6, 3))
plt.bar(candidate_sets_w, best_scores_w, color=["gray", "seagreen"])
plt.ylabel("best compatibility")
plt.title("5: adding an unseen class changes the choice set")
plt.show()
```
▶ What you'll see: the decision is not limited by the set of labels with examples; it is limited by the set of available descriptions.

*Why it's done this way:* zero-shot learning moves the parameterization from “one learned output node per class” to “one comparable semantic vector per class.” Any new class with a vector can be inserted into the argmax without retraining the final classifier.

### 6. Calibration protects unseen classes from seen-class bias

A common pitfall is that seen classes inherit an advantage: the encoder was tuned on them, so their scores can be systematically higher. Generalized zero-shot learning subtracts or adjusts a seen-class bias so unseen classes are not drowned out merely because they were present during training.

```python
biased_scores_w = scores_w.copy()
biased_scores_w[seen_w] += 0.12  # toy seen-class logit advantage from training.
print("biased scores:", dict(zip(classes_w, np.round(biased_scores_w, 3))))
print("biased winner:", classes_w[np.argmax(biased_scores_w)])
```
▶ What you'll see: adding a small seen-class bonus can make a seen class dominate close unseen alternatives.

```python
gamma_w = 0.12
calibrated_scores_w = biased_scores_w.copy()
calibrated_scores_w[seen_w] -= gamma_w
print("calibrated scores:", dict(zip(classes_w, np.round(calibrated_scores_w, 3))))
print("calibrated winner:", classes_w[np.argmax(calibrated_scores_w)])
assert np.allclose(calibrated_scores_w, scores_w)
plt.figure(figsize=(5, 3))
xpos_w = np.arange(len(classes_w))
plt.bar(xpos_w - 0.18, biased_scores_w, width=0.36, label="biased", color="crimson")
plt.bar(xpos_w + 0.18, calibrated_scores_w, width=0.36, label="calibrated", color="teal")
plt.xticks(xpos_w, classes_w); plt.ylabel("compatibility")
plt.title("6: calibration removes a seen-class bonus")
plt.legend(); plt.show()
```
▶ What you'll see: calibration lowers seen-class scores back onto the same scale as unseen descriptions.

*Why it's done this way:* validation must match the target setting. If the target includes unseen classes, the argmax should compare class descriptions fairly; otherwise a healthy-looking score can simply encode training-set bias.

## 🛠️ Setup

```python
import numpy as np  # Load NumPy for arrays, dot products, cosine scores, and synthetic zero-shot data.
import matplotlib.pyplot as plt  # Load Matplotlib for bars, scatter plots, and heatmaps.
np.random.seed(0)  # Make every toy example reproducible.

def zsl_cosine(u, v):  # Compute cosine similarity for two semantic vectors.
    u = np.asarray(u, dtype=float)  # Convert the first vector to floats.
    v = np.asarray(v, dtype=float)  # Convert the second vector to floats.
    denom = np.linalg.norm(u) * np.linalg.norm(v)  # Compute the product of vector lengths.
    return 0.0 if denom == 0 else float(np.dot(u, v) / denom)  # Return guarded cosine compatibility.

def zsl_scores(x, A):  # Score one input embedding against every class attribute vector.
    return np.array([zsl_cosine(x, a) for a in A])  # Return one cosine score per class.

def zsl_softmax(logits):  # Convert logits to probabilities in a numerically stable way.
    logits = np.asarray(logits, dtype=float)  # Convert to float array for exponentiation.
    exps = np.exp(logits - np.max(logits))  # Subtract the max to avoid overflow.
    return exps / exps.sum()  # Normalize exponentials into probabilities.
```

### Basic 7 — Compare cosine with raw dot product

### Basic 10 — Apply a seen-class calibration offset

**Goal.** Subtract a seen-class bonus, because generalized zero-shot settings compare seen and unseen classes together. We build it in 2 steps.

