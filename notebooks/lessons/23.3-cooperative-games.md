# 23.3 — Cooperative Games

Cooperative game theory studies how a group should divide value when players can form coalitions. In this lesson, you will build the characteristic function $v(S)$, compute Shapley values from marginal contributions, test whether an allocation is stable in the core, and compare Shapley attribution with Banzhaf-style power indices.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build cooperative games one idea at a time. Run each cell in order and read the printed intermediate values — every piece of math, including the Shapley weighting formula, is computed from scratch. This walkthrough is self-contained and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import itertools  # enumerate coalitions and arrival orders exactly.
import math  # factorials for the Shapley weighting formula.
import numpy as np  # arrays and numerical checks.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
np.random.seed(0)  # reproducibility for any randomized displays.

def coalition_key(players):
    return tuple(sorted(players))

def powerset(players):
    players = tuple(players)
    groups = []
    for r in range(len(players) + 1):
        groups.extend(itertools.combinations(players, r))
    return groups

def game_value(v, coalition):
    return float(v.get(coalition_key(coalition), 0.0))

def shapley_values(players, v):
    n = len(players)
    out = {p: 0.0 for p in players}
    for i in players:
        others = [p for p in players if p != i]
        for S in powerset(others):
            weight = math.factorial(len(S)) * math.factorial(n - len(S) - 1) / math.factorial(n)
            out[i] += weight * (game_value(v, S + (i,)) - game_value(v, S))
    return out

def shapley_by_permutations(players, v):
    out = {p: 0.0 for p in players}
    orders = list(itertools.permutations(players))
    for order in orders:
        before = ()
        for p in order:
            out[p] += game_value(v, before + (p,)) - game_value(v, before)
            before = before + (p,)
    return {p: out[p] / len(orders) for p in players}

def banzhaf_counts(players, v, quota=None, weights=None):
    swings = {p: 0 for p in players}
    if quota is not None and weights is not None:
        for p in players:
            others = [q for q in players if q != p]
            for S in powerset(others):
                without = sum(weights[q] for q in S)
                with_p = without + weights[p]
                if without < quota <= with_p:
                    swings[p] += 1
    else:
        for p in players:
            others = [q for q in players if q != p]
            for S in powerset(others):
                if game_value(v, S) == 0 and game_value(v, S + (p,)) > 0:
                    swings[p] += 1
    total = sum(swings.values())
    index = {p: swings[p] / total if total else 0.0 for p in players}
    return swings, index

def core_violations(players, v, alloc):
    bad = []
    for S in powerset(players):
        if len(S) == 0 or len(S) == len(players):
            continue
        assigned = sum(alloc[p] for p in S)
        required = game_value(v, S)
        if assigned + 1e-9 < required:
            bad.append((S, assigned, required))
    return bad
```

### 1. Characteristic functions: value belongs to coalitions

A cooperative game starts with players $N$ and a characteristic function $v:2^N\to\mathbb{R}$ with $v(\emptyset)=0$. The function is the whole evidence table: it says what every possible coalition can produce before we decide how to divide the grand-coalition value. Equal splitting ignores this table; cooperative-game reasoning begins by reading it.

```python
players_w = ("A", "B", "C")
v_w = {(): 0, ("A",): 1, ("B",): 1, ("C",): 0,
       ("A", "B"): 4, ("A", "C"): 2, ("B", "C"): 2,
       ("A", "B", "C"): 6}
coalitions_w = powerset(players_w)
values_w = np.array([game_value(v_w, S) for S in coalitions_w])
labels_w = ["∅" if len(S) == 0 else "".join(S) for S in coalitions_w]
print(list(zip(labels_w, values_w.astype(int))))
assert game_value(v_w, ()) == 0
```
▶ What you'll see: every coalition, from ∅ through ABC, has a specified value.

```python
plt.figure(figsize=(7, 2.8))
plt.imshow(values_w.reshape(1, -1), cmap="viridis", aspect="auto")
plt.colorbar(label="v(S)")
plt.xticks(range(len(labels_w)), labels_w)
plt.yticks([])
plt.title("1: characteristic-function table")
plt.show()
```
▶ What you'll see: AB is worth more than A+B alone, while C alone is worth 0.

*Why it's done this way:* A payoff rule has no meaning until the game specifies what each coalition can make on its own.

### 2. Marginal contribution depends on who arrived before you

A player's contribution is not one fixed number. It is $v(S\cup\{i\})-v(S)$, where $S$ is the coalition already present. In the same game, B adds 3 after A, but B adds 4 after A and C. That dependence is exactly why Shapley averages over many possible formation orders.

```python
player_w = "B"
others_w = [p for p in players_w if p != player_w]
predecessors_w = powerset(others_w)
marginals_w = np.array([game_value(v_w, S + (player_w,)) - game_value(v_w, S) for S in predecessors_w])
pred_labels_w = ["∅" if len(S) == 0 else "".join(S) for S in predecessors_w]
print("B marginal contributions:", list(zip(pred_labels_w, marginals_w)))
assert list(marginals_w) == [1.0, 3.0, 2.0, 4.0]
```
▶ What you'll see: B's marginal contribution changes with the predecessor coalition.

```python
plt.figure(figsize=(5, 3))
plt.bar(pred_labels_w, marginals_w, color="steelblue")
plt.title("2: B's marginal contribution by predecessor set")
plt.xlabel("coalition before B arrives")
plt.ylabel("v(S∪{B}) - v(S)")
plt.show()
```
▶ What you'll see: the tallest bar is when A and C are already present, because B completes the high-value grand coalition.

*Why it's done this way:* Marginal contribution measures the value a player actually unlocks in context, so synergy and redundancy appear automatically.

### 3. Shapley value: average over all arrival orders

The Shapley value is the average marginal contribution over all $n!$ arrival orders. Equivalently,

$$\phi_i=\sum_{S\subseteq N\setminus\{i\}}\frac{|S|!(n-|S|-1)!}{n!}\big(v(S\cup\{i\})-v(S)\big).$$

The factorial weight counts how many permutations have exactly coalition $S$ before player $i$: the players in $S$ can be ordered in $|S|!$ ways, the players after $i$ in $(n-|S|-1)!$ ways, and there are $n!$ total orders.

```python
orders_w = list(itertools.permutations(players_w))
rows_w = []
for order in orders_w:
    before = ()
    row = []
    for p in order:
        row.append(game_value(v_w, before + (p,)) - game_value(v_w, before))
        before = before + (p,)
    rows_w.append(row)
order_marginals_w = np.array(rows_w)
phi_perm_w = shapley_by_permutations(players_w, v_w)
phi_formula_w = shapley_values(players_w, v_w)
print("permutation Shapley:", phi_perm_w)
print("formula Shapley:", phi_formula_w)
assert np.allclose([phi_formula_w[p] for p in players_w], [2.5, 2.5, 1.0])
```
▶ What you'll see: both implementations give A=2.5, B=2.5, C=1.0.

```python
plt.figure(figsize=(5, 3))
plt.bar(players_w, [phi_formula_w[p] for p in players_w], color="darkorange")
plt.axhline(game_value(v_w, players_w) / len(players_w), color="gray", linestyle="--", label="equal split")
plt.title("3: Shapley values from average marginals")
plt.ylabel("credit")
plt.legend()
plt.show()
```
▶ What you'll see: A and B receive more than C because their average marginal contributions are larger.

*Why it's done this way:* Averaging over all arrival orders removes arbitrary bargaining order and turns fairness into a symmetry calculation.

### 4. Efficiency, symmetry, and dummy behavior

Shapley values satisfy efficiency: the credits sum to $v(N)$. They also respect symmetry: A and B receive the same value because the game treats them the same. The dummy axiom says that if a player adds exactly the same amount to every coalition, that player receives exactly that amount — no extra credit for value that would have existed anyway.

```python
players_dummy_w = ("A", "B", "D")
base_values_w = {(): 0, ("A",): 2, ("B",): 2, ("A", "B"): 5}
v_dummy_w = {}
for S in powerset(players_dummy_w):
    without_D = tuple(p for p in S if p != "D")
    v_dummy_w[coalition_key(S)] = game_value(base_values_w, without_D) + (1 if "D" in S else 0)
phi_dummy_w = shapley_values(players_dummy_w, v_dummy_w)
print("dummy-game Shapley:", phi_dummy_w)
print("sum:", sum(phi_dummy_w.values()), "grand value:", game_value(v_dummy_w, players_dummy_w))
assert round(phi_dummy_w["D"], 6) == 1.0
assert abs(sum(phi_dummy_w.values()) - game_value(v_dummy_w, players_dummy_w)) < 1e-9
```
▶ What you'll see: D receives exactly 1 because D always adds exactly 1.

```python
plt.figure(figsize=(5, 3))
plt.bar(players_dummy_w, [phi_dummy_w[p] for p in players_dummy_w], color=["teal", "teal", "crimson"])
plt.title("4: dummy player gets its constant marginal value")
plt.ylabel("Shapley value")
plt.show()
```
▶ What you'll see: D's bar is exactly 1, while A and B split the remaining productive value.

*Why it's done this way:* Efficiency allocates the whole surplus, while the dummy rule prevents attribution from rewarding irrelevant participants.

### 5. The core: stable allocations no coalition wants to block

Fairness and stability are related but different. The core contains allocations $x$ with $\sum_i x_i=v(N)$ and $\sum_{i\in S}x_i\ge v(S)$ for every coalition $S$. If a coalition receives less than it can make alone, that coalition has a blocking objection and the allocation is unstable.

```python
alloc_w = phi_formula_w.copy()
checks_w = []
for S in powerset(players_w):
    if 0 < len(S) < len(players_w):
        checks_w.append(("".join(S), sum(alloc_w[p] for p in S), game_value(v_w, S)))
print("coalition allocation vs value:", checks_w)
viol_w = core_violations(players_w, v_w, alloc_w)
assert len(viol_w) == 0
```
▶ What you'll see: every proper coalition receives at least its standalone value under this Shapley allocation.

```python
lhs_w = np.array([row[1] for row in checks_w])
rhs_w = np.array([row[2] for row in checks_w])
x_w = np.arange(len(checks_w))
plt.figure(figsize=(6, 3))
plt.bar(x_w - 0.18, lhs_w, width=0.36, label="allocated to S", color="seagreen")
plt.bar(x_w + 0.18, rhs_w, width=0.36, label="v(S)", color="gray")
plt.xticks(x_w, [row[0] for row in checks_w])
plt.title("5: core constraints checked coalition by coalition")
plt.ylabel("value")
plt.legend()
plt.show()
```
▶ What you'll see: each green allocation bar is at least as high as the gray requirement bar.

*Why it's done this way:* The core is an equilibrium-style constraint: no coalition should prefer to leave the grand coalition.

### 6. Banzhaf power: pivotal coalitions in voting games

In simple voting games, value is often binary: a coalition either wins or loses. The Banzhaf count asks how often a player is pivotal: without them the coalition loses, with them it wins. This is not the same as Shapley value, but it is another marginal-contribution average used for power analysis.

```python
players_vote_w = ("A", "B", "C")
weights_w = {"A": 2, "B": 1, "C": 1}
quota_w = 3
swings_w, power_w = banzhaf_counts(players_vote_w, {}, quota=quota_w, weights=weights_w)
print("swing counts:", swings_w)
print("normalized Banzhaf:", power_w)
assert swings_w == {"A": 3, "B": 1, "C": 1}
```
▶ What you'll see: A is pivotal more often because A carries two votes in a quota-three game.

```python
plt.figure(figsize=(5, 3))
plt.bar(players_vote_w, [power_w[p] for p in players_vote_w], color="mediumpurple")
plt.title("6: normalized Banzhaf power")
plt.ylabel("share of pivotal swings")
plt.show()
```
▶ What you'll see: A has 60% of the pivotal power, while B and C have 20% each.

*Why it's done this way:* Banzhaf focuses on turning losing coalitions into winning coalitions, which is the relevant marginal event in voting power.

```python
def banzhaf_power(players, quota, weights):

        for S in powerset(others):
            without = sum(weights[q] for q in S)
            with_p = without + weights[p]
            if without < quota <= with_p:
                swings[p] += 1
    total = sum(swings.values())
    return swings, {p: swings[p] / total if total else 0.0 for p in players}
```

#### B6. Compute one player's Shapley value by formula

**Goal.** Sum weighted marginal contributions for player B, because that is the Shapley formula in action. We build it in 3 steps.

#### B8. Verify efficiency

**Goal.** Check that Shapley credits sum to $v(N)$, because the grand-coalition value should be fully allocated. We build it in 2 steps.

```python
players_b8 = ("A", "B", "C")
v_b8 = {(): 0, ("A",): 1, ("B",): 1, ("C",): 0, ("A", "B"): 4, ("A", "C"): 2, ("B", "C"): 2, ("A", "B", "C"): 6}
phi_b8 = shapley_values(players_b8, v_b8)
total_b8 = sum(phi_b8.values())
grand_b8 = game_value(v_b8, players_b8)
print("sum phi:", total_b8, "v(N):", grand_b8)
assert abs(total_b8 - grand_b8) < 1e-9
```

#### A1. Approximate Shapley by random permutations

**Goal.** Estimate Shapley values from sampled arrival orders, because exact enumeration becomes expensive as the number of players grows. We build it in 4 steps.

```python
players_a1 = ("A", "B", "C", "D")
weights_a1 = {"A": 2.0, "B": 2.0, "C": 1.0, "D": 0.5}
def value_a1(S):
    total = sum(weights_a1[p] for p in S)
    return total + 0.4 * (len(S) >= 2) + 0.6 * (("A" in S) and ("B" in S))
v_a1 = {coalition_key(S): value_a1(S) for S in powerset(players_a1)}
exact_a1 = shapley_values(players_a1, v_a1)
print("exact:", exact_a1)
```

```python
rng_a1 = np.random.default_rng(1)
running_a1 = {p: 0.0 for p in players_a1}
errors_a1 = []
for t_a1 in range(1, 401):
    order_a1 = tuple(rng_a1.permutation(players_a1))
    before_a1 = ()
    for p_a1 in order_a1:
        running_a1[p_a1] += game_value(v_a1, before_a1 + (p_a1,)) - game_value(v_a1, before_a1)
        before_a1 = before_a1 + (p_a1,)
    est_a1 = np.array([running_a1[p] / t_a1 for p in players_a1])
    exact_vec_a1 = np.array([exact_a1[p] for p in players_a1])
    errors_a1.append(float(np.linalg.norm(est_a1 - exact_vec_a1)))
print("final estimate:", {p: round(running_a1[p] / 400, 3) for p in players_a1})
```

```python
assert errors_a1[-1] < errors_a1[0]
print("initial error:", round(errors_a1[0], 3), "final error:", round(errors_a1[-1], 3))
```

```python

plt.plot(errors_a1, color="teal")
plt.title("A1: sampled-permutation Shapley error")
plt.xlabel("samples")
plt.ylabel("L2 error vs exact")
plt.show()
```
▶ What you'll see: the approximation error generally shrinks as more random orders are averaged.

👀 Takeaway: sampled permutations trade exactness for scalability while preserving the Shapley logic.
