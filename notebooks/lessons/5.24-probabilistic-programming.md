# 5.24 — Probabilistic Programming

Probabilistic programming (PPL) lets us write the data-generating story directly — random choices, observed evidence, and deterministic calculations — while a separate inference procedure conditions that story on what we saw. In this lesson, every model is tiny enough to inspect: a program trace has a prior probability, observations add likelihood, normalization turns trace scores into a posterior, and simple NumPy samplers approximate the same answers when enumeration is too expensive.

## 📖 Concept walkthrough — build each idea from scratch

Before the worked examples, we build probabilistic programming one idea at a time. Run each cell in order and read the printed intermediate values — every probability is shown before it becomes code. This walkthrough is self-contained (it imports what it needs) and uses a `_w` suffix so it never clashes with the examples below.

```python
import numpy as np  # arrays, probabilities, and tiny samplers.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
np.random.seed(0)  # reproducibility for simulation and sampling.
```

### 1. A probabilistic program is a data-generating story

A probabilistic program describes how hidden causes and visible data are generated. Here the hidden binary variable `z` says which world we are in: `z=0` is common but rarely emits `y=1`, while `z=1` is rarer but often emits `y=1`. Running the program forward draws from the joint distribution $p(z,y)$; it does **not** yet condition on an observed `y`.

```python
p_z_w = np.array([0.7, 0.3])  # prior p(z): z=0 is more common than z=1.
p_y1_given_z_w = np.array([0.1, 0.8])  # likelihood p(y=1|z) for each possible trace.
print("prior p(z):", p_z_w)  # inspect the hidden-choice probabilities.
print("p(y=1 | z):", p_y1_given_z_w)  # inspect how each trace predicts the observation.
assert np.isclose(p_z_w.sum(), 1.0)  # priors must sum to 1.
```
▶ What you'll see: `z=0` has prior mass 0.7, but `z=1` makes `y=1` much more likely.

```python
z_draws_w = np.random.choice([0, 1], size=12, p=p_z_w)  # run the hidden random choice.
y_draws_w = (np.random.rand(12) < p_y1_given_z_w[z_draws_w]).astype(int)  # emit y from the selected likelihood.
print("simulated z:", z_draws_w)  # inspect hidden choices from the prior program.
print("simulated y:", y_draws_w)  # inspect visible observations generated from those choices.
```
▶ What you'll see: most `z` values are 0, but the `y=1` outcomes occur more often when `z=1` appears.

```python
plt.figure(figsize=(4.4, 3))  # make a compact story plot.
plt.bar(["p(z=0)", "p(z=1)"], p_z_w, color="steelblue", label="prior")  # prior bars.
plt.scatter([0, 1], p_y1_given_z_w, color="crimson", s=80, label="p(y=1|z)")  # likelihood markers.
plt.ylim(0, 1); plt.title("1: prior choices and observation model")  # readable probability scale.
plt.ylabel("probability"); plt.legend(); plt.show()  # render the comparison.
```
▶ What you'll see: the likely trace before observing data (`z=0`) is not the trace that best explains `y=1` (`z=1`).

*Why it's done this way:* separating the prior from the likelihood is the core PPL idea. The prior says which executions are plausible before data; the likelihood says how compatible each execution is with the observation. Inference will multiply them because a trace must be both plausible and explanatory.

### 2. Trace semantics: every execution path has a joint score

A PPL backend can treat one execution path as a **trace**: the sampled choices plus a probability score. With one binary latent variable, there are only two traces. Their joint scores for observing `y=1` are $p(z)p(y=1\mid z)$, exactly the prior mass times the likelihood contribution accumulated by the `observe` statement.

```python
trace_names_w = np.array(["z=0", "z=1"])  # names for the two possible traces.
joint_y1_w = p_z_w * p_y1_given_z_w  # unnormalized posterior weights: p(z, y=1).
print("trace joint scores p(z,y=1):", np.round(joint_y1_w, 3))  # [0.07, 0.24].
print("evidence p(y=1):", round(float(joint_y1_w.sum()), 3))  # 0.310.
assert np.allclose(joint_y1_w, [0.07, 0.24])  # worked arithmetic from the lesson.
assert round(float(joint_y1_w.sum()), 3) == 0.310  # evidence check.
```
▶ What you'll see: `z=1` has the larger trace score after seeing `y=1`, even though it had smaller prior mass.

```python
joint_table_w = np.column_stack([p_z_w * (1 - p_y1_given_z_w), joint_y1_w])  # columns y=0 and y=1.
print("joint table rows z, cols y=0/y=1:\n", np.round(joint_table_w, 3))  # inspect full p(z,y).
print("joint table sum:", round(float(joint_table_w.sum()), 3))  # a complete joint distribution sums to 1.
assert np.isclose(joint_table_w.sum(), 1.0)  # p(z,y) is normalized before conditioning.
```
▶ What you'll see: the four joint cells sum to 1; conditioning will slice out the `y=1` column.

```python
plt.figure(figsize=(4.6, 3))  # visualize trace weights for the observed event.
plt.bar(trace_names_w, joint_y1_w, color=["gray", "seagreen"])  # one bar per latent trace.
plt.title("2: trace scores after observe(y=1)")  # label the conditioning event.
plt.ylabel("p(z) × p(y=1|z)"); plt.show()  # render scores.
```
▶ What you'll see: the `z=1` trace bar is 0.24, larger than the 0.07 bar for `z=0`.

*Why it's done this way:* a trace score is local multiplication of probability factors. This is why PPLs can separate model and inference: the model only needs to report scores for executions, and enumeration, sampling, or optimization can consume those scores later.

### 3. Conditioning normalizes trace scores into a posterior

The scores $p(z,y=1)$ are not yet a probability distribution over `z` because they sum to the evidence $p(y=1)=0.31$, not to 1. Conditioning divides each score by that evidence:

$$p(z\mid y=1)=\frac{p(z)p(y=1\mid z)}{\sum_{z'}p(z')p(y=1\mid z')}.$$

```python
evidence_w = joint_y1_w.sum()  # normalizing constant p(y=1).
posterior_w = joint_y1_w / evidence_w  # Bayes rule over traces.
print("posterior p(z | y=1):", np.round(posterior_w, 6))  # [0.225806, 0.774194].
assert round(float(posterior_w[1]), 6) == 0.774194  # 0.24 / 0.31.
assert np.isclose(posterior_w.sum(), 1.0)  # posterior is normalized.
```
▶ What you'll see: after observing `y=1`, the posterior belief in `z=1` jumps to about 0.774.

```python
plt.figure(figsize=(4.6, 3))  # compare before and after conditioning.
x_w = np.arange(2)  # x positions for grouped bars.
plt.bar(x_w - 0.18, p_z_w, width=0.36, label="prior", color="lightgray")  # prior bars.
plt.bar(x_w + 0.18, posterior_w, width=0.36, label="posterior", color="seagreen")  # posterior bars.
plt.xticks(x_w, trace_names_w); plt.ylim(0, 1)  # readable labels.
plt.title("3: conditioning updates belief"); plt.ylabel("probability"); plt.legend(); plt.show()
```
▶ What you'll see: mass moves from `z=0` to `z=1` because `y=1` is much easier to explain under `z=1`.

*Why it's done this way:* normalization is the step that turns relative trace plausibility into usable probabilities. The numerator rewards traces that were likely and fit the observation; the denominator is the total probability of seeing the observation under the whole program.

### 4. Posterior predictive reuses the posterior trace weights

Once we have $p(z\mid y=1)$, we can predict future observations by averaging each trace's data-generating rule under the posterior. For a new binary outcome $y_{new}$, the posterior predictive is $p(y_{new}=1\mid y=1)=\sum_z p(y_{new}=1\mid z)p(z\mid y=1)$.

```python
pred_y1_w = float(np.sum(posterior_w * p_y1_given_z_w))  # average likelihood under posterior trace weights.
prior_pred_y1_w = float(np.sum(p_z_w * p_y1_given_z_w))  # prior predictive before observing y=1.
print("prior predictive p(y=1):", round(prior_pred_y1_w, 3))  # same as evidence for one draw.
print("posterior predictive p(y_new=1 | y=1):", round(pred_y1_w, 3))  # about 0.642.
assert round(pred_y1_w, 3) == 0.642  # 0.225806*0.1 + 0.774194*0.8.
```
▶ What you'll see: after seeing one positive observation, the next positive is predicted as much more likely.

```python
draw_z_post_w = np.random.choice([0, 1], size=2000, p=posterior_w)  # sample traces from posterior.
draw_y_new_w = (np.random.rand(2000) < p_y1_given_z_w[draw_z_post_w]).astype(int)  # simulate future y from each trace.
print("Monte Carlo predictive:", round(float(draw_y_new_w.mean()), 3))  # close to exact 0.642.
assert abs(draw_y_new_w.mean() - pred_y1_w) < 0.04  # simulation should approximate the exact value.
```
▶ What you'll see: Monte Carlo simulation lands near the exact posterior predictive probability.

```python
plt.figure(figsize=(4.6, 3))  # compare predictive probabilities.
plt.bar(["before data", "after y=1"], [prior_pred_y1_w, pred_y1_w], color=["gray", "seagreen"])  # predictive bars.
plt.ylim(0, 1); plt.ylabel("p(next y=1)"); plt.title("4: posterior predictive update"); plt.show()
```
▶ What you'll see: the predictive bar rises because the posterior now favors the high-emission trace.

*Why it's done this way:* posterior prediction is not a new formula bolted onto Bayes; it is the same program averaged over updated trace weights. This is why PPLs feel compositional: learn a posterior over latent choices, then run the generative story forward through those choices.

### 5. A tiny PPL is just sample, observe, and an inference loop

A minimal PPL can be written as a model function plus an inference wrapper. The model declares possible traces and scores; enumeration loops over every trace, accumulates prior and observation likelihood, and normalizes. This is toy-sized, but the interface mirrors real systems: model code is separate from the inference strategy.

```python
def model_score_w(z_w, y_obs_w):  # score one complete trace for a chosen observation.
    prior_w = np.array([0.7, 0.3])[z_w]  # p(z).
    like_y1_w = np.array([0.1, 0.8])[z_w]  # p(y=1|z).
    likelihood_w = like_y1_w if y_obs_w == 1 else (1 - like_y1_w)  # p(y_obs|z).
    return prior_w * likelihood_w  # joint trace score p(z,y_obs).

scores_enum_w = np.array([model_score_w(0, 1), model_score_w(1, 1)])  # enumerate traces for y=1.
print("enumerated scores:", np.round(scores_enum_w, 3))  # should match [0.07, 0.24].
assert np.allclose(scores_enum_w, joint_y1_w)  # same arithmetic as direct table code.
```
▶ What you'll see: the model function returns exactly the trace scores from the hand-built table.

```python
def enumerate_posterior_w(y_obs_w):  # inference backend: enumerate all possible z values.
    scores_w = np.array([model_score_w(0, y_obs_w), model_score_w(1, y_obs_w)])  # trace scores.
    if scores_w.sum() == 0:  # impossible observation under every trace.
        raise ValueError("all traces have zero likelihood")  # inference cannot normalize zero mass.
    return scores_w / scores_w.sum()  # normalized posterior over z.

post_enum_w = enumerate_posterior_w(1)  # condition on y=1.
print("backend posterior:", np.round(post_enum_w, 6))  # inspect normalized answer.
assert np.allclose(post_enum_w, posterior_w)  # enumeration reproduces Bayes exactly.
```
▶ What you'll see: the inference wrapper returns `[0.225806, 0.774194]` without changing the model.

*Why it's done this way:* PPL design pays off when the same model can be paired with different backends. Enumeration is exact for tiny discrete spaces; for larger spaces, the backend can switch to sampling while the model still exposes trace scores.

### 6. Sampling approximates posterior trace weights when enumeration is too large

Enumeration sums over every latent assignment, which grows exponentially when a program has many random choices. A simple alternative is importance sampling from the prior: draw traces from $p(z)$, weight each by $p(y=1\mid z)$, and normalize. This approximates the posterior because high-likelihood traces receive more weight after they are sampled.

```python
n_is_w = 5000  # number of prior traces to draw.
z_is_w = np.random.choice([0, 1], size=n_is_w, p=p_z_w)  # proposal q(z)=p(z).
weights_is_w = p_y1_given_z_w[z_is_w]  # importance weight p(y=1|z) because proposal is the prior.
post1_is_w = float(weights_is_w[z_is_w == 1].sum() / weights_is_w.sum())  # weighted fraction for z=1.
print("importance posterior p(z=1|y=1):", round(post1_is_w, 3))  # close to exact 0.774.
assert abs(post1_is_w - posterior_w[1]) < 0.04  # finite-sample approximation check.
```
▶ What you'll see: the weighted sample estimate is close to the exact posterior but not identical.

```python
cum_est_w = np.cumsum(weights_is_w * (z_is_w == 1)) / np.cumsum(weights_is_w)  # running posterior estimate.
plt.figure(figsize=(5, 3))  # convergence diagnostic.
plt.plot(cum_est_w, color="steelblue", linewidth=1)  # running weighted estimate.
plt.axhline(posterior_w[1], color="crimson", linestyle="--", label="exact")  # exact posterior reference.
plt.title("6: importance sampling approaches exact conditioning")  # explain plot.
plt.xlabel("number of traces"); plt.ylabel("p(z=1 | y=1)"); plt.legend(); plt.show()
```
▶ What you'll see: the running estimate wiggles early, then settles near the exact posterior line.

*Why it's done this way:* sampling trades exactness for scalability. The weighted average is mathematically the same Bayes numerator/denominator, but the sums are estimated from random traces instead of exhaustive enumeration.

### 7. Conditioning can fail when every trace has zero likelihood

A common PPL failure mode is observing something impossible under the model. If every trace assigns likelihood 0, the evidence is 0 and Bayes' denominator cannot normalize anything. Good PPL code should reveal that collapse instead of silently returning nonsense.

```python
p_y2_given_z_w = np.array([0.0, 0.0])  # impossible observation y=2 under both traces.
zero_scores_w = p_z_w * p_y2_given_z_w  # joint trace scores for impossible evidence.
print("impossible trace scores:", zero_scores_w)  # all zero.
print("evidence:", float(zero_scores_w.sum()))  # zero denominator.
assert zero_scores_w.sum() == 0.0  # no posterior can be formed.
```
▶ What you'll see: every trace receives score 0, so the evidence is exactly 0.

```python
plt.figure(figsize=(4.4, 3))  # visualize inference collapse.
plt.bar(trace_names_w, zero_scores_w, color="crimson")  # all bars at zero.
plt.ylim(0, 0.05); plt.title("7: zero-likelihood conditioning collapses")  # zoom near zero.
plt.ylabel("trace score"); plt.show()
```
▶ What you'll see: no trace remains alive after the impossible observation.

*Why it's done this way:* the denominator in Bayes' rule is not a technicality; it is the model's total probability for the evidence. If that number is zero, the model says the data cannot happen, so inference must stop or the model must be revised.

### ✍️ Toy 1 · A program samples hidden causes and data

A probabilistic program first samples hidden choices, then samples visible data conditional on those
choices. This is forward simulation, before conditioning on observations.

```python
import numpy as np                              # arrays + checks (safe to repeat).
import matplotlib.pyplot as plt                 # one picture per toy.

t1_rng = np.random.default_rng(0)               # seeded simulator.
t1_prior = np.array([0.6, 0.4])                 # p(z=0), p(z=1)
print("prior p(z):", t1_prior.tolist())         # -> [0.6, 0.4]
t1_p_y1 = np.array([0.2, 0.75])                 # emission probabilities
print("p(y=1 | z):", t1_p_y1.tolist())          # -> [0.2, 0.75]
t1_z = t1_rng.choice([0, 1], size=8, p=t1_prior)  # 8 hidden traces            # -> [1 0 0 0 1 1 1 1]
print("sampled z:", t1_z.tolist())              # -> [1, 0, 0, 0, 1, 1, 1, 1]
t1_u = t1_rng.random(8)                         # uniforms for emission        # -> [0.544 0.935 0.816 0.003 0.857 0.034 0.73  0.176]
print("emission uniforms:", np.round(t1_u, 3).tolist())  # -> [0.544, 0.935, 0.816, 0.003, 0.857, 0.034, 0.73, 0.176]
t1_y = (t1_u < t1_p_y1[t1_z]).astype(int)       # observed y draws             # -> [1 0 0 1 0 1 1 1]
print("sampled y:", t1_y.tolist())              # -> [1, 0, 0, 1, 0, 1, 1, 1]
t1_positive = int(t1_y.sum())                   # count visible positives      # -> 5
print("number of y=1:", t1_positive)            # -> 5
assert t1_positive == 5 and t1_z.size == 8      # seeded forward simulation result

plt.figure(figsize=(4.8, 2.8))
plt.bar(["p(z=0)", "p(z=1)"], t1_prior, color="#4c78a8", label="prior")
plt.scatter([0, 1], t1_p_y1, color="crimson", s=80, label="p(y=1|z)")
plt.ylim(0, 1)
plt.ylabel("probability")
plt.legend()
plt.title("Toy 1 · random choices then emissions")
plt.show()
```
▶ What you'll see: the visible `y` values are generated from the emission probabilities selected by the sampled `z` values.

### ✍️ Toy 2 · Trace scores multiply prior and likelihood

For an observed event, each trace receives an unnormalized score equal to prior mass times likelihood.

```python
import numpy as np                              # arrays + checks (safe to repeat).

t2_rng = np.random.default_rng(0)               # seeded generator for reproducibility.
t2_prior = np.array([0.8, 0.2])                 # prior over two traces
print("prior:", t2_prior.tolist())              # -> [0.8, 0.2]
t2_like_y1 = np.array([0.1, 0.9])               # likelihood of observing y=1
print("likelihood p(y=1|z):", t2_like_y1.tolist())  # -> [0.1, 0.9]
t2_joint = t2_prior * t2_like_y1                # trace scores p(z,y=1)        # -> [0.08 0.18]
print("trace scores:", np.round(t2_joint, 3).tolist())  # -> [0.08, 0.18]
t2_evidence = t2_joint.sum()                    # total probability of y=1     # -> 0.26
print("evidence:", round(float(t2_evidence), 3))  # -> 0.26
assert np.allclose(t2_joint, [0.08, 0.18]) and round(float(t2_evidence), 3) == 0.26

plt.figure(figsize=(4.4, 2.8))
plt.bar(["z=0", "z=1"], t2_joint, color=["#bab0ac", "#54a24b"])
plt.ylabel("p(z) p(y=1|z)")
plt.title("Toy 2 · observed trace scores")
plt.show()
```
▶ What you'll see: the lower-prior trace `z=1` wins because it explains `y=1` much better.

### ✍️ Toy 3 · Conditioning normalizes trace scores

Conditioning divides trace scores by their sum, turning relative support into posterior probabilities.

```python
import numpy as np                              # arrays + checks (safe to repeat).

t3_rng = np.random.default_rng(0)               # seeded generator for reproducibility.
t3_prior = np.array([0.8, 0.2])                 # prior over traces
print("prior:", t3_prior.tolist())              # -> [0.8, 0.2]
t3_like_y1 = np.array([0.1, 0.9])               # observation likelihood
print("likelihood:", t3_like_y1.tolist())       # -> [0.1, 0.9]
t3_scores = t3_prior * t3_like_y1               # unnormalized posterior scores # -> [0.08 0.18]
print("scores:", np.round(t3_scores, 3).tolist())  # -> [0.08, 0.18]
t3_evidence = t3_scores.sum()                   # normalizer                   # -> 0.26
print("evidence:", round(float(t3_evidence), 3))  # -> 0.26
t3_posterior = t3_scores / t3_evidence          # posterior p(z|y=1)           # -> [0.307692 0.692308]
print("posterior:", np.round(t3_posterior, 6).tolist())  # -> [0.307692, 0.692308]
assert np.isclose(t3_posterior.sum(), 1.0) and round(float(t3_posterior[1]), 6) == 0.692308

plt.figure(figsize=(4.8, 2.8))
t3_x = np.arange(2)
plt.bar(t3_x - 0.18, t3_prior, width=0.36, label="prior", color="#bab0ac")
plt.bar(t3_x + 0.18, t3_posterior, width=0.36, label="posterior", color="#54a24b")
plt.xticks(t3_x, ["z=0", "z=1"])
plt.ylim(0, 1)
plt.ylabel("probability")
plt.legend()

plt.show()
```
▶ What you'll see: the posterior shifts mass toward `z=1` after the observed `y=1`.

### ✍️ Toy 4 · Posterior predictive averages traces

```python
import numpy as np                              # arrays + checks (safe to repeat).
```

### ✍️ Toy 5 · Enumeration is a tiny inference backend

A toy PPL backend can enumerate each possible trace, call a model-scoring function, and normalize the
scores.

```python
import numpy as np                              # arrays + checks (safe to repeat).

t5_rng = np.random.default_rng(0)               # seeded generator for reproducibility.
t5_prior = np.array([0.65, 0.35])               # model prior
print("prior:", t5_prior.tolist())              # -> [0.65, 0.35]
t5_like_y1 = np.array([0.2, 0.7])               # model likelihood for y=1
print("likelihood y=1:", t5_like_y1.tolist())   # -> [0.2, 0.7]
def t5_score(z, y_obs):                         # score one trace for one observation.
    t5_likelihood = t5_like_y1[z] if y_obs == 1 else 1 - t5_like_y1[z]
    return t5_prior[z] * t5_likelihood

t5_scores = np.array([t5_score(0, 1), t5_score(1, 1)])  # enumerate two traces # -> [0.13  0.245]
print("enumerated scores:", np.round(t5_scores, 3).tolist())  # -> [0.13, 0.245]
t5_evidence = float(t5_scores.sum())            # normalizing constant          # -> 0.375
print("evidence:", round(t5_evidence, 3))       # -> 0.375
t5_posterior = t5_scores / t5_evidence          # backend posterior             # -> [0.346667 0.653333]
print("posterior:", np.round(t5_posterior, 6).tolist())  # -> [0.346667, 0.653333]
assert np.allclose(np.round(t5_posterior, 6), [0.346667, 0.653333])  # exact enumeration result

plt.figure(figsize=(4.4, 2.8))
plt.bar(["z=0", "z=1"], t5_posterior, color="#4c78a8")
plt.ylim(0, 1)
plt.ylabel("posterior probability")
plt.title("Toy 5 · enumerate traces then normalize")
plt.show()
```
▶ What you'll see: a few lines of enumeration reproduce Bayes' rule for the two possible traces.

### ✍️ Toy 6 · Importance sampling weights prior traces

When enumeration is too large, sample traces from the prior and weight each sample by how well it
explains the observation.

```python
import numpy as np                              # arrays + checks (safe to repeat).

t6_rng = np.random.default_rng(0)               # seeded importance sampler.
```

### Easy 3 — Implement a tiny enumeration backend

**Goal.** Write a reusable enumeration function, because a PPL backend should take a model score function and return normalized trace probabilities. We build it in 3 steps.

```python
def score_trace_e3(z_e3, y_obs_e3):  # model score for one trace and one observation.
```

### Advanced 2 — Metropolis sampling over traces

**Goal.** Implement a tiny Metropolis sampler, because MCMC draws posterior traces using only unnormalized scores. We build it in 4 steps.

```python
prior_a2 = np.array([0.7, 0.3])  # p(z).
like_a2 = np.array([0.1, 0.8])  # p(y=1|z).
def score_a2(z_a2):  # unnormalized posterior score.
    return prior_a2[z_a2] * like_a2[z_a2]  # p(z,y=1).
print("scores:", [score_a2(0), score_a2(1)])  # inspect target density up to a constant.
assert np.allclose([score_a2(0), score_a2(1)], [0.07, 0.24])  # score check.
```
▶ What you'll see: the sampler only needs the two unnormalized target scores.

```python
chain_a2 = np.zeros(3000, dtype=int)  # storage for z samples.
z_cur_a2 = 0  # start at trace z=0.
accept_a2 = 0  # count accepted flips.
for t_a2 in range(chain_a2.size):  # run a simple flip proposal chain.
    z_prop_a2 = 1 - z_cur_a2  # propose the other binary trace.
    ratio_a2 = score_a2(z_prop_a2) / score_a2(z_cur_a2)  # target ratio because proposal is symmetric.
    if np.random.rand() < min(1.0, ratio_a2):  # accept/reject step.
        z_cur_a2 = z_prop_a2  # move to proposal.
        accept_a2 += 1  # record acceptance.
    chain_a2[t_a2] = z_cur_a2  # store current trace.
print("acceptance rate:", round(accept_a2 / chain_a2.size, 3))  # inspect mixing.
```

```python
burn_a2 = 300  # discard early transient samples.
post1_a2 = float(np.mean(chain_a2[burn_a2:] == 1))  # empirical posterior mass for z=1.
print("MCMC p(z=1|y=1):", round(post1_a2, 3))  # close to exact 0.774.
assert abs(post1_a2 - 0.774194) < 0.05  # MCMC approximation check.
```

```python
running_a2 = np.cumsum(chain_a2 == 1) / (np.arange(chain_a2.size) + 1)  # running mean of z=1.
plt.figure(figsize=(5, 3))  # create trace diagnostic plot.
plt.plot(running_a2, color="purple", linewidth=1)  # running posterior estimate.
plt.axhline(0.774194, color="crimson", linestyle="--", label="exact")  # reference.
plt.title("Advanced 2: Metropolis posterior estimate"); plt.xlabel("iteration"); plt.ylabel("running p(z=1)"); plt.legend(); plt.show()
```
▶ What you'll see: the MCMC running average approaches the exact posterior after burn-in.

👀 Takeaway: MCMC uses score ratios, so it can sample from posteriors without computing the evidence upfront.

### Advanced 5 — Show how posterior geometry affects sampling

**Goal.** Compare a narrow and a wide posterior for the same random-walk sampler, because bad geometry makes generic inference mix slowly. We build it in 4 steps.

```python
def log_normal_score_a5(x_a5, sigma_a5):  # unnormalized log density for N(0, sigma^2).
    return -0.5 * (x_a5 / sigma_a5) ** 2  # constant omitted because MCMC only needs ratios.

def rw_chain_a5(sigma_a5, step_a5, n_a5=2500):  # random-walk Metropolis for one Gaussian target.
    x_a5 = 0.0  # start at the mode.
    chain_a5 = np.zeros(n_a5)  # storage.
    acc_a5 = 0  # acceptance counter.
    for t_a5 in range(n_a5):  # iterate proposals.
        prop_a5 = x_a5 + step_a5 * np.random.randn()  # local random-walk proposal.
        log_ratio_a5 = log_normal_score_a5(prop_a5, sigma_a5) - log_normal_score_a5(x_a5, sigma_a5)  # target ratio in log space.
        if np.log(np.random.rand()) < min(0.0, log_ratio_a5):  # accept or reject.
            x_a5 = prop_a5  # move to proposal.
            acc_a5 += 1  # count acceptance.
        chain_a5[t_a5] = x_a5  # store state.
    return chain_a5, acc_a5 / n_a5  # samples and acceptance rate.
print("sampler defined")  # confirm helper exists.
```
▶ What you'll see: a tiny random-walk sampler that uses only unnormalized log scores.

```python
wide_a5, acc_wide_a5 = rw_chain_a5(sigma_a5=1.0, step_a5=0.6)  # well-scaled target.
narrow_a5, acc_narrow_a5 = rw_chain_a5(sigma_a5=0.08, step_a5=0.6)  # same step on narrow target.
print("accept wide:", round(acc_wide_a5, 3), "accept narrow:", round(acc_narrow_a5, 3))  # compare acceptance.
assert acc_wide_a5 > acc_narrow_a5  # narrow geometry rejects more with same step.
```

```python

sd_narrow_a5 = float(np.std(narrow_a5[500:]))  # posterior spread sampled for narrow target.
print("sample sd wide:", round(sd_wide_a5, 3), "sample sd narrow:", round(sd_narrow_a5, 3))  # inspect geometry.

```

