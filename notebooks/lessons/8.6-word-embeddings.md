### 1. Context windows create co-occurrence evidence

Embeddings begin with the distributional idea: a word is partly defined by the company it keeps. A **context window** turns a token sequence into center-context pairs. A narrow window mostly captures local substitution and syntax; a wider window captures broader topic. The design choice matters because the geometry can only reflect the neighborhoods we count.

```python
sentences_w = ["king man royal", "queen woman royal", "king prince man", "queen princess woman"]  # tiny inline corpus.
tokens_w = [s.split() for s in sentences_w]  # tokenize by spaces for a controlled toy example.
vocab_w = sorted({tok for sent in tokens_w for tok in sent})  # fixed vocabulary order for matrices.
idx_w = {w: i for i, w in enumerate(vocab_w)}  # word -> row/column index.
print("vocab:", vocab_w)  # inspect the coordinate system.
print("sentences:", tokens_w)  # inspect the evidence source.
```
▶ What you'll see: a seven-word vocabulary and four short sentences where royalty and gender words appear in patterned neighborhoods.

```python
def cooc_matrix_w(tokens, window):  # count center-context pairs inside a symmetric window.
    C = np.zeros((len(vocab_w), len(vocab_w)), dtype=float)  # rows=center words, columns=context words.
    for sent in tokens:  # scan each sentence independently.
        for pos, word in enumerate(sent):  # choose each center word.
            lo, hi = max(0, pos - window), min(len(sent), pos + window + 1)  # local context bounds.
            for j in range(lo, hi):  # visit nearby positions.
                if j != pos:  # skip the center word itself.
                    C[idx_w[word], idx_w[sent[j]]] += 1  # add one directed co-occurrence.
    return C  # return the count matrix.

C1_w = cooc_matrix_w(tokens_w, window=1)  # narrow local context.
C2_w = cooc_matrix_w(tokens_w, window=2)  # wider topical context.
print("window=1 count king→man:", C1_w[idx_w["king"], idx_w["man"]])  # direct neighbor evidence.
print("window=2 count king→royal:", C2_w[idx_w["king"], idx_w["royal"]])  # wider window reaches farther.
assert C1_w[idx_w["king"], idx_w["man"]] == 1.0  # concrete local count.
assert C2_w[idx_w["king"], idx_w["royal"]] == 1.0  # concrete wide-window count.
```
▶ What you'll see: the same corpus gives different counts when the context rule changes.

```python
plt.figure(figsize=(5, 4))  # compact heatmap of co-occurrence evidence.
plt.imshow(C2_w, cmap="viridis", aspect="auto")  # color shows how often each context appears.
plt.xticks(range(len(vocab_w)), vocab_w, rotation=45, ha="right")  # label context words.
plt.yticks(range(len(vocab_w)), vocab_w)  # label center words.
plt.colorbar(label="count")  # translate colors back to counts.
plt.title("1: co-occurrence counts with window=2"); plt.show()  # render the matrix.
```
▶ What you'll see: rows for related words light up in similar columns, which is the raw material embeddings compress.

*Why it's done this way:* A one-hot vector says only “which word is this?”; the co-occurrence row says “which contexts does this word predict?” Mathematically, each row is an empirical neighborhood distribution. If two rows have similar nonzero columns, any later compression has a reason to put those words near each other.

### 2. PPMI keeps surprising pairs, not merely frequent pairs

Raw counts over-reward common words. **Pointwise mutual information** compares an observed count to the count expected under independence: $$\operatorname{PMI}(w,c)=\log\frac{C_{wc}N}{C_{w\cdot}C_{\cdot c}}.$$ **PPMI** clips negative PMI to zero, preserving positive surprise while discarding below-chance associations.

```python
words4_w = ["king", "queen", "man", "woman"]  # controlled lesson vocabulary.
Ctoy_w = np.array([[0., 0., 5., 5.],  # king has two contexts, including man.
                   [0., 0., 5., 5.],  # queen has the same row total.
                   [5., 5., 0., 0.],  # man contexts.
                   [5., 5., 0., 0.]]) # woman contexts.
row_w = Ctoy_w.sum(axis=1)  # center-word totals.
col_w = Ctoy_w.sum(axis=0)  # context-word totals.
N_w = Ctoy_w.sum()  # total co-occurrence events.
print("row sums:", row_w, "total:", N_w)  # inspect the denominators.
assert row_w[idx_w.get("king", 0)] if False else N_w == 40.0  # concrete total from the lesson block.
```
▶ What you'll see: every row sums to 10 and the corpus total is 40.

```python
def ppmi_w(C):  # compute positive PMI with safe divide-by-zero handling.
    total = C.sum()  # N in the PMI formula.
    rows = C.sum(axis=1, keepdims=True)  # C_w·.
    cols = C.sum(axis=0, keepdims=True)  # C_·c.
    expected = rows @ cols / total  # independence expectation for each pair.
    with np.errstate(divide="ignore", invalid="ignore"):  # zero counts have undefined log ratios.
        pmi = np.log((C * total) / (rows @ cols))  # log observed/expected.
    return np.maximum(np.nan_to_num(pmi, neginf=0.0, posinf=0.0), 0.0)  # clip to PPMI.

PPMI_w = ppmi_w(Ctoy_w)  # weighted count matrix.
king_man_w = PPMI_w[0, 2]  # PPMI(king, man).
print("PPMI(king, man):", round(king_man_w, 3))  # log((5*40)/(10*10)).
assert round(king_man_w, 3) == 0.693  # log 2, from the source lesson.
```
▶ What you'll see: a raw count of 5 becomes 0.693 because it is twice the independence expectation.

```python
plt.figure(figsize=(4.5, 3.5))  # compare the weighted matrix visually.
plt.imshow(PPMI_w, cmap="magma", aspect="auto")  # bright = surprising positive association.
plt.xticks(range(4), words4_w); plt.yticks(range(4), words4_w)  # readable labels.
plt.colorbar(label="PPMI")  # weighted association scale.
plt.title("2: PPMI keeps positive surprise"); plt.show()  # render the matrix.
```
▶ What you'll see: only above-chance associations remain bright; zero or negative evidence is clipped away.

*Why it's done this way:* PMI divides the observed joint frequency by what independence predicts. The log makes “twice expected” become a clean additive value, `log(2)=0.693`. Clipping to PPMI makes a sparse nonnegative matrix that emphasizes informative associations and is easier to factor or visualize.

### 3. Skip-gram Word2Vec learns vectors by predicting context

Skip-gram Word2Vec gives each center word an input vector $v_w$ and each context word an output vector $u_c$. The probability of context $c$ is a softmax over dot products: $$P(c\mid w)=\frac{\exp(u_c^\top v_w)}{\sum_j\exp(u_j^\top v_w)}.$$ Training increases the dot product for observed pairs and decreases competing context scores through the softmax gradient.

```python
pairs_w = []  # observed skip-gram pairs from the toy corpus.
for sent in tokens_w:  # scan corpus.
    for pos, word in enumerate(sent):  # center position.
        for j in range(max(0, pos - 1), min(len(sent), pos + 2)):  # window size 1.
            if j != pos:  # exclude self.
                pairs_w.append((idx_w[word], idx_w[sent[j]]))  # store integer pair.
print("first 6 pairs:", [(vocab_w[a], vocab_w[b]) for a, b in pairs_w[:6]])  # inspect training data.
print("number of pairs:", len(pairs_w))  # small enough for full softmax.
assert len(pairs_w) == 16  # four 3-token sentences create 4 directed adjacent pairs each.
```
▶ What you'll see: center words such as `king` are paired with their immediate neighbors.

```python
rng_w = np.random.default_rng(0)  # local reproducible generator.
V_w, d_w = len(vocab_w), 2  # tiny vocabulary and two-dimensional embeddings for plotting.
Vin_w = 0.1 * rng_w.normal(size=(V_w, d_w))  # input vectors v_w.
Uout_w = 0.1 * rng_w.normal(size=(V_w, d_w))  # output vectors u_c.
center_w, context_w = pairs_w[0]  # choose one observed pair.
scores_w = Uout_w @ Vin_w[center_w]  # all context logits u_j^T v_w.
probs_w = np.exp(scores_w - scores_w.max()); probs_w = probs_w / probs_w.sum()  # stable softmax.
print("pair:", vocab_w[center_w], "→", vocab_w[context_w])  # chosen training example.
print("probability sums to:", round(float(probs_w.sum()), 6))  # softmax check.
assert round(float(probs_w.sum()), 6) == 1.0  # probabilities must normalize.
```
▶ What you'll see: every possible context gets a probability and the probabilities sum to 1.

```python
loss0_w = -np.log(probs_w[context_w])  # negative log-likelihood for the observed context.
y_w = np.zeros(V_w); y_w[context_w] = 1.0  # one-hot target context.
grad_scores_w = probs_w - y_w  # softmax-cross-entropy gradient.
grad_v_w = Uout_w.T @ grad_scores_w  # derivative with respect to the center vector.
grad_U_w = grad_scores_w[:, None] * Vin_w[center_w][None, :]  # derivative for every output vector.
Vin_w[center_w] -= 0.5 * grad_v_w  # one SGD step on v_w.
Uout_w -= 0.5 * grad_U_w  # one SGD step on all output vectors.
probs_after_w = np.exp((Uout_w @ Vin_w[center_w]) - (Uout_w @ Vin_w[center_w]).max()); probs_after_w /= probs_after_w.sum()  # recompute.
loss1_w = -np.log(probs_after_w[context_w])  # new loss.
print("loss before→after:", round(float(loss0_w), 3), "→", round(float(loss1_w), 3))  # inspect improvement.
assert loss1_w < loss0_w  # one step should make this observed context more likely.
```
▶ What you'll see: the negative log-likelihood drops after one gradient step on the observed pair.

```python
plt.figure(figsize=(5, 4))  # inspect the current input embedding table.
plt.scatter(Vin_w[:, 0], Vin_w[:, 1], s=85, color="teal")  # plot every learned center vector.
for word_w, vec_w in zip(vocab_w, Vin_w): plt.text(vec_w[0] + 0.01, vec_w[1] + 0.01, word_w)  # label words.
plt.scatter(Vin_w[center_w, 0], Vin_w[center_w, 1], s=160, facecolors="none", edgecolors="red", linewidths=2)  # mark updated center.
plt.axhline(0, color="gray", linewidth=0.5); plt.axvline(0, color="gray", linewidth=0.5)  # coordinate axes.
plt.title("3: skip-gram input vectors after one update"); plt.show()  # render the tiny embedding space.
```
▶ What you'll see: the updated center word is circled inside the same 2-D space that later training would reshape.

*Why it's done this way:* Softmax turns dot products into a normalized prediction problem. The gradient `probs - one_hot` has a clear meaning: predicted contexts that were too probable get pushed down, and the true context gets pulled up. Repeating this over many windows makes words with similar predictive jobs learn similar vectors.

### 4. GloVe factorizes global co-occurrence structure

GloVe starts from global counts instead of local prediction steps. Its target is approximately $$v_w^\top u_c + b_w + b_c \approx \log C_{wc},$$ with a weight that downplays extremely rare or extremely common pairs. It is still chasing geometry: dot products should explain log co-occurrence ratios.

```python
C_glove_w = C2_w.copy()  # use the wider co-occurrence matrix as global evidence.
obs_glove_w = np.argwhere(C_glove_w > 0)  # only positive counts have log targets.
rng_g_w = np.random.default_rng(1)  # reproducible GloVe initialization.
W_g_w = 0.05 * rng_g_w.normal(size=(V_w, 2))  # word vectors.
U_g_w = 0.05 * rng_g_w.normal(size=(V_w, 2))  # context vectors.
bw_g_w = np.zeros(V_w); bc_g_w = np.zeros(V_w)  # biases.
print("positive co-occurrence cells:", len(obs_glove_w))  # inspect training size.
```
▶ What you'll see: GloVe trains only on cells with observed positive counts in this toy setup.

```python
def glove_loss_w(W, U, bw, bc):  # weighted squared error over positive counts.
    total_loss = 0.0  # accumulator.
    for i, j in obs_glove_w:  # each positive co-occurrence.
        x = C_glove_w[i, j]  # observed count.
        weight = min((x / 2.0) ** 0.75, 1.0)  # simple GloVe-style weighting.
        err = W[i] @ U[j] + bw[i] + bc[j] - np.log(x)  # prediction minus log-count.
        total_loss += 0.5 * weight * err ** 2  # weighted squared loss.
    return float(total_loss)  # numeric summary.

loss_start_g_w = glove_loss_w(W_g_w, U_g_w, bw_g_w, bc_g_w)  # initial objective.
print("initial GloVe loss:", round(loss_start_g_w, 3))  # inspect starting error.
```
▶ What you'll see: random vectors do not yet explain the log-count matrix.

```python
for epoch_g_w in range(120):  # many tiny passes over positive co-occurrences.
    for i, j in obs_glove_w:  # update one count cell at a time.
        x = C_glove_w[i, j]  # count.
        weight = min((x / 2.0) ** 0.75, 1.0)  # downweight low counts.
        err = W_g_w[i] @ U_g_w[j] + bw_g_w[i] + bc_g_w[j] - np.log(x)  # residual.
        old_w = W_g_w[i].copy(); old_u = U_g_w[j].copy()  # simultaneous-style update.
        W_g_w[i] -= 0.05 * weight * err * old_u  # gradient for word vector.
        U_g_w[j] -= 0.05 * weight * err * old_w  # gradient for context vector.
        bw_g_w[i] -= 0.05 * weight * err  # word bias gradient.
        bc_g_w[j] -= 0.05 * weight * err  # context bias gradient.
loss_end_g_w = glove_loss_w(W_g_w, U_g_w, bw_g_w, bc_g_w)  # final objective.
print("GloVe loss start→end:", round(loss_start_g_w, 3), "→", round(loss_end_g_w, 3))  # inspect convergence.
assert loss_end_g_w < loss_start_g_w  # training should reduce weighted log-count error.
```
▶ What you'll see: the weighted reconstruction loss falls after GloVe-style updates.

```python
plt.figure(figsize=(5, 4))  # inspect the fitted GloVe word vectors.
plt.scatter(W_g_w[:, 0], W_g_w[:, 1], s=85, color="purple")  # plot trained word vectors.
for word_w, vec_w in zip(vocab_w, W_g_w): plt.text(vec_w[0] + 0.01, vec_w[1] + 0.01, word_w)  # label points.
plt.axhline(0, color="gray", linewidth=0.5); plt.axvline(0, color="gray", linewidth=0.5)  # axes.
plt.title("4: GloVe vectors fitted to log co-occurrence"); plt.show()  # render.
```
▶ What you'll see: words become movable points whose dot products and biases were trained to reconstruct global counts.

*Why it's done this way:* Taking logs makes multiplicative count differences additive, which matches dot-product geometry better than raw counts. The weighting function says “trust real co-occurrences, but do not let a single giant frequency dominate every vector.”

### 5. Vector geometry makes similarity and analogy visible

Once words are vectors, similarity is usually read with cosine direction, not raw dot product length. Analogies use offsets: `king - man + woman` asks for the point reached by preserving the “royal” direction while swapping the gender direction. This works in the toy plane exactly, and in real spaces only approximately.

```python
E_w = {"king": np.array([2., 1.]), "queen": np.array([2., 3.]),
       "man": np.array([1., 0.]), "woman": np.array([1., 2.]),
       "car": np.array([-2., -1.])}  # hand-built vectors from the lesson block.
def cos_w(a, b):  # cosine similarity helper.
    return float(np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b)))  # normalized dot product.
print("cos(king, queen):", cos_w(E_w["king"], E_w["queen"]))  # aligned royal words.
print("cos(king, car):", cos_w(E_w["king"], E_w["car"]))  # opposite direction.
assert round(cos_w(E_w["king"], E_w["queen"]), 3) == 0.868  # concrete toy cosine.
assert round(cos_w(E_w["king"], E_w["car"]), 3) == -1.0  # exact opposite ray.
```
▶ What you'll see: `car` lies in the opposite direction, while `king` and `queen` are positively aligned.

```python
query_w = E_w["king"] - E_w["man"] + E_w["woman"]  # offset analogy.
print("king - man + woman =", query_w)  # computed analogy point.
print("queen vector =", E_w["queen"])  # target point.
assert np.allclose(query_w, E_w["queen"])  # exact toy analogy.
```
▶ What you'll see: the offset lands exactly at `[2, 3]`, the constructed queen point.

```python
plt.figure(figsize=(4.5, 4))  # plot the toy analogy plane.
for word, vec in E_w.items():  # draw every word.
    plt.scatter(vec[0], vec[1], s=80)  # point in embedding space.
    plt.text(vec[0] + 0.05, vec[1] + 0.05, word)  # label point.
plt.arrow(E_w["man"][0], E_w["man"][1], 0, 2, head_width=0.08, color="gray", length_includes_head=True)  # man→woman.
plt.arrow(E_w["king"][0], E_w["king"][1], 0, 2, head_width=0.08, color="gray", length_includes_head=True)  # king→queen.
plt.axhline(0, color="black", linewidth=0.5); plt.axvline(0, color="black", linewidth=0.5)  # axes.
plt.title("5: analogy as a shared offset"); plt.show()  # render.
```
▶ What you'll see: the vertical offset from `man` to `woman` is copied from `king` to `queen`.

*Why it's done this way:* Cosine removes vector length so frequency-like magnitude does not masquerade as semantic similarity. Offsets work when a relation is encoded as a roughly consistent direction; the caveat is that real corpora mix meanings, biases, and artifacts, so geometry is evidence, not truth.

### 6. FastText-style subwords share evidence across rare forms

Word2Vec and GloVe give unrelated parameters to `play`, `played`, and `playing` unless their whole-word contexts overlap. FastText adds character n-gram vectors, so morphologically related words share pieces. This helps rare words borrow strength from frequent relatives.

```python
def trigrams_w(word):  # simple character trigram set without boundary symbols.
    return {word[i:i+3] for i in range(len(word) - 2)}  # all length-3 substrings.
tri_play_w = trigrams_w("play")  # {'pla','lay'}.
tri_playing_w = trigrams_w("playing")  # includes pla and lay.
tri_played_w = trigrams_w("played")  # includes pla and lay.
print("play trigrams:", sorted(tri_play_w))  # inspect subword pieces.
print("playing overlap:", sorted(tri_play_w & tri_playing_w))  # shared pieces.
assert tri_play_w == {"pla", "lay"}  # concrete source number.
```
▶ What you'll see: `play` shares both of its trigrams with longer inflected forms.

```python
def jaccard_w(a, b):  # set overlap divided by union size.
    return len(a & b) / len(a | b)  # Jaccard similarity.
j_playing_w = jaccard_w(tri_play_w, tri_playing_w)  # overlap with playing.
j_played_w = jaccard_w(tri_play_w, tri_played_w)  # overlap with played.
print("Jaccard(play, playing):", round(j_playing_w, 3))  # 2/5.
print("Jaccard(play, played):", round(j_played_w, 3))  # 2/4.
assert round(j_playing_w, 3) == 0.4 and round(j_played_w, 3) == 0.5  # source lesson values.
```
▶ What you'll see: the overlap numbers are 0.4 and 0.5, giving rare forms a concrete bridge.

```python
all_tris_w = sorted(tri_play_w | tri_playing_w | tri_played_w)  # tiny subword vocabulary.
tri_idx_w = {g: i for i, g in enumerate(all_tris_w)}  # trigram index.
rng_sub_w = np.random.default_rng(2)  # reproducible subword vectors.
G_w = rng_sub_w.normal(size=(len(all_tris_w), 2))  # one vector per trigram.
def subword_vec_w(word):  # average character n-gram vectors.
    ids = [tri_idx_w[g] for g in trigrams_w(word)]  # active subword ids.
    return G_w[ids].mean(axis=0)  # averaged word vector.
vecs_sub_w = np.vstack([subword_vec_w(w) for w in ["play", "playing", "played"]])  # compose three word vectors.
print("subword vector shape:", vecs_sub_w.shape)  # three dense vectors.
plt.figure(figsize=(4, 3)); plt.scatter(vecs_sub_w[:, 0], vecs_sub_w[:, 1], s=90, color="teal")  # plot them.
for word, vec in zip(["play", "playing", "played"], vecs_sub_w): plt.text(vec[0], vec[1], word)  # labels.
plt.title("6: words built from shared trigrams"); plt.show()  # render.
```
▶ What you'll see: related word forms are constructed from overlapping ingredients instead of isolated lookup rows.

*Why it's done this way:* Averaging subword vectors makes the full word a composition of reusable parts. That changes the statistical unit from “only the exact token gets trained” to “every substring receives updates,” which is why rare and unseen morphological variants can still get meaningful vectors.

### ✍️ Toy 1 · Context windows become co-occurrence counts

A context window turns each center token into directed center-context evidence. With window size 1,
each token only sees its immediate neighbors.

```python
import numpy as np
import matplotlib.pyplot as plt

t1_rng = np.random.default_rng(0)  # -> seeded generator for this toy
t1_tokens = np.array("sun bright sky sun".split())  # -> ['sun', 'bright', 'sky', 'sun']
print("tokens:", t1_tokens.tolist())  # -> ['sun', 'bright', 'sky', 'sun']
t1_vocab = np.unique(t1_tokens)  # -> ['bright', 'sky', 'sun']
print("vocabulary:", t1_vocab.tolist())  # -> ['bright', 'sky', 'sun']
t1_counts = np.zeros((len(t1_vocab), len(t1_vocab)), dtype=int)  # -> 3x3 zero matrix
t1_pairs = []  # -> []
for t1_pos, t1_word in enumerate(t1_tokens):
    t1_lo = max(0, t1_pos - 1)
    t1_hi = min(len(t1_tokens), t1_pos + 2)
    for t1_j in range(t1_lo, t1_hi):
        if t1_j != t1_pos:
            t1_center_id = int(np.where(t1_vocab == t1_word)[0][0])
            t1_context_id = int(np.where(t1_vocab == t1_tokens[t1_j])[0][0])
            t1_counts[t1_center_id, t1_context_id] += 1
            t1_pairs.append((str(t1_word), str(t1_tokens[t1_j])))
print("center-context pairs:", t1_pairs)  # -> [('sun', 'bright'), ('bright', 'sun'), ('bright', 'sky'), ('sky', 'bright'), ('sky', 'sun'), ('sun', 'sky')]
print("co-occurrence matrix:", t1_counts.tolist())  # -> [[0, 1, 1], [1, 0, 1], [1, 1, 0]]
assert t1_counts.tolist() == [[0, 1, 1], [1, 0, 1], [1, 1, 0]]

plt.figure(figsize=(4.3, 3.4))
plt.imshow(t1_counts, cmap="viridis", aspect="auto")
plt.xticks(range(len(t1_vocab)), t1_vocab, rotation=30, ha="right")
plt.yticks(range(len(t1_vocab)), t1_vocab)
plt.colorbar(label="count")
plt.title("Toy 1 · window-1 co-occurrence")
plt.show()
```
▶ What you'll see: every off-diagonal count is `1` because each word appears beside the other two once.

### ✍️ Toy 2 · PPMI keeps positive surprise

PPMI compares observed co-occurrence to independence. Positive log ratios stay; zero or below-chance
pairs are clipped to zero.

```python
import numpy as np

t2_rng = np.random.default_rng(0)  # -> seeded generator for this toy
t2_counts = np.array([[4.0, 0.0], [1.0, 3.0]])  # -> [[4.0, 0.0], [1.0, 3.0]]
print("count matrix:", t2_counts.tolist())  # -> [[4.0, 0.0], [1.0, 3.0]]
t2_row_sums = t2_counts.sum(axis=1, keepdims=True)  # -> [[4.0], [4.0]]
print("row sums:", t2_row_sums.ravel().tolist())  # -> [4.0, 4.0]
t2_col_sums = t2_counts.sum(axis=0, keepdims=True)  # -> [[5.0, 3.0]]
print("column sums:", t2_col_sums.ravel().tolist())  # -> [5.0, 3.0]
t2_total = float(t2_counts.sum())  # -> 8.0
print("total count:", t2_total)  # -> 8.0
t2_expected = t2_row_sums @ t2_col_sums / t2_total  # -> [[2.5, 1.5], [2.5, 1.5]]
print("expected under independence:", t2_expected.tolist())  # -> [[2.5, 1.5], [2.5, 1.5]]
t2_ratio = np.divide(t2_counts, t2_expected, out=np.zeros_like(t2_counts), where=t2_expected > 0)  # -> [[1.6, 0.0], [0.4, 2.0]]
print("observed / expected:", np.round(t2_ratio, 3).tolist())  # -> [[1.6, 0.0], [0.4, 2.0]]
with np.errstate(divide="ignore", invalid="ignore"):
    t2_pmi = np.log(t2_ratio)  # -> [[0.470004, -inf], [-0.916291, 0.693147]]
print("PMI before clipping:", np.round(t2_pmi, 3).tolist())  # -> [[0.47, -inf], [-0.916, 0.693]]
t2_ppmi = np.maximum(np.nan_to_num(t2_pmi, neginf=0.0), 0.0)  # -> [[0.470004, 0.0], [0.0, 0.693147]]
print("PPMI after clipping:", np.round(t2_ppmi, 3).tolist())  # -> [[0.47, 0.0], [0.0, 0.693]]
assert round(float(t2_ppmi[1, 1]), 3) == 0.693

plt.figure(figsize=(4.0, 3.2))
plt.imshow(t2_ppmi, cmap="magma", aspect="auto")
plt.xticks([0, 1], ["ctx0", "ctx1"])
plt.yticks([0, 1], ["word0", "word1"])
plt.colorbar(label="PPMI")
plt.title("Toy 2 · positive surprise remains")
plt.show()
```
▶ What you'll see: only above-chance cells stay bright; the below-chance count is clipped to `0`.

### ✍️ Toy 3 · Skip-gram softmax update raises the target context

Skip-gram turns dot products into context probabilities. One gradient step nudges the observed
context upward and lowers the negative log-likelihood.

```python
import numpy as np

t3_rng = np.random.default_rng(0)  # -> seeded generator for this toy
t3_vocab = np.array(["tea", "cup", "cake"])  # -> ['tea', 'cup', 'cake']
print("vocabulary:", t3_vocab.tolist())  # -> ['tea', 'cup', 'cake']
t3_center_vec = np.array([0.2, -0.1])  # -> [0.2, -0.1]
print("center vector:", t3_center_vec.tolist())  # -> [0.2, -0.1]
t3_output_vecs = np.array([[0.1, 0.0], [0.0, 0.2], [-0.1, 0.1]])  # -> output context vectors
print("output vectors:", t3_output_vecs.tolist())  # -> [[0.1, 0.0], [0.0, 0.2], [-0.1, 0.1]]
t3_target_index = 1  # -> cup
print("target context:", str(t3_vocab[t3_target_index]))  # -> cup
t3_scores = t3_output_vecs @ t3_center_vec  # -> [0.02, -0.02, -0.03]
print("scores before:", np.round(t3_scores, 3).tolist())  # -> [0.02, -0.02, -0.03]
t3_exp_scores = np.exp(t3_scores - t3_scores.max())  # -> [1.0, 0.960789, 0.951229]
print("stable exponentials:", np.round(t3_exp_scores, 6).tolist())  # -> [1.0, 0.960789, 0.951229]
t3_probs = t3_exp_scores / t3_exp_scores.sum()  # -> [0.343404, 0.329939, 0.326656]
print("probabilities before:", np.round(t3_probs, 6).tolist())  # -> [0.343404, 0.329939, 0.326656]
t3_loss_before = -float(np.log(t3_probs[t3_target_index]))  # -> 1.1088466082162867
print("loss before:", round(t3_loss_before, 6))  # -> 1.108847
t3_target = np.zeros(len(t3_vocab))  # -> [0.0, 0.0, 0.0]
t3_target[t3_target_index] = 1.0  # -> [0.0, 1.0, 0.0]
print("one-hot target:", t3_target.tolist())  # -> [0.0, 1.0, 0.0]
t3_grad_scores = t3_probs - t3_target  # -> [0.343404, -0.670061, 0.326656]
print("gradient wrt scores:", np.round(t3_grad_scores, 6).tolist())  # -> [0.343404, -0.670061, 0.326656]
t3_grad_center = t3_output_vecs.T @ t3_grad_scores  # -> [0.001675, -0.101347]
print("gradient wrt center:", np.round(t3_grad_center, 6).tolist())  # -> [0.001675, -0.101347]
t3_grad_output = t3_grad_scores[:, None] * t3_center_vec[None, :]  # -> [[0.068681, -0.03434], [-0.134012, 0.067006], [0.065331, -0.032666]]
print("gradient wrt output vectors:", np.round(t3_grad_output, 6).tolist())  # -> [[0.068681, -0.03434], [-0.134012, 0.067006], [0.065331, -0.032666]]
t3_lr = 0.5  # -> 0.5
print("learning rate:", t3_lr)  # -> 0.5
t3_center_after = t3_center_vec - t3_lr * t3_grad_center  # -> [0.199163, -0.049327]
print("center after:", np.round(t3_center_after, 6).tolist())  # -> [0.199163, -0.049327]
t3_output_after = t3_output_vecs - t3_lr * t3_grad_output  # -> updated context vectors
print("output vectors after:", np.round(t3_output_after, 6).tolist())  # -> [[0.06566, 0.01717], [0.067006, 0.166497], [-0.132666, 0.116333]]
t3_scores_after = t3_output_after @ t3_center_after  # -> [0.01223, 0.005132, -0.03216]
print("scores after:", np.round(t3_scores_after, 6).tolist())  # -> [0.01223, 0.005132, -0.03216]
t3_exp_after = np.exp(t3_scores_after - t3_scores_after.max())  # -> [1.0, 0.992927, 0.956512]
t3_probs_after = t3_exp_after / t3_exp_after.sum()  # -> [0.33904, 0.336642, 0.324319]
print("probabilities after:", np.round(t3_probs_after, 6).tolist())  # -> [0.33904, 0.336642, 0.324319]
t3_loss_after = -float(np.log(t3_probs_after[t3_target_index]))  # -> 1.0887360062171403
print("loss after:", round(t3_loss_after, 6))  # -> 1.088736
assert t3_loss_after < t3_loss_before

plt.figure(figsize=(4.8, 2.8))
plt.bar(t3_vocab, t3_probs, alpha=0.55, label="before", color="#4e79a7")
plt.bar(t3_vocab, t3_probs_after, alpha=0.55, label="after", color="#f28e2b")
plt.ylim(0, 0.4)
plt.xlabel("context word")
plt.ylabel("softmax probability")
plt.title("Toy 3 · target context probability rises")
plt.legend()
plt.show()
```
▶ What you'll see: `cup` moves from probability `0.329939` to `0.336642`, and the loss drops.

### ✍️ Toy 4 · GloVe fits a log-count with weighted squared error

A GloVe-style update compares a dot product plus biases to `log(count)`. One gradient step cuts the
weighted reconstruction error.

```python
import numpy as np

t4_rng = np.random.default_rng(0)  # -> seeded generator for this toy
t4_count = 2.0  # -> 2.0
print("co-occurrence count:", t4_count)  # -> 2.0
t4_target = float(np.log(t4_count))  # -> 0.6931471805599453
print("log-count target:", round(t4_target, 6))  # -> 0.693147
t4_weight = min((t4_count / 4.0) ** 0.75, 1.0)  # -> 0.5946035575013605
print("GloVe weight:", round(t4_weight, 6))  # -> 0.594604
t4_word_vec = np.array([0.2, 0.1])  # -> [0.2, 0.1]
print("word vector before:", t4_word_vec.tolist())  # -> [0.2, 0.1]
t4_context_vec = np.array([0.1, -0.2])  # -> [0.1, -0.2]
print("context vector before:", t4_context_vec.tolist())  # -> [0.1, -0.2]
t4_word_bias = 0.0  # -> 0.0
t4_context_bias = 0.0  # -> 0.0
t4_pred_before = float(t4_word_vec @ t4_context_vec + t4_word_bias + t4_context_bias)  # -> 0.0
print("prediction before:", round(t4_pred_before, 6))  # -> 0.0
t4_error_before = t4_pred_before - t4_target  # -> -0.6931471805599453
print("error before:", round(t4_error_before, 6))  # -> -0.693147
t4_loss_before = 0.5 * t4_weight * t4_error_before ** 2  # -> 0.14283953564400662
print("weighted loss before:", round(t4_loss_before, 6))  # -> 0.14284
t4_lr = 0.4  # -> 0.4
print("learning rate:", t4_lr)  # -> 0.4
t4_old_word_vec = t4_word_vec.copy()  # -> [0.2, 0.1]
t4_old_context_vec = t4_context_vec.copy()  # -> [0.1, -0.2]
t4_word_vec = t4_word_vec - t4_lr * t4_weight * t4_error_before * t4_old_context_vec  # -> [0.216486, 0.067028]
print("word vector after:", np.round(t4_word_vec, 6).tolist())  # -> [0.216486, 0.067028]
t4_context_vec = t4_context_vec - t4_lr * t4_weight * t4_error_before * t4_old_word_vec  # -> [0.132972, -0.183514]
print("context vector after:", np.round(t4_context_vec, 6).tolist())  # -> [0.132972, -0.183514]
t4_word_bias = t4_word_bias - t4_lr * t4_weight * t4_error_before  # -> 0.16485911177319254
print("word bias after:", round(t4_word_bias, 6))  # -> 0.164859
t4_context_bias = t4_context_bias - t4_lr * t4_weight * t4_error_before  # -> 0.16485911177319254
print("context bias after:", round(t4_context_bias, 6))  # -> 0.164859
t4_pred_after = float(t4_word_vec @ t4_context_vec + t4_word_bias + t4_context_bias)  # -> 0.34620413472370437
print("prediction after:", round(t4_pred_after, 6))  # -> 0.346204
t4_error_after = t4_pred_after - t4_target  # -> -0.3469430458362409
print("error after:", round(t4_error_after, 6))  # -> -0.346943
t4_loss_after = 0.5 * t4_weight * t4_error_after ** 2  # -> 0.03578605963548144
print("weighted loss after:", round(t4_loss_after, 6))  # -> 0.035786
assert t4_loss_after < t4_loss_before

plt.figure(figsize=(4.4, 2.8))
plt.bar(["before", "after"], [t4_loss_before, t4_loss_after], color=["#e15759", "#59a14f"])
plt.ylabel("weighted squared error")
plt.title("Toy 4 · GloVe update lowers loss")
plt.show()
```
▶ What you'll see: the prediction moves toward the log-count target and the weighted loss falls by about 4×.

### ✍️ Toy 6 · Subword vectors share pieces across forms

FastText-style words are built from reusable character n-grams. Related forms share trigrams, so
rare forms can borrow evidence from common pieces.

```python
import numpy as np

t6_rng = np.random.default_rng(0)  # -> seeded generator for this toy
def t6_trigrams(t6_word):
    return {t6_word[t6_i:t6_i + 3] for t6_i in range(len(t6_word) - 2)}

t6_code = t6_trigrams("code")  # -> {'cod', 'ode'}
print("code trigrams:", sorted(t6_code))  # -> ['cod', 'ode']
t6_coder = t6_trigrams("coder")  # -> {'cod', 'der', 'ode'}
print("coder trigrams:", sorted(t6_coder))  # -> ['cod', 'der', 'ode']
t6_coding = t6_trigrams("coding")  # -> {'cod', 'din', 'ing', 'odi'}
print("coding trigrams:", sorted(t6_coding))  # -> ['cod', 'din', 'ing', 'odi']
t6_overlap_coder = t6_code & t6_coder  # -> {'cod', 'ode'}
print("code ∩ coder:", sorted(t6_overlap_coder))  # -> ['cod', 'ode']
t6_overlap_coding = t6_code & t6_coding  # -> {'cod'}
print("code ∩ coding:", sorted(t6_overlap_coding))  # -> ['cod']
t6_jaccard_coder = len(t6_overlap_coder) / len(t6_code | t6_coder)  # -> 0.6666666666666666
print("Jaccard(code, coder):", round(t6_jaccard_coder, 3))  # -> 0.667
t6_jaccard_coding = len(t6_overlap_coding) / len(t6_code | t6_coding)  # -> 0.2
print("Jaccard(code, coding):", round(t6_jaccard_coding, 3))  # -> 0.2
t6_all_trigrams = sorted(t6_code | t6_coder | t6_coding)  # -> ['cod', 'der', 'din', 'ing', 'ode', 'odi']
print("subword vocabulary:", t6_all_trigrams)  # -> ['cod', 'der', 'din', 'ing', 'ode', 'odi']
t6_subword_vecs = np.array([[1.0, 0.0], [0.0, 1.0], [0.5, 0.5], [-0.5, 0.5], [1.0, 1.0], [0.0, 0.5]])  # -> six 2-D vectors
print("subword vectors:", t6_subword_vecs.tolist())  # -> [[1.0, 0.0], [0.0, 1.0], [0.5, 0.5], [-0.5, 0.5], [1.0, 1.0], [0.0, 0.5]]

print("code ids:", t6_code_ids)  # -> [0, 4]
t6_coder_ids = [t6_index[t6_gram] for t6_gram in sorted(t6_coder)]  # -> [0, 1, 4]
print("coder ids:", t6_coder_ids)  # -> [0, 1, 4]
t6_coding_ids = [t6_index[t6_gram] for t6_gram in sorted(t6_coding)]  # -> [0, 2, 3, 5]
print("coding ids:", t6_coding_ids)  # -> [0, 2, 3, 5]
t6_code_vec = t6_subword_vecs[t6_code_ids].mean(axis=0)  # -> [1.0, 0.5]
print("code vector:", t6_code_vec.tolist())  # -> [1.0, 0.5]
t6_coder_vec = t6_subword_vecs[t6_coder_ids].mean(axis=0)  # -> [0.666667, 0.666667]
print("coder vector:", np.round(t6_coder_vec, 6).tolist())  # -> [0.666667, 0.666667]
t6_coding_vec = t6_subword_vecs[t6_coding_ids].mean(axis=0)  # -> [0.25, 0.375]
print("coding vector:", t6_coding_vec.tolist())  # -> [0.25, 0.375]
assert round(t6_jaccard_coder, 3) == 0.667 and round(t6_jaccard_coding, 3) == 0.2

plt.figure(figsize=(4.2, 3.2))

plt.xlabel("subword dimension 1")
plt.ylabel("subword dimension 2")
plt.title("Toy 6 · words average shared trigrams")
```

### Basic 3 — Make center-context pairs

**Goal.** Build skip-gram training pairs with a window of one, because Word2Vec predicts nearby context words from a center word. We build it in 2 steps.

```python
tokens_b3 = [["king", "loves", "queen"]] # one short sentence.
pairs_b3 = [] # collect directed center-context pairs.
for sent_b3 in tokens_b3: # scan the sentence.
    for i_b3, word_b3 in enumerate(sent_b3): # choose the center word.
        for j_b3 in range(max(0, i_b3 - 1), min(len(sent_b3), i_b3 + 2)): # window size one.
            if i_b3 != j_b3: pairs_b3.append((word_b3, sent_b3[j_b3])) # add context pair.
```

### Easy 1 — Train a tiny skip-gram model

**Goal.** Learn 2-D vectors with full-softmax skip-gram, because Word2Vec makes center words predict contexts. We build it in 4 steps.

```python

vocab_e1 = sorted({w_e1 for s_e1 in sentences_e1 for w_e1 in s_e1}) # vocabulary.
idx_e1 = {w_e1: i_e1 for i_e1, w_e1 in enumerate(vocab_e1)} # index map.
print("vocab:", vocab_e1) # inspect words.
```
▶ What you'll see: a small vocabulary suitable for exact softmax.

```python
pairs_e1 = [] # center-context training pairs.
for s_e1 in sentences_e1:
    for i_e1, w_e1 in enumerate(s_e1):
        for j_e1 in range(max(0, i_e1 - 1), min(len(s_e1), i_e1 + 2)):
            if i_e1 != j_e1: pairs_e1.append((idx_e1[w_e1], idx_e1[s_e1[j_e1]])) # directed pair.
print("pairs:", len(pairs_e1)) # inspect training size.
assert len(pairs_e1) == 16 # four short sentences.
```
▶ What you'll see: 16 skip-gram examples.

```python
rng_e1 = np.random.default_rng(3) # reproducible initialization.
V_e1, d_e1 = len(vocab_e1), 2 # sizes.
Vin_e1 = 0.1 * rng_e1.normal(size=(V_e1, d_e1)); U_e1 = 0.1 * rng_e1.normal(size=(V_e1, d_e1)) # vectors.
losses_e1 = [] # track training loss.
for epoch_e1 in range(80): # repeated passes.
    total_e1 = 0.0 # epoch loss.
    for center_e1, context_e1 in pairs_e1: # one full-softmax update.
        logits_e1 = U_e1 @ Vin_e1[center_e1] # context scores.
        probs_e1 = np.exp(logits_e1 - logits_e1.max()); probs_e1 /= probs_e1.sum() # softmax.
        total_e1 += -np.log(probs_e1[context_e1]) # NLL.
        y_e1 = np.zeros(V_e1); y_e1[context_e1] = 1.0 # target.
        g_e1 = probs_e1 - y_e1 # score gradient.
        old_v_e1 = Vin_e1[center_e1].copy() # simultaneous update.
```

```python
        err_e3 = W_e3[i_e3] @ U_e3[j_e3] + bw_e3[i_e3] + bc_e3[j_e3] - np.log(C_e3[i_e3, j_e3])
        total_e3 += 0.5 * err_e3 ** 2
    return float(total_e3)
start_e3 = loss_e3(W_e3, U_e3, bw_e3, bc_e3) # starting loss.
```

### Advanced 1 — Negative sampling approximation

**Goal.** Replace full softmax with one positive and a few negative contexts, because large vocabularies make exact normalization expensive. We build it in 4 steps.

```python
vocab_a1 = ["king", "queen", "man", "woman", "car"] # tiny vocabulary.
rng_a1 = np.random.default_rng(6) # reproducible vectors.
Vin_a1 = 0.1 * rng_a1.normal(size=(5, 2)); U_a1 = 0.1 * rng_a1.normal(size=(5, 2)) # input/output embeddings.
center_a1, pos_a1 = 0, 2 # observed pair king→man.
negs_a1 = np.array([1, 4]) # sampled non-contexts queen and car for this update.
print("positive:", vocab_a1[pos_a1], "negatives:", [vocab_a1[i_a1] for i_a1 in negs_a1]) # inspect training labels.
```
▶ What you'll see: one true context and two sampled negatives.

```python
def sigmoid_a1(x_a1): return 1 / (1 + np.exp(-x_a1)) # logistic function.
def ns_loss_a1(Vin_a1, U_a1): # negative-sampling loss for one center.
    pos_score_a1 = U_a1[pos_a1] @ Vin_a1[center_a1] # positive dot.
    neg_scores_a1 = U_a1[negs_a1] @ Vin_a1[center_a1] # negative dots.
    return float(-np.log(sigmoid_a1(pos_score_a1)) - np.sum(np.log(sigmoid_a1(-neg_scores_a1)))) # logistic loss.
start_a1 = ns_loss_a1(Vin_a1, U_a1) # initial loss.
print("start loss:", round(start_a1, 3)) # inspect.
```
▶ What you'll see: the logistic objective is high when positives and negatives are not separated.

```python
v_old_a1 = Vin_a1[center_a1].copy() # save center vector.
pos_grad_a1 = (sigmoid_a1(U_a1[pos_a1] @ v_old_a1) - 1) # derivative for positive logit.
neg_grad_a1 = sigmoid_a1(U_a1[negs_a1] @ v_old_a1) # derivatives for negative logits.
grad_v_a1 = pos_grad_a1 * U_a1[pos_a1] + neg_grad_a1 @ U_a1[negs_a1] # center gradient.
Vin_a1[center_a1] -= 0.5 * grad_v_a1 # update center vector.
U_a1[pos_a1] -= 0.5 * pos_grad_a1 * v_old_a1 # update positive output vector.
U_a1[negs_a1] -= 0.5 * neg_grad_a1[:, None] * v_old_a1 # update negative output vectors.
end_a1 = ns_loss_a1(Vin_a1, U_a1) # final loss.
print("loss start→end:", round(start_a1, 3), "→", round(end_a1, 3)) # inspect update.
assert end_a1 < start_a1 # one step should improve this sampled objective.
```
▶ What you'll see: loss falls by raising the positive dot and lowering negative dots.

```python
plt.figure(figsize=(4, 3)) # compare sampled objective.
plt.bar(["before", "after"], [start_a1, end_a1], color=["gray", "teal"]) # show loss drop.
plt.title("Advanced 1: negative-sampling step"); plt.ylabel("loss") # labels.
plt.show() # display.
```
▶ What you'll see: the after bar is lower for the sampled logistic task.

👀 Takeaway: negative sampling avoids a full vocabulary softmax by contrasting observed pairs with sampled non-pairs.

### Advanced 2 — Window size changes geometry

**Goal.** Compare narrow and wide context matrices, because embedding meaning depends on the context definition. We build it in 4 steps.

```python
sentences_a2 = [["king", "rules", "kingdom"], ["queen", "rules", "kingdom"], ["car", "drives", "road"]] # toy corpus.
vocab_a2 = sorted({w_a2 for s_a2 in sentences_a2 for w_a2 in s_a2}) # vocabulary.
idx_a2 = {w_a2: i_a2 for i_a2, w_a2 in enumerate(vocab_a2)} # index map.
print("vocab:", vocab_a2) # inspect.
```
▶ What you'll see: royal and driving topic words share short sentences.

```python
def cooc_a2(window_a2): # build co-occurrence for a chosen window.
    C_a2 = np.zeros((len(vocab_a2), len(vocab_a2)))
    for s_a2 in sentences_a2:
        for i_a2, w_a2 in enumerate(s_a2):
            for j_a2 in range(max(0, i_a2-window_a2), min(len(s_a2), i_a2+window_a2+1)):
                if i_a2 != j_a2: C_a2[idx_a2[w_a2], idx_a2[s_a2[j_a2]]] += 1
    return C_a2
C1_a2 = cooc_a2(1); C2_a2 = cooc_a2(2) # narrow and wide counts.
print("king→kingdom window1/window2:", C1_a2[idx_a2["king"], idx_a2["kingdom"]], C2_a2[idx_a2["king"], idx_a2["kingdom"]]) # compare reach.
```
▶ What you'll see: the wider window sees across the middle word.

```python
def row_cos_a2(C_a2, w1_a2, w2_a2): # cosine between count rows.
    a_a2, b_a2 = C_a2[idx_a2[w1_a2]], C_a2[idx_a2[w2_a2]]
    den_a2 = np.linalg.norm(a_a2) * np.linalg.norm(b_a2)
    return 0.0 if den_a2 == 0 else float(a_a2 @ b_a2 / den_a2)
sim1_a2 = row_cos_a2(C1_a2, "king", "queen"); sim2_a2 = row_cos_a2(C2_a2, "king", "queen") # compare.

```
▶ What you'll see: changing the context window changes row similarity.

```python
plt.figure(figsize=(4, 3)) # plot comparison.

```
▶ What you'll see: the wide-window bar reflects broader topical evidence.

👀 Takeaway: embedding geometry inherits the window rule used to collect context.

### Advanced 3 — Debias by projecting out a direction

**Goal.** Remove a chosen relation direction from vectors, because embedding spaces can contain directions we want to inspect or neutralize. We build it in 3 steps.


### Advanced 5 — Evaluate analogy by nearest vector

**Goal.** Compute an analogy query and retrieve its nearest neighbor, because real embedding evaluation ranks candidates rather than checking exact equality. We build it in 3 steps.

```python
words_a5 = np.array(["king", "queen", "man", "woman", "car"]) # labels.
E_a5 = np.array([[2., 1.], [2., 3.], [1., 0.], [1., 2.], [-2., -1.]]) # toy embeddings.
query_a5 = E_a5[0] - E_a5[2] + E_a5[3] # king - man + woman.
print("query:", query_a5) # inspect analogy point.
```
▶ What you'll see: the query vector is `[2, 3]`.

```python
norms_a5 = np.linalg.norm(E_a5, axis=1) * np.linalg.norm(query_a5) # cosine denominators.
sims_a5 = (E_a5 @ query_a5) / norms_a5 # cosine to every candidate.
sims_a5[[0, 2, 3]] = -np.inf # exclude source words king, man, woman.
best_a5 = int(np.argmax(sims_a5)) # nearest remaining word.
print("best answer:", words_a5[best_a5], "score:", round(float(sims_a5[best_a5]), 3)) # inspect result.
assert words_a5[best_a5] == "queen" # expected analogy answer.
```
▶ What you'll see: `queen` is the nearest allowed candidate.

```python
plt.figure(figsize=(4, 3)) # show candidate scores.
plot_scores_a5 = np.where(np.isfinite(sims_a5), sims_a5, 0.0) # finite values for bars.
```

▶ What you'll see: the `queen` bar is highest after excluding query source words.
