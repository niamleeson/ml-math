# 17.7 — Meta-Learning & Few-Shot

Meta-learning asks a model to learn **how to adapt** rather than only how to solve one fixed dataset. Few-shot learning is the test: after seeing only a tiny support set for a new task, the learner must make useful query predictions by reusing structure learned across many similar episodes.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build meta-learning one idea at a time. Run each cell in order and read the printed intermediate values — every piece of math is spelled out so episodes, support/query splits, prototypes, and MAML-style adaptation are not black boxes. This walkthrough is self-contained and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays, distances, gradients, and synthetic tasks.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
np.random.seed(0)  # reproducibility for episodes and task draws.
```

### 1. Few-shot tasks are episodes, not ordinary batches

A few-shot episode has a **support set** (the tiny labeled examples allowed for adaptation) and a **query set** (held-out examples used to test whether adaptation worked). A 2-way 2-shot episode means two classes and two labeled support examples per class. Training with episodes matters because the model practices the same small-data situation it will face at test time.

```python
support_x_w = np.array([[-1.0, 0.0], [-0.8, 0.2], [1.0, 0.0], [0.9, -0.2]])  # four labeled support points.
support_y_w = np.array([0, 0, 1, 1])  # two examples for class 0 and two for class 1.
query_x_w = np.array([[0.2, 0.05], [-0.7, 0.1], [1.2, -0.1]])  # points to classify after seeing support.
print("support shape:", support_x_w.shape, "query shape:", query_x_w.shape)  # inspect episode sizes.
print("shots per class:", [int(np.sum(support_y_w == k)) for k in [0, 1]])  # confirm 2-shot.
```
▶ What you'll see: a tiny 2-way 2-shot support set and three query points.

```python
plt.figure(figsize=(4.5, 3.4))  # create one compact episode plot.
plt.scatter(support_x_w[support_y_w == 0, 0], support_x_w[support_y_w == 0, 1], s=90, marker="o", label="support class 0")  # class 0 support.
plt.scatter(support_x_w[support_y_w == 1, 0], support_x_w[support_y_w == 1, 1], s=90, marker="s", label="support class 1")  # class 1 support.
plt.scatter(query_x_w[:, 0], query_x_w[:, 1], s=120, marker="*", color="black", label="queries")  # query points.
plt.axvline(0, color="gray", linewidth=0.6)  # reference boundary for intuition.
plt.title("1: support-query episode"); plt.legend(); plt.show()  # render the episode.
```
▶ What you'll see: support points define the task, while black stars are not used to build the classifier.

*Why it's done this way:* ordinary minibatches reward performance after many examples; episodes reward performance after the same tiny support budget available at deployment. The support/query split prevents the learner from confusing adaptation data with evaluation data.

### 2. Prototypical networks rebuild the classifier from support geometry

A prototypical network represents each class by its support mean. With identity features $f_\theta(x)=x$, the prototype is simply $c_k=|S_k|^{-1}\sum_{x_i\in S_k}x_i$. The query is scored by squared distance to each prototype, then softmax is applied to **negative** distances so closer classes get larger probabilities.

```python
c0_w = support_x_w[support_y_w == 0].mean(axis=0)  # class-0 prototype = support mean.
c1_w = support_x_w[support_y_w == 1].mean(axis=0)  # class-1 prototype = support mean.
protos_w = np.vstack([c0_w, c1_w])  # stack prototypes for vectorized distances.
print("c0:", np.round(c0_w, 3), "c1:", np.round(c1_w, 3))  # inspect support means.
assert np.allclose(np.round(c0_w, 3), [-0.9, 0.1]) and np.allclose(np.round(c1_w, 3), [0.95, -0.1])  # lesson numbers.
```
▶ What you'll see: the two support means are `(-0.900, 0.100)` and `(0.950, -0.100)`.

```python
q_w = np.array([0.2, 0.05])  # the worked query from the lesson block.
d2_w = np.sum((protos_w - q_w) ** 2, axis=1)  # squared Euclidean distance from query to each prototype.
print("squared distances:", np.round(d2_w, 4))  # inspect d0^2 and d1^2.
assert np.allclose(np.round(d2_w, 4), [1.2125, 0.5850])  # self-check the concrete lesson values.
```
▶ What you'll see: the query is closer to class 1 than class 0.

```python
logits_w = -d2_w  # negative distances become logits: closer means larger.
prob_w = np.exp(logits_w - np.max(logits_w)) / np.sum(np.exp(logits_w - np.max(logits_w)))  # stable softmax.
print("class probabilities:", np.round(prob_w, 3))  # inspect proto-net probabilities.
assert round(float(prob_w[1]), 3) == 0.652  # lesson class-1 probability.
```
▶ What you'll see: class 1 gets probability about 0.652 because its prototype is nearer.

```python
plt.figure(figsize=(4.5, 3.4))  # visualize query distances.
plt.scatter(support_x_w[:, 0], support_x_w[:, 1], c=support_y_w, cmap="coolwarm", s=80)  # support points.
plt.scatter(protos_w[:, 0], protos_w[:, 1], marker="X", s=180, color="gold", edgecolor="black", label="prototypes")  # class means.
plt.scatter([q_w[0]], [q_w[1]], marker="*", s=160, color="black", label="query")  # query point.
for p_w in protos_w:  # draw query-to-prototype segments.
    plt.plot([q_w[0], p_w[0]], [q_w[1], p_w[1]], color="gray", linestyle="--")
plt.title("2: prototype distances classify the query"); plt.legend(); plt.show()
```
▶ What you'll see: the dashed line to class 1 is shorter, so the class-1 negative-distance logit is larger.

*Why it's done this way:* a prototype is the least-squares representative of a class under squared Euclidean distance. Rebuilding prototypes from support data lets a new task define new class weights without gradient-training a fresh classifier.

### 3. Episodic accuracy depends on the task distribution

Meta-learning assumes training episodes resemble test episodes. If support and query classes share the same geometry, prototype accuracy looks strong; if query points come from a shifted comparison set, the same numeric score can be misleading.

```python
rng_w = np.random.default_rng(1)  # local reproducible episode generator.
centers_w = np.array([[-1.0, 0.0], [1.0, 0.0]])  # two shared class centers.
support_ep_w = np.vstack([centers_w[k] + 0.18 * rng_w.normal(size=(2, 2)) for k in [0, 1]])  # 2-shot support.
query_ep_w = np.vstack([centers_w[k] + 0.18 * rng_w.normal(size=(20, 2)) for k in [0, 1]])  # matched query distribution.
y_query_ep_w = np.repeat([0, 1], 20)  # query labels.
print("support/query sizes:", support_ep_w.shape, query_ep_w.shape)  # inspect episode.
```
▶ What you'll see: one matched 2-way episode with 4 support points and 40 queries.

```python
proto_ep_w = np.vstack([support_ep_w[:2].mean(axis=0), support_ep_w[2:].mean(axis=0)])  # class means from support only.
dists_ep_w = np.sum((query_ep_w[:, None, :] - proto_ep_w[None, :, :]) ** 2, axis=2)  # query-to-prototype distances.
pred_ep_w = np.argmin(dists_ep_w, axis=1)  # nearest prototype prediction.
acc_ep_w = np.mean(pred_ep_w == y_query_ep_w)  # matched episode accuracy.
print("matched episode accuracy:", round(float(acc_ep_w), 3))  # inspect performance.
assert acc_ep_w > 0.9  # this task geometry is easy when train/test episodes match.
```
▶ What you'll see: high accuracy because the query distribution matches the support geometry.

```python
shifted_query_w = query_ep_w + np.array([0.7, 0.0])  # introduce a comparison-set shift.
shifted_dists_w = np.sum((shifted_query_w[:, None, :] - proto_ep_w[None, :, :]) ** 2, axis=2)  # distances under same prototypes.
shifted_acc_w = np.mean(np.argmin(shifted_dists_w, axis=1) == y_query_ep_w)  # shifted accuracy.
print("shifted episode accuracy:", round(float(shifted_acc_w), 3))  # inspect drop from mismatch.
```
▶ What you'll see: accuracy changes when query geometry no longer matches the support-task assumption.

```python
plt.figure(figsize=(4.8, 3))  # compare matched and shifted validation.
plt.bar(["matched", "shifted"], [acc_ep_w, shifted_acc_w], color=["seagreen", "indianred"])  # show validation mismatch.
plt.ylim(0, 1.05); plt.ylabel("accuracy"); plt.title("3: episode design controls validation meaning"); plt.show()
```
▶ What you'll see: the shifted bar is lower, illustrating why few-shot validation must match the target setting.

*Why it's done this way:* meta-learning optimizes adaptation averaged over tasks. If those tasks encode the wrong nuisance structure, the learner can optimize the wrong term perfectly and still fail on the desired task family.

### 4. MAML learns an initialization, not a final one-task model

Model-Agnostic Meta-Learning (MAML) chooses an initial parameter $\theta$ so one or a few gradient steps on a support set produce low query loss. We use the smallest possible regression task family: each task is a line $y=a x$, and the model is $\hat y=w x$. The support gradient adapts $w$ for one task; meta-learning asks which initial $w$ adapts well across many slopes.

```python
task_a_w = 2.0  # one task's true slope.
w0_w = 0.0  # meta-initialization before adaptation.
x_support_m_w = np.array([-1.0, 0.0, 1.0])  # tiny support set.
y_support_m_w = task_a_w * x_support_m_w  # support labels for this task.
print("initial w:", w0_w, "task slope:", task_a_w)  # inspect the adaptation problem.
```
▶ What you'll see: the learner starts at slope 0 and sees only three support points from a slope-2 task.

```python
pred_support_w = w0_w * x_support_m_w  # support predictions before adaptation.
grad_support_w = np.mean((pred_support_w - y_support_m_w) * x_support_m_w)  # gradient of 0.5 mean squared error.
alpha_w = 0.5  # inner-loop step size.
w1_w = w0_w - alpha_w * grad_support_w  # one MAML inner update.
print("support gradient:", round(float(grad_support_w), 3), "adapted w:", round(float(w1_w), 3))  # inspect inner step.
assert round(float(w1_w), 3) == 0.667  # with mean(x^2)=2/3, one step moves by 0.5*1.333.
```
▶ What you'll see: one support gradient moves the slope from 0 toward the task slope.

```python
x_query_m_w = np.array([-0.5, 0.5, 1.5])  # query inputs not used in the inner update.
y_query_m_w = task_a_w * x_query_m_w  # query truths.
query_loss_before_w = 0.5 * np.mean((w0_w * x_query_m_w - y_query_m_w) ** 2)  # no adaptation.
query_loss_after_w = 0.5 * np.mean((w1_w * x_query_m_w - y_query_m_w) ** 2)  # after support adaptation.
print("query loss before/after:", round(float(query_loss_before_w), 3), round(float(query_loss_after_w), 3))  # inspect benefit.
assert query_loss_after_w < query_loss_before_w  # adaptation helped this task.
```
▶ What you'll see: query loss falls after one support update, even though query labels were held out.

*Why it's done this way:* the inner loop uses support data to specialize to the current task; the outer loop judges that specialization on query data. This separation trains an initialization that is easy to adapt, not a parameter that is already optimal for every task.

### 5. The MAML outer loop differentiates through adaptation

For the same line tasks, the one-step adapted weight is $w'=w-\alpha(w-a)E[x^2]$. The query loss depends on $w'$, so the meta-gradient includes the derivative of the inner step: $\frac{d w'}{d w}=1-\alpha E[x^2]$. This is the "gradient through a gradient" that makes MAML different from ordinary pretraining.

```python
slopes_w = np.array([-2.0, -1.0, 1.0, 2.0])  # a distribution of few-shot tasks.
w_meta_w = 0.5  # candidate initialization.
alpha_meta_w = 0.4  # inner-loop step size.
xsq_w = np.mean(x_support_m_w ** 2)  # E[x^2] on support inputs.
print("support E[x^2]:", round(float(xsq_w), 3))  # inspect curvature term.
assert round(float(xsq_w), 3) == 0.667  # concrete support curvature.
```
▶ What you'll see: the support curvature is 2/3, controlling how far one gradient step moves.

```python
meta_losses_w = []  # store query losses after one adaptation per task.
meta_grads_w = []  # store exact one-step MAML gradients for this simple family.
for a_w in slopes_w:  # loop over tasks in the meta-batch.
    w_adapt_w = w_meta_w - alpha_meta_w * ((w_meta_w - a_w) * xsq_w)  # analytic inner update.
    qsq_w = np.mean(x_query_m_w ** 2)  # query curvature.
    loss_w = 0.5 * ((w_adapt_w - a_w) ** 2) * qsq_w  # query MSE after adaptation.
    grad_w = (w_adapt_w - a_w) * qsq_w * (1 - alpha_meta_w * xsq_w)  # chain rule through w'.
    meta_losses_w.append(loss_w); meta_grads_w.append(grad_w)  # collect task terms.
print("task query losses:", np.round(meta_losses_w, 3))  # inspect outer objective pieces.
print("mean meta-gradient:", round(float(np.mean(meta_grads_w)), 3))  # update direction for w_meta.
```
▶ What you'll see: each task contributes a post-adaptation query loss and a gradient through the inner step.

```python
beta_w = 0.2  # outer-loop step size.
w_next_w = w_meta_w - beta_w * np.mean(meta_grads_w)  # one meta update.
print("meta w before/after:", round(float(w_meta_w), 3), round(float(w_next_w), 3))  # inspect outer update.
plt.figure(figsize=(4.6, 3))
plt.bar([str(s) for s in slopes_w], meta_losses_w, color="steelblue")
plt.title("5: outer loss after one inner step"); plt.xlabel("task slope"); plt.ylabel("query loss"); plt.show()
```
▶ What you'll see: the bar heights are query losses **after** adaptation, which is the objective MAML minimizes.

*Why it's done this way:* ordinary training differentiates a loss at the current weights; MAML differentiates the query loss at the adapted weights. The extra chain-rule factor rewards initializations whose support gradients move in useful directions.

### 6. Few-shot adaptation needs regularization and sanity checks

With only a few support examples, adaptation can overfit the support set or erase useful shared structure. A practical meta-learner controls inner-step size, number of steps, distance scale, or regularization strength, then validates on query episodes that match the target deployment.

```python
support_noisy_w = np.array([[-1.0, -2.2], [0.0, 0.1], [1.0, 2.3]])  # a tiny noisy line task.
xn_w, yn_w = support_noisy_w[:, 0], support_noisy_w[:, 1]  # split features and labels.
w_start_w = 0.0  # shared initialization.
steps_w = np.arange(1, 8)  # try several inner-step counts.
print("support points:", support_noisy_w)  # inspect the scarce noisy evidence.
```
▶ What you'll see: three support points roughly follow a line but include noise.

```python
query_clean_x_w = np.linspace(-1.2, 1.2, 30)  # clean query grid from the underlying task.
query_clean_y_w = 2.0 * query_clean_x_w  # underlying slope-2 target.
losses_steps_w = []  # query losses after different adaptation lengths.
for nstep_w in steps_w:  # sweep inner-loop length.
    w_tmp_w = w_start_w  # reset initialization for each sweep value.
    for _ in range(int(nstep_w)):  # repeat support updates.
        grad_w = np.mean((w_tmp_w * xn_w - yn_w) * xn_w)  # support gradient.
        w_tmp_w -= 0.55 * grad_w  # inner adaptation.
    losses_steps_w.append(0.5 * np.mean((w_tmp_w * query_clean_x_w - query_clean_y_w) ** 2))  # query loss.
print("query losses by steps:", np.round(losses_steps_w, 4))  # inspect over-adaptation risk.
```
▶ What you'll see: query loss improves at first, then may flatten or worsen as the tiny noisy support set dominates.

```python
best_step_w = int(steps_w[np.argmin(losses_steps_w)])  # choose by query validation, not support fit.
plt.figure(figsize=(4.6, 3))
plt.plot(steps_w, losses_steps_w, marker="o", color="purple")
plt.axvline(best_step_w, color="red", linestyle="--", label=f"best={best_step_w}")
plt.title("6: inner adaptation length is a validation knob"); plt.xlabel("support gradient steps"); plt.ylabel("query loss"); plt.legend(); plt.show()
```
▶ What you'll see: a best inner-step count selected by query loss rather than by support loss.

*Why it's done this way:* few-shot support data is too small to trust by itself. Meta-learning therefore tunes adaptation rules against held-out query behavior so regularization removes nuisance variation without deleting task-specific signal.

### ✍️ Toy 2 · Prototypes are support means

For each class, average only its support points. The result is the class prototype used by a
nearest-prototype classifier.

```python
import numpy as np

t2_rng = np.random.default_rng(0)
print("rng seed:", 0)  # -> 0
t2_support_x = np.array([[-2.0, 0.0], [-1.0, 1.0], [1.0, 0.0], [3.0, 2.0]])
print("support x:", t2_support_x.tolist())  # -> [[-2.0, 0.0], [-1.0, 1.0], [1.0, 0.0], [3.0, 2.0]]
t2_support_y = np.array([0, 0, 1, 1])
print("support y:", t2_support_y.tolist())  # -> [0, 0, 1, 1]
t2_class0 = t2_support_x[t2_support_y == 0]
print("class 0 points:", t2_class0.tolist())  # -> [[-2.0, 0.0], [-1.0, 1.0]]
t2_c0 = t2_class0.mean(axis=0)
print("class 0 prototype:", t2_c0.tolist())  # -> [-1.5, 0.5]
t2_class1 = t2_support_x[t2_support_y == 1]
print("class 1 points:", t2_class1.tolist())  # -> [[1.0, 0.0], [3.0, 2.0]]
t2_c1 = t2_class1.mean(axis=0)
print("class 1 prototype:", t2_c1.tolist())  # -> [2.0, 1.0]
t2_protos = np.vstack([t2_c0, t2_c1])
print("prototype matrix:", t2_protos.tolist())  # -> [[-1.5, 0.5], [2.0, 1.0]]
assert np.allclose(t2_protos, [[-1.5, 0.5], [2.0, 1.0]])

plt.figure(figsize=(4.4, 3.2))
plt.scatter(t2_support_x[:, 0], t2_support_x[:, 1], c=t2_support_y, cmap="coolwarm", s=90)
plt.scatter(t2_protos[:, 0], t2_protos[:, 1], marker="X", s=180, color="gold", edgecolor="black")
plt.title("Toy 2 · support means become prototypes")
plt.show()
```
▶ What you'll see: each gold X sits exactly at the mean of its two same-class support points.

### ✍️ Toy 3 · Negative distances become class probabilities

A query is scored by squared distance to each prototype. Negating those distances makes the closer
prototype the larger softmax logit.

```python
import numpy as np

t3_rng = np.random.default_rng(0)
print("rng seed:", 0)  # -> 0
t3_protos = np.array([[-1.5, 0.5], [2.0, 1.0]])
print("prototypes:", t3_protos.tolist())  # -> [[-1.5, 0.5], [2.0, 1.0]]
t3_query = np.array([0.0, 0.5])
print("query:", t3_query.tolist())  # -> [0.0, 0.5]
t3_diffs = t3_protos - t3_query
print("diffs:", t3_diffs.tolist())  # -> [[-1.5, 0.0], [2.0, 0.5]]
t3_d2 = np.sum(t3_diffs ** 2, axis=1)
print("squared distances:", t3_d2.tolist())  # -> [2.25, 4.25]
t3_logits = -t3_d2
print("negative-distance logits:", t3_logits.tolist())  # -> [-2.25, -4.25]
t3_exp = np.exp(t3_logits - np.max(t3_logits))
print("stable exp:", np.round(t3_exp, 3).tolist())  # -> [1.0, 0.135]
t3_probs = t3_exp / t3_exp.sum()
print("probabilities:", np.round(t3_probs, 3).tolist())  # -> [0.881, 0.119]
t3_pred = int(np.argmax(t3_probs))
print("predicted class:", t3_pred)  # -> 0
assert t3_pred == 0 and round(float(t3_probs[0]), 3) == 0.881

plt.figure(figsize=(4.4, 2.8))
plt.bar(["class 0", "class 1"], t3_probs, color=["seagreen", "gray"])
plt.ylim(0.0, 1.0)
plt.ylabel("probability")
plt.title("Toy 3 · closer prototype wins")
plt.show()
```
▶ What you'll see: class 0 gets most of the probability because its squared distance is smaller.

### ✍️ Toy 4 · Episode accuracy changes under query shift

The same prototypes can look perfect on matched queries and much worse when the query geometry is
shifted away from the support task.

```python
import numpy as np

t4_rng = np.random.default_rng(0)
print("rng seed:", 0)  # -> 0
t4_protos = np.array([[-1.0, 0.0], [1.0, 0.0]])
print("prototypes:", t4_protos.tolist())  # -> [[-1.0, 0.0], [1.0, 0.0]]
t4_query = np.array([[-1.2, 0.0], [-0.8, 0.0], [0.8, 0.0], [1.2, 0.0]])
print("matched queries:", t4_query.tolist())  # -> [[-1.2, 0.0], [-0.8, 0.0], [0.8, 0.0], [1.2, 0.0]]
t4_y = np.array([0, 0, 1, 1])
print("true labels:", t4_y.tolist())  # -> [0, 0, 1, 1]
t4_d = np.sum((t4_query[:, None, :] - t4_protos[None, :, :]) ** 2, axis=2)
print("matched distances:", np.round(t4_d, 2).tolist())  # -> [[0.04, 4.84], [0.04, 3.24], [3.24, 0.04], [4.84, 0.04]]
t4_pred = np.argmin(t4_d, axis=1)
print("matched predictions:", t4_pred.tolist())  # -> [0, 0, 1, 1]
t4_acc = float(np.mean(t4_pred == t4_y))
print("matched accuracy:", round(t4_acc, 3))  # -> 1.0
t4_shift = np.array([1.5, 0.0])
print("shift:", t4_shift.tolist())  # -> [1.5, 0.0]
t4_shifted = t4_query + t4_shift
print("shifted queries:", np.round(t4_shifted, 1).tolist())  # -> [[0.3, 0.0], [0.7, 0.0], [2.3, 0.0], [2.7, 0.0]]

print("shifted distances:", np.round(t4_shift_d, 2).tolist())  # -> [[1.69, 0.49], [2.89, 0.09], [10.89, 1.69], [13.69, 2.89]]
```

### ✍️ Toy 5 · One support gradient adapts a slope

MAML's inner loop specializes the initialization with a support gradient before checking query loss.

```python
import numpy as np

t5_rng = np.random.default_rng(0)
```

### ✍️ Toy 6 · The outer gradient passes through adaptation

The meta-gradient is not just the query gradient; it also includes the derivative of the inner
support step.

```python
import numpy as np

t6_rng = np.random.default_rng(0)
print("rng seed:", 0)  # -> 0
t6_slopes = np.array([-1.0, 1.0, 3.0])
print("task slopes:", t6_slopes.tolist())  # -> [-1.0, 1.0, 3.0]
t6_w = 0.5
print("meta w:", t6_w)  # -> 0.5
t6_alpha = 0.5
print("inner alpha:", t6_alpha)  # -> 0.5
t6_xsq = 1.0
print("support E[x^2]:", t6_xsq)  # -> 1.0
t6_qsq = 4.0
print("query E[x^2]:", t6_qsq)  # -> 4.0
t6_w_adapt = t6_w - t6_alpha * (t6_w - t6_slopes) * t6_xsq
print("adapted weights:", t6_w_adapt.tolist())  # -> [-0.25, 0.75, 1.75]
t6_diffs = t6_w_adapt - t6_slopes
print("post-adapt diffs:", t6_diffs.tolist())  # -> [0.75, -0.25, -1.25]
t6_losses = 0.5 * (t6_diffs ** 2) * t6_qsq
print("query losses:", t6_losses.tolist())  # -> [1.125, 0.125, 3.125]
t6_chain = 1.0 - t6_alpha * t6_xsq
print("chain factor:", t6_chain)  # -> 0.5
t6_grads = t6_diffs * t6_qsq * t6_chain
print("meta-grad terms:", t6_grads.tolist())  # -> [1.5, -0.5, -2.5]
t6_mean_grad = float(np.mean(t6_grads))
print("mean meta-gradient:", round(t6_mean_grad, 3))  # -> -0.5
t6_beta = 0.1
print("outer beta:", t6_beta)  # -> 0.1
t6_w_next = t6_w - t6_beta * t6_mean_grad
print("next meta w:", round(float(t6_w_next), 3))  # -> 0.55
assert t6_mean_grad < 0.0 and t6_w_next > t6_w

plt.figure(figsize=(4.4, 2.8))
plt.bar([str(t6_s) for t6_s in t6_slopes], t6_losses, color="steelblue")
plt.xlabel("task slope")
plt.ylabel("query loss after adaptation")
plt.title("Toy 6 · outer loss after inner step")
plt.show()
```
▶ What you'll see: each task contributes a query loss and a chain-rule-scaled meta-gradient term.

### ✍️ Toy 7 · Query validation chooses adaptation length

More support updates can fit a tiny noisy support set while making the clean query set worse. The
query loss is the sanity check.


### Basic 10 — Choose a useful initialization
