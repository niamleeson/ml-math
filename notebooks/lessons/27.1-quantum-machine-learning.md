# 27.1 — Quantum Machine Learning

Quantum machine learning (QML) asks whether amplitudes, interference, measurement, and trainable quantum circuits can become useful learning features. In this lesson, we simulate tiny qubit systems with NumPy only: states are complex vectors, gates are unitary matrices, measurement probabilities are squared magnitudes, and learning still means minimizing an ordinary scalar loss.

Before the terse worked examples, we build quantum machine learning one idea at a time. Run each cell in order and read the printed intermediate values — every piece of math is spelled out so amplitudes, gates, kernels, and gradients are not black boxes. This walkthrough is self-contained (it imports what it needs) and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays, complex state vectors, unitary matrices, and small linear algebra checks.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
np.random.seed(0)  # reproducibility for sampling demos and training initial values.
```

### 1. A qubit is a normalized complex state vector

A one-qubit state is a two-entry vector $|\psi\rangle=[\alpha,\beta]^T$. The entries are **amplitudes**, not probabilities. The only normalization rule is $|\alpha|^2+|\beta|^2=1$, so the vector has unit length in complex space. That unit length matters because measurement will later turn squared magnitudes into probabilities that must add to one.

```python
psi_w = np.array([0.6 + 0.0j, 0.0 + 0.8j])  # define amplitudes for |0> and |1>; the second has a phase.
prob_w = np.abs(psi_w) ** 2  # convert amplitudes to candidate probabilities by squared magnitude.
norm_w = float(np.sum(prob_w))  # total probability mass, which must equal 1 for a valid quantum state.
print("state amplitudes:", psi_w)  # inspect complex amplitudes directly.
print("squared magnitudes:", prob_w, "sum:", round(norm_w, 3))  # verify normalization.
assert np.isclose(norm_w, 1.0)  # a valid state must have total squared magnitude 1.
```
▶ What you'll see: the amplitudes `[0.6, 0.8j]` have probabilities `0.36` and `0.64`, summing to exactly 1.

```python
plt.figure(figsize=(4, 3))  # create a compact amplitude/probability diagnostic.
plt.bar(["|0>", "|1>"], prob_w, color=["steelblue", "darkorange"])  # show measurement mass per basis state.
plt.ylim(0, 1)  # probabilities live between 0 and 1.
plt.ylabel("probability = |amplitude|²")  # label the Born-rule quantity.
plt.title("1: normalized one-qubit state")  # title the plot with the concept id.
plt.show()  # display the probability bars.
```
▶ What you'll see: outcome `|1>` is more likely even though the hidden state is still a complex vector.

*Why it's done this way:* QML starts with the same linear algebra habit as classical ML — vectors first — but the vector must stay normalized because only squared magnitudes become observable probabilities.

### 2. Measurement turns amplitudes into probabilities and expectations

Measurement in the computational basis reads `0` with probability $|\alpha|^2$ and `1` with probability $|\beta|^2$. A common scalar readout is the Pauli-$Z$ expectation, $\langle Z\rangle=P(0)-P(1)$. This is the bridge from a quantum state to a classical number a loss function can use.

```python
psi_meas_w = np.array([0.6, 0.8], dtype=complex)  # use the lesson's real-amplitude state.
probs_meas_w = np.abs(psi_meas_w) ** 2  # Born rule: probabilities are squared magnitudes.
z_exp_w = float(probs_meas_w[0] - probs_meas_w[1])  # Pauli-Z expectation equals P(0)-P(1).
print("P(0):", round(probs_meas_w[0], 3), "P(1):", round(probs_meas_w[1], 3))  # inspect probabilities.
print("<Z>:", round(z_exp_w, 3))  # inspect the scalar observable.
assert round(z_exp_w, 3) == -0.280  # matches the grounded lesson calculation.
```
▶ What you'll see: `P(1)=0.64` is larger than `P(0)=0.36`, so the $Z$ expectation is negative.

```python
shots_w = 1000  # choose a finite number of repeated measurements.
outcomes_w = np.random.default_rng(0).choice([0, 1], size=shots_w, p=probs_meas_w)  # sample measurement outcomes.
counts_w = np.array([np.sum(outcomes_w == 0), np.sum(outcomes_w == 1)])  # count observed zeros and ones.
plt.figure(figsize=(4.5, 3))  # create a probability-versus-samples figure.
plt.bar(["theory P(0)", "theory P(1)"], probs_meas_w, alpha=0.65, label="Born rule")  # plot exact probabilities.
plt.scatter([0, 1], counts_w / shots_w, color="black", zorder=3, label="1000-shot estimate")  # overlay sampled frequencies.
plt.ylim(0, 1); plt.ylabel("probability")  # keep the probability scale readable.
plt.title("2: measurement samples a distribution")  # title the plot with concept id.
plt.legend()  # distinguish theory from samples.
plt.show()  # display the measurement plot.
```
▶ What you'll see: finite shots wobble around the exact probabilities; the state vector itself is not directly printed by hardware.

*Why it's done this way:* the measurement is part of the model because it decides which scalar information reaches the optimizer; unmeasured amplitude structure is invisible to the loss.

### 3. Gates are norm-preserving matrices

An allowed gate is a unitary matrix $U$ satisfying $U^\dagger U=I$. Multiplying $U|\psi\rangle$ rotates amplitudes without changing total probability. The $R_y(\theta)$ gate is especially useful for ML because an angle can encode data or serve as a trainable parameter.

```python
theta_w = np.pi / 3  # choose the lesson angle for a concrete rotation.
Ry_w = np.array([[np.cos(theta_w / 2), -np.sin(theta_w / 2)],
                 [np.sin(theta_w / 2),  np.cos(theta_w / 2)]], dtype=complex)  # one-qubit Y rotation.
ket0_w = np.array([1.0, 0.0], dtype=complex)  # computational-basis |0> state.
rot_state_w = Ry_w @ ket0_w  # apply the gate to prepare a feature state.
rot_probs_w = np.abs(rot_state_w) ** 2  # measurement probabilities after rotation.
print("Ry(pi/3)|0>:", np.round(rot_state_w.real, 3))  # inspect amplitudes [cos(pi/6), sin(pi/6)].
print("probabilities:", np.round(rot_probs_w, 3), "<Z>:", round(float(rot_probs_w[0] - rot_probs_w[1]), 3))  # inspect readout.
assert np.isclose(np.sum(rot_probs_w), 1.0)  # unitary gates preserve normalization.
assert np.allclose(np.round(rot_probs_w, 3), [0.750, 0.250])  # grounded lesson numbers.
```
▶ What you'll see: $R_y(\pi/3)|0\rangle=[0.866,0.500]$, giving `P(0)=0.750`, `P(1)=0.250`, and `<Z>=0.500`.

```python
angles_w = np.linspace(0, 2 * np.pi, 160)  # sweep possible rotation angles.
z_curve_w = np.cos(angles_w)  # for Ry(theta)|0>, <Z> equals cos(theta).
plt.figure(figsize=(5, 3))  # create an expectation curve figure.
plt.plot(angles_w, z_curve_w, color="teal")  # show how the observable changes with the angle.
plt.scatter([theta_w], [np.cos(theta_w)], color="red", zorder=3, label="θ=π/3")  # mark the worked angle.
plt.xlabel("θ"); plt.ylabel("<Z>")  # label parameter and readout.
plt.title("3: Ry gate maps an angle to a measurable expectation")  # title the plot.
plt.legend(); plt.show()  # display the expectation curve.
```
▶ What you'll see: a smooth cosine readout, which is why circuit parameters can be optimized with gradients.

*Why it's done this way:* gates are just linear algebra with a physics constraint — preserve norm — so a circuit is a stack of safe matrix multiplications before measurement.

### 4. Interference makes branches reinforce or cancel

A Hadamard gate sends $|0\rangle$ to an equal superposition $[1/\sqrt2,1/\sqrt2]$. Equal probabilities are not just ignorance: if later gates recombine paths, amplitudes can add or subtract. Applying a second Hadamard to that superposition returns exactly to $|0\rangle$ by constructive and destructive interference.

```python
H_w = (1 / np.sqrt(2)) * np.array([[1, 1], [1, -1]], dtype=complex)  # Hadamard gate.
psi_after_h_w = H_w @ ket0_w  # create equal superposition.
psi_after_hh_w = H_w @ psi_after_h_w  # recombine paths with a second Hadamard.
print("H|0>:", np.round(psi_after_h_w.real, 3))  # inspect equal amplitudes.
print("HH|0>:", np.round(psi_after_hh_w.real, 3))  # inspect return to |0>.
assert np.allclose(psi_after_hh_w, ket0_w)  # H is its own inverse, so two H gates recover |0>.
```
▶ What you'll see: one Hadamard spreads probability evenly; two Hadamards cancel the `|1>` branch and recover `|0>`.

```python
probs_h_w = np.abs(psi_after_h_w) ** 2  # probabilities after one Hadamard.
probs_hh_w = np.abs(psi_after_hh_w) ** 2  # probabilities after two Hadamards.
x_w = np.arange(2)  # bar positions for |0>, |1>.
plt.figure(figsize=(4.8, 3))  # create grouped probability bars.
plt.bar(x_w - 0.18, probs_h_w, width=0.36, label="after H", color="mediumpurple")  # show superposition measurement probabilities.
plt.bar(x_w + 0.18, probs_hh_w, width=0.36, label="after H then H", color="seagreen")  # show interference result.
plt.xticks(x_w, ["|0>", "|1>"]); plt.ylim(0, 1.05)  # label basis states and bound probabilities.
plt.ylabel("measurement probability"); plt.title("4: interference changes readable probabilities")  # label the figure.
plt.legend(); plt.show()  # display grouped bars.
```
▶ What you'll see: the second Hadamard turns a 50/50 distribution into certainty for `|0>`.

*Why it's done this way:* useful quantum circuits do not merely store many amplitudes; they arrange interference so the measured outcomes favor the desired answer.

### 5. A quantum feature map defines a kernel

A feature map prepares a state from data, for example $|\phi(x)\rangle=R_y(x)|0\rangle$. A quantum kernel compares two prepared states by squared inner product, $K(a,b)=|\langle\phi(a)|\phi(b)\rangle|^2=\cos^2((a-b)/2)$ for this one-qubit map. This is the practical bridge to classical ML: data becomes a state, and similarity becomes an overlap.

```python
def feature_state_w(x):  # prepare a one-qubit feature state from scalar x.
    return np.array([np.cos(x / 2), np.sin(x / 2)], dtype=complex)  # Ry(x)|0> amplitudes.

a_w, b_close_w, b_far_w = 0.2, 0.7, 2.6  # choose the grounded close and far comparisons.
K_close_w = float(abs(np.vdot(feature_state_w(a_w), feature_state_w(b_close_w))) ** 2)  # state-overlap kernel.
K_far_w = float(abs(np.vdot(feature_state_w(a_w), feature_state_w(b_far_w))) ** 2)  # far-state overlap.
print("K(0.2, 0.7):", round(K_close_w, 3))  # inspect high similarity.
print("K(0.2, 2.6):", round(K_far_w, 3))  # inspect low similarity.
assert round(K_close_w, 3) == 0.939 and round(K_far_w, 3) == 0.131  # grounded lesson numbers.
```
▶ What you'll see: nearby angles have high overlap, while separated angles have low overlap.

```python
xs_w = np.linspace(0, np.pi, 50)  # small dataset of scalar inputs.
Kmat_w = np.array([[abs(np.vdot(feature_state_w(xi), feature_state_w(xj))) ** 2 for xj in xs_w] for xi in xs_w])  # pairwise kernel matrix.
plt.figure(figsize=(4.2, 3.4))  # create a kernel heatmap.
plt.imshow(Kmat_w, cmap="viridis", origin="lower", extent=[0, np.pi, 0, np.pi], aspect="auto")  # show similarities over input pairs.
plt.colorbar(label="K(x, x')")  # add similarity scale.
plt.xlabel("x'"); plt.ylabel("x")  # label the two inputs being compared.
plt.title("5: quantum feature-map kernel")  # title the heatmap.
plt.show()  # display the kernel matrix.
```
▶ What you'll see: a bright diagonal, because each state is most similar to itself and less similar as angles separate.

*Why it's done this way:* the circuit-induced kernel matters only if its geometry separates labels better than a classical baseline; the state preparation is the model design choice.

### 6. A variational circuit exposes a scalar loss

A variational quantum circuit uses trainable angles. In the simplest one-qubit classifier, encode $x$ with $R_y(x)$, apply a trainable $R_y(\theta)$, then measure $Z$. The prediction is $\hat y=\langle Z\rangle=\cos(x+\theta)$, and the loss can be ordinary squared error.

```python
x_data_w = np.array([-1.0, -0.2, 0.3, 1.1])  # tiny scalar dataset.
y_data_w = np.sign(x_data_w)  # labels in {-1, +1} for a toy classifier readout.
y_data_w[y_data_w == 0] = 1  # avoid zero labels if a data point lands exactly at 0.
theta_grid_w = np.linspace(-np.pi, np.pi, 181)  # scan parameter values for a cost landscape.
loss_grid_w = np.array([np.mean((np.cos(x_data_w + th) - y_data_w) ** 2) for th in theta_grid_w])  # squared loss for each theta.
best_theta_w = float(theta_grid_w[np.argmin(loss_grid_w)])  # best grid parameter.
print("best θ on grid:", round(best_theta_w, 3), "best loss:", round(float(np.min(loss_grid_w)), 3))  # inspect landscape minimum.
assert loss_grid_w.min() < loss_grid_w.max()  # the parameter changes the model output.
```
▶ What you'll see: the same circuit form gives a scalar loss for each parameter value.

```python
plt.figure(figsize=(5, 3))  # create a one-dimensional cost landscape.
plt.plot(theta_grid_w, loss_grid_w, color="purple")  # show loss as theta changes.
plt.axvline(best_theta_w, color="red", linestyle="--", label="best grid θ")  # mark the best parameter.
plt.xlabel("θ"); plt.ylabel("mean squared loss")  # label parameter and objective.
plt.title("6: variational-circuit cost landscape")  # title the plot.
plt.legend(); plt.show()  # display the landscape.
```
▶ What you'll see: a trainable angle creates a smooth classical objective, even though predictions came from a circuit readout.

*Why it's done this way:* QML training is still optimization of a real-valued loss; the quantum part defines the prediction map and observable being optimized.

### 7. Parameter-shift gradients train the circuit

For rotation gates, the derivative of an expectation can be computed by evaluating the same circuit at shifted parameters: $\partial_\theta f(\theta)=\frac{1}{2}\{f(\theta+\pi/2)-f(\theta-\pi/2)\}$. This means a classical optimizer can use gradients without differentiating through hardware internals.

```python
theta_ps_w = 1.2  # use the grounded lesson parameter.
y_target_w = 1.0  # target label.
pred_ps_w = float(np.cos(theta_ps_w))  # one-qubit Ry(theta)|0> Z expectation.
loss_ps_w = (pred_ps_w - y_target_w) ** 2  # squared loss.
dexp_ps_w = 0.5 * (np.cos(theta_ps_w + np.pi / 2) - np.cos(theta_ps_w - np.pi / 2))  # parameter-shift derivative of cos(theta).
grad_ps_w = 2 * (pred_ps_w - y_target_w) * dexp_ps_w  # chain rule for squared loss.
print("prediction:", round(pred_ps_w, 3), "loss:", round(loss_ps_w, 3), "gradient:", round(grad_ps_w, 3))  # inspect training pieces.
assert round(pred_ps_w, 3) == 0.362 and round(loss_ps_w, 3) == 0.407 and round(grad_ps_w, 3) == 1.189  # grounded numbers.
```
▶ What you'll see: the optimizer receives an ordinary gradient, `1.189`, even though the prediction is a circuit expectation.

```python
thetas_ps_w = np.linspace(0, np.pi, 120)  # sweep parameters for gradient visualization.
losses_ps_w = (np.cos(thetas_ps_w) - y_target_w) ** 2  # loss curve against theta.
plt.figure(figsize=(5, 3))  # create a loss-and-gradient plot.
plt.plot(thetas_ps_w, losses_ps_w, color="navy", label="loss")  # show the objective.
plt.scatter([theta_ps_w], [loss_ps_w], color="red", label="θ=1.2")  # mark the worked parameter.
plt.arrow(theta_ps_w, loss_ps_w, -0.18, -0.18 * grad_ps_w, width=0.01, color="red", length_includes_head=True)  # show descent direction.
plt.xlabel("θ"); plt.ylabel("loss")  # label axes.
plt.title("7: parameter-shift supplies a trainable gradient")  # title the plot.
plt.legend(); plt.show()  # display the gradient visualization.
```
▶ What you'll see: the arrow points left/down because a positive gradient means gradient descent reduces θ.

*Why it's done this way:* parameter shift turns quantum expectation derivatives into extra circuit evaluations, so the training loop remains classical gradient descent around a quantum readout.

## 🛠️ Setup

```python
import numpy as np  # load NumPy for complex state vectors, gates, kernels, gradients, and assertions.
import matplotlib.pyplot as plt  # load Matplotlib for state bars, probability plots, landscapes, and loss curves.
from math import pi  # use the standard-library pi constant in small formulas.
np.random.seed(0)  # make stochastic measurement and initialization examples reproducible.

I2 = np.eye(2, dtype=complex)  # identity gate for one qubit.
X = np.array([[0, 1], [1, 0]], dtype=complex)  # Pauli-X bit-flip gate.
Z = np.array([[1, 0], [0, -1]], dtype=complex)  # Pauli-Z observable used for readout.
H = (1 / np.sqrt(2)) * np.array([[1, 1], [1, -1]], dtype=complex)  # Hadamard gate for superposition and interference.
ket0 = np.array([1.0, 0.0], dtype=complex)  # computational basis state |0>.
ket1 = np.array([0.0, 1.0], dtype=complex)  # computational basis state |1>.

def Ry(theta):  # define a one-qubit rotation around the y axis.
    return np.array([[np.cos(theta / 2), -np.sin(theta / 2)], [np.sin(theta / 2), np.cos(theta / 2)]], dtype=complex)  # unitary rotation matrix.

def probs(state):  # convert a normalized state vector into computational-basis probabilities.
    state = np.asarray(state, dtype=complex)  # ensure complex arithmetic is used consistently.
    p = np.abs(state) ** 2  # Born rule: squared magnitudes are probabilities.
    assert np.isclose(np.sum(p), 1.0, atol=1e-8)  # guard that the state is normalized before interpreting probabilities.
    return p  # return P(0), P(1), or larger basis probabilities.

def z_expectation(state):  # compute the Pauli-Z expectation for a one-qubit state.
    p = probs(state)  # read probabilities in the computational basis.
    return float(p[0] - p[1])  # <Z> = P(0)-P(1).

def feature_state(x):  # encode a scalar x as Ry(x)|0>.
    state = Ry(x) @ ket0  # rotate the |0> state by the data angle.
    assert np.isclose(np.linalg.norm(state), 1.0)  # unitary preparation preserves norm.
    return state  # return the prepared feature state.

def qkernel(a, b):  # compute the state-overlap kernel for two scalar inputs.
    return float(abs(np.vdot(feature_state(a), feature_state(b))) ** 2)  # squared inner product between prepared states.
```

### Basic 1 — Normalize a qubit state

**Goal.** Build a valid one-qubit state and verify its squared magnitudes sum to one, because no measurement probabilities make sense until normalization holds. We build it in 2 steps.

```python
amp_b1 = np.array([3 + 0j, 4 + 0j], dtype=complex)  # start with an unnormalized amplitude vector in a familiar 3-4-5 ratio.
state_b1 = amp_b1 / np.linalg.norm(amp_b1)  # divide by vector length so the state has norm 1.
print("normalized state:", np.round(state_b1, 3))  # inspect amplitudes after normalization.
assert np.isclose(np.linalg.norm(state_b1), 1.0)  # verify valid quantum-state length.
```
▶ What you'll see: the unnormalized `[3,4]` vector becomes `[0.6,0.8]`.

```python
prob_b1 = np.abs(state_b1) ** 2  # convert normalized amplitudes into measurement probabilities.
print("probabilities:", np.round(prob_b1, 3), "sum:", round(float(prob_b1.sum()), 3))  # inspect Born-rule probabilities.
plt.figure(figsize=(4, 3))  # create a compact probability bar chart.
plt.bar(["|0>", "|1>"], prob_b1, color="teal")  # show probability in each basis state.

```
▶ What you'll see: probabilities `0.36` and `0.64` add to one.

👀 Takeaway: amplitudes are not probabilities, but their squared magnitudes must form a probability distribution.

### Basic 5 — Check that a gate is unitary

**Goal.** Verify $H^\dagger H=I$, because only norm-preserving matrices are valid closed-system gates. We build it in 2 steps.

```python
unitarity_b5 = H.conj().T @ H  # multiply H dagger by H to test the unitary condition.
print("H†H:\n", np.round(unitarity_b5.real, 3))  # inspect the identity matrix result.
assert np.allclose(unitarity_b5, I2)  # Hadamard is unitary.
```
▶ What you'll see: the product is the identity matrix.

```python
state_b5 = np.array([0.6, 0.8], dtype=complex)  # choose a valid input state.
out_b5 = H @ state_b5  # apply the Hadamard gate.
plt.figure(figsize=(4, 3))  # create a before/after norm-preservation plot.
plt.bar(["||ψ||² before", "||Hψ||² after"], [np.linalg.norm(state_b5) ** 2, np.linalg.norm(out_b5) ** 2], color=["gray", "seagreen"])  # compare squared norms.
```

### Advanced 1 — Train a variational quantum classifier from scratch

**Goal.** Implement a tiny variational quantum classifier with NumPy state vectors and parameter-shift gradients, because this is the core QML training loop without Qiskit, PennyLane, or deep-learning libraries. We build it in 5 steps.

```python

    return np.cos(x_vals_a1 + p_a1[0]) * np.cos(p_a1[1])  # simulated expectation after data and trainable rotations.

def loss_a1(p_a1):  # define mean squared error for current parameters.
    return float(np.mean((predict_a1(x_a1, p_a1) - y_a1) ** 2))  # scalar objective.

for step_a1 in range(100):  # run gradient descent.
    pred_now_a1 = predict_a1(x_a1, params_a1)  # evaluate current circuit expectations.
    base_loss_a1 = float(np.mean((pred_now_a1 - y_a1) ** 2))  # evaluate current loss.

    losses_a1.append(base_loss_a1)  # store loss history.
print("final params:", np.round(params_a1, 3), "loss start->end:", round(losses_a1[0], 3), "->", round(losses_a1[-1], 3))  # inspect progress.
assert losses_a1[-1] < losses_a1[0]  # verify training reduced loss.
```

### Advanced 4 — Include shot noise in training gradients

**Goal.** Compare exact and shot-based parameter-shift gradients, because real quantum hardware estimates expectations from finite samples. We build it in 4 steps.

```python
theta_a4 = 0.9  # current trainable angle.
y_a4 = -1.0  # target expectation.
shots_a4 = 300  # finite measurement budget per shifted circuit.
rng_a4 = np.random.default_rng(4)  # local reproducible sampling.
print("theta:", theta_a4, "target:", y_a4, "shots:", shots_a4)  # inspect experiment setup.
```
▶ What you'll see: the gradient estimate will be noisy because each shifted expectation uses only 300 shots.

```python
def sample_z_a4(theta_in_a4):  # estimate <Z> from finite shots for Ry(theta)|0>.
    p0_a4 = (1 + np.cos(theta_in_a4)) / 2  # convert exact expectation to P(0).
    draws_a4 = rng_a4.choice([1.0, -1.0], size=shots_a4, p=[p0_a4, 1 - p0_a4])  # sample Z eigenvalues +1 and -1.
    return float(np.mean(draws_a4))  # finite-shot expectation estimate.

exact_pred_a4 = float(np.cos(theta_a4))  # exact expectation.
exact_grad_a4 = 2 * (exact_pred_a4 - y_a4) * (-np.sin(theta_a4))  # exact squared-loss gradient.
print("exact pred:", round(exact_pred_a4, 3), "exact grad:", round(exact_grad_a4, 3))  # inspect exact values.
```

```python
estimates_a4 = []  # store repeated noisy gradient estimates.
for rep_a4 in range(80):  # repeat the shot-based estimate many times.
    pred_hat_a4 = sample_z_a4(theta_a4)  # estimate current expectation.
    plus_hat_a4 = sample_z_a4(theta_a4 + np.pi / 2)  # estimate shifted plus expectation.
    minus_hat_a4 = sample_z_a4(theta_a4 - np.pi / 2)  # estimate shifted minus expectation.
    d_hat_a4 = 0.5 * (plus_hat_a4 - minus_hat_a4)  # parameter-shift expectation derivative estimate.
    estimates_a4.append(2 * (pred_hat_a4 - y_a4) * d_hat_a4)  # noisy chain-rule loss gradient.
estimates_a4 = np.array(estimates_a4)  # convert to array for statistics.
print("shot-grad mean:", round(float(estimates_a4.mean()), 3), "std:", round(float(estimates_a4.std()), 3))  # inspect noise.
```

```python
plt.figure(figsize=(5, 3))  # create a histogram of noisy gradients.
plt.hist(estimates_a4, bins=16, color="mediumpurple", alpha=0.8)  # show repeated shot-based gradients.
plt.axvline(exact_grad_a4, color="red", linestyle="--", label="exact gradient")  # mark exact gradient.
plt.title("Advanced 4: shot noise in parameter-shift gradients")  # title the plot.
plt.xlabel("estimated dL/dθ"); plt.ylabel("count")  # label axes.
plt.legend(); plt.show()  # display histogram.
```
▶ What you'll see: shot-based gradients cluster around the exact value but have visible spread.

👀 Takeaway: finite measurement budgets turn QML optimization into noisy stochastic optimization.

### Advanced 5 — Sweep trainability across random initializations

**Goal.** Train the same small variational circuit from many starting angles, because initialization can decide whether a circuit reaches a good basin. We build it in 4 steps.

```python

final_losses_a5 = []  # store final loss for each initialization.
trajectories_a5 = []  # store a few loss curves.
print("number of initializations:", len(inits_a5))  # inspect sweep size.
```
▶ What you'll see: the same problem will be trained from 13 different starting angles.

```python

    theta_cur_a5 = float(init_a5)  # initialize current parameter.
    curve_a5 = []  # loss trajectory for this initialization.
    for step_a5 in range(18):  # run a short gradient descent so initialization differences remain visible.
        pred_a5 = np.cos(x_a5 + theta_cur_a5)  # circuit expectations.
        loss_cur_a5 = float(np.mean((pred_a5 - y_a5) ** 2))  # current loss.
```
