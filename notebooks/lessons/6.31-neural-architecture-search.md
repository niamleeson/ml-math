# 6.31 — Neural Architecture Search

Neural Architecture Search (NAS) treats the neural-network design itself as the object being optimized: instead of only learning weights, we compare candidate architectures by validation loss, training stability, and compute cost. In this lesson, we build a tiny NAS world from scratch in NumPy so the architecture objective, candidate encoding, validation ranking, and cost tradeoffs are visible cell by cell.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build neural architecture search one idea at a time. Run each cell in order and read the printed intermediate values — every number is deliberately small so the search logic is inspectable. This walkthrough is self-contained and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays, small neural nets, losses, and search loops.
import matplotlib.pyplot as plt  # visual debugging for rankings, curves, and tradeoffs.
np.random.seed(0)  # reproducibility for every random candidate and toy dataset.
```

### 1. The architecture objective: search over designs, not just weights

NAS starts by separating two things that are often blended together: the **weights** learned inside a network and the **architecture** that decides how many units, layers, gates, or operations the weights live in. For each architecture $a$, we train weights $w_a$ on training data, then choose the architecture with the smallest validation loss: $a^*=\arg\min_{a\in\mathcal A} L_{val}(w_a,a)$. The validation set matters because a larger architecture can fit training points while failing to generalize.

```python
arch_names_w = np.array(["tiny", "wide", "deep", "wide+skip"])  # candidate architectures in the search space.
val_loss_w = np.array([0.42, 0.31, 0.36, 0.28])  # validation loss after each candidate has been trained.
train_loss_w = np.array([0.46, 0.18, 0.20, 0.16])  # training loss can favor larger models too strongly.
print("candidates:", arch_names_w)
print("validation losses:", val_loss_w)
```
▶ What you'll see: four architecture candidates, each with a validation loss that will decide the winner.

```python
best_idx_w = int(np.argmin(val_loss_w))  # architecture objective chooses the smallest validation loss.
print("best architecture:", arch_names_w[best_idx_w])
print("best validation loss:", val_loss_w[best_idx_w])
assert arch_names_w[best_idx_w] == "wide+skip"
assert round(float(val_loss_w[best_idx_w]), 2) == 0.28
```
▶ What you'll see: `wide+skip` wins because its validation loss is 0.28, even though several candidates train well.

```python
x_w = np.arange(len(arch_names_w))
plt.figure(figsize=(5, 3))
plt.bar(x_w - 0.18, train_loss_w, width=0.36, label="train", color="gray")
plt.bar(x_w + 0.18, val_loss_w, width=0.36, label="validation", color="seagreen")
plt.xticks(x_w, arch_names_w, rotation=15)
plt.ylabel("loss")
plt.title("1: NAS selects by validation loss")
plt.legend()
plt.show()
```
▶ What you'll see: the validation bars, not the training bars, determine the selected architecture.

*Why it's done this way:* architecture is a capacity decision, so training loss alone rewards memorization. Validation loss estimates how the trained weights behave on fresh data, which is why NAS optimizes $L_{val}(w_a,a)$ rather than the raw training objective.

### 2. Candidate networks as composed affine maps and gates

A candidate architecture is not magic; it is a composed function. The smallest useful scratch pass is an affine signal followed by a gate such as ReLU. If a layer receives $x=[1.5,-0.5]$, weights $[1.2,0.2]$, and bias $0.4$, its pre-activation is $1.2\cdot1.5+0.2\cdot(-0.5)+0.4=2.1$, then ReLU keeps it positive. NAS changes how many such maps exist and how they connect.

```python
x_signal_w = np.array([1.5, -0.5])  # two input features for a tiny candidate block.
weight_w = np.array([1.2, 0.2])  # one neuron's incoming weights.
bias_w = 0.4  # visible bias from the lesson arithmetic.
z_w = float(weight_w @ x_signal_w + bias_w)  # affine signal before the gate.
print("affine pieces:", weight_w * x_signal_w, "+ bias", bias_w)
print("pre-activation z:", round(z_w, 3))
assert round(z_w, 3) == 2.100
```
▶ What you'll see: the affine signal is exactly `1.8 - 0.1 + 0.4 = 2.1`.

```python
h_w = max(0.0, z_w)  # ReLU gate preserves positive signals and clips negative ones.
print("ReLU(z):", round(h_w, 3))
assert round(h_w, 3) == 2.100
```
▶ What you'll see: the positive signal passes through unchanged.

```python
zs_w = np.linspace(-2, 3, 80)
relu_w = np.maximum(0, zs_w)
plt.figure(figsize=(4.5, 3))
plt.plot(zs_w, relu_w, color="purple")
plt.scatter([z_w], [h_w], color="red", label="our signal")
plt.axhline(0, color="black", linewidth=0.6)
plt.title("2: ReLU gates an affine signal")
plt.xlabel("pre-activation z")
plt.ylabel("activation max(0,z)")
plt.legend()
plt.show()
```
▶ What you'll see: negative signals are erased, while our positive signal sits on the identity branch.

*Why it's done this way:* affine maps mix features linearly, while gates make the composed network nonlinear. NAS searches over where to spend these blocks because more gates increase expressiveness but also make optimization and compute harder.

### 3. Weight training inside each architecture

NAS compares architectures only after each candidate has had a fair chance to train its weights. The training knob is still ordinary gradient descent: if one scalar parameter is $2.0$, learning rate is $0.06$, and gradient is $1.65$, the update is $2.0-0.06\cdot1.65=1.901$. The architecture search sits outside this inner optimization loop.

```python
theta_w = 2.0  # current scalar weight in one candidate architecture.
eta_w = 0.06  # learning rate for the inner weight optimizer.
grad_w = 1.65  # derivative of training loss with respect to theta.
theta_new_w = theta_w - eta_w * grad_w  # gradient descent update.
print("old theta:", theta_w, "gradient:", grad_w, "new theta:", round(theta_new_w, 3))
assert round(theta_new_w, 3) == 1.901
```
▶ What you'll see: one reliable nudge moves the weight from 2.000 to 1.901.

```python
theta_path_w = [theta_w]
for step_w in range(8):
    grad_step_w = theta_path_w[-1] - 1.0  # gradient of 0.5*(theta-1)^2.
    theta_path_w.append(theta_path_w[-1] - eta_w * grad_step_w)
print("theta path:", np.round(theta_path_w, 3))
assert theta_path_w[-1] < theta_path_w[0]
```
▶ What you'll see: repeated small steps drift toward the optimum at 1.0.

```python
plt.figure(figsize=(4.5, 3))
plt.plot(theta_path_w, marker="o", color="teal")
plt.axhline(1.0, color="black", linestyle="--", label="optimum")
plt.title("3: inner-loop weight training")
plt.xlabel("step")
plt.ylabel("theta")
plt.legend()
plt.show()
```
▶ What you'll see: the parameter approaches the target smoothly instead of jumping in one step.

*Why it's done this way:* NAS is bi-level in spirit: weights are optimized inside each architecture, then architectures are compared outside that process. Without the inner loop, we would rank random initializations rather than trained designs.

### 4. Turning architecture scores into a calibrated comparison

Search algorithms often turn raw architecture scores into probabilities for sampling or weighting candidates. A softmax converts scores into positive weights that sum to one. Comparing score $2.1$ against baseline $0.4$ gives $e^{2.1}/(e^{2.1}+e^{0.4})\approx0.846$, so the better-scoring candidate is much more likely but not the only possible choice.

```python
score_w = 2.1
baseline_w = 0.4
exp_score_w = np.exp(score_w)
exp_base_w = np.exp(baseline_w)
prob_w = exp_score_w / (exp_score_w + exp_base_w)
print("exp(score):", round(exp_score_w, 3), "exp(base):", round(exp_base_w, 3))
print("softmax probability:", round(prob_w, 3))
assert round(prob_w, 3) == 0.846
```
▶ What you'll see: the 2.1-scored candidate receives probability about 0.846.

```python
scores_w = np.array([0.4, 1.0, 1.7, 2.1])
probs_w = np.exp(scores_w) / np.sum(np.exp(scores_w))
print("candidate probabilities:", np.round(probs_w, 3))
assert round(float(np.sum(probs_w)), 6) == 1.0
```
▶ What you'll see: probabilities sum to 1, with the largest score receiving the largest share.

```python
plt.figure(figsize=(4.6, 3))
plt.bar(["a0", "a1", "a2", "a3"], probs_w, color="darkorange")
plt.ylabel("sampling probability")
plt.title("4: softmax turns scores into search probabilities")
plt.show()
```
▶ What you'll see: the search distribution concentrates on high-scoring architectures but still leaves exploration mass.

*Why it's done this way:* raw scores have arbitrary scale, while a softmax gives a normalized comparison. Keeping nonzero probability on weaker candidates supports exploration, which matters because early validation estimates are noisy.

### 5. Scale, normalization, and memory bookkeeping

Architecture choices change activation scale and hardware cost. If the signal $2.1$ is normalized using mean $1.0$ and variance $0.25$, the normalized value is $(2.1-1.0)/\sqrt{0.25001}\approx2.2$. If the candidate stores 5 activation vectors of length 128 as 32-bit floats, memory is $5\cdot128\cdot4/1024=2.5$ KB. NAS must track both numerical behavior and resource use.

```python
signal_w = 2.1
mean_w = 1.0
var_w = 0.25
eps_w = 1e-5
normed_w = (signal_w - mean_w) / np.sqrt(var_w + eps_w)
print("normalized signal:", round(normed_w, 3))
assert round(normed_w, 3) == 2.200
```
▶ What you'll see: the signal is 2.2 standard deviations above the local mean.

```python
vectors_w = 5
width_w = 128
bytes_per_float_w = 4
memory_kb_w = vectors_w * width_w * bytes_per_float_w / 1024
print("activation memory KB:", round(memory_kb_w, 3))
assert round(memory_kb_w, 3) == 2.500
```
▶ What you'll see: even a tiny activation block has a measurable memory cost.

```python
widths_w = np.array([32, 64, 128, 256])
mem_w = vectors_w * widths_w * bytes_per_float_w / 1024
plt.figure(figsize=(4.5, 3))
plt.plot(widths_w, mem_w, marker="o", color="crimson")
plt.title("5: width increases activation memory")
plt.xlabel("hidden width")
plt.ylabel("KB for 5 activation vectors")
plt.show()
```
▶ What you'll see: memory grows linearly with width, so architecture quality is never just validation loss.

*Why it's done this way:* normalization keeps gradients on a usable scale, while memory accounting keeps the design deployable. NAS objectives often add penalties because the best validation loss may be too expensive to train or serve.

### 6. Cost-aware search and the Pareto view

A practical NAS score often combines validation loss with a cost penalty, such as $L_{val}+\alpha\cdot\text{cost}$. But one scalar penalty is not the only view: the Pareto frontier shows architectures that are not simultaneously worse in both loss and cost. This makes the tradeoff explicit instead of hiding it in one number.

```python
names_w = np.array(["tiny", "wide", "deep", "skip", "huge"])
loss_w = np.array([0.42, 0.31, 0.36, 0.28, 0.25])
cost_w = np.array([1.0, 2.5, 2.0, 3.0, 7.0])
alpha_w = 0.03
objective_w = loss_w + alpha_w * cost_w
print("cost-aware objective:", np.round(objective_w, 3))
assert round(float(objective_w[3]), 3) == 0.370
```
▶ What you'll see: `huge` has the lowest raw loss but pays a large cost penalty.

```python
best_cost_idx_w = int(np.argmin(objective_w))
pareto_w = []
for i_w in range(len(names_w)):
    dominated_w = np.any((loss_w <= loss_w[i_w]) & (cost_w <= cost_w[i_w]) & ((loss_w < loss_w[i_w]) | (cost_w < cost_w[i_w])))
    pareto_w.append(not dominated_w)
pareto_w = np.array(pareto_w)
print("cost-aware winner:", names_w[best_cost_idx_w])
print("Pareto candidates:", names_w[pareto_w])
assert names_w[best_cost_idx_w] == "skip"
```
▶ What you'll see: a scalar penalty selects `wide`, while the frontier keeps several defensible tradeoffs.

```python
plt.figure(figsize=(4.8, 3.4))
plt.scatter(cost_w, loss_w, s=90, color=np.where(pareto_w, "seagreen", "gray"))
for i_w, name_w in enumerate(names_w):
    plt.text(cost_w[i_w] + 0.05, loss_w[i_w], name_w)
plt.xlabel("relative compute cost")
plt.ylabel("validation loss")
plt.title("6: NAS as a loss-cost tradeoff")
plt.show()
```
▶ What you'll see: Pareto candidates sit on the lower-left boundary; dominated models are worse in both dimensions.

*Why it's done this way:* architecture search is a constrained optimization problem. A cost-aware objective encodes one deployment preference, while the Pareto view preserves alternatives when the final budget is not yet fixed.

### ✍️ Toy 1 · Validation loss chooses the architecture

NAS ranks trained candidate designs by validation loss, not by the training loss that a large model can drive down too easily.

```python
import numpy as np
import matplotlib.pyplot as plt

t1_rng = np.random.default_rng(0)                 # seeded for reproducibility.
t1_names = np.array(["tiny", "wide", "deep", "skip", "cheap", "huge"])
t1_train_loss = np.array([0.52, 0.22, 0.19, 0.21, 0.49, 0.08])
t1_val_loss = np.array([0.48, 0.33, 0.36, 0.29, 0.44, 0.40])
print("candidate names:", t1_names.tolist())                         # -> ['tiny', 'wide', 'deep', 'skip', 'cheap', 'huge']
print("training losses:", t1_train_loss.tolist())                    # -> [0.52, 0.22, 0.19, 0.21, 0.49, 0.08]
print("validation losses:", t1_val_loss.tolist())                    # -> [0.48, 0.33, 0.36, 0.29, 0.44, 0.4]
t1_gap = t1_val_loss - t1_train_loss
print("validation minus training:", np.round(t1_gap, 2).tolist())    # -> [-0.04, 0.11, 0.17, 0.08, -0.05, 0.32]
t1_best = int(np.argmin(t1_val_loss))
print("best by validation:", t1_names[t1_best], round(float(t1_val_loss[t1_best]), 2))  # -> skip 0.29
assert t1_names[t1_best] == "skip"

plt.figure(figsize=(5.4, 3.0))
t1_x = np.arange(t1_names.size)
t1_width = 0.36
plt.bar(t1_x - t1_width / 2, t1_train_loss, width=t1_width, label="train", color="gray")
plt.bar(t1_x + t1_width / 2, t1_val_loss, width=t1_width, label="validation", color="seagreen")
plt.xticks(t1_x, t1_names, rotation=15)
plt.ylabel("loss")
plt.title("Toy 1 · NAS selects by validation loss")
plt.legend()
plt.show()
```
▶ What you'll see: `huge` wins training loss, but `skip` has the smallest validation loss and is selected.

### ✍️ Toy 2 · Affine maps feed ReLU gates

A candidate block first mixes features with weights and a bias, then ReLU clips any negative pre-activation to zero.

```python
import numpy as np

t2_rng = np.random.default_rng(0)                 # seeded for reproducibility.
t2_x = np.array([[2.0, -1.0], [0.0, 1.0], [-2.0, 1.0]])
t2_w = np.array([1.0, -0.5])
t2_b = 0.25
print("inputs:", t2_x.tolist())                                      # -> [[2.0, -1.0], [0.0, 1.0], [-2.0, 1.0]]
print("weights:", t2_w.tolist(), "bias:", t2_b)                     # -> [1.0, -0.5] bias 0.25
t2_contrib = t2_x * t2_w
print("per-feature contributions:", t2_contrib.tolist())             # -> [[2.0, 0.5], [0.0, -0.5], [-2.0, -0.5]]
t2_z = t2_contrib.sum(axis=1) + t2_b
print("pre-activations:", t2_z.tolist())                             # -> [2.75, -0.25, -2.25]
t2_h = np.maximum(t2_z, 0.0)
print("ReLU activations:", t2_h.tolist())                            # -> [2.75, 0.0, 0.0]
assert np.allclose(t2_h, [2.75, 0.0, 0.0])

plt.figure(figsize=(4.8, 3.0))
t2_idx = np.arange(t2_z.size)
plt.bar(t2_idx - 0.18, t2_z, width=0.36, label="z", color="steelblue")
plt.bar(t2_idx + 0.18, t2_h, width=0.36, label="ReLU(z)", color="darkorange")
plt.axhline(0, color="black", linewidth=0.8)
plt.xlabel("example")
plt.ylabel("signal")
plt.title("Toy 2 · gates erase negative signals")
plt.legend()
plt.show()
```
▶ What you'll see: only the first pre-activation is positive, so the other two bars drop to zero after ReLU.

### ✍️ Toy 3 · Inner-loop training takes small gradient steps

Architecture search wraps an ordinary weight optimizer. On a quadratic loss, each gradient step moves the scalar weight toward the target.

```python
import numpy as np

t3_rng = np.random.default_rng(0)                 # seeded for reproducibility.
t3_theta0 = 2.5
t3_target = 1.0
t3_eta = 0.2
print("start theta:", t3_theta0)                                     # -> 2.5
print("target theta:", t3_target)                                    # -> 1.0
t3_grad0 = t3_theta0 - t3_target
print("gradient 0:", round(float(t3_grad0), 3))                      # -> 1.5
t3_theta1 = t3_theta0 - t3_eta * t3_grad0
print("theta 1:", round(float(t3_theta1), 3))                        # -> 2.2
t3_grad1 = t3_theta1 - t3_target
print("gradient 1:", round(float(t3_grad1), 3))                      # -> 1.2
t3_theta2 = t3_theta1 - t3_eta * t3_grad1
print("theta 2:", round(float(t3_theta2), 3))                        # -> 1.96
t3_grad2 = t3_theta2 - t3_target
print("gradient 2:", round(float(t3_grad2), 3))                      # -> 0.96
t3_theta3 = t3_theta2 - t3_eta * t3_grad2
print("theta 3:", round(float(t3_theta3), 3))                        # -> 1.768
t3_grad3 = t3_theta3 - t3_target
print("gradient 3:", round(float(t3_grad3), 3))                      # -> 0.768
t3_theta4 = t3_theta3 - t3_eta * t3_grad3
print("theta 4:", round(float(t3_theta4), 4))                        # -> 1.6144
t3_path = np.array([t3_theta0, t3_theta1, t3_theta2, t3_theta3, t3_theta4])
print("theta path:", np.round(t3_path, 4).tolist())                  # -> [2.5, 2.2, 1.96, 1.768, 1.6144]
assert t3_target < t3_path[-1] < t3_path[0]

plt.figure(figsize=(4.8, 3.0))
plt.plot(np.arange(t3_path.size), t3_path, marker="o", color="teal")
plt.axhline(t3_target, linestyle="--", color="black", label="target")
plt.xlabel("step")
plt.ylabel("theta")
plt.title("Toy 3 · inner weights train before ranking")
plt.legend()
plt.show()
```
▶ What you'll see: the parameter descends smoothly toward `1.0` instead of jumping there in one move.

### ✍️ Toy 4 · Softmax turns architecture scores into probabilities

Search scores become a sampling distribution by shifting, exponentiating, and normalizing.

```python
import numpy as np

t4_rng = np.random.default_rng(0)                 # seeded for reproducibility.
t4_scores = np.array([0.2, 1.2, 0.7, 2.0, 1.5, 0.0])
print("raw scores:", t4_scores.tolist())                             # -> [0.2, 1.2, 0.7, 2.0, 1.5, 0.0]
t4_shifted = t4_scores - t4_scores.max()
print("shifted scores:", np.round(t4_shifted, 3).tolist())           # -> [-1.8, -0.8, -1.3, 0.0, -0.5, -2.0]
t4_exp = np.exp(t4_shifted)
print("exponentials:", np.round(t4_exp, 3).tolist())                 # -> [0.165, 0.449, 0.273, 1.0, 0.607, 0.135]
t4_probs = t4_exp / t4_exp.sum()
print("probabilities:", np.round(t4_probs, 3).tolist())              # -> [0.063, 0.171, 0.104, 0.38, 0.231, 0.051]
print("probability sum:", round(float(t4_probs.sum()), 6))           # -> 1.0
t4_best = int(np.argmax(t4_probs))
print("most sampled index:", t4_best, round(float(t4_probs[t4_best]), 3))  # -> 3 0.38
assert abs(float(t4_probs.sum()) - 1.0) < 1e-12
assert t4_best == 3

plt.figure(figsize=(4.8, 3.0))
plt.bar(np.arange(t4_probs.size), t4_probs, color="darkorange")
plt.xlabel("architecture index")
plt.ylabel("sampling probability")
plt.title("Toy 4 · softmax keeps exploration mass")
plt.show()
```
▶ What you'll see: index `3` gets the most probability, but every candidate keeps a nonzero chance.

### ✍️ Toy 5 · Normalization and activation memory are bookkeeping

▶ What you'll see: normalization centers the six activations while memory accounting gives the tiny block's KB cost.

### ✍️ Toy 6 · Cost penalties and Pareto fronts expose tradeoffs

A scalar penalty picks one design, while the Pareto frontier keeps every architecture that is not worse in both loss and cost.

```python
import numpy as np

t6_rng = np.random.default_rng(0)                 # seeded for reproducibility.
t6_names = np.array(["tiny", "wide", "deep", "skip", "huge-lite", "huge"])
t6_loss = np.array([0.52, 0.40, 0.35, 0.31, 0.28, 0.25])
t6_cost = np.array([1.0, 2.0, 4.0, 3.0, 6.0, 9.0])
t6_alpha = 0.03
print("validation loss:", t6_loss.tolist())                          # -> [0.52, 0.4, 0.35, 0.31, 0.28, 0.25]
print("relative cost:", t6_cost.tolist())                            # -> [1.0, 2.0, 4.0, 3.0, 6.0, 9.0]
t6_objective = t6_loss + t6_alpha * t6_cost
print("cost-aware objective:", np.round(t6_objective, 3).tolist())   # -> [0.55, 0.46, 0.47, 0.4, 0.46, 0.52]
t6_best = int(np.argmin(t6_objective))
print("penalized winner:", t6_names[t6_best])                        # -> skip
t6_pareto = []
for t6_i in range(t6_names.size):
    t6_dominated = np.any((t6_loss <= t6_loss[t6_i]) & (t6_cost <= t6_cost[t6_i]) & ((t6_loss < t6_loss[t6_i]) | (t6_cost < t6_cost[t6_i])))
    t6_pareto.append(not t6_dominated)
t6_pareto = np.array(t6_pareto)
print("Pareto candidates:", t6_names[t6_pareto].tolist())            # -> ['tiny', 'wide', 'skip', 'huge-lite', 'huge']
assert t6_names[t6_best] == "skip"
assert t6_names[t6_pareto].tolist() == ["tiny", "wide", "skip", "huge-lite", "huge"]

plt.figure(figsize=(5.0, 3.2))
```

## 🛠️ Setup

```python
import numpy as np  # load NumPy for arrays, toy neural networks, losses, and search loops.
import matplotlib.pyplot as plt  # load Matplotlib for compact visual checks of search behavior.
np.random.seed(0)  # make random examples reproducible.

def relu(z):  # apply the ReLU gate used by the toy networks.
    return np.maximum(0.0, z)

def mse(y, yhat):  # compute mean squared error for train and validation checks.
    return float(np.mean((y - yhat) ** 2))

def softmax(scores):  # turn architecture scores into normalized probabilities.
    shifted = scores - np.max(scores)
    exps = np.exp(shifted)
    return exps / np.sum(exps)

def one_hidden_predict(X, W1, b1, W2, b2):  # run a one-hidden-layer network from scratch.
    H = relu(X @ W1 + b1)
    return H @ W2 + b2

def count_params(input_dim, width, output_dim=1):  # count dense one-hidden-layer parameters.
    return input_dim * width + width + width * output_dim + output_dim

def memory_kb(batch, width, bytes_per_float=4):  # estimate activation memory for one hidden layer.
    return batch * width * bytes_per_float / 1024
```

```python
    b1_e1 = np.zeros(width_e1)
```

### Advanced 3 — Track a Pareto frontier during search

**Goal.** Update the non-dominated set as trials arrive, because NAS often returns a frontier instead of one fixed architecture. We build it in 4 steps.

```python
trial_loss_a3 = np.array([0.44, 0.39, 0.33, 0.35, 0.29, 0.31])
trial_cost_a3 = np.array([1.0, 1.6, 3.2, 2.0, 6.0, 2.8])
print("trials:", len(trial_loss_a3))
```
▶ What you'll see: six architecture trials have both validation loss and relative cost.

```python
frontier_a3 = []
for i_a3 in range(len(trial_loss_a3)):
    seen_loss_a3 = trial_loss_a3[:i_a3 + 1]
    seen_cost_a3 = trial_cost_a3[:i_a3 + 1]
    keep_count_a3 = 0
    for j_a3 in range(i_a3 + 1):
        dominated_a3 = np.any((seen_loss_a3 <= seen_loss_a3[j_a3]) & (seen_cost_a3 <= seen_cost_a3[j_a3]) & ((seen_loss_a3 < seen_loss_a3[j_a3]) | (seen_cost_a3 < seen_cost_a3[j_a3])))
        keep_count_a3 += int(not dominated_a3)
    frontier_a3.append(keep_count_a3)
print("frontier size after each trial:", frontier_a3)
assert frontier_a3[-1] == 5
```

```python
final_mask_a3 = []
for i_a3 in range(len(trial_loss_a3)):
    dominated_a3 = np.any((trial_loss_a3 <= trial_loss_a3[i_a3]) & (trial_cost_a3 <= trial_cost_a3[i_a3]) & ((trial_loss_a3 < trial_loss_a3[i_a3]) | (trial_cost_a3 < trial_cost_a3[i_a3])))
    final_mask_a3.append(not dominated_a3)
final_mask_a3 = np.array(final_mask_a3)
print("final frontier ids:", np.where(final_mask_a3)[0])
```

```python

    plt.text(trial_cost_a3[i_a3] + 0.05, trial_loss_a3[i_a3], f"t{i_a3}")
```

▶ What you'll see: non-dominated trials lie along the best observed loss-cost boundary.

👀 Takeaway: maintaining a frontier prevents NAS from discarding useful low-cost alternatives.

### Advanced 4 — Separate proxy and final evaluation

**Goal.** Compare a cheap proxy ranking with a final ranking, because NAS can be misled when early training performance is not perfectly correlated with final validation loss. We build it in 3 steps.

```python
names_a4 = np.array(["a0", "a1", "a2", "a3", "a4"])

print("proxy best:", names_a4[int(np.argmin(proxy_a4))])
print("final best:", names_a4[int(np.argmin(final_a4))])
```
▶ What you'll see: the proxy winner and final winner can differ.

```python
proxy_rank_a4 = np.argsort(np.argsort(proxy_a4))

rank_corr_a4 = np.corrcoef(proxy_rank_a4, final_rank_a4)[0, 1]

```

### Advanced 5 — Simulate a search trace with regret

**Goal.** Track best-so-far validation loss during a sequence of trials, because NAS progress is measured by how quickly search finds strong architectures. We build it in 4 steps.

```python
trial_vals_a5 = np.array([0.52, 0.47, 0.49, 0.41, 0.39, 0.43, 0.35, 0.36])

```
▶ What you'll see: the incumbent validation loss only stays flat or improves as trials accumulate.

```python

```

```python
improvements_a5 = np.r_[trial_vals_a5[0] - best_so_far_a5[0], best_so_far_a5[:-1] - best_so_far_a5[1:]]
```
