# 3.48 — Multiclass & Multilabel Strategies

Multiclass and multilabel classification answer different questions with different probability rules: **multiclass** chooses exactly one class by making logits compete through softmax, while **multilabel** asks many independent yes/no questions through sigmoids. In this lesson, you will build both strategies from scratch in NumPy, compute the empirical-risk numbers behind model selection, and see why validation thresholds, penalties, and stability costs matter as much as the raw training loss.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build multiclass and multilabel strategy one idea at a time. Run each cell in order and read the printed intermediate values — the notebook keeps logits, probabilities, losses, penalties, thresholds, and validation decisions visible so the modeling contract is never hidden.

```python
import numpy as np  # arrays, logits, probabilities, and numerical checks.
import matplotlib.pyplot as plt  # compact visualizations for probabilities, losses, and thresholds.

```

### 1. Multiclass softmax: one example, one winning class

A multiclass classifier receives one score (a **logit**) per class, but it must return one probability distribution that sums to 1. Softmax does this by exponentiating every logit and dividing by the total exponentiated score: $p_k=e^{z_k}/\sum_j e^{z_j}$. The subtraction by the maximum logit below is not a modeling change; it is the standard numerically stable way to compute the same ratio without overflow.

```python
logits_w = np.array([2.0, 1.0, -0.5])  # raw class scores for cat, dog, bird.
labels_w = np.array(["cat", "dog", "bird"])  # names for readable output.
shifted_w = logits_w - np.max(logits_w)  # subtract the largest logit before exponentiating.
print("logits:", logits_w)  # inspect the raw, unnormalized evidence.
print("shifted logits:", shifted_w)  # same relative gaps, safer exponentials.
```
▶ What you'll see: the largest class has shifted logit 0, and the other classes keep their gaps below it.

```python
exp_w = np.exp(shifted_w)  # convert logit gaps into positive scores.
softmax_w = exp_w / np.sum(exp_w)  # normalize so probabilities compete and sum to 1.
print("exp scores:", np.round(exp_w, 3))  # inspect positive evidence before normalization.
print("softmax probabilities:", np.round(softmax_w, 3), "sum=", round(float(np.sum(softmax_w)), 3))  # inspect the distribution.
assert np.allclose(np.round(softmax_w, 3), [0.69, 0.254, 0.057])  # concrete lesson probabilities.
assert round(float(np.sum(softmax_w)), 6) == 1.0  # multiclass probabilities must sum to one.
```
▶ What you'll see: cat gets about 0.690 probability, dog 0.254, bird 0.057; increasing one class necessarily leaves less mass for others.

```python
plt.figure(figsize=(4.6, 3))  # create one compact probability chart.
plt.bar(labels_w, softmax_w, color=["seagreen", "steelblue", "gray"])  # draw one probability per class.
plt.ylim(0, 1)  # probabilities live on [0, 1].
plt.title("1: softmax probabilities compete")  # title the chart.
plt.ylabel("probability")  # label the probability scale.
plt.show()  # display the chart.
```
▶ What you'll see: one dominant bar and two smaller bars that together still make the total exactly 1.

*Why it's done this way:* softmax is the right normalization when the label space is mutually exclusive. Exponentials make higher logits count multiplicatively more, while division by the shared sum turns separate scores into a single competition. Subtracting the maximum preserves all differences because $e^{z_k-c}/\sum_j e^{z_j-c}=e^{z_k}/\sum_j e^{z_j}$.

### 2. Multiclass cross-entropy and empirical risk

Once softmax produces probabilities, the loss for a verified class is negative log probability: $-\log p_y$. The log matters because probability errors are multiplicative: improving the true-class probability from 0.01 to 0.10 is a huge improvement, and log loss rewards that strongly. Empirical risk is just the average loss over examples, exactly the Part 1 ERM frame made concrete.

```python
P_w = np.array([[0.808, 0.164, 0.028],  # example 0: true class 0 is likely.
                [0.117, 0.891, 0.044],  # example 1: true class 1 is likely.
                [0.200, 0.300, 0.604]]) # example 2: true class 2 is only moderately likely.
y_w = np.array([0, 1, 2])  # verified multiclass labels, one per row.
true_probs_w = P_w[np.arange(len(y_w)), y_w]  # pick the probability assigned to each true class.
print("true-class probabilities:", true_probs_w)  # inspect the values that cross-entropy scores.
```
▶ What you'll see: the third example is the least confident correct prediction and will contribute the largest loss.

```python
losses_w = -np.log(true_probs_w)  # per-example multiclass cross-entropy losses.
risk_w = float(np.mean(losses_w))  # empirical risk averages losses over the sample.
print("losses:", np.round(losses_w, 3))  # 0.213, 0.115, 0.504 from the toy probabilities.
print("empirical risk:", round(risk_w, 3))  # average loss.
assert np.allclose(np.round(losses_w, 3), [0.213, 0.115, 0.504])  # concrete loss checks.
assert round(risk_w, 3) == 0.278  # average of the three displayed losses.
```
▶ What you'll see: the loss is small when the true class probability is high and larger when it is only 0.604.

```python
plt.figure(figsize=(4.6, 3))  # create a compact risk breakdown.
plt.bar(["ex0", "ex1", "ex2"], losses_w, color="darkorange")  # show per-example losses.
plt.axhline(risk_w, color="black", linestyle="--", label="mean risk")  # show the average.
plt.title("2: empirical risk averages losses")  # title the plot.
plt.ylabel("-log p(true class)")  # label the loss scale.
plt.legend()  # show the mean line label.
plt.show()  # display the chart.
```
▶ What you'll see: one dashed average line summarizing three individual training losses.

*Why it's done this way:* ERM needs a scalar objective, so each example's probabilistic mistake is converted into a loss and then averaged. The average is crucial: it keeps the objective comparable across dataset sizes and makes every later cost, validation gap, or penalty a correction to the same scale.

### 3. Multilabel sigmoid: many independent yes/no labels

A multilabel example can have several true labels at once, so probabilities must **not** compete. Instead, each label has its own sigmoid probability $\sigma(z)=1/(1+e^{-z})$. A high probability for "algebra" does not force down the probability for "geometry" because the correct answer can contain both.

```python
ml_logits_w = np.array([1.5, 0.4, -1.2, 2.2])  # scores for four possible tags.
tags_w = np.array(["algebra", "geometry", "calculus", "word problem"])  # tag names.
ml_probs_w = 1 / (1 + np.exp(-ml_logits_w))  # independent sigmoid probability per tag.
print("sigmoid probabilities:", np.round(ml_probs_w, 3))  # inspect independent label probabilities.
print("sum of probabilities:", round(float(np.sum(ml_probs_w)), 3))  # not constrained to 1.
assert np.allclose(np.round(ml_probs_w, 3), [0.818, 0.599, 0.231, 0.900])  # concrete sigmoid checks.
```
▶ What you'll see: probabilities can sum to more than 1 because they are separate yes/no decisions.

```python
target_w = np.array([1, 1, 0, 1])  # this problem has algebra, geometry, and word-problem tags.
bce_terms_w = -(target_w * np.log(ml_probs_w) + (1 - target_w) * np.log(1 - ml_probs_w))  # binary CE per tag.
ml_loss_w = float(np.mean(bce_terms_w))  # average across labels for this example.
print("per-label BCE:", np.round(bce_terms_w, 3))  # inspect each yes/no loss.
print("multilabel loss:", round(ml_loss_w, 3))  # average across tags.
assert round(ml_loss_w, 3) == 0.271  # concrete multilabel loss.
```
▶ What you'll see: false labels are punished through $-\log(1-p)$, while true labels are punished through $-\log p$.

```python
plt.figure(figsize=(5.2, 3))  # create a compact multilabel probability plot.
plt.bar(tags_w, ml_probs_w, color=np.where(target_w == 1, "seagreen", "crimson"))  # green true tags, red absent tags.
plt.axhline(0.5, color="black", linestyle="--", label="threshold 0.5")  # common decision threshold.
plt.xticks(rotation=20)  # rotate long labels.
plt.ylim(0, 1)  # probabilities live on [0, 1].
plt.title("3: multilabel sigmoids do not compete")  # title the chart.
plt.legend()  # show threshold label.
plt.show()  # display the chart.
```
▶ What you'll see: multiple green true tags can all sit above the threshold at the same time.

*Why it's done this way:* multilabel classification is a vector of Bernoulli problems. Using softmax here would be mathematically wrong because it would spend one fixed unit of probability mass across labels that can co-occur; independent sigmoid losses let every label decide yes/no on its own evidence.

### 4. Decision thresholds and validation gaps

Probabilities are not the final product; decisions require thresholds. In multiclass, the usual threshold is implicit: choose the argmax. In multilabel, every tag needs a cutoff, and changing that cutoff trades false positives for false negatives. Validation data is where we check whether a tempting threshold improvement survives beyond the training table.

```python
val_probs_w = np.array([[0.90, 0.70, 0.20],
                        [0.60, 0.40, 0.30],
                        [0.20, 0.80, 0.55],
                        [0.45, 0.35, 0.75]])  # validation multilabel probabilities.
val_true_w = np.array([[1, 1, 0],
                       [1, 0, 0],
                       [0, 1, 1],
                       [0, 0, 1]])  # validation labels.
thresholds_w = np.array([0.3, 0.5, 0.7])  # candidate thresholds.
print("validation shape:", val_probs_w.shape)  # four examples, three labels.
```
▶ What you'll see: each example can have more than one positive label.

```python
f1s_w = []  # collect micro-F1 for each threshold.
for t_w in thresholds_w:  # try each candidate cutoff.
    pred_w = (val_probs_w >= t_w).astype(int)  # make multilabel yes/no decisions.
    tp_w = int(np.sum((pred_w == 1) & (val_true_w == 1)))  # true positives.
    fp_w = int(np.sum((pred_w == 1) & (val_true_w == 0)))  # false positives.
    fn_w = int(np.sum((pred_w == 0) & (val_true_w == 1)))  # false negatives.
    f1_w = 2 * tp_w / (2 * tp_w + fp_w + fn_w)  # micro-F1 across all labels.
    f1s_w.append(f1_w)  # store this threshold's score.
    print("t=", t_w, "tp/fp/fn=", (tp_w, fp_w, fn_w), "F1=", round(f1_w, 3))  # inspect counts.
assert np.allclose(np.round(f1s_w, 3), [0.750, 1.000, 0.800])  # concrete validation scores.
```
▶ What you'll see: threshold 0.5 is perfect on this validation toy, while 0.3 overpredicts and 0.7 underpredicts.

```python
plt.figure(figsize=(4.6, 3))  # create a threshold sweep plot.
plt.plot(thresholds_w, f1s_w, marker="o", color="purple")  # plot F1 by threshold.
plt.axvline(thresholds_w[int(np.argmax(f1s_w))], color="black", linestyle="--", label="best validation t")  # mark best threshold.
plt.ylim(0, 1.05)  # F1 scale.
plt.title("4: choose threshold with validation")  # title the plot.
plt.xlabel("threshold")  # label the threshold axis.
plt.ylabel("micro-F1")  # label the score axis.
plt.legend()  # show the best-threshold marker.
plt.show()  # display the curve.
```
▶ What you'll see: the middle threshold has the highest validation score, not because it is default but because the held-out counts say so.

*Why it's done this way:* training loss and decision quality are not identical. Thresholds convert calibrated-ish probabilities into actions, and validation protects us from choosing a cutoff that only looks good on examples the model already optimized.

### 5. Penalties, stability, and the final selection score

The source lesson emphasizes that the raw training number is only part of the decision. A flexible strategy may lower training loss but pay a complexity, regularization, or operational cost. The model we carry forward should be chosen by the full score implied by the method, then sanity-checked by the size of the gap.

```python
verified_losses_w = np.array([0.213, 0.096, 0.505])  # source lesson's checked per-example losses.
raw_risk_w = float(np.mean(verified_losses_w))  # empirical risk R_S.
method_cost_w = 0.050  # complexity or operational cost from the lesson.
selection_score_w = raw_risk_w + method_cost_w  # full score for the baseline strategy.
print("R_S:", round(raw_risk_w, 3), "cost:", method_cost_w, "score:", round(selection_score_w, 3))  # inspect the arithmetic.
assert round(raw_risk_w, 3) == 0.271  # source lesson risk.
assert round(selection_score_w, 3) == 0.321  # source lesson score.
```
▶ What you'll see: the raw average 0.271 becomes a decision score of 0.321 after the cost is included.

```python
flexible_score_w = 0.369  # more flexible alternative from the source lesson.
display_score_w = round(selection_score_w, 3)  # use the displayed decision score for the source lesson arithmetic.
gap_w = flexible_score_w - display_score_w  # absolute evidence gap.
relative_gap_w = gap_w / flexible_score_w  # compare the gap to the alternative's scale.
stable_score_w = 0.80 * display_score_w  # stabilizing knob reduces the decision score by 20%.
scores_w = np.array([display_score_w, flexible_score_w, stable_score_w])  # compare all options.
print("gap:", round(gap_w, 3), "relative gap:", round(relative_gap_w, 3))  # inspect evidence size.
print("stable score:", round(stable_score_w, 3), "winner index:", int(np.argmin(scores_w)))  # inspect final decision.
assert round(gap_w, 3) == 0.048 and round(relative_gap_w, 3) == 0.130  # source lesson gap checks.
assert round(stable_score_w, 3) == 0.257  # source lesson stabilized score.
```
▶ What you'll see: the stabilized option has the lowest full score, while the flexible alternative needs to overcome a visible 0.048 gap.

```python
plt.figure(figsize=(5, 3))  # create a model-selection bar chart.
plt.bar(["baseline+cost", "flexible", "stabilized"], scores_w, color=["steelblue", "gray", "seagreen"])  # compare full decision scores.
plt.ylabel("lower is better")  # lower score wins.
plt.title("5: select by full score, not raw fit")  # title the chart.
plt.xticks(rotation=12)  # make labels readable.
plt.show()  # display the chart.
```
▶ What you'll see: the stabilized bar is lowest even though the raw fit alone was not the whole story.

*Why it's done this way:* model selection is a contract between fit, cost, uncertainty, and action. Averaging losses gives the fit term, but the cost term prevents brittle flexibility from winning by convenience; the gap tells us whether the apparent improvement is large enough to trust.

### ✍️ Toy 1 · Softmax turns logits into one competing distribution

Six class logits can be any real numbers. Softmax shifts, exponentiates, and normalizes them into probabilities that sum to one.

```python
import numpy as np
import matplotlib.pyplot as plt

t1_rng = np.random.default_rng(0)
t1_logits = np.array([2.0, 1.0, 0.0, -1.0, 0.5, -0.5])
print("logits:", t1_logits.tolist())  # -> [2.0, 1.0, 0.0, -1.0, 0.5, -0.5]
t1_labels = np.array(["A", "B", "C", "D", "E", "F"])
print("labels:", t1_labels.tolist())  # -> ['A', 'B', 'C', 'D', 'E', 'F']
t1_shifted = t1_logits - np.max(t1_logits)
print("shifted logits:", t1_shifted.tolist())  # -> [0.0, -1.0, -2.0, -3.0, -1.5, -2.5]
t1_exp = np.exp(t1_shifted)
print("exp scores:", np.round(t1_exp, 3).tolist())  # -> [1.0, 0.368, 0.135, 0.05, 0.223, 0.082]
t1_probs = t1_exp / np.sum(t1_exp)
print("softmax probabilities:", np.round(t1_probs, 3).tolist())  # -> [0.538, 0.198, 0.073, 0.027, 0.12, 0.044]
t1_prob_sum = float(np.sum(t1_probs))
print("probability sum:", round(t1_prob_sum, 3))  # -> 1.0
t1_winner = t1_labels[int(np.argmax(t1_probs))]
print("winning class:", str(t1_winner))  # -> A

plt.figure(figsize=(4.8, 3))
plt.bar(t1_labels, t1_probs, color="steelblue")
plt.ylim(0, 1)
plt.ylabel("probability")
plt.title("Toy 1 · softmax competition")
plt.show()
assert np.allclose(np.round(t1_probs, 3), [0.538, 0.198, 0.073, 0.027, 0.12, 0.044]) and round(t1_prob_sum, 6) == 1.0
```
▶ What you'll see: class `A` has the largest probability, and all six probabilities add to exactly one distribution.

### ✍️ Toy 2 · Multiclass cross-entropy averages true-class surprise

After softmax, cross-entropy keeps only the probability assigned to the true class for each row. Negative log turns low true-class probability into high loss.

```python
import numpy as np

t2_rng = np.random.default_rng(0)
t2_P = np.array([[0.70, 0.20, 0.10], [0.10, 0.80, 0.10], [0.20, 0.30, 0.50], [0.60, 0.25, 0.15], [0.15, 0.20, 0.65], [0.05, 0.85, 0.10]])
print("probability table shape:", t2_P.shape)  # -> (6, 3)
t2_y = np.array([0, 1, 2, 0, 2, 1])
print("true classes:", t2_y.tolist())  # -> [0, 1, 2, 0, 2, 1]
t2_rows = np.arange(len(t2_y))
print("row indices:", t2_rows.tolist())  # -> [0, 1, 2, 3, 4, 5]
t2_true_probs = t2_P[t2_rows, t2_y]
print("true-class probabilities:", t2_true_probs.tolist())  # -> [0.7, 0.8, 0.5, 0.6, 0.65, 0.85]
t2_losses = -np.log(t2_true_probs)
print("cross-entropy losses:", np.round(t2_losses, 3).tolist())  # -> [0.357, 0.223, 0.693, 0.511, 0.431, 0.163]
t2_risk = float(t2_losses.mean())
print("empirical risk:", round(t2_risk, 3))  # -> 0.396

plt.figure(figsize=(5, 3))
plt.bar(["ex0", "ex1", "ex2", "ex3", "ex4", "ex5"], t2_losses, color="darkorange")
plt.axhline(t2_risk, color="black", linestyle="--", label="mean")
plt.ylabel("-log p(true)")
plt.title("Toy 2 · multiclass CE risk")
plt.legend()
plt.show()
assert np.allclose(np.round(t2_losses, 3), [0.357, 0.223, 0.693, 0.511, 0.431, 0.163]) and round(t2_risk, 3) == 0.396
```
▶ What you'll see: the row with true-class probability `0.50` has the largest loss, and the dashed line is the mean risk.

### ✍️ Toy 3 · Sigmoid labels do not compete in multilabel prediction

For multilabel output, each tag gets an independent sigmoid probability and binary cross-entropy term. Several tags can be true at once.

```python
import numpy as np

t3_rng = np.random.default_rng(0)
t3_logits = np.array([1.2, -0.4, 0.7, 2.0, -1.0, 0.1])
print("tag logits:", t3_logits.tolist())  # -> [1.2, -0.4, 0.7, 2.0, -1.0, 0.1]
t3_probs = 1.0 / (1.0 + np.exp(-t3_logits))
print("sigmoid probabilities:", np.round(t3_probs, 3).tolist())  # -> [0.769, 0.401, 0.668, 0.881, 0.269, 0.525]
t3_prob_sum = float(t3_probs.sum())
print("probability sum:", round(t3_prob_sum, 3))  # -> 3.513
t3_target = np.array([1, 0, 1, 1, 0, 0])
print("target tags:", t3_target.tolist())  # -> [1, 0, 1, 1, 0, 0]
t3_bce = -(t3_target * np.log(t3_probs) + (1 - t3_target) * np.log(1 - t3_probs))
print("per-label BCE:", np.round(t3_bce, 3).tolist())  # -> [0.263, 0.513, 0.403, 0.127, 0.313, 0.744]
t3_loss = float(t3_bce.mean())
print("multilabel loss:", round(t3_loss, 3))  # -> 0.394
t3_pred = (t3_probs >= 0.5).astype(int)
print("threshold predictions:", t3_pred.tolist())  # -> [1, 0, 1, 1, 0, 1]

plt.figure(figsize=(5, 3))
plt.bar(np.arange(6), t3_probs, color=np.where(t3_target == 1, "seagreen", "crimson"))
plt.axhline(0.5, color="black", linestyle="--", label="0.5 threshold")
plt.xlabel("tag")
plt.ylabel("probability")
plt.title("Toy 3 · independent sigmoid tags")
plt.legend()
plt.show()
assert round(t3_prob_sum, 3) == 3.513 and round(t3_loss, 3) == 0.394
```
▶ What you'll see: probabilities sum to more than `1` because the tags are independent yes/no decisions.

### ✍️ Toy 4 · A multilabel threshold changes micro-F1

Thresholds convert probabilities into yes/no tag decisions. Sweeping the cutoff changes true positives, false positives, false negatives, and micro-F1.

```python
import numpy as np

t4_rng = np.random.default_rng(0)
t4_probs = np.array([0.90, 0.65, 0.55, 0.40, 0.25, 0.10])
print("validation probabilities:", t4_probs.tolist())  # -> [0.9, 0.65, 0.55, 0.4, 0.25, 0.1]
t4_true = np.array([1, 1, 0, 1, 0, 0])
print("validation truth:", t4_true.tolist())  # -> [1, 1, 0, 1, 0, 0]
t4_thresholds = np.array([0.30, 0.50, 0.70])
print("thresholds:", t4_thresholds.tolist())  # -> [0.3, 0.5, 0.7]
t4_f1s = []
t4_counts = []
for t4_threshold in t4_thresholds:
    t4_pred = (t4_probs >= t4_threshold).astype(int)
    t4_tp = int(np.sum((t4_pred == 1) & (t4_true == 1)))
    t4_fp = int(np.sum((t4_pred == 1) & (t4_true == 0)))
    t4_fn = int(np.sum((t4_pred == 0) & (t4_true == 1)))
    t4_f1 = 2 * t4_tp / (2 * t4_tp + t4_fp + t4_fn)
    t4_f1s.append(t4_f1)
    t4_counts.append((t4_tp, t4_fp, t4_fn, t4_pred.tolist()))
print("tp/fp/fn/pred:", t4_counts)  # -> [(3, 1, 0, [1, 1, 1, 1, 0, 0]), (2, 1, 1, [1, 1, 1, 0, 0, 0]), (1, 0, 2, [1, 0, 0, 0, 0, 0])]
print("micro-F1 values:", np.round(t4_f1s, 3).tolist())  # -> [0.857, 0.667, 0.5]
t4_best_threshold = float(t4_thresholds[int(np.argmax(t4_f1s))])
print("best threshold:", t4_best_threshold)  # -> 0.3

plt.figure(figsize=(4.8, 3))
plt.plot(t4_thresholds, t4_f1s, marker="o", color="purple")
plt.ylim(0, 1.05)
plt.xlabel("threshold")
plt.ylabel("micro-F1")
plt.title("Toy 4 · threshold sweep")
plt.show()
assert np.allclose(np.round(t4_f1s, 3), [0.857, 0.667, 0.5]) and t4_best_threshold == 0.3
```
▶ What you'll see: threshold `0.3` wins by recovering all true tags while adding only one false positive.

### ✍️ Toy 5 · Penalty and stability select the final strategy

Raw average loss is only one term. Add a method cost, compare against a flexible alternative, then check whether a stabilized option has the lowest full score.

```python
import numpy as np

t5_rng = np.random.default_rng(0)
t5_losses = np.array([0.20, 0.18, 0.31, 0.22, 0.27, 0.24])
print("strategy losses:", t5_losses.tolist())  # -> [0.2, 0.18, 0.31, 0.22, 0.27, 0.24]
t5_risk = float(t5_losses.mean())
print("raw risk:", round(t5_risk, 3))  # -> 0.237
t5_cost = 0.06
print("method cost:", t5_cost)  # -> 0.06
t5_score = t5_risk + t5_cost
print("baseline full score:", round(t5_score, 3))  # -> 0.297
t5_flexible = 0.35
print("flexible score:", t5_flexible)  # -> 0.35
t5_gap = t5_flexible - t5_score
print("absolute gap:", round(t5_gap, 3))  # -> 0.053
t5_relative_gap = t5_gap / t5_flexible
print("relative gap:", round(t5_relative_gap, 3))  # -> 0.152
t5_stable = 0.80 * t5_score
print("stabilized score:", round(t5_stable, 3))  # -> 0.237
t5_scores = np.array([t5_score, t5_flexible, t5_stable])
```

## 🛠️ Setup

```python
import numpy as np # load NumPy for arrays, logits, losses, thresholds, and small numerical checks.
import matplotlib.pyplot as plt # load Matplotlib for the bars, heatmaps, and line plots used throughout the lesson.
np.random.seed(0) # make all random examples reproducible across notebook runs.

def softmax(z): # define a stable multiclass probability transform.
    z = np.asarray(z, dtype=float) # convert input logits to a float array.
    shifted = z - np.max(z, axis=-1, keepdims=True) # subtract the row maximum for numerical stability.
    exp_z = np.exp(shifted) # exponentiate shifted logits into positive scores.
    return exp_z / np.sum(exp_z, axis=-1, keepdims=True) # normalize each row so probabilities sum to one.

def sigmoid(z): # define the independent multilabel probability transform.
    z = np.asarray(z, dtype=float) # convert logits to float arrays for stable arithmetic.
    return 1 / (1 + np.exp(-z)) # return one Bernoulli probability per label.

def multiclass_ce(probs, y): # compute multiclass cross-entropy for a batch.
    probs = np.asarray(probs, dtype=float) # ensure probabilities are numeric.
    y = np.asarray(y, dtype=int) # ensure class labels are integer indices.
    return -np.log(probs[np.arange(len(y)), y]) # pick each true-class probability and take negative log.

def binary_ce(probs, targets): # compute elementwise binary cross-entropy for multilabel targets.
    probs = np.clip(np.asarray(probs, dtype=float), 1e-9, 1 - 1e-9) # avoid log(0) in tiny demos.
    targets = np.asarray(targets, dtype=float) # convert targets to numeric 0/1 values.
    return -(targets * np.log(probs) + (1 - targets) * np.log(1 - probs)) # Bernoulli negative log likelihood.

def micro_f1(pred, true): # compute micro-F1 across all label decisions.
    pred = np.asarray(pred, dtype=int) # convert predictions to integer 0/1 decisions.
    true = np.asarray(true, dtype=int) # convert truth to integer 0/1 labels.
    tp = np.sum((pred == 1) & (true == 1)) # count true positives.
    fp = np.sum((pred == 1) & (true == 0)) # count false positives.
    fn = np.sum((pred == 0) & (true == 1)) # count false negatives.
    return 0.0 if (2 * tp + fp + fn) == 0 else float(2 * tp / (2 * tp + fp + fn)) # return guarded F1.
```

### Advanced 1 — Calibration: probabilities versus accuracy

**Goal.** Bin predicted confidences and compare them to empirical accuracy, because decision thresholds only make sense when probabilities are reasonably calibrated. We build it in 4 steps.

```python
conf_a1 = np.array([0.55, 0.62, 0.68, 0.71, 0.76, 0.82, 0.88, 0.93, 0.96, 0.99]) # predicted true-class confidence.
correct_a1 = np.array([0, 1, 1, 0, 1, 1, 1, 1, 1, 1]) # whether the prediction was correct.
bins_a1 = np.array([0.5, 0.7, 0.85, 1.0]) # confidence bins.
print("mean confidence:", round(float(np.mean(conf_a1)), 3), "accuracy:", round(float(np.mean(correct_a1)), 3)) # inspect global calibration.
```
▶ What you'll see: average confidence and average correctness are close but not identical.

```python
bin_conf_a1 = [] # store average confidence per bin.
bin_acc_a1 = [] # store empirical accuracy per bin.
for lo_a1, hi_a1 in zip(bins_a1[:-1], bins_a1[1:]): # loop over bin intervals.
    mask_a1 = (conf_a1 >= lo_a1) & (conf_a1 < hi_a1 if hi_a1 < 1.0 else conf_a1 <= hi_a1) # select confidences in this bin.
    bin_conf_a1.append(float(np.mean(conf_a1[mask_a1]))) # average confidence.
    bin_acc_a1.append(float(np.mean(correct_a1[mask_a1]))) # average correctness.
print("bin confidence:", np.round(bin_conf_a1, 3)) # inspect calibration x-values.
print("bin accuracy:", np.round(bin_acc_a1, 3)) # inspect calibration y-values.
```

```python
ece_a1 = float(np.sum([np.sum((conf_a1 >= lo_a1) & (conf_a1 < hi_a1 if hi_a1 < 1.0 else conf_a1 <= hi_a1)) / len(conf_a1) * abs(c_a1 - a_a1) for lo_a1, hi_a1, c_a1, a_a1 in zip(bins_a1[:-1], bins_a1[1:], bin_conf_a1, bin_acc_a1)])) # expected calibration error.
print("ECE:", round(ece_a1, 3)) # inspect weighted calibration gap.
assert round(ece_a1, 3) == 0.068 # verify the concrete calibration number.
```

```python
plt.figure(figsize=(4.5, 3.5)) # create a reliability plot.
plt.plot([0, 1], [0, 1], linestyle="--", color="gray", label="perfect calibration") # diagonal reference.
plt.scatter(bin_conf_a1, bin_acc_a1, color="purple", s=70, label="bins") # plot bin calibration points.
plt.xlim(0.5, 1.0) # focus on observed confidences.
plt.ylim(0.0, 1.05) # accuracy scale.
plt.title("Advanced 1: calibration by confidence bin") # title the plot.
plt.xlabel("mean confidence") # label x-axis.
plt.ylabel("empirical accuracy") # label y-axis.
plt.legend() # show labels.
plt.show() # display the plot.
```
▶ What you'll see: bins above the diagonal are underconfident, and bins below it are overconfident.

👀 Takeaway: probability quality matters because thresholds and costs rely on probability scale, not just rank order.

### Advanced 2 — Class imbalance and weighted cross-entropy

**Goal.** Upweight rare classes, because average loss can otherwise be dominated by common labels. We build it in 4 steps.

```python
y_a2 = np.array([0, 0, 0, 0, 1, 2]) # class 0 is common, classes 1 and 2 are rare.
probs_a2 = np.array([[0.7, 0.2, 0.1], [0.8, 0.1, 0.1], [0.6, 0.3, 0.1], [0.9, 0.05, 0.05], [0.4, 0.5, 0.1], [0.4, 0.4, 0.2]]) # predicted probabilities.
counts_a2 = np.bincount(y_a2, minlength=3) # count examples per class.
print("class counts:", counts_a2) # inspect imbalance.
```
▶ What you'll see: the common class has four examples, while rare classes have one each.

```python
raw_losses_a2 = multiclass_ce(probs_a2, y_a2) # compute unweighted CE per example.
weights_a2 = len(y_a2) / (3 * counts_a2) # inverse-frequency class weights with mean scale near one.
example_weights_a2 = weights_a2[y_a2] # assign each example its class weight.
print("class weights:", np.round(weights_a2, 3)) # inspect rare-class emphasis.
print("raw losses:", np.round(raw_losses_a2, 3)) # inspect base losses.
```

```python
unweighted_a2 = float(np.mean(raw_losses_a2)) # ordinary empirical risk.
weighted_a2 = float(np.sum(example_weights_a2 * raw_losses_a2) / np.sum(example_weights_a2)) # weighted empirical risk.
print("unweighted risk:", round(unweighted_a2, 3), "weighted risk:", round(weighted_a2, 3)) # compare objectives.
assert round(unweighted_a2, 3) == 0.583 # verify unweighted number.
assert round(weighted_a2, 3) == 0.867 # verify weighted number.
```

```python
plt.figure(figsize=(5, 3)) # create a weighted-loss plot.
plt.bar(np.arange(len(y_a2)), raw_losses_a2, color="gray", label="raw CE") # raw losses.
plt.bar(np.arange(len(y_a2)), example_weights_a2 * raw_losses_a2, alpha=0.65, color="crimson", label="weighted contribution") # weighted contributions.
plt.title("Advanced 2: rare classes count more") # title the chart.
plt.xlabel("example") # label x-axis.
plt.ylabel("loss contribution") # label y-axis.
plt.legend() # show labels.
plt.show() # display the plot.
```
▶ What you'll see: rare-class examples contribute much more after weighting.

👀 Takeaway: weighting changes the empirical-risk contract so rare classes are not washed out by common ones.

### Advanced 4 — Tune label-specific thresholds

**Goal.** Let each label use its own threshold, because different labels can have different base rates and calibration. We build it in 4 steps.

```python
probs_a4 = np.array([[0.80, 0.20], [0.70, 0.25], [0.40, 0.45], [0.30, 0.65], [0.20, 0.45]]) # validation probabilities for two labels.
true_a4 = np.array([[1, 0], [1, 0], [0, 1], [0, 1], [0, 1]]) # label 1 needs a lower threshold.
grid_a4 = np.array([0.3, 0.5, 0.7]) # candidate thresholds per label.
print("grid:", grid_a4) # inspect candidate cutoffs.
```
▶ What you'll see: the second label's positives live around 0.45 to 0.65.

```python
best_score_a4 = -1.0 # initialize best validation F1.
best_pair_a4 = None # initialize best pair of thresholds.
for t0_a4 in grid_a4: # sweep label-0 threshold.
    for t1_a4 in grid_a4: # sweep label-1 threshold.
        pred_a4 = np.column_stack([probs_a4[:, 0] >= t0_a4, probs_a4[:, 1] >= t1_a4]).astype(int) # apply label-specific thresholds.
        score_a4 = micro_f1(pred_a4, true_a4) # score this pair.
        if score_a4 > best_score_a4: # keep the best validation pair.
            best_score_a4 = score_a4 # update best score.
            best_pair_a4 = (t0_a4, t1_a4) # update best thresholds.
print("best pair:", best_pair_a4, "F1:", round(best_score_a4, 3)) # inspect selected thresholds.

```

```python

```
▶ What you'll see: the label-specific policy recovers positives that a shared 0.5 threshold misses.

👀 Takeaway: multilabel thresholding is part of the model strategy, especially when labels have different score scales.
