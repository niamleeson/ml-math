# 9.22 — Retrieval-Augmented Generation

Retrieval-Augmented Generation (RAG) gives a language model a small, relevant library before it answers. Instead of asking the model to rely only on stored parameters, we retrieve evidence chunks, weight them by relevance, and condition the answer on those chunks so factual behavior depends on visible evidence rather than memory alone.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build RAG one idea at a time. Run each cell in order and read the printed intermediate values — chunking, dense retrieval, cosine similarity, top-k selection, reranking, and the final mixture formula are all implemented with tiny NumPy arrays. This walkthrough is self-contained and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays, vector math, and tiny dense embeddings.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
from collections import Counter  # simple bag-of-words counts from scratch.
np.random.seed(0)  # reproducibility for toy projections.
```

### 1. A tiny corpus and the evidence problem

RAG starts with a corpus: documents that may contain the answer. The language model does not read the whole corpus; a retrieval step must select a few relevant pieces. That design turns the question from "what does the model remember?" into "which evidence did we supply?" In the toy corpus below, only one document directly answers where the course keeps retrieval examples.

```python
corpus_w = [
    "rag retrieves evidence chunks before a generator writes an answer",
    "chunk overlap keeps definitions connected across boundaries",
    "cosine similarity ranks dense query and document vectors",
    "the notebook examples live in the retrieval augmented generation lesson",
    "irrelevant context can make a fluent answer hallucinate",
]
query_w = "where are the retrieval augmented generation examples"
for i_w, doc_w in enumerate(corpus_w):
    print(i_w, "->", doc_w)
print("query ->", query_w)
```
▶ What you'll see: five short documents and one query; document 3 is the most direct answer.

```python
relevant_w = np.array([0, 0, 0, 1, 0])  # 1 marks the document that truly answers the query.
plt.figure(figsize=(5, 2.4))
plt.bar(range(len(corpus_w)), relevant_w, color="seagreen")
plt.xticks(range(len(corpus_w)))
plt.ylim(0, 1.2)
plt.title("1: ground-truth answer document")
plt.xlabel("document id")
plt.ylabel("relevant?")
plt.show()
```
▶ What you'll see: one green bar at document 3 — the retriever's job is to put that bar near the top.

*Why it's done this way:* RAG separates knowledge access from generation. The corpus stores candidate evidence, the query asks for a fact, and the relevance label gives us a diagnostic target: if retrieval misses the evidence, no generator can reliably ground the answer.

### 2. Chunking: turn long text into retrievable units

Documents are often too long to fit or too broad to rank as one unit. Chunking breaks a document into overlapping windows. If chunk size is 6 tokens and overlap is 2, the stride is `6 - 2 = 4`; each new chunk starts four tokens after the previous one. Overlap is not a decoration: it prevents a definition split across a boundary from disappearing.

```python
long_doc_w = "rag systems split long documents into overlapping chunks so definitions stay near supporting details"
tokens_w = long_doc_w.split()
chunk_size_w = 6
overlap_w = 2
stride_w = chunk_size_w - overlap_w
print("tokens:", tokens_w)
print("chunk size:", chunk_size_w, "overlap:", overlap_w, "stride:", stride_w)
assert stride_w == 4
```
▶ What you'll see: the stride calculation is exactly chunk size minus overlap.

```python
chunks_w = []
starts_w = []
for start_w in range(0, len(tokens_w), stride_w):
    chunk_w = tokens_w[start_w:start_w + chunk_size_w]
    if chunk_w:
        chunks_w.append(" ".join(chunk_w))
        starts_w.append(start_w)
for j_w, chunk_w in enumerate(chunks_w):
    print(j_w, "start", starts_w[j_w], "->", chunk_w)
assert chunks_w[1].split()[:2] == chunks_w[0].split()[-2:]
```
▶ What you'll see: the last two tokens of chunk 0 reappear at the beginning of chunk 1.

```python
plt.figure(figsize=(6, 2.6))
for j_w, start_w in enumerate(starts_w):
    plt.broken_barh([(start_w, min(chunk_size_w, len(tokens_w) - start_w))], (j_w - 0.35, 0.7), facecolors="steelblue")
plt.yticks(range(len(chunks_w)), [f"chunk {j}" for j in range(len(chunks_w))])
plt.xlabel("token position")
plt.title("2: overlapping chunk windows")
plt.show()
```
▶ What you'll see: horizontal bars overlap by two token positions, preserving boundary context.

*Why it's done this way:* Retrieval ranks chunks, not abstract documents. Smaller chunks improve precision because they contain less unrelated text; overlap protects recall because facts crossing a boundary are still visible together. The stride formula is the arithmetic knob that controls this precision-recall tradeoff.

### 3. Dense retrieval: make text into vectors

A dense retriever maps both query and chunks into the same vector space. Here we build a tiny embedding from scratch: count vocabulary words, then project those counts into three semantic dimensions. This is not a trained embedding model, but it shows the same geometry: related texts should point in similar directions.

```python
vocab_w = sorted(set(" ".join(corpus_w + [query_w]).split()))
word_to_idx_w = {word_w: i_w for i_w, word_w in enumerate(vocab_w)}
print("vocab size:", len(vocab_w))
print("first words:", vocab_w[:8])
```
▶ What you'll see: a small vocabulary built only from the inline toy corpus and query.

```python
def bow_w(text_w):
    counts_w = Counter(text_w.split())
    vec_w = np.zeros(len(vocab_w))
    for word_w, count_w in counts_w.items():
        if word_w in word_to_idx_w:
            vec_w[word_to_idx_w[word_w]] = count_w
    return vec_w

semantic_w = np.zeros((len(vocab_w), 3))
for word_w in ["rag", "retrieval", "retrieves", "augmented", "generation", "generator", "examples", "notebook", "lesson"]:
    if word_w in word_to_idx_w:
        semantic_w[word_to_idx_w[word_w]] = np.array([1.0, 0.2, 0.0])
for word_w in ["chunk", "chunks", "overlap", "boundaries", "definitions"]:
    if word_w in word_to_idx_w:
        semantic_w[word_to_idx_w[word_w]] = np.array([0.0, 1.0, 0.2])
for word_w in ["cosine", "similarity", "dense", "vectors", "ranks"]:
    if word_w in word_to_idx_w:
        semantic_w[word_to_idx_w[word_w]] = np.array([0.2, 0.0, 1.0])
print("semantic matrix shape:", semantic_w.shape)
```
▶ What you'll see: each vocabulary word receives a small three-dimensional meaning vector.

```python
def embed_w(text_w):
    return bow_w(text_w) @ semantic_w

doc_vecs_w = np.vstack([embed_w(doc_w) for doc_w in corpus_w])
query_vec_w = embed_w(query_w)
print("query vector:", np.round(query_vec_w, 2))
print("document vectors:\n", np.round(doc_vecs_w, 2))
assert doc_vecs_w.shape == (5, 3)
```
▶ What you'll see: documents and the query are now dense 3-number vectors in the same space.

```python
plt.figure(figsize=(4.5, 3.4))
plt.scatter(doc_vecs_w[:, 0], doc_vecs_w[:, 2], s=80, color="steelblue", label="docs")
plt.scatter([query_vec_w[0]], [query_vec_w[2]], s=120, color="crimson", label="query")
for i_w in range(len(corpus_w)):
    plt.text(doc_vecs_w[i_w, 0] + 0.03, doc_vecs_w[i_w, 2], f"d{i_w}")
plt.xlabel("RAG/generation axis")
plt.ylabel("cosine/vector axis")
plt.title("3: dense retrieval space")
plt.legend()
plt.show()
```
▶ What you'll see: the query lands near documents with retrieval/generation words, especially document 3.

*Why it's done this way:* Bag-of-words alone only matches exact tokens. The projection groups words like `retrieval`, `augmented`, `generation`, and `notebook` onto a shared axis, so the dot/cosine geometry can retrieve meaning-related chunks even when wording is not identical.

### 4. Cosine similarity ranks evidence by direction

Dense retrieval usually compares vectors with cosine similarity: $\cos(q,d)=\frac{q\cdot d}{\lVert q\rVert\lVert d\rVert}$. The dot product rewards shared semantic coordinates, while the denominator removes length effects. A long chunk should not win merely because it has more words; it should win because it points in the same direction as the query.

```python
def cosine_w(a_w, b_w):
    denom_w = np.linalg.norm(a_w) * np.linalg.norm(b_w)
    return 0.0 if denom_w == 0 else float(np.dot(a_w, b_w) / denom_w)

raw_dots_w = doc_vecs_w @ query_vec_w
cosines_w = np.array([cosine_w(query_vec_w, doc_vecs_w[i_w]) for i_w in range(len(corpus_w))])
print("raw dots:", np.round(raw_dots_w, 3))
print("cosines:", np.round(cosines_w, 3))
```
▶ What you'll see: both scores favor related documents, but cosine normalizes for vector length.

```python
rank_w = np.argsort(cosines_w)[::-1]
print("ranking by cosine:", rank_w)
print("top document:", rank_w[0], corpus_w[rank_w[0]])
assert int(rank_w[0]) == 3
```
▶ What you'll see: document 3 ranks first because it aligns most strongly with the query vector.

```python
plt.figure(figsize=(5, 3))
plt.bar(range(len(corpus_w)), cosines_w, color="purple")
plt.xticks(range(len(corpus_w)))
plt.xlabel("document id")
plt.ylabel("cosine(query, doc)")
plt.title("4: cosine scores for dense retrieval")
plt.show()
```
▶ What you'll see: the tallest bar is document 3, the evidence we need.

*Why it's done this way:* Cosine uses direction rather than magnitude. That matters because chunks can differ in length, and RAG needs semantic alignment with the question, not a reward for verbose text. The top-k retriever is just sorting these similarities.

### 5. Top-k recall and misleading context

After scoring, RAG keeps only the top `k` chunks. Top-k recall asks whether the needed evidence appears in that retained set. Increasing `k` can improve recall, but it also sends more context to the generator; irrelevant chunks can distract or even encourage hallucination.

```python
top2_w = rank_w[:2]
recall_top2_w = relevant_w[top2_w].sum() / relevant_w.sum()
print("top-2 ids:", top2_w)
print("top-2 recall:", round(float(recall_top2_w), 3))
assert round(float(recall_top2_w), 3) == 1.000
```
▶ What you'll see: recall is 1.000 because the single relevant document appears in the top two.

```python
ks_w = np.arange(1, 6)
recalls_w = np.array([relevant_w[rank_w[:k_w]].sum() / relevant_w.sum() for k_w in ks_w])
noise_w = np.array([k_w - relevant_w[rank_w[:k_w]].sum() for k_w in ks_w])
print("recall by k:", recalls_w)
print("irrelevant chunks by k:", noise_w)
```
▶ What you'll see: recall becomes perfect quickly, while the number of irrelevant chunks keeps growing.

```python
plt.figure(figsize=(5, 3))
plt.plot(ks_w, recalls_w, marker="o", label="recall")
plt.plot(ks_w, noise_w / noise_w.max(), marker="s", label="scaled irrelevant context")
plt.xlabel("k retrieved chunks")
plt.title("5: recall versus context noise")
plt.legend()
plt.show()
```
▶ What you'll see: after recall reaches 1, larger k mostly adds irrelevant context.

*Why it's done this way:* Retrieval is a bottleneck. If k is too small, the answer evidence may be absent; if k is too large, the generator sees distractors. Top-k recall and context-noise counts make that tradeoff visible instead of relying on vibes.

### 6. Reranking and the RAG probability mixture

The lesson formula is $p(y\mid x)=\sum_{d\in TopK(x)}p(y\mid x,d)p(d\mid x)$. Retrieval supplies document weights $p(d\mid x)$; generation supplies answer likelihoods $p(y\mid x,d)$. A reranker can adjust the top-k order with a more targeted score before those weights are used.

```python
topk_w = rank_w[:2]
retriever_scores_w = cosines_w[topk_w]
bonus_w = np.array([1.0 if "notebook" in corpus_w[i_w] or "lesson" in corpus_w[i_w] else 0.0 for i_w in topk_w])
rerank_scores_w = 0.8 * retriever_scores_w + 0.2 * bonus_w
print("top-k docs:", topk_w)
print("retriever scores:", np.round(retriever_scores_w, 3))
print("rerank scores:", np.round(rerank_scores_w, 3))
```
▶ What you'll see: the chunk with notebook/lesson evidence receives an extra targeted rerank bonus.

```python
weights_w = np.exp(rerank_scores_w) / np.sum(np.exp(rerank_scores_w))
answer_likelihoods_w = np.array([0.9 if relevant_w[i_w] == 1 else 0.4 for i_w in topk_w])
grounded_prob_w = float(np.sum(weights_w * answer_likelihoods_w))
print("evidence weights:", np.round(weights_w, 3))
print("answer likelihoods:", answer_likelihoods_w)
print("grounded probability:", round(grounded_prob_w, 3))
assert grounded_prob_w > 0.6
```
▶ What you'll see: the final probability is a weighted average of likelihoods conditioned on retrieved evidence.

```python
memory_only_w = 0.4
gain_w = grounded_prob_w - memory_only_w
print("memory-only probability:", memory_only_w)
print("RAG gain:", round(gain_w, 3))
plt.figure(figsize=(4.5, 3))
plt.bar(["memory only", "with RAG"], [memory_only_w, grounded_prob_w], color=["gray", "seagreen"])
plt.ylim(0, 1)
plt.ylabel("p(correct answer)")
plt.title("6: retrieval raises grounded answer probability")
plt.show()
```
▶ What you'll see: conditioning on retrieved evidence raises the toy probability above the memory-only baseline.

*Why it's done this way:* The mixture formula says RAG quality depends on two terms: retrieval probability for evidence and generation likelihood given that evidence. Reranking improves the first term; faithful answering improves the second. If either term is weak, the weighted sum stays weak.

### ✍️ Toy 1 · Evidence labels mark answerable documents

### ✍️ Toy 2 · Chunk stride creates overlap

Chunking is just window arithmetic. The stride is `chunk size - overlap`, so the next chunk starts
before the previous chunk has fully ended.

```python
import numpy as np

t2_rng = np.random.default_rng(0)
t2_tokens = np.array("alpha beta gamma delta epsilon zeta eta theta".split())
print("tokens:", t2_tokens.tolist())  # -> ['alpha', 'beta', 'gamma', 'delta', 'epsilon', 'zeta', 'eta', 'theta']
t2_chunk_size = 4
print("chunk size:", t2_chunk_size)  # -> 4
t2_overlap = 1
print("overlap:", t2_overlap)  # -> 1
t2_stride = t2_chunk_size - t2_overlap
print("stride:", t2_stride)  # -> 3
t2_starts = np.arange(0, t2_tokens.size, t2_stride)
print("chunk starts:", t2_starts.tolist())  # -> [0, 3, 6]
t2_lengths = np.minimum(t2_chunk_size, t2_tokens.size - t2_starts)
print("chunk lengths:", t2_lengths.tolist())  # -> [4, 4, 2]
t2_chunks = [t2_tokens[start:start + t2_chunk_size].tolist() for start in t2_starts]
print("chunks:", t2_chunks)  # -> [['alpha', 'beta', 'gamma', 'delta'], ['delta', 'epsilon', 'zeta', 'eta'], ['eta', 'theta']]
t2_overlap_tokens = np.intersect1d(t2_tokens[0:4], t2_tokens[3:7])
print("overlap tokens between chunk 0 and 1:", t2_overlap_tokens.tolist())  # -> ['delta']
assert t2_overlap_tokens.tolist() == ["delta"]

plt.figure(figsize=(5.6, 2.8))
for t2_row, t2_start in enumerate(t2_starts):
    plt.broken_barh([(int(t2_start), int(t2_lengths[t2_row]))], (t2_row - 0.35, 0.7), facecolors="#4c78a8")
plt.yticks(np.arange(t2_starts.size), ["chunk 0", "chunk 1", "chunk 2"])
plt.xlabel("token position")
plt.title("Toy 2 · stride 3 leaves a 1-token overlap")
plt.show()
```
▶ What you'll see: chunk 1 starts at token 3, so `delta` appears in both chunk 0 and chunk 1.

### ✍️ Toy 4 · Cosine normalizes vector length

A large dot product can come from length alone. Cosine divides by both vector norms so matching
direction wins.

```python
import numpy as np

t4_rng = np.random.default_rng(0)
t4_query = np.array([1.0, 1.0])
print("query vector:", t4_query.tolist())  # -> [1.0, 1.0]
t4_docs = np.array([[2.0, 2.0], [4.0, 0.0], [0.0, 3.0]])
print("document vectors:", t4_docs.tolist())  # -> [[2.0, 2.0], [4.0, 0.0], [0.0, 3.0]]
t4_dots = t4_docs @ t4_query
print("dot products:", t4_dots.tolist())  # -> [4.0, 4.0, 3.0]
t4_query_norm = np.linalg.norm(t4_query)
print("query norm:", round(float(t4_query_norm), 3))  # -> 1.414
t4_doc_norms = np.linalg.norm(t4_docs, axis=1)
print("document norms:", np.round(t4_doc_norms, 3).tolist())  # -> [2.828, 4.0, 3.0]
t4_denoms = t4_query_norm * t4_doc_norms
print("cosine denominators:", np.round(t4_denoms, 3).tolist())  # -> [4.0, 5.657, 4.243]
t4_cosines = t4_dots / t4_denoms
print("cosines:", np.round(t4_cosines, 3).tolist())  # -> [1.0, 0.707, 0.707]
t4_rank = np.argsort(t4_cosines)[::-1]
print("cosine ranking:", t4_rank.tolist())  # -> [0, 2, 1]
assert int(t4_rank[0]) == 0

plt.figure(figsize=(4.6, 2.8))
plt.bar(["d0", "d1", "d2"], t4_cosines, color="#b279a2")
plt.ylim(0, 1.1)
plt.ylabel("cosine(query, doc)")
plt.title("Toy 4 · same direction beats same dot")
plt.show()
```
▶ What you'll see: `d0` wins because it points in the same direction as the query.

### ✍️ Toy 5 · Top-k recall asks whether evidence survived

```python
t5_rng = np.random.default_rng(0)
```

### ✍️ Toy 6 · Larger k adds context noise

After recall is good enough, extra chunks can mostly add irrelevant tokens. Count total context and
irrelevant context separately.

```python
import numpy as np

t6_rng = np.random.default_rng(0)
t6_rank = np.array([2, 0, 3, 1])
print("retrieval rank:", t6_rank.tolist())  # -> [2, 0, 3, 1]
t6_relevant = np.array([0, 1, 1, 0])
print("relevance by doc id:", t6_relevant.tolist())  # -> [0, 1, 1, 0]
t6_context_lengths = np.array([40, 30, 50, 20])
print("tokens by doc id:", t6_context_lengths.tolist())  # -> [40, 30, 50, 20]
t6_ks = np.arange(1, 5)
print("k values:", t6_ks.tolist())  # -> [1, 2, 3, 4]
```

## 🛠️ Setup

```python
import numpy as np  # load NumPy for arrays, linear algebra, ranking, and small numerical checks.
import matplotlib.pyplot as plt  # load Matplotlib for heatmaps, bars, scatters, and line plots.
from collections import Counter  # load Counter for simple token-count embeddings from scratch.
np.random.seed(0)  # make all stochastic examples reproducible across notebook runs.

def rag_tokenize(text):  # Split lowercase text on spaces for the toy examples.
    return text.lower().split()

def rag_cosine(a, b):  # Compute guarded cosine similarity for dense vectors.
    a = np.asarray(a, dtype=float)  # Convert the first input to a float array.
    b = np.asarray(b, dtype=float)  # Convert the second input to a float array.
    denom = np.linalg.norm(a) * np.linalg.norm(b)  # Product of vector lengths.
    return 0.0 if denom == 0 else float(np.dot(a, b) / denom)  # Return 0 for empty evidence.

def rag_softmax(scores):  # Convert scores into positive weights that sum to 1.
    scores = np.asarray(scores, dtype=float)  # Ensure NumPy arithmetic.
    shifted = scores - np.max(scores)  # Stabilize the exponentials.
    exps = np.exp(shifted)  # Exponentiate shifted scores.
    return exps / np.sum(exps)  # Normalize into probabilities.

def rag_chunk_tokens(tokens, chunk_size, overlap):  # Make overlapping chunks from a token list.
    stride = chunk_size - overlap  # Move by non-overlapped tokens each time.
    chunks = []  # Store token chunks.
    for start in range(0, len(tokens), stride):  # Slide a fixed-size window.
        piece = tokens[start:start + chunk_size]  # Slice the current chunk.
        if piece:  # Keep nonempty chunks.
            chunks.append(piece)  # Save it.
    return chunks  # Return list of token lists.

def rag_bow(text, vocab):  # Convert text to a bag-of-words vector over a fixed vocabulary.
    counts = Counter(rag_tokenize(text))  # Count words in the text.
    return np.array([counts.get(word, 0) for word in vocab], dtype=float)  # Vectorize counts.

def rag_show_scores(scores, title):  # Draw a small score bar chart.
    plt.figure(figsize=(5, 3))  # Create a compact figure.
    plt.bar(range(len(scores)), scores, color="teal")  # Plot one bar per document or chunk.
    plt.title(title)  # Add the provided title.
    plt.xlabel("candidate id")  # Label ids.
    plt.ylabel("score")  # Label scores.
    plt.show()  # Display the plot.
```
