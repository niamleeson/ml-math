# 9.7 — KV Cache & Inference Optimization

KV cache & inference optimization asks a practical Transformer question: during autoregressive generation, why recompute the same prefix again and again? In this lesson, you will build tiny attention blocks from scratch, reuse cached keys and values correctly, and inspect the speed, memory, and correctness tradeoffs that make cached decoding useful in real language-model serving.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build cached decoding one idea at a time. Run each cell in order and read the printed intermediate values — every array is tiny enough to inspect, and every speedup claim is tied back to the attention formula. This walkthrough is self-contained (it imports what it needs) and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays + linear algebra for tiny attention blocks.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
np.random.seed(0)  # reproducibility for toy projections and tokens.
```

### 1. Autoregressive attention starts from Q, K, and V

A decoder-only Transformer turns each token state into a query, key, and value. At generation step $t$, the new query $q_t$ compares against all prefix keys $K_{1:t}$, then averages the matching values $V_{1:t}$:

$$\mathrm{Attn}(q_t,K_{1:t},V_{1:t})=\mathrm{softmax}(q_tK_{1:t}^\top/\sqrt{d_k})V_{1:t}.$$

The cache does not change this formula. It changes which pieces are recomputed. First, we build the formula directly on a tiny prefix.

```python
X_w = np.array([[1.0, 0.0, 0.5],
                [0.2, 1.0, 0.0],
                [0.0, 0.4, 1.0]])  # three token states, d_model=3.
Wq_w = np.eye(3)                     # identity projections keep the numbers readable.
Wk_w = np.array([[1.0, 0.0], [0.0, 1.0], [0.5, 0.5]])
Wv_w = np.array([[1.0, 0.0], [0.0, 1.0], [1.0, -1.0]])
print("X shape:", X_w.shape, "Wk shape:", Wk_w.shape, "Wv shape:", Wv_w.shape)
```
▶ What you'll see: three token states and small projection matrices that will produce two-dimensional keys and values.

```python
Q_w = X_w @ Wq_w[:, :2]        # one query per token, using two query dimensions.
K_w = X_w @ Wk_w               # one cached key per token.
V_w = X_w @ Wv_w               # one cached value per token.
print("Q:\n", np.round(Q_w, 3))
print("K:\n", np.round(K_w, 3))
print("V:\n", np.round(V_w, 3))
```
▶ What you'll see: Q, K, and V are just linear projections of the same token states.

```python
def softmax_w(z):
    z = z - np.max(z)              # subtract max for stable exponentials.
    e = np.exp(z)                  # convert scores to positive weights.
    return e / np.sum(e)           # normalize to sum to 1.

q_last_w = Q_w[-1]                 # query for the newest token.
scores_w = q_last_w @ K_w.T / np.sqrt(K_w.shape[1])
weights_w = softmax_w(scores_w)
out_w = weights_w @ V_w
print("scores:", np.round(scores_w, 3))
print("weights:", np.round(weights_w, 3), "sum=", round(float(weights_w.sum()), 3))
print("attention output:", np.round(out_w, 3))
assert round(float(weights_w.sum()), 3) == 1.0
```
▶ What you'll see: the newest query produces one score per prefix token, a normalized softmax distribution, and a weighted value average.

```python
plt.figure(figsize=(4.4, 3))
plt.bar(["tok0", "tok1", "tok2"], weights_w, color="teal")
plt.title("1: attention weights over the prefix")
plt.ylabel("softmax weight")
plt.ylim(0, 1)
plt.show()
```
▶ What you'll see: attention is a probability-like vote over existing prefix values; larger query-key alignment gets a larger bar.

*Why it's done this way:* The key is the searchable address, the query is the lookup request, and the value is the content returned by the lookup. Dividing scores by $\sqrt{d_k}$ keeps dot products from growing too large as dimension increases; otherwise softmax saturates and gradients or probabilities become brittle. Caching preserves the same $qK^\top$ math but avoids rebuilding old addresses and contents.

### 2. The KV cache stores old keys and values, not old queries

During decoding, old tokens never need to ask new questions. Only the newest token needs a query, because only the newest hidden state must be produced before the next token is sampled. Old keys and values are still needed as memory, so the cache stores $K_{1:t}$ and $V_{1:t}$ and appends one row per generated token.

```python
prefix_w = np.array([[1.0, 0.0, 0.5],
                     [0.2, 1.0, 0.0],
                     [0.0, 0.4, 1.0],
                     [0.8, 0.1, 0.2]])
K_cache_w = prefix_w @ Wk_w
V_cache_w = prefix_w @ Wv_w
print("cache lengths:", len(K_cache_w), len(V_cache_w))
print("first cached key:", np.round(K_cache_w[0], 3))
```
▶ What you'll see: each prefix token contributes exactly one key row and one value row to the cache.

```python
new_x_w = np.array([0.1, 0.3, 1.0])       # the newest token state.
q_new_w = new_x_w @ Wq_w[:, :2]           # compute only the new query.
k_new_w = new_x_w @ Wk_w                  # compute the new key once for future steps.
v_new_w = new_x_w @ Wv_w                  # compute the new value once for future steps.
print("q_new:", np.round(q_new_w, 3))
print("k_new:", np.round(k_new_w, 3), "v_new:", np.round(v_new_w, 3))
```
▶ What you'll see: the new token creates one query for the current lookup and one key/value pair to append.

```python
K_plus_w = np.vstack([K_cache_w, k_new_w])
V_plus_w = np.vstack([V_cache_w, v_new_w])
scores_plus_w = q_new_w @ K_plus_w.T / np.sqrt(K_plus_w.shape[1])
weights_plus_w = softmax_w(scores_plus_w)
out_plus_w = weights_plus_w @ V_plus_w
print("old length -> new length:", len(K_cache_w), "->", len(K_plus_w))
print("attention output with appended cache:", np.round(out_plus_w, 3))
assert len(K_plus_w) == 5 and len(V_plus_w) == 5
```
▶ What you'll see: adding one token appends one key row and one value row, growing cache length 4 → 5.

*Why it's done this way:* The current output depends on old keys and values because attention may read from any prefix position. It does not depend on old queries, because those queries were only needed to produce old outputs that have already been consumed. Storing K and V is therefore the minimal reusable state for exact autoregressive attention.

### 3. Cached decoding matches recomputation exactly

A KV cache is an optimization, not an approximation. If the cache was built from the same prompt prefix, same weights, and same positions, cached attention must equal full recomputation for the newest token. We verify that by computing the same output two ways.

```python
full_prefix_w = np.vstack([prefix_w, new_x_w])
Q_full_w = full_prefix_w @ Wq_w[:, :2]
K_full_w = full_prefix_w @ Wk_w
V_full_w = full_prefix_w @ Wv_w
print("full recompute shapes:", Q_full_w.shape, K_full_w.shape, V_full_w.shape)
```
▶ What you'll see: full recomputation rebuilds Q, K, and V for all five prefix tokens.

```python
scores_full_w = Q_full_w[-1] @ K_full_w.T / np.sqrt(K_full_w.shape[1])
weights_full_w = softmax_w(scores_full_w)
out_full_w = weights_full_w @ V_full_w
print("cached output:", np.round(out_plus_w, 6))
print("full output:  ", np.round(out_full_w, 6))
print("max difference:", np.max(np.abs(out_plus_w - out_full_w)))
assert np.allclose(out_plus_w, out_full_w)
```
▶ What you'll see: cached and full outputs are identical to numerical precision.

```python
plt.figure(figsize=(4.6, 3))
plt.bar(["dim0 cached", "dim0 full", "dim1 cached", "dim1 full"],
        [out_plus_w[0], out_full_w[0], out_plus_w[1], out_full_w[1]],
        color=["teal", "gray", "teal", "gray"])
plt.xticks(rotation=20)
plt.title("3: cache is exact reuse")
plt.ylabel("attention output")
plt.show()
```
▶ What you'll see: paired bars overlap, because caching reuses the exact same keys and values full recomputation would rebuild.

*Why it's done this way:* The equality follows from substituting the cached $K_{1:t},V_{1:t}$ into the original formula. Since linear projections of old tokens are deterministic, storing their results is algebraically the same as recomputing them. The cache becomes wrong only when the stored prefix, weights, masks, or positions no longer match the requested computation.

### 4. Complexity: recompute grows quadratically, cache grows linearly in new states

Without a cache, generating through length $T$ repeatedly processes prefixes of lengths $1,2,\ldots,T$, so the number of token states projected is $1+2+\cdots+T=T(T+1)/2$. With a cache, each generated step projects only the new token, so it projects $T$ token states. Attention still scores the new query against the whole prefix, but the expensive old K/V projections are not repeated.

```python
T_w = 5
recompute_states_w = sum(range(1, T_w + 1))
cached_states_w = T_w
print("without cache states:", recompute_states_w)
print("with cache states:", cached_states_w)
assert recompute_states_w == 15 and cached_states_w == 5
```
▶ What you'll see: the lesson's core arithmetic — length 5 costs 15 projected token states without cache and 5 with cache.

```python
lengths_w = np.arange(1, 65)
recompute_curve_w = lengths_w * (lengths_w + 1) / 2
cache_curve_w = lengths_w
speedup_curve_w = recompute_curve_w / cache_curve_w
print("speedup at T=64:", round(float(speedup_curve_w[-1]), 1), "x by projection-count model")
assert round(float(speedup_curve_w[-1]), 1) == 32.5
```
▶ What you'll see: the projection-count speedup grows with sequence length because recomputation repeats more old work.

```python
plt.figure(figsize=(5, 3))
plt.plot(lengths_w, recompute_curve_w, label="recompute old K/V", color="crimson")
plt.plot(lengths_w, cache_curve_w, label="cache: new token only", color="seagreen")
plt.title("4: projected token states during generation")
plt.xlabel("generated length T")
plt.ylabel("token states projected")
plt.legend()
plt.show()
```
▶ What you'll see: a curved red line versus a straight green line; the vertical gap is avoided repeated work.

*Why it's done this way:* Autoregressive generation is sequential, so we cannot compute future tokens in parallel before sampling them. The best easy win is to never redo deterministic prefix work. The triangular number $T(T+1)/2$ is the cost of forgetting; the linear $T$ is the cost of remembering.

### 5. KV memory is the price paid for speed

The cache stores two tensors — keys and values — for every layer, head, token position, and head dimension. A simple memory estimate is

$$\text{bytes}=2\times L\times H\times T\times d_{head}\times\text{bytes per number},$$

where the leading 2 means K plus V. This memory grows linearly with context length and batch size, so a speed optimization can become the serving bottleneck.

```python
L_w, H_w, Tmem_w, dhead_w, bytes_per_w = 2, 2, 4, 3, 2
kv_bytes_w = 2 * L_w * H_w * Tmem_w * dhead_w * bytes_per_w
print("KV bytes:", kv_bytes_w)
assert kv_bytes_w == 192
```
▶ What you'll see: the worked example from the lesson block gives exactly 192 bytes for a tiny fp16 cache.

```python
T_grid_w = np.array([128, 512, 2048, 8192])
L_big_w, H_big_w, d_big_w, b_big_w = 32, 32, 128, 2
per_seq_mb_w = 2 * L_big_w * H_big_w * T_grid_w * d_big_w * b_big_w / (1024 ** 2)
print("MB per sequence:", np.round(per_seq_mb_w, 1))
```
▶ What you'll see: memory grows in direct proportion to context length; quadrupling tokens quadruples KV memory.

```python
plt.figure(figsize=(5, 3))
plt.plot(T_grid_w, per_seq_mb_w, marker="o", color="purple")
plt.title("5: KV cache memory grows linearly")
plt.xlabel("context length T")
plt.ylabel("KV cache MB per sequence")
plt.xscale("log", base=2)
plt.show()
```
▶ What you'll see: a straight trend on these log-spaced context lengths; the cache is cheap at short prompts and expensive at long ones.

*Why it's done this way:* Inference trades compute for memory. Caching old K/V removes repeated projections, but every retained token now occupies memory in every layer and head. Production systems therefore combine KV caching with batching limits, quantized caches, sliding windows, or eviction policies when contexts become large.

### 6. Correctness pitfalls: prefix and position must match the cache

A cache is only valid for the exact prefix and positional geometry that produced it. If we reuse keys from a different prompt, the attention computation still returns numbers, but they correspond to the wrong memory. If we append a token with the wrong position encoding, query-key alignment also shifts.

```python
right_prefix_w = prefix_w.copy()
wrong_prefix_w = prefix_w.copy()
wrong_prefix_w[1] = np.array([1.5, -0.2, 0.1])  # pretend token 1 came from another prompt.
K_right_w = right_prefix_w @ Wk_w
V_right_w = right_prefix_w @ Wv_w
K_wrong_w = wrong_prefix_w @ Wk_w
V_wrong_w = wrong_prefix_w @ Wv_w
print("changed cached key row:", np.round(K_right_w[1], 3), "->", np.round(K_wrong_w[1], 3))
```
▶ What you'll see: the cache can have the right shape while containing a key from the wrong prefix.

```python
q_check_w = new_x_w @ Wq_w[:, :2]
right_out_w = softmax_w(q_check_w @ np.vstack([K_right_w, k_new_w]).T / np.sqrt(2)) @ np.vstack([V_right_w, v_new_w])
wrong_out_w = softmax_w(q_check_w @ np.vstack([K_wrong_w, k_new_w]).T / np.sqrt(2)) @ np.vstack([V_wrong_w, v_new_w])
diff_wrong_w = float(np.linalg.norm(right_out_w - wrong_out_w))
print("right output:", np.round(right_out_w, 3))
print("wrong-cache output:", np.round(wrong_out_w, 3))
print("L2 difference:", round(diff_wrong_w, 3))
assert diff_wrong_w > 0.05
```
▶ What you'll see: both outputs look numerically plausible, but the wrong-prefix cache changes the answer.

```python
pos_w = np.arange(5)[:, None] * np.array([[0.01, -0.02]])
K_pos_right_w = K_plus_w + pos_w
K_pos_shift_w = K_plus_w + (np.arange(1, 6)[:, None] * np.array([[0.01, -0.02]]))
w_right_pos_w = softmax_w(q_new_w @ K_pos_right_w.T / np.sqrt(2))
w_shift_pos_w = softmax_w(q_new_w @ K_pos_shift_w.T / np.sqrt(2))
print("right position weights:", np.round(w_right_pos_w, 3))
print("shifted position weights:", np.round(w_shift_pos_w, 3))
```
▶ What you'll see: a small position shift changes the query-key scores and therefore the attention weights.

*Why it's done this way:* Attention has no external memory label saying “this key came from token 17 of this exact prompt.” The numbers themselves encode that identity through token content and position. Reusing a cache across prompts or miscounting positions silently changes $qK^\top$, so cache bookkeeping is part of the model, not just engineering plumbing.

## 🛠️ Setup

```python
import numpy as np # Load NumPy for arrays, dot products, softmaxes, and small numerical checks.
import matplotlib.pyplot as plt # Load Matplotlib for heatmaps, bars, and FLOP or memory curves.
np.random.seed(0) # Make every random toy example reproducible.

def softmax(z): # Define a stable softmax for one-dimensional score arrays.
    z = np.asarray(z, dtype=float) # Convert inputs to float arrays so subtraction and exponentials are predictable.
    z = z - np.max(z) # Subtract the largest score so exponentials do not overflow.
    e = np.exp(z) # Convert shifted scores into positive unnormalized weights.
    return e / np.sum(e) # Normalize weights so they sum to one.

def attention(q, K, V): # Define single-query scaled dot-product attention from scratch.
    q = np.asarray(q, dtype=float) # Ensure the query is a float vector.
    K = np.asarray(K, dtype=float) # Ensure keys are a float matrix.
    V = np.asarray(V, dtype=float) # Ensure values are a float matrix.
    weights = softmax(q @ K.T / np.sqrt(K.shape[1])) # Score all keys, scale by sqrt(d_k), and normalize.
    return weights @ V, weights # Return both the value average and the inspectable weights.

def kv_memory_bytes(layers, heads, tokens, head_dim, bytes_per_number=2, batch=1): # Estimate KV cache storage.
    return 2 * batch * layers * heads * tokens * head_dim * bytes_per_number # K plus V for every layer, head, token, and dimension.

def show_bar(labels, values, title, ylabel="value"): # Define a compact bar helper for repeated diagnostics.
    plt.figure(figsize=(4.8, 3)) # Start a readable notebook-sized figure.
    plt.bar(labels, values, color="teal") # Draw values as bars for simple comparisons.
    plt.title(title) # Label the concept being inspected.
    plt.ylabel(ylabel) # Label the numeric axis.
    plt.xticks(rotation=15) # Rotate labels slightly so long names fit.
    plt.show() # Display the figure.
```

### Basic 1 — Build one attention lookup

**Goal.** Compute scaled dot-product attention for one query, because KV caching reuses exactly this lookup at every decoding step. We build it in 2 steps.

```python
q_b1 = np.array([1.0, 0.5]) # Define one query vector for the newest token.
K_b1 = np.array([[1.0, 0.0], [0.0, 1.0], [0.8, 0.2]]) # Define three prefix keys to search over.
V_b1 = np.array([[10.0, 0.0], [0.0, 10.0], [6.0, 4.0]]) # Define the values returned by the attention weights.
print("q:", q_b1) # Inspect the query.
print("K shape:", K_b1.shape, "V shape:", V_b1.shape) # Inspect cache-like matrix shapes.
```
▶ What you'll see: one query and three key/value rows, matching a length-3 prefix.

```python
out_b1, weights_b1 = attention(q_b1, K_b1, V_b1) # Compute the attention output and the weights over prefix keys.
print("weights:", np.round(weights_b1, 3), "sum:", round(float(weights_b1.sum()), 3)) # Inspect normalized attention weights.
print("output:", np.round(out_b1, 3)) # Inspect the weighted value average.
assert round(float(weights_b1.sum()), 3) == 1.0 # Verify softmax produced normalized weights.

```
▶ What you'll see: the query puts the most weight on keys with the largest scaled dot products, then averages their values.

👀 Takeaway: KV caching speeds up inference without changing the attention lookup formula.

**Goal.** Quantize cached values to fewer bytes, because real inference systems sometimes reduce cache precision to fit longer contexts or larger batches. We build it in 4 steps.

```python
V_float_a4 = np.array([[1.5, -0.5], [0.2, 1.0], [1.0, -0.6], [0.3, 0.7]]) # Define a small value cache.
scale_a4 = 0.1 # Choose a fixed quantization scale.
zero_a4 = 128 # Choose an unsigned 8-bit zero point.
print("float value cache:\n", V_float_a4) # Inspect original values.
```
▶ What you'll see: the value cache contains small real numbers.

```python
q_a4 = np.clip(np.round(V_float_a4 / scale_a4) + zero_a4, 0, 255).astype(np.uint8) # Quantize values to uint8.
V_deq_a4 = (q_a4.astype(float) - zero_a4) * scale_a4 # Dequantize back to approximate floats.
print("quantized uint8:\n", q_a4) # Inspect stored integers.
print("dequantized:\n", np.round(V_deq_a4, 3)) # Inspect approximate recovered values.
```
▶ What you'll see: values become compact integers and recover approximately after dequantization.


▶ What you'll see: storage falls sharply, with small value reconstruction error for this scale.

### Advanced 5 — Diagnose position-shift cache bugs

**Goal.** Show that wrong cache positions change attention, because positional encodings are part of the key geometry. We build it in 4 steps.

```python
K_base_a5 = np.array([[1.0, 0.0], [0.5, 0.5], [0.0, 1.0], [0.2, 0.8]]) # Define content-only keys.
V_a5 = np.array([[1.0, 0.0], [0.5, 0.5], [0.0, 1.0], [0.2, 0.8]]) # Use matching values for easy interpretation.
q_a5 = np.array([0.4, 0.9]) # Define the newest query.
pos_step_a5 = np.array([0.05, -0.03]) # Define a tiny linear position feature.
print("base K shape:", K_base_a5.shape) # Inspect key matrix.
```
▶ What you'll see: four cached keys with a small positional feature to be added.

```python

K_right_a5 = K_base_a5 + positions_right_a5 # Add correct positional encoding to keys.
K_shift_a5 = K_base_a5 + positions_shift_a5 # Add shifted positional encoding to keys.
print("right first key:", np.round(K_right_a5[0], 3), "shifted first key:", np.round(K_shift_a5[0], 3)) # Inspect the position mismatch.
```
▶ What you'll see: the shifted cache changes every key even though content is unchanged.

