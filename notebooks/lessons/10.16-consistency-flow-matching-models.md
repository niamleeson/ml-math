# 10.16 — Consistency & Flow-Matching Models

Consistency and flow-matching models are faster generative models built around **paths** from noise to data. Flow matching learns the velocity field that moves samples along a chosen path, while consistency models learn a function whose prediction stays the same when you view the same trajectory at different noise levels.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build consistency and flow matching one idea at a time. Run each cell in order and read the printed intermediate values — every piece of math, including the vector field and ODE stepping rule, is made visible. This walkthrough is self-contained and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays, random numbers, and small vectorized simulations.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
np.random.seed(0)  # reproducibility for toy noise and toy data.
```

### 1. A transport path from noise to data

Flow matching begins by choosing a path between a noise point $x_0$ and a data point $x_1$. The simplest path is linear:

$$x_t=(1-t)x_0+t x_1, \qquad 0\le t\le 1.$$

Read this as interpolation. At $t=0$ we are exactly at noise; at $t=1$ we are exactly at data; in between we are a weighted average. The model's job is not to guess the final sample in one mysterious jump — it learns how points should move along this path.

```python
x0_w = 0.0  # one-dimensional noise endpoint.
x1_w = 2.0  # one-dimensional data endpoint.
t_w = 0.3  # an intermediate time on the path.
xt_w = (1 - t_w) * x0_w + t_w * x1_w  # linear interpolation between endpoints.
print("x_t:", round(xt_w, 4))  # 0.7*0 + 0.3*2 = 0.6.
assert round(xt_w, 4) == 0.6  # concrete check from the source lesson.
```
▶ What you'll see: the point at time 0.3 is 0.6, exactly 30% of the way from 0 to 2.

```python
ts_w = np.linspace(0, 1, 11)  # inspect the whole path at evenly spaced times.
path_w = (1 - ts_w) * x0_w + ts_w * x1_w  # compute x_t for every time.
print("path:", np.round(path_w, 2))  # a straight ramp from 0 to 2.
plt.figure(figsize=(4.4, 3))  # compact trajectory figure.
plt.plot(ts_w, path_w, marker="o", color="teal")  # show x_t versus t.
plt.xlabel("time t"); plt.ylabel("x_t")  # label the interpolation axes.
plt.title("1: linear path from noise to data"); plt.show()  # render the path.
```
▶ What you'll see: a straight line whose slope is constant — the cleanest possible transport geometry.

*Why it's done this way: the interpolation formula separates the **geometry** of generation from the neural network. If we define a path first, training can ask for the velocity needed to follow that path instead of asking the model to invent both the route and the destination at once.*

### 2. Flow matching learns the velocity field

For the linear path, differentiating with respect to time gives

$$\frac{d x_t}{dt}=x_1-x_0.$$

That derivative is the target velocity. Flow matching trains a model $v_\theta(x_t,t)$ to output this velocity from the current point and time. In a real model, $x_0$ and $x_1$ are hidden after we form $x_t$, so the network must learn the average direction that points noisy states toward data states.

```python
v_w = x1_w - x0_w  # derivative of (1-t)x0 + t*x1 with respect to t.
step_w = 0.1  # a small Euler step in time.
x_next_w = xt_w + step_w * v_w  # x_{t+dt} ≈ x_t + dt * velocity.
print("target velocity:", round(v_w, 3))  # 2 - 0 = 2.
print("one Euler step:", round(x_next_w, 4))  # 0.6 + 0.1*2 = 0.8.
assert round(v_w, 3) == 2.0 and round(x_next_w, 4) == 0.8  # source lesson numbers.
```
▶ What you'll see: the target velocity is 2, and a step of size 0.1 moves the point from 0.6 to 0.8.

```python
x0s_w = np.array([-2.0, -1.0, 0.0, 1.0])  # several noise endpoints.
x1s_w = np.array([1.0, 2.0, 2.0, 4.0])  # paired data endpoints.
t_grid_w = np.array([0.0, 0.5, 1.0])  # inspect start, middle, and end.
for pair_w in range(len(x0s_w)):  # show each training pair's constant velocity.
    xs_w = (1 - t_grid_w) * x0s_w[pair_w] + t_grid_w * x1s_w[pair_w]  # path positions.
    vel_w = x1s_w[pair_w] - x0s_w[pair_w]  # target velocity for that pair.
    print(f"pair {pair_w}: x_t={np.round(xs_w, 2)}, v={vel_w:.1f}")  # inspect target labels.
```
▶ What you'll see: each pair has a straight path and a constant velocity label, but different pairs point with different speeds.

```python
plt.figure(figsize=(4.6, 3.4))  # compact phase view.
for pair_w in range(len(x0s_w)):  # draw every path as a line over time.
    xs_w = (1 - ts_w) * x0s_w[pair_w] + ts_w * x1s_w[pair_w]  # path for this pair.
    plt.plot(ts_w, xs_w, marker=".", label=f"pair {pair_w}")  # line = trajectory.
plt.xlabel("time t"); plt.ylabel("x_t")  # axes.
plt.title("2: many paths imply many velocity labels"); plt.legend(); plt.show()  # render.
```
▶ What you'll see: every path is simple, but the collection creates a velocity-learning problem over many states.

*Why it's done this way: flow matching turns generative modeling into supervised regression on vector fields. The derivative $x_1-x_0$ is the exact direction that preserves the chosen path, so learning it teaches the sampler how to move without running a long reverse diffusion chain.*

### 3. Sampling is ODE integration through the learned field

Once a velocity field is learned, sampling means solving the ordinary differential equation

$$\frac{dx}{dt}=v_\theta(x,t).$$

The simplest solver is Euler integration: start from noise and repeatedly add $\Delta t\,v(x,t)$. If the learned field is exact for a linear path, only a few steps are enough; if the field is approximate, large steps amplify errors.

```python
def euler_integrate_w(x_start, velocity_fn, n_steps):  # integrate dx/dt = v(x,t) from t=0 to t=1.
    x = float(x_start)  # keep a scalar state for this audit-friendly example.
    history = [x]  # store states for plotting.
    dt = 1.0 / n_steps  # equal time step size.
    for k in range(n_steps):  # step through time.
        t = k * dt  # current time.
        x = x + dt * velocity_fn(x, t)  # Euler update.
        history.append(x)  # save the new state.
    return np.array(history)  # return all states.

exact_velocity_w = lambda x, t: 2.0  # exact velocity from x0=0 to x1=2.
traj_w = euler_integrate_w(0.0, exact_velocity_w, 5)  # integrate using five large steps.
print("trajectory:", np.round(traj_w, 3))  # should land exactly at 2 for a constant field.
assert round(float(traj_w[-1]), 3) == 2.0  # exact constant velocity integrates cleanly.
```
▶ What you'll see: five Euler steps move from 0 to 2 in increments of 0.4.

```python
steps_w = np.array([1, 2, 5, 10])  # compare few-step samplers.
ends_w = np.array([euler_integrate_w(0.0, exact_velocity_w, int(s))[-1] for s in steps_w])  # final states.
print("final states:", np.round(ends_w, 3))  # exact for a constant field.
plt.figure(figsize=(4.4, 3))  # compare trajectories.
for s_w in steps_w:  # plot each step count.
    hist_w = euler_integrate_w(0.0, exact_velocity_w, int(s_w))  # integrate.
    plt.plot(np.linspace(0, 1, len(hist_w)), hist_w, marker="o", label=f"{s_w} steps")  # show states.
plt.axhline(2.0, color="black", linestyle="--", linewidth=1)  # true data endpoint.
plt.xlabel("time t"); plt.ylabel("sample x")  # labels.
plt.title("3: ODE integration turns velocity into a sample"); plt.legend(); plt.show()  # render.
```
▶ What you'll see: all curves hit the same endpoint because the toy velocity is constant; real learned fields are not this forgiving.

*Why it's done this way: the probability-flow ODE view says generation can be deterministic transport. Euler's rule is just the first-order approximation to the ODE integral, and the number of steps trades sampling cost against numerical and model error.*

### 4. A probability-flow vector field moves a distribution, not one point

A generative model must move a whole cloud of noise into a whole cloud of data. In one dimension, a simple probability-flow field can contract a standard normal cloud toward a target Gaussian with mean $\mu$ and standard deviation $\sigma$:

$$x_t=(1-t)z+t(\mu+\sigma z), \qquad v(z)=\mu+(\sigma-1)z.$$

The same hidden noise coordinate $z$ traces each particle. When $\sigma<1$, the velocity both shifts the mean and compresses the spread.

```python
z_w = np.linspace(-2, 2, 9)  # deterministic noise particles for inspection.
mu_w, sigma_w = 2.0, 0.5  # target data distribution mean and scale.
t_mid_w = 0.4  # intermediate time.
x_mid_w = (1 - t_mid_w) * z_w + t_mid_w * (mu_w + sigma_w * z_w)  # probability path.
v_field_w = mu_w + (sigma_w - 1.0) * z_w  # derivative with respect to t.
print("mid mean/std:", round(float(x_mid_w.mean()), 3), round(float(x_mid_w.std()), 3))  # shifted and compressed.
print("velocities:", np.round(v_field_w, 2))  # left particles move faster right than right particles.
assert round(float(v_field_w[4]), 3) == 2.0  # particle z=0 moves by the target mean shift.
```
▶ What you'll see: the cloud has moved right and partly compressed; velocities are larger on the left than on the right.

```python
plt.figure(figsize=(5, 3.6))  # flow-field figure.
for t_plot_w in [0.0, 0.4, 0.8, 1.0]:  # show several times.
    x_plot_w = (1 - t_plot_w) * z_w + t_plot_w * (mu_w + sigma_w * z_w)  # positions at this time.
    plt.scatter(x_plot_w, np.full_like(x_plot_w, t_plot_w), s=30, label=f"t={t_plot_w}")  # cloud slice.
plt.quiver(x_mid_w, np.full_like(x_mid_w, t_mid_w), v_field_w, np.zeros_like(v_field_w),
           angles="xy", scale_units="xy", scale=10, color="crimson", width=0.006)  # velocity arrows.
plt.xlabel("x"); plt.ylabel("time t")  # axes.
plt.title("4: probability-flow field shifts and compresses a cloud"); plt.legend(); plt.show()  # render.
```
▶ What you'll see: dots drift right while getting closer together; the red arrows show the local transport direction.

*Why it's done this way: the ODE is not merely moving one sample. It moves probability mass. A valid velocity field must push every part of the noise distribution so the final ensemble has the data distribution's location and spread.*

### 5. Consistency functions agree across time on the same trajectory

A consistency model learns a function $f_\theta(x_t,t)$ that predicts the same clean endpoint from different times on the same path. For a linear path with known $x_0$ and $x_1$, the ideal consistency target is simply $x_1$ for every $t>0$. The training pressure is

$$f_\theta(x_t,t)\approx f_\theta(x_s,s)\approx x_1.$$

That is why consistency models can sample in one or a few large jumps: they learn a time-invariant answer along a trajectory, not only a tiny local denoising direction.

```python
x0_c_w, x1_c_w = -1.0, 3.0  # one path from noise to data.
times_c_w = np.array([0.2, 0.5, 0.8])  # three noisy views of the same path.
xs_c_w = (1 - times_c_w) * x0_c_w + times_c_w * x1_c_w  # states along that path.
ideal_f_w = np.full_like(xs_c_w, x1_c_w)  # ideal consistency output at every time.
print("states:", np.round(xs_c_w, 3))  # different inputs.
print("ideal f(x_t,t):", ideal_f_w)  # same clean prediction.
assert np.allclose(ideal_f_w, 3.0)  # consistency target is time-invariant on this path.
```
▶ What you'll see: the states differ, but the ideal consistency function returns 3 for all of them.

```python
def toy_consistency_w(x_t, t, x0=-1.0):  # exact inverse for the linear path when x0 is known.
    return (x_t - (1 - t) * x0) / t  # rearrange x_t=(1-t)x0+t*x1 to solve for x1.

preds_c_w = toy_consistency_w(xs_c_w, times_c_w, x0_c_w)  # recover x1 from each noisy state.
print("recovered endpoints:", np.round(preds_c_w, 3))  # all should be 3.
print("consistency spread:", round(float(preds_c_w.max() - preds_c_w.min()), 6))  # disagreement.
assert round(float(preds_c_w.max() - preds_c_w.min()), 6) == 0.0  # perfect agreement.
```
▶ What you'll see: every time slice recovers the same endpoint, so the consistency spread is zero.

```python
plt.figure(figsize=(4.6, 3))  # visualize constant predictions.
plt.plot(times_c_w, xs_c_w, marker="o", label="state x_t", color="gray")  # actual noisy states.
plt.plot(times_c_w, preds_c_w, marker="s", label="f(x_t,t)", color="seagreen")  # consistency output.
plt.axhline(x1_c_w, color="black", linestyle="--", linewidth=1, label="data endpoint")  # target.
plt.xlabel("time t"); plt.ylabel("value")  # labels.
plt.title("5: consistency output stays fixed across time"); plt.legend(); plt.show()  # render.
```
▶ What you'll see: noisy states climb along the path, while the consistency prediction is flat at the clean endpoint.

*Why it's done this way: consistency training enforces a global invariant along each trajectory. Instead of asking only “what is the next tiny velocity?”, it asks “what clean sample should all these noisy states agree on?”, which is the mathematical reason few-step sampling becomes possible.*

### ✍️ Toy 3 · Euler integration accumulates velocity steps

```python
import numpy as np
```

## 🛠️ Setup

```python
import numpy as np  # load NumPy for arrays, vector fields, ODE steps, and numerical checks.
import matplotlib.pyplot as plt  # load Matplotlib for trajectory, cloud, and flow-field visualizations.
np.random.seed(0)  # make all examples reproducible.

def linear_path(x0, x1, t):  # compute x_t=(1-t)x0+t*x1 for scalars or arrays.
    return (1 - t) * x0 + t * x1  # interpolation from noise endpoint to data endpoint.

def linear_velocity(x0, x1):  # compute the flow-matching target for a linear path.
    return x1 - x0  # derivative of x_t with respect to t.

def euler_solve(x_start, velocity_fn, n_steps):  # integrate dx/dt=v(x,t) from t=0 to 1.
    x = np.array(x_start, dtype=float)  # support scalar or vector states.
    hist = [x.copy()]  # keep every state for plotting and debugging.
    dt = 1.0 / n_steps  # uniform time step.
    for k in range(n_steps):  # advance the ODE one time slice at a time.
        t = k * dt  # current left-endpoint time.
        x = x + dt * velocity_fn(x, t)  # Euler update.
        hist.append(x.copy())  # store the updated state.
    return np.array(hist)  # return the full trajectory.

def show_1d_path(ts, xs, title):  # tiny helper for trajectory plots.
    plt.figure(figsize=(4, 3))  # compact notebook figure.
    plt.plot(ts, xs, marker="o", color="teal")  # draw time versus state.
    plt.xlabel("time t")  # label time axis.
    plt.ylabel("state x")  # label state axis.
    plt.title(title)  # describe the example.
    plt.show()  # display the figure.
```

## 🟢 Basics (warm-up)

### Basic 1 — Interpolate from noise to data

**Goal.** Compute the simplest transport path, because both flow matching and consistency models need a notion of “same trajectory.” We build it in 2 steps.

```python
x0_b1 = 0.0  # noise endpoint.
x1_b1 = 2.0  # data endpoint.
t_b1 = 0.3  # time between noise and data.
print("endpoints:", x0_b1, x1_b1, "time:", t_b1)  # inspect the path ingredients.
```
▶ What you'll see: the example uses the source lesson's hand-auditable endpoints 0 and 2.

```python
xt_b1 = linear_path(x0_b1, x1_b1, t_b1)  # compute (1-t)x0+t*x1.
print("x_t:", round(float(xt_b1), 4))  # inspect the interpolated state.
assert round(float(xt_b1), 4) == 0.6  # verify 0.7*0 + 0.3*2 = 0.6.
```


### Advanced 5 — Compare stochastic diffusion-style wandering with deterministic flow

**Goal.** Contrast noisy iterative updates with deterministic ODE transport, because flow matching and consistency models are motivated by reducing slow random denoising chains. We build it in 4 steps.

```python

steps_a5 = 20  # update count.
```

```python
    diff_a5 = diff_a5 + 0.18 * (target_a5 - diff_a5) + 0.08 * rng_a5.normal(size=n_paths_a5)  # noisy denoising-style update.

print("noisy mean/std:", round(float(diff_a5.mean()), 3), round(float(diff_a5.std()), 3))  # noisy endpoint stats.
```
