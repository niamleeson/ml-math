# 24.2 — Genetic Programming

Genetic programming (GP) keeps the evolutionary loop from genetic algorithms, but the candidate is now an executable expression tree. In this lesson, we evolve tiny symbolic-regression programs from scratch: trees predict values, supervised loss scores behavior, subtree crossover and mutation create children, and parsimony pressure keeps tree growth from turning into bloat.

## 📖 Concept walkthrough — build each idea from scratch

Before the worked examples, we build genetic programming one idea at a time. Run each cell in order and inspect the printed values and plots. The walkthrough uses a `_w` suffix so it does not clash with the examples below.

```python
import numpy as np  # arrays, vectorized evaluation, and seeded random search.
import matplotlib.pyplot as plt  # expression-tree diagrams and GP diagnostics.
import random  # standard-library randomness for tree choices.
np.random.seed(0)  # reproducible NumPy examples.
random.seed(0)  # reproducible tree choices.
```

### 1. A program is an expression tree

GP represents a candidate model as a tree: internal nodes are functions such as `+` or `*`, and leaves are variables or constants. The same tree can be printed as an expression and evaluated on data. This is the key representation shift from evolving numeric vectors to evolving executable structure.

```python
tree_w = ('+', ('*', 'x', 'x'), 1.0)  # x*x + 1, stored as nested tuples.
def eval_tree_w(t, x):
    if t == 'x':
        return x
    if isinstance(t, (int, float)):
        return np.full_like(x, float(t), dtype=float)
    op, left, right = t
    a, b = eval_tree_w(left, x), eval_tree_w(right, x)
    return a + b if op == '+' else a * b
x_w = np.array([-1., 0., 1., 2.])
yhat_w = eval_tree_w(tree_w, x_w)
print("tree:", tree_w)
print("predictions:", yhat_w)
assert np.allclose(yhat_w, [2, 1, 2, 5])
plt.figure(figsize=(5, 3))
pts_w = {'+': (0.5, 0.9), '*': (0.25, 0.55), '1': (0.75, 0.55), 'x1': (0.12, 0.2), 'x2': (0.38, 0.2)}
for a, b in [('+', '*'), ('+', '1'), ('*', 'x1'), ('*', 'x2')]:
    plt.annotate('', xy=pts_w[b], xytext=pts_w[a], arrowprops=dict(arrowstyle='->'))
for label, (px, py) in pts_w.items():
    plt.text(px, py, 'x' if label.startswith('x') else label, ha='center', va='center', bbox=dict(boxstyle='circle', fc='white'))
plt.axis('off'); plt.title('1: expression tree for x² + 1'); plt.show()
```
▶ What you'll see: a small tree whose output exactly matches $x^2+1$ on the toy inputs.

*Why it's done this way:* trees let crossover and mutation operate on syntactic parts while evaluation turns syntax into supervised predictions.

### 2. Fitness comes from supervised learning loss

A GP tree is not rewarded for looking elegant; it is rewarded for predicting target values. For symbolic regression we use mean squared error, then convert it to a score by negating or minimizing it.

```python
x_w = np.array([-1., 0., 1., 2.])
y_w = x_w ** 2 + 1
candidates_w = [('x+1', ('+', 'x', 1.0)), ('x²+1', ('+', ('*', 'x', 'x'), 1.0)), ('2x+1', ('+', ('*', 2.0, 'x'), 1.0))]
def eval_tree_w(t, x):
    if t == 'x': return x
    if isinstance(t, (int, float)): return np.full_like(x, float(t), dtype=float)
    op, l, r = t; a, b = eval_tree_w(l, x), eval_tree_w(r, x)
    return a + b if op == '+' else a * b
mses_w = np.array([np.mean((eval_tree_w(t, x_w) - y_w) ** 2) for _, t in candidates_w])
print("MSEs:", dict(zip([n for n, _ in candidates_w], np.round(mses_w, 3))))
assert np.allclose(mses_w, [2.0, 0.0, 2.5])
plt.figure(figsize=(5, 3))
plt.bar([n for n, _ in candidates_w], mses_w, color=['gray', 'seagreen', 'gray'])
plt.ylabel('mean squared error'); plt.title('2: behavior supplies fitness'); plt.show()
```
▶ What you'll see: `x²+1` wins because its prediction error is zero.

*Why it's done this way:* supervised loss makes GP a model-discovery method rather than a syntax-prettiness contest.

### 3. Closure keeps offspring valid

Closure means every subtree can be placed wherever the operators expect it. In this numeric-only lesson, every subtree maps an array of `x` values to an array of numbers, so swapping subtrees cannot create invalid syntax or incompatible types.

```python
parent1_w = ('+', ('*', 'x', 'x'), 1.0)
parent2_w = ('*', ('+', 'x', 2.0), ('+', 'x', -1.0))
child_w = ('+', ('+', 'x', 2.0), 1.0)  # subtree x*x was replaced by x+2.
x_w = np.linspace(-2, 2, 100)
def eval_tree_w(t, x):
    if t == 'x': return x
    if isinstance(t, (int, float)): return np.full_like(x, float(t), dtype=float)
    op, l, r = t; a, b = eval_tree_w(l, x), eval_tree_w(r, x)
    return a + b if op == '+' else a * b
vals_w = eval_tree_w(child_w, x_w)
print("child is finite:", bool(np.all(np.isfinite(vals_w))))
assert np.all(np.isfinite(vals_w))
plt.figure(figsize=(5, 3))
plt.plot(x_w, eval_tree_w(parent1_w, x_w), label='parent 1')
plt.plot(x_w, eval_tree_w(parent2_w, x_w), label='parent 2')
plt.plot(x_w, vals_w, label='valid child', linewidth=3)
plt.title('3: closure makes subtree swaps executable'); plt.legend(); plt.show()
```
▶ What you'll see: the child is still a valid numeric function over the whole input grid.

*Why it's done this way:* valid offspring let the search spend evaluations comparing behavior instead of repairing broken programs.

### 4. Subtree crossover swaps reusable structure

Subtree crossover chooses a branch from one parent and replaces it with a branch from another. This recombines partial solutions: one parent might contribute a useful square, another a useful shift.

```python
left_w = ('+', ('*', 'x', 'x'), 1.0)
right_w = ('*', ('+', 'x', 2.0), ('+', 'x', -1.0))
child_w = ('+', ('*', 'x', 'x'), ('+', 'x', -1.0))
x_w = np.linspace(-2, 2, 120)
def eval_tree_w(t, x):
    if t == 'x': return x
    if isinstance(t, (int, float)): return np.full_like(x, float(t), dtype=float)
    op, l, r = t; a, b = eval_tree_w(l, x), eval_tree_w(r, x)
    return a + b if op == '+' else a * b
print("child sample:", np.round(eval_tree_w(child_w, np.array([-1., 0., 1.])), 2))
plt.figure(figsize=(5.5, 3))
plt.plot(x_w, eval_tree_w(left_w, x_w), label='parent A')
plt.plot(x_w, eval_tree_w(right_w, x_w), label='parent B')
plt.plot(x_w, eval_tree_w(child_w, x_w), label='crossover child', linewidth=3)
plt.title('4: subtree crossover changes function behavior'); plt.legend(); plt.show()
```
▶ What you'll see: the child curve differs from both parents but inherits pieces of their behavior.

*Why it's done this way:* recombination explores combinations of already-useful subexpressions without enumerating every tree from scratch.

### 5. Mutation replaces a subexpression

Mutation injects new material by replacing one subtree with a randomly generated subtree. It protects GP from getting stuck when the current population lacks a needed building block.

```python
base_w = ('+', 'x', 1.0)
mutant_w = ('+', ('*', 'x', 'x'), 1.0)  # mutate leaf x into subtree x*x.
x_w = np.linspace(-2, 2, 100)
def eval_tree_w(t, x):
    if t == 'x': return x
    if isinstance(t, (int, float)): return np.full_like(x, float(t), dtype=float)
    op, l, r = t; a, b = eval_tree_w(l, x), eval_tree_w(r, x)
    return a + b if op == '+' else a * b
print("base at [-1,0,1]:", eval_tree_w(base_w, np.array([-1., 0., 1.])))
print("mutant at [-1,0,1]:", eval_tree_w(mutant_w, np.array([-1., 0., 1.])))
plt.figure(figsize=(5, 3))
plt.plot(x_w, eval_tree_w(base_w, x_w), label='before mutation')
plt.plot(x_w, eval_tree_w(mutant_w, x_w), label='after mutation')
plt.title('5: mutation can add missing curvature'); plt.legend(); plt.show()
```
▶ What you'll see: mutation turns a line into a curve by adding a square subtree.

*Why it's done this way:* crossover rearranges existing pieces, while mutation introduces new pieces the population may not yet contain.

### 6. Parsimony pressure fights bloat

Large trees can grow neutral branches that do not improve predictions. GP usually adds a complexity price, such as $\text{MSE}+\lambda|T|$, so extra nodes must earn their keep.

```python
sizes_w = np.array([5, 9, 3])
raw_mse_w = np.array([0.0, 0.0, 0.25])
lam_w = 0.05
scores_w = raw_mse_w + lam_w * sizes_w
names_w = ['small exact', 'large exact', 'short imperfect']
print("penalized scores:", dict(zip(names_w, np.round(scores_w, 3))))
assert np.allclose(scores_w, [0.25, 0.45, 0.40])
plt.figure(figsize=(5, 3))
plt.bar(names_w, raw_mse_w, label='raw MSE', color='lightgray')
plt.bar(names_w, lam_w * sizes_w, bottom=raw_mse_w, label='λ|T|', color='orange')
plt.ylabel('objective to minimize'); plt.xticks(rotation=12)
plt.title('6: parsimony prices tree size'); plt.legend(); plt.show()
```
▶ What you'll see: the smaller exact tree beats the larger exact tree because it has less complexity cost.

*Why it's done this way:* parsimony pressure is regularization for programs; it discourages bloat that does not reduce error.

### ✍️ Toy 1 · An expression tree executes on inputs

A GP individual is executable syntax. Evaluate one tiny tree on three inputs so the nested tuple
turns into numeric predictions.

```python
import numpy as np                              # arrays and tree outputs.
import matplotlib.pyplot as plt                 # one picture per toy.

t1_rng = np.random.default_rng(0)               # seeded generator  # -> seed 0
t1_tree = ('*', ('+', 'x', 1.0), 2.0)           # tree 2*(x+1)      # -> 2x + 2
t1_x = np.array([-1.0, 0.0, 2.0])               # inputs            # -> [-1, 0, 2]

def t1_eval_tree(t1_t, t1_x_values):
    if t1_t == 'x':
        return t1_x_values
    if isinstance(t1_t, (int, float)):
        return np.full_like(t1_x_values, float(t1_t), dtype=float)
    t1_op = t1_t[0]
    t1_left = t1_eval_tree(t1_t[1], t1_x_values)
    t1_right = t1_eval_tree(t1_t[2], t1_x_values)
    if t1_op == '+':
        return t1_left + t1_right
    return t1_left * t1_right

t1_pred = t1_eval_tree(t1_tree, t1_x)           # predictions       # -> [0, 2, 6]
print("tree:", t1_tree)                        # -> ('*', ('+', 'x', 1.0), 2.0)
print("x:", t1_x.tolist())                     # -> [-1.0, 0.0, 2.0]
print("predictions:", t1_pred.tolist())        # -> [0.0, 2.0, 6.0]
assert np.allclose(t1_pred, [0.0, 2.0, 6.0])    # the tree computes 2*(x+1).

plt.figure(figsize=(4.8, 2.8))
plt.plot(t1_x, t1_pred, marker="o", color="teal")
plt.xlabel("x"); plt.ylabel("tree output")
plt.title("Toy 1 · tree syntax becomes numbers"); plt.show()
```
▶ What you'll see: the tree maps `[-1,0,2]` to `[0,2,6]`.

### ✍️ Toy 2 · Supervised loss ranks trees

The best-looking program is the one with the smallest prediction error, not the prettiest syntax.
Compare three tiny trees against a target table.

```python
import numpy as np                              # arrays and losses.

t2_rng = np.random.default_rng(0)               # seeded generator       # -> seed 0
t2_x = np.array([-1.0, 0.0, 1.0, 2.0])          # inputs                 # -> [-1, 0, 1, 2]
t2_y = t2_x ** 2                                # target x^2             # -> [1, 0, 1, 4]
t2_names = np.array(["x", "x*x", "x+1"])      # candidate names        # -> x, x*x, x+1
t2_trees = ['x', ('*', 'x', 'x'), ('+', 'x', 1.0)]  # candidate trees

def t2_eval_tree(t2_t, t2_x_values):
    if t2_t == 'x':
        return t2_x_values
    if isinstance(t2_t, (int, float)):
        return np.full_like(t2_x_values, float(t2_t), dtype=float)
    t2_op = t2_t[0]
    t2_left = t2_eval_tree(t2_t[1], t2_x_values)
    t2_right = t2_eval_tree(t2_t[2], t2_x_values)
    if t2_op == '+':
        return t2_left + t2_right
    return t2_left * t2_right

t2_pred = np.array([t2_eval_tree(t2_tree, t2_x) for t2_tree in t2_trees])  # predictions  # -> rows for x, x*x, x+1
t2_errors = t2_pred - t2_y                      # residuals             # -> compare to target
t2_mse = np.mean(t2_errors ** 2, axis=1)        # mean squared errors   # -> [2, 0, 1]
t2_winner = int(np.argmin(t2_mse))              # best tree index       # -> 1
print("target:", t2_y.tolist())                # -> [1.0, 0.0, 1.0, 4.0]
print("predictions:", t2_pred.tolist())        # -> [[-1,0,1,2], [1,0,1,4], [0,1,2,3]]
print("MSE:", dict(zip(t2_names.tolist(), t2_mse.tolist())))  # -> {'x': 2.0, 'x*x': 0.0, 'x+1': 1.0}
print("winner:", t2_names[t2_winner])          # -> x*x
assert t2_names[t2_winner] == "x*x"             # exact behavior wins.

plt.figure(figsize=(4.8, 2.8))
plt.bar(t2_names, t2_mse, color=["gray", "seagreen", "gray"])
plt.ylabel("MSE"); plt.title("Toy 2 · lower loss is better fitness"); plt.show()
```
▶ What you'll see: `x*x` has zero MSE and wins the behavior test.

### ✍️ Toy 3 · Closure keeps subtree swaps valid

In a closed numeric GP system, every subtree returns numbers on the same input array. Swapping a
subtree therefore still yields a runnable child.

```python
import numpy as np                              # arrays and finite checks.

t3_rng = np.random.default_rng(0)               # seeded generator       # -> seed 0
t3_parent_a = ('+', ('*', 'x', 'x'), 1.0)       # parent A: x^2 + 1
t3_parent_b = ('*', ('+', 'x', 1.0), 2.0)       # parent B: 2*(x+1)
t3_child = ('+', ('+', 'x', 1.0), 1.0)          # child: (x+1)+1
t3_x = np.array([-2.0, -1.0, 0.0, 1.0, 2.0])   # inputs  # -> [-2, -1, 0, 1, 2]

def t3_eval_tree(t3_t, t3_x_values):
    if t3_t == 'x':
        return t3_x_values
    if isinstance(t3_t, (int, float)):
        return np.full_like(t3_x_values, float(t3_t), dtype=float)
    t3_op = t3_t[0]
    t3_left = t3_eval_tree(t3_t[1], t3_x_values)
    t3_right = t3_eval_tree(t3_t[2], t3_x_values)
    if t3_op == '+':
        return t3_left + t3_right
    return t3_left * t3_right

t3_a_vals = t3_eval_tree(t3_parent_a, t3_x)     # parent A values  # -> [5, 2, 1, 2, 5]
t3_b_vals = t3_eval_tree(t3_parent_b, t3_x)     # parent B values  # -> [-2, 0, 2, 4, 6]
t3_child_vals = t3_eval_tree(t3_child, t3_x)    # child values     # -> [0, 1, 2, 3, 4]
t3_is_finite = bool(np.all(np.isfinite(t3_child_vals)))  # validity # -> True
print("parent A:", t3_a_vals.tolist())         # -> [5.0, 2.0, 1.0, 2.0, 5.0]
print("parent B:", t3_b_vals.tolist())         # -> [-2.0, 0.0, 2.0, 4.0, 6.0]
print("child:", t3_child_vals.tolist())        # -> [0.0, 1.0, 2.0, 3.0, 4.0]
print("child finite:", t3_is_finite)           # -> True
assert t3_is_finite                             # closure produced an executable numeric child.

plt.figure(figsize=(4.8, 2.8))
plt.plot(t3_x, t3_a_vals, marker="o", label="parent A")
plt.plot(t3_x, t3_b_vals, marker="s", label="parent B")
plt.plot(t3_x, t3_child_vals, marker="^", linewidth=3, label="child")
plt.xlabel("x"); plt.ylabel("output"); plt.legend()
plt.title("Toy 3 · closure keeps offspring runnable"); plt.show()
```
▶ What you'll see: the child curve is finite at every input, so the swap needs no repair.

### ✍️ Toy 4 · Subtree crossover recombines behavior

Crossover can keep one parent's square and borrow another parent's shifted branch, producing a new
function without inventing every node from scratch.

```python
import numpy as np                              # arrays and tree evaluation.

t4_rng = np.random.default_rng(0)               # seeded generator       # -> seed 0
t4_parent_a = ('+', ('*', 'x', 'x'), ('*', 2.0, 'x'))  # x^2 + 2x
t4_parent_b = ('*', ('+', 'x', 1.0), ('+', 'x', -1.0)) # (x+1)(x-1)
t4_donor = ('+', 'x', -1.0)                     # borrowed subtree      # -> x - 1
t4_child = ('+', ('*', 'x', 'x'), t4_donor)     # child: x^2 + x - 1
t4_x = np.array([-1.0, 0.0, 1.0])               # sample inputs         # -> [-1, 0, 1]

def t4_eval_tree(t4_t, t4_x_values):
    if t4_t == 'x':
        return t4_x_values
    if isinstance(t4_t, (int, float)):
        return np.full_like(t4_x_values, float(t4_t), dtype=float)
    t4_op = t4_t[0]
    t4_left = t4_eval_tree(t4_t[1], t4_x_values)
    t4_right = t4_eval_tree(t4_t[2], t4_x_values)
    if t4_op == '+':
        return t4_left + t4_right
    return t4_left * t4_right

t4_a_vals = t4_eval_tree(t4_parent_a, t4_x)     # parent A sample  # -> [-1, 0, 3]
t4_b_vals = t4_eval_tree(t4_parent_b, t4_x)     # parent B sample  # -> [0, -1, 0]
t4_b_vals = np.where(np.isclose(t4_b_vals, 0.0), 0.0, t4_b_vals)  # remove signed zero # -> [0, -1, 0]
t4_child_vals = t4_eval_tree(t4_child, t4_x)    # child sample     # -> [-1, -1, 1]
print("donor subtree:", t4_donor)              # -> ('+', 'x', -1.0)
print("parent A sample:", t4_a_vals.tolist())  # -> [-1.0, 0.0, 3.0]
print("parent B sample:", t4_b_vals.tolist())  # -> [0.0, -1.0, 0.0]
print("child sample:", t4_child_vals.tolist()) # -> [-1.0, -1.0, 1.0]
assert np.allclose(t4_child_vals, [-1.0, -1.0, 1.0])  # child has its own behavior.

plt.figure(figsize=(4.8, 2.8))
t4_grid = np.linspace(-2.0, 2.0, 100)
plt.plot(t4_grid, t4_eval_tree(t4_parent_a, t4_grid), label="parent A")
plt.plot(t4_grid, t4_eval_tree(t4_parent_b, t4_grid), label="parent B")
plt.plot(t4_grid, t4_eval_tree(t4_child, t4_grid), linewidth=3, label="child")
plt.xlabel("x"); plt.ylabel("output"); plt.legend()
plt.title("Toy 4 · subtree crossover changes the curve"); plt.show()
```
▶ What you'll see: the child is a new curve that visibly differs from both parents.

### ✍️ Toy 5 · Mutation replaces one leaf with a subtree

Mutation introduces a missing building block. Replacing a leaf `x` by `x*x` turns a line into a
curved program.

```python
import numpy as np                              # arrays and tree outputs.

t5_rng = np.random.default_rng(0)               # seeded generator       # -> seed 0
t5_base = ('+', 'x', 1.0)                       # base tree: x + 1
t5_replacement = ('*', 'x', 'x')                # mutation subtree       # -> x*x
t5_mutant = ('+', t5_replacement, 1.0)          # mutant: x*x + 1
t5_x = np.array([-1.0, 0.0, 1.0, 2.0])          # inputs                 # -> [-1, 0, 1, 2]

def t5_eval_tree(t5_t, t5_x_values):
    if t5_t == 'x':
        return t5_x_values
    if isinstance(t5_t, (int, float)):
        return np.full_like(t5_x_values, float(t5_t), dtype=float)
    t5_op = t5_t[0]
    t5_left = t5_eval_tree(t5_t[1], t5_x_values)
    t5_right = t5_eval_tree(t5_t[2], t5_x_values)
    if t5_op == '+':
        return t5_left + t5_right
    return t5_left * t5_right

t5_base_vals = t5_eval_tree(t5_base, t5_x)      # before mutation  # -> [0, 1, 2, 3]
t5_mut_vals = t5_eval_tree(t5_mutant, t5_x)     # after mutation   # -> [2, 1, 2, 5]
print("replacement subtree:", t5_replacement)  # -> ('*', 'x', 'x')
print("base outputs:", t5_base_vals.tolist())  # -> [0.0, 1.0, 2.0, 3.0]

```
▶ What you'll see: the mutated curve bends upward while the base program stays linear.

### ✍️ Toy 6 · Parsimony prices extra nodes

Two programs can fit equally well, so GP often adds a size penalty. The smaller exact tree wins over
a bloated exact tree.

```python
import numpy as np                              # arrays and penalized scores.

t6_rng = np.random.default_rng(0)               # seeded generator       # -> seed 0
t6_names = np.array(["small exact", "bloated exact", "tiny wrong"])  # programs
t6_mse = np.array([0.0, 0.0, 0.16])             # raw prediction loss    # -> [0, 0, 0.16]
t6_sizes = np.array([3.0, 7.0, 2.0])            # node counts            # -> [3, 7, 2]
t6_lambda = 0.05                                # size price            # -> 0.05
t6_penalty = t6_lambda * t6_sizes               # complexity cost       # -> [0.15, 0.35, 0.1]
t6_total = t6_mse + t6_penalty                  # penalized objective   # -> [0.15, 0.35, 0.26]
t6_winner = int(np.argmin(t6_total))            # best index            # -> 0
print("raw MSE:", t6_mse.tolist())             # -> [0.0, 0.0, 0.16]
print("sizes:", t6_sizes.tolist())             # -> [3.0, 7.0, 2.0]
print("penalty:", np.round(t6_penalty, 3).tolist())  # -> [0.15, 0.35, 0.1]
print("total:", np.round(t6_total, 3).tolist())      # -> [0.15, 0.35, 0.26]
print("winner:", t6_names[t6_winner])          # -> small exact
assert t6_names[t6_winner] == "small exact"     # parsimony breaks the exact-fit tie.
```

## 🛠️ Setup

```python
import numpy as np  # arrays and vectorized tree evaluation.
import matplotlib.pyplot as plt  # every example includes a GP-relevant visualization.
import random  # standard-library tree sampling, crossover, and mutation.
np.random.seed(0)  # reproducible NumPy behavior.
random.seed(0)  # reproducible Python random behavior.

OPS = ('+', '-', '*')  # closed numeric binary operators used throughout the lesson.
CONSTS = (-2.0, -1.0, 0.5, 1.0, 2.0)  # small constants so random trees stay interpretable.

def is_leaf(t):  # check whether a tree node is a terminal.
    return t == 'x' or isinstance(t, (int, float))

def eval_tree(t, x):  # evaluate a numeric expression tree on a NumPy input array.
    if t == 'x':
        return x.astype(float)
    if isinstance(t, (int, float)):
        return np.full_like(x, float(t), dtype=float)
    op, left, right = t
    a, b = eval_tree(left, x), eval_tree(right, x)
    if op == '+':
        return a + b
    if op == '-':
        return a - b
    if op == '*':
        return a * b
    raise ValueError('unknown operator')

def tree_size(t):  # count nodes as a simple complexity measure.
    return 1 if is_leaf(t) else 1 + tree_size(t[1]) + tree_size(t[2])

def tree_depth(t):  # measure maximum root-to-leaf depth.
    return 0 if is_leaf(t) else 1 + max(tree_depth(t[1]), tree_depth(t[2]))

def tree_str(t):  # print a tree as an infix expression.
    if t == 'x':
        return 'x'
    if isinstance(t, (int, float)):
        return str(int(t)) if float(t).is_integer() else str(float(t))
    return '(' + tree_str(t[1]) + ' ' + t[0] + ' ' + tree_str(t[2]) + ')'

def random_tree(rng, max_depth):  # sample a closed expression tree.
    if max_depth == 0 or rng.random() < 0.35:
        return 'x' if rng.random() < 0.55 else float(rng.choice(CONSTS))
    return (rng.choice(OPS), random_tree(rng, max_depth - 1), random_tree(rng, max_depth - 1))

def paths(t):  # list all subtree paths, with () meaning the root.
    if is_leaf(t):
        return [()]
    return [()] + [(1,) + p for p in paths(t[1])] + [(2,) + p for p in paths(t[2])]

def get_subtree(t, path):  # read a subtree by path.
    for step in path:
        t = t[step]
    return t

def replace_subtree(t, path, repl):  # return a copy of t with one subtree replaced.
    if not path:
        return repl
    op, left, right = t
    if path[0] == 1:
        return (op, replace_subtree(left, path[1:], repl), right)
    return (op, left, replace_subtree(right, path[1:], repl))

def crossover(a, b, rng):  # subtree crossover between two numeric trees.
    pa_list = paths(a)
    pb_list = paths(b)
    pa = pa_list[int(rng.integers(len(pa_list)))]
    pb = pb_list[int(rng.integers(len(pb_list)))]
    return replace_subtree(a, pa, get_subtree(b, pb))

def mutate(t, rng, max_depth=2):  # replace a random subtree with a new random tree.
    p_list = paths(t)
    return replace_subtree(t, p_list[int(rng.integers(len(p_list)))], random_tree(rng, max_depth))

def mse(t, x, y):  # supervised regression loss for one tree.
    pred = np.clip(eval_tree(t, x), -1e6, 1e6)
    return float(np.mean((pred - y) ** 2)) if np.all(np.isfinite(pred)) else 1e12

def objective(t, x, y, lam=0.0):  # MSE plus optional parsimony penalty.
    return mse(t, x, y) + lam * tree_size(t)

def tournament(pop, losses, rng, k=3):  # choose the best among k random candidates.
    idx = rng.choice(len(pop), size=k, replace=False)
    return pop[int(idx[np.argmin(np.array(losses)[idx])])]

def draw_simple_tree(labels, edges, title):  # small text-arrow expression-tree diagram.
    plt.figure(figsize=(5, 3))
    for a, b in edges:
        plt.annotate('', xy=labels[b][1], xytext=labels[a][1], arrowprops=dict(arrowstyle='->'))
    for key, (label, pos) in labels.items():
        plt.text(pos[0], pos[1], label, ha='center', va='center', bbox=dict(boxstyle='round', fc='white'))
    plt.axis('off')
    plt.title(title)
    plt.show()
```

#### A1. Track bloat with and without parsimony

**Goal.** Compare average tree size across generations, because GP can bloat when selection ignores complexity. We build it in 4 steps.

```python
def run_gp_a1(lam_a1):
    rng_a1 = np.random.default_rng(11)  # same seed for a fair parsimony comparison.
    x_a1 = np.linspace(-2, 2, 50); y_a1 = x_a1 ** 2 + x_a1 + 1
    pop_a1 = [random_tree(rng_a1, 3) for _ in range(40)]
    best_a1, size_a1 = [], []
    for gen_a1 in range(35):
        losses_a1 = [objective(t, x_a1, y_a1, lam=lam_a1) for t in pop_a1]
        best_a1.append(min(losses_a1)); size_a1.append(np.mean([tree_size(t) for t in pop_a1]))
        new_a1 = [pop_a1[int(np.argmin(losses_a1))]]
        while len(new_a1) < len(pop_a1):
            p1_a1 = tournament(pop_a1, losses_a1, rng_a1); p2_a1 = tournament(pop_a1, losses_a1, rng_a1)
            child_a1 = crossover(p1_a1, p2_a1, rng_a1) if rng_a1.random() < 0.75 else p1_a1
            if rng_a1.random() < 0.35:
                child_a1 = mutate(child_a1, rng_a1, max_depth=2)
            new_a1.append(child_a1)
        pop_a1 = new_a1
    return np.array(best_a1), np.array(size_a1)
print("helper ready")
```
▶ What you'll see: the helper runs the same GP recipe for any parsimony weight.

```python

    best_obj_a5.append(float(losses_a5[best_idx_a5])); avg_size_a5.append(float(np.mean([tree_size(t) for t in pop_a5])))
```
