# 10.19 — Video & 3D Generation

Video and 3D generation extend image generation with structure that a single picture can ignore: time must move smoothly, viewpoints must agree, and geometry must remain shared underneath every rendered frame. In this lesson, we build those ideas from scratch with tiny NumPy scenes so every consistency term, projection, voxel grid, and ray-sampling step is inspectable.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build video and 3D generation one idea at a time. Run each cell in order and read the printed intermediate values — every piece of math is spelled out so temporal consistency, projection geometry, voxels, and NeRF-style sampling are not black boxes. This walkthrough is self-contained and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays, linear algebra, grids, and synthetic toy scenes.
import matplotlib.pyplot as plt  # plots, frame grids, 3D scatters, and voxel displays.
np.random.seed(0)  # reproducibility for all toy generation.
```

### 1. Temporal consistency: a generated object should follow one latent trajectory

A video is not just a stack of good-looking images. The same object should have a state that evolves through time, so we start with the smallest possible motion model: a 3D point with initial position $p_0$ and velocity $v$. The latent state at time $t$ is

$$p_t=p_0+t v.$$

This says every frame is tied to the same hidden cause. If a generator resamples position independently per frame, each still frame might look plausible, but the sequence flickers because adjacent frames disagree about where the object is.

```python
p0_w = np.array([0.0, 0.0, 0.0])  # initial 3D point.
v_w = np.array([1.0, 0.5, 0.2])  # constant velocity in x, y, and z.
t_w = 3.0  # the lesson's hand-checkable time.
p3_w = p0_w + t_w * v_w  # p_t = p_0 + t v.
speed_w = np.linalg.norm(v_w)  # Euclidean speed, length of the velocity vector.
print("p_3:", np.round(p3_w, 4))
print("speed:", round(speed_w, 3))
assert np.allclose(p3_w, [3.0, 1.5, 0.6])
assert round(speed_w, 3) == 1.136
```
▶ What you'll see: at `t=3`, the point is exactly `(3.000, 1.500, 0.6000)` and the speed is `1.136`.

```python
times_w = np.arange(6)  # six video frames.
traj_w = p0_w[None, :] + times_w[:, None] * v_w[None, :]  # one shared trajectory for all frames.
print("trajectory:\n", np.round(traj_w, 2))
```
▶ What you'll see: x, y, and z advance by fixed increments each frame, so the object has memory.

```python
noise_w = np.array([[0.00, 0.00, 0.00], [0.10, -0.05, 0.00], [-0.08, 0.10, 0.03],
                    [0.06, -0.12, 0.00], [-0.05, 0.08, -0.02], [0.04, -0.04, 0.01]])
independent_w = traj_w + noise_w  # plausible per-frame locations with small inconsistencies.
smooth_cost_w = float(np.sum((np.diff(independent_w, axis=0) - v_w) ** 2))  # deviations from constant motion.
print("temporal consistency cost:", round(smooth_cost_w, 4))
assert round(smooth_cost_w, 4) == 0.2131
```
▶ What you'll see: the cost is positive because neighboring frames do not all agree with the same velocity.

```python
plt.figure(figsize=(5, 3))
plt.plot(times_w, traj_w[:, 0], marker="o", label="shared trajectory x")
plt.plot(times_w, independent_w[:, 0], marker="s", label="independent frame x")
plt.xlabel("frame t"); plt.ylabel("x position"); plt.title("1: temporal consistency vs flicker")
plt.legend(); plt.show()
```
▶ What you'll see: the shared trajectory is a clean line, while independently changed frame positions wobble around it.

*Why it's done this way:* the formula $p_t=p_0+tv$ compresses many frames into one initial state plus one velocity. The temporal loss compares actual frame-to-frame changes with that shared velocity, so the model is rewarded for preserving identity and motion instead of inventing a new object position at every time step.

### 2. Projection: 3D state becomes frames through camera geometry

A 3D generator must decide not only where points live in space, but also how a camera sees them. We use the pinhole projection rule

$$u=f\frac{x}{z},\qquad v=f\frac{y}{z},$$

where $(x,y,z)$ is a 3D point and $f$ is the focal length. Dividing by depth $z$ is the key geometry: points farther away look closer to the image center. If two views share the same 3D point cloud, their images remain consistent because both are projections of one underlying scene.

```python
points3_w = np.array([[-1.0, -1.0, 4.0], [1.0, -1.0, 4.0], [1.0, 1.0, 4.0], [-1.0, 1.0, 4.0],
                      [-1.0, -1.0, 6.0], [1.0, -1.0, 6.0], [1.0, 1.0, 6.0], [-1.0, 1.0, 6.0]])
f_w = 2.0
uv_w = f_w * points3_w[:, :2] / points3_w[:, 2:3]
print("projected first four corners:\n", np.round(uv_w[:4], 3))
assert np.allclose(np.round(uv_w[0], 3), [-0.5, -0.5])
```
▶ What you'll see: near cube corners at depth 4 project to image coordinates around ±0.5.

```python
near_size_w = uv_w[:4, 0].max() - uv_w[:4, 0].min()
far_size_w = uv_w[4:, 0].max() - uv_w[4:, 0].min()
print("near projected width:", round(float(near_size_w), 3))
print("far projected width:", round(float(far_size_w), 3))
assert round(float(near_size_w), 3) == 1.0
assert round(float(far_size_w), 3) == 0.667
```
▶ What you'll see: the farther square is smaller because the same 3D width is divided by a larger depth.

```python
fig = plt.figure(figsize=(8, 3))
ax0 = fig.add_subplot(1, 2, 1, projection="3d")
ax0.scatter(points3_w[:, 0], points3_w[:, 1], points3_w[:, 2], c=points3_w[:, 2], cmap="viridis", s=70)
ax0.set_title("2: shared 3D cube"); ax0.set_xlabel("x"); ax0.set_ylabel("y"); ax0.set_zlabel("z")
ax1 = fig.add_subplot(1, 2, 2)
ax1.scatter(uv_w[:, 0], uv_w[:, 1], c=points3_w[:, 2], cmap="viridis", s=70)
ax1.set_aspect("equal"); ax1.set_title("pinhole projection"); ax1.set_xlabel("u"); ax1.set_ylabel("v")
plt.show()
```
▶ What you'll see: the 3D cube has two depth layers, and the projected far layer appears tighter toward the center.

*Why it's done this way:* projection is a deterministic decoder from latent geometry to pixels. Sharing 3D points before projecting means different views are not independent guesses; they are constrained outputs of the same scene, which is exactly the geometric consistency missing from image-only generation.

### 3. Voxels: generate a 3D object as occupied cells

A voxel grid is the 3D analogue of a pixel image: each cell says whether a small cube of space is occupied. This representation is simple, discrete, and easy to visualize. The downside is resolution: doubling detail in each axis multiplies memory by $2^3=8$, so voxel models are great for toy geometry but expensive at high resolution.

```python
grid_w = np.linspace(-1.0, 1.0, 9)
X_w, Y_w, Z_w = np.meshgrid(grid_w, grid_w, grid_w, indexing="ij")
radius_w = 0.75
sphere_w = X_w**2 + Y_w**2 + Z_w**2 <= radius_w**2
print("grid shape:", sphere_w.shape)
print("occupied voxels:", int(sphere_w.sum()))
assert sphere_w.shape == (9, 9, 9)
assert int(sphere_w.sum()) == 123
```
▶ What you'll see: a 9×9×9 grid with 123 occupied cells forming a coarse sphere.

```python
z_mid_w = sphere_w[:, :, 4]
print("middle z-slice occupied cells:", int(z_mid_w.sum()))
plt.figure(figsize=(3.4, 3.2))
plt.imshow(z_mid_w.T, origin="lower", cmap="Greys")
plt.title("3: voxel sphere middle slice"); plt.xlabel("x cell"); plt.ylabel("y cell"); plt.show()
```
▶ What you'll see: the central slice is a filled disk, because slicing a sphere through its center gives a circle.

```python
fig = plt.figure(figsize=(4, 4))
ax = fig.add_subplot(111, projection="3d")
ax.voxels(sphere_w, facecolors="skyblue", edgecolor="k", linewidth=0.2)
ax.set_title("3: generated voxel object")
plt.show()
```
▶ What you'll see: a blocky 3D ball made of occupied cube cells; look for stair-step edges from coarse resolution.

*Why it's done this way:* a voxel generator can treat geometry like a 3D image and predict occupancy per cell. The occupancy formula $x^2+y^2+z^2\le r^2$ is a hand-coded generator for a sphere; learned voxel models replace that rule with probabilities, but still need spatial consistency so neighboring occupied cells form coherent surfaces.

### 4. NeRF-style ray sampling: render by accumulating density and color

NeRF replaces hard voxels with a continuous function that returns density and color at any 3D location. A camera ray samples points through space, converts density to opacity, and alpha-composites colors from front to back. In one dimension along a ray, the essential equations are

$$\alpha_i=1-\exp(-\sigma_i\Delta_i),\qquad w_i=T_i\alpha_i,$$

where $\sigma_i$ is density, $\Delta_i$ is sample spacing, $\alpha_i$ is local opacity, and $T_i$ is how much light survived earlier samples.

```python
depth_w = np.linspace(1.0, 5.0, 9)
delta_w = depth_w[1] - depth_w[0]
sigma_w = np.exp(-0.5 * ((depth_w - 3.0) / 0.45) ** 2) * 3.0
color_w = np.stack([depth_w / depth_w.max(), 0.3 * np.ones_like(depth_w), 1.0 - depth_w / depth_w.max()], axis=1)
print("depth samples:", np.round(depth_w, 2))
print("densities:", np.round(sigma_w, 3))
assert round(float(sigma_w[4]), 3) == 3.0
```
▶ What you'll see: density peaks near depth 3, so the ray mostly hits a surface there.

```python
alpha_w = 1.0 - np.exp(-sigma_w * delta_w)
trans_w = np.cumprod(np.r_[1.0, 1.0 - alpha_w[:-1]])
weights_w = trans_w * alpha_w
rgb_w = weights_w @ color_w
print("alpha:", np.round(alpha_w, 3))
print("weights sum:", round(float(weights_w.sum()), 3))
print("rendered RGB:", np.round(rgb_w, 3))
assert round(float(weights_w.sum()), 3) == 0.966
```
▶ What you'll see: weights concentrate around the dense middle samples, and their sum is below 1 because some background light survives.

```python
plt.figure(figsize=(5, 3))
plt.plot(depth_w, sigma_w, marker="o", label="density σ")
plt.bar(depth_w, weights_w, width=0.18, alpha=0.5, label="render weight")
plt.xlabel("depth along ray"); plt.title("4: ray samples become render weights")
plt.legend(); plt.show()
```
▶ What you'll see: high density creates high render weights, but only after accounting for visibility from earlier samples.

*Why it's done this way:* the exponential opacity formula comes from survival probability through matter: dense or long intervals block more light. Multiplying by transmittance makes the renderer depth-aware, so a back surface cannot incorrectly shine through a front surface. This is the mathematical pressure that makes different views agree in a continuous 3D representation.

## 🛠️ Setup

```python
import numpy as np  # load NumPy for arrays, synthetic video, projections, voxel grids, and ray math.
import matplotlib.pyplot as plt  # load Matplotlib for frame plots, heatmaps, 3D scatters, and voxel visualizations.
np.random.seed(0)  # make every random toy example reproducible.

def project_points(P, f=1.0):  # project 3D points to 2D pinhole coordinates.
    P = np.asarray(P, dtype=float)  # ensure numeric array inputs.
    return f * P[:, :2] / P[:, 2:3]  # divide x,y by depth z and scale by focal length.

def temporal_cost(path, velocity):  # measure how much consecutive displacements deviate from one velocity.
    path = np.asarray(path, dtype=float)  # convert a sequence of positions to floats.
    velocity = np.asarray(velocity, dtype=float)  # convert the reference velocity to floats.
    return float(np.sum((np.diff(path, axis=0) - velocity) ** 2))  # squared smoothness/consistency penalty.

def make_sphere_voxels(n, radius):  # generate a centered voxel sphere.
    grid = np.linspace(-1.0, 1.0, n)  # coordinates for each voxel center along one axis.
    X, Y, Z = np.meshgrid(grid, grid, grid, indexing="ij")  # 3D coordinate arrays.
    return X**2 + Y**2 + Z**2 <= radius**2  # occupied cells inside the sphere.

def render_ray(depth, sigma, color):  # alpha-composite colors along one camera ray.
    depth = np.asarray(depth, dtype=float)  # depth samples along the ray.
    sigma = np.asarray(sigma, dtype=float)  # density at each sample.
    color = np.asarray(color, dtype=float)  # RGB color at each sample.
    delta = float(depth[1] - depth[0]) if len(depth) > 1 else 1.0  # uniform sample spacing.
    alpha = 1.0 - np.exp(-sigma * delta)  # convert density over distance into local opacity.
    trans = np.cumprod(np.r_[1.0, 1.0 - alpha[:-1]])  # light surviving before each sample.
    weights = trans * alpha  # visible contribution of each sample.
    return weights @ color, weights, alpha  # rendered RGB plus inspectable weights.
```

### Advanced 1 — Smooth a noisy generated trajectory

**Goal.** Fit one constant-velocity path to noisy frame positions, because post-processing or training losses often pull video latents toward smooth trajectories. We build it in 4 steps.

```python

obs_a1 = true_a1 + noise_a1
print("observed first/last:", np.round(obs_a1[0], 2), np.round(obs_a1[-1], 2))
```
▶ What you'll see: noisy observations around an underlying line.

```python
A_a1 = np.c_[np.ones_like(t_a1), t_a1]
coef_x_a1 = np.linalg.lstsq(A_a1, obs_a1[:, 0], rcond=None)[0]
coef_y_a1 = np.linalg.lstsq(A_a1, obs_a1[:, 1], rcond=None)[0]
fit_a1 = np.c_[A_a1 @ coef_x_a1, A_a1 @ coef_y_a1]
print("fitted velocity:", np.round([coef_x_a1[1], coef_y_a1[1]], 3))
assert np.allclose(np.round([coef_x_a1[1], coef_y_a1[1]], 1), [0.8, -0.3])
```
▶ What you'll see: least squares recovers a velocity close to the true motion.

