# 7.20 — Vision Transformers (ViT)

A Vision Transformer turns an image into a short sentence of patch tokens, adds position information so the model knows where each visual word came from, then uses scaled dot-product attention to let every patch borrow information from every other patch before a classification head makes a prediction.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build ViT one idea at a time. Run each cell in order and read the printed intermediate values — every reshape, projection, attention weight, and probability is shown so the image-to-transformer recipe is not a black box. This walkthrough is self-contained (it imports what it needs) and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays, reshapes, projections, attention, and small numerical checks.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
```

### 1. Patches turn an image grid into tokens

ViT starts by refusing to treat every pixel as its own token. A pixel-level sequence is too long, so we group nearby pixels into fixed-size non-overlapping patches. For a 4×4 grayscale image and 2×2 patches, there are `4/2 = 2` patches along each side and `2×2 = 4` total tokens. Each token is just the flattened 2×2 block before the model learns any meaning.

```python
img_w = np.arange(16, dtype=float).reshape(4, 4)  # a tiny 4x4 image with visible pixel identities.
patch_w = 2  # each visual word will cover a 2x2 block.
print("image shape:", img_w.shape)
print(img_w)
```
▶ What you'll see: a 4×4 grid where neighboring pixels can be grouped into four 2×2 visual words.

```python
patches_w = []  # collect flattened 2x2 patches in reading order.
for r_w in range(0, img_w.shape[0], patch_w):
    for c_w in range(0, img_w.shape[1], patch_w):
        patches_w.append(img_w[r_w:r_w+patch_w, c_w:c_w+patch_w].reshape(-1))
patches_w = np.array(patches_w)  # shape: number_of_patches x pixels_per_patch.
print("patch table shape:", patches_w.shape)
print(patches_w)
assert patches_w.shape == (4, 4)
```
▶ What you'll see: four rows, each holding the four pixels from one 2×2 patch.

```python
plt.figure(figsize=(4, 3))
plt.imshow(img_w, cmap="viridis")
for cut_w in [1.5]:
    plt.axhline(cut_w, color="white", linewidth=2)
    plt.axvline(cut_w, color="white", linewidth=2)
plt.title("1: 4x4 image split into 2x2 patches")
plt.colorbar(label="pixel value")
plt.show()
```
▶ What you'll see: white grid lines mark the four patches that become the four transformer tokens.

*Why it's done this way:* attention costs grow roughly with the square of sequence length. Grouping 16 pixels into 4 patch tokens cuts the pair count from `16×16 = 256` to `4×4 = 16`, while still preserving local pixel neighborhoods inside each token.

### 2. A patch embedding is a learned linear projection

A flattened patch is raw pixels, but a transformer expects vectors in a common embedding dimension. ViT learns a matrix `E` that maps each patch vector into an embedding: `tokens = patches @ E`. This is the same linear algebra as a dense layer applied independently to every visual word.

```python
E_w = np.array([[0.10, 0.00, 0.20],
                [0.00, 0.10, 0.10],
                [0.10, 0.20, 0.00],
                [0.20, 0.10, 0.10]])  # maps 4 patch pixels to 3 embedding coordinates.
tokens_w = patches_w @ E_w  # one embedded token per patch.
print("E shape:", E_w.shape)
print("embedded token shape:", tokens_w.shape)
print(np.round(tokens_w, 2))
assert tokens_w.shape == (4, 3)
```
▶ What you'll see: the 4×4 patch table becomes a 4×3 token table.

```python
first_manual_w = patches_w[0] * E_w[:, 0]  # contributions to coordinate 0 of token 0.
print("patch 0:", patches_w[0])
print("coord-0 contributions:", np.round(first_manual_w, 2))
print("coord-0 sum:", round(float(first_manual_w.sum()), 2))
assert round(float(first_manual_w.sum()), 2) == round(float(tokens_w[0, 0]), 2)
```
▶ What you'll see: one embedding coordinate is a weighted sum of the four pixels in the patch.

```python
plt.figure(figsize=(4.4, 3))
plt.imshow(tokens_w, cmap="magma", aspect="auto")
plt.colorbar(label="embedded value")
plt.xlabel("embedding coordinate")
plt.ylabel("patch token")
plt.title("2: projected patch embeddings")
plt.show()
```
▶ What you'll see: each patch now has three learned features instead of four raw pixels.

*Why it's done this way:* the projection matrix is how ViT converts local pixel patterns into the same vector space used by attention. Because every patch shares `E`, the model applies the same visual vocabulary everywhere in the image.

### 3. Position embeddings break location symmetry

Attention sees a set of token vectors. If two patch embeddings are identical, attention alone does not know whether one came from the top-left or bottom-right. ViT adds a learned position table `P`, one row per sequence location, so the input is `X = patch_embedding + position_embedding`.

```python
same_tokens_w = np.ones((4, 3))  # four identical patch embeddings.
pos_w = np.arange(12, dtype=float).reshape(4, 3) / 100.0  # tiny unique position offsets.
Xpos_w = same_tokens_w + pos_w  # position-aware transformer input.
print("token 0 after position:", np.round(Xpos_w[0], 2))
print("token 1 after position:", np.round(Xpos_w[1], 2))
print("difference:", np.round(Xpos_w[1] - Xpos_w[0], 2))
assert np.allclose(np.round(Xpos_w[1] - Xpos_w[0], 2), [0.03, 0.03, 0.03])
```
▶ What you'll see: identical tokens become different once position rows are added.

```python
plt.figure(figsize=(4.4, 3))
plt.imshow(Xpos_w, cmap="viridis", aspect="auto")
plt.colorbar(label="token + position")
plt.xlabel("embedding coordinate")
plt.ylabel("sequence position")
plt.title("3: position-coded tokens")
plt.show()
```
▶ What you'll see: rows that started equal now show a smooth positional pattern.

```python
cls_w = np.zeros((1, 3)) + 0.5  # a learnable class token in toy form.
seq_w = np.vstack([cls_w, tokens_w + pos_w])  # prepend class token before the patch tokens.
print("sequence shape with class token:", seq_w.shape)
print("class token:", seq_w[0])
assert seq_w.shape == (5, 3)
```
▶ What you'll see: the sequence has one extra token that can collect image-level information.

*Why it's done this way:* adding positions preserves the transformer recipe while injecting the missing image order. The class token is a learned summary slot; after attention mixes all tokens, its final vector is used as the image representation for classification.

### 4. Scaled dot-product attention mixes patch information

Attention computes a similarity score from each query token to each key token, normalizes each row with softmax, and uses those weights to average value vectors. In ViT, this is where a patch can borrow information from distant patches instead of only from a local convolution window.

```python
Q_w = np.array([[1., 0.], [0., 1.]])  # two simple query vectors.
K_w = np.array([[1., 0.], [0., 1.]])  # matching keys.
V_w = np.array([[2., 0.], [0., 3.]])  # values to be mixed.
scores_w = Q_w @ K_w.T  # unscaled toy scores.
print("scores:\n", scores_w)
assert np.allclose(scores_w, np.eye(2))
```
▶ What you'll see: each token scores itself higher than the other token.

```python
def softmax_w(z_w):
    z_w = z_w - np.max(z_w, axis=-1, keepdims=True)  # stabilize exponentials row by row.
    exp_w = np.exp(z_w)
    return exp_w / np.sum(exp_w, axis=-1, keepdims=True)

weights_w = softmax_w(scores_w)
out_w = weights_w @ V_w
print("attention weights:\n", np.round(weights_w, 3))
print("attention output:\n", np.round(out_w, 3))
assert np.allclose(np.round(weights_w[0], 3), [0.731, 0.269])
assert np.allclose(np.round(out_w[0], 3), [1.462, 0.807])
```
▶ What you'll see: the first token mostly keeps its own value but still borrows from the second token.

```python
plt.figure(figsize=(4, 3))
plt.imshow(weights_w, cmap="Blues", vmin=0, vmax=1)
plt.colorbar(label="attention weight")
plt.xlabel("key token")
plt.ylabel("query token")
plt.title("4: row-normalized attention")
plt.show()
```
▶ What you'll see: each row sums to 1, so every query forms a probability distribution over keys.

*Why it's done this way:* dot products measure compatibility, softmax turns arbitrary scores into normalized mixing weights, and multiplying by `V` forms a weighted average. The `1/sqrt(d)` scale used in real ViTs keeps high-dimensional dot products from becoming so large that softmax saturates.

### 5. Patch size controls sequence length and attention cost

Patch size is not just an implementation detail. Larger patches shorten the sequence and make attention cheaper, but they also make the first visual words coarser. Before training begins, patch size decides how much fine detail can be represented by a single token.

```python
image_side_w = 224  # standard ViT image side length.
patch_sizes_w = np.array([8, 16, 32])  # candidate square patch sizes.
tokens_count_w = (image_side_w // patch_sizes_w) ** 2  # number of patch tokens.
pairs_w = tokens_count_w ** 2  # query-key pair count for global attention.
print("patch sizes:", patch_sizes_w)
print("tokens:", tokens_count_w)
print("attention pairs:", pairs_w)
assert int(tokens_count_w[1]) == 196
```
▶ What you'll see: 16×16 patches produce 196 patch tokens for a 224×224 image.

```python
relative_w = pairs_w / pairs_w[1]  # compare attention cost against patch size 16.
print("cost relative to 16x16 patches:", np.round(relative_w, 2))
assert round(float(relative_w[0]), 2) == 16.0
assert round(float(relative_w[2]), 2) == 0.06
```
▶ What you'll see: halving patch size from 16 to 8 makes global attention about 16× more expensive.

```python
plt.figure(figsize=(4.6, 3))
plt.plot(patch_sizes_w, pairs_w, marker="o", color="crimson")
plt.yscale("log")
plt.xlabel("patch size")
plt.ylabel("attention pair count (log)")
plt.title("5: larger patches shorten attention")
plt.show()
```
▶ What you'll see: attention cost drops steeply as patch size grows.

*Why it's done this way:* global attention compares every token with every token, so token count matters quadratically. Patch size trades spatial resolution for compute: small patches preserve details but cost more; large patches are efficient but can erase small objects at tokenization.

### 6. A head turns the final representation into class probabilities

After transformer blocks mix the patch tokens, ViT uses a small classification head on the final class token. A linear map produces logits, and softmax converts those logits into probabilities that sum to one.

```python
cls_final_w = np.array([1.0, 0.5, -0.2])  # pretend this is the final class-token representation.
W_head_w = np.array([[0.2, -0.1, 0.3],
                     [1.5, 0.8, -0.4],
                     [0.1, 0.4, 0.2]])  # maps embedding coordinates to three classes.
logits_w = cls_final_w @ W_head_w.T
print("logits:", np.round(logits_w, 3))
```
▶ What you'll see: each class receives one unnormalized score.

```python
probs_w = softmax_w(logits_w.reshape(1, -1)).ravel()
print("probabilities:", np.round(probs_w, 3))
print("sum:", round(float(probs_w.sum()), 3))
print("predicted class:", int(np.argmax(probs_w)))
assert round(float(probs_w.sum()), 3) == 1.0
```
▶ What you'll see: the largest logit becomes the largest probability, and all probabilities sum to 1.

```python
plt.figure(figsize=(4.2, 3))
plt.bar(["cat", "dog", "car"], probs_w, color="seagreen")
plt.ylim(0, 1)
plt.ylabel("probability")
plt.title("6: softmax classification head")
plt.show()
```
▶ What you'll see: one class has the highest probability, but the head still represents uncertainty over all classes.

*Why it's done this way:* logits can be any real numbers, but classification needs a comparable distribution. Softmax exponentiates score differences and normalizes them, so training can push the correct class logit up relative to the others.

## 🛠️ Setup

```python
import numpy as np  # load NumPy for image arrays, patch reshaping, linear projections, and attention math.
import matplotlib.pyplot as plt  # load Matplotlib for patch grids, heatmaps, bars, and cost curves.
np.random.seed(0)  # make every random toy projection reproducible.

def vit_softmax(z):  # define a stable row-wise softmax used by attention and classification cells.
    z = np.asarray(z, dtype=float)  # convert inputs to floats so exponentials are predictable.
    z = z - np.max(z, axis=-1, keepdims=True)  # subtract each row's max to avoid overflow.
    exp = np.exp(z)  # exponentiate shifted scores.
    return exp / np.sum(exp, axis=-1, keepdims=True)  # normalize so each row sums to one.

def make_patches(image, patch_size):  # split a 2-D image into flattened non-overlapping patches.
    patches = []  # collect patches in row-major order.
    for r in range(0, image.shape[0], patch_size):  # step down the image by patch height.
        for c in range(0, image.shape[1], patch_size):  # step across the image by patch width.
            patches.append(image[r:r+patch_size, c:c+patch_size].reshape(-1))  # flatten each patch.
    return np.array(patches, dtype=float)  # return a token table.

def attention(Q, K, V, scale=True):  # compute scaled dot-product attention from scratch.
    scores = Q @ K.T  # compare every query with every key.
    if scale:  # use transformer scaling unless a toy example disables it.
        scores = scores / np.sqrt(Q.shape[1])  # prevent high-dimensional dot products from saturating softmax.
    weights = vit_softmax(scores)  # normalize each query row over all keys.
    return weights @ V, weights  # return mixed values and inspectable attention weights.
```

```python
print("image:\n", img_b1)  # inspect the grid before tokenization.
```

▶ What you'll see: the bright object is stronger in the small-patch token grid and diluted in the large-patch grid.

👀 Takeaway: patch size chooses the visual granularity before the transformer can reason globally.

### Advanced 3 — Compare global attention to local windows

**Goal.** Count pair comparisons for global versus windowed attention, because ViT uses global attention while Swin-style variants reduce cost with locality. We build it in 3 steps.

```python
grid_side_a3 = 8  # imagine an 8x8 patch-token grid.

global_pairs_a3 = tokens_a3 ** 2  # every token attends to every token.
print("tokens:", tokens_a3, "global pairs:", global_pairs_a3)  # inspect global attention cost.
```
▶ What you'll see: 64 tokens create 4096 global query-key comparisons.

```python
windows_per_side_a3 = grid_side_a3 // window_a3  # number of windows per side.
```

### Advanced 4 — Inspect attention is not automatically explanation

**Goal.** Change value vectors while keeping attention weights fixed, because high attention weight shows mixing, not a guaranteed causal explanation of the final class. We build it in 4 steps.

```python
Q_a4 = np.array([[1., 0.], [0., 1.]])  # fixed queries.
K_a4 = np.array([[1., 0.], [0., 1.]])  # fixed keys, so weights are fixed.
V1_a4 = np.array([[2., 0.], [0., 3.]])  # first set of values.
V2_a4 = np.array([[-2., 0.], [0., 3.]])  # second set changes what token 0 carries.
_, weights_a4 = attention(Q_a4, K_a4, V1_a4, scale=False)  # compute the fixed attention weights.
print("weights:\n", np.round(weights_a4, 3))  # inspect attention pattern.
```
▶ What you'll see: token 0 attends mostly to key 0 in both cases.

```python
out1_a4 = weights_a4 @ V1_a4  # mix the first value set.
out2_a4 = weights_a4 @ V2_a4  # mix the changed value set with identical weights.
print("output with V1:", np.round(out1_a4[0], 3))  # inspect first result.
print("output with V2:", np.round(out2_a4[0], 3))  # inspect changed result.
assert np.sign(out1_a4[0, 0]) != np.sign(out2_a4[0, 0])  # same attention can carry opposite content.
```

```python
head_a4 = np.array([1., 0.])  # read only the first output coordinate as a toy logit.
logits_a4 = np.array([out1_a4[0] @ head_a4, out2_a4[0] @ head_a4])  # compare downstream scores.

```


👀 Takeaway: attention weights reveal where information is mixed, not a complete causal explanation by themselves.

### Advanced 5 — Train only a tiny classification head

**Goal.** Fit a softmax head on fixed toy class-token features, because ViT classification ends with ordinary linear logits and cross-entropy gradients. We build it in 5 steps.

```python
features_a5 = np.array([[1.0, 0.2], [0.8, 0.1], [-0.8, 0.0], [-1.0, -0.2]])  # fixed class-token features for four images.
labels_a5 = np.array([0, 0, 1, 1])  # two images per class.
W_a5 = np.zeros((2, 2))  # initialize a two-class linear head.
print("features shape:", features_a5.shape, "labels:", labels_a5)  # inspect training data.
```
▶ What you'll see: class 0 lives on the positive side of axis 0, class 1 on the negative side.

```python
losses_a5 = []  # store cross-entropy loss during head training.
eta_a5 = 0.5  # learning rate for the tiny head.
Y_a5 = np.eye(2)[labels_a5]  # one-hot labels.
for step_a5 in range(80):
    logits_loop_a5 = features_a5 @ W_a5.T  # compute class logits.
    probs_loop_a5 = vit_softmax(logits_loop_a5)  # convert to probabilities.
    loss_a5 = -np.mean(np.log(probs_loop_a5[np.arange(len(labels_a5)), labels_a5] + 1e-12))  # cross-entropy.
    grad_logits_a5 = (probs_loop_a5 - Y_a5) / len(labels_a5)  # gradient of cross-entropy wrt logits.
    grad_W_a5 = grad_logits_a5.T @ features_a5  # gradient wrt the linear head.
    W_a5 -= eta_a5 * grad_W_a5  # gradient descent update.
    losses_a5.append(loss_a5)  # record loss.
print("loss start -> end:", round(losses_a5[0], 3), "->", round(losses_a5[-1], 3))
assert losses_a5[-1] < losses_a5[0]  # verify learning reduced loss.
```

```python
final_probs_a5 = vit_softmax(features_a5 @ W_a5.T)  # compute trained probabilities.
preds_a5 = np.argmax(final_probs_a5, axis=1)  # predicted classes.
print("final probabilities:\n", np.round(final_probs_a5, 3))  # inspect confidence.
print("predictions:", preds_a5)  # inspect predicted labels.
assert np.array_equal(preds_a5, labels_a5)  # verify the simple head learned the separator.
```

```python
plt.figure(figsize=(5, 3))
plt.plot(losses_a5, color="purple")
plt.title("Advanced 5: training a ViT-style head")
plt.xlabel("gradient step")
plt.ylabel("cross-entropy")
plt.show()
```
▶ What you'll see: cross-entropy falls as the linear head learns to separate the fixed image features.

```python
plt.figure(figsize=(4, 3))
plt.scatter(features_a5[:, 0], features_a5[:, 1], c=labels_a5, cmap="coolwarm", s=90)
plt.axvline(0, color="black", linestyle="--")
plt.title("Advanced 5: fixed class-token features")
plt.xlabel("feature 0"); plt.ylabel("feature 1")
plt.show()
```
▶ What you'll see: the fixed features are linearly separable, so the head can classify them cleanly.

👀 Takeaway: after ViT builds an image representation, the final classifier is ordinary softmax regression.
