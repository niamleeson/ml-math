# 22.3 — Informed Search & A*

Informed search keeps the path-cost discipline of uniform-cost search, then adds a heuristic estimate of the remaining distance to the goal. In this lesson, you will build A* from scratch on small grids, inspect the exact `g`, `h`, and `f=g+h` values, and see why admissible heuristics preserve optimal paths while greedier variants trade proof for speed.

## 📖 Concept walkthrough — build each idea from scratch

Before the worked examples, we build informed search one idea at a time. Run each cell in order and read the printed intermediate values. The walkthrough is self-contained and uses a `_w` suffix so it never clashes with the examples below.

from collections import deque  # simple queues for some frontier diagnostics.
import numpy as np  # arrays, grids, masks, and numerical checks.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
np.random.seed(0)  # reproducibility for any stochastic demos.

### 1. From blind path cost to a goal-directed compass

Uniform-cost search (UCS) already respects accumulated path cost `g(n)`, so it is safe on weighted graphs. Its weakness is that it is blind: a cheap prefix that walks away from the goal can look just as promising as a cheap prefix that walks toward the goal. A heuristic `h(n)` is a compass: it estimates the remaining cost-to-go and lets the frontier prefer states that are both cheap so far and plausibly close to the goal.

```python
grid_w1 = np.zeros((5, 5), dtype=int)  # 0 means free cell.
start_w1, goal_w1 = (0, 0), (4, 4)  # search from top-left to bottom-right.
rows_w1, cols_w1 = np.indices(grid_w1.shape)  # coordinate arrays for every cell.
h_w1 = np.abs(rows_w1 - goal_w1[0]) + np.abs(cols_w1 - goal_w1[1])  # Manhattan distance to goal.
print("h(start):", int(h_w1[start_w1]), "h(goal):", int(h_w1[goal_w1]))  # 8 and 0 on a 5x5 four-neighbor grid.
print("heuristic grid:\n", h_w1)  # inspect the compass values.
plt.figure(figsize=(4, 3.5))
plt.imshow(h_w1, cmap="viridis")
plt.colorbar(label="Manhattan h(n)")
plt.scatter([start_w1[1], goal_w1[1]], [start_w1[0], goal_w1[0]], c=["white", "red"], s=90, edgecolor="black")
plt.text(start_w1[1], start_w1[0], "S", ha="center", va="center", color="black")
plt.text(goal_w1[1], goal_w1[0], "G", ha="center", va="center", color="white")
plt.title("1: heuristic as distance-to-go compass")
plt.xticks(range(5)); plt.yticks(range(5)); plt.gca().invert_yaxis(); plt.show()
```
▶ What you'll see: the goal has heuristic 0, and the start has heuristic 8, the exact number of four-neighbor moves in an empty grid.

*Why it's done this way:* `g` says what a path has already paid, while `h` says what it still probably owes. A* works because those two quantities are measured in the same cost units and can be added.

### 2. A* ranks the frontier by `f(n)=g(n)+h(n)`

A* keeps the exact cost-so-far `g(n)` from UCS and adds the heuristic `h(n)`. The priority score is

$$f(n)=g(n)+h(n).$$

A low `f` means: "this partial route has paid little and still looks close." In an empty grid with a consistent Manhattan heuristic, many cells can tie with the same optimal `f`; the search is still safe because each tied cell has a lower-bound estimate equal to the best possible path cost.

```python
shape_w2 = (5, 5)
start_w2, goal_w2 = (0, 0), (4, 4)
rows_w2, cols_w2 = np.indices(shape_w2)
g_w2 = rows_w2 + cols_w2  # exact cost from start in an empty four-neighbor grid along shortest paths.
h_w2 = np.abs(rows_w2 - goal_w2[0]) + np.abs(cols_w2 - goal_w2[1])  # admissible cost-to-go.
f_w2 = g_w2 + h_w2  # A* priority.
print("g at (2, 1):", int(g_w2[2, 1]), "h:", int(h_w2[2, 1]), "f:", int(f_w2[2, 1]))
assert int(f_w2[start_w2]) == 8 and int(f_w2[goal_w2]) == 8
fig, ax = plt.subplots(1, 3, figsize=(9, 3))
for a_w2, M_w2, title_w2 in zip(ax, [g_w2, h_w2, f_w2], ["g: cost so far", "h: cost to go", "f=g+h"]):
    im_w2 = a_w2.imshow(M_w2, cmap="magma")
    a_w2.set_title(title_w2); a_w2.set_xticks(range(5)); a_w2.set_yticks(range(5))
    for r_w2 in range(5):
        for c_w2 in range(5):
            a_w2.text(c_w2, r_w2, int(M_w2[r_w2, c_w2]), ha="center", va="center", color="white", fontsize=8)
fig.colorbar(im_w2, ax=ax.ravel().tolist(), shrink=0.75, label="value")
plt.suptitle("2: A* adds exact past cost and estimated future cost"); plt.show()
```
▶ What you'll see: `g` rises away from the start, `h` falls toward the goal, and `f` stays at the optimal path length on shortest-route cells.

*Why it's done this way:* adding `g+h` makes every frontier score a lower-bound guess of total solution cost when `h` is admissible; UCS is the special case where `h=0`.

### 3. Admissibility and consistency are the safety math

Admissibility means `0 ≤ h(n) ≤ h*(n)`, where `h*(n)` is the true cheapest remaining cost. Manhattan distance is admissible on a four-neighbor grid with unit costs because every move changes row or column by exactly one, so at least `|Δrow|+|Δcol|` moves are required. It is also consistent: for every neighbor `m` of `n`, `h(n) ≤ cost(n,m)+h(m)`. With unit moves, Manhattan distance can drop by at most 1 in one step.

```python
shape_w3 = (5, 5)
goal_w3 = (4, 4)
rows_w3, cols_w3 = np.indices(shape_w3)
manhattan_w3 = np.abs(rows_w3 - goal_w3[0]) + np.abs(cols_w3 - goal_w3[1])
over_w3 = 1.6 * manhattan_w3  # an intentionally overestimating heuristic except at the goal.
violations_w3 = []
for r_w3 in range(shape_w3[0]):
    for c_w3 in range(shape_w3[1]):
        for dr_w3, dc_w3 in [(1, 0), (-1, 0), (0, 1), (0, -1)]:
            nr_w3, nc_w3 = r_w3 + dr_w3, c_w3 + dc_w3
            if 0 <= nr_w3 < shape_w3[0] and 0 <= nc_w3 < shape_w3[1]:
                if manhattan_w3[r_w3, c_w3] > 1 + manhattan_w3[nr_w3, nc_w3]:
                    violations_w3.append(((r_w3, c_w3), (nr_w3, nc_w3)))
print("Manhattan consistency violations:", len(violations_w3))
print("overestimate at start:", over_w3[0, 0], "true remaining:", manhattan_w3[0, 0])
assert len(violations_w3) == 0 and over_w3[0, 0] > manhattan_w3[0, 0]
plt.figure(figsize=(5, 3))
plt.bar(["true h*", "Manhattan h", "1.6×h"], [manhattan_w3[0, 0], manhattan_w3[0, 0], over_w3[0, 0]], color=["gray", "seagreen", "crimson"])
plt.ylabel("estimated remaining cost from start")
plt.title("3: admissible estimate versus overestimate")
plt.show()
```
▶ What you'll see: Manhattan has zero consistency violations, while multiplying it by 1.6 overshoots the true start-to-goal distance.

*Why it's done this way:* the proof needs `h` to be a lower bound. If a heuristic overestimates, a truly optimal path can be assigned a falsely high `f` and delayed behind a worse route.

### 4. A* around walls returns the same optimal cost with fewer distractions

Walls make the compass useful. The heuristic does not change the correct answer: the returned path cost is still the sum of edge costs along the route. What changes is the order in which alternatives are inspected. Cells that are cheap but point into a wall or away from the goal tend to receive worse `f` scores and are postponed.

```python
grid_w4 = np.zeros((5, 5), dtype=int)
grid_w4[1:4, 2] = 1  # a vertical wall with openings around it.
start_w4, goal_w4 = (0, 0), (4, 4)
def astar_w4(grid, start, goal):
    def h(cell): return abs(cell[0] - goal[0]) + abs(cell[1] - goal[1])
    open_heap = [(h(start), 0, start)]
    came, g = {start: None}, {start: 0}
    closed = []
    while open_heap:
        _, cost, cur = heapq.heappop(open_heap)
        if cur in closed: continue
        closed.append(cur)
        if cur == goal: break
        for dr, dc in [(1,0),(-1,0),(0,1),(0,-1)]:
            nb = (cur[0] + dr, cur[1] + dc)
            if 0 <= nb[0] < grid.shape[0] and 0 <= nb[1] < grid.shape[1] and grid[nb] == 0:
                ng = cost + 1
                if ng < g.get(nb, 10**9):
                    g[nb], came[nb] = ng, cur
                    heapq.heappush(open_heap, (ng + h(nb), ng, nb))
    path = []
    cur = goal
    while cur is not None:
        path.append(cur); cur = came[cur]
    return path[::-1], closed, g[goal]
path_w4, closed_w4, cost_w4 = astar_w4(grid_w4, start_w4, goal_w4)
print("path:", path_w4)
print("path states:", len(path_w4), "cost:", cost_w4, "expanded:", len(closed_w4))
assert cost_w4 == 8 and len(path_w4) == 9
vis_w4 = np.full(grid_w4.shape, 0.0); vis_w4[grid_w4 == 1] = -1
for r, c in closed_w4: vis_w4[r, c] = 0.45
for r, c in path_w4: vis_w4[r, c] = 1.0
plt.figure(figsize=(4, 3.5))
plt.imshow(vis_w4, cmap="viridis")
plt.scatter([start_w4[1], goal_w4[1]], [start_w4[0], goal_w4[0]], c=["white", "red"], s=90, edgecolor="black")
plt.title("4: A* explored cells and final path")
plt.xticks(range(5)); plt.yticks(range(5)); plt.gca().invert_yaxis(); plt.show()
```
▶ What you'll see: A* routes around the wall with cost 8, shading explored cells and highlighting the final path.

*Why it's done this way:* a heuristic is not a shortcut around correctness; it is a priority rule that helps certify the same optimal path after inspecting fewer irrelevant states.

### 5. Weighted A* makes the search greedier

Weighted A* uses `f_w(n)=g(n)+w h(n)` for `w>1`. The larger heuristic term makes the frontier chase the goal more aggressively. That often shrinks the explored set, but the admissibility proof applies to `h`, not to `w h`; multiplying by `w` can overestimate the remaining cost and remove the optimality guarantee.

```python
h_start_w5 = 8
priority_plain_w5 = 0 + h_start_w5
priority_weighted_w5 = 0 + 2 * h_start_w5
node_g_w5, node_h_w5 = 3, 5
node_plain_w5 = node_g_w5 + node_h_w5
node_weighted_w5 = node_g_w5 + 2 * node_h_w5
print("A* start priority:", priority_plain_w5, "weighted start priority:", priority_weighted_w5)
print("node g=3,h=5 -> A*:", node_plain_w5, "weighted:", node_weighted_w5)
assert priority_weighted_w5 == 16 and node_weighted_w5 == 13
plt.figure(figsize=(5, 3))
plt.bar(["start A*", "start w=2", "node A*", "node w=2"], [priority_plain_w5, priority_weighted_w5, node_plain_w5, node_weighted_w5], color=["seagreen", "crimson", "seagreen", "crimson"])
plt.ylabel("frontier priority")
plt.title("5: weighting h changes the score scale")
plt.xticks(rotation=15)
plt.show()
```
▶ What you'll see: the heuristic part is doubled, so nodes that merely look closer to the goal become much more attractive.

*Why it's done this way:* weighting is a deliberate speed-quality knob. It can be useful in practice, but you should say out loud that the optimality proof has been traded away.

### 6. Common pitfalls: overestimates, weak heuristics, and mixed units

Three mistakes cause most A* bugs. First, an overestimating heuristic can hide the optimal path. Second, `h=0` is admissible but uninformative, so A* collapses to UCS. Third, `g` and `h` must use the same units: adding minutes to meters produces a priority with no mathematical meaning.

```python
labels_w6 = ["UCS h=0", "safe A*", "greedy h-only", "mixed units"]
expanded_w6 = np.array([18, 12, 9, 14])  # illustrative counts from the same small-grid style of problem.
proof_safe_w6 = np.array([1, 1, 0, 0])  # UCS and admissible A* are proof-safe; greedy and mixed units are not.
print("methods:", labels_w6)
print("optimality proof safe flags:", proof_safe_w6.tolist())
assert proof_safe_w6.tolist() == [1, 1, 0, 0]
fig, ax1 = plt.subplots(figsize=(5.5, 3.2))
ax1.bar(labels_w6, expanded_w6, color=["gray", "seagreen", "orange", "crimson"])
ax1.set_ylabel("explored cells (illustrative)"); ax1.set_title("6: fewer expansions are not the whole story")
ax1.tick_params(axis="x", rotation=15)
ax2 = ax1.twinx()
ax2.plot(labels_w6, proof_safe_w6, color="black", marker="o", linewidth=2)
ax2.set_ylabel("optimality proof safe?", color="black"); ax2.set_ylim(-0.1, 1.1)
plt.show()
```
▶ What you'll see: a method can explore fewer cells while losing the conditions that prove optimality.

*Why it's done this way:* informed search is a contract: heuristic information buys efficiency only when the heuristic remains a valid lower bound in the same cost units as the path cost.

## 🛠️ Setup

```python
import heapq  # priority queues for all frontier-based searches in this notebook.
from collections import deque  # queue container for frontier-growth bookkeeping.
import numpy as np  # arrays, grids, masks, and numerical checks.
import matplotlib.pyplot as plt  # plotting grids, heatmaps, paths, and comparison bars.
np.random.seed(0)  # make the examples deterministic.

MOVES = [(1, 0), (-1, 0), (0, 1), (0, -1)]  # four-neighbor grid actions with unit cost unless stated otherwise.

def manhattan(cell, goal):  # admissible heuristic for four-neighbor unit-cost grids.
    return abs(cell[0] - goal[0]) + abs(cell[1] - goal[1])  # row distance plus column distance.

def euclidean(cell, goal):  # another admissible but usually less aligned heuristic for four-neighbor grids.
    return float(np.sqrt((cell[0] - goal[0]) ** 2 + (cell[1] - goal[1]) ** 2))  # straight-line distance.

def neighbors(grid, cell):  # yield legal four-neighbor cells that are not obstacles.
    for dr, dc in MOVES:  # try down, up, right, left.
        nb = (cell[0] + dr, cell[1] + dc)  # candidate neighbor.
        if 0 <= nb[0] < grid.shape[0] and 0 <= nb[1] < grid.shape[1] and grid[nb] == 0:  # inside and free.
            yield nb  # return the valid neighbor.

def reconstruct(came_from, goal):  # rebuild a path after search succeeds.
    if goal not in came_from:  # no route was discovered.
        return []  # return empty path.
    path = []  # collect states from goal back to start.
    cur = goal  # begin at the goal.
    while cur is not None:  # follow parents until the start parent marker.
        path.append(cur)  # record the current state.
        cur = came_from[cur]  # move to its predecessor.
    return path[::-1]  # reverse into start-to-goal order.

def search_grid(grid, start, goal, heuristic=None, weight=1.0, mode="astar", costs=None):  # UCS, greedy, or A* on a grid.
    if heuristic is None:  # default to zero heuristic.
        heuristic = lambda cell, g: 0.0  # zero heuristic makes A* equal UCS.
    costs = {} if costs is None else dict(costs)  # optional extra cost for entering specific cells.
    counter = 0  # deterministic tie-breaker for heap entries.
    g_score = {start: 0.0}  # exact best cost found from start to each state.
    came_from = {start: None}  # parent pointers for the best known routes.
    open_heap = []  # priority queue frontier.
    closed = []  # expansion order.
    open_sizes, closed_sizes = [], []  # frontier and explored sizes over time.
    def priority(cell):  # compute the selected frontier score.
        h = heuristic(cell, goal)  # remaining-cost estimate.
        if mode == "ucs": return g_score[cell]  # UCS ignores h.
        if mode == "greedy": return h  # greedy ignores g.
        return g_score[cell] + weight * h  # A* or weighted A*.
    heapq.heappush(open_heap, (priority(start), counter, start))  # seed frontier.
    closed_set = set()  # fast membership for expanded states.
    while open_heap:  # continue until no candidates remain.
        open_sizes.append(len(open_heap)); closed_sizes.append(len(closed_set))  # record growth before popping.
        _, _, current = heapq.heappop(open_heap)  # pop best-priority state.
        if current in closed_set:  # skip stale heap entries.
            continue  # another better copy was already expanded.
        closed_set.add(current); closed.append(current)  # mark expansion.
        if current == goal:  # success.
            break  # stop search.
        for nb in neighbors(grid, current):  # scan legal moves.
            step_cost = costs.get(nb, 1.0)  # cost of entering neighbor.
            tentative = g_score[current] + step_cost  # exact cost through current.
            if tentative < g_score.get(nb, float("inf")):  # found a cheaper route.
                g_score[nb] = tentative  # store best cost.
                came_from[nb] = current  # store parent.
                counter += 1  # update tie-breaker.
                heapq.heappush(open_heap, (priority(nb), counter, nb))  # push with selected priority.
    path = reconstruct(came_from, goal)  # produce final path if any.
    return {"path": path, "cost": g_score.get(goal, float("inf")), "closed": closed, "g": g_score, "open_sizes": open_sizes, "closed_sizes": closed_sizes}  # search diagnostics.

def path_cost(path, costs=None):  # compute cost of a returned path by summing entered-cell costs.
    costs = {} if costs is None else dict(costs)  # optional weighted cells.
    if not path: return float("inf")  # no route has infinite cost.
    return sum(costs.get(cell, 1.0) for cell in path[1:])  # start cell costs zero; each move enters the next cell.

def draw_grid(grid, start, goal, path=None, explored=None, title="grid search"):  # visualize obstacles, explored cells, and path.
    image = np.zeros(grid.shape, dtype=float)  # base free-cell image.
    image[grid == 1] = -1.0  # obstacles are negative/dark.
    if explored is not None:  # mark explored states.
        for r, c in explored:
            if grid[r, c] == 0: image[r, c] = 0.35  # explored but not necessarily final path.
    if path is not None:  # mark final path.
        for r, c in path:
            image[r, c] = 1.0  # high value for path cells.
    plt.figure(figsize=(4.5, 3.8))  # compact grid figure.
    plt.imshow(image, cmap="viridis")  # draw the grid.
    plt.scatter([start[1], goal[1]], [start[0], goal[0]], c=["white", "red"], s=90, edgecolor="black")  # mark endpoints.
    plt.text(start[1], start[0], "S", ha="center", va="center", color="black")  # start label.
    plt.text(goal[1], goal[0], "G", ha="center", va="center", color="white")  # goal label.
    plt.xticks(range(grid.shape[1])); plt.yticks(range(grid.shape[0]))  # show grid coordinates.
    plt.title(title)  # label the plot.
    plt.gca().invert_yaxis()  # keep row 0 visually at the top.
    plt.show()  # display the plot.
```

#### B1. Compute a Manhattan heuristic `_b1`

**Goal.** Measure a grid state's remaining distance with Manhattan distance, because A* needs a same-unit estimate of cost-to-go. We build it in 2 steps.

```python
start_b1 = (0, 0)  # top-left start state.

h_start_b1 = manhattan(start_b1, goal_b1)  # |4-0| + |4-0|.
h_mid_b1 = manhattan((2, 3), goal_b1)  # a mid-grid state's estimate.
print("h(start):", h_start_b1, "h(2,3):", h_mid_b1)  # inspect remaining-cost estimates.
assert h_start_b1 == 8 and h_mid_b1 == 3  # verify the arithmetic.
```
▶ What you'll see: the start estimates 8 remaining moves, while a closer state estimates 3.

rows_b1, cols_b1 = np.indices((5, 5))  # coordinate arrays for all cells.

#### A1. Show how an overestimating heuristic can fail

**Goal.** Build a tiny weighted graph where an inadmissible heuristic chooses a suboptimal goal too early, because this is the concrete danger behind the proof condition. We build it in 3 steps.

```python
graph_a1 = {"S": [("A", 2), ("B", 1)], "A": [("G", 2)], "B": [("G", 10)], "G": []}  # optimal S-A-G costs 4; bad S-B-G costs 11.
h_bad_a1 = {"S": 0, "A": 100, "B": 0, "G": 0}  # overestimate A's remaining cost, hiding the optimal branch.
h_good_a1 = {"S": 0, "A": 2, "B": 10, "G": 0}  # exact admissible remaining costs.
print("optimal route should cost 4 via A")  # state the ground truth.
```
▶ What you'll see: the graph has one cheap branch and one expensive branch.

```python
def astar_graph_a1(graph, start, goal, h):
    heap = [(h[start], 0, start, [start])]  # priority, g, node, path.
    closed = []  # expansion order.
    while heap:  # search until goal.
        _, g, node, path = heapq.heappop(heap)  # pop best f.
        if node in closed: continue  # skip repeats.
        closed.append(node)  # mark expansion.
        if node == goal: return path, g, closed  # stop at first popped goal, as A* does with admissible h.
        for nb, cost in graph[node]:  # expand neighbors.
            heapq.heappush(heap, (g + cost + h[nb], g + cost, nb, path + [nb]))  # push candidate.
    return [], float("inf"), closed  # no route.
path_bad_a1, cost_bad_a1, closed_bad_a1 = astar_graph_a1(graph_a1, "S", "G", h_bad_a1)  # inadmissible search.
path_good_a1, cost_good_a1, closed_good_a1 = astar_graph_a1(graph_a1, "S", "G", h_good_a1)  # admissible search.
print("bad heuristic:", path_bad_a1, cost_bad_a1, "good heuristic:", path_good_a1, cost_good_a1)  # compare.
assert cost_bad_a1 == 11 and cost_good_a1 == 4  # demonstrate failure.
```

```python
plt.figure(figsize=(5, 3))  # create failure comparison.
plt.bar(["inadmissible h", "admissible h"], [cost_bad_a1, cost_good_a1], color=["crimson", "seagreen"])  # compare returned costs.
plt.axhline(4, color="black", linestyle="--", label="optimal cost")  # mark optimum.
plt.title("A1: overestimating h can return a bad route")  # title.
plt.ylabel("returned path cost")  # label.
plt.legend(); plt.show()  # display.
```
▶ What you'll see: the bad heuristic returns cost 11 even though a cost-4 route exists.

👀 Takeaway: admissibility is not decoration; it is the lower-bound condition that makes first-goal termination safe.

#### A5. Build an admissibility heatmap from true costs

**Goal.** Plot the gap `h*−h` over a maze, because the gap shows where a heuristic is exact and where obstacles make it underestimate. We build it in 3 steps.

```python
grid_a5 = np.zeros((6, 6), dtype=int)  # grid.
grid_a5[2, 1:6] = 1  # horizontal wall; cells above the wall must detour left before going down.
goal_a5 = (5, 5)  # target.
free_a5 = [(r, c) for r in range(6) for c in range(6) if grid_a5[r, c] == 0]  # free cells.
print("free cells:", len(free_a5))  # inspect state count.
```
▶ What you'll see: the maze leaves a corridor where true distance can exceed Manhattan distance.

```python
gap_a5 = np.full(grid_a5.shape, np.nan)  # h* - h for each free cell.
for cell_a5 in free_a5:  # compute exact remaining cost by UCS from each cell.
    res_a5 = search_grid(grid_a5, cell_a5, goal_a5, heuristic=manhattan, mode="ucs")  # exact shortest route.
    gap_a5[cell_a5] = res_a5["cost"] - manhattan(cell_a5, goal_a5)  # admissibility slack.
print("min gap:", np.nanmin(gap_a5), "max gap:", np.nanmax(gap_a5))  # inspect underestimation.
assert np.nanmin(gap_a5) >= 0  # admissibility means no negative gap.
```

```python
plot_gap_a5 = np.where(grid_a5 == 1, -1, np.nan_to_num(gap_a5, nan=0))  # walls as -1.
plt.figure(figsize=(4.4, 3.6))  # create heatmap.
plt.imshow(plot_gap_a5, cmap="viridis")  # visualize slack.
plt.colorbar(label="h* - h (walls=-1)")  # add scale.
plt.title("A5: admissibility slack heatmap")  # title.
plt.xticks(range(6)); plt.yticks(range(6)); plt.gca().invert_yaxis(); plt.show()  # display.
```
▶ What you'll see: nonnegative gaps everywhere, with larger gaps where walls force detours.

👀 Takeaway: admissible heuristics may underestimate by different amounts, and those gaps drive extra exploration.
