# 23.4 — Auctions

Auctions are mechanism design in miniature: the designer chooses allocation and payment rules, while bidders choose bids from private information. This lesson builds first-price, second-price, English, Dutch, reserve-price, and common-value simulations from scratch so the incentive logic is visible in code and plots.

### 1. Mechanism design: choose rules before agents choose bids

A game fixes payoffs and asks what self-interested agents will do. Mechanism design turns that around: it chooses the rules so that self-interested behavior reveals useful information. In a single-item auction, bidders know their own private values, the seller does not, and the mechanism maps bids to a winner and a payment. The central design question is whether selfish bidding makes the hidden values easier or harder to infer.

```python
values_w1 = np.array([10.0, 7.0, 4.0])  # private values: what the item is worth to each bidder.
bids_truth_w1 = values_w1.copy()  # truthful reports are the clean benchmark.
bids_shaded_w1 = 0.75 * values_w1  # first-price style shading lowers all bids below value.
print("values:", values_w1)  # inspect the hidden information the seller wants to elicit.
print("truthful bids:", bids_truth_w1)  # inspect direct revelation.
print("shaded bids:", np.round(bids_shaded_w1, 2))  # inspect strategic reports.
```
▶ What you'll see: the same values can produce different reports depending on the payment rule.

```python
plt.figure(figsize=(5, 3))  # compare hidden values and two reporting behaviors.
x_w1 = np.arange(len(values_w1))  # bidder positions.
plt.bar(x_w1 - 0.25, values_w1, width=0.25, label="value", color="gray")  # true private information.
plt.bar(x_w1, bids_truth_w1, width=0.25, label="truthful bid", color="seagreen")  # direct reports.
plt.bar(x_w1 + 0.25, bids_shaded_w1, width=0.25, label="shaded bid", color="darkorange")  # strategic reports.
plt.xticks(x_w1, ["A", "B", "C"])  # label bidders.
plt.ylabel("dollars")  # common scale.
plt.title("1: mechanism rules shape reports")  # identify the concept.
plt.legend()  # show series labels.
plt.show()  # display the comparison.
```
▶ What you'll see: truthful bidding reveals values exactly; shaded bidding preserves rank but hides surplus.

*Why it's done this way:* separating values from bids makes the mechanism-design problem concrete: the seller observes bids, not values, so the payment rule must make useful reports individually rational.

### 2. Allocation, payment, and utility in a second-price auction

In a second-price auction, the highest bidder wins but pays the second-highest bid. Utility is value minus payment for the winner and zero for everyone else. With bids `(10, 7, 4)`, bidder A wins, pays 7, and earns utility `10 - 7 = 3`. The key design lever is that the bid determines whether A wins, but once A wins the price is set by someone else.

```python
bids_w2 = np.array([10.0, 7.0, 4.0])  # submitted bids from A, B, C.
values_w2 = np.array([10.0, 7.0, 4.0])  # use truthful values for the worked allocation.
order_w2 = np.argsort(bids_w2)[::-1]  # rank bidders from highest bid to lowest bid.
winner_w2 = int(order_w2[0])  # highest bid wins.
price_w2 = float(bids_w2[order_w2[1]])  # winner pays the second-highest bid.
utilities_w2 = np.zeros_like(values_w2)  # non-winners receive zero utility.
utilities_w2[winner_w2] = values_w2[winner_w2] - price_w2  # winner surplus.
print("winner:", winner_w2, "price:", price_w2)  # inspect allocation and payment.
print("utilities:", utilities_w2)  # inspect payoffs.
assert winner_w2 == 0 and price_w2 == 7.0 and utilities_w2[0] == 3.0  # verify the source calculation.
```
▶ What you'll see: bidder A wins, pays 7, and earns utility 3.

```python
plt.figure(figsize=(5, 3))  # visualize bids, price, and winner surplus.
plt.bar(["A", "B", "C"], bids_w2, color=["seagreen", "gray", "gray"])  # draw bids with the winner highlighted.
plt.axhline(price_w2, color="crimson", linestyle="--", label="second price paid")  # show payment.
plt.ylabel("bid")  # bid scale.
plt.title("2: second-price allocation and payment")  # title the plot.
plt.legend()  # label the price line.
plt.show()  # display the auction outcome.
```
▶ What you'll see: A's bar is highest, while the dashed line at 7 is the price A pays.

*Why it's done this way:* the payment rule disconnects the winner's own bid from the exact price, which is what makes the incentive calculation different from first price.

### 3. Truthfulness in second price: bid exactly when winning is worthwhile

Suppose A's value is 10 and the highest opposing bid is 7. If A bids below 7, A loses and earns 0. If A bids 10 or 13, A wins, pays 7, and earns 3. Overbidding does not help here, but it can make A win at a price above value; underbidding can make A lose profitable wins. Truthful bidding wins exactly the nonnegative-surplus cases.

```python
value_w3 = 10.0  # A's private value.
opponent_price_w3 = 7.0  # highest bid among opponents; this sets the second price if A wins.
trial_bids_w3 = np.linspace(0, 14, 57)  # sweep A's possible bids.
wins_w3 = trial_bids_w3 > opponent_price_w3  # A wins exactly when its bid clears the opponent.
utility_w3 = np.where(wins_w3, value_w3 - opponent_price_w3, 0.0)  # second-price utility.
print("utility at bid 6:", utility_w3[np.argmin(np.abs(trial_bids_w3 - 6))])  # losing utility.
print("utility at bid 10:", utility_w3[np.argmin(np.abs(trial_bids_w3 - 10))])  # truthful utility.
print("utility at bid 13:", utility_w3[np.argmin(np.abs(trial_bids_w3 - 13))])  # overbid utility in this case.
assert utility_w3[np.argmin(np.abs(trial_bids_w3 - 10))] == 3.0  # verify the worked surplus.
```
▶ What you'll see: bids above 7 earn 3, while bids below or equal to 7 earn 0.

```python
plt.figure(figsize=(5, 3))  # visualize weak dominance against a fixed opponent price.
plt.plot(trial_bids_w3, utility_w3, color="seagreen")  # utility by A's bid.
plt.axvline(value_w3, color="black", linestyle="--", label="truthful bid = value")  # mark truthful bid.
plt.axvline(opponent_price_w3, color="crimson", linestyle=":", label="highest opponent bid")  # mark threshold.
plt.xlabel("A's bid")  # bid axis.
plt.ylabel("A's utility")  # payoff axis.
plt.title("3: second-price truthfulness around a fixed price")  # title.
plt.legend()  # show references.
plt.show()  # display utility curve.
```
▶ What you'll see: truthful bidding is safely on the winning side exactly when the price is below value.

*Why it's done this way:* the curve shows why second price is truthful without assuming generosity: the selfish rule is to win if and only if the externally set price is no more than your value.

### 4. First price changes one line and creates bid shading

In a first-price auction, the highest bidder wins and pays their own bid. With value 10 and opponent max 7, bidding 10 wins but earns 0, while bidding 8 wins and earns 2. Because the bidder's own bid becomes the payment, the selfish calculation is to shade: bid just enough to win, not the full value.

```python
value_w4 = 10.0  # A's value.
opponent_max_w4 = 7.0  # highest opponent bid.
trial_bids_w4 = np.linspace(0, 12, 49)  # possible first-price bids.
first_price_utility_w4 = np.where(trial_bids_w4 > opponent_max_w4, value_w4 - trial_bids_w4, 0.0)  # own bid is payment.
best_idx_w4 = int(np.argmax(first_price_utility_w4))  # best bid on this grid.
print("best grid bid:", trial_bids_w4[best_idx_w4], "utility:", first_price_utility_w4[best_idx_w4])  # inspect shading.
print("truthful utility:", value_w4 - value_w4)  # utility from bidding value after winning.
assert first_price_utility_w4[best_idx_w4] > 0.0  # verify shading improves over truthful utility.
```
▶ What you'll see: the best grid bid is just above 7, not 10.

```python
plt.figure(figsize=(5, 3))  # visualize the incentive to shade.
plt.plot(trial_bids_w4, first_price_utility_w4, color="darkorange", label="first-price utility")  # utility curve.
plt.axvline(value_w4, color="black", linestyle="--", label="truthful bid")  # truthful bid.
plt.axvline(opponent_max_w4, color="crimson", linestyle=":", label="opponent max")  # win threshold.
plt.xlabel("A's bid")  # bid axis.
plt.ylabel("A's utility")  # utility axis.
plt.title("4: first-price auctions reward shading")  # title.
plt.legend()  # label lines.
plt.show()  # display curve.
```
▶ What you'll see: utility peaks just above the opponent's bid and falls to zero at the truthful bid.

*Why it's done this way:* comparing the first-price curve to the second-price curve isolates the mechanism change: making the bidder pay their own bid turns truthfulness into a bad default.

### 5. Reserve prices trade higher payments for allocation risk

A reserve price is a minimum acceptable price. With bids `(10, 7, 4)`, reserve 0 yields revenue 7, reserve 8 yields revenue 8 because only A clears the reserve, and reserve 11 yields revenue 0 because nobody clears it. The reserve can raise price when competition is weak, but too high a reserve kills the sale.

```python
bids_w5 = np.array([10.0, 7.0, 4.0])  # bids from the source calculation.
reserves_w5 = np.linspace(0, 12, 49)  # candidate reserve prices.
revenues_w5 = []  # store second-price-with-reserve revenue for each reserve.
for r_w5 in reserves_w5:  # evaluate each reserve.
    eligible_w5 = bids_w5[bids_w5 >= r_w5]  # bidders who clear the reserve.
    if len(eligible_w5) == 0:  # no allocation if nobody clears reserve.
        revenues_w5.append(0.0)  # revenue is zero.
    elif len(eligible_w5) == 1:  # one eligible bidder pays reserve.
        revenues_w5.append(float(r_w5))  # reserve replaces missing second price.
    else:  # at least two eligible bidders.
        revenues_w5.append(float(max(r_w5, np.sort(eligible_w5)[-2])))  # second price subject to reserve.
revenues_w5 = np.array(revenues_w5)  # convert to array for plotting.
print("revenue at r=0:", revenues_w5[np.argmin(np.abs(reserves_w5 - 0))])  # source case.
print("revenue near r=8:", revenues_w5[np.argmin(np.abs(reserves_w5 - 8))])  # source case.
print("revenue near r=11:", revenues_w5[np.argmin(np.abs(reserves_w5 - 11))])  # source case.
assert revenues_w5[np.argmin(np.abs(reserves_w5 - 0))] == 7.0  # verify first reserve case.
```
▶ What you'll see: revenue rises from 7 to 8, then eventually falls to 0.

```python
plt.figure(figsize=(5, 3))  # visualize the reserve tradeoff.
plt.plot(reserves_w5, revenues_w5, color="purple")  # revenue as a function of reserve.
plt.axvline(8, color="seagreen", linestyle="--", label="useful reserve")  # reserve that raises revenue.
plt.axvline(11, color="crimson", linestyle="--", label="too high")  # reserve that blocks allocation.
plt.xlabel("reserve price")  # reserve axis.
plt.ylabel("seller revenue")  # revenue axis.
plt.title("5: reserve prices can help or kill the sale")  # title.
plt.legend()  # label references.
plt.show()  # display curve.
```
▶ What you'll see: a plateau, a useful reserve region, and a collapse when the reserve exceeds all bids.

*Why it's done this way:* reserves are a revenue tool, but the visualization forces the allocation-risk side of the tradeoff to be visible.

### 6. Private values versus common values: when information changes the game

The truthfulness story assumes private values: each bidder knows what the item is worth to them. In common-value settings, like drilling rights or uncertain ad inventory, the item has one underlying value and bidders receive noisy signals. Winning after bidding aggressively can mean your signal was the most optimistic, creating a winner's curse unless bids are adjusted downward.

```python
rng_w6 = np.random.default_rng(6)  # reproducible common-value simulation.
n_auctions_w6 = 4000  # number of simulated auctions.
n_bidders_w6 = 5  # bidders per auction.
true_value_w6 = rng_w6.uniform(40, 80, size=n_auctions_w6)  # common value of the item.
signals_w6 = true_value_w6[:, None] + rng_w6.normal(0, 10, size=(n_auctions_w6, n_bidders_w6))  # noisy estimates.
naive_bids_w6 = signals_w6  # naive bidders bid their signal.
adjusted_bids_w6 = signals_w6 - 8.0  # cautious bidders shade to offset winner's curse.
winner_naive_w6 = np.argmax(naive_bids_w6, axis=1)  # winners under naive bidding.
winner_adjusted_w6 = np.argmax(adjusted_bids_w6, axis=1)  # same ranking under constant shading.
profit_naive_w6 = true_value_w6 - naive_bids_w6[np.arange(n_auctions_w6), winner_naive_w6]  # winner profit.
profit_adjusted_w6 = true_value_w6 - adjusted_bids_w6[np.arange(n_auctions_w6), winner_adjusted_w6]  # adjusted profit.
print("mean naive winner profit:", round(float(np.mean(profit_naive_w6)), 3))  # winner's curse.
print("mean adjusted winner profit:", round(float(np.mean(profit_adjusted_w6)), 3))  # shading correction.
assert np.mean(profit_adjusted_w6) > np.mean(profit_naive_w6)  # verify adjustment helps.
```
▶ What you'll see: naive common-value winners overpay on average; adjusted bidders do better.

```python
plt.figure(figsize=(5, 3))  # visualize winner-profit distributions.
plt.hist(profit_naive_w6, bins=40, alpha=0.65, label="naive signal bid", color="crimson")  # naive profits.
plt.hist(profit_adjusted_w6, bins=40, alpha=0.65, label="adjusted bid", color="seagreen")  # adjusted profits.
plt.axvline(0, color="black", linewidth=1)  # break-even reference.
plt.xlabel("winner profit")  # profit axis.
plt.ylabel("auction count")  # frequency axis.
plt.title("6: winner's curse in common-value auctions")  # title.
plt.legend()  # label distributions.
plt.show()  # display histogram.
```
▶ What you'll see: naive winners often land left of zero because winning selects overly optimistic signals.

*Why it's done this way:* the common-value simulation marks the boundary of the simple private-value result: auction rules and information structure jointly determine incentives.

```python
t5_rng = np.random.default_rng(0)
```

### ✍️ Toy 6 · Common values create winner's curse pressure

With a common value, the winner often has the most optimistic signal. Shading those signal bids can improve winner profit.

```python
import numpy as np

t6_rng = np.random.default_rng(0)
print("rng seed:", 0)  # -> 0
t6_true_values = np.full(4, 10.0)
print("true common values:", t6_true_values.tolist())  # -> [10.0, 10.0, 10.0, 10.0]
```

## 🛠️ Setup

```python
import numpy as np  # arrays, simulation, and simple numerical checks.
import matplotlib.pyplot as plt  # visual diagnostics for every example.
np.random.seed(0)  # make examples reproducible.

def second_price_auction(bids, values=None, reserve=0.0):  # allocate one item by highest bid and second-price payment.
    bids = np.asarray(bids, dtype=float)  # use numeric bids.
    values = bids if values is None else np.asarray(values, dtype=float)  # values default to truthful bids for simple demos.
    eligible = np.where(bids >= reserve)[0]  # bidders clearing the reserve.
    if len(eligible) == 0:  # no bidder clears the reserve.
        return -1, 0.0, np.zeros_like(bids)  # no winner, no revenue, zero utilities.
    order = eligible[np.argsort(bids[eligible])[::-1]]  # sort eligible bidders by bid.
    winner = int(order[0])  # highest eligible bidder wins.
    price = reserve if len(order) == 1 else max(float(reserve), float(bids[order[1]]))  # second bid or reserve.
    utilities = np.zeros_like(bids)  # non-winner utility is zero.
    utilities[winner] = values[winner] - price  # winner utility is value minus payment.
    return winner, float(price), utilities  # return allocation, payment, utilities.

def first_price_auction(bids, values=None, reserve=0.0):  # allocate one item by highest bid and own-bid payment.
    bids = np.asarray(bids, dtype=float)  # numeric bids.
    values = bids if values is None else np.asarray(values, dtype=float)  # values default to bids.
    eligible = np.where(bids >= reserve)[0]  # bidders clearing reserve.
    if len(eligible) == 0:  # no sale.
        return -1, 0.0, np.zeros_like(bids)  # no winner, no revenue, zero utilities.
    winner = int(eligible[np.argmax(bids[eligible])])  # highest eligible bid wins.
    price = float(bids[winner])  # first-price payment equals own bid.
    utilities = np.zeros_like(bids)  # initialize utilities.
    utilities[winner] = values[winner] - price  # winner surplus.
    return winner, price, utilities  # return outcome.

def english_auction(values, step=0.5):  # simulate an ascending auction with private values.
    values = np.asarray(values, dtype=float)  # numeric values.
    price = 0.0  # start at zero.
    active = np.ones(len(values), dtype=bool)  # all bidders start active.
    history = []  # track active-count curve.
    while np.sum(active) > 1 and price <= np.max(values) + step:  # ascend until one bidder remains.
        history.append((price, int(np.sum(active))))  # record active bidders.
        price += step  # raise price.
        active = values >= price  # bidders drop when price exceeds value.
    winner = int(np.argmax(values))  # highest-value bidder remains.
    payment = min(price, np.max(values))  # approximate price where second-highest drops out.
    return winner, float(payment), np.array(history)  # return outcome and path.

def dutch_auction(values, start=12.0, step=0.5):  # simulate a descending clock auction.
    values = np.asarray(values, dtype=float)  # numeric values.
    prices = np.arange(start, -step, -step)  # descending clock prices.
    for price in prices:  # scan until someone accepts.
        accept = np.where(values >= price)[0]  # bidders willing to buy at current price.
        if len(accept) > 0:  # first acceptance ends auction.
            winner = int(accept[np.argmax(values[accept])])  # break ties by highest value.
            return winner, float(price), prices[:np.where(prices == price)[0][0] + 1]  # outcome and clock path.
    return -1, 0.0, prices  # no one accepts.

def simulate_private_values(n_auctions=2000, n_bidders=5, seed=0):  # draw iid private values.
    rng = np.random.default_rng(seed)  # local generator.
    return rng.uniform(0, 1, size=(n_auctions, n_bidders))  # values in [0,1].
```
