# 5.13 — Dynamic Bayesian Networks

Dynamic Bayesian networks (DBNs) extend Bayesian networks into time by repeating a small probabilistic template instead of drawing a brand-new graph for every time step. In this lesson, you will build the moving parts from scratch: a prior belief, a tied transition model, sensor evidence, prediction, filtering, smoothing, and the parameter-sharing idea that makes DBNs practical.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build dynamic Bayesian networks one idea at a time. Run each cell in order and read the printed intermediate values — every probability vector is normalized and inspected so the temporal reasoning never becomes a black box. This walkthrough is self-contained and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays, matrix multiplication, and probability normalization.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
np.random.seed(0)  # reproducibility for any sampled sequences.
```

### 1. A temporal joint is too large to draw one slice at a time

A Bayesian network over time has variables such as weather at day 1, day 2, day 3, and so on. If we draw every variable separately and learn a separate conditional table for every day, the model grows with the length of the sequence. A DBN starts from the opposite habit: define one local rule and reuse it at every slice.

```python
T_w = 10  # number of time slices in the sequence.
states_w = np.array(["sunny", "rainy"])  # two possible values for each hidden state x_t.
print("time slices:", T_w)  # inspect the sequence length.
print("hidden states per slice:", states_w.tolist())  # inspect the state space.
```
▶ What you'll see: a length-10 binary temporal process, small enough to inspect but long enough to expose parameter growth.

```python
untied_params_w = (T_w - 1) * len(states_w)  # each binary transition row needs one free probability at each time.
tied_params_w = len(states_w)  # the tied transition matrix needs one free probability per row total.
print("untied binary transition parameters:", untied_params_w)  # (10-1)*2 = 18.
print("tied template transition parameters:", tied_params_w)  # 2 free rows reused across time.
assert untied_params_w == 18 and tied_params_w == 2  # lesson numbers from the source block.
```
▶ What you'll see: tying shrinks 18 transition parameters down to 2 for this tiny example.

```python
plt.figure(figsize=(4.6, 3))  # create a compact parameter-count comparison.
plt.bar(["untied over time", "tied DBN template"], [untied_params_w, tied_params_w], color=["crimson", "seagreen"])  # compare model sizes.
plt.ylabel("free transition parameters")  # label the parameter count.
plt.title("1: parameter tying keeps the DBN small")  # title the plot.
plt.xticks(rotation=10)  # keep labels readable.
plt.show()  # display the plot.
```
▶ What you'll see: the untied bar is much taller because it learns a different transition rule at every step.

*Why it's done this way:* A temporal joint over many slices has repeated structure. If the mechanism “today’s state causes tomorrow’s state” is stable, learning one shared transition table pools evidence across all adjacent pairs. That is the DBN bet: time can be long, but the local causal rule can be short.

### 2. The two-slice template: prior plus transition

The simplest DBN is first-order: once you know the current state, the next state does not need the entire past. Its joint distribution factors as $p(x_{1:T})=p(x_1)\prod_{t=2}^T p(x_t\mid x_{t-1})$. We store $p(x_1)$ as a row vector and $p(x_t\mid x_{t-1})$ as a transition matrix.

```python
prior_w = np.array([0.7, 0.3])  # p(x1): 70% sunny, 30% rainy.
A_w = np.array([[0.8, 0.2], [0.25, 0.75]])  # rows are previous states, columns are next states.
print("prior:", prior_w, "sum:", prior_w.sum())  # verify a valid distribution.
print("transition row sums:", A_w.sum(axis=1))  # each row must sum to 1.
assert np.allclose(A_w.sum(axis=1), 1.0)  # stochastic matrix check.
```
▶ What you'll see: every row is a probability distribution over tomorrow’s state.

```python
plt.figure(figsize=(4.3, 3.2))  # create a transition heatmap.
plt.imshow(A_w, cmap="Blues", vmin=0, vmax=1)  # color each conditional probability.
plt.colorbar(label="p(next | current)")  # add probability scale.
plt.xticks([0, 1], states_w)  # label next-state columns.
plt.yticks([0, 1], states_w)  # label current-state rows.
plt.title("2: two-slice transition template")  # title the matrix.
plt.xlabel("x_t")  # next state.
plt.ylabel("x_{t-1}")  # previous state.
plt.show()  # display the heatmap.
```
▶ What you'll see: sunny tends to stay sunny (0.8) and rainy tends to stay rainy (0.75), so the process has inertia.

*Why it's done this way:* The prior answers “where do we start?” and the transition answers “how does one slice generate the next?” Multiplying these local pieces gives the full sequence probability without explicitly storing an enormous table over every possible history.

### 3. Prediction: push belief one step forward

Prediction asks, “before seeing new evidence, what do I believe about the next state?” For a row-vector belief $b_{t-1}$, the next prior is $b_t^- = b_{t-1}A$. Each new probability is a weighted average of transition rows, weighted by how likely the previous states were.

```python
belief_w = np.array([0.7, 0.3])  # current belief before predicting.
pred_w = belief_w @ A_w  # one DBN prediction step.
print("belief before:", belief_w)  # inspect p(x_{t-1}).
print("predicted next belief:", np.round(pred_w, 3))  # inspect p(x_t) before evidence.
assert np.allclose(np.round(pred_w, 3), [0.635, 0.365])  # source-block arithmetic.
```
▶ What you'll see: `[0.7, 0.3] @ [[0.8,0.2],[0.25,0.75]] = [0.635, 0.365]`.

```python
contrib_w = belief_w[:, None] * A_w  # contribution from each previous state to each next state.
print("contribution table:\n", np.round(contrib_w, 3))  # rows add into the predicted vector.
print("column sums:", np.round(contrib_w.sum(axis=0), 3))  # equals pred_w.
```
▶ What you'll see: sunny contributes `[0.56, 0.14]` and rainy contributes `[0.075, 0.225]`; column sums form the prediction.

```python
plt.figure(figsize=(4.5, 3))  # create a before/after belief plot.
plt.bar(np.arange(2) - 0.18, belief_w, width=0.36, label="before", color="gray")  # current belief.
plt.bar(np.arange(2) + 0.18, pred_w, width=0.36, label="predicted", color="teal")  # next prior.
plt.xticks([0, 1], states_w)  # label state names.
plt.ylim(0, 1)  # probability scale.
plt.ylabel("probability")  # label y axis.
plt.title("3: prediction moves belief through A")  # title the plot.
plt.legend()  # show labels.
plt.show()  # display the plot.
```
▶ What you'll see: uncertainty shifts toward rainy because some sunny probability can transition to rain.

*Why it's done this way:* Matrix multiplication is marginalization. For each possible next state, we sum over all previous states: previous belief times transition probability. The operation keeps exactly the information the first-order Markov model says matters.

### 4. Evidence update: multiply by sensor likelihood and renormalize

Filtering incorporates an observation at the current slice. If the sensor says “umbrella seen,” each hidden state receives a likelihood $p(e_t\mid x_t)$. The unnormalized posterior is prediction times likelihood, and the normalizer turns those scores back into probabilities.

```python
sensor_umbrella_w = np.array([0.1, 0.9])  # p(umbrella | sunny), p(umbrella | rainy).
unnorm_w = pred_w * sensor_umbrella_w  # evidence scores for each hidden state.
Z_w = unnorm_w.sum()  # normalizing constant p(e_t | previous evidence).
filtered_w = unnorm_w / Z_w  # posterior p(x_t | evidence through t).
print("unnormalized scores:", np.round(unnorm_w, 4))  # multiply prediction by likelihood.
print("normalizer Z:", round(float(Z_w), 4))  # sum of scores.
print("filtered belief:", np.round(filtered_w, 3))  # normalized posterior.
assert np.allclose(np.round(filtered_w, 3), [0.162, 0.838])  # umbrella strongly favors rain.
```
▶ What you'll see: umbrella evidence flips belief strongly toward rainy even though the prediction was only mildly rainy.

```python
plt.figure(figsize=(4.6, 3))  # create a prediction-vs-filtering plot.
plt.bar(np.arange(2) - 0.18, pred_w, width=0.36, label="before evidence", color="orange")  # predicted prior.
plt.bar(np.arange(2) + 0.18, filtered_w, width=0.36, label="after umbrella", color="seagreen")  # posterior.
plt.xticks([0, 1], states_w)  # label state names.
plt.ylim(0, 1)  # probability scale.
plt.ylabel("probability")  # label y axis.
plt.title("4: evidence reweights the state vector")  # title the plot.
plt.legend()  # show legend.
plt.show()  # display plot.
```
▶ What you'll see: the rainy bar rises sharply because umbrella is much more likely under rain.

*Why it's done this way:* Prediction carries prior belief from the dynamics; the likelihood carries what the sensor just said. Multiplying combines independent pieces of evidence for each state, and dividing by the sum enforces the probability rule that posterior probabilities must add to 1.

### 5. Filtering across many slices

A DBN repeats prediction and evidence update at every time step. This gives online filtering: after each observation, we maintain $p(x_t\mid e_{1:t})$, the current-state belief using all evidence seen so far.

```python
evidence_w = np.array([1, 1, 0, 1, 0, 0])  # 1 = umbrella observed, 0 = no umbrella.
sensor_w = np.array([[0.9, 0.1], [0.1, 0.9]])  # rows: no umbrella, umbrella; columns: sunny, rainy.
print("evidence sequence:", evidence_w.tolist())  # inspect observation timing.
print("sensor rows [no umbrella, umbrella]:\n", sensor_w)  # inspect likelihood table.
```
▶ What you'll see: the sensor table says no umbrella favors sunny and umbrella favors rainy.

```python
beliefs_w = []  # store filtered beliefs after each slice.
bel_w = prior_w.copy()  # start at p(x1) before the first evidence update.
for t_w, obs_w in enumerate(evidence_w):  # process observations in time order.
    if t_w > 0:  # after the first slice, predict from the previous filtered belief.
        bel_w = bel_w @ A_w  # prediction step.
    bel_w = bel_w * sensor_w[obs_w]  # evidence likelihood for this observation.
    bel_w = bel_w / bel_w.sum()  # renormalize.
    beliefs_w.append(bel_w.copy())  # save the current filtered posterior.
beliefs_w = np.array(beliefs_w)  # convert list to a time-by-state array.
print("filtered rainy probabilities:", np.round(beliefs_w[:, 1], 3))  # inspect p(rainy | evidence so far).
assert beliefs_w.shape == (6, 2)  # six filtered two-state distributions.
```
▶ What you'll see: rainy probability rises after umbrella observations and falls after no-umbrella observations.

```python
plt.figure(figsize=(5, 3))  # create a filtering time-series plot.
plt.plot(beliefs_w[:, 0], marker="o", label="sunny", color="goldenrod")  # filtered sunny probability.
plt.plot(beliefs_w[:, 1], marker="o", label="rainy", color="steelblue")  # filtered rainy probability.
plt.xticks(range(len(evidence_w)), [f"t{i+1}" for i in range(len(evidence_w))])  # label time points.
plt.ylim(0, 1)  # probability scale.
plt.ylabel("filtered probability")  # label y axis.
plt.title("5: filtering repeats predict → update")  # title plot.
plt.legend()  # show state labels.
plt.show()  # display plot.
```
▶ What you'll see: a belief trajectory rather than one static probability vector.

*Why it's done this way:* Filtering is a recursive algorithm because the filtered belief is a compact summary of the entire past. The Markov state plus the current posterior is sufficient for the next prediction, so we do not need to keep every previous hidden-state assignment.

### 6. Filtering, prediction, and smoothing answer different questions

Evidence timing matters. Filtering estimates the present from past and present evidence. Prediction estimates the future before future evidence arrives. Smoothing estimates a past state after later evidence has arrived, so it can revise old beliefs.

```python
last_filtered_w = beliefs_w[-1]  # p(x_T | e_1:T).
one_step_future_w = last_filtered_w @ A_w  # p(x_{T+1} | e_1:T), no new evidence.
print("last filtered belief:", np.round(last_filtered_w, 3))  # current posterior.
print("one-step prediction:", np.round(one_step_future_w, 3))  # future prior.
assert np.isclose(one_step_future_w.sum(), 1.0)  # prediction remains a distribution.
```
▶ What you'll see: the future prediction is less extreme than the latest filtered belief because dynamics mix the states.

```python
backward_w = np.ones(2)  # initialize backward message after final time.
smoothed_w = np.zeros_like(beliefs_w)  # store smoothed beliefs.
for t_w in range(len(evidence_w) - 1, -1, -1):  # sweep backward through time.
    smooth_score_w = beliefs_w[t_w] * backward_w  # combine filtered belief with future message.
    smoothed_w[t_w] = smooth_score_w / smooth_score_w.sum()  # normalize smoothed belief.
    if t_w > 0:  # build message to the previous slice.
        likelihood_next_w = sensor_w[evidence_w[t_w]]  # likelihood at the current slice.
        backward_w = A_w @ (likelihood_next_w * backward_w)  # sum over current states for each previous state.
print("filtered rainy at t1:", round(float(beliefs_w[0, 1]), 3))  # online answer at t1.
print("smoothed rainy at t1:", round(float(smoothed_w[0, 1]), 3))  # revised answer after all evidence.
```
▶ What you'll see: smoothing can change the first-slice belief because later observations provide indirect evidence about earlier states.

```python
plt.figure(figsize=(5, 3))  # create timing comparison plot.
plt.plot(beliefs_w[:, 1], marker="o", label="filtered rainy", color="steelblue")  # online estimates.
plt.plot(smoothed_w[:, 1], marker="s", label="smoothed rainy", color="purple")  # hindsight estimates.
plt.ylim(0, 1)  # probability scale.
plt.xlabel("time index")  # label time.
plt.ylabel("p(rainy)")  # label probability.
plt.title("6: later evidence revises earlier states")  # title plot.
plt.legend()  # show labels.
plt.show()  # display plot.
```
▶ What you'll see: filtered and smoothed curves differ most where future evidence changes the interpretation of the past.

*Why it's done this way:* These are different conditional probabilities. Prediction leaves out future evidence by design, filtering uses evidence up to now, and smoothing uses evidence from both sides of a past time. Mixing them up is a common DBN bug.

### 7. A DBN slice can contain multiple variables

A hidden state can be a vector, not just one binary variable. HMMs use one discrete hidden state and one observation; Kalman filters use linear-Gaussian continuous states; general DBNs can include several variables inside each slice. The rule is the same: the slice must contain enough information to make the future conditionally independent of the older past.

```python
weather_vals_w = ["sunny", "rainy"]  # first within-slice variable.
traffic_vals_w = ["light", "heavy"]  # second within-slice variable.
joint_states_w = [(w_w, tr_w) for w_w in weather_vals_w for tr_w in traffic_vals_w]  # vector-valued x_t flattened.
print("joint slice states:", joint_states_w)  # inspect the combined state space.
print("number of joint states:", len(joint_states_w))  # 2*2 = 4 states.
assert len(joint_states_w) == 4  # two binary variables become four joint values.
```
▶ What you'll see: a slice with weather and traffic is represented as four joint state values.

```python
A_joint_w = np.array([[0.60, 0.20, 0.15, 0.05], [0.30, 0.45, 0.10, 0.15], [0.20, 0.10, 0.45, 0.25], [0.05, 0.15, 0.25, 0.55]])  # tied transition over joint slice states.
prior_joint_w = np.array([0.5, 0.2, 0.2, 0.1])  # starting belief over the four joint states.
pred_joint_w = prior_joint_w @ A_joint_w  # one prediction step for a vector-valued state.
print("joint transition row sums:", A_joint_w.sum(axis=1))  # verify conditional distributions.
print("predicted joint belief:", np.round(pred_joint_w, 3))  # inspect next-slice belief.
assert np.allclose(A_joint_w.sum(axis=1), 1.0)  # valid transition matrix.
```
▶ What you'll see: the exact same matrix rule works after flattening a multi-variable slice into joint states.

```python
plt.figure(figsize=(5, 3))  # create joint-state prediction plot.
plt.bar([f"{w}/{tr}" for w, tr in joint_states_w], pred_joint_w, color="darkcyan")  # show predicted probability by joint state.
plt.xticks(rotation=20)  # keep labels readable.
plt.ylabel("probability")  # label probability.
plt.title("7: vector-valued slice as joint state")  # title plot.
plt.show()  # display plot.
```
▶ What you'll see: probability is distributed over combinations such as sunny/light and rainy/heavy, not just single labels.

*Why it's done this way:* The Markov property is about information, not about having one variable. If weather alone cannot predict tomorrow’s traffic, include traffic or another sufficient variable in the slice. A state that is too small violates the model’s own conditional-independence assumption.

### Basic 5 — Apply sensor likelihood

**Goal.** Multiply a predicted belief by observation likelihoods, because evidence reweights states according to how well they explain what was observed. We build it in 2 steps.

```python
pred_b5 = np.array([0.635, 0.365]) # predicted belief before evidence.
like_b5 = np.array([0.1, 0.9]) # p(umbrella | sunny), p(umbrella | rainy).
score_b5 = pred_b5 * like_b5 # unnormalized posterior scores.
print("scores:", np.round(score_b5, 4)) # inspect likelihood-weighted probabilities.
```

```python
post_b5 = score_b5 / score_b5.sum() # normalize scores into posterior probabilities.

assert np.allclose(np.round(post_b5, 3), [0.162, 0.838]) # verify the update.
plt.figure(figsize=(4, 3)) # create an evidence update plot.

```
▶ What you'll see: the posterior strongly favors rainy after umbrella evidence.

👀 Takeaway: evidence update is elementwise multiplication followed by normalization.

### Basic 6 — Compute the normalizer

**Goal.** Isolate the normalizing constant $Z$, because it is the quantity that turns local evidence scores into a valid probability vector. We build it in 2 steps.

```python
score_b6 = np.array([0.0635, 0.3285]) # reuse the unnormalized scores from umbrella evidence.
Z_b6 = score_b6.sum() # compute total evidence probability under the predicted belief.
print("Z:", round(float(Z_b6), 4)) # inspect the normalizer.
assert round(float(Z_b6), 4) == 0.392 # verify the exact score sum.
```
▶ What you'll see: the total unnormalized mass is 0.392.

```python
normalized_b6 = score_b6 / Z_b6 # divide every score by the same constant.

plt.figure(figsize=(4, 3)) # create a before/after normalization plot.

plt.title("Basic 6: normalization") # title the plot.
plt.legend() # show labels.
plt.show() # display plot.
```
▶ What you'll see: normalized bars are larger because they are rescaled to sum to 1.

👀 Takeaway: normalization preserves relative evidence while enforcing the probability scale.

### Basic 7 — Run two filtering steps

**Goal.** Chain prediction and evidence twice, because filtering is a repeated online update rather than a one-off calculation. We build it in 3 steps.

```python
A_b7 = np.array([[0.8, 0.2], [0.25, 0.75]]) # transition table.
sensor_b7 = np.array([[0.9, 0.1], [0.1, 0.9]]) # likelihood rows: no umbrella, umbrella.
bel_b7 = np.array([0.7, 0.3]) # initial prior before any observation.
print("start:", bel_b7) # inspect starting belief.
```
▶ What you'll see: the filter starts with the same prior used above.

```python
obs_b7 = np.array([1, 0]) # umbrella at t1, then no umbrella at t2.
filtered_b7 = [] # store filtered beliefs.
for t_b7, o_b7 in enumerate(obs_b7): # process observations in order.
```

### Advanced 1 — Forward-backward smoothing

**Goal.** Smooth past states with future evidence, because hindsight estimates $p(x_t\mid e_{1:T})$ rather than online $p(x_t\mid e_{1:t})$. We build it in 5 steps.

```python

```

### Advanced 2 — Viterbi most likely path

**Goal.** Compute the single most likely hidden path, because sometimes we need a best explanation rather than marginal beliefs at each time. We build it in 5 steps.

```python
A_a2 = np.array([[0.8, 0.2], [0.25, 0.75]]) # transition probabilities.
sensor_a2 = np.array([[0.9, 0.1], [0.1, 0.9]]) # likelihood rows for observations.
obs_a2 = np.array([1, 1, 0, 1, 0]) # evidence sequence.
prior_a2 = np.array([0.7, 0.3]) # initial prior.
print("observations:", obs_a2.tolist()) # inspect sequence.
```
▶ What you'll see: Viterbi will find one hidden weather path explaining these observations.

```python

loglike_a2 = np.log(sensor_a2[obs_a2]) # likelihood log scores by time and state.
delta_a2 = np.zeros((len(obs_a2), 2)) # best log score ending in each state.
back_a2 = np.zeros((len(obs_a2), 2), dtype=int) # best previous state pointers.
delta_a2[0] = np.log(prior_a2) + loglike_a2[0] # initialize first slice.
print("initial delta:", np.round(delta_a2[0], 3)) # inspect starting log scores.
```

```python
for t_a2 in range(1, len(obs_a2)): # dynamic program over time.
    for j_a2 in range(2): # compute best path ending in state j.
        scores_a2 = delta_a2[t_a2 - 1] + logA_a2[:, j_a2] # previous best plus transition.
        back_a2[t_a2, j_a2] = int(np.argmax(scores_a2)) # remember best previous state.
        delta_a2[t_a2, j_a2] = scores_a2[back_a2[t_a2, j_a2]] + loglike_a2[t_a2, j_a2] # add observation likelihood.
print("final delta:", np.round(delta_a2[-1], 3)) # inspect final best scores.
```

```python

path_a2[-1] = int(np.argmax(delta_a2[-1])) # start traceback from best final state.
for t_a2 in range(len(obs_a2) - 1, 0, -1): # follow backpointers.
    path_a2[t_a2 - 1] = back_a2[t_a2, path_a2[t_a2]] # recover previous state.

```

```python
plt.show() # display plot.
```
▶ What you'll see: a single path, not a probability curve, because Viterbi maximizes jointly over hidden states.

👀 Takeaway: marginal filtering answers “how likely is each state now,” while Viterbi answers “which whole path is most likely.”


👀 Takeaway: tying is a statistical assumption that trades flexibility for much better data sharing across time.

### Advanced 5 — Diagnose evidence timing bugs

**Goal.** Compare filtering, prediction, and smoothing on the same time index, because using the wrong temporal query silently changes the answer. We build it in 5 steps.

```python
A_a5 = np.array([[0.8, 0.2], [0.25, 0.75]]) # transition matrix.
sensor_a5 = np.array([[0.9, 0.1], [0.1, 0.9]]) # likelihood rows.
obs_a5 = np.array([1, 1, 0, 1, 0]) # evidence sequence.
prior_a5 = np.array([0.7, 0.3]) # initial prior.
query_t_a5 = 2 # compare answers at the third slice.
print("query time index:", query_t_a5) # inspect target time.
```
▶ What you'll see: all three calculations will talk about the same hidden slice but condition on different evidence.

```python
filt_a5 = [] # store filtered beliefs.
bel_a5 = prior_a5.copy() # initialize forward pass.
for t_a5, o_a5 in enumerate(obs_a5): # filter through all evidence.
    if t_a5 > 0: # predict between slices.
        bel_a5 = bel_a5 @ A_a5 # dynamics.
    bel_a5 = bel_a5 * sensor_a5[o_a5] # evidence.
    bel_a5 = bel_a5 / bel_a5.sum() # normalize.
    filt_a5.append(bel_a5.copy()) # save filtered belief.
filt_a5 = np.array(filt_a5) # convert to array.
print("filter at query:", np.round(filt_a5[query_t_a5], 3)) # p(x_t | e_1:t).
```

```python
predict_from_previous_a5 = filt_a5[query_t_a5 - 1] @ A_a5 # p(x_t | e_1:t-1), before seeing query evidence.
print("prediction before query evidence:", np.round(predict_from_previous_a5, 3)) # prediction answer.
```

```python
beta_a5 = np.ones((len(obs_a5), 2)) # backward messages.
for t_a5 in range(len(obs_a5) - 2, -1, -1): # backward pass.
    beta_a5[t_a5] = A_a5 @ (sensor_a5[obs_a5[t_a5 + 1]] * beta_a5[t_a5 + 1]) # future evidence message.
    beta_a5[t_a5] = beta_a5[t_a5] / beta_a5[t_a5].sum() # scale message.
smooth_a5 = filt_a5 * beta_a5 # combine forward and backward terms.
smooth_a5 = smooth_a5 / smooth_a5.sum(axis=1, keepdims=True) # normalize.
print("smooth at query:", np.round(smooth_a5[query_t_a5], 3)) # p(x_t | e_1:T).
```

```python
answers_a5 = np.vstack([predict_from_previous_a5, filt_a5[query_t_a5], smooth_a5[query_t_a5]]) # stack the three query answers.
plt.figure(figsize=(5, 3)) # create grouped comparison.
plt.bar(np.arange(3) - 0.18, answers_a5[:, 0], width=0.36, label="sunny", color="goldenrod") # sunny answers.
plt.bar(np.arange(3) + 0.18, answers_a5[:, 1], width=0.36, label="rainy", color="steelblue") # rainy answers.
plt.xticks(range(3), ["predict", "filter", "smooth"]) # label query types.
plt.ylim(0, 1) # probability scale.
plt.ylabel("probability at query time") # label y axis.
plt.title("Advanced 5: evidence timing changes the answer") # title plot.
plt.legend() # show labels.
plt.show() # display plot.
```
▶ What you'll see: the three bars differ because prediction excludes query evidence, filtering includes it, and smoothing also includes later evidence.

👀 Takeaway: always name the temporal query before coding DBN inference: prediction, filtering, and smoothing are not interchangeable.
