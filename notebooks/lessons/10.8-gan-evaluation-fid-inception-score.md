# 10.8 — GAN Evaluation (FID, Inception Score)

GAN evaluation is hard because the training loss is part of a game, not a direct promise that generated samples are realistic or diverse. In this lesson, you will build two distribution-level metrics from scratch: Fréchet Inception Distance (FID), which compares real and generated feature Gaussians through means and covariances, and Inception Score (IS), which rewards generated samples whose predicted labels are both confident and diverse.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build GAN evaluation one idea at a time. Run each cell in order and read the printed intermediate values — every piece of math, including the Fréchet distance and the KL divergence behind Inception Score, is derived and shown. This walkthrough is self-contained and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import numpy as np  # arrays, covariance, eigendecompositions, and KL arithmetic.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
np.random.seed(0)  # reproducibility for toy generated samples.
```

### 1. Evaluation is distribution matching, not cherry-picking

A GAN can produce a few impressive samples while missing whole parts of the real distribution. So evaluation should compare **sets** of real and generated samples. In a toy two-feature world, one coordinate can stand for a class-like factor and the other for style. A good generator must land in the same cloud, not just near one favorite point.

```python
real_w = np.array([[-1.2, 0.0], [-0.8, 0.4], [-1.0, -0.3],
                   [ 1.0, 0.2], [ 1.3, -0.2], [ 0.8, 0.5]])  # two real modes.
good_w = real_w + np.array([[0.1, 0.0], [0.0, -0.1], [0.1, 0.1],
                            [-0.1, 0.0], [0.0, 0.1], [-0.1, -0.1]])  # covers both modes.
collapsed_w = np.array([[-1.1, 0.1], [-1.0, 0.0], [-0.9, -0.1],
                        [-1.2, 0.2], [-0.8, -0.2], [-1.0, 0.1]])  # covers only left mode.
print("real shape:", real_w.shape, "good shape:", good_w.shape, "collapsed shape:", collapsed_w.shape)
```
▶ What you'll see: three small sample sets with the same number of generated points, so the comparison is about distribution shape.

```python
plt.figure(figsize=(4.8, 3.5))
plt.scatter(real_w[:, 0], real_w[:, 1], s=80, label="real", color="black")
plt.scatter(good_w[:, 0], good_w[:, 1], s=70, label="good generator", color="seagreen")
plt.scatter(collapsed_w[:, 0], collapsed_w[:, 1], s=70, label="collapsed", color="crimson", marker="x")
plt.axvline(0, color="gray", linewidth=0.6); plt.xlabel("feature 0"); plt.ylabel("feature 1")
plt.title("1: samples must cover the distribution"); plt.legend(); plt.show()
```
▶ What you'll see: the collapsed generator has realistic-looking left-mode points but completely misses the right mode.

*Why it's done this way:* GAN metrics evaluate distributions because individual images can be cherry-picked. The moment we summarize a batch, missing modes and diversity errors become visible as changes in means, covariances, or class marginals.

### 2. Features, means, and covariances are the FID ingredients

FID does not compare raw pixels in this toy lesson. It compares **feature vectors**: lower-dimensional representations that should capture semantic content. From each feature set we compute a mean vector $m$ and covariance matrix $C$. The mean tracks where the cloud is centered; the covariance tracks spread and correlations, so mode collapse can be detected even when the average looks acceptable.

```python
m_real_w = np.mean(real_w, axis=0)  # center of the real feature cloud.
m_good_w = np.mean(good_w, axis=0)  # center of the good generated feature cloud.
m_collapsed_w = np.mean(collapsed_w, axis=0)  # center of the collapsed feature cloud.
print("means real/good/collapsed:", np.round(m_real_w, 3), np.round(m_good_w, 3), np.round(m_collapsed_w, 3))
```
▶ What you'll see: the good mean is near the real mean, while the collapsed mean shifts left because one mode vanished.

```python
C_real_w = np.cov(real_w, rowvar=False, bias=True)  # covariance: feature spread and co-movement.
C_good_w = np.cov(good_w, rowvar=False, bias=True)
C_collapsed_w = np.cov(collapsed_w, rowvar=False, bias=True)
print("real covariance:\n", np.round(C_real_w, 3))
print("collapsed covariance:\n", np.round(C_collapsed_w, 3))
```
▶ What you'll see: the collapsed covariance is much smaller along feature 0 because it no longer spans both modes.

```python
fig, ax = plt.subplots(1, 2, figsize=(7, 3))
ax[0].imshow(C_real_w, cmap="viridis"); ax[0].set_title("real C")
ax[1].imshow(C_collapsed_w, cmap="viridis"); ax[1].set_title("collapsed C")
for a in ax: a.set_xticks([0, 1]); a.set_yticks([0, 1])
plt.suptitle("2: covariance stores diversity"); plt.show()
```
▶ What you'll see: covariance heatmaps make the lost spread of the collapsed generator visible.

*Why it's done this way:* matching only means would miss a generator that averages correctly while producing too little variety. Covariance adds the second-order shape of the distribution, which is the simplest way FID notices diversity collapse.

### 3. Fréchet distance between Gaussian feature distributions

FID approximates real and generated feature distributions as Gaussians, then uses the squared 2-Wasserstein / Fréchet distance:

$$FID=\lVert m_r-m_g\rVert^2+\mathrm{Tr}\left(C_r+C_g-2(C_rC_g)^{1/2}\right).$$

Read the formula as two penalties. The first term punishes center mismatch. The trace term punishes covariance mismatch. For diagonal covariances, the covariance part becomes $\sum_j(\sqrt{\sigma^2_{r,j}}-\sqrt{\sigma^2_{g,j}})^2$, so it is literally a squared distance between standard deviations.

```python
mr_w = np.array([0.0, 0.0])  # real feature mean.
mg_w = np.array([1.0, 0.5])  # generated feature mean.
Cr_diag_w = np.array([1.0, 0.25])  # real feature variances.
Cg_diag_w = np.array([0.64, 0.5105])  # generated feature variances chosen for an auditable toy FID.
mean_term_w = float(np.sum((mr_w - mg_w) ** 2))
cov_term_w = float(np.sum((np.sqrt(Cr_diag_w) - np.sqrt(Cg_diag_w)) ** 2))
print("mean term:", round(mean_term_w, 3), "covariance term:", round(cov_term_w, 3))
```
▶ What you'll see: the mean mismatch contributes 1.25 and the covariance mismatch contributes about 0.086.

```python
fid_diag_w = mean_term_w + cov_term_w
print("toy diagonal FID:", round(fid_diag_w, 3))
assert round(fid_diag_w, 3) == 1.336
plt.figure(figsize=(4, 3))
plt.bar(["mean", "covariance", "FID"], [mean_term_w, cov_term_w, fid_diag_w], color=["teal", "orange", "purple"])
plt.title("3: FID is center mismatch + spread mismatch"); plt.ylabel("distance contribution"); plt.show()
```
▶ What you'll see: most of this toy FID comes from the shifted mean, but covariance still adds a measurable penalty.

```python
def frechet_distance_w(m1, C1, m2, C2):  # FID from scratch using eigenvalues of C1 C2.
    mean_part = float(np.sum((m1 - m2) ** 2))
    eigvals = np.linalg.eigvals(C1 @ C2).real
    eigvals = np.maximum(eigvals, 0.0)  # tiny negatives can appear from floating-point roundoff.
    cov_part = float(np.trace(C1) + np.trace(C2) - 2 * np.sum(np.sqrt(eigvals)))
    return mean_part + cov_part
fid_good_w = frechet_distance_w(m_real_w, C_real_w, m_good_w, C_good_w)
fid_collapsed_w = frechet_distance_w(m_real_w, C_real_w, m_collapsed_w, C_collapsed_w)
print("FID good:", round(fid_good_w, 3), "FID collapsed:", round(fid_collapsed_w, 3))
assert fid_good_w < fid_collapsed_w
```
▶ What you'll see: the generator covering both modes has a lower FID than the collapsed generator.

*Why it's done this way:* the matrix square-root term is what makes covariance comparison geometric rather than a raw elementwise subtraction. It asks how much one Gaussian ellipsoid must be transported to become the other; lower is better, and zero means identical means and covariances.

### 4. Inception Score starts with confident conditional labels

Inception Score assumes a classifier gives $p(y\mid x)$ for each generated sample. A single good sample should produce a confident label distribution: one class probability high and the rest low. We build that with a softmax over logits.

```python
logits_w = np.array([1.2, 0.3, -0.4])  # classifier scores for one generated sample.
exp_w = np.exp(logits_w - np.max(logits_w))  # stable softmax numerator.
pyx_w = exp_w / np.sum(exp_w)  # p(y|x).
print("p(y|x):", np.round(pyx_w, 4), "top probability:", round(float(np.max(pyx_w)), 4))
assert round(float(np.max(pyx_w)), 4) == 0.6217
```
▶ What you'll see: the top class receives probability 0.6217, so the classifier is moderately confident.

```python
plt.figure(figsize=(4, 3))
plt.bar(["class 0", "class 1", "class 2"], pyx_w, color="steelblue")
plt.ylim(0, 1); plt.title("4: conditional label distribution p(y|x)"); plt.ylabel("probability"); plt.show()
```
▶ What you'll see: one bar is tallest, but the distribution is not perfectly one-hot.

*Why it's done this way:* softmax converts arbitrary classifier scores into probabilities that sum to 1. IS uses these probabilities because confidence is a proxy for recognizability: if generated samples look like clear objects, $p(y\mid x)$ should have low entropy.

### 5. Inception Score uses KL to reward confidence and diversity

Confidence alone is not enough: a generator that makes only one clear class should not score highly. IS compares each conditional distribution $p(y\mid x)$ to the marginal $p(y)$ over all generated samples:

$$IS=\exp\left(\mathbb{E}_x\, KL(p(y\mid x)\Vert p(y))\right).$$

The KL is large when a sample is confident but the overall batch is diverse. If every sample has the same class, then $p(y\mid x)$ and $p(y)$ look similar, the KL shrinks, and IS does not reward mode collapse.

```python
uniform_w = np.ones(3) / 3  # a diverse marginal over three classes.
kl_one_w = float(np.sum(pyx_w * np.log(pyx_w / uniform_w)))
contribution_w = float(np.exp(kl_one_w))
print("KL against uniform:", round(kl_one_w, 3), "exp(KL):", round(contribution_w, 3))
assert abs(round(contribution_w, 3) - 1.215) <= 0.01
```
▶ What you'll see: the single-sample contribution exponentiates to about 1.215 against a uniform marginal.

```python
probs_good_w = np.array([[0.90, 0.05, 0.05], [0.05, 0.90, 0.05], [0.05, 0.05, 0.90],
                         [0.85, 0.10, 0.05], [0.10, 0.85, 0.05], [0.05, 0.10, 0.85]])
probs_collapsed_w = np.array([[0.90, 0.05, 0.05], [0.88, 0.07, 0.05], [0.92, 0.04, 0.04],
                              [0.89, 0.06, 0.05], [0.91, 0.05, 0.04], [0.87, 0.08, 0.05]])
def inception_score_w(probs):
    marginal = np.mean(probs, axis=0)
    kls = np.sum(probs * (np.log(probs) - np.log(marginal)), axis=1)
    return float(np.exp(np.mean(kls))), marginal, kls
is_good_w, marg_good_w, kls_good_w = inception_score_w(probs_good_w)
is_collapsed_w, marg_collapsed_w, kls_collapsed_w = inception_score_w(probs_collapsed_w)
print("IS good:", round(is_good_w, 3), "marginal:", np.round(marg_good_w, 3))
print("IS collapsed:", round(is_collapsed_w, 3), "marginal:", np.round(marg_collapsed_w, 3))
assert is_good_w > is_collapsed_w
```
▶ What you'll see: confident samples spread across classes score higher than confident samples all in one class.

```python
plt.figure(figsize=(4.8, 3))
plt.bar(["diverse confident", "collapsed confident"], [is_good_w, is_collapsed_w], color=["seagreen", "crimson"])
plt.title("5: Inception Score rewards confidence + diversity"); plt.ylabel("IS (higher is better)"); plt.show()
```
▶ What you'll see: the diverse batch has the higher score because its marginal label distribution is broader.

*Why it's done this way:* KL measures how surprising a sample's label distribution is relative to the batch marginal. Exponentiating turns the average KL into an effective number of recognizable classes, so the score rises only when samples are individually sharp and collectively varied.

### 6. Metric pitfalls: finite samples, classifier bias, and domain mismatch

FID and IS are useful cautionary tools, not absolute truth. FID depends on the feature extractor and suffers sampling noise. IS depends even more directly on a classifier's label space, so it can be meaningless when the generated domain does not match that classifier.

```python
rng_w = np.random.default_rng(0)
large_real_w = rng_w.normal(size=(2000, 2))
large_gen_w = rng_w.normal(loc=[0.05, -0.03], scale=[1.02, 0.98], size=(2000, 2))
small_real_w = large_real_w[:40]
small_gen_w = large_gen_w[:40]
def mean_cov_w(X):
    return np.mean(X, axis=0), np.cov(X, rowvar=False, bias=True)
fid_large_w = frechet_distance_w(*mean_cov_w(large_real_w), *mean_cov_w(large_gen_w))
fid_small_w = frechet_distance_w(*mean_cov_w(small_real_w), *mean_cov_w(small_gen_w))
print("FID with 2000 samples:", round(fid_large_w, 3), "FID with 40 samples:", round(fid_small_w, 3))
```
▶ What you'll see: the small-sample FID can differ noticeably even though both sets come from nearly the same distribution.

```python
wrong_domain_probs_w = np.tile(np.array([[0.34, 0.33, 0.33]]), (6, 1))  # classifier is unsure on every sample.
is_wrong_w, marginal_wrong_w, _ = inception_score_w(wrong_domain_probs_w)
print("wrong-domain marginal:", np.round(marginal_wrong_w, 3), "IS:", round(is_wrong_w, 3))
assert round(is_wrong_w, 3) == 1.0
```
▶ What you'll see: an unsure classifier gives IS ≈ 1 even if the generated samples might be good in a different domain.

*Why it's done this way:* metric formulas are only as meaningful as their features and probabilities. FID can rank distributional similarity in a chosen feature space; IS can rank classifier confidence and label diversity. Neither directly proves human quality, fairness, or downstream usefulness.

## 🛠️ Setup

```python
import numpy as np # load NumPy for arrays, covariance estimates, eigenvalues, softmax, and KL calculations.
import matplotlib.pyplot as plt # load Matplotlib so every metric can be inspected visually.
np.random.seed(0) # make all random examples reproducible across notebook runs.

def softmax(z): # Convert logits into normalized class probabilities.
    z = np.asarray(z, dtype=float) # Convert inputs to float arrays so exponentiation is predictable.
    shifted = z - np.max(z, axis=-1, keepdims=True) # Subtract the max for numerical stability without changing softmax values.
    exp_z = np.exp(shifted) # Exponentiate shifted logits into positive weights.
    return exp_z / np.sum(exp_z, axis=-1, keepdims=True) # Normalize each row so probabilities sum to one.

def mean_cov(X): # Estimate the Gaussian feature summary used by FID.
    X = np.asarray(X, dtype=float) # Convert features to a float array.
    return np.mean(X, axis=0), np.cov(X, rowvar=False, bias=True) # Return mean vector and population covariance matrix.

def frechet_distance(m1, C1, m2, C2): # Compute FID-style Fréchet distance between two Gaussian feature summaries.
    m1 = np.asarray(m1, dtype=float); m2 = np.asarray(m2, dtype=float) # Ensure means are numeric vectors.
    C1 = np.asarray(C1, dtype=float); C2 = np.asarray(C2, dtype=float) # Ensure covariances are numeric matrices.
    mean_part = float(np.sum((m1 - m2) ** 2)) # Compute squared distance between feature means.
    eigvals = np.linalg.eigvals(C1 @ C2).real # Get eigenvalues whose square roots form the trace of the matrix square root.
    eigvals = np.maximum(eigvals, 0.0) # Clip tiny negative roundoff values before square roots.
    cov_part = float(np.trace(C1) + np.trace(C2) - 2 * np.sum(np.sqrt(eigvals))) # Compute covariance mismatch term.
    return mean_part + cov_part # Lower is better; zero means identical Gaussian summaries.

def inception_score(probs): # Compute IS from a matrix of p(y|x) rows.
    probs = np.asarray(probs, dtype=float) # Convert probabilities to a float array.
    marginal = np.mean(probs, axis=0) # Estimate p(y) across generated samples.
    kls = np.sum(probs * (np.log(probs) - np.log(marginal)), axis=1) # Compute KL(p(y|x)||p(y)) per sample.
    return float(np.exp(np.mean(kls))), marginal, kls # Exponentiate the average KL and return diagnostics.

def show_feature_cloud(real, gen, title): # Plot real and generated feature vectors in two dimensions.
    plt.figure(figsize=(4, 3)) # Start a compact scatter figure.
    plt.scatter(real[:, 0], real[:, 1], color="black", label="real") # Draw real features as black points.
    plt.scatter(gen[:, 0], gen[:, 1], color="teal", marker="x", label="generated") # Draw generated features as teal crosses.
    plt.title(title) # Label the figure with the example name.
    plt.xlabel("feature 0") # Label the first feature axis.
    plt.ylabel("feature 1") # Label the second feature axis.
    plt.legend() # Show which points are real and generated.
    plt.show() # Display the feature cloud.
```


```python
show_feature_cloud(real_b1, gen_b1, "B1: real vs generated features") # Visualize coverage before reducing samples to summaries.
```
▶ What you'll see: generated points sit near both real modes rather than only one mode.

### Basic 2 — Compute a feature mean

**Goal.** Summarize where a sample cloud is centered, because the first FID term is squared mean distance. We build it in 2 steps.

```python
real_b2 = np.array([[-1.0, 0.0], [-0.8, 0.3], [0.9, -0.2], [1.1, 0.2]]) # Define a real feature batch.
gen_b2 = np.array([[-0.9, 0.1], [-0.7, 0.2], [0.8, -0.1], [1.0, 0.3]]) # Define a generated feature batch.
mean_real_b2 = np.mean(real_b2, axis=0) # Average each feature coordinate over real samples.
mean_gen_b2 = np.mean(gen_b2, axis=0) # Average each feature coordinate over generated samples.
print("real mean:", np.round(mean_real_b2, 3), "generated mean:", np.round(mean_gen_b2, 3)) # Inspect centers before computing distance.
```
▶ What you'll see: the two means are close because generated samples cover the same two regions.

```python
mean_gap_b2 = float(np.sum((mean_real_b2 - mean_gen_b2) ** 2)) # Compute the squared center mismatch.
print("squared mean gap:", round(mean_gap_b2, 3)) # Inspect the first FID ingredient.
assert round(mean_gap_b2, 3) == 0.003 # Verify the hand-checkable mean-distance value.
plt.figure(figsize=(4, 3)); plt.bar(["feature 0", "feature 1"], mean_gen_b2 - mean_real_b2, color="orange") # Plot coordinate-wise mean shift.
plt.axhline(0, color="black", linewidth=0.8); plt.title("B2: generated mean minus real mean"); plt.show() # Display the shift bars.
```
▶ What you'll see: small bars show the generated cloud's center shift from the real cloud.

👀 Takeaway: FID begins by asking whether generated features are centered like real features.

### Basic 3 — Compute a covariance matrix

**Goal.** Measure feature spread, because FID must notice mode collapse even when means look reasonable. We build it in 2 steps.

```python
C_real_b3 = np.cov(real_b3, rowvar=False, bias=True) # Estimate real covariance over feature coordinates.
C_collapsed_b3 = np.cov(collapsed_b3, rowvar=False, bias=True) # Estimate collapsed covariance.

```

```python
plt.figure(figsize=(4, 3)); plt.bar(["real var0", "collapsed var0"], [C_real_b3[0, 0], C_collapsed_b3[0, 0]], color=["black", "crimson"]) # Compare the most important variance.

```
▶ What you'll see: missing a mode sharply shrinks the generated feature variance.

👀 Takeaway: covariance is the FID ingredient that makes diversity errors visible.

### Basic 4 — Compute the diagonal FID formula

**Goal.** Evaluate a diagonal-covariance FID by hand, because this reveals the meaning of the Fréchet covariance term. We build it in 3 steps.

```python
mr_b4 = np.array([0.0, 0.0]) # Set the real Gaussian mean.
mg_b4 = np.array([1.0, 0.5]) # Set the generated Gaussian mean.
vr_b4 = np.array([1.0, 0.25]) # Set real variances for two features.
vg_b4 = np.array([0.64, 0.5105]) # Set generated variances for two features.
print("means:", mr_b4, mg_b4, "variances:", vr_b4, vg_b4) # Inspect all FID ingredients.
```
▶ What you'll see: two means and two diagonal variance vectors.

```python
mean_part_b4 = float(np.sum((mr_b4 - mg_b4) ** 2)) # Compute ||m_r - m_g||^2.
cov_part_b4 = float(np.sum((np.sqrt(vr_b4) - np.sqrt(vg_b4)) ** 2)) # Compute diagonal covariance mismatch.
fid_b4 = mean_part_b4 + cov_part_b4 # Add the two FID parts.

```

```python
plt.figure(figsize=(4, 3)); plt.bar(["mean", "cov", "total"], [mean_part_b4, cov_part_b4, fid_b4], color=["teal", "orange", "purple"]) # Plot the FID decomposition.
plt.title("B4: diagonal FID pieces"); plt.ylabel("distance"); plt.show() # Display the FID components.
```
▶ What you'll see: the FID total is the sum of a center penalty and a spread penalty.

### Basic 5 — Use the general Fréchet helper

**Goal.** Compute FID from means and covariance matrices, because real feature covariances are not always diagonal. We build it in 2 steps.

```python
real_b5 = np.array([[-1.0, 0.0], [-0.8, 0.3], [0.9, -0.2], [1.1, 0.2]]) # Define real features.
gen_b5 = np.array([[-0.9, 0.1], [-0.7, 0.2], [0.8, -0.1], [1.0, 0.3]]) # Define generated features.
mr_b5, Cr_b5 = mean_cov(real_b5) # Compute real Gaussian summary.
mg_b5, Cg_b5 = mean_cov(gen_b5) # Compute generated Gaussian summary.
print("mean summaries:", np.round(mr_b5, 3), np.round(mg_b5, 3)) # Inspect the summaries before distance.
```
▶ What you'll see: the summary compresses every batch into one mean and one covariance.

```python
fid_b5 = frechet_distance(mr_b5, Cr_b5, mg_b5, Cg_b5) # Compute general FID-style distance.
print("FID:", round(fid_b5, 4)) # Inspect the distance.
assert fid_b5 < 0.1 # Verify the near-real generator gets a small FID.
plt.figure(figsize=(4, 3)); plt.bar(["near-real FID"], [fid_b5], color="seagreen") # Visualize the small distance.
plt.ylim(0, 0.1); plt.title("B5: low FID for close feature clouds"); plt.show() # Display the score.
```
▶ What you'll see: a small FID because generated features cover the same modes with similar spread.

👀 Takeaway: the FID helper wraps the Gaussian mean and covariance comparison into one lower-is-better score.

### Basic 6 — Compare good and collapsed generators with FID

**Goal.** Show that FID penalizes mode collapse, because the collapsed generator's covariance no longer matches real features. We build it in 3 steps.
