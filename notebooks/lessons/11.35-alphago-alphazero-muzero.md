### 1. Returns and Bellman backups: reward is not the same as consequence

Alpha-style systems search because an action's useful evidence can arrive later. The return is the discounted ledger $G_t=r_t+\gamma r_{t+1}+\gamma^2r_{t+2}+\cdots$. A Bellman backup replaces a long unknown tail with the current value estimate: $y=r+\gamma V(s')$.

```python
rewards_w = np.array([1.0, 0.0, 2.0])  # immediate, next, and delayed reward.
gamma_w = 0.9  # discount future rewards but do not erase them.
powers_w = gamma_w ** np.arange(len(rewards_w))  # [1, gamma, gamma^2].
return_w = float(np.sum(powers_w * rewards_w))  # discounted return.
print("discount weights:", np.round(powers_w, 3))
print("discounted return:", round(return_w, 3))
assert round(return_w, 3) == 2.62
```
▶ What you'll see: the delayed reward still matters, but the reward two steps away counts as 1.62 instead of 2.0.

```python
r_w = 1.0  # observed one-step reward.
next_value_w = 0.8  # current value estimate for the next state.
q_old_w = 0.4  # current action-value estimate.
alpha_w = 0.5  # partial update rate.
target_w = r_w + gamma_w * next_value_w  # one-step bootstrap target.
q_new_w = q_old_w + alpha_w * (target_w - q_old_w)  # move halfway to target.
print("bootstrap target:", round(target_w, 3))
print("updated Q:", round(q_new_w, 3))
assert round(target_w, 3) == 1.72 and round(q_new_w, 3) == 1.06
```
▶ What you'll see: the estimate moves from 0.4 toward 1.72 without letting one sample overwrite all prior evidence.

```python
plt.figure(figsize=(4.4, 3))
plt.bar(["old Q", "target", "new Q"], [q_old_w, target_w, q_new_w], color=["gray", "black", "teal"])
plt.title("1: Bellman target and partial update")
plt.ylabel("value")
plt.show()
```
▶ What you'll see: the new estimate lands between the old estimate and the one-step target.

*Why it's done this way:* Discounting makes delayed outcomes comparable to immediate ones, and bootstrapping controls variance by using $V(s')$ instead of waiting for every rollout to finish. The price is bias: if $V$ is wrong, the target is wrong too, so Alpha-style systems use search and repeated updates to improve the target itself.

### 2. Policy and value estimates: learned priors before search

A policy says which actions look promising; a value says how good the state looks after consequence is considered. AlphaGo used learned policy/value networks to guide Go search, and AlphaZero learned them from self-play. We use tiny NumPy tables instead of deep networks so the shapes are visible.

```python
logits_w = np.array([1.0, 0.0, -1.0])  # unnormalized preferences for three legal moves.
exp_w = np.exp(logits_w - np.max(logits_w))  # stable softmax numerator.
policy_w = exp_w / np.sum(exp_w)  # probabilities sum to 1.
values_after_moves_w = np.array([0.7, 0.2, -0.4])  # value estimates if each move is chosen.
expected_value_w = float(policy_w @ values_after_moves_w)  # policy-weighted consequence.
print("policy:", np.round(policy_w, 3), "sum:", round(float(policy_w.sum()), 3))
print("policy-weighted value:", round(expected_value_w, 3))
assert np.allclose(np.round(policy_w, 3), [0.665, 0.245, 0.09])
```
▶ What you'll see: the largest logit gets most probability, but weaker moves still keep nonzero support.

```python
plt.figure(figsize=(4.6, 3))
plt.bar(["move 0", "move 1", "move 2"], policy_w, color="slateblue")
plt.title("2: policy prior from logits")
plt.ylabel("probability")
plt.show()
```
▶ What you'll see: a probability distribution, not a single hard choice, so search can still explore alternatives.

*Why it's done this way:* Softmax turns arbitrary scores into comparable action probabilities. Search uses these probabilities as priors: a high-prior move gets inspected earlier, but a low-prior move is not mathematically impossible. The value estimate supplies a cheap approximation to many future rewards when full rollouts are too expensive.

### 3. MCTS with UCT: optimism balances exploitation and exploration

Monte Carlo Tree Search repeatedly chooses a path, expands it, evaluates the leaf, and backs the value up. The UCT/PUCT idea is to score an edge by observed quality plus an uncertainty bonus. A move with few visits can win temporarily because information has value.

```python
Q_w = np.array([0.55, 0.45, 0.10])  # current mean values for three actions.
N_w = np.array([5, 2, 0])  # visit counts.
total_w = int(np.sum(N_w))  # parent visits.
c_w = 1.0  # exploration strength.
uct_w = Q_w + c_w * np.sqrt(2 * np.log(total_w + 1) / np.maximum(N_w, 1))  # UCT-style index.
uct_w[N_w == 0] = np.inf  # always try an unvisited legal action at least once.
print("Q:", Q_w, "N:", N_w)
print("UCT scores:", np.round(uct_w, 3))
print("selected action:", int(np.argmax(uct_w)))
assert int(np.argmax(uct_w)) == 2
```
▶ What you'll see: the unvisited move wins even with a low current value because its uncertainty is maximal.

```python
def backup_path_w(q_values_w, counts_w, action_w, leaf_value_w):
    counts_w[action_w] += 1  # one more simulation used this action.
    q_values_w[action_w] += (leaf_value_w - q_values_w[action_w]) / counts_w[action_w]  # running mean backup.
    return q_values_w, counts_w

Q2_w, N2_w = backup_path_w(Q_w.copy(), N_w.copy(), 2, 0.8)  # optimistic leaf result for action 2.
print("after backup Q:", np.round(Q2_w, 3), "N:", N2_w)
assert round(float(Q2_w[2]), 3) == 0.8 and int(N2_w[2]) == 1
```
▶ What you'll see: the backed-up action gets one visit and its mean value becomes the leaf evaluation.

```python
plt.figure(figsize=(5, 3))
plt.bar(np.arange(3) - 0.18, Q2_w, width=0.36, label="Q", color="teal")
plt.bar(np.arange(3) + 0.18, N2_w / np.max(N2_w), width=0.36, label="scaled visits", color="orange")
plt.xticks(range(3), ["a0", "a1", "a2"])
plt.title("3: search statistics after one backup")
plt.legend()
plt.show()
```
▶ What you'll see: action 2 now has both a value estimate and a visit count, so future decisions can trade it against older evidence.

*Why it's done this way:* The exploitation term $Q$ chooses moves that already look good; the exploration term shrinks like $1/\sqrt{N}$ so uncertainty fades as evidence accumulates. The backup is an incremental mean because each simulation is another sample of that edge's consequence.

### 4. AlphaZero-style self-play: search becomes the training target

AlphaZero does not need human moves. It uses search to produce a stronger policy target, then trains the policy/value estimates to imitate the search result and game outcome. We use a tiny take-away game: from pile size $s$, choose 1 or 2 stones; taking the last stone wins.

```python
def legal_take_w(s_w):
    return np.array([a_w for a_w in [1, 2] if a_w <= s_w], dtype=int)

def true_value_take_w(s_w):
    return 1.0 if s_w % 3 != 0 else -1.0  # winning except multiples of 3 under perfect play.

pile_w = 5
legal_w = legal_take_w(pile_w)
priors_w = np.array([0.45, 0.55])  # imperfect learned policy prior over take 1/take 2.
print("legal actions:", legal_w)
print("perfect-play value at pile 5:", true_value_take_w(pile_w))
assert true_value_take_w(5) == 1.0
```
▶ What you'll see: both actions are legal, and pile 5 is winning with correct play.

```python
visits_w = np.zeros(len(legal_w), dtype=int)
q_take_w = np.zeros(len(legal_w), dtype=float)
for sim_w in range(30):
    score_w = q_take_w + 1.5 * priors_w * np.sqrt(np.sum(visits_w) + 1) / (1 + visits_w)  # PUCT.
    idx_w = int(np.argmax(score_w))
    next_s_w = pile_w - legal_w[idx_w]
    leaf_w = -true_value_take_w(next_s_w)  # opponent's value becomes current player's value by negation.
    visits_w[idx_w] += 1
    q_take_w[idx_w] += (leaf_w - q_take_w[idx_w]) / visits_w[idx_w]
search_policy_w = visits_w / np.sum(visits_w)
print("visit counts:", visits_w)
print("search policy target:", np.round(search_policy_w, 3))
print("Q estimates:", np.round(q_take_w, 3))
assert int(np.argmax(search_policy_w)) == 2 - 1
```
▶ What you'll see: search concentrates visits on taking 2 stones, the move that leaves a losing multiple of 3.

```python
plt.figure(figsize=(4.8, 3))
plt.bar(["take 1", "take 2"], search_policy_w, color="seagreen")
plt.title("4: MCTS visits become the policy label")
plt.ylabel("visit fraction")
plt.show()
```
▶ What you'll see: the training label is sharper than the original prior because search checked consequences.

*Why it's done this way:* Self-play creates its own supervised targets: the improved policy is the normalized visit distribution, and the value target is the eventual outcome. The negation in the leaf value appears because two-player zero-sum games flip perspective after every move.

### 5. AlphaGo versus AlphaZero: human imitation is optional, not the core trick

AlphaGo used expert games to initialize a policy, then reinforced and searched with value guidance. AlphaZero removed the human-data phase and let self-play plus MCTS produce both targets. The shared core is policy improvement: make the next policy closer to search than to the weaker prior.

```python
expert_policy_w = np.array([0.70, 0.20, 0.10])  # imitation target from humans.
selfplay_policy_w = np.array([0.10, 0.15, 0.75])  # MCTS target from self-play.
current_policy_w = np.array([0.34, 0.33, 0.33])  # model before the update.
blend_w = 0.4  # one small training step toward the chosen target.
updated_from_expert_w = (1 - blend_w) * current_policy_w + blend_w * expert_policy_w
updated_from_selfplay_w = (1 - blend_w) * current_policy_w + blend_w * selfplay_policy_w
print("expert update:", np.round(updated_from_expert_w, 3))
print("self-play update:", np.round(updated_from_selfplay_w, 3))
assert np.allclose(np.round(updated_from_selfplay_w, 3), [0.244, 0.258, 0.498])
```
▶ What you'll see: the same update rule can move toward human labels or toward MCTS labels.

```python
x_w = np.arange(3)
plt.figure(figsize=(5, 3))
plt.bar(x_w - 0.25, current_policy_w, width=0.25, label="current", color="gray")
plt.bar(x_w, expert_policy_w, width=0.25, label="expert", color="steelblue")
plt.bar(x_w + 0.25, selfplay_policy_w, width=0.25, label="self-play search", color="darkorange")
plt.xticks(x_w, ["a0", "a1", "a2"])
plt.title("5: two possible policy targets")
plt.legend()
plt.show()
```
▶ What you'll see: AlphaGo's expert target and AlphaZero's search target can point to different moves.

*Why it's done this way:* Imitation is a data source, not the essential algorithmic idea. The essential idea is policy iteration: evaluate consequences with search, then train the policy/value function so tomorrow's search starts from a better prior and a better leaf estimate.

### 6. MuZero: learn the model needed for planning, not the full environment

MuZero searches without a hand-coded transition model. It learns a compact dynamics function that predicts the next hidden state, reward, policy, and value. The model only has to be useful for planning; it does not need to reconstruct every pixel or hidden environment detail.

```python
states_w = np.array([0, 1, 2, 3])  # four tiny hidden states.
actions_w = np.array([0, 1])  # two actions.
next_state_table_w = np.array([[1, 2], [2, 3], [3, 0], [0, 1]])  # learned dynamics g(s,a)->s'.
reward_table_w = np.array([[0.0, 0.2], [0.1, 1.0], [0.0, -0.2], [1.0, 0.0]])  # learned reward head.
value_head_w = np.array([0.3, 0.5, -0.1, 0.8])  # learned value head for hidden states.
print("next state from s=1:", next_state_table_w[1])
print("rewards from s=1:", reward_table_w[1])
assert int(next_state_table_w[1, 1]) == 3 and round(float(reward_table_w[1, 1]), 1) == 1.0
```
▶ What you'll see: the learned model predicts what state and reward each action leads to.

```python
root_w = 1
one_step_scores_w = []
for a_w in actions_w:
    ns_w = next_state_table_w[root_w, a_w]
    score_w = reward_table_w[root_w, a_w] + gamma_w * value_head_w[ns_w]
    one_step_scores_w.append(score_w)
one_step_scores_w = np.array(one_step_scores_w)
print("model-based one-step scores:", np.round(one_step_scores_w, 3))
print("chosen action:", int(np.argmax(one_step_scores_w)))
assert np.allclose(np.round(one_step_scores_w, 3), [0.01, 1.72])
```
▶ What you'll see: action 1 wins because its immediate reward plus next hidden-state value is much larger.

```python
plt.figure(figsize=(4.6, 3))
plt.bar(["a0", "a1"], one_step_scores_w, color="purple")
plt.title("6: MuZero-style reward + value planning")
plt.ylabel("r + γV(hidden next)")
plt.show()
```
▶ What you'll see: the learned dynamics table lets us plan with imagined transitions before touching the real environment.

*Why it's done this way:* MuZero separates representation, dynamics, and prediction so search can roll forward in latent space. The Bellman-style score $r+\gamma V(h')$ is enough for planning even if the hidden state is not human-interpretable, because the search only needs rewards, values, and legal policy guidance.

## 🛠️ Setup

```python
import numpy as np  # load NumPy for arrays, small tables, and hand-built MCTS.
import matplotlib.pyplot as plt  # load Matplotlib for heatmaps, bars, lines, and search diagnostics.
np.random.seed(0)  # make every stochastic demonstration reproducible.

def softmax(x):  # convert logits into a probability distribution.
    x = np.asarray(x, dtype=float)  # ensure predictable numerical operations.
    e = np.exp(x - np.max(x))  # subtract max for stable exponentials.
    return e / np.sum(e)  # normalize positive scores to sum to one.

def ttt_winner(board):  # return 1 for X win, -1 for O win, 0 for draw/unfinished.
    b = np.asarray(board, dtype=int).reshape(3, 3)  # view the flat board as a 3x3 grid.
    lines = list(b) + list(b.T) + [np.diag(b), np.diag(np.fliplr(b))]  # rows, columns, diagonals.
    sums = np.array([np.sum(line) for line in lines])  # line sums identify three-in-a-row.
    if np.any(sums == 3):
        return 1
    if np.any(sums == -3):
        return -1
    return 0

def ttt_legal(board):  # list empty tic-tac-toe cells.
    return np.where(np.asarray(board) == 0)[0]  # legal actions are zero-valued cells.

def ttt_step(board, action, player):  # apply one move and report the next board and terminal reward.
    nxt = np.asarray(board, dtype=int).copy()  # copy so the caller's board is unchanged.
    nxt[action] = player  # place the current player's mark.
    winner = ttt_winner(nxt)  # check whether the move ended the game.
    done = winner != 0 or len(ttt_legal(nxt)) == 0  # terminal if win or filled board.
    reward = 1.0 if winner == player else (-1.0 if winner == -player else 0.0)  # reward from mover's view.
    return nxt, reward, done  # return transition pieces.

def toy_policy_value(board, player):  # tiny hand-built policy/value stand-in for a neural net.
    legal = ttt_legal(board)  # inspect legal cells.
    scores = np.zeros(9, dtype=float) - 5.0  # illegal cells get tiny prior after softmax masking.
    center_bonus = np.array([0.2, 0.4, 0.2, 0.4, 1.0, 0.4, 0.2, 0.4, 0.2])  # prefer center and edges slightly.
    scores[legal] = center_bonus[legal]  # assign heuristic logits to legal cells.
    for a in legal:  # make immediate wins and blocks very attractive.
        nb, _, _ = ttt_step(board, a, player)
        if ttt_winner(nb) == player:
            scores[a] = 3.0
        nb2, _, _ = ttt_step(board, a, -player)
        if ttt_winner(nb2) == -player:
            scores[a] = max(scores[a], 2.5)
    probs = np.zeros(9, dtype=float)  # full action vector for convenience.
    probs[legal] = softmax(scores[legal])  # normalize only legal moves.
    value = 0.15 * np.sum(np.asarray(board) * player)  # crude material-style value from current player's view.
    return probs, float(np.clip(value, -1, 1))  # return policy prior and bounded value.

def puct_scores(Q, N, P, c=1.5):  # compute AlphaZero-style search scores.
    return Q + c * P * np.sqrt(np.sum(N) + 1) / (1 + N)  # quality plus prior-weighted exploration.

def discounted_return(rewards, gamma):  # compute G from a finite reward list.
    rewards = np.asarray(rewards, dtype=float)  # ensure vector math.
    return float(np.sum((gamma ** np.arange(len(rewards))) * rewards))  # sum gamma^t r_t.
```
▶ What you'll see: the printed or plotted output exposes the intermediate calculation for this step.

## 🟢 Basics (warm-up)

### Basic 1 — Discount a delayed reward

**Goal.** Compute a finite return, because Alpha-style value targets must compare immediate and delayed rewards. We build it in 2 steps.

```python
rewards_b1 = np.array([1.0, 0.0, 2.0])  # define a three-step reward stream.
gamma_b1 = 0.9  # choose the same discount used in the walkthrough.
weights_b1 = gamma_b1 ** np.arange(len(rewards_b1))  # compute [1, gamma, gamma^2].
print("weights:", np.round(weights_b1, 3))  # inspect the discount multipliers.
```
▶ What you'll see: later rewards receive smaller weights.

```python
G_b1 = discounted_return(rewards_b1, gamma_b1)  # compute the discounted consequence.
print("return:", round(G_b1, 3))  # inspect the final return.
assert round(G_b1, 3) == 2.62  # verify 1 + 0.9*0 + 0.9^2*2.
plt.figure(figsize=(4, 3))

plt.title("Basic 1: discounted reward contributions")

```
▶ What you'll see: the third reward contributes 1.62 after discounting.

👀 Takeaway: value learning optimizes discounted consequence, not only immediate reward.

### Basic 6 — Back up one leaf value

**Goal.** Update an edge's running mean after one simulation, because MCTS stores average outcomes on visited actions. We build it in 2 steps.

```python
Q_b6 = np.array([0.2, 0.0])  # current action means.
N_b6 = np.array([4, 0])  # current visit counts.
action_b6 = 0  # choose the edge that was traversed.
leaf_value_b6 = 0.8  # value returned by rollout or value network.
print("before Q,N:", Q_b6, N_b6)  # inspect statistics before backup.
```
▶ What you'll see: action 0 already has four samples.

```python
N_b6[action_b6] += 1  # add one visit.
Q_b6[action_b6] += (leaf_value_b6 - Q_b6[action_b6]) / N_b6[action_b6]  # incremental mean update.
print("after Q,N:", np.round(Q_b6, 3), N_b6)  # inspect statistics after backup.
assert round(float(Q_b6[0]), 3) == 0.32 and int(N_b6[0]) == 5  # verify the running mean.
plt.figure(figsize=(4, 3))
```
