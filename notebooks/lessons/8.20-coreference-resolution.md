# 8.20 — Coreference Resolution

Coreference resolution is the memory problem of NLP: after a text has candidate mentions like `Alice`, `she`, and `the company`, the model must decide which spans name the same real-world entity. In this lesson, we build the coreference pipeline from scratch with small NumPy arrays: mention-pair features, antecedent probabilities, agreement masks, transitive clustering, and entity-level evaluation.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build coreference resolution one idea at a time. Run each cell in order and inspect the printed values — the point is to make every link score, mask, cluster merge, and metric visible. This walkthrough is self-contained and uses a `_w` suffix on its variables so it never clashes with the examples below.

### 1. Mentions are the units we compare

Coreference does not start from raw characters; it starts from **mentions**: spans that might refer to entities. A mention can be a name (`Alice`), a pronoun (`she`), or a description (`the engineer`). To keep the math small, we encode each mention with interpretable features: type, gender, number, sentence position, and whether it is a pronoun. Those features are the raw material for deciding whether an earlier mention can be an antecedent of a later one.

```python
mentions_w = ["Alice", "she", "Bob", "he", "the company", "it"]  # candidate mentions in document order.
types_w = np.array([0, 1, 0, 1, 2, 1])  # 0=name, 1=pronoun, 2=description.
gender_w = np.array([1, 1, 2, 2, 0, 0])  # 0=neutral/unknown, 1=feminine, 2=masculine.
number_w = np.array([1, 1, 1, 1, 1, 1])  # 1=singular in this toy document.
sent_w = np.array([0, 1, 1, 2, 2, 3])  # sentence index for distance and recency.
print("mentions:", list(enumerate(mentions_w)))  # inspect the mention indices used later.
print("sentence positions:", sent_w)  # inspect discourse order.
```
▶ What you'll see: six mentions with stable integer indices, so every later pair like `(0,1)` has a clear meaning.

```python
feature_table_w = np.vstack([types_w, gender_w, number_w, sent_w]).T  # one row of features per mention.
print("feature rows [type, gender, number, sentence]:\n", feature_table_w)  # inspect the compact mention representation.
plt.figure(figsize=(5, 3))  # create a compact feature heatmap.
plt.imshow(feature_table_w, cmap="viridis", aspect="auto")  # visualize mention attributes as columns.
plt.colorbar(label="encoded value")  # add a numeric legend.
plt.yticks(range(len(mentions_w)), mentions_w)  # label rows by mention text.
plt.xticks(range(4), ["type", "gender", "number", "sent"])  # label feature columns.
plt.title("1: mention feature table")  # title the plot.
plt.show()  # display the heatmap.
```
▶ What you'll see: pronouns and names differ by type, while compatible mentions share gender and number codes.

*Why it's done this way: coreference is a structured prediction problem over mentions, not tokens. Once every mention has a row of features, a pairwise model can ask focused questions like “does this pronoun agree with that earlier name?” without re-parsing the whole sentence each time.*

### 2. Mention-pair scoring turns evidence into a link score

A mention-pair resolver scores an earlier mention `i` as a possible antecedent for a later mention `j`. We build a tiny feature vector $\phi(m_i,m_j)$ with four parts: same gender, same number, exact string match, and negative sentence distance. A linear score $s(i,j)=w^\top\phi(m_i,m_j)$ then says how plausible the link is.

```python
def pair_features_w(i_w, j_w):  # build interpretable features for an antecedent-candidate pair.
    same_gender_w = 1.0 if gender_w[i_w] == gender_w[j_w] and gender_w[i_w] != 0 else 0.0  # known gender agreement.
    same_number_w = 1.0 if number_w[i_w] == number_w[j_w] else 0.0  # singular/plural agreement.
    exact_w = 1.0 if mentions_w[i_w].lower() == mentions_w[j_w].lower() else 0.0  # surface reuse.
    distance_w = float(sent_w[j_w] - sent_w[i_w])  # discourse distance in sentences.
    return np.array([same_gender_w, same_number_w, exact_w, -distance_w])  # negative distance rewards recency.
weights_w = np.array([2.0, 1.0, 1.5, 0.3])  # hand-built linear weights for the toy resolver.
print("features Alice→she:", pair_features_w(0, 1))  # inspect a plausible pronoun link.
print("features Bob→she:", pair_features_w(2, 1))  # inspect an impossible backward/nonmatching link example.
```
▶ What you'll see: Alice→she receives gender and number evidence, while the Bob/she comparison lacks gender agreement.

```python
score_alice_she_w = float(weights_w @ pair_features_w(0, 1))  # score Alice as antecedent for she.
score_bob_he_w = float(weights_w @ pair_features_w(2, 3))  # score Bob as antecedent for he.
score_company_it_w = float(weights_w @ pair_features_w(4, 5))  # score company as antecedent for it.
print("scores:", round(score_alice_she_w, 3), round(score_bob_he_w, 3), round(score_company_it_w, 3))  # inspect three plausible links.
assert round(score_alice_she_w, 3) == 2.7  # 2 gender + 1 number - 0.3 distance.
```
▶ What you'll see: plausible pronoun links get positive scores because agreement outweighs recency cost.

```python
all_pairs_w = [(0, 1), (2, 3), (4, 5), (0, 3)]  # compare three good links and one gender-mismatched link.
pair_scores_w = np.array([weights_w @ pair_features_w(i_w, j_w) for i_w, j_w in all_pairs_w])  # score each pair.
plt.figure(figsize=(5, 3))  # create a compact score plot.
plt.bar([f"{mentions_w[i]}→{mentions_w[j]}" for i, j in all_pairs_w], pair_scores_w, color="steelblue")  # visualize pair scores.
plt.xticks(rotation=20)  # keep labels readable.
plt.title("2: mention-pair scores")  # title the plot.
plt.ylabel("w·φ score")  # label the score scale.
plt.show()  # display the bar chart.
```
▶ What you'll see: mismatched Alice→he is lower than the agreement-respecting links.

*Why it's done this way: a linear score is the simplest transparent version of a learned resolver. Each feature contributes an additive reason for or against a link, so the final score can be audited before it is normalized into probabilities.*

### 3. Antecedent probabilities normalize competing earlier mentions

For a later mention $j$, only earlier mentions $i<j$ can be antecedents. We compute scores for those candidates and apply a softmax: $p(i\mid j)=\exp(s(i,j))/\sum_{k<j}\exp(s(k,j))$. This makes candidates compete; a good score matters because it is high **relative to the other possible antecedents for the same mention**.

```python
def softmax_w(x_w):  # stable softmax for one candidate list.
    z_w = x_w - np.max(x_w)  # subtract max to avoid overflow while preserving probabilities.
    e_w = np.exp(z_w)  # exponentiate shifted scores.
    return e_w / np.sum(e_w)  # normalize to probabilities that sum to one.

j_w = 3  # resolve the pronoun "he".
candidates_w = np.arange(j_w)  # only previous mentions can be antecedents.
scores_for_he_w = np.array([weights_w @ pair_features_w(i_w, j_w) for i_w in candidates_w])  # score each antecedent.
print("candidates for he:", [mentions_w[i] for i in candidates_w])  # inspect candidate names.
print("scores:", np.round(scores_for_he_w, 3))  # inspect unnormalized evidence.
```
▶ What you'll see: Bob should score highest for `he`, but Alice and `she` still appear as competing earlier mentions.

```python
probs_for_he_w = softmax_w(scores_for_he_w)  # convert scores into a distribution over antecedents.
print("antecedent probabilities:", np.round(probs_for_he_w, 3))  # inspect normalized competition.
print("probability sum:", round(float(np.sum(probs_for_he_w)), 3))  # verify valid probabilities.
assert round(float(np.sum(probs_for_he_w)), 3) == 1.0  # softmax must sum to one.
```
▶ What you'll see: Bob receives the largest probability, and all probabilities sum to 1.

```python
plt.figure(figsize=(5, 3))  # create a compact distribution plot.
plt.bar([mentions_w[i] for i in candidates_w], probs_for_he_w, color="darkorange")  # visualize antecedent probabilities.
plt.title("3: p(antecedent | he)")  # title the plot.
plt.ylabel("probability")  # label the probability scale.
plt.ylim(0, 1)  # keep a probability range.
plt.show()  # display the bar chart.
```
▶ What you'll see: the distribution is peaked on Bob rather than spread evenly over all earlier mentions.

*Why it's done this way: softmax does not decide whether a link is globally good; it decides which candidate is best for this mention. That local competition is why a resolver can choose one antecedent even when several candidates have positive evidence.*

### 4. Agreement masks block impossible links before normalization

A high score can still be illegal. If a pronoun is singular masculine, a singular feminine name should not survive merely because it is close. We use a binary mask $M_{ij}$ that is 1 for allowed pairs and 0 for forbidden pairs, then multiply the exponentiated scores by the mask before normalizing.

```python
def allowed_w(i_w, j_w):  # symbolic agreement mask for the toy resolver.
    if number_w[i_w] != number_w[j_w]:  # number disagreement blocks the link.
        return 0
    if gender_w[i_w] != 0 and gender_w[j_w] != 0 and gender_w[i_w] != gender_w[j_w]:  # known gender mismatch blocks the link.
        return 0
    return 1  # otherwise keep the candidate.
mask_for_he_w = np.array([allowed_w(i_w, j_w) for i_w in candidates_w])  # compute candidate mask for he.
print("mask for he:", mask_for_he_w)  # inspect allowed and blocked candidates.
assert mask_for_he_w.tolist() == [0, 0, 1]  # only Bob is compatible with he.
```
▶ What you'll see: Alice and she are masked out for `he`, leaving Bob.

```python
def masked_softmax_w(scores_w, mask_w):  # softmax with zero probability for forbidden candidates.
    exp_w = np.exp(scores_w - np.max(scores_w)) * mask_w  # exponentiate then zero blocked pairs.
    if np.sum(exp_w) == 0:  # guard against all candidates being blocked.
        return np.zeros_like(scores_w, dtype=float)  # return no-link probabilities.
    return exp_w / np.sum(exp_w)  # normalize only allowed candidates.
masked_probs_he_w = masked_softmax_w(scores_for_he_w, mask_for_he_w)  # apply agreement before normalization.
print("masked probabilities:", np.round(masked_probs_he_w, 3))  # inspect final distribution.
assert np.allclose(masked_probs_he_w, np.array([0.0, 0.0, 1.0]))  # Bob is the only legal antecedent.
```
▶ What you'll see: forbidden candidates receive exactly zero probability, not just a small probability.

```python
plt.figure(figsize=(5, 3))  # create a before/after mask plot.
plt.bar(np.arange(3) - 0.18, probs_for_he_w, width=0.35, label="unmasked")  # show original softmax.
plt.bar(np.arange(3) + 0.18, masked_probs_he_w, width=0.35, label="masked")  # show masked softmax.
plt.xticks(range(3), [mentions_w[i] for i in candidates_w])  # label candidates.
plt.title("4: agreement mask changes normalization")  # title the plot.
plt.ylabel("probability")  # label the probability scale.
plt.legend()  # show legend.
plt.show()  # display the comparison.
```
▶ What you'll see: probability mass that used to leak to incompatible mentions is reassigned to the legal antecedent.

*Why it's done this way: constraints are most effective before clustering. If an impossible pair is allowed to become a link, transitivity can merge entire entity chains, and the later mask cannot cleanly undo the damage.*

### 5. Links induce clusters by transitivity

Coreference output is not a list of isolated pair decisions; it is a partition of mentions into entity clusters. If `Alice` links to `she`, and another later mention links to `she`, all three belong to one chain. We implement the smallest possible union-find to make transitivity explicit.

```python
def clusters_from_links_w(n_w, links_w):  # build clusters from undirected coreference links.
    parent_w = list(range(n_w))  # each mention starts as its own parent.
    def find_w(x_w):  # find the representative of a mention.
        while parent_w[x_w] != x_w:  # follow parent pointers until the root.
            parent_w[x_w] = parent_w[parent_w[x_w]]  # path compression.
            x_w = parent_w[x_w]  # move upward.
        return x_w  # return root.
    for a_w, b_w in links_w:  # merge every predicted coreference pair.
        ra_w, rb_w = find_w(a_w), find_w(b_w)  # find both roots.
        if ra_w != rb_w:  # only merge different components.
            parent_w[rb_w] = ra_w  # attach one component to the other.
    groups_w = defaultdict(list)  # collect mentions by representative.
    for idx_w in range(n_w):  # assign every mention to a component.
        groups_w[find_w(idx_w)].append(idx_w)  # append mention index.
    return list(groups_w.values())  # return list of clusters.

links_w = [(0, 1), (2, 3), (4, 5)]  # Alice-she, Bob-he, company-it.
clusters_w = clusters_from_links_w(len(mentions_w), links_w)  # induce clusters from links.
print("clusters:", [[mentions_w[i] for i in c] for c in clusters_w])  # inspect entity chains.
```
▶ What you'll see: six mentions collapse into three two-mention entity clusters.

```python
cluster_ids_w = np.empty(len(mentions_w), dtype=int)  # prepare one cluster id per mention.
for cid_w, cluster_w in enumerate(clusters_w):  # loop through induced clusters.
    cluster_ids_w[cluster_w] = cid_w  # assign ids to all mentions in the cluster.
print("cluster ids:", cluster_ids_w)  # inspect partition as a vector.
assert cluster_ids_w.tolist() == [0, 0, 1, 1, 2, 2]  # verify the canonical chain ids.
```
▶ What you'll see: linked mentions share the same id, and different entities have different ids.

```python
same_entity_w = cluster_ids_w[:, None] == cluster_ids_w[None, :]  # pairwise same-cluster matrix.
plt.figure(figsize=(4, 3))  # create a cluster matrix plot.
plt.imshow(same_entity_w.astype(int), cmap="Greens", aspect="auto")  # visualize entity equivalence.
plt.xticks(range(len(mentions_w)), mentions_w, rotation=45)  # label columns.
plt.yticks(range(len(mentions_w)), mentions_w)  # label rows.
plt.title("5: transitive entity clusters")  # title the plot.
plt.show()  # display the matrix.
```
▶ What you'll see: block-diagonal squares show each entity chain after transitive closure.

*Why it's done this way: downstream systems need entities, not pair scores. QA wants to know that all mentions in a chain are the same answer candidate, so the resolver must convert local links into a global partition.*

### 6. Evaluation: pairwise links and B-CUBED entity quality

Pairwise precision/recall counts overlapping links, but entity applications often care whether each mention's predicted cluster matches its gold cluster. B-CUBED evaluates that mention by mention: precision is “how pure is my predicted cluster?” and recall is “how much of my gold cluster did the prediction recover?” The final score averages over mentions.

```python
gold_ids_w = np.array([0, 0, 1, 1, 2, 2])  # gold clusters: Alice/she, Bob/he, company/it.
pred_ids_w = np.array([0, 0, 0, 0, 2, 2])  # predicted mistake: Alice/she and Bob/he were bridged.
print("gold ids:", gold_ids_w)  # inspect truth.
print("pred ids:", pred_ids_w)  # inspect mistaken clustering.
```
▶ What you'll see: the prediction has one bad bridge that merges two people into a four-mention cluster.

```python
def links_from_ids_w(ids_w):  # enumerate unordered mention pairs inside each cluster.
    pairs_w = set()  # collect unique pairs.
    for cid_w in sorted(set(ids_w)):  # loop through clusters.
        members_w = np.where(ids_w == cid_w)[0]  # find mentions in this cluster.
        for a_pos_w in range(len(members_w)):  # first mention in pair.
            for b_pos_w in range(a_pos_w + 1, len(members_w)):  # second mention after first.
                pairs_w.add((int(members_w[a_pos_w]), int(members_w[b_pos_w])))  # add unordered pair.
    return pairs_w  # return set of coreferent pairs.

gold_links_w = links_from_ids_w(gold_ids_w)  # gold pair links.
pred_links_w = links_from_ids_w(pred_ids_w)  # predicted pair links.
overlap_w = gold_links_w & pred_links_w  # true-positive links.
print("pair precision/recall:", round(len(overlap_w) / len(pred_links_w), 3), round(len(overlap_w) / len(gold_links_w), 3))  # inspect pairwise scores.
assert round(len(overlap_w) / len(pred_links_w), 3) == 0.429  # 3 correct of 7 predicted links.
```
▶ What you'll see: pairwise precision is hurt by the bad bridge and all the extra implied pairs it creates.

```python
def bcubed_w(gold_w, pred_w):  # compute B-CUBED precision, recall, and F1 from cluster-id vectors.
    precisions_w, recalls_w = [], []  # per-mention scores.
    for i_w in range(len(gold_w)):  # evaluate each mention as the anchor.
        pred_cluster_w = set(np.where(pred_w == pred_w[i_w])[0])  # predicted cluster containing mention i.
        gold_cluster_w = set(np.where(gold_w == gold_w[i_w])[0])  # gold cluster containing mention i.
        inter_w = len(pred_cluster_w & gold_cluster_w)  # correct mentions in the predicted chain.
        precisions_w.append(inter_w / len(pred_cluster_w))  # purity of predicted cluster.
        recalls_w.append(inter_w / len(gold_cluster_w))  # coverage of gold cluster.
    p_w = float(np.mean(precisions_w))  # average mention precision.
    r_w = float(np.mean(recalls_w))  # average mention recall.
    f_w = 0.0 if p_w + r_w == 0 else 2 * p_w * r_w / (p_w + r_w)  # harmonic mean.
    return p_w, r_w, f_w  # return metric tuple.

p_b3_w, r_b3_w, f_b3_w = bcubed_w(gold_ids_w, pred_ids_w)  # evaluate mistaken clustering.
print("B-CUBED P/R/F1:", round(p_b3_w, 3), round(r_b3_w, 3), round(f_b3_w, 3))  # inspect entity metric.
assert round(f_b3_w, 3) == 0.8  # B-CUBED reflects high recall but reduced precision.
```
▶ What you'll see: recall stays high because every gold partner is recovered, but precision falls because clusters contain impostors.

```python
plt.figure(figsize=(5, 3))  # create a metric comparison plot.
plt.bar(["pair P", "pair R", "B3 P", "B3 R", "B3 F1"], [0.5, 1.0, p_b3_w, r_b3_w, f_b3_w], color=["gray", "gray", "purple", "purple", "purple"])  # compare scores.
plt.ylim(0, 1.05)  # keep metric scale bounded.
plt.title("6: pairwise vs B-CUBED evaluation")  # title the plot.
plt.show()  # display the metric bars.
```
▶ What you'll see: the same clustering error looks different under link overlap and mention-level entity evaluation.

*Why it's done this way: pairwise metrics are easy to derive from links, but B-CUBED better matches the entity-chain product requirement. It penalizes polluted clusters mention by mention, which is exactly the failure mode caused by a bad bridge.*

## 🛠️ Setup

```python
import numpy as np  # load NumPy for arrays, scoring, masks, and metric calculations.
import matplotlib.pyplot as plt  # load Matplotlib for heatmaps, bars, and diagnostic plots.
from collections import defaultdict, Counter  # load standard-library grouping/counting helpers for clusters.
np.random.seed(0)  # make all examples reproducible.

def softmax(x):  # compute a stable softmax over one score vector.
    x = np.asarray(x, dtype=float)  # convert scores to floats.
    z = x - np.max(x)  # shift by the maximum for numerical stability.
    e = np.exp(z)  # exponentiate shifted scores.
    return e / np.sum(e)  # normalize into probabilities.

def masked_softmax(scores, mask):  # compute softmax while zeroing forbidden candidates.
    scores = np.asarray(scores, dtype=float)  # convert scores to floats.
    mask = np.asarray(mask, dtype=float)  # convert mask to 0/1 floats.
    e = np.exp(scores - np.max(scores)) * mask  # exponentiate and remove forbidden links.
    return np.zeros_like(scores, dtype=float) if np.sum(e) == 0 else e / np.sum(e)  # normalize if any candidate remains.

def pairwise_features(mi, mj):  # build a small mention-pair feature vector from two mention dictionaries.
    gender_ok = 1.0 if mi["gender"] == mj["gender"] and mi["gender"] != "unk" else 0.0  # known gender match.
    number_ok = 1.0 if mi["number"] == mj["number"] else 0.0  # number match.
    exact = 1.0 if mi["text"].lower() == mj["text"].lower() else 0.0  # exact string reuse.
    pronoun_target = 1.0 if mj["kind"] == "pronoun" else 0.0  # target mention is a pronoun.
    distance = float(mj["sent"] - mi["sent"])  # sentence distance.
    return np.array([gender_ok, number_ok, exact, pronoun_target, -distance], dtype=float)  # negative distance rewards nearby antecedents.

def agreement_ok(mi, mj):  # symbolic number/gender/type agreement gate.
    if mi["number"] != mj["number"]:  # block singular/plural mismatch.
        return 0
    if mi["gender"] != "unk" and mj["gender"] != "unk" and mi["gender"] != mj["gender"]:  # block known gender mismatch.
        return 0
    return 1  # allow the pair otherwise.

def clusters_from_links(n, links):  # convert predicted links into transitive clusters.
    parent = list(range(n))  # initialize one component per mention.
    def find(x):  # find root component.
        while parent[x] != x:  # follow parent pointers.
            parent[x] = parent[parent[x]]  # compress path.
            x = parent[x]  # move upward.
        return x  # return root.
    for a, b in links:  # merge linked mentions.
        ra, rb = find(a), find(b)  # find roots.
        if ra != rb:  # if not already together.
            parent[rb] = ra  # merge components.
    groups = defaultdict(list)  # collect mentions by root.
    for i in range(n):  # assign every mention.
        groups[find(i)].append(i)  # append to its root group.
    return list(groups.values())  # return clusters.

def ids_from_clusters(n, clusters):  # convert a list of clusters to one id per mention.
    ids = np.empty(n, dtype=int)  # allocate ids.
    for cid, cluster in enumerate(clusters):  # loop through clusters.
        ids[cluster] = cid  # assign cluster id.
    return ids  # return vector.

def links_from_ids(ids):  # enumerate unordered same-cluster pairs.
    pairs = set()  # collect pairs.
    for cid in sorted(set(ids)):  # loop through cluster ids.
        members = np.where(np.asarray(ids) == cid)[0]  # find cluster members.
        for a in range(len(members)):  # first member position.
            for b in range(a + 1, len(members)):  # second member position.
                pairs.add((int(members[a]), int(members[b])))  # store pair.
    return pairs  # return pair set.

def pairwise_f1(gold_ids, pred_ids):  # compute pairwise precision, recall, and F1.
    gold, pred = links_from_ids(gold_ids), links_from_ids(pred_ids)  # get gold and predicted links.
    hit = len(gold & pred)  # count overlapping links.
    p = 0.0 if len(pred) == 0 else hit / len(pred)  # link precision.
    r = 0.0 if len(gold) == 0 else hit / len(gold)  # link recall.
    f = 0.0 if p + r == 0 else 2 * p * r / (p + r)  # harmonic mean.
    return p, r, f  # return metrics.

def bcubed(gold_ids, pred_ids):  # compute B-CUBED precision, recall, F1.
    gold_ids = np.asarray(gold_ids)  # ensure arrays.
    pred_ids = np.asarray(pred_ids)  # ensure arrays.
    ps, rs = [], []  # per-mention precision and recall.
    for i in range(len(gold_ids)):  # evaluate each mention.
        pred_cluster = set(np.where(pred_ids == pred_ids[i])[0])  # predicted cluster containing mention i.
        gold_cluster = set(np.where(gold_ids == gold_ids[i])[0])  # gold cluster containing mention i.
        overlap = len(pred_cluster & gold_cluster)  # number of correct companions.
        ps.append(overlap / len(pred_cluster))  # cluster purity.
        rs.append(overlap / len(gold_cluster))  # gold coverage.
    p, r = float(np.mean(ps)), float(np.mean(rs))  # average scores.
    f = 0.0 if p + r == 0 else 2 * p * r / (p + r)  # harmonic mean.
    return p, r, f  # return metrics.

def show_ids(ids, labels, title):  # visualize cluster ids as a same-entity matrix.
    ids = np.asarray(ids)  # ensure array.
    plt.figure(figsize=(4, 3))  # compact figure.
    plt.imshow((ids[:, None] == ids[None, :]).astype(int), cmap="Greens", aspect="auto")  # same-cluster matrix.
    plt.xticks(range(len(labels)), labels, rotation=45)  # label columns.
    plt.yticks(range(len(labels)), labels)  # label rows.
    plt.title(title)  # title plot.
    plt.show()  # display.
```

### Basic 1 — List mentions in document order

**Goal.** Create candidate mentions with minimal metadata, because coreference compares mentions only after they have been detected. We build it in 2 steps.

```python
mentions_b1 = [  # store mention records in the order they appear.
    {"text": "Alice", "kind": "name", "gender": "f", "number": "sg", "sent": 0},
```

### Advanced 5 — End-to-end tiny resolver with metrics

**Goal.** Run a complete toy resolver from mentions to clusters to evaluation, because coreference quality depends on all steps working together. We build it in 5 steps.

```python

    {"text": "Alice", "kind": "name", "gender": "f", "number": "sg", "sent": 0},
    {"text": "Bob", "kind": "name", "gender": "m", "number": "sg", "sent": 0},
    {"text": "She", "kind": "pronoun", "gender": "f", "number": "sg", "sent": 1},
    {"text": "him", "kind": "pronoun", "gender": "m", "number": "sg", "sent": 1},
    {"text": "company", "kind": "desc", "gender": "unk", "number": "sg", "sent": 2},
    {"text": "It", "kind": "pronoun", "gender": "unk", "number": "sg", "sent": 3},
]
labels_a5 = [m["text"] for m in mentions_a5]  # labels.
weights_a5 = np.array([2.0, 1.0, 1.5, 0.5, 0.3])  # scoring weights.

```
▶ What you'll see: six mentions include three intended entities.

```python

for j_a5 in range(len(mentions_a5)):  # resolve each mention.
    if mentions_a5[j_a5]["kind"] != "pronoun":  # only pronouns link in this toy resolver.
        continue  # descriptions and names start entities unless linked later.
    cand_a5 = np.arange(j_a5)  # earlier candidates.
    scores_a5 = np.array([weights_a5 @ pairwise_features(mentions_a5[i], mentions_a5[j_a5]) for i in cand_a5])  # scores.

    links_a5.append((best_a5, j_a5))  # store link.
print("links:", [(labels_a5[i], labels_a5[j]) for i, j in links_a5])  # inspect decoded links.
```

