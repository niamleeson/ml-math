# 2.13 — Integer & Combinatorial Optimization

Integer and combinatorial optimization studies problems where decisions are discrete: choose this item or not, assign this worker to exactly one job, visit this city before that one. In this lesson, we build tiny 0-1 and permutation problems from scratch, see why continuous relaxations provide useful bounds but not always legal answers, and use those bounds to prune a branch-and-bound search.

## 📖 Concept walkthrough — build each idea from scratch

Before the worked examples, we build the lesson one idea at a time. Run each cell in order and inspect the printed arrays — every constraint, objective, relaxation, and pruning decision is kept tiny enough to audit by hand. This walkthrough is self-contained and uses a `_w` suffix so it never clashes with the examples below.

```python
import numpy as np  # arrays, enumeration, and small linear-algebra checks.
import matplotlib.pyplot as plt  # visual debugging for feasible sets, costs, and search trees.
np.random.seed(0)  # reproducibility for examples that use random data.
```

### 1. Discrete feasible sets are isolated choices, not smooth bowls

A continuous optimizer can slide from one feasible point to another by taking averages. A 0-1 decision cannot: the average of "do not pick" and "pick" is 0.5, which is useful as a bound but illegal as a final decision. That is why integer optimization feels like searching a constellation of points instead of descending a surface.

```python
z_points_w = np.array([[0, 0], [0, 1], [1, 0], [1, 1]], dtype=float)  # every 2-bit decision.
avg_w = 0.5 * (z_points_w[0] + z_points_w[-1])  # average of (0,0) and (1,1).
print("binary feasible points:\n", z_points_w)
print("average of two feasible points:", avg_w)
print("is the average binary?", bool(np.all((avg_w == 0) | (avg_w == 1))))
```
▶ What you'll see: four legal corner points and an average `[0.5, 0.5]` that is not a valid binary decision.

```python
values_w = np.array([3.0, 4.0])  # objective coefficients for two yes/no choices.
obj_w = z_points_w @ values_w  # objective value at each isolated point.
print("objective values:", obj_w)
assert np.array_equal(obj_w, np.array([0., 4., 3., 7.]))

plt.figure(figsize=(4, 3))
plt.scatter(z_points_w[:, 0], z_points_w[:, 1], s=90, color="teal", label="integer points")
plt.scatter([avg_w[0]], [avg_w[1]], s=90, color="crimson", label="illegal average")
for idx_w, point_w in enumerate(z_points_w):
    plt.text(point_w[0] + 0.03, point_w[1] + 0.03, f"value {obj_w[idx_w]:.0f}")
plt.xticks([0, 1]); plt.yticks([0, 1]); plt.xlim(-0.2, 1.2); plt.ylim(-0.2, 1.2)
plt.title("1: binary choices are isolated points"); plt.legend(); plt.show()
```
▶ What you'll see: only the four corners are legal; the red midpoint lives inside the relaxed square but outside the integer set.

*Why it's done this way:* listing the four points makes the geometry undeniable. Continuous optimization relies on paths and averages; integer optimization must reason over discrete alternatives, so we need enumeration, relaxations, and pruning rather than gradients alone.

### 2. A 0-1 knapsack is value maximization with a capacity constraint

Knapsack is the smallest useful template: each item has value $v_j$, weight $w_j$, and a decision $z_j\in\{0,1\}$. The objective is $v^Tz$ and the constraint is $w^Tz\le C$. Because there are only three items here, we can enumerate every binary vector and verify the best legal choice exactly.

```python
weights_w = np.array([2, 3, 4])  # item weights.
values_knap_w = np.array([3, 4, 5])  # item values.
capacity_w = 5  # total weight limit.
choices_w = np.array([[int(bit) for bit in format(i, "03b")] for i in range(8)])  # all 2^3 choices.
print("choices shape:", choices_w.shape)
print(choices_w)
```
▶ What you'll see: eight possible 0-1 item subsets, from selecting nothing to selecting all three items.

```python
total_weight_w = choices_w @ weights_w  # w^T z for each subset.
total_value_w = choices_w @ values_knap_w  # v^T z for each subset.
feasible_w = total_weight_w <= capacity_w  # capacity test.
print("weights:", total_weight_w)
print("values: ", total_value_w)
print("feasible:", feasible_w.astype(int))
```
▶ What you'll see: some high-value subsets are illegal because their total weight exceeds 5.

```python
masked_value_w = np.where(feasible_w, total_value_w, -np.inf)  # infeasible choices cannot win.
best_idx_w = int(np.argmax(masked_value_w))
best_z_w = choices_w[best_idx_w]
print("best z:", best_z_w, "weight:", total_weight_w[best_idx_w], "value:", total_value_w[best_idx_w])
assert np.array_equal(best_z_w, np.array([1, 1, 0]))
assert total_weight_w[best_idx_w] == 5 and total_value_w[best_idx_w] == 7

plt.figure(figsize=(5, 3))
colors_w = np.where(feasible_w, "seagreen", "crimson")
plt.bar(np.arange(len(choices_w)), total_value_w, color=colors_w)
plt.axhline(total_value_w[best_idx_w], color="black", linestyle="--", label="best legal value")
plt.xticks(np.arange(len(choices_w)), ["".join(map(str, z)) for z in choices_w], rotation=45)
plt.ylabel("value"); plt.title("2: enumerate knapsack subsets"); plt.legend(); plt.show()
```
▶ What you'll see: green bars are legal subsets, red bars violate capacity, and `[1,1,0]` is the best legal subset with value 7.

*Why it's done this way:* enumeration is exponential, but for a toy problem it is the cleanest truth source. We compute objectives and constraints as dot products because the same linear form scales to integer programming formulations.

### 3. LP relaxation gives a bound, but fractional answers can be illegal

A relaxation replaces $z_j\in\{0,1\}$ with $0\le z_j\le1$. For knapsack, the relaxed problem can take fractions of items. That fractional solution is not a legal 0-1 answer, but its value is an upper bound on the best integer value because it optimizes over a larger feasible set.

```python
weights_gap_w = np.array([4.0, 5.0])
values_gap_w = np.array([7.0, 10.0])
capacity_gap_w = 6.0
choices_gap_w = np.array([[0, 0], [0, 1], [1, 0], [1, 1]], dtype=float)
int_weights_gap_w = choices_gap_w @ weights_gap_w
int_values_gap_w = choices_gap_w @ values_gap_w
int_feasible_gap_w = int_weights_gap_w <= capacity_gap_w
print("integer weights:", int_weights_gap_w)
print("integer values: ", int_values_gap_w)
```
▶ What you'll see: the best legal integer subset is item 2 alone, value 10.

```python
best_int_gap_w = float(np.max(np.where(int_feasible_gap_w, int_values_gap_w, -np.inf)))
density_gap_w = values_gap_w / weights_gap_w  # value per unit capacity.
order_gap_w = np.argsort(density_gap_w)[::-1]  # fractional knapsack fills best density first.
print("value densities:", density_gap_w, "order:", order_gap_w)
assert best_int_gap_w == 10.0
```
▶ What you'll see: item with value 10 has density 2.0, so the relaxation takes it first.

```python
remaining_gap_w = capacity_gap_w
z_frac_gap_w = np.zeros_like(values_gap_w)
for item_w in order_gap_w:
    take_w = min(1.0, remaining_gap_w / weights_gap_w[item_w])
    z_frac_gap_w[item_w] = take_w
    remaining_gap_w -= take_w * weights_gap_w[item_w]
frac_value_gap_w = float(z_frac_gap_w @ values_gap_w)
gap_w = frac_value_gap_w - best_int_gap_w
print("fractional z:", z_frac_gap_w, "value:", frac_value_gap_w)
print("integrality gap:", gap_w)
assert np.allclose(z_frac_gap_w, np.array([0.25, 1.0]))
assert frac_value_gap_w == 11.75 and gap_w == 1.75

plt.figure(figsize=(4.5, 3))
plt.bar(["integer best", "LP relaxation"], [best_int_gap_w, frac_value_gap_w], color=["seagreen", "orange"])
plt.ylabel("objective value"); plt.title("3: relaxation is a bound, not a legal answer"); plt.show()
```
▶ What you'll see: the fractional relaxation reaches 11.75, beating the best legal integer value 10 by 1.75.

*Why it's done this way:* the density rule solves fractional knapsack greedily because each remaining capacity unit should buy the largest value per weight. The result is an upper bound: every integer vector is also feasible for the relaxation, but the relaxation may choose fractional coordinates no integer solution can use.

### 4. Assignment constraints are permutations

In an assignment problem, each row must choose exactly one column and each column must be chosen exactly once. The objective may be a simple sum of selected costs, but the feasible set is combinatorial: for $n$ jobs there are $n!$ permutations. Tiny matrices can be enumerated directly so the one-row-one-column constraint is visible.

```python
cost_w = np.array([[4, 1, 3],
                   [2, 0, 5],
                   [3, 2, 2]], dtype=float)
perms_w = np.array([[0, 1, 2], [0, 2, 1], [1, 0, 2], [1, 2, 0], [2, 0, 1], [2, 1, 0]])
print("cost matrix:\n", cost_w)
print("permutations:\n", perms_w)
```
▶ What you'll see: each permutation says which job column each row receives.

```python
assign_costs_w = np.array([cost_w[np.arange(3), perm_w].sum() for perm_w in perms_w])
best_assign_idx_w = int(np.argmin(assign_costs_w))
print("assignment costs:", assign_costs_w)
print("best assignment:", perms_w[best_assign_idx_w], "cost:", assign_costs_w[best_assign_idx_w])
assert np.array_equal(perms_w[best_assign_idx_w], np.array([1, 0, 2]))
assert assign_costs_w[best_assign_idx_w] == 5
```
▶ What you'll see: assignment `(1,0,2)` costs `1 + 2 + 2 = 5`, the best among all six permutations.

```python
best_matrix_w = np.zeros_like(cost_w)
best_matrix_w[np.arange(3), perms_w[best_assign_idx_w]] = 1
print("binary assignment matrix:\n", best_matrix_w.astype(int))
print("row sums:", best_matrix_w.sum(axis=1), "column sums:", best_matrix_w.sum(axis=0))

plt.figure(figsize=(4, 3))
plt.imshow(cost_w, cmap="magma_r")
for r_w in range(3):
    for c_w in range(3):
        mark_w = "✓" if best_matrix_w[r_w, c_w] == 1 else ""
        plt.text(c_w, r_w, f"{cost_w[r_w,c_w]:.0f}{mark_w}", ha="center", va="center")
plt.title("4: best one-to-one assignment"); plt.colorbar(label="cost"); plt.show()
```
▶ What you'll see: one checked cell in every row and every column, with total checked cost 5.

*Why it's done this way:* permutations encode the all-different column constraint without extra bookkeeping. The equivalent binary matrix exposes the linear constraints: every row sum equals 1 and every column sum equals 1.

### 5. Branch-and-bound combines search with relaxation bounds

Branch-and-bound explores integer decisions as a tree. At a partial node, we compute a bound by allowing undecided variables to be fractional. If that upper bound cannot beat the best feasible integer solution found so far (the incumbent), the whole branch can be pruned without enumerating its leaves.

```python
weights_bb_w = np.array([4.0, 5.0, 3.0])
values_bb_w = np.array([7.0, 10.0, 5.0])
capacity_bb_w = 8.0
density_bb_w = values_bb_w / weights_bb_w
order_bb_w = np.argsort(density_bb_w)[::-1]
print("density order:", order_bb_w)
```
▶ What you'll see: the relaxation will pack undecided items by value density to get an optimistic upper bound.

```python
def fractional_bound_w(fixed_w):
    used_weight_w = sum(weights_bb_w[i_w] * val_w for i_w, val_w in fixed_w.items())
    used_value_w = sum(values_bb_w[i_w] * val_w for i_w, val_w in fixed_w.items())
    if used_weight_w > capacity_bb_w:
        return -np.inf
    remaining_w = capacity_bb_w - used_weight_w
    bound_w = used_value_w
    for item_w in order_bb_w:
        if item_w in fixed_w:
            continue
        take_w = min(1.0, remaining_w / weights_bb_w[item_w])
        bound_w += take_w * values_bb_w[item_w]
        remaining_w -= take_w * weights_bb_w[item_w]
        if remaining_w <= 0:
            break
    return float(bound_w)

print("root bound:", fractional_bound_w({}))
print("bound with item 1 excluded:", fractional_bound_w({1: 0}))
assert round(fractional_bound_w({}), 3) == 15.25
```
▶ What you'll see: each partial assignment gets an optimistic value that may include fractional pieces of undecided items.

```python
incumbent_value_w = 0.0
incumbent_z_w = None
nodes_seen_w = 0
nodes_pruned_w = 0

def search_w(fixed_w):
    global incumbent_value_w, incumbent_z_w, nodes_seen_w, nodes_pruned_w
    nodes_seen_w += 1
    bound_w = fractional_bound_w(fixed_w)
    if bound_w <= incumbent_value_w:
        nodes_pruned_w += 1
        return
    if len(fixed_w) == len(weights_bb_w):
        z_w = np.array([fixed_w[i_w] for i_w in range(len(weights_bb_w))], dtype=float)
        weight_w = float(z_w @ weights_bb_w)
        value_w = float(z_w @ values_bb_w)
        if weight_w <= capacity_bb_w and value_w > incumbent_value_w:
            incumbent_value_w = value_w
            incumbent_z_w = z_w.copy()
        return
    next_item_w = len(fixed_w)
    search_w({**fixed_w, next_item_w: 1})
    search_w({**fixed_w, next_item_w: 0})

search_w({})
print("incumbent z:", incumbent_z_w, "value:", incumbent_value_w)
print("nodes seen:", nodes_seen_w, "nodes pruned:", nodes_pruned_w)
assert np.array_equal(incumbent_z_w, np.array([0., 1., 1.]))
assert incumbent_value_w == 15.0
```
▶ What you'll see: the search finds items 1 and 2 with value 15, while pruning branches whose relaxed bound cannot improve the incumbent.

```python
bb_trace_w = []
def collect_bb_trace_w(fixed_w, depth_w=0):
    bound_w = fractional_bound_w(fixed_w)
    status_w = "pruned" if bound_w <= incumbent_value_w else "kept"
    bb_trace_w.append((depth_w, dict(fixed_w), bound_w, status_w))
    if status_w == "pruned" or len(fixed_w) == len(weights_bb_w):
        return
    next_item_w = len(fixed_w)
    collect_bb_trace_w({**fixed_w, next_item_w: 1}, depth_w + 1)
    collect_bb_trace_w({**fixed_w, next_item_w: 0}, depth_w + 1)

collect_bb_trace_w({})
fig, ax = plt.subplots(figsize=(6, 3.5))
level_counts_w = {d_w: 0 for d_w, _, _, _ in bb_trace_w}
pos_w = {}
for idx_w, (depth_w, fixed_w, bound_w, status_w) in enumerate(bb_trace_w):
    k_w = level_counts_w[depth_w]
    level_counts_w[depth_w] += 1
    pos_w[idx_w] = (k_w, -depth_w)
    color_w = "crimson" if status_w == "pruned" else "seagreen"
    ax.scatter(k_w, -depth_w, s=180, color=color_w)
    label_w = "root" if not fixed_w else "".join(str(fixed_w[i_w]) for i_w in range(len(fixed_w)))
    ax.text(k_w, -depth_w + 0.12, label_w, ha="center", fontsize=8)
    ax.text(k_w, -depth_w - 0.22, f"B={bound_w:.1f}", ha="center", fontsize=8)
for i_w, (depth_w, fixed_w, _, _) in enumerate(bb_trace_w):
    if depth_w == 0:
        continue
    parent_fixed_w = dict(list(fixed_w.items())[:-1])
    parent_idx_w = next(j_w for j_w, (_, f_w, _, _) in enumerate(bb_trace_w) if f_w == parent_fixed_w)
    ax.plot([pos_w[parent_idx_w][0], pos_w[i_w][0]], [pos_w[parent_idx_w][1], pos_w[i_w][1]], color="gray", lw=1)
ax.set_axis_off(); ax.set_title("5: branch-and-bound tree with pruned nodes")
plt.show()
```
▶ What you'll see: green nodes can still compete with the incumbent; red nodes are cut off by their relaxed bound.

*Why it's done this way:* the relaxation is deliberately optimistic, so pruning is safe: if even the optimistic version of a branch cannot win, no stricter integer descendant can win. That is the bridge from continuous bounds to discrete search.

### 6. Rounding and symmetry are formulation pitfalls

Two common mistakes are rounding a relaxation without checking feasibility and searching symmetric duplicates as if they were different. Rounding can violate constraints or lose value; symmetry multiplies the tree with equivalent configurations. Small diagnostics expose both before they scale into expensive bugs.

```python
z_relax_w = np.array([0.6, 0.6])
weights_round_w = np.array([5.0, 5.0])
values_round_w = np.array([9.0, 9.0])
capacity_round_w = 5.0
z_rounded_w = (z_relax_w >= 0.5).astype(float)
print("relaxed z:", z_relax_w, "rounded z:", z_rounded_w)
print("rounded weight:", z_rounded_w @ weights_round_w, "capacity:", capacity_round_w)
assert z_rounded_w @ weights_round_w > capacity_round_w
```
▶ What you'll see: naïvely rounding both 0.6 variables up selects two items and violates the capacity.

```python
all_pairs_w = np.array([[i_w, j_w] for i_w in range(3) for j_w in range(3) if i_w != j_w])
symmetry_broken_w = all_pairs_w[all_pairs_w[:, 0] < all_pairs_w[:, 1]]
print("ordered pairs without self-pairs:\n", all_pairs_w)
print("unique unordered pairs after i<j:\n", symmetry_broken_w)
assert len(all_pairs_w) == 6 and len(symmetry_broken_w) == 3

plt.figure(figsize=(4.5, 3))
plt.bar(["with symmetric duplicates", "after i < j"], [len(all_pairs_w), len(symmetry_broken_w)], color=["orange", "seagreen"])
plt.ylabel("candidate count"); plt.title("6: symmetry-breaking removes duplicates"); plt.show()
```
▶ What you'll see: enforcing `i < j` cuts the equivalent pair count in half.

*Why it's done this way:* feasibility checks protect against illegal rounded answers, while symmetry-breaking adds a harmless ordering convention that keeps the solver from revisiting equivalent choices.

**Goal.** Score each binary decision with $v^Tz$, because integer programs usually keep the objective linear even when decisions are discrete.


### Basic 3 — Check a capacity constraint

**Goal.** Mark which subsets fit in a knapsack, because constraints decide which high-value choices are legal.

```python
choices_b3 = np.array([[0, 0], [0, 1], [1, 0], [1, 1]])
weights_b3 = np.array([4, 5])
capacity_b3 = 6

```
▶ What you'll see: selecting both items violates the capacity even though each item alone is feasible.

```python
plt.figure(figsize=(4.5, 3))
plt.scatter(used_b3, choices_b3 @ np.array([1, 1]), c=np.where(feasible_b3, "seagreen", "crimson"), s=90)
for idx_b3, z_b3 in enumerate(choices_b3):
    plt.text(used_b3[idx_b3] + 0.1, (choices_b3 @ np.array([1, 1]))[idx_b3], "".join(map(str, z_b3)))
plt.axvline(capacity_b3, color="black", linestyle="--", label="capacity")
plt.xlabel("used weight"); plt.ylabel("items selected"); plt.title("Basic 3: capacity filters candidates")
plt.legend(); plt.show()
```
▶ What you'll see: the red subset lies to the right of the capacity line, so it is illegal.

👀 Takeaway: integer feasibility is a logical test on each candidate, not a gradient direction.

### Basic 6 — Compute value density

**Goal.** Rank items by value per weight, because fractional knapsack relaxations fill capacity by density.

```python
weights_b6 = np.array([4.0, 5.0])
```

### Advanced 1 — Run branch-and-bound for knapsack

**Goal.** Implement a complete tiny branch-and-bound solver, because exact discrete search becomes practical only when weak branches are pruned.

```python
weights_a1 = np.array([4.0, 5.0, 3.0])
values_a1 = np.array([7.0, 10.0, 5.0])
capacity_a1 = 8.0
order_a1 = np.argsort(values_a1 / weights_a1)[::-1]

def bound_a1(fixed_a1):
    used_w_a1 = sum(weights_a1[i_a1] * v_a1 for i_a1, v_a1 in fixed_a1.items())
    used_v_a1 = sum(values_a1[i_a1] * v_a1 for i_a1, v_a1 in fixed_a1.items())
    if used_w_a1 > capacity_a1:
        return -np.inf
    remaining_a1 = capacity_a1 - used_w_a1
    total_a1 = used_v_a1
    for item_a1 in order_a1:
        if item_a1 in fixed_a1:
            continue
        take_a1 = min(1.0, remaining_a1 / weights_a1[item_a1])
        total_a1 += take_a1 * values_a1[item_a1]
        remaining_a1 -= take_a1 * weights_a1[item_a1]
        if remaining_a1 <= 0:
            break
    return float(total_a1)

best_value_a1 = 0.0
best_z_a1 = np.zeros(3)
seen_a1 = 0
pruned_a1 = 0
stack_a1 = [dict()]
while stack_a1:
    fixed_now_a1 = stack_a1.pop()
    seen_a1 += 1
    if bound_a1(fixed_now_a1) <= best_value_a1:
        pruned_a1 += 1
        continue
    if len(fixed_now_a1) == 3:
        z_a1 = np.array([fixed_now_a1[i_a1] for i_a1 in range(3)], dtype=float)
        value_a1 = float(z_a1 @ values_a1)
        if float(z_a1 @ weights_a1) <= capacity_a1 and value_a1 > best_value_a1:
            best_value_a1 = value_a1
            best_z_a1 = z_a1
    else:
        next_i_a1 = len(fixed_now_a1)
        stack_a1.append({**fixed_now_a1, next_i_a1: 0})
        stack_a1.append({**fixed_now_a1, next_i_a1: 1})
print("best:", best_z_a1, best_value_a1, "seen:", seen_a1, "pruned:", pruned_a1)
assert best_value_a1 == 15.0
```
▶ What you'll see: the solver returns the same optimum as enumeration while pruning some nodes.
