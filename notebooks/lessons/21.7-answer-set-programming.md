# 21.7 — Answer Set Programming

Answer set programming (ASP) describes a problem as rules over possible worlds, then keeps only the worlds that are self-consistent, supported, and constraint-satisfying. In this lesson, we build the machinery from scratch in pure Python: atoms, normal rules, grounding, negation-as-failure, the Gelfond-Lifschitz reduct, stable-model checking, choice rules, constraints, and answer-set enumeration.

## 📖 Concept walkthrough — build each idea from scratch

Before the terse worked examples, we build answer set programming one idea at a time. Run each cell in order and read the printed intermediate values — every piece of logic is made explicit so the solver is not a black box. This walkthrough is self-contained and uses a `_w` suffix on its variables so it never clashes with the examples below.

```python
import itertools  # finite possible-world enumeration and grounding products.
import numpy as np  # small arrays for visual summaries.
import matplotlib.pyplot as plt  # all walkthrough visualizations.
np.random.seed(0)  # reproducibility for any randomized display choices.
```

### 1. Normal logic programs as rules over possible worlds

A normal logic rule has the shape `head :- positive_body, not negative_body`. Read it as: the head must be true when all positive body atoms are true and none of the negated atoms can be proved. We start with a tiny program and a tiny rule evaluator before worrying about stable models.

```python
def rule_w(head, pos=(), neg=()):
    return {"head": head, "pos": tuple(pos), "neg": tuple(neg)}

def atoms_of_w(program):
    atoms = set()
    for r in program:
        if r["head"] is not None:
            atoms.add(r["head"])
        atoms.update(r["pos"])
        atoms.update(r["neg"])
    return tuple(sorted(atoms))

program_w = [rule_w("a"), rule_w("b", pos=("a",)), rule_w("c", pos=("b",))]
print("atoms:", atoms_of_w(program_w))
print("rules:", program_w)
```
▶ What you'll see: three atoms and three rules; `a` is a fact, `b` depends on `a`, and `c` depends on `b`.

```python
def body_true_w(rule, model):
    model = set(model)
    return all(a in model for a in rule["pos"]) and all(a not in model for a in rule["neg"])

def satisfies_rule_w(rule, model):
    if not body_true_w(rule, model):
        return True
    return rule["head"] is not None and rule["head"] in model

candidate_w = {"a", "b"}
print("candidate:", sorted(candidate_w))
print("rule satisfaction:", [satisfies_rule_w(r, candidate_w) for r in program_w])
```
▶ What you'll see: the candidate violates `c :- b` because it contains `b` but omits the supported consequence `c`.

```python
all_atoms_w = atoms_of_w(program_w)
worlds_w = [set(s) for k in range(len(all_atoms_w) + 1) for s in itertools.combinations(all_atoms_w, k)]
model_flags_w = [all(satisfies_rule_w(r, m) for r in program_w) for m in worlds_w]
print("number of possible worlds:", len(worlds_w))
print("models:", [sorted(m) for m, ok in zip(worlds_w, model_flags_w) if ok])
```
▶ What you'll see: several classical models survive rule satisfaction; stable semantics will later keep only the smallest supported one.

*Why it's done this way:* ASP begins by separating the declarative problem statement from search. A candidate world is just a set of atoms; rule satisfaction checks whether the world obeys the implications. That is not yet enough, because ordinary satisfaction allows extra unsupported atoms, but it gives us the first filter.

### 2. Least models give support for positive programs

When a program has no `not`, its intended model is the least fixed point: start with nothing, repeatedly add rule heads whose bodies are true, and stop when nothing changes. This computes support instead of merely accepting any superset that satisfies the rules.

```python
def least_model_w(positive_program):
    model = set()
    changed = True
    trace = []
    while changed:
        changed = False
        for r in positive_program:
            if r["head"] is not None and all(a in model for a in r["pos"]):
                if r["head"] not in model:
                    model.add(r["head"])
                    changed = True
                    trace.append(tuple(sorted(model)))
    return model, trace

lm_w, trace_w = least_model_w(program_w)
print("least model:", sorted(lm_w))
print("growth trace:", trace_w)
assert lm_w == {"a", "b", "c"}
```
▶ What you'll see: the model grows from `a` to `a,b` to `a,b,c` and then stops.

```python
plt.figure(figsize=(4.5, 3))
plt.step(range(len(trace_w) + 1), [0] + [len(t) for t in trace_w], where="post", color="seagreen")
plt.xticks(range(len(trace_w) + 1))
plt.xlabel("derivation step")
plt.ylabel("atoms derived")
plt.title("1: least-model construction")
plt.show()
```
▶ What you'll see: a staircase that rises only when a rule head becomes justified by already-derived atoms.

*Why it's done this way:* The least model is the support test for positive logic. It rejects arbitrary atoms because an atom enters only when some rule earns it. Stable-model semantics will reduce programs with negation into positive programs, then apply exactly this support check.

### 3. Negation-as-failure and the Gelfond-Lifschitz reduct

ASP's `not busy` does not mean busy is false in a classical proof system. It means busy is absent from the candidate world, so the rule may fire. The Gelfond-Lifschitz reduct evaluates that assumption: remove any rule whose negated atom is in the candidate, then erase the remaining `not` literals.

```python
def reduct_w(program, candidate):
    candidate = set(candidate)
    reduced = []
    for r in program:
        if any(a in candidate for a in r["neg"]):
            continue
        reduced.append(rule_w(r["head"], pos=r["pos"], neg=()))
    return reduced

choice_like_w = [rule_w("am", neg=("pm",)), rule_w("pm", neg=("am",))]
for cand_w in [{"am"}, {"pm"}, {"am", "pm"}, set()]:
    red_w = reduct_w(choice_like_w, cand_w)
    print("candidate", sorted(cand_w), "reduct", red_w)
```
▶ What you'll see: each candidate rewrites the same program differently because `not` is evaluated relative to that candidate.

```python
red_am_w = reduct_w(choice_like_w, {"am"})
lm_am_w, _ = least_model_w(red_am_w)
print("reduct least model for {am}:", sorted(lm_am_w))
assert lm_am_w == {"am"}
```
▶ What you'll see: assuming `am` makes the `pm` rule disappear and leaves `am` as the supported least model.

*Why it's done this way:* Negation-as-failure is powerful because absence can license choices, but it must be checked for circular self-consistency. The reduct turns “under this assumption, which rules remain?” into an ordinary positive program whose least model can be compared back to the assumption.

### 4. Stable models are fixed points of the reduct

A candidate is an answer set if it equals the least model of its own reduct. Equality matters: if the reduct derives less, the candidate contains unsupported atoms; if it derives more, the candidate omitted consequences it committed to.

```python
def is_stable_w(program, candidate):
    reduced = reduct_w(program, candidate)
    least, _ = least_model_w(reduced)
    return set(candidate) == least, least, reduced

for cand_w in [{"am"}, {"pm"}, {"am", "pm"}, set()]:
    ok_w, least_w, _ = is_stable_w(choice_like_w, cand_w)
    print("candidate", sorted(cand_w), "least(reduct)=", sorted(least_w), "stable?", ok_w)
```
▶ What you'll see: `{am}` and `{pm}` are stable; `{am,pm}` and `{}` fail the fixed-point check.

```python
atoms_choice_w = atoms_of_w(choice_like_w)
worlds_choice_w = [set(s) for k in range(3) for s in itertools.combinations(atoms_choice_w, k)]
stable_flags_w = [is_stable_w(choice_like_w, m)[0] for m in worlds_choice_w]
plt.figure(figsize=(5, 3))
plt.bar(["{" + ",".join(sorted(m)) + "}" for m in worlds_choice_w], stable_flags_w, color=["seagreen" if x else "lightgray" for x in stable_flags_w])
plt.xticks(rotation=25)
plt.ylabel("stable? 1=yes")
plt.title("2: candidate-vs-stable enumeration")
plt.show()
```
▶ What you'll see: only the one-slot worlds survive; look for green bars at `{am}` and `{pm}`.

*Why it's done this way:* Stable semantics is not ordinary truth-table satisfaction. It asks whether a world can reproduce itself after its own default-negation assumptions are applied. That self-reproduction is what makes an answer set a self-justifying possible world.

### 5. Grounding turns schemas into finite propositional rules

ASP systems often let us write templates such as `assign(task,slot)`. Before stable-model search, those templates are grounded into ordinary atom strings over a finite domain. Grounding is the bridge from a compact human statement to a finite Boolean search space.

```python
def ground_assign_w(tasks, slots):
    rules = []
    for task in tasks:
        for slot in slots:
            other_slots = [s for s in slots if s != slot]
            rules.append(rule_w(f"assign({task},{slot})", neg=tuple(f"assign({task},{s})" for s in other_slots)))
    return rules

tasks_w = ["t1", "t2"]
slots_w = ["am", "pm"]
grounded_w = ground_assign_w(tasks_w, slots_w)
print("ground rules:", len(grounded_w))
print(grounded_w[:2])
```
▶ What you'll see: the schema becomes four concrete rules, one possible assignment per task-slot pair.

```python
atoms_ground_w = atoms_of_w(grounded_w)
print("ground atoms:", atoms_ground_w)
print("candidate worlds before constraints:", 2 ** len(atoms_ground_w))
```
▶ What you'll see: four ground atoms yield sixteen possible worlds before stable-model filtering.

*Why it's done this way:* Grounding makes the solver's universe explicit. The price is combinatorial growth, but the benefit is that stable-model checking can operate on simple finite sets of atoms rather than higher-level templates.

### 6. Choice rules, constraints, and enumerating answer sets

Real ASP usually separates generation from rejection. Choice-like rules generate candidate assignments; constraints with no head reject worlds that violate requirements such as “not both tasks in AM.” Enumeration tries all finite worlds here so the semantics are visible.

```python
def stable_models_w(program):
    atoms = atoms_of_w(program)
    out = []
    for k in range(len(atoms) + 1):
        for combo in itertools.combinations(atoms, k):
            cand = set(combo)
            if any(r["head"] is None and body_true_w(r, cand) for r in program):
                continue
            ok, _, _ = is_stable_w(program, cand)
            if ok:
                out.append(cand)
    return out

constraint_w = rule_w(None, pos=("assign(t1,am)", "assign(t2,am)"))
schedule_w = grounded_w + [constraint_w]
answers_w = stable_models_w(schedule_w)
print("answer sets:", [sorted(a) for a in answers_w])
assert len(answers_w) == 3
```
▶ What you'll see: three schedules survive; the all-AM schedule is rejected by the constraint.

```python
labels_w = ["{" + ", ".join(sorted(a)) + "}" for a in answers_w]
am_counts_w = [sum("am" in atom for atom in a) for a in answers_w]
plt.figure(figsize=(6, 3))
plt.bar(range(len(answers_w)), am_counts_w, color="steelblue")
plt.xticks(range(len(answers_w)), labels_w, rotation=30, ha="right")
plt.ylabel("AM assignments")
plt.title("3: enumerated answer sets after constraint")
plt.show()
```
▶ What you'll see: no bar reaches 2, because the constraint removed the world where both tasks are assigned AM.

*Why it's done this way:* Generation makes the legal space broad enough to include alternatives; constraints carve away impossible worlds without rewriting the generator. Enumeration is brute force here, but it exposes exactly what industrial ASP solvers accelerate with grounding, propagation, and SAT-style search.

### ✍️ Toy 1 · A normal rule filters candidate worlds

A candidate world satisfies a rule only when a true body has its head included too.

```python
import numpy as np                              # arrays and tiny numeric checks.
import matplotlib.pyplot as plt                 # one picture per toy.

t1_rng = np.random.default_rng(0)               # reproducible toy seed.
print("rng seed:", 0)                           # -> 0
t1_program = [
    {"head": "p", "pos": (), "neg": ()},
    {"head": "q", "pos": ("p",), "neg": ()},
]
print("program:", t1_program)                   # -> [{'head': 'p', 'pos': (), 'neg': ()}, {'head': 'q', 'pos': ('p',), 'neg': ()}]
t1_candidate = {"p"}
print("candidate:", sorted(t1_candidate))       # -> ['p']

def t1_body_true(t1_rule, t1_model):
    return all(t1_atom in t1_model for t1_atom in t1_rule["pos"]) and all(t1_atom not in t1_model for t1_atom in t1_rule["neg"])

def t1_satisfies(t1_rule, t1_model):

t1_flags = np.array([t1_satisfies(t1_rule, t1_candidate) for t1_rule in t1_program], dtype=int)  # -> [1 0]

plt.title("Toy 1 · one violated rule")

```
▶ What you'll see: `{p}` satisfies the fact rule but violates the rule that requires `q` when `p` holds.

### ✍️ Toy 3 · The reduct evaluates negation against a candidate

Default-negated atoms are checked against the candidate: rules blocked by that assumption disappear.

```python
import numpy as np                              # arrays and tiny numeric checks.

t3_rng = np.random.default_rng(0)               # reproducible toy seed.
print("rng seed:", 0)                           # -> 0
t3_program = [

    {"head": "right", "pos": (), "neg": ("left",)},

    t3_out = []
```

### ✍️ Toy 4 · Stable models reproduce themselves

A stable model equals the least model of its own reduct.

```python
import numpy as np                              # arrays and tiny numeric checks.

t4_rng = np.random.default_rng(0)               # reproducible toy seed.
print("rng seed:", 0)                           # -> 0
t4_program = [
    {"head": "left", "pos": (), "neg": ("right",)},
    {"head": "right", "pos": (), "neg": ("left",)},
]
print("program:", t4_program)                   # -> [{'head': 'left', 'pos': (), 'neg': ('right',)}, {'head': 'right', 'pos': (), 'neg': ('left',)}]

def t4_reduct(t4_program, t4_candidate):
    t4_out = []
    for t4_rule in t4_program:
        if not any(t4_atom in t4_candidate for t4_atom in t4_rule["neg"]):
            t4_out.append({"head": t4_rule["head"], "pos": t4_rule["pos"]})
    return t4_out

def t4_least(t4_program):
    t4_model = set()
    t4_changed = True
    while t4_changed:
        t4_changed = False
        for t4_rule in t4_program:
            if all(t4_atom in t4_model for t4_atom in t4_rule["pos"]) and t4_rule["head"] not in t4_model:
                t4_model.add(t4_rule["head"])
                t4_changed = True
    return t4_model

t4_worlds = [set(), {"left"}, {"right"}, {"left", "right"}]
print("worlds:", [sorted(t4_world) for t4_world in t4_worlds]) # -> [[], ['left'], ['right'], ['left', 'right']]
t4_leasts = [t4_least(t4_reduct(t4_program, t4_world)) for t4_world in t4_worlds]
print("least(reduct):", [sorted(t4_least_model) for t4_least_model in t4_leasts]) # -> [['left', 'right'], ['left'], ['right'], []]
t4_stable = np.array([t4_world == t4_least_model for t4_world, t4_least_model in zip(t4_worlds, t4_leasts)], dtype=int)  # -> [0 1 1 0]
print("stable flags:", t4_stable.tolist())      # -> [0, 1, 1, 0]
assert t4_stable.tolist() == [0, 1, 1, 0]

plt.figure(figsize=(4.8, 2.8))
plt.bar(["{}", "{left}", "{right}", "{both}"], t4_stable, color=["seagreen" if t4_flag else "lightgray" for t4_flag in t4_stable])
plt.ylim(0, 1.2)
plt.ylabel("stable?")
plt.title("Toy 4 · fixed points survive")
plt.show()
```
▶ What you'll see: exactly the one-choice worlds reproduce themselves after the reduct.

### ✍️ Toy 6 · Choice generation plus constraints enumerates answer sets

Choice atoms generate possible schedules; constraints reject worlds that break the problem rules.

```python
import numpy as np                              # arrays and tiny numeric checks.

t6_rng = np.random.default_rng(0)               # reproducible toy seed.
print("rng seed:", 0)                           # -> 0
t6_atoms = ["pick(a,am)", "pick(a,pm)", "pick(b,am)", "pick(b,pm)"]
print("atoms:", t6_atoms)                       # -> ['pick(a,am)', 'pick(a,pm)', 'pick(b,am)', 'pick(b,pm)']
t6_worlds = []
for t6_mask in range(2 ** len(t6_atoms)):
    t6_world = {t6_atom for t6_i, t6_atom in enumerate(t6_atoms) if (t6_mask >> t6_i) & 1}
    t6_worlds.append(t6_world)
print("world count:", len(t6_worlds))           # -> 16

def t6_exactly_one(t6_world, t6_task):
    t6_count = sum(f"pick({t6_task}," in t6_atom for t6_atom in t6_world)
    return t6_count == 1

def t6_allowed(t6_world):
    t6_one_each = t6_exactly_one(t6_world, "a") and t6_exactly_one(t6_world, "b")
    t6_not_both_am = not ({"pick(a,am)", "pick(b,am)"} <= t6_world)
    return t6_one_each and t6_not_both_am

t6_answers = [t6_world for t6_world in t6_worlds if t6_allowed(t6_world)]
print("answer sets:", [sorted(t6_ans) for t6_ans in t6_answers]) # -> [['pick(a,am)', 'pick(b,pm)'], ['pick(a,pm)', 'pick(b,am)'], ['pick(a,pm)', 'pick(b,pm)']]
t6_am_counts = np.array([sum("am" in t6_atom for t6_atom in t6_ans) for t6_ans in t6_answers])  # -> [1 1 0]
print("AM counts:", t6_am_counts.tolist())      # -> [1, 1, 0]
assert len(t6_answers) == 3

plt.figure(figsize=(5.0, 2.8))
plt.bar(range(len(t6_answers)), t6_am_counts, color="steelblue")
plt.xticks(range(len(t6_answers)), ["Aam/Bpm", "Apm/Bam", "Apm/Bpm"], rotation=15)
plt.ylabel("AM picks")
plt.title("Toy 6 · constraint removes both-AM")
plt.show()
```
▶ What you'll see: generation makes sixteen worlds, and the tiny constraints leave three answer sets.

## 🛠️ Setup

```python
import itertools  # Use Cartesian products and subsets to ground and enumerate finite programs.
import numpy as np  # Use arrays for compact counts, costs, and plotting values.
import matplotlib.pyplot as plt  # Use Matplotlib for candidate/stable visual checks.
np.random.seed(0)  # Make all examples reproducible.

def asp_rule(head, pos=(), neg=()):
    return {"head": head, "pos": tuple(pos), "neg": tuple(neg)}

def asp_atoms(program):
    atoms = set()
    for r in program:
        if r["head"] is not None:
            atoms.add(r["head"])
        atoms.update(r["pos"])
        atoms.update(r["neg"])
    return tuple(sorted(atoms))

def asp_body_true(rule, model):
    model = set(model)
    return all(a in model for a in rule["pos"]) and all(a not in model for a in rule["neg"])

def asp_satisfies_constraints(program, model):
    return all(not asp_body_true(r, model) for r in program if r["head"] is None)

def asp_reduct(program, candidate):
    candidate = set(candidate)
    return [asp_rule(r["head"], r["pos"], ()) for r in program if not any(a in candidate for a in r["neg"])]

def asp_least_model(positive_program):
    model = set()
    changed = True
    while changed:
        changed = False
        for r in positive_program:
            if r["head"] is not None and all(a in model for a in r["pos"]):
                if r["head"] not in model:
                    model.add(r["head"])
                    changed = True
    return model

def asp_is_stable(program, candidate):
    candidate = set(candidate)
    if not asp_satisfies_constraints(program, candidate):
        return False
    return candidate == asp_least_model(asp_reduct(program, candidate))

def asp_answer_sets(program):
    atoms = asp_atoms(program)
    answers = []
    for k in range(len(atoms) + 1):
        for combo in itertools.combinations(atoms, k):
            candidate = set(combo)
            if asp_is_stable(program, candidate):
                answers.append(candidate)
    return answers

def asp_choice_exactly_one(prefix, item, options):
    return [asp_rule(f"{prefix}({item},{opt})", neg=tuple(f"{prefix}({item},{other})" for other in options if other != opt)) for opt in options]
```

## 🟢 Basics (warm-up)

### Basic 1 — Represent atoms and facts

**Goal.** Store a tiny logic program as data, because ASP solvers manipulate rules rather than procedural branches. We build it in 2 steps.

```python
program_b1 = [asp_rule("light"), asp_rule("see", pos=("light",))]
atoms_b1 = asp_atoms(program_b1)
print("program:", program_b1)
print("atoms:", atoms_b1)
```
▶ What you'll see: `light` appears as a fact and `see` appears as a consequence atom.

```python
least_b1 = asp_least_model(program_b1)
print("least model:", sorted(least_b1))
assert least_b1 == {"light", "see"}
plt.figure(figsize=(4, 3))
plt.bar(["light", "see"], [a in least_b1 for a in ["light", "see"]], color="seagreen")
plt.title("Basic 1: derived atoms")
plt.ylabel("in least model")
plt.show()
```
▶ What you'll see: both atoms are derived because `see` is supported by `light`.

👀 Takeaway: facts seed a positive program, and rules propagate their consequences.

### Basic 2 — Check a rule body

**Goal.** Test positive and default-negated body literals, because every later filter depends on whether a rule fires. We build it in 2 steps.

```python
rule_b2 = asp_rule("play", pos=("free",), neg=("rain",))
model_b2 = {"free"}
print("rule fires?", asp_body_true(rule_b2, model_b2))
assert asp_body_true(rule_b2, model_b2)
```
▶ What you'll see: the body is true because `free` is present and `rain` is absent.

```python
model_rain_b2 = {"free", "rain"}

plt.figure(figsize=(4, 3))
plt.bar(["free only", "free+rain"], [1, 0], color=["seagreen", "lightgray"])
plt.title("Basic 2: negation-as-failure gate")
plt.ylabel("body true")
plt.show()
```
▶ What you'll see: adding `rain` blocks a rule that depends on `not rain`.

👀 Takeaway: `not x` is a candidate-relative absence test, not a classical proof of falsehood.

### Basic 3 — Build a least model

**Goal.** Derive consequences until a fixed point, because positive rules need support rather than arbitrary truth assignment. We build it in 2 steps.

```python

print("least model:", sorted(model_b3))
assert model_b3 == {"a", "b", "c"}
```
▶ What you'll see: the chain derives `a`, then `b`, then `c`.

```python

plt.figure(figsize=(4, 3))

plt.title("Basic 3: least model rejects extras")
plt.ylabel("atom count")
plt.show()
```
▶ What you'll see: the candidate is larger only because it added an unsupported atom.

👀 Takeaway: least-model reasoning is the support mechanism behind stable models.

▶ What you'll see: reachability contains the transitive connection in addition to direct edges.

👀 Takeaway: positive recursive logic grows to a least fixed point, which is exactly the supported closure.

### Advanced 5 — Plan actions as answer sets

**Goal.** Choose one action per time step and enforce a goal, because ASP is often used for small planning and configuration problems. We build it in 3 steps.

```python
times_a5 = ["0", "1"]
actions_a5 = ["move", "wait"]
program_a5 = []
for t_a5 in times_a5:
    program_a5 += asp_choice_exactly_one("do", t_a5, actions_a5)
program_a5 += [asp_rule("at_goal", pos=("do(0,move)", "do(1,move)")), asp_rule(None, neg=("at_goal",))]
print("ground atoms:", len(asp_atoms(program_a5)))
```
▶ What you'll see: action choices plus a derived `at_goal` atom form the planning search space.

```python
answers_a5 = asp_answer_sets(program_a5)
print("plans:", [sorted(a) for a in answers_a5])
assert len(answers_a5) == 1
assert {"do(0,move)", "do(1,move)", "at_goal"} == answers_a5[0]
```

```python
move_counts_a5 = [sum("move" in atom for atom in ans) for ans in answers_a5]
plt.figure(figsize=(4, 3))
plt.bar(["surviving plan"], move_counts_a5, color="seagreen")
plt.title("Advanced 5: goal-constrained plan")
plt.ylabel("move actions")
plt.show()
```
▶ What you'll see: only the plan with two moves survives because the constraint requires `at_goal`.

👀 Takeaway: ASP planning states what counts as a valid world, then stable-model search finds the action set that realizes it.
